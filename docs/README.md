# 開発ドキュメントの構成

docs/ 直下に置くファイルは、本書と [ROADMAP.md](ROADMAP.md) の2つだけとする。
その他の文書は、次の表の分類に従って下位ディレクトリへ置く。
既存の分類に収まらない文書が必要になったときは、ディレクトリを追加してから本書の表へ行を加える。

| ディレクトリ | 置く文書 | 書き方 |
|---|---|---|
| [rules/](rules/) | 本プロジェクトが実装する中将棋の競技規則とローカルルールの規則書 [chu-shogi.md](rules/chu-shogi.md)。標準規則と規則コードの定義、および典拠の一覧を含む。凍結した設計書、監査、提案、および調査メモの本文に現れる RULES.md は、この規則書の旧名である。 | 条文の番号と規則コードを他の文書と実装が参照するので、改版時は版数と変更点を本文に記す。 |
| [plans/](plans/) | マイルストーンの作業を進めるための一時的な計画書。仕様の正ではなく、完了時に有効な内容をコードのdocコメントとADRへ移して凍結し、[plans/archived/](plans/archived/)へ移す。直下には起案中、進行中、および待機中の設計書だけを置く。 | [plans/README.md](plans/README.md) の型に従う。 |
| [adr/](adr/) | 設計判断の記録（ADR）。採った方式、棄却した代案、およびその根拠を1決定1ファイルで置き、[adr/README.md](adr/README.md) を索引とする。 | adr/README.md のテンプレートに従う。承認後は本文を書き換えず、決定を変えるときは新しいADRで置き換え、置き換えられたADRは [adr/archive/](adr/archive/) へ移す。 |
| [measurements/](measurements/) | 棋力測定、速度測定、学習、および診断の記録。1測定1ファイルで、その測定を計画した設計書ごとのディレクトリ `<設計書名>/` に置き、どの設計書も計画していない測定は `adhoc/` に置く。ファイル名は `minase match run` の `--run-dir` の名前と一致させる。 | plans/README.md の「測定記録」節に従う。 |
| [lessons/](lessons/) | 作業で詰まった箇所から得た汎用的な教訓。1教訓1ファイルで、[lessons/README.md](lessons/README.md) を索引とする。 | plans/README.md の「教訓」節に従う。 |
| [guides/](guides/) | 人間とエージェントが手順どおりに実行する手引き。[guides/README.md](guides/README.md) を索引とする。ファイルの形式、記録の欄、およびコードが実装する式は、それを読み書きするコードのdocコメントが定めるので、手引きには書かずに該当する項目を示す。 | 手順を実行順に書き、判断規則と標準コマンドを本文に含める。 |
| [audits/](audits/) | ある時点のコード、テスト、または文書を対象にした監査報告と、学習実験や採否判断の原因を切り分けた調査報告。保存棋譜、対局記録、教師データ、または重みから、ある時点のminaseの挙動を調べた診断もここに置く。ファイル名に監査日または調査日を含める。 | 冒頭に基準コミットと範囲を明記する。原因の調査報告では、観測事実、原因仮説、未検証事項、および再現資料を区別する。報告は監査後に更新せず、修正は設計書として起案する。 |
| [research/](research/) | 他エンジンのソースコード、論文、および公開の記録を調べた先行研究の調査メモ。設計書とADRが方式の根拠として参照し、[research/README.md](research/README.md) を索引とする。通信プロトコル（USI、CECP）と外部エンジンの調査は [research/protocols/](research/protocols/) にまとめ、[research/protocols/README.md](research/protocols/README.md) を索引とする。 | 結論を先に書き、一次資料へリンクする。作成後は移動せず、minaseに関する記述が古くなったら冒頭に記述の時点とその後の決定を書き足す。 |
| [proposals/](proposals/) | minaseの方式についての提案と、その検討の議論。調査メモや診断を根拠に、何を試すかを利用者が選ぶための候補と試す順序を示す。選んだ候補をどう試して採否を決めるかは設計書が定める。[proposals/README.md](proposals/README.md) を索引とする。 | proposals/README.md に従う。最初の節「候補の扱い」の表に、候補ごとに未決、設計書へ、不採用、取り下げのいずれかを書き、それより後の本文には採否と進捗を書かない。未決の候補がなくなった提案は、冒頭に決着を書いて凍結し、[proposals/archived/](proposals/archived/) へ移す。 |

分類に迷う文書は、次の順で判定し、最初に当てはまったものとする。

1. 将来の作業に適用できる1文の規則を持つなら、教訓である。
2. 現行の実装が従う方式の選択とその理由なら、ADRである。
3. ある時点のminase自身のコード、棋譜、データ、または文書を調べた報告で、以後は凍結するなら、監査報告である。
4. minaseの方式の候補を示して採否を待つなら、提案である。
5. 他エンジン、論文、または公開の記録で確かめた外部の事実として、設計の根拠に参照され続けるなら、調査メモである。

新しく書くときは、外部の事実を調査メモに、minaseへの当てはめを提案か設計書に分けて書く。
すでに両方を含んでいる既存の文書は、本文の大半が当たる側に振り分ける。
測定の結果は、設計書や調査メモの本文に書かず、測定記録へ置いてリンクする。

# 調整機の出品はvast.aiの検証済みを求めず、条件による自動の選択では実メモリの下限を必須にする

## ステータス

承認済み。決定日は2026年10月22日。

## コンテキスト

SPSAは、vast.aiで借りる物理コアの多い計算機（以下、調整機）で実行し、出品はアーキテクチャ、スレッド数、および貸出期限で絞る（[出品と同時対局数のADR](run-one-game-per-physical-core-with-the-default-hash-and-filter-rented-offers-by-architecture-threads-and-duration.md)）。
同じADRにより、同時対局数は物理コア数とメモリの両方から決まり、メモリの少ない機械では同時対局数が下がる。
[vast.aiでの教師生成](../plans/vast-selfplay.md)の選定条件は、vast.aiの検証済み（`verified`）であることも求める。
`vastai search offers`は、既定では検証済みの出品だけを返す。

[aspiration windowsの形](../plans/archived/aspiration-window-forms.md)のセッションでは、`launch.py`の条件による自動の選択がメモリを条件に含めていなかったので、実メモリが260,000 MB以上の出品だけを手で照会して借りた。

## 決定

調整機の出品には、vast.aiの検証済みであることを求めず、照会に`verified=any`を明示する。
`launch.py`の条件による自動の選択では、実メモリの下限`--min-cpu-ram`を必須の引数とする。

## 検討した代案

検証済みの出品だけを借りる案は、SPSAが機密の情報を扱わないので、2026年10月22日にエンジンの開発者が退けた。
自動の選択でメモリを条件にしない案は、メモリの少ない安い出品が最安として選ばれると同時対局数が下がり、所要時間と費用がかえって増えるので採らなかった。
メモリの下限に固定の値を置く案は、1局あたりの最大常駐メモリが探索の形の変更で増えるので採らず、セッションごとに`game_rss_bytes`から求めた値を指定する。

## 結果

検証されていない出品は、表示と実際の割り当てが違うことがある。
2026年10月22日には、検証されていないEPYC 9B45の出品で、コンテナに46 CPUぶんしか割り当てられない機械と、SSHに接続できない機械に当たり、どちらも本番の前に削除した（[統括計画](../plans/search-forms.md)の状態）。
出品IDを指定する`--offer`の形にはメモリの条件がないので、手で選ぶときは`cpu_ram`を確かめる。
指定の目安は[SPSAの手引き](../guides/spsa.md)の第8節にある。

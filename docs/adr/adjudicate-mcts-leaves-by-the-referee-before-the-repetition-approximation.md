# MCTSは新しい節点を審判層の裁定で終局させてから反復の近似を適用し、引き分けの勝率を由来を問わず同じ値にする

## ステータス

承認済み。決定日は2026年10月28日。

## コンテキスト

[MCTSの反復の扱いを定めた決定](archive/score-repetition-in-mcts-by-the-alpha-beta-rules.md)は、探索木の中の反復をαβ探索と同じ規則で近似し、引き分けの値をR1の反復に限ってcpから勝率へ換算すると定めていた。
この決定の下で、探索木の駆動部`crates/minase/src/search/mcts/driver.rs`は、新しい節点について相手の最後の王駒の捕獲と合法手なしだけを終局とし、審判層`crates/minase-core/src/game/adjudication/`が裁定する詰み（RULES.md第21条第2項）、駒枯れ（第22条）、裸玉（E3）、および正確なR1の4回目の出現を判定していなかった。
2026年10月28日の[監査](../audits/alphazero-rl-readiness-2026-10-28.md)は、駒枯れの勝ちと引き分け、および詰みの3例で、審判層が終局とする局面を探索木がネットに評価させ、確定した結果と異なるQを返すことを再現した。
自己対局の価値の教師は選んだ手のQであり、方策の目標も同じ探索木から作るので、この不一致は終局の近くの教師を歪め、1手32回の探索では規則上の詰みを見逃す。
αβ探索は[探索木の中では駒枯れ、裸玉、および詰みの裁定を近似する決定](approximate-exhaustion-and-mate-inside-search-tree.md)に従い、詰みは1手深く読んで王駒の捕獲として得るが、探索回数の少ないMCTSではその代用が働かない。
[局面と合法手生成器を対局の履歴から独立させる決定](keep-game-history-out-of-position-and-movegen.md)は、探索は`Game`を経由しないと記しており、本決定はMCTSに限ってその例外を設ける。
AlphaZeroは探索中の終局と得点をゲームの規則で決め（Silver et al., arXiv:1712.01815、補足資料Domain Knowledge）、lc0は葉の終局をネットの評価より先に確定する（`src/search/classic/search.cc`、コミット1227b4c）。
Gumbel dlshogiは、手数の上限に達した対局を除くだけでは入玉宣言の退化が止まらず、3手詰めの判定を自己対局に入れて解消した（山岡忠夫「Gumbel dlshogiを作る」[その8](https://tadaoyamaoka.hatenablog.com/entry/2025/07/19/085509)、[その9](https://tadaoyamaoka.hatenablog.com/entry/2025/07/19/140913)）。
エンジンの開発者は、[監査対応の設計書](../plans/alphazero-audit-remediation.md)でこの決定を下した。

## 決定

`SearchSnapshot`は根の`Game`の複製を持ち、MCTSの駆動部は新しい節点を作るとき、根の`Game`の複製に経路の着手を`Game::play`で順に適用して審判層の裁定を得る。
子の辺はその経路の`Game::legal_moves`（R2とR3の禁止手を除いた合法手）から作り、選択済みの辺の再生で`Game::play`がエラーを返した場合、または経路の末尾より前に終局した場合は、探索の状態の不整合として元のエラーを報告して探索を止める。
末尾の着手で終局した場合は、着手の後の手番側が勝者かどうかで子の勝ち負けを決め、距離を0とする。
王駒の捕獲、詰み、合法手なし、駒枯れ、および裸玉の勝敗は詰みの帯、正確なR1の裁定による勝敗は反復の帯で表し、引き分けは引き分けの節点とする。
終局でなければ、探索木の既存の反復の近似（直近の出現からの1周による打ち切り）を適用し、深さの上限の判定はその後に行う。
勝敗が確定した節点と引き分けの節点は、評価値の帯の区分とは別に、反復の近似への依存を示す印を持つ。
この印は近似による打ち切りでだけ立て、自己対局の投了の抑止に使う。
引き分けの勝率は、自己対局では0.5、対局ではR1の引き分けと同じ`DrawValue`を由来を問わずに使い、相手側の手番の節点では1から引く。
木の再利用は、既存の条件に加えて、古い根の`Game`を実際に指された手で進めた状態（局面、規則、反復の履歴、攻撃連続数、連続可逆手数、駒枯れの猶予、手数、終局の有無、および履歴のキーの列）が新しい根の`Game`と一致する場合に限る。
この比較はminase-coreが提供する。
MCTSの対局エンジンは引き続き成り規則P0（P5なし）だけを受け付け、終局規則E1、E2、およびE3は審判層の裁定に従う。
αβ探索の入力、根の候補手の選別、およびαβ探索の内部の裁定は変えない。

## 検討した代案

審判層の部品（詰みの判定、駒枯れの判定）を個別に公開し、裁定の順序を探索側にも書く案は採らなかった。
将来の規則の変更で審判層と探索が再びずれる余地が残るからである。

詰みの回避手の判定（第21条第3項b〜d）に探索木の反復の近似を使う案は採らなかった。
実際には継続する反復を回避手から除いて詰みと誤る経路と、規則上の詰みを継続と誤る経路の両方が生じ、近似に依存した判定であることを終局の確定へ伝えられないからである。

合法性の検査を省いて審判の状態だけを進める軽いAPIを測定の前に足す案は採らなかった。
`Game`と`Game::play`は公開済みであり、経路上で裁定を繰り返す費用は軽いAPIでも残るからである。
軽いAPIは、本番の駆動部での測定とGPUの試走で1サイクルの時間が予算に収まらず、再生の費用がその主因だと確かめられた場合に限り検討する。

駒枯れの引き分けだけを0.5に固定する案は採らなかった。
引き分けという同じ結果の選好を終局の理由で変える必然性がないからである。

## 結果

探索木の終局は審判層と一致し、終局の葉にネットの評価を要求しない。
経路の再生は節点を作るたびに合法性の検査と裁定を繰り返すので、探索木のCPUの費用が増える。
監査の補助測定では、1本の乱数対局の経路の再生に1手で約6 µs、8手で37〜53 µsかかった。
本番の駆動部を一様評価器で駆動した109局面の測定では、根の探索時間の中央値が、Gumbelの32回の探索で0.094 msから0.555 msへ、PUCTの800回の探索で2.09 msから19.1 msへ増え、完了したシミュレーション1回あたりでは約3 µsから約40 µsになった（[測定記録](../measurements/alphazero-audit-remediation/alphazero-audit-remediation-driver-cost.md)）。
自己対局の生成はGPUの推論が律速である見込みのまま変わらないが、GPUの推論を含む1サイクルの時間は[強化学習の実行](../plans/alphazero-rl.md)の試走で確かめる。
MCTSは[局面と合法手生成器を対局の履歴から独立させる決定](keep-game-history-out-of-position-and-movegen.md)が定める「探索は`Game`を経由しない」という原則の例外になるが、`Position`と`MoveGenerator`が履歴を持たないという決定自体は変わらない。
同じ局面に至る別の手順を合流させる探索グラフ（DAG）を検討するときは、経路の再生で状態を求める前提を見直す必要がある。
実装は`crates/minase/src/search/snapshot.rs`と`crates/minase/src/search/mcts/driver.rs`にある。

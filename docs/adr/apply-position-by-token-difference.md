# `position`の着手列は、前回受理した列との差分だけを適用する

## ステータス

承認済み。決定日は2026年9月21日。

## コンテキスト

USIのGUIとLishogi-Botは、毎手、開始局面からの全着手列を`position`で送る。
全着手列を開始局面から適用し直す処理は、手数に比例して時間がかかる。
[棋力向上段階2](../plans/archived/strength-stage2.md)の反復継続の判断のSTCでは、2,873plyの対局の2,864手目に基準側が時間切れになった（[測定記録](../measurements/strength-stage2-iteration-stc.md)）。
原因は、全着手の再生の固定費が2,860手で約65 msに達し、予算式の安全余裕30 msを超えたことだった。
段階2は、2026年9月4日に、接頭辞が一致する`position`の差分適用を採用した。
[USI先読み](../plans/archived/ponder.md)では、先読みが外れた後の`position`がこの条件に当たらない問題が生じた。
先読みが外れると、予想手Yを含む前回の`… X Y`に続いて、相手が実際に指した手Zを含む`… X Z`が届き、新しい列が前回の列の延長にならないからである。
そこで2026年9月21日に、末尾の1手だけが異なる列の扱いを加えた。

## 決定

開始局面が前回受理した`position`と同じで、新しい着手列が前回の列を接頭辞に持つ場合は、追加された着手だけを現局へ適用する。
前回の列と末尾の1手だけが異なる場合は、最後の1手を適用する前の対局状態から、その1手だけを適用する。
どちらにも当たらない場合は開始局面から全着手列を適用し、条件の詳細は`UsiProtocol::handle_position`と`Engine::before_last_move`のdocコメントにある。

## 検討した代案

予算式の安全余裕を広げる案は、予算そのものを変えて棋力に影響するので採らなかった。

## 結果

差分の適用も全着手列の適用と同じく原子的であり、不合法な着手を含む差分は対局状態を変えない。
受理後の局面、手数、および終局状態は、全着手列を適用した場合と一致する。
末尾の1手の置き換えは先読みに限らない一般の規則として働く。
探索の挙動は変わらないので、この変更だけの棋力測定は行わず、段階2と先読みの採否測定に含めて判定した。
以後、1手あたりの固定費は対局の手数に依存しない大きさに保つ（[手数に比例する固定費は超長手数の対局で時間切れを起こす](../lessons/per-move-overhead-grows-with-game-length.md)）。

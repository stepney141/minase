# 静的評価を置換表に保存しない

## ステータス

置き換え済み。決定日は2026年9月12日。[置換表のエントリを16バイトの2語の原子値に保ち、補正前の静的評価と探索値なしの記録を持たせる](../store-static-evals-and-eval-only-records-in-two-word-tt-entries.md)によって置き換えられた。

## コンテキスト

チェスのエンジンには、ノードの静的評価を置換表のエントリに保存し、同じ局面に再び来たときに評価の計算を省くものがある。
[棋力向上段階6](../../plans/archived/strength-stage6.md)の時点の評価関数は、駒と升ごとの重みを持つ学習PSTであり、差分更新によりplyごとの累算値から定数時間の補間で評価が求まった。
[評価の費用のbench](../../measurements/strength-stage6/strength-stage6-eval-cost-bench.md)では、通常探索と静止探索の各ノードで評価を10回余分に計算すると処理時間が2.40%増えたので、評価1回の費用はノードの処理時間の0.24%だった。
置換表に保存しても省けるのは、置換表に当たったノードの評価1回分にすぎない。
段階計画は、探索の挙動を変えない高速化を、NPSの改善が3%以上見込める場合に限って実装する。

## 決定

静的評価を置換表に保存しない。
エントリの16バイト2語は、検証キー、探索値、深さ、バウンド、記録手、および世代だけを持つ。

## 検討した代案

静的評価をエントリに保存する案は、上記のとおりNPSの改善の上限が0.24%で事前ゲートの3%に届かないので、実装せずに見送った。

## 結果

エントリの大きさを増やさずに済み、[Lazy SMP](../../plans/archived/lazy-smp.md)が定めた原子操作の契約を変えない。
見送りの根拠は、評価関数がPSTだった時期の評価費用である。
2026年10月12日に既定の評価関数は[NNUE](../../plans/archived/nnue-replacement.md)に置き換わり、この測定の値が現行の評価関数に当てはまるかは確かめていない。
したがって、この案を再び提案する場合は、現行の評価関数で評価1回の費用を測り直し、事前ゲートを満たすかを確かめる必要がある。

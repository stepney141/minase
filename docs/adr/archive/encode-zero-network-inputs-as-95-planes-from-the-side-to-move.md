# AlphaZero型探索のネットの入力は、手番側から見た盤の95面とし、履歴、利き、および左右反転による水増しを入れない

## ステータス

承認済み。決定日は2026年10月27日。

## コンテキスト

AlphaZero型探索のモンテカルロ木探索（MCTS）が使うニューラルネットワーク（以下ネット）は、局面を受け取り、各合法手の有望さの確率分布（方策）と手番側の勝率（価値）を返す。
入力の定義は、対局用のMCTS、自己対局生成器、およびPythonの学習器の3者が共有し、学習したネットはその定義に依存する。
AlphaZeroとlc0は過去の数局面を入力に含めるが、将棋のdlshogiは履歴の面を持たずに強さを得ている。
dlshogiは駒の利きと利き数の面が学習の短縮に有効だったとも報告している。
規則セット`engine-default`（L0＋P0＋R1＋E0）では成り権の保留が生じないので、次の合法手は駒の配置、手番、および直前の着手で獅子以外の駒が相手獅子を取った升（先獅子の判定の起点、RULES.md第15条）だけで決まる。
中将棋の初期配置は点対称だが、王将と醉象の位置が左右で異なるので左右対称ではない（RULES.md第5条）。
決定の経緯は[ネットの入出力と推論の設計書](../plans/archived/alphazero-network.md)にある。

## 決定

入力は、手番側から見た12×12の盤の95面とする。
94面は、手番側と相手側のそれぞれについて、NNUEとPSTの特徴が使う47種類の駒の状態（`eval::features::piece_state`）を1面ずつ割り当てたものであり、残る1面は、直前の着手で獅子以外の駒が相手獅子を取った升（`Position::lion_capture_square`）を示す面とする。
後手番では盤を180度回転してから符号化し、ネットが常に手番側から見た盤を見るようにする。
成り権の保留がある局面は符号化せず、エラーにする。
過去の局面の履歴、反復の回数、および利きの面は入れず、左右反転によるデータの水増しもしない。

## 検討した代案

履歴の面を入れる案は採らなかった。
履歴を含めると同じ局面でも入力が変わるので、NNキャッシュの鍵と学習データの両方に履歴を持たせる必要が生じる。
反復は探索木の側で規則どおりに扱い、ネットには判断させない。

利きと利き数の面を入れる案は、初版では採らなかった。
学習器のPython側で計算するには中将棋の規則の判定をPythonにも実装し直す必要があり、Rust側で計算して学習データに書くと1局面あたり数百バイト増えるからである。
この面は、初版の学習が動いた後に、同じ条件のネット同士のGSPRTで効果を測る候補として残す。

後手番で段だけを反転する案は採らなかった。
NNUEの特徴は段だけを反転し、左右の対称性を線形の重みの鏡映対の共有で扱うが、畳み込みのネットにはその仕組みがない。
初期配置が点対称なので、180度回転すれば後手番の盤は先手番の盤と同じ並びに見える。

左右反転でデータを水増しする案は、初期配置が左右対称でないので採らなかった。

## 結果

入力は局面だけから決まるので、NNキャッシュの鍵は、αβ探索の置換表と同じく`Position::zobrist`と`Position::rights_zobrist`の排他的論理和で足りる。
P1、P2、またはP5の規則セットで学習するには、保留の升を示す面を足して入力の定義を改める必要がある。
`eval::features::piece_state`の番号を変えると入力が変わり、学習済みのネットを使えなくなる。
この変更は、Rustが書き出してコミットした固定局面集`tools/train/zero/fixtures/nn-positions.jsonl`との一致を確かめるテストが検出する。
配置の詳細は`crates/minase/src/nn/encoding.rs`のdocコメントにある。

# 学習する評価関数の出力Kを初期値の重みファイルの値に固定し、データから推定し直さない

## ステータス

置き換え済み。決定日は2026年9月14日。[勝率尺度を重みファイルの1定数とし、教師の勝率尺度は較正コマンドで求めて学習の引数で与える](../hold-cp-per-logit-in-the-weight-header-and-pass-the-teacher-scale-explicitly.md)によって置き換えられた。

## コンテキスト

学習では、評価値を出力Kで割ってシグモイドに通した勝率を教師値へ近づける。
教師値の側では、教師の探索値を教師用Kで割って勝率へ換算する。
教師用Kは、探索値と対局結果の対応を表す尺度であり、教師を生成した評価関数ごとに異なる。
出力Kは学習時の換算尺度であって実行時には使われないが、学習した重みの目盛り、つまり評価値の大きさを決める。
[評価関数の世代反復](../../plans/archived/evaluation-gen1.md)までは、出力Kを学習ごとに混合データから推定し直していた。
世代1の再学習では出力Kが大きくなって評価値の目盛りが広がり、[時間制御測定](../../measurements/pst-gen1-tc.md)の得点率90.9%に、知識の増加だけでなく目盛りの変化が枝刈りに与えた影響が含まれた可能性がある。
静止探索の余裕値など、評価値の絶対量に依存する探索の係数は、そのときの目盛りに合わせて導かれている。

## 決定

学習器は、学習の初期値として与えた重みファイルのヘッダの出力Kをそのまま使い、データから推定し直さない。
[棋力向上段階7](../../plans/archived/strength-stage7.md)以降の学習は、出力Kを当時の重みファイルの値1072.6529541015625に保っている。
教師用Kは、出力Kと別に、教師の分類ごとに訓練集合から推定する。

## 検討した代案

学習ごとに混合データから出力Kを推定する案は、教師の世代や入力データを足すたびに目盛りが動き、評価関数の効果と目盛りの効果が測定で混ざるので採らなかった。
世代0の重みを相手に出力Kだけを変えた対局で、過去の得点率から目盛りの効果を遡って切り分ける案は、どの採否も変えないうえに数千ペアを要するので行わなかった。

## 結果

出力Kの変更による換算尺度の差は、以後の学習では生じない。
学習で重みそのものの目盛りが動く分は残るので、探索用駒価値との差は学習後の診断で点検する。
NNUEの学習も、基準の重みファイルの出力Kを引き継いで固定する（詳細は`pst::base`と`nnue::train::base`のdocコメントにある）。
教師用Kを推定する単位は、[教師データを来歴ファイルで分類し、MNSDの形式は変えない](classify-teacher-data-by-provenance-files.md)が定める。

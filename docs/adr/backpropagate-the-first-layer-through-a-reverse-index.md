# NNUEの学習器は第1層の勾配をホストで作る逆索引から固定の順で足し、アトミック加算を使わない

## ステータス

承認済み。決定日は2026年10月12日。

## コンテキスト

NNUEの第1層の後退（逆伝播）では、バッチ内の各局面で発火した特徴の行へ、その局面の勾配を足し込む。
逆索引とは、バッチ内の「どの局面のどの視点で、どの特徴が発火したか」の組を、特徴番号ごとにまとめ直した表である。
駒除去差分の補助損失とは、盤上の駒を1枚除いたときの評価の変化が参照と同じ向きになることを求める補助的な損失であり、除去ごとに出力部の内積を計算し直す。
bulletとvariant-nnue-pytorchは第1層の後退をアトミック加算で書き、tataraは逆索引をデバイス上の4段のカーネルで作る（[学習器の速度の調査](../research/nnue-trainer-speed.md)）。
アトミック加算は加算の順序が実行ごとに変わるので、GPUの結果をCPU参照実装と比べるには緩い許容誤差が要り、学習も再現しない。
[Rust製NNUE学習器](../plans/archived/nnue-trainer-rust.md)は、学習を止めて再開しても重みがビット単位で一致することを求めていた。
1スレッドが1行の範囲を直列に走査する最初の実装では、出現回数の多い行を受け持つスレッドの遅れが全体の完了を待たせ、第1層と線形の経路の後退がそれぞれ1更新の47%と26%を占めた（[検査と試走の記録](../measurements/nnue-trainer-rust/nnue-trainer-rust-checks.md)）。

## 決定

第1層と線形の経路の後退は、ホストのワーカースレッドがバッチごとに計数ソートで作る逆索引を使い、行を128要素の区分に分けて区分ごとの部分和を作り、第2のカーネルが行ごとに区分を昇順に足す。
局面方向の縮約はブロックごとの部分和を固定の順で足し、駒除去差分の補助損失の内積はレーンごとの昇順の部分和を距離16、8、4、2、1のワープ内シャッフルで足す固定の木を加算順と定め、前進と出力部と補助損失の内積ではCPU参照実装も同じ順で足す。
カーネルの内側のループは単精度で計算し、倍精度は局面方向で大きな項が相殺する和に限る（詳細は`nnue::data`の逆索引と`nnue::reference`のdocコメントにある）。

## 検討した代案

アトミック加算による後退は、加算順が変わって決定性を失うので採らなかった。
tataraのように逆索引をデバイス上で作る案は、後退のカーネルを1本で済ませて決定性を保つことを優先して採らなかった。
CPU参照実装の素直な昇順の加算をGPUに真似させる案は、シャッフルが直列になって補助損失のカーネルが遅くなったので採らなかった（[教訓](../lessons/define-reduction-order-on-the-gpu.md)）。
内側のループを倍精度で書く案は、GeForceの倍精度の演算速度が単精度の1/64なので採らなかった（[教訓](../lessons/no-f64-in-gpu-kernel-inner-loops.md)）。

## 結果

同じ入力に対してGPUのカーネルは同じ結果を返し、連続して走らせた学習とエポックの境界で止めて再開した学習は、重みと最適化器の状態がビット単位で一致する。
加算順が異なる後退の縮約も含め、GPUとCPU参照実装の一致は`|GPU−CPU| ≤ 10⁻⁶ + 10⁻⁵·|CPU|`で判定し、同じ入力で2回実行した結果にはビット単位の一致を求める。
ホストのワーカーが逆索引を作ってバッチを供給する時間、または転送の時間がGPUの計算時間を上回ることが分かった場合は、逆索引の構築をデバイス側へ移すことを再検討する。

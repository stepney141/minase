# AlphaZero型探索の自己対局生成器は、多数の局の探索木から葉を1つずつ集めて推論をまとめ、各局は1手ごとに新しい探索木で探索する

## ステータス

承認済み。決定日は2026年11月15日。
[Sequential Halvingが最後に残した手を指すADR](archive/batch-zero-self-play-leaves-across-many-games.md)を置き換える。

## コンテキスト

置き換えたADRは、生成器がスレッドごとに推論器を1つと複数の局を持ち、各局の葉を1回の推論にまとめると定めた。
同じADRは、各局がSequential Halvingの最後に残した手を指し、温度つきの手の抽選とディリクレ雑音を使わないとも定めた。
Gumbel AlphaZeroの探索は仮想損失を使わず、1つの探索木で評価を待つ葉を1つまでとするので、1局の探索から一度に推論へ出せる局面は1つしかない。
dlshogiの自己対局生成器は、多数の局を1つのプロセスで同時に進め、各局の葉をまとめて1回の推論にかける構成をとる（DeepLearningShogiの`selfplay/self_play.cpp`、コミット79df19e）。
2026年11月15日に、最初の30手を根の訪問回数に比例して抽選すると決まった（[序盤の抽選のADR](start-zero-self-play-from-the-initial-position-and-sample-the-first-30-moves-by-root-visit-counts.md)）。
これにより、置き換えたADRから指す手の選び方だけが変わり、推論のまとめ方と探索木の扱いは変わらない。

## 決定

生成器は、スレッドごとに推論器（ONNX Runtimeのセッション）を1つと複数の局を持つ。
各スレッドは、各局を評価待ちになるまで進め、評価を待つ局の葉を1回の推論にまとめる処理をくり返す。
スレッドの数とスレッドごとの局の数は起動引数で与え、推論器の最大バッチはスレッドごとの局の数とする。
TensorRTのエンジンのキャッシュを複数のスレッドが同時に作り始めないように、推論器はスレッドを起動する前に順に作る。
各局は、1手ごとに新しい探索木でGumbelの探索を行い、根の勝敗が確定したら、探索回数が残っていても探索を終える。
指す手は、序盤の抽選のADRに従って選ぶ。
ディリクレ雑音は使わない。

## 検討した代案

1局の内部で仮想損失を使って葉をまとめる案は、置き換えたADRと同じ理由で採らなかった。
Gumbelの探索で1つの木から複数の葉を同時に選ぶと、Sequential Halvingの各回の選択が、評価をまだ逆伝播していない訪問を含めて行われることになり、参照実装として照合したDeepMindのライブラリmctxの探索と一致しなくなる。

前の手の探索木の部分木を次の手へ持ち越す案は、置き換えたADRと同じ理由で採らなかった。
Sequential Halvingは根の訪問回数の和で各回の選択対象を決めるので、前の手の訪問が残った木では探索回数の配分が崩れ、mctxの探索も手ごとに新しい木を作る。

ディリクレ雑音は採らなかった。
根の候補手の抽出に足すGumbel乱数が、すでに手の選択に乱択性を与えているからである。

## 結果

1回の推論のバッチの大きさは、そのスレッドで評価を待つ局の数になり、サイクルの終わりに残りの局が減るとバッチも小さくなる。
1局の探索木は1手ごとに捨てるので、木の容量は1局あたり16 MiBの上限で足りる。
1手32回の探索が使う量は見積もりで約100 KBであり、上限に達したら設定の誤りとしてエラーで止める。
実装は`crates/minase/src/bin/minase/zero_selfplay/`にある。

# 捕獲履歴の寄与を歩兵価値の定数倍に抑え、静止探索の順序にも使う

## ステータス

承認済み。決定日は2026年10月10日。

## コンテキスト

捕獲履歴（capture history）は、動かす駒、到達升、および取られる駒種ごとに捕獲手の成績を学習し、捕獲手の順序に使う表である。
MVV-LVA順は駒の価値だけで順序を決め、その局面でその捕獲が実際に良かったかを考慮しない。
[棋力向上段階12](../plans/strength-stage12.md)では、捕獲手がβ打ち切りを起こしたときにその手へ加点し、先に読んだ捕獲手を減点する表を通常探索に加えた。
[bench](../measurements/strength-stage12-capture-history-bench.md)では深さ6のノード数が4.41%減り、NPSは1.93%下がったが、STCは750有効ペア、得点率47.6%の`H0`だった（[測定記録](../measurements/strength-stage12-capture-history-stc.md)）。
[不採用だった探索部の改良の再調整](../plans/search-revival-spsa.md)は、上限と尺度をSPSAで調整し直して採用した（[採用のADR](adopt-revived-search-items-as-a-bundle.md)）。
[手の順序付けの改善](../plans/move-ordering.md)は、静かな手がβ打ち切りを起こしたときにも探索済みの捕獲手を減点する変更と、静止探索の群内の順序に表を使う変更を加えた。
[診断](../measurements/move-ordering-diag.md)では、前者は順序を変える段が16.47%あったが、βカットした捕獲手を後ろへ動かす件数が前へ動かす件数の約2倍だった。
後者は群の先頭を20.48%で変えた。
両者を含む7候補の構成は、STCとLTCの`H1`で一括して採用した（[STC](../measurements/move-ordering-all-stc.md)、[LTC](../measurements/move-ordering-all-ltc.md)）。
静止探索の群内の順序、静かな手の同点破り、およびhistory malusの3候補を外した構成は、全7候補の構成との対称仮説の直接対局で、得点率48.2%の`H0`だった（[測定記録](../measurements/move-ordering-no358-vs-all-stc.md)）。
この直接対局の記録は、設計書の本文からはリンクされていない。

## 決定

通常探索の捕獲手は、取る駒の価値の合計に捕獲履歴の換算値を加えた値の降順、次に動かす駒の価値の昇順で並べる。
換算値の絶対値は、歩兵価値に尺度の百分率を掛けた値以下に収める。
値は上限に近づくほど更新量が小さくなる重力式で更新し、表全体を半分にする方式は使わない。
β打ち切りを起こした手が捕獲手でも静かな手でも、同じノードで先に探索した捕獲手を減点する。
静止探索では、取る駒の価値の群の構造を保ち、群の中を捕獲履歴の生の値の降順、動かす駒の価値の昇順、生成順で並べる。

## 検討した代案

換算値に上限を設けない案は、学習値が取る駒の価値の差の大きい手の順序を覆し得るので採らなかった。
減点を持つ表で上限を超えたときに全体を半分にする方式は、重力式なら値が常に上限の範囲に収まるので採らなかった。
静止探索の順序を変えない案は、上記の直接対局で3候補を外した構成が負けたので採らなかった。

## 結果

上限、尺度、および持ち越しの減衰率は`crates/minase/src/search/alphabeta/params.rs`にある。
直接対局は3候補をまとめて外したので、静止探索の群内の順序だけの寄与は分からない。
静かな手の打ち切りでの減点は、診断では不利な兆候を示したまま一括で採用したので、単独で外す提案には非劣性の測定が要る。

# 教師データを来歴ファイルで分類し、MNSDの形式は変えない

## ステータス

承認済み。決定日は2026年9月23日。

## コンテキスト

教師データのMNSDファイルは、ヘッダに規則セット、生成コミット、教師の重みの検査和、ノード上限、およびシードを持つ。
[評価関数の世代反復](../plans/archived/evaluation-gen1.md)以降の学習器は、教師用Kを推定する単位を重みの検査和だけで決め、検証集合への割り当てをシードと対局番号から決めていた。
[棋力向上段階9](../plans/archived/strength-stage9.md)は、教師データに対する3種類の追加を試すことにした。
保存済みの局面を深く探索し直して探索値を置き換える付け直し、lishogiの人間どうしの棋譜の局面、および棋譜の途中局面から始める自己対局である。
付け直した探索値は同じ重みでも探索の条件が異なり、棋譜の局面には現行の探索値ではなく対局結果だけを教師にする必要があった。
同じ棋譜に由来する局面と自己対局は互いに相関するので、訓練集合と検証集合の分割で同じ側へ入れる必要もあった。
これらは、重みの検査和とシードだけでは区別できない。

## 決定

各MNSDファイルに必須の来歴ファイル`<MNSD>.provenance.json`を付け、教師の探索条件、対局結果の由来、開始局面の由来、混合比λ、および棋譜との対応を記す。
学習器は、生成コミット、重みの検査和、ノード数、規則セット、探索条件、対局結果の由来、および開始局面の由来の組を教師の分類とし、教師用Kを分類ごとに訓練集合から推定し、λを分類ごとに適用する。
付け直した探索値は元のMNSDを書き換えずにMNRS形式の付け直しファイルへ書き、学習器が読み込み時に差し替えてから生成時の除外を適用し直す（詳細は`training::provenance`と`training::rescore`のdocコメントにある）。

## 検討した代案

MNSDの形式を改めて来歴の欄を足す案は、段階9が教師データの形式を変えない範囲で計画されたので採らなかった。
付け直しで元のMNSDの探索値を上書きする案は、局面、対局結果、対局番号、および検証集合への割り当てが保たれる保証を失うので採らなかった。
来歴ファイルのない既存のファイルについて来歴を推測で補う案は、教師値と検証分割を明示されないまま変え得るので採らず、来歴は`minase data selfplay provenance`で明示的に与える。

## 結果

乱数開始の自己対局の検証集合への割り当てはシードと対局番号のハッシュで、棋譜に由来するデータでは棋譜IDのハッシュで決まり、同じ棋譜に由来する局面は同じ側へ入る。
λが0の分類では教師用Kを推定せず、仮の値でも埋めない。
来歴ファイルや付け直しファイルだけを差し替えると教師値と検証の分割が変わるので、学習の記録はそれらの検査和を固定して照合する。
後の[先読み教師](use-lookahead-teacher-values.md)と混合比の上書きも、分類の属性として扱われる。
形式と検査の細目は、`crates/minase/src/training/provenance.rs`の`Provenance`と、`crates/minase-trainer/src/data/mnsd.rs`の`InputProvenance`と`Dataset::open`のdocコメントにある。

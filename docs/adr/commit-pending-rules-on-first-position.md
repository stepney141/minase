# 次局の規則を、対局開始前に受理した最初の局面設定で確定する

## ステータス

承認済み。決定日は2026年8月10日。

## コンテキスト

minaseは、規則セットを起動引数`--rules`のほか、USIの`setoption name RuleSet`とCECPの`option RuleSet=...`でも受け取る。
受け取った規則を直ちに現局へ適用すると、1つの対局の局面と反復の履歴を、途中から別の規則で裁定することになる。
そこで、受け取った規則を次の対局の開始時に確定する仕組みが必要になった。
USIの原典では、GUIが新しい対局の開始を`usinewgame`で知らせる。
しかし[プロトコル層](../plans/protocol-layer.md)の調査では、lishogiとエンジンを仲介するLishogi-Botが`usinewgame`を送らず、対局ごとに`setoption`、`position`、`go`の順で送ることをソースで確かめた（[USI原典仕様とlishogi系拡張の調査](../research/protocols/usi-lishogi.md)）。

## 決定

受け取った規則は受信時に検証し、次局用の規則として保持する。
次局用の規則は、USIの`usinewgame`とCECPの`new`に加えて、対局開始前の状態で最初に受理した局面設定の時点で、現局の規則として確定する。
詳細は`Engine`と`EngineCommand::SetRules`のdocコメントにある。

## 検討した代案

`usinewgame`だけを対局の開始とする案は、Lishogi-Bot経由の対局で規則が反映されないので採らなかった。
受け取った規則を直ちに現局へ適用する案は、対局の途中で裁定の規則が変わるので採らなかった。
規則の検証を対局の開始時まで遅らせる案は、誤りの通知が設定の送信から離れた時点になるので採らなかった。

## 結果

対局中に届いた局面設定は、Lishogi-Botが毎手送る全着手列の再送として扱い、現局の規則で局面を作り直す。
次局用の規則は、対局が終わって次の対局が始まるまで適用されない。
エンジンは起動時から常に検証済みの規則を持つので、規則の決まっていない対局は存在しない。

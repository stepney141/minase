# AlphaZero型探索のネットのTensorRTのFP16の出力は、合法手の確率と価値をどちらも許容誤差5×10⁻²で照合する

## ステータス

承認済み。決定日は2026年11月16日。
[合法手の確率を1×10⁻²、価値を5×10⁻²で照合するADR](archive/compare-fp16-zero-network-values-within-five-hundredths.md)を置き換える。

## コンテキスト

学習したネットを推論に使う前に、PyTorchの出力を基準として、ONNX RuntimeのCPUとTensorRTのFP16の出力を固定局面集の288局面で照合する（[ネットの出力の照合の手引き](../guides/alphazero-network-check.md)）。
照合は、ONNXへの書き出しで出力の並びがずれた場合や、minaseが別の着手のlogitを読む場合、価値を読み違える場合を検出するために行う。
FP16の合法手の確率（各局面の合法手のlogitをsoftmaxで正規化した値）の許容誤差1×10⁻²は、1回目の強化学習で使った10ブロック128チャネルのネットで決めた値である。
そのネットを1サイクル学習した後のFP16の確率の差の最大は2.8×10⁻³であり、各合法手のlogitを合法手の列で隣にある着手のものと読み違えた場合の差は、局面ごとの中央値で3.5×10⁻²、全体の最大で0.21であった。
2回目の強化学習は20ブロック256チャネルのネットで始めたが（[2回目の実行の設計書](../plans/alphazero-rl-2.md)）、ランダムに初期化したネットはlogitの散らばりが小さいので、許容誤差を確かめる材料にならない（[教訓](../lessons/judge-low-precision-inference-on-trained-outputs.md)）。
[準備の設計書](../plans/archived/alphazero-rl-2-prep.md)では、大きいネットのために許容誤差を広げる案は、その時点では根拠がないとして採らなかった。

2026年11月16日、2回目の強化学習の系列`cycles-rl2-az`のサイクル1で学習したネットを、学習に使ったvast.aiの機械（RTX 4090）で、バッチの大きさ1、7、256の3組ずつ照合した。
ONNX RuntimeのCPUの3組は、FP16の1目盛りを除いたlogitの差と価値の差が許容誤差1×10⁻⁴に収まって合格した。参考に求めた合法手の確率の差の最大は6.5×10⁻⁴、価値の差の最大は4.5×10⁻⁷であった。
一方、TensorRTのFP16における合法手の確率の差は、最大がバッチの大きさ1で0.0121、7で0.0044、256で0.0123であり、3組のうち2組が1×10⁻²を超えた。
FP16の価値の差の最大は0.0041であった。
各局面におけるFP16の確率の差の最大は、288局面の中央値が1.6×10⁻³、99パーセンタイルが7〜8×10⁻³であり、1×10⁻²を超えたのは、バッチの大きさ1で1局面、256で2局面だけであった。
1×10⁻²を超えた局面の合法手のlogitの最大は14〜15であった。
同じネットで各合法手のlogitを隣の着手のものと読み違えた場合の確率の差は、局面ごとの最大値が最小0.0173、中央値0.052であり、全体の最大は0.29であった。
固定局面集での層ごとの出力の絶対値の最大は97.0（方策ヘッドの最初の畳み込み）で、FP16の上限65,504から遠かった。
0でない出力のうちFP16の最小の正規数（約6.1×10⁻⁵）より小さいものの割合も、どの層でも4.4×10⁻⁴以下であった。
飽和も桁落ちも起きておらず、差は、10ブロックのネットの約2倍にあたる約40層の畳み込みを通したFP16の丸めの累積とみられる。

## 決定

TensorRTのFP16の照合では、各局面の合法手の確率の差と価値の差を、どちらも許容誤差5×10⁻²と比べる（2026年11月16日の利用者の決定）。
ONNX RuntimeのCPUの照合では、従来どおり合法手のlogitの差と価値の差を、どちらも許容誤差1×10⁻⁴と比べる。
サイクル1のネットはこの決定より前の許容誤差で不合格としたので、生成と学習の出力をそのまま残し、照合だけを新しい許容誤差でやり直す。

## 検討した代案

確率の許容誤差を2×10⁻²にする案は採らなかった。
観測した差の約1.6倍の余裕しかなく、学習が進んでlogitが大きくなると丸めの差も増えるので、後のサイクルで再び許容誤差を超えるおそれがある。
1回目の学習では、FP16の価値の差の最大が、サイクル1の0.0094からサイクル6の0.0218へ、6サイクルで約2.3倍に増えた（[置き換えたADR](archive/compare-fp16-zero-network-values-within-five-hundredths.md)）。

許容誤差1×10⁻²を保ち、方策ヘッドだけをTensorRTでFP32に固定して推論する案も採らなかった。
この案には、ONNX RuntimeのTensorRT実行プロバイダで層ごとの精度を固定する実装と、生成の速さへの影響の測定が要る。
一方で、読み違えはCPUの照合（許容誤差1×10⁻⁴）で検出でき、FP16で起きうる飽和や桁落ちもこのネットでは見られないので、精度を上げて得るものが小さい。

## 結果

許容誤差の5×10⁻²は、観測した丸めの差の最大0.0123の約4倍であり、読み違えた場合の288局面の差の最大0.29の約6分の1である。
両者の幾何平均は約0.06であり、5×10⁻²はその近くにある。
読み違えの検出は主にCPUの1×10⁻⁴の照合が担い、FP16の照合は、飽和や桁落ちのような丸めより桁の大きい差を検出する。
FP16の照合だけでは、少数の局面でだけ起きる読み違えを見逃しうるので、CPUの照合は省略しない。
学習が進んで確率か価値の差が5×10⁻²に近づいた場合は、その時点の差の推移と層ごとの値の範囲を調べてから、許容誤差か推論の精度を決め直す。

# AlphaZero型探索のネットのTensorRTのFP16の出力は、合法手の確率を1×10⁻²、価値を5×10⁻²で照合する

## ステータス

承認済み。決定日は2026年10月29日。
[logitではなく合法手の確率と価値で照合するADR](archive/compare-fp16-zero-network-outputs-on-legal-move-probabilities.md)を置き換える。

## コンテキスト

学習したネットを推論に使う前に、PyTorch、ONNX RuntimeのCPU、およびTensorRTのFP16の出力を固定局面集の288局面で照合する（[ネットの出力の照合の手引き](../guides/alphazero-network-check.md)）。
照合は、ONNXへの書き出しで出力の並びがずれた場合や、minaseが別の着手のlogitや価値を読む場合を検出するために行う。
2026年10月28日の決定では、FP16の照合を、合法手の確率の差の許容誤差1×10⁻²と、価値の差の許容誤差2×10⁻²で行うことにした。
価値の許容誤差は、1サイクル分学習したネットの価値の差1.1×10⁻²に余裕を持たせた値であった。

強化学習のサイクルを回すと、FP16の価値の差の最大は、サイクル1から順に0.0094、0.0115、0.0146、0.0152、0.0173、0.0218と増え、サイクル6のネットでバッチの大きさ256の照合が2×10⁻²を超えた（[強化学習の実行の設計書](../plans/alphazero-rl.md)、NASの`cycles.jsonl`）。
同じネットの合法手の確率の差の最大は7.5×10⁻³で、CPUの照合はすべての項目で1×10⁻⁵未満であった。
価値の差が最大の局面は、PyTorchの価値が0.534（logit 0.14）の局面であり、sigmoidの飽和ではなく、価値のlogitに約0.09の誤差が積み重なったものであった。
固定局面集での層ごとの活性化の値の最大は、サイクル1で約22、サイクル6で約26であり、FP16の上限65,504から遠く、飽和も桁落ちも起きていなかった。
差は、約22層を通したFP16の丸めの累積が、学習が進むにつれて大きくなったものとみられる。
固定局面集の288局面のPyTorchの価値は0.10から0.93に分布しており、価値の読み出しがずれた場合や、ほかの局面の価値を読んだ場合の差は、これより1桁大きい。

## 決定

TensorRTのFP16の照合は、各局面の合法手のlogitをsoftmaxで正規化した確率の差を許容誤差1×10⁻²で、価値の差を5×10⁻²で比べる（2026年10月29日の利用者の決定）。
ONNX RuntimeのCPUの照合は、従来どおり合法手のlogitと価値の差をどちらも1×10⁻⁴で比べる。
サイクル6のネットはこの決定より前の許容誤差で不合格としたので、学習し直したネットを新しい許容誤差で照合する。

## 検討した代案

価値の頭部だけをTensorRTでFP32に固定して推論する案は採らなかった。
ONNX RuntimeのTensorRTの実行プロバイダで層ごとの精度を固定する実装と、生成の速さへの影響の測定が要る一方で、価値の差0.02は、MCTSの1手32回の探索で勝率の推定がばらつく幅に比べて小さいからである。

許容誤差を変えずに、学習窓の変更で価値の過学習が減ったネットで照合し直す案は採らなかった。
差の増加は丸めの累積によるもので、過学習が減っても差が縮むとは限らず、照合が通るかどうかが学習の方式に左右されるからである。

## 結果

新しい許容誤差は、価値の読み出しのずれや読み違えのような1桁大きい差を検出しつつ、学習が進んで増える丸めの累積を許す。
学習が進んで価値の差が5×10⁻²に近づいた場合は、その時点の差の推移と層ごとの値の範囲を調べてから、許容誤差か推論の精度を決め直す。

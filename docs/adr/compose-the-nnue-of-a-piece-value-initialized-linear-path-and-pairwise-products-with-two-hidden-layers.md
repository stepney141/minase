# NNUEを、探索用駒価値で初期化した線形の経路と、要素積と2段の隠れ層を持つ非線形の経路で組み立てる

## ステータス

承認済み。決定日は2026年11月4日。

## コンテキスト

[旧ADR](archive/compose-the-nnue-of-a-piece-value-initialized-linear-path-and-a-direct-screlu-head.md)は、NNUEの評価を線形の経路と非線形の経路の和とし、非線形の経路を幅128の第1層の活性化と出力重みの直接内積にすると決めていた。
[別のADR](archive/keep-the-direct-screlu-head-after-the-hidden-layer-candidates-did-not-lower-validation-loss.md)は、幅16の隠れ層の候補を検証損失の比較だけで見送っていた。
その比較で使った先読み教師は翌日に廃止されたので、隠れ層が不要だと確かめられたわけではない。

2026年11月3日に開発者は、将棋より盤も駒も大きい中将棋のネットが将棋のネットより小さいことを問題にし、教師の世代反復の前に、隠れ層を加える前提で構成を見直すと決めた（[設計書](../plans/archived/nnue-architecture-revision.md)）。
世代反復は最大8世代にわたって同じ構成を使うので、後で構成を変えると、それまでの世代のネットをすべて再学習することになる。

作業の途中で次のことが分かった。

- 累算値を16ビットにすると命令数が1.32%減り、隠れ層を除いた幅256の費用は命令数の増加で1.70%だった。差分更新を1回の走査へまとめる変更は速くならなかった（[速度の記録](../measurements/nnue-architecture-revision/nnue-architecture-revision-speed.md)）。
- tataraやStockfishと同じi8の尺度64で隠れ層の重みを持つと、量子化誤差の平均が29.80 cpとなって学習器の検査の上限26.82 cpを超えた。誤差の大半はこの重みの丸めから来ており、尺度を256へ上げると再学習なしで9.45 cpへ下がった（[学習の記録](../measurements/nnue-architecture-revision/nnue-architecture-revision-training.md)）。勝率尺度が約1,072 cpあり、tataraの約290 cpより1刻みが粗くなるからである。
- 第1層の初期値を標準偏差0.05から約0.00494へ下げると、最良の検証損失が0.457598から0.457554へ下がり、固定ノードの対局の結果が−34.2 Eloから−2.6 Eloへ改善した（[学習の記録](../measurements/nnue-architecture-revision/nnue-architecture-revision-init-training.md)、[固定ノードの記録](../measurements/nnue-architecture-revision/nnue-architecture-revision-init-fixed-nodes.md)）。

幅128の基準に対する最終の候補の棋力は次のとおりである。
同じ30ファイルの教師、同じ引数、および同じシードで学んだネットどうしの比較である。

候補の評価は基準と同等以上の精度で教師の探索値と対局結果を予測し、対局の記憶も増えていないが、同じノード数で強くはなっておらず、時間制御では速度の分だけ負ける。
この教師では、幅と隠れ層を増やしても棋力の利得が見えない。
2026年11月4日に開発者は、この構成を`H1`なしで確定し、世代反復へ進むと決めた。

## 決定

NNUEの評価を、線形の経路と非線形の経路の和とする。

線形の経路は、基底特徴の上に序中盤用と終盤用の2列を持ち、手番側の視点の和を盤上総駒数で補間する。
初期値は基準の重みファイルの探索用駒価値から作る。
盤上の駒の行には、自駒ならその駒状態の駒価値を、相手駒なら符号を反転した値を、144升と2列に同じ値として置き、王駒と先獅子の対象升の行は0とする。
前の世代の学習済みPSTは、ネットの初期値に使わない。
式は`crates/minase-trainer/src/nnue/train/base.rs`の`Base::initial_linear`のdocコメントにある。

非線形の経路は次のとおりとする。
式、型、値域、およびバイト配置は`crates/minase/src/eval/nnue/head.rs`の`PairwiseL16L32`と`format.rs`のdocコメントにある。

- 第1層の幅は256である。各視点の成分を4等分し、隣り合う区画の成分どうしを掛ける要素積（pairwise multiplication）を活性化とする。
- 要素積の出力を、幅15の層、その2乗とclipped ReLUの連結30個（dual activation）、および幅32の層へ通し、出力へ直接足す経路（skip接続）を加える。後段の配置はtataraのLayerStackとやねうら王のSFNN-1536と同じである。局面に応じた後段の切り替えは入れない。
- 第1層は尺度255のi16、累算値はi16とする。第1層の重みは絶対値220以下、バイアスは510以下とし、最大145行の発火でもi16に収まるようにする。
- 隠れ層の重みはi16の尺度256とする。先行エンジンのi8の尺度64は、minaseの勝率尺度では粗い。skip接続と幅32の層の出力重みもi16の尺度4,096とする。
- P型では、第1層の重みとバイアスを成分$`j`$と$`j+H/2`$で、skip接続の重みと幅15の層の各行を各視点の成分$`j`$と$`j+H/4`$で共有する。これで局面とその鏡映の評価が一致する。推論はこの共有を使って積和の回数を減らす。

学習器は、第1層の重みを標準偏差$`\sqrt{1/(3\times13{,}680)}\approx0.00494`$の正規分布で初期化する。
tataraの`uniform:fanin`とnnue-pytorchの一様分布±$`\sqrt{1/D}`$と同じ分散である。

## 検討した代案

幅128の直接内積のままにする案は、開発者の目的に合わないので採らなかった。
幅512は、幅256の結果を見てから考える。

隠れ層の有無を測り直す案は、開発者が不要とした。

活性化をSCReLUのままにする案は、隠れ層への入力が2倍になるので採らなかった。
tataraの記録では要素積のほうが強い（+29.5 ±13.2 nElo）ので、要素積に固定した。

隠れ層の重みをi8のまま検査を越えてSTCへ進む案は、幅32の層の丸めが手番側に約+20 cpの偏りを残すので採らなかった。
切り捨てを最近接の丸めに変える案は、誤差が28.06 cpにしか下がらなかった。

第1層の初期値を0.05のままにする案は、固定ノードの対局で基準より有意に弱かった。

候補が`H1`を取るまで切り分けを続ける案は、幅15の層の鏡映の扱い、SCReLU、および教師の増量が残っていたが、表現力が足りない兆候がないこと、教師の増量は世代反復と重なることから、開発者が選ばなかった。
先に高速化する案は、削れる費用が数%と見込まれ、`H0`を覆すには足りないと考えて選ばなかった。

線形の経路を廃止する案（StockfishのSFNNv17に相当）は、手の順序付けの同点破りとUSIの評価の内訳表示が線形の経路の重みを参照し、世代反復の出発点である手書きの評価関数v0を表す経路でもあるので採らなかった。
線形の経路の他の代案は[旧ADR](archive/compose-the-nnue-of-a-piece-value-initialized-linear-path-and-a-direct-screlu-head.md)にある。

## 結果

この構成は棋力の向上を示さないまま確定した。
世代反復の各世代のSTCと、最終候補と統合前のネットの比較が、この決定の検証になる。
最終候補が統合前のネットに勝てなければ、構成も含めて見直す。

エンジンは探索速度が約9%落ちる。
出力部1回の計算は負荷の少ないときで約113 nsであり、幅128の直接内積の約7倍である。
評価は累算器の更新の約3割でしか計算されないので、探索全体への影響は単純な見積りより小さい。

固定の4つの出力部は削除し、出力部は1つになった。
位相補間の係数は出力部から除いた。
旧い出力部の重みファイルは復号で拒否し、変換器は作らない。
層積みの設計書の前提は変わったので、書き直すか取り下げるかを開発者が決めることとし、2026年11月4日に取り下げた（草稿はコミット`e2539378`の`docs/plans/nnue-layer-stack.md`）。

新しい形式は旧いネットを読めないので、構成と埋め込みネットは同時に変わる。
2026年11月4日に開発者は、構成の見直しのブランチ全体をmasterへ統合して、世代反復の起点とすると決めた。
これは、masterの置き換えを世代反復の最終候補で行うとした2026年11月3日の決定を改めるものである。
統合後のmasterのエンジンは、結果回帰の補正を持つ統合前のネットより弱いと見込まれるので（直接は測っていない）、最終候補が決まるまではmasterからのリリースとBotの更新でエンジンが弱くなる。
統合前のコミット`5ea52649`はブランチ`nnue-width128-regressed`に残し、最終候補の比較の基準にする。

# 先読みが的中したら同じ探索を続け、時間予算を的中の時点から測る

## ステータス

承認済み。決定日は2026年9月21日。

## コンテキスト

USIの先読みでは、エンジンが`bestmove X ponder Y`で相手の次の手の予想Yを添え、GUIはXとYを指した局面で`go ponder`を送る。
相手の実際の着手がYなら`ponderhit`が届き、異なれば`stop`が届く。
[USI先読み](../plans/ponder.md)は、的中した後の探索の続け方と、時間予算を測る起点を決める必要があった。
Stockfish、やねうら王、およびHaChuは経過時間を探索の起点から測り、先読みの時間を予算に全額算入する（[設計書の参考資料](../plans/ponder.md#参考資料)）。
この方式では長い先読みの後に的中と同時に指すことになるので、各エンジンは目標時間の25%増しや先読み時間の残り時間への足し戻しなどの別の機構で目減りを補っている（[同じ参考資料](../plans/ponder.md#参考資料)）。
minaseの予算は加算と秒読みの項が大半を占め、残り時間の項は88手以上で割るので、先読みで節約した時間は後の手の予算へほとんど戻らない。

## 決定

`ponderhit`を受けても探索を止めず、同じ探索のまま時間の制限を有効にして、1手の標準予算softと打ち切りの上限hardを的中の時点から測る。
次の反復を始める判定と、的中の時点で進行中だった反復を続けるかの1回だけの再判定は、探索の起点からの累積時間に固定比を掛けた予測完了時刻を、的中までの時間と予算の和と比べて行う。
詳細は`SearchHandle::ponderhit`、`iteration_prediction_fits`、および`Searcher::check_time`のdocコメントにある。

## 検討した代案

`ponderhit`で探索を止め、置換表を使って時計つきの探索をやり直す案は、進行中の反復を捨て、置換表の世代を1つ余分に進め、浅い反復からやり直す時間を自分の持ち時間から使うので採らなかった。
予算を探索の起点から測る案は、上記の理由で先読みの利益を捨てるので採らず、目減りを補う機構も持たない。
的中からの経過時間に固定比を掛けて次の反復を予測する案は、次の反復の所要時間が探索全体の累積時間に比例するので所要時間を過小に見積もり、完了できない反復を毎回始めてhardで打ち切られるので採らなかった。
的中の時点で進行中の反復を無条件に続ける案は、長い先読みの後の的中でhardまで使ってその反復を捨てる手が増えるので採らなかった。

## 結果

先読みでない探索では的中までの時間が0なので、判定は先読みのない式と一致し、固定深さのbench総ノード数は変わらない。
先読みは、STCが有効208ペアでLLR 2.9505、LTCが有効215ペアでLLR 2.9512の`H1`であり、的中率はSTCで49.5%、LTCで52.0%だった（[STC](../measurements/ponder-stc.md)、[LTC](../measurements/ponder-ltc.md)）。
候補は相手の手番中にもCPUを使うので、CPU時間の合計は基準の約2.0倍であり、この測定が示すのは同じ時計の下での強さである。
予算がUSIオプション`USI_Ponder`の値に依存しないので、minaseは`USI_Ponder`を宣言せず、受け取っても無視する。
測定は評価関数がPSTとFMだった時期の構成で行ったので、起点や再判定の方式を変える提案には現行の構成での再測定が要る。

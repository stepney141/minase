# 勝率尺度を重みファイルの1定数とし、NNUEの教師の探索値も既定ではその尺度で勝率へ換算する

## ステータス

承認済み。決定日は2026年11月14日。[勝率尺度を重みファイルの1定数とし、教師の勝率尺度は較正コマンドで求めて学習の引数で与える](archive/hold-cp-per-logit-in-the-weight-header-and-pass-the-teacher-scale-explicitly.md)を置き換える。

## コンテキスト

[以前の決定](archive/hold-cp-per-logit-in-the-weight-header-and-pass-the-teacher-scale-explicitly.md)は、ネットの評価値を勝率へ換算する勝率尺度`cp_per_logit`を重みファイルのヘッダの1定数とし、教師の探索値を勝率へ換算する教師の勝率尺度`teacher_cp_per_logit`を、学習の必須の引数`--teacher-cp-per-logit`で、訓練集合からの推定（`calibrate`）か較正ファイルとして与えると定めていた。
以前の決定は、2つの尺度を1つにまとめる案を、分類の間で教師の勝率尺度が最大約1.6倍異なり棋力への影響を測っていないので採らなかった。

評価値を勝率へ換算する尺度の調査（[調査メモ](../research/win-rate-scale-k-prior-art.md)）では、調べた13件のうち11件が、手で決めた定数か一度推定して固定した値を使い、学習のたびに推定するのはEtherealのチューナーとdlshogiの`--use_evalfix`の2件だけだった。
やねうら王のwikiの[ふかうら王の学習](https://github.com/yaneurao/YaneuraOu/wiki/%E3%81%B5%E3%81%8B%E3%81%86%E3%82%89%E7%8E%8B%E3%81%AE%E5%AD%A6%E7%BF%92)は、教師ファイルの評価値と勝敗の関係から係数を決める`--use_evalfix`と、固定の係数を与える`--evalfix-a`を、どちらも方法として挙げる。
[標準レシピv1](../plans/nnue-standard-recipe.md)の世代反復は、第1世代の最初の4本から勝率尺度を一度推定して固定し、各世代の教師を前の世代のネットが同じ規則とノード数で生成するので、1世代の教師は1つの分類にまとまる。
中断した世代反復では、推定した教師の勝率尺度（707.9 cp）と勝率尺度（679.03 cp）の差は約4%だった。
2026年11月14日にエンジンの開発者は、教師の勝率尺度を既定では勝率尺度と同じ値にし、推定と較正ファイルは選べる方法として残すと決めた。

## 決定

勝率尺度`cp_per_logit`は、以前の決定と同じく、重みファイル（MNPT、MNUE）のヘッダが持つ値を唯一の定数とし、学習の初期値に与えた重みファイルの値を、学習中および書き出す重みにもそのまま使う。
`minase-trainer nnue train`の`--teacher-cp-per-logit`は省略でき、省略したときは教師の探索値を`--base`のネットの勝率尺度で勝率へ換算する。
`calibrate`と較正ファイルのパスは、従来どおり指定でき、使った値と出どころは`config.json`に記録する。
PST、FM、および同時学習の学習器と、教師値を使う診断の`--teacher-cp-per-logit`は、以前の決定のとおり必須のまま変えない。

## 検討した代案

NNUEでも学習のたびに推定するのを標準とする案は、同じ方式の先行例が2件にとどまるので採らない。
推定の機能を消す案は、ふかうら王の学習が方法の1つとして挙げており、教師の分類が混ざる学習に要るので採らない。
将棋の600やbulletの400といった先行例の定数を使う案は、駒の価値の体系が違うので採らない。

## 結果

標準レシピの学習と連続生成スクリプトは`--teacher-cp-per-logit`を渡さず、教師の探索値とネットの評価値の目盛りが一致する。
`config.json`の教師の勝率尺度の出どころは`base`となる。
勝率尺度そのものは、世代反復の第1世代の最初の4本から一度だけ推定して固定する。これはnnue-pytorch、Stockfish、およびdlshogiと同じ決め方である。

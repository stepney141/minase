# ノード数は着手を適用する直前に1つずつ共有カウンタへ数える

## ステータス

承認済み。決定日は2026年9月19日。

## コンテキスト

ノード数は、`go nodes N`の上限、進捗の表示、およびNPSの計算に使う。
本ADRは、2つの時期に下した決定をまとめて記録する。
1つは2026年8月23日に[Lazy SMP](../plans/lazy-smp.md)で決めた共有カウンタの方式であり、もう1つは2026年9月19日に決めたノードの数え方である。
9月19日の[調査](../research/node-count-definition.md)時点の探索は、根、通常探索、および静止探索の各入口でノードを数えていた。
通常探索は残り深さ0で同じ局面のまま静止探索を呼ぶので、末端の局面を2回数え、表示ノード数の約33%が二重計上であった。
Stockfishとやねうら王は、探索中に実際の着手を盤面へ適用した回数をノード数とする（[調査の既存エンジンの数え方](../research/node-count-definition.md#既存エンジンの数え方)）。
8月23日のLazy SMPでは、全ワーカーのノード数を1個の共有の`AtomicU64`で数え、上限があるときは比較交換で1ノードずつ予約する。
上限があるときの一括予約は、単一の共有カウンタでは`Finished.nodes`の正確さと決定性を両立できないので、設計の段階で採らなかった。
同じ8月23日には、停止フラグとの偽共有を避けるキャッシュラインの分離と、上限がないときの1024ノード単位の一括反映を試した。
ワーカーあたりNPSの変化は`Threads=1`で−0.3%、2で+0.2%、4で+2.3%であり、ゲートの3%に届かなかった（[測定記録](../measurements/lazy-smp-counter-nps-gate.md)）。

## 決定

ノードは、通常探索と静止探索が着手を盤面へ適用する直前にだけ数え、null move、根、および盤面へ適用しない最後の王駒を取る手は数えない。
反復または置換表で打ち切られる子局面は、着手を適用した後に判定するので1ノードと数える。
各ノードは数えた時点で1個の共有カウンタへ反映し、上限があるときは比較交換で1ノードずつ予約して、上限を超える予約を拒否する。

## 検討した代案

探索関数の入口で数える旧方式は、末端の局面を二重に数えるので採らなかった。
キャッシュラインの分離と1024ノード単位の一括反映は、NPSのゲートに届かなかったので採らなかった。
一括反映は[合法手生成の高速化の第2期](../plans/movegen-speedup-2.md)の段階6でも試したが、毎ノードの反映へ戻した版との差がNPSの測定の幅に収まったので外した（[測定記録](../measurements/movegen-speedup-2-stage6-bench-depth5.md)）。

## 結果

minaseのノード数とNPSは、Stockfishおよびやねうら王と同じ定義の値として比較できる（[調査の採用した定義](../research/node-count-definition.md#採用した定義)）。
2026年9月19日より前の記録に残るノード数とNPSは二重計上を含み、その扱いは調査メモが記す。
`Finished.nodes`は、上限があれば必ずN以下になる。
1ノードあたりの費用が変われば共有カウンタの競合の割合も変わるので、一括反映の再提案には現行の評価関数での再測定が要る。
停止条件の検査と計数は`crates/minase/src/search/alphabeta/searcher.rs`の`enter_node`にあり、予約は`team.rs`の`reserve_node`にある。

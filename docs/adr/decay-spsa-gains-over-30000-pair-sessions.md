# SPSAの利得は範囲の1/6の摂動幅まで減衰させ、標準の規模を30,000ペアにする

## ステータス

承認済み。決定日は2026年10月17日。

## コンテキスト

[旧ADR](archive/decay-spsa-gains-from-one-sixth-of-the-range.md)は、SPSAの摂動幅と学習率の減衰を定め、標準のセッションを375反復×8ペアの3,000ペアとした。
3,000ペアの根拠は、22係数の調整を仮定した模擬比較である（[模擬比較の記録](../measurements/spsa-gain-calibration/spsa-gain-simulation.md)）。
この模擬比較は、係数ごとの2次関数で交互作用のない目的関数を仮定していた。
実対局での裏付けは、22係数のセッション（[記録](../measurements/spsa-gain-calibration/spsa-stage9-20260925-c5.md)）と29係数のセッション（[記録](../measurements/search-revival-spsa/search-revival-t.md)）の値が、それぞれ段階ゲートで`H1`となった2例だけである。

2026年10月17日に、探索の関数形をStockfishとYaneuraOuの形へ寄せる7本の設計書を起案した（[係数の関数形の比較](../research/search-coefficient-forms-prior-art.md)）。
これらをすべて採用すると、調整する係数の数は約95になり、3,000ペアで足りることを示す材料はない。
SPSAは全係数を同時に摂動させるので、1反復の費用は係数の数によらないが、各係数の勾配の推定にはほかの係数の影響が雑音として混ざる。
このため、係数が増えるほど、同じ精度を得るのに必要な反復数が増える。

公開されている調整の規模は、[チェスエンジンのSPSA調整で使われた対局数](../research/chess-engine-spsa-session-sizes.md)によれば、Stockfishの22係数で約5万ペア、OpenBench上の8〜14係数で約8万ペアである。
手元のStockfishの履歴（コミット5c4cef0b）では、探索の調整を反映した最近のコミットが100〜170個の定数を一度に変えている。
コミット90c83c38では、約124個の定数を非常に長い持ち時間の12.5万局（約6.25万ペア）で調整した。
時間管理の定数だけを調整したコミット0f01a516と738ac2a1も、6〜11個の定数に3.5万局と7万局を使っている。
これらは必要数の下限を示すものではないが、minaseの3,000ペアは同じ程度の係数の数に対して1桁以上小さい。

## 決定

利得の減衰は旧ADRのまま引き継ぐ。
すなわち、α = 0.602、γ = 0.101、Aを総反復数の0.1倍とするfishtestの既定の指数で減衰させ、終了時の摂動幅`c_end`を範囲の1/6、終了時の学習率`r_end`を0.002とし、更新則の形`θ ← θ + (a/c)·D·flip`は変えない。
これらの式は、`spsa_runner`の`model`モジュールの`rates`と`update`で実装する。

標準のセッションを3,750反復×8ペアの30,000ペアとする。
これは2026年10月17日のエンジンの開発者の決定である。
総反復数は摂動幅と学習率の式に入るので、規模は開始前に決め、途中で延長しない（[反復予算の調査](../research/spsa-iteration-budget.md)）。

## 検討した代案

3,000ペアを標準に保つ案は、上記のとおり係数の数が増える調整で足りる根拠がないので採らなかった。
各調整で新しい係数と同じ仕組みの既存の係数だけを中くらいの予算で調整し、最後に全係数を大きな予算で調整し直す案もあったが、採らなかった。
係数の数ごとの必要な予算を、模擬比較の道具で見積もってから決める案も、採らなかった。

## 結果

同時対局数16のセッションでは、3,000ペアで27,138秒（1ペア約9秒）かかったので、30,000ペアは約75時間（約3日）を要する見込みである。
旧ADRの利得の終端の値は3,000ペアの模擬比較で選んだものであり、30,000ペアの減衰で同じ値がよいかは確かめていない。
3,000ペアで調整して採用した過去の値は、そのまま有効である。
30,000ペアでも、所定の反復を終えたことは最適値への収束を意味しない。

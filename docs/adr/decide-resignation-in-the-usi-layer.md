# 投了はUSI層が採用結果の評価値で単発に判定する

## ステータス

承認済み。決定日は2026年9月25日。

## コンテキスト

issue #6は、minaseが明らかに負けた局面で自ら投了できるようにすることを求めた。
USIでは、エンジンが着手の代わりに`bestmove resign`を返すと投了になる。
やねうら王は探索の結果に投了を表す指し手を含め、閾値をUSIオプション`ResignValue`で与える（[USI投了の参考資料](../plans/archived/usi-resignation.md#参考資料)）。
保存済みの自己対局記録104,224局へ仮想の投了条件を当てた[診断](../research/usi-resignation-diagnosis.md)では、どの閾値でも投了した側が結局は勝つか引き分ける局が0件にならなかった。
詰まされる読みだけを条件にしても、その読みを出した側が実際の対局で勝った局が、発火した局の0.03%あった。
決定は[USI投了](../plans/archived/usi-resignation.md)で下した。

## 決定

USI層は`bestmove`を送る直前に、採用結果の完了深さが1以上で、評価値が`−ResignValue`以下なら`bestmove resign`を返す。
`ResignValue`は1以上99,999以下で既定値を20,000 cpとし、直前の手の評価値は保持しない。
詳細は`UsiProtocol::should_resign`と`write_bestmove`のdocコメントにある。

## 検討した代案

探索の結果に投了を表す指し手を持ち込む案は、指し手型に着手でない値が入り、審判層、ハーネス、および保存記録のすべてで特殊値の扱いが要るので採らなかった。
同じ判定が複数の手で続いたときだけ投了する案は、3,000 cpの誤投了が連続1手の942局から連続2手で820局、連続3手で770局へしか減らず、状態を持つ費用に見合わないので採らなかった。
4,000 cpのような小さい既定値は、人間の相手に対して早すぎる投了になるので採らなかった。
詰みだけを特別に扱う分岐や無効を表す特別な値を設ける案は、値の範囲だけで詰まされる読みに限ることも無効にすることもできるので採らなかった。

## 結果

`ResignValue`の名前と意味はやねうら王のオプションに合わせたので、GUIの利用者は既知の設定として扱える（[USI投了の参考資料](../plans/archived/usi-resignation.md#参考資料)）。
通常の評価値はほとんど6,000 cpを超えないので、既定では詰まされる読みが出た局面だけで投了する。
深さ0の採用結果は根の静的評価であり探索の裏付けがないので、投了しない。
投了はエンジンの対局状態を変えず、終局の状態遷移はGUIの`gameover`が担う。
探索部は変わらないので、投了しない探索のノード数は変わらない。
診断は2026年9月8日以降の評価尺度の記録を使っており、評価関数は2026年10月12日にNNUEへ置き換わったので、既定値を見直すときは現行の評価尺度で診断し直す必要がある。

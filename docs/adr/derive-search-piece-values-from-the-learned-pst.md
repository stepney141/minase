# 探索用駒価値は学習PSTから導いた値に固定する

## ステータス

承認済み。決定日は2026年9月8日。

## コンテキスト

探索は、捕獲手の並べ替え、静的交換評価（SEE）、静止探索の余裕値、および歩兵価値を単位とする枝刈りの余裕値に、駒状態ごとの駒価値を使う。
駒状態は駒種と成りの区分の組であり、47個ある。
当初の駒価値は、最初の手書き評価関数v0の表のままだった。
[棋力向上段階3](../plans/strength-stage3.md)は、採用中の学習PSTの重みから駒価値を導いた。
各駒状態について、自駒の重みの144升平均と、相手駒の重みの符号を反転した144升平均の中間値を駒価値とする。
導いた値は、成っていない龍王が1,000に対して1,180、角鷹が1,250に対して1,603のように、v0の表と一致しなかった。
王将、玉将、および太子は教師局面に常に両側1枚ずつあり、その重みは勝敗を説明しないので学習で定まらない。
そこで王駒の値は導出せず、非王駒の最大値に歩兵の値を加えた値とした。
導いた駒価値は、[STC](../measurements/strength-stage3-values-stc.md)と[LTC](../measurements/strength-stage3-values-ltc.md)でともに`H1`となった。
続く[PSTの序中盤と終盤の補間](../plans/tapered-pst.md)は、開始版の重みから導いた47個の値を重みファイルに固定し、PSTの再学習後も導き直さないことにした。
[NNUEによるPST＋FMの完全代替](../plans/nnue-replacement.md)も、基準の重みファイルの47個の値をNNUEの重みファイルへ写して固定した。

## 決定

探索用駒価値は、段階3の式で学習PSTから導いた47個の値を重みファイルに格納した固定値とし、評価関数を学習し直しても導き直さない。
王駒の値は、非王駒の最大値に成っていない歩兵の値を加えた値とする。
盤上に現れ得る非王駒の値はすべて正でなければならず、重みファイルの復号時にこの条件と王駒の式を検査する。

## 検討した代案

v0の表を、評価値を勝率へ換算する学習時の尺度Kの比で一様に拡大する案は、学習PSTの駒どうしの相対価値を反映できず、評価関数を学び直すたびに比を更新する必要があるので採らなかった。
評価関数の学習ごとに駒価値を導き直す案と、序中盤と終盤で駒価値も補間する案は、評価関数の変化とSEEや枝刈りの変化を切り分けられなくなるので採らなかった。

## 結果

駒価値は`crates/minase/src/eval/nnue/format.rs`が復号時に検査し、`Nnue::piece_value`と`Nnue::pawn_value`が探索へ渡す。
SEEの最も安い攻撃駒の選択と、捕獲手を駒価値の合計が正かどうかで判定する順序付けは、正値性の検査に依存する。
評価関数が学ぶ駒の価値は探索用駒価値から離れ得るので、その差はSEEと余裕値の不整合として測定結果に含まれる。
駒価値を導き直す場合は、評価関数とは別の候補として段階ゲートで測る必要がある。

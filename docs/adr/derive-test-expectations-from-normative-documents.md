# テストの期待値を規範文書から導き、現在の実装から導かない

## ステータス

承認済み。決定日は2026年8月15日。

## コンテキスト

2026年8月14日に既存のテスト357件を棚卸しすると、約60件が現在の実装の出力や非公開の欄をそのまま写していた。
たとえば初期駒21種の動き（RULES.md第9条）は、実装の表から期待値を導き直す自己参照のテストでしか守られていなかった。
評価の駒価値の定数はテストの中へ丸写しされ、出自の表がリポジトリになかったので、数値の変更を検知するだけで正しさを検査していなかった。
このようなテストは、意図した挙動からの逸脱ではなく、実装の変更を検出する。
[テストスイートのspec-first再構築](../plans/spec-first-tests.md)は、ユニットテストを全廃し、規範文書から作った挙動の表に基づいて書き直した。

## 決定

テストの期待値は、RULES.mdと各領域の規範文書、外部のプロトコルと実装との互換性の契約、および確認済みの過去の不具合から導き、現在の実装の出力を正しさの証拠にしない。
規範文書から期待値を確定できない挙動は、テストの名前またはコメントで実装の契約であることを明示してから書く。
規則に関わるテストは、`article_14_1_...`のように根拠の条番号を名前に含める。

## 検討した代案

実装を写した既存のテストを残して補強する案は、正しい変更でも期待値を書き換えることになり、逸脱を検出しないので採らなかった。
カバレッジに目標値を設ける案は採らず、カバレッジは欠落を見つける二次的な指標にとどめ、テストの検出力は意味を変える変異を実装へ一時的に加えて確かめた。

## 結果

再構築の後のテストは、正しい変更では通り、規範からの逸脱では失敗することを目指す。
それより前に下した[perftの数値を合法手生成の正しさの基準にしない](verify-movegen-without-perft-counts.md)決定も、同じ考え方に立つ。
修正に伴う回帰テストは、修正を外すと失敗することを確かめてから残す（[教訓](../lessons/confirm-regression-test-fails-without-fix.md)）。
再構築の当時は設計書の確定事項も規範文書に含めていたが、設計書は完了時に凍結する記録になったので、以後の規範はRULES.md、手引き、プロトコルの調査メモ、コードのdocコメント、およびADRに置かれる。
テストの正本はコードとして書かれたテストそのものであり、挙動の表と対応台帳は再構築の作業記録として凍結した。
2026年10月13日に、エンジンの開発者の判断で、テストのコメントから挙動の表の番号（`D6-CLI-01`など）と表への参照を取り除き、期待値の根拠は条番号、ADR、または契約の内容で直接書くことにした。

# 棋力測定の対局ではエンジンの投了を無効にする

## ステータス

承認済み。決定日は2026年9月25日。

## コンテキスト

対局ハーネス`minase match run`は、`bestmove resign`を当該局の負けとして数える。
[USI投了](../plans/usi-resignation.md)により、minaseは既定で詰まされる読みが出た局面で投了するようになった。
投了は、規則上の終局より前に対局を終わらせる。

## 決定

ハーネスは、USIエンジンの起動時に`setoption name ResignValue value 99999`を候補と基準の両方へ無条件に送る。
CECPのエンジンには送らない。

## 検討した代案

投了を有効のまま測る案は、基準が先に投了した局で候補が勝ち切れたかを観測できず、勝ち切りの退行が隠れるので採らなかった。
この案では保存記録が完走した対局でなくなり、投了の閾値の診断のような事後の分析もできなくなる。
投了の有無で自己対局の強さを比べる測定は、投了が期待得点を減らすだけで増やさないので行わない。

## 結果

99,999は`ResignValue`の上限であり、評価値の絶対値は詰みの値30,000を超えないので、この設定のminaseは投了しない。
このオプションの設定は両側で同じ対局条件であり、機能比較のスイッチではない。
`ResignValue`を持たない旧コミットはUSIの慣例どおり未知のオプション名を無視するので、コミット対コミットの対称性は保たれる。
投了は自己対局の測定に影響しないので、投了の変更はGSPRTによる採否の対象にならない。
送信は`crates/minase/src/harness/engine/process.rs`にあり、手順は[棋力測定の手引き](../guides/sprt.md)にある。
ハーネスが評価値を見て対局を打ち切る早期投了の裁定は本決定とは別の問題であり、待機中の[早期投了の導入判定](../plans/match-early-resignation.md)が扱う。

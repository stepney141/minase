# AlphaZero型探索の自己対局は1,000手で打ち切り、打ち切った対局を学習データから除く

## ステータス

承認済み。決定日は2026年10月14日。

## コンテキスト

自己対局の対局が長引くと、生成時間を費やすだけでなく、勝敗の決まらない手順が学習データに入る。
dlshogiのGumbel AlphaZero版では、手数の上限まで対局を引き延ばす退化した戦略が学習された。
αβ探索の自己対局の対局長の分布は裾が重く、NNUEの教師の生成では7,500局のうち86局が手数の上限4,000手に達した（[記録](../measurements/nnue-lr-schedule/nnue-lr-schedule-training.md)）。
一様ランダムな手の対局は、[ランダム対局検証ハーネス](../plans/archived/random-play.md)の実測（代表9規則セットの2,700局と反復規則R1の1,000局、計3,700局）で、手数の中央値が242手、99パーセンタイルが928手であり、大半が王駒の捕獲か詰みで終わった。
教師データの形式MNSDの終局理由には、手数の上限による打ち切りがない（`crates/minase/src/training/records.rs`）。
2026年10月14日に、エンジンの開発者は上限を1,000手の固定値とし、上限に達した対局を学習から除くと決めた（[統括計画](../plans/alphazero.md)、[自己対局生成器の設計書](../plans/archived/alphazero-selfplay.md)）。

## 決定

自己対局の手数の上限は、乱択の序盤の手を含めて1,000手とする。
上限に達しても終局していない対局は、学習データのファイルに書かず、塊の集計の`discarded_max_ply`に件数を記録する。

## 検討した代案

上限を対局長の分布の高いパーセンタイルから決める案は採らなかった。
αβ探索の自己対局の分布は裾が重く、高いパーセンタイルで決めると上限が数千手になり、引き延ばしの余地を広げるからである。

上限に達した対局を引き分けとして記録する案は採らなかった。
長引く対局の多くは互角ではなく勝ちを決め切れていない局面であり、引き分けの教師は対局の実態と合わないからである。

## 結果

1,000手は生成時間ではなく学習の健全性のための値であり、上限に達した対局の局面は捨てられる。
捨てる対局がRLの生成時間に占める割合は、[強化学習の実行](../plans/alphazero-rl.md)の試走と最初のサイクルで測り、上限に達した対局が10%を超えたら、上限または投了の条件を見直す。
上限は`crates/minase/src/bin/minase/zero_selfplay/`の定数`MAX_PLY`にある。

# AlphaZero型探索の自己対局は3,000手で打ち切り、打ち切った対局を学習データから除く

## ステータス

承認済み。決定日は2026年11月1日。

## コンテキスト

2026年10月14日の[前のADR](archive/discard-zero-self-play-games-that-reach-1000-plies.md)は、自己対局の手数の上限を乱択の序盤を含めて1,000手とし、上限に達した対局を学習から除くと決めた。
前のADRは、上限に達した対局の割合が10%を超えたら、上限または投了の条件を見直すとしていた。
2026年10月31日に学び直した[強化学習](../plans/alphazero-rl.md)の本線では、捨てた対局の割合がサイクル6の5.5%から、サイクル7で11.5%、サイクル8で17.0%に増えた。
捨てた対局に費やした着手数は、サイクル8で全体の27.2%であった。

[長い対局の調査](../measurements/alphazero-rl/alphazero-rl-long-games.md)では、上限だけを3,000手に上げた生成器で、サイクル8のネットに400局を指させた。
1,000手を超えた対局は19.1%であり、その長さは中央値1,262手、90パーセンタイル1,952手、最長2,886手であった。
3,000手に達したのは400局中2局であった。
1,000手の時点の駒は92枚中の中央値22枚で、その後に取った駒は100手あたり0.7枚であった。
1,000手を超えた対局の66%は勝敗がつき、そのうち1,000手の時点で評価値が有利だった側が89%で勝った。
記録した局面のうち、同じ対局で同じ局面が再び現れた割合は0〜5%であった。
上限に達していたのは、互角の局面での引き延ばしや同じ手順の繰り返しではなく、少ない駒で有利な側が勝ちきれない終盤であった。
中将棋の規則には、進展のない対局を終わらせる仕組みがなく、駒枯れの規則も一方の王以外の駒が1枚以下になるまでは働かない。

1サイクルは、[塊のADR](commit-zero-self-play-in-fixed-game-chunks-up-to-the-first-prefix-reaching-the-target-positions.md)により、訓練局面数の目標に届いたところで締める。
このため、捨てる対局に費やした着手数の分だけ、1サイクルの生成時間が延びる。
2026年11月1日に、エンジンの開発者は上限を3,000手に上げると決めた。

## 決定

自己対局の手数の上限は、乱択の序盤の手を含めて3,000手とする。
上限に達しても終局していない対局は、前のADRと同じく学習データのファイルに書かず、塊の集計の`discarded_max_ply`に件数を記録する。

## 検討した代案

1,000手の上限を保つ案は採らなかった。
捨てる対局の割合が前のADRの見直しの基準を超えて増え続け、捨てた着手の分だけ1サイクルの生成が延びるからである。
また、勝ちきる終盤の局面が学習に入らないので、ネットが勝ちきり方を覚える機会がない。

上限を2,000手にする案は採らなかった。
調査の標本では、2,000手に達した対局が、3,000手で捨てた2局を含めて400局中9局（2.3%）あり、捨てる対局に費やす着手の合計は3,000手の上限より多くなるからである。

1,000手に達した対局を引き分けとして学習に使う案は採らなかった。
1,000手を超えて勝敗がついた対局の約9割は、その時点で評価値が有利だった側の勝ちであり、引き分けの教師は対局の実態と合わないからである。
前のADRも、同じ理由でこの案を採らなかった。

前のADRは、上限を高くすると引き延ばしの余地が広がるとした。
dlshogiのGumbel AlphaZero版では、手数の上限まで対局を引き延ばす退化した戦略が学習された。
本決定でも上限に達した対局は引き分けとして学ばせずに捨てるので、上限まで引き延ばしても学習上の得はない。
調査でも、1,000手を超えた対局はほとんどが3,000手より前に勝敗か反復で終わった。

## 結果

捨てる対局は調査の標本で約0.5%になり、捨てていた着手の分だけ1サイクルの生成が短くなる見込みである。
1局あたりの局面数が増えるので、1サイクルに入る独立な対局の数は減る。
上限に達した対局の割合と、捨てた対局の着手の割合は、サイクルごとに生成器の集計で確かめ、10%を超えたら上限または投了の条件を見直す。
変更より前のサイクルの`config.json`は`max_ply`に1,000を記録しており、変更の後には、それらのサイクルの未完了の生成を再開できない。
上限は`crates/minase/src/bin/minase/zero_selfplay/mod.rs`の定数`MAX_PLY`にある。

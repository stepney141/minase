# 補助ワーカーは深さを飛ばし、最も深い反復を完了したワーカーの結果を採る

## ステータス

承認済み。決定日は2026年8月23日。

## コンテキスト

[Lazy SMP](../plans/lazy-smp.md)は、複数の探索ワーカーがそれぞれ独立に反復深化を行い、置換表だけを共有する並列化方式である。
初版では、補助ワーカーが主ワーカーと同じ深さの列を探索し、ルート合法手の並びをワーカー番号の分だけ回転させていた。
初版の`Threads=2`は、固定深さ6のbenchで経過時間を1.4%しか縮めなかった（[測定記録](../measurements/lazy-smp-v1-diversification-bench.md)）。
時間制御の自己対局でも、有効81ペアの時点でEloはおよそ+2（±45）であり、測定を止めた（[測定記録](../measurements/lazy-smp-threads2-tc.md)）。
指し手順序付けは置換表の記録手を先頭へ入れ替えるので、主ワーカーが根の記録を書いた後は、補助ワーカーも回転した並びを捨てて主ワーカーと同じ手から読んでいた。
補助ワーカーは主ワーカーを遅れてなぞる複製になり、新しい情報をほとんど供給しなかった。
診断では、補助ワーカーが同じ深さを主ワーカーより先に探索する深さスキップの構成だけが、深さ5で経過時間を18%縮めた。
補助ワーカーが1つ深い反復にいる構成では、主ワーカーは利益を得ず、逆に補助ワーカーが主ワーカーの記録から利益を得ていたが、その結果は捨てられていた。

## 決定

補助ワーカーk（k=1、…、Threads−1）は周期`p = 2 + ((k - 1) % 4)`を持ち、深さ1、`(d - 1) % p == 0`を満たす深さd、および深さ上限だけを昇順に探索する。
ルート合法手の回転、時刻、および乱数は多様化に使わない。
停止時には、最も深い反復を完了したワーカーの最善手、評価値、深さ、および主変化を、同じ反復の組として採用する。
同じ深さなら、ワーカー番号が小さいもの（主ワーカーは0）を優先する。

## 検討した代案

ルート合法手の回転は、置換表の記録手の先頭入れ替えに打ち消されるので採らなかった。
補助ワーカーを常に1つ深い反復に置く案は、固定深さの経過時間が13〜25%延びたので採らなかった。
ワーカー番号をそのまま周期にする案は、ワーカーが多いと深さ1しか探索しない補助ワーカーが生じるので採らず、周期を4種類で循環させた。
主ワーカーの結果だけを採る初版の方式は、補助ワーカーが得た利益を捨てるので採らなかった。

## 結果

第2版はbenchのゲートを深さ5で26.5%、深さ6で17.9%の短縮で通過した（[測定記録](../measurements/lazy-smp-v2-bench-gate.md)）。
時間制御のGSPRTは上限500ペアで判定保留（LLR 2.615）であったが、固定局数のEloは+62.1（95%信頼区間［+41.5, +83.0］）であった（[測定記録](../measurements/lazy-smp-v2-threads2-tc.md)）。
設計書は500ペアの判定保留を不採用と定めていたが、この規定から逸脱することを明記して採用した。
現行の[棋力測定の手引き](../guides/sprt.md)は信頼区間を採用の根拠に読み替えることを禁じており、この採用はその規則より前の判断である。
後に[秒読みつき時計での持ち時間と秒読みの活用](../plans/byoyomi-time-usage.md)が、同じ深さのワーカーの間で途中結果の有無を比べる基準を加えた。
`Threads=4`対`Threads=2`の測定は行っていない。
測定は評価関数v0の時期に行ったので、多様化の方式を変える提案には再測定が要る。
実装は`crates/minase/src/search/alphabeta/deepening.rs`の`auxiliary_depths`と、`team.rs`の`select_worker_outcome`にある。

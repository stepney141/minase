# プロファイル誘導最適化（PGO）でビルドしない

## ステータス

承認済み。決定日は2026年9月15日。

## コンテキスト

PGOは、代表的な入力で実行頻度を集め、そのプロファイルを適用して再ビルドする最適化である。
[合法手生成と利き計算の高速化](../plans/archived/movegen-speedup.md)の作業単位Dとして、捕獲生成とSEEを改修した作業単位Cまでの同じソースで、通常版とPGO版を手動ビルドで比べた。
プロファイルを集める学習入力は、測定用のbenchの局面とは別に、ランダム対局から採った局面とした。
[PGOの測定記録](../measurements/movegen-speedup-pgo-bench-depth5.md)では、局面別の探索結果は両版で一致し、NPSの比は1.183倍から1.190倍で、採否の判断値として事前に置いた10%の増加を超えた。
再生成は約65秒、プロファイルは6,089,008バイトであり、同じ学習入力でもプロファイルのSHA-256は実行ごとに異なった。
採否測定のために、rustcのラッパーでプロファイルを適用し、プロファイルの作成時に記録したソースとツールチェーンの識別子をビルド時に照合する再現基盤も一度実装した（[ラッパーで適用する教訓](../lessons/pgo-profile-path-via-wrapper.md)）。
対局ハーネスはコミットを展開して標準の手順でビルドするので、PGOを使うにはプロファイルを候補コミットに含め、ソースを変えるたびに作り直す必要がある。

## 決定

PGOを採用せず、標準の`cargo build --release`の成果物を使う。
エンジンの開発者は、ソースを変えるたびにプロファイルを再生成する運用と、ビルド手順の追加がコードベースを複雑にしすぎると判断した。
再現基盤の実装は取り消した。

## 検討した代案

効果を確かめたPGOを採用し、プロファイルの再生成を高速化の各コミットの手順に組み込む案は、上記の運用の負担を理由に採らなかった。
プロファイルを`.cargo/config.toml`の`rustflags`から相対パスで渡す方式は、依存クレートのコンパイルが失敗するので、そもそも使えない。

## 結果

この決定により、約1.19倍の速度の向上は見送った。
同じマイルストーンの最終の自己対局は、採否の判断より前にPGOを含む構成で行ったので、PGOを外した採用版そのものの自己対局は行っていない。
再検討する場合は、測定記録の判断値10%、学習入力と測定用の局面の分離、およびビルド時の識別子の照合を出発点にする。
PGOの効果は改修の内容と重なるので、1.19倍という値は単位Cまでのソースに対するものであり、現行のソースでは測り直しが要る。

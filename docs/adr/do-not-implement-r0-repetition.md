# 日本中将棋連盟式の千日手（R0）を実装せず、既定の反復規則をR1にする

## ステータス

承認済み。決定日は2026年8月9日。

## コンテキスト

標準規則の千日手は、同一局面が4回現れる前に反復を仕掛けた側が手を変える義務を負う規則であり、RULES.md第31条にR0として収録されている。
仕掛けた側は、連続王手、利きを当てる着手、同じ手順、およびじっとの優先順位で決まる（R0第2項）。
これらの文言は対人の運用を前提としており、プログラムで裁定するには条文にない解釈を補う必要がある。
[対局管理層の設計](../plans/archived/game-referee.md)は、R0を規則コードとして受理しつつ対局の構築時に未対応として拒否した。
[合法手生成器の総仕上げ](../plans/archived/movegen-hardening.md)は、4回目の同一局面の検出だけを報告し、仕掛けた側の決定と敗北の裁定を呼び出し側に委ねる部分実装を加えた。
[審判ロジック再編](../plans/archived/adjudication-refactor.md)は、この部分実装を含めてR0の扱いを見直した。

## 決定

R0をRustの型、規則コード、状態、分岐、および公開APIのいずれでも表現せず、規則の本文と典拠はRULES.mdに記録として残す。
対局を始めるにはR1、R2、またはR3のいずれかを明示しなければならず、R0の別名や他の反復規則への暗黙の置き換えは設けない。
エンジンの既定の規則セットは、反復規則にR1を採る。

## 検討した代案

条文に解釈を補ってR0を裁定する案は、RULES.mdが定めていない規則をコードが発明することになるので採らなかった。
R0を規則コードとして受理し、対局の構築時に未対応として拒否する案は、選べない規則を型に残すだけなので採らなかった。
4回目の出現を検出して報告するだけの部分実装は、終局の判断を呼び出し側へ押し付け、規則としての意味を持たないので撤去した。

## 結果

標準規則をそのままの形では対局に使えず、規則セットの指定では反復規則を常に明示する必要がある（RULES.md第33条第4項）。
既定にR1を選んだのは、Lishogiの規則ライブラリscalashogiという照合できる参照実装があり、裁定の実装を検証できたからである。
当時のR2には照合できる参照実装がなく、R0は実装しないので、既定にできる反復規則はR1だけだった。
R0を将来実装するには、仕掛けた側の決定に要る解釈をRULES.mdで先に確定する必要がある。

# 置換表の行を先読みしない

## ステータス

承認済み。決定日は2026年9月17日。

## コンテキスト

[第2期の高速化の起案時の診断](../measurements/movegen-speedup-2-diagnostics-depth5.md)では、置換表の照合が探索中の自己時間の13.9%を占める最大の項目だった。
照合は1ノードあたり約58ナノ秒で、DRAMの遅延に相当する。
この待ちを隠す方法として、着手を適用した直後に子局面の置換表の行をプリフェッチ命令で読み込み、照合までの間に取得を済ませる方式が考えられた。
minaseのエンジンとライブラリはworkspaceのlintで`unsafe_code = "forbid"`を定めている（[`unsafe`は学習器のクレートだけに許す](allow-unsafe-only-in-the-trainer-crate.md)）。
`_mm_prefetch`は`#[target_feature]`つきの関数なので、呼び出し側に`unsafe`を要する。
[合法手生成と利き計算の高速化（第2期）](../plans/movegen-speedup-2.md)では、この制約の下で置換表の待ちを減らす方法を検討した。

## 決定

置換表の行の先読みを実装しない。
エンジンの開発者は、`unsafe`を許可しないと決めた。
置換表の待ちは、探索木を変える変更で照合の回数そのものを減らす方向で扱う。

## 検討した代案

`unsafe_code`を緩めて`_mm_prefetch`を着手の適用の直後に置く試作は、局面別の探索結果が一致し、NPSの比は1.026倍から1.029倍だったが、`unsafe`を許さない決定により採らなかった。
`unsafe`なしでは、ラッパー関数を経由してもコンパイルできなかった（rustc 1.98.0）。
着手の適用の直後に子局面の行を通常の読み込みで先に読む方式は、[第1期の単位Eの記録](../measurements/movegen-speedup-unit-e-bench-depth5.md)で一貫した差がなかった。
通常の読み込みは値が届くまで後続の命令を止めるので、非同期のプリフェッチ命令でなければ待ちを隠せない。
置換表の既定の容量を3次キャッシュに収まる大きさへ下げる案は、対局条件そのものを変えるので扱わなかった。

## 結果

置換表の照合の待ちは、探索木を変えない高速化では残る負荷として扱う。
照合の回数を減らす変更は、[静止探索で置換表の照会より先にstand-patと候補の有無を判定する](check-tt-after-stand-pat-and-trim-lion-captures-in-qsearch.md)決定で採用した。
再提案は、`unsafe`を禁じる決定を見直す場合に限られ、その場合も現行の評価関数と置換表で速度を測り直す必要がある。

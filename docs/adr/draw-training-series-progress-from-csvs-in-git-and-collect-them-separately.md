# 学習の系列の進捗図は、gitに置くCSVから描き、記録からCSVを作る収集と、CSVから図を描く作図を別の操作にする

## ステータス

承認済み。決定日は2026年11月16日。

## コンテキスト

学習の系列の進捗図は、固定の相手に対する強さ、方策と価値の損失、固定の検証用データによる診断、1局の手数、および自己対局の終わり方の割合を、横軸を揃えて縦に並べた1枚の画像である（[学習の系列の記録と進捗図の設計書](../plans/archived/training-series-records.md)）。
図の元になる値は、3か所に分かれている。
サイクルごとの生成と学習の統計は、強化学習の実行器`minase_zero run-cycles`が、NASの系列の記録（1サイクル1行のJSON）に書く。
固定の相手に対する強さの値は、測定記録の付随ディレクトリにある集計`summary.json`にあり、固定の検証用データによる診断の値は、診断の道具`minase_zero external-eval`が書くJSONにある。
系列の記録は、1回目の強化学習の32サイクルで27 MBあり、サイクルごとに増えるので、gitに置くには大きい。
1回目の系列の記録は、記録の欄を改める前の形式で書かれており、今の実行器が書く記録とは欄の名前が違う。

## 決定

進捗図の元になる値は、gitで管理する系列ごとのディレクトリに置く3つのCSV（`cycles.csv`、`strength.csv`、`validation.csv`）とする（2026年11月16日のエンジンの開発者の決定）。
道具`tools/train/progress/series_progress.py`の`collect`が、系列の定義`series.toml`が指す集計と診断のJSON、および引数で渡した系列の記録を読んでCSVを書き、`plot`がCSVだけを読んで進捗図を描く。
この道具は、依存パッケージをロックファイルで固定した、独立したPythonの環境に置く。
1回目の強化学習の系列の`cycles.csv`は一度限りの変換で作り、道具には今の実行器が書く欄だけを読ませる。

## 検討した代案

NASの系列の記録から直接図を描く案は、NASにつながらない場所で図を作り直せないので採らなかった。

系列の記録そのものをgitに置く案も採らなかった。
1回目の32サイクルで27 MBあり、サイクルごとに大きくなる一方で、図に使うのはそのうちの一部の欄だけである。

学習の指標を表示するTensorBoardを使う案は採らなかった。
NASも表示用のサーバーも使わずに、gitにあるファイルだけから共有用の画像を作り直す用途には、TensorBoardが前提とする構成が大きすぎる。

作図の依存パッケージを、学習器と実行器のPythonの環境（`tools/train/zero`）に足す案も採らなかった。
この環境は借りた計算機にも導入するので、そこでは使わない作図の依存パッケージまで入る。

1回目の系列の記録にある古い欄名の読み替えを道具に持たせる案は、使い終えた形式との互換のためだけのコードを残すことになるので採らなかった。

## 結果

進捗図は、gitにあるファイルだけから、`plot`で作り直せる。
CSVの列の定義と、系列の記録のどの欄からどの列を作るかは`series_progress.py`のdocstringが定め、形式の一覧は[ファイル形式の手引き](../guides/file-formats.md)の「学習の系列の記録」の節にある。
CSVに列を足すときは、docstringの定義と`collect`を同時に改める。
2026年11月16日に、2回目の強化学習の系列`cycles-rl2-az`のサイクル1〜3の記録から`collect`で作った`cycles.csv`の全列が、記録の欄から別に計算した値と一致することを確かめた（[最初のセッションの記録](../measurements/alphazero-rl-2/alphazero-rl-2-first-session.md)）。
収集と系列のページの更新の手順は、[深層強化学習を回す手引き](../guides/alphazero-training.md)の「定例の測定を行う」の節にある。

# NNUEの学習は、エポックの最後に残る1バッチ未満の局面を、そのエポックでは学ばない

## ステータス

承認済み。決定日は2026年11月23日。

## コンテキスト

NNUEの学習器は、エポック（訓練局面をひととおり学ぶ期間）ごとに訓練局面の全体を並べ替え、`--batch`の局面数（標準は16,384）ずつ区切って重みを更新する（[並べ替えのADR](shuffle-the-whole-training-set-per-epoch-with-rao-sandelius-buckets.md)）。
訓練局面数が`--batch`で割り切れないと、エポックの最後に`--batch`に満たない端数バッチが残る。
これまでの学習器は、端数バッチでも勾配をそのバッチの局面数で平均し、通常のバッチと同じ1回の更新を行っていた。
局面が少ないほど勾配の向きは不正確になるが、最適化手法のAdamWは勾配の大きさで更新を割るので、不正確な向きのまま通常の大きさの更新になる。

[診断の測定](../measurements/adhoc/nnue-early-stop-diagnosis.md)では、端数バッチを172局面と5局面にした学習で、直後の12更新のあいだ、訓練に使わない対局で測った誤差（検証損失）が2.4〜4.9%大きくなった。端数バッチが8,036局面の対照では、変化は揺れの範囲だった。
王の位置を使わない入力P型のネットの世代反復（前の世代のネットで教師を生成して次の世代のネットを学ぶ反復）の第2世代の学習は、各エポックの端数バッチが363局面であり、約1.0エポックと約2.0エポックの時点の検証が、それぞれ端数バッチの4更新後と8更新後に当たったので、その2点の検証損失だけが約3%大きかった。
当時の標準レシピは検証損失で学習を止める時点を決めていたので、この跳ねは停止の判定にも入り込む。

## 決定

間引き後の訓練局面数をM、`--batch`の局面数をmとして、1エポックの更新回数をfloor(M÷m)（小数点以下の切り捨て）とし、並べ替えた訓練局面の先頭からその回数だけ、ちょうどm局面ずつで更新する。残った端数の局面は、そのエポックでは学ばない。
Mがmに満たない教師は、学習を始める前にエラーにする。

## 検討した代案

- **次のエポックの局面で満杯にする、または端数を次のエポックへ繰り越す**。先行のNNUEの学習器（bullet、nnue-pytorch、tatara、BulletOu、variant-nnue-pytorch）は、教師を末尾から先頭へ読み続けて満杯にする。minaseの学習器は、エポックの番号とエポックの中の位置から並びを作り直して再開するので、境界のバッチが2つのエポックに属すると、再開のたびに2つの並びを作り直す処理が要る。先行の学習器は、進み具合を固定のバッチ数で数え、並びを再現して再開する仕組みを持たないので、この処理が要らない。
- **端数バッチの勾配を、その局面数ではなくmで割る**。更新は小さくなるが、AdamWが持つ勾配の移動平均に、向きの不正確な勾配が入ることは防げない。
- **検証の時点を端数バッチの直後からずらす**。不正確な更新そのものが残る。

## 結果

どの更新もちょうどm局面で行われ、エポックの境界で検証損失が跳ねなくなった（[確認の記録](../measurements/nnue-decay-to-end/nnue-decay-to-end-trainer-check.md)）。
捨てる局面は1エポックあたりm局面未満であり、世代反復の第1世代では2,584局面（訓練局面の0.0027%）である。並びはエポックごとに変わるので、同じ局面が捨てられ続けることはない。
1エポックの更新回数は、`config.json`の`preprocessing.updates_per_epoch`に記録される。学習器は再開のときに前処理の欄の全体を照合するので、この値を持たない、修正前の学習器が書いた出力からは再開できない。
minaseのAlphaZero型の学習器も、囲碁のエンジンKataGoにならって端数を捨てており、2つの学習器の扱いがそろった。
NNUEより前の評価関数であるPST（駒と升ごとの点数の表）とFM（2駒の関係を補う因子分解機）の学習器は、1エポックの更新回数を切り上げで数えたままである。どちらも現行のエンジンの評価関数の学習には使っていない。

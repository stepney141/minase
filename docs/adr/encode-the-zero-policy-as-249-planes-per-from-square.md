# AlphaZero型探索のネットの方策は、移動元の升ごとに249種類の移動を割り当てた35,856要素で表す

## ステータス

承認済み。決定日は2026年10月27日。

## コンテキスト

ネットの方策の出力は、各合法手に1つの値（logit）を対応させる必要があり、自己対局の方策の教師、学習器の損失、および探索の事前確率がこの対応を共有する。
minaseの着手は正準形`Move { from, mid, to, promote }`で表され、空いた中継升を通る2段階移動は同じ到達升への直接の跳びと同じ値に正準化される（`crates/minase-core/src/mv.rs`）。
中継升を持つ着手は、第1段階で相手駒を取る2歩と居喰いだけである。
AlphaZeroとlc0は、方策を移動元の升ごとの面として畳み込みで出力する。
中将棋エンジンHaChuは、2段階移動を第1歩の方向と第2歩の方向の組で符号化する。
決定の経緯は[ネットの入出力と推論の設計書](../plans/archived/alphazero-network.md)にある。

## 決定

方策の出力は、移動元の升144個のそれぞれに249種類の移動を割り当てた249面、計35,856要素とする。
249種類は、中継升のない直線上の移動が8方向と距離1〜11で88種、その成りで88種、獅子の桂馬型の跳びで8種、第1段階で取って別の升へ進む2歩が第1歩の8方向と第2歩の7方向で56種、居喰いが8種、およびじっとの1種である。
居喰いは隣の相手駒を取って元の升へ戻る着手、じっとは空いた隣の升へ進んで元の升へ戻る着手である（RULES.md第3条）。
後手番では入力と同じく盤を180度回転して符号化する。
ラベルは着手の値だけから盤面なしに計算する。
評価器は、ネットの出力のうち依頼された合法手のラベルの位置の値だけを取り出す。
方策は、取り出した値だけをsoftmaxで正規化して求め、非合法手には確率を割り当てない。

## 検討した代案

移動先を基準にして距離3以上をまとめる121面の案は採らなかった。
出力は半分になるが、ラベルから元の着手を復元するには盤面が要る。
出力層は128チャネルから249チャネルへの1×1畳み込みで1局面あたり約460万積和であり、10ブロック128チャネルの本体の約4.4億積和の約1%なので、面を半分にしても推論の速さはほとんど変わらない。

2段階移動の第1段と第2段を分けて出力する案は採らなかった。
中間の節点で付け喰い（RULES.md第16条）を含む合法性を保証する必要があり、初版の負担に見合わない。

すべての着手の形を通し番号で並べる平坦な列挙は採らなかった。
移動元の升ごとの面にすれば、出力層は1×1畳み込み1つで済み、AlphaZeroとlc0の方策出力と同じ型になる。

## 結果

ラベルは着手の値だけから決まるので、単射性、ラベルから着手への逆写像、および後手番の回転の一致を、盤面を用意せずに性質試験で確かめられる。
2歩系の64種がHaChuの「第1歩方向×第2歩方向」の符号化と同型なので、HaChuとの照合にも使える。
方策の出力はFP32で1局面あたり約143 KBあり、全要素の複写と非有限値の検査はCPUでの処理時間を大きくする。
このため評価器`nn::Evaluator`は合法手のlogitだけを返し、非有限値の検査も取り出したlogitと価値だけに行う。
ラベルの割り当てを変えると学習済みのネットと固定局面集`tools/train/zero/fixtures/nn-positions.jsonl`が使えなくなる。
面の内訳と方向の番号は`crates/minase/src/nn/policy.rs`のdocコメントにある。

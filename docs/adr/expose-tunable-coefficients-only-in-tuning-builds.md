# 調整する係数は調整用ビルドでだけ外から変えられるようにする

## ステータス

承認済み。決定日は2026年9月25日。

## コンテキスト

SPSAは、同じエンジンに係数の異なる2つの設定を与えて対局させるので、エンジンは対局ごとに係数の値を受け取れなければならない。
[SPSAによる探索係数と時間管理係数の調整](../plans/archived/spsa.md)の起案時、探索と時間管理の係数はソースの各所に散らばった定数だった。
先行するエンジンの公開方式は、次のとおり分かれていた。
やねうら王の`tune.py`は、調整の開始時にC++のソースの定数を変数とUSIオプションへ書き換え、終了時に書き戻す（[SPSAの設計書の参考資料](../plans/archived/spsa.md#参考資料)）。
dlshogiは探索係数を常にUSIオプションとして公開し、Viridithasは実行時の構造体に係数を常に持つ（[SPSAの設計書の参考資料](../plans/archived/spsa.md#参考資料)）。
HobbesとakimboはRustのマクロで係数ごとに定数版と調整版の関数を生成し、Recklessは調整版で`static mut`を使う（[SPSAの設計書の参考資料](../plans/archived/spsa.md#参考資料)）。
ワークスペースの`Cargo.toml`は`unsafe_code = "forbid"`を指定している。

## 決定

調整する係数は`crates/minase/src/search/alphabeta/params.rs`の1つの表に定義し、マクロが、通常ビルドでは既定値を返す`const fn`を、cargo feature `tuning`を付けた調整用ビルドでは`AtomicI32`を読む関数を生成する。
調整用ビルドだけが係数を`Tune_<名前>`のUSIオプションとして宣言し、範囲外の値と最初の`go`より後の変更を拒否する。
係数はすべて`i32`とし、小数や倍率は既定値で従来の式と一致する整数表現で持ち、各係数の意味と単位は`params.rs`のdocコメントに従う。

## 検討した代案

ソースへ一時的なパッチを当てる案は、Rustではマクロとfeatureで同じ目的を果たせるので、パッチを当てる道具を別に保守する理由がなく採らなかった。
係数を通常ビルドでもUSIオプションとして公開する案は、通常ビルドの探索でも係数を毎回実行時に読み出すことになり、lishogiのBotやGUIに調整用の設定を数十個見せることになるので採らなかった。
調整版で`static mut`を使う案は、`unsafe`の禁止と両立しないので採らなかった。

## 結果

通常ビルドの係数は定数のままであり、配布とlishogiのBotには通常ビルドだけを使う。
係数から導く値は、`setoption`が確定した後の探索の生成時か使用時に計算する必要があり、USIの入力を読む前に行う評価関数の初期化の時点で計算して保持する形にはできない。
LMRの減深表はプロセス内で1回だけ作るので、最初の`go`より後の変更を拒否しないと表と係数が食い違う。
対局ハーネスは局ごとにエンジンを起動し直し、`isready`の前に`setoption`を送るので、この制約の下でも表は調整値から作られる。
表の既定値は[SPSAの結果の反映のADR](apply-spsa-results-by-rewriting-default-literals.md)の手順で書き換える。

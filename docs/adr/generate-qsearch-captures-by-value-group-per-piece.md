# 静止探索の捕獲は、取る駒の価値の群ごとに駒別の利きから生成する

## ステータス

承認済み。決定日は2026年9月15日。

## コンテキスト

静止探索は捕獲手だけを読む探索の末端であり、ノードの多くは最初の数手でβを超えて打ち切られる。
それにもかかわらず、以前の静止探索はノードごとに全捕獲を生成し、整列してから読んでいた。
[合法手生成と利き計算の高速化](../plans/archived/movegen-speedup.md)の単位Bは、取る駒の価値が高い群から順に生成し、打ち切られたノードでは後の群を生成しない段階生成を試した。
通常駒の捕獲の生成方式として、自駒ごとの利きと、取る駒がある升の集合（対象升）の積を取る駒別生成と、対象升から取り手を逆引きする方式を比べた。
[単位Bの測定記録](../measurements/movegen-speedup/movegen-speedup-unit-b-bench-depth5.md)では、探索木の一致を確かめるために静止探索の手順だけを小さく変えた照合参照コミットに対する速度比は、群ごとに通常駒を全走査する初版で1.159倍、利きをノードごとに1回だけ求める駒別生成で1.328倍、同じ状態で逆引きにした版で1.190倍だった。
駒価値の順位を前計算して群の構築から整列と線形探索を除いた版は1.501倍で、局面別の探索結果はいずれも一致した。

## 決定

静止探索の捕獲は、取る駒の価値の群の降順に段階的に生成し、通常駒の利きはノードの初期化で1回だけ求めて保持し、各群では群の対象升との積だけを出力する。
特殊駒（獅子、角鷹、飛鷲）は経由升でも取るので、専用の経路で生成する。
置換表の手は先頭に返し、他の手の相対順序は変えない。

## 検討した代案

対象升から取り手を逆引きする方式は、打ち切りが起きないノードで全群の対象升を逆引きするので、駒別生成より遅く採らなかった。
対象升が少ないノードだけ逆引きに切り替える混成方式は、決定の翌日の2026年9月16日に、[第2期の段階3の測り直し](../measurements/movegen-speedup-2/movegen-speedup-2-stage3-counts.md)の試算に基づいて着手しないと決めた。
逆引きは対象升1升でも走りの計算だけで8回を要し、対象升が1升のノードの現行の走査（利きと走りの計算の合計0.82回）を上回ったからである。
置換表の手を先頭の手と入れ替える以前の方式は、整列で先頭にあった手を置換表の手の位置まで降格させ、段階生成ではその順序を再現できないので採らず、他の手の相対順序を保ったまま置換表の手を先頭へ移す回転に改めた。

## 結果

公開の捕獲生成の着手集合と順序は変わらず、通常駒の探索専用の生成は対象升に絞った公開生成の部分列と一致する。
静止探索の候補は、後にそこから獅子の一部の捕獲を除いた（[静止探索は置換表の照会より先にstand-patと候補の有無を判定する](check-tt-after-stand-pat-and-trim-lion-captures-in-qsearch.md)）。
回転は列の操作としては実装せず、`QsearchBuffers::next`が置換表の手を先に返し、群の中の同じ手を飛ばすことで同じ順序を作る。
回転は探索木を変え、[回転の測定記録](../measurements/movegen-speedup/movegen-speedup-rotation-bench-depth5.md)では深さ5の15局面のノード数の差は0.016%だった。
段階化はノードごとの固定費を生むので、件数の削減率から速度を見積もらない（[段階生成の固定費の教訓](../lessons/staged-generation-fixed-cost.md)）。
群の中の順序には後に捕獲履歴を使うようになった（[捕獲履歴の寄与を歩兵価値の定数倍に抑え、静止探索の順序にも使う](bound-capture-history-and-use-it-in-qsearch.md)）。
測定は評価関数がNNUEへ置き換わる前のものであり、逆引きを再提案するには現行の評価関数で測り直す必要がある。

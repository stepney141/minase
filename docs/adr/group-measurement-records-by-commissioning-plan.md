# 測定記録は測定を計画した設計書ごとのディレクトリに置き、凍結した文書の中でもリンクのパスだけは書き換える

## ステータス

承認済み。決定日は2026年10月18日。

## コンテキスト

docs/measurements/ には、棋力測定、速度測定、学習、および診断の記録が1測定1ファイルで411件あり、記録に付随する生データや再現用スクリプトを入れたディレクトリ42個と同じ階層に並んでいた。
記録は2026年9月に249件、10月には18日までに119件増え、ある設計書のもとで行った測定をディレクトリの一覧から拾い出すことが難しくなった。
記録はADRと凍結した設計書の根拠であり、ADRが参照する記録だけで195件あるので、記録を削って一覧を短くすることはできなかった。

配置を変えると、docs/measurements/ の記録、docs/adr/ のADR、docs/plans/archived/ の完了した設計書、および docs/audits/ の監査報告から記録へのリンクが切れる。
これらの文書は、作成後に本文を書き換えない規則を持つ。
ただし、[ADRの不変性](README.md#不変性)はリンク切れの修正を例外として認め、[設計書の書き方](../plans/README.md#完了時の移し替えと凍結)は、凍結した設計書を docs/plans/archived/ へ移すときに、その設計書を指すリンクを書き換える手順を定めている。
再配置の手順と、書き換えたリンクが移動前と同じファイルを指すことの検証は、[測定記録の再配置の設計書](../plans/archived/measurements-layout.md)にある。

## 決定

記録は、その測定を計画した設計書のファイル名から`.md`を除いた名前のディレクトリ`docs/measurements/<設計書名>/`に置き、どの設計書も計画していない測定だけを`docs/measurements/adhoc/`に置く。
測定名は変えず、付随ディレクトリは記録と同じディレクトリに置き、一度置いた記録は設計書が完了しても動かさない。
この再配置では、凍結した文書の中でもリンクの参照先とリンクの表示文字列に書かれたパスだけを書き換え、本文中のパスと、`<コミット>:docs/measurements/...`の形でコミットを添えた参照は、記録した時点の場所として残す。この例外は、2026年10月18日にエンジンの開発者が認めた。

## 検討した代案

測定の種類（STC、LTC、bench、診断）ごとに分ける案は、ファイル名の接尾辞と重複し、1つの設計書の記録が散らばるので採らなかった。
月ごとに分ける案は、記録を日付で探す読み手がいないので採らなかった。
探索、NNUE、合法手生成のような対象領域ごとに分ける案は、新しい記録のたびに境界の判断が要るので採らなかった。
索引ファイルを加える案は、更新漏れが起こり、索引ファイルを作らない規則にも反するので採らなかった。

測定名から、ディレクトリ名と重なる接頭辞（`strength-stage6-`など）を外す案は採らなかった。
接頭辞を外すと、別々の設計書のディレクトリに同じ測定名が現れ得るが、実行ディレクトリ`data/matches/<測定名>/`は階層を持たないのでそれらを区別できず、記録と実行ディレクトリを突き合わせられなくなるからである。
完了した設計書の記録を archived/ の層へ移す案は、設計書が完了するたびに記録のパスとリンクが変わるので採らなかった。
同じ記録を参照する設計書ごとに複製やシンボリックリンクを置く案は、どれが正か分からなくなるので採らなかった。

凍結した文書のリンクを書き換えない案は、ADRと凍結した設計書から記録へのリンクが切れるので採らなかった。
本文中のパスまで書き換える案は、コミットを添えた参照や当時の実行コマンドを、当時のコミットに存在しないパスに変えてしまうので採らなかった。
旧パスに転送用のファイルを残す案は、411個のファイルが直下に残り、再配置の目的に反するので採らなかった。

## 結果

ある設計書のもとで行った測定は、docs/measurements/ 直下にあるその設計書の名前のディレクトリを開けば一覧できる。
新しい記録を書く人は、測定を計画した設計書を1つ決めれば置き場所が決まる。
設計書を起案する前に行った測定は adhoc/ に置くので、ある設計書に属させたい測定は、先に設計書を起案してから行う必要がある。
置き場所の規則は、[設計書の書き方](../plans/README.md)の「測定記録」節が定める。

凍結した文書の書き換えは、この再配置に限って認めた例外であり、凍結の規則そのものは変えない。
付随ディレクトリのスクリプト、パッチ、および JSON は、記録した時点の作業ツリーを前提に書かれているので、内容を変えずに移した。
例えば magic-bitboard-prototype/reproduce.py は自分の位置から2段上をリポジトリの根とみなすので、移動後の位置からは正しく動かない。
これらを再実行するときは、再配置の直前のコミット eaaec86e を取り出して実行する。

masterに統合していないブランチのうち12本は、docs/measurements/ に記録を追加または変更している。
これらのブランチをmasterへ統合するときは、統合のコミットの中で、直下に置かれた記録をこの決定に従って移し、ブランチで追加または変更した文書のリンクと本文中のパスを書き換える必要がある。

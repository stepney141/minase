# 評価ネットをHugging Face Hubのモデルリポジトリへ置き、NNUEの公開名にやねうら王に倣った構造名を入れる

## ステータス

承認済み。決定日は2026年11月25日。

## コンテキスト

αβ探索のNNUEとPV-MCTSのONNXネットは、どちらも実行ファイルに埋め込まない。エンジンは、USIオプション`EvalFile`または`NnModel`で指定した外部ファイルを読む（[EvalFileでのNNUE読み込みのADR](search-with-an-evalfile-nnue-whose-structure-is-chosen-on-load.md)）。
2026年11月21日の[前のADR](archive/host-evaluation-networks-on-hugging-face-hub.md)では、ネットの公開先をエンジンのGitHubリリースからHugging Face Hubのモデルリポジトリ`stepney141/minase-nets`へ移し、公開名を`minase-<方式>-<構造>-<規則>-<YYYYMMDD>-<SHA256先頭8桁>.<拡張子>`と定めた。
このうちNNUEの`<構造>`には、P型なら`p`、HalfKP_vmなら`halfkp`として、入力特徴集合の種類だけを書いていた。
一方でエンジンは、第1層の片側の幅（1つの視点の第1層の出力の数）をネットの読み込みのときにファイルから決めるので、同じP型でも幅の違うネットが同じ`<構造>`で並びうる。
PSQTの有無と後段の層の出力数も、ファイル名からは分からなかった。

将棋のNNUEでは、ネットの構造を短い名前で書く慣習がある。
やねうら王は、2視点の出力を連結する通常のNNUEを`halfkp_256x2-32-32`や`halfkpvm_256x2-32-32`のように`<特徴>_<片側の幅>x2-<第1隠れ層>-<第2隠れ層>`の形で書く（[architecturesの一覧](https://github.com/yaneurao/YaneuraOu/tree/a7a683b536de491d5f956f42dfca823a19c9ea03/source/eval/nnue/architectures)）。
やねうら王は、2視点の出力の要素ごとの積を後段へ渡すStockfish型のネット（SFNN）を、`SFNN_halfka2_1024_7_64_k3k3`のように先頭に`SFNN`を付けて書く。SFNNの名前に`x2`を付けないのは、2視点を連結しないからである。
やねうら王のSFNNの名前に書く第1隠れ層の値は、出力のうち後段の層を飛ばして出力へ直接足すskip出力の1つを除いた数であり、出力16のうち1つをskip出力にする層を15と書く。
将棋のNNUEの学習器tataraの作者が開発しているエンジンrshogiは、`layerstacks-halfka_hm_merged-1536x16x32-psqt`のように次元を`x`でつなぎ、skipを含めた出力数を書く。
Stockfishは、ネットを`nn-<SHA256先頭12桁>.nnue`と名付け、構造を名前に入れない。

minaseのネットはtataraの形式であり、ファイルの先頭の構造記述に、入力特徴集合の名前、片側の幅、PSQTの有無、および後段の各層の出力数を持つ。
P型はtataraのLayerStack構造で、2視点の要素ごとの積、二乗の切り詰め、および第1隠れ層のskip出力を持つSFNN型である。
HalfKP_vmはtataraのSimple構造で、2視点を連結する通常のNNUEである。

## 決定

評価ネットはこれまでどおりエンジンの版数から分離して、Hugging Face Hubのモデルリポジトリ`stepney141/minase-nets`に、`minase-<方式>-<構造>-<規則>-<YYYYMMDD>-<SHA256先頭8桁>.<拡張子>`の名前で置く。
NNUEの`<構造>`はやねうら王の書き方に倣い、ファイルの構造記述から機械的に決まる`[sfnn_]<特徴>_<片側の幅>x<第1隠れ層の出力数>x<第2隠れ層の出力数>[_psqt]`とする。
たとえば片側の幅が256のP型は、SFNN型なので`sfnn_`を付け、PSQTを持つので`_psqt`を付けて、`sfnn_p_256x16x32_psqt`と書く。片側の幅が256のHalfKP_vmは`halfkpvm_256x32x32`と書く。
学習と測定に使うネットワーク接続の記憶装置（NAS）の内部保管名は、既存の測定記録とスクリプトとの互換性を保つため、`<64桁SHA-256>.bin`のまま変えない。

## 検討した代案

ネットをエンジンの`vX.Y.Z`のGitHubリリースに添付する案と、ネット専用のタグ`net-*`のGitHubリリースに添付する案は、前のADRで採らなかった。
前者は、コードに変更がなくても強いネットができるたびにエンジンの版数を上げる必要があり、後者は、コードリポジトリのリリース一覧に大きな重みが混ざり、1ファイル2 GiBの上限を受けるからである。
この判断は本ADRでも変えない。

やねうら王の名前をそのまま使い、P型を`sfnn_p_256_15_32_psqt`、HalfKP_vmを`halfkpvm_256x2-32-32`と書く案は、区切りが`_`と`-`と`x`の3種類に分かれて読みにくいので採らなかった。
また、ファイル名の項目の区切りに使う`-`が構造名の中にも現れ、項目の境目が分かりにくくなる。

第1隠れ層の値に、やねうら王と同じくskip出力を除いた15を書く案は、ファイルの構造記述にある`AffineTransform[16<-512]`の出力数16と値が合わなくなるので採らなかった。
skip出力を`15+1`のように別に書く案は、tataraのLayerStackが必ずskip出力を1つ持つので情報が増えないうえ、名前が長くなるので採らなかった。

rshogiのように`layerstacks`や`simple`のような構造の種類を先頭に書く案は、tataraの内部の呼び名をファイル名に持ち込むので採らなかった。
SFNN型を表すには、やねうら王と、tataraのやねうら王形式への変換の両方で使われている`sfnn`のほうが、将棋のNNUEを扱う利用者に通じやすい。

Stockfishと同じく構造を名前に入れない案は、利用者が単体でダウンロードしたファイルの構造を、エンジンに読ませるまで判別できないので採らなかった。

前のADRの名前で公開済みだった2本のネットを、そのままの名前で残す案は、モデルリポジトリの中で2つの命名規則が混ざるので採らなかった。
この2本は2026年11月25日に、モデルリポジトリの1回のコミットで新しい名前へ付け替えた。
それより前のリビジョンを固定したURLは、古い名前のまま引き続き使える。

## 結果

単体で保存したファイルの名前から、入力特徴集合、SFNN型かどうか、片側の幅、第1隠れ層と第2隠れ層の出力数、PSQTの有無、規則セット、作成日、およびSHA-256の先頭8桁が分かる。
構造名の各値は構造記述と一対一に対応するので、公開の前に構造記述と照らして名前を確かめられる。
一方で、やねうら王を使い慣れた利用者は、SFNN型の第1隠れ層の値がやねうら王の値より1大きいことに注意する必要がある。
エンジンはファイル名ではなくファイル全体のSHA-256でネットを識別するので（[SHA-256による識別のADR](identify-nnue-networks-by-the-sha256-of-the-whole-file.md)）、公開名を付け替えても照合の仕組みは変わらない。
構造名の書き方、ディレクトリ構成、モデルカードの記載項目、および公開の手順は、[リリースの手引き](../guides/release.md#評価ネットの公開手順hugging-face-hub)にある。

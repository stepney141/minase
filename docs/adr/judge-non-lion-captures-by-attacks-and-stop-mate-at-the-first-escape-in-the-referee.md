# 審判層は獅子でない駒の捕獲可能性を利きの逆引きで判定し、合法手なしと詰みを駒ごとの生成で最初の逃れる手で打ち切る

## ステータス

承認済み。決定日は2026年10月28日。

## コンテキスト

[MCTSは新しい節点を審判層の裁定で終局させる決定](adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)により、MCTSの探索木は新しい節点を作るたびに、根の`Game`の複製に経路の着手を`Game::play`で順に適用するようになった（以下、この適用を再生という）。
その[測定](../measurements/alphazero-audit-remediation/alphazero-audit-remediation-driver-cost.md)では根の探索時間の中央値が自己対局用のGumbel AlphaZeroの32回の探索で0.094 msから0.555 msへ増え、プロファイルでは`Game::play`が探索の命令数の93.9%を占めた。
`Game::play`は、着手の合法性検査、反復規則R1（RULES.md第31条、攻撃的着手を続けた側を負けとするLishogi式の4回反復の裁定）の攻撃的着手の判定、合法手なしの判定、および詰み判定で合法手の全件生成を繰り返し、再生1手につき約10回の全件生成に当たる費用がかかっていた。
このうち詰み判定は、逃れる手が見つかるまで候補手を1つずつ仮に指し、そのたびに相手が最後の王駒を取れるかを全件生成で調べていた。
一方、`Position::gives_check`は、王駒1枚の場合の王手を、合法手生成ではなく王駒の升への疑似利き`Position::attackers_to_by`で判定しており、乱数局面での合法手生成との一致が試験で固定されていた。
将棋エンジンのやねうら王は、探索の中で合法手の全件生成を避け、1手の合法性を全件生成との照合ではなくその1手だけで調べ、王手の有無を利きの逆引き（王駒の升へ利いている駒を調べる処理）で求める（[調査メモ](../research/yaneuraou-check-detection-for-referee.md)）。
エンジンの開発者は、[審判層の裁定が繰り返す合法手生成の削減の設計書](../plans/referee-adjudication-movegen.md)でこの決定を下した。

## 決定

相手の駒が獅子でない升について、その升へ手番側の疑似利きが届くことと、その駒を取る合法手があることは一致する。
審判層の判定は、この升ごとの補題を使う。
補題が成り立つのは、獅子の捕獲制限、先獅子、および付け喰い（RULES.md第14条から第16条）が獅子を取る手だけに適用され、既出局面の再現を禁じる反復規則R2とR3は、局面を再現し得ない捕獲手に適用されず、中将棋では自分の王駒の安全が着手を制限しない（第8条第3項から第5項）からである。
この補題により、最後の王駒が1枚の場合の捕獲可能性、いずれかの王駒の捕獲可能性（駒枯れの引き分けと裸玉の裁定）、およびR1の攻撃的着手のうち王駒の条件を、王駒の升ごとの`attackers_to_by`の論理和で判定する。
王将または玉将と、太子の計2枚が残る場合の「残存王駒をすべて1手で取れるか」は、1手で両方を取る合法手が要るので、全件生成で判定する。

捕獲先が獅子になり得る判定では、補題を使わず、関係する駒1枚の合法手生成で判定する。
着手の合法性検査は動かす駒1枚の合法手との照合、R1の攻撃的着手のうち動かした駒の条件はその駒1枚の捕獲手の生成、駒枯れの猶予（第22条第5項）は王駒だけになった側の王駒1枚の生成で行う。
詰み判定の候補手ごとに行うR1の攻撃的着手の判定は、反復の裁定が実際にその値を参照する場合だけ計算する。
合法手なしの判定と詰み判定は1回の走査にまとめ、手番側の王駒、王駒へ疑似利きを持つ相手駒の升へ疑似利きが届く駒、残りの駒の順に駒ごとに生成し、最初の逃れる手（詰みでは終局しない終局規則E1では、反復規則で禁止されない最初の合法手）で打ち切る。

## 検討した代案

全件生成を維持する案は採らなかった。
再生1手あたり約10回の全件生成は、探索木の経路が深くなるほど積み上がり、裁定の結果を変えずに減らせるからである。

王駒が2枚の場合も疑似利きで近似する案は採らなかった。
1手で両方を取るには獅子の2枚取りか角鷹または飛鷲の2段階の捕獲が要り、その合法性は升ごとの補題では決まらないからである。

R1の攻撃的着手の2つの条件をまとめて疑似利きで判定し、動かした駒が取れる相手駒が獅子だけの場合に全件生成へ戻す案は採らなかった。
動かした駒1枚の捕獲手の生成は、獅子の捕獲制限と先獅子の状態を含めて全件生成の中のその駒の捕獲手と一致するので、場合分けを増やさずに正確に判定できるからである。

駒枯れの猶予を疑似利きで判定する案は採らなかった。
駒枯れの余分な駒（王駒以外に1枚だけ残った駒）は獅子であり得て、王駒だけの側の王駒がその獅子に疑似利きを持っていても、先獅子（第15条第1項）のために取れない局面があるからである。

合法性の検査を省いて審判の状態だけを進める軽いAPIは、[MCTSの節点を審判層で裁定する決定](adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)が定めた条件（GPUの試走で1サイクルの時間が予算に収まらず、再生の費用が主因だと確かめられた場合）を満たしていないので、本決定には含めなかった。
本決定は合法性の検査を省かず、生成する駒を動かす駒1枚に減らすだけである。

`Game`に合法手列を保持して葉の`Game::legal_moves`にも使う案は、本決定に含めなかった。
設計時点のプロファイルでは葉の`legal_moves`は探索の命令数の約3%であり、状態を増やす割に効果が小さいと見込んだからである。

やねうら王の王手回避の生成のように、詰み判定の候補を王駒の移動、攻撃駒の捕獲、および合駒に限る案は採らなかった。
中将棋の詰みの定義（第21条第3項）は、即時の勝ちと引き分けを生じる着手と、相手の最後の王駒を先に取る着手も逃れる手に数えるからである。
そのため候補の集合は全件のまま、生成の順序だけを変えた。

駒ごとの生成を`MoveGenerator::generate_moves`と同じ駒種順で行い、上の3つの群に分けない案は採らなかった。
同じ109局面の測定で、3つの群に分けると、群を求める利きの逆引きの分だけ序盤では3〜5%遅くなった。
しかし王駒の捕獲の近傍では、詰み判定で試す候補手が再生1手あたりGumbelで20.6から1.9へ、PUCTで30.5から2.8へ減り、探索時間が0.56〜0.62倍になった。
全局面の合計でも0.87倍（Gumbel）と0.98倍（PUCT）になった。

王駒への利きを局面に付随させて差分更新する方式（やねうら王の`checkersBB`）は採らなかった。
`attackers_to_by`の費用が測定で問題になっていないからである。

## 結果

審判層の裁定の結果は変わらず、MCTSの本番の駆動部の出力とαβ探索の深さ6のbench（`minase dev bench`）の局面ごとの結果は変更の前後で時間の項目を除いて一致した。
本番の駆動部を一様評価器で駆動した109局面の測定では、再生1手あたりに正規化した探索時間の中央値が、序盤で変更前の0.16〜0.23倍、王駒の捕獲の近傍で0.04〜0.05倍になり、探索関数の区間の命令数は66.23 G命令から5.91 G命令になった（[測定記録](../measurements/referee-adjudication-movegen/referee-adjudication-movegen-driver-cost.md)）。
変更後の`Game::play`の費用は、再生1手あたり合法手の全件生成の約0.32回分である。

補題は採用規則の性質に依存する。
獅子でない駒を取る手を禁じる規則、または自分の王駒の安全で着手を制限する規則をローカルルールとして加える場合は、本決定の判定を見直す必要がある。
その場合でも、現行の全件生成による判定を試験の中に複製した参照実装との突き合わせの試験（`crates/minase-core/src/game/adjudication/tests/`）で食い違いを検出できる。

変更後のプロファイルでは、葉の`Game::legal_moves`の全件生成が探索の命令数の37.9%を占める最大の項目になった。
`Game`に合法手列を保持する案を見送った理由（効果が約3%で小さい）は変更後には当てはまらないので、経路の再生の費用を再び減らす必要が生じたときは、この案から検討する。

実装は`crates/minase-core/src/game/adjudication/mate.rs`、`bare_king.rs`、`exhaustion.rs`、`crates/minase-core/src/game/repetition/r1.rs`、および`crates/minase-core/src/movegen/mod.rs`と`checked.rs`にある。

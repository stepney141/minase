# 保存するファイル形式の版は1つにし、実行専用の一時ファイルだけは独自の配置を認める

## ステータス

承認済み。決定日は2026年10月16日。

## コンテキスト

[各ファイル形式の版を1つにし、過去のファイルを読み続けない](archive/keep-one-version-per-file-format.md)は、2026年10月13日に、形式ごとの版を1つにすること、変換コマンドを作らないこと、`MN`で始まる独自形式をエンジンが読む重み（MNUEとMNPT）と学習器が読む教師データ（MNSD）の3つに限ること、および学習器の内部だけで使うファイルにはNPZとJSONを使うことを定めた。
その後、[メモリより大きい教師データの一様シャッフル](../plans/archived/out-of-core-shuffle.md)は、NNUEの学習器が教師データMNSDを再生して得た局面を、その学習の実行だけが読み書きする一時ファイルへ書き出し、エポックごとにbucket（区画）へ振り分けて並べ替える方式を採った。
一時ファイルは1回の実行の中だけで読み書きされ、実行の終了時に削除される。
一時ファイルの局面の総数は事前に分からないので、局面を追記しながら書く必要がある。
NPZの中の配列NPYは配列の形をヘッダに持つので、追記した後にヘッダを書き戻す処理を学習器のNPZの書き出し処理に加えなければ、追記しながら書けない。
また、一時ファイルを別の実行の入力に使うことや、保存して再利用することは、派生ファイルを2つ目の保存形式として持つことに等しく、[学習時の局面の並べ方の予備測定](../measurements/shuffle-order-preliminary.md)の後に設計書が棄却した案である。

## 決定

保存するファイル形式についての先の決定を、そのまま維持する。
各形式の版は1つだけにし、読み手は現行の配置だけを受け付け、変換コマンドを作らない。
`MN`の独自形式はMNSD、MNUE、MNPTの3つに限り、学習器が保存するチェックポイントや設定にはNPZとJSONを使う。

これに加えて、1つの実行だけが読み書きし、その実行の終了時に削除する一時ファイルには、保存形式の規則を適用しない。
一時ファイルは、実行ごとに固有の名前の作業ディレクトリに作り、版番号も識別子も持たせない。
配置の仕様は、書き出す側のモジュールのdocコメントに書く。
別の実行の入力として受け付けず、キャッシュとして再利用もせず、強制終了や電源断で残ったものは手動で削除する。
一時ファイルの配置を変えるときは、同じコミットで読み込み側と書き出し側の両方を変える。

## 検討した代案

一時ファイルもNPZで書く案は、追記しながら書くためにNPZの書き出し処理へヘッダの書き戻しを加えることになり、一時ファイルのためだけに保存形式の処理を複雑にするので採らなかった。
一時ファイルを保存して再利用する派生ファイルの形式にする案は、2つ目の保存形式を持つことになり、先読みの条件や入力の組み合わせを変えるたびに作り直しが要るので採らなかった。
先の決定の本文に例外を追記する案は、承認済みのADRの本文を書き換えないという[ADRの規約](README.md)に反するので採らず、本ADRを新しく書いて先の決定を置き換えた。

## 結果

保存形式についての制約は変わらず、一時ファイルだけが規則の外に置かれる。
一時ファイルの配置の仕様はコードのdocコメントだけに書き、[ファイル形式の一覧](../guides/file-formats.md)には、一時ファイルが保存形式ではないことと、仕様の参照先だけを書く。
一時ファイルが残った場合の回収の手順は、NNUEの学習の手引きに書く。

# プロトコルの種類、探索方式、入出力の記録は起動引数に残し、ONNX Runtimeの場所は環境変数に残す

## ステータス

承認済み。決定日は2026年11月12日。

## コンテキスト

[起動引数と診断ツールをUSIへ移す計画](../plans/cli-to-usi.md)は、エンジンへの情報の渡し方を、プロセスの起動時から起動後のプロトコルへ移した。
規則セットとニューラルネットのファイルは、USIのオプションで渡すようになった（[規則セットの決定](require-the-rule-set-through-the-protocol-and-keep-no-default.md)、[ネットの決定](select-zero-networks-by-the-usi-option-nnmodel.md)）。
残る起動時の情報は、起動引数`--protocol`、`--search`、`--io-log`と、ONNX Runtimeの共有ライブラリの場所を指す環境変数`ORT_DYLIB_PATH`である。
これらもプロトコルへ移すかどうかを決める必要があった。
`--search`は、NNUEを使うαβ探索と、AlphaZero型探索のMCTSのどちらで探索するかを選ぶ（[探索方式を起動時に選ぶ決定](select-the-search-method-at-startup-through-a-closed-enum.md)）。
`--io-log`は、エンジンが受け取った行と送った行をファイルへ記録する（[入出力の記録の決定](record-protocol-io-with-a-launch-argument.md)）。

## 決定

`--protocol`、`--search`、`--io-log`は起動引数のまま残し、`ORT_DYLIB_PATH`は環境変数のまま残す。
起動引数に置くのは、プロトコルが始まる前に決まっていなければならない情報に限る。

## 検討した代案

`--protocol`をプロトコルへ移す案は成り立たない。
どのプロトコルで入力を解釈するかは、最初の入力を読む前に決まっている必要がある。

`--search`をUSIのオプションにする案は採らなかった。
接続の直後にエンジンが名前とオプションを宣言する握手で、宣言するオプションの集合が探索方式で決まるからである。
`Threads`の範囲はαβ探索で1〜256、MCTSで1だけであり、`NnBackend`などはMCTSだけが宣言する。
オプションにする実現方法は2つあるが、どちらにも欠点がある。
方式が決まる前に届いた設定を溜めて`isready`で適用する方法では、方式に固有の誤りの通知が`setoption`の直後から`isready`へ遅れる。
探索方式を選ぶオプション（仮に`Search`と呼ぶ）を受けた時点で探索器を作り直す方法では、それより前に送った設定が黙って失われる。対局ハーネスは`USI_Hash`を追加のオプションより先に送るので、実際にこの順序になる。
どちらの方法でも、握手では両方式のオプションをまとめて宣言することになる。
対局ハーネスは、握手の宣言の範囲に照らして指定値を対局の前に検査しているので、まとめて宣言すると、方式に合わない値を検出できなくなる。

`--io-log`をUSIのオプションにする案は採らなかった。
記録は、入力スレッドが1行を読み終えた直後に、起動からの経過時間を付けて書く。
オプションで途中から有効にすると、有効にする前の行は記録できない。
欠けるのは握手だけではない。入力スレッドは処理より先に行を読むので、記録を有効にする`setoption`と同時に送られた`go`も、受信の時刻を記録できないことがある。
時間切れの調査では`go`の受信の時刻を記録から読むので、欠けることがある記録は調査の資料にならない。
Stockfishはオプション`Debug Log File`で記録を有効にするが、この理由で同じ方式は採らなかった。

`ORT_DYLIB_PATH`をUSIのオプションにする案は採らなかった。
共有ライブラリの読み込みは最初の推論器を作るときなので、技術的には移せる。
しかし、環境を設定する`tools/train/zero/env.sh`は、同時に`LD_LIBRARY_PATH`で、GPUでの推論に要る共有ライブラリ（TensorRT、CUDA、cuDNN）の場所も渡しており、こちらは起動時にしか渡せない。
片方だけを移しても、起動の前の環境の設定は減らない。
また、サブコマンドに残した自己対局生成器`minase data zero-selfplay`も同じ初期化を使うので、渡し方が2通りになる。

## 結果

エンジンの起動は`minase --protocol <usi|cecp> [--search <alphabeta|mcts>] [--io-log <パス>]`の形になった。
この3つの起動引数は、CONTRIBUTING.mdの互換性の対象である。
引数を渡せないLishogi-Bot（オンライン対局サイトlishogiとエンジンを仲介するプログラム）のために、配備用のリポジトリは`--protocol usi`を固定した起動用のスクリプトを置き続ける。
対局ハーネスが`commit:`のエンジンを起動する固定の引数は`--protocol usi`であり、MCTSは`--candidate-args '--search mcts'`のように起動引数を足して選ぶ（[起動引数を足す決定](append-startup-arguments-to-commit-engine-specs.md)）。

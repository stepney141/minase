# USI経路では探索の手を対局へ適用せず、局面の同期に失敗した後は着手を返さない

## ステータス

承認済み。決定日は2026年8月14日。

## コンテキスト

lishogiのBotとして指すとき、minaseはLishogi-Botを介してUSIで対局する。
Lishogi-Botは毎手、初期局面と全着手列を`position`で送り、続けて`go`を送る（[USI原典仕様とlishogi系拡張の調査](../research/protocols/usi-lishogi.md)）。
着手が対局に反映されるかどうかと終局の裁定は、lishogiのサーバが決める。
USIの原典は、`go`に対して必ず`bestmove`を返すことを求める。
一方、規則の差や壊れた棋譜のために`position`を受理できなかった後に、保持している古い局面から着手を返すと、サーバから見て不正な手を黙って送ることになる。
この扱いは[外部対局接続](../plans/engine-connectivity.md)で決めた。

## 決定

USIの`go`は対局状態の複製の上で探索し、返した手を`Engine`の対局へ適用しない。
対局が進行中でないとき、および直前の`position`を受理できなかったときの`go`には、エラーの情報行だけを返して`bestmove`を返さない。
詳細は`UsiProtocol`の`start_go`と`handle_position`のdocコメントにある。

## 検討した代案

CECPと同じく探索の手を対局へ適用する案は、次の`position`が全着手列で局面を作り直すので冗長であり、サーバの認識と食い違う状態を持つ分岐だけが増えるので採らなかった。
同期に失敗した後も保持している局面から`bestmove`を返す案は、不正な手を黙って送る経路を残すので採らなかった。

## 結果

`bestmove`を送った後も`Engine`は対局中のままであり、次の`position`で局面を同期する。
USIの原典の要求に反して`bestmove`を返さない場合があるので、その`go`への応答を期限なしに待つGUIは止まる。
Lishogi-Bot経由の対局では規則セット`lishogi`を使い、この規則セットではminaseの裁定がlishogiの棋譜と一致することを照合で確かめてある。
そのため、サーバが終局させた対局へ`go`が届くことはなく、他の規則セットとの裁定の互換性は確かめていない。
USIにはエンジンから終局を知らせる標準の手段がないので、minaseはUSIで終局を自分から出力しない。

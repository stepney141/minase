# 本番の型と関数の中に`#[cfg(test)]`の項目を置かず、試験専用のコードは子モジュールと`test-util`へ分ける

## ステータス

承認済み。決定日は2026年11月2日。

## コンテキスト

モンテカルロ木探索（MCTS）のエンジンには、探索木を再利用したかを試験で確かめるためだけのフィールド`reused`があり、探索木には試験のときだけ手数の上限を縮めるフィールド`max_ply`と、`#[cfg(not(test))]`で本番の定数を返す分岐があった。
試験と本番で異なるコードがコンパイルされるので、試験が本番の挙動を確かめていない部分が生じる。
試験用の評価器`UniformEvaluator`は既定で公開されており、本番の公開APIに試験専用の項目が混ざっていた。

エンジンの開発者は2026年11月2日に、試験専用のコードを本番のコードから分離すると決めた（[コードの配置の設計書](../plans/archived/zero-code-layout.md)）。

## 決定

本番の型のフィールド、本番の関数の中の分岐、および本番の型のメソッドに`#[cfg(test)]`を付けず、`#[cfg(not(test))]`も使わない。
`#[cfg(test)]`を付けるのは、試験用の子モジュールの宣言だけとする。
試験だけが使う補助関数はその子モジュール（`X/tests.rs`または`X/test_support.rs`）に置き、別の実行ファイルの試験から使う補助の項目は、フィーチャ`test-util`で公開する`test_util`モジュールに置く。

## 検討した代案

試験のために本番の抽象を増やす案は採らなかった。
たとえば`Engine`の推論器の生成をトレイトにする案である。
Rustの子モジュールは親モジュールの非公開のフィールドを読めるので、子モジュールに`impl`を書けば、本番の抽象も可視性も増やさずに分離できる。

`UniformEvaluator`を`#[cfg(test)]`だけにする案は採らなかった。
実行ファイルの試験はライブラリの`cfg(test)`を見られないので、自己対局生成器の試験から使えない。

`UniformEvaluator`を各試験に複製する案は採らなかった。
ライブラリの試験と実行ファイルの試験の両方に同じコードが増える。

ライブラリの試験だけが使う補助関数`rotate`と`random_positions`を`test-util`で公開する案は採らなかった。
`test-util`が有効で`cfg(test)`が偽のビルドで未使用のコードの警告が出て、`cargo clippy --workspace --all-targets -- -D warnings`が失敗する。

## 結果

`UniformEvaluator`は既定の公開APIから外れ、`minase::nn::test_util::UniformEvaluator`になる。
これは公開APIの互換性を壊す変更である。
`crates/minase/Cargo.toml`は、minase-coreと同じ形で、自分自身を指す開発依存で`test-util`を有効にするので、`cargo build`の実行ファイルには入らない。
探索木の手数の上限は常に存在するフィールドになり、試験と本番が同じコードを通る。
探索木の容量の計算は`Tree`自身の大きさを含まないので、容量の上限は変わらない。
この規則は`docs/guides/testing-minase-rules.md`に書く。
αβ探索と評価関数の`#[cfg(test)]`の項目は、この決定より前のコードであり、別の設計書で同じ規則を適用する。
`#[cfg(test)] mod tests`のファイル内モジュールは、モジュールの宣言なので規則に反しない。

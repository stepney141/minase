# 置換表を1スロット1エントリの直接マップのまま保つ

## ステータス

承認済み。決定日は2026年9月12日。

## コンテキスト

minaseの置換表は、局面キーの下位ビットで1つのスロットを選び、そこに1エントリだけを置く直接マップである。
異なる局面の記録は、過去の世代の記録か、新しい記録の方が深い場合に置き換えられる。
[棋力向上段階6](../plans/archived/strength-stage6.md)の[置換表の対局再生診断](../measurements/strength-stage6-tt-replay.md)では、STC相当の再生で、静止探索の浅い記録が過去の世代の深い記録を上書きする保存が、保存全体の7.1%を占めた。
そこで、64バイトに揃えた4エントリのクラスタを1スロットにし、空きがなければ最も古く、次に最も浅い記録を置き換える方式を実装した。
クラスタ化の効果は置換表の再利用による探索効率にしかないので、同じ着手列に沿って置換表を保持したまま固定深さ6で探索する再生で、総ノード数が3%以上減ることを採否測定へ進む基準とした。
[クラスタ化の対局再生](../measurements/strength-stage6-tt-cluster-replay.md)では、1手17万ノードの再生で浅い記録による上書きが14%減ったが、照合成功率は25.9%のまま変わらなかった。
固定深さ6の再生では、総ノード数の減少は0.14%だった。

## 決定

置換表は1スロット1エントリの直接マップのまま保つ。
エントリの16バイト2語の配置と原子操作の契約も変えない。

## 検討した代案

4エントリのクラスタ化は、上記のとおり基準の3%に届かなかったので、採否測定へ進めずに実装を外した。
深さと世代を重み付きで合成する置換優先度は、係数を1つ持ち込むので段階6では試していない。
Stockfishはこの優先度を`depth − 8·age`として使う（[Lazy SMPの設計書の参考資料](../plans/archived/lazy-smp.md#参考資料)）。
古さを深さより優先する置換順序では、深い過去の記録もクラスタ内で最古になれば追い出されるので、効果が出なかった原因はこの順序にあると考えられるが、確かめてはいない。

## 結果

置換表の構造を変える提案は、固定深さの対局再生で総ノード数の減少を示してから段階ゲートにかける必要がある。
深さを重み付けする置換優先度は未測定の候補として残る。
[HaChu対minaseの条件格子測定](../plans/archived/hachu-condition-grid.md)で置換表容量を16倍変えても差が検出されなかったことは、置換表の改良の効果が小さい可能性を示すが、上限の証明ではない。

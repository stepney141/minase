# Zobristハッシュを64ビットに保つ

## ステータス

承認済み。決定日は2026年8月22日。

## コンテキスト

minaseは、局面の同一性をZobristハッシュで判定する。
探索局面キーは、駒配置、手番、および先獅子の状態を含む通常のZobrist値と、成り権の保留状態を表すZobrist値の排他的論理和である。
このキーは、対局管理層の反復の裁定、探索内の反復の検出、および置換表の索引と照合に使う。
置換表は、キーの下位ビットでスロットを選び、上位32ビットを検証キーとして照合する。
[探索部](../plans/archived/search.md)の設計にあたり、中将棋の状態空間の大きさに対して64ビットで足りるかが論点になった。
衝突の確率は状態空間の大きさではなく、実際に生成されるキーの数による誕生日限界で決まる。
反復判定での衝突の確率は、1局あたり約2⁻⁴¹である。
置換表の衝突は設計上許容されるものであり、Hyatt–Cozzieの実験は衝突が棋力にほとんど影響しないことを示している。

## 決定

Zobristハッシュと探索局面キーの幅を64ビットに保つ。
反復の裁定でも、キーの一致を同一局面とみなし、完全な局面の署名とは照合しない。

## 検討した代案

キーを64ビットより広げる案は、衝突による問題が観測されていないので採らなかった。

## 結果

キーは1語に収まり、置換表のエントリは検証キーを32ビットに切り詰めて16バイトに収まる。
キーの衝突による誤った反復の裁定は、確率が十分に小さいものとして許容する。
衝突による問題が観測された場合は、この決定を再検討する。
実装は`crates/minase-core/src/position/zobrist.rs`にあり、探索局面キーの合成は`crates/minase/src/search/snapshot.rs`の`search_key`にある。

# TensorRTのエンジンのキャッシュは、ネットの検査和、GPUの機種名とメモリ容量、および最大バッチで分けたディレクトリに置く

## ステータス

承認済み。決定日は2026年10月27日。

## コンテキスト

TensorRTは、初回の読み込みでネットをGPU向けに最適化したエンジンを作る。
[実現性の実測](../measurements/alphazero-environment/alphazero-feasibility.md)では、10ブロック128チャネルのネットのセッションの作成に、エンジンの作成を含めて作業機で8.3秒、Colab機で3.7〜13.4秒かかった。
ONNX RuntimeのTensorRT実行プロバイダは、エンジンをキャッシュのディレクトリへ保存し、ファイル名をネットの識別子、精度、および計算能力から作る。
識別子は、ネットのファイル名、グラフの入力名とノードの出力名、OS、ONNX Runtimeの版、CUDAの版、およびTensorRTの版のハッシュであり、重みを含まない（ONNX Runtime 1.28 の`tensorrt_execution_provider_utils.h`の`TRTGenerateId`、523〜596行）。
ファイル名の末尾には`_fp16`と`_sm<計算能力>`が付く（`tensorrt_execution_provider.cc` 3378〜3389行と3512〜3525行）。
minaseはネットをメモリから読むので、ファイル名もハッシュに入らず、同じ構成で重みだけが違う2つのネットは同じ名前のエンジンになる。
同じ箇所の注記は、計算能力が同じでもメモリの大きいGPUで作ったエンジンをメモリの小さいGPUで読み込めない場合があるとしている。
最適化プロファイルが変わると、ONNX Runtimeは同じ名前のエンジンを作り直して上書きする（同 3555行）。
借りた機械はGPUを1枚だけ使う。
決定の経緯は[ネットの入出力と推論の設計書](../plans/archived/alphazero-network.md)にある。

## 決定

TensorRTのエンジンは、ネットのSHA-256、GPUの機種名、GPUのメモリ容量（MiB）、および最大バッチの4つから求めたSHA-256の16進64文字を名前とするディレクトリに置く。
ディレクトリはキャッシュの親ディレクトリの下に作り、ONNX Runtimeのエンジンのキャッシュの置き場所として渡す。
GPUの機種名とメモリ容量は`nvidia-smi`で照会し、GPUがちょうど1枚でなければエラーとする。
TensorRTの版、ONNX Runtimeの版、CUDAの版、計算能力、および精度は、ONNX Runtimeがエンジンのファイル名で区別するので、鍵に入れない。
最適化プロファイルはバッチの大きさ1から最大バッチまでとし、最適値を最大バッチに置く。
タイミングキャッシュは使わない。

## 検討した代案

ネットの検査和だけを鍵にする案は、借りた機械で作ったエンジンを作業機のGPUで読み込むおそれがあるので採らなかった。

ONNX Runtimeの既定の名前だけに任せる案は、重みの違うネットのエンジンを取り違えるので採らなかった。

TensorRTの版と計算能力もminase側で鍵に入れる案は採らなかった。
TensorRTの版を安全なRustで知る手段は、セッションを作る前にはなく、どちらの値もONNX Runtimeのファイル名がすでに区別している。

最大バッチを鍵に入れない案は採らなかった。
最大バッチの異なる2つの設定が同じディレクトリを使うと、起動のたびにエンジンが作り直され、同時に動く2つのプロセスが同じファイルを互いに上書きする。

## 結果

ネット、GPU、または最大バッチを変えるたびに、新しいディレクトリでエンジンが作られ、古いディレクトリは残る。
借りた機械には永続する記憶領域を置かないので、借りるたびにエンジンを作り直す。
`nvidia-smi`のない環境ではTensorRTを選べない。
キャッシュの親ディレクトリは、エンジンではUSIオプション`NnCacheDir`、検査用の`minase dev nn-eval`では`--cache-dir`で与える。
鍵の計算は`crates/minase/src/nn/tensorrt_cache.rs`にある。

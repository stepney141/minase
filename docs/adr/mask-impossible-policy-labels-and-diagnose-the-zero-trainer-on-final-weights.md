# AlphaZero型探索の学習器は、常に不可能な方策のラベルを損失の正規化から除き、価値を対局結果と根の価値の混合で学び、最終の重みで訓練集合の標本と検証集合を同じ条件で診断する

## ステータス

承認済み。決定日は2026年10月28日。

## コンテキスト

[学習器の教師と損失を定めた決定](archive/train-the-zero-value-on-mixed-results-and-root-values.md)は、方策の損失を35,856出力の全体にかけたlog-softmaxとの交差エントロピーとし、合法手だけで正規化しないと定めていた。
方策のラベルは、移動元の升ごとに249種類の移動を割り当てた35,856要素である（[方策のADR](encode-the-zero-policy-as-249-planes-per-from-square.md)）。
2026年10月28日の[監査](../audits/alphazero-rl-readiness-2026-10-28.md)の列挙では、盤面によらず常に不可能なラベルが19,748あり、残る16,108の内訳は、不成の直線の移動5,192、成りの直線の移動2,456、桂馬型の跳び880、移動元以外へ進む2歩6,424、居喰い1,012、およびじっと144である。
全logitが等しい場合、全35,856出力で正規化したときと有効な16,108出力で正規化したときの方策の損失の差は`log(35,856/16,108) ≈ 0.80`である。
KataGoは`python/katago/train/model_pytorch.py`の`PolicyHead`で盤外のlogitを定数で抑え、lc0は`tf/tfprocess.py`の設定`mask_legal_moves`で合法手だけのsoftmaxにし、dlshogiはマスクなしで学習している（いずれも参照日2026年10月28日）。
同じ決定は、対局結果だけに対する価値の検証損失を監視するとしていた。
しかし、訓練の損失は更新中の重みと訓練モードで平均し、検証の損失は最終の重みと推論モードで測るので、[学習器の確認](../measurements/alphazero-trainer/alphazero-trainer-gpu-resume-check.md)で見た訓練の損失0.326と検証の損失0.798の差からは、同一対局の勝敗の相関による過学習、バッチ正規化の移動統計のずれ、およびランダムな対局の結果の予測の難しさを区別できない。
エンジンの開発者は、[監査対応の設計書](../plans/archived/alphazero-audit-remediation.md)でこの決定を下した。

## 決定

方策の損失の計算では、長さ35,856のブールの定数マスク（真の要素数16,108）の外のlogitを、単精度へ変換したうえで負の無限大へ置き換えてからlog-softmaxを取る。
方策の目標のラベルがマスクの外にあればエラーにする。
マスクは学習器の符号化で方策のラベルの定義から計算し、ネットの出力層、ONNXの構造、および推論側の処理は変えない。
価値の教師は(1−λ)·結果 + λ·根の価値とし、λは0.333から始める。
価値の損失はsigmoidの手前のlogitに対する二値交差エントロピーとし、損失は方策と価値の和とする。
最適化器はネステロフのモーメンタムつきSGDとし、学習率などの値は既定値を持たない必須の引数とし、bf16を選んでもネットの順伝播だけに自動混合精度を適用する。
学習の終わりに、最終の重みの推論モードで、訓練集合のうち基本シードと対局番号の`hash64 % 20 == 1`を満たす対局の標本と、検証集合（`hash64 % 20 == 0`）を、同じ関数と局面単位の算術平均で測る。
集計には、対局数と局面数とともに、方策の損失、混合した教師に対する価値の損失、対局結果だけに対する価値の損失、合法手に乗る確率質量（マスクの中のlogitで正規化した確率の合法手の和）、および方策の一致率（合法手の中でlogitが最大の手が教師の確率が最大の手に含まれる割合）を記録する。
合法手の列は、MNSDを読む拡張モジュールが局面の再生時に生成して返し、ディスク上の形式は変えない。
診断では勾配、バッチ正規化の移動統計、および学習に使う乱数の状態を変えない。

## 検討した代案

ネットの出力層にマスクを入れる案は採らなかった。
損失の側に置けばONNXと推論を変えずに済み、推論はもともと合法手のlogitだけを取り出して正規化するからである。

合法手だけで正規化する方策の損失は、本決定では採らず、最初のサイクルで合法手に乗る確率質量を測ってから判断する。
dlshogiはマスクなしで学習しており、全体のsoftmaxが学習を不能にするとは言えないからである。

訓練中の平均損失と検証損失の差を過学習の証拠とする案は採らなかった。
重みと動作モードが異なる2つの値の差だからである。

価値の損失に使う局面の間引き、λの変更、および重みの移動平均は、本決定では実装しない。
間引きとλは最初のサイクルの診断を見て利用者が決め、移動平均は10サイクル目の進捗測定の後に判断する（[強化学習の実行](../plans/alphazero-rl.md)）。

## 結果

常に不可能なラベルはlog-softmaxの正規化から外れるので、損失の値は従来の集計と単純には比べられない。
合法手の列の分だけメモリが増える（100万局面で約170 MBの計算値）。
集計には、訓練中の平均損失とは別の名前で診断の値が入り、λの良し悪しは、教師の定義で変わらない対局結果だけに対する価値の損失で判断する。
実装は`tools/train/zero/minase_zero/`と`tools/train/zero/mnsd_reader/`にあり、集計の欄は`train.py`のdocstringにある。

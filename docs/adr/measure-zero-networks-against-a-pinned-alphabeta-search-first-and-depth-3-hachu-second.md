# AlphaZero型探索のネットの強さは、コミットを固定したαβ探索との対局を主に、深さ3のHaChuとの対局を副に測る

## ステータス

承認済み。決定日は2026年11月14日。

## コンテキスト

minaseのAlphaZero型探索は、ニューラルネットワーク（以下、ネット）で局面を評価しながらモンテカルロ木探索（以下、MCTS）を行い、ネットを自己対局と学習のサイクルで育てる。
強化学習の1回目では、10サイクル前の自分のネットとの対局で強さを測った。
Eloの差の点推定は、サイクル10に対するサイクル20が+199、サイクル20に対するサイクル30が+237であったが、サイクル32のネットは、minaseのαβ探索に、持ち時間10秒で1手ごとに0.1秒を加える対局の97ペア194局で、2勝192敗であった（[記録](../measurements/alphazero-rl/alphazero-rl-restart-stc-c0032.md)）。
将棋のAlphaZero型エンジンAobaZeroとdlshogiの開発者も、過去の自分との対局は外部のエンジンとの対局よりEloの差を大きく見せると述べている（[強さを測る固定の相手の設計書](../plans/archived/mcts-fixed-opponents.md)の「先行実装」の節）。
そこで、2回目の学習では、学習の間ずっと変えない相手との対局で強さを測ることにした。

2026年11月13日に、利用者は、強さの比較に中将棋の外部エンジンHaChuを使うと決めた。
設計書は、HaChuを主な相手、コミット45d5db54のαβ探索を副次の相手とし、HaChuの思考の深さを予備の対局で選ぶことにした。
HaChuはノード数の制限を持たず、時間の制限では機械の速さと負荷で強さが変わるので、機械によらない固定の強さにできるのは深さだけである。
HaChuは既出の局面を再現する着手を禁じる規則R2で指し、自己対局の規則セット`lishogi`が採る、同一局面の4回目の出現を裁定する規則R1に対応しないので、HaChuとの対局は、HaChuの既定の設定に対応する規則`L1,L3,P0,P5,P6,R2,E1,E2`（[競技規則](../rules/chu-shogi.md)第33条第7項）で行う。

深さの選定では、1回目の学習のサイクル32のネットを、HaChuの深さ1から4と30ペア（同じ開始局面で先後を入れ替えた2局を1ペアとする）ずつ対局させた（[記録](../measurements/mcts-fixed-opponents/mcts-fixed-opponents-hachu-depth.md)）。
MCTSの得点率は、深さ1から順に98.3%、74.1%、26.8%、10.7%であった。
深さ2から4では、手数の上限1,900手に達して破棄したペアと、HaChuの不正着手のあったペアが、試行したペアの13%から17%を占めた。
HaChuの既定の規則は反復を禁じ、駒枯れの裁定も持たないので、対局は王駒を取るか投了するまで終わらない。長い対局では、MCTSとHaChuのどちらも、優勢な終盤を勝ちきれていなかった。
不正着手は7件あり、すべて、HaChuが反復の判定に直近の200局面しか使わないために、200手より前の局面を再現する着手を指したものであった。
設計書は、破棄と不正着手のあるペアが5%を超えた条件の値を使わないと定めていたので、得点率が2割から8割に入り、かつ5%以下に収まる深さはなかった。

一方、45d5db54のαβ探索の1手500ノードとの規則セット`lishogi`の対局では、1回目のサイクル10、20、および32のネットの各100ペアで、破棄ペア、エンジンの異常、および反則負けが0件であった（[記録](../measurements/mcts-fixed-opponents/mcts-fixed-opponents-alphabeta-baseline.md)）。
`lishogi`の規則は、同一局面の4回目の出現と、王駒1枚だけになった側の負けを裁定するので、対局が終わる。

## 決定

ネットの強さの主な指標は、コミット45d5db54のαβ探索との対局とし、副次の指標は、深さ3に固定したHaChuとの対局とする（2026年11月14日の利用者の決定）。
この決定は、HaChuを主な指標とした2026年11月13日の設計を置き換える。

主な指標の対局は、1手800シミュレーションのMCTS（USIのオプション`NnBatchSize`は16）と、1手500ノードに制限したコミット45d5db54のαβ探索との対局である。このαβ探索は、評価関数として、差分計算する小型のニューラルネットワークNNUEを埋め込んでいる。
規則は規則セット`lishogi`とし、手数の上限は4,096手とする。
破棄したペアがあるときは、破棄したペアをMCTSの2敗とした場合と2勝とした場合のEloを併記し、破棄したペアが試行したペアの5%を超えた回の値は、伸びの判定に使わず、原因を調べる。

副次の指標の対局は、同じMCTSと、HaChu（Debianパッケージ収録の版、コミットdf26f4a）の深さ3（CECPの`sd 3`）の対局である。
規則は`L1,L3,P0,P5,P6,R2,E1,E2`とし、HaChuの棋譜の配列の上限2,000手に収まるように、手数の上限を1,900手とする。HaChuの置換表は256 MBとする。
HaChuとの対局では、破棄ペアと、拒否着手または不正着手のあった対局を含むペアの割合が5%を超えても値を捨てない。代わりに、有効ペアのElo（破棄したペアだけを除き、HaChuの拒否着手と不正着手をHaChuの反則負けとして数えた値）、拒否着手と不正着手のペアも除いたElo、破棄したペアをMCTSの2敗とした場合と2勝とした場合のElo、および影響ペア（破棄したペアか、拒否着手または不正着手のあったペアの、どちらかに当たるペア）の割合を毎回記録する。
HaChuの拒否着手と不正着手は毎回分類し、既知の2つの食い違いのどちらにも当たらないものがあれば、原因を調べる。既知の食い違いは2つある。1つは、HaChuが局面の同一を駒の配置と手番だけで判定し、審判層が判定に含める先獅子の状態（直前の着手で獅子以外の駒が獅子を取ったかどうか）を見ないために、審判層が認めた着手を既出の局面の再現として拒否するものである。もう1つは、HaChuが直近の200局面しか覚えないために、200手より前の局面を再現する着手を指し、審判層がそれを不正着手とするものである。

MCTSは、測定の系列ごとにコミットを固定する。
2回目の学習で10サイクルごとに行う測定のペア数は、主な指標を400ペア、副次の指標を100ペアとする。
主な指標のペア数を多くするのは、Eloの95%信頼区間を狭くするためであり、元の設計でHaChuに400ペア、αβ探索に100ペアを割り当てていたものを、主と副の変更に合わせて逆にした。

ある回の得点率が9割を超えるか1割を下回った場合は、その相手の条件を隣の条件に改める。αβ探索は250ノードか1,000ノード、HaChuは1つ浅い深さか1つ深い深さにする。
条件を改めるときは、同じネットを新旧2つの条件で対局させ、2つの条件のEloの差を以後の測定値に足して、改める前の値と比べられるようにする。

強さの比較にHaChuを使うことと、主と副を入れ替えることは利用者の決定である。そのほかの条件は、設計を担うAIエージェントのClaudeが設計書で提案し、利用者が2026年11月13日に設計書の遂行を指示したものである。定例の測定のペア数の変更は、主と副を入れ替える決定に合わせて、Claudeが設計書の規則から導いたものである。

1回目の学習のネットの基準の値は、[αβ探索との記録](../measurements/mcts-fixed-opponents/mcts-fixed-opponents-alphabeta-baseline.md)と[HaChuとの記録](../measurements/mcts-fixed-opponents/mcts-fixed-opponents-hachu-baseline.md)にある。
対局の起動、集計、および拒否着手と不正着手の分類には、[固定の相手との対局のスクリプト](../measurements/mcts-fixed-opponents/mcts-fixed-opponents-scripts/)を使う。

## 検討した代案

HaChuを主な指標のまま使う案は採らなかった。
深さ2から4のどれでも、破棄と不正着手のあるペアが13%から17%あり、その扱い方によってEloが深さ2で87、深さ3で75動くので、10サイクルごとの伸びを判定する主な指標に向かないからである。たとえば深さ3では、有効ペアのEloが−175、不正着手のペアを除くと−209、破棄したペアを2勝とすると−134であった。
長い対局は、双方が優勢な終盤を勝ちきれないことから起き、深さを変えても減らなかった。

HaChuの手数の上限を1,900手より延ばす案は採らなかった。
HaChuは2,000手を超えると異常終了し、上限を延ばすにはHaChuのソースを書き換える必要がある。さらに、HaChuの既定の規則では反復による引き分けも駒枯れもないので、上限を延ばしても対局が終わるとは限らない。

審判層だけに裸玉の裁定（規則E3）のような終局の規則を足す案は採らなかった。
HaChuが知らない規則で勝敗を裁定することになり、HaChuの既定の規則で対局するという前提が崩れるからである。

10サイクル前の自分のネットを相手にする案は、1回目の学習の結果と先行実装の記述のとおり、伸びを大きく見せるので採らなかった。
最新のmasterのαβ探索を相手にする案は、NNUEを更新するたびに相手の強さが変わるので採らなかった。

## 結果

主な指標の相手は、minase自身のαβ探索とNNUEであり、[統括計画](../plans/alphazero.md)の目標である「MCTSがαβ探索とNNUEの組合せと同等以上に強くなること」までの距離を直接示す。
ただし、minaseの外の実装ではないので、評価の癖を共有している可能性があり、独立した相手による確認は副次のHaChuとの対局が担う。
HaChuとの対局が示すのは、反復、成り、および終局の扱いが自己対局の規則`lishogi`と異なる規則での強さであり、影響ペアの扱いによるEloの幅を併記して読む。

1回目の学習のサイクル10のネットは、αβ探索の500ノードに対する得点率が3.5%であった。2回目の学習はネットをランダムに初期化して始めるので、最初の測定から、得点率が1割を下回って250ノードの条件に改める手順が要る見込みである。この手順を使う時点は、[2回目の実行の設計書](../plans/alphazero-rl-2.md)が定める。

基準を測ったMCTSのコミットc1c84466から、2回目の学習の測定に使うコミットまでの間に、MCTSの探索の結果を変える変更が入った場合は、基準の3つのネットを新しいコミットで2つの相手と測り直す。

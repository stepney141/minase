# 静止探索に専用の深さ上限を置かない

## ステータス

承認済み。決定日は2026年9月5日。

## コンテキスト

静止探索は、読みの末端で捕獲手だけを読み進め、駒の取り合いの途中で評価しないための探索である。
minaseの静止探索は置換表とdelta pruningを持ち、捕獲は有限なので停止する。
それでも深い経路が静止探索のノードの無視できない割合を占めるなら、専用の深さ上限で打ち切り、上限に達したノードでは静的評価を返す案があった。
[棋力向上段階3](../plans/strength-stage3.md)は、深さ8以上のノードが静止探索のノードの1%未満なら、上限は発動しない改良として見送るという基準を測定前に定めた。
上限で削れるのは分布の裾だけなので、裾が1%未満なら実装と測定の費用に見合わないという判断である。
[深さ分布のbench](../measurements/strength-stage3-qsearch-depth-bench.md)では、深さ5の探索で静止探索のノード2,189,588のうち、99.18%が深さ7以内にあり、深さ8以上は0.82%だった。
最大深さは16である。

## 決定

静止探索に、静止探索へ入ってからの深さに対する専用の上限を置かない。
静止探索の停止は、置換表、delta pruning、およびSEEによる枝刈りに任せる。

## 検討した代案

分布の99パーセンタイルの深さを上限とし、上限で静的評価を返す案は、深さ8以上が0.82%で基準に届かなかったので実装しなかった。

## 結果

静止探索の深さを制限するのは、探索全体の上限`MAX_PLY`だけである。
後に[不採用だった探索部の改良の再調整](../plans/search-revival-spsa.md)が採用した`QsearchMoveLimit`は、1ノードで読む捕獲手の数を制限する別の仕組みであり、本決定とは独立である。
深さ分布は、捕獲手の数の制限を入れる前で、評価関数がNNUEへ置き換わる前の構成で測ったので、深さ上限を再提案するときは現行の構成で分布を測り直す必要がある。

# 調整機のSPSAは標準ライブラリのPythonのスクリプトで操作し、コミットをgit bundleで渡し、期限での自己停止と取得後の削除で費用を抑える

## ステータス

承認済み。決定日は2026年10月18日。

## コンテキスト

SPSAは、vast.aiで借りる物理コアの多い計算機（以下、調整機）で実行する（[調整機のADR](run-spsa-on-rented-machines-with-nps-scaled-time-controls.md)）。
開発と棋力測定に使う手元の機械（以下、測定機）が調整機を作り、調整機がビルドとセッションを実行し、測定機が実行ディレクトリを取得して再開用の写しを保つ。
これらの操作には、出品の条件の判定、換算係数と同時対局数の計算、記録の連続性の検査など、判定と計算が多い。
最初の実装は判定と計算をPythonの断片に任せたBashのスクリプトだったが、2026年10月18日にエンジンの開発者は、読みにくく保守しにくいとしてこの書き方を退けた。
調整機に使うvast.aiの公式のRustのイメージ（Debian bookworm）には、Python 3.11が含まれる。

[vast.aiでの教師生成](../plans/vast-selfplay.md)も、同じvast.aiの操作（機械の作成、起動時スクリプトによる自己停止、停止と削除の確認）を使う。
教師生成の作業の単位はファイルごとの多数のバッチであり、SPSAの作業の単位は1つの長いプロセスである。

調整対象のコミットは、多くの場合まだmasterへ統合していないブランチにある。
`.cargo/config.toml`は`target-cpu=native`を指定するので、測定機でビルドした実行ファイルは測定機のCPU向けの命令を含む。

vast.aiは前払いの残高から課金する。
残高が0になると機械は停止するが、停止した機械のディスクの課金は負の残高として続き、保存したカードへの請求か、猶予期間の後の機械とデータの削除で精算される（[vast.aiでの教師生成](../plans/vast-selfplay.md)の設計判断）。

## 決定

測定機で動く`launch.py`と`fetch.py`、調整機で動く`remote.py`、および教師生成と共通の`scripts/vast/common.py`は、標準ライブラリだけを使うPythonで書く。
シェルは、vast.aiが起動時に実行する`scripts/vast/onstart.sh`の自己停止と権限の修正だけに使い、`launch.py`がそこへ期限とジョブの起動行を加える。
SPSAのスクリプトは`scripts/vast-spsa/`に、教師生成のスクリプトとは別に置き、共通の処理だけを`common.py`で共有する。

調整対象のコミットとrunnerのコミットは、測定機で`git bundle`にまとめて調整機へ送り、調整機はそれをcloneして`commit:`の形式でビルドする。

費用は、セッションごとに見積もりに余裕を加えた額だけを入金し、自動補充を設定せず、調整機の自己停止と取得後の削除で抑える。
調整機は作成時に決めた期限に自分を停止し、測定機の`fetch.py`も期限の超過を見て停止を要求する。
取得と検査を終えた調整機は削除する。

## 検討した代案

判定と計算をPythonの断片に任せたBashのスクリプトは、上記のとおりエンジンの開発者が退けた。
教師生成のスクリプトを汎用化してSPSAも扱う案は、作業の単位が違うので分岐が増え、採らなかった。

GitHubへブランチをpushして調整機にcloneさせる案は、未統合のブランチを公開リポジトリへ出すので採らなかった。
測定機でビルドした実行ファイルを送る案は、測定機のCPU向けの命令を含むので採らなかった。
`git bundle`なら、ブランチを公開せずに、測定機と同じ`commit:`の照合を使える。

入金した残高を費用の上限の代わりにする案は、残高が0になっても停止した機械のディスクの課金が続くので採らなかった。
期限に調整機を自分で削除させる案は、測定機へまだ取得していない記録を消して取り戻せなくするので採らなかった（[vast.aiでの教師生成](../plans/vast-selfplay.md)の設計判断）。

## 結果

スクリプトの仕様（ファイルの配置と形式、計算式、終了コード）は各スクリプトのdocstringにあり、手順は[SPSAの手引き](../guides/spsa.md)の第8節にある。
調整機でのビルドは機械ごとに`target-cpu=native`で行われるので、同じコミットでも実行ファイルのSHA-256は機械ごとに変わる。
再開時にこの違いを受け入れる照合は、[再開のADR](resume-from-the-manifest-and-accept-rebuilt-tuning-commits.md)が定める。
2026年10月の2回のセッションでは、口座のAPIが2要素認証での再ログインを求めている間も、自己停止に使うコンテナ用のAPIの鍵で調整機を停止できた（[SPSAの手引き](../guides/spsa.md)の第8節）。

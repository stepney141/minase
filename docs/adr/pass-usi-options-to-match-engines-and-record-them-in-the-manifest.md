# 対局ハーネスは候補と基準のUSIオプションを`--candidate-option`と`--baseline-option`で受け取り、エンジンの宣言と照合して実行条件に記録する

## ステータス

承認済み。決定日は2026年10月28日。

## コンテキスト

対局ハーネス`minase match run`は、候補と基準のエンジンに`USI_Hash`、`ResignValue`などの決まったUSIオプションだけを送り、それ以外のオプションを指定する引数を持たなかった。
AlphaZero型探索のMCTSは、推論のバッチの大きさ`NnBatchSize`（既定256）をUSIオプションで受け取るので、進捗測定の条件として明示も変更もできなかった（2026年10月28日の[監査](../audits/alphazero-rl-readiness-2026-10-28.md)）。
minaseのUSIは未知の名前のオプションを無視し、不正な値では直前の設定を保つので、送っただけでは設定されたことを保証できない。
`commit:`のエンジンの起動引数は、[起動引数の拡張の決定](append-startup-arguments-to-commit-engine-specs.md)により`--candidate-args`と`--baseline-args`で追加でき、実行条件に記録している。
エンジンの開発者は、[監査対応の設計書](../plans/archived/alphazero-audit-remediation.md)でこの決定を下した。

## 決定

`--candidate-option '名前=値'`と`--baseline-option '名前=値'`を繰り返し指定できるようにし、最初の`=`で名前と値を分ける。
`RuleSet`、`USI_Hash`、`ResignValue`、`Seed`、および`Threads`は既存の測定条件と資源管理が扱う予約名として拒否し、予約名との照合と、同じ側（候補または基準）での名前の重複の照合では、ASCIIの大文字と小文字を区別しない。
指定したオプションは、エンジンの事前起動で得たUSIの宣言と名前を完全一致で照合し、`spin`は宣言された範囲の整数、`combo`は宣言された選択肢、`check`は`true`か`false`であることを検査し、`string`はそのまま受理して、未宣言の名前と検査を実装しない型は拒否する。
受理した列は候補と基準それぞれの`manifest.json`に保存し、再開では保存した列から復元して、CLIでの再指定は同じ値でも拒否する。
記録の形式の版を6から7へ上げ、旧版の実行ディレクトリとオプションの欄を欠く記録は、空の列で補わずに拒否する。

## 検討した代案

探索回数に応じて推論のバッチを自動で小さくする案は採らなかった。
黙った補完になり、測定の条件が実行条件に残らないからである。

`Threads`をこの引数で変えられるようにする案は採らなかった。
同時対局数の計算と資源の記録がエンジンの宣言した既定値を使っているので、実効値の記録とあわせて別に設計する必要がある。

## 結果

進捗測定の推論のバッチは、候補と基準に同じ値を明示して記録できる。
形式の版が変わるので、版6までの実行ディレクトリの再開と集計は、その測定を開始したハーネスで行う。
実装は`crates/minase/src/bin/minase/match_runner/`と`crates/minase/src/harness/`にあり、手順は[棋力測定の手引き](../guides/sprt.md)の「エンジンの指定方法」の節にある。

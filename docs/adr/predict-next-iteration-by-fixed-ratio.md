# 次の反復の完了時刻を、累積経過時間の固定倍で予測する

## ステータス

承認済み。決定日は2026年9月4日。

## コンテキスト

反復深化の時間管理は、反復の完了時にsoftを照合して次の深さへ入るかを決める。
段階1までは経過時間がsoft未満なら次の反復を始めたので、始めた反復がhardに達して探索の途中で打ち切られ、その計算が捨てられる手が多かった。
[棋力向上段階2](../plans/strength-stage2.md)は、次の反復を完了できる見込みがあるときだけ始める判断を加えることにした。
段階2の着手時に深さ8までの探索で測った反復ごとの累積時間の比は、深さの偶奇によって大きく振れた。

## 決定

反復の完了時に、経過時間がsoft未満で、かつ経過時間に固定比`IterationRatio`を掛けた予測完了時刻がhard以下の場合だけ、次の深さへ入る。
どちらかを満たさなければsoftによる停止として現在の最善手を返し、hardによる探索途中の打ち切りは安全弁として残す。
判定は`should_start_next_iteration`と`iteration_prediction_fits`のdocコメントにある。

## 検討した代案

直前の2反復の所要時間の比から次の反復の所要時間を予測する案は、比が深さの偶奇で大きく振れて予測に使えないので採らなかった。
softの一定割合を超えたら次の反復を始めない案は、係数が1つ増えるだけで、次の反復がhardに収まるかの判断を含まないので採らなかった。

## 結果

採用済みの予算式を基準に、STCが有効1,111ペアでLLR +2.958、LTCが有効1,551ペアでLLR +2.949の`H1`だった（[STC](../measurements/strength-stage2-iteration-stc.md)、[LTC](../measurements/strength-stage2-iteration-ltc.md)）。
STCでは基準側に時間切れが1件出たが、原因は`position`の全着手の再生の固定費であり、[`position`の着手列は、前回受理した列との差分だけを適用する](apply-position-by-token-difference.md)の決定につながった。
固定比の当初値は2.5であり、現行値は後にSPSAで調整した値である。
予測が過大なら時間が時計に残って後の手へ回り、過小ならhardで打ち切られるので、どちらの誤りも時間切れを生まない。
最善手が安定したときの扱いは[反復の延長信号を使わず、最善手が安定したときだけ早く止める](stop-early-on-stable-best-move-without-extensions.md)にある。
先読みが的中した探索での予測の扱いは[先読みが的中したら同じ探索を続け、時間予算を的中の時点から測る](continue-search-and-measure-budget-from-ponderhit.md)にある。
後に[秒読みつき時計での持ち時間と秒読みの活用](../plans/byoyomi-time-usage.md)は、持ち時間を使い切った後の秒読み期の手に限り、予測を使わずhardだけで次の反復を始めるかを決める形に改めた。
測定は評価関数がPSTとFMだった時期の構成で行ったので、予測の方式を変える提案には現行の構成での再測定が要る。

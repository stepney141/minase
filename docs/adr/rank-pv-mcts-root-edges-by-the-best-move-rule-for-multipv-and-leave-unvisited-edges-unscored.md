# PV-MCTSのMultiPVは、探索を変えずに、終了時の根の辺を最善手と同じ比較規則で並べて上位N本を出し、2本目以降の未訪問の辺には評価値を付けない

## ステータス

承認済み。決定日は2026年11月17日。

## コンテキスト

MultiPV（multiple principal variations）は、根の上位N手の読み筋を同時に出す機能であり、Nの指定は[USIオプション`MultiPV`のADR](declare-multipv-in-the-usi-layer-and-rank-info-lines-only-when-it-is-two-or-more.md)に従う。
PV-MCTSは、方策と価値を出すネットで木を広げるモンテカルロ木探索であり、木では局面を節点、指し手を節点から子へ向かう辺で表す。
minaseのPV-MCTSは、探索の終了時にだけ`info`を出し、最善手を`Node::best_edge`の比較規則で選ぶ（[MCTSの対局の探索のADR](search-mcts-games-by-puct-with-virtual-loss-batches.md)）。
比較規則は、まず、確定した勝ちの手、未確定の手、確定した負けの手の順に並べる。
次に、確定した手どうしは確定した値で、未確定の手どうしは訪問回数で比べる。
訪問回数が同じなら、訪問済みの手は平均の勝率Qで、未訪問の手は方策の正規化前の値logitで比べ、最後まで同じなら元の辺の順を保つ。

dlshogiは、Nが2以上のとき、探索中にたどる辺を選ぶ選択式を変えずに、根の子を比較関数で部分的に整列して上位N本を出し、未訪問の手は評価値を付けずに出す。
ただし、Nが1のときは訪問回数が同じ手を方策で比べない別の関数で最善手を選ぶので、Nが1の最善手とNが2以上の1本目が一致しないことがある。
ふかうら王（dlshogiのPV-MCTSをやねうら王の枠組みへ移したエンジン）は、最善手を選ぶ関数と同じ比較関数で上位N本を整列して1本目を`bestmove`にし、未訪問の手を勝率0.5として出す。
判断の詳細と先行実装の行番号は、[MultiPVの設計書](../plans/archived/multipv.md)の「PV-MCTSの方式」の節にある。

## 決定

PV-MCTSの探索は変えず、探索の終了時に、根の辺を最善手と同じ比較規則で降順に安定に並べ（`Node::ranked_edges`）、上位N本を読み筋とする（2026年11月17日のエンジンの開発者の決定）。
各読み筋は、根の辺の手に、その子の節点から最善の辺をたどった手を続けた列であり、深さは読み筋の手数である。
評価値は、1本目では、未訪問のときも含めて、Nが1のときと同じ値をそのまま使う。
2本目以降では、確定した辺は子の勝敗を根の手番側から見て手数を1増やした値、未確定で訪問済みの辺はQを勝率尺度で評価値へ換算した値とし、未訪問の辺は評価値を付けずにその手だけの読み筋として出す。
各行の`nodes`は、いまと同じく探索全体のシミュレーションの回数である。

## 検討した代案

上位N手へ訪問を配る選択式を新しく作る案は採らなかった。
どの先行実装にもなく、対局の探索の配り方を変えてしまう。

最善手と読み筋の順位に別々の比較規則を使うdlshogiの案は採らなかった。
1つの比較規則を使えば、1本目の手は常に`bestmove`と一致する。

未訪問の辺を勝率0.5、すなわち評価値0として出すふかうら王の案は採らなかった。
未訪問の辺にはその手を指した後の局面の価値の推定がなく、0は推定ではなく根拠のない値である。
USIの原典は`info`行の`score`を必須としておらず、dlshogiも評価値のない行を出す。

未訪問の辺を出さない案は採らなかった。
比較規則では未訪問の未確定の辺は確定した負けの辺より上位にあるので、未訪問の辺を省くと、その下の確定した負けの手の行まで省くか、比較規則の順を飛ばして出すことになる。

2本目以降の行の`nodes`にその辺の訪問回数を出すふかうら王の案は採らなかった。
USIの`nodes`は探索全体の量であり、ふかうら王の該当箇所のコメントにもGUIの側に特別な扱いが要ると記されている。

## 結果

既定値1では、探索の結果と出力が変わらない（[PV-MCTSのN本の読み筋の一致の記録](../measurements/multipv/multipv-mcts-default-equivalence.md)）。
Nが2以上でも探索は変わらないので、2番手以下の手は最善手より少なく読まれ、その評価値は最善手の評価値より粗い推定になる。
読み筋を作るのに並べるのは辺の添字の列であり、木の辺そのものは並べ替えないので、次の手での木の再利用は変わらない。
探索中の定期的な`info`の出力は、PV-MCTSが探索の終了時にだけ`info`を出す規則を保つために扱わない。
仕様は`crates/minase/src/search/mcts/engine.rs`と`tree.rs`のdocコメントにある。

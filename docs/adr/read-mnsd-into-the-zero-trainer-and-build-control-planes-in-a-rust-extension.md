# AlphaZero型探索の学習器は、MNSDをRustの拡張モジュールで読み、利きの面を拡張モジュールで作り、駒の面と方策のラベルはPythonでバッチごとに作る

## ステータス

承認済み。決定日は2026年11月15日。
[利きの面と対局全体から決まる教師を拡張モジュールで作るADR](archive/read-mnsd-into-the-zero-trainer-and-build-control-planes-and-replay-targets-in-a-rust-extension.md)を置き換える。

## コンテキスト

強化学習の教師データは形式MNSDで記録され、局面の復元には中将棋の着手の適用と合法手の生成が要るので、PyTorchの学習器はMNSDを単体では読めない。
置き換えたADRは、PyO3の拡張モジュール`minase_mnsd_reader`で訓練局面を読み、入力の利きの64面と、対局全体を見て決まる補助目標の教師（短期の価値、相手の次の手、相手の局面の全合法手）を拡張モジュールで作ると定めた。
2026年11月15日に、学習器は補助目標を持たないと決まった（[方策と価値だけを学ぶADR](train-the-zero-network-on-the-policy-and-value-losses-without-auxiliary-targets.md)）。
利きの判定は中将棋の規則そのものであり、Pythonで実装し直すと推論との不一致を生むという事情は変わらない。

## 決定

MNSDは、`minase::training::records::Reader`を包むPyO3の拡張モジュール`minase_mnsd_reader`（`tools/train/zero/mnsd_reader/`）で読む。
拡張モジュールは、除外の印がなく、価値と方策の候補の両方を記録した項目を訓練局面として選ぶ。
返すのは、局面ごとの盤の駒コード、手番、先獅子の升、価値、対局結果、根の総訪問回数、方策の候補、および全合法手であり、補助目標の教師は返さない。
着手は正準形（移動元、経由升、移動先、成り）の列と局面ごとの区切りの位置で返し、Pythonの`minase_zero.encoding`が方策のラベルに直す。
全合法手は、学習の更新には使わず、最終の重みの診断（合法手の確率質量と方策の一致率）と固定の検証用データの診断に使う。
入力のうち駒の95面はPythonがバッチごとにGPUの上で作り、利きの64面は拡張モジュールが盤の配列から、推論器と同じRustの関数を呼び出して作る。
拡張モジュールは、学習器の環境定義におけるuvのpath依存としてmaturinでビルドし、PyO3への依存はCargoのフィーチャ`python`を有効にしたときだけ入れる。
学習器は、教師の種類がMCTS、由来が乱数開始の自己対局、規則が`JCSA`（規則コードL0＋P0＋R1＋E0）であるファイルだけを訓練に受け付け、リプレイバッファに同じパスまたは同じ（基本シード、対局番号）の対局が2回現れたらエラーとする。

## 検討した代案

利きの面をPythonで計算する案と、利きの面をMNSDに書く案は、置き換えたADRと同じ理由で採らなかった。
前者は推論の符号化との一致をPythonの側で保つ必要を生み、後者は1局面あたり約1.2 KB増え、符号化を変えるたびに教師データを作り直すことになる。

159面を拡張モジュールの中で実体化して返す案は採らなかった。
リプレイバッファから抽出した局面を159面の単精度で展開すると、1局面あたり約92 KBになるので、盤の配列のまま保持してバッチごとに展開する。

## 結果

拡張モジュールが返す局面の列が固定局面集の入力と一致することは、Rustの試験とPythonの試験で確かめる。
補助目標の教師がなくなったので、データセットのメモリは1局面あたり置き換えたADRより28＋4C＋2Lバイト（Cは相手の候補数、Lは相手の局面の合法手数）減る。
探索なしで記録した固定の検証用データを読むときは、拡張モジュールが指した手を確率1の候補として、今までと同じ局面を返す。
訓練に受け付ける規則セットを`lishogi`へ切り替える変更は、[2回目の実行の設計書](../plans/alphazero-rl-2.md)のフェーズ1で行う。
成り権の保留を追跡する規則セットで学習する場合は、入力の面と拡張モジュールの受け入れの検査を変える必要がある。

# プロトコルの入出力の記録を起動引数`--io-log`で有効にする

## ステータス

承認済み。決定日は2026年9月27日。

## コンテキスト

GUI、lishogiのBotブリッジ、または対局ハーネスとの間でだけ起きる不具合を調べるには、エンジンが受け取った行と送った行の記録が要る。
対局ハーネスは子エンジンの送受信を保存しない。
StockfishはUCIのオプションでログのファイルを指定し、標準入出力を複写する（[調査メモ](../research/engine-debugging-survey.md)）。
minaseを起動する側の対局ハーネス、Botブリッジ、および開発用GUIは、いずれも起動引数を指定できる。
時間切れの調査では、エンジンが`go`を受けてから`bestmove`を返すまでの時間を、エンジン側の記録から読みたい。
この判断は[デバッグ機能の整備](../plans/archived/debugging-tools.md)で下した。

## 決定

エンジンは起動引数`--io-log <パス>`を受け取ると、そのパスにファイルを新規に作り、受け取った行と送った行を起動からの経過ミリ秒と向きの記号を付けて1行ずつ記録する。
同じパスにファイルがあれば起動をエラーで終え、記録の書き込みに失敗すればエンジンを終了コード1で終える。
行の形式と時刻の定義は`crates/minase/src/bin/minase/io_log.rs`のdocコメントにある。

## 検討した代案

USIのオプションでログを有効にする案は、`setoption`より前の握手を記録できないので採らなかった。
既存のファイルを上書きする案は、同じパスを指定した2回目の起動が調査中の記録を消すので採らなかった。
記録が欠けても対局を続ける案は、記録が調査の資料として信頼できなくなるので採らなかった。

## 結果

起動引数なので、USIだけでなくCECPの入出力も記録できる。
`--io-log`を指定しない場合の入出力は1バイトも変わらない。
対局ハーネスは局ごとにエンジンを起動し直すので、起動コマンドに固定のパスを書くと2局目の起動が失敗する。
`--io-log`はエンジンの起動引数として、CONTRIBUTING.mdの互換性の対象に含まれる。

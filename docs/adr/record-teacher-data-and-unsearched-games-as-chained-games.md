# 教師データと探索を行わない対局の記録を、対局単位の連鎖で記録するMNSDの1形式にまとめる

## ステータス

承認済み。決定日は2026年11月15日。

## コンテキスト

[教師データを対局単位の連鎖で記録する決定](archive/record-teacher-data-as-chained-games.md)は、教師データの形式をMNSDに一本化した。
MNSDは、1局ごとに開始局面を1回だけ書き、以後は1手ごとに指した手、探索値、除外の理由などの印、および方策を並べ、読み手は対局管理の`Game`で手順を再生して各局面を復元する形式である。
1局は、指した手を持つ局面ごとの記録と、最後の手を指した後の局面の記録からなり、この局面ごとの記録を項目と呼ぶ。
ファイルのヘッダにある教師の種類の欄は、αβ探索とモンテカルロ木探索（MCTS）の2つの値をとっていた。
この欄は、項目の並び（MCTSの項目だけが探索の訪問回数を持つ）、探索値の2バイトの読み方（αβ探索は評価値、MCTSは勝率）、およびどの道具がそのファイルを受け付けるかを決める。

2026年11月13日に、AlphaZero型探索のネットを、学習に使わない固定の棋譜で診断することが決まった（[固定の検証用データの設計書](../plans/archived/zero-validation-games.md)）。
棋譜はlishogiの人間同士の対局であり、局面ごとの探索値を持たない。
診断の道具は、この棋譜を、学習器と同じ拡張モジュールで、学習器と同じ局面の列として読む必要がある。
MNSDは、対局の由来が実戦の対局であること、項目が探索値を持たないこと、および方策が指した手1つであることを、すでに表せた。
足りないのは、探索を行っていないことを表すヘッダの値だけであった。

## 決定

教師データの形式はMNSDの版3だけとし、ヘッダの教師の種類に、αβ探索とMCTSに加えて「探索なし」を足す。
探索なしのファイルでは、どの項目も探索値、探索の訪問回数、および除外の理由を持たない。
方策は、指した手を持つ項目ではその指した手1つとし、最後の項目では持たない。
ヘッダにある教師の重みのチェックサムと教師の規模は0とする。
書き込みと読み込みの両方で、これに反するファイルを拒む。
NNUEとPSTの学習器はαβ探索のファイルだけを、AlphaZero型探索の学習器はMCTSのファイルだけを学習に読み、探索なしのファイルは診断の道具だけが読む。
対局単位の連鎖、着手の番号、方策の確率、および除外の理由の付け方は、本決定が置き換えた[対局単位の連鎖の決定](archive/record-teacher-data-as-chained-games.md)と、それを詳しくした[着手の番号と方策の確率の決定](index-moves-into-sorted-legal-moves-and-store-policies-as-probabilities.md)および[除外の理由の決定](record-excluded-positions-with-a-reason.md)のとおりである。
仕様は`crates/minase/src/training/records.rs`のdocコメントにある。

## 検討した代案

教師の種類にαβ探索の値を流用する案は採らなかった。
探索なしの記録は訪問回数も探索値も持たないので、αβ探索の種類のままでも読み書きはできる。
しかし、探索を行っていないファイルに、教師の種類はαβ探索であると書くことになる。
エンジンの開発者は2026年11月13日に、人間の棋譜をαβ探索によるものとして扱うのはおかしいとして、この案を退けた。
既存の`minase data lishogi games`が書くファイルは、局面の出どころが人間の棋譜で、探索値と最善手をαβ探索が付けたものなので、教師の種類がαβ探索、由来が実戦の対局のままで正しい。

検証用の新しい形式を作る案は、局面の符号化、着手の番号、および読み込みを2つの形式でそろえ続ける必要があり、[各形式の版を1つにする決定](keep-one-version-per-saved-format-and-allow-run-private-scratch-files.md)にも反するので採らなかった。
診断のたびに棋譜のファイルを再生する案は、学習器の拡張モジュールとは別の再生と符号化の経路を持つことになるので採らなかった。
形式の版を上げる案は採らなかった。
ファイルの構造は変わらず、今の版のファイルはそのまま読めるからである。
新しい種類のファイルを古いバイナリが読むと、未知の教師の種類としてエラーになる。

探索なしの記録に除外の理由を持たせる案は採らなかった。
除外の理由は、学習の用途ごとに局面を選別するための印であり、診断は指した手のあるすべての局面を使うからである。

## 結果

探索なしのファイルを書くのは`minase data lishogi validation`であり、読むのはAlphaZero型探索の学習器にある診断の道具`minase_zero external-eval`だけである。
NNUEとPSTの学習器は、これまでMCTSのファイルを拒んでいたのと同じく、探索なしのファイルを拒む。
AlphaZero型探索の学習器は、学習のための読み込みで教師の種類がMCTSでないファイルを拒むので、探索なしのファイルを学習に混ぜることはできない。

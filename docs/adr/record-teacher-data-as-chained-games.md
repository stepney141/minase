# 教師データを対局単位の連鎖で記録するMNSDの1形式にまとめる

## ステータス

承認済み。決定日は2026年10月14日。

## コンテキスト

MNSDの版1は、評価関数NNUEとPSTの学習のために、局面ごとに盤の144バイトを含む160バイトのレコードで局面、探索値、対局結果だけを持っていた。
局面の由来はレコードの1バイトにあった（[由来をMNSDのレコードに置く決定](record-the-origin-in-mnsd-records.md)）。
一方、[AlphaZero型探索の設計書](../plans/alphazero.md)は、方策を学ぶために、ネットの出力の位置で方策を持つ別の形式MNZTを、masterへ統合していないブランチで定義していた。
2026年10月14日にエンジンの開発者は、将棋のhcp、hcpe、hcpe3、psvの間のように教師データに互換を持たせ、できれば形式を統一することと、圧縮で縮めたデータも学習の際には展開が要るので圧縮前の生のバイナリを小さくすることを求めた。
将棋とチェスの形式を調べると、自己対局のデータには、開始局面と手順から局面を復元する対局単位の形式（dlshogiのhcpe3、Stockfishの`.binpack`）が使われていた（調査の出典は[教師データ形式の統一の設計書](../plans/archived/unified-teacher-format.md)の参考資料にある）。
中将棋の12×12の盤は、これらの既存形式のどれでも表せない。

## 決定

教師データの形式をMNSDの版2に一本化し、MNZTを作らない。
版2は対局単位の形式であり、1局ごとに開始局面を1回だけ書き、以後は1手ごとに指した手、価値、印、および方策を並べ、読み手は対局管理`Game`で手順を再生して各局面を復元する。
由来、結果、および終局理由は対局ヘッダに、規則セット、教師の種類（αβ探索かMCTSか）、および教師の規模はファイルのヘッダに置き、教師の分類と検証分割は版1と同じ欄から同じ規則で決める。
NNUEとPSTの学習器は、除外の理由がなく価値を持つ局面だけを、ファイル、対局、項目の順に読み、教師の種類がMCTSのファイルは拒否する。
学習器は復元した局面を、駒のある升の144ビットの集合と駒ごとの駒コードの可変長の列でメモリに持ち、ファイル単位で並列に読む。
仕様は`crates/minase/src/training/records.rs`と`crates/minase-trainer/src/data/`のdocコメントにある。

## 検討した代案

MNSDとMNZTを併存させて変換を用意する案は、局面の符号化、対局の識別、および検証分割を2つの形式でそろえ続ける必要があり、[各形式の版を1つにする決定](keep-one-version-per-file-format.md)にも反するので採らなかった。
局面ごとに盤を書く案は、版1のデータ20万局面の実測で、1升1バイトの盤なら1局面約182バイト（方策を含む）、空き升を1ビットにした上限つきの符号でも約130バイト、可変長の符号と位置の索引でも約85バイトになり、対局単位の約9バイトより1桁大きいので採らなかった。
将棋のhcpのような固定長のハフマン符号は、盤上の駒が4〜92枚と変わる中将棋では最悪の場合が大きくなる。
ファイル全体をzstdで縮める案（同じ20万局面で1局面11.9バイト）は、学習器が使うときに展開した大きさが変わらないので採らなかった。
着手を合法手と照合せずに適用する案は、壊れたファイルから不正な局面を作り得るので採らなかった。
版1のファイルを1局面だけの対局として版2へ書き写す案は、元の対局番号や「記録なし」の終局理由のような移行のためだけの値を形式に持ち込むので採らず、既存のデータは必要な分を生成し直す。
dlshogiのhcpe3が持つ最大手数のフラグ、対戦相手、および最大手数の設定は、学習の損失には使われず、手数の上限に達した対局も外部エンジンとの対局も書かない現在の生成器では意味を持たないので、形式に含めない。
学習器のメモリで版1と同じく盤を144バイトで持つ案は、版1のデータの平均53枚の駒に対して半分が空き升になるので採らなかった。
駒の頻度に応じたハフマン符号（平均約53バイト）は、特徴量を作るたびの復号が重くなるので採らなかった。

## 結果

同じ条件で生成すると、版2のファイルは版1の約17分の1になり（202万局面の自己対局で324 MBが19 MB）、NNUEとPSTの学習結果はビット単位で一致した（[照合の記録](../measurements/unified-teacher-format-equivalence.md)）。
読み手は合法手の生成を毎手行うので、手順の再生に1項目あたり約11マイクロ秒かかり、学習器は版1のメモリ写像より読み込みが遅い。
学習器はファイル単位の並列読み込みでこの時間を抑え、811万局面の4ファイルでは前処理が版1より約31秒長くなった。
同じ4ファイルの学習の最大常駐メモリは、版2の2.32 GBが、メモリ写像を使う版1の2.73 GBより小さかった。
手順が途切れている版1のファイルは版2へ移せないので、2026年10月14日に`data/`の版1のファイル44個（約18.3 GB）を削除し、以後の学習に要るデータは、それを必要とする計画の着手時に生成し直す。
PythonのDLの学習器は版2の局面を自分では復元できないので、AlphaZeroの計画を統合するときに、Rustの読み込みをPythonから呼ぶ拡張モジュールを作る。
外部の教師データ形式との互換は持たない。

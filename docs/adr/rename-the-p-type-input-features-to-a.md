# 王の位置で条件付けない入力特徴集合の名前をP型からA型へ改め、重みファイルの構造記述の名前も`A`にする

## ステータス

承認済み。決定日は2026年11月25日。

## コンテキスト

minaseのNNUEには、入力特徴集合が2つある。
1つは自玉の升ごとに第1層の別の行を引くHalfKP_vmで、もう1つは王の位置で条件付けず、盤上の全部の駒の駒状態と升の組と、先獅子の対象升を入力にする集合である。
後者は、2026年10月に[NNUEによるPST＋FMの完全代替の設計書](../plans/archived/nnue-replacement.md)で「P型」と名付け、コードでは`FeatureSet::P`、重みファイルの先頭の構造記述では`Features=P(Friend)[13680->256x2]`と書いてきた。
この名前は外部の文献から採ったものではない。

将棋とチェスのNNUEでは、`P`は玉を除く駒の特徴を指す。
やねうら王の`Features::P`は「玉以外の駒のBonaPiece」であり、玉の位置を表す`Features::K`と組み合わせて`kp_256x2-32-32`の入力に使われる（[p.h](https://github.com/yaneurao/YaneuraOu/blob/a7a683b536de491d5f956f42dfca823a19c9ea03/source/eval/nnue/features/p.h#L16-L20)）。
Stockfishの学習器nnue-pytorchは、学習だけに使う仮想の特徴として、`HalfKP`に玉を除く64升×10駒種の`P`を、`HalfKAv2_hm`に両方の玉を含む64升×12駒種の`A`を足していた（[halfkp.py](https://github.com/official-stockfish/nnue-pytorch/blob/ba499f2819dab17ec1784ea6522ee004ff32fd57/halfkp.py#L46-L47)、[halfka_v2_hm.py](https://github.com/official-stockfish/nnue-pytorch/blob/ba499f2819dab17ec1784ea6522ee004ff32fd57/halfka_v2_hm.py#L87)）。
minaseのこの集合は王将と太子も駒状態の1つとして含むので、`P`の名前では玉を除く集合と誤解される。
本ADRと同じ2026年11月25日に、評価ネットの公開名へ構造記述の名前を小文字で入れると決めたので（[公開名のADR](host-evaluation-networks-on-hugging-face-hub-and-name-them-by-structure.md)）、この誤解はファイル名にも及ぶ。
また、玉を除く本来の意味のP型を後で入れたくなったときに、古い呼び名と衝突する。

構造記述の名前は、ヘッダのハッシュにも入っている。
入力特徴集合のハッシュは名前のFNV-1aで計算し、ヘッダのネットのハッシュと、区分数の後に置く第1層のハッシュは、この値から作る（`crates/minase/src/eval/nnue/input/mod.rs`）。
そのため、ファイル上の名前を変えると、既存の重みファイルは読み込みのときに名前の不一致で拒否される。

## 決定

この入力特徴集合の名前を、nnue-pytorchの全駒の特徴の名前に合わせて「A型」に改める。
文書の呼び名、コードの`FeatureSet::A`、重みファイルの構造記述の名前`A`、および評価ネットの公開名の`sfnn_a_…`を、すべて同じ名前にそろえる。
重みファイルの形式の版番号`0x7AF32F21`は変えず、旧名`P`のファイルを読む互換の経路は設けない。
既存のネットは、構造記述の1文字と2つのハッシュだけを書き換えてA型の名前のファイルへ変換し、変換後のファイル全体のSHA-256で識別する。
過去の文書も、凍結した設計書、記録、および承認済みのADRを含めて、地の文の「P型」をA型に書き換える。
ただし、当時のファイルのバイト列やコードの識別子を引用した部分、文書のファイル名、パス、およびURLは変えない。
`P`の名前は、玉を除く本来の意味の入力特徴集合を入れるときのために空けておく。

## 検討した代案

呼び名、コード、および公開名だけを`A`にして、ファイル上の名前は`P`のまま残す案は、既存のネットとSHA-256をそのまま使える。
しかし、公開名に入れる特徴の名前が構造記述の名前を小文字にしたものという規則に例外ができ、構造記述の`P`がA型を指すという対応を読み手が覚える必要が残るので、エンジンの開発者の判断で採らなかった。

旧名`P`のファイルも読めるように、名前の照合で`P`を`A`の別名として受け付ける案は、AGENTS.mdが禁じる互換のための代替経路に当たるので採らなかった。

過去の文書を書き換えず、注記で読み替えさせる案は、凍結した文書の不変性を守れる。
しかし、本来の意味のP型を後で入れると、過去の文書の「P型」と新しい「P型」が別のものを指し、注記の日付を見なければ区別できなくなるので採らなかった。

改名前のネットとの混同を避けるために、本来の意味の集合を後で入れるときにも`P`の名前を使わないと今から決める案は、玉を除く集合を将棋とチェスの慣習どおり`P`と呼べなくなるので採らなかった。
本来の意味の集合は特徴の数が13,680と異なり、構造記述に次元が入るので、改名前のネットと読み込みのときに取り違えることはない。

## 結果

旧名`P`の重みファイルは、minase 3.0.1以降のエンジンと学習器では読めない。
minase 3.0.0までのエンジンは逆に、A型の名前のファイルを読めない。
読めるファイルの組が変わるだけで評価は変わらないので、エンジンの開発者はこれを互換性を壊す変更とは扱わず、パッチ版の3.0.1として出す。

変換したネットはSHA-256が変わるので、標準のネットの指定は変換後のSHA-256に移す。
それまでの測定記録、学習の記録、および教師ファイルのヘッダの`network_checksum`は、変換前のSHA-256のまま残る。
変換前のファイルもNASに残すので、記録の再現には変換前のファイルとminase 3.0.0までのエンジンを使う。

Hugging Face Hubのモデルリポジトリでは、mainの`nnue/p/`から変換前のファイルを外し、変換したファイルを`nnue/a/`に置く。
minase 3.0.0用のファイルは、外す前のリビジョンを固定したURLで取得できる。

2026年11月25日より前のコミットメッセージ、ブランチ名、文書のファイル名、変換前のネットのヘッダ、およびminase 3.0.0までのコードでは、`P`がA型を指す。
これらは書き換えられないので、[ADRの用語の節](README.md#用語)と[NNUEの評価関数の手引き](../guides/evaluation-nnue.md)に日付つきで書く。

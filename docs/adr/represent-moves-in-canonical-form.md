# 着手を経由升の捕獲だけを区別する正準形で表す

## ステータス

承認済み。決定日は2026年7月31日。

## コンテキスト

獅子、角鷹、および飛鷲は、1手の中で2段階に動ける（RULES.md第11条、第12条）。
当初の着手の型は、1段階の移動、2段階移動、および直接の跳びを別々の列挙子で表し、生成器は2段階移動を経路ごとに列挙していた。
空升を経由する2段階移動は、同じ到達升への跳びやじっとと同じ結果局面になるので、盤上で同じ着手が複数の値で現れた。
[指し手正準化の設計](../plans/move-canonicalization.md)によれば、裸の獅子1枚で生成される88手のうち、結果局面が異なる手は25手だった。
結果局面と合法性が同じなのに値が異なる手は、探索で同じ部分木を重ねて読ませ、外部から受け取った着手の照合も複雑にする。

## 決定

着手を、移動元、経由升、到達升、および成りの4つ組の単一の構造体で表し、経由升は第1段階で相手駒を取る場合にだけ持たせる。
経由升が空の2段階移動は生成も表現もせず、跳びとして表し、じっとは駒ごとに1手だけ生成する。
正準形の不変条件と生成規則の細目は、`Move`と獅子および角鷹・飛鷲の生成関数のdocコメントにある。

## 検討した代案

列挙子を分けた型のまま、生成の段階で重複する経路だけを除く案は採らなかった。
型が重複を表現できる限り、生成器以外の経路から来た着手との照合で同じ問題が残るからである。
不変条件をスマートコンストラクタで型に強制する案も採らなかった。
対局管理層は受け取った着手を生成済みの合法手と照合して検証するので、型で弾かなくても不正な値は受理されない。

## 結果

同じ結果局面に至る着手は1つの値になった。
捕獲する升は着手のフィールドに持たず、適用前の局面と着手から導く。
経路を別々に数える外部実装とは合法手の数が一致しなくなり、perftの数値照合をやめる判断につながった（[perftの数値を合法手生成の正しさの基準にしない](verify-movegen-without-perft-counts.md)）。
外部の記法は経路を書くので、USIの解析は中間升に相手駒がない3升の表記を正準形へまとめ、出力はじっとに中間升を補う（`notation::usi`）。

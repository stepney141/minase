# 規則セットは起動後のプロトコルで必ず指定させ、エンジンは既定値を持たない

## ステータス

承認済み。決定日は2026年11月12日。

## コンテキスト

minaseは、対局に採用する規則コードの組である規則セットを、起動引数`--rules`で必須の値として受け取り、起動後はUSIのオプション`RuleSet`とCECPの`option RuleSet=`でも受け取っていた。
同じ情報の入口が2つあり、エンジンを起動する側は、引数の組み立てとオプションの送信の両方を知る必要があった。
オンライン対局サイトlishogiとエンジンを仲介するLishogi-Botは、エンジンへ起動引数を渡せないので、配備用のリポジトリは引数を固定した起動用のスクリプトを置いていた。
[起動引数と診断ツールをUSIへ移す計画](../plans/cli-to-usi.md)は、起動後のプロトコルで渡せる情報をプロトコルへ集めることにし、規則セットの入口を1つにする方法を決める必要があった。

起動引数をなくすと、規則セットを受け取る前のエンジンが何の規則を持つかが問題になる。
起動引数`--rules`は必須だったので、これまでのエンジンは、指定のない規則で対局を始めることがなかった。

## 決定

起動引数`--rules`を削除し、規則セットはUSIのオプション`RuleSet`、またはCECPの`option RuleSet=`でだけ受け取る。
エンジンは規則セットの既定値を持たず、未設定のままUSIの`isready`またはCECPの最初の`new`を受けると、エラーの行を出して終了コード1で終わる。
最初に受けた規則セットは現局用と次局用の両方の規則になり、2回目以降は[次局から確定する](commit-pending-rules-on-first-position.md)これまでの扱いに従う。
宣言と拒否の文言は、`crates/minase/src/protocol/usi.rs`と`crates/minase/src/protocol/cecp.rs`のdocコメントにある。

## 検討した代案

`RuleSet`の既定値を規則セット`JCSA`にする案は採らなかった。
指定を忘れたクライアントが、意図しない規則のまま対局を始められるからである。
起動時に規則を明示させていた契約を、プロトコルの側で保つ。

未設定を最初の`position`で検出する案は採らなかった。
Lishogi-Botと対局ハーネスは、どちらも`usi`、`setoption`、`isready`の順に送るので、`isready`のほうが早く、1か所で検出できる。

未設定の`isready`にエラーの行だけを返して待つ案は採らなかった。
`readyok`を待つ相手が、応答の期限まで止まるからである。
推論器の準備に失敗したときも、minaseは同じくエラーの行を出して終了する。

未設定の状態を対局の状態機械`Engine`の内部に持たせる案は採らなかった。
現局用の規則、次局用の規則、および対局そのものに未設定の場合分けが広がるからである。
プロトコルの構造体が`Engine`を0個または1個所有し、最初の有効な規則セットを受けた時点で生成する。

## 結果

エンジンは`minase --protocol <usi|cecp>`で起動でき、起動する側は規則セットを起動引数として組み立てる必要がなくなった。
エンジンを起動するすべてのクライアントは、`isready`または`new`より前に規則セットを送る必要がある。
XBoardでは、起動設定`-firstOptions "RuleSet=<規則>"`を指定する。XBoard 4.9.1がこのオプションを最初の`new`より前に送ることは、実物の入出力の記録で確かめた。
`isready`を送らない入力に備えて、対局の状態を必要とするコマンドは、規則セットが未設定の間はエラーの行で拒否し、この場合はセッションを続ける。
`USI_Hash`や`Threads`のように対局に依存しない設定は、規則セットより先に届いても、届いた時点で検査して適用する。

対局ハーネスと係数調整`minase spsa`が`commit:`のエンジンを起動する固定の引数は、`--protocol usi`だけになった。
起動引数`--rules`を必須としていた版のコミットを対戦相手にする測定では、その側に`--baseline-args`で引数を足す（[起動引数を足す決定](append-startup-arguments-to-commit-engine-specs.md)）。
固定の引数が変わったので、対局ハーネスの記録形式の版を7から8へ上げ、版7の実行ディレクトリの再開と集計は、その測定を開始したハーネスで行う。
`match run --rules`も既定値をなくし、新規の実行で必須にした。

# 反復による勝敗を、詰み帯の内側の専用の帯で表し、置換表の打ち切りに使わない

## ステータス

承認済み。決定日は2026年10月15日。

## コンテキスト

探索木の中で求める反復の勝敗は、対局履歴と探索経路に依存する。
R1（RULES.md第31条）では、同じ局面へ戻る着手が攻撃側の負けになるかどうかは、その周回の全着手が攻撃的であったかどうかで決まる。
R2とR3では、合法手がすべて禁止手である局面の負け（第23条）が、どの局面が既出かという履歴に依存する。
これらの値を詰み帯の値で返すと、置換表に保存された値が、別の経路、後の手番の探索、または置換表を共有する別のワーカーで、裁定の前提を満たさない局面の打ち切りに誤って使われる（graph history interaction）。
[探索内の反復の扱いに関する既存実装の調査](../research/search-repetition-prior-art.md)によれば、やねうら王、Apery、およびPikafishは詰み帯をそのまま使い、ElephantEyeは詰み帯の内側に専用の帯を設けて置換表の打ち切りから除く。
決定の経緯は[探索部の反復負け回避と反復禁止](../plans/archived/search-repetition.md)の設計書にある。

## 決定

反復による勝敗は、詰み帯の下端`MATE_THRESHOLD`（29,744）のすぐ内側に設けた専用の帯の値で返す。
勝ちの値は`REPETITION_WIN − ply`（`REPETITION_WIN`は29,743）、負けはその負値であり、絶対値が`REPETITION_BAND_START`（29,487）以上`MATE_THRESHOLD`未満の範囲を専用の帯とする。
置換表はこの帯の値を手数の補正なしに記録し、通常探索と静止探索のどちらの照会でも打ち切りには使わず、記録手だけを使う。
詰み帯に対する探索の保護（浅い枝刈りの共通条件、負の詰み帯を脱するまで手を飛ばさない条件、null move pruningの開始条件と返却値の制限、aspiration windowsの窓の端、補正履歴の更新の除外）は、閾値を専用の帯の下端へ下げて両方の帯に適用する。
USIの投了判定では、負の専用の帯の値については`ResignValue`によらず投了と判定しない。

## 検討した代案

詰み帯の値をそのまま使う案（やねうら王、Apery、Pikafish）は、置換表を通じた漏れを防げないので採らなかった。
R1の攻撃側の判定は周回の全着手に依存するので、連続王手の回数だけを見る将棋より経路依存が強い。
Pikafishのように置換表のキーへ既出の印を混ぜる案は、既出の状態が異なる経路の間で置換表がヒットしなくなるうえ、周回の攻撃側という経路依存までは区別できないので採らなかった。
引き分けの値`DRAW_SCORE`（0）も打ち切りから除く案（ElephantEye）は、引き分けの値を評価関数が返さない値にする必要があり、本決定の範囲を超えるので採らなかった。
`MATE_THRESHOLD`自体を下げる案は、置換表の詰み値の手数補正とUSIの`mate`表示まで変わるので採らず、保護の閾値には別の定数を設けた。

## 結果

帯の値は手数補正を受けないので、どの深さで読み出しても帯の中にとどまり、通常の値として誤って打ち切りに使われることはない。
専用の帯の値に基づいて選ばれた記録手は順序づけに使われ、帯の値を含めて求めた祖先ノードの通常の評価値は置換表に残るので、経路依存の誤りは完全には消えない。
これは、反復を引き分けとする従来の近似が既に持つ漏れと同じ性質のものである。
置換表に保存された詰みの距離に読み出し位置の手数を足した和が256を超える深い詰みの値は、補正後に専用の帯へ入るので打ち切りに使われなくなる。
これは実際の探索深さでは起こらない既知の制約である。
通常の評価値の絶対値はNNUEの`EVALUATION_LIMIT`（28,999）以下であり、帯に届かないことをコンパイル時の検査とテストで確かめている。
定数と判定関数は`crates/minase/src/search/mod.rs`に、置換表の扱いは`alphabeta/negamax.rs`と`alphabeta/quiesce.rs`に、投了の扱いは`crates/minase/src/protocol/usi.rs`の`should_resign`にある。

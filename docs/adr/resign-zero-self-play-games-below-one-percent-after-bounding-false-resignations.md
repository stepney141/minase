# AlphaZero型探索の自己対局は、選んだ手の勝率が1%を下回った側を投了させ、誤った投了の割合の片側95%上限が5%以下と確かめてから有効にする

## ステータス

承認済み。決定日は2026年10月28日。

## コンテキスト

minaseの自己対局は1局の平均が293〜435手と長く（[評価関数の設計書](../plans/archived/evaluation.md)、[世代1の設計書](../plans/archived/evaluation-gen1.md)）、投了がなければ、勝敗の決まった終盤に生成時間の多くを費やす。
一方、誤った投了で終えた対局は勝敗の教師が誤っており、投了した対局だけを見ても、どの対局の投了が誤りだったかは分からない。
強化学習（RL）の初めのサイクルでは、ネットの価値の出力が意味を持たない。

dlshogiの自己対局は、選んだ手（訪問回数が最大の手）の勝率pについて|2p−1|が0.99を超えた時点、つまり勝率が0.5%を下回るか99.5%を上回った時点で対局を終え、同じ勝率を教師の評価値にも使う（DeepLearningShogiの`selfplay/self_play.cpp`、コミット79df19e）。
lc0は、投了の条件を満たしても投了させずに最後まで指させる対局の割合（`resign-playthrough`）を設け、誤った投了を監視する。
自己対局の探索は、根の候補手の多くに少数の訪問を均等に配るGumbel AlphaZeroのSequential Halvingで行う（[Gumbel AlphaZeroのADR](use-gumbel-alphazero-for-zero-self-play-search.md)）。
探索木の中の同一局面の反復は、審判層の裁定の後に、直近の出現からの1周だけを調べる近似で打ち切る（[MCTSの終局判定のADR](adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)）。

[以前の決定](archive/resign-zero-self-play-games-below-one-percent-after-calibration.md)は、あるサイクルの誤った投了の割合が5%以下になったら次のサイクルから投了を有効にすると定めていた。
2026年10月28日の[監査](../audits/alphazero-rl-readiness-2026-10-28.md)の「投了の較正の標本数」の節は、この割合が点推定であり、標本数の条件がないことを指摘した。
投了の条件が成立して最後まで指させた対局が1局だけで、その1局で投了の条件が成立した側が負けていれば、観測値0%で有効化の条件を満たしてしまう。
独立な二項試行で誤りを0件観測したときの片側95%上限は1−0.05^(1/n)であり、n=1なら95%、n=100なら約2.95%である。
エンジンの開発者は、[監査対応](../plans/archived/alphazero-audit-remediation.md)で有効化の条件に標本数と上限を加え、投了の閾値、誤った投了の数え方、および除外の規則は以前の決定から引き継いだ。

## 決定

ある側の手番で、Sequential Halvingが最後に残した手のQ（根の手番側から見た期待得点で、勝ちを1、引き分けを0.5、負けを0とする）が1%を下回ったら、その側を投了させる。
学習データの各局面の価値（根の期待得点）にも、同じQを記録する。
ただし、根の勝敗の確定が反復に由来する場合と、根の部分木に反復で打ち切った節点が1つでもある場合は、勝率によらず投了しない。
最後に残った手が未訪問の場合は、探索がその手を調べておらず勝率の根拠がないので投了せず、価値にはGumbelの方式が未訪問の手に与える混合価値（mctxの`qtransform_completed_by_mix_value`の値）を記録する。
訪問した候補手がすべて確定した負けになると、確定した負けを最後の手の候補から除く規則（[Gumbel AlphaZeroのADR](use-gumbel-alphazero-for-zero-self-play-search.md)の結果の節）により、未訪問の手が最後に残る。

投了は初めのサイクルでは無効にし、すべての対局を最後まで指させながら、投了の条件が成立した時点を記録する。
誤った投了の割合は、最後まで指させた対局のうち投了の条件がいずれかの側で成立した対局の数nを分母とし、条件が最初に成立した側が負けなかった対局（勝ち、引き分け、手数の上限での打ち切り）の数xを分子とする。
各サイクルの完了したすべての塊から1対局を1標本としてxとnを数え、二項分布のClopper–Pearson法による片側95%上限を求める。
n≥100かつ上限が5%以下のサイクルに限り、次のサイクルの投了を有効にし、有効にしたサイクルでも全対局の20%は最後まで指させて同じ較正を続ける。
条件を満たさないサイクルの次のサイクルは、n=0の場合を含めて投了を無効にする。
あるサイクルの割合x/nが5%を超えたら、そのサイクルの投了で終えた対局を学習データに入れず、その分を投了を無効にして生成し直す。

## 検討した代案

投了しない案は採らなかった。
勝敗の決まった終盤の手順に生成時間の多くを費やすからである。

根の訪問全体の平均を勝率とする案は採らなかった。
Sequential Halvingは初めに最大16手へ訪問を均等に配るので、平均は悪い手の価値で下がり、投了を早めて価値の教師も下げる。

dlshogiと同じ0.5%を閾値とする案は採らなかった。
自己対局生成器の起案時の設計書は、dlshogiの閾値を勝率0.99（1%）と読み違えて1%を採っていた。
2026年10月27日の着手時にdlshogiのソースで0.5%と確かめたが、閾値の誤りは誤った投了の割合の較正で監視するので、1%のまま維持した。

誤った投了の割合の点推定が5%以下なら有効にする以前の条件は採らなかった。
標本が少ないサイクルでは、誤りの多い閾値でも偶然に条件を満たすからである。

## 結果

n=100の場合、上限はx=0で約2.95%、x=1で約4.66%、x=2で約6.16%なので、有効にできるのは誤った投了が1件以下のときである。
投了の有無と最後まで指させる割合は、生成器の起動引数`--playthrough-percent`で受け取り、100は投了の無効を表し、投了を有効にしたサイクルでは20を与える。
xとnは生成器のサイクルの集計`summary.json`の`false_resignations`と`resign_triggered_playthrough_games`であり、上限の計算と有効化の判断は[強化学習の実行](../plans/alphazero-rl.md)が各サイクルの開始前に行う。
誤った投了の割合はサイクルのすべての塊が確定するまで決まらないので、生成器は投了で終えた対局を塊ごとに別のファイルに書き、割合が5%を超えたサイクルでは、そのファイルを学習データのファイルの一覧から外す（[塊のADR](commit-zero-self-play-cycles-in-fixed-game-chunks.md)）。
外した対局数の分を生成し直す処理は、強化学習の実行が別の出力先で生成器を起動して行う。
閾値と上限は`crates/minase/src/bin/minase/zero_selfplay/`の定数`RESIGN_THRESHOLD`と`FALSE_RESIGNATION_LIMIT`にある。

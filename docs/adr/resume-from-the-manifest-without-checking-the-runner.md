# 再開は実行条件を`manifest.json`だけから読み、runnerと測定機を照合しない

## ステータス

承認済み。決定日は2026年10月5日。

## コンテキスト

`minase match run`と`minase spsa`は、中断した実行を`--resume`で再開できる。
以前の再開は、利用者に全条件を指定し直させ、保存済みの`manifest.json`と完全一致で照合していた。
照合の対象には、対局を進める実行ファイル（runner）自身のSHA-256と、測定機のCPUの情報も含まれていた。
2026年10月5日の[補助ツールのサブコマンド化](../plans/cli-subcommands.md)でrunnerはエンジンと同じ`minase`になったので、探索や評価だけの変更でもSHA-256が変わり、作業ツリーを再ビルドすると測定を再開できなくなった。
fishtest、fastchess、cutechess-cli、およびAyaneは、いずれも再開時にrunner自身のハッシュを照合しない（[再開条件の簡素化の参考資料](../plans/match-resume-simplification.md#参考資料)）。
fastchessは、中断時に保存した設定ファイルだけを読んで再開する（[再開条件の簡素化の参考資料](../plans/match-resume-simplification.md#参考資料)）。
審判層、開始局面の生成、および時計の裁定の意味の変化は、審判層の試験、perft、および固定シードの出力の一致で検証している。
実行ディレクトリの記録形式は版で区別され、この決定より前の版4は起動ごとの記録`invocations.json`を持たない。

## 決定

`--resume`は実行条件をすべて`manifest.json`から読み、再開時に条件を変える引数はペア数の目標を引き上げる`--target-pairs`だけとする。
runnerの版とSHA-256、および測定機は照合せずに起動ごとに`invocations.json`へ記録し、対局するエンジンの実行ファイルのSHA-256は引き続き照合する。
`random`はSHA-256を照合せずに指定の種類だけで同一とみなし、版4の実行ディレクトリは集計などの読み取りでだけ受け付けて再開を拒み、手順の詳細は`RunStore::resume`と`match_runner`の`resume`モジュールのdocコメントに従う。

## 検討した代案

runnerが自分の実行ファイルをハッシュをキーにした置き場へ保存し、ハッシュが異なる再開ではそのパスを示して止める案は、先行例のない照合を保つために保存と手順を増やすので採らなかった。
対局の進行を統括するrunnerをPythonのスクリプトへ移す案は、スクリプトが呼ぶ`minase`の同一性の照合が残るので、問題を解消しない。
再開時に同時対局数を測定機に合わせて変える案は、時間制御の対局でエンジンが受けるCPUの競合が再開の前後で変わるので採らなかった。
版4の実行ディレクトリへ版5の起動の記録を書き足す案は、1つの実行ディレクトリに2つの形式が混ざるので採らなかった。

## 結果

作業ツリーの`minase`を再ビルドした後でも測定とSPSAを再開でき、起動の記録に複数のrunnerが現れた測定はそのことを測定記録に書く。
ツールチェーンの更新などでコミットのビルド結果が変わるとエンジンの照合が失敗し、その測定は元のエンジンでなければ再開できない。
物理コア数の少ない測定機で再開すると同時対局数がコア数を超えることがあり、過剰な競合による時間切れは`time_forfeits`に現れる。
`minase match report`の校正用の指標は測定機ごとに意味が変わるので、全起動の測定機の記録が一致しない実行ディレクトリの集計は拒否する。
SPSAの総反復数は利得の式に入るので、`minase spsa --resume`には延長の引数を設けない。

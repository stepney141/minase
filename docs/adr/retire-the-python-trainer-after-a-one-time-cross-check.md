# Pythonの学習器は一度だけ照合した後に撤去し、Rustの学習器だけを正とする

## ステータス

承認済み。決定日は2026年10月13日。

## コンテキスト

評価関数の学習は、Pythonの学習ツール（パッケージ`minase_train`）で行ってきた。
[Rust製NNUE学習器](../plans/archived/nnue-trainer-rust.md)は、NNUEの学習器をRustで書き直し、PyTorchの学習器と1更新の勾配と重みが一致することを確かめたうえで、Pythonの整数参照推論や診断を独立した照合役として残す予定だった。
Pythonの学習器を残すと、学習の式を2つの言語で保守し続けることになり、Rustの学習器へ機能を足すたびにPython側との照合を求める圧力が生じる。
現行の重みに至る手順は、PSTの学習、FMの学習と補正の縮小、同時学習、およびFMの倍率の焼き込みの4つからなっていた。

## 決定

PST、FM、および同時学習の学習器と診断をRustへ移し、Pythonの学習器と一致することを一度だけ確かめてから、Pythonの学習ツール、照合の経路、`minase dev pst-probe`、および`minase dev nnue-probe`を削除する。
以後はRustの学習器だけを正とし、学習の正しさはCPU参照実装と数値微分の一致、GPUのカーネルとCPU参照実装の等価性、および連続した学習と再開した学習のビット単位の一致で保つ（詳細は`nnue::reference`と`nnue::gpu::equivalence`のdocコメントにある）。

## 検討した代案

Pythonの学習器を独立した照合役として残す案は、2つの言語での保守と照合の圧力が続くので採らなかった。
同時学習器のPython実装を含むブランチをマージしてから照合する案は、削除するためのコードを一度取り込むことになるので採らず、そのコミットのソースを`git archive`でリポジトリの外へ展開して実行した。

## 結果

照合は、Pythonが使った初期値と局面の学習順を一時的にRustへ与えて行い、3回の更新の後の状態、短縮した学習の各エポックの検証損失と最良エポック、および書き出した整数の重みが一致した（[照合の記録](../measurements/python-trainer-retirement-checks.md)）。
`fm scale --fm-scale 611`は、当時の既定の重みファイル`crates/minase/nets/pst.bin`をバイト単位で再生成した。
照合のための一時的な引数は照合の後に削除したので、Pythonと同じシードを与えても、Rustの学習器の順列と乱数はPythonと一致しない。
`docs/measurements/`と`docs/research/`に残る`minase_train`を読み込むスクリプトは過去の測定の記録であり、現在は実行できない。
学習器の部品はPyTorchとの互換を条件にせず、学習の式を変えるときは、Pythonとの一致ではなく上記のテストを先に直す。

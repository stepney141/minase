# 補助ツールを実行ファイル`minase`のサブコマンドにし、エンジンはサブコマンドなしで起動する

## ステータス

承認済み。決定日は2026年10月5日。

## コンテキスト

エンジンのcrate`minase`は、エンジン本体のほかに、対局測定、係数調整、学習データの生成、および検証と診断のための補助ツールを10個の実行ファイルとして持っていた。
`cargo install minase`はcrateの実行ファイルをすべて導入するので、エンジンだけを使いたい環境にも開発者向けのツールが入っていた。
補助ツールが使う対局ハーネス、学習データの共有コード、および学習の記録形式は、すでにエンジンのcrateのライブラリ部にあった。
対局ハーネスの`commit:`指定は、指定したコミットを`cargo build --release --bin minase`でビルドし、`--protocol usi --rules <規則>`を付けて起動する（`crates/minase/src/harness/commit.rs`と`player.rs`）。
この判断は[補助ツールのサブコマンド化](../plans/cli-subcommands.md)で下した。

## 決定

補助ツールは実行ファイル`minase`のサブコマンドとし、目的別の群`match`、`data`、`dev`に分け、該当するツールが1つしかない係数調整は群を作らずに`minase spsa`とする。
サブコマンドを指定しない呼び出しをエンジンの起動とし、`--protocol`と`--rules`の必須はこのときだけ課して、エンジンの引数とサブコマンドの併用は拒否する。
引数の規則の詳細は`crates/minase/src/bin/minase/main.rs`の`Arguments`のdocコメントにある。

## 検討した代案

補助ツールを公開しない別のcrateへ移し、`minase`のライブラリ部を依存として使う案は、エンジンの実行ファイルを小さく保てるが、10個の実行ファイルが残り、呼び出し方の規則も統一されないので採らなかった。
各実行ファイルに`required-features`を付けて`cargo install`の対象から外す案は、変更は最小だが、ツールを使うたびに`--features`の指定が要り、呼び出し方も統一されないので採らなかった。
エンジンの起動を`minase usi`のようなサブコマンドへ移す案は、対局ハーネスがコミットごとに起動の形を知る必要を生み、変更の前後をまたぐコミット対コミットの測定が成り立たなくなるので採らなかった。

## 結果

`cargo install`が導入する実行ファイルは`minase`の1つになり、`minase --help`から全ツールを辿れる。
エンジンの実行ファイルに補助ツールのコードが加わったが、探索の局面別のノード数は変わらず、NPSの中央値は移動前の0.9955倍だった（[速度の測定記録](../measurements/cli-subcommands-bench-depth5.md)）。
ツールの実行ファイルのSHA-256は、探索や評価だけを変えたコミットでも変わるので、生成用の実行ファイルは専用のworktreeに固定する（[教訓](../lessons/pin-generation-binary-to-worktree.md)）。
補助ツールはすべて`minase`のプロセスとして動くので、進行中の測定はプロセス名ではなく引数を含めて探す（[教訓](../lessons/check-running-measurements-before-cpu-load.md)）。
グローバルアロケータは`main.rs`の1つの宣言がすべてのツールに適用される（[実行ファイルでmimallocを使う](use-mimalloc-in-executables.md)）。
サブコマンドとその引数は開発者向けであり、CONTRIBUTING.mdの互換性の対象外とした。
変更の前のコミットの`minase`はサブコマンドを知らないので、スクリプトは変更以後のコミットだけを扱い、旧い実行ファイル名へ切り替える分岐を持たない。

# 調整機では物理コア1つにつき1局を既定の置換表で指させ、出品はアーキテクチャ、スレッド数、および貸出期限で絞る

## ステータス

承認済み。決定日は2026年10月17日。

## コンテキスト

SPSAは、vast.aiで借りる物理コアの多い計算機（以下、調整機）で、負荷時の速度の比で伸ばした持ち時間により実行する（[調整機のADR](run-spsa-on-rented-machines-with-nps-scaled-time-controls.md)）。
調整機のADRは、機械をCPUの世代ではなく実測の負荷時の速度と時間単価で選び、所要時間の見込みが24時間を超える機械では本番を始めないと定める。
本ADRは、そのときの同時対局数、置換表の容量、および照会の段階で出品を絞る条件を定める。

時間制御の対局では、探索スレッドの合計を物理コア数以下に抑え、同時対局数を物理コア数から1を引いた数とする（[同時対局数のADR](derive-default-concurrency-from-physical-cores.md)）。
[vast.aiでの教師生成の試走](../measurements/vast-selfplay/vast-selfplay-trial.md)では、SMTの論理スレッドの数まで同時に探索させても、機械全体の探索速度は約11%しか増えず、1スレッドの速度は約半分になった。
`minase spsa`は先後を入れ替えた2局を順に指し、1局につき候補と基準の2つのエンジンがそれぞれ置換表を確保する。
1局あたりの最大常駐メモリは、[段階8の記録](../measurements/strength-stage8/strength-stage8-elo200.md)で約613 MBだった。
[historyの形](../plans/archived/history-forms.md)と[correction historyの表](../plans/archived/correction-history-tables.md)は、エンジン1つあたりのメモリをそれぞれ約157 MBと約37 MB増やす見込みだった。
2026年10月17日の照会では、物理192コアでメモリ126 GBのEPYC 9654の2基構成が1時間1.01米ドル、メモリ755 GBのEPYC 9K84の2基構成が1時間1.87米ドルで出品されていた。

minaseはSIMDの組込み命令を直接使わず、`.cargo/config.toml`の`target-cpu=native`により、ビルドした機械の命令に合わせて最適化される。
物理コア数は出品の情報になく、借りた後に`lscpu`で数えるまで分からない。
測定機での30,000ペアのSPSAには約75時間かかる（[SPSAの手引き](../guides/spsa.md)）。

## 決定

同時対局数は、物理コア数から1を引いた数と、実メモリを1局あたりの最大常駐メモリの1.25倍で割った数の小さい方とし、SMTの論理スレッドは数えない。
1局あたりの最大常駐メモリはセッションごとに測定機で調整用ビルド同士の1ペアを指して求め、1.25倍はOSとrunnerのための余裕とする。
置換表はエンジンの既定の256 MBのまま対局させ、メモリが足りない機械では同時対局数を下げる。

出品は、`cpu_arch`がx86-64で、スレッド数`cpu_cores`が192以上で、貸出期限`duration`が2日以上のものに絞る。
所要時間の見込みの上限は24時間とし、`remote.py`の固定値とする。

## 検討した代案

SMTの論理スレッドの数まで同時に対局させる案は、機械全体の速度が約11%しか増えないので採らなかった。
1スレッドの速度が約半分になると換算係数`f`がほぼ2倍になり、所要時間の短縮は約1割にとどまる。
置換表のメモリは2倍要り、時計の管理の遅れによる時間切れの危険も増す。

調整機だけ置換表を縮める案は、測定機の対局と条件が変わるので採らなかった。
同時対局数を下げずに、メモリの足りる機械だけを候補にする案は、メモリの少ない安い機械を候補から外すので採らなかった。
同時対局数を下げても`f`は実際の同時対局数で測るので、1手あたりの探索量はそろう。

CPUの世代や命令セットで出品を絞る案は、エンジンがビルドした機械の命令に合わせて最適化されるので不要であり、採らなかった。
x86-64に限るのは、テストと測定を行ってきた環境と同じにするためである。
スレッド数192以上は、SMTを持つCPUでは物理96コア以上に当たり、物理コアの少ない機械を借りて試す手間を省くための足切りである。
貸出期限は貸し手が設定した、その機械を借りていられる最長の期間であり、課金は実際に借りた時間の分だけなので、1セッションの最長24時間に再開の余裕を加えた2日を下限とした。

上限の24時間は、1セッションを1日に収め、測定機の約75時間に対して約3倍以上の速さを求めるための値である。

## 結果

物理192コアの機械では、メモリが足りれば同時対局数は191になる。
探索の形の変更で1局のメモリが増えると、同じ機械でも同時対局数が下がるので、`game_rss_bytes`はセッションごとに測り直す。
`remote.py`は物理コア数を`lscpu`で数え、コンテナに割り当てられたCPUを見ないので、出品の表示より少ないCPUしか割り当てられない機械では、割り当てを超える同時対局数で対局させてしまう。割り当ての不足が大きく、負荷時の速度が下がって所要時間の見込みが24時間を超えた場合は、本番を始めずに止まる（[SPSAの手引き](../guides/spsa.md)の第8節）。
上限の24時間を変えるには、`remote.py`の値を変える。
出品の検証済みの扱いと、自動の選択での実メモリの下限は、[検証済みとメモリの下限のADR](accept-unverified-rented-offers-and-require-a-memory-floor-in-automatic-selection.md)が定める。

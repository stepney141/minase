# AlphaZero型探索の学習は、パラメータ数の10倍の局面を持つ直近のサイクルを学習窓とし、そのサイクルの生成量の4倍の標本を窓から一様に抽出して学ぶ

## ステータス

承認済み。決定日は2026年10月31日。
[生成量だけを抽出するADR](archive/sample-zero-training-positions-from-a-window-of-ten-times-the-parameter-count.md)を置き換える。

## コンテキスト

学習窓をパラメータ数の10倍の局面に広げ、窓から一様に抽出する方式は、2026年10月29日の利用者の決定で、価値の過学習への対処として入れた。
窓の決め方と、1回の学習に1つの対局の全局面が入らないようにする理由は、置き換えたADRと同じである。
置き換えたADRは、抽出の数をそのサイクルの生成の訓練局面数Nとしたので、窓が満ちると各局面は平均約1回しか使われなかった。
KataGoの手引きは、新しいデータ1行あたりの学習の回数として、4を慎重な値（conservative）として勧める（`SelfplayTraining.md` 58、67行）。
ふかうら王の学習も、教師局面の使用回数を設計の項目として挙げる（[調査](../research/alphazero-rl-training-efficiency.md)）。
利用者は2026年10月31日に、使用回数を増やすことを含む9つの技法をまとめて採ると決めた。

## 決定

サイクルcの学習窓は、cから古い順にさかのぼって、訓練局面（価値と方策の候補を記録した項目）の合計が初めてネットのパラメータ数の10倍以上になるまでのサイクルとし、合計が届かないうちは全サイクルとする。
抽出の数は、サイクルcの生成の訓練局面数Nの4倍とする。
抽出は、更新に使う長さ4Nの通し番号の列sとして作る。
Tを窓の訓練局面数、q=⌊4N/T⌋、r=4N−qTとし、学習のシードから作る1本の乱数列（PCG64）で、まずT個全体の順列をq回、続いて重複のないr個を、部分的なFisher–Yates法で順に引き、つないだものをsとする。
T≥4Nならq=0となり、重複のない4N個を引く。
拡張モジュールにはsの重複を除いた番号を渡して局面を読み、学習器はsの順に局面を参照する。
更新回数はceil(4N/バッチの大きさ)とし、抽出の検査和`sample_sha256`と読んだ順序の検査和`data_order_sha256`は、重複を含むs全体から求める。
検証集合は最新のサイクルの対局単位の分割とする。
q回の順列で始める抽出の組み立ては、Claudeが補った決定である。

## 検討した代案

抽出の数をNのままにする案は採らなかった。
窓が満ちた後は各局面が平均約1回しか使われず、生成の費用に対して学習の量が小さい。

抽出の数を8Nにする案は採らなかった。
KataGoの手引きが慎重な値として勧めるのは4であり、窓が4,780万局面と大きいので、8倍にしても同じ局面が近い更新に集まりやすくなるだけである。

窓より大きい抽出を、局面ごとに独立に重複を許して引く案は採らなかった。
全体の順列をq回つなぐほうが、各局面の使用回数のばらつきが小さく、T≥4Nのときに今までの手順と同じになる。

## 結果

窓が満ちると、1サイクルの学習は約400万標本を読み、各局面は平均約4回使われる。
最初のサイクルはT=Nなので、全局面の順列を4回つないだ列を読む。
メモリは重複を除いた抽出の数に比例し、読み込みの時間は窓全体の局面数に比例する。
再開の照合は、置き換えたADRと同じ規則を列sに当てはめる。
学習率の予定は[学習率の予定のADR](warm-up-the-zero-learning-rate-over-two-million-samples-and-anneal-it-within-each-cycle.md)が定める。
実装は`tools/train/zero/minase_zero/data.py`の`sample_training_indices`と`read_window`、および`train.py`にある。

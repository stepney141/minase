# エンジンの異常は起こした側の負けとし、手数上限に達したペアは破棄する

## ステータス

承認済み。決定日は2026年8月11日。

## コンテキスト

別プロセスのエンジン同士の対局では、不正着手、クラッシュ、応答の停止、および時間切れが起こり得る（[コミット対コミットの測定](compare-commits-as-separate-engine-processes.md)）。
CECPのエンジンは、審判層が合法とした相手の着手を`Illegal move`で拒否することもある。
fastchessとfishtestは、こうした異常を起こしたエンジンの負けとして数える（[対局ハーネスのバイナリ対戦化](../plans/archived/match-harness.md#fishtestとの構造対応)）。
一方、1局の手数には上限があり、上限に達した局は規則上の決着を持たない。
[探索部](../plans/archived/search.md)は、上限に達した局を引き分けとして数えるとバイアスの源になると判断した。
GSPRTの観測単位はペアなので、片方の局に決着がなければ、そのペアは得点の分類を持たない。

## 決定

不正着手、クラッシュ、応答タイムアウト、時間切れ、および拒否着手は、起こしたエンジンの当該局の反則負けとして統計へ入れ、理由別の件数を報告する。
手数上限に達した局を含むペアは、2局とも統計から除き、破棄した件数だけを報告する。
エンジンの投了（USIの`bestmove resign`と、CECPで着手を返さずに結果だけを返す応答）は通常の負けとして異常には数えず、分類の詳細は`EngineFailure`と`run_pair`のdocコメントに従う。

## 検討した代案

異常で終わった局を統計から除く案は、クラッシュするエンジンや持ち時間内に着手できないエンジンの弱さが測定結果に現れなくなるので採らなかった。
手数上限に達した局を引き分けとして数える案は、上記のバイアスを持ち込むので採らなかった。

## 結果

採否の判定の前に異常の件数を確かめ、0でなければ原因を調べる運用が必要になる。
手順と、測定機の外部要因による時間切れの扱いは[棋力測定の手引き](../guides/sprt.md)の「異常時の裁定」にある。
HaChuとの測定では、規則の実装差による拒否と、棋譜配列の上限による2,001手目前後のクラッシュがHaChuの負けとして入る（[等時間GSPRTの記録](../measurements/hachu-vs-search-tc60.md)）。
このため外部エンジンとの測定では、`rejected_moves`と`crashes`の内訳を結果とともに記録する。
手数上限を下げて測定を短くする案は、破棄されるペアを増やすので[別のADR](reject-measurement-shortcuts-that-lose-accuracy.md)で採らないと決めた。

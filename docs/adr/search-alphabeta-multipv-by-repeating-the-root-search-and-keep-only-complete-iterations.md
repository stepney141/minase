# αβ探索のMultiPVは、各深さで根の探索をN回繰り返して選んだ手を除いていき、全N本を読み終えた反復だけを結果にする

## ステータス

承認済み。決定日は2026年11月17日。

## コンテキスト

MultiPV（multiple principal variations）は、根の上位N手の読み筋を同時に出す機能であり、Nの指定は[USIオプション`MultiPV`のADR](declare-multipv-in-the-usi-layer-and-rank-info-lines-only-when-it-is-two-or-more.md)に従う。
minaseのαβ探索は、深さ1から1ずつ深くして探索を繰り返す反復深化で読み、各深さの根の探索を、前の反復の最善手の評価値の平均の近くに置いた狭い窓（aspiration window）で始める（[窓の置き方のADR](center-aspiration-windows-on-the-best-move-average-and-move-both-edges-on-failure.md)）。
上限時間で止めた反復の値は捨て、秒読みと固定時間の探索だけは、止めた反復で読み終えた手の途中結果を採ることがある（[中断した反復を捨てるADR](keep-discarding-hard-interrupted-iterations-and-reject-fair-share-budgets.md)）。
並列化のLazy SMPでは、複数のスレッド（ワーカー）が置換表を共有して同じ根を探索し、進捗を通信層へ送るワーカーを主ワーカー、それ以外を補助ワーカーと呼ぶ。
結果には、完了した深さが最も大きいワーカーの結果を採る。

チェスエンジンのStockfishは、各深さで根の探索をN回繰り返し、k回目はk−1回目までに選んだ手を除いた残りの手から最善の手を探す（0始まりの添字`pvIdx`が k−1 に当たるループ）。
将棋エンジンのやねうら王も、このループを移している。
Stockfishは、2回目以降の探索で根の置換表への保存と最善手の変化の計数を止め、止まった反復で読み終えた読み筋を残して未完了の順位には前の反復の値を出す。
やねうら王は、Nが2以上ではLazy SMPのスレッドを選ばずに主スレッドの結果を採るが、Stockfishは2026年4月のコミット50e8ff1eでNが2以上でもスレッドを選ぶようにした。
判断の詳細と先行実装の行番号は、[MultiPVの設計書](../plans/archived/multipv.md)の「αβ探索の方式」から「αβ探索の出力の時期」までの節にある。

## 決定

αβ探索は、反復深化の各深さで根の探索をN回繰り返し、k回目は同じ深さで選んだk−1本の手を除いた残りの手から最善の手とその値と読み筋を求め、選んだ読み筋を回ごとに値の降順へ安定に並べ直す（2026年11月17日のエンジンの開発者の決定）。
k回目の窓の中心、最初に読む手、および詰みを探す印（seek mate。前の反復の値が勝ちか負けに近いときに立て、null move pruningと王手の手のLMRを控えめにする印）は、前の反復のN本のうち、この反復でまだ選んでいない最上位の手（基準の手）から決める。
基準の手が前の反復のN本になければ、詰みを探す印は立てない。
2回目以降は、探索済みの局面の値を記録する置換表へ根の局面の評価値と最善手を保存せず、根のcorrection history（静的評価と探索値の差を局面の特徴ごとに学ぶ表）も更新しない。
また、根で最善手が変わった回数を数えず、探索値が窓の上端を超えた（fail highした）後に次の反復の深さを減らす持ち越しの量を、減衰させも更新もしない。
根のhistory（指し手の成績の表）の更新は、除いた手があっても残りの手の中の成績として意味を保つので行う。
全N本を窓の中で読み終えた反復だけを完了とし、途中で止まった反復は読み終えた読み筋も含めて丸ごと捨て、Nが2以上では途中結果を使わない。
時間管理は、並べ直した後の1本目の手と値で、Nが1のときと同じ規則で判断し、最善手の変化の回数は1本目の回でだけ数える。
詰みによる早期停止は、N本目の値が3手以内の勝ちのときか、1本目の値がちょうど2手の負けのときとする。
読み筋は値の降順に並ぶので、前者は上位N手のすべてが勝ちと決まったこと、後者は最善手でも負けと決まったことを表す。
Lazy SMPでは補助ワーカーもN本を読み、結果を採るワーカーの選び方は変えず、採ったワーカーの最後に完了した反復のN本を結果とする。
探索中の`info`は、全N本を読み終えた反復ごとにN行をまとめて出す。
Nが1のときは2回目以降に関わる処理をすべて飛ばし、探索の手順はいまと同じである。

## 検討した代案

根の窓の下端をN番手の値の下まで下げて、1回の探索で上位N手の正確な値を同時に求める案は採らなかった。
窓が広いほど枝を刈れなくなるので、1本目の探索そのものが遅くなり、Stockfish、やねうら王、およびdlshogiのどれも採っていない。

2回目以降の窓と最初に読む手の基準を、Stockfishのように、その時点の根の手の並びのk番目（添字`pvIdx`の位置）にある手にする案は採らなかった。
Stockfishの根の手の並びは各回の後に並べ直されるので、その位置の手は前の反復のk番目の手とは限らない。
前の反復で完了したN本を各回の出発点にすれば、どの回がどの手から始まるかを反復の結果だけから説明できる。
2回目以降を値の範囲を絞らない全窓で読む案も、1本目と同じ窓の仕組みが使えるのに枝を刈れなくなるので採らなかった。

Stockfishと同じく2回目以降も根のcorrection historyを更新する案は採らなかった。
除いた手がある探索の値は根の局面の値ではなく、correction historyは駒の配置の一部をキーにして多くの局面で共有されるので、Nが大きいときにk回目の低い値が根以外の局面の補正まで引き下げる。

止まった反復で読み終えた読み筋を残すStockfishの案は採らなかった。
出力の行ごとに深さが異なり、前の反復の読み筋を手ごとに保持して出力に使う仕組みと、止まった探索の値が先に完了した読み筋の確定した負けを追い越さないようにする補正が要る。
1本目にだけ途中結果を使う案も、止まった反復の1本目だけを新しい深さにすることになり、全N本で完了を判定する規則と矛盾する。

Nが2以上で、時間管理の指標（評価値の低下、最善手の安定、最善手の変化の回数、および最善手への探索量の集中）による持ち時間の伸縮を止める案は採らなかった。
Stockfishもやねうら王もNが2以上でこの伸縮を使い続け、伸縮を使うかどうかの判定は、相手の手番に読む先読み（ponder）が当たった後の手で持ち時間の目安を25%増やす処理などと共有されているので、Nが2以上のときだけ止めると共有の判定を2つに割ることになる。
Nを2以上にするのは検討と診断のためで、対局と棋力測定は既定値1で行う。

評価値の低下の因子に、Stockfishのように最後に読んだ読み筋の探索値を使う案は採らず、1本目の値を使う。
時間管理の判断を並べ直した後の1本目の手で行う以上、評価値の低下も同じ手の値で測る。

Nが2以上なら主ワーカーの結果だけを採るやねうら王の案は採らなかった。
いまもNが1で補助ワーカーの結果がより深ければ最後にその結果を出しており、採ったワーカーのN本はその深さでそろっているので、主ワーカーに限る理由がない。
限ればNが1の経路と2以上の経路を別々に確かめることになる。

窓外れの読み直しの途中や、1本ずつの読み筋の完了ごとに途中経過を出す案は採らなかった。
Stockfishはノード数が1,000万を超えた後に1本ごとにも出力し、やねうら王はそれに既定値300ミリ秒の出力の間隔の下限を加えるが、minaseは1本の読み筋でも反復の完了ごとにだけ出しており、その規則を保つ方が単純である。

詰みを探す印を、Stockfishのようにその時点の根の手の並びのk番目（添字`pvIdx`の位置）の手の値で決める案は採らなかった。
Stockfishの2回目以降のその手の値は、読んでいない手に与えた負の無限大であることがあり、Stockfishはこの印の閾値を棋力のための調整の対象にしないと明記している。

## 結果

既定値1では、探索の結果、USIの出力、持ち時間つきの探索の時間管理の判断、および速さが変わらない（[αβ探索のN本の読み筋の一致の記録](../measurements/multipv/multipv-alphabeta-default-equivalence.md)）。
Nが2以上では、各深さで根の探索をN回行うので、同じ深さに届くまでの時間が延びる。
最初の反復のN本がそろう前に止まると、結果は深さ0の静的評価のままであり、短い思考時間で大きなNを指定すると読み筋が出ないことがある。
2番手以下の手は1本目より少なく読まれ、その値は除いた手のない探索とは別の窓と表の状態で求めた値である。
Nが2以上で最善手への探索量の割合が小さく見えることは補正しないので、Nが2以上の持ち時間つきの探索は、Nが1より長く考えることがある。
深い検討で出力の更新が遅いという要望が出たら、1本ごとの途中経過の出力を別に計画する。
仕様は`crates/minase/src/search/alphabeta/root.rs`と`deepening.rs`のdocコメントにある。

# 探索方式は起動引数`--search`で起動時に選び、探索の境界の閉じた列挙型`Searcher`で束ねる

## ステータス

承認済み。決定日は2026年10月27日。

## コンテキスト

AlphaZero型探索のMCTSは、αβ探索の置き換えではなく、同じエンジンで共存する第2の探索方式として入る（[統括計画](../plans/alphazero.md)）。
2つの方式は、対局の間に持ち越す状態が異なる。
αβ探索は置換表、ワーカー別のhistory表、およびワーカー数を持ち、MCTSは推論のセッション、再利用する探索木、および推論の設定を持つ。
USIのオプションも、`USI_Hash`の意味と`Threads`の範囲が方式で異なり、推論の設定（`NnBackend`、`NnCacheDir`、`NnBatchSize`）はMCTSにだけある。
lc0は2025年に探索の実装を方式ごとのディレクトリへ分け、起動時に1つの探索を選んで、その探索のオプションだけを公開する構造にした。
対局ハーネスで`commit:<コミット>`と指定したエンジンは、ハーネスがそのコミットを`cargo build --release --bin minase`でビルドする（[コミットを別プロセスで比べるADR](compare-commits-as-separate-engine-processes.md)）。
エンジンの開発者は、[探索方式の共存とMCTSの設計書](../plans/archived/alphazero-mcts.md)でこの構造を決めた。

## 決定

探索方式は起動引数`--search alphabeta|mcts`で起動時に1回だけ選び、既定はαβ探索とする。
探索方式に依存しない境界`crate::search`に、方式ごとの状態を包む閉じた列挙型`Searcher`を置き、プロトコル層は`Searcher`の公開APIだけを使う。
`Searcher`は、オプションの宣言と設定、`isready`での準備、対局をまたぐ状態の消去、および探索の開始の操作を持つ。
探索を始めるときは自身を探索スレッドへ移し、終了時に`SearchHandle::join`で受け取り直す。
オプションは方式に依存しない記述の型で宣言し、USIやCECPの文字列への変換はプロトコル層に残す。
持ち時間の配分式と探索の時計も境界に置き、両方の方式が使う。
CECPでは`--search mcts`を受け付けず、起動時にエラーで終了する。

## 検討した代案

別のバイナリ`minase-zero`にする案は採らなかった。
プロトコル層の配線を二重に持つことになり、ハーネスの`commit:`のビルドが`--bin minase`だけを作る前提とも合わない。

別のクレートに分ける案は採らなかった。
[src構成の整理](../plans/archived/src-layout.md)が定めたワークスペース化の契機（外部の利用者、公開、ビルド時間の問題）のいずれにも当たらない。

`dyn`トレイトで方式を登録する案は採らなかった。
方式が2つで増やす予定もない現状では、列挙型の網羅的な`match`より検査が弱くなるだけである。

USIオプションで実行中に方式を切り替える案は採らなかった。
方式ごとに持つ状態とオプションの集合が異なり、選ばれていない方式のオプションが表に出るからである。
lc0も探索をUCIのオプションで切り替えない。

CECPでもMCTSを使えるようにする案は採らなかった。
到達の判定もRLの進捗測定もUSIで行い、CECPの実装には推論の設定を渡す手段がない。

## 結果

境界を加えた変更の前後で、αβ探索の深さ6のbenchの局面ごとのノード数、最善手、および評価値は一致した。
推論の失敗で止まった探索は`Finished`を送らずに終わり、`SearchHandle::join`がパニックと区別して原因を返すので、プロトコル層はセッションをエラーで終える。
3つ目の探索方式を足すときは、`Searcher`に列挙子を足せば、未対応の操作がコンパイルエラーとして現れる。
自己対局生成器とbenchは、方式のモジュールを直接使ってよい。
実装は`crates/minase/src/search/searcher.rs`と、起動引数を解析する`crates/minase/src/bin/minase/`にある。

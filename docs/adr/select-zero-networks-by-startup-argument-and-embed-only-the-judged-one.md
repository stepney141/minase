# AlphaZero型探索のネットは起動引数`--nn-model`のファイルで指定し、到達の判定に使うネットだけを埋め込む

## ステータス

承認済み。決定日は2026年10月27日。

## コンテキスト

強化学習（RL）の途中のネットは、作業機のNASにファイルとして置き、コミットしない（[強化学習の実行の設計書](../plans/alphazero-rl.md)）。
各サイクルの生成と進捗測定は借りた機械で行い、借りた機械にはリポジトリがないので、ネットをコミットしてハーネスの`commit:`指定で選ぶことはできない。
進捗測定では、同じバイナリの候補と基準に別のネットを与える。
対局ハーネス`minase match run`には、候補と基準のそれぞれに任意のUSIオプションを与える引数がない。
TensorRTはネットを替えるたびにエンジンを作り直す。
StockfishのUCIオプション`EvalFile`（`src/engine.cpp` 136行と`src/nnue/network.cpp` 91〜110行、コミット5c4cef0b）とlc0の`WeightsFile`（`src/neural/shared_params.cc` 45行と74〜76行、コミットd91bd14）は、埋め込みのネットを既定にしてファイルで差し替える。
dlshogiは、ネットのファイルをUSIオプション`DNN_Model`（`cppshogi/usi.cpp` 103行、コミット79df19e）で指定する。
エンジンの開発者は、2026年10月26日にこの方式を決めた。
決定の経緯は[ネットの入出力と推論の設計書](../plans/archived/alphazero-network.md)にある。

## 決定

MCTSのエンジンと自己対局生成器は、起動引数`--nn-model <パス>`でONNXのファイルを指定し、起動時に1回だけ読む。
起動時にファイルの内容をバイト列として読み込み、そのバイト列からONNX Runtimeでセッションを作り、同じバイト列のSHA-256をネットの検査和とする。
検査和は、TensorRTのエンジンのキャッシュの鍵と、自己対局生成器が教師データ（MNSD）のヘッダに書く「教師の重みの検査和」に使う。
ファイルを読めない場合とセッションを作れない場合は、別のネットへ切り替えずにエラーで終了する。
到達の判定に使うネットだけを`crates/minase/nets/`に置いて埋め込み、埋め込みを持つビルドでは`--nn-model`を省くと埋め込みのネットを使う。

## 検討した代案

USIオプションでネットを指定する案は採らなかった。
同じバイナリの候補と基準に別のネットを与えるには、エンジンごとに任意の`setoption`を送る拡張がハーネスに必要になり、`setoption`のたびにネットを読み直す処理も必要になる。
起動引数なら、ネットのパスはエンジンの起動コマンドに入るので、ハーネスの既存の起動コマンドの形式と、起動引数を足す汎用の拡張だけで指定できる。

測定に使うネットをすべてコミットして`commit:`で選ぶ案は、借りた機械にリポジトリがないので採らなかった。

## 結果

ネットのパスはハーネスの実行条件に残るが、ネットの内容は残らない。
同じパスのファイルを書き換えると記録と対局のネットの対応が失われるので、RLはネットをサイクル番号つきのファイル名で保持し、上書きしない。
推論のコードは学習済みの重みより先にmasterへ入るが、既定の探索の評価関数としては使われないので、既定の探索のbenchの結果とテストの結果を変えない。
エンジンの`--nn-model`は[探索方式の共存とMCTS](../plans/archived/alphazero-mcts.md)が、生成器の`--nn-model`は[自己対局生成器](../plans/alphazero-selfplay.md)が実装し、検査用の`minase dev nn-eval`も同じ読み込みを使う。
ネットの読み込みは`crates/minase/src/nn/onnx.rs`の`Network`にある。

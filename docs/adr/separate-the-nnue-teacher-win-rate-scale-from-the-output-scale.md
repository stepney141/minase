# NNUEの教師の勝率尺度K_tを学習器の必須の引数で渡し、ネットの出力の換算の尺度K_o＝8,128÷mと分ける

## ステータス

承認済み。決定日は2026年11月19日。[勝率尺度を重みファイルの1定数とし、NNUEの教師の探索値も既定ではその尺度で勝率へ換算する](archive/convert-nnue-teacher-values-with-the-network-win-rate-scale-by-default.md)を置き換える。

## コンテキスト

[以前の決定](archive/convert-nnue-teacher-values-with-the-network-win-rate-scale-by-default.md)は、ネットの評価値を勝率へ換算する勝率尺度をMNUEのヘッダの1定数とし、NNUEの学習では教師の探索値を、既定で`--base`のネットの勝率尺度で勝率へ換算するとした。
勝率尺度は、世代反復の第1世代で最初に生成した4本の教師ファイルから一度だけ推定して固定していた。

tataraの形式には実数の勝率尺度の欄がなく、構造記述の末尾に、量子化したネットの整数の出力をセンチポーンへ換算する整数の除数`fv_scale`を書く。
ネットの実数の出力yはロジットの単位であり、出力の量子化の尺度は127×64＝8,128なので、y＝1に当たる整数の出力は8,128である。
したがって除数をmとすると、1ロジットあたりのcpである出力の換算の尺度はK_o＝8,128÷mに丸められる。
教師の勝率尺度K_tを1つの尺度としてmへ丸めると、K_t＝1,072.65 cpのときm＝8、K_o＝1,016 cpとなり、評価値が約5%縮む。
tataraの勝率モデルの損失（`nnue2score`と`in_scaling`）は、出力の換算と教師の換算に別の尺度を使う形を表せる。
`--base`は廃止した（[学習器の構成のADR](split-the-nnue-trainer-into-a-shared-loop-and-structure-backends.md)）。

## 決定

教師の勝率尺度K_tは、`minase-trainer nnue train <構造>`の必須の引数`--teacher-cp-per-logit <K_t>`で正の有限な実数として渡し、`minase-trainer data calibrate`で先に求める。
m＝round(8,128÷K_t)、K_o＝8,128÷mとし、学習の損失を`[σ(K_o y / K_t) − σ(s / K_t)]²`とする（yはネットの実数の出力、sは教師の探索値、σはシグモイド関数）。
mは1以上で32ビットの正の整数でなければならず、満たさなければ学習器は入力のエラーで止まる。
K_tは世代反復の第1世代の最初の4本から一度だけ求め、全世代の学習器に同じ値を渡す。
PV-MCTSの勝率尺度は`NnCpPerLogit`で別に渡し、NNUEの`fv_scale`から決めない。

## 検討した代案

K_tを1つにしてmへ丸める案は、上の例で評価値が約5%縮むので採らなかった。
K_tそのものを8,128÷mに丸めて学習に使う案は、教師の較正まで変えるので採らなかった。
K_tを重みのファイルに持たせて前の世代から引き継ぐ案は、tataraの形式に欄がないので採らなかった。
NNUEの学習で`calibrate`と較正ファイルを選べる形を残す案は、標準の手順が数値を一度求めて全世代に渡す形であり、選べる方法を残す用途がないので採らなかった。
PST、FM、および同時学習の学習器の`--teacher-cp-per-logit`は、以前の決定のとおり変えない。

## 結果

学習器は、K_t、m、K_oを`config.json`と再開用のチェックポイントに記録し、再開のときにK_tの違いを拒否する。
推論は整数の出力をmで割ってK_o yに当たるセンチポーンを返すので、学習と推論の尺度が一致する。
K_tが16,256 cpを超えるとmが0になって換算を定義できないので、その値は拒否する。
v0のネットは後段を持たず、評価値が除数によらずv0になるので、K_tを求める前に`fv_scale`＝1で書き出す。

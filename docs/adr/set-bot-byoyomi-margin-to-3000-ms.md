# lishogiのBotの`ByoyomiMargin`を3,000 msにする

## ステータス

承認済み。決定日は2026年10月10日。

## コンテキスト

`ByoyomiMargin`は、秒読み期の1手で使う時間から差し引く余裕をミリ秒で指定するminaseのUSIオプションである。
エンジンが`bestmove`を返してから、Lishogi-Botが着手をlishogiのサーバへ送って受理されるまでには、Bot側の処理と通信の時間がかかる。
この時間が余裕を超えると、エンジンが時間内に着手を決めても、サーバ上では時間切れになる。
マイルストーン[秒読みつき時計での持ち時間と秒読みの活用](../plans/byoyomi-time-usage.md)では、当初、Bot側の処理時間の最大値に通信の見込み500 msを加えて余裕を600 msと見積もり、2026年10月8日にBotへ設定した。
通信の遅れは測っていなかった。
2026年10月8日から10日までに、秒読み60秒の上限（59.4秒）まで考えた213手のうち10手が時間切れになり、10局を落とした。
Botのログ全体の25,799手で`bestmove`から着手の`POST`の応答までの時間を測ると、0.6秒を超えた手が796手（3.1%）、2秒を超えた手が57手、3秒を超えた手が10手あった。
0.6秒を超えた手の割合は、上限まで考えた手が時間切れになった割合（4.7%）とおおむね一致した。

## 決定

lishogiのBotでは、`ByoyomiMargin`を3,000 msにする。
設定は別リポジトリ`minase-lishogi-bot`の`config.yml`にある。

## 検討した代案

600 msのままにする案は、上記の時間切れが続くので採らなかった。
実測の最大値を超える余裕を取る案は、3秒を超えた手が25,799手のうち10手と少なく、秒読み60秒の対局で使える時間を余計に削るので採らなかった。

## 結果

秒読み60秒の対局では、使えなくなる時間は5%である。
この値で時間切れが0件になるかは、秒読みつきの対局20局の記録で確かめる。

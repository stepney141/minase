# GSPRTの対立仮説H1を10 Eloにする

## ステータス

承認済み。決定日は2026年9月4日。

## コンテキスト

それまでのGSPRTはH1を5 Eloとしていた。
当時は、探索と時間管理の改良を段階ごとに積む棋力向上の段階計画が進行中であり、各段階が複数の項目を採否測定にかけていた。
GSPRTの期待ペア数はH0とH1の得点差の二乗に反比例し、真の効果がH0とH1の中間にあるときに最大になる。
[棋力測定の所要時間削減](../plans/archived/match-cost-reduction.md)の試算では、H1が5 Eloのままだと、効果が10 Elo以下の変更は1回の採否に2〜4日を要した。
一方、段階ゲートで測った2件のLTCの効果は大きく、200〜400ペアで決着していた（[段階1の最終構成](../measurements/strength-stage1-final-ltc.md)、[段階1の段階的な手生成](../measurements/strength-stage1-staged-picker-ltc.md)）。
自己対局で持ち時間を2倍にすると+216 Eloの差が出ており（[持ち時間の感度](../measurements/sensitivity-time2x.md)）、探索量の伸びしろが大きい水準にあった。
チェスの測定基盤OpenBenchの解説も、新しいエンジンの設定例として[0, 10]の境界を挙げる（[所要時間削減の参考資料](../plans/archived/match-cost-reduction.md#参考資料)）。

## 決定

採否のGSPRTはH0を0 Elo、H1を10 Eloとし、α=β=0.05は変えない。
H1は`minase::stats::GSPRT_H1_ELO`の定数であり、実行ごとの値は`manifest.json`の`h1_elo`に記録する。
採否の測定は既定の仮説だけを使い、変更ごとにH1を選ばない。

## 検討した代案

H1を5 Eloのまま保つ案は、段階計画の残りの進行が測定待ちで律速されるので採らなかった。
変更の種類ごとにH1を選ぶ案は、測定前に固定した規則で裁量を排するという方針に反するので採らなかった。
正規化Elo（得点の標準偏差で割った尺度）で境界を定める案は、引き分け率が約3%で安定し、ロジスティックEloとの差が実質ないので採らなかった。

## 結果

真の効果が5 Eloや10 Eloの変更は、H1が5 Eloのときより採用されにくくなる。
代わりに、10 Elo以上の変更の採否と、効果のない変更の棄却が速く済む。
H1が5 Eloだった時期の測定は、`manifest.json`の`h1_elo`で見分けられる。
H1の10 Eloは恒久の値ではなく、新しい境界のLTCで`H0`となった候補が3件続いた時点、または段階計画が完了した時点で見直す。
段階ゲートを通った2つの候補のどちらを採るかを決める直接対局に限り、`gsprt`サブコマンドの`--elo0`と`--elo1`で対称な仮説を指定できる。
既定の仮説の`H0`は候補が10 Elo以上強いことを否定するだけで、基準側が強いことを示さないので、対等な2候補の比較には使えないからである（[棋力測定の手引き](../guides/sprt.md)の「統計的手続き」）。
根拠の試算はPSTとFMを評価関数としていた時期のペア得点分散によるので、境界を見直す場合は現在の分散で計算し直す。

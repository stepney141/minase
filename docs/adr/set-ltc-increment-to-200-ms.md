# LTCの加算を0.2秒にする

## ステータス

承認済み。決定日は2026年9月4日。

## コンテキスト

[段階ゲート](screen-at-stc-and-decide-at-ltc.md)の当初のLTCは、fishtestのLTCと同じ持ち時間60秒と1手0.6秒の加算だった（[段階ゲートの参考資料](../plans/match-staged-gate.md#参考資料)）。
1エンジンが1局で使える思考時間の上限は、持ち時間に加算と片側の手数の積を足した値である。
fishtestの値は、チェスの1局が片側約70手で終わる場合の値である（[所要時間削減の参考資料](../plans/match-cost-reduction.md#参考資料)）。
一方、中将棋の対局は、当時のLTCの再集計で片側約240手続いていた（[棋力測定の所要時間削減](../plans/match-cost-reduction.md)）。
同じ加算では、片側の総思考時間がfishtestの約2倍になり（[所要時間削減の参考資料](../plans/match-cost-reduction.md#参考資料)）、1局の時間の大半を加算が占めていた。
時間管理の予算式は初手から加算を項に含むので、加算を減らすと全手数帯の到達深さが下がる。
LTCの役割は、STCより深い探索でも変更の効果が保たれるかを確かめることである。

## 決定

LTCを持ち時間60秒と1手0.2秒の加算とし、片側の総思考時間をfishtestのLTC（[所要時間削減の参考資料](../plans/match-cost-reduction.md#参考資料)）と同程度に揃える。
STCは持ち時間10秒と1手0.1秒の加算のまま変えない。
揃えるのは費用であり、240手へ0.2秒ずつ配る条件と70手へ0.6秒ずつ配る条件で探索の内容が等価になるとは主張しない。

## 検討した代案

fishtestの名目値（[所要時間削減の参考資料](../plans/match-cost-reduction.md#参考資料)）のまま保つ案は置き換えた。
時間制御の妥当性を自前で正当化しないという段階ゲートの目的は、片側の総思考時間を揃えることでも保て、1局の費用を約半分にできるからである。
加算をなくして持ち時間だけにする案は、持ち時間が尽きた後の時間切れを避ける最低予算を時間管理に保証させることになり、測定条件の都合を時間管理の設計へ持ち込むので採らなかった。
STCの加算も手数に合わせて縮める案は、加算が0.03秒程度になり、プロセス間通信と時計の丸めの誤差を無視できなくなるので採らなかった。

## 結果

煙試験では時間切れとエンジン異常が0件、手数上限の局を除く1局の平均時間は224秒で、到達深さは全手数帯でSTCを上回った（[LTCの煙試験](../measurements/match-cost-ltc-smoke.md)）。
同じ記録の試算では、LTCの処理能力は旧条件の実測82ペア/時から約150ペア/時へ上がる。
加算0.2秒は時間管理の予算式を変えずに選んだので、予算式を変える変更は新しいLTCの下で採否を測る。
中将棋の平均手数が大きく変わった場合は、同じ考え方で加算を見直す余地がある。

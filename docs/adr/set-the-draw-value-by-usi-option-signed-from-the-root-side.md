# 千日手の引き分けの値は利用者がUSIオプションで固定値を与え、根の手番側に＋、相手側に−の符号で返す

## ステータス

承認済み。決定日は2026年10月15日。

## コンテキスト

従来の探索は、探索木の中で同一局面が再現すると、反復規則R1（RULES.md第31条）の引き分けとして評価値0を返していた。
このためエンジンは、千日手の引き分けを評価値0の通常の局面と同じ価値とみなし、ほかの手の評価値が0よりわずかに低いだけでも千日手を選んでいた。
相手が自分より弱いと分かっている対局では、引き分けを避けたいという要望がある。
一方、2026年10月15日のlishogiの対局では、Minaseは劣勢の局面からR1の千日手で引き分けを得ており、引き分けを避けることが常に良いわけではない。
引き分けの値を設定する仕組みは一般にcontemptと呼ばれ、主要エンジンの実装と測定の記録は[引き分けの評価値（contempt）の既存実装と測定の調査](../research/draw-value-prior-art.md)に整理した。
Stockfishの記録では、0以外の引き分け値は自己対局ではEloの変化がないかわずかに下がり、実力の劣る旧版を相手にしたときだけ数Eloの向上を示した。
決定の経緯は[引き分けの評価値の設定（DrawValue）](../plans/draw-value.md)の設計書にある。

## 決定

R1の再現が引き分けになる場合、利用者が設定する固定の値を返す。
値はやねうら王と同じ`DrawValueBlack`と`DrawValueWhite`の2つのUSIオプションで与える。
探索の開始時に根の手番に応じてどちらか一方の値（vとする）を選び、引き分けを返すノードの手番が根の手番と同じなら＋v、異なれば−vを返す。
値の単位はMinaseの評価値と同じcpであり、範囲は評価関数の出力と同じ±28,999とする。
既定値は0であり、既定の設定では従来の探索の挙動は変わらない。
2つのオプションのいずれかの値が`setoption`で変わった場合は、置換表とhistory表を空にする。

## 検討した代案

Stockfishが採用していた、評価値への加算や根の評価値に応じて値を変える動的なcontemptは採らなかった。
Stockfishではこれらは導入と取り消しを繰り返したうえで削除され、現行のコードに残っていないためである。
相手の強さに応じて値を変えるLc0の方式も採らなかった。
対戦相手を把握しているのは対局ごとに相手を見るBotの側なので、Botがオプションの値を選び、エンジンは受け取った値を適用するだけにする設計が単純である。

千日手になる手を選んだ側の手番で値を決めるdlshogiの方式は採らなかった。
この方式は探索が非対称になると、やねうら王の作者が指摘している。
根の手番で符号を決める方式であれば、引き分けの価値を両者で打ち消し合う対称な探索が保たれる。

やねうら王のように歩兵1枚の価値を100として指定させ、駒価値で換算する方式は採らなかった。
MinaseのNNUEにおける歩兵の評価値は約68 cp（標準偏差約40 cp）と局面による変動が大きく、固定の換算係数が定まらないためである。

0以外の既定値は採らなかった。
Stockfishの記録では、Contempt=20の自己対局はSTCで0.10±2.0 Elo、LTCで−2.06±1.9 Eloと−2.69±1.9 Eloにとどまり、H1=10 Eloの段階ゲートを通ることは見込めないためである。
やねうら王の既定値−2（内部値−1）は、0に切り捨てられない最小の値として同点の手を区別するために選ばれた値であり、測定に基づく値ではない。

値をR2とR3の再現にも適用する案は採らなかった。
R2では探索木の中の再現は禁止手として除かれるため、引き分けにならない。
R3の禁止されない再現に返す0は、対局の引き分けではなく、局面の周回によって双方に損得が生じないことを表す探索上の近似であるため、引き分けの値を適用せず0のままとする。

引き分けの値と`ResignValue`の整合性を`setoption`で検査する案は採らなかった。
2つのオプションのどちらが先に送られるかによって受理と拒否が変わり、処理の単純さを損なうためである。
投了判定は引き分けの値を含む評価値で行うので、引き分けの値を`-ResignValue`以下に設定すると、千日手しか残らない局面で投了し得る。
この組み合わせの扱いは利用者の運用に委ねる。

## 結果

既定の設定では千日手を避ける効果はなく、効果を得るには利用者が値を与える必要がある。
本プロジェクトが運用するlishogiのBotでは、2つのオプションをどちらも−1に設定する。
−1 cpは候補手の評価値がちょうど同じである場合にだけ千日手を避けさせる最小の値であり、形勢差のある手より千日手の回避を優先させるには数十cpの値が要る。
そのような値は、強い相手や劣勢の局面で本来確保できる引き分けを捨てる危険を伴う。
自己対局では両者が同じ値を使うため、弱い相手との引き分けを避けるというcontempt本来の効果は相殺されて測れない。
そのため、0以外の値による効果は棋力の測定の対象にしない。
置換表のキーは根の手番とオプションの値を区別しないため、同じ対局の中で双方の手番の局面を解析すると、別の手番を根にした探索の値が再利用され得る。
対局中のエンジンは自分の手番の局面だけを根にするため通常の対局では問題にならず、やねうら王も対処していない既知の近似として許容する。
実装箇所は、オプションの解析と置換表の消去が`crates/minase/src/protocol/usi.rs`の`handle_setoption`、探索への値の受け渡しが`crates/minase/src/search/snapshot.rs`の`SearchSnapshot::with_draw_value`、探索ノードでの符号づけが`crates/minase/src/search/alphabeta/searcher.rs`の`repetition_score`である。

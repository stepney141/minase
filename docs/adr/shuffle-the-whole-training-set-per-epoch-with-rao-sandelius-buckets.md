# NNUEの学習は毎エポック訓練集合全体を一様に並べ替え、メモリに収まらないデータは実行専用の一時ファイルのbucketへ振り分ける

## ステータス

承認済み。決定日は2026年10月16日。

## コンテキスト

NNUE（差分更新できる小型のニューラルネット）の学習器は、教師データMNSDを再生して得た局面を1局面約100バイトの圧縮表現でメモリに持ち、エポック（全局面を1回ずつ学習に使う単位）ごとに全局面の順番をFisher–Yates法で並べ替えていた。
この方式は、教師データが測定機のメモリ（30 GB）に収まらない規模になると使えない。
[学習時の局面の並べ方の予備測定](../measurements/out-of-core-shuffle/shuffle-order-preliminary.md)では、811万局面のデータで4つの並べ方を比べた。
ファイルを塊で交互に読んで13万局面の窓の中だけで並べ替える方式（Stockfishの学習器の流し読みに相当）は、2つの学習率の条件とも全シードで検証損失が明確に悪く、対局単位で4つに分けて区画の中だけで並べ替える方式も既定の学習率では少し悪かった。
エンジンの開発者は2026年10月14日に、シャッフルによって精度の高い学習ができること、メモリより大きいデータを扱えること、ディスクの使用量の順に優先すると述べた。
先行例として、やねうら王の補助ツールは盤面のハッシュ値でbucketへ振り分けた派生ファイルを1回だけ作り、Stockfishの学習器は事前のシャッフルを行わずに窓の中だけで混ぜる（出典は[設計書](../plans/archived/out-of-core-shuffle.md)の参考資料にある）。

## 決定

`minase-trainer nnue train`は、学習の開始時にMNSDを1局ずつ再生し、適格な局面の一時表現を、その実行だけが読み書きする一時ファイルへ書き出す。
エポックごとに、エポックのシードから各訓練局面へ独立かつ一様にbucket（区画）番号を割り当て、一時ファイルから`B`個のbucketへ振り分ける。
その後、bucketを1つずつメモリへ読んでFisher–Yates法で並べ替え、bucketの番号順に連結した順序で学習器へ供給する。
各局面の割り当てが独立で一様であり、bucketの中も一様に並べ替えるので、連結した全体は全局面の一様な並べ替えになる（Rao–Sandelius方式）。
`B`とbucketの局面数の上限は利用者が`--buckets`と`--bucket-positions`で明示し、学習器はデータの大きさから自動で決めたり、メモリ不足のときに自動で切り替えたりしない。
`--buckets 1`は一時ファイルを使わず、以前と同じく全局面をメモリに持って同じ順列と同じ学習結果を出す。
bucketの容量は、1局面の一時表現の最大の大きさ（定数）から決めた局面数の上限だけで判定し、上限を超えるbucketがあればそのエポックの振り分けを終えた時点で学習を止める。
一時表現は、現行の圧縮表現に先読み後の探索値、対局結果、入力ファイルの番号、対局番号、手数を加えたものとし、教師値は学習時に作る。
教師の勝率尺度の推定に使う探索値と結果は、局面とは別の一時ファイルにまとめ、標本の列を複数回走査して推定する。
一時ファイルの配置は`crates/minase-trainer/src/data/spill.rs`のdocコメントに、順列の作り方は`crates/minase-trainer/src/data/shuffle.rs`のdocコメントにある。

## 検討した代案

現行方式を既定とし、メモリに収まらない場合だけ局面単位でシャッフル済みの派生ファイルを使う案は、大規模データで頼る固定順の精度が未確認のまま残り、読み込みの経路も2つになるので採らなかった。
派生ファイルに一本化する案は、固定順の非劣性の証明を要し、先読みの条件や入力の組み合わせを変えるたびに作り直しが要り、2つ目の保存形式を持つことになるので採らなかった。
対局単位に分けて各区画の中だけで並べ替える案と、窓で混ぜる案は、混ぜる範囲に精度が依存し、予備測定で範囲が狭いと悪化したので採らなかった。
盤面のハッシュでbucketを決める案は、同じ盤面を同じbucketに集め、順がエポックによらず固定されるので採らなかった。
各局面に乱数の鍵を付けて外部ソートする案は、同じ一様性を得るのに鍵の分だけ読み書きが増えるので採らなかった。
bucketの容量を実際のバイト数で判定する案は、成功する割り当てが局面の大きさに依存して一様性を崩すので採らなかった。
3局面の大きさが60、40、40バイト、B=2、上限80バイトなら、成功するのは60バイトの局面が単独になる割り当てだけであり、その局面は先頭か末尾にしか現れない。
データの大きさから`B`を自動で決める案と、メモリ不足のときに自動で切り替える案は、同じ引数で順列と結果が変わり、プロジェクトが禁じるフォールバックに当たるので採らなかった。
読んでいるbucketから次のエポックのbucketへ振り分け直して読み書きを約2Dに減らす案は、測定なしの最適化に当たるので、最初の実装では採らず、1エポックに約3D（Dは一時表現の総量）の読み書きを許した。
一時ファイルを残して再開に使う案は、一時ファイルを保存する形式にすることになるので採らなかった。

## 結果

学習器は、`B≥2`では局面数に比例する配列をメモリに持たず、扱える教師データの規模はディスクの容量だけで決まる。
B=1の学習は変更前とビット単位で同じ結果を出す（[照合記録](../measurements/out-of-core-shuffle/out-of-core-shuffle-equivalence.md)）。
B≥2の学習では、各エポックに各訓練局面がちょうど1回ずつ、B=1と同じ教師情報で、別の一様な順列により供給されるので、精度の差は順列の違い、つまりシードの違いによる雑音の範囲にしか現れない。
このため、起案時に予定していたB=1とB=16の複数シードによる精度比較は、エンジンの開発者の判断で2026年10月17日にB=16の煙試験1回に簡略化した。
時間とメモリの測定は[B=16の測定記録](../measurements/out-of-core-shuffle/out-of-core-shuffle-time-memory.md)にある。
再開時は、MNSDから一時ファイルを作り直し、最後に保存したエポックの次のエポックを先頭からやり直す。
`B`は順列を決めるので再開時に記録と一致しなければならず、bucketの局面数の上限と作業ディレクトリは変えてよい。
`B`と上限の選び方は[NNUEの学習の手引き](../guides/nnue-training.md)にある。

# R2とR3が禁じる着手を探索木の中で読まず、禁止手しかない局面を負けとする

## ステータス

承認済み。決定日は2026年10月15日。

## コンテキスト

反復規則R2は同じ手番の既出局面を再現する着手を、R3は4回目の出現を生じさせる着手を、それぞれ不合法とする（RULES.md第31条、第26条第11項）。
根では審判層の`Game::legal_moves`が禁止手を候補から除くので、探索が不合法な着手を返すことはない。
一方、[探索木の中では規則の裁定を近似する決定](approximate-adjudication-inside-search-tree.md)に基づき、探索は禁止手を引き分けになる手として読んでいた。
この近似では、相手が禁止手しか指せない局面を勝ちと見抜けず、自分が禁止手で局面を逃れられると見込むことがあった。
Minaseは、使用頻度にかかわらず先行文献の規則をすべて実装するよう努めるので（利用者の決定）、R2とR3の探索内の扱いも規則どおりにした。
R2はHaChuとの強さ比較の規則セット（RULES.md第33条第7項）にも含まれる。
HaChuも既定の設定（R2）で、再現する着手を候補手の一覧から除外している（`hachu.c`2287行から2301行、コミット`df26f4a`）。
決定の経緯は[探索部の反復負け回避と反復禁止](../plans/archived/search-repetition.md)の設計書にある。

## 決定

規則がR2またはR3の場合、`negamax`は各候補手を取得した直後に着手を適用して反復規則のキーを求め、R2では対局履歴または探索経路に1回でも現れていれば、R3では出現回数が既に3回なら、その手を読まずに取り消す。
禁止手は、最初の手かどうかの判定、late move reductionの順位、late move pruningが数える静かな手の数、履歴表の更新に使う探索済みの手の一覧のいずれにも含めず、ノード数にも数えない。
合法手がすべて禁止手だった局面は、第23条により手番側の負けとし、[反復の勝敗の専用の帯](reserve-a-path-dependent-band-for-repetition-outcomes.md)の値`−(REPETITION_WIN − ply)`を返す。
同一局面のキーは、審判層と探索が共有する`minase_core::repetition_key`で作り、R2とR3では成り権の保留状態（第24条第1項d）を含めない。
`Game`はこのキーの履歴を`repetition_key_history`として持ち、探索の対局履歴にはこの値を渡す。
R1では禁止の判定を行わず、探索の手順とノード数は変わらない。

## 検討した代案

禁止手に値を返して最善値の計算に含める案は採らなかった。
禁止手は対局で指せない手であり、引き分けにも負けにもならないので、値を与える理由がないからである。
探索の側で同一局面のキーを定義し直す案は、審判層と食い違う余地を残すので採らなかった。
P2のように盤面を変えずに成り権の保留状態だけが変わる規則では、探索局面キー（保留状態を含む）と審判層のキー（含まない）が異なる局面を別と扱うので、共有の関数が必要である。
禁止手しかない局面を詰み帯の値で返す案は、どの手が禁止手かが対局履歴と探索経路に依存するので、置換表を通じて別の経路で誤った負けの値が再利用されるため採らなかった。
R3で禁止されない再現（2回目と3回目の出現）を、4回目の出現まで周回を続けて読む案は、周回のたびに探索の深さを消費し、読み切れないことが多いので採らず、現行どおり引き分けの値で打ち切る。

## 結果

R2とR3の探索は、根の候補と同じ基準で禁止手を除くので、相手が禁止手しか指せない局面を勝ちと読める。
禁止手を除いて求めたノードの値は、経路に依存するまま通常の評価値として置換表へ保存される。
別の経路では合法な手を除いた値が再利用されることがあるが、これは反復を引き分けとする従来の近似が既に持つ漏れと同じ性質のものである。
null moveの部分木では、反復の照合が直近のnull move直後以降の探索経路に限られるので、対局履歴とnull moveより前の経路にある局面を再現する着手には、禁止が適用されない。
R3の引き分けの打ち切りは、後の周回で選択肢が減ることとその結末の負けを読まない近似である。
`Game::search_key_history`は`repetition_key_history`に置き換わり、値が反復規則に依存するようになった。
禁止の判定は`crates/minase/src/search/alphabeta/searcher.rs`の`move_is_forbidden`に、呼び出しの位置は`alphabeta/negamax.rs`の手のループにある。
採否は、R1の既定の規則では発動しないため棋力測定ではなく、規則への適合の修正としてテストで判定した（利用者の決定。CONTRIBUTING.mdの「棋力に影響し得る変更はSPRTで判定する」に対する例外）。

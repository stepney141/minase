# モジュールを関心事ごとのファイルに分け、非公開の欄を使える範囲をディレクトリの親子で表す

## ステータス

承認済み。決定日は2026年9月26日。

## コンテキスト

2026年9月の時点で、探索部の`search/mod.rs`は2,579行、その試験は4,653行あり、局面、規則セット、および審判の各ファイルも2,000行を超えていた。
対局ハーネスも2,493行の1ファイルに、エンジンの起動、通信、時計、対局の進行、および保存形式への変換を持っていた。
新しい機能を加えるときに、変更すべきファイルを配置から決められなかった。
Rustの非公開の項目と欄は、定義したモジュールとその子孫からしか見えない。
2026年8月10日の[src構成の整理](../plans/src-layout.md)は、中核モジュールの内部をフラットな配置に保つと決めていたが、その配置では局面の欄のように一部のファイルだけに触れさせたい範囲を表せなくなっていた。
[探索部と評価関数のモジュール再編](../plans/search-eval-layout.md)、[中核モジュールの再編](../plans/core-layout.md)、および[実行ファイルと対局ハーネスのモジュール再編](../plans/bin-harness-layout.md)が、以下の方針で配置を改めた。

## 決定

1つのファイルには1つの関心事だけを置き、複数のファイルが非公開の欄に触れる型は、ディレクトリに昇格させて欄に触れる処理を子モジュールの`impl`に分ける。
ディレクトリの`mod.rs`には、子モジュールの宣言、公開する名前の`pub use`、および子が欄を共有する型の定義だけを置く。
複数の関心事を通して検査する試験はそのディレクトリの`tests/`の下に主題別のファイルで置き、1つの関心事だけを検査する試験は定義元のファイルの`mod tests`に残す。

## 検討した代案

型の`impl`を兄弟のファイルへ分ける案は、欄を`pub(crate)`へ広げることになり、型の不変条件を守る範囲がcrate全体へ広がるので採らなかった。
中核モジュールの内部をフラットに保つ案は、上記の理由で改めた。
すべての試験を定義元のファイルの`mod tests`へ散らす案は、探索の試験の多くが制限の構築から置換表の確認までを1つの試験で通して検査し、1つのファイルに帰属させられないので採らなかった。

## 結果

`Position`の欄に触れるコードが`position/`の中に限られることを、コンパイラが検査する。
移動に伴う可視性の拡大は、`pub(super)`や`pub(in crate::search)`のように参照に必要な最小の範囲にとどめ、新しい`pub`は加えない。
`Searcher`のように定義を`mod.rs`に置くと宣言が埋もれる型は、専用のファイルに定義して欄を`pub(super)`とし、親のディレクトリの中だけに公開している。
400行以下で1つの処理だけを持つファイルは分割していない。
移動の後に見つかった重複の統合は、出力や保存形式を変える判断を伴うので、配置の変更とは別に扱う。

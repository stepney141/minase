# 学習器は評価関数ごとに独立したパイプラインを持ち、データの読み込みと汎用の部品だけを共有する

## ステータス

承認済み。決定日は2026年10月13日。

## コンテキスト

[Python学習器のRustへの移植と撤去](../plans/archived/python-trainer-retirement.md)は、Rustで書いたNNUEの学習器に加えて、PST、FM、およびPSTとFMの同時学習の学習器と、学習の前後に使う診断をRustへ移した。
NNUEの線形の経路は、鏡映を共有して盤上総駒数で2端点を補間するPSTそのものであり、PSTの学習器と順伝播、二値交差エントロピー、駒除去差分の補助損失（駒を1枚除いたときの評価の変化を参照と同じ向きにする損失）、および切り詰めの範囲が同じ式である。
そこで当初は、NNUEの学習器に線形の経路だけを学ぶモデルを加え、PSTの学習器をNNUEの部品とバッチの供給に相乗りさせる設計を採った。
しかし、NNUE、PST、およびFMは構造のまったく異なる評価関数である。
この設計で書いたPSTの学習器の最初の実装では、1エポックの訓練の大半を、バッチの単一スレッドでの構築と、PSTが使わないNNUE用の逆索引の構築が占めていた（[照合の記録](../measurements/python-trainer-retirement/python-trainer-retirement-checks.md)）。

## 決定

学習器は1つのクレート`crates/minase-trainer`の実行ファイル`minase-trainer`とし、`nnue`、`pst`、`fm`、`joint`、`diag`のサブコマンドで呼び分ける。
特徴とバッチの作り方、モデル、順伝播と逆伝播、駒除去差分、チェックポイント、および学習ループは評価関数ごとに持ち、同時学習はPSTとFMの部品を組み合わせて作る。
すべての学習器で共有するのは、教師データの読み込み、検証分割、先読み教師、教師用K、および教師値を扱う`data`と、Adamの更新、ロジットに対する二値交差エントロピー、加算順を固定した並列の和などの汎用の部品を置く`nn`だけとする（詳細は`data`と`nn`のモジュールのdocコメントにある）。

## 検討した代案

PSTの学習器をNNUEの学習器の線形の経路として実現する案は、評価関数の異なる学習器のパイプラインを共通化しすぎるので、2026年10月13日にエンジンの開発者の判断で改めた。
PSTとFMの学習器を別のクレートに分ける案は、共有の部品を二重に持つか、さらに共有のクレートを切り出すことになるので採らなかった。

## 結果

NNUEの線形の経路とPSTの学習器は同じ形の式を別々に持ち、この重複は受け入れる。
新しい評価関数の学習器を加えるときは、既存のパイプラインに相乗りさせず、`data`と`nn`の上に専用のパイプラインを置く。

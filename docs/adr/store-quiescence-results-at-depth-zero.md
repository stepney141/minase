# 静止探索の結果を深さ0で置換表へ保存する

## ステータス

承認済み。決定日は2026年8月23日。

## コンテキスト

[探索部](../plans/archived/search.md)の初版では、静止探索は置換表を使っていなかった。
[Lazy SMP](../plans/archived/lazy-smp.md)の初版が速くならなかった原因を調べると、単一ワーカーの深さ5の探索で、置換表を照会する残り深さ1以上のノードは、12.76Mノードのうち242Kで、全ノードの約2%しかなかった（[測定記録](../measurements/lazy-smp-v1-diversification-bench.md)）。
残りは置換表を使わない深さ0のノードと静止探索であり、置換表の共有が減らせる部分木はごく一部であった（[教訓](../lessons/qsearch-dag-without-tt.md)）。
初版の置換表は、同じ局面への書き込みを常に受け入れていた。
静止探索が深さ0の記録を書くようになると、この規則では通常探索の深い記録が消える。
そこでLazy SMPの第2版は、静止探索で置換表を照会・記録し、同じ局面への書き込みを深さで制限した。
`--each nodes=100000`のGSPRTは有効445ペアでLLR 2.958の`H1`となり、固定深さ5の経過時間は11.1秒から4.2秒へ短縮した（[測定記録](../measurements/qsearch-tt-nodes100k.md)）。

## 決定

静止探索は置換表を照会し、結果を深さ0で保存する。
同じ局面のエントリは、新しい結果の深さが保存済みの深さ以上のときだけ置き換え、浅い結果は捨てる。
通常探索のカットオフには、要求された深さ以上の記録が必要なので、静止探索の評価値が通常探索を打ち切ることはなく、その記録手だけが指し手順序付けに使われる。

## 検討した代案

静止探索で置換表を使わない初版の方式は、上記の測定で棄却した。
同じ局面へ常に書き込む初版の規則は、深さ0の記録が深い記録を消すので採らなかった。

## 結果

静的評価だけでβ以上となって打ち切るノードでは、置換表を照会も保存もしない。
この順序は、後の[合法手生成と利き計算の高速化（第2期）](../plans/archived/movegen-speedup-2.md)の段階7が定めた。
静止探索は反復を検出しないので、静止探索の記録に経路依存の値は入らない。
実装は`crates/minase/src/search/alphabeta/quiesce.rs`の`quiesce`と、`tt.rs`の`store`にある。
測定は評価関数v0と、当時の静止探索の構成で行ったので、静止探索の置換表利用をやめる提案には再測定が要る。

# 置換表のエントリを16バイトの2語の原子値に保ち、補正前の静的評価と探索値なしの記録を持たせる

## ステータス

承認済み。決定日は2026年10月21日。

## コンテキスト

[2語の置換表の旧ADR](archive/use-atomic-two-word-transposition-entries.md)は、2026年8月23日に、1エントリを2個の`AtomicU64`からなる16バイトにすると決めた。
[Lazy SMP](../plans/archived/lazy-smp.md)では複数の探索ワーカーが1つの置換表を共有するが、それまでの置換表は`Vec<Entry>`を`&mut`で操作しており、共有できなかった。
StockfishとC++版のやねうら王は共有置換表への競合する読み書きを通常のメモリアクセスのまま許容しているが、同じ競合をRustの通常のメモリアクセスで再現すると未定義動作になる。
置換表の値のうち、評価値による打ち切りに要るのは検証キー、評価値、深さ、および境界の種類である。
記録手は手の並べ替えと減深の判断にしか使わず、着手として使う前に現局面の合法手との一致を確かめ、世代は置換の優先度にしか使わない。
旧ADRはこの区別に従い、打ち切りに要る値を1語目（`critical`）に、助言として使う記録手と世代を2語目（`advisory`）に置いた。
その後、1語目には主変化の木に属するノードとして保存した印（以下、PVの印）も置かれ、その使い方は[浅い前向き枝刈りのADR](extend-shallow-pruning-to-stockfish-ranges-and-skip-it-when-a-royal-is-attacked.md)にある。

[静的評価を置換表に保存しない旧ADR](archive/do-not-store-static-eval-in-tt.md)は、2026年9月12日に、エントリに静的評価を持たないと決めた。
[棋力向上段階6](../plans/archived/strength-stage6.md)の時点の評価関数は学習PSTであり、[評価の費用のbench](../measurements/strength-stage6/strength-stage6-eval-cost-bench.md)では評価1回の費用はノードの処理時間の0.24%だった。
段階計画は探索の挙動を変えない高速化をNPSの改善が3%以上見込める場合に限って実装するので、旧ADRは保存を見送った。
旧ADRは、2026年10月12日に既定の評価関数が[NNUE](../plans/archived/nnue-replacement.md)へ置き換わったことを受けて、再提案には現行の評価関数で評価1回の費用を測り直す必要があると記録していた。

Stockfishは置換表のエントリに補正前の静的評価を持ち、置換表に当たれば評価関数を呼ばずにその値を使う（`src/search.cpp:856-874, 1756-1762`）。
照会で当たらなかったノードでは、探索値`VALUE_NONE`と未探索を表す深さで、静的評価だけを持つ記録を書く（同`873, 1786`）。
探索の結果を保存するときにも、静的評価を添える（同`1657`）。
2026年10月17日のエンジンの開発者の決定により、[探索の関数形の見直しの統括計画](../plans/search-forms.md)の各サブタスクでは、形や値がStockfishとYaneuraOuで違えばStockfishに合わせ、Stockfishにある項目は入れる。
[静止探索の補正と枝刈りの形の見直し](../plans/archived/qsearch-forms.md)は、静止探索の入口をStockfishの順序へ寄せる項目の一部として、静的評価の保存を実装した。
それまでのエントリでは、2語目の33〜63ビットと1語目の59〜63ビットが予約領域だった。

## 決定

1エントリは2個の`AtomicU64`からなる16バイトのままとし、予約領域に補正前の静的評価と探索値なしの目印を置く。
1語目は、ビット0〜31に検証キー、32〜47に探索値、48〜55に深さ、56〜57に境界の種類、58にPVの印、59に探索値なしの目印を置き、60〜63を0に保つ。
2語目は、ビット0〜24に記録手、25〜32に世代、33〜48に補正前の静的評価を置き、49〜63を0に保つ。
静的評価の欄の「なし」は、評価関数の出力の範囲の外にある`i16::MIN`で表し、評価値0と区別する。
静的評価には、詰みの手数の基準を移す変換を掛けない。

書き込み側は2語目をRelaxedで書いた後に1語目をReleaseで公開し、読み取り側は1語目をAcquireで読んでから2語目を読む。
置換の可否は既存値を読んでから判定し、比較交換で判定し直さずに、競合を待たずに書き込む。
64ビットの原子値を使えないコンパイル対象は、コンパイル時に拒否する。

探索値なしの記録は、補正前の静的評価だけを持ち、探索値、境界の種類、深さ、および記録手を持たない記録である。
照会の結果の型`Hit`は、探索値を`value: Option<TtValue>`、静的評価を`static_eval: Option<i32>`として持ち、探索値なしの記録の値を通常の探索値として読めない形にする。
探索値なしの記録では、2語目に別の書き込みに由来する手が残っていても記録手を常になしとし、空のエントリとは目印のビットで区別する。
空のエントリは、目印が0で境界の種類が0のエントリである。

探索値なしの記録は、深さ0の記録と同じ置き換えの規則で書く。
書き込みの競合がない場合、空のエントリ、同じ局面の深さ0の記録、および過去の世代の別の局面の記録を置き換え、同じ局面の深さ1以上の記録と、同じ世代の別の局面の記録は置き換えない。
既存の探索値なしの記録は深さ0として扱うので、同じ局面の探索の結果はこれを常に置き換える。
探索値なしの記録のPVの印は、根では真、通常探索ではそのノードのttPv、静止探索では偽とし、照会に当たらなかったノードで書くStockfishの印と同じ値にする。

通常探索、根、および静止探索は、照会で当たった記録に静的評価があればその値を補正前の静的評価とし、なければ評価関数の値を求める。
照会で当たらなかった場合に限り、求めた静的評価を探索値なしの記録として書き、当たったが静的評価がない場合は書かない。
静止探索では、この書き込みを最善値の初期値がβ以上で返す場合に限る（[静止探索の入口のADR](probe-the-tt-before-the-qsearch-stand-pat-and-blend-fail-highs-toward-beta.md)）。
探索の結果を保存するときは、そのノードで使った補正前の静的評価を添える。
補正値は置換表に保存せず、読むたびに現在の鍵、着手の記録、および補正表から求め直す（[correction historyのADR](sum-material-placement-and-continuation-correction-histories-and-apply-them-to-the-qsearch-stand-pat.md)）。

探索値なしの記録は、探索値と記録手を使うすべての箇所で使わない。
対象は、静止探索の打ち切りとstand-patの置き換え、通常探索の打ち切りとそれに伴う履歴の更新、打ち切りの前に子局面の置換表と照合する処理、および通常探索と根の判定用の評価値である。
置換表の値と深さを使うLMR（後方の手を浅く読む減深）の減深量の計算、記録手を使う手の並べ替え、記録手の有無で決める内部反復減深（置換表の記録手がないノードを浅く読む減深）、およびUSIの診断の表示も対象に含む。
子局面との照合は深さ0の記録も比較に使うので、深さの条件では探索値なしの記録を除けず、探索値の有無で除く。
照合に成功したかだけを使う`tt_hits`と、reverse futility pruningなどが使う「置換表に当たったか」は、探索値なしの記録でも真とする。

2語目は検証キーと同じ原子操作では読まれないので、複数のワーカーが同時に書くと、記録手と静的評価は別の局面の値になり得る。
旧ADRが記録手について受け入れたこの近似を、Stockfishと同じく静的評価にも広げて受け入れる。
`invariants`フィーチャの累算値の検査は、置換表の静的評価を使う場合も残し、置換表の値との一致の検査には置き換えない。

## 検討した代案

静的評価を置換表に保存しない旧ADRの方式は、Stockfishにある項目は入れるというエンジンの開発者の決定により採らなかった。
旧ADRが再提案の条件とした評価1回の費用の測り直しは行っておらず、本決定はその条件を満たしたことを根拠にしていない。

エントリを16バイトより大きくして静的評価の欄を設ける案は、予約領域に16ビットの静的評価と1ビットの目印が収まるので採らなかった。
補正後の静的評価を保存する案は、補正表が探索中に学習して同じ局面の補正値が変わり、Stockfishも補正前の値を保存するので採らなかった。
静的評価の「なし」を0で表す案は、評価値0と区別できないので採らなかった。
照会で当たったが静的評価を持たない記録のノードでも探索値なしの記録を書く案は、Stockfishが書かないので採らなかった。
`invariants`の累算値の検査を置換表の静的評価との一致の検査に置き換える案は、並行書き込みと照合キーの衝突で静的評価が別の局面の値になり得るので採らなかった。

旧ADRが棄却した案は、次のとおり棄却したままとする。
StockfishやC++版のやねうら王と同じく競合を通常のメモリアクセスで許容する案は、Rustでは未定義動作になるので採らない（[Lazy SMPの設計書の参考資料](../plans/archived/lazy-smp.md#参考資料)）。
置換の可否を比較交換で判定し直す案も採らない。
競合で浅い結果が後から公開されても、最後に公開された1語目は1回の書き込みに由来する探索値であり、打ち切りの正しさは損なわれないからである。

## 結果

打ち切りに使う値は1回の原子的な読み取りで得るので、別々の書き込みの値が混ざらない。
記録手と静的評価は1語目と異なる書き込みに由来することがあり、静的評価はstand-patと枝刈りの判定に入るので、この近似は探索値以外の判定にも及ぶ。
1つのワーカーで同じ評価関数を使い、照合キーの衝突がなければ、置換表の静的評価は同じ局面の評価関数の値と一致する。

エントリの大きさは16バイトのままであり、[benchの記録](../measurements/qsearch-forms/qsearch-forms-bench.md)の最大常駐メモリは、設計書を始めた時点のmaster`662c1ab6`と同じ約509.4 MBだった。
静的評価の欄と探索値なしの目印を加えたコミットと、通常探索と根で静的評価を読み出すコミットは、benchの全15局面の深さ3、5、7で、探索ノード数、評価値、および最善手が直前のコミットと一致した。
深さ9の全15局面では、置換表の静的評価を静止探索で30,788回、通常探索と根で73,345回使い、探索値なしの記録を静止探索で85,301件、通常探索と根で50,113件書いた。
置換表の一致は、静止探索で8,632回から41,309回に、通常探索で44,873回から78,601回に増えた。
この一致には探索値なしの記録との一致も含まれるが、その内訳は数えていない。

NNUEの累算値は着手の直後に更新されるので、置換表の静的評価で省けるのは評価関数の出力の計算だけであり、その速度の変化は測っていない。
静止探索の形の変更をすべて入れた版`e9abbc86`は、1つのコアに固定したNPSが約7.4%低く、16本のbenchを同時に走らせた負荷時のNPSが約16%低かった。
NPSの低下の内訳は測っていない。

ThreadSanitizerなどのサニタイザは検証の道具に採っておらず（[ADR](do-not-adopt-sanitizers-or-miri.md)）、並行書き込みの近似は競合試験で確かめていない。
1スロットに複数のエントリを置くクラスタ化は、[置換表を1スロット1エントリの直接マップのまま保つADR](keep-transposition-table-direct-mapped.md)が扱う。
実装は`crates/minase/src/search/alphabeta/tt.rs`にあり、ビット配置とメモリ順序の詳細は`TranspositionTable`の`probe`、`store`、および`store_static_eval`と、`Hit`のdocコメントにある。
2026年10月18日のエンジンの開発者の決定により、探索の関数形の各サブタスクはSTCの結果によらず採用し、7本を通して元のmasterより強くなったかは統括計画のフェーズ10のLTCで確かめる（[採用の例外のADR](adopt-search-form-subtasks-regardless-of-stc-and-check-the-whole-chain-by-ltc-on-the-measurement-machine.md)）。

形の変更の90係数を、vast.aiで借りた計算機で30,000ペアのSPSAにより調整した（[SPSAの記録](../measurements/qsearch-forms/qsearch-forms.md)）。
最終値を反映した版は、同じ計算機で持ち時間を換算せずに行ったSTCで、設計書を始めた時点のmasterに対して107ペアで`H1`（約+261 Elo）だった（[STCの記録](../measurements/qsearch-forms/qsearch-forms-stc.md)）。
逐次検定は境界を越えた時点で止まるので、この点推定は大きめに出やすく、採否には使っていない。

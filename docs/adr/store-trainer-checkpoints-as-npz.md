# 学習器のチェックポイントをNPZに置き、設定そのものを収めて比べる

## ステータス

承認済み。決定日は2026年10月13日。

## コンテキスト

学習器`minase-trainer`は、NNUE、PST、FM、およびPSTとFMの同時学習の4種の学習について、学習を中断して再開するためのチェックポイントを、`MNTRCKPT`、`MNFMCKPT`、`MNJTCKPT`の3種のマジックを持つ独自のバイナリ形式で書いていた。
これらは学習器の内部でしか読まれず、末尾にファイル全体のSHA-256を置き、`config.json`の設定と入力を結びつけるための検査和も持っていた。
NNUEの学習器は、最良のチェックポイントを読み直して同じ内容で書いた`nnue-float.bin`も出力していた。
[各形式の版を1つにする決定](archive/keep-one-version-per-file-format.md)は、学習器の内部だけで使うファイルに独自形式を作らないことを定めた。
学習器はすでに、浮動小数点の重みの受け渡しに無圧縮のNPZを使っていた。

## 決定

4種の学習器のチェックポイントを、無圧縮のNPZの`latest.npz`と`best.npz`に置き換える。
NPZには、現行の状態（モデルの重み、最適化器のモーメントとステップ数、マスク、固定した初期値、勾配の履歴）を配列として収め、学習器の種別、進捗、および`config.json`の比較対象の欄（`settings`、`inputs`、`preprocessing`）をJSONの配列`meta`に収める。
再開時には、種別、配列の名前と形、および`meta`の設定と現在の`config.json`の欄ごとの一致を確かめ、検査和は使わない。
`nnue-float.bin`は書かず、量子化前の最良モデルには`best.npz`を使う。
配列の一覧は各学習器の`checkpoint.rs`のdocコメントにある。

## 検討した代案

3種の独自形式を、先頭の識別部と末尾の検査和を持つ1つの共通の外枠にまとめる案は、独自形式が1つ残り、検査和による照合も残るので採らなかった。
設定を結びつける検査和を残す案は、設定そのものを収めて比べれば不要であり、不一致のときにどの欄が違うかも示せないので採らなかった。

## 結果

`MN`の独自形式から3種のチェックポイントが消えた。
チェックポイントはNumPyなど学習器以外のツールでも読める。
実データでNNUEとPSTを1エポックで止めて2エポック目を再開した学習は、中断しない学習と損失の列も最終の重みも一致した（[照合の記録](../measurements/file-format-consolidation-equivalence.md)）。
旧形式のチェックポイントからは再開できないので、変更前に始めた学習は変更前のコミットで完了させる。

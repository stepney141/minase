# AlphaZero型探索の実行器は、系列の基本シードの加算値を必須の引数で受け取り、生成の区間をサイクルごとの幅10⁹に収める

## ステータス

承認済み。決定日は2026年11月15日。
[生成し直しに5×10⁸を足すシードのADR](archive/take-the-zero-series-seed-offset-as-a-required-runner-argument.md)を置き換える。

## コンテキスト

実行器`minase_zero run-cycles`は、出力の置き場所と記録を分けた学習の単位（系列）ごとに加算値を受け取り、サイクルの自己対局の基本シードをサイクル番号×10⁹＋加算値とし、対局のシードを基本シードと対局番号から導く。
区間[基本シード＋1, 基本シード＋対局数]が重なると同じ対局を生成し直すことになるので（[隣接するシードの教訓](../lessons/derive-seed-adjacent-collision.md)）、実行器は全系列で共有するシードの台帳`seed-ledger.jsonl`に区間を登録し、既存の区間と重なれば起動を拒む。
置き換えたADRは、加算値を必須の引数`--generation-seed-offset`で受け取り、誤った投了による生成し直しには基本シードにさらに5×10⁸を足すと定め、加算値を0以上5×10⁸未満、加算値＋5×10⁸＋対局数の上限を10⁹以下に限っていた。
2026年11月15日に、投了はAobaZeroの方式で閾値を較正し、誤った投了の多いサイクルを生成し直す手順はなくすと決まった（[投了の較正のADR](calibrate-the-zero-self-play-resignation-threshold-as-aobazero-does-and-record-the-gumbel-choice-value.md)）。
生成し直しのために予約していた区間は、使われなくなった。

## 決定

実行器は、系列の基本シードの加算値を必須の引数`--generation-seed-offset`で受け取り、1回目の学習の主な系列である本線と、それ以外の別系列を区別せずに、サイクルの生成の基本シードをサイクル番号×10⁹＋加算値とする。
加算値は0以上10⁹未満とし、加算値＋対局数の上限が10⁹を超えるときは、台帳に登録する前に止める。
加算値は実行器がサイクルごとに追記する記録に残す。
新しい系列を起動するときは、最初のセッションの前に、予定するサイクルの区間が台帳の既存の区間と重ならない加算値を選ぶ。

## 検討した代案

加算値を0以上5×10⁸未満に限る規則を保つ案は採らなかった。
その上限は生成し直しの区間を各サイクルの幅10⁹に収めるためのものであり、生成し直しがなくなった後は理由がないからである。

系列の名前からシードを自動で導く案は、置き換えたADRと同じ理由で採らなかった。
名前の違う系列の区間が重ならないとは名前からは言えず、重なりは結局台帳で検査することになる。

## 結果

1回目の本線は加算値0にあたり、記録済みのシードは変わらない。
置き換えたADRの規則で登録した区間は台帳に残り、新しい系列の区間はそれらと重ならないように選ぶ。
2回目の学習の系列`cycles-rl2-az`の加算値は3×10⁸とした。
置き換えたADRで3×10⁸を割り当てた系列`cycles-rl2`は、生成の区間を台帳に登録しないまま使われなくなった。
`cycles-rl2-az`がサイクル1〜50で使う区間は、1サイクル100万局までなら、台帳の既存の区間と重ならない。
実装は`tools/train/zero/minase_zero/runner.py`にある。

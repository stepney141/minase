# NNUEの訓練集合は学習時にハッシュの剰余で間引き、前処理は間引く前の全体で行う

## ステータス

承認済み。決定日は2026年10月17日。

## コンテキスト

[NNUEの検証損失の頭打ちの切り分け](../plans/nnue-early-best-epoch.md)では、独立な単位である対局の数が少ないことが頭打ちの原因かを調べるため、同じ局面数で「少数の対局から全局面を使う」学習と「多数の対局から疎に使う」学習を比べる必要があった。
教師データを生成し直して対局数を変えるには約1日かかる。
nnue-pytorchは、読み込み時に平均してN局面を飛ばして1局面を使う`--random-fen-skipping`で、1局から使う局面を減らす（同計画の「先行実装」）。

## 決定

`minase-trainer nnue train`の`--train-subsample games:<k>:<r>`と`positions:<k>:<r>`で、訓練集合を学習時に間引く。
残す局面は、`games`では（ファイルの通し番号、対局番号）、`positions`では（ファイルの通し番号、対局番号、手数）のSplitMix64のハッシュをkで割った余りがrのものとする。
教師の勝率尺度、先読み教師、観測マスク、および初期値は間引く前の訓練集合全体から作り、1エポックの更新回数、学習率の倍率、および再開の検査は抽出後の局面数から計算する。
式と記録の項目は`crates/minase-trainer/src/data/subsample.rs`と`nnue/train/record.rs`のdocコメントにある。

## 検討した代案

教師データを対局数を変えて生成し直す案は、生成に約1日かかり、生成の乱数による差も比較に混ざるので採らなかった。
局面を局面単位で検証集合へ分け直す案は、同じ対局の局面が訓練と検証の両方に入り、対局の情報が検証側へ漏れるので採らなかった。
乱数生成器で局面を選ぶ案は、一時ファイルへ振り分ける学習（`--buckets`が2以上）と再開のたびに同じ集合を再現する手順が要るので採らなかった。
鍵だけで決まるハッシュなら、この手順は要らない。
教師の勝率尺度や観測マスクを抽出後の集合から作る案は、間引き方の違いに尺度や初期値の違いが混ざるので採らなかった。
更新回数を間引く前の局面数から計算したままにする案は、予定したバッチ数に満たずに学習器が停止するので採らなかった。

## 結果

`--train-subsample`を指定しない学習は、この引数を加える前の学習器とビット単位で同じ重みを書き出す。
指定した値、抽出後の局面数と対局数、および抽出した局面の番号列の検査和は`config.json`に記録され、再開時には変更できない。
`games`の抽出後の局面数は対局の長さに左右されるので、同じkでもrごとに更新回数が厳密には揃わない。

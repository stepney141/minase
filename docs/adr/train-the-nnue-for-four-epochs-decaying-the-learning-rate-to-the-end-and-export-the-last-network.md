# NNUEは約4エポックの学習の終わりまでに学習率を余弦減衰で下げきり、最後のネットを書き出して、検証損失は見張りに使う

## ステータス

承認済み。決定日は2026年11月23日。標準レシピv4に適用した。
[NNUEの学習期間は未学習対局での検証損失から選ぶ](archive/select-the-nnue-checkpoint-on-held-out-games.md)を置き換える。

## コンテキスト

標準レシピv3を定めた[以前の決定](archive/select-the-nnue-checkpoint-on-held-out-games.md)は、訓練に使わない対局での誤差（検証損失）を約0.5エポックごとに測り、2回続けて最小値を更新しなければ学習を止めて、最小だった時点の重みを書き出すとしていた。エポックは、訓練局面をひととおり学ぶ期間である。
学習率の予定は、その前のレシピの更新回数（390,656更新）を期間とする余弦減衰（学習率を余弦曲線に沿って滑らかに下げる予定）のまま残していた。

この組み合わせで、王の位置を使わない入力P型のネットの世代反復（前の世代のネットで教師を生成して次の世代のネットを学ぶ反復）を進めたところ、第1世代と第2世代は、どちらも1.5エポックの重みを書き出して2.5エポックで止まった。
原因を調べた[診断の測定](../measurements/adhoc/nnue-early-stop-diagnosis.md)は、次の3点を示した。

- 検証損失は1エポックで横ばいになり、その後の訓練損失はエポックの境界をまたぐときにだけ下がった。同じ局面を2回目に学ぶ時点からは、訓練局面への適合が進んでも検証損失は下がり続けない。
- 学習が止まった時点の学習率は、初期値の0.997倍と0.984倍であり、減衰はほとんど働いていなかった。減衰の期間だけを4エポックに縮めると、検証損失は約2.5%下がり、最小は3.0エポックへ移った。
- 横ばいの区間の検証損失の揺れは標準偏差で約0.5%、学習のシードを変えたときの差は約1%だったのに、停止を決めた差は約0.2%だった。シードを変えると、選ばれる時点は1.5エポックから2.5エポックに変わった。

一方、同じ教師を長く学び続けると弱くなることは、以前の決定の根拠になった[測定](../measurements/adhoc/tatara-p-generalization.md)が示している。30本の教師を2.83エポック学んだネットは、8.02エポック学んだネットに+51.6 Elo（95%信頼区間+28.2〜+75.5）で勝った。
学習の長さを先に決める先行のNNUEの学習器のうち、チェスの学習器bulletの配布例と、将棋の学習器tataraの余弦減衰の設定は、どちらも学習率を下げる期間を学習の長さに合わせ、決めた長さの最後の重みを使う（[調査メモ](../research/nnue-training-recipes.md)、[設計書](../plans/archived/nnue-decay-to-end.md)の参考資料）。

そこで、学習の長さを約4エポックに固定して学習率をその終わりまでに下げきり、最後の重みを使う条件を、標準レシピv3の条件と対局で比べた。
どちらの条件も、端数バッチを捨てるように直した学習器で、世代反復の第1世代の教師43本を学んだ（[学習の記録](../measurements/nnue-decay-to-end/nnue-decay-to-end-gen1-training.md)）。
短時間の時間制御（STC）の逐次検定で、新しい条件のネットは`H1`（候補が有意に強いという判定）を取り、819ペアで+21.0 Elo（95%信頼区間+6.6〜+35.5）だった（[判定の記録](../measurements/nnue-decay-to-end/nnue-decay-to-end-gen1-stc.md)）。

[測定の手引き](../guides/sprt.md)は、採用の決定を長時間の時間制御（LTC）の判定だけが下すと定める。
設計書も、第3世代の教師で2つの条件を比べ、同じ2つのネットのLTCで標準レシピを改めると計画していた。
2026年11月23日に、エンジンの開発者は、第1世代の教師でのSTCの`H1`をもって新しい条件を標準レシピに採用し、第3世代の教師での比較とLTCは行わないと決めた。

## 決定

NNUEの学習は、更新をまとめる単位である1 superbatchを約0.5エポックとし、8 superbatch（約4エポック）で終える。1エポックの更新回数をUとして、1 superbatchの更新回数はceil(U÷2)（小数点以下の切り上げ）である。
学習率は、同じ8 superbatchで初期値の0.027倍まで余弦減衰で下げ、最後の重みを書き出す。学習器には`--superbatches 8 --lr-schedule cosine:8:0.027`を渡し、`--validation-patience`は渡さない。
検証損失は約0.5エポックごとに全検証対局で測り、最後の検証損失が、重みの更新を始めてから測った検証損失の最小値の1.02倍を超えたネットは使わない。

## 検討した代案

- **検証損失が最小の重みを選び続ける（以前の決定）**。横ばいの区間のどの点が選ばれるかが検証損失の揺れで決まり、学習率を下げきる前の重みが選ばれる。対局でも新しい条件に負けた。
- **減衰の期間だけを縮め、検証損失による停止を残す**。学習率を下げている途中の横ばいの2点で止まり得る。
- **学習の長さを更新回数で決める**。世代反復は第N世代の教師を約N億局面とするので、同じ更新回数が指すエポック数が世代で変わる。検証損失の最小は、訓練局面が2,370万から2億600万までの学習で1.5〜2.7エポックにあり、エポック数のほうが一定に近かった。
- **4エポック以外の長さ**。2エポックや8エポックとの対局での比較は行っていない。長い側は、8.02エポックのネットが2.83エポックのネットに負けた測定があるので延ばさない。
- **停止の判定に最小の改善幅を設ける**。横ばいの区間でかえって早く止まる。
- **検証損失を平滑化して停止を判定する**。平滑化の幅と、平滑化した値に対応する重みの決め方が増える。
- **学習中の重みを平均して使う（指数移動平均のEMA、複数の時点の重みを平均するSWA）**。保存と再開と量子化の検査が増え、NNUEで対局の利得を数値で示した記録が見つからなかった。
- **検証損失が改善しないときに学習率を下げる（newbob、plateau）**。学習率が検証損失の揺れで決まる。
- **最後の検証損失が閾値を超えたときに、検証損失が最小だった重みへ自動で差し替える**。差し替えた重みは学習率を下げきる前のものであり、以前の決定の問題が戻る。

## 結果

学習の長さと学習率の予定が教師の量によらず同じ引数になり、世代ごとに減衰の期間と上限を計算する必要がなくなる。
検証損失が最小だった時点の重みを保存するファイル`best.npz`は、標準レシピでは作られず、駒除去差分の診断には`latest.npz`を渡す。

採用の根拠は、手書きの評価関数が生成した第1世代の教師での、P型のネットのSTCだけである。
ネットが生成した教師での比較、LTC、および自玉の位置ごとに別の重みを使う入力HalfKP_vmでの比較は行っていない。世代反復の第3世代以降の判定で、世代ごとの伸びが第2世代までと比べて鈍らないかを見る。

閾値の1.02倍は、最適性を確かめた値ではない。診断の測定で4エポックまで学んだ3つの学習は最後の検証損失が最小値の1.004〜1.014倍、対局を4分の1に絞って訓練局面への適合を進ませた学習は1.021倍であり、閾値はそのあいだに置いた。世代ごとに、最後の検証損失と最小値の比を対局の結果と一緒に記録し、世代反復の完了のときに見直す。
最後の検証損失が閾値を超えた場合は、そのネットを使わずに学習を止めて原因を調べる。別の時点の重みで代えることはしない。

第1世代の教師では、新しい条件のネットは、量子化誤差（実数の重みを整数へ書き出した前後の評価値の差）の絶対値の最大が319.8 cp（cpはセンチポーンで、歩兵1枚の100分の1）、駒除去差分の符号反転の割合が0.060%であり、以前の条件のネットの109.0 cpと0.041%より大きかった。この2つの値に合否の基準はないが、世代ごとに記録して推移を追う。

# 探索が使う評価関数を、USIのオプションEvalFileで指定した外部のファイルのNNUEの1つにし、PSTとFMのコードは比較用に残す

## ステータス

承認済み。決定日は2026年11月17日。[探索が使う評価関数をNNUEの1つにし、PSTとFMのコードは比較用に残す](archive/use-nnue-as-the-only-search-evaluation.md)を置き換える。

## コンテキスト

[以前の決定](archive/use-nnue-as-the-only-search-evaluation.md)は、αβ探索が使う評価関数を、`crates/minase/nets/nnue.bin`を`include_bytes!`で実行ファイルに埋め込んだNNUE（着手ごとに差分で更新できる小さなニューラルネットワーク）だけにしていた。
NNUEだけを使う根拠は、幅128のNNUEがPST＋FMに対してSTCとLTCの両方で`H1`になったことであり、PSTとFMのコードは学習した評価関数を比べる基準として残していた。

次に試す入力特徴集合HalfKP_vmは、自玉の升ごとに別の第1層の行を引くので、ネットは約500 MBになる（[tatara化とHalfKP_vmの設計書](../plans/nnue-tatara-framework-and-halfkp-vm.md)）。
GitHubはgitの1ファイルに100 MiBまでしか許さないので、このネットはgitに入れることも、ビルドのときに埋め込むこともできない。
世代反復の連続生成スクリプトも、世代ごとのネットをgitにコミットし、教師を作る計算機でそのコミットからエンジンをビルドしていたので、大きなネットでは回せなかった。
PV-MCTS（ニューラルネットで木を広げるモンテカルロ木探索）は、すでにONNXのネットのファイルをUSIのオプション`NnModel`で受け取り、`isready`で読んでいた。
2026年11月15日にエンジンの開発者は、ネットを実行ファイルに埋め込まず、既定のネットも持たないと決めた。
この判断は[NNUEの外部ファイル化の設計書](../plans/archived/nnue-external-network-file.md)で下した。

## 決定

探索が使う評価関数はNNUEだけとし、ネットは実行ファイルに埋め込まない。
αβ探索は、USIのオプション`EvalFile`（CECPでは`option EvalFile=`）で受け取ったパスのファイルを、USIでは`isready`で、CECPでは`new`か探索の開始で読む。
既定のネットは持たず、`EvalFile`が未設定か、ファイルを読めないか、形式の検証に通らなければ、エラーを出して終了コード1で止まる。
PV-MCTSは、探索値のセンチポーンへの換算と引き分けの値の勝率への換算に使う勝率尺度を、これまでのように埋め込んだNNUEのヘッダから読むのをやめ、USIのオプション`NnCpPerLogit`で受け取って`isready`で検査する。
PST単独、PST＋FM、および駒得評価v0のコードは、`eval/pst/`と`handcrafted.rs`にテストごと残し、探索からは呼ばない。
オプションの宣言、読み込みの時期、およびエラーの文言は、`crates/minase/src/search/alphabeta/engine.rs`と`crates/minase/src/protocol/`のdocコメントにある。

## 検討した代案

ネットの埋め込みを続ける案は、約500 MBのネットをgitにも実行ファイルにも置けないので採らなかった。
Git LFSにネットを置く案は、計算機がコミットからビルドする流れに、LFSの取得と容量の管理を足すので採らなかった。
Stockfishのように既定のネットを埋め込み、`EvalFile`で上書きできるようにする案は、既定のネットを持たないという決定に反し、大きなネットではやはり埋め込めないので採らなかった。

やねうら王のオプション`EvalDir`のように、ディレクトリを受け取って決まった名前のファイルを読む案は採らなかった。
この方式では候補と基準のネットを別々のディレクトリに決まった名前で置く必要があり、NASにSHA-256の名前で置いたネットを、測定で候補と基準にそのまま渡せない。
PV-MCTSの`NnModel`に倣って`NnueModel`と名付ける案は、GUIの利用者が知る名前ではないので採らなかった。
`EvalFile`は、Stockfishでもネットのファイルのパスを受け取るオプションの名前である。

Stockfishのように`setoption`の処理の中でネットを読む案は採らなかった。
重い準備を`isready`で行うのはUSIの約束であり、`NnModel`の扱いとも揃う。
`setoption name EvalFile`はパスを保存し、読み込み済みのネットと、前のネットの評価に基づく置換表およびhistory表を捨てるだけにする。
パスが変わったときだけ読み直す案は、同じパスのファイルを差し替えた場合に古いネットのまま進むので採らず、同じパスを設定し直した場合も次の`isready`で読み直す。
読み込みに失敗したときに、前のネットや埋め込みのネットで続ける案は、安全に続けられないときは止めるというプロジェクトの方針に反するので採らなかった。

PV-MCTSにもNNUEのネットを`EvalFile`で要求する案は採らなかった。
1つの実数のために約500 MBのネットを読ませ、PV-MCTSの実行の条件を2つのネットに依存させるからである。
勝率尺度を定数にする案は、学習で決まる値を手で固定するので採らなかった。

PSTとFMのコードを削除する案は、学習した評価関数の比較の基準を失うので採らなかった。
PST＋FMをNNUEへ蒸留する案は、ネットを旧い評価へ縛るので採らなかった（[アーキテクチャの考察](../proposals/archived/nnue-architecture-discussion.md)）。
駒得評価v0、PST、NNUEを実行時に切り替える案は、どのコミットでも探索が使う評価関数を1つに保ち、評価関数の比較をコミット対コミットの対局で行うという方針に反するので採らなかった。

## 結果

ネットはgitに入れない。
開発中のネットは、PV-MCTSのONNXのネットと同じNAS（ネットワークに接続した記憶装置）に、ファイル全体のSHA-256の16進数をファイル名にして置く。
リリースでは、採用したネットをGitHubのリリースに添付し（1ファイル2 GiB未満を受け付ける）、SHA-256をリリースノートに書く。
crates.ioへ公開するパッケージには本番のネットが入らず、テストの固定ネットだけが入る。
`crates/minase/nets/nnue.bin`はgitの管理から外したが、履歴は書き換えていないので、過去のコミットは埋め込んだネットのままビルドして比べられる。

エンジンを起動する側は、αβ探索の`isready`の前に`EvalFile`を、PV-MCTSの`isready`の前に`NnModel`と`NnCpPerLogit`を送る必要がある。
開発用GUIとlishogi Botは、この変更を含む版へ移るときに追従する。
ネットをファイル全体のSHA-256で識別する決定は[ネットの識別子のADR](identify-nnue-networks-by-the-sha256-of-the-whole-file.md)にある。
比較用のコードを残すことは、未使用のコードを温存しないというプロジェクトの方針の例外であり、エンジンの開発者が2026年10月9日に決めた。

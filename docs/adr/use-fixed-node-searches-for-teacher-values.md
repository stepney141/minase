# 教師値の探索は深さではなくノード数で打ち切る

## ステータス

承認済み。決定日は2026年8月26日。

## コンテキスト

評価関数の学習データは、エンジン同士の自己対局で現れた局面に、その局面の探索値と対局結果を付けたものである。
探索値は教師値の主成分なので、1局面あたりの探索の打ち切り方が、教師の質と生成にかかる時間の両方を決める。
[評価関数の設計書](../plans/archived/evaluation.md)の起案時には、中将棋の合法手数は1局面あたり100を超え、局面によって大きく変わった。
当時のbenchでは、深さ6まで読む探索の1局面平均が約983 ms、深さ4で約124 msであり、深さを固定すると1局面の費用が34 msから3.5秒まで変動した。
学習には数千万局面が必要であり、その生成に何時間かかるかを事前に見積もれなければ計画を立てられない。

## 決定

教師値を付ける探索は、各局面でノード数の上限に達した時点で打ち切る。
生成器の既定の上限は100,000ノードであり、教師データを作る計画ごとに`--nodes`で明示して変えられる（詳細は`DEFAULT_NODES`のdocコメントにある）。

## 検討した代案

一定の深さまで読む案は、分岐の多い局面ほど費用が急に増え、生成量の見積もりが立たないので採らなかった。

## 結果

1局面の費用がほぼ一定になり、1世代の生成時間をノード数と並列度から見積もれる。
探索が実時間に依存しないので、生成コミット、シード、および引数が同じなら、並列度によらず出力ファイルはバイト単位で一致する。
教師値の読みの深さは局面の分岐の多さで変わり、分岐の多い局面ほど浅い読みの値になる。
ノード数は教師の分類を定める項目の1つなので、ノード数の異なるデータは教師用Kを別に推定する（[教師データを来歴ファイルで分類し、MNSDの形式は変えない](classify-teacher-data-by-provenance-files.md)）。
[NNUEの教師データの生成](../measurements/nnue-replacement-generation.md)は、同じ方式で上限を20,000ノードに下げて局面数を増やした。

# NNUEの入力特徴集合に王の位置で条件付けないP型を使う

## ステータス

承認済み。決定日は2026年10月12日。

## コンテキスト

NNUEの入力特徴集合とは、局面と視点から、第1層のどの行を発火させるかを定める規則である。
基底特徴は、47種類の駒状態と2陣営と144升の組の13,536個に、先獅子の対象升144個を加えた13,680個の特徴であり、PSTとFMの入力と同じである。
文脈とは、視点ごとに特徴の番号付けを決める値であり、着手で文脈が変わった視点では差分更新ができず、第1層を全再計算する。
P型は、基底特徴をそのまま入力にする入力特徴集合である。
HalfKP-hm-b8は、自陣の王将（なければ太子）の位置を8区分にまとめ、その駒が盤の左半分にあれば盤面全体を左右鏡映してから、区分ごとに別の行を引く入力特徴集合であり、特徴数は109,440である。
チェスと将棋のNNUEは自玉の位置で条件付けた入力を使うが、中将棋で同じ形が成り立つかは確かめられていなかった（[入力特徴の調査](../research/nnue-input-features.md)）。
教師データを数えると、太子が現れた対局は1.77%にとどまり、自玉の升は自陣の最下段の中央に偏っていたので、太子とデータ量はHalfKP型を退ける理由にならなかった。
[NNUEによるPST＋FMの完全代替](../plans/nnue-replacement.md)は、両方を幅128で同じデータと同じ設定から学び、P型を基準側とする対称な仮説（elo0=−5、elo1=+5）のSTCで比べた。
HalfKP-hm-b8の候補は114有効ペアのペンタノミアル度数[80, 0, 30, 0, 4]で`H0`となった（[記録](../measurements/nnue-replacement-features-stc.md)）。

## 決定

NNUEの入力特徴集合をP型とし、文脈を1種類、特徴番号を基底特徴の番号そのものとする。
入力特徴集合の契約と各実装の番号付けの詳細は、`FeatureSet`、`P`、および`HalfKpHmB8`のdocコメントにある。

## 検討した代案

HalfKP-hm-b8は、上記のSTCでP型に負けたので採らなかった。
HalfKP-hm-b8は、重みファイルがP型の約8倍の約28 MBになり、自玉が区分をまたぐ着手ではその視点の第1層を全再計算する費用も持つ。
自玉の144升をそのまま条件にするHalfKP型は、幅128で第1層だけで約504 MB（左右鏡映で約252 MB）になり、重みファイルとして扱えないので候補にしなかった。

## 結果

`HalfKpHmB8`の実装と、そのための文脈ごとの全再計算の経路はコードに残っており、探索が使う組を`ActiveFeatureSet`の型の別名とネットの差し替えだけで比べ直せる。
比較は初代のネットの幅128と全30ファイルの教師で行ったので、教師の量や幅が大きく変わった場合は、HalfKP型を再提案する前に測り直す必要がある。
採用の根拠となった段階ゲートはP型のコミット`90280a0`を測ったものであり、別の入力特徴集合のネットを埋め込んだバイナリには及ばない。

# PV-MCTSの探索木の全節点の不変条件を、フィーチャ`invariants`の下で、探索の終わり、自己対局の各手の決定の前、および木の付け替えの前後に検査する

## ステータス

承認済み。決定日は2026年11月17日。

## コンテキスト

PV-MCTSの探索木では、辺ごとに訪問回数、勝率の和、および評価を待つ間に一時的に負けとして数える仮想損失を持ち、シミュレーションのたびに経路の辺を更新する。
この更新を誤っても、誤った統計は手の選び方を変えるだけで、探索を止めるエラーにはならないので、誤りが表に出にくい。
先行エンジンでは、チェスのCeresが木の全体を検査する`validate-store`を、チェスのlc0が節点の操作ごとの`assert`を持つ（[エンジン開発のデバッグ手法の調査](../research/engine-debugging-survey.md)）。
minaseは、重い整合検査をCargoのフィーチャ`invariants`の下に置き、`cargo test`では常に有効にしている（[整合検査のADR](enable-invariant-checks-in-tests-by-feature.md)）。
判断の詳細は[PV-MCTSのデバッグ道具の設計書](../plans/archived/mcts-debugging-tools.md)の「探索木の検査」の節にある。

## 決定

`invariants`の下に、探索木の全節点を根からたどって10の条件を確かめる`Tree::validate`と、それに加えて、経路を選んでから評価と逆伝播を終えるまでの未完了の選択と、根の評価待ちが残っていないことを確かめる終了時の検査`Driver::assert_finished`を置く（2026年11月17日のエンジンの開発者の決定）。
対局の探索のループの正常な終わりと、自己対局の各手の決定の前では終了時の検査を行い、指された手の先の部分木を次の探索の根にする木の付け替えの前と後では`validate`を行う。
勝率の和を含む等式は64ビットの浮動小数点数で計算し、根からの手数の上限をMAX_PLY（256手）、辺に累積した訪問の数をkとして、k(k + MAX_PLY)·2⁻⁵² の丸めの差を許す。
仮想損失は符号のない整数なので、戻す前に経路の全辺の値が正であることも確かめる。
検査に失敗したら、失敗した条件、経路の辺の添字の列、および関係する値を含むメッセージでパニックする。

## 検討した代案

シミュレーションのたびに全節点を検査する案は採らなかった。
シミュレーションの回数をnとすると、節点の数もnに比例して増えるので、検査の費用の合計がnの2乗に比例する。

各操作の後に変更した経路だけを検査する案（lc0）は、1つのエンジンにしか先例がなく、同じ誤りを単体試験で捕まえられるので採らなかった。
探索の終わりの検査は、途中で打ち消し合った誤り、たとえば評価待ちの葉に再び達した（衝突した）選択の仮想損失を、誤った辺から2回引いて元に戻る誤りを見逃し得る。
この種の誤りは、評価待ちの経路が複数ある途中、衝突の直後、および評価を中止した選択を戻す取り消しの直後に`validate`を呼ぶ単体試験で捕まえる。
このため`validate`は、評価待ちの葉が残る探索の途中の状態も、仮想損失の数が未完了の選択と合っていれば受け入れる。

勝率の和の等式を厳密に比べる案は、加算の順序の違いによる丸めの差で正しい木を拒むので採らなかった。
許す幅の根拠は、k個の0〜1の値の和の丸めの誤差がおよそk²·2⁻⁵³以下で、各訪問の値も経路の長さに比例する回数の1 − xの計算を経ることにある。

勝敗が確定した節点の平均の勝率Qが1や0であることは検査しない。
勝敗の確定は過去の勝率の和を書き換えないからである。
手を選ぶたびに事前確率を足していく累積値にも上限を課さない。
この値は選択の取り消しでも戻らないからである。

## 結果

通常のビルドには検査の処理が入らず、探索の結果と速さは変わらない。
2026年11月17日に、PV-MCTSの固定局面の探索`bench`の出力が、`invariants`付きのreleaseビルドでも通常のビルドと全行一致し、検査に失敗しないことを確かめた（[照合の記録](../measurements/mcts-debugging-tools/mcts-debugging-tools-verification.md)）。
`cargo test`の中の探索、自己対局、および木の付け替えは、すべて検査を受ける。
探索木の構造や統計の更新を変えるときは、`Tree::validate`の条件も同じ変更で改める。
条件の一覧と許す幅は`crates/minase/src/search/mcts/tree/validate.rs`の`Tree::validate`のdocコメントにある。

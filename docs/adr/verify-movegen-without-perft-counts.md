# perftの数値を合法手生成の正しさの基準にしない

## ステータス

承認済み。決定日は2026年7月31日。

## コンテキスト

perftは、ある局面から指定した深さまでの合法手の列を数え上げ、その総数を外部実装の参照値や過去の自分の値と照合する、合法手生成器の検証手法である。
minaseは当初、lishogiの規則ライブラリshogiopsの参照値と、過去の自分の出力を回帰テストの基準として固定した値（自己回帰値）の2つを照合していた。
2026年7月31日の[指し手正準化](../plans/archived/move-canonicalization.md)で、獅子の2段階移動のうち同じ結果になる経路を1手にまとめるよう指し手の表現を改めた。
その結果、minaseの手数は経路を別々に数える外部実装と一致しなくなった。
同じ数え方をする外部実装を探すか、正準形と外部の表現の間の変換層を書かない限り、外部の参照値とは照合できない。

## 決定

perftの数値を、合法手生成の正しさを判定するテストの基準にしない。
外部実装との数値照合は再挑戦せず、自己回帰値も固定しない。
合法手生成の正しさは、RULES.mdの条項ごとの境界局面のテストとランダムなプロパティテストで検証し、外部実装との照合は、保存棋譜の指し手を1手ずつ再生し、審判層の判定と突き合わせることで行う。

## 検討した代案

外部実装の手数に合わせる変換層を書く案は、変換層自体の正しさを別に検証する必要があり、その費用が照合で得られる利益に見合わないので採らなかった。
自己回帰値だけを残す案は、正しい変更でも値が変わるたびに自己回帰値を書き換えることになり、正しさの基準として働かないので採らなかった。

## 結果

perft自体は`minase dev perft`として残し、初手ごとに手数を分けて数えるdivideによる不具合の絞り込みと、速度の計測に使う。
獅子の規則の相互作用を系統的に網羅する検証は失われ、その代わりを条文ごとの事例テストが担う。
経緯は凍結した[中将棋の合法手生成の設計書](../plans/archived/movegen.md)の9節にある。

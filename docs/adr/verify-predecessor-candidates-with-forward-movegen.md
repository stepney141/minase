# 直前局面は逆向きに構成した候補を順方向の合法手生成器で検証して求める

## ステータス

承認済み。決定日は2026年9月18日。

## コンテキスト

`PredecessorGenerator`は、対象局面へ1手の局面合法手で到達できる直前局面をすべて返す公開APIであり、逆方向探索を行う外部のプログラムが使う。
直前局面を漏れなく求めるには、移動元、取られた駒、成り、および先獅子と成り権保留の一時状態を逆にたどる必要がある。
獅子の捕獲制限と成りの規則は合法手生成器に実装済みであり、同じ判定を逆向きにもう1つ書くと、2つの実装が食い違う危険が生じる。
[直前局面生成器の設計](../plans/archived/predecessor-generator.md)では、検証の方式と、一時状態の表現を変えるかどうかが論点になった。

## 決定

駒の動きの幾何的な反転、初期配置から盤上の駒を差し引いた不足在庫（取られた駒の由来別の枚数）、および局所条件を満たす一時状態の値から真の直前局面をすべて含む上位集合として候補を作り、各候補着手を順方向の`MoveGenerator`で検証して対象局面に一致したものだけを返す。
候補着手の合法性は、動かす駒1枚の合法手だけを生成する`MoveGenerator::is_legal_move`で判定し、候補局面をその場で進めて対象局面と比べた後に巻き戻す。
`Position`の一時状態の内部表現は変えず、読み出しのアクセサと`Hash`の実装を加えた。

## 検討した代案

逆生成の側に獅子の捕獲制限と成りの判定を持つ案は、規則の判定が2か所に分かれるので採らなかった。
初版から使っていた、候補局面の複製に`Position::try_make_move`を適用する方式は、[計測記録](../measurements/predecessor-generator-profile.md)で検証の段階が実戦に近い局面の所要時間の5割から6割を占めたので採らず、決定の方式に改めた。
改めた後、実戦に近い局面の所要時間の中央値は改める前の0.44倍から0.66倍になり、検証の段階の割合は1割から2割へ下がった。
対象局面の先獅子の記録升から候補着手を先に絞る案は、先獅子の状態がある局面にしか効かず、残る費用の中心が候補の構築と集合の検査だったので採らなかった。
返却の`Vec`をやめて検証に合格した局面を参照で渡す内部イテレーションのAPIは、公開APIの変更を伴ううえ、重複排除の集合が残って削減幅が限られるので採らなかった。
先獅子の状態と成り権保留を1つの公開値へまとめる案は、生成器が使わない探索、評価、学習データ、および拡張SFENの処理経路まで作り替えることになるので採らなかった。

## 結果

`is_legal_move`は全合法手の生成と同じ駒別の生成関数を使うので、検証の判定は`try_make_move`と一致する。
保証する完全性は、`predecessor`モジュールのdocコメントが参照する設計書の「直前局面の定義」の集合Aに対する相対的なものであり、初期局面からの到達可能性は判定しない。
不足在庫が多い局面では返却の集合が大きくなり、計測記録では王駒2枚と数枚だけの局面で採用数が約150万局面、返却に2秒強と数GBのメモリを要した。
後続の逆方向探索は、この規模を前提に設計する必要がある。

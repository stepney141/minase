# NNUEの学習器をRustのホストとNVRTCで実行時にコンパイルするCUDA C++のカーネルで書く

## ステータス

承認済み。決定日は2026年10月12日。

## コンテキスト

NNUEの学習器は、当初はPythonとPyTorchで書かれ、16,384局面の1更新に0.6〜0.8秒かかり、訓練約7,600万局面の1エポックに47〜61分を要すると見込まれた（[学習の記録](../measurements/nnue-replacement-training.md)）。
その時間の86〜89%はGPUカーネルの実行時間であり、大半は(局面数, 145, 幅)の密な配列を作って読み書きする実装に費やされ、本来必要な第1層の疎な計算は1割に満たなかった（[学習器の速度の調査](../research/nnue-trainer-speed.md)）。
同じ調査は、将棋のNNUE学習器tataraの速さが、Rustという言語ではなく、疎なgather、逆索引による後退、融合した最適化器、および非同期のデータ供給という設計に由来することを確かめた。
PyTorchの自動微分の枠内でこれを直すには第1層と補助損失のカスタムカーネルを書く必要があり、Rustで書くのと同じ作業量になる。
評価関数の改善は、採用した評価関数で教師を生成し直して学び直す世代反復を主な経路としており、学習の時間は反復の周期の3〜5割を占めていた。

## 決定

NNUEの学習器を、ホストをRust、カーネルをCUDA C++で書き、カーネルのソースを`include_str!`で埋め込んで起動時にNVRTCでコンパイルする。
学習は最初からGPUで行い、CPUでの学習は`--device cpu`を明示したときだけ、GPUカーネルと1対1に対応するCPU参照実装を並列化した経路で行う。
GPUがなければ明示的なエラーで止め、CPUへ黙って切り替えない（詳細は`nnue::gpu`と`nnue::train::backend::Backend`のdocコメントにある）。

## 検討した代案

tataraをフォークする案は採らなかった（[NNUEの完全代替の参考資料](../plans/nnue-replacement.md#参考資料)）。
将棋固有の盤、駒、教師形式、および特徴抽出の部分を書き直す必要があり、PSTを移した線形の経路や、駒を1枚除いたときの評価の変化の向きを参照に合わせる補助損失（駒除去差分の補助損失）を持つminaseの構成がtataraの2つの構成のどちらにも当てはまらず、nightlyのRustにも依存するからである。
カーネルをRustからPTXへコンパイルするcuda-oxideで書く案は、nightlyのRustと固定リビジョンを要し、tatara自身が境界検査の費用を記録しているので採らなかった（[学習器の速度の調査](../research/nnue-trainer-speed.md)）。
nvccでビルド時にコンパイルする案は、ビルドにnvccを要し、GPUのないサンドボックスでビルドとCPUのテストができなくなるので採らなかった。
CPUだけの学習経路を先に作って測ってからGPUへ進む案は、エンジンの開発者が退けた。

## 結果

訓練約8,270万局面の全30ファイルの1エポックは、2つの入力特徴集合で145秒と155秒になり、Pythonの学習器の見込みの約20分の1になった（[検査と試走の記録](../measurements/nnue-trainer-rust-checks.md)）。
GPUの1更新は27〜32 msであり、残る支配項は駒除去差分の補助損失のカーネル（20.5 ms）である。
cudarcの`dynamic-loading`で`libcuda`を実行時に読み込むので、GPUのない環境でもビルドとCPUのテストができる。
GPUを要するテストは名前を`gpu_`で始めて`#[ignore]`を付け、GPUのある環境で`--ignored`を付けて実行する。
学習器の実装をcodexへ委任する場合も、GPUのテストと学習は委任元がGPUのある環境で実行する（[教訓](../lessons/run-gpu-training-outside-codex-sandbox.md)）。

1. 検証済みの評価ファイルでも、探索窓の幅が0になって深さ5を完了できない。

   [root.rs](../../src/search/alphabeta/root.rs)の66行は、歩兵価値に46を掛けて100で整数除算する。
   歩兵価値が1または2なら幅は0になり、71行の拡大処理でも0のままである。
   深さ5以降で直前の評価値が詰みの範囲外にあると、探索窓の両端が一致し、89行からのループの完了条件`alpha < score < beta`を満たせなくなる。
   時間上限やノード上限がなければ、この反復は終了しない。

   `Pst::decode`は正の歩兵価値を受理するので、この条件は検証済みの公開API入力から到達できる。
   再現では歩兵価値を変更し、王駒価値とチェックサムも形式仕様に従って更新した。
   王駒2枚だけの局面`k11/12/12/12/12/12/12/12/12/12/12/11K b`を、深さ5と10,000ノードの上限で探索すると、歩兵価値100では132ノードで深さ5を完了したが、1と2では10,000ノードを使って深さ4の結果を返した。
   埋め込み評価の通常値では、この条件は発生しない。
   根拠は[段階6の探索窓の契約](../plans/strength-stage6.md)と、[評価ファイルの検証](../../src/eval/pst/format.rs)である。

2. 合法手がない通常探索ノードを、有利な通常評価で打ち切る場合がある。

   [negamax.rs](../../src/search/alphabeta/negamax.rs)の81行から115行は、手番を仮に相手へ渡すnull moveによる枝刈りを、231行の合法手なし判定より先に行う。
   王駒以外の駒が残っていれば、自駒に塞がれて合法手が0でもこの枝刈りに入れる。
   仮の子局面が通常評価で打ち切られると、敗北を検出する前にその値を返す。

   局面`KP10/PP10/12/12/12/12/12/12/12/12/12/11k b`には先手の合法手がない。
   深さ1の全窓探索は`-30000`を返すが、深さ4、窓`[486, 487]`では`+487`を0ノードで返した。
   [第23条](../../RULES.md)と[探索部の終局契約](../plans/search.md)が要求する`-MATE + ply`に反し、祖先へ誤った下界を渡す。
   静止探索の末端で合法手なしを見逃す既知の問題とは別に、通常探索にも到達可能な経路がある。

3. 補助ワーカーが指定深さを完了しても、残りの探索が止まらない。

   [deepening.rs](../../src/search/alphabeta/deepening.rs)の184行から185行は、補助ワーカーが深さ上限へ達しても自身のループを抜けるだけで、共有停止状態を更新しない。
   [並列探索の契約](../plans/lazy-smp.md)は、いずれかのワーカーが指定深さを完了した時点で全員を停止すると定めている。
   そのため、補助が先に必要な結果を得ても、主ワーカーの追加探索が返却を遅らせる。

   2ワーカーで、補助の深さ1完了後に主ワーカーを開始する順序を同期機構で固定した。
   補助は36ノードで完了したが、主も36ノードを探索し、計72ノードを消費した。
   この条件で主が新たに展開するノード数は0であるべきであり、補助の完了を共有する処理が欠けている。

4. 補助スレッドの生成失敗が、作成済みワーカーへ伝わらない。

   [team.rs](../../src/search/alphabeta/team.rs)の258行で`scope.spawn`が失敗すると、ワーカー本体を保護する`run_worker_guarded`の外側でパニックする。
   共有停止状態を更新する処理を通らず、`thread::scope`が既存ワーカーの終了を待つ。
   無期限探索などでは、既存ワーカーが継続するため、生成失敗の通知が長時間返らなくなる。
   [並列探索の生成失敗契約](../plans/lazy-smp.md)に従い、既存ワーカーにも停止を通知してから失敗を返す必要がある。

   検査プロセス内だけで、第2補助スレッドの生成に資源不足エラー`EAGAIN`を注入した。
   生成失敗自体は発生したが、共有停止は`false`のままで、第1補助は検査用の100 ms期限で終了するまで残った。
   ログには`spawn_failed=true team_stop=false watchdog_expired=true`と記録された。
   実際の資源枯渇やシステム全体の制限変更は使っていない。

5. 静止探索の枝刈りが、捕獲と同時に成る利益を無視する。

   局面`11k/12/6p5/12/6O5/12/12/12/12/12/12/K11 b`では、麒麟が歩兵を取って獅子に成る`6e6c+`が合法である。

   ところが窓`[1300, 1301]`では0ノードで874を返し、上端以上の手を見逃した。

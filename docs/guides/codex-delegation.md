# codexへの実装委任の手引き

本書は、AGENTS.mdの共通ポリシーに従ってプログラムの実装をcodexへ委任するときの手順と、既知の落とし穴を記す。
委任元のエージェント（Claudeなど）は設計の確定、レビュー、検証、およびコミットを担い、codexは指示書に書かれた範囲の編集だけを行う。

## 指示書の書き方

指示書は委任元の作業用ディレクトリのファイルに置き、codexには「指示書 <パス> を全文読んで実行せよ」という短い依頼だけを渡す。
長い本文をコマンド置換で引数へ埋め込むと、実行環境の権限確認に拒否されることがある。
編集してよい範囲をファイル単位で明記する。
範囲を明記した過去の委任では、範囲外の編集は起きていない。
指示書には、codex自身にファイルを直接編集させることと、別のエージェントへの再委譲や待機を禁じることを明記する。
環境によっては、codexが依頼を別のエージェントへ再委譲し、成果のないまま完了を報告することがある。

## サンドボックスの制約

codexのサンドボックスにはネットワークもGPUもない。
依存を追加させた場合、codexは`Cargo.lock`を更新できないので、委任元で`cargo build`を実行して`Cargo.lock`を更新し、`cargo fmt`、`cargo clippy`、および`cargo test`を実行し直す。
GPUを要する学習の扱いは [GPUを要する学習はcodexへ委任しない](../lessons/run-gpu-training-outside-codex-sandbox.md) に従う。

worktreeのgit管理領域は本体の`.git/worktrees/<名前>/`にあり、サンドボックスからは書き込めないので、codexはworktreeでコミットできない。
worktreeで作業させるときは、指示書に「コミットしない、git addもしない、1回の実行で1フェーズだけ」と書き、フェーズごとに委任元が検証してコミットする。

## 完了後の確認

codexが完了を報告したら、`git status`で実際の変更があることを確かめてから完了として扱う。
codexが報告する速度比は同時に走る負荷で歪むので、採否に使う数値は委任元が負荷のない状態で測り直す。

## 変種ごとの採否

複数の変種を比べる作業は、「変種ごとに1コミット」で委任する。
委任元が`scripts/bench_compare.py --parent <直前の変種>`で連鎖して測り、採用しない変種は`git reset --soft`とcherry-pickで外す。
codexがコミットできない場合は、変種ごとの差分を`target/*.patch`に出力させ、委任元が`git apply`で再現して`diff -q`で一致を確かめる。

## Claude Codeから委任する場合の注意

Agentツールの`isolation: "worktree"`でcodexのサブエージェントを起動してはならない。
転送役のサブエージェントが先に完了すると、未変更のworktreeが自動削除され、バックグラウンドで走るcodexの成果を回収できなくなる。
worktreeで委任するときは、worktreeを自分で作り、そのディレクトリから委任する。

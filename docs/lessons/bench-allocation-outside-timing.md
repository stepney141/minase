# 速度指標の計測区間に大容量メモリの確保を含めない

## 症状

探索部フェーズ3で置換表を導入した直後、benchのNPSが約195万から約16.5万へ落ちた。
探索自体は置換表により約10%のノード削減で速くなっており、この低下は探索の性能を反映していなかった。

## 原因

benchが局面ごとに256MBの置換表を計測区間の内側で確保していた。
確保直後の初回アクセスで起こるページフォルトが計測時間を支配し、NPSが探索速度ではなくメモリ確保の費用を測っていた。
NPSはmimalloc採否など性能判断の実測指標であるため、この歪みは判断を誤らせる。

## 以後の規則

NPSや実行時間を測るbenchでは、置換表など大容量メモリの確保を計測区間の外に置き、1個を使い回して計測外でクリアし、指標は各局面の探索時間の合計から計算する。
新しい性能指標を追加したときは、確保サイズを変えても指標が動かないことを確認して、計測区間に確保や初期化が混入していないことを検証する。

# 明示的SIMDの前に自動ベクトル化の機械語を確かめる

## 症状

SIMDライブラリを組み込めば評価関数の累算が速くなると見込んだが、現行の機械語を読むと、対象の4つの核はLLVMが既にAVX2の256ビット命令へ自動ベクトル化しており、ライブラリで書き直しても同一の命令列か、ライブラリにない命令（符号つきの拡張乗算）のためにかえって長い命令列になることが分かった。

## 原因

要素数が固定で境界条件のない単純なループは、`target-cpu`が命令集合を与えていればLLVMが自動ベクトル化できる場合がある。
対象の核は呼び出し元へインライン展開されるので、プロファイルや関数名の検索では機械語が読めず、ベクトル化の有無が見えないまま明示的SIMDの効果を見込んでしまう。

## 以後の規則

明示的SIMDの導入を検討するときは、対象の核に`#[inline(never)]`を付けた診断用ビルドを別のターゲットディレクトリへ作って`objdump -d`で命令名ごとの出現数を数え、候補のライブラリで同じ核を検証用のcrateに書いて得た出現数と比べ、候補の命令数が少ないか、コンパイラが出さなかった命令を候補が使う核に限って本体で試作して測る。

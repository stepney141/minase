# 文書の引用には版を固定した出所と元のライセンスを書く

## 症状

2026年9月28日の第三者コード混入監査で、`docs/`とルートの文書に第三者の文章やコードを転載した箇所が29件見つかり、そのうち8件はGPL-3.0系のコードの転載だった。
最大のものは、調査メモがStockfishの`src/search.cpp`から計12行を逐語で転記した箇所である。
引用元のライセンスを明示した文書は1つもなく、出所をコミット、ファイルパス、および行番号で示した2つの文書もURLを載せていなかった。
このため、crateの分割でライセンスを決める際に、29件を1件ずつ照合し直して出所を補う必要が生じた。

## 原因

`docs/`にはライセンスを付けないので、`docs/`に転載する第三者のコードと文章は、元のライセンスの条件か、著作権法第32条の引用の要件（必然性、主従関係、明瞭区別、出所明示）で正当化するしかない。
和訳は翻案にあたるが、第43条は第32条の引用に伴う翻訳を認めるので、引用の要件を満たす訳文は許諾に頼らずに載せられる。
引用を書いた時点で出所とライセンスを記録しておかないと、後から要件を満たすかどうかを確かめられない。

## 以後の規則

調査メモや設計書に第三者のソースコードを逐語で引用するとき、または英語の文章を訳して載せるときは、引用元のURL（版を固定したリンク）、版、および元のライセンスを明示し、原文を照合できず出所を示せない引用は引用符を外して要旨に改める。
引用は論述に必要な範囲に限り、本文と区別できる形で置く。
引用元を手元のチェックアウトから写す場合は、[参照実装の複製を確かめる教訓](verify-reference-checkout-is-pristine.md)に従う。
本規則は文書の引用に限り、crateのコードへの転記は対象外である。

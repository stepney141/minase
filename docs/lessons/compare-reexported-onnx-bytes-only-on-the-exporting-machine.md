# 書き出し直したONNXのバイト列の一致は書き出した機械でのみ確かめる

## 症状

AlphaZero型探索のネットの照合で、学習器の`fixture-eval`は、チェックポイントからONNXを書き出し直し、学習の出力`model.onnx`とバイト列が一致することを確かめてから推論する。
Colab機のL4で学習したネットでは、同じColab機の`fixture-eval`は通ったが、作業機で同じチェックポイントと`model.onnx`を与えると「weights are not identical」で失敗した。
重みのファイルは検査和で一致を確かめて転送しており、取り違えはなかった。

## 原因

PyTorchのONNXへの書き出しは、BatchNormを定数畳み込みで直前の畳み込みの重みとバイアスへ融合する。
この単精度の計算の丸めがCPUによって変わり、作業機で書き出し直したONNXは70個の初期値のうち28個が最大4.8×10⁻⁷異なった。
計算グラフと初期値の名前は一致しており、違いは数値の最後の数ビットだけであった。
書き出し直したバイト列が一致するかどうかの検査は、書き出した機械と同じ機械でしか成り立たない。

## 以後の規則

チェックポイントと書き出したネットの対応をバイト列で確かめる検査は、書き出した機械で1回だけ行う。
ほかの機械では書き出し直さず、その検査を通った機械で書き出した参照の出力を基準に、推論の出力だけを照合する。
機械をまたいで重みの同一性を確かめたいときは、ファイルの検査和で確かめる。

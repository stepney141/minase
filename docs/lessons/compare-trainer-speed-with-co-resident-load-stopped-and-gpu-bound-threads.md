# 学習器のGPUの計算を変えた版は、同じ機械の他の処理を止め、GPUが律速になるスレッド数でも速さを比べる

## 症状

A型のLayerStackの学習器で、第1層の勾配の区分内の和をf32にした版とf64にした版の実学習の速さを比べた。
`--threads 4`で版の順序を入れ替えて1組ずつ計2組測ると、GPUの1回の更新が3.6 ms短いはずのf32版が、2組ともf64版より5〜9%遅く出た。
同じ機械で動いていたlishogiのBotを止めて測り直すと、`--threads 4`では2つの版は同じ速さ（f32版÷f64版の比0.998）で、`--threads 16`ではf32版が17%速かった。

## 原因

Botが対局に応じて最大約8コアを使い、それが2組ともf32版の学習の時間帯と重なっていた。
`--threads 4`では教師のバッチを組んで渡す処理（供給）が律速であり、供給にかかるCPUの時間がBotの負荷で伸びた分だけ、実学習が遅くなっていた。
また、供給が律速の条件では、GPUの計算の速さの差は実学習の速さに現れない。

## 以後の規則

学習器のGPUの計算を変えた版の実学習の速さを比べるときは、同じ機械のBotや対局の測定を止め、版の順序を入れ替えた2組以上を測る。
先に`bench-step`で`--threads`を変えて供給できる毎秒の局面数を測り、本番で使うスレッド数に加えて、速い方の版のGPUの上限（16,384を1回の更新の時間で割った毎秒の局面数）を供給が上回るスレッド数でも比べる。
前者は本番の条件での差を、後者はGPUの計算の差そのものを示す。
速さは、superbatchの局面数の合計を`training_seconds`の合計で割った値で比べる。

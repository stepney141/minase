# 回帰テストは修正を外して失敗を確認する

## 症状

設計監査対応で追加した回帰テスト（0検査、PST配線、Drop時の停止とjoin、パニック時の停止通知、固定深さの主ワーカー進捗）は、修正後のコードに対して書いたため、修正がなくても通過するテストになっている危険があった。

## 原因

修正後の挙動だけを見てテストを書くと、テストが検査しているのは修正ではなく現状の出力になる。
自動の変異検査器を導入していないので、テストが不具合を検出する力は手動で確かめるしかない。

## 以後の規則

回帰テストを追加したら、修正対象の処理を一時的に外してテストが失敗することを確認し、その後で修正を戻して採用する。

# GPU推論を伴う生成器が遅いときは、まず1回の推論の平均バッチと呼び出し回数を数える

## 症状

強化学習の自己対局生成器`zero_selfplay`をTensorRTで初めて動かしたところ、毎秒115局面しか出なかった。
推論速度（バッチ64で毎秒23,800評価）とCPUの1シミュレーションの費用（2〜5 µs）から見込んだ値の数十分の1であり、「推論1回あたり約17 msのCPU費用がある」と推定して調査を委任した。

## 原因

推定が「バッチは常に満杯」という前提に立っていた。
実際には、塊32局と同時64局の組合せで1回の推論の平均バッチが約11葉にとどまり、推論の呼び出しが想定の5.6倍の14,611回になっていた。
推論1回の固定費約3 msに呼び出し回数を掛けると、所要時間のほぼ全部を説明できた。
CPU側の1葉あたりの費用は14〜36 µsで、推定の数百µsより1桁小さかった。

## 以後の規則

GPU推論を伴う生成器や探索の速度を見積もり、または実測と比べるときは、CPUの費用を疑う前に、推論の呼び出し回数と1回あたりの平均バッチを数えて出力に含める。
平均バッチが設定の上限を大きく下回っていれば、同時に進める局数、塊の大きさ、および局の補充の仕組みを先に見直す。

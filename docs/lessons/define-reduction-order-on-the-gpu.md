# 縮約の順序はGPU側で固定の木として定義し、CPU参照にその順を書く

## 症状

GPUカーネルの結果をCPU参照実装とビット単位に近く一致させるため、CPUの昇順の加算順をGPUが真似る実装にしたところ、32レーンの積を1つずつレーン0へ送る直列のシャッフルになり、補助損失のカーネルが29 msから45 msへ遅くなった。

## 原因

縮約の順序を「CPUの素直なループの順」と決めると、GPUでは並列度を捨てて直列化するしかない。順序の定義をどちらの側に置くかで、速度が決まる。

## 以後の規則

GPUとCPU参照を同じ加算順で一致させたいときは、順序をGPUで速い固定の木（レーンごとの部分和を昇順に作り、距離16、8、4、2、1のシャッフルで足す）として定義し、CPU参照にその木を素直なループで書く。固定順の木は実行ごとに同じ結果を返すので、再現性も保てる。アトミック加算は順序が変わるので使わない。

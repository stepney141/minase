# 通信の余裕は遅れの分布の裾から決める

## 症状

lishogiのBotで秒読みの締切に残す余裕（`ByoyomiMargin`）を600 msにしたところ、2日間で10局を時間切れで落とした。
秒読み60秒の上限まで考えた213手のうち10手（4.7%）が時間切れであり、評価値+4356の勝勢の局も含まれていた。

## 原因

余裕は、Bot側の処理時間の最大値に、lishogiまでの通信の見込み500 msを加えた推定で決めており、通信の遅れを測っていなかった。
Botのログで着手の`POST`の往復時間を測ると、0.6秒を超えた手が25,799手中796手（3.1%）あり、最大は2.66秒だった。
秒読み期の探索は毎手のように上限まで考えるので、1手あたり数%の超過確率でも、上限まで考える手が数十手続く対局では時間切れの確率が過半になる。

## 以後の規則

通信を挟む時計の余裕は、見込みの値ではなく、運用ログから測った遅れの分布の裾から決める。
1局で上限まで考える手数を掛けた時間切れの確率が十分小さくなる分位点を選び、根拠の分位点と標本数を設定の近くに書く。

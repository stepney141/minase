# 隣接する基本シードは1局ずれた同じ対局列を生む

## 症状

`selfplay_gen`でシード3とシード4の世代1データを別々に生成したところ、2回目のサマリ（破棄局数、詰み局数、探索値の最小と最大）が1回目とほぼ同一で、レコードを直接比べるとシード4の第n局はシード3の第n+1局と盤面も探索値も完全に一致した。
世代0の`gen0b.bin`（シード2、420局）も`gen0.bin`（シード1）の第2〜421局の完全な複製であり、世代0の1,002,722局面のうち78,307局面が重複していた。
この重複は、同一対局内の再出現しか除外しない生成器と、ファイルのシードと対局番号で分ける検証分割の双方をすり抜け、検証集合を汚染していた。

## 原因

`rng::derive_seed(base, n)`は`splitmix64(base + n)`であり、基本シードと系列番号を加算してから混合するため、基本シードが1違うと系列番号が1ずれただけの同じ対局シード列になる。
混合方式そのものの修正は、`match_runner`の開始局面と過去の測定シードの再現性を変えるため、利用者の判断を待って見送った。

## 以後の規則

同じ生成器や測定を複数の基本シードで走らせるときは、基本シードを対局数（ペア数）以上離す（7,500局なら100000、200000、300000のように）。
複数シードの出力を合わせる前にはサマリの統計を突き合わせ、一致していればレコードを直接比べて複製を検出する。
`derive_seed`の混合方式を変える提案は、生成データと測定シードの再現性の契約を含めて利用者へ諮る。

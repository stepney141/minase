# スレッドを所有するハンドルはDropで回収する

## 症状

`SearchHandle`は探索スレッドの`JoinHandle`と停止フラグを所有していたが`Drop`処理を持たず、呼出し側が`join`を呼ばずに破棄すると探索スレッドが切り離され、外部停止だけを条件とする探索は終了しない処理になり得た。
補助ワーカーのパニックは主ワーカーの完了後まで検出されず、主ワーカー自身がパニックした場合は停止フラグを立てる者がいないため、残る補助ワーカーの回収が外部からの停止要求まで終わらなかった。

## 原因

スレッドの回収責任者が型として定まっておらず、呼出し側が必ず`join`を呼ぶという規律に依存していた。
ワーカーのパニック時に誰が停止を通知するかという契約も文書化されていなかった。

## 以後の規則

スレッドを生成する型は自らを唯一の回収責任者とし、`Drop`でも停止要求と`join`を行い、いずれかのワーカーがパニックしたら残るワーカーへ停止を通知してからペイロードを呼出し側へ返し、破棄時の待機時間の上限は実装前に契約として決める。

# 教師生成を速くする変更は、benchではなく教師生成の負荷で効果を判断する

## 症状

HalfKP_vmのFinny tablesは、行数の診断において、第1層の全再計算で足し引きする重みの行数を、`bench`では87.2%、教師生成では84.2%と、同程度に減らした。
しかし、CPUサイクル数は深さ19の`bench`で1.15%減ったのに対し、1手2万ノードの教師生成では0.14%しか減らず、95%信頼区間で0と区別できなかった。

## 原因

`bench`は1局面を長い1回の探索で読むが、教師生成は1手ごとに2万ノードの短い探索を繰り返す。
探索ごとに払う費用（表の確保や、表の項目を初めて使うときの全再計算など）の重みと、ノードあたりに省ける行数が2つの負荷で違うので、`bench`でのサイクル数の削減率や行数の削減率は、そのまま教師生成でのサイクル数の削減率にはならない。
どの費用が効いたかは測っていない。

## 以後の規則

教師生成を速くするための変更は、実装を磨き込む前の試作の段階で、教師生成の負荷（本番と同じノード数と同時対局数）によるサイクル数の対比較で効果を判定し、`bench`の結果や行数などの削減率から効果を見積もらない。

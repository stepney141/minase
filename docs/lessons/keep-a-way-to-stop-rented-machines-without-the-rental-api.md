# 借りた機械は、貸し手のAPIの認証が切れても止められるようにしておく

## 症状

NNUEの世代反復の第3世代で、計算機を時間単位で借りられる市場vast.aiの機械に、教師ファイルを約40時間かけて生成させていた。
作業機の制御スクリプトは、機械の状態の照会と削除にvast.aiのAPIを使い、そのAPIは利用者が端末で行う2段階認証のセッションを要する。
生成の途中でこのセッションが切れ、制御スクリプトは機械の状態を照会できずに終了した。
借りた機械は生成を続けて課金も続いたが、制御スクリプトは機械を削除できず、完成した教師ファイルの作業機への回収も止まった。
セッションの更新は利用者にしかできないので、利用者が端末に戻るまで、作業機からは機械を削除できなかった。
第2世代でも同じセッションの失効が1回あり、出品が出るのを待って借り直す再試行のスクリプトが、残高の照会に失敗して止まっていた。

## 原因

セッションが1日前後で切れるのに対し、1世代の生成には31〜42時間かかったので、生成の途中でセッションが必ず1回は切れる条件だった。
制御スクリプトは、認証が切れたら終了するだけで、借りたままの機械を止める手段を持っていなかった。
機械の停止と削除が、利用者の操作を要する認証だけに依存していた。

## 以後の規則

借りた機械を、貸し手のAPIの認証の有効期間より長く動かすときは、認証を使わずに機械を止められる経路と、認証を使わずに成果物を回収できる経路を、始める前に用意する。
vast.aiでは、機械の起動時に渡されるコンテナ専用の鍵で、機械の内部からその機械自身を停止でき、SSHの接続先を控えておけば、APIの認証なしで成果物を回収できる。
始める前に、認証が切れる見込みの時刻を利用者に伝え、切れる前に更新を頼む。

# GPUカーネルの内側のループで倍精度を使わない

## 症状

Rust製NNUE学習器のGPU版で、補助損失のカーネルと第1層の後退のカーネルが設計の見積り（1更新10〜20 ms）の数倍の時間（合わせて57 ms）を使っていた。`nvidia-smi dmon`ではSM使用率100%、メモリ帯域使用率1〜8%で、帯域ではなく演算が律速だった。

## 原因

GeForceのGPUは倍精度の演算速度が単精度の1/64である。CPU参照実装が倍精度で累算していたのに合わせ、1更新あたり数億回の積和を`double`で行っていた。最適化器も要素ごとに倍精度の`pow`を計算していた。

## 以後の規則

GPUカーネルの内側のループ（局面数×発火数×幅の桁で回る積和）は単精度で書き、倍精度は局面方向で大きな項が相殺する和（出力重みの勾配、損失の総和など、要素数が局面数の桁のもの）に限る。ステップごとの定数（AdamWのバイアス補正など）はホストで1回計算して引数で渡す。CPU参照は倍精度のままでよく、GPUとの差は等価性の許容誤差で吸収する。

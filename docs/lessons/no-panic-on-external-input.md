# 外部入力でパニックしない

## 症状

USIで`position startpos moves 1あ`のように非ASCII文字を含む着手を受けると、minaseは文字列スライスの文字境界検査に失敗し、終了コード101で停止した。
`setoption name USI_Hash value 18446744073709551615`のような過大な置換表容量では、MiBからバイトへの換算が桁あふれし、`expect`で停止した。
同じ解析器を使う`match_runner`では、相手エンジンが非ASCIIの着手を出力すると、当該エンジンの反則負けではなく測定全体が停止した。
一方で`position`の未知の形式や解釈できないSFEN欄は、エラーを返さず黙って無視または4欄として補完され、GUIとエンジンが異なる局面を持ったまま対局が進み得た。

## 原因

公開解析器と設定処理が、外部入力を内部の前提（ASCIIであること、表現可能な容量であること、既知の形式であること）を満たすものとして扱い、前提の検査をパニックする演算、`unreachable!`、または黙示的な既定値で代替していた。
パニック条件をrustdocへ書いても、プロトコル層が上限を検査せずに値を渡すため停止は防げなかった。

## 以後の規則

プロトコル、設定、ファイルなど外部から受ける値は、解析またはコンストラクタの時点で専用エラーへ変換し、バイト添字によるスライス、桁あふれし得る換算、`unreachable!`、および黙示的な補完を外部入力の経路に置かない。

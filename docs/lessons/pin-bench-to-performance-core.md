# 速度比較のbenchは性能コアへ固定して測る

## 症状

棋力向上段階9の評価特徴の費用測定で、同じバイナリで実行した`minase dev bench`の毎秒の探索ノード数が、実行ごとに1.56Mから1.95Mまでばらついた。
このばらつきの幅は約20%であり、比べたい構成間の差（−9.3%）より大きかった。

## 原因

測定機はlishogiのBotの対局や別の探索プロセスと共用されており、測定中の負荷平均は約6だった。
測定機（Intel Core Ultra 7 265KF）は性能コアと高効率コアのハイブリッド構成であり、固定しない実行ではOSがbenchのスレッドをどちらのコアにも割り当て、他プロセスとの競合の度合いも実行ごとに変わる。

## 以後の規則

速度を比べるbenchは`taskset -c <性能コアの論理CPU>`で固定し（例 `taskset -c 3 minase dev bench --depth 5 --repetitions 3`）、比べるすべての構成を同じCPUで測る。
固定後も各構成を3回測り、値の幅が構成間の差より十分小さいことを確かめてから差を評価する。
固定しても他の負荷の影響は残り得るので、測る前に負荷の大きい測定が動いていないことを確かめる（[測定中の負荷の確認](check-running-measurements-before-cpu-load.md)）。

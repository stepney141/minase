# ランダム初期化の評価関数では探索が止まらない

## 症状

ランダム初期化のNNUEを探索の評価関数に組み込んだコミットでは、benchが深さ5の最初の局面を5分で終えられず、深さ1のbench再現性テストも60秒を超えて完走しなかった。
そのため、推論だけを先に入れてNPSを測る予定のフェーズが、`cargo test`の通らないコミットになった。

## 原因

駒価値を持たない評価では、静止探索のstand-pat（着手せずに静的評価を採る打ち切り）がほとんど効かず、捕獲の応酬を末端まで全列挙する。
探索の実用性は評価関数が駒価値を持つことに依存しており、推論コードの正しさとは独立である。

## 以後の規則

評価関数の推論コードは学習済みの重みと同じコミットで入れ、ランダム初期化の重みは差分更新と全再計算の一致テストおよびPython参照実装との照合にだけ使い、benchのNPSと探索のテストは学習済みの重みで行う。

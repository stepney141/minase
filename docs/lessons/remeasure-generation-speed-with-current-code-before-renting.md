# 機械を借りる前に現行のコードの全負荷の速さを測り直す

## 症状

NNUEの世代反復の設計書は、教師1本の生成を約12分と見積もり、8世代で約68時間、約68米ドルとした。
本番の生成機で最初の本を作ると約29分かかり、1本あたりの局面も少なかったので、8世代の費用は約165米ドルになる見込みになった。
利用者の決定で世代数を8から4へ減らした。

## 原因

見積もりの土台は、約3週間前のコミットで測った試走の速さであり、その後に入った探索と評価関数の変更を、16プロセスの同時実行で測ったネットの速度比だけで補正していた。
その間に探索へ入った大きな表で1局あたりのメモリが約10倍になり、同時384局の全体の探索速度は約3分の1に落ちていた。
同時実行数が多いほどメモリの帯域を奪い合うと考えられ、16プロセスで測った速度比は384スレッドの実行を再現しなかった。
1世代の局面数を数える実装でも、学習に使える局面を表す生成ログの`recorded_positions`と、除外分を含むヘッダの`entry_count`を取り違えていた。

## 以後の規則

借りる機械の費用を見積もるときは、本番と同じコミットのビルドを本番と同じ同時実行数で短時間動かし、全体の処理速度と常駐メモリを測ってから、費用を利用者へ示す。
安い機械の通し試験だけでは速さの見積もりを確かめられないので、本番の機種で数分の測定を行う。
最初の出力を受け取ったら見積もりと比べ、大きく外れていれば利用者へ報告して進め方を決める。

# 不採用の比較候補はマージの前に戻し、採用候補との差分を確かめる

## 症状

2026年10月13日、masterのエンジンが、段階ゲートで採用されたP型のNNUEではなく、P型との比較で`H0`となったHalfKP-hm-b8のNNUEで探索していることが見つかった。
採用されたネットはSTCとLTCでともに`H1`だったが、マージされたブランチの先頭では、入力特徴集合と埋め込みのネットが不採用の候補のものに置き換わっていた。

## 原因

[NNUEの共通土台と初代のネットによるPST＋FMの完全代替](../plans/archived/nnue-replacement.md)では、採用の候補のコミット`90280a0`の直後に、入力特徴集合を比べる測定の候補として、既定の入力特徴集合とネットを切り替えるコミット`3dc5e9e`を同じブランチに積んだ。
コミット対コミットの測定では、比較する設定をコミットとして確定させる必要があるため、比較の候補は既定値を書き換えたコミットになる。
この候補は[型の比較の測定](../measurements/nnue-replacement/nnue-replacement-features-stc.md)で`H0`となったが、切り替えを戻さないままブランチをmasterへマージした。
採否の記録はすべて正しかったので、記録を読むだけでは食い違いに気づけなかった。

## 以後の規則

既定値を切り替える比較の候補は、採用の候補を含むブランチの先頭に積まず、採用の候補から切った別のブランチで作る。
同じブランチに積んだ場合は、`H0`の判定が出た時点で切り替えを戻すコミットを作る。
マージの前には、採用した候補のコミットとマージするブランチの先頭の差分を、対局の挙動に関わるコード（評価、探索、時間管理）と埋め込みの重みファイルについて確かめ、重みファイルのSHA-256が採用の候補のものと一致することを確かめる。

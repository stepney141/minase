# 計測用の共有カウンタはマルチスレッドの速度を歪める

## 症状

探索ノード数の二重計上を調べるため、`negamax`が静止探索へ渡した回数を数える原子カウンタを1個追加してbenchを実行した。
1スレッドのNPSは計測コードの有無で変わらなかったが、16スレッド、深さ7のNPSは約2,870万から約2,250万へ下がった。
この低い値から補正後のNPSを約1,500万と見積もったが、修正後に計測コードなしで測った値は約2,240万であり、見積りは約3割過小だった。

## 原因

追加したカウンタは`static`の`AtomicU64`であり、全ワーカーが毎ノード同じキャッシュラインへ書き込んだ。
書き込みのたびにキャッシュラインがコア間を往復するので、計測コード自体がスレッド数に比例する費用を生んだ。
1スレッドでは競合が起こらないため、この費用は単一スレッドの確認では見えない。

## 以後の規則

マルチスレッドの探索に計測用のカウンタを入れるときは、カウンタをワーカーごとの局所変数に置いて探索の終了後に合算し、速度の値は計測コードを入れないバイナリで測り直して、計測コードつきの実行からは回数の比だけを読む。

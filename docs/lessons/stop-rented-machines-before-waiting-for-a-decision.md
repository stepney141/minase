# 判断を待つ前に借りた機械を止める

## 症状

強化学習のサイクルを回すプログラム（実行器`minase_zero run-cycles`）を、終了後にGoogle Colabで借りた仮想機械（Colab機）を止める処理と連鎖させて起動していた。
10サイクル目の後の進捗測定に同じ機械を使うつもりで、この連鎖を外し、実行器の終了を待つ形に変えた。
その後、利用者の判断を仰ぐ質問の回答を待つ間に、実行器はサイクル6の照合の不合格で止まり、止まったColab機は約3.7時間、計算も接続もないまま置かれ、気づいたときにはColab側に回収されていた。

## 原因

質問の回答を待つ間は作業が進まないのに、借りた機械の停止を、回答の後の作業者の操作に任せていた。
実行器が異常で止まる場合を、停止の連鎖の外で扱っていなかった。

## 以後の規則

借りた機械で長い処理を走らせるときは、正常終了でも異常終了でも機械を止める処理を連鎖させ、同じ機械を後で使う都合のために連鎖を外さない。
利用者の判断を仰ぐ前には、必要なファイルを受け取って機械を止める。後で同じ機械を使えば借り直しの導入を省けるとしても、待つ間に機械を借りたままにしない。

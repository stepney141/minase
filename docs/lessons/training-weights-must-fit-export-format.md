# 学習する重みの範囲を保存形式に合わせる

## 症状

棋力向上段階7の世代2の再学習では、10エポックを計算して最良エポック8を選択した後、量子化時の範囲超過で候補を保存できなかった。
序中盤用の鏡映1対が約−4,236.5366センチポーンとなり、1/8センチポーン単位の整数−33,892は符号付き16ビット整数の下限−32,768を下回った。

2026年11月18日、[tatara化とHalfKP_vmの設計書](../plans/archived/nnue-tatara-framework-and-halfkp-vm.md)で載せ替えたA型を教師37本で64 superbatch学んだときも、書き出しで同じ種類の失敗が起きた。
LayerStackの幅16の層の重みは、区分ごとの組と全区分に共通の組（tataraの`L1 shared`）を別々に学び、書き出しで足してから8ビット整数へ量子化する。
学習中は2組をそれぞれtataraと同じ±127/64に収めていたが、和を64倍して丸めた値の1つが−133になり、8ビット整数の下限−128を下回った。

## 原因

学習中の重みに保存形式の範囲制約がなく、有限な重みでも保存できない値になり得た。
段階7の例では、全27,360値の丸め結果と格納可否は独立した参照計算と一致し、単位変換と鏡映展開にも不整合は検出されなかった。
当該特徴は18,848回観測され、補間係数の偏差平方和257.632は識別性の基準100以上を満たしていたが、この基準は重みが保存範囲に収まることを保証しない。

LayerStackの例では、学習中の範囲を配列ごとに課していたが、保存されるのは2つの配列の和なので、配列ごとの範囲は保存の範囲を保証しなかった。
tataraは書き出しで和を8ビットへ切り詰めて続けるので、範囲を写しただけでは、切り詰めずにエラーで止めるminaseの書き出しと合わなかった。

## 以後の規則

学習の最適化領域を出力形式が表せる範囲と一致させ、範囲の違反を出力時の例外や後処理まで持ち越さない。
書き出しで複数の配列を足したり畳み込んだりしてから量子化するときは、足した後の値が出力形式の範囲に収まるように、各配列の学習中の範囲を決める。
先行実装の範囲を写すときは、先行実装が書き出しで切り詰めているかを確かめ、切り詰めているなら学習の側の範囲を改める。
非有限値と有限な範囲外の値を区別して検査し、量子化の単位と境界を独立した参照計算で照合する。
各更新後の射影を導入する場合は最適化規則の変更として条件を明示し、その条件で再学習して候補を診断したうえで、既存の棋力測定ゲートにより採否を判定する。

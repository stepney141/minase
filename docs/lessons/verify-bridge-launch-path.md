# ブリッジ経由のエンジン起動は設定どおりに起動されることを実際に確かめる

## 症状

lishogi Bot接続の設計書は、Lishogi-Botの設定`engine_options`がminaseの起動引数`--protocol=usi --rules=lishogi`になると、ブリッジのソースの該当行だけを読んで記していた。
Dockerイメージの中でブリッジの`create_engine`を呼ぶと、minaseは引数なしで起動されて直ちに終了し、ブリッジは`EOFError`で止まった。

## 原因

ブリッジは起動コマンドを引数つきのリストのまま`shell=True`で`Popen`へ渡す。
リストと`shell=True`の組合せでは先頭要素だけがシェルのコマンドになり、残りはシェルの位置引数になってエンジンには届かない。
設定項目の読み取り箇所だけを見ると引数は組み立てられているように見え、実際の起動経路まで追わないと欠陥に気づけない。

## 以後の規則

外部のブリッジやハーネスからエンジンを起動する経路は、設定ファイルの読み取り箇所を読むだけで済ませず、そのブリッジの起動関数を実際に呼び、エンジンが期待どおりの引数で起動して握手に応答することを配備と同じ環境で確かめてから設計書に書く。
引数を要するエンジンは、ブリッジの引数機構を当てにせず、引数を固定したラッパースクリプトを起動対象にする。

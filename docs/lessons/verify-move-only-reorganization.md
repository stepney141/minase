# 移動だけの再編は出力と試験名の一致で確かめる

## 症状

`src/core/`の再編では、benchのNPSの中央値が基点の3回の計測の範囲の下限を約0.15%下回り、探索部と評価関数の再編では上限を約0.07%上回った。
どちらも`nm --size-sort`で比べたminaseの関数の集合と各関数の機械語のバイト数は基点と一致しており、生成コードは変わっていなかった。
実行ファイルと対局ハーネスの再編では、試験の件数が788件から772件に減ったが、差の16件は別の試験バイナリで重複して実行されていた試験であり、移動の誤りではなかった。
探索部の再編には、自分自身を`--exact`で子プロセスとして起動する試験があり、モジュールパスを含む試験の完全修飾名を改め忘れると、子プロセスが該当する試験を1件も実行せずに成功で終わってしまう。

## 原因

NPSは同じバイナリでも計測ごとに揺れるので、範囲を外れたことだけでは生成コードの変化を意味しない。
試験の完全修飾名はファイルの移動で変わり、件数は重複実行の解消で変わるので、名前の一覧や件数をそのまま比べると、移動に誤りがなくても差が出る。
逆に、試験がすべて通っても、試験が実際に実行された証拠にはならず、移動したコードの出力が変わっていない保証にもならない。

## 以後の規則

処理を変えない移動の再編では、各コミットで経過時間の欄を除くbenchの出力（探索に関わらないコードでは固定シードの出力）が基点と全行一致し、`cargo test`の試験名の末尾、つまりモジュールパスを除いた部分の集合が基点と一致することを確かめる。
NPSが基点の揺れの範囲を外れた場合は、`nm --size-sort`で関数の集合と機械語のバイト数を基点と比べ、差があれば[呼び出し元の機械語を比較する教訓](check-caller-codegen-for-local-optimizations.md)に従う。
自分自身を子プロセスとして起動する試験は`--nocapture`で実行し、子の出力に`1 passed`が現れることを確かめる。
移動したソース行そのものを確かめたいときは、学習器のPythonコードの再編と同じく、移動前後のソース行の多重集合の差がimport文などあらかじめ許容した差だけであることを確かめる。
benchの出力の照合には`scripts/bench_compare.py`を使える（[デバッグの手引き](../guides/debugging.md)の「挙動の変化の検出」）。

# 参照実装の手元の複製は未コミットの改変を確認してから引用する

## 症状

探索内の反復の扱いを調べたとき、手元のやねうら王の複製を読んで「勝敗は4回目の出現でだけ返す」と調査メモに書いた。
実際の上流は、根より後の1回の再現で勝敗を返す。
設計書の設計判断は、この誤った記述を根拠の1つにしていた。

## 原因

手元の複製は別の作業のためのブランチにあり、127個のファイルに未コミットの改変があった。
作業ツリーの`is_repetition`はその改変の一部であり、`git log -1`で確認したコミットの内容とは異なっていた。
コミットのハッシュを記録しても、読んだのが作業ツリーである限り、その版を読んだことにはならない。

## 以後の規則

参照実装を手元の複製から引用するときは、先に`git status --short`で改変がないことを確かめ、改変がある場合は`git show <コミット>:<パス>`で当該コミットの内容を読む。

# 保存済みのペアの記録を読み込む速さ

## 目的

[aspiration windowsの形のSTC](../aspiration-window-forms/aspiration-window-forms-stc.md)は上限の3,000ペアまで続き、そのSTCを実行したvast.aiの計算機（調整機）のrunnerは、最後のペアを書き終えてから最終の集計を出力するまでに約26分かかった。
この間、runnerは1スレッドでCPUを使い、カーネル時間が多かった。
原因を測定機で特定し、直した後に同じ条件で所要時間を比べる。
棋力測定ではない。

## コマンドライン

STCの実行ディレクトリ（3,000ペア、ペアの記録は約1.5 GB）を作業用のディレクトリへ2つ写し、`minase match run --resume`で再開した。
新しく指すペアはないので、再開の処理では、保存済みの全ペアの読み込みと検証、エンジンの照合、および最終の集計（全局の棋譜を再生して先読みの統計を数え直す`match_runner`の`ponder_summary`）だけが行われる。
実行ファイルは測定機で各コミットからビルドし直したので、調整機で記録したSHA-256と一致しない。照合を通すため、測定用の写しに限り、`manifest.json`の候補と基準のSHA-256を測定機でビルドした実行ファイルの値に書き換えた。元の実行ディレクトリには触れていない。

```console
/usr/bin/time -v <runner> match run --resume <写し>
```

原因の特定には、`manifest.json`を書き換える前の写しの再開を、`perf record -e cpu_core/cycles/u,cpu_atom/cycles/u -F 499 --user-callchains -g`で計測しながら実行した。この実行はエンジンの照合で止まったので、プロファイルは保存済みの全ペアの読み込みと検証の段階だけを含む。

## エンジン

修正前のrunnerは`7631da34`（版2.4.0）、修正後のrunnerはブランチ`json-read-and-launch-ram`のコミット`8d0346d0`である。
修正は、`match_runner`、`match_report`、および`spsa_runner`のJSONの読み込みで、`serde_json::from_reader`にバッファのない`std::fs::File`を渡していたのを、`std::fs::read`でファイル全体を読んでから`serde_json::from_slice`で解析する形に改めたものである。

## 環境

測定機はIntel Core Ultra 7 265KF（性能コア8個と高効率コア12個、20スレッド）である。
ほかの対局測定、SPSA、教師生成、および学習は動いていなかった。lishogiのBotは止めていない。

## 結果

修正前の読み込みと検証の段階のプロファイルでは、カーネルが48.5%、`read`が15.8%、`serde_json::iter::LineColIterator<std::io::Bytes<std::fs::File>>::next`が20.2%を占めた。
`serde_json`は`std::io::Read`から1バイトずつ読むので、バッファのない`File`では1バイトごとに`read`のシステムコールが発行される。棋譜の再生（合法手の生成や着手の適用）は上位に現れなかった。

再開の全体の所要時間は次のとおりである。

| 量 | 修正前 | 修正後 |
|---|---:|---:|
| 経過時間 | 7分26秒 | 1分51秒 |
| ユーザー時間 | 177.4秒 | 108.5秒 |
| カーネル時間 | 267.8秒 | 0.7秒 |
| 最大常駐メモリ | 540,608 KB | 556,124 KB |
| 標準出力の`elapsed` | 236.3秒 | 66.6秒 |

最終の集計の出力（先読みの統計、度数、LLR、判定、および異常件数）は、修正前と修正後で1行も違わなかった。

## 結論

最終の集計と再開時の検証が遅かった原因は、保存済みの記録を1バイトずつシステムコールで読んでいたことである。
ファイル全体を読んでから解析する形に改めると、測定機での再開の全体は約4倍速くなり、カーネル時間はほぼなくなった。
測定機では修正前でも再開の全体が約7分半で終わったのに対し、調整機では最終の集計だけで約26分かかっていた。調整機ではシステムコールが測定機より重いと考えられ、短縮の幅はさらに大きいと見込まれる。
残るユーザー時間は棋譜の再生とJSONの解析であり、今回は手を付けていない。

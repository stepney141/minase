# 世代反復の学習が1〜2エポックで止まる原因の診断

## 目的

[P型の世代反復](../../plans/nnue-generation-iteration.md)の第1世代と第2世代の学習は、どちらも検証損失の最小が1.5エポックにあり、2.5エポックで止まった。
本記録は、第1世代の教師43本を作業機で学び直し、この早い停止が学習器の不具合によるものか、教師と学習の条件から生じるものかを切り分ける。
調べた要因は、同じ局面を繰り返し学ぶことによる訓練局面への適合、学習率の減衰の期間、学習のシード、訓練に使う対局と局面の数、およびエポック末尾の端数バッチの5つである。

本記録で使う語は次のとおりである。
エポックは、訓練局面をひととおり学ぶ期間である。
superbatchは、決まった回数の更新をまとめた単位であり、学習器は1 superbatchごとに検証損失を測る。
検証損失は、訓練に使わない対局（教師の対局の約5%）の全局面で測った、ネットが出す勝率と教師の探索値から換算した勝率の差の2乗の平均である。
訓練損失は、そのsuperbatchで学んだ局面について、更新の直前に測った同じ誤差の平均である。
端数バッチは、訓練局面数がバッチの局面数16,384で割り切れないときに、エポックの最後に残る16,384局面未満のバッチである。
本記録の表では、損失を100万倍した値で示す。

## コマンドライン

実行は、付随ディレクトリの[`run.sh`](nnue-early-stop-diagnosis/run.sh)で行った。
引数は順に、実行名、最初と最後の本の番号、バッチの局面数、1 superbatchの更新回数、superbatchの数、学習率の予定、学習のシード、および学習器へそのまま渡す追加の引数である。
`run.sh`は次の学習器を起動する。

```console
minase-trainer nnue train layerstack --data <本> --rules lishogi \
  --teacher-cp-per-logit 733.1159421542734 --lambda 1.0 --seed <シード> --threads 16 \
  --output-dir <出力先> --batch <バッチ> --superbatches <superbatchの数> \
  --validation-superbatches 1 --device cuda --lr-schedule <予定> \
  --batches-per-superbatch <1 superbatchの更新回数> <追加の引数>
```

実行した条件は次のとおりである。
`L`は、世代反復の本番と同じ減衰の期間390,656更新を、1 superbatchが963更新のときのsuperbatchの数で表した`cosine:405.66562824506747:0.027`である。

| 実行名 | 起動 | 本番との違い |
|---|---|---|
| A-base | `run.sh A-base 0 42 16384 963 24 $L 1` | 検証の間隔を1/6エポック（963更新）にし、検証損失による停止を外して4エポックまで学ぶ |
| B-cos4 | `run.sh B-cos4 0 42 16384 963 24 cosine:24:0.027 1` | A-baseの減衰の期間を4エポック（23,112更新）に縮める |
| C-seed2 | `run.sh C-seed2 0 42 16384 963 24 $L 2` | A-baseの学習のシードを2にする |
| E-pos4 | `run.sh E-pos4 0 42 16384 963 12 $L 1 --train-subsample positions:4:0` | 全対局から局面を約4分の1に間引く |
| G-games4 | `run.sh G-games4 0 42 16384 963 12 $L 1 --train-subsample games:4:0` | 対局を約4分の1に絞り、その全局面を使う |
| F-pos16 | `run.sh F-pos16 0 42 16384 963 8 $L 1 --train-subsample positions:16:0` | 全対局から局面を約16分の1に間引く |
| K-rem172 | `run.sh K-rem172 0 3 16432 4 280 constant:1 1` | 本0〜3だけを使い、端数バッチを172局面にする |
| K-rem5 | `run.sh K-rem5 0 3 16281 4 284 constant:1 1` | 本0〜3だけを使い、端数バッチを5局面にする |
| K-ctrl | `run.sh K-ctrl 0 3 16001 4 290 constant:1 1` | 本0〜3だけを使い、端数バッチを8,036局面にする（対照） |

学習のシードは、重みの初期値と局面を並べる順を決める。検証に回す対局は教師ファイルのシードで決まるので、学習のシードを変えても検証の対局は変わらない。
Kで始まる3本は、バッチの局面数を変えて端数バッチの大きさだけを変えた実行であり、学習率は一定で、4更新ごとに検証した。

## エンジン

学習器は、世代反復が全世代に使うコミット`f2eb705febe317229addc561ff8a0838c545e2eb`のビルド（`data/nnue-generation-iteration/bin/minase-trainer`、SHA-256は`4a444c19…`）である。
教師は、同じコミットの生成器が手書きの評価関数v0のネットで生成した第1世代の43本（`data/nnue-generation-iteration/gen-1/teacher/`）であり、規則セットは`lishogi`である。
43本の訓練局面は94,685,720、検証局面は4,956,611で、1エポックは5,780更新である。
本0〜3の4本の訓練局面は8,840,588、検証局面は462,728である。

## 環境

2026年11月23日に、作業機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB、NVIDIA GeForce RTX 3060 Ti）で実行した。
43本を使う実行は1本ずつ順に行い、本0〜3だけを使う3本は、A-baseおよびB-cos4と同じ時間帯に並行して実行した。
43本の学習の最大常駐メモリは12,555,736 KiBで、A-baseの所要時間は15分2秒だった。
学習器の出力は`data/nnue-early-stop-analysis-20261123/`にあり、全実行のsuperbatchごとの損失を[`curves.csv`](nnue-early-stop-diagnosis/curves.csv)に写した。

## 結果

### 本番の学習の再現

A-baseの検証損失は、本番と同じ更新回数の点（2,889、5,778、8,667、11,556、14,445更新）で、[第1世代の学習の記録](../nnue-generation-iteration/nnue-generation-iteration-gen1-training.md)の値と小数点以下9桁まで一致した。
以下の実行は、検証の間隔と各行に書いた変更のほかは、本番と同じ学習である。

### 学習のシードを変えると、選ばれる時点が変わる

| 項目 | シード1（A-base） | シード2（C-seed2） |
|---|---:|---:|
| 2、3、4エポック目の検証損失の平均 | 961.3、963.1、967.5 | 952.3、951.2、957.6 |
| 1.17エポック以降の検証損失の標準偏差 | 4.8 | 3.9 |
| 0.5エポックごとの検証損失（0.5〜4.0エポック） | 988.6、965.1、960.0、962.1、962.3、957.5、971.3、967.7 | 983.6、953.9、953.9、952.2、945.1、950.9、954.6、958.3 |
| 本番の停止の規則が選ぶ時点と止まる時点 | 1.5エポックと2.5エポック | 2.5エポックと3.5エポック |

本番の停止の規則は、0.5エポックごとに検証損失を測り、2回続けて最小値を更新しなければ止めて、最小だった時点の重みを選ぶ。
シード2でも、訓練損失はエポックの境界でだけ下がり、検証損失は1.0エポックの後に横ばいになった。
シードの間の検証損失の差（約1%）は、1つの学習の中の点の間の揺れ（標準偏差で約0.5%）より大きい。
シード1で停止を決めた差は、960.0と962.1および962.3の差（約0.2%）である。

### 対局数が少ないほど、早く悪化する

| 訓練に使った局面 | 対局数 | 局面数 | 検証損失の最小 | 最小の位置 |
|---|---:|---:|---:|---|
| 全部（A-base） | 303,930 | 94,685,720 | 955.3 | 1.83エポック（10,593更新） |
| 全対局から約4分の1（E-pos4） | 304,412 | 23,664,811 | 998.1 | 2.67エポック（3,852更新） |
| 対局の約4分の1の全局面（G-games4） | 76,405 | 23,688,657 | 1,067.7 | 2.00エポック（2,889更新） |

局面数がほぼ同じE-pos4とG-games4では、対局数が約4倍のE-pos4の検証損失の最小が6.5%小さかった。
G-games4の訓練損失は8.0エポックで662.0まで下がり、検証損失は2.0エポックの1,067.7から8.0エポックの1,136.8まで上がった。
どの条件でも、検証損失の最小は1.8〜2.7エポックにあった。F-pos16は最初の検証点が2.66エポックなので、それより前に最小があった可能性がある。

### 端数バッチの直後に検証損失が跳ねる

| 端数バッチの局面数 | 1回目の境界 | 2回目の境界 |
|---:|---:|---:|
| 8,036（K-ctrl） | −0.62% | +0.75% |
| 172（K-rem172） | +3.38% | +3.00% |
| 5（K-rem5） | +2.35% | +4.87% |

表の値は、端数バッチの直後の12更新のあいだに測った検証損失の平均を、直前の40更新のあいだの平均と比べた変化である。
直前の40更新のあいだの検証損失の標準偏差は、平均の0.5〜0.9%だった。
K-rem172の1回目の境界では、境界の40〜79更新後の平均は直前の平均の−0.1%まで戻った。
学習器は、端数バッチでも勾配をそのバッチの局面数で平均し（`crates/minase-trainer/kernels/layerstack/backward.cu`）、通常のバッチと同じ1回の更新を行う。

第2世代の本番の学習は、訓練局面が206,258,539で端数バッチが363局面、1エポックが12,590更新であり、1.0エポックと2.0エポックの検証は12,594更新と25,188更新の時点、つまり端数バッチの4更新後と8更新後に行われていた。
[第2世代の学習の記録](../nnue-generation-iteration/nnue-generation-iteration-gen2-training.md)では、この2点の検証損失（999.6と997.8）が、1.5エポックと2.5エポックの値（969.9と970.8）より約3%大きい。
第1世代の本番の学習は、端数バッチが2,584局面で、1.0エポックと2.0エポックの検証（5,778更新と11,556更新）が端数バッチ（5,780更新目と11,560更新目）より前にあった。

## 結論

検証損失の最小が1〜2エポックに来るのは、同じ局面を2回目に学ぶ時点から訓練局面への適合だけが進むためであり、学習器の不具合によるものではない。
ただし、本番の学習は学習率がほとんど下がらないうちに止まっており、減衰の期間を4エポックに縮めると検証損失は約2.5%下がった。
本番の停止の規則は、検証損失の揺れより小さい差で止まる時点を決めており、選ばれる時点は学習のシードで変わった。
端数バッチの直後に検証損失が約3〜5%跳ねる現象は学習器の不具合であり、第2世代の1.0エポックと2.0エポックの検証値を押し上げていたが、早い停止の原因ではない。
どの変更についても、対局での強さは測っていない。

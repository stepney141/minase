# 規則書の読みが分かれる箇所での本番の挙動

## 目的

規則書 [chu-shogi.md](../../rules/chu-shogi.md) の第17版の条文から読みが一意に決まらない4つの箇所と、条文を改めるかどうかが論点になる詰みの定義について、規則を実装したcrate `minase-core`の現在の実装（以下「本番」）がどう振る舞うかを、駒を置いて構成した局面と手順で観測する。
5つの箇所は、[規則実装の形式検証の実現可能性と検証を強める候補](../../proposals/rules-formal-verification.md)の検討で見つかったものである。
この観測は、[規則書の読みが分かれる箇所の読みの候補](../../proposals/rulebook-readings.md)の根拠であり、どの設計書も計画していない。

## コマンドライン

測定日は2026年11月26日である。
`crates/minase-core`を、リポジトリの中でGitが追跡しない`target/rules-exp/core`へ複製し、[rulebook-readings-probe.patch](rulebook-readings-behavior-20261126/rulebook-readings-probe.patch)を当てて、追加した試験を実行した。

```console
mkdir -p target/rules-exp && cd target/rules-exp
cp -r ../../crates/minase-core core
patch -p3 -d core < ../../docs/measurements/adhoc/rulebook-readings-behavior-20261126/rulebook-readings-probe.patch
cd core
cargo test --test rulebook_readings -- --nocapture --test-threads=1
cargo test --lib rulebook_reading_probe -- --nocapture
```

パッチは3つのファイルを変える。
`Cargo.toml`は、複製をワークスペースから切り離すために書き換える。
`tests/rulebook_readings.rs`は、ライブラリが外部へ公開している型と関数（以下「公開API」）だけを呼ぶ試験である。
`src/game/adjudication/mod.rs`の末尾には、審判の層（反復と終局を裁定する`game/`以下のコード）の非公開の関数を呼ぶ試験のモジュールを足す。
本番の関数の本体は変えない。

試験は期待値を検査せず、観測した値を表示する。
表示した行は、[public-api.txt](rulebook-readings-behavior-20261126/public-api.txt)と[probe.txt](rulebook-readings-behavior-20261126/probe.txt)に保存した。

## 結果

座標は、升を作る関数`Square::new`に渡す0から11までの（筋、段）で書く。
段0は先手側の最下段で、段が増える向きが先手の前方である。
筋0は、エンジンの通信規約USIの表記の12筋に当たる。
第5条に従い、先手の王駒を王将、後手の王駒を玉将と書く。
どの局面も、駒の枚数は初期配置の枚数以内である。
1つ目の箇所の手順は初期配置から始まる。
ほかの局面は駒を置いて構成したものであり、初期配置から到達できることは確かめていない。

### 同一局面の条件としての先獅子（第24条第1項c）

初期配置から次の手順を、着手を検証して適用し裁定する関数`Game::play`で進めた。
先手は、奇数の手で仲人を動かし、1手目に(3,4)から(3,5)へ、3手目に(3,5)から(3,4)へ進め、5手目と7手目に同じ往復を繰り返す。
後手は、獅子を2手目に(6,9)から(6,7)へ、4手目に(6,5)へ進め、6手目に(6,3)の歩兵を取り、8手目に隣接する(5,2)の先手の獅子を取る。
9手目に先手の奔王が(6,2)から(5,2)へ進んで後手の獅子を取り、双方に獅子がなくなる。
10手目からは、後手の仲人(8,7)から(8,6)、先手の仲人(3,4)から(3,5)、後手の仲人(8,6)から(8,7)、先手の仲人(3,5)から(3,4)の4手を繰り返す。

本番は、獅子以外の駒が獅子を取った升を、局面の一時的な状態として記録する（以下「先獅子の記録」）。
反復の判定は、局面から作る64ビットの値（以下「反復のキー」）の一致で同一局面を数える。
9手目の後の局面は、先獅子の記録（`Position::lion_capture_square`）が(5,2)だった。
13手目の後の局面は、盤と手番が9手目の後と同じで、先獅子の記録がなく、反復のキーは9手目の後と異なった。
本番は、この2つの局面を同一局面と数えなかった。

| 規則 | 結果 |
|---|---|
| `L0,P0,R2,E1,E2` | 13手目を受理し、14手目を反復の禁止で拒否した。 |
| `L0,P0,R3,E1,E2` | 21手目を受理し、22手目を反復の禁止で拒否した。 |
| `L0,P0,R1,E1,E2` | 21手目の後は対局が続き、22手目の後に反復による引き分けで終局した。 |

### P2の待機と最奥段の救済の併用（第30条）

本番は、成りを見送った駒の升を、成り権の保留の集合として局面に持つ。
P2が定める1手番の待機も、P5が定める歩兵の恒久の保留も、この集合の1ビットで表す。
この観測は、保留のビットの有無に対する合法手生成器の応答を調べるものである。

先手の香車を(0,10)、歩兵を(1,10)、銀将を(2,9)、王将を(5,0)に、後手の玉将を(5,5)に置き、先手番で、香車、歩兵、および銀将のそれぞれが非捕獲で1升前へ進む手を、合法手を生成する関数`MoveGenerator::generate_moves`の出力から調べた。
香車と歩兵は最奥段へ進み、銀将は敵陣の中で進む。
「保留あり」は、3枚に`PositionBuilder::mark_promotion_deferred`で保留のビットを付けた局面である。
表の「不成」と「成り」は、その手が出力に含まれたことを表す。

| 規則 | 保留 | 香車（最奥段へ） | 歩兵（最奥段へ） | 銀将（敵陣の中） |
|---|---|---|---|---|
| `L0,P2,R1,E0` | あり | 不成だけ | 不成と成り | 不成だけ |
| `L0,P2,R1,E0` | なし | 不成と成り | 不成と成り | 不成と成り |
| `L0,P2,P3,R1,E0` | あり | 不成と成り | 不成と成り | 不成だけ |
| `L0,P2,P3,R1,E0` | なし | 不成と成り | 不成と成り | 不成と成り |
| `L0,P2,P3,P6,R1,E0` | あり | 成りだけ | 成りだけ | 不成だけ |
| `L0,P2,P3,P6,R1,E0` | なし | 成りだけ | 成りだけ | 不成と成り |
| `L0,P2,P5,P6,R1,E0` | あり | 不成だけ | 成りだけ | 不成だけ |
| `L0,P2,P5,P6,R1,E0` | なし | 成りだけ | 成りだけ | 不成と成り |

この表には、対局では生じない状態が含まれる。
P2の待機は、敵陣の外から入って不成を選んだ駒に、その側の直後の1手番だけ付く。
歩兵と銀将は1升ずつしか進めないので、敵陣へ入った直後の升は奥から4段目であり、(1,10)の歩兵と(2,9)の銀将にP2の待機が付いていることはない。
同じ側の2枚以上の駒に、同時にP2の待機が付いていることもない。
P5を含む規則では、不成のまま(1,10)まで進んだ歩兵には恒久の保留が付いているはずなので、歩兵の「保留なし」の行も対局では生じない。
香車については、どの規則でも「保留あり」と「保留なし」の両方が対局で生じ得る。
以上は駒ごとの状態についての説明であり、表の局面の全体が対局で生じることを示すものではない。

### 付け喰いの優先が及ぶ範囲（第15条第8項、第16条第7項）

先手の獅子を(5,5)、後手の獅子Aを(6,6)、後手の成獅子（麒麟が成った獅子）Bを(7,7)、後手の金将を(6,7)、後手の飛車を(2,2)、先手の王将を(0,0)、後手の玉将を(11,11)に置き、先手番で、先手の獅子の着手を`generate_moves`の出力から調べた。
Aは先手の獅子に隣接し、金将の足がある。
Bは先手の獅子から2升離れている。
「記録あり」は、`Position::set_lion_capture`で先獅子の記録を(2,2)に付けた局面であり、直前に後手の飛車がその升で先手の別の獅子を取った状況に当たる。

| 規則 | 記録 | Aだけを取る | Aを居喰いする | Aを取ってBを取る | Bへ直接跳ぶ | Aを取って空升(7,6)へ進む |
|---|---|---|---|---|---|---|
| `L0,P0,R1,E0` | あり | 不合法 | 不合法 | 合法 | 不合法 | 不合法 |
| `L0,L4,P0,R1,E0` | あり | 合法 | 合法 | 合法 | 不合法 | 合法 |
| `L1,P0,R1,E0` | あり | 合法 | 合法 | 合法 | 不合法 | 合法 |
| 上の3つの規則 | なし | 合法 | 合法 | 合法 | 不合法 | 合法 |

### 終局条件の優先順位

本番の裁定の順は、王駒の捕獲、R1、駒枯れまたは裸玉、合法手なし、詰みである（`game/adjudication/mod.rs`の`adjudicate_after_move`）。
次の4つの例で、本番が採った裁定と、それより後の順位の条件が同じ着手の後に成立していたことを観測した。

例1は、裸玉による勝ち（E3）と、相手の合法手なしの組である。
先手の王将を(0,11)、香車を(0,10)と(1,11)、歩兵を(1,10)、太子を(5,5)に、後手の玉将を(6,6)に置き、後手番で、後手の玉将が(5,5)の太子を取る手を`Game::play`で指した。
着手の後、先手の`generate_moves`の出力は0手だった。

| 規則 | `Game::play`の結果 |
|---|---|
| `L1,L2,P0,P3,R1,E1,E3`（規則セット`lishogi`） | 裸玉による先手の勝ち |
| `L0,P0,R1,E3` | 裸玉による先手の勝ち |
| `L0,P0,R1,E0` | 合法手なしによる後手の勝ち |
| `L0,P0,R1,E2` | 合法手なしによる後手の勝ち |

例2から例4は、審判の層の関数を直接呼び、最後の着手の後の本番の裁定（`adjudicate_after_move`）と、同じ局面と履歴に対する合法手なしと詰みの判定（`stalemate_or_mate`）を並べた。
`stalemate_or_mate`は、手番側の負けの理由として、詰みまたは合法手なしを返す。
試験は、最後の局面で手番側の王駒に相手の利きが届いているかどうかも表示する。

例2は、R1が引き分けと裁定する4回目の出現と、手番側の詰みの組である。
先手の王将を(0,11)、仲人を(4,5)に、後手の玉将を(6,4)、飛車を(0,0)と(7,11)、麒麟を(1,11)、仲人を(9,5)に置き、先手番から16手を進めた。
最初の5手は、先手の仲人(4,5)から(4,6)、後手の仲人(9,5)から(9,6)、先手の王将(0,11)から(1,10)、後手の仲人(9,6)から(9,5)、先手の仲人(4,6)から(4,5)である。
続けて、後手の仲人(9,5)から(9,6)、先手の王将(1,10)から(0,11)、後手の仲人(9,6)から(9,5)、先手の王将(0,11)から(1,10)の4手を2回繰り返し、最後に後手の仲人(9,5)から(9,6)、先手の王将(1,10)から(0,11)、後手の仲人(9,6)から(9,5)の3手を指した。
16手目の後は先手番で、開始の局面の4回目の出現であり、先手の王将は(0,0)の飛車の王手を受けていた。

| 規則 | 本番の裁定 | `stalemate_or_mate`の判定 |
|---|---|---|
| `L0,P0,R1,E2` | 反復による引き分け | 詰みによる先手の負け |
| `L0,P0,R1,E0` | 反復による引き分け | 詰みによる先手の負け |

例3は、駒枯れによる勝ち（E0）と、勝つ側の詰みの組である。
先手の王将を(0,11)、香車を(0,10)、歩兵を(1,11)と(2,9)に、後手の玉将を(1,10)に置き、後手番で、後手の玉将が(2,9)の歩兵を取る手を指した。
着手の後は先手番で、先手の王将は王手を受けていなかった。
`stalemate_or_mate`の判定が合法手なしではなく詰みだったので、先手には合法手がある。
盤の上では、その手は王将が(1,10)へ進む1手であり、その升は後手の玉将の利きの中にある。

| 規則 | 本番の裁定 | `stalemate_or_mate`の判定 |
|---|---|---|
| `L0,P0,R1,E0` | 駒枯れによる先手の勝ち | 詰みによる先手の負け |
| `L0,P0,R1,E2` | 詰みによる後手の勝ち | 詰みによる先手の負け |
| `L0,P0,R1,E3` | 裸玉による先手の勝ち | 詰みによる先手の負け |

例4は、死に駒を除いて双方が王駒だけになった引き分けと、R2の禁止による合法手なしの組である。
先手の王将を(0,10)、歩兵を(1,11)に、後手の玉将を(0,9)に置き、後手番から9手を進めた。
手順は、後手の玉将(0,9)から(1,9)、先手の王将(0,10)から(0,9)、後手の玉将(1,9)から(0,8)、先手の王将(0,9)から(1,9)、後手の玉将(0,8)から(0,9)、先手の王将(1,9)から(1,10)、後手の玉将(0,9)から(0,10)、先手の王将(1,10)から(0,11)、後手の玉将(0,10)から(0,9)である。
9手目の後は先手番で、先手の王将は王手を受けていなかった。
(1,11)の歩兵は最奥段で移動不能であり、王将の移動先の1つを塞ぐ。
残る2つの移動先は、どちらも既出の局面を再現する。
この試験は9手の着手を審判の層の関数で進めており、各着手がR2の禁止に当たらないことは`Game::play`では確かめていない。

| 規則 | 本番の裁定 | `stalemate_or_mate`の判定 |
|---|---|---|
| `L0,P0,R2,E0` | 駒枯れの規定による引き分け | 合法手なしによる先手の負け |
| `L0,P0,R2,E3` | 裸玉の規定による引き分け | 合法手なしによる先手の負け |
| `L0,P0,R2,E2` | 合法手なしによる後手の勝ち | 合法手なしによる先手の負け |

### 詰みが王手を要件とするか（第21条第3項）

例3の局面は、着手の後の先手の王将が王手を受けていない。
先手には合法手があるが、その手の後に王将を取られ得る。
駒枯れを採用しない`L0,P0,R1,E2`で、本番はこの局面を詰みによる後手の勝ちと裁定した。

## 結論

5つの箇所のすべてで、本番は一方の読みを一貫して実装しており、終局条件の優先順位は4つの例で、後の順位の条件を先に適用した場合と異なる勝敗を与えた。

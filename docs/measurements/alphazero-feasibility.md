# AlphaZero型探索の実現性の実測（フェーズ0）

## 目的

[AlphaZero型探索と深層強化学習](../plans/alphazero.md)のフェーズ0として、作業機と候補のレンタル機で、ネットの推論速度、1シミュレーションあたりのCPUの費用、既存の自己対局の対局長と合法手数の分布、および教師生成の速度を測り、強化学習の1サイクルの所要時間と費用を一次見積もりする。本記録は項目ごとに測れた時点で書き足し、未測定の項目は「未測定」と明記する。

## 環境

作業機は、CPUがIntel Core Ultra 7 265KF（20コア、ハイパースレッディングなし）、メモリ30 GiB、GPUがNVIDIA GeForce RTX 3060 Ti（8 GiB、ドライバ615.71.09）、CUDA 13.4、Linux 6.18.53である。
2026年10月8日時点でNVIDIA Container Toolkitは導入されておらず、コンテナイメージの中でのGPUの実測は導入後に行う。
レンタル機の環境は、借りた時点でここに書く。

## 第3項　対局長と合法手数の分布

### 生成記録から読める値

2026年10月3日に生成した教師（`data/gen3/generate-1100000.log` から `generate-1500000.log` までの5件、コミット44ae7cb、10万ノード、乱択手なし、手数上限4,000）の集計行は次のとおりである。

| 項目 | 値 |
|---|---|
| 対局数 | 37,500 |
| 手数上限4,000に達して除いた対局 | 1,194（3.2%） |
| 平均手数（上限に達した対局を含む） | 603〜628 |
| 詰みによる終局 | 32,466（86.6%） |
| 反復による勝敗 | 2,396 |
| 反復による引き分け | 1,264 |
| 駒枯れによる勝敗と引き分け | 70 |
| 王駒の捕獲 | 110 |

手数上限4,000に達した対局が3.2%あるので、対局長の99パーセンタイルは4,000以上である。
設計書は、強化学習の手数の上限を「対局長の分布の99パーセンタイル以上」と定めているが、この分布ではその規則が上限を4,000以上に置くことになり、上限に達した対局を学習から除く設計と合わせると、生成時間の相当な割合を除かれる対局に費やすことになる。
ヒストグラムとパーセンタイルの詳細は、下の「分布の計測」で確定し、上限の決め方は設計書の改訂で扱う。

### 分布の計測

同じ5件の教師データ（`data/gen3/generated-1100000.bin` から `generated-1500000.bin`、計15,150,946局面）を、使い捨ての集計ツール（scratchpadに置き、リポジトリには入れない）で数えた。
対局長は、ファイルと対局番号の組ごとに記録された最大の手数であり、MNSDが戦術的な局面と詰みの帯の局面を記録しないため、実際の対局長の下界である。
手数上限に達して除かれた1,194局は教師データに含まれないので、この分布にも含まれない。

| 対局長（下界） | 値 |
|---|---|
| 局数 | 36,195 |
| 平均 | 499 |
| 50パーセンタイル | 414 |
| 90パーセンタイル | 708 |
| 95パーセンタイル | 989 |
| 99パーセンタイル | 2,633 |
| 99.9パーセンタイル | 3,810 |
| 最大 | 3,989 |

分布は300〜450手に山があり、1,000手を超える裾が全体の約5%、上限到達の3.2%を合わせると約8%の対局が1,000手を超える。
2,000手の対局1局は400手の対局5局分の生成時間を使うので、上限の置き方が生成の費用に直接響く。

合法手数は20件ごとに1件を抽出した757,548局面について、規則セット`engine-default`で数えた。

| 合法手数 | 値 |
|---|---|
| 平均 | 73.6 |
| 50パーセンタイル | 76 |
| 90パーセンタイル | 109 |
| 99パーセンタイル | 133 |
| 最大 | 207 |

設計書の「中将棋の合法手は1局面で100手を超えることが多い」と「合法手が平均300手」という見積もりはどちらも過大であり、平均は約74手、100手を超える局面は約18%である。
MNZTの1局面は、方策の組4バイト×74手に局面の表168バイトを加えて約0.5 KBになり、RLの1サイクル100万局面で約0.5 GB、100サイクルで約50 GBとなる（設計書の見積もり130 GBの約4割）。
Gumbel方式の候補数m＝16は、平均74手の約2割に当たる。

## 第4項　教師生成の速度

現行の生成器の速度は、新たに測らず、2026年10月3日の生成記録で確定する。
`data/gen3/generate-1500000.log`（コミット44ae7cb、`minase data selfplay generate`、10万ノード、同時対局数16、置換表16 MB、規則`L0,P0,R1,E0`）の`searched_positions_per_second`は369.97であり、同じ条件の5件の記録では311〜370の範囲にある。
教師5,000万局面の生成には、毎秒370局面で約37.5時間（約1.6日）、毎秒311局面なら約44.7時間（約1.9日）を要する。
設計書の見込み（約1.3日）より長く、同時対局数を19に上げてもCPUの物理コア数（20）の制約から1.4日程度が下限である。

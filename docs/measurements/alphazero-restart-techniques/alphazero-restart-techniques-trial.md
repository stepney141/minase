# 新しい構成の試走

## 目的

[学習技法の導入の設計書](../../plans/archived/alphazero-restart-techniques.md)のフェーズ5として、Colab機のL4で新しい構成の1サイクル（生成、読み込み、学習、照合）を実行器で回し、各処理の時間とColabの計算単位（CU）の消費を測る。
この値で、[強化学習の実行の設計書](../../plans/alphazero-rl.md)の1サイクルの所要時間と費用の見積もりを直す。

## コマンドライン

測定日は2026年10月31日である。
作業機で[launch-trial.sh](alphazero-restart-techniques-trial/launch-trial.sh)を次のように起動した。

```console
nohup setsid bash launch-trial.sh rl-trial-r1 9a66eaaa086a00b21a529e9f67155eaf4bdc26a1 \
  > /mnt/synology_nas/minase/alphazero/logs/launch-rl-trial-r1.log 2>&1 < /dev/null &
```

`launch-trial.sh`は、Colab機のL4を1台借りて導入を済ませ、学習器の実行器`minase_zero run-cycles`で、本線の`cycles/`とは別の系列`trial-restart`のサイクル1を回し、終了コードによらず機械を止める。
実行器の引数は、本線と同じく1サイクルの訓練局面100万、塊20、完全探索32回、4スレッド×128局、バッチ256、学習率0.01でcosine annealing、bf16、および学習窓4,780.2万局面（パラメータ数4,780,200の10倍）とし、重みの移動平均は無効にした。
サイクル1の対局数は、[作業機の再開の確認](alphazero-restart-techniques-resume-check.md)の1,024局の集計（訓練局面19,103、1局あたり約18.7局面）から、実行器が100万局面に届く数として53,605局と決めた。
別系列の生成のシードは、実行器の規則（サイクル番号×10⁹＋7×10⁸）で1,700,000,000となり、共有の台帳に`trial-restart-0001-gen`として登録された。

## エンジン

生成器、学習器、および実行器は、ブランチ`alphazero-restart-techniques`のコミット9a66eaaaの書庫をColab機で展開してビルドした。
初期のネットには、[ランダム初期化のネットの出力の照合](alphazero-restart-techniques-random-net-output-check.md)のシード20261031のネット（SHA-256 `b2de222c…7c48`）を使い、NASの`trial-restart/cycle-0000/`に置いた。
規則セットは`engine-default`（L0＋P0＋R1＋E0）、投了は無効（最初のサイクルなので較正の前）である。

## 環境

Colab機のL4（GPUはNVIDIA L4、CPUはIntel Xeon 2.20 GHzの6コア12スレッド、メモリ52 GB）を、2026年10月31日12時52分から13時51分（日本時間）まで借りた（セッション名`rl-trial-r1`）。

## 結果

### 時間と費用

| 処理 | 時間 | 設計書の見積もり |
|---|---|---|
| 導入（借りてから実行器の起動まで） | 約3.6分 | ― |
| 生成 | 2,032秒（33.9分） | 約2,030秒 |
| 学習の工程（読み込み、更新、診断、書き出し、転送を含む） | 1,186秒（19.8分） | ― |
| 　うち読み込み | 27.5秒 | 約630秒（窓が満ちたとき） |
| 　うち更新 | 1,063秒（毎秒3,637標本） | 約570秒 |
| 　うち診断 | 22.5秒 | ― |
| 照合 | 89秒 | 174秒 |
| サイクル全体（実行器の区間） | 55.7分 | 約57分 |
| セッション全体 | 59.4分 | ― |

CUの残高は、借りる前の318.83から止めた後の317.07へ1.76減った（[借用の記録](alphazero-restart-techniques-trial/rentals.jsonl)、[区間の記録](alphazero-restart-techniques-trial/sessions.jsonl)）。
実行器が記録したサイクルの区間の残高の差も1.76であり、残高の更新の粒度のため、導入の分と区別できない。

### 生成

[生成の集計](alphazero-restart-techniques-trial/selfplay-summary.json)は、53,605局、4,718,188手を記録した。
このうち探索した手番は、完全探索が1,019,332、速い探索が3,055,447であり、残る643,409手は序盤の乱択の手である。
探索した手番に占める完全探索の割合は0.250であり、訓練局面の数は完全探索の手番の数と同じ1,019,332であった。
53,558局（99.9%）が王手限定の3手以内の勝ちによる打ち切り（MNSDの終局理由12）で終わり、46局が王駒の捕獲、1局が詰みで終わった。
手数の上限による打ち切りと投了はなかった。
1局の手数は平均88.0、中央値72、99パーセンタイル292であった。
ランダム初期化のネットは王駒を守らないので、ほとんどの対局が打ち切りで終わり、学習が進んだネットとは対局の長さと終局の内訳が異なる。

生成した教師データは20塊の40ファイルで94.5 MBであり、訓練局面あたり約93バイトであった。

### 学習と照合

学習は、窓がこのサイクルだけで、窓の訓練局面数Tが最新のサイクルの訓練局面数Nに等しいので、検証用に分けた対局の53,072局面を除いた訓練局面966,260の4倍の3,865,040標本を、15,098回の更新で学んだ（[学習の集計](alphazero-restart-techniques-trial/train-summary.json)）。
ウォームアップの累計標本数は終了時に3,865,040であり、200万標本のウォームアップを超えた。
読み込みの最大常駐メモリは5.28 GBであった。
最終の重みでの対局結果に対する価値の損失は、訓練の標本で0.629、検証集合で0.659であった。

照合では、学習したネットについて、PyTorchの出力を基準に、ONNX RuntimeのCPUとTensorRTのFP16のバッチ1、7、256の6通りを比べ、すべて許容誤差に収まった。
CPUのlogitの差は最大8.05×10⁻⁶、TensorRTのFP16の合法手の確率の差は最大1.02×10⁻³、価値の差は最大2.95×10⁻³であった（[サイクルの記録](alphazero-restart-techniques-trial/cycle-record.json)）。
サイクルの記録は、実行器がNASの`trial-restart.jsonl`に書いた行から、学習の集計と重複する`training_summary`の欄を除いたものである。

### 窓が満ちたときの見積もり

試走の窓は1サイクルだけなので、読み込みの時間は窓が満ちたときより短く、メモリも少ない。
読み込みの時間は窓の全手番の再生に比例し、試走では1秒あたり約17万手であった。
窓が満ちると訓練局面は4,780.2万、1訓練局面あたりの手番は4.1〜4.6（試走は序盤の乱択の手を含めて4.63）になるので、約2.0億〜2.2億手を約19〜22分で読み込む見込みである。
読み込みのメモリは重複を除いた抽出の数に比例し、窓が満ちると約390万局面（試走の約4倍）になるので、約21 GBと見込む。
更新は、1サイクルの訓練局面が試走と同じ約102万なら、その4倍の約408万標本で約19分になる。
これらを合わせると、窓が満ちた後の1サイクルは、生成約34分、読み込み約19〜22分、更新約19分、および照合などの約2分を合わせて、約74〜77分になる。
試走の消費は1時間あたり約1.8 CUなので、1サイクルは約2.2〜2.3 CUになる。

生成の時間は、ネットの評価の回数が1訓練局面あたり一定なので、学習が進んでも大きくは変わらないと見込む。
ただし、3手以内の勝ちの判定の時間は王手の多い中盤の局面で増える（[判定の時間の測定](alphazero-restart-techniques-mate3-cost.md)）ので、対局が長くなった後のサイクルで測り直す。
教師データの大きさも、方策の候補の数と1局の手数で変わるので、学習が進んだサイクルの値で窓の転送の時間を見積もり直す。

## 結論

新しい構成の1サイクルは、試走（窓は1サイクル）で55.7分、1.76 CUであった。
生成の時間は見積もりどおりだったが、更新は、補助ヘッドの追加と価値ヘッドの拡張により、見積もりの約1.9倍の1,063秒かかった。
窓が満ちた後の1サイクルは約74〜77分、約2.2〜2.3 CUと見込む。

# 2回目の強化学習の最初のセッション（サイクル1〜3）

## 目的

2回目の強化学習の本線の系列`cycles-rl2-az`のサイクル1〜3を回し、[設計書](../../plans/alphazero-rl-2.md)のフェーズ2の4点を確かめる。
4点は、生成した教師データのヘッダの規則セットが`lishogi`であること、1サイクルの時間と料金と対局数と1局の手数を記録してサイクル4〜10の費用を見積もり直すこと、検証用の対局での対局結果に対する価値の損失がサイクル3で0.693を下回ること、および、サイクル3のネットが探索なしで乱択のエンジンに勝ち越し、1手800シミュレーションの対局で初期ネットに勝ち越すことである。
あわせて、実行器が書いた系列の記録から、道具`series_progress.py`で`cycles.csv`と進捗図が作れることを確かめる（[学習の系列の記録と進捗図の設計書](../../plans/training-series-records.md)のフェーズ4）。

## コマンドライン

サイクルは、vast.aiの機械を借りる起動スクリプト[launch-vast.py](alphazero-rl-2-sessions/launch-vast.py)で回した。
作業機のブランチ`alphazero-rl-2`の作業ツリーの根で、bashから次のように起動した。
`$A`はNASの`/mnt/synology_nas/minase/alphazero`、`$W`は作業機の作業ツリー、`$C`は送ったコミット、`$L`はセッションのラベルである。

```bash
nohup setsid python3 docs/measurements/alphazero-rl-2/alphazero-rl-2-sessions/launch-vast.py \
  --offer 56262265 --label minase-$L --image nvidia/cuda:13.0.3-base-ubuntu24.04 \
  --hours 3.5 --commit $C --root $A --salvage-dir $A/salvage \
  -- --cycles-dir cycles-rl2-az --base-cycles-dir cycles-rl2-az --branch-from 0 \
  --cycle1-reference-summary $A/transfer-vast/cycle-0001/selfplay/summary.json \
  --generation-commit $C --trainer-commit $C \
  --first-cycle 1 --last-cycle 3 --cycle-minutes 35 \
  --start-position initial --generation-seed-offset 300000000 \
  --target-positions 1000000 --chunks 20 --simulations 32 --threads-per-gpu 4 --games-per-thread 128 \
  --replay-buffer-games 1500000 \
  --batch-size 1024 --lr 0.04 --momentum 0.9 --weight-decay 0.0001 --clip-grad-norm 10 \
  --value-lambda 0.333 --precision bf16 --checkpoint-steps 50 \
  --train-seed-base 20261100 --minase $W/target/release/minase --poll-seconds 60 \
  > $A/logs/runner-$L.log 2>&1 < /dev/null &
```

セッションは2回に分かれた。
1回目は`$C`がコミット`3fb311f9`、`$L`が`rl2-c0001-0003`であり、サイクル1で学習したネットの照合で止まった（「経過」の節）。
2回目は、照合の許容誤差を改めたコミット`8e419486`を`$C`とし、`$L`を`rl2-c0001-0003-resume`として、同じ引数で起動し直した。

サイクル3の後の対局は、定例の測定用にMCTSを固定した作業ツリー`data/worktrees/alphazero-rl-2-routine`（コミット`8e419486`、以下`$R`）のスクリプトとハーネスで、本体のリポジトリの根から行った。

```bash
source $R/tools/train/zero/env.sh
export XDG_CACHE_HOME=$HOME/.cache
M=8e419486e7cf5c93bbefb4f856bc203f2213cd21
S=$R/docs/measurements/alphazero-rl-2/alphazero-rl-2-routine-scripts
python3 -I $S/run_rl2_match.py random --harness $R/target/release/minase --mcts-commit $M \
  --net $A/nets/cycles-rl2-az/cycle-0003.onnx --name alphazero-rl-2-first-c0003-random --seed 2026111611 --pairs 20
python3 -I $S/run_rl2_match.py versus --harness $R/target/release/minase --mcts-commit $M \
  --net $A/nets/cycles-rl2-az/cycle-0003.onnx --baseline-net $A/cycles-rl2-az/cycle-0000/model.onnx \
  --name alphazero-rl-2-first-c0003-versus --seed 2026111612 --pairs 20
```

固定の検証用データの診断は、作業ツリー`$W`の`tools/train/zero`で、サイクルごとに次のように行った。

```bash
uv run --frozen python -m minase_zero external-eval --checkpoint $A/cycles-rl2-az/cycle-NNNN/train/checkpoint.pt \
  --data $A/validation/zero-validation-games.mnsd --device cuda \
  --out $W/docs/training/alphazero-rl-2/validation/cycle-NNNN.json
```

## エンジン

生成器と学習器のコミットは、1回目のセッション（サイクル1の生成と学習）が`3fb311f9`、2回目のセッション（サイクル1の照合とサイクル2〜3）が`8e419486`である。
2つのコミットの間の変更は、TensorRTのFP16の照合の許容誤差、文書、および起動スクリプトのdocstringだけであり、Rustのコードと学習器の計算は同じである。
初期ネットはNASの`cycles-rl2-az/cycle-0000/model.onnx`（SHA-256 `4b430a44…`）である。
対局のMCTSは、作業ツリー`$R`の`minase`に`--search mcts`を指定したものであり、`NnBatchSize`は16、推論はTensorRTのFP16である。

## 環境

サイクルは、vast.aiのRTX 4090を4枚積んだ機械（カナダのケベック州、machine 154269、Intel Xeon Platinum 8352V、使えるCPUは69個、ドライバ580.178.04）で回した。
出品は56262265で、料金はディスクの保管料を含めて1時間1.904米ドルであった。
1回目のセッションはインスタンス60892045、2回目はインスタンス60895953であり、どちらも同じ機械である。
コンテナのイメージは`nvidia/cuda:13.0.3-base-ubuntu24.04`である。

サイクル3の後の対局と診断は、作業機（Intel Core Ultra 7 265KF、20コア20スレッド、NVIDIA GeForce RTX 3060 Ti 8 GB）で2026年11月16日に行った。
対局はシミュレーション回数で制限したので、結果は負荷の影響を受けない。

## 経過

2026年11月16日15時58分（日本時間、以下同じ）に1回目のセッションを起動した。
環境の導入は約5分で終わり、生成前の照合では、初期ネットをこの機械のONNX RuntimeのCPUとTensorRTのFP16で読ませた出力を作業機のPyTorchの出力と比べ、6つの組（CPUとFP16のそれぞれバッチの大きさ1、7、256）とも合格した（49秒）。
差の最大は、CPUで合法手のlogitが3.04×10⁻⁵、価値が8.87×10⁻⁸、FP16で合法手の確率が1.28×10⁻⁵、価値が2.51×10⁻⁴であった。

サイクル1の生成と学習は終わったが、学習したネットのTensorRTのFP16の照合で、合法手の確率の差の最大がバッチの大きさ1で0.0121、256で0.0123となり、当時の許容誤差1×10⁻²を超えて実行器が止まった。
CPUの照合は合格し、層の出力に飽和も桁落ちもなかったので、利用者の決定で確率の許容誤差を5×10⁻²に改めた（[ADR](../../adr/compare-fp16-zero-network-probabilities-and-values-within-five-hundredths.md)）。
起動スクリプトは、NASにないファイルの受け取りを終えてから、16時22分にインスタンスを削除した。

照合の出力を`cycles-rl2-az/cycle-0001/rejected-fp16-tolerance/`へ移し、生成と学習の出力は残したまま、16時40分に2回目のセッションを起動した。
照合の最初の段では、チェックポイントからONNXを書き出し直し、学習したときのONNXとバイト単位で比べる。
この一致は同じCPUの機械でしか成り立たないので、1回目と同じ機械の出品を借りた。
実行器はサイクル1の照合だけをやり直して合格し、続けてサイクル2と3を回して17時31分に正常に終わった。
起動スクリプトは、NASにないファイルを受け取って検査和を照合してから、インスタンスを削除した。

系列の記録`cycles-rl2-az.jsonl`のサイクル1の行では、`machine`と`interval`の欄が2回目のセッションのインスタンス60895953を指し、`trainer_commit`の欄が再開のコミット`8e419486`を指す。
実際にサイクル1を生成し学習したのはインスタンス60892045とコミット`3fb311f9`であり、実際のコミットは生成の集計の`generation_commit`と、学習の集計の`provenance.trainer_commit`に残っている。

## 結果

### 教師データの規則

サイクル1〜3の学習に使った32個の教師データのファイルは、どれもヘッダの規則セットが`L1,L2,P0,P3,R1,E1,E3`（`lishogi`）であった。

### 対局と学習

| サイクル | 対局数 | 訓練局面 | 1局の手数 | 千日手の引き分け | 手数の上限に達した対局 | 検証の価値の損失 | 訓練の標本の価値の損失 | 人間の棋譜の価値の損失 | 人間の手との一致率 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 9,527 | 1,028,294 | 107.9 | 0 | 0 | 0.732 | 0.549 | 0.749 | 1.38% |
| 2 | 2,320 | 1,090,730 | 470.1 | 14 | 3 | 0.781 | 0.490 | 0.773 | 1.61% |
| 3 | 2,128 | 956,990 | 449.7 | 89 | 4 | 0.593 | 0.413 | 0.755 | 1.99% |

検証の価値の損失は、そのサイクルの自己対局のうち学習に使わなかった対局での、対局結果に対する価値の損失である。
人間の棋譜の値は、固定の検証用データ（lishogiの人間同士の棋譜811局、164,504局面）での診断である。
同じデータでは、ランダムに初期化したネット（1回目の学習のサイクル0と、2回目の学習の以前の初期ネット）の価値の損失が0.693、一致率が0.96%と0.77%であり、1回目の学習のサイクル10は0.685と3.32%であった（[基準の記録](../zero-validation-games/zero-validation-games-baseline.md)）。
投了の閾値は3サイクルとも0であり、投了で終わった対局はなかった。
サイクル1は全局が、王手と王駒の捕獲だけで3手以内に勝ちを強制できる局面での打ち切りで終わった。
サイクル2と3では、その打ち切りが1,604局と1,190局、裸玉の勝ちが698局と840局であった。

TensorRTのFP16の照合の合法手の確率の差の最大は、サイクル1〜3で0.0123、0.0116、0.0181であり、新しい許容誤差5×10⁻²に収まった。
サイクル1の同じネットでも、照合をやり直すとバッチの大きさ7の差が0.0044から0.0105に変わった。TensorRTのエンジンを作るたびに選ばれる計算の方法が変わるからとみられる。
作業機（RTX 3060 Ti）でのサイクル1のネットの照合も6つの組とも合格し、FP16の確率の差の最大は0.0121、価値の差の最大は0.0045であった。

### 時間と料金

| サイクル | 生成 | 学習 | 照合 | 生成器が作った局面 | 学習に入った割合 |
|---|---|---|---|---|---|
| 1 | 560秒 | 236秒 | 146秒 | 1,632,287 | 63% |
| 2 | 1,209秒 | 218秒 | 146秒 | 4,026,084 | 27% |
| 3 | 478秒 | 218秒 | 146秒 | 956,990 | 100% |

工程の時間は実行器の記録の`elapsed_seconds`であり、受け取りの時間を含む。
サイクル1の照合はやり直した2回目の値である。
サイクルの開始から次のサイクルの開始までは、サイクル2が26.5分、サイクル3が14.3分であった。
生成器が作った局面は、終わった対局の局面の数であり、学習に入った割合は、そのうちサイクルに含めた訓練局面の割合である。

生成器は、前のサイクルの1局あたりの訓練局面数から見積もった対局数の上限を20個の塊に分け、塊ごとに対局番号順に確定させ、先頭からの訓練局面の累計が目標の100万に届いた塊でサイクルを締める。
塊は、その塊のすべての対局が終わるまで確定しないので、1局が長くなると、先頭の塊の中の長い対局が終わる前に、後ろの番号の対局が次々に始まって終わる。
サイクル2では、1局の手数がサイクル1の107.9手から470.1手へ約4.4倍に延び、先頭の5つの塊（2,320局）で目標に届いたが、それらの塊がそろう前に、上限の9,265局のほぼ全局を指し終えていた。
学習に入らなかった約294万局面の分だけ、生成が長くなった。
サイクル3では逆に1局がわずかに短くなり、上限の2,128局をすべて含めても目標に4.3%届かなかった。
1局の手数の変化が小さいサイクルの時間は、サイクル3の約14分が目安になる。

1回目のセッションは作成から削除まで24.4分、2回目は51.1分であり、料金はそれぞれ約0.77米ドルと約1.62米ドルである。
vast.aiの口座の残高は、2回の借用で61.93米ドルから59.43米ドルへ2.50米ドル減った。
導入は2回とも約5分、生成前の照合は約1.5分であった。

## 系列の記録の道具

実行器の系列の記録`$A/cycles-rl2-az.jsonl`を`series_progress.py`の`collect --cycles-record`に渡すと、3行25列の`cycles.csv`ができた。
各列を、道具のdocstringの対応表に従って記録の欄から別に計算した値と比べ、不一致は0件であった。
続けて`plot`に1回目の強化学習の系列を参照として渡すと、6つのパネルの進捗図が描けた。
強さのパネルは、まだ測っていないので空であった。
確認はリポジトリの外の一時ディレクトリで行い、系列のページは最初の定例の測定で作る。

## サイクル3のネットの対局

どちらの対局も、規則セット`lishogi`、手数の上限4,096手、同時対局数2で、先後を入れ替えた2局を1ペアとして20ペアを指した。
ペンタノミアル度数は、サイクル3のネットから見たペアの得点（0、0.5、1、1.5、2）ごとのペア数である。

| 対局 | サイクル3のネットの条件 | 相手 | ペンタノミアル度数 | 終局 | 手数の中央値（最小〜最大） | 実行時間 |
|---|---|---|---|---|---|---|
| `random` | 1手1シミュレーション（探索なし） | 乱択のエンジン | [0, 0, 0, 0, 20] | 王駒の捕獲40局 | 71.5手（16〜211手） | 28.1秒 |
| `versus` | 1手800シミュレーション | 初期ネットの1手800シミュレーション | [0, 0, 0, 0, 20] | 王駒の捕獲23局、裸玉17局 | 245手（29〜545手） | 17.8分 |

サイクル3のネットは、どちらの対局でも40局すべてに勝った。
エンジンの異常終了と時間切れは0件であった。
実行時間はハーネスの`summary.json`の`active_wall_time_ns`である。
2つの対局の実行ディレクトリは、本体のリポジトリの`data/matches/<測定名>.tar.zst`へ圧縮して残した。

## 結論

フェーズ2の4点はすべて満たした。
教師データのヘッダの規則は`lishogi`であり、検証用の対局での価値の損失はサイクル3で0.593となって0.693を下回り、サイクル3のネットは乱択のエンジンにも初期ネットにも全勝した。
1サイクルの時間は、1局の手数がほぼ変わらないサイクル3で14.3分、手数が約4.4倍に延びたサイクル2で26.5分であった。

この値から、サイクル4〜10の7サイクルは、1サイクル14〜27分として100〜186分、導入と生成前の照合と受け取りを加えて約1.8〜3.2時間と見込む。
料金は、今回の出品の1時間1.904米ドルで約3.4〜6.1米ドルになる（推論）。
手数が大きく延びるサイクルでは、対局数の上限が前のサイクルの1局の手数から見積もられるので、学習に入らない局面の生成が増え、時間が延びる。

一方で、自己対局の検証用の対局での価値の損失は、サイクル1と2で0.693を上回り、訓練の標本との差が0.18〜0.29あった。
人間の棋譜での価値の損失も3サイクルとも0.693を上回っており、学習の初めのネットの勝敗の予測は、自己対局の外の局面ではまだ五分の予測より悪い。
TensorRTのFP16の確率の差の最大はサイクル3で0.0181になり、サイクル1の0.0123より大きいので、許容誤差5×10⁻²との距離を以後のサイクルでも見る。

# 自己対局が1,000手の上限に達する原因の調査

## 目的

強化学習の本線のサイクル6〜8で、自己対局が手数の上限1,000手に達して捨てられる割合が5.5%から17.0%に増えたので、上限に達する対局がどう進み、上限を外すとどう終わるかを調べ、上限の扱いを決める材料にする。

## コマンドライン

調査は2段階で行った。
第1段階では、本線のサイクル6と8の学習データ（投了以外で終えた対局のファイル）を読み、対局の長さごとに、駒数、取り合いの間隔、評価値、および同じ局面の再現を集計した。
第2段階では、生成器の手数の上限だけを3,000手に変えた検証用の一時的なビルドで、サイクル8の学習を終えたネットに400局を指させ、1,000手を超えた対局を最後まで追った。
このビルドの変更は、`crates/minase/src/bin/minase/zero_selfplay/mod.rs`の定数`MAX_PLY`を`1_000`から`3_000`にした1行だけであり、コミットしていない。
集計のスクリプトと起動スクリプトは、本記録と同じ名前のディレクトリ`alphazero-rl-long-games/`にある。
起動スクリプトの出力先と生成器のパスは、作業機の一時ディレクトリのものである。

```console
# 第1段階（学習器の環境の上で実行する）
uv run --frozen --project tools/train/zero python long_games.py \
  /mnt/synology_nas/minase/alphazero/cycles/cycle-0006 /mnt/synology_nas/minase/alphazero/cycles/cycle-0008
uv run --frozen --project tools/train/zero python long_trend.py /mnt/synology_nas/minase/alphazero/cycles/cycle-0008

# 第2段階（tools/train/zero/env.shを読み込んで実行する）
minase data zero-selfplay --output-dir <出力先> \
  --nn-model /mnt/synology_nas/minase/alphazero/cycles/cycle-0008/train/model.onnx --nn-backend tensorrt \
  --generation-commit ac2b3f3e0b6d3eeff6cf6cd21d7ddfe9be9b1dd2 --seed 900000000000 --games 400 --chunk-games 50 \
  --target-positions 1000000000 --simulations 32 --playthrough-percent 100 --threads 4 --games-per-thread 64
uv run --frozen --project tools/train/zero python diag_long.py <出力先を selfplay/ として置いたディレクトリ>
```

第2段階の基本シード9×10¹¹の対局番号1〜400は、シードの台帳に`diag-maxply3000-c0008-gen`として登録した。

## エンジン

第1段階のデータ（サイクル6と8）は、局面数の目標による締めを入れた本線の生成器（コミットf8eac7e9）が生成した。
第2段階の生成器は、masterのコミットac2b3f3eに上記の1行の変更を加えたものである。
規則は`engine-default`（`L0,P0,R1,E0`）、探索はGumbel AlphaZeroの1手32回（確率0.25の完全探索。それ以外の手番は8回）で、投了は無効にした。
ネットは本線のサイクル8の学習を終えたもの（SHA-256 `d41e98ca…d119`）であり、本線ではサイクル9の生成に使った。

## 環境

第2段階は作業機で実行した。
CPUはIntel Core Ultra 7 265KF（20コア20スレッド）、GPUはNVIDIA GeForce RTX 3060 Ti（8 GB）であり、推論はTensorRTのFP16で行った。
生成のスレッドは4、スレッドごとの同時対局数は64であった。
本線のColab機のL4とは推論の数値がわずかに異なるので、対局の内容は本線と同じにはならない。

## 結果

本線のサイクル6〜8では、手数の上限で捨てた対局と、その対局に費やした着手の割合が次のように増えた。

| サイクル | 対局数 | 捨てた対局 | 捨てた対局の着手の割合 |
|---|---|---|---|
| 6 | 8,528 | 469（5.50%） | 10.0% |
| 7 | 8,307 | 951（11.45%） | 18.7% |
| 8 | 8,232 | 1,401（17.02%） | 27.2% |

第1段階では、サイクル8の学習データに残った6,483局のうち、800手以上の1,143局が次のように進んだ。
駒数の中央値は、100手目に82枚、400手目に40枚、600手目に29枚、800手目に23枚であった。
取った駒の数の中央値は、400〜600手目に100手あたり5.5枚、600〜800手目に2.5枚であった。
600手目で評価値が有利な側（手番によらず先手の勝率に直した値が0.5から0.1より大きく離れた側）は、勝敗がついた対局の86.0%（781局中）で勝ち、駒数が多い側は77.1%（851局中）で勝った。
サイクル6でも、長さの帯ごとの駒数と評価値の傾向は同じであった。

第2段階の400局は158.8秒で終わった。
投了以外で終えた397局の平均は669手であり、1,000手を超えた対局は76局（19.1%）、3,000手に達して捨てた対局は2局（0.5%）であった。
1,000手を超えた76局の長さは、中央値1,262手、90パーセンタイル1,952手、最長2,886手であった。
2,000手に達した対局は、3,000手で捨てた2局を含めて9局（2.3%）であった。
76局のうち50局（66%）は勝敗がつき、26局（34%）は反復による引き分けで終わった。
1,000手の時点の駒数は中央値22枚であり、飛車、角行、龍王、龍馬、奔王、獅子などの強い駒は双方合わせて中央値2枚で、獅子が盤上に残っていた対局は54%であった。
1,000手より後に取った駒の数は、100手あたり中央値0.7枚であった。
勝敗がついた対局のうち、1,000手の時点で評価値が有利だった側の勝ちは89%（45局中）であった。
引き分けになった対局の1,000手の時点の評価値は、0.5からの差が中央値0.16で、勝敗がついた対局を含む全体の中央値0.28より互角に近かった。
1,000手より後に記録した局面のうち、同じ対局の中で同じ局面が再び現れた割合は、対局ごとに0〜5%であった。

## 結論

上限に達する対局は、少ない駒で有利な側が勝ちきれないまま長く続く終盤であり、上限を外すと3分の2は勝敗がつき、その約9割は1,000手の時点で評価値が有利な側の勝ちになるので、上限を3,000手に上げる（[手数の上限のADR](../../adr/discard-zero-self-play-games-that-reach-3000-plies.md)）。

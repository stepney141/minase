# 強化学習の10サイクル目の進捗測定

## 目的

[強化学習の実行の設計書](../../plans/alphazero-rl.md)の「進捗測定」の節に従い、サイクル10のネットとサイクル0（ランダム初期化）のネットを、PUCTの1手800シミュレーションの固定200ペアで比べてEloを記録し、最初の進捗測定で求める2点（探索なしの方策と乱択エンジンの対局、および作業機での3者の出力の照合）で学習が働いていることを確かめる。
あわせて、進捗測定に使う推論のバッチの大きさ`NnBatchSize`を決め、サイクル1〜10の学習の診断と、生成と無関係な固定の検証用棋譜での診断をまとめる。

## コマンドライン

`NnBatchSize`は、`tools/train/zero/feasibility`の`batch_probe`で、固定局面集の288局面、1手800シミュレーションを、上限16、64、256で比べて決めた（[出力](alphazero-rl-progress-c0010/batch-probe.json)）。

```console
batch_probe --nn-model nets/cycle-0010.onnx --backend tensorrt --cache-dir <キャッシュ> \
  --fixture tools/train/zero/fixtures/nn-positions.jsonl --positions 288 --simulations 800 --batch-sizes 16,64,256
```

対局は[progress-workstation.sh](alphazero-rl-progress-c0010/progress-workstation.sh)で、`progress-workstation.sh 0010 0000 16 10010 20010 <出力先>`として行った。
中身は次の3つの`minase match run`である。

```console
minase match run --run-dir c0010-vs-c0000 --seed 10010 \
  --candidate "minase --protocol usi --rules engine-default --search mcts --nn-model nets/cycle-0010.onnx" \
  --baseline "minase --protocol usi --rules engine-default --search mcts --nn-model nets/cycle-0000.onnx" \
  --candidate-option NnBatchSize=16 --baseline-option NnBatchSize=16 --each nodes=800 --concurrency 2 elo --pairs 200
minase match run --run-dir c0010-nodes1-vs-random --seed 20010 \
  --candidate "minase ... --nn-model nets/cycle-0010.onnx" --baseline random \
  --candidate-option NnBatchSize=16 --each nodes=1 --concurrency 2 elo --pairs 100
minase match run --run-dir c0000-nodes1-vs-random --seed 20010 （候補のネットだけをcycle-0000.onnxにしたもの）
```

作業機での3者の出力の照合は[check.sh](alphazero-rl-progress-c0010/check.sh)（価値の許容誤差5×10⁻²）で、固定の検証用棋譜の診断は学習器の`external-eval`で、αβ探索の教師データ`generated-8200000.bin`（SHA-256 `e22a09e6…7d0d`）から、シード20261030で1,000局を選んで行った（[各ネットの出力](alphazero-rl-progress-c0010/external/)）。

## エンジン

`minase`は、ブランチ`alphazero-rl`のworktreeでmasterのコミットd786c5e1と同じ`crates/`からリリースビルドしたものである。
サイクル10のネットは`nets/cycle-0010.onnx`（SHA-256 `6a44415f2645896468b7bb473fd1021fb680708bbd74a3e8a44006d74ae2a676`）、サイクル0のネットは`nets/cycle-0000.onnx`（SHA-256 `641a311e3b9f7b23f5516a3785c2b7c44b5526328924bb269d10f3421b0c06e3`）である。
規則セットは`engine-default`（L0＋P0＋R1＋E0）である。
サイクル1〜5の生成と学習はコミットd786c5e1、サイクル6の学習以後はコミットe66de512の学習器と実行器で行い、サイクル6の生成はd786c5e1、サイクル7以後の生成はe66de512の生成器（生成器のソースはd786c5e1と同じ）である。

## 環境

対局と照合は、作業機（Intel Core Ultra 7 265KF、20コア20スレッド、GPUはRTX 3060 Ti 8 GB、ドライバ615.78.08）で、2026年10月30日9時25分から9時48分に行った。
設計書は進捗測定の対局を借りた機械で行うとするが、シミュレーション回数で制限する対局は結果が機械の速さに依存せず、作業機が空いていたので、借り直しの導入とCUを省くために作業機で行った（Claudeの判断）。
MCTSは`Threads=1`、`USI_Hash`は既定、同時対局数は2である。

## 結果

### NnBatchSize

| 上限 | 1探索の推論の回数 | 衝突 | 葉の深さの平均 | 16との最善手の一致率 | 16との根の訪問の分布の全変動距離 | 288局面の秒数 |
|---|---|---|---|---|---|---|
| 16 | 46.4 | 3.1 | 6.18 | ― | ― | 17.0 |
| 64 | 14.7 | 4.5 | 4.65 | 0.479 | 0.266 | 10.7 |
| 256 | 8.7 | 6.2 | 3.29 | 0.403 | 0.336 | 9.9 |

測定の前に、16を基準として、64と256のうち最善手の一致率が0.9以上かつ全変動距離の平均が0.05以下のものの最大を採り、どれも満たさなければ16とすると決めていた（Claudeの決定）。
64と256はどちらも満たさなかったので、`NnBatchSize`は16とし、以後の進捗測定でも16に固定する。
バッチを大きくすると仮想損失で同じ探索の葉が浅くなり、800シミュレーションの探索の結果が大きく変わった。

### 対局

| 対局 | ペア | ペンタノミアルの度数 | Elo | 平均手数（中央値） | 終局理由 |
|---|---|---|---|---|---|
| サイクル10対サイクル0（800回） | 200 | [0, 0, 0, 0, 200] | +∞ | 55.6（46） | 王駒の捕獲389、詰み11 |
| サイクル10の方策（nodes=1）対乱択 | 100 | [0, 0, 0, 0, 100] | +∞ | 35.7（26） | 王駒の捕獲199、詰み1 |
| サイクル0の方策（nodes=1）対乱択 | 100 | [28, 0, 52, 0, 20] | −27.9［−75.8, +19.1］ | 422.2（337） | 王駒の捕獲138、詰み62 |

3つとも、破棄したペアとエンジンの異常（不正着手、クラッシュ、応答の時間切れ、拒否着手）は0件であった。
経過時間は、800回の200ペアが948秒、nodes=1の100ペアが114秒と305秒であった。
サイクル10は800回の対局の400局すべてに勝ったので、Eloの点推定は無限大であり、1局あたりの期待得点の95%下限（rule of three）は1−3/400＝0.9925である。
探索なしの方策は、サイクル0では乱択と同程度（得点率0.46）だったが、サイクル10では乱択に200局すべてで勝った。

### 作業機での照合

サイクル10のネットは、作業機でも6通りとも合格した。
CPUのlogitの差は最大8×10⁻⁶、TensorRTのFP16の合法手の確率の差は最大6.4×10⁻³、価値の差は最大8.9×10⁻³であった（[ログ](alphazero-rl-progress-c0010/check.log)）。

価値の損失はすべて対局結果に対するもので、最終の重みで求めた。
サイクル1〜5は直近1サイクルの全局面で、サイクル6以後は学習窓から抽出して学んだ。

「所要」は、実行器から見た生成、学習、および照合の経過時間の和である。

## 結論

サイクル10のネットは、800回の探索でランダム初期化のネットに400局すべてで勝ち、探索なしの方策でも乱択に200局すべてで勝ったので、学習は働いている。
学習窓からの抽出を始めたサイクル6以後は、最新のサイクルの訓練の標本と検証集合の価値の損失の差が0.10〜0.20に縮み、生成と無関係なαβの棋譜に対する価値の損失もln 2を下回った。
進捗測定の`NnBatchSize`は16に固定する。

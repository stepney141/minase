# 作業機のGPUでの学習と中断からの再開

## 目的

[学習器の設計書](../../plans/archived/alphazero-trainer.md)のフェーズ2として、作業機のGPUで1サイクル分の学習を行う。
途中で`SIGKILL`により止めて最後のチェックポイントから再開した学習が、中断せずに学習した場合と、読んだ局面の順序、更新回数、および学習したネットで一致することを確かめる。
あわせて、学習の速さと学習曲線を記録する。

## コマンドライン

学習データは[generate.sh](alphazero-trainer-gpu-resume-check/generate.sh)で作った。
`init`でランダムに初期化した10ブロック128チャネルのネット（シード20261028）を作り、そのONNXで1,000局の自己対局を生成した。
実際の生成は、`init`を実装する前に同じ手順（`torch.manual_seed(20261028)`の直後に`ZeroNet(10, 128)`を作ってONNXへ出力する）で作ったネットで行った。
後で`init`が書いたONNXはこれとバイト単位で一致した（SHA-256 `a01d01d4…4168`）ので、generate.shは`init`から始まる手順として書いた。

学習の引数は[run-train.sh](alphazero-trainer-gpu-resume-check/run-train.sh)に固定した。
主な値は、バッチの大きさ256、学習率0.01、モーメンタム0.9、重み減衰1×10⁻⁴、勾配のノルムの上限10、λ=0.333、精度bf16、50更新ごとのチェックポイント、シード20261101である。

```console
bash run-train.sh <data>/train-a          # 止めない学習（A）
bash kill-and-resume.sh                    # 止めて再開する学習（B）
```

[kill-and-resume.sh](alphazero-trainer-gpu-resume-check/kill-and-resume.sh)は、Bを起動し、200回目の更新のチェックポイントを示す行が標準エラーに現れた直後に、uvとそれが起動したPythonの2つのプロセスを`SIGKILL`で止め、`train --resume`で再開する。
借りた機械が予告なく止まる場合に合わせて、終了処理の機会を与えないシグナルを選んだ。
最初の試行では、`pgrep`が2つのプロセスを返したのに`kill`へ1つの引数として渡したため止まらず、Bは最後まで走った。
この試行の出力は捨て、2つのプロセスを止める形でやり直した試行を記録した。

## エンジン

学習器は、ブランチ`alphazero-trainer`のコミットdb2119a8（集計の`trainer_commit`）である。
生成器は、`crates/`がmasterのae6a3723と同一のworktreeからリリースビルドした`minase`であり、教師データの形式MNSDのヘッダに書かれた生成コミットはae6a3723である。
規則セットは`engine-default`（L0＋P0＋R1＋E0）である。
生成の推論は、ONNX Runtime 1.28.3のTensorRTの実行プロバイダ（TensorRT 10.14.1.48、FP16）で行った。

生成器は`nice -n 10`で、2スレッド、スレッドごとの同時対局数64で動かした。

## 結果

### 学習データ

1,000局の自己対局は377秒で終わり、探索した局面は107,600（毎秒286局面）であった（[集計](alphazero-trainer-gpu-resume-check/selfplay-summary.json)、[ログ](alphazero-trainer-gpu-resume-check/selfplay.log)）。
終局の理由は王駒の捕獲が980局、詰みが20局で、先手が494勝、後手が506勝し、引き分けと手数の上限による打ち切りはなかった。
投了は無効にした。
1局あたりの探索した局面は平均107.6であり、1サイクルの100万局面は約9,300局に当たる。

学習窓は、4つの塊の投了以外で終えた対局のファイル（`chunk-0000N.mnsd`）と、0局の投了の対局のファイル（`chunk-0000N.resigned.mnsd`）4つである。
訓練局面は101,819、検証局面は5,781であり、バッチ256で1サイクルの更新は398回になる。

### 学習曲線

Aの50更新ごとの訓練の平均損失は次のとおりである（[集計](alphazero-trainer-gpu-resume-check/summary-a.json)）。
policyは35,856出力に対する方策の交差エントロピー、valueは混合した教師に対する価値の二値交差エントロピー、value_resultは対局結果だけに対する同じ損失である。

| 更新回数 | policy | value | value_result |
|---|---|---|---|
| 50 | 7.032 | 0.691 | 0.689 |
| 100 | 5.315 | 0.680 | 0.670 |
| 150 | 4.962 | 0.646 | 0.605 |
| 200 | 4.861 | 0.595 | 0.497 |
| 250 | 4.780 | 0.559 | 0.418 |
| 300 | 4.738 | 0.540 | 0.374 |
| 350 | 4.689 | 0.529 | 0.351 |
| 398 | 4.676 | 0.517 | 0.326 |

サイクル全体の訓練の平均損失は、policyが5.134、valueが0.595、value_resultが0.492であった。
学習の後の検証集合の平均損失は、policyが4.649、valueが0.813、value_resultが0.798であった。

方策の検証損失は訓練の終盤と同程度であり、方策は対局をまたいで学べている。
一方、対局結果に対する価値の検証損失0.798は、常に0.5を出す場合のln 2（約0.693）より大きく、訓練の終盤の0.326と大きく離れた。
1サイクルの学習では各局面を1回しか読まないが、同じ対局の局面は盤面の大部分を共有するので、先に読んだ局面から対局を見分けて結果を覚えられる。
これは[対局内で一定な教師成分は記憶される](../../lessons/game-constant-target-memorization.md)の教訓が述べる記憶の兆候であり、訓練と検証は同じ経路で損失を計算しているので、検証側だけの誤りでは説明できない。
今回の1,000局は1サイクルの約9分の1であり、ランダムに初期化したネットの対局は結果の予測が難しい。
強化学習の実行では同じ指標をサイクルごとに記録するので、最初のサイクルの値を見て判断する必要がある。

### 学習の速さ

Aの50更新ごとの学習の速さは、最初の区間を除いて毎秒4,630〜4,660局面であった。
サイクル全体では、最初の区間の準備を含めて毎秒4,375局面である。
[実現性の実測](../alphazero-environment/alphazero-feasibility.md)で、作業機の合成データによるbf16、バッチ256の学習は毎秒4,901局面であり、データの準備を含めた本測定の速さはその約95%であった。
学習窓の読み込みとファイルのSHA-256の計算は4.0秒、検証は0.38秒であった。

### 中断と再開

Bは200回目の更新のチェックポイントを確定させた直後に止まった。
チェックポイントには、全398回のうち完了した更新200回と、読んだ訓練局面51,200が記録されていた（[1回目のログ](alphazero-trainer-gpu-resume-check/train-b-run1.log)）。
再開した学習は「resume: completed_steps=200/398」と出力して201回目の更新から続け、最後まで終えた（[2回目のログ](alphazero-trainer-gpu-resume-check/train-b-run2.log)）。

AとBの集計（[A](alphazero-trainer-gpu-resume-check/summary-a.json)、[B](alphazero-trainer-gpu-resume-check/summary-b.json)）は、時間の欄を除くすべての欄で一致した。
一致した欄は、訓練局面数、検証局面数、更新回数398、読んだ訓練局面101,819、`data_order_sha256`（`60483412…74e8e`）、8区間の学習曲線、訓練と検証の平均損失、および`model.onnx`のSHA-256（`45204684…a6bb`）である。
この環境では、GPUの計算も再開の有無によらず同じ値になった。

## 結論

学習器は作業機のGPUで、合成データの約95%の速さで1サイクル分を学習した。
途中で`SIGKILL`により止めて再開した学習は、止めない学習と、読んだ局面の順序、更新回数、損失、および出力したネットのバイト列まで一致した。
1,000局の学習では、対局結果に対する価値の検証損失がln 2を上回る記憶の兆候が出た。

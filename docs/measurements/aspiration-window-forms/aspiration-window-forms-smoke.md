# aspiration windowsの形の変更の候補の事前対局

## 目的

[aspiration windowsの幅と窓の移し方の見直しの設計書](../../plans/archived/aspiration-window-forms.md)のフェーズ4として、SPSAの最終値を反映した候補がSTCの条件で時間切れやエンジン異常を起こさないことを確かめ、時間の使い方の変化を見るために、起点と32ペアを対局させる。
棋力の判定には使わない。

## コマンドライン

[統括計画](../../plans/search-forms.md)の決定により、SPSAを終えた調整機で、持ち時間を換算せずに対局を実行した。
候補のコミットは、測定機で作った`git bundle`で調整機のcloneへ取り込んだ。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/aspiration-window-forms-smoke --seed 4800000000 \
  --candidate commit:469009043d784a28259d7e59f5a2c232a9b23ad9 \
  --baseline commit:03f5d79dab86eac1ad2cdb15a3c0faaf3d867ad6 \
  --each time=10000+100 --concurrency 191 elo --pairs 32
```

実行ディレクトリは、終了後に測定機の`data/matches/aspiration-window-forms-smoke`へ取得し、集計は測定機で次のコマンドで行った。

```console
data/spsa/aspiration-window-forms-runner/minase match report \
  --run-dir data/matches/aspiration-window-forms-smoke
```

候補の`cargo test`（通常ビルドと調整用ビルド）は、既定値を反映した後もすべて通った。テストを直すコミットは要らなかった。
事前対局は、測定機でのテストと並行して行った。

## エンジン

候補は、形の変更に[SPSAの最終値](aspiration-window-forms.md)を反映したコミット`469009043d784a28259d7e59f5a2c232a9b23ad9`である。
起点は、設計書を始めた時点のmaster`03f5d79dab86eac1ad2cdb15a3c0faaf3d867ad6`である。
runnerは、調整機で形の変更の最後のコミット`7631da34`をビルドした通常のminase（版2.4.0、SHA-256`ffaf3f22…`）である。
規則は`engine-default`（`L0,P0,R1,E0`）である。

## 環境

調整機は、vast.aiのインスタンス57080553（AMD EPYC 9K84の2基構成、物理192コア、論理384スレッド、ベトナム）である。測定機との1コアの速さの比`f`は1.37である（[時間切れの事前確認](aspiration-window-forms-safety.md)）。
両エンジンの`Threads`は1、`USI_Hash`は既定の256 MB、同時対局数の設定は191である（対局は32ペアなので、同時に動いたのは最大32ペアである）。

## 結果

| 量 | 値 |
|---|---:|
| 有効ペア | 30（手数上限による破棄2） |
| ペンタノミアル度数 | [4, 1, 17, 2, 6] |
| 正規化した平均得点 | 0.542 |
| Elo | +29.0 |
| 95%信頼区間 | [−45.0, +105.8] |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 631.4秒（`summary.json`の累計） |
| 1局の最大常駐メモリ | 1,015,439,360バイト |

値は`minase match report`が保存記録から再計算した集計による。
破棄した2ペアは、1局目が手数上限の4,096手に達したペア19と、2局目が達したペア26である。
30ペアの固定局数Eloは信頼区間の幅が約150 Eloあり、強さの判定には使わない。

時間の使い方は次のとおりである。
総思考時間と終局時の残り時間は、有効な30ペアの`pairs/`に保存された各手の思考時間から計算した。終局時の残り時間は、持ち時間に「1手あたりの加算×着手数」を足し、思考時間の合計を引いた値である。

| 量 | 候補 | 起点 |
|---|---:|---:|
| 総思考時間 | 2,513.4秒 | 2,480.6秒 |
| 着手数 | 19,600 | 19,598 |
| 1手の平均思考時間 | 128.2 ms | 126.6 ms |
| 終局時の残り時間の中央値 | 811 ms | 1,295 ms |

候補と起点の総思考時間の比（候補÷起点）は1.013である。

手数帯ごとの完了深さ（反復深化で読み終えた深さの平均）と思考時間の中央値は、有効な30ペアについて`scripts/clock_profile.py`を`--role candidate`と`--role baseline`で別々に実行して集計した。
候補の完了深さは反復の深さであり、A5で窓の深さを減らして完了した反復も、その反復の深さとして数える。

| 手数帯 | 候補の完了深さ | 起点の完了深さ | 候補の思考時間の中央値 | 起点の思考時間の中央値 |
|---|---:|---:|---:|---:|
| 0〜49 | 15.44 | 16.50 | 112 ms | 94 ms |
| 50〜99 | 14.93 | 15.82 | 112 ms | 102 ms |
| 100〜149 | 14.66 | 15.44 | 112 ms | 102 ms |
| 150〜199 | 14.31 | 15.12 | 121 ms | 111 ms |
| 200〜299 | 14.00 | 14.74 | 132 ms | 122 ms |
| 300〜399 | 14.17 | 14.91 | 132 ms | 132 ms |
| 400以降 | 18.66 | 22.56 | 83 ms | 91 ms |

探索を止めた理由の内訳は、候補では上限の時間による停止が170手（0.87%）、目安の時間による停止が19,430手、起点では上限の時間による停止が43手（0.22%）、目安の時間による停止が19,555手だった。
上限の時間による停止は、候補では170手のうち169手、起点では43手のうち42手が400手目以降の手数帯で起きた。
完了深さは全体の平均で候補16.09、起点18.11である。
`clock_profile.py`が出す時間予算の比と上限の超過量は、起点の係数の予算式に基づくので、候補の時間の使い方の解釈には使わない。

## 結論

候補は、時間切れとエンジン異常を起こさなかった。
総思考時間は起点とほぼ同じで、終局時の残り時間の中央値は起点より少なく、上限の時間による停止は起点の約4倍だった。いずれも400手目以降の局面に集中している。
完了深さは、すべての手数帯で起点より浅く、400手目より前の手数帯では約0.7〜1.1手浅い。
設計書の手順どおり、同じ調整機で逐次検定のSTCへ進む。

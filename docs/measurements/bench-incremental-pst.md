# PST差分更新のbench速度比較

## 目的

探索中のPST評価をply別の累算値から差分更新する変更について、探索結果を維持したまま速度基準を満たすかを判定する。

## コマンドライン

基準と候補で、次のコマンドを1回ずつ実行した。

```sh
cargo run --release --bin bench -- --repetitions 3
```

## エンジン

基準はコミット`0b4b8cc45cdb6f28ea7dbb65bb6f83612df01684`、候補はコミット`1cf91f450d9c493e60db33f28ca77ce2d904367e`である。
候補は先手視点と後手視点のPST生重み和をplyごとに保持し、通常着手とnull moveで差分更新する。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KFであり、物理コア数と論理CPU数はいずれも20である。
rustcとCargoはいずれも1.98.0であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

depth=3の総ノード数は、基準と候補の両方で569,697であった。
基準の中央値は0.205380秒、2,773,864 NPSであり、候補の中央値は0.169422秒、3,362,582 NPSであった。
候補の中央値は基準より21.22%高く、採用基準の3%を上回った。
通常手、成り、2枚取り、居喰い、じっと、先獅子状態の発生と消滅、およびnull moveについて、差分値が完全再計算値と一致した。
`cargo test`、Clippy、および整形検査は成功し、独立レビューの指摘1件は通常着手による先獅子状態消滅のテスト追加で解消した。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

探索ノード数が不変で速度が21.22%向上したため、PST差分更新を採用する。

# ply別手配列再利用のbench速度比較

## 目的

通常探索と静止探索の手配列をply別に再利用する変更について、探索結果を維持したまま速度基準を満たすかを判定する。

## コマンドライン

基準と候補で、次のコマンドを1回ずつ実行した。

```sh
cargo run --release --bin bench -- --repetitions 3
```

## エンジン

基準はコミット`538d4926eb9d79f24c4892a5f1b66f3554b1af09`である。
候補はこのコミットを基に、`Searcher`へ通常手と捕獲手のply別バッファを加えた一時作業ツリーである。
候補は採用基準を満たさなかったためコミットせず、実装を除去した。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KFであり、物理コア数と論理CPU数はいずれも20である。
rustcとCargoはいずれも1.98.0であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

depth=3の総ノード数は、基準と候補の両方で569,697であった。
基準の中央値は0.205380秒、2,773,864 NPSであり、候補の中央値は0.203119秒、2,804,752 NPSであった。
候補の中央値は基準より1.11%高く、採用基準の3%に届かなかった。
候補では`cargo test --lib`の448件が成功した。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

探索ノード数は不変だったが速度改善が1.11%にとどまったため、ply別手配列再利用を不採用とし、実装を除去した。

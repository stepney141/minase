# 反復出現回数表のbench速度比較

## 目的

探索履歴と探索経路の線形走査を出現回数表へ置き換える変更について、探索結果を維持したまま速度基準を満たすかを判定する。

## コマンドライン

基準と候補で、次のコマンドを1回ずつ実行した。

```sh
cargo run --release --bin bench -- --repetitions 3
```

## エンジン

基準はコミット`eb2c62a1f526119e50c40f72026ee24d0d0f7c96`である。
候補はこのコミットを基に、対局履歴と探索経路をワーカー固有の`HashMap<u64, usize>`へ集約した一時作業ツリーである。
候補は採用基準を満たさなかったためコミットせず、実装を除去した。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KFであり、物理コア数と論理CPU数はいずれも20である。
rustcとCargoはいずれも1.98.0であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

depth=3の総ノード数は、基準と候補の両方で569,697であった。
基準の中央値は0.205380秒、2,773,864 NPSであり、候補の中央値は0.211645秒、2,691,760 NPSであった。
候補の中央値は基準より2.96%低下し、採用基準の3%改善を満たさなかった。
反復に関する既存テスト3件は候補でも成功した。
標準benchの15局面は各局面を`Game::from_position`から作るため、対局履歴が根局面の1件だけであり、長い履歴の走査を削減する効果は測定されない。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

探索ノード数は不変だったが速度が2.96%低下したため、反復出現回数表を不採用とし、実装を除去した。

# lishogiのBotの`ByoyomiMargin` 3,000 msでの秒読みつき対局の記録

## 目的

[秒読みつき時計での持ち時間と秒読みの活用](../../plans/archived/byoyomi-time-usage.md)のフェーズ5（配備の確認と文書）として、lishogiのBotで`ByoyomiMargin`を3,000 msにした後の秒読みつきの対局をLishogi-Botのログで調べ、Bot側の時間切れが0件であることと、秒読み期の思考時間と秒読みの比を記録する。
3,000 msを選んだ理由は[ADR](../../adr/set-bot-byoyomi-margin-to-3000-ms.md)にあり、そこでは秒読みつきの対局20局で時間切れが0件であることを確かめると定めている。

## コマンドライン

```console
python3 -I docs/measurements/byoyomi-time-usage/bot-byoyomi-margin-3000/byoyomi_record.py \
  minase-lishogi-bot/logs/lishogi-bot.log "2026-10-10 01:26:47"
```

ログは配備リポジトリ`minase-lishogi-bot`の`logs/lishogi-bot.log`であり、2026年10月23日の解析の時点で648 MBあった。
ログは配備リポジトリでも管理していないので、本記録には含めない。
スクリプトは[bot-byoyomi-margin-3000/byoyomi_record.py](bot-byoyomi-margin-3000/byoyomi_record.py)にある。
第2引数は、Botが`ByoyomiMargin` 3,000 msで起動し直した時刻（UTC）である。
スクリプトはこの時刻より後に始まって終局した秒読みつきの対局を対象にし、この時刻より後にエンジンへ送られた`ByoyomiMargin`の値が1つに定まらなければ、誤りとして止まる。

秒読み期の手とは、Lishogi-Botがエンジンへ送ったBot側の持ち時間が0の手をいう。
Lishogi-Botは、lishogiが報告する残り時間から`move_overhead`（1,900 ms）と秒読みを引き、負になれば0とした値を送る。
このため、持ち時間がわずかに残っている最後の数手も秒読み期の手に含まれる。
エンジンの`go`、`ponderhit`、`bestmove`の行は対局IDを持たないので、探索の開始から`bestmove`までの間に進行中の対局が1つだけだった手に限って対局と結び付けた。
もう1局と同時に指していた時間帯の手は解析から外れるので、秒読み期の手の数と、秒読み期の手を持つ対局の数は、実際の値の下限である。
Botの着手の数、送信にかかった時間、および応答コードは、対局IDを持つ着手の`POST`の行から数えた。
送信にかかった時間は、`bestmove`の行から`POST`の応答の行までの時間である。

## エンジン

エンジンはcrates.ioで公開したminaseであり、12局が2.3.0、39局が2.4.0で指された。
2.4.0への更新は2026年10月12日04:12（UTC）で、配備リポジトリのコミットはe35ac24である。
`ByoyomiMargin`を3,000 msにした配備リポジトリのコミットは8e8d620である。
規則セットは`lishogi`（`L1,L2,P0,P3,R1,E1,E3`）で、`Threads=4`、`USI_Hash`は2,048 MB、先読みありである。
対局の仲介はLishogi-Bot 1.2.0であり、`move_overhead`は1,900 msである。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、段階Aの採否測定と同じ測定機である。
Botのコンテナは、CPUを8コア分、メモリを6 GBに制限している。
Botは最大2局を同時に指す。
同じ機械では別の作業も動いていたが、期間中の負荷は記録していない。
期間は2026年10月10日01:26（UTC）からで、対象の最後の対局は2026年10月22日13:05に始まった。
期間中にBotは2回起動し直した。
1回目は上記の2.4.0への更新である。
2回目は2026年10月21日13:10の機械の再起動であり、配備リポジトリの設定は変わっていない。

## 結果

期間中に始まった秒読みつきの対局は57局であり、着手前に中止された6局を除く51局を対象にした。
51局すべてにlishogiの終局通知（`gameFinish`）が残っており、Botの44勝7敗だった。
終局理由が時間切れの対局は9局あり、いずれも勝者がBotなので、時間切れになったのは相手である。

| 項目 | 値 |
|---|---|
| 対象の対局 | 51局（2.3.0が12局、2.4.0が39局） |
| Bot側の時間切れ | 0局 |
| 相手の時間切れ | 9局 |
| Botの着手 | 4,766手 |
| 秒読み期の手を解析できた対局 | 23局 |
| 解析できた秒読み期の手 | 828手（うち先読みの的中136手） |
| 締切の100 ms手前より後まで探索した手 | 828手 |

締切は秒読みから`ByoyomiMargin`の3,000 msを引いた時刻である。
解析できた秒読み期の手では、エンジンはすべて締切まで探索していた。
このため、思考時間と秒読みの比は秒読みの長さだけで決まる。
思考時間は締切を2〜21 ms上回っており、この差には、探索を止めてから`bestmove`がLishogi-Botへ届くまでの時間が含まれる。

先読みが的中した手は、思考時間を`ponderhit`から数えた。
段階Aを入れる前の[実戦の調査](../../research/lishogi-byoyomi-time-usage.md)では、秒読み期の思考時間と秒読みの比の中央値は0.515だった。

送信にかかった時間は、51局のBotの着手のうち、`bestmove`と結び付けられた4,570手で測った。
中央値は120 ms、99パーセンタイルは939 ms、最大は2,507 msであり、0.6秒を超えた手は265手、2秒を超えた手は17手、3秒を超えた手は0手だった。
締切までの残りを「秒読み −（探索の開始から送信の応答までの時間）」で求めると、最小は対局2Wc2xReWの先読みが的中した手の485 msで、思考は57,008 ms、送信は2,507 msだった。
この残りには、相手の着手がBotへ届くまでの時間を含めていないので、実際の残りはこれより小さい。

1手に日単位の時間をかけられる通信対局（correspondence）を含めると、期間中の全着手は14,862手であり、送信が3秒を超えた手が2手あった。
2026年10月20日の4,677 msと2026年10月23日の3,617 msであり、どちらも通信対局の手だった。
同じ遅れが秒読み期の手で起きれば時間切れになる。
3秒を超える遅れは、ADRが3,000 msを選んだ時点でも25,799手中10手あり、まれな遅れとして許容したものである。

51局の着手の送信のうち11手に、lishogiがHTTP 400を返した。
いずれの対局もその後に続いており、時間切れとは関係しない。

対局ごとの内訳は次のとおりである。
「秒読み期の手（解析）」は、対局と結び付けられた秒読み期の手の数である。

「送信の最大」は、その対局で`bestmove`と結び付けられた着手のうち、送信にかかった時間の最大である。

## 結論

`ByoyomiMargin` 3,000 msの下で、Botは秒読みつきの対局51局を指してBot側の時間切れが0件だったので、ADRが定めた確認を満たす。
解析できた秒読み期の手828手ではエンジンがすべて締切まで探索したが、締切までの残りは最小で485 msまで縮んだ手があり、3秒を超える送信の遅れが秒読み期の手で起きれば時間切れになり得る。

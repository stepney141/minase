# 補助ツールのサブコマンド化の前後の探索速度（bench深さ5）

## 目的

補助ツールを実行ファイル`minase`のサブコマンドへ移したことで、探索のノード数が変わらず、NPS中央値が移動前の0.98倍以上を保つかを、[補助ツールのサブコマンド化](../plans/cli-subcommands.md)の「検証」の節の基準で判定する。

## コマンドライン

移動前の`bench`と移動後の`minase dev bench`を、同じP-core（CPU 3）に固定して交互に5回ずつ実行した。

```console
taskset -c 3 <移動前>/bench --depth 5 --threads 1 --repetitions 3
taskset -c 3 <移動後>/minase dev bench --depth 5 --threads 1 --repetitions 3
```

局面別の比較には、両者を1回ずつ`--depth 5`（`--repetitions`は既定の1）で実行し、各行から経過時間とNPSの欄を除いて照合した。

```console
taskset -c 3 <移動前>/bench --depth 5
taskset -c 3 <移動後>/minase dev bench --depth 5
```

## エンジン

移動前はコミット`61224bf`（探索と評価のコードはmasterの`fb3be04`と同一）、移動後はコミット`75969be`である。いずれも通常のrelease設定（リンク時最適化あり）でビルドし、`bench`は規則セット`engine-default`を固定で使う。
実行ファイル`minase`の大きさは、移動前が1,708,568バイト、移動後が4,157,472バイトである。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、2026年10月5日に、同じ測定機で走っていた対局測定の終了を確かめてから、他の負荷を走らせずに1スレッドで測った。

## 結果

各回の3回実行の中央値NPSは次のとおりである。総ノード数は全回で324,829と一致した。

| 版 | 1回目 | 2回目 | 3回目 | 4回目 | 5回目 | 中央値 |
|---|---:|---:|---:|---:|---:|---:|
| 移動前 | 1,866,912 | 1,862,663 | 1,858,953 | 1,863,052 | 1,858,907 | 1,862,663 |
| 移動後 | 1,839,965 | 1,855,669 | 1,854,368 | 1,851,841 | 1,859,173 | 1,854,368 |

移動後の中央値は移動前の0.9955倍である。
局面別の出力は、15局面すべてで深さ、ノード数、最善手、および探索値が一致した。

## 結論

ノード数は変わらず、NPSの比0.9955は基準の0.98を上回るので、移動による探索速度の低下は判定基準の範囲内である。

# correction historyの表の変更の候補の事前対局

## 目的

[correction historyの表の追加と持ち越しの設計書](../../plans/archived/correction-history-tables.md)のフェーズ4として、SPSAの最終値を反映した候補がSTCの条件で時間切れやエンジン異常を起こさないことを確かめ、時間の使い方の変化を見るために、起点と32ペアを対局させる。
棋力の判定には使わない。

## コマンドライン

[統括計画](../../plans/search-forms.md)の決定により、SPSAを終えた調整機で、持ち時間を換算せずに対局を実行した。
候補のコミットは、測定機で作った`git bundle`で調整機のcloneへ取り込んだ。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/correction-history-tables-smoke --seed 4200000000 \
  --candidate commit:5ed505eca0a525dff9f21c1d6d3e166f82d04089 \
  --baseline commit:e21b765545d679d55add9b324c1a3b08d77e8f6d \
  --each time=10000+100 --concurrency 191 elo --pairs 32
```

実行ディレクトリは、終了後に測定機の`data/matches/correction-history-tables-smoke`へ取得し、集計は測定機で次のコマンドで行った。

```console
data/spsa/correction-history-tables-runner/minase match report \
  --run-dir data/matches/correction-history-tables-smoke
```

## エンジン

候補は、形の変更に[SPSAの最終値](correction-history-tables.md)を反映したコミット`5ed505eca0a525dff9f21c1d6d3e166f82d04089`である。
起点は、設計書を始めた時点のmaster`e21b765545d679d55add9b324c1a3b08d77e8f6d`である。
runnerは、調整機で形の変更の最後のコミット`e695176a`をビルドした通常のminase（版2.4.0、SHA-256`d3e7ea8c…`）である。
規則は`engine-default`（`L0,P0,R1,E0`）である。

## 環境

調整機は、vast.aiのインスタンス56856484（AMD EPYC 9K84の2基構成、物理192コア、論理384スレッド、ベトナム）である。測定機との1コアの速さの比`f`は1.29である（[時間切れの事前確認](correction-history-tables-safety.md)）。
両エンジンの`Threads`は1、`USI_Hash`は既定の256 MB、同時対局数の設定は191である（対局は32ペアなので、同時に動いたのは最大32ペアである）。

## 結果

| 量 | 値 |
|---|---:|
| 有効ペア | 29（手数上限による破棄3） |
| ペンタノミアル度数 | [2, 0, 16, 0, 11] |
| 正規化した平均得点 | 0.655 |
| Elo | +111.5 |
| 95%信頼区間 | [+32.9, +203.2] |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 538.7秒（`summary.json`の累計） |
| 1局の最大常駐メモリ | 985,698,304バイト |

値は`minase match report`が保存記録から再計算した集計による。
破棄した3ペアは、いずれも1局が手数上限の4,096手に達したペアである。
29ペアの固定局数Eloは信頼区間の幅が約170 Eloあり、強さの判定には使わない。

時間の使い方は次のとおりである。
総思考時間と終局時の残り時間は、有効な29ペアの`pairs/`に保存された各手の思考時間から計算した。終局時の残り時間は、持ち時間に「1手あたりの加算×着手数」を足し、思考時間の合計を引いた値である。

| 量 | 候補 | 起点 |
|---|---:|---:|
| 総思考時間 | 1,769.9秒 | 1,748.7秒 |
| 着手数 | 12,599 | 12,590 |
| 1手の平均思考時間 | 140.5 ms | 138.9 ms |
| 終局時の残り時間の中央値 | 867 ms | 1,123 ms |

候補と起点の総思考時間の比（候補÷起点）は1.012である。

手数帯ごとの完了深さ（反復深化で読み終えた深さの平均）と思考時間の中央値は、有効な29ペアについて`scripts/clock_profile.py`を`--role candidate`と`--role baseline`で別々に実行して集計した。

| 手数帯 | 候補の完了深さ | 起点の完了深さ | 候補の思考時間の中央値 | 起点の思考時間の中央値 |
|---|---:|---:|---:|---:|
| 0〜49 | 13.25 | 13.46 | 122 ms | 122 ms |
| 50〜99 | 12.64 | 12.63 | 122 ms | 122 ms |
| 100〜149 | 12.55 | 12.50 | 112 ms | 112 ms |
| 150〜199 | 12.19 | 12.40 | 112 ms | 122 ms |
| 200〜299 | 11.75 | 12.02 | 122 ms | 132 ms |
| 300〜399 | 11.19 | 11.79 | 132 ms | 142 ms |
| 400以降 | 11.76 | 12.82 | 92 ms | 101 ms |

探索を止めた理由の内訳は、候補では上限の時間による停止が72手（0.57%）、目安の時間による停止が12,527手、起点では上限の時間による停止が34手（0.27%）、目安の時間による停止が12,556手だった。
完了深さは全体の平均で候補12.03、起点12.40である。
`clock_profile.py`が出す時間予算の比と上限の超過量は、起点の係数の予算式に基づくので、候補の時間の使い方の解釈には使わない。

## 結論

候補は、時間切れとエンジン異常を起こさなかった。
総思考時間は起点とほぼ同じで、終局時の残り時間は起点より少なく、上限の時間による停止は起点の約2倍だった。
完了深さは、序盤は起点とほぼ同じで、200手以降は起点より浅い。
設計書の手順どおり、同じ調整機で逐次検定のSTCへ進む。

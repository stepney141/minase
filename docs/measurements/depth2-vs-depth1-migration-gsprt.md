# depth=2対depth=1の移行検証GSPRT

## 目的

対局ハーネスをUSIプロセス方式へ差し替えた移行検証として、`depth=2`対`depth=1`のGSPRTがin-process時代の同一シード実行と同じペンタノミアル度数とLLRでH1採用になることを、プロセス方式の逐次実行（フェーズ2）およびコミット指定と並列実行（フェーズ3）の両方で再現する。

## コマンドライン

フェーズ3（コミット指定と並列実行）の実行は次のとおりで、シードは記録なし。

```console
match_runner --candidate commit:f7a228d --candidate-limit depth=2 \
  --baseline commit:0045833 --baseline-limit depth=1 --concurrency 8 gsprt
```

フェーズ2（逐次実行、パス形式のエンジン指定）の実行のコマンドライン全体は記録なし。

## エンジン

候補はコミットf7a228d（`depth=2`）、基準は凍結ベースラインのコミット0045833（`depth=1`）である。
規則セットは記録なし。

## 環境

2026年8月11日に測定した。
フェーズ3の実行は同時対局数8、フェーズ2の実行は逐次である。
CPU型、コア数、ワーカー数、`USI_Hash`は記録なし。

## 結果

207ペアでLLR 2.9576に達し、判定はH1（候補が有意に強い）だった。
フェーズ3の実行は、2コミットのビルドから判定まで9.0秒で完走した。
ペンタノミアル度数の値、破棄ペア数、異常件数は記録なし。
フェーズ2の逐次実行、フェーズ3の並列実行、およびin-process時代の同一シード実行の3者で、ペンタノミアル度数とLLR値は一致した。
固定深さ対局のため`time_forfeits`は該当しない。

## 結論

移行の前後で判定と統計値が一致し、プロセス方式への差し替えとコミット指定・並列実行が統計層の結果を変えないことを確認した。

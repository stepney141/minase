# 自己対局の持ち時間感度（持ち時間2倍の固定200ペアElo）

## 目的

同じコミット同士の対局で候補側だけに2倍の持ち時間を与え、自己対局で持ち時間2倍がどれだけのElo差に相当するかを参考値として測る。

## コマンドライン

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/sensitivity-time2x --seed 20260828 \
  --candidate commit:bfeb1aa --baseline commit:bfeb1aa \
  --candidate-limit time=60000+600,byoyomi=1000 \
  --each time=30000+300,byoyomi=500 --concurrency 16 elo --pairs 200
```

実行に使った`match_runner`は、対局ハーネスの効率化（`--run-dir`と再開、`match_report`）を含む作業ツリーからビルドしたバイナリ（SHA-256 `da126857f6961975f74107e1f9823a0bf26ff1f69dcfe69c323178914c033f22`）であり、その内容は後にコミット`3b35793`としてmasterへ入った。
`match_report`は両側の時間制御が等しい測定だけを集計するため、この測定は標準出力の要約を記録とする。

## エンジン

候補と基準はいずれも現行の学習PSTのコミット`bfeb1aa284c934b1eec5e692808d0914d2facf8d`であり、バイナリのSHA-256は`480aaaf7a92d91c719cbec5aa2cc9c6ab98ac3013390db310473a93c208f883c`である。
候補側の思考制限は`time=60000+600,byoyomi=1000`、基準側は`time=30000+300,byoyomi=500`である。
規則セットは`engine-default`（L0＋P0＋R1＋E0）を両エンジンと審判層に与えた。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ33,218,965,504バイト）であり、OSはLinuxである。
候補と基準のワーカー数はいずれも`Threads=1`、`USI_Hash`はいずれも256 MB、同時対局数は16、手数上限は4,096手、応答タイムアウトは120秒とした。
この測定は2026年8月28日15時47分から18時46分（JST）に、学習や生成と重ねずに単独で実行した。

## 結果

200ペア（有効197、手数上限4,096による破棄3）を完走した。
ペンタノミアル度数は`[5, 0, 77, 2, 113]`、Eloは+216、95%信頼区間は+181〜+257である。
エンジン異常、`time_forfeits`、および拒否着手はいずれも0件であり、経過は10,714秒（3.0時間）である。

## 結論

自己対局では持ち時間2倍あたり約216 Eloが得られ、HaChu戦の4倍測定から見積もった約125 Eloの約1.7倍であるが、この値は評価関数の速度低下の重さを解釈する目安にとどめ、線形性は仮定せず採否には用いない。

# pst-gen0-tc

## 目的

世代0の自己対局データで学習した学習PST（段階1、レビュー修正後のコミット）と、着手前の駒得評価関数v0の最終コミット（v0基準）を、標準時間制御の対等条件GSPRTで比べ、学習PSTの採否と評価関数マイルストーンの最終ゲートを判定する。

## コマンドライン

```console
cargo run --release --bin match_runner -- --candidate commit:7e13888 --baseline commit:e553493 --each time=30000+300,byoyomi=500 --concurrency 16 --seed 20260827 gsprt
```

同時対局数8で開始したところ1ペアに約10分かかり判定まで半日以上を要すると分かったため、開始15分で中断し、同時対局数16（20コアのうち4コアをOSとハーネスに残す値）で最初から実行し直した。
この測定は`--run-dir`の導入前に実施したため、実行ディレクトリは残っていない。
測定名は本記録で付けた名前である。

## エンジン

候補はコミット7e13888（学習PSTのレビュー修正後。評価関数は初版のコミット588363aと同一）、基準はコミットe553493（v0基準）である。
規則セットはコマンドラインで指定せず、`commit:`指定でハーネスが自動付与する既定の規則セットを両エンジンに与えた（名前は記録なし）。

## 環境

CPUはIntel Core Ultra 7 265KF（20コア。論理コア数は記録なし）、両エンジン`Threads=1`、`USI_Hash`は既定、同時対局数は16である。

## 結果

ペア数は436（有効435、手数上限による破棄1）、ペンタノミアル度数は[57, 0, 213, 2, 163]、LLRは2.955、判定は`H1`である。
`engine_failures`および`time_forfeits`はすべて0である。
経過時間は21,210秒（5.9時間）である。
候補の得点率は62.3%（約+87 Elo）で、固定ノードGSPRT（pst-gen0-nodes100k.md）の58.1%より高い。
NPSが9%低いにもかかわらず時間制御の方が差が大きいのは、時間制御では固定ノードより深く読める分だけ評価の差が増幅されるためと考えられるが、2つの測定は開始局面も局数も異なるので、この差自体を有意とは見なさない。

## 結論

学習PSTはv0基準に時間制御GSPRTで`H1`であり、採用するとともに評価関数マイルストーンの最終ゲートを満たした。

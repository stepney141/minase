# ファイル形式の整理の前後で学習結果が一致することの照合記録

## 目的

[ファイル形式の整理の設計書](../plans/file-format-consolidation.md)は、教師データMNSDの来歴JSONを撤去し、教師の分類と検証分割をレコードの由来とヘッダから決める方式へ変える。
この変更は学習の入力の読み方を変えるだけであり、乱数開始の自己対局のデータでは、局面数、教師用K、訓練集合と検証集合の分け方、および各エポックの損失を変えてはならない。
本書は、変更前の学習器で取った基準と、変更後の学習器で同じ条件の学習を行った結果を記録し、両者がビット単位で一致することを確かめる。

## 環境

測定機はIntel Core Ultra 7 265KF（20コア、ハイパースレッディングなし）である。
学習はすべてCPUで行い、同時に他の測定は走らせていない。
変更前の学習器は、着手時点のmasterのコミットf99b6b6を`cargo build --release -p minase-trainer`でビルドしたもので、実行ファイルのSHA-256は`88a46ede01751e26ec76571119e3cc1626cf6abf88d36cabea81945937f31561`である。

## 照合の条件

入力は、乱数開始の自己対局で生成した次の2ファイルであり、この順に`--data`へ与える。
どちらも教師の重みの検査和`6c1bc5d5…a3d2`、生成コミット8d0e382、1局面2万ノード、規則セット`L0,P0,R1,E0`で生成されている。

| ファイル | バイト数 | 記録数 | SHA-256 |
|---|---|---|---|
| `data/nnue-replacement-gen/generated-2000000.bin` | 470,959,496 | 2,943,496 | `e1bcd27058a043a9a1ee4ec0a35648a9a03245decb0c4902489d37456d46c673` |
| `data/nnue-replacement-gen/generated-2100000.bin` | 461,509,096 | 2,884,431 | `319f56a9b8cbf40f16656c00952156925658ea47217e4557d37ff88e1731b109` |

初期の重みは次の3ファイルである。
NNUEの線形経路の初期値は同時学習`j75`の量子化前の重み、出力用Kと探索用駒価値の基準は埋め込みのPST＋FMの重み、PSTの初期値は埋め込みの初期PSTである。

| 用途 | ファイル | SHA-256 |
|---|---|---|
| NNUEの`--init-pst` | `data/pst-fm-joint-training/j75/pst-float.npz` | `828f8c0064e6bface1b85324cdc47bb0b26f037fa8b2f89eb97dbc2949dfebdd` |
| NNUEの`--base` | `crates/minase/nets/pst.bin` | `efe2c1455f19c1b019051d672d37204e714ed1043daec88b44422c3a7f780c53` |
| PSTの`--init` | `crates/minase/nets/pst-init.bin`（MNPT版2） | `a7a9d32e23a4e4744401d713ee65a7584ae9c7d7a29d784e90b178056afba196` |

`crates/minase/nets/pst-init.bin`は、整理の後にFMの次元0のMNPT版3へ書き直される。
変更後の照合では書き直した後のファイルを使い、PSTの重みそのものは同じである。

変更前の学習器では、NNUEとPSTをそれぞれ次のコマンドで2エポック学習した。
`$D`は`data/nnue-replacement-gen`、`$ROOT`はリポジトリのルートである。
変更後の学習器では、`--lambda-override`を必須の引数`--lambda`に置き換え、値は同じにする。

```sh
minase-trainer nnue train --device cpu --threads 4 --feature-set P --width 16 \
  --data $D/generated-2000000.bin $D/generated-2100000.bin \
  --init-pst $ROOT/data/pst-fm-joint-training/j75/pst-float.npz \
  --base $ROOT/crates/minase/nets/pst.bin \
  --lambda-override 1.0 --batch 16384 --epochs 2 --seed 1 \
  --output-dir <出力先>

minase-trainer pst train --threads 4 \
  --data $D/generated-2000000.bin $D/generated-2100000.bin \
  --init $ROOT/crates/minase/nets/pst-init.bin \
  --removal-reference init --lambda-override 0.75 \
  --lr 0.03 --batch 16384 --epochs 2 --patience 5 --seed 1 \
  --output-dir <出力先>
```

比べる値は、`config.json`の`preprocessing`にある訓練局面数、検証局面数、教師用K、および訓練と検証の通し番号の列のSHA-256と、`training.jsonl`の各エポックの訓練損失、駒除去差分の補助損失、総損失、および検証損失である。
浮動小数点の値はJSONに書かれた最短の10進表現のまま比べる。

1回の所要時間は、NNUEが約203秒、PSTが約30秒である。

## 変更後の照合

教師データとMNPTを置き換えた後の学習器で、同じ条件の学習をNNUEとPSTそれぞれ2回ずつ行った。
照合は2回行った。
1回目は、来歴JSONを撤去して由来と`--lambda`へ移した時点のコミットbf1a96aで、PSTの`--init`には書き直す前の版2の`pst-init.bin`を使った。
2回目は、MNPTを版3だけにして`pst-init.bin`をFMの次元0の版3へ書き直した後のコミット3763e6fである。
書き直した`pst-init.bin`のSHA-256は`8e82a245009b08ed81c149e26fa8fe42e2c7eb82a5d324047b57bc53972f444f`である。

どちらの照合でも、NNUEとPSTの4回の学習のすべてで、訓練局面数、検証局面数、教師用K、訓練と検証の通し番号のSHA-256、および各エポックの訓練損失、補助損失、総損失、検証損失が、変更前の基準と文字列として完全に一致した。
したがって、由来とヘッダから教師の分類と検証集合を決める方式へ移っても、乱数開始の自己対局のデータでは学習の入力と軌跡が変わらない。

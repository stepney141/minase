# FM候補の診断

## 目的

[Factorization Machineによる2駒関係評価](../plans/factorization-machine.md)の第1フェーズと第2フェーズの診断として、最終候補（潜在次元32、λ=1.0、λres=1e-4、シード1）を開始版の2端点PSTと比較し、Rust評価とPython参照評価の一致、量子化誤差、局面帯別の誤差、駒の除去、および着手差を記録する。

## コマンドライン

```console
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py diagnose --run-dir data/fm-cand-lam1e-4
```

設定は`data/fm-configs/fm-cand-lam1e-4.toml`（[学習記録](fm-phase1-training.md)と同じ入力、診断標本は世代と局面帯ごとに最大10,000局面をシード1で抽出）である。
教師値はλ=1.0（教師探索値だけ）であり、基準と候補の検証損失は同じ教師値で測っている。

## エンジン

基準は開始版`b0153cf27df655a32cb9a255fd380b21bba002b5`の`nets/pst.bin`（MNPTバージョン2）であり、基準側の評価は開始版worktreeで構築した`pst_probe`で行った。
候補はブランチ`fm-eval`のコミット`ffeedb3de5a305d5a81b8bb3ae33920e89acb3ba`で構築した`pst_probe`（SHA-256 `5e2ec3dfce1f7ee249da3b3df7c382d7368372016dd8312f8391d692558b8aea`）で評価し、候補ファイルの固定PST、探索用駒価値、およびKは基準と一致する。

## 環境

Intel Core Ultra 7 265KF（20コア）、メモリ30 GB、Python 3.12.14である。
診断中は本体ツリーの対局測定が並走していたが、診断の結果は実行時間に依存しない。

## 結果

### Rust評価とPython参照評価の一致

診断標本91,841局面すべてで、候補`pst_probe`の`eval`はPythonの整数参照評価と一致し、`eval_pst`は基準`pst_probe`の`eval`と一致した。

### 量子化誤差

診断標本91,841局面で、浮動小数点評価と整数評価の平均絶対誤差は0.526 cp、最大は1.910 cpであり、上限2 cpの内側である。

### 代表局面の駒の除去と着手差

代表局面6局面の非王駒352枚の除去では、自駒を除くと評価が下がり相手駒を除くと上がるという符号が候補でもすべて保たれ、FMの補正分の絶対値は平均52 cp、最大252 cpであった。
合法手ごとの着手差の診断では、FM込みの評価差とPSTだけの評価差の差（FM分）は392手で平均-17.6 cp、標準偏差113.1 cp、最大絶対値417 cpであり、歩兵価値（100 cp）に対する比は平均0.89、最大4.17である。

代表局面に合法な成り手はなく（帯3の局面は成り手の列挙対象外）、成りの診断は記録なしである。
1手あたりのFM分が歩兵価値と同程度に達する局面があり、futility pruningの余裕値（歩兵の0.5〜1.5倍）に対して無視できない大きさである。
探索側の定数は設計判断どおり変更せず、この記録は採否判定の解釈に使う。

## 結論

候補はPython参照評価と一致し、量子化誤差は上限内で、全局面帯で検証損失と教師誤差を改善し、駒の除去の符号も保たれているので、第3フェーズ（bench）と採否測定へ進む。

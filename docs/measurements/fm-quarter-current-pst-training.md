# 補正1/4のFMの候補FnとFaの学習、点検、および探索速度

## 目的

[補正1/4のFMの再学習](../plans/fm-quarter-current-pst.md)のフェーズ2として、採用PSTの候補Lを固定し、先読みを使わない教師（候補Fn）と先読みつきの教師（候補Fa）でFMの補正を学習して、補正1/4を施す。
あわせて、実装の正しさの検査と、探索速度の比較を記録する。

## コマンドライン

学習器は、ブランチ`fm-quarter-current-pst`の`e881daa`の`tools/train/`（コマンド`train-fm`）である。
入力は世代2の5ファイル（`data/strength-stage7/gen2/generated-600000.bin`から`generated-1000000.bin`）と世代3の5ファイル（`data/gen3/generated-1100000.bin`から`generated-1500000.bin`）である。

```console
train-fm train --init crates/minase/nets/pst.bin --data <10ファイル> \
  --output data/fm-quarter-current-pst-<fn|fa>/fm.bin \
  --epochs 200 --patience 3 --lambda-override 1.0 --device cuda \
  [--lookahead-gamma 0.9 --lookahead-plies 40]   # Faだけ
train-fm quarter --input data/fm-quarter-current-pst-<fn|fa>/fm.bin \
  --output data/fm-quarter-current-pst-<fn|fa>/fm-quarter.bin
```

学習条件は、潜在次元32、補正の正則化係数λres=10⁻⁴、AdamW、学習率10⁻³、重み減衰10⁻⁴、バッチ4,096、乱数シード1である。
早期終了は一般的な定義（最良値は∞から始め、厳密な改善で更新し、最後の更新から3エポック続けて更新がなければ止め、学習したエポックの中の最良の重みを返す）に従う。
2本はGPUで同時に、`nice -n 19`、2スレッドで学習した。

探索速度は、M、Fn、Faのビルドを性能コアのCPU 3へ固定し、3構成を交互に5巡実行して、中央値を比べた。

```console
taskset -c 3 minase-<m|fn|fa> dev bench --depth 9 --repetitions 3
```

## エンジン

基点のM（master `86d8a89`）の採用PSTは候補L（SHA-256 `b2d2cd1b…`）である。
候補Fnはブランチ`fm-quarter-current-pst`の`23f318e`、候補Faはブランチ`fm-quarter-current-pst-fa`の`a4b2cc1`であり、両者の差は重みファイルと初期局面の評価値のテストだけである。
探索速度のビルドのSHA-256は、Mが`40c6e8cd…`、Fnが`6344cca6…`、Faが`4fa64a25…`である。

## 環境

測定機はIntel Core Ultra 7 265KF（性能コア8、高効率コア12、実メモリ32 GB、GeForce RTX 3060 Ti）である。
学習は2026年10月6日9時15分に始まり、Faは9時49分、Fnは10時5分に終わった。1エポックは約2分である。
学習の間、別の作業の対局（同時16局の秒読みの測定）が同じ測定機で走っていた。
探索速度は12時6分から12時9分に測り、その間に他の対局は走っていなかった。

## 結果

訓練は27,745,843局面、検証は1,462,975局面（対局の識別子のハッシュで約5%）であり、1エポックは6,774更新である。
教師Kは訓練集合から推定し、Fnは世代2と世代3で777.57と783.57、Faは758.35と765.95だった。

| 項目 | Fn（先読みなし） | Fa（先読みつき） |
|---|---|---|
| 最良エポック／止まったエポック | 14／17 | 8／11 |
| 総更新回数 | 115,158 | 74,514 |
| 検証損失（エポック0→最良） | 0.439550→0.437434 | 0.432304→0.430257 |
| 補正の標準偏差（ロジット、検証集合） | 0.239 | 0.257 |
| 補正の標準偏差（補正1/4の前→後、検証の1万局面） | 258→64 cp | 273→68 cp |
| 量子化誤差の平均（補正1/4の前／後） | 0.57／0.51 cp | 0.52／0.50 cp |
| 指数（補正1/4の前→後） | 8→9 | 9→10 |
| 初期局面の評価値（補正1/4の後） | 35 cp | 41 cp |
| 補正1/4の重みのSHA-256 | `b3e05f5e…` | `85e4e455…` |

検証損失の推移は次のとおりである。
Fnは、1エポック目に0.437719まで下がった後、14エポックの0.437434まで緩やかに下がり、15から17エポックで更新が止まった。
Faは、1エポック目に0.430717まで下がった後、8エポックの0.430257で最良となり、9から11エポックで更新が止まった。
当時のFM（`fm-eval`の`docs/measurements/fm-phase1-training.md`）の補正の標準偏差は0.227であり、大きさは同程度である。

点検の結果は次のとおりである。

| 検査 | Fn | Fa |
|---|---|---|
| Rustと学習器の評価値の一致（`fm-diagnostics`、10万局面） | 一致 | 一致 |
| 土台のPST、探索用駒価値、出力Kの不変 | 不変 | 不変 |
| 補正1/4がすべて0か | 0ではない | 0ではない |
| `cargo test` | すべて通過 | すべて通過 |

探索速度（5巡の中央値）は次のとおりである。

| 構成 | NPS | Mとの比 | benchのノード数 |
|---|---:|---:|---:|
| M | 2,140,231 | 1.000 | 6,470,606 |
| Fn | 1,997,893 | 0.934 | 6,405,122 |
| Fa | 1,850,972 | 0.865 | 5,711,806 |

FnとFaは同じ構造であり、速度の差は重みの違いで探索木が変わったことによると考えられる。

## 結論

どちらの候補も早期終了で止まり、点検に合格したので、計画書のとおり段階ゲートへ進める。
FMの補正は、PSTと違って十数エポックで検証損失が下げ止まった。
探索速度の費用は、当時のFMの約1.2%より大きく、Fnで約7%、Faで約14%である。

# FM選択手のPST教師による診断

2026年9月9日、保存局面とFMの実戦局面から各8局面を抽出し、FM補正を零にした共通PST教師で選択手を比較した。
1,000,000から10,000,000ノードへ増やすと16局面中5局面で最上位手集合が変わり、事前の安定性条件を満たさなかった。
本標本128局面への拡大は行わず、今回の固定16局面における診断として結論を限定する。

## 条件

診断コードはfm-evalの`c688c11a1351e73f23f7051122dbee994a17e1d9`である。
実行開始後に同じソースをコミットし、実行開始時からバイナリとソースが変わっていないことを検査和で確認した。
FM候補は前回の不採用モデルであり、教師はその埋め込みだけを零にしたモデルである。
教師と候補のPST、評価尺度K、探索用駒価値が一致し、PST基準`b0153cf27df655a32cb9a255fd380b21bba002b5`とも一致することを検査した。

抽出元は保存91,841局面と実戦7,002局面である。
PST評価[-1,000, 1,000)センチポーンを対象に、駒数5帯とPST評価500センチポーン刻みの層を合わせ、各対局最大2局面、シード1で64組を固定した。
本標本は保存60対局と実戦32対局に由来し、13層を含む。
今回読んだのは先頭8組で、保存8対局と実戦8対局から各1局面、共通5層である。
FM補正や教師結果は抽出条件に用いていない。
保存側の元局面は6生成ファイルとバイト単位で照合し、生成コミット、重み、シード、対局番号で由来を識別した。

提案手はFMとPSTそれぞれ100,000ノードで固定した。
教師の親探索は100,000、1,000,000、10,000,000ノードであり、全予算の最善手と2提案手の和集合を比較対象にした。
重複を除いた同じ候補集合の各子局面を、全予算で独立に探索した。
各探索は1スレッド、置換表64 MBとし、置換表を毎回作り直した。
局面ファイルには完全な対局履歴がないので、復元した局面から新しい対局を始めている。

主指標は親視点のD=T(PST選択手)−T(FM選択手)で、正なら教師はPSTの選択手を高く評価する。
同じ手ならD=0とし、詰み、終局、深さ0の未完了探索はセンチポーン差に混ぜない。
子探索の符号を親視点へ反転し、詰み距離には候補手の1手を加えた。
比較集合の最大値は全合法手の最善値を意味せず、PST教師自体も真値ではない。

## 結果

10,000,000ノードでのDの平均は保存側15.875、実戦側40.750センチポーンだった。
各側8局面のうち5局面でDが正であり、残る3局面は提案手が同じため0だった。
すべて通常のセンチポーン比較が可能であり、詰み・終局・未完了探索による除外はなかった。
各側とも8対局から1局面ずつなので、局面等重みと対局等重みの平均は一致する。

| 教師ノード数 | 保存側の平均D | 実戦側の平均D | 保存側の正／零／負 | 実戦側の正／零／負 |
|---|---:|---:|---:|---:|
| 100,000 | 13.500 | 16.250 | 4／3／1 | 4／3／1 |
| 1,000,000 | 11.875 | 30.250 | 3／5／0 | 5／3／0 |
| 10,000,000 | 15.875 | 40.750 | 5／3／0 | 5／3／0 |

Dの単位はセンチポーンである。
10,000,000ノードで100センチポーン以上の正の差は実戦側の1局面だけで、その差は109センチポーンだった。
保存側の最大差は37センチポーンであり、負方向に100センチポーン以上の差はなかった。
これらは100,000ノードで改めて生成した提案手の比較であり、実戦棋譜に記録された着手そのものの評価ではない。

| 教師予算の変更 | 厳密な正負反転 | 0と非0の変化 | 最上位手集合の変化 | 比較可能局面 |
|---|---:|---:|---:|---:|
| 100,000 → 1,000,000 | 2 | 2 | 8 | 16 |
| 1,000,000 → 10,000,000 | 0 | 2 | 5 | 16 |

最上位手の集合には同点を含む。
1,000,000から10,000,000ノードで厳密な正負反転は消えたが、最上位手集合の変化は保存側2局面、実戦側3局面に残った。
事前の条件に従い、教師が安定したとは判定せず、本標本への拡大を止めた。

同じ16局面の静的FM補正は、保存側で平均−3.250、実戦側で平均+962.625センチポーンだった。
この値はmanifestのsource_indexで前回の静的診断を照合し、eval−eval_pstとして計算した。
大きな静的補正と、選択手間の教師評価差は異なる量であり、今回の結果から前者を同じ大きさの悪手選択と解釈することはできない。
実戦側の平均Dは保存側より大きいものの、各側8局面、共通5層、PST教師への依存と残る順位変化のため、敗因の確定や母集団への一般化はしない。

正式測定の179探索は合計547,100,000ノードで、所要時間は331.24秒だった。
すべてノード上限で終了し、子探索の完了深さは100,000ノードで3～6、1,000,000ノードで5～9、10,000,000ノードで7～12だった。
実行環境はLinux x86_64、rustc 1.98.0である。

## 判断

FM不採用は既存の自己対局測定に基づく判断として維持する。
今回は棋力の採否測定ではなく、PST教師を深くするだけでは判定の安定性を十分に確保できなかった診断として完了する。

次の最小実験は、再学習せずFM補正を1/4に縮めた1候補を作り、元FMと同一条件の短時間自己対局で比較することである。
重み形式の指数を1増やせば、整数の切り捨てを伴って補正を1/4にでき、固定PST、評価尺度、駒価値、探索コードを保てる。
これは補正の振幅に直接介入する実験であり、教師の順位を正解と仮定せずに棋力への効果を調べられる。
改善しても分布外での誤差と探索との不整合は区別できず、PSTを上回ることも意味しない。
採用には改めてPSTとの短時間・長時間の逐次検定が必要であり、今回の診断では縮小モデルの作成と対局は実施していない。

## 再現手順

元リポジトリのfm-eval worktreeで実行した。
`FM_DIAG_ROOT`は元リポジトリの絶対パス、`FM_DIAG_PY`は既存の学習用仮想環境である。
出力先は未使用のディレクトリを指定する。

```sh
FM_DIAG_ROOT=/home/stepney141/board-games/minase
FM_DIAG_PY="$FM_DIAG_ROOT/tools/train/.venv/bin/python"
git show b0153cf27df655a32cb9a255fd380b21bba002b5:nets/pst.bin > /tmp/fm-teacher-base.bin
"$FM_DIAG_PY" tools/train/pst/fm_teacher_diagnostics.py prepare \
  --diagnostics-root "$FM_DIAG_ROOT/data/fm-search-diagnosis" \
  --archive-run "$FM_DIAG_ROOT/data/fm-eval-archive/fm-cand-lam1e-4" \
  --candidate nets/pst.bin --baseline /tmp/fm-teacher-base.bin \
  --output-dir data/fm-teacher-reproduction \
  --seed 1 --per-cohort 64 --pilot-per-cohort 8
cargo build --offline --release --bin fm_teacher_probe
/usr/bin/time -o data/fm-teacher-reproduction/pilot.time \
  target/release/fm_teacher_probe \
  --positions data/fm-teacher-reproduction/pilot.mnsd \
  --candidate-pst nets/pst.bin \
  --teacher-pst data/fm-teacher-reproduction/teacher-pst.bin \
  --proposal-nodes 100000 --teacher-nodes 100000,1000000,10000000 \
  --hash-mb 64 > data/fm-teacher-reproduction/pilot.jsonl
"$FM_DIAG_PY" tools/train/pst/fm_teacher_diagnostics.py analyze \
  --manifest data/fm-teacher-reproduction/manifest.json \
  --results data/fm-teacher-reproduction/pilot.jsonl \
  --sample-kind pilot --output data/fm-teacher-reproduction/report.json
```

数値と検査和は[機械可読記録](fm-teacher-diagnosis.json)に保存した。
生出力、標本、教師、manifest、execution.jsonは元リポジトリの`data/fm-teacher-diagnosis/`に保存し、`checksums.json`で照合できる。
準備時の来歴と実行コマンドは保存済みmanifestとexecution.jsonにある。
探索の各出力行がモデル2個と局面入力のSHA256を持ち、集計時にmanifestとの一致を検査する。
同一シードの再準備で標本と教師のバイト一致を確認し、16局面の1,000・2,000ノード再実行では時間以外の全出力が一致した。

## 検証

Rustの618テスト、Pythonの76テスト、フォーマット、全ターゲットのClippyが通過した。
独立レビューで符号、詰み距離、終局、候補集合、層合わせ、入力照合、および比較不能値の扱いを確認した。
通常の探索・評価コードと採用モデルは変更していない。

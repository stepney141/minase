# hachu-grid-fixed1-2

## 目的

HaChu対minaseの条件格子測定（[設計書](../plans/hachu-condition-grid.md)）の1手固定時間セルとして、minaseを1手1秒の秒読み、HaChuを1手2秒の固定時間（`st 2`）で対局させ、「この条件ではHaChuが明確に強い」という利用者の仮説を固定200ペアのEloで確かめる。
採否の判定には使わない。

## コマンドライン

```console
match_runner --run-dir data/matches/hachu-grid-fixed1-2 --seed 20560903 \
  --candidate commit:156816d --candidate-limit time=0+0,byoyomi=1000 \
  --baseline "cecp:../hachu-debian/hachu" --baseline-limit time=0+0,byoyomi=2000 \
  --rules L1,L3,P0,P5,P6,R2,E1,E2 --concurrency 12 elo --pairs 200
```

`match_runner`は、CECPエンジンへ秒読みだけの時間制御を`st`として伝える対応を加えたコミット67679b2を固定したworktreeでビルドしたバイナリ（SHA-256 `014796f572b856cb04b8424145f666b3abc044c43e297c4f2bcd9b99400d9d1e`）である。
候補と基準の時間制御が異なるため`match_report`は使えず、標準出力の要約を記録の値とし、累計実行時間は`summary.json`の`active_wall_time_ns`を使う。

## エンジン

候補は補間PST採用後のminaseのコミット`156816d6b3e1624e5e7809436842c1e2315824e8`（バイナリのSHA-256 `6466f222c57b46fcba082492d25b17ef3273e9d406e13f6173fca947b465cc3a`）であり、`Threads`は1である。
基準はHaChu（Debianパッケージ収録のオリジナル版、コミットdf26f4a、`../hachu-debian`で`gcc -O2`によりビルド）であり、規則オプションは既定設定（“Okazaki rule” 無効、“Promote on entry” 有効、“Allow repeats” 無効）である。
規則セットは審判層とminase側の双方に`L1,L3,P0,P5,P6,R2,E1,E2`を与えた。
シードは[time1](hachu-grid-time1.md)と同じ20560903であり、開始局面は同じ200個である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ33,218,965,504バイト）、OSはLinuxである。
候補の`Threads`は1、HaChuはワーカー数を報告しない。
`USI_Hash`は256 MB、HaChuの`memory`は256 MB、同時対局数は明示の12、手数上限は4,096手、応答タイムアウトは120秒である。
時間制御は候補が`go btime 0 wtime 0 byoyomi 1000`、基準が起動時`st 2`と毎手`time 200`（センチ秒）である。
HaChuは`st`のとき`time`の0.4倍（0.8秒）を目標とし、0.16倍（0.32秒）を超えたら新しい反復深化を始めず、0.98倍（1.96秒）で探索を中断する。
測定中に他の対局、生成、学習は走らせていない。

## 結果

200ペアを実行し、有効ペア200、破棄ペア0であった。
ペンタノミアル度数は[12, 0, 87, 0, 101]、Eloの点推定は+166.2（95%信頼区間+131.4〜+204.5）であった。
不正着手、応答タイムアウト、および拒否着手は0件、クラッシュは1件、`time_forfeits`は12件である。
累計実行時間は8,615秒、1局の実時間の中央値は238秒である。

実際の1手あたりの思考時間は、minaseが中央値0.51秒、平均0.55秒、最大0.92秒で、1秒を超えた手はない。
HaChuは中央値0.56秒、平均0.68秒、最大2.17秒で、81,585手のうち12手が2秒を超えた。
`time_forfeits`12件はすべてこの12手であり、超過は1〜168 ms（2,000〜2,168 ms）である。
HaChuの中断上限1.96秒と時間切れ判定2秒の余裕が40 msしかなく、探索の中断検査の粒度と入出力の遅延がそれを超えた局である。
クラッシュ1件（ペア169第2局）はHaChuが2,002手目で落ちたもので、hachu.cの棋譜配列上限`MAXMOVES 2000`による既知の挙動である。
13件はいずれもHaChuの負けとして算入した。

13局をすべてHaChuの勝ちへ振り替えた感度計算ではペンタノミアルは[16, 0, 92, 0, 92]、Elo +139.0、95%信頼区間+104.7〜+176.1である。
13局を引き分けとして扱った場合はペンタノミアルは[12, 4, 83, 9, 92]、Elo +152.4、95%信頼区間+118.5〜+189.3である。

## 結論

minase 1手1秒対HaChu 1手2秒の固定時間でも、minaseは+166.2 Elo（時間切れをすべてHaChuの勝ちに振り替えても+139.0 Elo）で明確に強く、「この条件ではHaChuが明確に強い」という仮説は支持されない。
minaseは秒読み1秒の約半分しか使っておらず、HaChuも2秒の約3分の1を目標に探索するので、実際の思考時間の比は約1:1.2にとどまる。

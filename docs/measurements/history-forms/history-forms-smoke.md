# historyの形の変更の候補の事前対局

## 目的

[historyの更新量の形とcontinuation historyの設計書](../../plans/history-forms.md)のフェーズ4として、STCの前に、SPSAの最終値を反映した候補が時間切れやエンジン異常を起こさないことと、時間の使い方の変化を確かめる。
32ペアの固定局数Eloは信頼区間が広く、強さの判定には使わない。

## コマンドライン

[統括計画](../../plans/search-forms.md)の決定により、SPSAを終えた調整機で、持ち時間を換算せずに実行した。
候補のコミットは、測定機で作った`git bundle`で調整機のcloneへ取り込んだ。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/history-forms-smoke --seed 3900000000 \
  --candidate commit:b06c8c9af4569c0789abcc5789a34387466e5cd0 \
  --baseline commit:58db4a5e50d24b60bc14b5e2b1343625385f6518 \
  --each time=10000+100 --concurrency 191 elo --pairs 32
```

実行ディレクトリは、終了後に測定機の`data/matches/history-forms-smoke`へ取得し、集計は測定機で次のコマンドで行った。

```console
data/spsa/history-forms-runner/minase match report \
  --run-dir data/matches/history-forms-smoke
```

## エンジン

候補は、[SPSAの記録](history-forms.md)の最終値を係数の表の既定値へ書き込んだコミット`b06c8c9af4569c0789abcc5789a34387466e5cd0`であり、調整機でビルドした実行ファイルのSHA-256は`23c8fe3f…`である。
起点は、サブタスク2の完了後のmasterの先頭`58db4a5e50d24b60bc14b5e2b1343625385f6518`であり、SHA-256は`43506663…`である。
runnerは、調整機で`b2cae818`をビルドした通常のminase（2.4.0、SHA-256`39fc5882…`）である。
規則セットは`engine-default`（`L0,P0,R1,E0`）、探索のワーカーは両者とも1、`USI_Hash`は既定の256 MBである。

## 環境

調整機は、[SPSAの記録](history-forms.md)と同じvast.aiのインスタンス56723270（AMD EPYC 9K84の2基構成、物理192コア、論理384スレッド、ベトナム）である。
この調整機の換算係数`f`（測定機の負荷時の速度÷調整機の負荷時の速度）は1.45であり、同じ持ち時間でも1手に読む局面は測定機より少ない。
同時対局数は191であり、32ペアの64局はすべて同時に指した。

## 結果

| 量 | 値 |
|---|---:|
| 有効ペア | 32（手数上限による破棄0） |
| ペンタノミアル度数 | [6, 0, 11, 2, 13] |
| 正規化した平均得点 | 0.625 |
| Elo | +88.7 |
| 95%信頼区間 | [−2.2, +193.7] |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 358.8秒（`summary.json`の累計） |
| 1局の最大常駐メモリ | 777,089,024バイト |

値は`minase match report`が保存記録から再計算した集計による。
32ペアの固定局数Eloは信頼区間の幅が約196 Eloあり、強さの判定には使わない。

時間の使い方は次のとおりである。
総思考時間と終局時の残り時間は、`pairs/`に保存された各手の思考時間から計算した。終局時の残り時間は、持ち時間に1手の加算を着手数だけ足し、思考時間の合計を引いた値である。

| 量 | 候補 | 起点 |
|---|---:|---:|
| 総思考時間 | 2,068.3秒 | 2,058.6秒 |
| 着手数 | 15,425 | 15,415 |
| 1手の平均思考時間 | 134.1 ms | 133.5 ms |
| 終局時の残り時間の中央値 | 1,423 ms | 1,407 ms |

候補と起点の総思考時間の比（候補÷起点）は1.005である。

手数帯ごとの完了深さ（反復深化で読み終えた深さの平均）と思考時間の中央値は、`scripts/clock_profile.py`を`--role candidate`と`--role baseline`で別々に実行して集計した。

| 手数帯 | 候補の完了深さ | 起点の完了深さ | 候補の思考時間の中央値 | 起点の思考時間の中央値 |
|---|---:|---:|---:|---:|
| 0〜49 | 13.12 | 12.89 | 121 ms | 92 ms |
| 50〜99 | 12.50 | 12.76 | 122 ms | 102 ms |
| 100〜149 | 12.46 | 12.52 | 122 ms | 112 ms |
| 150〜199 | 12.36 | 12.07 | 112 ms | 122 ms |
| 200〜299 | 12.07 | 11.83 | 122 ms | 142 ms |
| 300〜399 | 11.95 | 12.12 | 132 ms | 142 ms |
| 400以降 | 13.72 | 12.87 | 92 ms | 92 ms |

探索を止めた理由の内訳は、候補では上限の時間による停止が25手（0.16%）、目安の時間による停止が15,400手、起点では上限の時間による停止が33手（0.21%）、目安の時間による停止が15,382手だった。
完了深さは全体の平均で候補12.63、起点12.40である。
`clock_profile.py`が出す時間予算の比と上限の超過量は、起点の係数の予算式に基づくので、候補の時間の使い方の解釈には使わない。

## 結論

候補は、時間切れとエンジン異常を起こさなかった。
総思考時間は起点とほぼ同じで、終局時の残り時間も近い。
候補は序盤に思考時間を多く使い、中盤以降は起点より少なく使った。
設計書の手順どおり、同じ調整機で逐次検定のSTCへ進む。

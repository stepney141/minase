# historyの形の変更の候補のSTC

## 目的

[historyの更新量の形とcontinuation historyの設計書](../../plans/archived/history-forms.md)のフェーズ5として、SPSAの最終値を反映した候補と起点を、短時間条件STCの逐次検定で対局させ、強さの変化を記録する。
[統括計画](../../plans/search-forms.md)の決定により、本書の変更はこの判定によらず採用し、LTCは行わない。
この記録は、統括計画のフェーズ10で7本を通して強くなっていなかった場合に、どのサブタスクで後退したかを調べる手がかりにする。

## コマンドライン

統括計画の決定により、SPSAを終えた調整機で、持ち時間を換算せずに実行した。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/history-forms-stc --seed 3950000000 \
  --candidate commit:b06c8c9af4569c0789abcc5789a34387466e5cd0 \
  --baseline commit:58db4a5e50d24b60bc14b5e2b1343625385f6518 \
  --each time=10000+100 --concurrency 191 gsprt --max-pairs 3000
```

実行ディレクトリは、終了後に測定機の`data/matches/history-forms-stc`へ取得した。

## エンジン

候補は、[SPSAの記録](history-forms.md)の最終値を係数の表の既定値へ書き込んだコミット`b06c8c9af4569c0789abcc5789a34387466e5cd0`であり、[事前対局](history-forms-smoke.md)と同じ実行ファイルである。
起点は、サブタスク2の完了後のmasterの先頭`58db4a5e50d24b60bc14b5e2b1343625385f6518`である。
runnerは、調整機で`b2cae818`をビルドした通常のminase（2.4.0、SHA-256`39fc5882…`）である。
規則セットは`engine-default`（`L0,P0,R1,E0`）である。

## 環境

調整機は、SPSAと同じvast.aiのAMD EPYC 9K84の2基構成（インスタンス56723270、物理192コア、論理384スレッド、runnerが記録した論理CPUは368、ベトナム）である。
この機械の1コアは測定機（Intel Core Ultra 7 265KF）より遅く、負荷時の速度の比`f`は1.45である（[事前確認の記録](history-forms-safety.md)）。持ち時間は換算していないので、1手の探索量は測定機の同じ条件より少ない。
候補と起点はいずれも`Threads=1`、`USI_Hash`は各256 MB、同時対局数は191である。
手数上限は4,096手、応答タイムアウトは120秒、仮説はH0がelo=0、H1がelo=10、α = β = 0.05である。
2026年10月20日5時50分ごろから6時4分ごろまで実施した。
STCを終えた後、調整機を削除した。作成からの費用は約17.1米ドル（約9.1時間 × 1時間約1.89米ドル）であり、時間切れの事前確認、SPSA、事前対局、およびSTCの合計である。見込みの所要時間が上限を超えて削除した1台目の約0.35米ドルを含めると、約17.5米ドルである。

## 結果

| 量 | 値 |
|---|---:|
| 判定 | `H1` |
| 判定までのペア | 221（有効218、手数上限到達による破棄3） |
| ペンタノミアル度数 | [24, 6, 105, 13, 70] |
| LLR | +2.956 |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 512.6秒（`summary.json`の`active_wall_time_ns`） |

有効218ペアの度数から求めた候補の平均得点は0.614であり、Eloに直すと約+80、正規化したペア得点の分散から求めた95%信頼区間はおよそ+50〜+112である。
逐次検定は境界を越えた時点で止まるので、この点推定は真の差より大きめに出やすい。固定局数の推定ではなく、採否にも使わない。
保存されたペアは番号1〜739のうち701個であり、判定の時点で並行して進んでいた番号222以降のペアは統計に含まれていない。
標準出力の`elapsed`は808.6秒であり、`summary.json`の累計より長い。

## 結論

候補は、調整機で持ち時間を換算しないSTCで、起点より有意に強かった（`H1`）。
時間切れとエンジン異常は0件だった。
利用者の決定により、本書の変更はこの判定によらず採用し、LTCは行わない。
起点は[前の設計書](../../plans/archived/shallow-pruning-extensions.md)を採用した版であり、前の設計書のSTCは、さらに1つ前の版に対して約+17 Elo（`H1`）だった（[記録](../shallow-pruning-extensions/shallow-pruning-extensions-stc.md)）。
2つのSTCは条件と相手が違うので、Eloを足し合わせて元のmasterとの差とはしない。7本のサブタスクを通して元のmasterより強くなったかは、統括計画のフェーズ10で確かめる。

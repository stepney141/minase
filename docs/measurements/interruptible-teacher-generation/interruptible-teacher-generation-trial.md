# 中断可能インスタンスとオンデマンドでの教師生成の比較

## 目的

[中断可能な計算機での教師生成の設計書](../../plans/archived/interruptible-teacher-generation.md)のフェーズ2として、計算機を時間単位で借りられる市場vast.aiの2つの借り方で教師ファイルを生成し、費用対効果を比べて標準の借り方を決める。
中断可能インスタンス（interruptible instance、一般にはspot instanceと呼ぶ）は、入札で安く借りる代わりに、より高い入札が入るといつでも止められる借り方である。
オンデマンドは、表示の時間単価で借り、貸し手が止めない借り方である。
教師ファイルは、手元の作業機で動く制御スクリプトが、vast.aiで借りた機械（生成機）の上で教師生成の生成器`minase data selfplay generate`を動かして作る。
生成器は7,500局の教師ファイルを250局ずつの塊に分けて確定させ、制御スクリプトは確定した塊を60秒おきに作業機へ回収するので、生成機が止められても回収済みの塊から別の機械で続きを生成できる。
費用対効果の主な指標は、受け入れの検査に通った記録局面1億あたりの総費用（米ドル）である。
記録局面は、教師ファイルに学習用として記録された局面である。
補助の指標として、1時間あたりの記録局面で表した実効の生成速度と、そこから換算した1世代37本の生成時間を併記する。

設計書は、2つの借り方で同じ10本ずつを生成すると定めていた。
中断可能インスタンスで6本を受け入れた時点で、利用者が、20本すべてを生成しなくても比べられると判断した。
そこで、中断可能インスタンスの実行は6本で止め、オンデマンドの費用は新たに借りずに、止められずに生成した区間の実測から時間単価の関数として求めた。
オンデマンドでは中断が起きないので、費用は時間単価と生成時間でほぼ決まるからである。

## コマンドライン

作業機で、制御スクリプト`scripts/vast/teacher_generation.py`を`systemd-run --user`のサービスとして次の引数で起動した。

```sh
python3 scripts/vast/teacher_generation.py run --run-dir <実行ディレクトリ> \
  --repo <本体のチェックアウト> --ref master --commit 29ef0099822bf44593d3293d5175666aaf4cac4d \
  --minase-bin <worktreeでビルドしたminase> --generation 0 --first-book 0 --last-book 9 \
  --seed-base 9701000000 --seed-book-step 100000 \
  --games 7500 --nodes 20000 --random-moves 0 --max-ply 4000 --hash-mb 16 --chunk-games 250 \
  --rental interruptible --max-price 2.1 --deadline 2026-11-14T17:36:23Z --max-cost 12 --max-rentals 11
```

6本目の教師ファイル（番号5）を受け入れた直後に、サービスの主プロセスへ`systemctl --user kill --kill-whom=main --signal=SIGTERM`で終了シグナルを送り、最後の回収と削除の確認を行わせた。
総費用は実行の前と後の口座の残高の差であり、実行中にほかの用途でvast.aiを使わなかった。
削除した機械の課金は数分遅れて残高に反映されるので（[復旧試験](interruptible-teacher-generation-recovery.md)）、残高は値が変わらなくなるまで待ってから読んだ。

## エンジン

制御スクリプトはブランチ`interruptible-teacher-generation`のコミット`d35b3874`、生成器はmasterのコミット`29ef0099822bf44593d3293d5175666aaf4cac4d`を各生成機でビルドしたものである。
規則セットは、生成器が固定する、日本中将棋連盟の規則に基づく`JCSA`（`L0,P0,R1,E0`）、教師の評価関数は埋め込みのNNUE（着手ごとに差分で更新できる小さなニューラルネットの評価関数）である。

## 環境

2026年11月14日の07:36から10:24（UTC）まで、vast.aiの中断可能インスタンスを最低入札額で借りた。
制御スクリプトは、EPYC 7B13かEPYC 9654で256スレッド以上の出品から、時間単価を見込みの探索速度で割った値の最も小さい出品を選ぶ。
入札額は、出品の最低入札額`min_bid`を0.0001米ドル単位で切り上げた値である。

|---|---|---|---|---:|---:|---|---|---|---|
| 1 | 58999800 | EPYC 7B13 | 米国ネバダ州 | 0.5334 | | 07:36:26 | | 07:36:30 | 作成の失敗 |
| 2 | 60504797 | EPYC 7B13 | カナダ・ケベック州 | 0.7467 | 0.7511 | 07:36:33 | 07:40:37 | 07:46:18 | 止められた |
| 3 | 57566278 | EPYC 7B13 | カナダ・ケベック州 | 0.8267 | | 07:46:22 | | 07:46:25 | 作成の失敗 |
| 4 | 60504797 | EPYC 7B13 | カナダ・ケベック州 | 0.8800 | 0.8844 | 07:46:27 | 07:50:14 | 07:59:58 | 止められた |
| 5 | 57084870 | EPYC 7B13 | ノルウェー | 1.0134 | 1.0245 | 08:00:00 | 08:12:39 | 10:23:59 | 終了シグナル |

時刻はUTC、入札額と時間単価は米ドル/時である。
時間単価は作成の直後に照会したインスタンスの`dph_total`で、入札額にストレージの料金を足した値である。
1回目と3回目は、作成の要求に`{"error": true, "status_code": 410, "msg": "error 410/3907: no_such_ask  Instance type <出品> is no longer available."}`が返り、インスタンスは作られなかった。
制御スクリプトはその出品を選ばないようにして、次の出品を借りた。
4回目は、2回目と同じ出品であり、最低入札額が0.7467米ドルから0.88米ドルに上がっていた。
借りた3台は、いずれも`cpu-info`のcpusetのスレッド数が256、cgroupのCPUの上限が245.76 CPU分で、出品の表示どおりのスレッド数を使えるかを確かめる借りた後の検査に通った。

## 結果

### 中断と移行

実行の2.792時間のうちに、借りた機械が2回止められた。
2回とも、観測した状態は`actual_status`が`exited`、`intended_status`、`cur_state`、および`next_state`が`stopped`であり、作業機から停止を要求した[復旧試験](interruptible-teacher-generation-recovery.md)の状態と同じであった。

| 回 | 作成から止まったことの検知まで | 生成の開始から検知まで | 検知から次の機械で生成を始めるまで | 失った計算の推定値 |
|---|---:|---:|---:|---:|
| 2 | 9分43秒 | 5分39秒 | 3分58秒 | 964局 |
| 4 | 13分28秒 | 9分41秒 | 12分44秒 | 1,216局 |

止まったことの検知は、2回続けて稼働中でない状態を観測した時点なので、実際に止められたのはその1〜2分前である。
失った計算の推定値は、その機械で終えた対局数から確定させて回収した塊の局数を引き、同時対局数256の半分を足した値であり、2回の合計の2,180局は教師ファイル約0.29本分に当たる。
4回目から5回目への移行が長いのは、5回目の機械がイメージの取得に約6分かかったからである。
5回目の機械は、2時間23分59秒の間止められず、教師ファイル0の残りと教師ファイル1〜5を生成した。
教師ファイル0は、4回目の機械が確定させた塊3組を5回目の機械が引き継いで完成させた。

### 生成と費用

| 項目 | 値 |
|---|---:|
| 受け入れた教師ファイル | 6本（番号0〜5） |
| 記録局面 | 16,762,644 |
| 実行の時間（最初の作成から最後の削除の確認まで） | 2.792時間 |
| 総費用（残高の差） | 2.668米ドル |
| 制御スクリプトが記録した費用の見込み | 2.784米ドル |
| 記録局面1億あたりの総費用 | 15.92米ドル |
| 実効の生成速度 | 毎時約600万記録局面（1本あたり27.9分） |
| 1世代37本の換算 | 約17.2時間、約16.5米ドル |

6本はすべて受け入れの検査に通った。
1世代37本の換算は、実行の時間と総費用を本数に比例させた値である。
5回目の機械で続けて生成した教師ファイル1〜5の受け入れの間隔は、平均21.97分であった。

### オンデマンドの費用の算出

オンデマンドの機械で10本を生成する時間を、作成から生成の開始までの約4.7分（0.08時間、復旧試験の2回の平均）と、止められなかった区間の1本あたり21.97分の10本分の和として、3.742時間と見積もる。
記録局面は、今回の6本の平均である1本あたり2,793,774とする。
時間単価をp米ドル/時とすると、記録局面1億あたりの総費用は約13.39p米ドルになる。
今回の中断可能インスタンスの15.92米ドルと等しくなるのは、pが約1.19米ドルのときである。

| オンデマンドの時間単価 | 出品と観測した時刻 | 記録局面1億あたり | 1世代37本の換算 |
|---:|---|---:|---:|
| 1.055米ドル | EPYC 7B13、英国、04:57〜05:04 | 約14.1米ドル | 約13.6時間、約14.4米ドル |
| 1.601米ドル | EPYC 7B13、カナダ・ケベック州、10:24 | 約21.4米ドル | 約13.6時間、約21.8米ドル |
| 2.002米ドル | EPYC 7B13、ノルウェー、06:20と10:24 | 約26.8米ドル | 約13.6時間、約27.3米ドル |

1.055米ドルの英国の7B13機は、[フェーズ0](interruptible-teacher-generation-candidates.md)で借りた後の検査に通ったが、06:20の検索では出品になかった。
1.601米ドルのケベック州の7B13機は、10:24の検索で初めて見つけた出品であり、借りた後の検査に通るかは確かめていない。
06:20と10:24の検索で、機種の条件を満たす7B13機のオンデマンドの出品のうち最も安かったのは1.335米ドルのネバダ州の機械であるが、この機械は[復旧試験](interruptible-teacher-generation-recovery.md)で借りた後の検査に落ちたので、表に含めない。
10:24の検索では、カナダ・ブリティッシュコロンビア州のEPYC 9654の384スレッド機が1時間1.006米ドルで出ていたが、借りた後の検査に通るかと、実際の生成の速さは確かめていない。

## 結論

今回の時間帯では、中断可能インスタンスの記録局面1億あたりの総費用は15.92米ドルであり、実行の前後に出ていたオンデマンドの7B13機（1時間1.601〜2.002米ドル）で算出した約21.4〜26.8米ドルの約0.59〜0.74倍であった。
中断可能インスタンスの1世代37本の換算は約17.2時間で、設計書が再検討の条件とした24時間に収まった。
したがって、標準の借り方は中断可能インスタンスとし、入札額は借りる時点の最低入札額とする。

ただし、オンデマンドの時間単価が約1.19米ドルを下回る出品があれば、オンデマンドの方が安くなる。
朝に出ていた英国の7B13機（1時間1.055米ドル）では約14.1米ドルとなり、中断可能インスタンスより約11%安かった。
中断は最初の約24分に2回起きた後、2時間24分起きなかったので、中断の頻度は時間帯と入札の競合に左右されると考えられ、1回の約2.8時間の観測からは推定できない。
この決定は、2026年11月14日の観測に基づく暫定のものである。

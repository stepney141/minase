# Lazy SMP初版のThreads=2対1の時間制御GSPRT

## 目的

初版の探索チームで既定ワーカー数だけを2へ変えた候補が、ワーカー数1の基準より時間制御で有意に強いかをGSPRTで判定する。

## コマンドライン

```console
match_runner --seed 20260822 --candidate commit:5f1f74b --baseline commit:90c1dd1 --each time=10000+100,byoyomi=200 --concurrency 8 gsprt
```

当時の`match_runner`には`--run-dir`がなく、実行ディレクトリは残っていない。

## エンジン

候補は測定用ブランチ`lazy-smp-threads2`のコミット5f1f74b（90c1dd1から`DEFAULT_THREADS`だけを2へ変更）、基準はコミット90c1dd1である。
規則セットはコマンドラインに指定がなく、記録なし。

## 環境

Intel Core Ultra 7 265KF（物理20コア、論理20コア、SMTなし）。
候補Threads=2、基準Threads=1。
`USI_Hash`は既定の256MB。
同時対局数8（8×2=16コアを使用）。

## 結果

開始から約55分の時点で有効81ペア、ペンタノミアル[14, 1, 51, 0, 15]、LLR −0.003、判定保留であり、ペア得点の平均0.503はElo換算で約+2、95%信頼区間はおよそ±45であった。
真のElo差が0付近であれば判定までの期待ペア数は約13,000（約1.5ペア/分で150時間超）になるため、継続せずに設計を改訂して再測定すると決め、約60分で測定を停止した。
停止時点の最終状態は有効92ペア、ペンタノミアル[17, 1, 55, 0, 19]、LLR 0.031、判定保留、`engine_failures`全0、`time_forfeits` 0である。
破棄ペア数は記録なし。
経過時間は約60分（手動停止）。

## 結論

判定保留のまま停止した記録であり、初版の多様化（同一深さ列とルート回転）は時間制御の棋力に転化しないと判断して設計改訂へ戻った。

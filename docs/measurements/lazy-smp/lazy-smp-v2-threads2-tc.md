# Lazy SMP第2版のThreads=2対1の時間制御GSPRT

## 目的

第2版の探索チームで既定ワーカー数だけを2へ変えた候補が、ワーカー数1の基準より時間制御で有意に強いかを、上限500ペアのGSPRTで判定する。

## コマンドライン

```console
match_runner --seed 20260822 --candidate commit:93bccd9 --baseline commit:4ec0b1d --each time=30000+300,byoyomi=500 --concurrency 8 gsprt --max-pairs 500
```

`--run-dir`の記録はなく、実行ディレクトリは残っていない。

## エンジン

候補は測定用ブランチ`lazy-smp-v2-threads2`のコミット93bccd9（4ec0b1dから`DEFAULT_THREADS`だけを2へ変更）、基準はコミット4ec0b1dである。
規則セットはコマンドラインに指定がなく、コミット4ec0b1dの`match_runner`は省略時にengine-defaultを適用する。

## 環境

Intel Core Ultra 7 265KF（物理20コア、論理20コア、SMTなし）。
候補Threads=2、基準Threads=1。
`USI_Hash`は既定の256MB。
同時対局数8（8×2=16コアを使用）。

## 結果

2026年8月22日に開始し、2026年8月23日に上限500ペアへ到達して終了した。
有効495ペア、破棄5ペア（いずれも手数上限）、ペンタノミアル[71, 3, 254, 14, 153]、LLR 2.615、decision: pending、`engine_failures`全0、`time_forfeits` 0、経過44,348秒（約12.3時間）。
LLRはH1境界2.944に届かず判定保留である。
固定局数のEloは、正規化ペア得点の平均0.588、分散0.107から+62.1（95%信頼区間［+41.5, +83.0］）であり、信頼区間は0を大きく上回る。
初版の同一深さ補助ワーカーは同じ指標で92ペアでおよそ+2（±45）であった（[lazy-smp-threads2-tc.md](lazy-smp-threads2-tc.md)）。
測定中、手数上限に近い長い対局が最古の未報告ペアに当たるとハーネスが他の同時枠を空けたまま待つため、8枠のうち1枠だけが動く時間帯が数回あり、経過時間はその分長い。

## 結論

設計書の規定では500ペアの判定保留は不採用だが、固定局数の95%信頼区間が0を大きく上回り、LLRが上限到達時点で境界の近傍にあったことを根拠に、規定からの逸脱を明記したうえで採用した。

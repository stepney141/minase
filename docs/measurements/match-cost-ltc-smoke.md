# match-cost-ltc-smoke

## 目的

現行masterのコミットどうしを新しいLTC条件`time=60000+200`で10ペア対局させ、時間切れが起きないこと、1局の平均時間が約220秒の±20%に収まること、および各手数帯の平均到達深さがSTCの同じ手数帯を上回ることを確認する。

## コマンドライン

```console
match_runner --run-dir data/matches/match-cost-ltc-smoke --seed 2026500000 \
  --candidate commit:17cdd68 --baseline commit:17cdd68 \
  --each time=60000+200 elo --pairs 10
```

## エンジン

候補と基準はともにコミット17cdd68（H1=10へ変更した直後のmaster）、規則セットは`engine-default`である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）、候補と基準の`Threads`は1、`USI_Hash`は256MB、同時対局数は自動計算の19である。

## 結果

ペンタノミアル度数は[5, 0, 2, 0, 2]、Eloの点推定は−120.4（95%信頼区間−458.6〜+70.5）であった。
同一コミットどうしなので点推定に意味はなく、時計の整合の確認だけに用いる。
破棄ペアは1（ペア8の第2局が4,096手の手数上限に到達）、不正着手、クラッシュ、応答タイムアウト、`time_forfeits`、および拒否着手はすべて0件、経過時間は1,148秒である。

1局の平均時間は、20局全体では259秒、手数上限に達したペアを除く18局では224秒（平均542手）であり、約220秒の±20%（176〜264秒）に収まる。
手数上限に達した局は4,096手を935秒で完走し、加算0.2秒の下でも1手あたりの固定費が安全余裕の内側に収まることを示した。
同時対局数19と1局224秒から見込まれるLTCの処理能力は約150ペア/時であり、旧LTCの実測82ペア/時のおよそ1.8倍である。

`scripts/clock_profile.py`による手数帯ごとの平均到達深さは次のとおりである（比較対象は同じ手順で集計した旧LTC strength-stage1-final-ltc とSTC strength-stage1-final-stc）。

| 手数帯 | 新LTC（60000+200） | 旧LTC（60000+600） | STC（10000+100） |
|---|---|---|---|
| 0〜49手目 | 7.38 | 8.15 | 6.41 |
| 50〜99手目 | 6.60 | 6.71 | 4.98 |
| 100〜149手目 | 6.46 | 5.87 | 4.20 |
| 150〜199手目 | 6.37 | 5.87 | 4.25 |
| 200〜299手目 | 6.33 | 6.27 | 4.61 |
| 300〜399手目 | 6.58 | 7.03 | 5.25 |
| 400手目以降 | 10.18 | 11.11 | 8.17 |

新LTCの1手の思考時間の中央値は0〜49手目で720ms、400手目以降で183ms、着手前の残り時間の中央値は300手目以降で約1,150msであり、停止理由はsoft limitが約85%、hard limitが約15%であった。
旧LTCとSTCの記録には停止理由がなく、比較できない。

## 結論

時間切れ、エンジン異常、および拒否着手は0件、1局の平均時間は224秒（手数上限の局を含めて259秒）、到達深さは全手数帯でSTCを上回ったため、加算0.2秒のLTCを採用する。

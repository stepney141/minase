# 1回目の強化学習のネットと深さ3のHaChuの対局による基準

## 目的

中将棋エンジンminaseのMCTSは、ニューラルネットワーク（以下、ネット）で局面を評価するAlphaZero型のモンテカルロ木探索であり、ネットは自己対局と学習を繰り返すサイクルごとに更新する。
[強さを測る固定の相手の設計書](../../plans/archived/mcts-fixed-opponents.md)のフェーズ3として、1回目の強化学習のサイクル10、20、および32のネットを使うMCTSを、探索の深さを3に固定した中将棋の外部エンジンHaChuと100ペア（先後を入れ替えた2局を1ペアとする）ずつ対局させ、2回目の学習の測定値と比べる基準のEloを求める。
あわせて、もう1つの固定の相手であるminaseのαβ探索とHaChuの2つに対する3つのネットのEloを並べ、1回目の学習で10サイクル前の自分のネットとの対局に見えた伸びが、固定の相手に対しても現れていたかを確かめる。
深さ3は、[深さの選定](mcts-fixed-opponents-hachu-depth.md)で得点率が5割に最も近かった深さである。ただし、どの深さでも、手数の上限による破棄やHaChuの反則を含むペアの割合が設計書の上限の5%を超えたので、2026年11月14日の利用者の決定で、固定したαβ探索を主な指標とし、HaChuとの対局は副次の指標になった。

## コマンドライン

測定日は2026年11月14日である。
[固定の相手との対局のスクリプト](mcts-fixed-opponents-scripts/)の`run_match.py`を、作業機のリポジトリのルートで、次のように3回実行した。
`<c>`は`0010`、`0020`、`0032`であり、この順に続けて実行した。ハーネスはシードから乱択で各ペアの開始局面を作るので、同じシードで対局した3つのネットの開始局面の列は同じである。
シードは深さの選定とは別の値にし、深さを選んだ開始局面の列と重ならないようにした。

```console
source tools/train/zero/env.sh   # bashで実行する
export XDG_CACHE_HOME=$HOME/.cache
W=data/worktrees/mcts-fixed-opponents
python3 -I $W/docs/measurements/mcts-fixed-opponents/mcts-fixed-opponents-scripts/run_match.py hachu \
  --harness $W/target/release/minase --mcts-commit c1c84466476eb36cf43abc529792469862b8e856 \
  --net data/mcts-fixed-opponents/nets/cycle-<c>.onnx --hachu ../hachu-debian/hachu --depth 3 \
  --name mcts-fixed-opponents-hachu-baseline-c<c> --seed 20261113300000 --pairs 100 --concurrency 4
```

スクリプトが起動した対局ハーネス`minase match run`のコマンドは次のとおりである（`<net>`はネットのファイルの絶対パス）。

```console
data/worktrees/mcts-fixed-opponents/target/release/minase match run \
  --run-dir data/matches/mcts-fixed-opponents-hachu-baseline-c<c> --seed 20261113300000 \
  --candidate commit:c1c84466476eb36cf43abc529792469862b8e856 --candidate-args '--search mcts' \
  --candidate-option NnModel=<net> --candidate-option NnBatchSize=16 --candidate-limit nodes=800 \
  --baseline cecp:../hachu-debian/hachu --baseline-limit depth=3 --baseline-hash 256 \
  --rules L1,L3,P0,P5,P6,R2,E1,E2 --max-ply 1900 --concurrency 4 elo --pairs 100
```

この3回は、HaChuをどう扱うかの利用者の決定を待つ間に暫定として始め、深さ3を副次の相手とする決定の後もそのまま使った。対局の結果は条件だけで決まるので、始めた時点は値に影響しない。
MCTSの着手をHaChuが受け付けなかった拒否着手と、HaChuが審判層の合法手にない着手を指した不正着手は、スクリプトのディレクトリの`check_hachu_forfeits.py`で分類した（結果は[forfeits-c0010.json](mcts-fixed-opponents-hachu-baseline/forfeits-c0010.json)、[forfeits-c0020.json](mcts-fixed-opponents-hachu-baseline/forfeits-c0020.json)、[forfeits-c0032.json](mcts-fixed-opponents-hachu-baseline/forfeits-c0032.json)）。

## エンジン

測る側のエンジン（ハーネスの候補、`--candidate`）は、[固定したαβ探索との基準の記録](mcts-fixed-opponents-alphabeta-baseline.md)と同じく、masterのコミットc1c84466のMCTSに、各サイクルのネットを与えたものである。コミットの指定からハーネスがビルドしたバイナリのSHA-256は`60e6611ef44f6b23669be6da2164b21dce4c0ef383b218813086fd7ee06e7c36`、ネットのONNXのSHA-256は同じ記録の表のとおりであり、ハーネスが記録したチェックサムとも一致した。
思考の制限は1手800回のシミュレーションであり、方策の温度は既定の1.4である。

相手のエンジン（ハーネスの基準、`--baseline`）は、[深さの選定の記録](mcts-fixed-opponents-hachu-depth.md)と同じHaChu（Debianパッケージ収録のオリジナル版、コミットdf26f4a、`gcc -O2`によりビルド、バイナリのSHA-256は`10db1299f95626fe58875b1c24a1cee6acce0eee5fb42ed8b17ce1373a9dcbdf`）で、規則オプションは既定の設定である。
思考の制限は深さ3（HaChuの通信規約CECPのコマンド`sd 3`）、探索済みの局面を覚える置換表は`memory 256`（256 MB）である。接続の検証は、深さの選定の記録にある。

規則は、HaChuの既定の設定に対応する規則コードの組`L1,L3,P0,P5,P6,R2,E1,E2`（[競技規則](../../rules/chu-shogi.md)第33条第7項）を、ハーネスの審判層（対局を管理して合法手と終局を裁定する層）とMCTSの双方に与えた。手数の上限`--max-ply`は1,900手である。
対局のハーネスは、深さの選定と同じバイナリである。

## 環境

作業機（Intel Core Ultra 7 265KF、物理20コア、論理20コア、NVIDIA GeForce RTX 3060 Ti 8 GB、ドライバ615.78.08）で、ONNX Runtime 1.31.1とTensorRT 10.14.1を使った。
MCTSのUSIのオプションは、`Threads`が1、`NnBatchSize`が16、`USI_Hash`が既定の256 MB（MCTSは使わない）であり、推論はTensorRT（FP16）である。HaChuは探索のスレッド数を報告しない。
同時対局数は4、応答タイムアウトは120秒である。
同じ機械では、オンライン対局サイトlishogiのBotが通信対局を指していた。対局はシミュレーション数と深さの制限なので、この負荷は対局の結果に影響しない。

## 結果

全部の対局で、エンジンの異常終了、応答タイムアウト、および時間切れ（`time_forfeits`）は0件であった。
有効ペアは、手数の上限に達した対局を含むペア（破棄ペア）を除いたペアであり、HaChuの拒否着手と不正着手で終わった対局は、ハーネスの扱いのとおりHaChuの反則負け（MCTSの勝ち）として含む。表の得点率とEloは、有効ペアでのMCTSの値である。
ペンタノミアル度数は、有効ペアを、先後を入れ替えた2局のMCTSの得点（0、0.5、1、1.5、2）ごとに数えた度数である。
影響ペアは、破棄ペアか、HaChuの拒否着手または不正着手のあった対局を含むペアの、どちらかに当たるペアであり、表の割合は試行した100ペアに対する値である。
集計は`summarize.py`の出力（[summary.json](mcts-fixed-opponents-hachu-baseline/summary.json)）である。

|---|---|---|---|---|---|---|---|---|
| 10 | [97, 0, 3, 0, 0] | 1.5% | −727 | [−∞, −594] | 0 | 1 | 1.0% | 618 |
| 20 | [76, 0, 21, 0, 1] | 11.7% | −351 | [−441, −286] | 2 | 4 | 6.0% | 1,372 |
| 32 | [43, 0, 45, 0, 8] | 31.8% | −133 | [−187, −84] | 4 | 12 | 16.0% | 1,788 |

終局の内訳は次のとおりである。MCTSの勝ちは、HaChuの投了、HaChuの反則負け、およびサイクル32の1局のHaChuの着手不能（HaChuの手番に合法手がなかったことによる負け、審判層の終局理由`Stalemate`、[競技規則](../../rules/chu-shogi.md)第23条）であり、HaChuの勝ちはすべて王駒の捕獲である。
MCTSは、ハーネスが投了を無効にしているので投了しない。

|---|---|---|---|---|---|---|

### HaChuの拒否着手と不正着手

HaChuの反則負けは3つのサイクルの合計で17件あり、すべて、HaChuと審判層の反復の判定の既知の食い違いに分類された。
不正着手16件は、既出の局面を再現する着手を禁じる規則R2の下で、HaChuが反復の判定に直近の200局面しか使わないために、202手から344手前の局面を再現する着手を指したものであった（分類`history_window`）。
サイクル32のペア33の第1局の拒否着手1件は、351手目のMCTSのじっと（獅子が動かずに手番を渡す着手、USIの`10e11f10e`）を、HaChuが理由のない`Illegal move`で拒否したものである（分類`placement_only_repetition`）。
この着手の後の局面は、4手前の局面と駒の配置と手番が同じであった。審判層は、直前の着手で獅子以外の駒が獅子を取ったかどうかという先獅子の状態も局面の同一の判定に含めるので、別の局面として着手を認めたが、HaChuは駒の配置と手番だけで判定するので、既出の局面の再現として拒否した。
HaChuはじっとをCECPの`@@@@`として受け、`@@@@`の照合では反復による拒否でも理由を付けないので（`hachu.c` 2714行と2731〜2736行）、理由のない`Illegal move`になる。

## 結論

2つの固定の相手に対する1回目の学習の3つのネットのEloは、次のとおりである。
αβ探索の値は[固定したαβ探索との基準の記録](mcts-fixed-opponents-alphabeta-baseline.md)の値であり、HaChuの値は上の結果の表にある有効ペアのEloである。

| サイクル | αβ探索（500ノード、規則セット`lishogi`） | HaChu（深さ3） |
|---|---|---|
| 10 | −576 [−798, −478] | −727 [−∞, −594] |
| 20 | −135 [−187, −88] | −351 [−441, −286] |
| 32 | +17 [−31, +67] | −133 [−187, −84] |

点推定の差は、サイクル10から20で、αβ探索に対して+441、HaChuに対して+376であり、サイクル20から32で、αβ探索に対して+152、HaChuに対して+218であった。
1回目の学習で、各サイクルのネットを10サイクル前の自分のネットと対局させた伸びは、サイクル10に対するサイクル20が+199、サイクル20に対するサイクル30が+237であった（[サイクル20](../alphazero-rl/alphazero-rl-restart-progress-c0020.md)、[サイクル30](../alphazero-rl/alphazero-rl-restart-progress-c0030.md)）。
この値は、MCTSのコミットd673bc1f、規則`engine-default`（今の`JCSA`）、および1手800シミュレーション同士の200ペアで測ったものであり、本記録とは規則、MCTSのコミット、および終点のサイクル（30と32）が異なるので、差の大きさを直接比べることはできない。
それでも、サイクルが進むにつれて強くなる傾向は、2つの固定の相手に対しても現れていた。
サイクル20から32の伸び（+152と+218）は、10サイクル前の自分のネットとの対局で見えたサイクル20から30の伸び（+237）を下回り、サイクル10から20の伸び（+441と+376）は、同じ対局の+199を上回った。
ただし、サイクル10の得点率は、αβ探索に対して3.5%、HaChuに対して1.5%であり、サイクル10の値の信頼区間は広いので、サイクル10から20の差の大きさは粗い。

この3つのネットの2つの相手に対する値を、2回目の学習の測定値と比べる基準とする。
HaChuとの対局の影響ペアの割合は、ネットが強くなるにつれて1.0%、6.0%、16.0%と増えた。

# move-ordering-no358-vs-all-stc

## 目的

[手の順序付けの改善](../plans/archived/move-ordering.md)で採用した7候補の構成から、NPSを下げた候補3（静止探索の群内の捕獲履歴）、候補5（PST差分による同点破り）、候補8（history malus）を外した構成（候補1、2、4、7）と、全7候補の構成のどちらが強いかを、対称仮説のGSPRTによる直接対局で判定する。利用者の2026年10月10日の要望による帰属の確認であり、採用済みの構成を変える判断は利用者が行う。

## コマンドライン

```console
cargo run --release --bin minase -- match run \
  --run-dir data/matches/move-ordering-no358-vs-all-stc --seed 2100400000 \
  --candidate commit:a53aa14 --baseline commit:ea0c75a \
  --concurrency 16 --each time=10000+100 gsprt --elo0=-5 --elo1=5 --max-pairs 3000
```

## エンジン

候補はブランチ`move-ordering-no358`のコミット`a53aa14`（全7候補の構成`ea0c75a`から候補8、候補5、候補3のコミットを`git revert`で外したもの。候補3の取り消しは候補4が加えた引数との衝突を手で解消した）、基準は採用した全7候補の構成`ea0c75a`である。規則は`engine-default`（`L0,P0,R1,E0`）、`USI_Hash`は既定の256 MB。仮説は`--elo0=-5 --elo1=5`の対称仮説であり、`H1`は候補（候補1、2、4、7）が5 Elo以上強いこと、`H0`は基準（全7候補）が5 Elo以上強いことを意味する。

候補のbench深さ6は総ノード数646,422、NPSは段階開始版の1,915kに対して1,792k（−6.4%）であり、全7候補の構成（690,307、−12.4%）よりNPSの低下が半分ほど小さい。

## 環境

2026年10月10日から11日にかけて、Intel Core Ultra 7 265KF（物理20コア、論理20コア）で測定した。候補と基準のワーカー数は1、同時対局数は16（lishogi Botのminaseが2プロセス同居）。

## 結果

| 項目 | 値 |
|---|---:|
| ペア数 | 1,298（有効1,267、破棄31） |
| ペンタノミアル度数 | [289, 45, 647, 39, 247] |
| 候補（候補1、2、4、7）の得点率 | 48.2%（Elo換算で約−12） |
| LLR | −2.94 |
| 判定 | `H0` |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、`time_forfeits` 0、拒否着手0 |
| 経過時間 | 11,655秒（約3時間14分） |

LLRは195ペアで−0.29、360ペアで+1.02、784ペアで0.00と推移し、以後は基準側が勝ち越して1,267ペアで`H0`の境界を越えた。破棄31ペアは手数上限への到達による。

## 結論

候補3、5、8を外した構成は、短時間条件で全7候補の構成より約12 Elo弱く、NPSの低下を伴う3候補は差し引きで棋力に寄与している。採用した全7候補の構成を変える理由はない。3候補のうちどれが効いているかは本測定からは分からない。

# move-ordering-stack-bench

## 目的

[手の順序付けの改善](../plans/move-ordering.md)の候補を1候補1コミットで積み上げながら、各コミット直後の`bench`深さ6の総ノード数とNPSを記録し、全候補を積み上げた構成の探索量と速度の変化を説明する材料にする。

## コマンドライン

各コミットのリリースビルド（フィーチャなし）をCPU 3へ固定し、5回の計測反復の中央値を取った。

```console
cargo build --release --bin minase
taskset -c 3 target/release/minase dev bench --depth 6 --repetitions 5
```

## エンジン

ブランチ`move-ordering`の各コミット。段階開始版はmaster `b784fe5`であり、コードは`cd081f4`と同一である。規則は`engine-default`（`L0,P0,R1,E0`）、ワーカーは1、置換表は`bench`の既定の256 MBである。

## 環境

Intel Core Ultra 7 265KF（物理20コア、論理20コア）、`rustc 1.98.0`。lishogi Botのminaseが2プロセス同居しているので、NPSは参考値であり、1〜3%の揺れを含む。対局ではないので、ペンタノミアル度数、判定、破棄ペア数、異常件数、`time_forfeits`、経過時間は該当しない。

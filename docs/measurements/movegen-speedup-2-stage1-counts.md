# 段階1の処理件数診断（bench深さ5）

## 目的

第2期の段階2から段階9の見込みと閾値を定めるために、静止探索の初期化における対象升数、利き計算と走り計算の回数、対象升と交わらない利き線の方向数、対象升へ届く自駒数、置換表の照合の的中率、SEEの早期終了に該当する呼出し数、および静止探索ノードの終わり方を数え、各件数を独立した参照値と照合する。

## コマンドライン

診断は本番の経路へ入れず、[診断差分](movegen-speedup-2-stage1-counts/diagnostic.patch)を親コミットへ当てた別ターゲットディレクトリのビルドで数えた。診断ビルドの`bench`は経過時間とNPSを出力せず、速度の測定には使わない。

```console
git apply docs/measurements/movegen-speedup-2-stage1-counts/diagnostic.patch
CARGO_TARGET_DIR=target/diag cargo build --release --bin bench
target/diag/release/bench --depth 5 --threads 1 --repetitions 1 2> counts.log
```

局面別の生の件数は[counts.log](movegen-speedup-2-stage1-counts/counts.log)、合計は[totals.json](movegen-speedup-2-stage1-counts/totals.json)、実行環境は[environment.json](movegen-speedup-2-stage1-counts/environment.json)にある。

## エンジン

親コミット`008f6590f7e0620fbb75e0cb4e418d7491ba5bfc`（探索と生成のコードは第1期の採用版`7a41b2c`と同一）に診断差分を当てたものである。
`bench`は規則セット`engine-default`を固定で使い、総ノード数は1,268,607である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月16日に1スレッドで測った。件数は決定的であり、同時負荷の影響を受けない。

## 結果

### 参照との照合

各件数は次の独立した参照と毎ノード照合し、初期化に到達した468,981ノードすべてで一致した。
不一致は`std::process::abort()`で停止する設計であり、停止は起きなかった。

| 件数 | 参照 |
|---|---|
| 対象升数 | 相手駒を走査し、駒コードから直接引いた駒価値の閾値判定と王駒の条件で再構成した集合の大きさ |
| 対象升へ届く自駒数 | 特殊駒を除く自駒について`piece_control_with_occupancy`で独立に求めた利きが対象升と交わる駒の数 |
| 利き計算回数 | 到達範囲と対象升の交差を別の走査で数え直した値 |
| 走り計算回数（`sliding_control`内のカウンタ） | 利き計算ごとの動きの定義の走り方向数の和 |
| 対象升と交わらない方向数 | 利き線の表`AttackTables::ray`を直接引いて数えた値 |
| SEEの早期終了 | 該当する呼出しで参照実装`see_reference`が`Some(v)`かつ`v < 0`なら停止 |

局面ごとの恒等式（終わり方の分割の和がノード数に一致すること、対象升数ビンの和が初期化ノード数に一致することなど）も同時に検査した。

### SEEの早期終了

`see_prunes`の呼出し639,417件のうち、経由升つきの手と麒麟が獅子を取って成る手の除外を通過したのは573,562件である。
そのうち`g0 ≥ 0`かつ`M − C + d_max ≤ 0`（`d_max`は使用中の駒価値表の成り益の上限）を満たし、逆引きなしに「枝刈りしない」と判定できるのは71,069件（除外後の12.4%、全呼出しの11.1%）である。
該当する呼出しでは参照実装の値がすべて非負（71,069件）であり、`None`（規則依存）は0件、負の値は0件だった。

## 結論

段階2の対象である「利き線が対象升と交わらない走り方向」は走り方向の69.9%を占め、遮蔽で届かない方向を合わせると走り計算の94.5%が捕獲を生まない。
段階3の逆引き方式は、対象升が1升のノードでも走り計算だけで8回を要し、現行の走査の利き計算と走り計算の合計（1升で2.86回、4升で9.29回）をどの対象升数でも上回るので、設計書の演算数の定義では着手条件を満たさない。ただしこの定義は、現行の走査が自駒約31枚に対して行う到達範囲の表引きを数えておらず、段階3の最終判断は設計書のとおり段階2の採用後に測り直してから下す。
段階6のSEEの早期終了は除外後の呼出しの12.4%に該当し、参照との矛盾はない。
段階7の静的評価の先行打ち切りは静止探索ノードの28.1%で照合と保存を省き、段階9の対象である候補が空のノードは候補生成へ進んだノードの36.5%である。

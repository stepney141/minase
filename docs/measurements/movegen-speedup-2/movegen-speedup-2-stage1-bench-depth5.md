# 段階1（`codegen-units = 1`）のbench比較（深さ5）

## 目的

releaseプロファイルへ`codegen-units = 1`を加えた候補が、照合参照コミットと局面別のノード数、最善手、探索値で一致するかを確かめ、親コミットとの交互測定でNPS中央値の増分が親の幅を超えるかで採否を決める。あわせて、`--parent`を加えた`scripts/bench_compare.py`が参照、基準、親との比較を1コマンドで行えることを確かめる。

## コマンドライン

```console
scripts/bench_compare.py --reference 5c1db50 --baseline 7a41b2c --parent 008f659 --depth 5 --repetitions 3 --rounds 3 --threads 1
```

スクリプトは参照、基準、親を`git archive`で`target/bench-cache/`へ展開して通常のrelease設定でビルドし、局面別の一致は1回実行で取る。速度は基準、参照、親、候補の4者を3回の交互測定にかけ、各回は3回実行の中央値NPSをとり、回ごとの中央値の中央値で比べる。親の幅は、親の回ごとのNPS中央値の最大と最小の差を中央値で割った値である。

## エンジン

基準は第1期の採用版であるコミット`7a41b2cbc7e10ab5a597156ec00219b657b764ff`である。
参照は照合参照コミット`5c1db5000baea831ce53d994cbf664ee12a0e5e6`であり、探索木は現行と同一である。
親はブランチの起点であるコミット`008f6590f7e0620fbb75e0cb4e418d7491ba5bfc`であり、`src/`の探索と生成のコードは基準と同一である。
候補は親に対して`Cargo.toml`の`[profile.release]`へ`codegen-units = 1`を加えたものである。
`bench`は規則セット`engine-default`を固定で使う。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月16日に他の負荷を走らせずに1スレッドで測った。
置換表は既定容量を1個使い回し、局面ごとの`clear()`は計測区間外である。

交互測定の回ごとの経過とNPS（各回は3回実行の中央値）は次のとおりである。

| 回 | 基準 | 親 | 候補 |
|---|---:|---:|---:|

回ごとの中央値の中央値は、基準がNPS 2,232,829（経過0.5682秒）、参照が1,502,234（0.8445秒）、親が2,230,830（0.5687秒）、候補が2,296,896（0.5523秒）であり、総ノード数はいずれも1,268,607である。
候補のNPSは基準比1.0287倍、参照比1.5290倍、親比1.0296倍である。
親の幅は0.45%（基準は0.75%、候補は0.86%）であり、候補の親に対する増分+2.96%はこれを超える。

## 結論

`codegen-units = 1`は局面別出力を保ったままNPSを親比1.0296倍にし、増分が親の幅を超えるので採用する。段階1の完了時点の累積は基準比1.0287倍である。

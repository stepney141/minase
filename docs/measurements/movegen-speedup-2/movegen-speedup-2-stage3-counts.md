# 段階3（対象升が少ないノードの逆引き生成）の演算数の測り直し（bench深さ5）

## 目的

段階2の採用版で、静止探索の初期化における対象升数ごとの現行の走査の演算数（利き計算と走り計算の回数）を測り直し、逆引きの演算数（対象升数×8方向の走りと近傍の固定利き）が現行を下回る最大の対象升数を段階3の閾値として定める。

## コマンドライン

診断は本番の経路へ入れず、[段階1の診断差分](movegen-speedup-2-stage1-counts/diagnostic.patch)を段階2の`ordinary_capturer`へ当て直した[診断差分](movegen-speedup-2-stage3-counts/diagnostic.patch)を、別ターゲットディレクトリのビルドで数えた。走り計算回数の参照は、段階2で利き線が対象升と交わる方向だけ走り計算を行うようになったため、利き計算ごとの走り方向数の和から利き線が交わらない方向数を引いた値へ改めた。

```console
git apply docs/measurements/movegen-speedup-2-stage3-counts/diagnostic.patch
CARGO_TARGET_DIR=target/diag cargo build --release --bin bench
target/diag/release/bench --depth 5 --threads 1 --repetitions 1 2> counts.log
```

局面別の生の件数は[counts.log](movegen-speedup-2-stage3-counts/counts.log)、合計は[totals.json](movegen-speedup-2-stage3-counts/totals.json)にある。

## エンジン

段階2の採用版であるコミット`876f45e`に診断差分を当てたものである。`bench`は規則セット`engine-default`を固定で使い、総ノード数は1,268,607である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月16日に1スレッドで測った。件数は決定的である。

## 結果

初期化に到達した468,981ノードすべてで、各件数は段階1と同じ独立した参照（走り計算回数だけ上記のとおり改めた参照）と一致した。
1ノードあたりの走り計算は段階1の17.04回から5.12回へ減り、利き計算は5.11回、対象升へ届く自駒は1.39枚で変わらない。
走り方向7,992,287のうち利き線が対象升と交わらない5,588,971方向（69.9%）は走り計算を省き、残る2,403,316方向のうち1,961,165方向（全体の24.5%）は遮蔽で届かない。

## 結論

逆引きの演算数は対象升が1升のノードでも走り計算だけで8回であり、現行の走査の合計0.82回をはじめ、どの対象升数でも現行を上回る。閾値は1未満になるので、設計書の着手条件に従い段階3には着手せず採用しない。現行の走査が自駒約31枚に対して行う到達範囲の表引きは演算数に含めていないが、段階2の後に残る走り計算が1ノード5.12回まで減っているため、この表引きを含めても対象升1升あたり8回の走り計算を下回る見込みはない。

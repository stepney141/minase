# 第3期高速化の起案時診断（bench深さ5）

## 目的

第2期の最終の採用版を対象に、[最終の残存負荷](movegen-speedup-2-final-profile-depth5.md)の上位5項目（静止探索の本体、通常駒の捕獲可能升の計算、SEEの逆引き、置換表の照合、主探索の本体）について、削減できる処理の件数を数え、[第3期の設計書](../plans/movegen-speedup-3.md)の段階の選定と見込みの根拠にする。

## コマンドライン

診断は本番の経路へ入れず、[診断差分](movegen-speedup-3-diagnostics-depth5/diagnostic.patch)を最終の採用版へ当てた別ターゲットディレクトリのビルドで数えた。経過時間は使わない。

```console
git apply docs/measurements/movegen-speedup-3-diagnostics-depth5/diagnostic.patch
CARGO_TARGET_DIR=target/diag cargo build --release --bin bench
target/diag/release/bench --depth 5 --threads 1 --repetitions 1
```

合計は[totals.json](movegen-speedup-3-diagnostics-depth5/totals.json)にある。

## エンジン

第2期の最終の採用版であるコミット`24ddf4f`（段階1、2、4、5、6、7、8、9を含む）に診断差分を当てたものである。`bench`は規則セット`engine-default`を固定で使い、総ノード数は1,201,518である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月17日に1スレッドで測った。件数は決定的である。

## 結果

### SEEの逆引き（`attackers_to_by`）

| 項目 | 値 |
|---|---:|
| 呼出し数（初期化ノード1件あたり） | 983,207（2.09） |
| 走りの方向数（8方向×呼出し数） | 7,865,656 |
| 対象升の利き線上に、その方向の逆へ走る自駒（仮想占有内）が1枚もない方向 | 6,963,718（88.5%） |
| その方向の逆へ走る自駒が盤上に1枚もない方向 | 119,421（1.5%） |
| 走りの利きが自駒に当たった方向 | 2,921,327（37.1%） |
| うち当たった駒が逆方向へ走る（逆引きの的中） | 400,729（5.1%） |
| 近傍走査で調べた自駒数（1呼出しあたり） | 4,802,686（4.88） |
| うち固定利きが対象升へ届く（的中） | 594,574（12.4%） |

方向ごとの走り駒の集合（対局者×絶対方向の8集合ずつ）があれば、利き線との交差検査で90.1%の方向は走り計算を省ける。

### 静止探索の初期化（`QsearchBuffers::initialize`）

| 項目 | 値 |
|---|---:|
| 初期化に到達したノード数 | 470,545 |
| 手番側に特殊駒（獅子、角鷹、飛鷲）があるノードの割合 | 68.5% |
| 特殊駒の候補の生成数（1ノードあたり） | 1,526,203（3.24） |
| うち段階8の除外（経由升で取って空升へ進む獅子の手） | 502,316（32.9%） |
| うち閾値と王駒の判定で残る | 620,903（40.7%） |
| 1ノードあたりの対象升数 | 15.07 |
| 到達範囲を引いた自駒数（1ノードあたり） | 14,125,451（30.02） |
| うち到達範囲が対象升と交わる | 2,447,937（5.20） |
| うち対象升へ実際に届く | 666,151（1.42） |
| 走り計算の回数（1ノードあたり） | 2,458,374（5.22） |

到達範囲の表引きは1ノードあたり30枚に対して行い、通過するのは5.2枚である。特殊駒の候補は生成した手の59.3%が除外か閾値で捨てられる。

### 置換表の照合

| 項目 | 値 |
|---|---:|
| 主探索の照合（的中） | 135,074（76,462、56.6%） |
| 静止探索の照合（静止探索ノードに対する割合） | 300,734（43.0%） |
| うち的中 | 26,097（8.7%） |

### 主探索の手選択器

| 項目 | 値 |
|---|---:|
| 手選択器を使ったノード数 | 85,308 |
| 捕獲を生成したノード数（1ノードあたりの生成数、返した割合） | 66,819（6.98、52.1%） |
| 非捕獲を生成したノード数（手選択器ノードに対する割合） | 29,456（34.5%） |
| 1ノードあたりの非捕獲の生成数と返した数 | 84.3、40.2（47.7%） |
| 殺し手として返した数 | 29,501 |

非捕獲手は生成した半数を実際に検査するので、整列の部分選択化で省ける比較は多くない。

## 結論

削減余地が最も大きいのはSEE逆引きの走り部分であり、方向ごとの走り駒集合との交差検査で走り計算の90%を省ける。次に、静止探索の初期化における自駒30枚の到達範囲の表引き（通過5.2枚）と、特殊駒の候補生成（59%が捨てられる）が続く。静止探索の置換表は照合の的中が8.7%で、探索木を変える変更として全廃を再評価する余地がある。主探索の非捕獲の整列は検査率が48%で優先度が低い。

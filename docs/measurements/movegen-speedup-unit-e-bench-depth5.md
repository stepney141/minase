# 単位E（残存負荷に応じた代替方式）の判定（bench深さ5）

## 目的

単位Dまでの採用版（コミット`d961adf`、PGO適用）の残存負荷を関数別に測り、設計書の候補表の着手条件を満たす候補だけを試し、試した候補の採否と着手しない候補の理由を記録する。

## コマンドライン

残存負荷は、単位Cの採用版（`888bd10`）のソースに`#[inline(never)]`を付けた診断ビルド（`RUSTFLAGS="-C target-cpu=native -C force-frame-pointers=yes"`、PGOなし）で`perf record -F 4000 --call-graph fp`を取り、性能コアの標本で集計した。
試した候補の速度は、候補と直前の採用版をPGOなし（`MINASE_PGO_GENERATE=1`）で別ターゲットディレクトリへビルドし、`bench --depth 5 --threads 1 --repetitions 3`の中央値を交互に3回ずつ測って比べた。PGOなしで比べるのは、候補ごとにプロファイルを再生成せずにコード変更だけの効果を見るためである。

## エンジン

残存負荷の診断は`888bd10`（PGO適用前の同じソース）、候補の比較は`d961adf`のソースに対する差分である。`bench`は規則セット`engine-default`を固定で使う。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、2026年9月15日に1スレッドで測った。速度の比較は他の負荷を走らせずに行った。

## 結果

性能コアの標本に対する包含時間（自己時間）は次のとおりである。標本には計測区間外の置換表クリア（約5%）を含む。

| 関数 | 包含時間 | 自己時間 |
|---|---:|---:|
| `Searcher::quiesce` | 66.1% | 3.2% |
| `QsearchBuffers::initialize`（相手駒の走査、特殊駒の生成、通常駒の利きの登録） | 30.8% | 7.4% |
| `MoveGenerator::collect_ordinary_capturers` | 17.8% | 4.9% |
| `piece_control_without_special` | 15.8% | 11.6% |
| `TranspositionTable::probe` | 12.4% | 12.3% |
| `Position::attackers_to_by`（SEEの逆引き） | 9.3% | 0.3% |
| うち走りの逆引き（`ordinary_attackers_to`、`sliding_control`を含む） | 7.3% | 3.9% |
| うち固定利きの逆引き | 3.4% | 3.3% |
| うち特殊利きの逆引き | 1.4% | 1.4% |
| `QsearchBuffers::generate_group` | 5.6% | 3.2% |
| `MoveGenerator::generate_special_captures`（獅子系） | 5.3% | 0.3% |
| `MoveRules::special_move_is_legal` | 5.1% | 1.7% |
| `AttackTables::sliding_control` | 4.5% | 4.3% |

試した候補は2件である。

| 候補 | 内容 | 直前の採用版との比較（経過の中央値、交互3回） | 判定 |
|---|---|---|---|
| E1 置換表行の先読み | 着手適用の直後に子局面のキーで置換表の行を`Relaxed`で読み、照合までのメモリ待ちを隠す。`unsafe`は禁止なので明示のプリフェッチ命令は使えず、読み込みを`black_box`で残す方式 | 採用版0.579秒、0.566秒、0.562秒に対して候補0.566秒、0.570秒、0.572秒 | 一貫した差がなく不採用 |
| E2 公開生成の判定省略と固定利き専用経路 | 公開の全手生成でも捕獲升を1回だけ求めて獅子規則と成りの判定を省き、走りを持たない駒では利き線の検査を省いて固定利きと対象升の積を直接使う | 採用版0.566秒、0.564秒、0.565秒に対して候補0.576秒、0.574秒、0.575秒 | 約1.8%遅く不採用 |

どちらも局面別の出力は参照と一致した。

着手しなかった候補と理由は次のとおりである。

| 候補 | 理由 |
|---|---|
| 同じ捕獲先の準備をノード内で共有する | SEEの逆引きは包含時間9.3%で、同じ到達升への再照会率19.7%（[処理件数診断](../movegen-speedup-ideas.md)）と占有に依存しない部分（固定利きと特殊利き、合計4.8%）の積は全体の1%程度にとどまる。 |
| 成りと不成りの交換列を共有する | 同じ移動元と到達升への再照会率9.9%と逆引きの包含時間9.3%の積は全体の1%未満である。 |
| 固定利きの逆引きを近傍走査に変える | 固定利きの逆引きの自己時間は3.3%であり、近傍走査で半減しても全体の2%に満たない。 |
| 固定利きを移動量ごとの集合演算で求める | 捕獲生成の固定利きは表の1回参照であり、自己時間として分離できる負荷が見えない。 |
| 走り計算を別方式に置き換える | 走りの計算（`sliding_control`4.3%と`piece_control_without_special`の走り部分）は残存負荷の主要部だが、192ビット集合に対する圧縮表や分岐なし演算は新しい表の構築と検証を要し、置き換えても半減が上限で見込みは全体の5%前後である。2倍の目標に対する残り約10%を1候補で埋められる見込みがなく、着手しない。 |
| 獅子系の生成と列挙を整理する | 獅子系の生成の包含時間は5.3%で、整理で省ける割合は小さい。 |
| 置換表行をプリフェッチする | E1として試し、差がなかった。 |

## 結論

単位Eは、試した2候補（E1、E2）がいずれも速度を上げず、残る候補は測った残存負荷から見込みが数%以下なので、いずれも採用しない。単位Dの取り消し後の採用版は単位Cまで（`888bd10`）で、基準比のNPSは1.500倍である。

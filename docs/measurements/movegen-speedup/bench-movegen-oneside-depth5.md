# 利き逆引きの片側化の基準0e3dfa6に対するbench比較（深さ5）

## 目的

利き逆引きの片側化、方向主導化、および特殊利きの走査限定を一体で含む作業ツリーが、現在の基準コミット`0e3dfa6`と同じ探索木を辿るかを局面別のノード数で確かめ、あわせて速度比を測る。

## コマンドライン

基準は`git archive`で別ディレクトリへ展開し、両版とも通常のrelease設定でビルドした。
局面別のノード数は1回実行で、速度は3回実行の中央値で取った。

```console
git archive 0e3dfa6 | tar -x -C <基準ディレクトリ>
(cd <基準ディレクトリ> && cargo build --release --bin bench)
cargo build --release --bin bench
<基準ディレクトリ>/target/release/bench --depth 5 --threads 1 --repetitions 1
target/release/bench --depth 5 --threads 1 --repetitions 1
<基準ディレクトリ>/target/release/bench --depth 5 --threads 1 --repetitions 3
target/release/bench --depth 5 --threads 1 --repetitions 3
```

## エンジン

基準はコミット`0e3dfa6b59c489049c15e2cd00455e190a3fbf52`（master）である。
試作はブランチ`movegen-speedup`の作業ツリーであり、同コミットに対して`Position::attackers_to`を`attackers_to_by`へ片側化し、走りの逆引きを方向主導に、特殊利きの走査を獅子、角鷹および飛鷲に限定した変更（`src/core/movegen/mod.rs`、`src/search/mod.rs`、`src/search/see.rs`）だけを含む。
`bench`は規則セット`engine-default`を固定で使う。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、2026年9月15日に他の負荷を走らせずに1スレッドで測った（測定直前のload averageは0.13）。
置換表は既定容量を1個使い回し、局面ごとの`clear()`は計測区間外である。

## 結果

局面別のノード数は15局面すべてで一致した。
最善手と探索値は`bench`が出力しないため未照合である。

3回実行の中央値は次のとおりである。

| 版 | 総ノード数 | 経過（中央値） | NPS（中央値） |
|---|---:|---:|---:|
| 基準 0e3dfa6 | 1,268,805 | 0.845秒 | 1,500,735 |
| 試作 | 1,268,805 | 0.638秒 | 1,988,570 |

速度比は1.325倍である。
基準比2倍（0.4227秒）にはこの試作からさらに33.8%、基準比1.5倍（0.5636秒）には11.7%の時間削減が必要である。

## 結論

片側化を含む試作は基準`0e3dfa6`と同じノード数を15局面すべてで再現し、NPSを1.325倍にした。

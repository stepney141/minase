# 固定時間の探索の締切と途中結果の配備後の確認（lishogiのBotの通信対局）

## 目的

[固定時間（movetime）の探索の締切と途中結果](../../plans/archived/movetime-deadline.md)を含むminase 2.6.0をlishogiのBotへ配備した後、通信対局（1手300秒）の探索について、300秒で打ち切られた探索の割合、途中結果を採った割合、途中結果が着手を変えた割合、および補助ワーカーの結果を指した割合を、配備前の2.5.0と比べて記録する。

## コマンドライン

```console
python3 scripts/lishogi_correspondence_movetime/analyze.py minase-lishogi-bot/logs/lishogi-bot.log \
  "2026-10-25 10:46:56" "2026-10-25 22:19:00"
```

集計の期間は、Botのコンテナを2.6.0へ入れ替えた時刻（2026年10月25日10時46分56秒、UTC）から22時19分（UTC）までである。
集計には、打ち切りの後に出る最後の`info`行（`time`が300秒以上の行）を主ワーカーの完了反復と区別して数える版のスクリプト（`7118f8db`）を使った。
出力の全文は[analyze.txt](movetime-deadline-bot-correspondence/analyze.txt)にある。

## エンジン

minase 2.6.0（crates.ioの公開版、`v2.6.0`のタグ`bac8e2c9`）である。
Botの設定は配備前と同じく、`Threads=4`、置換表2,048 MB、通信対局の思考時間の上限300秒、先読みなしである。
比較に使う2.5.0の値は、[調査メモ](../../research/movetime-prior-art-and-correspondence-usage.md)の2026年9月18日から10月24日12時（UTC）までの集計である。

## 環境

Botは測定機（Intel Core Ultra 7 265KF、物理20コア）のDockerコンテナで動き、通常対局と通信対局を合わせて最大2局を同時に指す。
集計期間中、測定機では別のプロジェクトの計算も動いていた。

## 結果

期間中に始まった通信対局の探索は111件で、そのうち105件を着手と停止理由まで照合できた。
照合できなかった6件は、2局の出力が重なって行を振り分けられなかった4件と、終了の`bestmove`を特定できなかった2件である。

| 項目 | 2.6.0（配備後） | 2.5.0（調査メモ） |
|---|---:|---:|
| 照合できた探索 | 105 | 205 |
| 300秒で打ち切られた探索 | 105（100%） | 97（47%） |
| 反復の完了時に止めた探索 | 0 | 108（平均56秒を使い残した） |
| 主ワーカーが最後に反復を完了した時刻の平均 | 206秒 | 192秒 |
| 途中結果を採った探索 | 16（15.2%） | 0 |
| 途中結果が着手を変えた探索 | 1（1.0%） | 0 |
| 補助ワーカーのより深い結果を指した探索 | 35（33.3%） | 36（17.6%） |
| 打ち切られた探索のうち主ワーカーの最後の完了反復の手を指した探索 | 54（51.4%） | 61（29.8%） |
| 主ワーカーの150秒時点の最善手と指した手が異なった探索 | 16（15.2%） | 40（19.5%） |

2.6.0では、すべての探索が上限の300秒まで続いた。
打ち切られた探索で主ワーカーの最後の完了反復の手を指した54件では、最後の完了反復から300秒までの平均73秒の探索が着手に反映されなかった。
2.5.0の同じ区分（61件）では平均172秒だった。

## 結論

配備後の通信対局では、予測による早期の停止がなくなり、すべての探索が上限の300秒まで続き、15.2%の探索で途中結果を採った。
一方、打ち切られた探索の3分の1では、主ワーカーの途中結果より、ワーカー間の選択の規則（完了深さを最優先する）によって補助ワーカーのより深い結果が指されており、この選択の規則の見直しは本計画の範囲外として残った。

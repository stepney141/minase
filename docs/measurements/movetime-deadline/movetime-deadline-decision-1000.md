# 固定時間の探索の締切と途中結果の判定条件（1手1,000 ms）

## 目的

[固定時間（movetime）の探索の締切と途中結果](../../plans/movetime-deadline.md)の候補と基準（変更前のコミット）を、判定条件`movetime=1000,timemargin=100`のGSPRTで比べ、[選別条件](movetime-deadline-screen-300.md)を通過した候補を採用するかを決める。

## コマンドライン

```console
minase match run --run-dir data/matches/movetime-deadline-decision-1000 --seed 6250000000 \
  --candidate commit:de7b151af8c0b3193c3f51aae5e81f466dafc5a1 --baseline commit:b62e83d434c932a4775eaab296680b7dd0697ce2 \
  --each movetime=1000,timemargin=100 --concurrency 12 gsprt
python3 scripts/movetime_deadline/smoke_profile.py data/matches/movetime-deadline-decision-1000
```

## エンジン

候補は`de7b151a`（バイナリのSHA-256は`2349660f…`）、基準は`b62e83d4`（エンジンのコードはmasterの`e600faa5`と同一、SHA-256は`16cac49a…`）である。
規則セットは`engine-default`、両者とも`Threads=1`、`USI_Hash`は256 MBである。
runnerは`de7b151a`のminase 2.5.0（SHA-256は`62b8f181…`）である。
仮説はH0がelo=0、H1がelo=10、α=β=0.05である。

## 環境

[選別条件](movetime-deadline-screen-300.md)と同じく、測定機とは別の機械ryzen0（AMD Ryzen Threadripper 2990WX、物理32コア、論理64コア、メモリ125 GB、Rust 1.99.0）で、同時12対局で実行した。
測定機は、別のプロジェクトの計算とlishogiのBotで埋まっていた。
測定中、ryzen0にはほかの計算がなかった。

## 結果

| 項目 | 値 |
|---|---|
| ペア数 | 328（有効325、破棄3） |
| ペンタノミアル度数 | [39, 21, 154, 30, 81] |
| LLR | ＋2.964 |
| 判定 | `H1` |
| 異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 27,127秒（約7.5時間） |

破棄の3ペアは、いずれも手数上限4,096手への到達による。
不合法な予想手は候補と基準のどちらも0件だった。

判定の時点で対局中だったペアも終局後に保存されたので、判定に使った328ペアにこれらを加えた348ペアの各手を集計した。
結果は次のとおりである。

| エンジン | 手数 | 思考時間/`movetime`の中央値 | `movetime`を超えた量の最大 | 超えた量の99パーセンタイル | 停止理由（hard/soft/深さ） | 途中結果を採った手 |
|---|---:|---:|---:|---:|---|---:|
| 候補 | 171,616 | 1.010 | 70.3 ms | 28.5 ms | 168,446/3,166/4 | 23,875（13.9%） |
| 基準 | 171,567 | 0.824 | 58.3 ms | 20.5 ms | 39,134/132,433/0 | 0 |

`movetime`を45 ms以上超えた手は18手（候補6手、基準12手）で、すべて各局の1〜24手目に出た。
そのうち8手は、測定の開始時に同時に始まった最初の12ペアの対局で出た。
[煙試験](movetime-deadline-smoke.md)と同じく、超過の大きい手はエンジンの起動直後に集中しており、`timemargin`の100 msに対して30 ms以上の余裕が残った。

手数帯ごとの完了深さの平均（途中結果を採った手は報告された深さから1を引く）は、0〜49手で候補22.64（基準21.99）、50〜99手で22.05（同21.34）、100〜199手で21.19（同20.61）、200手以上で20.88（同20.48）であり、すべての手数帯で候補が基準を上回った。

## 結論

判定条件のGSPRTは`H1`で、エンジン異常、時間切れ、および拒否着手が0件だったので、設計書の規則に従って候補を採用する。

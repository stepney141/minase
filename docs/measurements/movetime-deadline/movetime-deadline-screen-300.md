# 固定時間の探索の締切と途中結果の選別条件（1手300 ms）

## 目的

[固定時間（movetime）の探索の締切と途中結果](../../plans/movetime-deadline.md)の候補と変更前のコミットを、選別条件`movetime=300,timemargin=100`のGSPRT（上限3,000ペア）で比べ、判定条件（1手1,000 ms）へ進むかを決める。

## コマンドライン

```console
minase match run --run-dir data/matches/movetime-deadline-screen-300 --seed 6150000000 \
  --candidate commit:de7b151af8c0b3193c3f51aae5e81f466dafc5a1 --baseline commit:b62e83d434c932a4775eaab296680b7dd0697ce2 \
  --each movetime=300,timemargin=100 --concurrency 12 gsprt --max-pairs 3000
python3 scripts/movetime_deadline/smoke_profile.py data/matches/movetime-deadline-screen-300
```

## エンジン

候補は`de7b151a`（バイナリのSHA-256は`2349660f…`）、基準は`b62e83d4`（エンジンのコードはmasterの`e600faa5`と同一、SHA-256は`16cac49a…`）である。
規則セットは`engine-default`、両者とも`Threads=1`、`USI_Hash`は256 MBである。
runnerは`de7b151a`のminase 2.5.0（SHA-256は`62b8f181…`）である。
仮説はH0がelo=0、H1がelo=10、α=β=0.05である。

## 環境

[煙試験](movetime-deadline-smoke.md)と同じく、測定機とは別の機械ryzen0（AMD Ryzen Threadripper 2990WX、物理32コア、論理64コア、メモリ125 GB、Rust 1.99.0）で、同時12対局で実行した。
測定機は、別のプロジェクトの計算とlishogiのBotで埋まっていた。
測定中、ryzen0にはほかの計算がなかった。

## 結果

| 項目 | 値 |
|---|---|
| ペア数 | 422（有効416、破棄6） |
| ペンタノミアル度数 | [59, 16, 212, 28, 101] |
| LLR | ＋2.946 |
| 判定 | `H1` |
| 異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 9,833秒（約2.7時間） |

破棄の6ペアは、いずれも手数上限4,096手への到達による。
不合法な予想手は候補と基準のどちらも0件だった。

判定の時点で対局中だった6ペアも終局後に保存されたので、判定に使った422ペアにこれらを加えた428ペアの各手を集計した。
結果は次のとおりである。

| エンジン | 手数 | 思考時間/`movetime`の中央値 | `movetime`を超えた量の最大 | 超えた量の99パーセンタイル | 停止理由（hard/soft/深さ） | 途中結果を採った手 |
|---|---:|---:|---:|---:|---|---:|
| 候補 | 204,315 | 1.045 | 35.9 ms | 24.8 ms | 191,232/13,079/4 | 31,117（15.2%） |
| 基準 | 204,271 | 0.841 | 56.5 ms | 23.6 ms | 39,005/165,263/3 | 0 |

手数帯ごとの完了深さの平均（途中結果を採った手は報告された深さから1を引く）は、0〜49手で候補18.21（基準17.57）、50〜99手で17.61（同16.95）、100〜199手で16.83（同16.26）、200手以上で17.56（同17.24）であり、すべての手数帯で候補が基準を上回った。

## 結論

選別条件は`H1`で異常が0件だったので、設計書の規則に従って判定条件（`movetime=1000,timemargin=100`）の本測定へ進む。

# nnue-architecture-revision-fixed-nodes

## 目的

[STC](nnue-architecture-revision-stc.md)で`H0`となった候補について、探索速度を除いた評価の質を基準と比べ、[設計書](../../plans/nnue-architecture-revision.md)の切り分けの手がかりを得る。
固定ノードの測定は診断であり、採否の根拠には使わない。
200ペアは所要時間を抑えるための暫定の規模であり、結果は仮説として扱う。

## コマンドライン

対局は、STCと同じrunnerで、本体のリポジトリのルートから実行した。

```console
minase-runner match run --run-dir data/matches/nnue-architecture-revision-fixed-nodes --seed 20261112000000 \
  --candidate commit:77e11950125c7215f8c7041cbd39a8d6f82e2295 \
  --baseline commit:ee1d6e08f294a5bfdc41c6737d445e0944928f77 \
  --each nodes=100000 --concurrency 16 elo --pairs 200
```

## エンジン

STCと同じである。
候補は`77e11950125c7215f8c7041cbd39a8d6f82e2295`、基準は`ee1d6e08f294a5bfdc41c6737d445e0944928f77`であり、規則セットは`engine-default`（L0,P0,R1,E0）である。

## 環境

2026年11月4日に測定機（Intel Core Ultra 7 265KF、物理20コア、論理20コア）で行った。
候補と基準のワーカー数（`Threads`）はともに1、`USI_Hash`はともに256 MB、同時対局数は16、思考制限は1手10万ノードである。
同じ機械でlishogiのBotと、別の作業の探索が動いていた時間がある。

## 結果

| 項目 | 値 |
|---|---|
| ペンタノミアル度数（候補のペア得点0、0.5、1、1.5、2） | 49、6、109、5、30 |
| 有効ペア数 | 199 |
| 破棄ペア数 | 1 |
| 候補の得点率 | 45.1% |
| Elo（95%信頼区間） | −34.2（−65.4〜−3.5） |
| 異常（不正着手、クラッシュ、タイムアウト、時間切れ、拒否着手） | いずれも0件 |
| 経過時間 | 3,466.9秒（1ペアあたり17.3秒） |

時間制御のSTCの得点率からは約−59 Eloであり、差の約25 Eloは速度の影響を含む可能性があるが、2つの区間は重なっている。

保存済みの対局の1手あたりの到達深さ（[集計のコード](nnue-architecture-revision-fixed-nodes/depth_summary.py)）は次のとおりであり、候補と基準の差は小さい。

| 測定 | 候補の平均 | 基準の平均 |
|---|---:|---:|
| 固定ノード（1手10万ノード） | 17.31 | 17.44 |
| STC | 17.63 | 17.88 |

深さ15のbenchの合計ノード数は候補が基準の約2倍だが、これは15局面のうち1局面（基準61,505、候補1,128,680）の差が支配しており、局面ごとの比は0.38〜18.35に散らばって系統的な増加ではない。

## 結論

候補は固定ノードでも基準より弱く、区間の上限が0を下回る。
設計書の表では「基準より有意に弱い」にあたり、速度だけで負けたのではなく、学習または表現に問題があるという仮説を立てる。
到達深さの差は小さいので、評価の形が探索と合わずに読みが浅くなったという説明は支持されない。

# 第1層の初期値を小さくしたネットの学習

## 目的

[設計書](../../plans/archived/nnue-architecture-revision.md)の切り分けの最初の候補として、第1層の重みの初期値を入力次元に応じた小さい値へ改めてネットを学習し、[標準偏差0.05の学習](nnue-architecture-revision-training.md)と比べる。
棋力の判定は別の測定で行う。

## コマンドライン

本体のリポジトリのルートで、`systemd-run`のサービス（nice値19、メモリ上限13 GB）として実行した。
`$F`は`data/nnue-lr-schedule-gen/generated-*.bin`の30ファイルを名前順に並べた配列である。

```console
systemd-run --user --unit=nar-train-init --same-dir -p MemoryMax=13G -p MemorySwapMax=0 -p Nice=19 \
  /usr/bin/time -v -o data/nnue-architecture-revision/train-init.time \
  data/nnue-architecture-revision/minase-trainer-init nnue train \
  --feature-set P --width 256 --head pairwise-l16-l32 --data $F \
  --base crates/minase/nets/pst.bin --lambda 1.0 \
  --batch 16384 --epochs 50 --patience 5 --seed 1 --threads 4 --device cuda \
  --lr-schedule cosine:3:0.1 --teacher-cp-per-logit calibrate --validation-interval 1000 \
  --output-dir data/nnue-architecture-revision/train-init
```

診断は[学習の手引き](../../guides/nnue-training.md)の8節の3つのコマンドで、前回と同じ標本の条件で行った。

## 環境

2026年11月4日に測定機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB、RTX 3060 Ti）で行った。
学習のコミットは`ae569cb2`である。
第1層の重みの初期値は、標準偏差$`\sqrt{1/(3\times13{,}680)}\approx0.00494`$の正規分布であり、tataraとnnue-pytorchの一様分布±$`\sqrt{1/D}`$と同じ分散である。
他の条件は前回と同じである。

## 結果

本学習の前に、教師を1ファイルにして2エポックだけ動かした試走では、検証損失が0.448586から0.447972へ下がり、幅15の層の$`z`$が1以上である割合が53.7%から31.0%へ減った。

駒除去差分の量子化前の2経路の差の最大は3.4×10⁻¹²センチポーンであり、合法手の評価差は47局面すべてで合法手の集合が一致した。

埋め込んだコミットは`9af68a00`である。
埋め込んだネットについて、ランダム対局の4,096局面で差分更新と全再計算の一致と左右鏡映の評価の一致を確かめ、`invariants`つきの深さ9のbenchが完走した。

### 対局結果を目標とした汎化差

対局の結果（手番側から勝ち1、引き分け0.5、負け0）を目標とした損失を、[過去の記録](../nnue-early-best-epoch/nnue-no-lookahead-training.md)と同じ条件で、訓練の対局（10局面ごとに選んだ7,945,821局面、210,787局）と検証の対局（全4,153,303局面、11,112局）について求めた。
評価はエンジンの整数の評価である。
汎化差は検証の損失から訓練の損失を引いた値である。
差の区間は、対局を単位とする対応のあるブートストラップ（1,000回、シード1）の95%区間である。
集計は[コード](nnue-architecture-revision-init-training/outcome_gap.rs)、[区間の計算](nnue-architecture-revision-init-training/gap_report.py)、および[出力](nnue-architecture-revision-init-training/gap_report.out)にある。
エポック0のネットは、線形の経路だけが探索用駒価値を持つ幅256のネットである。

| ネット | 訓練 | 検証 | 汎化差 |
|---|---:|---:|---:|
| エポック0 | 0.496498 | 0.494280 | −0.002218 |
| 基準（`5257f374`、幅128） | 0.454644 | 0.453016 | −0.001628 |
| 候補1（標準偏差0.05） | 0.454411 | 0.453026 | −0.001385 |
| 候補2（新しい初期値） | 0.454365 | 0.452789 | −0.001576 |

| 比較 | 汎化差の差 | 95%区間 | 検証の損失の差 | 95%区間 |
|---|---:|---|---:|---|
| 候補2−基準 | +0.000052 | [−0.000111, +0.000218] | −0.000227 | [−0.000382, −0.000071] |
| 候補1−基準 | +0.000243 | [+0.000077, +0.000405] | +0.000011 | [−0.000151, +0.000169] |
| 候補1−候補2 | +0.000191 | [+0.000050, +0.000319] | +0.000237 | [+0.000103, +0.000364] |
| 候補2−エポック0 | +0.000642 | [−0.002072, +0.003301] | −0.041491 | [−0.044170, −0.038942] |

候補2の汎化差は基準と区別できず、エポック0との差の区間も0を含むので、隠れ層が訓練の対局を記憶している様子はない。
候補2の検証の損失は基準より有意に低く、対局結果の予測はわずかに良い。

### 線形の経路の結果回帰

`fit-linear`が新しい構成のネットで動くことを、候補2のネットで確かめた。

```console
data/nnue-architecture-revision/minase-trainer-init nnue fit-linear \
  --base data/nnue-architecture-revision/train-init/nnue.bin --data $F \
  --tau 10 20 40 80 --seed 20261104 --output-dir data/nnue-architecture-revision/fit-init --threads 8
```

所要時間は1分48秒、最大常駐メモリは3.3 GBである。
選ばれたτは80で、判定の対局（10,271局）の損失は0.645464から0.638853へ下がり、Dは−0.006611（95%区間−0.008446〜−0.004787）である（[出力](nnue-architecture-revision-init-training/fit_report.out)）。
基準のネットのDは[−0.007093](../nnue-outcome-regression/nnue-outcome-regression-fit.md)であり、新しい構成でも線形の経路に回帰の余地が同じ程度に残る。
書き出した`nnue.bin`（SHA-256 `07a5048e…`）は復号を通り、線形の経路だけが元のネットと異なる。
補正したネットは本書の判定では使わない。

## 結論

初期値を小さくすると、検証損失は標準偏差0.05より4.4×10⁻⁵低く、基準のネットより3.2×10⁻⁵低くなった。
幅15の層の飽和は減ったが、累算値が1以上である割合は増えた。
対局結果を目標とした検証の損失も基準より低く、汎化差は基準と区別できない。
棋力は対局で判定する。

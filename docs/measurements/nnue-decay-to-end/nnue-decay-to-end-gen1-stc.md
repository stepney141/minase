# 第1世代の教師での関門の対局（STC）

## 目的

[端数バッチと学習率の設計書](../../plans/nnue-decay-to-end.md)のフェーズ2として、第1世代の教師43本を候補の条件で学んだネットを候補、現行の条件で学んだネットを対照とし、短時間の時間制御（STC、持ち時間10秒、1手0.1秒加算）の逐次検定（GSPRT、一般化逐次確率比検定）で比べる。
このGSPRTは、候補が対照より0 Elo強いという仮説`H0`と、10 Elo強いという仮説`H1`のどちらに近いかを、対数尤度比（LLR）で判定する。
判定は、第3世代の教師を候補の条件でも学ぶかどうかを決める関門に使う。`H1`か、上限の3,000ペアで判定が出ずにLLRが0以上なら通過とし、第3世代で2つの条件の両方を学ぶ。`H0`か、上限でLLRが負なら不通過とし、候補の条件を不採用とする。

候補の条件は、約4エポック（エポックは訓練局面をひととおり学ぶ期間）で学習を終え、その終わりまでに学習率を初期値の0.027倍まで下げて、最後の重みを使う条件である。
現行の条件は、学習率を下げる期間を390,656更新とし、訓練に使わない対局で測った誤差（検証損失）が2回続けて最小値を更新しなければ止めて、最小だった時点の重みを使う条件である。
2つのネットの学習は[学習の記録](nnue-decay-to-end-gen1-training.md)にある。

## コマンドライン

本体のリポジトリのルートで、[`run-match.sh`](nnue-decay-to-end-gen1-stc/run-match.sh)により、nice値19、メモリ上限12 GiB、スワップなしの`systemd-run`のサービスとして実行した。

```console
run-match.sh nnue-decay-to-end-gen1-stc 20261330000000 stc <候補のネット> <対照のネット> 10
```

`run-match.sh`は次のコマンドを起動する。

```console
minase match run \
  --run-dir data/matches/nnue-decay-to-end-gen1-stc --seed 20261330000000 \
  --candidate commit:f2eb705febe317229addc561ff8a0838c545e2eb \
  --baseline commit:f2eb705febe317229addc561ff8a0838c545e2eb \
  --candidate-option EvalFile=<候補のネット> --baseline-option EvalFile=<対照のネット> \
  --rules lishogi --each time=10000+100 --concurrency 10 gsprt --max-pairs 3000
```

## エンジン

| 側 | コミット | ネットのSHA-256（`/mnt/synology_nas/minase/nnue/nets/`に同じ名前で置いてある） |
|---|---|---|
| 候補（候補の条件で学んだネット） | `f2eb705febe317229addc561ff8a0838c545e2eb` | `027a823a1a8a50d5a4ff9c1810a24792498e629ba09346a0c51e276d7827d326` |
| 対照（現行の条件で学んだネット） | `f2eb705febe317229addc561ff8a0838c545e2eb` | `bc06ed57b004d4c5fd3d07da6551d608827359f298bdef3cad7af253a4927c5d` |

両側のコミットは、世代反復が教師の生成と判定の対局に使っているコミットであり、エンジンの実行ファイルは同じ1つのビルドである。
対局の実行記録`manifest.json`の`network_sha256`は、候補と対照のどちらも、学習の記録のネットのSHA-256と一致した。
規則セットは、オンライン対局サイトlishogiの実装に近い`lishogi`（規則コード`L1,L2,P0,P3,R1,E1,E3`）である。

## 環境

2026年11月23日16時50分から19時22分（日本時間）まで、作業機（Intel Core Ultra 7 265KF、物理コア20、論理コア20、メモリ30 GB）で行った。
対局ツールは、世代反復の実行ディレクトリにある同じコミットの`minase`（SHA-256は`42bd5b34…`）で、起動は1回である。
エンジンの設定は、両側ともスレッド数（`Threads`）が1、置換表の容量（`USI_Hash`）が256 MBであり、同時対局数は10である。
同じ作業機で、lishogiのBotのコンテナが動いていた。

## 結果

```text
summary: mode=gsprt pairs=823 valid_pairs=819 discarded_pairs=4
pentanomial: [106, 90, 369, 107, 147]
llr: 2.9482718568
decision: H1
engine_failures: illegal_moves=0 crashes=0 timeouts=0 time_forfeits=0 rejected_moves=0
elapsed: 9146.259970 s
```

判定は`H1`であり、候補の条件で学んだネットは、現行の条件で学んだネットより有意に強い。
`pentanomial`（先後を入れ替えた2局を1ペアとした、ペアごとの5通りの結果の数）は候補から見た値で、2局とも負けたペアが106、1敗1分が90、1勝1敗か2分が369、1勝1分が107、2局とも勝ったペアが147である。
819ペアの得点率は0.530で、Eloに直すと候補が+21.0（95%信頼区間+6.6〜+35.5）である。信頼区間は、ペアごとの得点の標準誤差から求めた。逐次検定は判定が出た時点で止まるので、この点推定は真の差より大きく出やすい。
破棄した4ペアは、どれも片方の対局が手数の上限4,096手に達したものである。
残る1,642局の終局理由は、王駒の捕獲1,213局、裸玉186局、千日手243局である。
エンジンの異常、時間切れ、および拒否着手は0件だった。

途中の経過では、149ペアの時点でLLRが−0.56、397ペアの時点で−0.02であり、その後に`H1`の境界へ達した。

## 結論

関門は通過である。
設計書の規則に従い、第3世代の教師を現行の条件と候補の条件の両方で学び、第3世代の教師での対局で第3世代のネットを選ぶ。
第1世代の教師での結果は、手書きの評価関数が生成した教師での結果であり、候補の条件を標準レシピに採用するかは、第3世代の教師での長時間の対局で決める。

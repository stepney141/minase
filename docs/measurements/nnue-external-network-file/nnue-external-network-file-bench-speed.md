# ネットを外部のファイルから読む前後のbenchの速さ

## 目的

ネットを埋め込んだmasterのコミットと、同じネットを`EvalFile`で渡した[外部ファイル化の設計書](../../plans/archived/nnue-external-network-file.md)のブランチの先頭のコミットで、深さ5の`bench`の速さが変わらないことを、性能コアに固定した5回の交互の測定で確かめる。
判定の基準は、ブランチの5回の平均とmasterの5回の平均の差が、masterの5回の値の幅（最大値と最小値の差）より小さいことである（[速度の比べ方の教訓](../../lessons/alternate-speed-rounds-against-parent.md)）。

## コマンドライン

`<NAS>`は`/mnt/synology_nas/minase/nnue/nets/987f060d545c09f0a42b4c668ea8b24cbf83c1770d11d663a94e4b82601274cd.bin`である。

```console
taskset -c 3 python3 scripts/bench_compare.py --reference ac95196a --baseline ac95196a --parent ac95196a \
  --depth 5 --rounds 5 --eval-file <NAS>
```

`bench_compare.py`は、3つの引数に与えたコミットと、作業ツリーをビルドした候補を、各回で`bench depth 5 threads 1 repetitions 3`の3回の反復の中央値の毎秒ノード数（nps）で、比べる版を交互にして5回ずつ測る。
`perf stat`はプロセスの起動から終了までを数えるので、`isready`でのファイルの読み込みとSHA-256の計算も計数に入る。
これを除いた探索の区間の計数は、エンジンに送るUSIのコマンドのうち`repetitions`だけを3と9に変えた2回の`perf stat`（`cpu_core`の`instructions`、`cycles`、`branch-misses`、`L1-dcache-load-misses`、利用者空間だけ）の差として、探索6回分を求めた。
`bench`の毎秒ノード数の計測区間には、`isready`の処理は入らない。

## エンジン

比べる元（`--reference`、`--baseline`、および`--parent`）はmasterのコミット`ac95196a`であり、ネットを埋め込んだ版である。
ブランチを切ったときのmasterは`57eb3d25`であり、この測定の前に`ac95196a`へ進んだが、その差は文書だけで、`crates/`、`Cargo.toml`、および`Cargo.lock`は同じである。
比べる先はブランチの先頭のコミット`48956be1`であり、`bench_compare.py`が作業ツリーをビルドしたものである。

## 環境

測定機はIntel Core Ultra 7 265KF（性能コア8、効率コア12、計20スレッド）、メモリ30 GiBである。
`bench`は性能コアの論理CPU 3に固定し、1スレッドで実行した。
lishogi Botのエンジンが動いていないことを確かめてから始め（開始時の1分の負荷平均0.47）、終了時にもBotのエンジンは動いていなかった。

## 結果

5回の毎秒ノード数は次のとおりである。

| 版 | 5回の値 | 平均 | 幅 |
|---|---|---|---|
| master `ac95196a` | 1,051,259、1,050,671、1,046,645、1,055,245、1,054,714 | 1,051,707 | 8,600（0.82%） |
| ブランチ `48956be1` | 1,063,943、1,052,451、1,060,178、1,057,320、1,057,485 | 1,058,275 | 11,492（1.09%） |

ブランチの平均はmasterより6,569 nps（0.62%）速く、差はmasterの幅8,600 npsより小さかった。
局面ごとの深さ、ノード数、最善手、および評価値は、15局面すべてで一致した。

探索6回分の利用者空間の命令数は、masterが14,071,994,979、ブランチが14,071,988,573であり、差は6,406命令（0.00005%）だった。
同じ区間のサイクル数はmasterが9,498,306,531、ブランチが9,462,996,015、分岐予測の失敗はmasterが7,780,932、ブランチが7,741,893、L1データキャッシュの読み込みの失敗はmasterが5,425,161、ブランチが5,590,123だった。

これより前に、論理CPU 12（効率コア）に固定し、lishogi Botの2局が動いている間に、masterの`57eb3d25`と同じ5回ずつの交互の測定を行ったところ、ブランチの平均がmasterより0.65%遅く、差がmasterの幅0.54%を超えた。
そのため原因を調べたところ、探索の区間の命令数は同じ方法で115,264命令（0.001%未満）しか違わず、プロセス全体でブランチが約1.7億命令多かった分は、反復の数によらない計測区間の外の処理（主に`isready`でのネットのファイルの読み込みとSHA-256）だった。
この結果と、Botが動いていない状態で性能コアに固定して測り直した上の結果から、効率コアでの差は探索の処理が増えたためではないと判断した。

## 結論

ネットを外部のファイルから読む変更は、同じネットを与えたときの`bench`の速さを変えない。

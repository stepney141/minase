# 世代反復の第1世代の教師の生成と学習

## 目的

[世代反復の設計書](../../plans/archived/nnue-generation-iteration.md)のフェーズ2として、手書きの評価関数v0をNNUEの形式に書き出したネット（以下、v0のネット）で第1世代の教師ファイル（以下、本）を生成し、その本だけから、王の位置を使わない入力A型のNNUE（着手ごとに差分で更新できる小さなニューラルネットの評価関数）を標準レシピv3で学ぶ。
あわせて、1億局面に相当する本数kと、教師の探索値を勝率へ換算する教師の勝率尺度K_tを求める。
学んだネットの強さは、[第1世代の判定](nnue-generation-iteration-gen1-stc.md)で測る。

## コマンドライン

本の生成、学習、および診断は、本書の[付随ディレクトリ](nnue-generation-iteration-gen1-training/)のスクリプトで起動した。
作業に使う手元の計算機を作業機、教師の生成のために借りる機械を生成機、学習のために借りるGPUつきの機械を学習機と呼ぶ。

### 本の生成

本は、作業機の制御スクリプト`teacher_generation.py`が、計算機を時間単位で借りられる市場vast.aiで生成機を1台ずつ借りて生成した。
起動は`generate-teachers.sh`で行い、制御スクリプトへ渡した主な引数は次のとおりである。

```console
python3 scripts/vast/teacher_generation.py run --run-dir <実行ディレクトリ> \
  --repo <worktree> --ref refs/nnue-generation-iteration/iteration \
  --commit f2eb705febe317229addc561ff8a0838c545e2eb --minase-bin <反復のコミットのminase> \
  --eval-file <v0のネット> --generation 1 --first-book <最初の番号> --last-book <最後の番号> \
  --seed-base 9100000000 --seed-book-step 100000 \
  --games 7500 --nodes 20000 --random-moves 0 --max-ply 4000 --hash-mb 16 --chunk-games 250 \
  --rental <借り方> --max-price <時間単価の上限> --deadline <絶対期限> \
  --max-cost <費用の上限> --max-rentals <借りる回数の上限>
```

番号iの本のシードは`9,100,000,000 + 100,000×i`である。
番号0〜3の4本を先に生成してkとK_tを求め、利用者がkを採ると決めてから番号4〜42を生成した。
借り方の「中断可能」は、入札で安く借りる代わりに、より高い入札が入るといつでも止められる借り方であり、「オンデマンド」は、表示の時間単価で借り、貸し手が止めない借り方である。
制御スクリプトは実行ディレクトリごとに引数を固定するので、借り方と時間単価の上限を変えるたびに実行ディレクトリを分けた。
`gen1-first4`は、借りた機械が起動しないまま制御スクリプトが不具合で終了した実行であり、不具合を直した後に、借りる回数の上限を上げた`gen1-first4b`でやり直した。

| 実行ディレクトリ | 番号 | 借り方 | 時間単価の上限 | 受け入れた本 |
|---|---|---|---|---|
| `gen1-first4` | 0〜3 | 中断可能 | 1.4米ドル | なし |
| `gen1-first4b` | 0〜3 | 中断可能 | 1.4米ドル | 0〜3 |
| `gen1-rest` | 4〜42 | 中断可能 | 1.4米ドル | 4〜17 |
| `gen1-rest2` | 18〜42 | 中断可能 | 3.5米ドル | 18〜20 |
| `gen1-b21-on-demand` | 21〜42 | オンデマンド | 1.5米ドル | 21〜42 |
| `gen1-b21-interruptible` | 21〜42 | 中断可能 | 3.5米ドル | なし |

最後の2つは、合う出品がなくなるたびに借り方を替えて制御スクリプトを起動し直す`generate_auto.py`が動かした。
回収済みの塊（7,500局を250局ずつに分けて確定させた単位）は、実行ディレクトリを替えるときに次の実行ディレクトリへ写して引き継いだ。

### kとK_t

kは`recipe_values.py`で、K_tは反復のコミットの学習器の較正のコマンド`data calibrate`で求めた。

```console
python3 recipe_values.py 1 <番号0〜3の生成ログのディレクトリ>
minase-trainer data calibrate --data <番号0〜3の本> --output <連続生成スクリプトの実行ディレクトリ>/calibration.json
```

### 学習

43本と生成ログを連続生成スクリプトの実行ディレクトリの`gen-1/teacher/`と`gen-1/logs/`へハードリンクで置き、`train-generation.sh`で連続生成スクリプト`generation_chain.py`を起動した。
スクリプトは学習機を借り、次の学習器と診断を学習機で実行した。

```console
minase-trainer nnue train layerstack --data <43本> --rules lishogi \
  --teacher-cp-per-logit 733.1159421542734 --lambda 1.0 --seed 1 --threads 16 \
  --output-dir <出力ディレクトリ> --batch 16384 --superbatches 136 \
  --validation-superbatches 1 --device cuda --lr-schedule cosine:135.22187608168917:0.027 \
  --batches-per-superbatch 2889 --validation-patience 2
minase-trainer diag nnue-removal --float <出力ディレクトリ>/best.npz --net <出力ディレクトリ>/nnue.bin \
  --data <43本> --sample 10000 --seed 1 --output <報告>
```

superbatchは、決まった回数の更新をまとめた単位であり、学習器は1 superbatchごとに検証損失を測る。
1 superbatchの更新回数B、学習率の減衰の期間T、およびsuperbatchの数の上限Sは、43本の生成ログの記録局面数の合計99,642,331から、設計書の「世代の手順」の式で求めた。
訓練局面数の見積りMは、合計の95%にあたる94,660,214である。
1エポックの更新回数Uは、Mを1回の更新の局面数16,384で割って切り上げた5,778であり、BはU÷2を切り上げた2,889である。
Tは、設計書が定める学習率の減衰の更新回数390,656をBで割った135.22であり、SはTを切り上げた136である。

### 作業機での診断

学習の後に、作業機で`diagnose-generation.sh 1`を実行し、評価値の分布、合法手の評価差、および第0世代とのあいだの対局単位の汎化差を求めた。

## エンジン

教師の生成器、学習器、およびエンジンは、ブランチ`nnue-generation-iteration`のコミット`f2eb705febe317229addc561ff8a0838c545e2eb`（以下、反復のコミット）である。
生成機と学習機は、制御スクリプトが送ったコードからこのコミットを展開してビルドした。
作業機の`minase`（SHA-256は`42bd5b34…`）と`minase-trainer`（`4a444c19…`）も、このコミットのビルドである。
本を生成したネットは、`minase-trainer nnue export-handcrafted`で書き出したv0のネット（SHA-256は`b2a0a450106bb3311f8ffe94f3bee17501347dabe93ecbc499827c66e07f0445`）であり、これを第0世代とする。
規則セットは、本、学習器の引数、および`bench`のいずれも`lishogi`（`L1,L2,P0,P3,R1,E1,E3`）である。
43本のヘッダの生成コミット、ネットのSHA-256、規則セット、シード、および探索のノード数は、制御スクリプトの受け入れの検査と連続生成スクリプトの照合に通った。

## 結果

### kとK_t

| 項目 | 値 |
|---|---|
| 番号0〜3の記録局面数 | 2,333,683、2,318,563、2,351,007、2,300,063 |
| 1本あたりの記録局面数の平均 | 2,325,829 |
| k（1億÷平均を整数に丸めた値） | 43 |
| K_t | 733.12 cp（教師の分類は1つ、推定の範囲50〜4,000 cpの端ではない） |

cpはセンチポーンで、歩兵1枚の100分の1である。
kは設計書の見込みの37と異なったので、2026年11月20日に利用者が43を採ると決めた。
設計書の「反復を止める条件」は、較正で教師の分類が1つにならないか、K_tが推定の範囲の端にある場合に残りの本を生成しないと定めており、較正の結果はこれに当たらなかった。

### 教師の量

| 項目 | 値 |
|---|---|
| 本数 | 43本（番号0〜42） |
| 対局数 | 322,500局を生成し、手数の上限で1,060局を破棄して、321,440局を保存した |
| 記録局面数 | 99,642,331（1本あたり2,317,264） |
| 訓練局面数と検証局面数 | 94,685,720と4,956,611 |
| 1本の生成時間 | 途中で引き継ぎのなかった41本は696〜799秒（EPYC 9654、384スレッド） |
| 生成の期間 | 19時間11分。このうち約6時間50分は利用者の判断を待って生成機を借りていなかった時間であり、約1時間は合う出品が現れるのを待っていた時間である |

生成の速さは、設計書の見積りの短い側（1本632秒）に近かった。
入札で借りた機械は3回止められ、合う出品がない状態が2回起きた。
1回目は入札額の上限を1.4米ドルから3.5米ドルへ上げ、2回目はオンデマンドも試すことにして、どちらも利用者の決定で続けた。
生成器がSIGBUSで異常終了した機械（machine_id 155327）は、同じ本の実行がコンテナの再起動をはさんで2回記録されており、機械の側の不具合とみて、利用者の決定で除外した。
同じコミットの生成器は、ほかの機械では43本を異常なく生成した。

### 学習の健全性

| superbatch | エポック数 | 更新回数 | 訓練損失 | 検証損失 | PSQTの移動量の平均 | PSQTの移動量の最大 |
|---|---|---|---|---|---|---|
| 0（学習前） | 0 | 0 | | 0.003014 | 0 cp | 0 cp |
| 1 | 0.50 | 2,889 | 0.001118 | 0.000989 | 12.20 cp | 169.3 cp |
| 2 | 1.00 | 5,778 | 0.000928 | 0.000965 | 13.34 cp | 206.2 cp |
| 3（書き出した重み） | 1.50 | 8,667 | 0.000874 | 0.000960 | 13.83 cp | 217.9 cp |
| 4 | 2.00 | 11,556 | 0.000861 | 0.000962 | 14.31 cp | 241.7 cp |
| 5（学習が止まった時点） | 2.50 | 14,445 | 0.000825 | 0.000962 | 14.62 cp | 244.4 cp |

損失は、ネットが出す勝率と、教師の探索値から換算した勝率の差の2乗の平均である。
PSQTは駒と升ごとの点数の表であり、移動量はv0の値からの変化である。
学習は、検証損失が2回続けて最小値を更新しなかったので、第5 superbatchで止まった（`summary.json`の`stopped_by`は`validation_patience`、`status`は`candidate`）。
書き出した重みは検証損失が最小だった第3 superbatchのものであり、`selected_validation_loss`は0.00096002である。
`training.jsonl`の`epochs`は、1 superbatchごとに0.4998ずつ増えた。
訓練損失は第5 superbatchまで下がり続けたが、検証損失は1.5エポックより後に改善しなかった。

学習の速さは毎秒118万〜126万局面（16スレッド）、学習の時間は441.7秒、教師の前処理は120.2秒だった。
学習器のプロセスの最大常駐メモリは12,223,036 KiB（11.66 GiB）で、1本あたり約0.27 GiBである。
設計書の見込み（1本あたり約0.36 GB、43本で約15.5 GB）より少なかった。
駒除去差分の診断のプロセスの最大常駐メモリは10,672,308 KiBだった。

対局単位の汎化差は、対局結果を目標とした損失の、検証対局での値から訓練対局での値を引いた差である。
この損失は、評価値から換算した勝率と対局結果（勝ちを1、引き分けを0.5、負けを0とする）の交差エントロピーの平均であり、上の表の検証損失とは別の量である。
評価値を勝率へ換算する尺度には、どちらのネットにもK_tを使った。

| ネット | 訓練対局での損失 | 検証対局での損失 | 汎化差 |
|---|---|---|---|
| 第0世代（v0） | 0.563988 | 0.563024 | −0.000964 |
| 第1世代 | 0.558495 | 0.558051 | −0.000444 |

訓練対局は303,930局の9,468,589局面（10局面ごと）、検証対局は15,990局の4,956,611局面である。
対局を単位とする対応のあるブートストラップ（1,000回）では、第0世代から第1世代を引いた汎化差の差は−0.000519（95%区間−0.000801〜−0.000236）、検証対局の損失の差は+0.004973（95%区間+0.004718〜+0.005241）だった。
第1世代は、訓練に使わなかった対局でも対局結果をv0よりよく予測する。
汎化差はv0より0.0005大きいが、どちらも負であり、検証対局の損失の差の約10分の1なので、訓練対局の記憶を示す大きさではない。

### 評価の形

書き出しの量子化誤差と層ごとの飽和の割合は、検証局面の標本10,000局面での値である（`summary.json`の`quantization`）。

| 項目 | 値 |
|---|---|
| 量子化誤差の絶対値の平均 | 8.24 cp |
| 量子化誤差の符号つきの平均 | +7.01 cp |
| 量子化誤差の絶対値の最大 | 107.4 cp |
| 第1層の飽和の割合 | 0.709 |
| 後段の1層目の飽和の割合（線形の半分） | 0.764 |
| 後段の1層目の飽和の割合（2乗の半分） | 0.014 |
| 後段の2層目の飽和の割合 | 0.560 |

飽和の割合は、活性化の前の値が0以下か1以上になった成分の割合である。
学習の統計では、飽和のほとんどは0以下の側であり、書き出した重みの時点で1以上の側は各層で0.2〜1.4%だった。

駒除去差分（盤上の駒を1枚ずつ除いたときの評価値の差分）の符号が、v0の駒割でその駒を除いたときの差分と逆になった除去は、学習機での診断（検証局面の標本10,000局面）で527,066件のうち243件（0.046%）であり、反転した差分の絶対値の平均は59.7 cp、最大は501 cpだった。
量子化の前の評価では、第1層の累算値から、除いた駒に対応する重みの行を引く計算と、除去後の局面から計算し直した値が一致した（差の最大は0 cp）。

評価値の分布は、NNUEより前の評価関数PST＋FM（駒と升ごとの点数の表PSTに、2駒の関係の補正FMを足したもの）を基準に、43本の全局面から抽出した10,000局面で比べた。

| ネット | 標準偏差 | PST＋FMに対する標準偏差の比 | 相関係数 | 差の絶対値の中央値 |
|---|---|---|---|---|
| PST＋FM（基準） | 1,875.0 cp | | | |
| 第0世代（v0） | 1,088.1 cp | 0.580 | 0.947 | 376 cp |
| 第1世代 | 1,116.6 cp | 0.596 | 0.955 | 359 cp |

診断の判定は、どちらのネットも「散らばりの尺度を変えた」（比が0.9〜1.1の外）である。
v0の駒割の尺度がPST＋FMより小さいためであり、第1世代はv0とほぼ同じ尺度を保っている。
盤上の駒数が0〜29、30〜59、60〜90の3つの帯での比は、この順に、第1世代が0.584、0.600、0.660、v0が0.563、0.590、0.657であり、どの帯でも第1世代とv0の差は0.03以下だった。

合法手の評価差は、人間の対局の中盤の局面967個（合法手は計85,757手）で、着手による評価の変化を比べた。
診断は、渡したファイルの各対局の開始局面だけを使う。教師の本は全対局を初期局面から生成しているので、本を渡すと局面がすべて初期局面になる。そこで、人間の対局の局面を開始局面として生成した別のファイルを使った。作り方は`diagnose-generation.sh`の冒頭にある。

| 項目 | 平均 | 絶対値の平均 | 絶対値の最大 |
|---|---|---|---|
| PST＋FMの評価の変化 | +6.11 cp | 99.05 cp | 3,414 cp |
| 第0世代（v0）の評価の変化 | +15.74 cp | 17.17 cp | 2,506 cp |
| 第1世代の評価の変化 | −16.23 cp | 44.40 cp | 2,512 cp |
| 第1世代とPST＋FMの評価の変化の差 | −22.34 cp | 88.88 cp | 1,800 cp |

2つのモデルの出力を突き合わせたとき、片方にしかない合法手は0件だった。
着手による評価の変化の絶対値の平均は、v0の17.2 cpから第1世代で44.4 cpに増えており、第1世代は、駒割と位置の表だけのv0よりも着手ごとの評価の差を大きくつけている。

### ネットの保管と動作の確認

第1世代のネットのSHA-256は`2c0236dd6fac64bcca3cd9e548b6760006dc2240debcc0c1c1d2e9157bf02ec9`であり、NAS（ネットワーク接続の記憶装置）の`/mnt/synology_nas/minase/nnue/nets/`にSHA-256の名前で置いた。
反復のコミットのエンジンに`EvalFile`で渡した深さ5の`bench`は15局面を完走し、世代の記録`gen-1/generation.json`に、反復のコミット、ネットのパスとSHA-256、およびK_tが書かれた。

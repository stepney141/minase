# 世代反復の第3世代の教師の生成と学習

## 目的

[世代反復の設計書](../../plans/archived/nnue-generation-iteration.md)のフェーズ3として、第2世代のNNUE（着手ごとに差分で更新できる小さなニューラルネットの評価関数）のネットで第3世代の教師ファイル（以下、本）を129本生成し、その本だけから、王の位置を使わない入力P型のNNUEを学ぶ。
本数は、1億局面に相当する本数k＝43の3倍である。
第3世代からは、学習の条件が標準レシピv3から標準レシピv4に替わり、学習器も、エポックの最後に残る端数のバッチで更新する不具合を直したコミットに替わった（[端数バッチと学習率の設計書](../../plans/archived/nnue-decay-to-end.md)）。
学んだネットの強さは、[第2世代との判定](nnue-generation-iteration-gen3-stc.md)と[masterとの比較](nnue-generation-iteration-gen3-master-stc.md)で測る。
教師の生成器、エンジン、および強さを判定する対局の条件は、第1世代と第2世代から変えていない。
作業に使う手元の計算機を作業機、教師の生成のために借りる機械を生成機、学習のために借りるGPUつきの機械を学習機と呼ぶ。

## コマンドライン

### 本の生成

機械は、計算機を時間単位で借りられる市場vast.aiで借りた。
条件に合う機械の出品が途絶えるたびに借り方を替えて制御スクリプト`teacher_generation.py`を起動し直す`generate_auto.py`（[第1世代の付随ディレクトリ](nnue-generation-iteration-gen1-training/)）を、次の引数で起動した。

```console
python3 generate_auto.py 3 128 <第2世代のネット> 2026-11-25T14:12:36Z 60 155327 1.5 1.5
python3 generate_auto.py 3 128 <第2世代のネット> 2026-11-25T14:12:36Z 60 155327,146109 1.5 1.5
```

引数は順に、世代、最後の番号、教師の生成に使うネット、絶対期限、費用の上限（米ドル）、除外する機械、オンデマンドの時間単価の上限、および中断可能インスタンスの入札額の上限である。
2行目は、最初に借りた機械が遅かったので、その機械を除外に加えて起動し直したものである（「結果」の「教師の量」）。
生成の条件は第1世代と同じ（1本7,500局、1手20,000ノード、`--random-moves 0`、`--max-ply 4000`、`--hash-mb 16`、`--chunk-games 250`）であり、番号iの本のシードは`9,300,000,000 + 100,000×i`である。

2026年11月23日に利用者が、vast.aiの残高が尽きた後の生成を手元の別の機械ryzen0で続けることと、残高が尽きる前からryzen0を並行して動かすことを決めた。
ryzen0には、反復のコミットをgit bundleから展開してビルドした生成器を置き、本書の[付随ディレクトリ](nnue-generation-iteration-gen3-training/)の`ryzen0_generation.py`で、番号の大きい側から1本ずつ生成した。

```console
python3 ryzen0_generation.py 3 128 <ryzen0に置いた第2世代のネット> <ネットのSHA-256> 64 nnue-generation-iteration-gen3-auto.service
```

ryzen0での生成のコマンドは、借りた機械と同じ条件で、同時対局数だけが64である。
完成した本は、借りた機械の場合と同じ受け入れの検査（全対局の復号と、ヘッダおよび生成ログの照合）に通してから置いた。

生成の途中でvast.aiの2段階認証のセッションが切れ、制御スクリプトが生成機を削除できないまま終了したので、認証の要らないSSHだけで本を回収して受け入れる`rented_collect.py`（同じ付随ディレクトリ）を動かした。

```console
python3 rented_collect.py 3 128 gen3-b1-on-demand <ネットのSHA-256> 2026-11-24T07:00:00Z
```

### 学習

129本と生成ログを、連続生成スクリプト`generation_chain.py`の実行ディレクトリの`gen-3/teacher/`と`gen-3/logs/`へハードリンクで置き、付随ディレクトリの`train-generation.sh`を次の引数で実行して`generation_chain.py`を起動した。

```console
train-generation.sh 3 129 9565 16 6 0.6 16 --offer 59566203
```

引数は順に、世代、本数、1 superbatchの更新回数B、学習のスレッド数、学習待ちの上限（時間）、学習機の時間単価の上限（米ドル）、CPUスレッド数の下限、および借りる出品である。
連続生成スクリプトは学習機を借り、学習器のコミットからビルドした学習器を使って、その機械の上で次の学習と診断を実行した。

```console
minase-trainer nnue train layerstack --data <129本> --rules lishogi \
  --teacher-cp-per-logit 733.1159421542734 --lambda 1.0 --seed 1 --threads 16 \
  --output-dir <出力ディレクトリ> --batch 16384 --superbatches 8 \
  --validation-superbatches 1 --device cuda --lr-schedule cosine:8:0.027 \
  --batches-per-superbatch 9565
minase-trainer diag nnue-removal --float <出力ディレクトリ>/latest.npz --net <出力ディレクトリ>/nnue.bin \
  --data <129本> --sample 10000 --seed 1 --output <報告>
```

superbatchは、決まった回数の更新をまとめた単位であり、学習器は1 superbatchごとに検証損失を測る。
標準レシピv4は、1 superbatchを約0.5エポックとして8 superbatch（約4エポック）を最後まで学び、学習率を余弦の予定`cosine:8:0.027`で終わりまでに初期値の0.027倍へ下げて、最後の重み`latest.npz`を書き出す。
検証損失が改善しないときに学習を止める`--validation-patience`は渡さない。
Bは、付随ディレクトリの`recipe_values.py`で、129本の生成ログの記録局面数の合計329,916,365から求めた。
訓練局面数の見積りMは合計の95%にあたる313,420,547、1エポックの更新回数の見積りUはMを1回の更新の局面数16,384で割って切り捨てた19,129であり、BはU÷2を切り上げた9,565である。
`diag nnue-removal`は、駒除去差分（盤上の駒を1枚ずつ除いたときの評価値の差分）の診断である。
教師の探索値を勝率へ換算する教師の勝率尺度K_tは、第1世代で求めた733.12 cp（cpはセンチポーンで、歩兵1枚の100分の1）である。

### 作業機での診断

学習の後に、作業機で、第1世代の付随ディレクトリの`diagnose-generation.sh 3`を実行し、評価値の分布、合法手の評価差、および対局単位の汎化差を診断した。
このうち評価値の分布の診断は全部の本をメモリに開くので、番号が3の倍数の43本だけを渡した。
対局単位の汎化差は129本の全部で求めた。

## エンジン

教師の生成器とエンジンには、全世代で共通に使うコミット（設計書の「反復のコミット」）`f2eb705febe317229addc561ff8a0838c545e2eb`からビルドしたものを使った。
学習器には、設計書の「学習器のコミット」`afdc36fb9695908762de36215248cccac816b0c3`からビルドしたものを使った。世代の記録`gen-3/generation.json`の`trainer_commit`は、このコミットと一致する。
本を生成したネットは、第2世代のネット（SHA-256は`736227caec4d391a73595b47be877dccb06a570baae18e0ca0030b2c0dba0129`）である。
規則セットは、本、学習器の引数、およびエンジンの動作の試験`bench`のいずれも`lishogi`（`L1,L2,P0,P3,R1,E1,E3`）である。
129本のヘッダの生成コミット、ネットのSHA-256、規則セット、シード、および探索のノード数は、受け入れの検査と連続生成スクリプトの照合に通った。

損失は、ネットが出す勝率と、教師の探索値から換算した勝率の差の2乗の平均である。
学習率の倍率は、各superbatchの最後の更新での値である。
PSQTは駒と升ごとの点数の表であり、移動量は、初期値にした手書きの評価関数v0（第0世代）の値からの変化である。
学習は8 superbatchを最後まで学んで終わった（`summary.json`の`stopped_by`は`completed`、`status`は`candidate`、`selected_superbatch`は8）。
`config.json`の`preprocessing.updates_per_epoch`にある実際の1エポックの更新回数Uは19,123であり、学習の長さ8B÷Uは4.0015エポックである。
`training.jsonl`の`epochs`は、1 superbatchごとに0.5002ずつ増えた。
検証損失は8 superbatchを通じて下がり続け、最後の検証損失0.00093282は更新後の検証損失の最小値と同じである。
最後の検証損失と最小値の比は1.000であり、標準レシピv4の見張りの条件（1.02倍以下）を満たした。
第1世代と第2世代の標準レシピv3の学習は、どちらも1.5エポックの重みを選んで2.5エポックで止まっていた。

学習の速さは毎秒131万〜139万局面（16スレッド）、学習の時間は1,703.4秒、教師の前処理は296.7秒だった。
学習器のプロセスの最大常駐メモリは37,281,712 KiB（35.55 GiB）で、1本あたり約0.28 GiBである。
駒除去差分の診断のプロセスの最大常駐メモリは33,895,164 KiBだった。

### 評価の形

学習器は、実数の重みをエンジンが読む整数の重みへ量子化して書き出す。
その量子化誤差と層ごとの飽和の割合は、検証局面の標本10,000局面での値である（学習器が出力する`summary.json`の`quantization`）。

| 項目 | 第3世代 | 第2世代 | 第1世代 |
|---|---|---|---|
| 量子化誤差の絶対値の平均 | 13.18 cp | 14.02 cp | 8.24 cp |
| 量子化誤差の符号つきの平均 | +10.62 cp | −12.93 cp | +7.01 cp |
| 量子化誤差の絶対値の最大 | 90.4 cp | 96.3 cp | 107.4 cp |
| 第1層の飽和の割合 | 0.505 | 0.601 | 0.709 |
| 後段の1層目の飽和の割合（線形の半分） | 0.666 | 0.801 | 0.764 |
| 後段の1層目の飽和の割合（2乗の半分） | 0.122 | 0.100 | 0.014 |
| 後段の2層目の飽和の割合 | 0.529 | 0.611 | 0.560 |

飽和の割合は、活性化の前の値が0以下か1以上になった成分の割合である。
量子化誤差の絶対値の最大は90.4 cpだった。
第1世代の教師を標準レシピv4で学んだネットでは、この値が319.8 cpまで増えていたが（[端数バッチと学習率の設計書](../../plans/archived/nnue-decay-to-end.md)）、第3世代では標準レシピv3で学んだ第1世代と第2世代より小さい。
書き出した重みの時点で1以上の側の飽和は、後段の1層目の2乗の半分で12.3%、第1層で2.6%、後段の1層目の線形の半分で0.7%だった。

駒除去差分の符号が、v0の駒割でその駒を除いたときの差分と逆になった除去は、学習機での診断（検証局面の標本10,000局面）で489,693件のうち1,322件（0.270%）であり、反転した差分の絶対値の平均は35.3 cp、最大は674 cpだった。
この割合は、第1世代の0.046%、第2世代の0.104%から、世代ごとに2倍以上に増えている。
量子化の前の評価では、第1層の累算値から、除いた駒に対応する重みの行を引く計算と、除去後の局面から計算し直した値が一致した（差の最大は0 cp）。

評価値の分布は、NNUEより前の評価関数PST＋FM（駒と升ごとの点数の表PSTに、2駒の関係の補正FMを足したもの）を基準に、番号が3の倍数の43本の全局面から抽出した10,000局面で比べた。

| ネット | 標準偏差 | PST＋FMに対する標準偏差の比 | 相関係数 | 差の絶対値の中央値 |
|---|---|---|---|---|
| PST＋FM（基準） | 1,724.8 cp | | | |
| 第0世代（v0） | 1,007.0 cp | 0.584 | 0.933 | 394 cp |
| 第2世代 | 1,106.7 cp | 0.642 | 0.944 | 361 cp |
| 第3世代 | 1,161.7 cp | 0.674 | 0.947 | 350 cp |

診断の判定は、どのネットも「散らばりの尺度を変えた」（比が0.9〜1.1の外）である。

盤上の駒数が0〜29、30〜59、60〜90の3つの帯での比は、この順に、第3世代が0.713、0.626、0.651、第2世代が0.666、0.610、0.651であり、駒の少ない帯で第3世代の評価値の散らばりが大きくなった。

合法手の評価差の診断では、人間の対局の中盤の局面967個（合法手は計85,757手）で、着手による評価の変化を比べた。

### ネットの保管と動作の確認

第3世代のネットのSHA-256は`cbbccf6f5ee7097fd890086d2cf4bca72ed969da28353cb0c4a2f4d781acc244`であり、NAS（ネットワーク接続の記憶装置）の`/mnt/synology_nas/minase/nnue/nets/`にSHA-256の名前で置いた。
反復のコミットのエンジンに、ネットを指定するオプション`EvalFile`で第3世代のネットを渡した深さ5の`bench`は15局面を完走し、世代の記録`gen-3/generation.json`に、反復のコミット、学習器のコミット、ネットのパスとSHA-256、およびK_tが書かれた。

## 結論

第3世代は、129本、記録局面数329,916,365の教師から、標準レシピv4で4.00エポックを学んだ最後の重みを書き出して作られ、見張りの条件を満たし、学習器の不具合を示す診断はなかった。

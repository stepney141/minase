# 世代反復の第1世代の生成と学習

## 目的

[世代反復の設計書](../../plans/nnue-generation-reset.md)の第1世代として、手書きの評価関数v0で教師を生成してNNUEを学習し、学習の健全性、D、および評価の形を記録する。
学習の途中で検証損失が上がり続けたので、λだけを変えた比較用の学習を行い、原因を切り分ける。
棋力は[第1世代のSTC](nnue-generation-reset-gen1-stc.md)に記録する。

## コマンドライン

教師は連続生成スクリプトで生成した。
主な引数は次のとおりであり、シードは本の番号`i`について$`9{,}010{,}000{,}000+100{,}000i`$である。

```console
python3 scripts/vast/generation_chain.py run --gen0-commit 6f874692fb91544c94394ca0e8df25299ef2e02d \
  --first-generation 1 --last-generation 1 --positions-per-generation <局面数> \
  --games 7500 --nodes 20000 --random-moves 0 --max-ply 4000 --hash-mb 16 \
  --calibration-books 4 --lambda 0.75 --feature-set P --width 256 --head pairwise-l16-l32 \
  --batch 16384 --epochs 50 --patience 5 --train-seed 1 --device cuda --validation-interval 1000 \
  --lr-schedule cosine:3:0.1 --train-threads 4 --removal-sample 10000 --removal-seed 1 --bench-depth 5
```

局面数は当初1億とし、生成機の障害の後に6,500万へ改めた。
スクリプトは第1世代のネットを次のコマンドで学習した。
`$BOOKS`は本0から本25までの26本である。

```console
minase-trainer nnue train --data $BOOKS --base base.bin --lambda 0.75 --teacher-cp-per-logit calibrate \
  --seed 1 --threads 4 --output-dir gen-1/train --feature-set P --width 256 --head pairwise-l16-l32 \
  --batch 16384 --epochs 50 --patience 5 --device cuda --validation-interval 1000 --lr-schedule cosine:3:0.1
```

比較用の学習は、`--lambda 1.0`、`--epochs 5`、および出力先のほかは同じである。
`base.bin`は、v0を線形の経路だけで表したネットに、最初の4本から求めたKを入れたものである。

診断は[スクリプト](nnue-generation-reset-gen1-training/gen1_diag.py)で順に実行した。
評価値の分布と駒除去差分の標本は10,000局面、シードは1、`fit-linear`の$`\tau`$は10、20、40、および80である。
対局単位の汎化差は[構成の見直しの集計](../nnue-architecture-revision/nnue-architecture-revision-init-training/outcome_gap.rs)で求め、[区間の計算](../nnue-architecture-revision/nnue-architecture-revision-init-training/gap_report.py)に通した。

## エンジン

| 名前 | コミット | 内容 |
|---|---|---|
| 第0世代 | `6f874692` | v0を線形の経路だけで表したネットを埋め込む。教師の生成に使った。 |
| λ=0.75のネット | `fb92b0bc` | 設計書の条件で学習した。ネットの検査和は`b71f5708…`である。 |
| λ=1.0のネット | `5f81bb71` | 同じ教師で学習した比較用。ネットの検査和は`b3ad4805…`である。 |

規則セットは`L0,P0,R1,E0`である。

## 環境

教師は2026年11月4日から5日に、vast.aiの出品48544090（AMD EPYC 9654の2基構成、384スレッド、1時間1.011米ドル）で生成した。
学習と診断は2026年11月5日に、作業機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB、RTX 3060 Ti）で行った。

## 結果

### 生成

生成機は2026年11月5日の6時57分ごろに接続できなくなった。
時刻は、スクリプトが30分の再試行の後に7時27分に止まったことからの逆算である。
スクリプトは生成機を削除し、インスタンスの一覧が空であることを確かめた。
貸し手の障害とみられる根拠は、作業機の回線が正常でそのホストにだけ接続できないことと、出品の検証状態が`verified`から`deverified`へ変わったことである。

選定条件に合う出品がなかったので、2026年11月5日の利用者の決定により、受け取った26本で学習した。

| 項目 | 値 |
|---|---:|
| 本 | 26本（予定は40本） |
| 対局 | 193,927局 |
| 記録局面 | 65,661,060 |
| 訓練と検証 | 62,348,534局面、3,312,526局面 |
| 1本の所要時間の中央値 | 1,783秒 |
| K（最初の4本から） | 679.03 cp |
| 生成機の実費 | 14.80米ドル |

実費は、作成の前と削除の後の残高の差である。

### 学習

2つの学習は、Kと訓練と検証の分割が一致している（`training_indices_sha256`は`b66215cc…`、`validation_indices_sha256`は`fba620c8…`）。
検証損失の目標がλで異なるので、2列の絶対値は直接比べられない。

| 項目 | λ=0.75 | λ=1.0 |
|---|---:|---:|
| エポック0の検証損失 | 0.486957 | 0.487536 |
| 途中検証の最小の検証損失 | 0.479785 | 0.479719 |
| その更新回数 | 1,000 | 8,000 |
| エポックごとの最良 | エポック1の0.482181 | エポック2の0.479712 |
| 最後のエポック | 6（早期終了） | 5（上限） |
| 最後のエポックの検証損失 | 0.484304 | 0.479761 |
| エポック1の訓練損失 | 0.474502 | 0.479610 |
| エポック1の検証損失−訓練損失 | 0.00768 | 0.00014 |
| エポック5の検証損失−訓練損失 | 0.01514 | 0.00123 |
| 非線形出力の標準偏差（エポック5） | 423 cp | 353 cp |
| 量子化誤差の平均（上限16.98 cp） | 8.48 cp | 4.64 cp |

λ=0.75の検証損失は1,000更新目から上がり続け、学習率を下げても戻らなかった。
エポック1の訓練損失はまだ学習に使っていない局面で計算する値であるが、λ=0.75では検証損失より0.00768低い。
1エポックの学習は約3分で、そのうち更新の計算は約46秒である。
1更新の30 msのうちGPUの計算は12 msであり、学習中のGPU使用率は約40%だった。

### 対局単位の汎化差

対局の結果を目標とした損失を、エンジンの整数の評価で求めた（[出力](nnue-generation-reset-gen1-training/gap_report.out)）。
訓練の対局は182,774局（10局面ごとに選んだ6,234,865局面）、検証の対局は9,762局（全3,312,526局面）である。
区間は対局を単位とする対応のあるブートストラップ（1,000回、シード1）の95%区間である。

| ネット | 訓練 | 検証 | 汎化差 |
|---|---:|---:|---:|
| 第0世代 | 0.484450 | 0.489303 | +0.004853 |
| λ=0.75 | 0.427195 | 0.469898 | +0.042703 |
| λ=1.0 | 0.478125 | 0.483199 | +0.005074 |

| 比較 | 汎化差の差 | 検証の損失の差 |
|---|---:|---:|
| λ=0.75−λ=1.0 | +0.037628 [+0.035823, +0.039356] | −0.013301 [−0.014966, −0.011743] |
| 第0世代−λ=1.0 | −0.000221 [−0.000685, +0.000284] | +0.006104 [+0.005641, +0.006600] |
| 第0世代−λ=0.75 | −0.037850 [−0.039950, −0.035718] | +0.019405 [+0.017504, +0.021359] |

λ=0.75だけが、訓練の対局の勝敗を検証の対局よりはるかに高い精度で予測している。
検証の対局の勝敗の予測は、λ=0.75が最も良い。

### Dと評価の形

| 項目 | λ=0.75 | λ=1.0 |
|---|---:|---:|
| D | −0.009184 | −0.009990 |
| Dの95%区間 | [−0.011376, −0.006734] | [−0.012411, −0.007401] |
| 選ばれた$`\tau`$ | 80 | 80 |
| 大きい補正（q=90） | 獅子 約−340 cp | 龍王 +284〜+311 cp、龍馬 +241〜+250 cp |
| 駒除去差分の符号反転 | 0.853%（4,220件） | 0.091%（450件） |
| 反転の平均の大きさ | 63.4 cp | 115.3 cp |
| PST＋FMに対する標準偏差の比 | 0.660 | 0.643 |
| PST＋FMとのピアソン相関 | 0.978 | 0.975 |

第0世代のPST＋FMに対する標準偏差の比は0.618、相関は0.970である。
比が0.62前後なのは、Kがこれまでのネットの1,072.7 cpの約0.63倍であることと整合する。
補正の詳細は[λ=0.75](nnue-generation-reset-gen1-training/fit_report-lambda075.out)と[λ=1.0](nnue-generation-reset-gen1-training/fit_report-lambda100.out)の出力にある。
合法手の評価差の診断では、どちらのネットも47局面すべてで合法手の集合がPST＋FMと一致した。

## 結論

λだけを変えると学習の形が大きく変わるので、λ=0.75の検証損失の上昇は教師に混ぜた対局結果に由来する。
汎化差の結果から、λ=0.75のネットは訓練の対局の勝敗を覚えていると判断する。
同じ教師と同じ初期値のλ=1.0のネットは第0世代と同程度の汎化差に留まるので、v0の書き出しと`--base`の読み込みの不具合では説明できない。
ただし、検証の対局の勝敗の予測はλ=0.75が最も良いので、この記憶だけで棋力を判断することはできず、対局で確かめる必要がある。

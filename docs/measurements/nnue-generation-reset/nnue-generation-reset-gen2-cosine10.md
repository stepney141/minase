# 第2世代の教師での学習率の予定と書き出すネットの比較

## 目的

第2世代までのネットは、検証損失がエポック2前後で最良になり、以後ほぼ平らになる。
2026年11月5日に利用者は、学習率の予定`cosine:3:0.1`の下げ方が先行の学習器より急であることを問題にし、次の比較を指示した。

- 総長を伸ばした`cosine:10:0.1`のネットが、第2世代のネットより強いか。
- 同じ学習の中で、検証損失が最良のネットと最後のネットのどちらが強いか。
- 最良のエポックが早い原因が第1層の幅にあるか（幅128で学習し、対局はしない）。

先行の学習器の学習率の予定は[調査メモ](../../research/nnue-training-recipes.md)にある。

## コマンドライン

学習、補正、診断、コミット、およびSTCは[スクリプト](nnue-generation-reset-gen2-cosine10/run_cosine10.py)で順に実行した。
教師、初期値、シード、およびその他の引数は[第2世代の学習](nnue-generation-reset-gen2-training.md)と同じで、`--lr-schedule cosine:10:0.1`と`--threads 8`だけが違う。

学習は当初`--patience 5`で始め、最良のエポックが早いと総長に届く前に止まることが分かったので、エポック5の後に`--epochs 10 --patience 50`へ改めて再開した。
この2つの引数は学習量の上限であり、学習の軌跡を変えない。

学習器は検証損失が最良のネットだけを書き出すので、エポック10のネットは、チェックポイントの複製の進捗の「最良」の欄だけをエポック10へ書き換えて再開し、通常の経路で書き出した。
重みと最適化器の状態は書き換えていない。
この手順は一度だけの比較のためのものであり、後に学習器へ`--export-epoch last`を加えた（コミット`6a69920f`）。

最良と最後の比較と幅128の学習は[スクリプト](nnue-generation-reset-gen2-cosine10/run_best_vs_last_and_width128.py)で実行した。
幅128の学習は、第2世代の学習の引数のうち`--width 128`と`--threads 8`だけを変えた。

STCはいずれも次の形で実行した。

```console
minase match run --run-dir data/matches/<測定名> --seed <シード> \
  --candidate commit:<候補> --baseline commit:<基準> \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

| 測定名 | シード | 候補 | 基準 |
|---|---:|---|---|
| `nnue-generation-reset-gen2-cosine10-stc` | 20261202500000 | `cosine:10:0.1`のエポック10 | 第2世代 |
| `nnue-generation-reset-gen2-cosine10-last-vs-best-stc` | 20261202600000 | `cosine:10:0.1`のエポック10 | `cosine:10:0.1`のエポック2 |

## 環境

2026年11月5日から6日に、作業機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB、RTX 3060 Ti）で行った。
学習とSTCは順に実行し、重ねていない。
第2世代は生成機のRTX 5090で学習したが、作業機で同じ条件で再学習したネットがバイト単位で同じだったので（[教師の量の比較](nnue-generation-reset-gen2-volume.md)）、GPUの違いは比較結果に影響しない。

最良はエポック3で、エポック8で早期終了した。
最良の検証損失は幅256の0.521349より0.000022高い。

[構成の見直しの初期値の比較](../nnue-architecture-revision/nnue-architecture-revision-init-training.md)では、同じ教師と同じ`cosine:3:0.1`で、隠れ層を持たない当時の幅128のネットの最良はエポック19、現行の構成はエポック3だった。
今回の幅128は出力部が現行の構成なので、最良のエポックが早い原因は第1層の幅ではなく、出力部の構成か教師の性質にあると考えられる。
出力部の構成の影響は、学習器が現行の出力部しか持たないので測っていない。

## 結論

`cosine:10:0.1`で10エポック学習したネットは第2世代に`H0`だった。
同じ学習の中でも、最後のネットは検証損失が最良のネットに`H0`だった。
今の構成と教師では、学習率を長く保つ学習も、決めた学習量の最後のネットを使う方式も、強くならない。
検証損失で最良のネットを選ぶ現行の方式は、この2つの比較で対局の裏付けを得た。
最良のエポックが早いことは、学習率の予定と第1層の幅では説明できない。

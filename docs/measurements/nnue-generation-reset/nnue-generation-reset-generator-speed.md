# 生成機での教師生成の速さ

## 目的

[世代反復の設計書](../../plans/nnue-generation-reset.md)の第1世代の生成が、[試走](../vast-selfplay/vast-selfplay-trial.md)から見積もった1本約12分の2倍以上かかったので、同じ生成機で過去のコードや同時対局数の条件と比べて、遅くなった理由と速くする余地を調べる。

## コマンドライン

全スレッドの比較は、生成の区切りで生成機が空いている間に、各コミットのビルドで次を実行した。
同時対局数`C`と同じ局数を指定し、1局を200手で打ち切るので、全スレッドがほぼ最後まで探索する。

```console
minase data selfplay generate --allow-dirty --output <一時ファイル> --seed <シード> --games <C> --concurrency <C> \
  --nodes 20000 --random-moves 0 --max-ply 200 --hash-mb 16
```

同時対局数96と144は、生成中のプロセスを`SIGSTOP`で一時停止して測った。
停止中のプロセスがメモリを保持しているので、同時192局以上はこの方法では測れない。
NUMAノードごとの条件は、`taskset -c 0-95,192-287`と`taskset -c 96-191,288-383`で同時192局のプロセスを2つ同時に動かした。
常駐メモリは、同時384局の開始から12秒後の`VmRSS`である。
1スレッドの速度は`taskset -c 5 minase dev bench --depth 9 --repetitions 1`で測った。

## エンジン

| コミット | 内容 |
|---|---|
| `9f393ecc`（2026年10月17日） | 試走のコミット。幅128のネットを埋め込む。continuation historyとcontinuation correction historyを持たない。 |
| `6f874692`（2026年11月4日） | 世代反復の第0世代。幅256、手書きの評価関数v0を線形の経路だけで表したネットを埋め込む。 |

規則セットは`L0,P0,R1,E0`である。

## 環境

2026年11月4日に、vast.aiの出品48544090（AMD EPYC 9654の2基構成、物理192コア、384スレッド、NUMAノード2、メモリ125 GB、1時間1.011米ドル）で測った。
ビルドは`rust:1.98.0-bookworm`のrustc 1.98.0と`target-cpu=native`である。
cgroupのCPU上限は368.64 CPU分である。

## 結果

本番の第1世代の本（7,500局）は次のとおりである。
2本目は、測定のための一時停止（約3分）を含む。

| 本 | 所要時間 | 記録局面（`recorded_positions`） | 全体の探索速度 |
|---|---:|---:|---:|
| 0 | 1,720秒 | 2,509,559 | 約3,740万NPS |
| 1 | 1,818秒 | 2,524,163 | 約3,530万NPS |

試走の1本は653秒、2,748,180局面、約1億1,100万NPSだった。

全スレッドの比較は次のとおりである。

| コミット | 条件 | 全体の探索速度 | 常駐メモリ |
|---|---|---:|---:|
| `9f393ecc` | 同時384局 | 1億540万NPS | 7.75 GB |
| `6f874692` | 同時384局（3回） | 3,564万、3,459万、3,565万NPS | 74.5 GB |
| `6f874692` | 同時96局 | 2,135万NPS | |
| `6f874692` | 同時144局 | 2,324万NPS | |
| `6f874692` | NUMAノードごとに同時192局を2つ（2回） | 3,772万、3,861万NPS | |

1スレッドの`dev bench`は`9f393ecc`が981,744 NPS（4,661,723ノード）、`6f874692`が463,189 NPS（196,431ノード）である。
探索の木の大きさが異なるので、この比は参考値である。

1局あたりの常駐メモリの増加は約178 MBである。
試走の後に入った2つの表は、continuation historyが69,755,904要素のi16で約140 MB（2026年10月19日のコミット`5e8471f2`）、continuation correction historyが18,040,320要素のi16で約36 MB（2026年10月20日のコミット`a03a1d9b`）であり、この2つの表が増加の大部分を占める。
これらの表の大きさは駒種の数と升の数の2乗に比例するので、チェスより盤も駒種も多い中将棋では大きくなる。
表の大きさが探索速度を下げたことは推測であり、表だけを変えた比較は行っていない。

## 結論

全体の探索速度は試走のコードの約3分の1になり、メモリは約10倍になった。
NUMAノードで分けても約9%しか速くならず、同時対局数を減らすと遅くなるので、同時384局のままとする。
1億局面には40本、約20時間かかるので、8世代では約165米ドルになる。
2026年11月4日の利用者の決定により、反復を第4世代までとした。
探索の表を小さくする案は、探索の変更になるので本書の対象外であり、別の計画としてSPRTで判定する必要がある。

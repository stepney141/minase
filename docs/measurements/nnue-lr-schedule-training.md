# NNUE学習器の学習率スケジュールの学習の記録

## 目的

[NNUE学習器の学習率スケジュール](../plans/nnue-lr-schedule.md)について、学習に使う教師データの生成、学習器の変更の検査、および5つの学習率の設定による学習の結果を記録する。
棋力測定ではないので、ペンタノミアル度数やLLRは持たない。
段階ゲートの測定は別の記録に書き、設計書からリンクする。

## 教師データの生成

学習に使う30ファイルは、[教師データ形式の統一](../plans/archived/unified-teacher-format.md)で以前のデータを削除したため、2026年10月14日に再生成したものである。
生成の条件は、[NNUEの完全代替](../plans/archived/nnue-replacement.md)のフェーズ1で新規に生成した20ファイルと同じであり、1ファイル7,500局、1局面20,000ノード、4,000手で破棄、置換表16 MB、ランダム着手なし、規則セット`L0,P0,R1,E0`である。
生成には、master `31c2a46`（評価関数はNNUE、埋め込みの`crates/minase/nets/nnue.bin`のSHA-256は`3679bebf…`）をdetached HEADでチェックアウトしたworktreeまたはcloneでビルドした`minase`を用いた。
以前の20ファイルの生成に用いたバイナリは基準M `8d0e382`（評価関数はPST＋FM）だったので、教師データの生成に用いた評価関数と探索は当時と異なる。

シードは、過去の生成と重ならない7,100,000から9,900,000までの100,000刻みの29個と10,100,000の1個とした。
7,000,000は[シャッフルの予備測定](shuffle-order-preliminary.md)、10,000,000は段階9の診断の再評価で使用済みだったので避けた。
生成は2台で分担した。

| 機械 | CPU | 同時対局数 | 定常の生成速度 | 分担 |
|---|---|---|---|---|
| 作業機 | Core Ultra 7 265KF（20コア） | 1本目は12、2本目以降は18 | 同時12局で約1.77局/秒（1ファイル約72分） | 7,100,000〜8,200,000と9,600,000〜9,900,000の16本 |
| ryzen0 | Ryzen Threadripper 2990WX（32コア、64スレッド） | 60 | 約1.51局/秒（1ファイル約83分）。同時30でも約1.62局/秒であり、この精度では同時対局数による差は検出できなかった | 8,300,000〜9,500,000と10,100,000の14本 |

ryzen0ではGitHubから`31c2a46`をcloneして`cargo build --release --locked --bin minase`でビルドした（Rust 1.99.0、作業機はRust 1.98.0）。
2台のバイナリが同一の出力を生成することは、シード123456789で8局を生成したファイルのSHA-256が両機で一致したこと（`6003c660…`）により確認した。
生成の探索は固定ノード数で打ち切るため、同じ機械で学習器の検査やビルドを並行実行しても生成データは変わらない。
表の生成速度は進捗行2点の差から出した暫定値であり、各ファイルの`generate-<シード>.log`の`elapsed_seconds`が揃った時点で置き換える。

作業機の1本目（シード7,100,000、同時12局、lishogiのBotと並行）は4,328秒で完了した。
ヘッダの形式の版は2、生成コミットは`31c2a46`、規則セット`L0,P0,R1,E0`、シード7,100,000であり、7,500局のうち86局を手数の上限で破棄して7,414局を保存した。
全局面3,479,022のうち、除外対象となった局面の内訳は、詰みの帯が0.79%、戦術的な局面が14.70%、反復が0.11%である。
学習器に読み込まれる局面数は2,809,947（訓練2,667,798、検証142,149）であり、教師用Kは1,000.28であった。
終局の内訳は、詰み7,064局、反復の引き分け97局、駒枯れの引き分け1局である。なお、重複局面は0であった。

## フェーズ1　学習器の変更の検査

学習器の変更（`--lr-schedule`と`--validation-interval`）は、ブランチ`nnue-lr-schedule`の2コミット（倍率と途中の検証）からなる。
検査は2026年10月14日に作業機（RTX 3060 Ti、CUDA 13.4、ドライバ615.71、cudarc 0.19.10、Rust 1.98.0）で行った。
検査の間、同じ機械で教師データの生成（同時12局）とlishogiのBotが動いていた。

| 検査 | 方法 | 結果 |
|---|---|---|
| 既定値のビット一致 | 1本目の教師データ（`generated-7100000.bin`）で、着手時のmaster `31c2a46`の学習器と変更後の学習器を、スケジュールと間隔の既定値、幅128、先読み教師（γ=0.9、n=40）、バッチ16,384、シード1、1エポック、`--threads 4`で学習し、`nnue.bin`のSHA-256と`training.jsonl`の損失欄を比較。変更後の学習器では`--validation-interval 50`を付けた3条件目も学習 | 3条件とも`nnue.bin`のSHA-256が`5e22b452…`で一致。エポック0の検証損失0.4434798238638906、エポック1の訓練損失0.4501682563548211、検証損失0.438854971494723、符号一致率0.7356848539079357がすべて一致 |
| 倍率の式 | `schedule.rs`の単体テスト（解析と表示の往復、不正な入力の拒否、t = 0、半減期、総長、下限に達した後の値、`validate`の境界） | 通過 |
| GPUとCPU参照の等価性（倍率つき） | `gpu_step_matches_parallel_cpu_with_mixed_targets_and_custom_coefficients`を倍率1.0と0.37で実行。`minase-trainer nnue check-equivalence`を両方の型、幅6（バッチ100）と幅128（バッチ4,096）で実行 | 通過。CLIは4条件とも「一致」（最大絶対誤差はP型幅128で1.144×10⁻⁵、HalfKP-hm-b8幅128で4.843×10⁻⁶、許容誤差`1e-6+1e-5×|CPU|`以内） |
| 指数減衰の再開 | `--lr-schedule exponential:1:0.1`で、2エポック連続で学習した場合と1エポックで中断して再開した場合（CPU、合成データ）の`latest.npz`の重み、AdamWの状態、更新回数、および`nnue.bin`を比較。`training.jsonl`の倍率の欄も式と比較 | ビット単位で一致 |
| 途中の検証の再開 | 1エポック後に`validation-interval.jsonl`へチェックポイントより後の行を模擬的に追記して再開し、行の切り詰めと再開後の`nnue.bin`の一致を検査（CPU、合成データ） | 通過 |
| 再開時の学習率スケジュールの変更の拒否 | `--lr-schedule`を変えて`--resume` | `checkpoint settings mismatch`で拒否 |
| 途中の検証の有無による学習結果の不変性 | `--validation-interval`の有無で`nnue.bin`、`latest.npz`、損失欄を比較（CPU、両方の型） | 一致 |
| 静的検査とテスト | `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test -p minase-trainer`（238件）、`cargo test -p minase-trainer -- --ignored gpu_`（31件） | すべて通過 |

1本目の教師データでの学習では、1エポックの更新回数Uは163であり、`--validation-interval 50`の途中の検証は更新50、100、150の3回記録された。
検証損失は0.4407、0.4394、0.4389と単調に減少し、エポック1終了時の値0.4389に達した。
検証集合142,149局面の評価は約0.7秒、途中の検証3回の所要時間は合計6.0秒（パラメータの回収と記録を含む）だった。
量子化誤差は平均7.18センチポーン（上限`K/40` = 26.8センチポーン以内）、最大37.50センチポーンで、平均に対する検査を通った。

## フェーズ2　5本の学習

教師データの30ファイルが揃ってから学習する。
`--validation-interval`は、全30ファイルの1エポックの更新回数Uの4分の1を切り上げた値とする。
1本目の訓練局面数2,667,798から30ファイルの訓練局面数を約8,000万と見込むと、Uは約4,900、`--validation-interval`は約1,225である。

# NNUEの初代のネットの学習と診断

## 目的

[NNUEの共通土台と初代のネットによるPST＋FMの完全代替](../../plans/archived/nnue-replacement.md)のフェーズ2の学習試走とフェーズ4の学習について、設定、学習曲線、量子化誤差、および対局前の検査の結果を記録する。
フェーズ2の試走は、学習器が本環境のGPUで幅128を実行できることと、1エポックの所要時間を確かめるためのものであり、候補ではない。
本書の「フェーズ2の試走」と「フェーズ3の正しさの検査」は、2026年10月11日に設計書を共通土台の構成へ改める前の番号であり、P型に固定した旧学習器（旧フェーズ2）と旧Rust実装（旧フェーズ3）の記録である。改めた設計書では、共通土台がフェーズ2、学習器の作り直しがフェーズ3に当たる。

## コマンドライン

学習器は、ブランチ`nnue-replacement`の`tools/train/`（コマンド`train-nnue`、本体の仮想環境を`PYTHONPATH=tools/train/src`で使う）である。
基準Mはmaster `6b97cc26`であり、初期値はJ75の整数化前のPST（`data/pst-fm-joint-training/j75/pst-float.npz`、SHA-256 `828f8c00…`）、駒価値と出力用Kは基準Mの`crates/minase/nets/pst.bin`（SHA-256 `efe2c145…`）から写す。

フェーズ2の試走は次の2本である。

```console
# エポック0（幅64）。フェーズ3の埋め込みと一致テストに使う。
train-nnue train --data data/gen3/generated-1500000.bin \
  --init-pst data/pst-fm-joint-training/j75/pst-float.npz --base crates/minase/nets/pst.bin \
  --width 64 --epochs 0 --device cuda --output <scratch>/epoch0-w64.bin
# 幅128、1エポック、先読み教師。GPUメモリと1更新の時間の測定用。
train-nnue train --data data/gen3/generated-1500000.bin \
  --init-pst data/pst-fm-joint-training/j75/pst-float.npz --base crates/minase/nets/pst.bin \
  --width 128 --epochs 1 --device cuda --lookahead-gamma 0.9 --lookahead-plies 40 \
  --output <scratch>/trial-w128.bin
```

その他の引数は既定値（バッチ16,384、除去差分の分割2,048、シード1、線形の学習率0.03、非線形の学習率10⁻³、非線形の重み減衰10⁻⁴、除去損失の係数1000、λ=1.0）である。

## 環境

学習機はRTX 3060 Ti（8 GB）、PyTorch 2.13.0（CUDA 13.0）である。
試走の間、同じ機械で浅い教師データの生成（同時12対局）とlishogiのBotが動いていた。

幅128の学習は本環境で実行でき、最大GPUメモリは8 GBの16%にとどまる。
1更新0.70秒を、既存の約2,920万局面と新規の約5,100万局面の合計（約8,000万局面、1エポック約4,900更新）に当てはめると、1エポックは検証を含めて約1時間である。
24時間の上限は約24エポックに当たり、50エポックの上限より先に時間の上限が働く。
エポック0の非線形部分は出力重みが0なので、量子化誤差は線形部分の丸めだけであり、幅128の1エポック後の誤差6.15センチポーンは活性化の整数近似（127で割る代わりに128で切り捨て）と第1層の尺度127による。

### 駒除去差分の補助損失の働き

幅128の1エポック後のネットで、訓練集合の先頭2,048局面について補助損失の内訳を調べた。
適格な除去（王駒を除く盤上の駒で、v0の参照が0でない向きを与えるもの）は1局面あたり60.9件あり、除去差分の平均絶対値は725センチポーン（線形部分が支配的で、非線形部分の寄与は30センチポーン）、参照の平均絶対値は464センチポーンだった。
下限側の罰則（参照の向きへの移動が0.25センチポーンに満たない）が発火した除去は適格な除去の8×10⁻⁶、上限側（基準より悪化）は0件、逆向きの除去も8×10⁻⁶だった。
したがって補助損失は係数1000を掛けても合計損失の約10⁻⁴にとどまり、学習中はほとんど束縛しない安全装置として働く。
同時学習（J75）の学習でも除去損失は1エポック目で約10⁻⁶、2エポック目で1桁下がっており、同じ性質である。
この状態は設計どおり（損失を課すが係数を調整しない）であり、対局前の検査には影響しない。

### 学習器の作り直しの検査と試走（改めた設計書のフェーズ3）

学習器`train-nnue`を、入力特徴集合の仕様、線形経路・特徴変換部・出力部の部品、特徴分解（HalfKP-hm-b8）、および3つのパラメータ群（線形、特徴変換部、出力部）の最適化へ作り直した。
入力は世代3の1ファイル（`data/gen3/generated-1500000.bin`、訓練2,814,063局面、検証144,088局面）、初期値はJ75の`pst-float.npz`、駒価値と出力用Kは`crates/minase/nets/pst.bin`である。
測定機では教師データの生成（同時12局）が並行して動いていた。

| 検査 | 方法 | 結果 |
|---|---|---|
| P型の回帰 | 作り直し前の実装（コミット`941438b`）と、120局面、幅4、シード13で比較 | エポック0と1エポック後の浮動小数点の全重み、損失列、およびMNUEファイルが一致 |
| エポック0の線形部分 | 両方の型で`--epochs 0`、幅64で書き出し、`nets/pst.bin`の線形重み、駒価値、Kと比較 | 両方とも一致。P型のネットは、作り直し前の学習器で作った埋め込みの`nets/nnue.bin`と線形、第1層、バイアス、出力がすべて一致 |
| エポック0のP型とHalfKP-hm-b8の同一性 | 上の2本を`minase dev nnue-probe`で試走の21,609局面について評価し、整数評価を比較。Pythonの`unittest`では王駒が一意でない局面も含めて浮動小数点と整数の評価を比較 | すべての局面で一致。検証損失も両方とも0.443790667 |
| 特徴分解の勾配と規則 | 非0の出力重みを持つ小さな例で仮想行の勾配、更新後の未観測の行、切り詰め、埋め草、畳み込み前後の順方向を検査（`unittest`、239件） | すべて通過 |

試走は、幅128、1エポック、先読み教師（γ=0.9、n=40）、バッチ16,384、除去差分の分割2,048で、両方の型について行った。

|---|---:|---:|
| 学習速度（局面/秒、検証を除く） | 27,021 | 20,860 |
| 1エポックの学習時間 | 104秒 | 135秒 |
| CUDAの最大確保メモリ | 2.33 GiB | 3.72 GiB |
| 検証損失（エポック0→1） | 0.437095→0.436078 | 0.437095→0.436605 |
| 検証の符号一致率（エポック1、引き分けを除く138,882局面） | 0.7759 | 0.7765 |

この速度から、全30ファイル（訓練は約7,600万局面）の1エポックは、P型で約47分、HalfKP-hm-b8で約61分と見込まれる。
候補1本あたり24時間の上限では、P型が約30エポック、HalfKP-hm-b8が約23エポックに当たる。
20エポックで収束するとすればHalfKP-hm-b8の学習は約20時間であり、1世代の生成時間（約22時間）を超えないので、設計書の「学習器」にあるtataraのフォークを再検討する条件には当たらない見込みである。
ただし、生成と同居した状態の値であり、収束までのエポック数はフェーズ4で確かめる。
どちらの型も8GBのGPUに収まる。

### フェーズ4の学習

学習器は[Rust製NNUE学習器（GPU）](../../plans/archived/nnue-trainer-rust.md)の`nnue-trainer train`（コミット`e4215f6`のバイナリ）であり、Pythonの学習器は使っていない（2026年10月12日の利用者の決定）。
入力は全30ファイル（既存10ファイルと新規20ファイル、訓練82,712,114局面、検証4,354,965局面）、初期値はJ75の`pst-float.npz`、駒価値と出力用Kは基準M `8d0e382`の`crates/minase/nets/pst.bin`、先読み教師（γ=0.9、n=40）、バッチ16,384、シード1、学習率と重み減衰は設計書の値、上限50エポック、改善なし5エポックで停止、ワーカー12である。
教師用Kは、世代2が758.4、世代3が766.0、新規の2万ノードのデータが1,184.9だった。
P型は2026年10月12日10時47分から11時12分、HalfKP-hm-b8は11時12分から11時37分に、同じ機械で続けて学習した（lishogiのBotが同居）。

| 検証（435万局面） | 約20秒 | 約20秒 |
| 完了したエポック数と停止理由 | 6、早期終了 | 6、早期終了 |
| 最良エポック | 1 | 1 |
| 検証損失（エポック0→最良） | 0.436832→0.434275 | 0.436832→0.434844 |
| 訓練損失（エポック1→6） | 0.43102→0.43005 | 0.43073→0.42920 |

どちらの型も検証損失はエポック1で最良になり、2エポック目以降は訓練損失が下がり続ける一方で検証損失が単調に悪化した。
検証損失ではP型がHalfKP-hm-b8より0.00057低い。
対局前の検査として、書き出した`nnue.bin`を`minase dev nnue-probe`で世代3の先頭20,000局面について評価し、`nnue-diagnostics compare`でPythonの整数参照と全局面一致することを確かめた。
量子化誤差の平均はどちらもK/40の内側だが、最大誤差は66.0センチポーン（P型）と40.7センチポーン（HalfKP-hm-b8）であり、Pythonの試走（35〜36）より大きい。
その他の診断（駒除去差分、互角帯の順位相関と評価値の分布、着手前後の評価差）は本節の末尾に追記する。

benchは、基準M（`8d0e382`）、A、Bの順に`taskset -c 3`で深さ9（15局面、`--repetitions 3`の中央値）を3巡交互に測った（2026年10月12日12時15分ごろ。同じ機械でフェーズ4の再学習（GPU、ワーカー12）とlishogiのBotが動いていたので、NPSの絶対値は低めに出ている可能性がある）。

| 全再計算の割合 | ― | 0.0003%（根だけ） | 1.21% |

HalfKP-hm-b8では、自玉の移動による文脈の変化で更新の1.21%が全再計算になり、幅128の非線形成分の差分更新と合わせてNPSは基準Mより約14%低い。
P型の幅128は約9%低い。

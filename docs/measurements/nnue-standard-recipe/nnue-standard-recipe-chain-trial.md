# 本数・リプレイバッファ・補正の有無を選べる連続生成スクリプトの試走

## 目的

[標準レシピv1の設計書](../../plans/archived/nnue-standard-recipe.md)のフェーズ2の最後の完了条件として、改めた連続生成スクリプト`scripts/vast/generation_chain.py`をvast.aiで借りた安い機械で動かし、少ない局数と短い学習の2世代を2世代分のリプレイバッファで続けて生成して学べることを確かめる。
確かめる点は次の4つである。

- 第1世代の本のヘッダが第0世代のコミット`6f874692`を持ち、第1世代の学習が生成機で`6f874692`からビルドした学習器で行われる。
- 第2世代は新しく借りた空の生成機（前の世代の成果物を持たない新しいインスタンス）から始まり、新しい名前空間の参照を`git bundle`から取得する。
- 第2世代の学習は、生成機へ送った第1世代の本を含む。
- 補正なしの指定で、学習したネットをコミットし、次の世代の初期値にする。

## コマンドライン

本番のブランチと参照を汚さないよう、`--worktree`にはリポジトリの使い捨てのclone（ブランチ`nnue-standard-recipe`のコミット`e1b632d5`）を、`--ref-prefix`には試走専用の`refs/nnue-standard-recipe-trial`を指定した。
起動に使ったスクリプトは[run-trial.sh](nnue-standard-recipe-chain-trial/run-trial.sh)にある。
サービスは`systemd-run --user`（nice値19、メモリ上限8 GB）で起動した。
作業機で同時に測定1のSTCが16局を並行して指していたので、作業機でのビルドは`CARGO_BUILD_JOBS=4`で4並列に抑えた（[教訓](../../lessons/check-running-measurements-before-cpu-load.md)）。

```console
run-trial.sh 1 --offer 53170012   # 第1世代を生成して生成機で学び、生成機を削除する
run-trial.sh 2 --offer 53170012   # 新しいインスタンスで第2世代を生成し、2世代分のリプレイバッファで学ぶ
```

本番と値を変えた引数は、`--books-per-generation 2`、`--games 40`、`--nodes 500`、`--seed-base 9500000000`、`--calibration-books 1`、`--batch 1024`、`--epochs 2`、`--train-threads 8`、`--removal-sample 100`、および生成機の選定条件と待ち時間である。
`--window 2`、`--fit no`、`--lr-linear 0.67903`、`--validation-interval 0`、`--train-place generator`は本番で使う可能性のある値にした。

最初の起動は、指定した出品48663891が照会の間に借りられて照会結果から消えていたので、生成機を作らずに止まった。
次に出品53170012で起動した直後に、作業機のビルドの並列数を抑えるためにサービスを`SIGTERM`で止め、`--offer`を外して同じ引数で再開した。
スクリプトは`SIGTERM`を受けると生成機を削除せずに止まり、再開時は保存した接続先へ接続し直した。

## エンジン

第0世代のコミットは`6f874692`（手書きの評価関数v0を線形の経路だけで表したMNUE、検査和`74afe0e5…`）である。
規則セットは`L0,P0,R1,E0`である。
作業機で本を検査する`minase`と、第1世代の較正に使う`minase-trainer`には、中断した系列の固定の実行ファイル（`data/nnue-generation-reset/bin/`の下）を使った。

## 環境

生成機はvast.aiの出品53170012（AMD Ryzen 9 3900X、24スレッド、メモリ16 GB、RTX 3060 Ti、フランス、1時間0.097米ドル）で、インスタンスは第1世代が59416206、第2世代が59417028である。
cgroupのCPU上限は23.04 CPU分、同時対局数は24だった。
作業機はIntel Core Ultra 7 265KF（20コア、メモリ30 GB、RTX 3060 Ti）である。

## 結果

実行は2026年11月6日に行った。
第1世代は21時51分から21時59分、第2世代は22時0分から22時8分で、どちらも約8分だった。
残高は92.2491米ドルから92.2151米ドルへ減ったので、試走全体の費用は約0.03米ドルである。
どちらの起動も「完了」を表示して終わり、生成機を削除した後のインスタンスの一覧は空だった。

| 確かめた条件 | 結果 |
|---|---|
| 第1世代の生成と学習 | 本0と本1（各40局）のヘッダには、生成コミット`6f874692`、検査和`74afe0e5…`、およびシード9,510,000,000と9,510,100,000が記録されていた。生成機のログには`HEAD is now at 6f874692`があり、学習器はそのコミットからビルドされた。学習の`--data`は第1世代の本2本だけで、`--lr-linear 0.67903`と`--validation-interval 0`が設定に記録された。 |
| 第1世代の較正 | 本0から求めた教師の勝率尺度は1,656.21 cpで、その値をKとした`base.bin`を初期値にした。 |
| 補正なしのコミット | 生成機の学習ジョブに補正のステップはなく、`fit/`は作られなかった。第1世代のコミット`f385e8ea`に埋め込んだネットは`gen-1/train/nnue.bin`とバイト単位で一致した。 |
| 新しい生成機での参照の取得 | 第2世代の生成機のログには、bundleから`refs/nnue-standard-recipe-trial/gen-1`を取得し、`f385e8ea`を展開した記録がある。第2世代の本のヘッダには、生成コミット`f385e8ea`と、そのネットの検査和`9c06cb79…`が記録されていた。 |
| 2世代分のリプレイバッファの学習 | 第2世代の学習の`--data`は、生成機の`/workspace/job/teacher/gen-1/`へ送った第1世代の本0と本1の後に、第2世代の本0と本1を並べたものだった。学習器は教師を生成コミットごとの2つの分類（`6f874692`と`f385e8ea`）に分け、教師の勝率尺度をそれぞれ1,683.58 cpと1,200.41 cpと推定した。 |
| 初期値の引き継ぎ | 第2世代の学習の初期値の検査和は`9c06cb79…`で、第1世代のコミットのネット（`gen-1/train/nnue.bin`）と一致した。 |
| 診断の入力 | 第2世代の駒除去差分の診断の入力は、第2世代の本2本だけだった。 |
| 参照の名前空間 | 使い捨てのcloneに作られた参照は`refs/nnue-standard-recipe-trial/gen-0`、`gen-1`、`gen-2`の3つだけである。 |

少ない局と短い学習で試したので、ネットの値や損失に意味はない。

## 結論

改めた連続生成スクリプトは、フェーズ2の完了条件である試走の確認項目をすべて満たした。
単体テスト（112件）と合わせて、フェーズ3の第1世代の生成に使う。

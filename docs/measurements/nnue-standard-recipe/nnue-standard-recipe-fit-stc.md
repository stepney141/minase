# 線形の経路の補正の要否の比較

## 目的

[標準レシピv1の設計書](../../plans/nnue-standard-recipe.md)の測定2として、学習後に線形の経路を対局結果へのロジスティック回帰で補正する工程（outcome regression）を外したネットが、補正したネットより強いかをSTCで判定する。
`H1`なら標準レシピv1では補正を行わず、それ以外は補正を続ける。
ネットは、[測定1](nnue-standard-recipe-lr-linear-stc.md)で選んだ線形の経路の学習率0.03で学んだものである。

## コマンドライン

比較用のコミットの作成とSTCは、[スクリプト](nnue-standard-recipe-fit-stc/run_fit.py)に引数`0.03`を与えて実行した。
学習はやり直していない。
候補は、対照のネットを補正する前のネット（[教師の量の比較](../nnue-generation-reset/nnue-generation-reset-gen2-volume.md)の全量の学習の出力`data/nnue-generation-reset/gen-2/volume/full/train/nnue.bin`、SHA-256の先頭`08b408d9`）である。
スクリプトは、このファイルのSHA-256を照合してから比較用のコミットに埋め込んだ。

```console
minase match run --run-dir data/matches/nnue-standard-recipe-fit-stc --seed 20261300200000 \
  --candidate commit:f29aa0c2a1b5a67a4b8d5522926d46ff4fe30569 \
  --baseline commit:f60eb6913d45f4c057031c4964788e1e95ea2442 \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

対局は設計書の作業ツリー`data/worktrees/nnue-standard-recipe`から実行し、候補と対照をその作業ツリーの`target/match-cache/`でビルドした。
対照は測定1でビルドしたものを使い、候補はこの測定で新しくビルドした。
どちらも同じ作業ツリーの同じビルド設定である（[教訓](../../lessons/do-not-mix-builds-across-cargo-config-changes.md)）。

| 対照 | `f60eb691`（参照`refs/nnue-generation-reset/gen-2-volume-full`） | 同じネットを補正したもの |

## 環境

2026年11月7日の1時54分から2時51分に、作業機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB、RTX 3060 Ti）で実行した。
対局はエンジンごとに1スレッド、`USI_Hash`は256 MB、同時対局数は16である。
STCの間、作業機ではlishogiのBotと、測定3の候補の学習（4スレッド、nice値19、メモリ上限5 GB）が動いていた。

## 結果

### 学習と補正

候補と対照は同じ学習の補正の前と後なので、学習の値は[測定1](nnue-standard-recipe-lr-linear-stc.md)の対照の列と同じである。
最良エポックは2、最良の検証損失は0.521349、補正のD（補正ありの予測の損失から補正なしの損失を引いた値）は−0.005679（95%区間[−0.007093, −0.004309]、τは80）である。
補正によって予測の損失は下がり、線形の経路には駒種ごとの平均で竪行+384、龍王+377、飛車+368、龍馬+314、獅子−281、仲人−50 cpが加わった。
駒除去差分の符号反転の割合は、補正前が1.99%（仲人0.2%）、補正後が4.21%（仲人55.9%）である。

### STC

| 有効ペア | 破棄ペア | 度数 | LLR | 判定 | 得点率 | 得点率から求めたElo |
|---:|---:|---|---:|---|---:|---:|
| 376 | 2 | [60, 4, 192, 9, 111] | +2.9947 | `H1` | 57.1% | 約+50 |

度数は、各ペアの2局で候補が得た合計点が0、0.5、1、1.5、および2点だったペアの数を、この順に並べたものである。
所要時間は3,357秒で、エンジン異常、時間切れ、および拒否着手は0件だった。
逐次検定は判定が出た時点で止まるので、得点率から求めたEloは真の差より大きく出やすい。

## 結論

補正を外したネットは補正したネットより強かった（`H1`）ので、標準レシピv1では補正を行わない。
補正は勝敗の予測の損失を下げたが、棋力は下げた。
中断した系列の第1世代の教師では、同じ手順で補正ありが補正なしに対して`H1`（得点率92.1%）だったが、第2世代の教師では優劣が逆になった。逆になった原因は調べていない。

# 載せ替えの確認に使う前と後のP型の学習

## 目的

[tatara化とHalfKP_vmの設計書](../../plans/archived/nnue-tatara-framework-and-halfkp-vm.md)の「載せ替えの確認」の節に従い、載せ替える前のP型と、tataraのLayerStackへ載せ替えた後のP型を、同じ教師から同じ条件で1本ずつ学び、学習の経過、書き出しの量子化誤差、および学習の速さを記録する。
2本の強さは、別の測定のGSPRT（[STC](nnue-tatara-framework-and-halfkp-vm-stc.md)とLTC）で比べる。

## 教師と共通の条件

教師は、中断した世代反復（[設計書](../../plans/archived/nnue-generation-reset.md)）の第2世代の37本を、教師データの形式MNSDの版2から版3へ書き直したもの（`data/nnue-tatara-framework-and-halfkp-vm/teacher-jcsa-v3/book-0.mnsd`〜`book-36.mnsd`、規則セット`JCSA`）である。
書き直しの経緯と検査は設計書の「載せ替えの確認」の節にある。
訓練は96,462,343局面、検証は5,162,867局面である。

2本は、教師の勝率尺度K_t＝679.029296875 cp（中断した系列で求めた値）、探索値と対局結果を混ぜる比率λ＝1.0、バッチ16,384局面、64 superbatch（390,656更新、約66.3エポック）、学習率の予定`cosine:64:0.027`、8 superbatchごとの検証、シード1、CUDA、学習のスレッド4で学び、最後のネットを使う。
探索用の駒価値は、前はminase独自の旧形式MNUEで書いた手書きの評価関数v0のネット（`data/nnue-generation-reset/base.bin`）が持つv0の駒割をネットに引き継いだ値、後は同じ値をエンジン内に持つ固定の表である。

## コマンドライン

どちらも本体のリポジトリのルートで、メモリ上限18 GiB、スワップなしの`systemd-run`のサービスとして実行した。
`$DATA`は37本を番号順に並べたものである。

載せ替える前のP型は、本書のブランチを切ったmasterのコミット`a48f03aa`に固定したworktreeの学習器で学んだ。

```console
minase-trainer nnue train --data $DATA --base data/nnue-generation-reset/base.bin \
  --output-dir data/nnue-tatara-framework-and-halfkp-vm/train-before --lambda 1.0 \
  --feature-set P --width 256 --head pairwise-l16-l32 --batch 16384 --superbatches 64 \
  --lr-schedule cosine:64:0.027 --validation-superbatches 8 --seed 1 --device cuda --threads 4
```

載せ替えた後のP型は、ブランチのコミット`8389b160`に固定したworktreeの学習器で学んだ。

```console
minase-trainer nnue train layerstack --data $DATA \
  --output-dir data/nnue-tatara-framework-and-halfkp-vm/train-after --rules JCSA \
  --teacher-cp-per-logit 679.029296875 --lambda 1.0 --batch 16384 --superbatches 64 \
  --lr-schedule cosine:64:0.027 --validation-superbatches 8 --seed 1 --device cuda --threads 4
```

後の学習器は、出力の量子化の尺度127×64＝8,128と教師の勝率尺度K_tから、書き出しの除数m＝round(8,128÷K_t)＝12と、出力の換算の尺度K_o＝8,128÷12＝677.33 cpを求めた。

## 環境

2026年11月18日に測定機（Intel Core Ultra 7 265KF、20コア、メモリ30 GiB、NVIDIA GeForce RTX 3060 Ti）で行った。
前の学習は4時16分から7時48分までの3時間32分（前処理377秒を含め12,697秒）である。
後の学習は14時42分から21時22分までの6時間40分（前処理154秒を含め23,978秒）である。
後の学習の間、14時45分から15時5分ごろまで、同じGPUで学習器のGPUの試験と、HalfKP_vmの学習器のメモリを測る短い学習を動かした。
lishogiのBotのエンジンは、どちらの学習の間も対局に応じて動いていた。

## 後のP型の1回目の学習における書き出しの失敗

後のP型は、はじめコミット`84b652bd`の学習器で学んだ。
64 superbatchまで学び終えた後、書き出しで次のエラーになり、ネットは書かれなかった。

```text
quantization overflow: l1_weights+l1_shared_weights[843] = -133
```

LayerStackの幅16の層の重みは、区分（tataraのLayerStackが局面によって切り替える後段の組で、P型では1つ）ごとの組と全区分に共通の組（tataraの`L1 shared`）を別々に学び、書き出しで足してから8ビット整数へ量子化する。
学習中は2組をそれぞれtataraと同じ±127/64に収めていたので、和を64倍して丸めた値が8ビット整数の範囲±127を超えた。
tataraは書き出しで和を8ビットへ切り詰めるが、minaseの書き出しは範囲外の値を切り詰めずにエラーで止める。
そこでコミット`8389b160`で2組をそれぞれ±127/128に収めるよう改め、学び直した。
1回目の検証損失は、superbatch 8までは学び直しと一致し、64で0.0014506だった。
教訓は[学習する重みの範囲を保存形式に合わせる](../../lessons/training-weights-must-fit-export-format.md)に足した。

## 結果

### 検証損失

| superbatch | 前のP型 | 後のP型 |
|---:|---:|---:|
| 0 | 0.0087956 | 0.0087956 |
| 8 | 0.0012590 | 0.0012973 |
| 16 | 0.0012897 | 0.0013204 |
| 24 | 0.0013174 | 0.0013440 |
| 32 | 0.0013522 | 0.0013805 |
| 40 | 0.0013622 | 0.0014151 |
| 48 | 0.0013950 | 0.0014225 |
| 56 | 0.0014103 | 0.0014386 |
| 64 | 0.0014149 | 0.0014470 |

どちらもsuperbatch 8で最も小さく、その後は同じ教師を繰り返し学ぶにつれて増えた。
superbatch 64の後の値は前より2.3%大きい。
検証損失は教師への当てはまりであり、強さは別の測定の対局で比べる。

### 書き出し

| 項目 | 前のP型 | 後のP型 |
|---|---:|---:|
| 量子化誤差の平均（絶対値） | 3.50 cp | 14.33 cp |
| 量子化誤差の符号つきの平均（整数の評価−実数の評価） | 記録なし | +10.18 cp |
| 量子化誤差の最大（絶対値） | 179.52 cp | 122.28 cp |
| 第1層の出力の飽和の割合 | 記録なし | 70.5% |
| 幅16の層の2乗の枝の飽和の割合 | 記録なし | 51.0% |
| 幅16の層の2乗しない枝の飽和の割合 | 記録なし | 69.5% |
| 幅32の層の飽和の割合 | 記録なし | 81.6% |
| 駒を除いた評価差の符号が逆になった割合 | 1.98% | 1.56% |
| 重みのファイルの大きさ | 7,070,652バイト | 3,919,422バイト |

量子化誤差は、検証集合から選んだ10,000局面で、書き出したネットのエンジンの評価と学習器の実数の評価の差である。
前の学習器は第1層を尺度255、要素積を独自の4分割、出力層の重みを16ビットで量子化し、後はtataraと同じく第1層を尺度127、後段の重みを8ビットで量子化するので、2つの誤差は同じ条件の値ではない。
飽和の割合は、実数の評価で活性化の前の値が0以下か1以上の成分の割合である。
駒を除いた評価差の符号が逆になった割合は、検証局面から王駒以外の盤上の駒を1枚ずつ除いたとき、書き出したネットの評価の差の符号がv0の駒価値の差と逆になった除去の割合である（前は516,352件中10,222件、後は514,444件中8,045件）。

### 学習の速さとGPUのメモリ

前の学習器の訓練の速さは、64 superbatchの中央値で毎秒560,207局面、後は毎秒271,154局面であり、後は前の約2.07倍の時間を要した。
訓練の時間の合計は、前が12,109秒、後が23,633秒である。
GPUのメモリの使用量は機械全体の値で、前の学習の最大は2,087,714,816バイトだった。
後のP型は、ほかのGPUの処理と重ならなかった1回目の学習で、最大900,464,640バイトだった。
設計書は学習2本の所要を約3時間と見込んでいたが、実際は2本で約10.2時間だった。
後の学習器の遅さの原因は、この測定では調べていない。

# NNUE学習の訓練・検証分割の検査

## 目的

NNUEの学習で検証損失がエポック1から2で最良になり、その後は訓練損失だけが下がり続ける原因として、訓練と検証の分割の不具合、局面の重複による漏れ、および両集合の分布の違いがないかを、学習器と同じ規則で集計して確かめる。

## コマンドライン

検査は、学習器のデータ層（`crates/minase-trainer/src/data/stream.rs`、`shuffle.rs`、`teacher.rs`）の規則を移植した使い捨てのプログラムで行った。プログラムはリポジトリには含めていない。
移植した規則は次のとおりである。

- 除外の印がある局面と、αβの探索値を持たない局面を除く。
- ファイルのヘッダのシードと対局番号のハッシュ`mix64(seed ^ (game * 0x9E3779B97F4A7C15))`（乗算はu64の折り返し演算）が20の倍数の対局を検証集合とする。
- 先読み教師はγ=0.9、n=40で、各局面の教師値を、同じ対局の後続40手までの探索値の重み付き平均とする（局面自身の探索値は含まない）。
- 教師の確率は、先読み後の値を単精度へ丸めてから、教師の勝率尺度1,007.494でロジスティック関数にかけたものである（λ=1.0）。

入力は[再生成した教師](nnue-lr-schedule-training.md)の30ファイル（`data/nnue-lr-schedule-gen/generated-*.bin`）である。
損失は、ネットの整数評価をそのネットの勝率尺度でロジスティック関数にかけた確率と、教師の確率との二値交差エントロピーである。
訓練側は各ファイルの訓練局面を10局面ごとに選んだ7,945,793局面、検証側は全4,153,303局面で計算した。
ネットは、エポック0の関数と同じ`crates/minase/nets/nnue-epoch0.bin`（PSTの初期値だけを持ち、データを学習していない）、現行の埋め込みネットであるP型のD0b（`data/nnue-hidden-layer-train/d0b/nnue.bin`、SHA-256 `046be0e6…`）、および[再学習したHalfKP-hm-b8](halfkp-retrain-stc.md)（`data/halfkp-retrain/train/nnue.bin`、SHA-256 `1af4c8f9…`）である。
局面の同一性は`Position::zobrist`で判定した。

## 環境

測定機（Intel Core Ultra 7 265KF、20コア、メモリ30 GB）で、2026年10月17日にnice値19、4スレッドで実行した（経過時間611秒、最大常駐メモリ約1.0 GB）。同じ機械で別のSPSAとlishogiのBotが動いていた。

## 結果

### 再現の照合

集計した局面数（訓練79,458,082、検証4,153,303）は学習器の記録と一致した。
検証損失も、エポック0のネットが0.457074（学習器は0.4570753）、D0bが0.448904（同0.4488929）、HalfKP-hm-b8が0.450014（同0.4500218）で、整数評価による差を除いて一致した。

### 分割

検証集合に入った対局の割合は、30ファイルで4.61%から5.46%、全体で5.01%（221,900局中11,112局）である。

| 項目 | 訓練 | 検証 |
|---|---:|---:|
| 対局数 | 210,788 | 11,112 |
| 局面数 | 79,458,082 | 4,153,303 |
| 1局あたりの局面数 | 377.0 | 373.8 |
| 平均の手数 | 300.2 | 295.6 |
| 探索値の絶対値の平均（センチポーン） | 2,094.7 | 2,078.2 |
| 先読み後の教師値の絶対値の平均（センチポーン） | 2,219.5 | 2,203.7 |
| 先読みによる教師値の変化の絶対値の平均（センチポーン） | 214.0 | 214.5 |
| 手番側の勝ち、引き分け、負けの割合 | 0.4849、0.0097、0.5055 | 0.4841、0.0111、0.5049 |

訓練と検証の分布に、目立った違いはない。

### 局面の重複

訓練局面の99.99%（79,448,364局面）は互いに異なる。
検証局面のうち訓練集合にも現れる局面は843局面（0.02%）で、すべて400手目以降だった。399手目までの検証局面に、訓練集合と同じ局面はない。

### 固定したネットの損失

損失の下限は、教師の確率そのものの二値エントロピーの平均であり、どのネットもこれより下げられない。

| ネット | 訓練 | 検証 | 検証−訓練 | 下限からの超過（訓練） | 下限からの超過（検証） |
|---|---:|---:|---:|---:|---:|
| 損失の下限 | 0.439837 | 0.441147 | +0.00131 | ― | ― |
| エポック0（PSTの初期値） | 0.455793 | 0.457074 | +0.00128 | 0.01596 | 0.01593 |
| P型 D0b | 0.446246 | 0.448904 | +0.00266 | 0.00641 | 0.00776 |
| HalfKP-hm-b8 | 0.444921 | 0.450014 | +0.00509 | 0.00508 | 0.00887 |

データを学習していないエポック0のネットでも、検証の損失は訓練より0.00128高く、損失の下限の差0.00131とほぼ等しい。
検証集合は教師の確率のエントロピーが平均でわずかに高く、もともと少し難しい。
D0bのエポック1の訓練損失（エポック中の平均0.44758）が検証損失（0.44892）より低かったのは、この差でほぼ説明できる。

学習後のネットでは、下限からの超過が検証で訓練より大きく、D0bで約2割、HalfKP-hm-b8で約7割大きい。
損失の値そのものは下限に近いので変化が小さく見えるが、検証での超過で見ると、エポック0の0.0159からD0bの0.0078へ約半分に減っている。

## 結論

訓練と検証の分割、局面の重複、および両集合の分布に不具合は見つからず、検証損失が早いエポックで最良になる原因は、約21万局という独立な対局の少なさに対してネットが訓練の対局に過剰に合わせることにあると見られるが、先読み教師がこれを強めているかどうかはこの検査では区別できない。

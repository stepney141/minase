# bucketによる一様シャッフル（B=16）の煙試験と、時間およびメモリの測定記録

## 目的

[メモリより大きい教師データの一様シャッフルの設計書](../../plans/archived/out-of-core-shuffle.md)の「検証」の6と7について、B=16の学習が完走してB=1と同程度の検証損失に達すること、メモリの上限を設けた環境で一時表現の全体がメモリに収まらない条件でも書き出しと再開まで完走すること、およびB=1に対する所要時間の増減を記録する。
本書は棋力測定の記録ではないので、ペンタノミアル度数やLLRは記録しない。

## 環境

測定機はIntel Core Ultra 7 265KF（20コア）、NVIDIA GeForce RTX 3060 Ti（8 GB）、メモリ30 GB、ディスクはNVMe SSDである。
学習器はブランチ`out-of-core-shuffle`のコミット67779260を`cargo build --release -p minase-trainer`でビルドしたもの（SHA-256の先頭`431d2b5b`）である。
測定の間、同じ機械で別の棋力測定（同時対局数16のLTC）とlishogiのBot（エンジン2つ、合計約4 GB）が動いていた。
このため、学習は`--threads 3`で行い、所要時間はこの負荷の下での値である。
同じ設定でもB=1の1エポックあたりの学習時間が約100秒から約180秒まで変動したため、所要時間の比較は目安であり、以下の表の値から20%以内の差を読み取ることはできない。
以下のコマンドでは、入力と出力を置いた`data/out-of-core-shuffle/`を`$D`、リポジトリのルートを`$ROOT`と書く。

## 煙試験（検証6）

[照合記録](out-of-core-shuffle-equivalence.md)と同じ版2の4ファイル（訓練7,822,295局面、検証408,100局面）を入力として、シード1のP型のネットを既定の学習率で5エポック、B=1とB=16で1回ずつ学習した。
B=16の学習は、bucketの局面数の上限を500,000（平均488,893に標準偏差の約16倍を足した値）とした。

```sh
minase-trainer nnue train --feature-set P --width 128 --data $D/teacher/measure-*.bin \
  --init-pst $ROOT/data/pst-fm-joint-training/j75/pst-float.npz --base $ROOT/crates/minase/nets/pst.bin \
  --lambda 1.0 --teacher-cp-per-logit calibrate --lookahead-gamma 0.9 --lookahead-plies 40 \
  --batch 16384 --seed 1 --threads 3 --device cuda --epochs 5 \
  [--buckets 16 --bucket-positions 500000 --scratch-dir $D/scratch] --output-dir <出力先>
```

| 項目 | B=1 | B=16 |
|---|---|---|
| 訓練局面の通し番号の列のSHA-256 | `2cdd100f…` | `2cdd100f…` |
| 教師の勝率尺度 | 2000.73997460196 | 2000.73997460196 |
| 検証損失（エポック0〜5） | 0.568566、0.536883、0.536677、0.536633、0.536631、0.536633 | 0.568566、0.536858、0.536664、0.536617、0.536615、0.536617 |
| 最良の検証損失（エポック） | 0.5366307（4） | 0.5366152（4） |
| 量子化誤差の平均（cp） | 19.95 | 16.92 |
| 前処理の秒数 | 134 | 140 |
| 各エポックの学習秒数 | 81、64、82、80、65 | 60、59、60、77、173 |

B=16の学習は完走し、作業ディレクトリは終了時に削除された。
最良の検証損失の差は−0.000016であり、[予備測定](shuffle-order-preliminary.md)で観測したシード間の標準偏差（約0.00001〜0.00005）の範囲にある。
量子化の検査の標本は、B=1が検証集合の順列の先頭1万件、B=16がFloydの方法で選んだ1万件と抽出のしかたが異なるので、量子化誤差の値は直接比較できない。

## 時間とメモリ（検証7）

### 条件

まず、学習プロセスの固定のメモリを、小さな入力（2ファイル、訓練176,003局面）のB=16の学習で測ると、最大常駐メモリは609 MBだった。
これを基に、B=16の学習を、メモリの上限2 GB、スワップなしのcgroupの中で動かすことにした。
データは[NNUE学習器の学習率スケジュール](../../plans/archived/nnue-lr-schedule.md)で生成した版2の30ファイルのうち先頭10ファイル（合計254,075,396バイト、訓練26,520,434局面、検証1,397,343局面）とした。
訓練局面の一時表現は26,520,434 × 138 = 3.66 GBで、1エポックぶんのbucketと合わせた一時ファイルは約7.3 GB、検証局面と教師の勝率尺度の入力を含めた作業ディレクトリは最大約7.7 GBになり、上限2 GBには収まらない。
一方、固定のメモリ、1つのbucket（上限1,700,000局面 × 146バイト ≈ 248 MB）、および先行して組み立てるバッチ（3 × 16,384局面）の和は上限に収まる。
bucketの局面数の上限1,700,000は、平均1,657,527に標準偏差（約1,247）の約34倍を足した値である。
B=1の学習は上限なしで同じ機械で行い、`/usr/bin/time -v`で最大常駐メモリを測った。

```sh
# B=1
/usr/bin/time -v minase-trainer nnue train --feature-set P --width 128 --data <10ファイル> \
  --init-pst $ROOT/data/pst-fm-joint-training/j75/pst-float.npz --base $ROOT/crates/minase/nets/pst.bin \
  --lambda 1.0 --teacher-cp-per-logit calibrate --lookahead-gamma 0.9 --lookahead-plies 40 \
  --batch 16384 --seed 1 --threads 3 --device cuda --epochs 2 --output-dir $D/time-memory/b1
# B=16（cgroupの中）
systemd-run --user --scope -p MemoryMax=2G -p MemorySwapMax=0 --quiet sh -c '
  /usr/bin/time -v minase-trainer nnue train <同じ引数> --buckets 16 --bucket-positions 1700000 \
    --scratch-dir $D/scratch --output-dir $D/time-memory/b16; cat /sys/fs/cgroup/<scope>/memory.peak /sys/fs/cgroup/<scope>/memory.events'
```

### 結果

| 項目 | B=1（上限なし） | B=16（上限2 GB） |
|---|---|---|
| 訓練局面の通し番号の列のSHA-256 | `edcf13fd…` | `edcf13fd…` |
| 教師の勝率尺度 | 1005.4073356939714 | 1005.4073356939714 |
| 検証損失（エポック0、1、2） | 0.4569392、0.4494546、0.4494179 | 0.4569392、0.4494434、0.4494236 |
| 前処理の秒数（再生と書き出し、教師の勝率尺度の推定、観測数の集計） | 376 | 281 |
| 各エポックの学習秒数（B=16は振り分けと読み戻しを含む） | 179、103 | 98、97 |
| 各エポックの検証秒数 | 12、7 | 6、6 |
| 書き出しまでの経過秒数（`summary.json`） | 689 | 496 |
| 経過時間（`/usr/bin/time`の wall clock） | 11分31秒 | 8分18秒 |
| ユーザーCPU時間 / システムCPU時間（秒） | 1,059 / 17 | 882 / 48 |
| ファイルシステムの入力 / 出力（512バイトのブロック数） | 567,424 / 133,168 | 44,266,312 / 22,259,792 |
| 最大常駐メモリ | 3.86 GB | 0.91 GB |
| cgroupの`memory.peak` | — | 2.00 GB（上限に一致） |
| cgroupの`memory.events` | — | `max` 60,345回、`oom` 0回、`oom_kill` 0回 |

B=16の学習は上限2 GBの中で書き出しまで完走し、OOM killerは発動しなかった。
`memory.peak`が上限に一致するのは、一時ファイルの読み書きによるページキャッシュがcgroupの使用量に数えられ、上限に達するたびに回収されたためであり（`max`の回数）、プロセス自身の最大常駐メモリは0.91 GBだった。
B=1の最大常駐メモリ3.86 GBから固定のメモリ約0.6 GBを引くと、1局面あたり約123バイトであり、30ファイル（訓練約7,950万局面）なら約10 GBに相当する。
B=16の一時ファイルの読み書きは、入出力のブロック数に現れている（約22.7 GBの読み込みと約11.4 GBの書き込み。元の一時表現の読み込み1回、エポックごとの振り分けによる読み込みと書き込み各1回、およびbucketの読み込み1回に相当する）。

この測定では、B=16はB=1より所要時間が短かった。
前処理では、B=1が全局面をメモリの配列へ集めるのに対してB=16は書き出しのバッファへ順に書くだけであること、エポックの学習では`--threads 3`のバッチの組み立てが律速で振り分けと読み戻しの時間が隠れることが理由と考えられる。
ただし、同時に走っていた棋力測定の負荷の影響を分けて測っていないので、この差を一般の条件での値とは扱わない。
この負荷の下で言えるのは、B=16の所要時間がB=1を上回らなかったことである。

### 再開

同じ10ファイルとcgroupの上限2 GBで、B=16の学習を`--epochs 1`で止めてから、同じ出力ディレクトリに`--resume`と`--epochs 2`を加えて再開した。
再開した学習は、MNSDから一時ファイルを作り直してエポック2を学習し、書き出しまで完走した（再開した起動の壁時計の時間は6分12秒、最大常駐メモリは0.90 GB、cgroupの`oom_kill`は0回）。
再開した学習の`training.jsonl`の各エポックの損失、`latest.npz`と`best.npz`の`meta`を除く全配列、量子化の検査の標本（SHA-256 `5e95eeed…`）、および書き出した`nnue.bin`は、止めずに2エポック学習したB=16の出力とバイト単位で一致した。
`config.json`の`resumes`には、再開時の`bucket_positions`と`scratch_dir`が記録された。

## 結論

B=16の学習は、4ファイルの煙試験でB=1と同程度の検証損失に達して完走し、10ファイルでは一時ファイルの全体がメモリの上限2 GBに収まらない条件でも、最大常駐メモリ0.91 GBで書き出しまで完走した。
1エポックで中断して再開した学習は、中断せずに完走した学習と同じ数値の状態に達した。
所要時間は、共用の負荷の下でB=1を上回らなかった。

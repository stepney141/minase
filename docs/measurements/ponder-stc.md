# ponder-stc

## 目的

[USI先読み（ponder）](../plans/ponder.md)のフェーズ4として、先読みを実装したコミット`817963a`が、その直前のコミット`036d3fa`より、先読みを対局条件に含む短時間条件で有意に強いかをGSPRTで判定し、通過ならLTCへ進める。
測るのは「同じ時計の下で、相手の手番中の計算も使える実装の強さ」であり、同じCPU時間あたりの効率ではない。

## コマンドライン

対局ハーネスは、ハーネスの実装コミット`b201f39`を固定したworktreeでビルドしたバイナリから起動した。

```console
target/release/match_runner \
  --run-dir /home/stepney141/board-games/minase/data/matches/ponder-stc --seed 38000919 \
  --candidate commit:817963a --baseline commit:036d3fa \
  --each time=10000+100 --ponder gsprt --max-pairs 3000
```

`--ponder`は両エンジンに同じ手順を適用する対局条件であり、ハーネスは予想手を返したエンジンにだけ`go ponder`を送る。
基準は予想手を返さないので、先読みをしない。

## エンジン

候補はコミット`817963ab5ecade01638ec587e3902fb5dd2a921d`（バイナリのSHA-256 `bffbcf064f3acc3f2c5f8b66aa5c7dc081af2092784c106dc633d47959829c00`）である。
先読みでない探索の`bench`深さ6の総ノード数は基準と同じ1,813,911であり、NPSの3回の中央値は基準の2,069,622に対して2,068,838だった。
基準はコミット`036d3fa4cabc9b310a080aedac824b319fb5f925`（バイナリのSHA-256 `0f6ee02416dc6ab4b8629ac23c4815f06bcd1769e19125cb6eaf8e456cad1e1c`）であり、エンジンのコードはmasterのコミット`e449abe`と同一である。
規則セットは`L0,P0,R1,E0`（engine-default）である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）であり、候補と基準はいずれも`Threads=1`、`USI_Hash`は各256 MBである。
同時対局数は、`--ponder`の自動計算（物理コア数から1を引き、`Threads`の2倍で割った商）による9である。
手数上限は4,096、応答タイムアウトは120秒、H1は10 Eloで、2026年9月21日に実施した。
同じ機械でlishogi Botのエンジンが1プロセス動いていた。

## 結論

`H1`かつ異常と不合法な予想手が0件なので、先読みをLTCへ進める。
候補は相手の手番中にもCPUを使うので、CPU時間の合計は基準の約2.0倍である。

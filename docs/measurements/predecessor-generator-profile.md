# 直前局面生成器の固定コーパス計測

## 目的

直前局面生成器`PredecessorGenerator`について、固定コーパスの各局面で候補構成数、順方向検証の回数、採用局面数、および経過時間を測り、設計書 [plans/predecessor-generator.md](../plans/predecessor-generator.md)「性能測定」の3つの改善案を導入するかどうかを判定する。合否の閾値は設けない。

## コマンドライン

計測は次のコマンドで実行した。コーパスの各局面は`src/core/predecessor/tests/profile.rs`の定数が拡張SFENで保持し、導出手順は同ファイルのテスト`predecessor_profile_corpus_has_documented_transitions`が再現する。

```console
cargo test --release predecessor_profile -- --ignored --nocapture
```

列挙だけの時間と検証込みの時間の分割は、同じテストモジュールに一時的な計測テストを置き、`reverse::enumerate_candidates`だけを呼ぶ時間と`generate_predecessors`全体の時間をそれぞれ21回測って中央値を取った。関数別の自己時間は、releaseビルドのテストバイナリを`perf record -g`で採取し、`perf report --no-children`で読んだ。

## エンジン

対象はブランチpredecessor-generatorであり、次の3版を測った。いずれも`cargo test --release`の既定プロファイル（LTO、`codegen-units = 1`）でビルドし、順方向の合法手生成器は各局面に併記した規則集合で構築した。

- 初版は、記録升を全144升に設定してから局所条件で検査し、候補局面のクローンに`Position::try_make_move`を適用する版である（コミット993b596に計測用の関数分割を加えたもの）。
- 記録升限定版は、局所条件を満たす升に限って記録升の変種を構成する版である（コミット3810cb8）。
- 最終版は、記録升限定版の順方向検証を、動かす駒の合法手だけを生成する`MoveGenerator::is_legal_move`と、候補局面のその場での適用と巻き戻しに置き換え、採用した局面を重複排除の集合へ移してから返却する版である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ30 GB）、rustc 1.98.0であり、2026年9月18日に他の負荷を走らせずに1スレッドで測った。経過時間は各局面で`generate_predecessors`を21回呼んだ中央値と20番目の値（95パーセンタイル）である。perfはこのCPUの性能コア（`cpu_core`）と高効率コア（`cpu_atom`）の標本を別に報告するため、割合は性能コアの標本（289,000件）を分母にした。

## 結果

コーパスは実戦に近い8局面と、王駒2枚と数枚だけの2局面からなる。候補数は集合`A`の検査を通った候補局面の数、検証数は順方向検証の回数、比は候補数を採用数で割った値である。最終版の結果は次のとおりである。

記録升限定版の関数別の自己時間（性能コア、計測テスト側のクロージャ23.7%を除く概算）は、順方向の合法手生成の関数群が約23%、libcの`memcpy`と`realloc`に相当する未解決シンボルが約30%、`Position::eq`が約6%、`HashMap::insert`とSipHashが約8%、候補の列挙が約10%、集合`A`の検査が約10%であった。単一の関数としては最大の処理が定まらなかったが、上の分割測定により、`memcpy`の多くが検証の段階の複製に属し、検証の段階が実戦に近い局面の5割から6割を占めることが分かった。

王駒2枚と数枚だけの局面では不足在庫が44由来に達し、獅子の2枚捕獲の逆生成では経由升と到達升に復元する駒の組合せが由来と成否の積で約7,700通りになる。着手側の麒麟が欠けているため記録升の変種も加わり、採用数は約150万局面、返却に2秒強と数GBのメモリを要する。これは集合`A`に対する相対的完全性の定義どおりの出力であり、生成器の誤りではない。この局面では採用した局面の保持が時間の大半を占めるため、検証の改善はほとんど効かない。

検証テストの所要時間は、最終版で通常の`cargo test`が約3秒、`cargo test predecessor_completeness -- --ignored --test-threads=1`が359秒（最大常駐メモリ0.5 GB）、`cargo test predecessor_oracle -- --ignored --test-threads=1`が550秒（同5.9 GB）であった。記録升限定版ではそれぞれ451秒（最大常駐メモリ0.4 GB）と604秒（同6.8 GB）であった。

## 結論

検証の段階が実戦に近い局面の5割から6割を占めていたため、設計書の第1の改善案（`is_legal_move`への置き換え）を採用し、あわせて再適用時の局面の複製をなくした。結果集合は変わらず、実戦に近い局面の中央値は記録升限定版の0.44〜0.66倍になり、検証の段階の割合は1割から2割へ下がった。第2の改善案（記録升による枝刈り）と第3の改善案（ビジターAPI）は導入しない。処理時間と返却集合の大きさは不足在庫の由来数と記録升の変種の数で決まり、後続の逆方向探索はこの規模を前提に設計する必要がある。

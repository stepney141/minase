# データ半分割のA対Bの固定ノード数1,200ペア

## 目的

[世代3の計画](../plans/pst-gen3.md)のデータ半分割の診断の主たる比較として、訓練データの一方の半分で学習したPST（A）と他方の半分で学習したPST（B）を固定ノード数で対局させ、事前に固定した2つの問いに答える。

## コマンドライン

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/pst-data-split-ab-nodes --seed 99400000 \
  --candidate commit:1c9bf35 --baseline commit:348bb5c \
  --each nodes=100000 --concurrency 3 elo --pairs 1200
```

## エンジン

候補はA（ブランチ`pst-data-split`の`1c9bf35`）、基準はB（同`348bb5c`）である。どちらもmaster `44ae7cb`の`nets/pst.bin`だけを差し替えたコミットであり、重みの学習は[学習の記録](pst-data-split-training.md)にある。
規則は`L0,P0,R1,E0`、両エンジンとも1手100,000ノードである。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）である。
同時3対局、両エンジンとも1スレッド、置換表256 MBで、世代3の生成（同時16対局）と並行して実行した。
固定ノード数の対局なので、並行した負荷は所要時間だけに影響する。
実施は2026年10月2日12時27分から19時56分である。

## 結果

| 項目 | 値 |
|---|---|
| ペア数 | 1,200（有効1,129、手数上限で破棄71） |
| ペンタノミアル度数 | [227, 16, 613, 22, 251] |
| Elo | +8.3（95%信頼区間 −5.0〜+21.6） |
| エンジン異常、時間切れ、拒否着手 | 0件 |
| 経過時間 | 27,084秒 |

## 結論

判定の前提条件（AとBの検証損失の差の絶対値が2×10⁻⁴以下）は、差が9.1×10⁻⁶で満たされていた（[学習の記録](pst-data-split-training.md)）。
事前に固定した2つの問いへの答えは次のとおりである。

| 問い | 規則 | 答え |
|---|---|---|
| 問1　差が採否測定の効果量（10 Elo）を超えると示されるか。 | 区間が［−10, +10］と重ならなければ「示された」。 | 区間が［−10, +10］と重なるので「示されない」。 |
| 問2　差が大差（30 Elo）に達するか。 | 区間が［−30, +30］に収まれば「達しない」、重ならなければ「達する」。 | 区間が［−30, +30］に収まるので「達しない」。 |

今回の1組の分割と共通の初期値では、検証損失がほぼ等しいAとBの間に大差を認めなかった。
差が10 Elo以下であることは、この精度では確かめられない。
過去の候補の負けの原因については、本測定からは判断しない。

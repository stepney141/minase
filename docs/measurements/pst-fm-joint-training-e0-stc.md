# pst-fm-joint-training-e0-stc

## 目的

[PSTとFMの同時学習](../plans/pst-fm-joint-training.md)の2候補がSTCで`H0`となった原因を切り分けるため、同時学習の初期値（エポック0、候補LのPSTと縮小前のFaのFM）をMと比べ、FMの補正を1/4に縮めないことだけで強さが下がるかを短時間条件STCで調べる。
この測定は原因の診断であり、エポック0は採用の候補ではない。

## コマンドライン

```console
data/pst-fm-joint-training/bin/minase-m match run \
  --run-dir data/matches/pst-fm-joint-training-e0-stc --seed 30000000 \
  --candidate commit:5b4113aa88b9832ef4217f64006f13a0747ce7fc \
  --baseline commit:21d6cd0eb0c3cee465254825af3c0a7c34aa3b14 \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

runnerは、[J75のSTC](pst-fm-joint-training-j75-stc.md)と同じ`minase`（SHA-256 `1d86c156…`）である。

## エンジン

候補はブランチ`pst-fm-joint-training-e0`の`5b4113a`（バイナリのSHA-256 `090d4c3a…`）である。
重みファイルは`data/fm-quarter-current-pst-fa/fm.bin`（SHA-256 `5793d867…`）であり、Mの重みとの違いはFMの指数が1小さいこと、すなわち補正が4倍であることだけである。
探索のテストの局面はJ100の候補と同じものを使い、初期局面の評価値のテストは68 cpに更新した。
基準はM（master `21d6cd0`、バイナリのSHA-256 `412b4f98…`）である。
規則セットは`engine-default`（`L0,P0,R1,E0`）、`Threads`は両者1、`USI_Hash`は両者256MBである。
GSPRTの仮説はH0がelo=0、H1がelo=10、α=β=0.05である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）、同時対局数は16である。
2026年10月8日7時54分に開始し、経過時間は2,049秒（約34分）だった。
他の作業の対局は重なっていない。

## 結果

| 項目 | 値 |
|---|---|
| ペア数 | 228（完走222、手数上限による破棄6） |
| ペンタノミアル度数 | [69, 3, 121, 2, 27] |
| 正規化得点 | 0.4043 |
| LLR | −2.978 |
| 判定 | `H0` |
| 不正着手、クラッシュ、応答タイムアウト、時間切れ、拒否着手 | すべて0件 |

同じ方法で求めた3つの測定の効果量は次のとおりである。
Eloはペンタノミアル度数の正規化得点をロジスティックで換算した点推定であり、括弧内はペア得点の標本分散から求めた95%区間である。
逐次検定の停止による偏りを補正していないので、目安として扱う。

| 対Mの測定 | ペア数 | Elo |
|---|---:|---|
| エポック0（本測定） | 222 | −67（−98〜−38） |
| [J100](pst-fm-joint-training-j100-stc.md) | 328 | −46（−72〜−21） |
| [J75](pst-fm-joint-training-j75-stc.md) | 1,245 | −8（−21〜+5） |

## 結論

FMの補正を1/4に縮めないことだけで、Mに対して約−67 Eloとなり、同時学習の開始点はMより明確に弱かった。
3つの測定は別々の開始局面列で行った間接比較であるが、点推定では、同時学習は開始点からJ100で約+21、J75で約+59だけ強さを取り戻しており、両候補の不採用の主因は縮小を外したことにあると考えられる。

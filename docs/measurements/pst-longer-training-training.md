# 候補Lの学習と診断

## 目的

[採用PSTの追加学習のエポック数の延長](../plans/pst-longer-training.md)のフェーズ2として、採用PSTのPcを初期値に、同じデータと学習条件で上限200エポック、打ち切りの待つエポック数5で学習し、学習したエポックの中で検証損失が最良の重みを候補Lとする。

## コマンドライン

設定ファイル`data/pst-longer-training.toml`は、Pcの設定ファイル`data/eval-coadaptation-lambda075.toml`から、`run.directory`を`data/pst-longer-training`に、`run.base_commit`をM（`aee6b87e933237cd1b364ef20c27f7a7483ba6d0`）に、`train.epochs`を200に改め、`train.patience = 5`を加えたものである。

```console
tools/train/.venv/bin/pst-workflow prepare --config data/pst-longer-training.toml
tools/train/.venv/bin/pst-workflow train --run-dir data/pst-longer-training
tools/train/.venv/bin/pst-workflow diagnose --run-dir data/pst-longer-training
```

## エンジン

学習器と診断器は、M（master `aee6b87`）の`tools/train/`であり、[早期終了を加えた学習器](pst-longer-training-trainer-regression.md)である。
初期値は、Mの`crates/minase/nets/pst.bin`（Pc、SHA-256 `a5bc54f1…`）である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB、GeForce RTX 3060 Ti）で、2026年10月5日19時7分から10月6日2時3分に準備、学習、診断を行った。
1エポックは約2分であり、同じ時間帯に対局は走っていなかった。

## 結果

学習は上限の200エポックまで回り、打ち切りは起きなかった。
200エポックのすべてで検証損失が最良値を更新し、最良エポックは200だった。

学習後の診断は次のとおりである。

| 検査 | 結果 |
|---|---|
| Rustと学習器の評価値の一致 | 100,000局面で一致 |
| 量子化の前後の平均絶対誤差 | 0.51 cp（最大1.74 cp） |
| 駒除去差分の符号の反転 | 0件（341件を検査） |
| 探索用駒価値と出力K | 不変 |
| 初期局面の評価値（学習器の参照値） | 33 cp（Pcは26 cp） |
| 重みのSHA-256 | `b2d2cd1b66359ea0dbe80868fc569a77d6305ca55467587d49a20d17ea556aca` |

[駒価値の歪みの教訓](../lessons/validation-loss-hides-material-distortion.md)に従って、Pcからの変化を測った。
量子化前の重みの差の平均絶対値と最大は、序中盤で107.6 cpと956.6 cp、終盤で249.8 cpと1,110.9 cpであり、PcがG23から動いた量（序中盤15.8 cp、終盤28.4 cp）の約7〜9倍である。
駒除去差分は、341件の差の絶対値の平均が109.1 cp（最大711 cp）で、基点の値に対する比の平均は0.19だった。
重みから導いた駒価値は大駒ほど大きく上がった。たとえば、序中盤で1,241 cpから1,428 cpへ、終盤で1,553 cpから2,090 cpへ上がった駒がある。

[評価値の分布の比較](eval-coadaptation-distribution.md)と同じスクリプト、局面、およびシードで、Pcに対する候補Lを比べた。
全局面の標準偏差の比は1.144であり、共適応の検証で定めた目安0.9〜1.1の外にあるので、候補Lは評価値の散らばりの尺度を変えた。
基点の評価値がほぼ互角の帯（絶対値0〜99 cp）では、Spearmanの順位相関が0.675、残差の標準偏差が92.1 cpであり、PcがG23から動いたとき（0.948、20.7 cp）より並びを大きく入れ替えた。

## 結論

学習したエポックの最良の検証損失はエポック0を下回り、駒除去差分の符号の反転もないので、計画書の規則に従って段階ゲートへ進む。
最良エポックが上限の200に達したので、検証損失はまだ下がっていると記録する。
候補Lは評価値の尺度を約14%大きくした一方、探索用駒価値は変えていない。探索の余裕値は探索用駒価値の歩兵に対する割合で決まるので、候補Lでは余裕値が評価値に対して相対的に小さくなる。
このずれは、重みに依存するテスト`qsearch_limit_does_not_count_delta_pruned_capture`の前提（金将を取ったときの評価値の変化が、探索用の駒価値とdeltaの余裕値の和に収まること）が崩れたことにも表れた。
段階ゲートの結果は、この尺度の変化を踏まえて読む。

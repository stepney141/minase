# 2端点PSTと単一PSTの学習と診断

## 目的

[PSTの序中盤と終盤の補間](../plans/tapered-pst.md)の第3フェーズとして、初期化版を初期値に単一PSTと2端点PSTを同じ条件で学習し、単一PSTが開始版と一致するかで採否測定の連鎖を確定する。

## コマンドライン

学習は[PSTの学習手順](../pst-training.md)のワークフローで実行した。
設定ファイルは`data/pst-tapered/pst-tapered-single.toml`と`data/pst-tapered/pst-tapered-tapered.toml`であり、`train.model`だけが異なる。

```console
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py prepare --config data/pst-tapered/pst-tapered-<model>.toml
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py generate --run-dir data/pst-tapered/<model>
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py train --run-dir data/pst-tapered/<model>
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py diagnose --run-dir data/pst-tapered/<model>
```

生成シードは空配列であり、既存の6ファイル（[第1フェーズの記録](pst-tapered-identifiability.md)）だけで学習した。
学習条件はAdam、学習率3、10エポック、バッチ16,384、乱数シード1、教師探索値の比率0.75、CUDAである。
1エポックは643更新、全体で6,430更新である。
診断は世代と局面帯ごとに最大10,000局面をシード1で抽出した。

## エンジン

基準コミットは初期化版`b687022e02e5821d45f5257165e80c2322201776`であり、その`nets/pst.bin`（SHA-256 `712c4fcc48b86e8d1dab2127ad85fb8235dbcb1ff6a7dca70b6ace4733ec76cf`）は開始版`af200b4`の重みを両端点へ複製し、開始版の実装で導出した探索用駒価値47個を固定したMNPTバージョン2である。
世代別の教師Kは804.030と1099.675、出力Kは訓練集合から再推定した1072.65292944であり、float32では開始版のK（1072.6529541015625）と同じ値になる。
規則セットは`L0,P0,R1,E0`である。

## 環境

学習はIntel Core Ultra 7 265KF、NVIDIA GeForce RTX 3060 Ti（CUDA 13.0、PyTorch 2.13.0）、Python 3.12.14で実行した。
最大常駐メモリは約3.1 GB、最大VRAMは約509 MBである。
対局ではないため、ワーカー数、`USI_Hash`、同時対局数は該当しない。

## 結果

### 学習曲線

単一PSTは10エポックのいずれも初期状態の検証損失0.509898887を下回らず、最良エポックは0であった。
出力ファイルは基準の`nets/pst.bin`とバイト単位で同一（SHA-256 `712c4fcc…`）であり、単一PSTは開始版と一致したと判定する。
学習の所要時間は420秒である。

2端点PSTはエポック7が最良で、検証損失は0.509898887から0.509635484へ下がった（世代0が0.418636から0.417734、世代1が0.518527から0.518324）。
訓練損失は0.505651から0.505368へ単調に下がり、検証損失はエポック5と8で一時的に上がった。
量子化誤差は学習器の検証標本10,000局面で平均0.506センチポーン、最大1.584センチポーン、初期局面の評価は先手視点で67センチポーン（開始版は−8）である。
所要時間は453秒であり、単一PSTより8%長い。
出力ファイルのSHA-256は`b172a1b3e1c620bbdb1b2f22d0c5ebc9fa11a891703d88c59c710301173feb5a`である。

同じ91,841局面について、`pst_probe`によるRustの評価はPythonの整数参照評価と基準と候補の両方で全件一致した。

### 端点ごとの駒価値

各端点の全升平均から導出した駒価値は、固定した探索用駒価値から次のように離れた。
終盤側では走り駒と獅子の価値が上がり、序中盤側では下がる。

| 駒 | 固定値 | 序中盤側 | 終盤側 |
|---|---|---|---|
| 歩兵 | 100 | 97 | 107 |
| 飛車 | 853 | 816 | 934 |
| 龍馬 | 1,015 | 962 | 1,119 |
| 龍王 | 1,180 | 1,108 | 1,326 |
| 奔王 | 1,708 | 1,556 | 1,956 |
| 獅子 | 2,522 | 2,465 | 2,666 |
| 角鷹 | 1,603 | 1,479 | 1,796 |
| 飛鷲 | 1,680 | 1,566 | 1,848 |

静的交換評価と静止探索の余裕値は固定値を使い続けるため、終盤側での最大15%の乖離は採否測定の結果に含まれる。

### 代表局面の駒の除去と成り

初期配置では、候補の評価が67センチポーンで、各駒を1枚除いた評価変化は基準と同じ符号を保つ。
自分の奔王を除くと基準−1,676に対して候補−1,545、獅子は−2,496に対して−2,407であり、序中盤側の走り駒の価値低下を反映する。
帯[0.0, 0.2)の代表局面（通算番号2,155、19枚）では、候補の評価が1,484センチポーンで基準より131高く、自分の飛鷲を除くと候補−1,575（基準−1,518）、相手の龍王を除くと候補+1,114（基準+1,074）であり、駒数が少ない局面では走り駒の価値が上がる。
帯[0.2, 0.4)の代表局面（36枚）では自分の麒麟を除く変化が−501から−592へ、相手の飛鷲を除く変化が+1,750から+1,826へ広がった。
駒損を有利と評価する除去はどの代表局面にもない。

合法な成り手があった代表局面は帯[0.6, 0.8)の1局面（72枚）だけで、成り手`7g4d+`の評価差は基準507に対して候補462であった。
他の5局面には合法な成り手がなく、その旨を`promotion_reason`に記録した。

## 結論

単一PSTの再学習は開始版と同一の重みで終わったため、設計書の分岐に従い構造比較を実施せず、開始版との採用比較`pst-tapered-adoption-stc`と`pst-tapered-adoption-ltc`だけで採否を判定する。
2端点PSTを埋め込んだ候補はコミット`77fe8c03e485d3a83b00d8f8a4127f7dbee0faca`である。
シードは、既存の測定（最大20530903）と対局列が重複しないよう、STCに20540903、LTCに20550903を使う。

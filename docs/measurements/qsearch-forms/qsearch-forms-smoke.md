# 静止探索の補正と枝刈りの形の変更の候補の事前対局

## 目的

[静止探索の補正と枝刈りの形の見直しの設計書](../../plans/archived/qsearch-forms.md)のフェーズ4として、SPSAの最終値を反映した候補がSTCの条件で時間切れやエンジン異常を起こさないことを確かめ、時間の使い方の変化を見るために、起点と32ペアを対局させる。
棋力の判定には使わない。

## コマンドライン

[統括計画](../../plans/archived/search-forms.md)の決定により、SPSAを終えた調整機で、持ち時間を換算せずに対局を実行した。
候補のコミットは、測定機で作った`git bundle`で調整機のcloneへ取り込んだ。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/qsearch-forms-smoke --seed 4500000000 \
  --candidate commit:c6cf0c729a6b8209e34c2a1df0f9744a87aae733 \
  --baseline commit:662c1ab6789e05ae8ef3c994772055f190d34996 \
  --each time=10000+100 --concurrency 191 elo --pairs 32
```

実行ディレクトリは、終了後に測定機の`data/matches/qsearch-forms-smoke`へ取得し、集計は測定機で次のコマンドで行った。

```console
data/spsa/qsearch-forms-runner/minase match report \
  --run-dir data/matches/qsearch-forms-smoke
```

候補の`cargo test`では、既定値を反映した直後に、反映前の既定値を前提にしていた6件のテストが失敗した。テストを直すコミット`ad926188`は探索を変えず（benchの出力は`c6cf0c72`と同じ）、エンジンの実行ファイルにも入らないので、事前対局はテストを直す作業と並行して`c6cf0c72`で行った。

## エンジン

候補は、形の変更に[SPSAの最終値](qsearch-forms.md)を反映したコミット`c6cf0c729a6b8209e34c2a1df0f9744a87aae733`である。
起点は、設計書を始めた時点のmaster`662c1ab6789e05ae8ef3c994772055f190d34996`である。
runnerは、調整機で形の変更の最後のコミット`e9abbc86`をビルドした通常のminase（版2.4.0、SHA-256`1585bb71…`）である。
規則は`engine-default`（`L0,P0,R1,E0`）である。

## 環境

調整機は、vast.aiのインスタンス56989145（AMD EPYC 9654の2基構成、物理192コア、論理384スレッド、スペイン）である。測定機との1コアの速さの比`f`は1.26である（[時間切れの事前確認](qsearch-forms-safety.md)）。
両エンジンの`Threads`は1、`USI_Hash`は既定の256 MB、同時対局数の設定は191である（対局は32ペアなので、同時に動いたのは最大32ペアである）。

## 結果

| 量 | 値 |
|---|---:|
| 有効ペア | 31（手数上限による破棄1） |
| ペンタノミアル度数 | [0, 0, 7, 3, 21] |
| 正規化した平均得点 | 0.863 |
| Elo | +319.6 |
| 95%信頼区間 | [+229.4, +467.5] |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 466.9秒（`summary.json`の累計） |
| 1局の最大常駐メモリ | 1,020,145,664バイト |

値は`minase match report`が保存記録から再計算した集計による。
破棄した1ペアは、2局目が手数上限の4,096手に達したペア1である。
31ペアの固定局数Eloは信頼区間の幅が約240 Eloあり、強さの判定には使わない。

時間の使い方は次のとおりである。
総思考時間と終局時の残り時間は、有効な31ペアの`pairs/`に保存された各手の思考時間から計算した。終局時の残り時間は、持ち時間に「1手あたりの加算×着手数」を足し、思考時間の合計を引いた値である。

| 量 | 候補 | 起点 |
|---|---:|---:|
| 総思考時間 | 1,815.0秒 | 1,895.0秒 |
| 着手数 | 13,450 | 13,428 |
| 1手の平均思考時間 | 134.9 ms | 141.1 ms |
| 終局時の残り時間の中央値 | 1,823 ms | 540 ms |

候補と起点の総思考時間の比（候補÷起点）は0.958である。

手数帯ごとの完了深さ（反復深化で読み終えた深さの平均）と思考時間の中央値は、有効な31ペアについて`scripts/clock_profile.py`を`--role candidate`と`--role baseline`で別々に実行して集計した。

| 手数帯 | 候補の完了深さ | 起点の完了深さ | 候補の思考時間の中央値 | 起点の思考時間の中央値 |
|---|---:|---:|---:|---:|
| 0〜49 | 16.73 | 13.22 | 92 ms | 112 ms |
| 50〜99 | 16.09 | 12.62 | 102 ms | 122 ms |
| 100〜149 | 15.65 | 12.49 | 102 ms | 112 ms |
| 150〜199 | 15.17 | 12.14 | 102 ms | 122 ms |
| 200〜299 | 14.81 | 11.67 | 121 ms | 142 ms |
| 300〜399 | 14.99 | 11.31 | 122 ms | 152 ms |
| 400以降 | 14.65 | 10.79 | 101 ms | 102 ms |

探索を止めた理由の内訳は、候補では上限の時間による停止が9手（0.07%）、目安の時間による停止が13,441手、起点では上限の時間による停止が82手（0.61%）、目安の時間による停止が13,346手だった。
完了深さは全体の平均で候補15.28、起点11.87である。
`clock_profile.py`が出す時間予算の比と上限の超過量は、起点の係数の予算式に基づくので、候補の時間の使い方の解釈には使わない。

## 結論

候補は、時間切れとエンジン異常を起こさなかった。
総思考時間は起点より約4%少なく、終局時の残り時間は起点より多く、上限の時間による停止は起点の約9分の1だった。
完了深さは、すべての手数帯で起点より約3〜4手深い。
設計書の手順どおり、同じ調整機で逐次検定のSTCへ進む。

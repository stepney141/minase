# 静止探索の採否GSPRT（nodes=100000）

## 目的

静止探索を導入したコミットと直前コミットを同一ノード数の対等条件で対戦させ、静止探索が棋力を有意に高めるかを判定する。

## コマンドライン

```console
match_runner --seed 20260822 --candidate commit:c12d460 --baseline commit:fa438de --each nodes=100000 --concurrency 8 gsprt
```

## エンジン

候補はコミットc12d460（静止探索あり）、基準はコミットfa438de（静止探索なし）である。
規則セットは`commit:`指定の既定であるengine-defaultである。

## 環境

CPU型、物理コア数、論理コア数は記録なし。
ワーカー数は候補と基準とも1である（本マイルストーンは単一スレッド設計）。
`USI_Hash`は記録なし（設計上の既定値は256MB）。
同時対局数は8である。

## 結果

ペンタノミアル度数は[1, 0, 28, 2, 178]（有効209ペア）であった。
LLRは2.953で判定はH1（候補が有意に強い）である。
破棄ペア数は1、異常件数は0である。
`time_forfeits`は該当なし（ノード数固定）。
経過時間は1013秒である。
benchの総ノード数は、depth=3で217,305から7,393,052へ約34倍、depth=4で1,708,418から77,415,194へ約45倍に増えた。

## 結論

静止探索を採用し、ノード数の増大は第2層のdelta pruningで対処する。

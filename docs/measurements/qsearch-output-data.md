# 静止探索の出力を学ぶ計画の学習データの記録

## 目的

[静止探索の出力を学ぶPSTの学習](../plans/qsearch-output-training.md)のフェーズ2として、採用版S0で15,000局の自己対局を生成し、局面の種類ごとの件数、除外の理由別の件数、および先読み教師値の分布を記録して、R、Q、Qcで共有する教師尺度K_gを固定する。
棋力測定ではなく、対局の勝敗を使わない。

## コマンドライン

生成は次のスクリプトで、2つの基本シードを順に実行した。

```console
P=data/qsearch-output-training/phase2
for SEED in 92000000 92100000; do
  $P/selfplay_gen generate --output $P/generated-$SEED.bin \
    --kinds $P/generated-$SEED.kinds --history $P/generated-$SEED.history.jsonl \
    --games 7500 --seed $SEED --nodes 100000 --random-moves 0 \
    --concurrency 16 --max-ply 4000 --hash-mb 16
done
```

検査と教師尺度の推定は次のコマンドで行った。

```console
target/release/selfplay_gen inspect $P/generated-<シード>.bin \
  --kinds $P/generated-<シード>.kinds --history $P/generated-<シード>.history.jsonl
tools/train/.venv/bin/python tools/train/pst/train_qsearch.py estimate-teacher-k \
  --data $P/generated-92000000.bin $P/generated-92100000.bin
```

生成の条件は採用PSTの学習データと同じである。
2つの基本シードは互いに10万離れ、[小標本](qsearch-output-leaf-sample.md)の91,000,000とも対局数以上離れている。

## エンジン

生成器は、ブランチ `qsearch-output-training` のコミット `c6c24f7` の生成処理からビルドした `selfplay_gen` を、ビルドの影響を受けないよう `data/qsearch-output-training/phase2/` へ複製して使った（SHA-256 `e773ef3a441cb211c9cf9d05ac89b2cae027e164ece0b3bf4e9b633e9b2b75b3`）。
評価関数は埋め込みの採用PSTであり、重みの検査和は`8125a343…`、規則は`engine-default`（`L0,P0,R1,E0`）である。
検査の `selfplay_gen inspect` はコミット `8b4d3cd` からビルドした。

生成器は、起動時の作業ツリーのHEADを来歴の生成コミットとして記録する。
1本目は `70e6cd0` の時点で起動し、2本目の起動までに同じworktreeへ `8b4d3cd` をコミットしたため、2本目の来歴の生成コミットは `8b4d3cd` になった。
2つのコミットの間の差分は検査機能、診断器、学習器、および文書だけであり、生成と対局の処理（`generate.rs`、`play.rs`、`opening.rs`）は変わっていない。
実行ファイルも同じ複製である。
このため、学習器は生成コミット以外の来歴（重みの検査和、ノード数、規則、探索条件、対局の由来、λ）がすべて一致する2つの教師分類を1つの教師として扱い、両方のコミットを記録する（`ffc3158`）。
長時間の生成中に同じworktreeへコミットしたことは、[生成コミットを固定する教訓](../lessons/pin-generation-binary-to-worktree.md)への違反である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）である。
1本目は2026年9月29日22時19分から9月30日1時59分、2本目は9月30日1時59分から5時35分に生成した。
lishogi Botが最大4スレッドを使うため、同時対局数は16とした。
探索はノード数で制限しているので、負荷と同時対局数は記録の内容に影響しない。

### 記録の一致の検査

両ファイルとも、種類ファイルの行数と記録数が一致した。
保存した着手列を初期局面から再生した局面と先獅子状態は、全7,086,870件で記録と一致した（不一致0件）。
各記録の種類は、履歴の次の着手から求めた種類と一致した。
生成器の2つの指定の本体の一致（指定なしとのバイト単位の一致など）は、[小標本の記録](qsearch-output-leaf-sample.md)の「エンジン」の節で確かめている。

### 訓練と検証の分割

既存の規則（棋譜IDのハッシュによる対局単位の分割）で分けた件数は次のとおりである。

| 局面の種類 | 訓練（件） | 検証（件） |
|---|---:|---:|
| 静かな局面 | 5,788,833 | 291,035 |
| 捕獲局面 | 875,477 | 44,284 |
| 成り局面 | 83,118 | 4,123 |

区間あたりの更新回数は、静かな訓練根を16,384根ずつに分けた354回であり、総更新回数は3,540回となる。
[更新回数の教訓](../lessons/check-steps-per-epoch-before-training.md)の下限2,000回を満たす。
Qcのバッチに加える捕獲根は、round(16,384 × 875,477 / 5,788,833) = 2,478根である。

### 先読み教師値

先読み値は、γ=0.9、40手の窓で、平均の対象を静かな局面だけとして求めた。
値は各局面の手番側から見たセンチポーンである。

| 局面の種類 | 先読み値の平均 | 先読み値の標準偏差 | 1%点 | 中央値 | 99%点 | 元の探索値との差の絶対値の平均 |
|---|---:|---:|---:|---:|---:|---:|
| 静かな局面 | −77.7 | 2,770 | −7,534 | −15.1 | 7,245 | 131.9 |
| 捕獲局面 | 366.3 | 2,458 | −6,168 | 90.1 | 8,111 | 201.3 |
| 成り局面 | 1,615.0 | 3,137 | −5,651 | 1,111.1 | 9,928 | 300.7 |

### 教師尺度

教師尺度K_gは、静かな訓練局面5,788,833件から既存の手順で推定して767.491528450171となった。
R、Q、Qcの学習にはこの値を固定して渡す。
採用PSTの学習で出力の尺度Kに使った1072.6529541015625は変えない。

## 結論

記録の一致の検査が全件で通り、教師尺度K_gを767.49に固定したので、フェーズ2を完了し、フェーズ3の学習へ進む。

# 対照Rと候補Q、Qcの学習の記録

## 目的

[静止探索の出力を学ぶPSTの学習](../plans/qsearch-output-training.md)のフェーズ3として、静かな局面の静的評価を教師へ近づける対照R、同じ局面から静止探索した値を教師へ近づける候補Q、およびQに捕獲局面を加えた候補Qcを、採用版S0から同じ条件で学習し、整合性を検査する。
棋力測定ではなく、対局の勝敗を使わない。

## コマンドライン

```console
P=data/qsearch-output-training/phase2
T=data/qsearch-output-training/phase3
nice -n 5 tools/train/.venv/bin/python tools/train/pst/train_qsearch.py train \
  --data $P/generated-92000000.bin $P/generated-92100000.bin \
  --init nets/pst.bin --output-dir $T/training \
  --qsearch-leaf $T/bin/qsearch_leaf \
  --teacher-k 767.491528450171 --k 1072.6529541015625 \
  --candidates R,Q,Qc --device cuda --leaf-jobs 16
for c in R Q Qc; do
  tools/train/.venv/bin/python tools/train/pst/pst_diagnostics.py \
    --data $P/generated-92000000.bin $P/generated-92100000.bin \
    --lookahead-gamma 0.9 --lookahead-plies 40 --base nets/pst.bin \
    --candidate $T/training/$c/pst.bin --probe target/release/pst_probe \
    --output-dir $T/integrity/$c
done
```

学習の全区間の記録は `qsearch-output-training/training.json`、整合性の検査の出力は `qsearch-output-training/integrity-<候補>.json` に保存した。

## エンジン

学習器はブランチ `qsearch-output-training` のコミット `ffc3158` の `train_qsearch.py` である。
末端の取り出しには、`3010740` の生成処理からビルドした `qsearch_leaf`（SHA-256 `d3e2a21e…`）の複製を使った。
初期重みは採用PST（`nets/pst.bin`、SHA-256 `72d7aee9…`）であり、整合性の検査の `pst_probe` はコミット `bcc32fa` からビルドした。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）とNVIDIA GeForce RTX 3060 Ti（8 GB）で、2026年9月30日5時44分から6時48分に学習した。
学習の途中で、同じ測定機で診断器の再現確認（同時16）を実行した。
取り出しはノード数で決まる静止探索なので、負荷は所要時間だけに影響する。

## 結果

### 学習の条件

| 項目 | 値 |
|---|---|
| 静かな訓練根 | 5,788,833件 |
| 捕獲訓練根（Qcだけ） | 875,477件 |
| 静かな検証根 | 291,035件 |
| バッチ | 静かな根16,384根、Qcはこれに捕獲根2,478根を加える |
| 区間あたりの更新回数 | 354回 |
| 総更新回数 | 3,540回（10区間） |
| 教師尺度K_g | 767.491528450171 |
| 出力の尺度K | 1072.6529541015625 |
| 学習率、乱数シード、駒除去差分の係数 | 0.03、1、1000 |
| 重みの選択 | 最終の更新後の重み |

3者の静かな根の抽出回数（57,999,360回）と更新回数（3,540回）は一致し、各区間の静かな根のバッチ列のSHA-256も3者で一致した。
Qcだけが捕獲根を8,772,120回抽出した。

### 末端の取り出し

全10区間で、QとQcの静かな訓練根と、Qcの捕獲訓練根の末端はすべて静的評価で決まり、除外した根は0件だった。
PythonとRustの末端の評価値は、全区間の全末端で一致した。
静かな訓練根の1回の取り出しは、同時16でCPU時間216〜250秒、経過40〜111秒であり、捕獲訓練根は経過17〜30秒だった。
経過時間の最大値は、診断器の再現確認と重なった区間である。
10回の合計はQが約9分、Qcが約12分であり、設計書の基準（それぞれ60分以内）を満たした。

### 整合性の検査

| 検査 | R | Q | Qc |
|---|---|---|---|
| 量子化の平均絶対誤差（センチポーン、10万局面） | 0.51 | 0.51 | 0.56 |
| 量子化の最大誤差（センチポーン） | 1.80 | 1.77 | 2.26 |
| RustとPythonの評価の一致（10万局面） | 全件一致 | 全件一致 | 全件一致 |
| RustとPythonの駒除去差分の一致（354件） | 全件一致 | 全件一致 | 全件一致 |
| 逆向きの駒除去差分 | 0 | 0 | 0 |

量子化の基準は平均絶対誤差2センチポーン以下であり、3者とも満たした。
S0にない逆向きの駒除去差分はなく、3者とも対局へ出せる。

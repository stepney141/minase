# 判定の差mの再校正（順位の損失の計画）

## 目的

[浅い探索の手の順位を学ぶ損失](../plans/rank-loss-training.md)の安定した組の判定と損失の尺度に使う差mを、[探索局面の計画](../plans/search-aware-evaluation.md)と同じ手順で、現在のS0で測り直す。
S0の探索は、同計画がmを校正した基点`5563d75`から変わっているからである。
棋力測定ではなく、対局の勝敗を使わない。

## コマンドライン

```console
E=data/rank-loss-training/bin/eval_teacher-795deec
O=data/rank-loss-training/calibration
$E prepare --out-dir $O --s0-commit 0a0171f945acbd5151295920fe3e0f27aaeb6fe5
$E select --out-dir $O
$E evaluate --out-dir $O --set calibration --jobs 4
$E evaluate --out-dir $O --set confirmation --jobs 4
$E classify --out-dir $O
```

作業ディレクトリは本体のリポジトリであり、根は`data/matches/`以下の5資料から抽出した。

## エンジン

`eval_teacher`は、探索局面の計画の診断器をブランチ`rank-loss-training`のコミット`795deec`へ移植したものであり、移植で変えたのはモジュールのパスだけである（SHA-256 `cc298f5f…`）。
探索と埋め込みPST（SHA-256 `72d7aee9…`）は、master `0a0171f`と同一である。
規則は`L0,P0,R1,E0`、各探索は1スレッド、探索ごとに新しい64 MiBの置換表、ノード上限だけの制限とした。
提案手の探索は100,000ノード、教師は1,000,000ノードと10,000,000ノードである。
抽出シードは探索局面の計画と同じ20260926であり、旧候補の手は全資料で保存着手を使った。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）で、2026年9月30日に実施した。
同じ測定機で自己対局の生成（同時16）が走っていたので、根の評価は同時4根で行った。
探索はノード数で決まるので、負荷は所要時間だけに影響し、下記の探索時間は負荷のない場合より長い。

## 結果

| 量 | 値 |
|---|---:|
| 校正根 | 64 |
| 通常評価で比較できた校正根 | 62 |
| \(\lvert D_{10M}-D_{1M}\rvert\) の90パーセンタイル | 117.7センチポーン |
| 歩兵価値Pの1/4 | 25センチポーン |
| 判定に使う差m | 117.7センチポーン |

校正集合の候補集合は根あたり平均2.67手、子探索342件の応答は通常評価336件、詰みを示す値6件だった。
教師の完了深さの中央値は、1,000,000ノードで10、10,000,000ノードで13である。
根あたりの探索時間は平均22.5秒（最大51.4秒）であり、評価全体の経過時間は6分10秒だった。

確認用128根の分類は次のとおりである。

| 分類 | 根の数 |
|---|---:|
| 基準手を安定して支持する | 11 |
| 旧候補手を安定して支持する | 3 |
| 差が小さい | 94 |
| 判定が不安定である | 19 |
| 通常評価では比較できない | 1 |

最初の3分類の合計は108根、基準手を安定して支持する根は11根であり、探索局面の計画の続行条件（64根以上と8根以上）も満たした。

## 結論

判定の差mを117.7センチポーンに固定し、順位の損失の計画の安定した組の判定と、損失の尺度\(\tau\)に使う。

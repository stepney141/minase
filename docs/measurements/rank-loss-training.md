# 対照Cと順位の損失の候補の学習

## 目的

[浅い探索の手の順位を学ぶ損失](../plans/rank-loss-training.md)のフェーズ3として、値の回帰だけで学ぶ対照Cと、順位の損失を重みβ（0.1、0.3、1.0）で加えた3候補を、採用版S0から同じ条件で学習し、設計書の規則でβを1つ選ぶ。
棋力測定ではなく、対局の勝敗を使わない。

## コマンドライン

```console
P=data/rank-loss-training
T=$P/phase3
for S in train validation; do
  $P/bin/eval_teacher-f060e35 rank-export --roots $P/phase2/roots-$S.jsonl \
    --results $P/phase2/results-$S.jsonl --output $T/children-$S.bin --index $T/children-$S.jsonl
done
nice -n 5 tools/train/.venv/bin/python tools/train/pst/train_rank.py train \
  --data $P/data/generated-94000000.bin $P/data/generated-94100000.bin \
  --init nets/pst.bin --output-dir $T/training \
  --qsearch-leaf $P/bin/qsearch_leaf-f060e35 \
  --teacher-k 763.9876650061155 --k 1072.6529541015625 --m 117.7 \
  --train-roots $P/phase2/roots-train.jsonl --train-results $P/phase2/results-train.jsonl \
  --train-children $T/children-train.bin --train-index $T/children-train.jsonl \
  --validation-roots $P/phase2/roots-validation.jsonl --validation-results $P/phase2/results-validation.jsonl \
  --validation-children $T/children-validation.bin --validation-index $T/children-validation.jsonl \
  --device cuda --leaf-jobs 16
```

学習の全区間の記録は`rank-loss-training/training.json`、小標本の集計は`rank-loss-training/pilot.json`に保存した。

## エンジン

学習器はブランチ`rank-loss-training`のコミット`f060e35`の`train_rank.py`であり、値の回帰には同じコミットの`train_qsearch.py`の対照Rの関数をそのまま使った。
子局面の書き出しと末端の取り出しには、同じコミットからフィーチャ`qsearch-leaf`付きでビルドした`eval_teacher`（SHA-256 `34aa4ec6…`）と`qsearch_leaf`（SHA-256 `7a91827e…`）を使った。
初期重みは採用PST（`nets/pst.bin`、SHA-256 `72d7aee9…`）であり、S0はmaster `0a0171f`である。
学習データは[生成し直した15,000局](rank-loss-selfplay-data.md)、順位の教師は[フェーズ2の教師](rank-loss-data.md)である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）とNVIDIA GeForce RTX 3060 Ti（8 GB）で、2026年10月1日11時22分から11時50分に、他の負荷のない状態で学習した。
子局面の書き出しを含む経過時間は28分11秒だった。

### 起動時の検査と受理集合

学習の開始前に、S0の重みで訓練の子局面87,414件と検証の子局面3,827件の末端を取り出し、Pythonで計算した深さ1の値が、Rustの静止探索の返り値の符号を反転した値（教師の生成時に記録した値）と全件一致することを確かめた。
末端が詰みとなった子局面は訓練236件、検証8件であり、いずれも安定した組には含まれなかった。
全10区間で、3候補の受理集合は訓練の安定した組26,353組のすべてであり、検証の最終評価の受理集合も1,154組のすべてだった。

Cの値の損失と平均絶対誤差は最後の区間まで下がり続けた。
3候補では、順位の損失が下がり正答率が上がる一方で、値の訓練損失、検証損失、および平均絶対誤差は区間を追って上がり、βが大きいほど上がり方が大きかった。

### βの選択

最終の重みの平均絶対誤差は、Cの0.05021に対して、β=0.1で0.05907（1.176倍）、β=0.3で0.06222（1.239倍）、β=1.0で0.06426（1.280倍）であり、3通りとも設計書の上限であるCの1.05倍を超えた。
したがって候補にできるβはなく、設計書の規則により見送りとした。
学習器の選択結果は`{"status": "見送り", "model": null, "beta": null, "eligible": []}`である。

量子化の平均絶対誤差は、10,000局面でCが0.51、β=0.1が0.50、β=0.3が0.50、β=1.0が0.51センチポーンであり、最大は1.98センチポーンだった。

## 結論

順位の損失は検証の安定した組の正答率をCの0.33から0.48〜0.51へ上げたが、その代わりに静的評価と教師値の平均絶対誤差を18〜28%悪化させ、3通りのβがすべて選択の上限を超えたので、βの選択で見送った。
損失が働かなかったのではなく、同じPSTの中で手の順位と局面の値が両立しなかった結果であり、採否前の診断（`rank-loss-diagnostics`）と棋力の測定は行っていない。

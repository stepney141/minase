# 順位の損失の候補と対照CのSTC

## 目的

[浅い探索の手の順位を学ぶ損失](../plans/rank-loss-training.md)の順位の損失を重みβ=1.0で加えた候補を、同じデータと更新回数で値の回帰だけを学んだ対照Cと短時間条件STCで対局させ、順位の損失による10 Eloの改善があるかをGSPRTで判定する。
候補は設計書のβの選択で除外されていたが、利用者が棋力の測定を優先すると決めたので、選択の規則から平均絶対誤差の上限だけを外して選ばれるβ=1.0の1本を測った。

## コマンドライン

```console
data/rank-loss-training/bin/match_runner-5ddcb8e \
  --run-dir data/matches/rank-loss-vs-control-stc --seed 96000000 \
  --candidate commit:04dad7263aaf8da9d64f97a3e84141217602f3df \
  --baseline commit:a1c93fcf9c127b7c9d4e8897cd4f0a62600374a1 \
  --each time=10000+100 gsprt --max-pairs 3000
```

`match_runner`は、ブランチ`rank-loss-training`のコミット`5ddcb8e`からビルドした（SHA-256 `b35cd27b…`）。

## エンジン

| 役割 | コミット | 内容 | 実行ファイルのSHA-256 |
|---|---|---|---|
| 候補 | `04dad72`（ブランチ`rank-loss-b10`） | master `0a0171f`の`nets/pst.bin`をβ=1.0の重み（SHA-256 `8ba90909…`）へ差し替え | `a66eb00a…` |
| 基準 | `a1c93fc`（ブランチ`rank-loss-c`） | master `0a0171f`の`nets/pst.bin`を対照Cの重み（SHA-256 `3d1ca9f0…`）へ差し替え | `ed91f1df…` |

両者の差は`nets/pst.bin`だけであり、探索はmaster `0a0171f`と同一である。
規則は`L0,P0,R1,E0`である。
対局の前に、両者の重みが整合性の検査（逆向きの駒除去差分0件、量子化の平均絶対誤差0.50〜0.51センチポーン）を通ることを確かめた。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）である。
候補と基準のワーカー数は1、`USI_Hash`は256 MB、同時対局数は19、時間制御は`time=10000+100`である。
2026年10月1日12時59分から13時29分に、他の負荷のない状態で実行した。

## 結果

| 項目 | 値 |
|---|---|
| ペンタノミアル度数 | [78, 1, 104, 1, 29] |
| 有効ペア | 213 |
| 破棄ペア（手数上限） | 6 |
| LLR | −2.952 |
| 判定 | `H0` |
| 候補の得点率 | 38.5% |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 1,764秒（`summary.json`の累計1,749秒） |

候補の得点率38.5%は、ロジスティックEloで約−81 Eloに当たる。

## 結論

順位の損失を加えた候補は対照Cに対して`H0`となり、10 Eloの改善を示せなかったので、設計書の「棋力の採否」の規定により不採用とし、S0との対局は行わない。
S0に対する候補とCの強さは測っていない。

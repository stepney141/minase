# 関係補正項の準備記録

## 目的

[残存誤りに対応する関係補正項](../plans/relational-correction.md)のフェーズ0として、採用版S0の新しい自己対局から採った根で大きな着手の誤りを判定し、探索の変更で解消を確認できない誤りを駒の関係の種類に分類して、補正項を1つ選ぶか見送るかを決める。
棋力測定ではなく、対局の勝敗を使わない。

## 事前登録

本節は、診断用の対局から採る根の着手、読み筋、および盤面を見る前の2026年10月1日に固定した。
結果を見た後に、標本、教師の判定、解消の判定、時間の上限の規則、停止の規則、分類の定義、および着手の基準を変えない。
時間の上限の数値だけは、本節の規則に従って診断に使わない6根で測った値を、診断用の根の追跡を始める前に「時間の上限」の節へ書き入れる。

### S0と判定の差

S0は、master `c47106a`の探索と埋め込みの採用PST（`nets/pst.bin`）である。
探索と評価のコードは[順位の損失の計画](../plans/rank-loss-training.md)のS0（master `0a0171f`）から変わっていないので、判定の差mは同計画が測り直した117.7センチポーン（[教師の校正](rank-loss-teacher-calibration.md)）を使う。

探索はすべて、本ブランチ`relational-correction`のコミット`bf897dd`をフィーチャ`search-trace`つきでビルドした`minase`で行う。
このコミットは、master `c47106a`に、履歴つきの自己対局の生成器（順位の損失の計画が使ったものと同じ2コミット）と、[探索の追跡記録](qsearch-output-search-trace.md)の追跡用フィーチャを移したものである。
追跡用フィーチャは、null moveの反復検出の修正の後の探索へ移植した。
フィーチャの有無にかかわらず、深さ6の`bench`の15局面のノード数、最善手、および評価値がmasterと一致し（総ノード数1,677,944）、フィーチャつきのライブラリのテスト704件はすべて通った。

探索の条件は、規則`engine-default`（`L0,P0,R1,E0`）、1スレッド、置換表64 MiB、`ResignValue 99999`、探索ごとに新しいプロセスとし、根はUSIの`position startpos moves`で履歴ごと与える。
`score mate n`を返した探索の値は詰みを示す値として通常の評価値と区別し、通常の評価値どうしの比較には含めない。

### 標本

診断用の対局は、`bf897dd`に固定したworktreeでビルドした`selfplay_gen`で、1回あたり1,024局を生成する。
設定は順位の損失の計画の学習データ（[生成の記録](rank-loss-selfplay-data.md)）と同じく、1手100,000ノード、置換表16 MiB、手数上限4,000、`--random-moves 0`、同時16対局とし、記録の種類と履歴を出力する。
第b回（bは1から4）の基本シードは99,000,000+100,000×(b−1)とする。
生成器の探索はS0と同じなので、過去の生成と測定に使っていないこの範囲のシードを使うことで、過去の診断の対局を生成し直さない。

手数上限で破棄された対局を除き、各対局の記録から1件を一様に選び、その局面を根とする。
記録の種類（静かな局面、捕獲局面、成り局面）では選り分けない。
第b回の選択の乱数は種20261001+bで初期化し、対局番号の昇順に1局1件を引く。
根は、保存した着手列を初期局面から再生した局面が記録の局面と一致することを確かめてから使う。
破棄された対局と、破棄されずに記録を1件も持たない対局からは根を採らないので、1回の根の数は1,024より少なくなる。
後者の対局数も回ごとに記録する。
採取は最大4回、すなわち4,096局までとする。

### 教師の判定

各根で、S0の提案と、教師の2予算の提案を求める。
S0の提案は根の100,000ノードの探索であり、その最善手を提案手s0、最後に完了した反復の深さをd0とする。
教師の提案は、根の1,000,000ノードと10,000,000ノードの探索の最善手である。
候補集合Cはこの3手から重複を除いた集合とし、USI表記の辞書順に並べる。

Cの各手の子局面を1,000,000ノードと10,000,000ノードで独立に探索し、評価値の符号を反転して根の手番側から見た手の値$Q_{1M}$と$Q_{10M}$を得る。
Cのすべての手で両予算の値が通常の評価値である根を比較可能な根とし、終局または詰みを示す値を含む根は比較不能として件数だけを数える。

比較可能な根で、2手a、bの組について$D_n=Q_n(a)-Q_n(b)$とし、[探索局面の計画](../plans/search-aware-evaluation.md)と同じ規則で組を分類する。
$|D_{1M}|\ge m$、$|D_{10M}|\ge m$、$D_{1M}$と$D_{10M}$が同符号、かつ$|D_{10M}-D_{1M}|\le m$の組は、Dの符号が示す手を安定して支持する。
$|D_{1M}|<m$かつ$|D_{10M}|<m$の組は小差とし、それ以外の組は不安定とする。
Cのすべての組が安定した支持か小差に入る根を、教師の判定が安定した根とする。

教師の最善手a\*は、Cの中で$Q_{10M}$が最大の手（同値はUSI表記の辞書順で先の手）とする。
S0の損失を$R=Q_{10M}(a^\ast)-Q_{10M}(s_0)$とし、教師の判定が安定した根で$R\ge m$の根を大きな誤りとする。

### 誤りの型

大きな誤りの各根で、a\*とs0の子局面の10,000,000ノードの探索の読み筋を使い、[相対2駒評価の準備記録](relative-pair-prep.md)と同じ規則で型S、H、Pを付ける。
駒の損得$\mu_k$は、盤上の駒の探索用駒価値の和を根の手番側から見た差とし、王駒を数えない。
読み筋のk手目は、子局面への手を1手目として数える。
読み筋は、指した後の局面が終局となる手までで切り詰め、それより後の手は捨てる。
この切り詰めは、追跡の経路にも同じく適用する。
読み筋がd0手より短い場合は、末端の駒の損得をそれ以降のすべての手数の値とみなして$\mu_{d_0}$を定める。
型は読み筋の記述であり、以下のどの判定の分母からも根を除かない。

### 探索の追跡と介入

大きな誤りの各根に、[探索の追跡記録](qsearch-output-search-trace.md)の「探索条件」「教師の値」「乖離の判定」「介入」の手順を、mを117.7に置き換えて適用する。
経路、教師の値、乖離点、停止の理由、追跡で関与した機構、および無効にする11機構の定義は、同記録のとおりとする。
前提条件として、`go nodes 100000`と`go depth d0`が、記録したs0、d0、および評価値を再現することを確かめる。
再現しない根が1根でもあれば、処理を止めて原因を調べる。

介入は、11機構をそれぞれ単独で無効にする11通りと、両経路の追跡で関与した機構をすべて同時に無効にする1通りである。
関与した機構がない根では、同時の介入を行わない。
各介入で`go depth d0`と`go nodes 100000`をそれぞれ実行し、選ばれた手bを記録する。
bの子局面がまだ探索されていなければ、両予算で探索する。

介入の選んだ手bは、b=a\*であるか、またはa\*とbの両予算の値がすべて通常の評価値で、組(a\*, b)が小差であるかbを安定して支持する場合に、誤りを解消したとする。
組がa\*を安定して支持する場合、不安定な場合、および比較不能な場合は、誤りを解消していない。

探索の変更で解消した根は、追跡で関与した機構の単独の介入と同時の介入のうち少なくとも1つで、`go depth d0`の選択と`go nodes 100000`の選択がともに誤りを解消した根とする。
次の根は、解消を確認できなかった根として残す。

- 追跡で関与しなかった機構の単独の介入だけが誤りを解消した根。
- 両経路とも乖離しなかった根、および追跡で関与した機構がない根。
- 時間の上限で追跡を打ち切った根。

すべての介入について、2つの探索の選択、選んだ手の両予算の値、および組の分類を記録し、別の読み方による件数を記録から計算し直せるようにする。

### 時間の上限

1根の追跡時間は、前提条件の検査、両経路の追跡、すべての介入の探索、および介入の選んだ手の両予算の評価に使った実時間の合計とし、教師の判定の探索は含めない。
1根の上限は、[探索の追跡記録](qsearch-output-search-trace.md)の6根の追跡時間の中央値の3倍とする。
同記録には根ごとの時間がなく、追跡は修正前のS0で行われたので、6根の追跡時間は本節の手順で測り直す。
6根では、現在のS0で提案手と候補集合を求め直し、同記録との一致は検査せず、大きな誤りでない根でも追跡とすべての介入を行う。
時間は、同時16の枠のうち6根を同時に処理し、測定機で他の計算を走らせない状態で測る。
この6根は診断の根に含めない。

1根の追跡が上限に達した場合は、その根の追跡を打ち切って「原因未確定（時間上限）」とし、分母Nに含める。
1回の追跡の段階、すなわちその回の大きな誤りのすべての追跡は、実時間4時間を上限とする。
上限に達した場合は、未処理の根を追跡せずに採取を止め、フェーズ0を診断未完了として記録して見送る。
この見送りは費用による中断であり、関係補正が不要だったという結論には置き換えない。

6根の追跡時間と上限の値は、診断用の根の追跡を始める前に次の表へ書き入れた。
測定は2026年10月1日17時22分から17時24分に、`phase0.py timing --jobs 16`で行った（出力は`data/relational-correction/phase0/timing/`）。
6根のうち4根は現在のS0でも大きな誤りであり、2根は大きな誤りではなかった。

| 項目 | 値 |
|---|---|
| 6根の追跡時間 | 6.38秒、7.36秒、11.80秒、14.16秒、19.73秒、41.48秒 |
| 中央値 | 12.98秒 |
| 1根の上限（中央値の3倍） | 38.94秒 |
| 1回の上限 | 実時間4時間 |

### 採取の停止

各回の追跡を終えた時点で、それまでの全回の大きな誤りのうち、探索の変更で解消を確認できなかった根の数をNとする。
N≥30なら採取を止め、そうでなければ次の回を生成する。
4回目の後は、Nにかかわらず採取を止める。
停止の判定は関係の分類を見る前に行い、分類は採取を止めた後に、全回の解消を確認できなかった根へまとめて1回だけ行う。

### 関係の分類

解消を確認できなかったすべての根を、型S、H、Pを問わず、次の4種類に分ける。
関与駒は、a\*の読み筋の最初の6手で動く駒と取られる駒である。
2つの子局面は、a\*の子局面とs0の子局面である。
チェビシェフ距離は、2升の筋の差と段の差の絶対値の大きい方である。

- 近接2駒は、少なくとも一方が関与駒で、互いのチェビシェフ距離が2以内の駒の組の配置によって、2つの子局面の違いを説明できる場合である。取る駒と取られる駒の接近、隣の駒による支え、および隣の駒による進路の塞ぎを含む。
- 王駒射線は、違いが、王駒から8方向のいずれかにある最初の駒と、その奥にある王駒へ向かう敵の走り駒の組の配置で説明できる場合である。
- 多駒は、違いが3枚以上の駒の同時の条件によって初めて説明でき、王駒射線に当たらない場合である。
- 不明は、上のいずれでも説明できない場合である。

読み筋の末端の局面は、関与駒がすでに取られていることがあるので分類の対象にせず、関係の帰結を確かめる証拠として使う。

分類の資料は、根ごとに同じ形式の文書とし、次の内容を含める。
根の局面、2つの子局面、およびa\*の読み筋の末端の局面の盤面を載せる。
a\*の読み筋の最初の6手について、各手で動く駒と取られる駒を示し、関与駒の一覧を付ける。
2つの子局面それぞれで、各関与駒からチェビシェフ距離2以内にある駒と、各王駒から8方向に並ぶ最初の2駒を列挙する。
両読み筋の駒の損得$\mu_k$の推移と、追跡の要約（乖離点、停止の理由、および追跡で関与した機構）も載せる。

分類者は、本計画の文脈を持たない新しいClaudeのエージェントとcodexの2者とする。
各分類者には4種類の定義と分類の資料だけを渡し、種類と補正項の対応、着手の基準、本計画の目的、および他方の分類結果を知らせない。
各分類者は、根ごとに4種類のいずれか1つと理由を返す。
両者が同じ種類とした根だけを、その種類の一致件数に数える。

### 着手の基準

採取を止めた時点の、探索の変更で解消を確認できなかった大きな誤りの総数をNとする。
Nには、時間の上限で打ち切った根、不明の根、および分類が一致しなかった根を含める。
Nが30未満なら、標本不足として見送る。
Nが30以上なら、一致件数が最も多い種類について、その件数がNの3分の1以上であれば、その種類に対応する補正項を実装する。
近接2駒は局所2駒表、王駒射線は射線表、多駒は幅64の小型NNUEに対応し、不明には対応する補正項がない。
同数の場合は、係数の少ない順に王駒射線、近接2駒、多駒を選ぶ。
どの種類も基準に届かなければ見送る。

## コマンドライン

生成は`bf897dd`に固定したworktree（`data/relational-correction/pinned`）を作業ディレクトリとして実行し、根の抽出、教師の判定、追跡、および集計は本ブランチの`relational-correction-prep/phase0.py`（コミット`c63a332`の版）で実行した。
第2回以降は、停止の判定を含めて`relational-correction-prep/run_batches.sh`で順に実行した。

```console
R=data/relational-correction
S=docs/measurements/relational-correction-prep/phase0.py
python3 $S timing --jobs 16
# 第b回（b=1, 2）。シードは99,000,000+100,000×(b−1)
(cd $R/pinned && $R/bin/selfplay_gen generate --output $R/phase0/batch1/generated.bin \
  --kinds $R/phase0/batch1/generated.kinds --history $R/phase0/batch1/generated.history.jsonl \
  --games 1024 --seed 99000000 --nodes 100000 --random-moves 0 \
  --concurrency 16 --max-ply 4000 --hash-mb 16)
$R/bin/selfplay_gen inspect $R/phase0/batch1/generated.bin \
  --kinds $R/phase0/batch1/generated.kinds --history $R/phase0/batch1/generated.history.jsonl
python3 $S sample --batch 1 --jobs 16
python3 $S teacher --batch 1 --jobs 16
python3 $S trace --batch 1 --jobs 16 --root-cap 38.94 --batch-cap 14400
python3 $S status
python3 $S packets --out $R/phase0/packets
```

第1回は、最初に本体のリポジトリの下から生成を起動したため、生成器が実行時に読む`git rev-parse HEAD`がmasterの`c47106a`を記録した。
実行ファイルは`bf897dd`のものだったが、来歴を正しく残すため、固定したworktreeから同じシードで生成し直した。
生成し直した対局の履歴は、最初の生成と全981局でバイト単位に一致した。
以下の結果は生成し直した記録だけによる。

## エンジン

分類者は、本セッションの文脈を持たずに起動したClaudeのエージェント（general-purpose）と、codex（`codex-companion`の新規タスク、推論の強さhigh）である。

深さd0の選択だけで判定すると、解消した根は66根、Nは26である。

### 探索の変更で解消した根

解消した30根のうち20根は1つの機構の単独の介入だけで、10根は2つ以上の機構の単独の介入でも解消した。
誤りを解消した介入の件数は、null moveが14根、aspiration windowが13根、LMRが12根、主探索の置換表による打ち切りが3根、関与した機構の同時の介入が16根である。
[探索の追跡記録](qsearch-output-search-trace.md)の6根と同じく、1つの根で複数の機構が選択を変えることが多く、件数は機構が誤りの原因であることの証拠ではない。
30根の識別子と介入ごとの結果は、`trace.jsonl`から再現できる。

## 結論

探索の変更で解消を確認できなかった大きな誤りは62根あったが、2者の分類が一致した根は近接2駒の15根が最多で、事前登録の基準21根に届かなかったので、関係を表す補正項は実装せずに見送る。
この結論は、本標本と本規則の下で補正項の種類を1つに絞る根拠がなかったことに限られ、関係を表す評価方式全般を否定しない。
近接2駒と多駒の間で分類が13根割れたことは、2つの種類の境界が配置の読みに依存し、同じ根を独立に分類しても安定しないことを示している。

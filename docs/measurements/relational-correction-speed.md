# 局所2駒表の零の表の速度

## 目的

[関係補正項の計画](../plans/relational-correction.md)の利用者の判断による測定のフェーズ1として、局所2駒表の値をすべて0にした半径1、2、3の構成の探索速度を採用版S0と比べ、[相対2駒評価の計画](../plans/relative-pair-eval.md)の規則で半径の上限$R_{\mathrm{speed}}$を求める。
棋力測定ではなく、対局の勝敗を使わない。

## コマンドライン

```console
B=data/relational-correction/bench
for i in 1 2 3; do
  for b in s0 r1 s0 r2 s0 r3; do
    taskset -c 3 $B/bench-$b --depth 5 --repetitions 3 | grep median
  done
done
```

`bench-s0`はmaster（探索と評価のコードは`c47106a`と同一）の`bench`、`bench-rR`は本ブランチのコミット`e9c3451`の`bench`に、半径Rの零の表を付けた版3の重み（`tools/train/pst/mnpt_v3.py upgrade --radius R`で採用PSTから作成）を埋め込んでビルドしたものである。
各構成は、S0と交互に3回ずつ実行し、各回が出力する3反復の中央値を記録した。

## エンジン

重みは、採用PSTの版2のファイル（SHA-256 `72d7aee9…`の重み本体）に零の表を付けた版3であり、学習PSTの重み、探索用駒価値、および出力尺度は版2とビット単位で一致する。
深さ5の`bench`は、4構成とも15局面のノード数、最善手、および評価値が一致し、総ノード数は688,332であった。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）で、2026年10月1日22時03分から22時05分に、性能コアの論理CPU 3へ固定して1スレッドで実行した。
同じ測定機では他の測定を走らせなかった。

## 結果

| 構成 | 毎秒の探索ノード数（3回） | 中央値 | S0との比 |
|---|---|---:|---:|
| S0 | 2,004,725、1,993,555、2,008,135、1,992,274、2,000,111、2,004,915、2,008,406、2,000,510、2,000,132 | 2,000,510 | 1.000 |
| 半径1 | 1,546,140、1,552,028、1,549,706 | 1,549,706 | 0.775 |
| 半径2 | 1,189,508、1,185,075、1,186,795 | 1,186,795 | 0.593 |
| 半径3 | 931,366、936,977、933,824 | 933,824 | 0.467 |

半径1でも基準の0.85倍に届かず、相対2駒評価の計画の規則では見送りとなる。
[設計書](../plans/relational-correction.md)の「利用者の判断による測定」節が事前に固定した代わりの規則により、半径1を選び、半径3の学習による半径の選択は行わない。

## 結論

零の表の局所2駒表は、半径1でS0の0.775倍の速度となり、速度の条件は満たさないが、事前の規則により半径1で学習へ進む。

# 探索局面と教師データの生成（探索局面の学習計画）

## 目的

[探索局面を用いた評価関数の学習](../plans/search-aware-evaluation.md)のフェーズ3として、S0同士の自己対局から根と探索局面を採取し、10,000,000ノードの教師でラベルを付けて、対照Aと候補Bの学習用の組を作る。

## コマンドライン

```console
target/release/search_aware_data --out-dir data/search-aware-evaluation/phase3 prepare \
  --s0-commit 5563d7526f6d727f195603aadf96147607209a2b
target/release/search_aware_data --out-dir data/search-aware-evaluation/phase3 collect \
  --start 202610000 --games 5600 --jobs 16
target/release/search_aware_data --out-dir data/search-aware-evaluation/phase3 extract --jobs 16
target/release/search_aware_data --out-dir data/search-aware-evaluation/phase3 label --jobs 16
data/search-aware-evaluation/pinned/search_aware_data --out-dir data/search-aware-evaluation/phase3 export
```

実行ファイルは、ブランチ `search-aware-evaluation` の `ae5f9c6` から `search-sampling` 付きでビルドした `search_aware_data`（SHA-256 `834a0af8…`）である。
フェーズ4の実装で同じバイナリのソースが変わったため、書き出しには、manifestの検査和と一致する複製を `data/search-aware-evaluation/pinned/` に固定して使った。

## エンジン

基点S0と教師は、ともにmaster `5563d75` の探索と埋め込みPST（SHA-256 `72d7aee9…`）である。
規則は `L0,P0,R1,E0`、各探索は1スレッドとした。
自己対局は1手100,000ノード、置換表16 MiB（局ごとに新規）、上限4,000手である。
採取は各根100,000ノード、教師は各局面10,000,000ノードで、どちらも探索ごとに新しい64 MiBの置換表を使った。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）で、2026年9月26日に実施した。
lishogi Botの `minase` が約4コアを使っていた。
探索はノード数で制限しているので、この負荷は所要時間だけに影響し、生成した値には影響しない。

## 結果

### 自己対局と根の抽出

5,600局の自己対局は2時間55分で終わった。
手数の中央値は425、平均は628.1で、勝敗が付いた局が5,224、引き分けが185、4,000手の上限に達した局が191であった。
各局から最大16根を抽出して89,420根を得て、根と採取局面の抽出は21分39秒で終わった。

静止探索が静的評価を呼んだ回数と、その内訳は次のとおりである。

| 区分 | 件数 | 割合 |
|---|---:|---:|
| 静的評価の呼出し | 6,639,196,672 | 100% |
| null move配下 | 540,782,350 | 8.15% |
| 反復を含む経路 | 0 | 0% |
| 同じ根で既出のPST入力 | 1,469,696,389 | 22.14% |
| 重複除去後の採取候補 | 4,628,717,933 | 69.72% |

根あたりの採取候補数の中央値は53,480であり、候補を持たない根はなかった。
反復を含む経路が0件なのは、通常探索が反復を検出した時点で静止探索へ進まず、静止探索の捕獲手は同じ局面を再現しないためである。
採取した局面の経路が終局に達して除外した根は508（0.57%）で、再生できなかった根はなかった。

分割は訓練4,480局、モデル選択560局、最終診断560局で、比率は80%、10%、10%であった。
分割をまたぐ重複と、それによる群の併合は0件であった。
同じ分割の中で、異なる履歴から同じPST入力に至った局面は122組あった。
訓練32,768組、モデル選択4,096組、最終診断256組を、教師を見る前にすべて確保した。

### 教師ラベル

107,008局面のラベル生成は9時間48分、書き出しは19分18秒で終わった。
教師の応答は通常評価と詰みを示す値だけで、終局と未完了はなかった。

| 集合 | 予定の組 | 受理した組 | 受理率 | 予定数の90%未満 |
|---|---:|---:|---:|---|
| 訓練 | 32,768 | 28,947 | 88.34% | 該当する |
| モデル選択 | 4,096 | 3,688 | 90.04% | 該当しない |
| 最終診断 | 256 | 229 | 89.45% | （別集計） |

訓練の不受理は、組の中に詰みを示す教師値を含むことによる。
役割ごとの詰みの割合は次のとおりである。

| 役割 | 局面 | 詰みを示す値 | 割合 |
|---|---:|---:|---:|
| 訓練の通常局面u | 32,768 | 501 | 1.53% |
| 訓練の通常局面v | 32,768 | 511 | 1.56% |
| 訓練の探索局面z | 32,768 | 3,119 | 9.52% |
| モデル選択の根 | 4,096 | 71 | 1.73% |
| モデル選択の探索局面 | 4,096 | 372 | 9.08% |
| 最終診断の根 | 256 | 8 | 3.13% |
| 最終診断の探索局面 | 256 | 21 | 8.20% |

探索局面の詰みは、通常局面のおよそ6倍の頻度で現れた。
訓練のzの詰み3,119件のうち2,497件（80%）は、評価値の絶対値が29,999、すなわち手番側が直ちに相手の王駒を取れる局面であり、2,886件は手番側の勝ちであった。
中将棋では王駒を相手の利きへ置く着手も合法であるため（RULES.md第8条）、静止探索が静的評価を呼ぶ局面には、王駒を取られる直前の局面が多く含まれる。
通常局面の詰みは、評価値の絶対値が29,990から29,997の範囲に分散していた。

群ごとの受理率に分けると、Aの組（uとv）だけなら96.95%、Bの組（uとz）だけなら89.12%が受理される。
設計書は両群を同じ組の集合で比べるため、判定には組全体の受理率を使う。

## 結論

訓練の受理率は88.34%であり、当初の停止条件「訓練またはモデル選択で使える組が予定数の90%未満である」に該当した。
不受理の原因はデータ量ではなく、採取した探索局面の約9.5%で教師が詰みを示す値を返すことにある。
静止探索の評価局面を定義どおり採ると、学習できない局面が学習分布の1割近くを占める。

この結果を受けて、AとBの学習を始める前に、設計書の訓練の受理条件を「受理した組で総更新回数が2,000回を超えること」に改めた（経緯は設計書の「状態」の節）。
受理した28,947組では、1エポック57回、計2,280回の更新になり、改訂後の条件を満たす。
モデル選択の受理率90.04%は、改訂後も維持した90%以上の条件を満たす。
したがって、受理した組でフェーズ4の学習へ進む。

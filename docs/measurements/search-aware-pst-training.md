# 対照Aと候補Bの学習（探索局面の学習計画）

## 目的

[探索局面を用いた評価関数の学習](../plans/search-aware-evaluation.md)のフェーズ4として、同じ組で通常局面だけを学ぶ対照Aと、半数を探索局面へ置き換えて学ぶ候補Bを、固定尺度K0の教師値で学習する。

## コマンドライン

```console
tools/train/.venv/bin/python tools/train/pst/search_aware.py train \
  --export data/search-aware-evaluation/phase3/export.jsonl --s0 nets/pst.bin \
  --out-dir data/search-aware-evaluation/phase4/training --device cuda
```

学習器はブランチ `search-aware-evaluation` の `0a494c0` である。
このコミットは、設計書の改訂（訓練の受理条件を総更新回数の下限へ改めたもの）を学習器へ反映している。

## エンジン

初期値はS0（master `5563d75`）の埋め込みPST（SHA-256 `72d7aee9…`）、K0は1072.6529541015625である。
入力は[探索局面と教師データの生成](search-aware-data.md)が受理した組であり、訓練28,947組、モデル選択3,688組である。
Aは各組のuとv、Bは各組のuとzを使い、どちらも57,894局面である。
モデル選択集合は、両群に共通の7,376局面（根とその採取局面が半数ずつ）である。
損失は、教師値を固定尺度K0で勝率へ換算した値に対する二値交差エントロピーと、S0を参照とする駒除去損失（係数1000）の和である。
最適化はAdam、学習率0.03、40エポック、バッチ1,024、乱数シード1であり、1エポック57回、計2,280回の更新を行った。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB、GeForce RTX 3060 Ti）で、2026年9月26日に実施した。
PyTorchは2.13.0+cu130である。
入力の検査を含む学習全体は29秒で終わった。

選択BCEが最小のエポックは、Aが39、Bが40であった。
Bは40エポック目まで選択BCEが下がり続けており、収束には達していない。
モデル選択集合の半数は探索局面なので、Bの選択BCEがAより低いことは分布の一致による部分を含み、棋力の根拠にはしない。

選んだ重みのSHA-256は、Aが `322596b2…`、Bが `4d995d74…` である。

## 結論

AとBは同じ組、同じ更新回数、同じ設定で学習を終え、[採否前の診断](search-aware-pst-diagnostics.md)へ進めた。

# 深い教師の校正（探索局面の学習計画）

## 目的

[探索局面を用いた評価関数の学習](../plans/search-aware-evaluation.md)のフェーズ2として、校正用64根で教師の判定に使う差mを固定し、学習ラベルの生成費用を実測する。

## コマンドライン

```console
target/release/eval_teacher prepare --out-dir data/search-aware-evaluation --s0-commit 5563d7526f6d727f195603aadf96147607209a2b
target/release/eval_teacher select --out-dir data/search-aware-evaluation
target/release/eval_teacher evaluate --out-dir data/search-aware-evaluation --set calibration --jobs 16
```

コマンドはブランチ `search-aware-evaluation` の `1dc5fd1` でビルドした `eval_teacher`（SHA-256 `2c924172…`）で実行した。

## エンジン

基点S0と教師は、ともにmaster `5563d75` の探索と埋め込みPST（SHA-256 `72d7aee9…`）である。
規則は `L0,P0,R1,E0`、各探索は1スレッド、探索ごとに新しい64 MiBの置換表、ノード上限だけの制限とした。
提案手の探索は100,000ノード、教師は1,000,000ノードと10,000,000ノードである。
旧候補の手は、全資料で保存着手を使った。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）で、2026年9月26日に実施した。
根の評価は16並列で行い、他の負荷はない。

## 結果

抽出シード20260926で、校正64根を旧NNUEの `nnue-gen1-nodes100k` と旧FMの `fm-quarter-vs-original-stc` から32根ずつ抽出した。
抽出は、確認用128根と合わせて22秒で終わり、再生できずに除外した局はなかった。
根の手数の中央値は221（最小26、最大593）である。

候補集合は根あたり平均2.66手であった。
教師の完了深さの中央値は、1,000,000ノードで9、10,000,000ノードで12である。
子探索340件の応答は、通常評価が332件、詰みを示す値が8件であり、終局と未完了はなかった。
10,000,000ノードの教師の最善手は、64根のうち22根でS0の提案手a0と一致し、13根で旧候補の保存着手acと一致した。

| 量 | 値 |
|---|---:|
| 通常評価で比較できた根 | 62 |
| \(\lvert D_{10M}-D_{1M}\rvert\) の90パーセンタイル | 142.1センチポーン |
| 歩兵価値Pの1/4 | 25センチポーン |
| 判定に使う差m | 142.1センチポーン |

mは90パーセンタイルで決まり、歩兵価値の約1.4倍である。

費用は、根あたりの教師探索が平均40,218,750ノード（最大55,000,000）、探索時間の平均20.7秒（最大33.5秒）であった。
16並列での実行は97秒で終わった。
平均から求めた並列時の探索速度は1スレッドあたり約194万ノード毎秒であり、10,000,000ノードの教師1回は約5.2秒になる。

学習ラベルの生成費用は、この実測から次のように見積もる。
設計書の約10万局面を10,000,000ノードで評価すると、単一スレッドで約144時間、16並列で約9時間になる。
自己対局による原棋譜の収集（約5,000局）は設計書の概算どおり約3時間とし、フェーズ3の校正標本で実測に置き換える。
棋力測定の3組（B対A、A対S0、B対S0）は、[段階8の実績](../plans/strength-stage12.md#測定の所要時間)からそれぞれSTCで約1〜2時間、LTCで約6時間と見積もり、効果が小さい場合は各LTCが30時間を超え得る。

## 結論

校正で比較できた根は62であり、下限の32を満たした。
判定に使う差mを142.1センチポーンに固定し、確認集合（[search-aware-teacher-confirmation](search-aware-teacher-confirmation.md)）の判定に用いる。

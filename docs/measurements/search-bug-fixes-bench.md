# search-bug-fixes-bench

## 目的

[探索部の不具合修正](../plans/search-bug-fixes.md)の各フェーズの完了時に、固定局面の探索ベンチ`bench`の深さ9の総ノード数を記録し、フェーズ3の逃げる手の上限`K`を事前の規則で選ぶ。
3件の修正はいずれも探索の挙動を変えるので、総ノード数の不変は採否の条件ではない。
採否は非劣性の自己対局測定で判定する。

## コマンドライン

```console
nice -n 19 cargo build -j 2 --release --bin bench
nice -n 19 ./target/release/bench --depth 9
```

## エンジン

各フェーズの完了時点のブランチ`search-bug-fixes`の作業ツリーで測定した。
基準は監査の基準コミット`b59e616`、フェーズ1は`24c0801`、フェーズ2は`602f7e1`、フェーズ3は`45f43f2`である。
探索は既定の1ワーカー、`bench`の既定の置換表容量である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）である。
測定時にはHaChuとの時間制御の測定（同時対局数19）が動いていたので、ビルドと実行は優先度19、ビルドの並列度2に制限した。
総ノード数は負荷に依存しないが、経過時間とNPSは負荷の影響を受けるので、本記録では比較に使わない。
NPSは後述のとおり、他の測定がない状態でPコアに固定して測り直した。

## 結果

| 時点 | 深さ9の総ノード数 | 直前の時点との差 |
|---|---:|---:|
| 基準（`b59e616`） | 16,519,597 | |
| フェーズ1（null moveをまたぐ反復の修正） | 15,195,794 | −8.0% |
| フェーズ2（delta pruningの成り益の修正） | 15,721,681 | +3.5% |
| フェーズ3（静止探索の逃げる手、`K`=3） | 28,820,000 | +83.3% |

フェーズ3の上限`K`は、候補1、2、3で定数だけを変えて測った。

| `K` | 深さ9の総ノード数 | `K`=1に対する倍率 |
|---|---:|---:|
| 1 | 28,196,260 | 1.000 |
| 2 | 28,791,857 | 1.021 |
| 3 | 28,820,000 | 1.022 |

事前の規則は「`K`=1の総ノード数の1.1倍（31,015,886）以下に収まる候補のうち最大の値」であり、3候補とも条件を満たすので`K`=3を選んだ。

`K`=3の版で、静止探索の入口に一時的な計数を置いて数えると、静止探索ノード24,971,212のうち11,253,952（45.1%）は、経路上で捕獲以外の逃げる手を既に指しているため置換表を照会も格納もしなかった。
この計数は静的評価で打ち切る呼び出しも含む。
置換表の制限がノード数の増加の原因かを確かめるため、`K`=3のまま全静止探索ノードで置換表を使う版（経路に依存する値を共有するので採用しない診断用の版）を測ると、総ノード数は29,995,176であり、制限した版より多かった。
したがって、フェーズ3の増加は置換表の制限ではなく、王駒がすべて狙われたノードで全合法手を読むこと自体による。

HaChuとの測定の終了後、他の測定がない状態で、基準とフェーズ3のNPSをPコア1個（CPU 3）に固定して測った。
lishogiのBotとして動くminaseが約3.7コアを使っていたが、両者に同じ条件である。
各版とも`--repetitions 3`の中央値を2回ずつ測り、値はそれぞれ0.1%以内で一致した。

```console
taskset -c 3 ./target/release/bench --depth 9 --repetitions 3
```

| 版 | 総ノード数 | 経過時間の中央値 | NPS |
|---|---:|---:|---:|
| 基準（`b59e616`） | 16,519,597 | 7.851秒 | 2,104,155 |
| フェーズ3（`45f43f2`） | 28,820,000 | 10.942秒 | 2,633,907 |

フェーズ3ではNPSが25%上がった一方、深さ9までの時間は39%延びた。
逃げる手を読むノードでは着手の適用を多数数える一方で、各子局面の多くが静止探索の浅い打ち切りで終わるため、1ノードあたりの費用が平均より小さい。

## 結論

フェーズ1と2はノード数を合計で4.8%減らし、フェーズ3は全合法手を読む分だけ深さ9のノード数を83%、所要時間を39%増やした。
`K`は事前の規則により3とした。
この増加が時間制御の対局で棋力を下げるかどうかは、非劣性の自己対局測定で判定する。

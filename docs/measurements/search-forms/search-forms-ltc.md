# 探索の関数形の7本を終えた版と統括計画の前のmasterのLTC

## 目的

[探索の関数形の見直しの統括計画](../../plans/search-forms.md)のフェーズ10として、7本のサブタスクを終えた版が、統括計画を始める前のmasterより長時間条件（60秒＋1手0.2秒）で強いかを、逐次検定GSPRTで判定する。

## コマンドライン

2026年10月23日の利用者の指示により、vast.aiで借りる計算機ではなく、手元の測定機で実行した。
runnerは、masterのコミット`0c419a2f`から作ったworktreeでビルドしたminase（版2.4.0、SHA-256`30eebeda…`）である。

```console
data/worktrees/search-forms-phase10/target/release/minase match run \
  --run-dir /home/stepney141/board-games/minase/data/matches/search-forms-ltc --seed 6000000000 \
  --candidate commit:09315663 --baseline commit:99ccc6bb \
  --concurrency 12 \
  --each time=60000+200 gsprt
```

シードの6,000,000,000は、保存済みの測定と各サブタスクの設計書が予約した範囲（3,200,000,000〜5,350,000,000）から、ペア数の上限の100,000以上離れている。

## エンジン

候補は、[サブタスク7](../../plans/archived/time-instability-scaling.md)を採用して7本のサブタスクをすべて終えた版`093156636262ac4798409df51180a417c0736808`（バイナリのSHA-256`43cd5510…`）である。
フェーズ10を始めた時点のmasterの先頭`0c419a2f`は、候補との差が`docs/guides/spsa.md`だけであり、エンジンの実行ファイルは同じである。
基準は、統括計画を始める前のmaster`99ccc6bbeff0360fe48598de54d96b1d4e64621a`（バイナリのSHA-256`336cf2c8…`）である。
規則は`engine-default`（`L0,P0,R1,E0`）である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）である。
両エンジンの`Threads`は1、`USI_Hash`は既定の256 MB、同時対局数は12である。
同じ機械でlishogiのBotが1局あたり4スレッドで最大2局を指しており、測定の開始の直前と途中で2局を同時に指していた。
同時対局数を上限の16ではなく12にしたのは、Botの最大8スレッドと合わせて物理20コアに収めるためである。
対局の開始の約13分後からは、利用者の別の作業（約10コアを使う計算）も同じ機械で動き、判定までの約52分のうち約40分は物理コア数を超える負荷がかかっていた。
この負荷は候補と基準の両方に及ぶ。
GSPRTの仮説は既定のelo0 = 0、elo1 = 10、α = β = 0.05である。

## 結果

| 量 | 値 |
|---|---:|
| 判定 | `H1` |
| ペア | 104（有効104、手数上限到達による破棄0） |
| ペンタノミアル度数 | [0, 0, 8, 7, 89] |
| LLR | +2.950 |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 3,124.2秒（`summary.json`の`active_wall_time_ns`） |

有効104ペアの度数から求めた候補の平均得点は0.945（Eloに直すと約+493）であり、正規化したペア得点の分散による95%信頼区間はおよそ+418〜+617である。
候補が負け越したペアは1つもなく、89ペアで2局とも勝った。
終局の内訳は、詰み201局と反復による引き分け7局だった。
1局あたりの最大常駐メモリは、候補が約484 MiB、基準が約298 MiBだった。
`pairs/`には、104より大きい番号のペアも含めて計108ペアが保存されている。runnerは終局したペアを番号の順に逐次検定へ取り込むので、統計に入ったのは判定までの1〜104番のペアだけである。

## 結論

7本のサブタスクを終えた版は、統括計画を始める前のmasterに対して、測定機のLTCで`H1`となった（LLR +2.950、約+493 Elo）。
時間切れとエンジン異常は0件だった。
各サブタスクは[採用の例外のADR](../../adr/adopt-search-form-subtasks-regardless-of-stc-and-check-the-whole-chain-by-ltc-on-the-measurement-machine.md)によりSTCの結果によらず採用しており、この判定により、7本を通して元のmasterより強くなったことが確かめられた。
サブタスクごとの寄与はこの測定からは分からず、サブタスク1のSTCが`H0`（約−17 Elo、[記録](../search-pruning-forms/search-pruning-forms-stc.md)）だったことの原因も、この測定は扱わない。

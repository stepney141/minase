# 反復負け回避と反復禁止のLTC

## 目的

[探索部の反復負け回避と反復禁止](../plans/search-repetition.md)の候補（根の反復負け回避、探索木の中の反復の勝敗、および探索木の中の反復禁止）を段階開始版と長時間条件で比べ、採否を決める。

## コマンドライン

```console
target/release/minase match run \
  --run-dir data/matches/search-repetition-ltc --seed 2500100000 \
  --candidate commit:bb9d412 --baseline commit:88655aa \
  --concurrency 16 --each time=60000+200 gsprt
```

runnerはブランチ`search-repetition`の作業ツリー（コミットdcd32b5、エンジンの版2.4.0）でビルドしたものを使った。
シードは[STC](search-repetition-stc.md)の基本シード2500000000から100,000離した値である。

## エンジン

| 役割 | コミット | 内容 |
|---|---|---|
| 候補 | bb9d412 | 根の反復負け回避、探索木の中のR1の攻撃側の勝敗、R2とR3の禁止手の処理 |
| 基準 | 88655aa | 段階開始版（着手時のmasterの先頭） |

規則セットはL0、P0、R1、E0である。両エンジンのバイナリのSHA-256は実行ディレクトリの`manifest.json`にある。

## 環境

| 項目 | 値 |
|---|---|
| CPU | Intel Core Ultra 7 265KF（物理20コア、論理20コア） |
| 実メモリ | 32 GB |
| ワーカー数 | 候補1、基準1 |
| `USI_Hash` | 候補256 MB、基準256 MB |
| 同時対局数 | 16 |
| 時間制御 | 持ち時間60秒、1手0.2秒加算（LTC） |

測定中に他の重い処理は走っていない。

## 結果

| 項目 | 値 |
|---|---|
| 実行ペア数と有効ペア数 | 380、377（手数上限による破棄3） |
| ペンタノミアル度数 | [58, 9, 190, 10, 110] |
| LLR | +2.974 |
| 判定 | `H1` |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0 |
| 時間切れ（`time_forfeits`） | 0 |
| 拒否着手（`rejected_moves`） | 0 |
| 経過時間 | 8,235秒（起動1回、`active_wall_time_ns`は8,214秒） |

反復による終局を[集計スクリプト](search-repetition-outcome-diag/count.py)で数えた結果は次のとおりである。

| 項目 | 局数 |
|---|---:|
| 対局（破棄した3ペアを含む） | 762 |
| 反復による負け | 277 |
| うち候補が負けた局 | 0 |
| うち基準が負けた局 | 277 |
| 反復による引き分け | 21 |

基準が反復で負けた277局のすべてで、基準が最後に出力した評価値は0であり、負けた側が4回目の出現を完成させた局は103局である。
反復負けの直前の形勢（最後の20手のうち最後の非0の評価値）は、負けた基準側の中央値が−406、−300以下の割合が58.3%であった。
候補は反復による負けが0局であり、設計書の見込み（すべての合法手が反復負けに直結した局を除いて0件）と一致する。
反復による引き分けは21局であり、STCの6局（586局中）より割合が高い。

## 結論

候補は長時間条件でも有意に強く（`H1`）、エンジン異常、時間切れ、および拒否着手が0件なので、項目1（根の反復負け回避）と項目2（探索木の中の反復の勝敗）を採用する。

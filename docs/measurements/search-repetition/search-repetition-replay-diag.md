# 記録局面での根の分類関数の照合と所要時間

## 目的

[探索部の反復負け回避と反復禁止](../../plans/archived/search-repetition.md)のフェーズ3として、保存済みの自己対局記録にある反復負け（RULES.md第31条R1）の局面で、根の合法手を分類する関数`Game::repetition_root_moves`が総当たりの参照実装と一致すること、負けた側が実際に指した手を反復負けに直結する手として検出すること、および全部の合法手が反復負けに直結する局の有無を確かめる。
あわせて、同じ局面で分類関数1回あたりの所要時間を測り、フェーズ2の完了条件（STCの1手あたりの思考時間の1%、約1ミリ秒以下）を判定する。

## コマンドライン

対局は行わず、`data/matches/movegen-speedup-2-stage7-9-ltc`（第2期高速化の最終LTC測定）の`pairs/*.json`を読み込んで入力データとした。
診断コードは一時的なものであり、リポジトリには[この記録のディレクトリ](search-repetition-replay-diag/)に控えだけを置いている。

所要時間の本計測は、コミット1c61291を`git archive`で別のディレクトリへ書き出し、`invariants`機能を有効にしないreleaseビルドのバイナリ（[timing_main.rs](search-repetition-replay-diag/timing_main.rs)）で行った。

```console
CARGO_BUILD_JOBS=2 nice -n 19 cargo build --release -p timing-bin
nice -n 19 ./target/release/timing-bin
```

同じコードを`crates/minase/tests/`の`#[ignore]`の統合テストとして`cargo test -p minase --release --test search_repetition_replay_diag -- --ignored --nocapture`で実行した計測の結果も参考として併記する。
テストではdev-dependenciesが`invariants`機能を有効にし、着手の適用と取り消しのたびに局面全体を検証するので、所要時間は通常ビルドの判定には使えない。

診断の手順は次のとおりである。
記録の`opening.moves`と各局の`turns`の着手を`Game::new(L0,P0,R1,E0)`へ順に`Game::play`で適用し、対局を最後まで再生したときの終局結果が記録の勝者および終局理由と一致することを確かめた。
負けた側の最後の着手の直前の対局の状態を根とし、分類関数の`winning`と`losing`を得た。
参照実装は、根の合法手のそれぞれを`Game`の写しへ`Game::play`で適用し、終局しなければ相手の合法手のそれぞれをさらに適用して、反復勝ちの手の集合と反復負けに直結する手の集合を作る総当たりであり、探索局面キーによる絞り込みを使わない。
所要時間は、各局面で分類関数の最初の呼び出しの所要時間と、続けて10回呼んだうちの最小の所要時間を`std::time::Instant`で測った。

## エンジン

対象の記録は候補コミット24ddf4f、基準コミットc6e2539の対局であり、規則セットはL0、P0、R1、E0である。
分類関数はコミット1c61291（ブランチ`search-repetition`。フェーズ1の分類関数とフェーズ2の根の選別を含む）のものである。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、実メモリ30 GBである。
計測中は別計画のNNUE教師生成（同時対局数18）が走っており、ロードアベレージは約27であった。
所要時間はこの負荷の下での値であり、負荷のない状態では短くなる。
再生と分類の照合は決定的であり、負荷に依存しない。

## 結果

対象は、終局理由が反復による負けの184局である。
対局の手数は中央値377手、最小33手、最大2,681手である。

| 項目 | 件数 |
|---|---:|
| 再生した終局結果が記録と一致しない局 | 0 |
| 分類関数と参照実装の`winning`または`losing`が（順序を含めて）一致しない局 | 0 |
| 負けた側の最後の着手が`losing`に含まれる局 | 184 |
| 全部の合法手が`losing`である局 | 0 |
| `winning`が空でない局 | 0 |
| 負けた側の最後の着手が4回目の出現を完成させた局 | 126 |
| 負けた側の最後の着手の後に相手の応手が4回目の出現を完成させた局 | 58 |

根における合法手の数は中央値78手（最小18手、最大144手）であり、`losing`の手数は1手が100局、2手が81局、3手が3局である。

所要時間は次のとおりである（単位はマイクロ秒）。

| 計測対象 | ビルド | 最小 | 中央値 | 90パーセンタイル | 最大 |
|---|---|---:|---:|---:|---:|
| 分類関数（最初の呼び出し） | release、`invariants`なし | 53 | 296 | | 1,080 |
| 分類関数（10回の最小値） | release、`invariants`なし | 47 | 277 | 534 | 758 |
| 参照実装（総当たり） | release、`invariants`なし | 1,537 | 59,859 | | 3,108,272 |
| 分類関数（最初の呼び出し） | releaseテスト、`invariants`あり | 347 | 4,882 | | 292,331 |
| 分類関数（10回の最小値） | releaseテスト、`invariants`あり | 317 | 4,306 | | 158,758 |

最初の呼び出しが1,000マイクロ秒を超えた局面は、`invariants`なしでは1局（1,080マイクロ秒）だけであり、同じ局面の10回の最小値は678マイクロ秒であった。
局面ごとの値は[results-release.json](search-repetition-replay-diag/results-release.json)と[results-invariants.json](search-repetition-replay-diag/results-invariants.json)にある。

## 結論

分類関数は184局のすべてで参照実装と一致し、負けた側が実際に指した手を漏れなく反復負けに直結する手として検出したので、フェーズ3の完了条件を満たす。
全部の合法手が反復負けに直結する局はなく、これら184局の反復負けはいずれも根の選別によって回避できた。
通常ビルド相当の所要時間は、負荷のある測定機でも1局面あたり最大0.76ミリ秒（10回の最小値）であり、フェーズ2の完了条件である約1ミリ秒以下を満たす。

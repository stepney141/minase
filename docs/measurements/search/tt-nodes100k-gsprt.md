# 置換表の採否GSPRT（nodes=100000）

## 目的

置換表を導入したコミットと直前コミットを同一ノード数の対等条件で対戦させ、置換表がノード効率の改善として棋力を有意に高めるかを判定する。

## コマンドライン

```console
match_runner --seed 20260812 --candidate commit:090839d --baseline commit:48b89c0 --each nodes=100000 --concurrency 8 gsprt
```

## エンジン

候補はコミット090839d（置換表あり）、基準はコミット48b89c0（置換表なし）である。
規則セットは`commit:`指定の既定であるengine-defaultである。

## 環境

CPU型、物理コア数、論理コア数は記録なし。
ワーカー数は候補と基準とも1である（本マイルストーンは単一スレッド設計）。
`USI_Hash`は記録なし（設計上の既定値は256MB）。
同時対局数は8である。

## 結果

ペンタノミアル度数は[39, 1, 168, 10, 142]（有効360ペア）であった。
LLRは2.948で判定はH1（候補が有意に強い）である。
破棄ペア数は3、異常件数は0である。
`time_forfeits`は該当なし（ノード数固定）。
経過時間は1565秒である。
benchの総ノード数は、depth=3で241,231から217,305へ約10%減り（約235万NPS）、depth=4で2,574,220から1,708,418へ約34%減った。

## 結論

置換表を採用する。

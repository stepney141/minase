# 浅い前向き枝刈りの拡張の候補の時間切れの事前確認

## 目的

[浅い前向き枝刈りの深さと対象の拡張](../../plans/archived/shallow-pruning-extensions.md)のフェーズ2として、SPSAの本番の前に、時間管理の4係数を思考時間が最も長くなる側の範囲の端に置いても、換算した持ち時間で時間切れとエンジン異常が起きないことを確かめる。
棋力測定ではない。

## コマンドライン

パラメーターファイル`shallow-pruning-extensions-safety.params`は、本番の71係数のファイルの写しで、開始値を`HardRemainingShare` = 50、`HardSoftRatio` = 800、`MinMoves` = 40、および`IterationRatio` = 150へ書き換えたものである。`MinMoves`の既定値はもともと40なので、この係数の値は変わらない。
反復数156は、[統括計画](../../plans/search-forms.md)が定める`⌈13 × 同時対局数 ÷ 16⌉`（同時対局数191）である。
持ち時間は、測定機のSTC`time=10000+100`に、この調整機で測った換算係数1.57を掛けた値である。
換算係数は、測定機の負荷時の速度776,638 NPSを、調整機で191本を同時に走らせた負荷時の速度495,019 NPSで割った比を小数第2位に丸めた値である。
測定機の値は、調整用ビルドを16本同時に`minase dev bench --depth 9 --repetitions 3`で走らせた平均NPSを6回測った中央値であり、6回の値は682,642、763,165、776,058、777,217、812,801、および817,491 NPSだった。同じ機械でlishogiのBotが対局しており、その思考と重なった回が低く出ている。
コマンドは、調整機の`scripts/vast-spsa/remote.py`が起動した。

```console
minase spsa \
  --run-dir /workspace/job/shallow-pruning-extensions-safety --seed 3500000000 \
  --engine commit:364c10aa --params /workspace/job/safety.params \
  --rules engine-default --each time=15700+157 --concurrency 191 \
  --iterations 156 --pairs-per-iteration 8
```

## エンジン

調整対象は、形の変更の最後のコミット`364c10aac8b32a6fe3953e4a1be06e8db638ac79`の調整用ビルドであり、調整機でビルドした実行ファイルのSHA-256は`ee844733…`である。
runnerは同じコミットの通常ビルド（版2.4.0、SHA-256`d70c957a…`）である。
調整機では、測定機で作った`git bundle`からブランチを取り込み、`cargo build --release --locked --bin minase`でrunnerを、`minase spsa params --engine commit:364c10aa --rules engine-default`で調整用ビルドを作った。
このコマンドが出力した既定のパラメーターファイルから`FmScale`の行を除いたものは、測定機で作った71係数のファイルと一致した。
規則は`engine-default`（`L0,P0,R1,E0`）、置換表は既定の256 MB、探索のワーカーは1である。

## 環境

調整機は、vast.aiのインスタンス56567047（出品28164421、AMD EPYC 9654の2基構成、物理192コア、論理384スレッド（runnerが記録した論理CPUは368）、メモリ約629 GiB、スペイン、1時間2.00米ドル）である。
同時対局数は、物理コア数から1を引いた191であり、メモリによる制限（調整機の実メモリを、1局あたりの最大常駐メモリ約606 MBの1.25倍で割った数）は受けなかった。
1局あたりの最大常駐メモリは、測定機で調整用ビルド同士の1ペアをSTCで指し、2局のそれぞれで候補と基準の最大常駐メモリを足し、大きい方の値（605,585,408バイト）とした。

## 結果

156反復をすべて適用し、1,248ペアのうち有効ペアは1,240、手数上限で破棄したペアは8だった。
異常件数は、不正着手、クラッシュ、応答タイムアウト、時間切れ（`time_forfeits`）、および拒否着手のいずれも0だった。
所要時間は1,721秒だった。

## 結論

時間管理の4係数を思考時間が最も長くなる側の範囲の端に置いても、換算した持ち時間で時間切れとエンジン異常は起きなかったので、本番のSPSAへ進む。

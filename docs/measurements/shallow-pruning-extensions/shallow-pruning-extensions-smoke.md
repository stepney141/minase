# 浅い前向き枝刈りの拡張の候補の事前対局

## 目的

[浅い前向き枝刈りの深さと対象の拡張](../../plans/shallow-pruning-extensions.md)のフェーズ4として、[SPSA](shallow-pruning-extensions.md)の最終値を反映した候補と起点を、STCの条件で32ペア対局させる。
時間切れとエンジン異常が出ないことを確かめ、時間の使い方の変化を記録する。
採否には使わない。

## コマンドライン

[統括計画](../../plans/search-forms.md)の決定により、SPSAを終えた調整機で、持ち時間を換算せずに実行した。
候補のコミットは、測定機で作った`git bundle`で調整機のcloneへ取り込んだ。

```console
target/release/minase match run \
  --run-dir /workspace/job/matches/shallow-pruning-extensions-smoke --seed 3600000000 \
  --candidate commit:29443569e7328386f6858c0695232792934cef2e \
  --baseline commit:a892a5e66106e756dd94df862aa0a2de3779f326 \
  --each time=10000+100 --concurrency 191 elo --pairs 32
data/spsa/shallow-pruning-extensions-runner/minase match report \
  --run-dir data/matches/shallow-pruning-extensions-smoke
```

実行ディレクトリは、終了後に測定機の`data/matches/shallow-pruning-extensions-smoke`へ取得し、集計は測定機で行った。

## エンジン

候補は、SPSAの最終値を係数の表の既定値へ書き込んだ`29443569e7328386f6858c0695232792934cef2e`であり、調整機でビルドしたバイナリのSHA-256は`336555125d0f28fded37615747361b4a7a7c92ede4951dec84aa3bc81a6a0973`である。
候補の後に、既定値に依存していたテストを直したコミットがあるが、テストだけの変更なのでエンジンのバイナリは変わらない。
起点は`a892a5e66106e756dd94df862aa0a2de3779f326`であり、SHA-256は`6b3114774f3bf666ab4843d56c0bd9ab505609a8092ad017206d3ddd993ab20b`である。
runnerは、調整機で`364c10aa`をビルドした通常のminase（2.4.0）であり、SHA-256は`d70c957afebd29773a32c23fb1849fdd1f7ab484bc0a94e04bed2c8f7dd4e3f0`である。SPSAのセッションと同じ実行ファイルである。
規則セットは`engine-default`（`L0,P0,R1,E0`）である。

## 環境

調整機は、SPSAと同じvast.aiのAMD EPYC 9654の2基構成（インスタンス56567047、物理192コア、論理384スレッド、runnerが記録した論理CPUは368）である。
この機械の1コアは測定機（Intel Core Ultra 7 265KF）より遅く、負荷時の速度の比`f`は1.57である（[事前確認の記録](shallow-pruning-extensions-safety.md)）。持ち時間は換算していないので、1手の探索量は測定機の同じ条件より少ない。
候補と起点はいずれも`Threads=1`、`USI_Hash`は各256 MB、同時対局数は191である。
手数上限は4,096手、応答タイムアウトは120秒である。
2026年10月19日8時46分から8時55分に実施した。

## 結果

| 量 | 値 |
|---|---:|
| 有効ペア | 31（手数上限による破棄1） |
| ペンタノミアル度数 | [4, 0, 16, 1, 10] |
| 正規化した平均得点 | 0.605 |
| Elo | +73.9 |
| 95%信頼区間 | [−6.0, +162.6] |
| エンジン異常 | 不正着手0、クラッシュ0、応答タイムアウト0、時間切れ0、拒否着手0 |
| 経過時間 | 524.7秒（`summary.json`の累計） |
| 1局の最大常駐メモリ | 626,974,720バイト |

値は`minase match report`が保存記録から再計算した集計による。
32ペアの固定局数Eloは信頼区間の幅が約170 Eloあり、強さの判定には使わない。
破棄した1ペア（ペア18）は、1局目を起点が詰みで勝ち、2局目が4,086手で手数上限に達した。

時間の使い方は次のとおりである。
総思考時間と終局時の残り時間は、`pairs/`に保存された各手の思考時間から計算した。終局時の残り時間は、持ち時間に1手の加算を着手数だけ足し、思考時間の合計を引いた値である。
この集計と下の手数帯ごとの集計は、破棄したペアの2局を含む64局によるものである。

| 量 | 候補 | 起点 |
|---|---:|---:|
| 総思考時間 | 2,098.9秒 | 2,082.8秒 |
| 着手数 | 15,928 | 15,921 |
| 1手の平均思考時間 | 131.8 ms | 130.8 ms |
| 終局時の残り時間の中央値 | 1,739 ms | 1,688 ms |

候補と起点の総思考時間の比は1.008である。

手数帯ごとの完了深さ（反復深化で読み終えた深さの平均）と思考時間の中央値は、`scripts/clock_profile.py`を`--role candidate`と`--role baseline`で別々に実行して集計した。

| 手数帯 | 候補の完了深さ | 起点の完了深さ | 候補の思考時間の中央値 | 起点の思考時間の中央値 |
|---|---:|---:|---:|---:|
| 0〜49 | 13.22 | 12.32 | 92 ms | 81 ms |
| 50〜99 | 12.93 | 11.57 | 102 ms | 92 ms |
| 100〜149 | 12.71 | 11.10 | 111 ms | 92 ms |
| 150〜199 | 12.21 | 10.59 | 122 ms | 102 ms |
| 200〜299 | 11.77 | 10.33 | 142 ms | 112 ms |
| 300〜399 | 11.97 | 10.72 | 142 ms | 131 ms |
| 400以降 | 12.32 | 13.56 | 92 ms | 82 ms |

探索を止めた理由の内訳は、候補では上限の時間による停止が28手（0.18%）、目安の時間による停止が15,900手、起点では上限の時間による停止が48手（0.30%）、目安の時間による停止が15,873手だった。
完了深さは全体の平均で候補12.31、起点11.62である。
`clock_profile.py`が出す時間予算の比と上限の超過量は、起点の係数の予算式に基づくので、候補の時間の使い方の解釈には使わない。

## 結論

候補は、時間切れとエンジン異常を起こさなかった。
総思考時間は起点とほぼ同じで、終局時の残り時間も近い。
設計書の手順どおり、同じ調整機でSTCへ進む。

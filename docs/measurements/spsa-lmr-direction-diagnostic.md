# SPSAの向きの診断（LMRの除数）

## 目的

`spsa_runner` が実エンジンの対局結果から係数を妥当な向きへ動かすかを、LMRの除数だけを対象にして開始値を範囲の上端の400に置いた短いセッションで観察する。
[SPSAの設計書](../plans/spsa.md)の「検証」が定める診断であり、合否の条件ではない。

## コマンドライン

```console
spsa_runner --run-dir data/spsa/lmr-direction-diagnostic --seed 5000000 \
  --engine commit:175b97d --params params-lmr.txt \
  --rules engine-default --each time=10000+100 --concurrency 16 \
  --iterations 40 --pairs-per-iteration 8
```

パラメーターファイルは次の1行である。

```text
LmrDivisor, 400, 100, 400, 15, 0.002
```

## エンジン

θ+とθ−はどちらも、コミット`175b97deece2e75302bdca9a3bf91cedd749121b`の調整用ビルド（SHA-256は`6cf259dada4f988230292ee3c0dd3279b96805d629e19d768d1d2045fd54832b`）である。
runnerはコミット`3f0e2195b311e1043271464b03bb0a811d0095a4`のビルド（SHA-256は`46f134ae952cb3525a2a5b2e09df706ae3e8b578d43271c32c89df1326e02d96`）である。
規則セットは`engine-default`（L0、P0、R1、E0）である。
LMRの除数を除く係数は既定値のままである。

## 環境

CPUはIntel Core Ultra 7 265KFであり、物理コア数と論理コア数はいずれも20である。
両エンジンは`Threads=1`、`USI_Hash`は既定の256 MB、同時対局数は16、時間制御はSTC（`time=10000+100`）である。
測定中は、lishogiのBot（4スレッド）が同じ測定機で対局していた。

## 結果

開始値が範囲の上端にあるので、全反復で一方の設定は除数400に切り詰められ、他方は約375（400から摂動幅を引いた値）になった。
40反復の320ペアのうち有効ペアは303、手数上限への到達による破棄は17であった。
θ+側のペンタノミアル度数は[51, 8, 169, 13, 62]であった。
除数の小さい側から見た勝ち数と負け数の差は、有効な606局の合計で+25であった。
θは400.000から398.325へ動き、適用番号10、20、30の時点ではそれぞれ399.135、398.615、398.322であった。
同時対局数16のもとで、40反復のうち38反復は反復番号と適用番号が一致せず、非同期の適用が実際に働いた。
エンジン異常、不正着手、応答タイムアウト、`time_forfeits`、および拒否着手はいずれも0件であった。
経過時間は3,219.9秒であった。

## 結論

θは現行値の200がある向きへ動いたが、勝ち数の差+25は606局に対して小さく、この規模では向きの正しさの統計的な証拠にはならないので、対局の進行、非同期の適用、および保存が実エンジンで動作することの確認として記録する。

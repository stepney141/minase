# 段階的 MovePicker の長時間 GSPRT

## 目的

段階的 MovePicker を実装した候補と直前の基準を比較し、この変更を採用するかを長時間 GSPRT で判定する。

## コマンドライン

次のコマンドを実行した。

```sh
cargo run --release --bin match_runner -- \
  --run-dir data/matches/strength-stage1-staged-picker-ltc \
  --seed 2026100000 \
  --candidate commit:9c5c898 \
  --baseline commit:014fc4b \
  --each time=60000+600 \
  gsprt
```

## エンジン

候補はコミット `9c5c8985427bd7cc1510bbee56fa56c4df69d2fd`、基準はコミット `014fc4b17d20d448a4fe9a57b2e36c684b9412b2` である。
候補は通常探索の指し手を、置換表手、捕獲手、2 個の killer 手、および静かな手の順に生成して選ぶ。
規則セットは標準規則 `L0,P0,R1,E0` である。

## 環境

CPU は Intel Core Ultra 7 265KF であり、物理コア数と論理 CPU 数はいずれも 20 である。
候補と基準のワーカー数は各 1、`USI_Hash` は各 256 MB、同時対局数は 19 である。
時間制御は両エンジンとも初期時間 60,000 ms、1 手 600 ms 加算である。

## 結果

388 ペアを実行し、383 ペアを有効、5 ペアを最大 4,096 手到達により破棄した。
ペンタノミアル度数は `[42, 8, 176, 11, 146]`、LLR は 2.9564842554、判定は `H1` であった。
候補の得点率は 63.77% であった。
不正着手、クラッシュ、応答タイムアウト、時間切れ、および拒否着手はすべて 0 件であった。
累計実行時間は 17,240.364720661 秒であった。

## 結論

長時間 GSPRT が `H1` かつ異常 0 件で終了したため、段階的 MovePicker を採用する。

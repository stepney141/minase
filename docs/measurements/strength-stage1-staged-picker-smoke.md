# 段階的 MovePicker の時間制御煙試験

## 目的

段階的 MovePicker の採否測定前に、時間制御の対局がエンジン異常なく完了することを 2 ペアで確認する。

## コマンドライン

次のコマンドを実行した。

```sh
cargo run --release --bin match_runner -- \
  --run-dir data/matches/strength-stage1-staged-picker-smoke \
  --seed 2026090101 \
  --candidate commit:9c5c898 \
  --baseline commit:014fc4b \
  --each time=10000+100 \
  --concurrency 2 \
  elo --pairs 2
```

## エンジン

候補はコミット `9c5c8985427bd7cc1510bbee56fa56c4df69d2fd`、基準はコミット `014fc4b17d20d448a4fe9a57b2e36c684b9412b2` である。
規則セットは標準規則 `L0,P0,R1,E0` である。

## 環境

CPU は Intel Core Ultra 7 265KF であり、物理コア数と論理 CPU 数はいずれも 20 である。
候補と基準のワーカー数は各 1、`USI_Hash` は各 256 MB、同時対局数は 2 である。
時間制御は両エンジンとも初期時間 10,000 ms、1 手 100 ms 加算である。

## 結果

2 ペアを実行し、2 ペアを有効、0 ペアを破棄した。
ペンタノミアル度数は `[0, 0, 2, 0, 0]` であり、候補の得点率と Elo 点推定はいずれも 50% と 0 Elo であった。
全ペアの得点が同じで分散が 0 のため、95% 信頼区間は算出できなかった。
不正着手、クラッシュ、応答タイムアウト、時間切れ、および拒否着手はすべて 0 件であった。
累計実行時間は 171.550600326 秒であった。

## 結論

時間制御の 4 局が異常なく完了したため、本測定を採否根拠には用いず、短時間 GSPRT を開始する事前条件を満たしたと判断した。

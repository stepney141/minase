# 段階的な手選択の短時間GSPRT

## 目的

段階的な手選択を実装した候補と直前の基準を比較し、長時間GSPRTへ進めるかを短時間GSPRTで判定する。

## コマンドライン

次のコマンドを実行した。

```sh
cargo run --release --bin match_runner -- \
  --run-dir data/matches/strength-stage1-staged-picker-stc \
  --seed 2026091000 \
  --candidate commit:9c5c898 \
  --baseline commit:014fc4b \
  --each time=10000+100 \
  gsprt --max-pairs 3000
```

## エンジン

候補はコミット `9c5c8985427bd7cc1510bbee56fa56c4df69d2fd`、基準はコミット `014fc4b17d20d448a4fe9a57b2e36c684b9412b2` である。
候補は通常探索の指し手を、置換表手、捕獲手、2 個の killer 手、および静かな手の順に生成して選ぶ。
規則セットは標準規則 `L0,P0,R1,E0` である。

## 環境

CPU は Intel Core Ultra 7 265KF であり、物理コア数と論理 CPU 数はいずれも 20 である。
候補と基準のワーカー数は各 1、`USI_Hash` は各 256 MB、同時対局数は 19 である。
時間制御は両エンジンとも初期時間 10,000 ms、1 手 100 ms 加算である。

## 結果

514 ペアを実行し、506 ペアを有効、8 ペアを最大 4,096 手到達により破棄した。
ペンタノミアル度数は `[67, 12, 248, 10, 169]`、LLR は 2.9578734712、判定は `H1` であった。
候補の得点率は 58.40% であった。
不正着手、クラッシュ、応答タイムアウト、`time_forfeits`、および拒否着手はすべて0件であった。
累計実行時間は 3,774.824061102 秒であった。

## 結論

短時間GSPRTが`H1`かつ異常0件で終了したため、段階的な手選択を長時間GSPRTへ進める。

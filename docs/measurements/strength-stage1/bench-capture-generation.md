# 捕獲専用手生成のbench速度比較

## 目的

捕獲専用手生成を静止探索へ適用した変更について、探索結果を維持したまま速度基準を満たすかを判定する。

## コマンドライン

基準と候補の各コミットで、次のコマンドを1回ずつ実行した。

```sh
cargo run --release --bin bench -- --repetitions 3
```

## エンジン

基準はコミット`afeecec344e3468ad300baa8435a52f3502690f2`、候補はコミット`9086e94bdff3218fdc2cc371a747b59f4469f489`である。
候補は、静止探索の手生成を全合法手生成後の捕獲判定から捕獲専用生成へ変更した。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KFであり、物理コア数と論理CPU数はいずれも20である。
rustcとCargoはいずれも1.98.0であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

depth=3の総ノード数は、基準と候補の両方で569,697であった。
基準の中央値は0.347281秒、1,640,451 NPSであり、候補の中央値は0.205380秒、2,773,864 NPSであった。
候補の中央値は基準より69.09%高く、採用基準の3%を上回った。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

探索ノード数が不変で速度が69.09%向上したため、捕獲専用手生成を採用する。

# strength-stage12-capture-history-bench

## 目的

[棋力向上段階12](../plans/strength-stage12.md)の項目3（捕獲履歴）の実装について、段階開始版とbench深さ6の総ノード数と毎秒探索ノード数（NPS）を比べて記録する。
設計書のとおり、総ノード数の不変は採否の条件にしない。

## コマンドライン

候補と段階開始版を別々のターゲットディレクトリでリリースビルドし、同じ条件で測った。

```console
cargo build --release --bin bench
taskset -c 3 target/release/bench --depth 6 --repetitions 3
```

## エンジン

候補はコミット`1ca19fc`（捕獲履歴の実装）、基準は段階開始版のコミット`df0c75e`である。
benchの規則は既定の`engine-default`（`L0,P0,R1,E0`）、探索ワーカーは1、置換表は256 MBである。
候補が加えた係数は、捕獲履歴の上限`CaptureHistoryLimit`（初期値20,755、範囲1〜32,767）と、捕獲履歴の寄与の尺度`CaptureHistoryScale`（歩兵の駒価値に対する百分率、初期値100、範囲0〜400）である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月27日に対局の測定が走っていないことを確かめてから、CPU 3に固定して測った。
経過時間は3回の中央値である。

## 結果

| 版 | 総ノード数 | 探索時間 | NPS |
|---|---:|---:|---:|
| 段階開始版 `df0c75e` | 1,677,944 | 0.847秒 | 1,980,408 |
| 候補 `1ca19fc` | 1,603,942 | 0.826秒 | 1,942,255 |

候補の総ノード数は段階開始版より4.41%少なく、NPSは1.93%低い。
探索時間は2.5%短い。

## 結論

捕獲履歴は同じ深さの探索木を4.41%小さくし、表の参照によるNPSの低下1.93%を上回るので、固定深さでは探索時間が短くなる。
採否はSTCとLTCの自己対局で判定する。

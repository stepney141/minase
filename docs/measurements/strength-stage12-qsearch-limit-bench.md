# strength-stage12-qsearch-limit-bench

## 目的

[棋力向上段階12](../plans/strength-stage12.md)の項目4（静止探索の手数制限、`N=1`）の実装について、例外ごとの適用件数と、段階開始版とのbench深さ6の総ノード数と毎秒探索ノード数（NPS）を記録する。
設計書のとおり、総ノード数の不変は採否の条件にしない。

## コマンドライン

例外の件数は、実装直後に一時的な計数を入れたビルドでbench深さ6を1回実行して数え、計数コードを外してから速度を測った。
候補と段階開始版は別々のターゲットディレクトリでリリースビルドし、同じ条件で測った。

```console
cargo build --release --bin bench
taskset -c 3 target/release/bench --depth 6 --repetitions 3
```

## エンジン

候補はコミット`a3845f2`（静止探索の手数制限の実装）、基準は段階開始版のコミット`df0c75e`である。
benchの規則は既定の`engine-default`（`L0,P0,R1,E0`）、探索ワーカーは1、置換表は256 MBである。
候補が加えた係数は、静止探索で例外を除いて読む捕獲手の上限`QsearchMoveLimit`（初期値1、範囲1〜16）である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア）、rustc 1.98.0であり、2026年9月27日に対局の測定が走っていないことを確かめてから、CPU 3に固定して測った。
経過時間は3回の中央値である。

## 結果

### 例外の適用件数

bench深さ6で、上限を超えた位置にあった捕獲手は175,459手であり、そのうち140,891手を読まなかった。
上限を超えても例外として読んだ手は、最後の王駒を取る手が0件、取り返しが24,247件、獅子の2枚取りが12,873件であり、取り返しと2枚取りの両方に当たる手が2,552件あった。
取り返しと2枚取りの例外は実際に働いており、最後の王駒を取る手の例外はこの局面集では働かなかった。

### bench

| 版 | 総ノード数 | 探索時間 | NPS |
|---|---:|---:|---:|
| 段階開始版 `df0c75e` | 1,677,944 | 0.841秒 | 1,995,087 |
| 候補 `a3845f2` | 1,325,021 | 0.707秒 | 1,873,888 |

候補の総ノード数は段階開始版より21.03%少なく、NPSは6.07%低く、探索時間は15.9%短い。
NPSが下がるのは、1ノードあたりの費用が小さい静止探索のノードが主に減り、残るノードの平均費用が上がるためである。

## 結論

静止探索の手数制限は同じ深さの探索木を21.03%小さくし、探索時間を15.9%短くする。
採否はSTCとLTCの自己対局で判定する。

# strength-stage2-iteration-stc

## 目的

棋力向上段階2の反復継続の判断（固定比2.5による次反復の完了予測）を、採用済みの予算式と標準STCのGSPRTで比較し、LTCへ進めるかを判定する。

## コマンドライン

```console
match_runner --run-dir data/matches/strength-stage2-iteration-stc --seed 20260913 \
  --candidate commit:62b5f04 --baseline commit:96aa2ef \
  --each time=10000+100 gsprt --max-pairs 3000
```

## エンジン

候補はコミット62b5f04、基準は予算式を採用したコミット96aa2ef、規則セットは`engine-default`である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）、候補と基準の`Threads`は1、`USI_Hash`は256MB、同時対局数は自動計算の19である。

## 結果

1,131ペアを実行し、有効ペア1,111、破棄ペア20（手数上限）であった。
ペンタノミアル度数は[189, 15, 605, 17, 285]、LLRは+2.958で`decision: H1`である。
不正着手、クラッシュ、応答タイムアウト、および拒否着手は0件、`time_forfeits`は1件、経過時間は8,306秒である。

時間切れはペア159第1局で、基準側（後手）が2,873plyの対局の2,864手目に起こした。
保存記録から再構成した当該手の残り時間は120msで、hard limitは残り時間の4分の1の30msだったが、思考時間は124msであった。
原因は、`position startpos moves ...`で全着手を再生する固定費が着手数に比例して増え、2,860手で約65ms（実測）に達したことである。
この固定費はハーネスの計時に含まれるため、残り時間が加算の近傍まで下がった超長手数の対局では、予算式の安全余裕30msを超える。
候補と基準の両方に同じ固定費があり、継続判断の変更が原因ではない。

## 結論

短時間GSPRTは`H1`で終了したが、時間切れ1件の原因が着手数に比例する`position`再生の固定費であると特定したため、候補をLTCへ進めるとともに、固定費を手数に依存しない大きさへ下げる差分適用を段階2の項目に加える。

# strength-stage3-qsearch-depth-bench

## 目的

棋力向上段階3の静止探索専用の深さ上限について、benchの静止探索の深さ分布を測り、設計書の事前基準（深さ8以上のノードが静止探索ノードの1%未満なら見送り）で要否を判定する。

## コマンドライン

```console
bench --depth 5
```

一時的なカウンタを入れた作業複製で実行し、計測コードは残していない。
静止探索へ入った手番からの深さ（通常探索の深さ0ノードを0とする）ごとに静止探索ノード数を数えた。

## エンジン

コミット1894d14（駒価値の再調整とSEEを含む）、規則セットは`engine-default`、`Threads`は1である。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）。
同時に駒価値の再調整のLTCが19並列で走っていたため、`nice -n 19`で1回だけ実行し、NPSは参考値としない。

## 結果

15局面の総ノード数は3,942,412、うち静止探索ノードは2,189,588である。

| 深さ | ノード数 | 割合 | 累積 |
|---|---|---|---|
| 0 | 1,490,468 | 68.07% | 68.07% |
| 1 | 275,974 | 12.60% | 80.67% |
| 2 | 154,999 | 7.08% | 87.75% |
| 3 | 107,358 | 4.90% | 92.66% |
| 4 | 61,415 | 2.80% | 95.46% |
| 5 | 41,352 | 1.89% | 97.35% |
| 6 | 22,365 | 1.02% | 98.37% |
| 7 | 17,777 | 0.81% | 99.18% |
| 8以上 | 17,880 | 0.82% | 100.00% |

最大深さは16である。

## 結論

深さ8以上のノードは静止探索ノードの0.82%で事前基準の1%を下回るため、静止探索専用の深さ上限は発動しない改良として見送り、実装しない。

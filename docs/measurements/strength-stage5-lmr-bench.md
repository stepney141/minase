# strength-stage5-lmr-bench

## 目的

棋力向上段階5のLMRの減深量について、設計書の「診断による係数の決定」節に従い、historyの最終構成（butterfly表だけ。piece-to history、counter move history、continuation history、malusはいずれも不採用または見送り）で係数`c`と閾値`H`を決める。

## コマンドライン

コミット7877531へ一時的な計測を入れた作業ツリーで、次のコマンドを実行した。

```sh
MINASE_LMR_DIAG=lmr-diag-d6.txt cargo run --release --bin bench -- --depth 6
python3 data/experiments/stage5-diag-tools/lmr_diag.py lmr-diag-d6.txt
```

## エンジン

基点はコミット7877531（順序付けキーの重複計算の除去を採用した構成）であり、計測コードはコミットしていない。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、benchは単一スレッドで実行した。
同じ機械でpiece-to historyのSTCが並行していたため、NPSは記録しない。
`USI_Hash`と同時対局数は該当しない。

## 結果

対象手は132,244手（残り深さ3が48,165手、深さ4が80,441手、深さ5が3,638手）、良い結果は434手（深さ順に251手、158手、25手）であった。
history値の分位点は75%点までが0、90%点が4、99%点が550であった。
現行の規則（`index ≥ 3`なら1）を同じ標本に適用すると、失う良い結果の割合は全体で35.5%（154/434）、深さ順に31.5%、41.1%、40.0%、減深量の平均は0.999であった。
適格な組は48組あり、減深量の平均が最大の組は`c = 2.00`、`H = 128`で、失う割合は全体で27.9%（121/434）、深さ順に19.5%、40.5%、32.0%、減深量の平均は1.557（深さ順に0.962、1.870、2.499）、発動率（現行と減深量が異なる対象手の割合）は60.3%であった。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

`c = 2.00`、`H = 128`を採用し、発動率が5%以上なので実装して採否測定へ進める。

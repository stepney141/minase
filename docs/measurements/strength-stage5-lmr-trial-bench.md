# strength-stage5-lmr-trial-bench

## 目的

棋力向上段階5のLMRの減深量について、「診断による係数の決定」節の計測コードと候補評価スクリプトが動くことを確かめ、選択規則が標本に対して縮退しないかを本診断の前に点検する。

## コマンドライン

piece-to historyの候補にmalusの下書きを適用した作業ツリーへ一時的な計測を入れ、次のコマンドを実行した。

```sh
MINASE_LMR_DIAG=lmr-diag-d5.txt cargo run --release --bin bench -- --depth 5
python3 data/experiments/stage5-diag-tools/lmr_diag.py lmr-diag-d5.txt
```

## エンジン

基点はコミット6084078にmalusの下書きを適用した未コミットの作業ツリーである。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

対象手は34,078手（残り深さ3が30,279手、深さ4が3,799手）、良い結果は200手（深さ3が151手、深さ4が49手）で、基礎率は0.6%であった。
現行の規則（`index ≥ 3`なら1）を同じ標本に適用すると、失う良い結果の割合は31.5%（63/200）、減深量の平均は0.999であった。
候補75組のうち失う割合が10%以下の組はなく、最小は`c = 4.0`の11.0%（減深量の平均0.642）であった。
history値の分位点は1%が−84、50%が−8、90%が0、99%が442であり、閾値候補の最小値1,024は99%点より大きく、増減はほとんど発動しなかった。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

「失う割合10%以下」の絶対基準では現行構成すら適格にならず縮退するため、本診断の前に、同じ標本の現行規則の失う割合を超えない組から減深量の平均が最大の組を選ぶ相対基準へ置き換え、閾値候補を64まで広げた。
本診断は、historyの最終構成が確定した後に深さ6で行う。

# strength-stage5-order-key-bench

## 目的

棋力向上段階5の順序付けキーの重複計算の除去（手選択器が捕獲手かどうかを手とともに返し、`negamax`が`move_order_key`を呼ばない変更）について、探索の挙動が不変であることと、NPSが低下しないことをbenchで判定する。

## コマンドライン

段階開始版と候補の各コミットで、次のコマンドを実行した。

```sh
cargo run --release --bin bench -- --repetitions 3
cargo run --release --bin bench -- --depth 5 --repetitions 3
```

雑音の幅を見るため、深さ5の3回計測を段階開始版と候補で交互に3組実行した。

## エンジン

段階開始版はコミットe172efb、候補はコミット7877531である。
対局ではないため、規則セットは該当しない。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）であり、benchは単一スレッドで実行した。
`USI_Hash`と同時対局数は該当しない。

## 結果

総ノード数は、深さ3で259,940、深さ5で1,553,119であり、段階開始版と候補で一致した。
交互に実行した深さ5のNPS中央値は、段階開始版が1,452,185、1,463,368、1,451,055（中央値1,452,185）、候補が1,455,143、1,454,120、1,453,071（中央値1,454,120）であった。
差は雑音の幅（約1%）の内側にあり、候補のNPSは低下していない。
破棄ペア数、異常件数、`time_forfeits`、対局の総経過時間は該当しない。

## 結論

総ノード数が一致し、NPSが低下していないため、順序付けキーの重複計算の除去を採用する。

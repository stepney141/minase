# 段階7の世代2追加後の端点の識別性

## 目的

[棋力向上段階7](../plans/strength-stage7.md)の再学習に先立ち、世代0〜2の全訓練集合で序中盤用と終盤用の重みを別々に学習できるかを確認する。
採用済みの鏡映共有モデルに合わせ、左右の鏡映対をまとめた6,840個の正準特徴で集計する。

## コマンドライン

```console
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONUNBUFFERED=1 \
  tools/train/.venv/bin/python tools/train/pst/taper_report.py \
  --data data/gen0.bin \
    data/gen1-s100000.bin data/gen1-s200000.bin data/gen1-s300000.bin \
    data/gen1-s400000.bin data/gen1-s500000.bin \
    data/strength-stage7/gen2/generated-600000.bin \
    data/strength-stage7/gen2/generated-700000.bin \
    data/strength-stage7/gen2/generated-800000.bin \
    data/strength-stage7/gen2/generated-900000.bin \
    data/strength-stage7/gen2/generated-1000000.bin \
  --model mirrored --lambda 0.75 \
  --pst data/strength-stage7/gen2/pst-base.bin \
  --output-dir data/strength-stage7/gen2/identifiability
```

実際の引数列と終了コードは`data/strength-stage7/gen2/commands.jsonl`の`identifiability`に保存した。
報告書と特徴別の集計は`data/strength-stage7/gen2/identifiability/`の`report.json`と`features.csv`、標準出力は`data/strength-stage7/gen2/identifiability.log`に保存した。

## エンジン

基準重みは鏡映共有モデルの採用コミット`960c56bcbb6088d0f0466d670ceea36dffeda5b7`から固定した`pst-base.bin`である。
ファイル全体のSHA-256は`b26e7841b168ed8e9f4bd8fe0094b7e0dbf6f74d76fae4ee95c19c18fa269b5c`、本体の検査和は`3000ae5c53f68742a7dad0ce48aab02dc3c6a8416cbbb8265e9aa0087713dc4a`で、出力Kは1072.6529541015625に固定した。
集計前に準備時のPythonソース、基準重み、生成器と診断器、および全11入力ファイルの検査和を再確認し、`all-generation-verified.json`へ保存した。

入力は世代0の1ファイル、世代1の5ファイル、および[世代2の生成記録](strength-stage7-gen2-generation.md)に記した5ファイルである。
既存6ファイルの検査和は[2端点PSTの識別性診断](pst-tapered-identifiability.md)と同じであり、全11ファイルのパス、検査和、シード、局面数を今回の`report.json`にも保存した。
対局単位の分割は`hash64(seed, game) % 20 == 0`を検証、それ以外を訓練とする既存規則を維持した。
教師Kは世代ごとの訓練集合だけから推定した。

## 環境

Intel Core Ultra 7 265KF、Linux 6.18.51-1-lts、Python 3.12.14、NumPy 2.5.2で集計した。
`OMP_NUM_THREADS`、`OPENBLAS_NUM_THREADS`、`MKL_NUM_THREADS`はいずれも2とし、教師生成、学習、および採否測定とは重ねて実行しなかった。

## 結果

2026年9月14日に終了コード0で完了し、集計コマンドの所要時間は129.077647秒だった。
盤上総駒数をNとした補間係数`φ = min(90, max(0, N − 2)) / 90`について、各特徴の出現回数と出現時の平均、および偏差平方和を集計した。
鏡映対の統計を正準特徴ごとに合わせてから偏差平方和を計算し、出現回数が0より大きく偏差平方和が100未満の特徴を識別できない特徴とした。

駒状態と陣営ごとの内訳は`report.json`の`state_summary`に保存した。
先獅子の対象升は72個の正準特徴がすべて観測され、出現27,398回のすべてが識別できない特徴に属した。

学習前に実際の訓練局面数23,879,611をバッチサイズ16,384で割って切り上げ、1エポック1,458回、10エポックで14,580回の更新になることを確認した。

診断報告書のSHA-256は`31f566749e38279f84814cd07568c62f19ba45e62c897a2cc6767268e12481cc`である。

独立監査では全11ファイルの実検査和、対局単位の分割、全レコードの駒数ヒストグラム、および帯別件数が一致した。
訓練局面だけを等しく重み付けした補間係数の平均と、学習の更新回数も一致した。
特徴別の偏差平方和は保存したCSVを対象に判定を再集計し、100の閾値に丸めで判定が変わり得る行がないことを確認した。
偏差平方和そのものの独立再計算は行っていない。
監査結果は`data/strength-stage7/gen2/identifiability-audit.json`に保存した。

## 結論

全11ファイルの訓練集合で識別できない特徴の出現割合0.228%が基準5%以下を満たしたため、採用中の鏡映共有モデルを初期値として世代2を含む再学習へ進む。
学習では出力K、47個の探索用駒価値、および計画で定めた学習条件を固定する。

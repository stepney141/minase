# 段階7の世代2再学習候補の長時間測定

## 目的

[棋力向上段階7](../plans/strength-stage7.md)の世代2再学習候補を採用済みの鏡映共有モデルと長時間条件（LTC）で比較し、候補を採用するかを判定する。

## コマンドライン

2026年9月14日08:43:51.830121に、日本標準時で次の測定を起動した。
保存した起動引数、標準出力、およびmanifestの条件は一致した。

```console
data/strength-stage7/match_runner \
  --run-dir data/matches/strength-stage7-gen2-ltc --seed 20950903 \
  --candidate commit:240fbfd607eb139030d92b5c718d579df62b20f6 \
  --baseline commit:960c56bcbb6088d0f0466d670ceea36dffeda5b7 \
  --rules engine-default --each time=60000+200 \
  --candidate-hash 256 --baseline-hash 256 --concurrency 19 \
  --max-ply 4096 --response-timeout 120 \
  gsprt --max-pairs 100000
```

両者の持ち時間は60秒、1手ごとの加算は0.2秒で、秒読みは使わない。
同じ開始局面から先後を入れ替えた2局を1ペアとし、[測定手順](../guides/sprt.md)の一般化逐次確率比検定で判定する。
帰無仮説H0は0 Elo、対立仮説H1は10 Elo、第一種と第二種の誤り確率はともに0.05である。
対数尤度比（LLR）の境界は約−2.944と+2.944で、上限は100,000ペアとする。

[短時間測定](strength-stage7-gen2-stc.md)のH1を受けてLTCへ進み、両測定の統計は合算しない。
LTCがH1となり、エンジン異常、時間切れ、および拒否着手が0件の場合だけ採用する。
上限到達による判定保留の場合は、同じ実行ディレクトリを再開して上限を増やす。

## 結果

測定プロセスは2026年9月14日10:52:25.561733に日本標準時で終了コード0となり、外側の起動処理もセッション69304で実際に終了コード0となった。
`summary.json`の`invocation_active: false`と`interrupted: false`を確認し、終了後の監査は共有ロックを取得して終了コード0で成功した。
起動と終了の記録は`data/strength-stage7/gen2-ltc-invocation.json`、`gen2-ltc-runner-exit.json`、および`gen2-ltc-outer-exit.json`に保存した。

番号1〜327の順序付き接頭部分を検定へ取り込み、有効320ペア、破棄7ペアとなった。
ペンタノミアル度数は`[47, 3, 167, 6, 97]`、最終LLRは`+2.9658032026`、判定は`H1`である。
各局の勝者と候補側の先後から独立に得点を再計算し、ログにある320回すべての順序付き統計と判定が一致した。
最初に判定境界へ達した番号は327で、それまでに欠番はない。

破棄7ペアはいずれも4,096手の上限到達を1局含み、統計から除外した。
検定へ取り込んだ327ペアの654局では、保存上の終局分類が勝敗決着638局、引き分け9局、手数上限7局であった。
不正着手、クラッシュ、応答タイムアウト、`time_forfeits`、拒否着手はすべて0件だった。

保存ファイルは全349ペアであり、番号328〜350のうち337を除く22ペアは先行保存分として最終検定の統計に含めない。
先行保存分を含む全698局の終局分類は、勝敗決着682局、引き分け9局、手数上限7局だった。
全保存分の終局と374,546回の着手応答を調べ、時計をナノ秒単位で再構成した結果も、上記5分類の異常はすべて0件だった。

基本シードは20950903で、ペア番号nに対する派生関数の入力は基本シードにnを加えた値である。
開始前の[シード監査](../../data/strength-stage7/gen2-absolute-ltc-seed-audit.json)では、過去150記録、ハッシュで固定した149資料、最新79件のmanifest、および段階7の生成と既存測定の予約を照合した。
世代2の5シード各7,500局と試行500局、両短時間測定の各3,000ペア予約、中断した固定200ペア測定と予定するHaChu測定の予約も対象に含め、今回の100,000入力`20950904..21050903`に区間重複と派生シード衝突がないことを確認した。
鏡映モデルのLTCで事前監査した100,000ペア分を実使用と扱わず、終了時の未保存投入を含む上限1,725に対応する`20910904..20912628`を予約として照合した。

今回の統計へ取り込んだ327ペアの入力は`20950904..20951230`であり、保存済みの最大番号350に対応する入力は20951253である。

# 段階7の世代2追加後の再学習

## 目的

[棋力向上段階7](../plans/strength-stage7.md)のフェーズ4として、採用中の鏡映共有モデルを世代0〜2の全データで再学習し、候補の書き出しと診断に進めるかを確認する。

## コマンドライン

2026年9月14日に、設定ファイル`data/strength-stage7/gen2.toml`を使って準備したワークフローの`train`を実行した。
以下では作業ディレクトリをリポジトリのルートとし、保存された絶対パスを相対パスで表記する。

```console
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONUNBUFFERED=1 \
  tools/train/.venv/bin/python tools/train/pst/pst_workflow.py train \
  --run-dir data/strength-stage7/gen2
```

ワークフローが起動した学習子プロセスの全引数は次のとおりである。
実際の引数列、作業ディレクトリ、終了コード、および所要時間は`data/strength-stage7/gen2/commands.jsonl`の`train`に保存されている。

```console
tools/train/.venv/bin/python tools/train/pst/train_pst.py train \
  --data data/gen0.bin \
    data/gen1-s100000.bin data/gen1-s200000.bin data/gen1-s300000.bin \
    data/gen1-s400000.bin data/gen1-s500000.bin \
    data/strength-stage7/gen2/generated-600000.bin \
    data/strength-stage7/gen2/generated-700000.bin \
    data/strength-stage7/gen2/generated-800000.bin \
    data/strength-stage7/gen2/generated-900000.bin \
    data/strength-stage7/gen2/generated-1000000.bin \
  --init data/strength-stage7/gen2/pst-base.bin \
  --output data/strength-stage7/gen2/training/pst.bin \
  --k 1072.6529541015625 --model mirrored --lr 3.0 --epochs 10 \
  --batch 16384 --seed 1 --lambda 0.75 --device cuda --validation-sample 10000
```

学習条件はモデル`mirrored`、Adam、学習率3、10エポック、バッチ16,384、乱数シード1である。
序中盤用と終盤用の2列を、6,840個の正準特徴で共有し、確率的な鏡映拡張は適用しない。
教師勝率は、探索値を世代別の尺度Kで勝率へ変換した値を75%、最終対局結果を25%の比率で混合した。
出力Kは1072.6529541015625に固定し、探索用駒価値47値は初期ファイルから引き継ぐ設定とした。

対局単位の分割`hash64(seed, game) % 20 == 0`を検証集合、それ以外を訓練集合とした。
各エポックの検証損失は全検証局面で求め、全体の損失を最小にするエポックを選択した。
`--validation-sample 10000`は学習後の量子化誤差を検証集合から抽出して測るための設定だが、今回は量子化中に停止したため標本の抽出には到達していない。

### 量子化中の停止

最良エポックを選択した後、`train_pst.py`の`command_train`が序中盤用の浮動小数点重みを`quantize`に渡したところ、次の例外で停止した。
同関数は重みを1/8センチポーン単位に丸め、符号付き16ビット整数に収まるかを検査する。

```text
OverflowError: trained weight does not fit i16
```

学習子プロセスは662.8170341279765秒後に終了コード1で終了し、ワークフローも失敗を報告した。
元の`training/`に保存されたファイルは`inputs.json`と`environment.json`だけであり、`pst.bin`、量子化前の`pst-float.npz`、および`complete.json`は作成されていない。
例外のスタックトレースは`data/strength-stage7/gen2/train.log`、ワークフローの失敗報告は`data/strength-stage7/gen2-train.log`に残っている。

量子化誤差の平均絶対値と最大値、書き出し後の初期局面評価、および候補の局面帯別診断は未測定である。
[参照設計の量子化基準](../plans/tapered-pst.md#局面帯別に診断する)は平均絶対誤差2センチポーン以下であり、最大誤差に対する上限ではないが、今回の元実行ではこの基準を判定できていない。
浮動小数点重みも保存前に失われているため、元実行の学習済み重みを用いたRust評価の照合、駒の除去、および成りの診断結果はない。

今回の記録では対局を行っていないため、ペンタノミアル度数、対数尤度比、Eloと95%信頼区間、破棄ペア数、および`time_forfeits`は非該当である。
学習処理では上記の例外1件が記録され、検証損失から棋力の採否は判定していない。

### 量子化失敗の再現

元の学習条件を保ち、出力先だけを診断用ディレクトリへ変えた再実行でも、最良エポック8の書き出しで同じ例外が生じた。
`data/strength-stage7/gen2/overflow-diagnosis/capture.py`は、固定したソースと全11入力を検査して元の学習器を実行し、例外時の局所変数から両端点の浮動小数点重みを保存して同じ例外を再送出する。
学習関数、乱数設定、および最良エポックの選択には介入していない。
再実行は671.1274863900035秒で終了コード1となり、エポック0〜10の損失は元のログの記録桁ですべて一致した。
元実行の浮動小数点重みは未保存のため、元実行と再実行の重みのバイト一致は確認できない。

採取した`failed-best-float.npz`のSHA-256は`3e7bb8b0b36a298c257f24b81c31dea50d2c37535997e8d712c652fba2c4bc03`である。
同ディレクトリの`invocation.json`と`capture.json`に引数列と採取結果、`replay.log`に学習出力を保存した。
再実行の最大常駐メモリは5,648,940 KiBであり、元実行の資源使用量とは区別する。

採取した配列を現行の量子化関数へ渡す次の検査は0.54秒で終了コード1となり、序中盤用の重みだけで同じ例外を再現した。

```console
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  tools/train/.venv/bin/python \
  data/strength-stage7/gen2/overflow-diagnosis/reproduce.py \
  data/strength-stage7/gen2/overflow-diagnosis/failed-best-float.npz
```

配列を二分して失敗を保つ側へ縮めると、特徴番号9677の1値だけで例外が再現し、その値を除くと検査は成功した。
全27,360値について、標準ライブラリの十進演算による最近接偶数丸めと符号付き16ビット整数への格納を独立参照にすると、量子化関数の丸め結果と成否が全件一致した。
範囲超過は次表の鏡映1対だけであり、全重みは有限値だった。

| 端点 | 特徴番号 | 重み（センチポーン） | 8倍して丸めた値 | 格納可能な下限 |
|---|---:|---:|---:|---:|
| 序中盤 | 9677 | −4236.53662109375 | −33,892 | −32,768 |
| 序中盤 | 9678 | −4236.53662109375 | −33,892 | −32,768 |

この1対は相手獅子の正準特徴4841であり、実際の学習初期値は序中盤−3,197.625、終盤−2,745センチポーンだった。
採取した最良状態の終盤重みは−3,233.70751953125センチポーンで、終盤側は保存範囲内にある。
全11入力の訓練集合からこの特徴を独立集計すると18,848回現れ、平均補間係数0.2708474816072439、偏差平方和257.63228017774424となり、学習前の識別性診断と一致した。
偏差平方和は基準100以上を満たしており、識別性の基準は重みが保存範囲に収まることを保証するものではない。
世代0、1、2の出現回数はそれぞれ630、10,807、7,411回であり、集計方法と補間係数の分布は同ディレクトリの`feature-audit.json`に保存した。

基準重みの読込、鏡映共有モデルへの初期化、展開、および再量子化をCPUで検査すると、全27,360値が元の整数配列とバイト単位で一致した。
採取した両端点でも、各6,840組の鏡映対の差はすべて0で、モデルへの再読込と展開は元の配列と一致した。
この検査では、単位変換、鏡映展開、および量子化の境界判定の不整合は検出されなかった。
独立参照と鏡映検査の根拠は、同ディレクトリの`storage-reference.json`と`mirror-unit-roundtrip.json`に保存した。

この失敗した実行の学習は重みの振幅を制約しないため、最良状態は固定した保存形式で表現できない。
学習の各更新後に重みを表現可能範囲へ射影する変更は学習規則を変えるので、恒久的な学習器変更を鏡映共有と出力Kの固定に限る当初の計画には含まれていなかった。
この変更を具体化して利用者へ方針を確認し、利用者は範囲への射影を追加して再学習することを選択した。
書き出し時の切り詰め、別エポックへの差し替え、および新しい条件での候補の学習は行っていない。

### 追加案の予備検査

各Adam更新後に有限性を検査し、重みを−4,096〜4,095.875センチポーンへ射影する案を、本体へ適用せずメモリ上のコピーで検査した。
鏡映共有モデルと人工的な2レコードを使い、上下各2バッチの実際のAdam更新で、次のバッチとエポック末の両端点が範囲内であることを確認した。
範囲内の連続値、鏡映対称性、およびパディング0も保たれ、非有限値6ケースは射影前に停止した。
提案差分を外した対照2ケースは範囲検査で失敗し、検査部は0.45594043799792416秒で終了した。
スクリプトと結果は`data/strength-stage7/gen2/overflow-diagnosis/projection-cpu-check.py`と`projection-cpu-check.json`に保存し、本体と既存テストの検査和が前後で一致することも確認した。

新規実行の設定では、生成済みの全11入力のパスと検査和、および学習条件が元実行と一致することを確認した。
これらは本体への実装前の検査であり、本データでの学習、量子化誤差の判定、および棋力測定は含まない。
利用者の選択に従い、射影を本体へ追加し、実際の学習更新を通る回帰テストを追加した。
変更前の本体では、3モデルの上下限6ケースと非有限値15ケースが失敗し、変更後はPST関連の全45テストが成功した。
射影をエポック末へ移す、上限を4096にする、第1列だけを射影する、および射影後に有限性を検査する4種類の誤実装も、隔離したコピー上で新テストがすべて検出した。
この確認は`data/strength-stage7/projection-regression-red.log`、`projection-pst-tests.log`、および`projection-mutations.json`に保存した。
学習器の変更は`train_epoch`に限られ、特徴定義、分割、および識別性診断のコードが変わっていないことを`projection-source-change.json`に記録した。
この実装を固定してから、新しい実行ディレクトリを準備する。

## 結論

10エポックの計算で最良エポック8の検証損失0.478427486を得たが、序中盤の鏡映1対が保存範囲を超え、候補を生成できなかった。
同条件の再実行と独立した整数格納でも失敗を再現した。

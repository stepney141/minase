# 段階7の開始重みの鏡映診断

## 目的

[棋力向上段階7](../plans/strength-stage7.md)のフェーズ0として、開始版の評価値が左右鏡映でどれだけ変わるかを測り、訓練集合で両方が未観測の鏡映対を再集計する。
測定日は2026年9月12日であり、採否は後続の自己対局測定で判定する。

## コマンドライン

```console
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  tools/train/.venv/bin/python data/strength-stage7/mirror_diag.py
```

集計結果は`data/strength-stage7/mirror-diag/report.json`、特徴出現数は`training-feature-counts.npy`、局面ごとの鏡映差は`validation-mirror-differences.npz`に保存した。
再実行時は出力ディレクトリを空ける。

重み共有後の正準特徴について、同じ入力で2端点の識別性も集計した。
結果は`data/strength-stage7/mirror-identifiability/report.json`と同ディレクトリの`features.csv`に保存した。

```console
tools/train/.venv/bin/python tools/train/pst/taper_report.py \
  --model mirrored \
  --data data/gen0.bin data/gen1-s100000.bin data/gen1-s200000.bin \
         data/gen1-s300000.bin data/gen1-s400000.bin data/gen1-s500000.bin \
  --pst nets/pst.bin --lambda 0.75 \
  --output-dir data/strength-stage7/mirror-identifiability
```

## エンジン

開始コミットは`d0d3c52024c5ab4d74cc82588640a55953426aad`である。
`nets/pst.bin`がこのコミットのファイルとバイト一致することを確認した。
ファイル全体のSHA-256は`b172a1b3e1c620bbdb1b2f22d0c5ebc9fa11a891703d88c59c710301173feb5a`、ヘッダに格納された本体の検査和は`93bbff7c49955e7e038ee26997143898de49f5700800cde4457547cd8c395335`、出力Kは1072.6529541015625である。
規則セットは`L0,P0,R1,E0`であり、候補エンジンは置かない。

入力は`data/gen0.bin`と`data/gen1-s100000.bin`から`data/gen1-s500000.bin`までの計6ファイルであり、[2端点の識別性診断](pst-tapered-identifiability.md)のファイル名、SHA-256、局面数と全件一致した。
対局単位の分割`hash64(seed, game) % 20 == 0`をそのまま使い、訓練10,520,846局面、検証541,965局面となった。
検証集合は抽出せず全局面を評価し、訓練集合の特徴出現数は鏡映拡張前の盤面から数えた。

## 環境

Intel Core Ultra 7 265KFの物理20コア、論理20コア上で実行した。
Python 3.12.14、NumPy 2.5.2、PyTorch 2.13.0+cu130を使用し、PyTorchのスレッド数は2、バッチは8,192局面とした。
対局を行わないため、エンジンのワーカー数、`USI_Hash`、同時対局数は非該当である。

## 結果

CPU上の所要時間は21.598秒であった。
棋力測定ではないため、ペンタノミアル度数、対数尤度比、Elo、破棄ペア、`time_forfeits`は非該当であり、評価値の照合で不一致はなかった。

### 検証集合の鏡映差

差は、手番を固定した元局面の整数評価から左右鏡映局面の整数評価を引いた値とする。
盤面と先獅子対象升を`features.mirror`で反転し、元局面と同じ補間係数を使って`train_pst.integer_evaluate`で評価した。
初期局面の両視点、検証集合から等間隔に選んだ200局面、その鏡映200局面の計402局面では、Rustの`pst_probe`による評価と全件一致した。

全検証局面の差の平均は+1.413センチポーン、標準偏差は48.978センチポーン、平均絶対差は38.680センチポーンであった。

### 初期局面と未観測の特徴

初期局面の整数評価は先手視点で+67センチポーン、後手視点で+48センチポーンとなり、先手視点から後手視点を引いた差は19センチポーンであった。
これらの値はPythonとRustで一致した。

訓練集合の全特徴出現625,111,606回を再集計すると、観測済み9,141特徴、未観測4,539特徴となった。
未観測のうち117特徴は鏡映相手が観測済みで、残り4,422特徴は両方が未観測の2,211対であり、計画の見積りを確認した。
重み共有はこの2,211対に新しい観測を与えないため、実装の狙いは観測された対への更新の共有と対称性の保証に置く。

### 正準特徴の端点識別性

鏡映対を1つの正準特徴として数えると、観測済みは4,629特徴、未観測は2,211特徴となった。
出現時の補間係数φの偏差平方和が100未満である観測済み特徴は2,621個で、その出現2,269,147回は全出現625,111,606回の0.363%であった。
識別できない特徴の出現割合が5%以下という基準を満たすため、重み共有モデルの学習へ進める。
訓練局面でのφの平均は0.6379477214411592であり、既存6ファイルを訓練集合とする場合の探索用駒価値の補間に使える。
世代2を加えた場合は、その訓練集合で平均を再計算する。

生成と測定のシードの監査は[strength-stage7-seed-audit](strength-stage7-seed-audit.md)に記録した。
生成シードは計画の値を使い、測定開始シードは既存測定との重複を避けて20900903へ変更した。

## 結論

開始重みの鏡映差は平均絶対38.680センチポーン、初期局面の両視点の差は19センチポーンであり、両方が未観測の2,211対を確認したため、計画どおり重み共有を実装して棋力を測る。

# 段階7の鏡映重み共有モデルの学習と診断

## 目的

[棋力向上段階7](../plans/strength-stage7.md)のフェーズ1として、既存の世代0と世代1のデータで鏡映の重み共有モデルを学習し、開始版との棋力測定に先立つ評価値の整合性を確認する。

## コマンドライン

2026年9月12日に、[PSTの学習手順](../guides/pst-training.md)のワークフローを設定ファイル`data/strength-stage7/mirror.toml`で実行した。
`prepare`が固定した条件とソースの検査和は`data/strength-stage7/mirror-training/prepared.json`、実行コマンドと学習の終了コード0は同ディレクトリの`commands.jsonl`に保存されている。

```console
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py prepare \
  --config data/strength-stage7/mirror.toml
tools/train/.venv/bin/python tools/train/pst/pst_workflow.py generate \
  --run-dir data/strength-stage7/mirror-training
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONUNBUFFERED=1 \
  tools/train/.venv/bin/python tools/train/pst/pst_workflow.py train \
  --run-dir data/strength-stage7/mirror-training
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONUNBUFFERED=1 \
  tools/train/.venv/bin/python tools/train/pst/pst_workflow.py diagnose \
  --run-dir data/strength-stage7/mirror-training
```

生成シードは空配列であり、入力は`data/gen0.bin`と`data/gen1-s100000.bin`から`data/gen1-s500000.bin`までの計6ファイルである。
ファイルと検査和は[開始時の鏡映診断](strength-stage7-mirror-diag.md)と同じで、新しい教師データは生成していない。
設定には`generate.max_ply = 600`が残るが、生成を行わないため今回の学習に影響しない。

学習条件はモデル`mirrored`、Adam、学習率3、10エポック、バッチ16,384、乱数シード1、探索値の教師比率λ = 0.75、出力K = 1072.6529541015625である。
対局単位の分割`hash64(seed, game) % 20 == 0`により、訓練10,520,846局面、検証541,965局面となり、1エポック643更新、合計6,430更新を行った。
重み共有では確率的な鏡映拡張を適用しない。

学習直後の量子化誤差は検証集合からシード1で10,000局面を抽出して測った。
後続の診断では同じ検証集合から世代と補間係数φの帯ごとに最大10,000局面をシード1で抽出し、共通標本91,841局面を基準と候補に使った。

候補の重みを組み込んだ後、Rustの検査と深さ5のベンチマークを実行した。
ベンチマークは基準と候補の各バイナリで3回ずつ測った。

```console
cargo test
cargo clippy --all-targets --all-features -- -D warnings
cargo fmt --check
target/release/bench --depth 5 --repetitions 3
```

## エンジン

基準は段階開始コミット`d0d3c52024c5ab4d74cc82588640a55953426aad`であり、重みのSHA-256は`b172a1b3e1c620bbdb1b2f22d0c5ebc9fa11a891703d88c59c710301173feb5a`である。
入力データの規則セットは`L0,P0,R1,E0`、教師探索は100,000ノードである。
診断のRustプローブは`938a7ca478c43ec22c59675e9cc30b1521fa2ddd`を固定したworktreeから構築し、バイナリのSHA-256は`94c33e504c5cc0d7c67b44697f7210c6c068677ec5a1a93b8b3801002113151e`である。

候補は`data/strength-stage7/mirror-training/training/pst.bin`で、SHA-256は`b26e7841b168ed8e9f4bd8fe0094b7e0dbf6f74d76fae4ee95c19c18fa269b5c`である。

候補を埋め込んだコミットは`960c56bcbb6088d0f0466d670ceea36dffeda5b7`である。

## 環境

Intel Core Ultra 7 265KFの物理20コア、論理20コア、NVIDIA GeForce RTX 3060 Ti上で実行した。
Python 3.12.14、NumPy 2.5.2、PyTorch 2.13.0、CUDA 13.0を使用した。
学習と診断では`OMP_NUM_THREADS=2`、`OPENBLAS_NUM_THREADS=2`、`MKL_NUM_THREADS=2`を指定し、ログを遅延なく保存するため`PYTHONUNBUFFERED=1`も指定した。
最大常駐メモリは3,163,116 KiB、最大GPUメモリは509,073,408 bytesであり、詳細は`training/environment.json`と`train.log`に保存した。
学習と診断のため、対局エンジンのワーカー数、`USI_Hash`、同時対局数は非該当である。

`training/artifact-checks.json`では、量子化後の全鏡映対が一致し、重みが開始重みの鏡映対の平均を量子化した値に一致することを確認した。

これらは評価関数の診断値であり、棋力の採否には使わない。

### 量子化とRust評価の一致

学習直後の10,000局面では、量子化前の浮動小数点評価と整数評価の平均絶対差が0.530092061センチポーン、最大差が2.194444656センチポーンであった。
全世代と全帯を合わせた診断標本91,841局面では、平均絶対差が0.528881192センチポーン、最大差が2.194444656センチポーンとなった。
[参照設計の量子化基準](../plans/tapered-pst.md#局面帯別に診断する)は、この共通標本の平均絶対誤差が2センチポーン以内であることなので、候補は基準を満たす。
最大差は診断値として記録し、判定には使わない。

同じ91,841局面について、基準と候補の双方でRustの評価がPythonの整数参照評価と全件一致した。
診断ワークフローは終了コード0で完了し、結果を`diagnostics/report.json`に保存した。

### 駒の除去と成り

初期局面と各帯の代表局面について、非王駒を1枚ずつ除く352通りを比較した。
基準と候補で評価変化の符号は全件一致し、自分の駒の除去はすべて負、相手の駒の除去はすべて正であった。
除去後は補間係数も変わるため、この変化を駒固有の価値とは見なさない。

合法な成り手はφ ∈ [0.6, 0.8)の代表局面の`7g4d+`だけであり、着手前の手番側視点に揃えた評価差は基準462センチポーン、候補427センチポーンであった。
双方の差がRustとPythonで一致した。
残る5局面には合法な成り手がなく、その理由を診断結果に保存した。

この記録では対局を行っていないため、ペンタノミアル度数、対数尤度比、Elo、破棄ペア数、`time_forfeits`は非該当である。
評価、成り、除去符号の不一致はいずれも0件であった。

### Rustの検査と探索速度

候補コミットで`cargo test`、全ターゲットと全機能を対象とするClippy、整形検査はすべて終了コード0で成功した。
ログは`data/strength-stage7/mirror-candidate-test.log`、`mirror-candidate-clippy.log`、`mirror-candidate-fmt.log`に保存した。

深さ5の総ノード数は基準1,438,048から候補1,465,171へ変化した。
各構成で3回の中央値を比べると、候補の1秒あたりの探索ノード数は基準より高く、速度低下は認めなかった。

## 結論

鏡映対の平均に由来する最良エポック0の候補は規定の診断と検査を満たしたため、採否は別の短時間および長時間の自己対局測定で判定する。

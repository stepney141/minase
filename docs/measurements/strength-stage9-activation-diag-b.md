# 棋力向上段階9の118列の発火率診断

## 目的

[棋力向上段階9](../plans/strength-stage9.md)のフェーズ3として、全計算の利き数の表から計算した7項目118列の追加特徴について、基本の教師での発火率、特徴値の分布、端点の識別性、特徴どうしの相関、学習PSTの残差との相関、安全な升の数の駒の区分ごとの分布、および敗局の検証局面での特徴値を記録する。特徴の除外と端点の共有の確定は、教師の構成が確定した後のフェーズ6で行う。

## コマンドライン

特徴値は、診断用のブランチのリリースビルドで、基本の教師の11ファイルのそれぞれについて次のコマンドで書き出した。

```console
target/release/pst_probe --pst nets/pst.bin \
  --positions data/<入力>.bin \
  --king-features data/strength-stage9/features-b/<入力>.mnkf \
  --mobility-histogram data/strength-stage9/features-b/<入力>.mobility.json
```

11ファイルの安全な升の度数は、区分ごとに和をとって1つのJSONへまとめた。診断は次のコマンドで実行した。

```console
tools/train/.venv/bin/python tools/train/pst/king_features_diag.py \
  --data data/gen0.bin data/gen1-s100000.bin ... data/strength-stage7/gen2/generated-1000000.bin \
  --king-features <上と同じ順のMNKFファイル11個> \
  --pst data/strength-stage9/pst-1633f53.bin --output-k 1072.6529541015625 --batch 65536 \
  --mobility-histogram data/strength-stage9/features-b/mobility-merged.json \
  --output data/strength-stage9/activation-diag-b.json
```

敗局の検証局面の特徴値は、敗因分析の着手列を規則セット `lishogi` で再生して表示した。

```console
target/release/pst_probe --usi-moves <着手列> --rules lishogi \
  --plies 50,140,144,174,176,178,180 --print-features
```

## エンジン

特徴の計算と診断器は、ブランチ `strength-stage9-diag-b` のコミット `2fe29dd` である。
学習PSTの残差に使った重みは段階開始版（masterの `6c5c559`、`1633f53` と同じ内容）の `nets/pst.bin` であり、出力Kは1072.6529541015625である。
特徴の定義の識別値は2、列数は118である。
列の並びは、項目1（0〜23）、項目2（24〜55）、項目3（56〜61）、項目4（62〜83）、項目5（84〜89）、項目6（90〜101）、項目7（102〜117）であり、各項目の前半が手番側、後半が相手側である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）で、2026年9月22日に実施した。
書き出しは11ファイルを並列に約1分で、診断は効率コアに固定して約3分で終わった。

## 結果

訓練の分割の局面数は23,879,611であり、世代ごとの教師Kは804.0、1099.7、777.6、局面数は877,601、9,643,245、13,358,765である。
王駒が2枚の側を含む局面は0.81%（手番側0.42%、相手側0.42%）であり、着手時の診断と同じである。

## 結論

118列のうち発火率が0.1%未満の列は4つ、識別性が100未満の列は1つであり、項目6の孤立の列は項目7の獅子の列と同一である。
手番側で即座の捕獲を意味する特徴は教師の除外により発火せず、この非対称は候補の学習で相手側の列だけが重みを持つ形として現れる見込みである。
敗局の検証局面では、項目1に加えて項目2の距離2の高い利き数の升と項目7の脅威が180手目までに発火しており、特徴としては危険を表現できる。
ただし、[利き数の表の速度](strength-stage9-table-bench.md)により項目2から項目7は見送りとなったので、本記録は後続の設計の入力として保持する。

# 棋力向上段階9の評価の償却と土台の費用の診断（bench深さ5）

## 目的

[棋力向上段階9](../plans/strength-stage9.md)のフェーズ1として、主探索の静的評価を1ノード1回にまとめた効果、静的評価と王手判定と静的交換評価の呼び出し回数、1手で利き数が変わる升の数、および全駒の利き集合と近傍の利き集合で評価特徴を計算する構成の速度を測り、フェーズ2の土台の設計に使う数値を残す。

## コマンドライン

速度は、各構成のリリースビルドを性能コア（論理CPU 3）へ固定し、段階開始版と交互に3回ずつ実行して、各回が出力する3反復の中央値を記録した。

```console
taskset -c 3 <構成のbench> --depth 5 --repetitions 3
```

回数は、カウンタを持つビルド（feature `foundation-diag`）を固定なしで1回実行して読んだ。

```console
cargo build --release --bin bench --features foundation-diag
target/release/bench --depth 5 --repetitions 1
```

## エンジン

| 構成 | 内容 | コミット |
|---|---|---|
| A | 段階開始版（master） | `6c5c559` |
| B | 項目1の24列を持つ候補の構成、償却前 | `84463f4`（ブランチ `strength-stage9`） |
| C | Bに評価の償却を加えた構成 | `063a4b0`（ブランチ `strength-stage9`） |
| D | Cにワーカーごとのカウンタを加えた回数用ビルド | `587fd81`（ブランチ `strength-stage9-diag-b`、feature `foundation-diag`） |
| E | Cに、全駒の利き集合を評価のたびに作って項目4と項目5の特徴値を計算する構成を加えたもの。重みはすべて0で、敵の利きがない升は全駒の利き集合の和から求める | 同上、feature `diag-mobility` |
| F | Cに、王駒を中心とする5×5の25升へ空の盤で届き得る駒だけの利き集合を作って項目2と項目3の特徴値を計算する構成を加えたもの。重みはすべて0 | 同上、feature `diag-neighbourhood` |

BからFの重みは項目1の学習済みの重みを持つ埋め込みの重みであり、Aの重みと異なるので、総ノード数はAが598,014、BからFが655,611である。
CからFの間では総ノード数と15局面の最善手と評価値が一致し、Dの全8通りのfeatureの組合せでも一致した。
EとFの追加の計算は、`std::hint::black_box` を通した0の係数で評価値へ加えているので、評価値を変えずに計算だけを残す。
規則は `engine-default` である。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）であり、速度の測定中は他の探索や生成を走らせていない。
2026年9月22日に実施した。
1回目の測定では、3巡目に別プロセスのビルドが重なって段階開始版の値が2,032,733まで下がったので、2回目の測定を採用した。
2回目では、どの構成でも3回の値の幅が1%以内だった。

主探索のノードのうちfutility境界を計算するのは59%であり、償却後にcorrection historyの更新で改めて評価するノードは0.7%である。
静的評価の94%は静止探索のstand-patが占めるので、評価の費用は静止探索の側で決まる。
省略の条件は、到達升に敵の疑似利きがなく、移動元へ敵の長い利きが届いていないことであり、逆引きで判定した。
静的交換評価の呼び出しは総ノード数の93%に当たるので、利き数の表による省略は呼び出しの11.7%の逆引きを省く。

### 1手あたりに利き数が変わる升の数

着手の前後で利き数の表を全計算し、値が異なる（色, 升）の組を数えた。

| 経路 | 着手数 | 変わった組の合計 | 1手あたりの平均 | 最大 |
|---|---:|---:|---:|---:|
| 主探索 | 412,167 | 7,163,862 | 17.4 | 77 |
| 静止探索（捕獲手） | 243,444 | 7,213,654 | 29.6 | 72 |
| 合計 | 655,611 | 14,377,516 | 21.9 | 77 |

この数は、差分更新が1手で書き換える升の数の下限である。
表の全体は288個の利き数と288個の方向ビット列なので、差分更新は全計算に比べて書き換えを平均で1割弱に抑える。

## 結論

評価の償却は探索木を変えず、項目1の構成では速度への効果が測定の揺れの中に収まるが、静的評価の費用が増える後続の項目のために採用してブランチ `strength-stage9` へ入れた。
全駒の利き集合を評価のたびに作る構成Eは償却後の0.357倍、近傍25升の利き集合の構成Fは0.293倍であり、どちらも項目の速度の条件0.85倍から遠い。
Eは参考値であり、項目4と項目5の拘束力のある判定はフェーズ2で利き数の表を使う本番の構成で行う。
Fは土台の条件を満たさなかった場合の代替として設計書が置いた構成であり、この値では代替として成り立たないので、利き数の表が土台の条件を満たさなければ項目2以降はすべて見送ることになる。
静的交換評価の省略の条件は呼び出しの11.7%でしか成立しないので、探索の側で回収できる費用は小さく、表の採否は評価特徴の効果で決まる。

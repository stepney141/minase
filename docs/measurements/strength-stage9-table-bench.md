# 棋力向上段階9の利き数の表の速度（bench深さ5）

## 目的

[棋力向上段階9](../plans/strength-stage9.md)のフェーズ2として、plyごとに差分更新する利き数の表と走りの方向の表、および王手判定と静的交換評価での表の利用を入れた構成の速度を段階開始版と比べ、土台の条件（0.90倍以上）を判定する。あわせて、利き数の表から敵の利きがない升を求める本番の構成で項目4と項目5を計算する速度の判定に必要な数値を残す。

## コマンドライン

各構成のリリースビルドを性能コア（論理CPU 3）へ固定し、基準と交互に3回ずつ実行して、各回が出力する3反復の中央値を記録した。

```console
taskset -c 3 <構成のbench> --depth 5 --repetitions 3
```

## エンジン

表の実装はブランチ `strength-stage9-table` にあり、初版が `7c5982d`、更新の費用を下げた版が `c031ba6` である。
`c031ba6` は、子の表を写してから直接更新する形、動かす駒の短い利きの相殺、および立っている方向ビットだけの反復を加えた。走りのビットボード化と短い利きの前計算は改善しなかったので採らなかった。
段階開始版との比較は、探索木を同じにするために、項目1の計算を外した測定用のビルド（`add_extra_features` を空にする一時的な変更で、埋め込みの重みの追加列は使われず、評価は段階開始版と一致する）で行った。この構成では全構成の総ノード数が598,014で段階開始版と一致し、15局面の最善手と評価値も一致した。
項目1の計算を含む構成どうしの比較は、総ノード数655,611で一致した。

## 環境

測定機はIntel Core Ultra 7 265KF（物理20コア、論理20コア、実メモリ32 GB）である。
初版の測定（1回目）では他の負荷がなく、段階開始版の値は2,232,004だった。
`c031ba6` の測定（2回目）では、別の作業者が起動したSPSAの本番セッション（同時対局16、エンジン32プロセス）が動いており、負荷平均は約17、段階開始版の値は2,138,000前後に下がった。
2回の測定で比は一致したので、2回目の値をそのまま記録する。
2026年9月22日に実施した。

項目1を含む構成では、C（1,958,813、1,963,705、1,963,679、中央値1,963,679）に対してG2（1,629,451、1,627,668、1,631,948、中央値1,629,451）は0.830倍だった。

表の写しだけの費用は0.991倍であり、0.97を下回らないので、取り消しつきの更新へは変えない。
更新の費用は初版で25%、改良版で19%であり、王手判定と静的交換評価の置き換えが回収する費用は1〜2%にとどまる。
フェーズ1の回数の診断では、静的交換評価の省略の条件は呼び出しの11.7%でしか成立せず、王手の判定は総ノード数の5.8%でしか呼ばれないので、この回収の小ささは回数と整合する。

### 費用の内訳

perf（cycles、本番の構成、ユーザー空間）では、初版の表に直接かかる自己時間が `remove_piece` 4.4%、`change_rays` 8.0%、`update_effect_table` 3.9%の合計約16%であり、これに576バイトの表を値で受け渡す写しが加わっていた。
1手で利き数が変わる（色, 升）の組は平均21.9（フェーズ1の診断）であり、更新は変わる升の数に比例する走査に加えて、動かす駒と取られる駒の短い利きと走りの列挙、および除いた升と置いた升に届いていた走りの伸長と打ち切りを行う。
1ノードの時間は段階開始版で約0.45 μsなので、改良版の更新は1ノードあたり約0.1 μsに当たる。

## 結論

利き数の表を入れた本番の構成は段階開始版の0.816倍であり、土台の条件0.90倍を満たさない。
設計書の速度の条件に従い、利き数の表は見送る。
土台の条件を満たさなかった場合の代替である近傍25升の利き集合の構成は、[土台の費用の診断](strength-stage9-foundation-diag.md)で償却後の0.293倍であり、項目の条件0.85倍を満たさないので、項目2と項目3も見送り、表を要する項目4から項目7も見送る。
項目4と項目5の本番の構成（表から敵の利きがない升を求める構成）の測定は、表を見送ったので行わない。
表の実装はブランチ `strength-stage9-table` に残し、masterへは入れない。
0.816倍は、目的の節の換算では約63 Eloの損失に当たり、この条件は利用者の決定による事前の選別なので、条件の見直しは利用者の判断に委ねる。

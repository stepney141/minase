# 持ち時間の伸縮の形の変更による探索ノード数と探索速度

## 目的

[探索の不安定さに応じた持ち時間の伸縮の設計書](../../plans/time-instability-scaling.md)のフェーズ1で入れた11個のコミットについて、固定深さの探索（`minase dev bench`）の探索ノード数、評価値、および最善手が起点と同じであることを確かめる。
本書の変更は時間管理だけを変え、固定深さの探索は時間予算を使わないので、全コミットで一致する見込みである。
あわせて、探索速度、最大常駐メモリ、および係数の既定値を動かしたときのテストの結果を記録する。
棋力測定ではない。新しい12係数はStockfishの値を換算した開始値のままであり、強さの変化はSPSAで調整した後に、事前対局と短時間条件（10秒＋1手0.1秒）の逐次検定STCで記録する。

## コマンドライン

ノード数は、各コミットの`cargo build --release --bin minase`によるminaseで、次のコマンドを深さ3、5、7について1回ずつ実行して数えた。
`dev bench`は固定の15局面を固定の深さで探索し、局面ごとに置換表と履歴の表を初期化するので、同じバイナリなら出力は毎回同じになる。

```console
minase dev bench --depth <深さ>
```

探索速度と最大常駐メモリは、起点と最後のコミットのminaseを交互に3回ずつ、性能コアのCPU 3に固定して測った（[速度比較のbenchは性能コアへ固定して測る](../../lessons/pin-bench-to-performance-core.md)）。
各回の値は、計測外のウォームアップ1回の後に3回探索した中央値である。最大常駐メモリは`/usr/bin/time -f %M`で取得した。

```console
/usr/bin/time -f %M taskset -c 3 minase dev bench --depth 9 --repetitions 3
```

係数の既定値に期待値を結びつけたテストがないことは、調整対象の103係数の既定値を範囲の1/3と2/3の位置（`最小 + (最大 − 最小) × 1/3`など、0の方向へ丸める）に一時的に置き換えた表で、`cargo test --workspace`と`cargo test -p minase --lib --features search-stats,tuning`を実行して確かめた。

## エンジン

起点はコミット`370f7077`（[サブタスク6](../../plans/archived/aspiration-window-forms.md)の完了後のmaster）である。
11個の実装コミットの後に、係数の既定値に依存していたテストを直したコミット`975876ee`と、実装のレビューの指摘を受けて反復の境界の継続判定で時計を読み直すように直したコミット`68d3a4d4`を加えた。形の変更の最後のコミットは`68d3a4d4`である。
探索速度は`975876ee`で測った。`68d3a4d4`の修正は時間予算を使う探索の反復の境界の判定だけを変え、固定深さの探索は変えない。
規則セットは`engine-default`、探索のワーカーは1、置換表は既定の256 MBである。

## 環境

測定機はIntel Core Ultra 7 265KF（性能コア8個と高効率コア12個、20スレッド）である。
ほかの対局測定、SPSA、教師生成、および学習は動いていなかった。lishogiのBotは止めておらず、探索速度はBotのエンジンが動いていない間にだけ測った。

## 結果

### 探索ノード数

15局面の合計は次のとおりである。「一致」は、全15局面の3つの深さで、探索ノード数、評価値、および最善手が直前のコミットと一致したことを表す。

|---|---|---:|---:|---:|---|
| 起点 | `370f7077` | 13,044 | 32,833 | 71,514 | — |
| T10（反復数の係数化） | `678c7eaf` | 13,044 | 32,833 | 71,514 | 一致 |
| T5の入力 | `7b78b1b9` | 13,044 | 32,833 | 71,514 | 一致 |
| 伸縮の枠組みとT1 | `fcd99662` | 13,044 | 32,833 | 71,514 | 一致 |
| T2 | `03eaa9f9` | 13,044 | 32,833 | 71,514 | 一致 |
| T3 | `fab1905a` | 13,044 | 32,833 | 71,514 | 一致 |
| T4 | `95c56622` | 13,044 | 32,833 | 71,514 | 一致 |
| T5の因子 | `56eba424` | 13,044 | 32,833 | 71,514 | 一致 |

全13コミットで、全15局面の3つの深さの探索ノード数、評価値、および最善手が起点と一致した。
根の探索に加えた最善手の変化の計数（T3）と、窓の読む深さに加えたT7の項（固定深さの探索では回数が0なので項も0）は、固定深さの探索を変えなかった。

### 探索速度と最大常駐メモリ

| minase | 深さ9の探索ノード数 | 時間の中央値（秒） | NPSの中央値 | 最大常駐メモリ（KB） |
|---|---:|---:|---:|---:|
| 起点`370f7077` | 190,601 | 0.2333 | 816,839 | 507,368 |
| 最後`975876ee` | 190,601 | 0.2337 | 815,623 | 507,016 |

1つのコアに固定したNPSは0.15%下がった。3回の測定の範囲（起点816,688〜817,640、最後814,128〜816,717）は重なっており、差は測定の揺れと区別できない。
最大常駐メモリは変わらなかった。

### 係数の既定値を動かしたテスト

1/3の表では、両方の検査が全テストを通った。
2/3の表では、`ponder_rechecks_pre_hit_iterations_once_and_checks_hard_first`の1件が失敗した。
このテストは、的中前の詰みの記録が次の完了反復で偽に戻った後、的中しても止まらないことを確かめる場合を含む。開始時刻600 msの反復の予測の当て直しが、`IterationRatio`の既定値（203%）では収まり、2/3の値（316%）では収まらなかったので、詰みの記録とは関係なく止まっていた。
反復の開始時刻を、`IterationRatio`の範囲（150〜400%）のどの値でも当て直しを通る300 msに直した（`975876ee`）。修正の後は、1/3と2/3の表のどちらでも全テストが通った。
`68d3a4d4`で加えたテストを含めて、1/3と2/3の表で検査をやり直し、どちらも全テストが通った。

## 結論

本書の形の変更は固定深さの探索を変えず、探索速度とメモリも変えなかった。係数の既定値に依存していたテストは1件であり、SPSAの前に直した。

# time-management-decomposition-d1-stc

## 目的

[持ち時間の効率的な使用](../plans/time-management-efficiency.md)の「分解測定」が定める候補D1（第0段階、第1段階、置換表の2修正）の段階ゲートのSTCである。
比較対象は共通基準B′（着手前の構成に置換表の2修正を加えたもの）である。

## コマンドライン

```console
target/release/match_runner --run-dir data/matches/time-management-decomposition-d1-stc --seed 20270917 \
  --candidate commit:2f72a52 --baseline commit:ae1c59b \
  --concurrency 16 --each time=10000+100 gsprt --max-pairs 3000
```

## エンジン

候補はコミット2f72a52（ブランチ`tm-decomp-d1`）、基準はコミットae1c59b（ブランチ`tm-decomp-base`）、規則セットは`L0,P0,R1,E0`、両側の`Threads`は1、`USI_Hash`は256 MBである。

## 環境

CPUはIntel Core Ultra 7 265KF（物理20コア、論理20コア）、同時対局数は明示した16である。
他の測定は走っておらず、負荷平均は15〜16であった。

## 結果

判定は`H0`であり、有効260ペアでLLRは−2.954（境界−2.944）に達した。
ペンタノミアル度数は[85, 10, 120, 5, 40]である。
実行した278ペアのうち18ペアは手数上限4,096手への到達により破棄した。
556局の手数は54〜4,096手（中央値416手）である。
時間切れ、不正着手、クラッシュ、応答タイムアウト、拒否着手はすべて0件、累計実行時間は2,711秒であった。

判定前の306局（153ペア）の保存記録から、候補と基準の到達深さ、1手の思考時間、着手前の残り時間を手数帯ごとに比べた中央値（深さは平均）は次のとおりである。

| 0〜50 | 6.00 | 6.94 | 81 ms | 122 ms | 10.3 s | 9.7 s |
| 50〜100 | 5.94 | 6.44 | 131 ms | 131 ms | 10.2 s | 8.8 s |
| 100〜200 | 6.08 | 6.51 | 132 ms | 132 ms | 9.7 s | 7.2 s |

| 600以上 | 15.28 | 15.53 | 91 ms | 81 ms | 7.1 s | 4.5 s |

1局の総思考時間の中央値はD1が23.7秒、B′が27.6秒で、終局時の残り時間の中央値はD1が6.7秒、B′が2.8秒である。
D1の完了深さは途中結果を採用した反復を数えないので、同じ思考時間でも基準より約0.5浅く報告される点に注意が必要である。

## 結論

第1段階だけの構成は基準に有意に劣る。
不採用の最終候補が持ち時間を使い切ったのとは逆に、D1は予算を公平な分担そのものにしたため、旧式が最後の反復を完了させる超過で実質的に使っていた時間（総思考時間で約14%）を使い残す。
序盤の係数は0〜50手で到達深さを約0.9浅くしており、この影響は設計書のとおりD2で切り分ける。
設計書の判定規則に従い、D2を測る。

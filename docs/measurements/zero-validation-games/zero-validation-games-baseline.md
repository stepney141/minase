# 固定の検証用データの作成と、1回目の実行のネットおよび2回目の初期ネットの基準の診断

## 目的

[固定の検証用データの設計書](../../plans/archived/zero-validation-games.md)のフェーズ1とフェーズ3として、オンライン対局サイトlishogiの人間同士の中将棋の棋譜から固定の検証用データを作り、AlphaZero型探索のネットを診断した。
AlphaZero型探索のネットは、自己対局の生成とネットの学習からなるサイクルを繰り返す強化学習で育てる。
強化学習の1回目の実行はサイクル32で中断し、2回目の実行で初めからやり直す。サイクル0のネットは、学習の前のランダムに初期化したネットである。
診断したネットは、1回目の実行のサイクル0、10、20、および32のネットと、2回目の実行のサイクル0のネットである。
目的は、2回目の実行のネットの診断の値と並べて読む基準を求めることであり、ネットの採否を判定するものではない。

## コマンドライン

測定日は2026年11月15日である。
検証用データは、ブランチ`zero-validation-games`のコミットb59eb37c80e675390d45a5077275ba093af8acdfで作った。
選別のスクリプトはworktreeのルートで実行した。
続く`minase`は、同じコミットを変更のない状態で別のディレクトリに取り出し、そこで、そのコミットと同じソースからビルドしたバイナリを実行した。
`<D>`はNASの`/mnt/synology_nas/minase/alphazero/validation`である。

```console
python3 scripts/select_validation_games.py --input /home/stepney141/board-games/minase/data/lishogi/games.ndjson \
  --output <D>/selected.ndjson --report <D>/selection.json
target/release/minase data lishogi validation --input <D>/selected.ndjson \
  --output <D>/zero-validation-games.mnsd --report <D>/replay.json --seed 20261113
```

診断は、worktreeの`tools/train/zero`で、ネットごとに次のコマンドを順に実行した。
`<A>`はNASの`/mnt/synology_nas/minase/alphazero`、`<チェックポイント>`と`<名前>`は「道具とネット」の節の表のとおりである。
作業機で別の対局が動いていたので、`systemd-run --user --scope -p MemoryMax=8G -p MemorySwapMax=0 nice -n 19`の下で実行した。

```console
uv run --frozen --no-sync python -m minase_zero external-eval --checkpoint <チェックポイント> \
  --data <A>/validation/zero-validation-games.mnsd --device cuda \
  --out <A>/external/zero-validation-games/<名前>.json
```

## 道具とネット

道具は、コミットb59eb37cに含まれる3つである。
棋譜を選ぶ`scripts/select_validation_games.py`、選んだ棋譜を再生して照合し、MNSDの形式で書き出す`minase data lishogi validation`、および検証用データでネットを診断する`minase_zero external-eval`である。
MNSDは、minaseの教師データの形式であり、検証用データは教師の種類を探索なしとして記録する。
入力の棋譜は、`scripts/fetch_lishogi_games.py`で取得した`data/lishogi/games.ndjson`（31,796,374バイト、23,567行、SHA-256 `58bbec58dd05005f697999a1555039c76399944ea14dea0030c4d37040834b5f`）である。

1回目のネットは、日本中将棋連盟の規則に基づく規則セット`JCSA`の自己対局で学んだものである。
検証用データは規則セット`lishogi`の対局なので、1回目のネットの診断の値には、規則の違いによる影響が含まれる。

データを作った後のコードのレビューで、選別のスクリプトを2点直した（コミット9a88a713）。
1つは、Botの肩書きを持つアカウントを、棋譜の全体のどこかで肩書きを付けて現れたアカウントとして除くことであり、もう1つは、改行で終わらない行と、取り込みの道具が読めない値を入力の誤りとすることである。
入力の棋譜には、肩書きを省いて現れたBotのアカウントも、そうした行や値もないので、直したスクリプトで作り直しても、`selected.ndjson`と`selection.json`のチェックサムは変わらなかった。

## 環境

CPUはIntel Core Ultra 7 265KF（20コア、20スレッド）、GPUはNVIDIA GeForce RTX 3060 Ti（ドライバ615.78.08）、PyTorchは2.11.0+cu130である。
診断はfp32で、128局面ずつ推論した。
診断の間、作業機では持ち時間つきの対局が同時8局で動いていた。診断は時間に依存しない処理なので、価値の損失と一致率の値はこの負荷の影響を受けない。

## 結果

### 検証用データ

選別では、23,567局のうち22,756局を次の理由で除き、811局を選んだ。
除外の条件は表の上から順に調べ、除いた対局は最初に当てはまった理由1つだけに数えた。
選別の条件には、中将棋でない対局、lishogiに内蔵されたAIとの対局、および勝者のない対局も含まれるが、どれも該当が0局だったので、表から省いた。

| 除いた理由 | 対局 |
|---|---|
| 初期局面の指定がある | 459 |
| 匿名の対局者がいる | 1,818 |
| Botのアカウントが対局者にいる | 8,836 |
| レート戦でない | 2,758 |
| レーティングがない、暫定である、または1600未満である | 7,779 |
| 終局の理由が投了、王駒の捕獲、裸玉の裁定のどれでもない | 304 |
| 40手未満である | 72 |
| いずれかの対局者の採用済みの対局が100局に達していた | 730 |

Botの肩書きを持つアカウントは、入力の棋譜の全体に13個あった。
対局者ごとの上限（100局）を適用する前の候補は1,541局、対局者80人で、最も対局の多い1人が477局（31.0%）に関わっていた。
選んだ811局は、対局者79人、最も対局の多い1人が100局（12.3%）に関わり、手数の合計は164,504手である。
811局すべてが規則セット`lishogi`の再生で記録と一致し、手の解析か適用の失敗、最後の手より前の終局、および最後の手の後の状態の不一致は、どれも0局であった。
MNSDに書いた検証用データは、811局、165,315項目からなる。項目は局面ごとの記録であり、指した手を持つ項目が164,504件、各対局の最後の手を指した後の局面の項目が811件である。診断には、指した手を持つ項目だけを使う。

同じ手順で作り直すと、4つのファイルがすべてバイト単位で一致した。
選別の報告（`selection.json`）と照合の報告（`replay.json`）は、[この記録の付随ファイル](zero-validation-games-baseline/)にも写した。

### 診断

価値の損失は、ネットが出した手番側の勝率と対局の勝敗の交差エントロピーであり、勝敗を常に五分と予測すると約0.693になる。
一致率は、ネットの方策で確率の最も高い合法手が人間の指した手と一致する局面の割合である。
どちらも1局の中で平均してから対局の間で平均した値であり、診断の出力は[付随ファイルの`external/`](zero-validation-games-baseline/external/)にある。

| ネット | 価値の損失 | 一致率 |
|---|---|---|
| 1回目のサイクル0 | 0.6934 | 0.96% |
| 1回目のサイクル10 | 0.6848 | 3.32% |
| 1回目のサイクル20 | 0.6405 | 8.10% |
| 1回目のサイクル32 | 0.6255 | 11.38% |
| 2回目のサイクル0 | 0.6932 | 0.77% |

手数の帯ごとの値は次のとおりである。
局面の手数は、その局面で指された手が初手から何手目にあたるかで表す。
各帯に局面が含まれる対局の数は、1〜40手目が811局、41〜100手目が808局、101〜200手目が677局、201手目以降が390局であり、局面の数は順に32,440、44,978、54,073、および33,013局面である。

|---|---|---|---|---|
| 1回目のサイクル0 | 0.6934 | 0.6935 | 0.6936 | 0.6937 |

1回目のサイクル32のネットをもう一度診断すると、全体と帯のすべての値が最初の診断と一致した。

## 結論

1回目の実行のネットでは、サイクル0からサイクル32にかけて、一致率が0.96%から11.38%へ上がり、価値の損失が0.6934から0.6255へ下がった。
設計書は、学習の進んだネットで一致率が上がることを検証の条件としており、この条件を満たしたので、この値を2回目の実行の値と比べる基準とする。
サイクル10の1〜40手目と41〜100手目の価値の損失は、五分と予測する場合の約0.693を上回っており、学習の初めのネットの勝敗の予測は、序盤から中盤の局面では五分の予測より悪かった。

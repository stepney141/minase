# 審判ロジック再編とR0撤去の設計書（第2版）

## 実施状況

本マイルストーンは未着手である。
2026年8月3日の探索着手前監査に基づき、同日に本設計書を作成した。
同日の設計レビューを受けて第2版へ改版し、R2の緩和方式を新規則コードR3として実装対象へ加え、`Position::zobrist()`のrustdoc更新と`Game::legal_moves`の署名方針を明記した。

## 目的

本マイルストーンは、日本中将棋連盟式千日手（R0）を実行可能な規則から撤去し、探索部と対局管理層が共有できる審判ロジックを整備する。
R0の規則本文と典拠は記録として`RULES.md`に残すが、Rustの型、規則コード、状態、分岐および公開APIでは表現しない。
また、R2の緩和方式（既出局面の4回目の再現だけを禁止する方式）を、新しい規則コードR3として実装可能な反復規則へ加える。

併せて、麒麟成獅子同一升例外（L2）とLishogi式4回反復裁定（R1）について、探索着手前監査で確認した不具合を修正する。
現在のテスト189件は全緑だが、この2件を検出する回帰テストがないため、テスト成功だけでは探索へ進む条件を満たさない。

本マイルストーンはプロトコル層と探索部のどちらにも依存しない。
完了後は、`Game`を対局の所有者として維持しつつ、探索部が`Position`と共有審判ロジックを直接利用できる。

## 適用範囲

本マイルストーンでは、次の作業を行う。

- L2の麒麟成獅子同一升例外を、対象となる新しい獅子だけに限定する。
- 先獅子トリガーの対象升をZobristハッシュへ含める。
- R1の実着手と仮想着手で、攻撃連続数の遷移を共通化する。
- R0に対応するRustコードとテストを削除する。
- R2の緩和方式を新しい規則コードR3として実装し、`RULES.md`を第9版へ改版する。
- R1の終局裁定とR2・R3の対局合法手フィルタを`Game::play`から分離する。
- 王駒捕獲、駒枯れ、合法手なしおよび詰みの裁定を、明示的な状態を受け取る関数へ分離する。
- `RULES.md`、`docs/ROADMAP.md`および後続設計書から参照される実装契約と、ハッシュ契約を記述する`Position::zobrist()`のrustdocを更新する。

プロトコル、棋譜入出力、`Game`のundo、探索アルゴリズム、評価関数および性能最適化は対象外とする。

## 設計判断

| 項目 | 決定 |
|---|---|
| R0 | `RULES.md`の記録だけに残し、Rustコードでは表現しない。 |
| 実装する反復規則 | R1、R2およびR3を実装し、同時採用を禁止する。 |
| R2の緩和方式 | 既出局面の4回目の再現だけを禁止する方式を、R2の意味を変えずに新コードR3として実装する。 |
| 反復規則の未指定 | `Rules`では許すが、`Game`の構築時に明示的なエラーとする。 |
| エンジン既定 | R1を明示的に採用する。 |
| 合法手の責務 | `MoveGenerator`は局面合法手を生成し、審判層はR2を含む対局合法手を決める。 |
| 局面キー | R1用のキーとR2・R3共用のキーを別型とし、現行の64ビットZobrist衝突リスクは許容する。 |
| 任意局面からの開始 | 渡された局面を履歴上の第1回とし、過去履歴の注入APIは追加しない。 |
| 初期裁定 | `Game::from_position`では自動裁定せず、現行契約を維持する。 |
| 探索内の循環 | 規則上の4回反復と分離し、本マイルストーンでは早期打切りを実装しない。 |
| 互換性 | R0の別名、予約`variant`、欠番維持、黙殺およびR1への暗黙変換を設けない。 |

## L2の適用範囲

現行のL2判定は、先獅子トリガーが麒麟成りによることと、捕獲対象が成駒であることだけを確認している。
トリガーの対象升を比較しないため、同時に盤上に存在する別の既存成獅子にも例外が及ぶ。

L2の例外は、捕獲対象の升が`LionTrigger::square`と一致する場合だけに適用する。
既存の不成獅子に加えて、既存の成獅子が例外にならないことを条文テストで固定する。

この修正により、先獅子トリガーの対象升が次の合法手を左右する。
第24条第1項cとの一致を保つため、`Position::zobrist()`はトリガーの有無、対象升および麒麟成りフラグを区別しなければならない。
増分更新、再計算およびmake/unmakeの3経路で同じ値を得ることを検査する。

## R1の攻撃連続数

現行の実着手処理は、攻撃的着手なら手番側の連続数を1増やし、非攻撃的着手なら0へ戻す。
第21条第3項cの仮想着手処理は加算だけを行うため、実着手と異なる状態をR1裁定へ渡す。

攻撃連続数の更新は、現在値、手番側および攻撃的着手かどうかを受け取り、更新後の値を返す純粋関数へ分離する。
実着手と仮想着手は同じ関数を使用する。

回帰テストでは、相手側だけが反復区間を通じて攻撃を継続し、手番側の第4回目を生じさせる候補手が非攻撃的である局面を構成する。
候補手によって手番側の連続数が0となり、相手側の継続攻撃による手番側の勝利が第21条第3項cの詰み逃れとして認識されることを検査する。

## R3の新設

R2の緩和方式を、新しい規則コードR3として実装する。
E1は厳格形式を原則として記述したうえで、人間の見落としを許容するために4回目の出現だけを禁止する形へ緩和されるのが通例であると記す。
緩和の動機は計算機実装に当てはまらないため、R2の意味は厳格形式のまま変更しない。

R3が禁止するのは、既出局面の4回目の出現を生じさせる着手だけである。
2回目と3回目の再現は合法とし、禁止着手は第27条第4項に従い第26条第11項の不合法な着手として扱う。
同一局面の判定はR2と同じく第24条第1項aからcまでで行い、同項dは循環回避のため除外する。
王手を受けている側への適用除外は、R2と同様に採用しない。

`RULES.md`は第9版へ改版する。
第31条へR3の行を追加し、R2の行にある緩和方式の文言をR3の行へ移し、第25条、第27条および第33条の排他と表示の規定を連動して修正する。
R3の典拠はE1であり、E2の4回目への言及は日本中将棋連盟式の裁定に掛かる文であることを典拠欄に注記する。

## 規則構築の契約

`Rules::standard()`は、ローカル差分のない規則集合を返す。
ただし、R0を実装しないため、この値は実行可能な反復規則を含まない。
`MoveGenerator::standard()`は履歴を必要としないので、引き続きこの値を使用できる。

`Rules::repetition_rule()`は`Option<RepetitionRule>`を返す。
R1、R2またはR3を含む場合は対応する値を返し、いずれも含まない場合は`None`を返す。

`Game::new`と`Game::from_position`は`Result<Self, GameBuildError>`を返す。
反復規則が未指定の場合は`GameBuildError::MissingRepetitionRule`を返し、R1へ置き換えない。
`GameBuildError`は公開型としてcrate rootから再公開する。
`Rules::engine_default()`はR1を含むため、`Game::with_default_rules()`は`Self`を返す無謬の構築関数として残す。

`RuleCode::R0`と`RepetitionRule::R0`を削除する。
`RuleCode::ALL`は、R0を除きR3を加えた、実装で選択できる13コードだけを含む。
`RuleCode`の`repr(u8)`値はR0以後で変化するが、旧値を維持する欠番は残さない。

## 合法手の用語

本設計書では、履歴依存性の異なる2種類の合法手を区別する。

- **局面合法手**：`Position`、`Rules`および`MoveGenerator`だけから決まる着手である。
- **対局合法手**：局面合法手から、R2またはR3が禁止する反復着手を除いた着手である。

`Position::try_make_move`は局面合法性だけを検査する。
`Game::play`と`Game::legal_moves`は対局合法性を検査する。
終局後の着手禁止は対局状態の制約であり、`MoveGenerator`へは組み込まない。

R2の中核判定は着手適用後の局面キーが履歴に存在するかどうかを調べ、R3の中核判定はそのキーの出現回数が既に3回に達しているかどうかを調べる。
`Game::play`は着手を1回だけ適用してこの判定を行い、禁止局面なら着手を取り消してエラーを返す。
着手列を絞り込む共有関数は候補手を一時的に適用し、同じ中核判定を呼んでから必ず局面を復元する。
共有関数は`&mut Position`を受け取る。
`Game::legal_moves`は公開署名の`&self`を維持し、内部で1回だけ複製した局面を共有関数へ渡す。
`Game::legal_moves`、合法手なし判定および詰み判定は、この共有関数を使用する。

## 反復状態

反復状態は反復規則ごとに用途が異なるため、1つの`HashMap<u64, RepetitionState>`を兼用しない。
内部表現は、R1、R2およびR3だけを持つ`enum`とする。

```rust
enum RepetitionHistory {
    R1(R1History),
    R2(R2History),
    R3(R3History),
}
```

`R1History`は、局面ごとの出現回数と最初の出現手数、および双方の攻撃連続数を保持する。
`R2History`は既出局面の集合だけを保持する。
`R3History`は局面ごとの出現回数だけを保持する。
R0用`variant`、未使用フラグおよび将来の反復方式を差し込む`trait`は追加しない。

R1のキーと、R2およびR3が共用するキーは別型とする。
R1用キーは`Position::zobrist()`と`Position::rights_zobrist()`を別フィールドで保持し、XORによる成分の混同を避ける。
R2・R3用キーは第24条第1項dを除外するため、`Position::zobrist()`だけを保持する。

本マイルストーンでは、Zobrist値の衝突を実用上無視できるという現行の前提を維持する。
完全な局面署名による照合は追加しない。
この前提は対局裁定にも適用されるため、rustdocと設計書に明記する。

## 審判状態

対局の履歴依存状態は、`Game`の個別フィールドではなく、名前を持つ内部状態へまとめる。

```rust
struct AdjudicationState {
    repetition: RepetitionHistory,
    piece_exhaustion_grace: bool,
    ply: u32,
}
```

`Game`は`Position`、`MoveGenerator`、`AdjudicationState`および終局結果を所有する。
`repetition_rule`、`mate_adjudication_enabled`および`piece_exhaustion_disabled`のように`Rules`または反復状態から導出できる重複フィールドは削除する。

`is_mate`が受け取るR2禁止判定と即時勝利判定は、現在`Option<&dyn Fn(...)>`として表現されている。
このコールバックは規則上の意味を型から読み取れないため、`AdjudicationState`と`Rules`を参照する名前付きの内部コンテキストへ置き換える。

探索専用の履歴`push`と`pop`、履歴差分トークンおよび置換表用の表現は追加しない。
探索部の設計時に、実際の探索経路と測定結果に基づいて決定する。

## 裁定関数

副作用を必要としない規則判定は、入力値から結果を返す内部関数へ分離する。
対象は次のとおりである。

- R1の攻撃連続数の遷移。
- R1の第4回目の反復結果。
- R2の既出局面再現判定。
- R3の4回目の出現を生じさせる着手の判定。
- 王駒捕獲による勝利。
- 駒枯れの成立と1手猶予の次状態。
- 合法手なしによる敗北。
- 詰みと第21条第3項cの即時勝利。

`piece_exhaustion_outcome`と`r1_repetition_result`は既に副作用のない形に近いため、審判モジュールへ移す。
`captures_last_royal`、`has_no_legal_move`および`is_mate`も同じ責務の下へまとめる。

`Game::play`は、入力を検証して状態遷移を確定する境界として残す。
処理順序は次のとおりとする。

1. 終局済みでないことと局面合法性を検査する。
2. 着手を適用し、R2またはR3の禁止局面なら着手を取り消してエラーを返す。
3. 手数と反復履歴を更新する。
4. 王駒捕獲、R1、駒枯れ、合法手なし、詰みの順に裁定する。
5. 終局した場合は結果を`Game`へ保存する。

投了と合意引き分けは盤面から導出されないため、`Game`に残す。

## 任意局面と履歴

`Game::from_position`は、渡された局面を手数0の第1回出現として記録する。
局面より前の着手履歴を推定せず、履歴を直接注入する公開APIも追加しない。

Universal Shogi Interface（USI）またはChess Engine Communication Protocol（CECP）から`position ... moves`相当の入力を受ける場合は、基点局面から`Game::play`で着手を再生して履歴を構築する。
中断対局の永続化形式はプロトコル層の設計で扱う。

`Game::from_position`は、王駒が既に存在しない場合や、駒枯れ条件を満たす場合でも、その場では自動裁定しない。
規則レベルの局面妥当性は呼び出し側の責任とする現行契約を維持する。
探索部は進行中の`Game`から得た局面だけを通常の探索開始点とする。

## 探索部との境界

探索部は`Game::play`を探索木の各節点で呼び出さない。
探索開始時に`Position`と必要な審判状態を受け取り、局面のmake/unmakeと共有裁定関数を利用する。
最善手が確定した後、対局管理側だけが`Game::play`を1回呼び出す。

規則上のR1は、第4回目の同一局面でのみ裁定する。
探索木内の2回目の循環を打ち切る方策を導入する場合は、探索上の評価として別に設計し、`GameResult::Repetition`を流用しない。

同じ`Position`でも反復履歴によって対局合法手と終局結果が変わる。
置換表のキーまたは再利用条件に履歴をどう反映するかは、探索部の設計書で決定する。

## 記録として残す規則

`RULES.md`では、R0の表、規則全文および典拠を削除しない。
R0は日本中将棋連盟式千日手の記録用識別子であり、Minaseの`RuleCode`ではないことを明記する。

第25条、第27条、第31条および第33条には、規則文書上のR0と実装で選択できるR1、R2およびR3の差を反映する。
文献上の標準規則がR0を採用する事実は保持し、Minaseで対局を開始する場合はR1、R2またはR3の明示を必須とする。

完了済み設計書は当時の実施記録として保持する。
`game-referee.md`、`local-rules.md`および`movegen-hardening.md`の冒頭には、本設計書によってR0のコード表現が後から廃止されたことを示す短い失効注記だけを追加する。

## 既知の規則上の曖昧さ

次の先獅子に関する論点は、R0とは独立して未解決である。

- 1手で獅子を2枚取る場合の先獅子トリガー升。
- 取った側に獅子が複数残る場合の禁止対象。
- 先獅子中に、制限側の獅子が隣接する相手獅子を取り返す着手。

本マイルストーンでは文献調査と規則変更を行わず、現行解釈を維持する。
L2の対象升比較は、麒麟が1枚の獅子を取って成る規定だけを修正するため、この未解決範囲を拡張しない。

## 実装フェーズ

実装は、挙動修正と構造変更を混在させないように5フェーズへ分ける。

### フェーズ1　L2とR1の修正

L2の対象升判定と先獅子トリガーのZobristハッシュを修正する。
`Position::zobrist()`のrustdocにある捕獲升を含めない旨の記述を、新しいハッシュ契約へ書き換える。
R1の攻撃連続数遷移を抽出し、実着手と仮想着手で共有する。
各不具合について、修正前に失敗する最小の条文テストを追加する。

### フェーズ2　R0の撤去

`RuleCode::R0`、`RepetitionRule::R0`、`RepetitionDetection`、R0用フィールド、分岐およびテストを削除する。
反復未指定を表す`Option`と`GameBuildError`を導入し、`Game`構築APIを更新する。
R3を`RuleCode`と`RepetitionRule`へ追加し、`RULES.md`を第9版へ改版して実装対応範囲とR3の規則を反映する。

### フェーズ3　反復層の分離

R1のキーとR2・R3共用のキーおよび履歴型を分離する。
R1裁定、攻撃連続数遷移およびR2・R3の禁止判定を`Game`から反復モジュールへ移す。
R2・R3の共有フィルタを`Game::play`、`Game::legal_moves`、合法手なし判定および詰み判定から利用する。

### フェーズ4　審判層の分離

駒枯れ、王駒捕獲、合法手なし、詰みおよび即時勝利を審判モジュールへ移す。
意味が不明瞭なコールバックを名前付きコンテキストへ置き換え、`Game::play`を状態遷移の調整に限定する。

### フェーズ5　文書と回帰検証

完了済み設計書へ失効注記を加え、`docs/ROADMAP.md`の現在地を更新する。
全テスト、静的検査、書式検査、perft自己回帰および作業ツリー保護を確認する。

## 検証

条文テストでは、次の境界を直接検査する。

- L2が新しい麒麟成獅子だけを例外とし、別の既存成獅子を例外にしない。
- 先獅子トリガーの対象升が異なる局面は、盤面と手番が同じでもZobrist値が異なる。
- 先獅子トリガーの増分更新、再計算およびunmakeが一致する。
- 非攻撃的なR1候補手が手番側の攻撃連続数を0へ戻す。
- R1の実着手と仮想着手が同じ入力に対して同じ次状態を返す。
- R1、R2およびR3のいずれも指定しない`Game`構築が`MissingRepetitionRule`を返す。
- R1、R2およびR3のうち2つ以上の同時指定が競合として拒否される。
- R3では既出局面の2回目と3回目の再現が合法であり、4回目の出現を生じさせる着手だけが拒否される。

統合テストでは、次の性質を検査する。

- 共有R2・R3フィルタと`Game::legal_moves`の着手集合が一致する。
- R2またはR3で拒否された着手の前後で、局面、履歴、手数および駒枯れ猶予が変化しない。
- 仮想裁定の前後で、局面と審判状態が完全に復元される。
- R1、R2、R3、E1およびE2の有効な全組合せで、裁定順序と終局理由が維持される。
- 同一の局面と履歴に対して、共有裁定関数と`Game::play`が同じ結果を返す。

初期局面perftの深さ1から4までの自己回帰値は、`36`、`1,296`、`48,315`、`1,801,639`とする。
これらは外部オラクルではなく、局面合法手の意図しない変化を検出する基準である。

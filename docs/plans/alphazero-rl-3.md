# 学習済みネットを拡張して行う3回目の強化学習

## 先に読む要約

本書は、中将棋エンジンminaseの3回目の自己対局学習の案である。
自己対局では、方策と勝率を予測するニューラルネットワークでモンテカルロ木探索を導き、約100万局面を生成して学習するまでを1サイクル、すなわち1世代と数える。
2回目の自己対局学習のサイクル100の重みを引き継ぎ、1回目のサイクル32の強さを超えることを目指す。
学習率を各サイクルで0.01から0.001へコサイン減衰させ、1回の更新に使うバッチを256局面、新しく生成した訓練局面数に対する学習量を4倍にする。
勝率を出す価値ヘッドを1チャネルから32チャネルへ広げ、盤面全体の升の情報を交換するglobal broadcasting blockを2個追加する。
移行直後の予測を保つように追加部分を初期化し、その後はネット全体を学習する。
学習用に保持する過去の対局をリプレイバッファと呼び、その範囲を直近4万局、現在の生成量で約20世代に縮める。
自己対局の探索は1手32回から64回へ増やし、生成できる対局数と教師の質の両方を測る。
GPUを借りるサービスvast.aiの費用上限を合計100米ドルとし、短時間で終えることより到達する棋力を優先する。
実装と実験の着手は別途決め、着手後は対局測定による採否と費用を記録して完了する。

## 状態

2026年11月18日に起案した計画であり、実装と第3回の実験には未着手である。
過去2回の記録と先行研究に基づいて、学習設定、ネット拡張、リプレイバッファ、および検証方法を提案する。
次は設計内容を確認し、実装と実験の着手を決める。

## 目的

追加の100米ドルで到達できる棋力を高め、1回目のサイクル32のネットを超えることを目指す。
2回目のサイクル100を出発点の基準とし、追加の学習標本数、経過時間、および費用に対する改善を記録する。
今回は既存の重みを引き継ぐため、ランダム初期化から学習した過去2回との差を、新しい設定だけの効果とは解釈しない。
今回は複数の変更を組み合わせる実験であり、個々の変更の因果効果を分離する実験でもない。

[2系列の調査](../research/alphazero-rl-2-efficiency.md)では、1回目は32サイクルで約1億2,018万標本を学習したのに対し、2回目は100サイクルで約9,038万標本にとどまった。
同じ人間の棋譜で測った価値の損失は終了時にそれぞれ0.6255と0.6634であり、学習標本数を揃えた途中の比較でも2回目の改善が遅れていた。
一方、2回目の固定相手との測定は16局しかなく、棋力差の大きさには不確かさがある。
このため、学習量、教師の新しさ、および価値を表現する層を見直し、実際の強さは対局で判定する。

## 適用範囲

対象はPythonの学習器、ネット定義、実行設定、および実験の準備と記録である。
推論の入出力、規則セット`lishogi`、対局結果と探索値を混ぜる価値の教師、およびGumbel AlphaZeroの探索アルゴリズムは現行の仕様を使う。
学習済み重みの移行は、この実験に向けた事前の変換処理として行い、実行時に旧構造を読み替える処理は追加しない。

## 設計判断

利用者は2026年11月18日に、一定学習率やバッチ1,024を前提にせず、棋力向上が見込める構造と学習設定へ変えること、既存の重みと自己対局データを使うこと、およびvast.aiに100米ドルまで使うことを決めた。
計算効率を求める一方、強くするための時間は惜しまないという方針である。
本書の起案と、実装や計算資源の利用の開始は分け、現段階では起案だけを行う。

| 項目 | 採る方式と理由 |
|---|---|
| 共通層と方策 | 20個の通常の残差ブロック、256チャネル、および2層の方策ヘッドを引き継ぐ。既存の重みを保ったまま拡張できるためである。 |
| 価値ヘッド | 1×1畳み込みを32チャネルへ広げ、12×12升の出力を平坦化して全結合4,608→256→1を使う。1回目の価値ヘッドも32チャネルであり、その表現力を戻す候補とする。ただし、2系列の差には他の変更もあるため、この拡張だけの効果は未検証である。 |
| 大域情報 | 通常の残差ブロック8個目と16個目の後にglobal broadcasting blockを挿入する。チェスでも使われた構造であり、プーリングより安定したという定性的な報告を根拠とする。中将棋での効果は未検証である。 |
| 学習率 | 最大0.01、最小0.001のコサイン減衰を各サイクルで行う。新しい教師に追従する更新と、サイクル末の小さい更新を組み合わせる。 |
| バッチ | 全体256、ミクロバッチ64を用いる。ミクロバッチは1枚のGPUが1回の順伝播で処理する局面数であり、GPU4枚なら各GPUが64局面を処理して1回更新する。通信とバッチ正規化への影響は実測する。 |
| 抽出 | 新規訓練局面数の4倍を学習する。新規訓練局面と同数だけを全履歴から抽出していた2回目より、生成した教師の利用を増やす。 |
| 履歴 | 最新のサイクルから遡り、検証用も含めて合計4万局以内に収まるサイクルを丸ごと使う。既存の局数による上限を使い、対象期間を固定する別の仕組みは増やさない。 |
| 探索 | 本実験では1手64回を用いる。32回と128回も短い診断で比較するが、128回への変更はその結果に基づく別の設計判断とする。 |
| 補助目標 | 今回は方策と価値の損失を使う。補助目標の再導入は教師の読み取り処理も変えるため、本実験の結果を見て次回以降の候補とするか判断する。 |

画像分類のResNetに対するコサイン減衰の報告は、自己対局での最適な再始動周期を直接定めるものではない。
ここでは、サイクル末の重みで次の教師を作る方式と、1回目の学習の経過を根拠に、サイクルごとに減衰させる。
最大0.01は1回目の値を引き継ぎ、バッチを1,024から256へ変える際に2回目の0.04を比例して下げた値とも一致する。
下限を0にしないのは、教師が変化し続ける学習で末尾の更新も残すためであり、0.001が最適かどうかは未検証である。
バッチを小さくして学習率を比例して下げても、大きいバッチと同一の軌跡になるわけではないので、速度と損失を別に測る。
同じ新規局面数なら、2回目に比べて学習標本数は4倍、更新回数は約16倍になる。
通信とバッチ正規化の条件も変わるため、時間がこの倍率で増えるとは仮定しない。

## リプレイバッファの範囲

直近4万局は、新しい教師を早く反映させるための初期値であり、一般に定まった最適値ではない。
2回目は150万局の上限に届かず、サイクル100でも1〜100の全履歴が抽出対象だった。
最新サイクルの訓練局面は全体の1.07%、サイクル1〜50は50.18%を占め、局面数で重み付けした平均の古さは49.79サイクルだった。
古い局面にも多様性を保つ役割はあるが、この割合では新しい探索方策が教師全体に反映されるまで長くかかる。
これが停滞の原因の1つだという仮説を採り、全履歴を抽出対象に含める設定を見直す。

先行例にも、共通の「何世代」という基準はない。
[AlphaGo Zeroの論文](https://ai6034.mit.edu/wiki/images/Nature24270_AlphaGoZero.pdf)は直近50万局を使い、自己対局の1反復を2万5,000局とするので、生成量では20反復分に相当する。
ただし生成、最適化、およびネットの評価は非同期に進むため、異なる20個のネットが生成したデータだけを保持する、という意味ではない。
[ELF OpenGoの補足資料](https://proceedings.mlr.press/v97/tian19a/tian19a-supp.pdf)も50万局を使い、通常は25個を超えるモデルの対局が混ざると報告する。
[KataGoの抽出処理](https://github.com/lightvector/KataGo/blob/d91ea855110dae533f0aada947b2b7d78cc8a4e1/python/shuffle.py#L414-L435)は累計局面数のべき乗で履歴の範囲を増やし、固定の世代数を使わない。
したがって、20世代前後には参考になる先例があるが、minaseの最適値を保証する根拠にはならない。

サイクル100の保存記録に4万局の上限を当てると、サイクル79〜100の22世代、39,683局、19,295,918訓練局面が対象になる。
最新の967,579訓練局面の割合は約5.01%となる。
1世代あたりの対局数は棋力や投了までの手数で変わるため、実装では既存の局数上限を使い、対象の世代数、平均の古さ、最新世代の比率も毎回記録する。
除外した古い教師は保存し続け、学習に抽出する範囲だけを変える。

履歴の長さと、1サイクルの学習量は別に管理する。
各世代の訓練局面数がほぼLで、直近G世代からrL標本を一様に抽出する場合、新しい局面が最初の学習で選ばれる確率は約r/Gになる。
G=20、r=4なら約20%であり、G=100、r=1の約1%より新しい教師を早く使える。
一方、直近G世代の履歴が満ちた定常状態では、1局面が抽出対象から外れるまでに使われる回数の期待値はおおむねrである。
履歴を短くする効果は、再利用の総量そのものより、利用する時期と教師の構成にある。

履歴を短くしすぎると、似た局面への過学習や、以前の局面で覚えた知識の忘却が起こり得る。
最初の比較候補を約10、20、40世代相当の2万、4万、8万局とし、実行時にどの世代まで含むかを集計する。
本線は4万局とし、固定検証集合での損失と対局成績が悪化した場合は、追加計算の前に抽出倍率と履歴範囲のどちらを変えるかを再検討する。
この比較は必要になった時点で、他の設定と開始重みを揃えて行う。

## ネットの構造と移行

global broadcasting blockは、256→256の1×1畳み込み、各チャネルで共有する144→144の全結合、および256→256の1×1畳み込みを残差接続の内側に置く。
最初の畳み込みの後はバッチ正規化とReLU、空間の全結合の後はReLU、バッチ正規化、ReLU、最後の畳み込みの後はバッチ正規化とする。
入力との加算の後にもReLUを置く。
空間の全結合は、12×12の升を行優先で平坦化した最後の次元に作用する。
バッチ正規化の設定は既存のネットに揃え、最後の正規化の倍率とバイアスを0で初期化する。
直前のブロックの出力はReLUを通って非負であり、追加した残差枝の出力は0になるため、挿入直後のブロックは恒等写像になる。
これは[Gumbel AlphaZeroの付録F.1と図11、13](https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/gumbel-alphazero.pdf)に基づく追加であり、通常の残差ブロックを置き換える同論文のネット全体と同一ではない。

価値ヘッドの1×1畳み込みは、元の1チャネルを新しいチャネル0へ移し、対応するバッチ正規化のパラメータと移動統計も移す。
価値ヘッドの1層目の全結合は、0〜143列へ旧重みを移し、追加した31チャネルに対応する列を0にする。
追加した31チャネルの畳み込み重みは乱数で初期化するため、対応する全結合の列が更新され始めると新しい特徴も学べる。
共通層、方策、および価値の最後の全結合はすべて移す。

最適化器の状態は、形が変わらない層の分も含めて移さず、重みの移行時に全体を初期化する。
移行後の更新数を0から数えて250更新のウォームアップを行い、それ以降はサイクルをまたいで最適化器と更新数を保つ。
元のチェックポイントのSHA-256、生成元のコミット、移行のシード、および移行後のパラメータ数を記録する。
20ブロック、256チャネルでは26,639,962パラメータとなり、元の25,182,204から約5.8%増える。
元のネット定義は固定したコミットから読み、一時的な変換スクリプトだけが扱う。
250更新のウォームアップは現行学習器の値を初期候補として引き継ぐ。
バッチ256では64,000標本に当たり、拡張後のネットに適した長さかどうかは試行で確かめる。

## 抽出と学習率

新規訓練局面数をL、履歴内の全訓練局面数をT、必須引数`--sample-multiplier`をrとし、抽出数をS=rLとする。
rは正の整数で、本線では4とする。
1巡ごとにT局面の一様な順列を作り、必要な長さを先頭から使う。
SがTを超えた場合は、同じ乱数生成器から新しい順列を作って続け、切り詰めない。
同じ局面を複数回学ぶ場合も、メモリには1件だけ保持し、更新の順序には必要な回数だけその局面を並べる。
抽出のシード、倍率、更新列のチェックサム、および中断時点を保存し、再開後も同じ列の続きから更新する。

サイクルの更新数をU=⌊S/256⌋とし、バッチに満たない端数を使わず、S<256ならエラーとする。
更新前のサイクル内の番号をt、移行後の累計更新数をsとし、どちらも0から数える。
U>1の学習率は次式とし、U=1では余弦の係数を1とする。

`η(t,s) = ηmax × min(1, (s+1)/250) × [0.1 + 0.9 × (1+cos(πt/(U−1)))/2]`

U>1でウォームアップを終えていれば、学習率はサイクルの先頭で最大値、末尾でその10%となる。
最初の250更新はウォームアップの係数も掛かり、短いサイクルなら次のサイクルへ継続する。
サイクルが替わるとtだけが0へ戻り、中断からの再開ではtとsの両方を引き継ぐ。
Nesterovのモーメンタム0.9、重み減衰0.0001、勾配ノルムの上限10、および価値教師の探索値の混合比0.333を使う。
上限で切り詰める前の勾配ノルムと、上限を超えた更新の割合も記録する。

## 系列と費用

生成、学習、および照合を順に行う実行器の系列名を`cycles-rl3`、参照元の配置を`cycles-rl3-base`、分岐番号を100とする。
参照元は既存教師と同じファイルシステム上に作り、自己対局の集計と教師をハードリンクで配置して、シンボリックリンクがないことを検査する。
ハードリンクも同じ実体を共有するため、配置前に教師と集計のSHA-256を記録し、配置後と学習後に変化がないことを照合する。
教師と集計は不変とし、サイクル100のネットだけを事前の重み移行と追加学習で準備する。
元の`cycles-rl2-az`のファイルは書き換えない。
新しい自己対局は101から始め、生成のシードの加算値を4×10⁸とし、既存の乱数シードの共有台帳で、使用済みの対局とシード区間が重ならないことを検査する。
移行直後のネットと、直近の教師でサイクル100の新規訓練局面数Lの4倍を追加学習したネットを別に保存する。
この追加学習を適応学習と呼び、適応学習後のネットをサイクル101の自己対局に使う。

系列のページは`docs/training/alphazero-rl-3/`、測定記録は`docs/measurements/alphazero-rl-3/`に置く。
進捗図は、元の1〜100の記録と新しい101以降の記録を連結した別の入力ファイルから作り、既存の学習を引き継いだ実験であることを明記する。
適応学習と新しい自己対局の費用をそれぞれ集計し、両方を100米ドルの上限に含める。
過去2回に支出した費用はこの上限に含めない。

100米ドルは新しい機械の導入、試行、学習、対局測定、転送、および保管の合計の上限である。
最初の試行には10米ドル以内を割り当て、その範囲で適応学習と最大3サイクルを行う。
最後の測定と回収のために5米ドル以上を確保し、必要な測定費用を見積もってから本学習の配分を決める。
GPU4枚は候補構成であり、短い試行で時間と料金を測るまで、実行できる総サイクル数は確約しない。
貸出枠の時間単価と転送料を確認し、既支出額とそのセッションの上限額の和が予算を超える機械は起動しない。
各セッションには終了期限と自己停止を設定し、成果物の回収とチェックサムの照合を終えた後に機械を削除する。
残高への入金がまだ反映されていない場合も、コードの準備は続け、利用可能な残高を超える実行は始めない。

## 実装フェーズ

1. 学習率、抽出倍率、ミクロバッチ、およびネットを変更し、CPUで入出力仕様と動作を検証する。重みの移行と、既存教師の配置を準備する。
2. 元のネットとの予測の一致、PyTorch、ONNX Runtime、およびTensorRTの出力、GPUでの勾配、中断と再開、および実行速度を確かめる。適応学習と最大3サイクルを、試行の費用上限内で回す。
3. 診断と対局結果を確認してから継続する。予算内で学習と定期的な棋力測定を行い、費用と到達した強さを記録する。

## 検証

移行の検証には固定局面集と保存済みの自己対局局面を使い、CPUの単精度で方策の正規化前の出力であるlogitの最大絶対誤差1e-5、勝率の最大絶対誤差1e-6以内を確かめる。
global broadcasting blockの恒等初期化と、価値ヘッドの追加チャネルが学習可能であることを検証する。
ネットの交換形式ONNXに出力し、CPU用のONNX RuntimeとGPU用のTensorRTで、バッチ数を変えた推論の入出力を照合する。
推論の入出力契約は変えず、Rust側の変更を前提にしない。
学習率はサイクルの先頭・中点・末尾、1更新だけのサイクル、ウォームアップの境界、および中断・再開を確かめる。
抽出は1巡未満・ちょうど1巡・複数巡の長さと、各完全な巡で全局面が1回ずつ現れることを確かめる。
CPUの試験に加え、実機ではGPU4枚、ミクロバッチ64、16ビット浮動小数点形式のbfloat16で有限の勾配と再開の一致を確認する。
再開試験ではGPUの型と枚数を揃え、コンパイル時に実行時の測定で計算方法を変えない`deterministic`設定を現行学習器から引き継ぐ。
[既存のGPUでの再開検証](../measurements/alphazero-multi-gpu/alphazero-multi-gpu-workstation.md#再開の一致2つ目の条件)に倣い、空のコンパイルキャッシュを使う別プロセスでも、抽出列、更新数、学習率、保存した重みと最適化器の状態、学習曲線、およびONNXのバイト列が一致することを条件とする。
一致しない場合は計算順序や保存状態を調べ、確認せず許容誤差を広げない。
コンパイルしたbfloat16の勾配は、有限であることに加え、コンパイルの有無による相対誤差が、同じ入力でのbfloat16と単精度の相対誤差以下であることを確かめる。

毎サイクル、最新の自己対局の検証集合でネットを診断し、固定したサイクル100の検証対局と、人間の棋譜811局も定期的に診断する。
人間の棋譜は診断だけに使う。
固定集合の損失差は対局単位の対応のあるブートストラップで95%信頼区間を求め、同じ母集団で比較する。
最初の試行で非有限の損失、出力照合の失敗、または棋譜の不整合があれば、次の自己対局を始めずに原因を調べる。
訓練損失だけが下がって検証損失が悪化する場合も、学習量の不足とは扱わず、履歴の範囲と再利用量を再検討する。
短い試行だけで最適な設定を確定したとは扱わない。

対局はネットの違いだけを比較できる条件に固定する。
両側に同じエンジンのコミットを使い、規則を`lishogi`とし、開始局面とシードを揃えて先後を入れ替えた2局を1ペアとする。
ネットはファイルのSHA-256で固定する。
最初の3サイクルの後に依存関係の節で固定した比較基準との100ペアを測り、得点率の95%信頼区間の上端が50%未満なら、次の学習を始める前に設定を再検討する。
この判定は大きな悪化を検出するための運用上の基準であり、通過を改善の証明には使わない。
その後は10サイクルを目安に、固定したminaseのαβ探索を1手500ノードで相手にして成績を記録し、深さ3の外部エンジンHaChuを副次の相手とする。
対局用のネットは1手800回探索とし、自己対局の教師を作る64回とは分ける。

最終候補は、逐次確率比検定（SPRT）の[手引き](../guides/sprt.md)に従って判定する。
帰無仮説をElo差0、対立仮説をElo差10、第1種と第2種の誤り確率を各0.05とする。
まず持ち時間10秒、1手ごとの加算0.1秒で測り、手引きの条件を満たした候補を、持ち時間60秒、1手ごとの加算0.2秒へ進める。
依存関係の節で固定した比較基準に対して、長い持ち時間の検定で対立仮説を採れば改善を採用する。
エンジン異常、時間切れ、および拒否着手は原則として0件を条件とし、外部要因による異常は手引きの「異常時の裁定」に従って原因と再集計を記録する。
1回目のサイクル32に対しても同じ条件の直接対局で判定し、こちらを超えた場合に到達目標を達成したとする。
予算内に検定が決着しなければ判定保留として記録し、十分な証拠なしに採用や目標達成としない。

## 完了条件

予算の範囲内で実行を終え、成果物を回収し、借りた機械を削除したことを確認する。
基準との対局結果、学習量、経過時間、費用、および各変更を組み合わせた実験であるという解釈上の限界を記録する。
採用した仕様をコードへ、理由を設計判断の記録（ADR）へ移し、系列の状態と進捗図を更新する。
目標の強さに到達しなかった場合も、その結果を明記して次の判断材料を残す。

# AlphaZero型探索の自己対局生成器の設計書

## 先に読む要約

本書は、[AlphaZero型探索と深層強化学習の統括計画](alphazero.md)の4本目のサブタスクであり、強化学習（RL）の学習データを作る自己対局の生成器`zero_selfplay`（サブコマンド`minase data zero-selfplay`）を実装する。
生成器は1プロセスで数百局を同時に進め、各局の探索がネットの評価を必要とした葉を複数局からまとめて1回の推論にかける。
各局の着手は、[探索方式の共存とMCTS](alphazero-mcts.md)のGumbel AlphaZeroの探索が最後に残した手とし、開始局面は初期局面から8〜16手の乱択の手順を指して作る。
対局は審判層で規則どおりに進め、手数の上限1,000手に達した対局は学習データから除き、勝率が1%を下回った側の投了は、誤った投了の割合を較正してから有効にする。
記録は教師データの形式MNSDの版2で、各局面の方策の目標、根の期待得点、および根の総訪問回数を持つ。
借りた機械が途中で止まっても続きから生成できるように、1サイクルの生成を数千局ずつの塊に分けて確定させる（借りた機械などの用語は統括計画の適用範囲の節が定める）。
完了条件は、検証の節の試験が通り、作業機で途中から再開した生成が確定済みの塊を残して欠けた塊だけを生成し直すことを確かめ、実装が統合ブランチへマージされることである。

## 目的

RLの計算の大半は自己対局の生成であり、1手あたり32回のシミュレーションの探索ではGPUの推論とCPUの木の操作のどちらも律速になり得る。
本書は、複数局の葉をまとめて推論することでGPUを埋め、RLの学習データを規則どおりの対局結果とともに記録する生成器を作る。
あわせて、投了と手数の上限で生成時間を節約しつつ、誤った勝敗や引き延ばしの退化を学習データに入れない規則を定める。

## 適用範囲

本書では、次の作業を行う。

- RLの自己対局を行う生成器`zero_selfplay`を`crates/minase/src/bin/minase/zero_selfplay/`に新設する。
- 手数の上限、投了とその較正、塊ごとの確定と再開、および塊のシードの派生を実装する。

次の項目は対象外とする。

- 探索そのもの。[探索方式の共存とMCTS](alphazero-mcts.md)で扱う。
- 生成した塊を作業機へ転送する手順と、試走および各サイクルの生成の運用。[実行環境と実現性の実測](alphazero-environment.md)と[強化学習の実行](alphazero-rl.md)で扱う。

## 依存関係

各局の探索は[探索方式の共存とMCTS](alphazero-mcts.md)のGumbel AlphaZeroの探索と、引き分けを0.5に固定する設定を使い、推論は[ネットの入出力と推論](alphazero-network.md)の`Evaluator`を使う。
開始局面の乱択の手順は、[評価関数](archived/evaluation.md)が作った`selfplay_gen`の機構を使う。
学習データは、[教師データ形式の統一](archived/unified-teacher-format.md)が定めた教師データの形式MNSDの版2で記録し、着手と方策の表し方は[着手の番号と方策の確率のADR](../adr/index-moves-into-sorted-legal-moves-and-store-policies-as-probabilities.md)に従う。
開始局面に人間の棋譜を使わないことは、統括計画の「ゼロから学習する」の節が定める。

### 生成器の構成

生成器は、1プロセスで数百局を同時に進め、各局の探索がネットの評価を必要とした葉を複数局からまとめて1回の推論にかける。
これはdlshogiの自己対局生成器の構成であり、1局の内部では仮想損失を使わずに済む。
CPUの木の操作とGPUの推論を重ねるため、局の集合を数個のスレッドに分け、各スレッドが自分の集合のバッチを交互に推論へ出す。

各局の着手は、Gumbel AlphaZeroのSequential Halvingが最後に残した手とする。
Gumbel乱数が手の選択に乱択性を与えるので、温度つきの手の抽選とディリクレ雑音は使わない。
開始局面は、`selfplay_gen`の既存の機構と同じく、初期局面から8〜16手の乱択の手順を指して作る。

### 対局の進め方と手数の上限

対局は審判層`Game`で進め、終局の理由と結果は規則どおりに記録する。
探索木の内側の近似とは異なり、学習データの対局結果は反復、駒枯れ、および詰みの規則で確定したものになる。
自己対局の探索は、引き分けの値のオプションによらず、探索木の中の引き分けを0.5とする（[探索方式の共存とMCTS](alphazero-mcts.md)の「反復と引き分けはαβ探索と同じ規則で扱う」の節）。
手数の上限は1,000手とし、上限に達した対局は学習データから除いて件数を記録する（2026年10月14日の利用者の決定）。
dlshogiのGumbel AlphaZero版（以下Gumbel dlshogi）で生じた、上限まで引き延ばす退化戦略を学習させないためである。
上限を対局長の分布から決めないのは、αβ探索の自己対局の対局長の分布は裾が重く（NNUEの教師の生成では7,500局中86局が4,000手に達した。[記録](../measurements/nnue-lr-schedule/nnue-lr-schedule-training.md)）、高いパーセンタイルで決めると上限が数千手になって引き延ばしの余地を広げるからである。
1,000手は生成時間ではなく学習の健全性のための値であり、上限に達した対局の局面は捨てられる。
上限で捨てる対局がRLの生成時間に占める割合は、試走と最初のサイクルで測る（[強化学習の実行](alphazero-rl.md)の「試走」の節）。
長引く対局の多くは互角ではなく勝ちを決め切れていない局面であり、MNSDの終局理由にも手数上限はないので、上限に達した対局を引き分けとして記録することはしない。

### 投了

投了は、ある側の手番で根の勝率が1%を下回った時点とする。
minaseの自己対局は1局の平均が293〜435手と長く（[evaluation.md](archived/evaluation.md)、[evaluation-gen1.md](archived/evaluation-gen1.md)）、投了がなければ勝敗の決まった終盤に生成時間の多くを費やすからである。
1%は、dlshogiの自己対局が勝率0.99で終局させるのと同じ閾値である。
ただし、価値の出力が意味を持たない初めのサイクルでは投了を無効にし、すべての対局を最後まで指させる。
このあいだも投了の条件が成立した時点を記録し、後述の誤った投了の割合を求めておく。
投了を有効にするのは、あるサイクルの誤った投了の割合が5%以下になった次のサイクルからとする。
有効にした後も、全対局の20%はlc0の`resign-playthrough`に倣って投了せずに最後まで指させ、誤った投了の割合を監視する。
誤った投了の割合は、最後まで指させた対局のうち投了の条件がいずれかの側で成立した対局を分母とし、投了の条件が成立した側が負けなかった対局（勝ち、引き分け、手数上限への到達を含む）を分子とする。
あるサイクルでこの割合が5%を超えた場合は、そのサイクルの投了で終えた対局を学習データに入れず、その分を投了を無効にして生成し直し、次のサイクルからも投了を無効に戻して較正し直す。
誤った投了で終えた対局は勝敗の教師が誤っており、どの対局が誤ったかは投了した対局からは分からないからである。
生成器は、投了を有効にするか無効にするかと、最後まで指させる割合を、サイクルごとの設定として受け取り、切り替えの判断は[強化学習の実行](alphazero-rl.md)が各サイクルの開始時に行う。

反復に関わる局面でも投了しない。
根の確定が反復に由来する場合と、根の部分木に反復で打ち切った節点が1つでもある場合は、勝率によらず投了しない（[探索方式の共存とMCTS](alphazero-mcts.md)の「反復と引き分けはαβ探索と同じ規則で扱う」の節）。
反復による勝敗は近似で判定した見込みであり、未訪問の手が残っていても、反復の近似値だけで根の勝率が閾値を下回り得るので、実際には避けられる負けを対局結果の教師にしないためである。

### 記録の形式

学習データは、教師データの形式MNSD（`crates/minase/src/training/records.rs`）の版2で、教師の種類をMCTS（モンテカルロ木探索）として記録する。
MNSDは対局単位の形式であり、1局ごとに開始局面を1回だけ書き、以後は1手ごとに指した手、価値、印、および方策を並べる。
印は、除外の理由、価値の有無、および最善手が指した手と同じかを表す1バイトである。
価値は、MCTSのファイルでは根の期待得点（勝ちを1、引き分けを0.5、負けを0とした得点の期待値で、1を65,535とする）である。
MCTSのファイルの各局面は、根の総訪問回数も持つ。
方策は、局面の合法手を決まった順に並べた番号と、確率1を65,535とする量子化した確率の組の列で持ち、ネットの出力層の符号化（移動元の升ごとの249面）には依存しない。

Gumbel方式の方策の目標はすべての合法手に正の確率を与え、上位の手だけに切り詰めると、確率の小さい好手を捨てる場合に方策の改善が成り立たなくなる。
MNSDは確率を最大剰余法で量子化し、量子化した値が0の候補を書かないので、約1/65,535未満の確率は0として学習器に渡る。
1局面で失う確率の合計は、書かれなかった候補の数を65,535で割った値より小さい。

RLの1局面は、合法手が平均300手と仮定し、確率が0にならない場合、固定部11バイトと候補1つ4バイトで約1.2 KBになり、1サイクル100万局面で約1.2 GB、100サイクルなら約120 GBになる。
合法手の数の分布は[実行環境と実現性の実測](alphazero-environment.md)で数え、この見積もりを置き換える。

### 塊ごとの確定と再開

借りた機械は、Colab機ではセッションの上限時間、残高の枯渇、およびColab側の都合で、レンタル機では貸し手の都合で止まり得る。
このため生成は、どの時点で止まっても再開できるようにする。
生成器は1サイクルの生成を数千局ずつの塊に分け、塊ごとに一時ファイルへ書いてから名前を変えて確定させる。
再開時は確定済みの塊を残し、欠けた塊だけを生成し直す。
各塊のシードは、サイクルの基本シードと塊の番号から派生させ、塊の対局数以上離れた値とする（[隣接する基本シードは1局ずれた同じ対局列を生む](../lessons/derive-seed-adjacent-collision.md)）。
生成器は、確定した塊に対局数、局面数、上限到達で除いた対局数、および生成条件の集計を添える。

借りた機械を止めて作業機の確定済みの塊だけから続きを走らせる確認は、[強化学習の実行](alphazero-rl.md)のフェーズ1で行う。


## 検証

次の試験を追加する。

- 反復に由来する負けの確定が、RLの自己対局で投了の条件にならないことを確かめる。
- 根の部分木に反復で打ち切った節点がある局面で、未訪問の手が残り根の勝敗が確定していなくても、根の勝率が投了の閾値を下回ったときに投了しないことを確かめる。
- 投了を無効にした生成器が、投了の条件の成立を記録しながら対局を最後まで指すこと、および誤った投了の割合が5%を超えたサイクルの投了で終えた対局が学習データに入らないことを確かめる。
- `DrawValueBlack`または`DrawValueWhite`を0以外に設定しても、生成器の探索では引き分けの節点の勝率が0.5のままであることを確かめる。

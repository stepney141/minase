# NNUEの教師局面を静止探索の末端へ置き換える比較の設計書

## 先に読む要約

中将棋エンジンminaseのNNUE（着手ごとに差分で更新できる小さなニューラルネット評価関数）は、自己対局の局面をそのまま教師にして学ぶ。
探索が評価関数を呼ぶのは駒の取り合いを静止探索（qsearch）で読み切った末端の局面が多いので、やねうら王の手順は、教師局面を静止探索の主要変化の末端へ置き換えてから学ぶ（qsearch leaf replacement、コマンド名は`qsearch_psv`）。
minaseはこの方式をNNUEの対局で測らないまま退けており、その理由は成り立たないと分かった（[ADR](../../adr/do-not-replace-nnue-teacher-positions-with-qsearch-leaves.md)）。
本書は、既存の教師30ファイルで、この方式で学んだネットと現行の方式で学んだネットを短時間の時間制御（STC）のGSPRTで比べる。
候補は、最善手が捕獲または成りの局面も教師に戻し、すべての局面を学習の前に1回だけ末端へ置き換える。
基準は、同じ教師と引数で学んだ補正前の幅128のネットである。
結果は[世代反復](../nnue-generation-reset.md)の教師に置き換えを入れるかの判断に使い、masterの埋め込みネットは置き換えない。
完了条件は、比較の判定が測定記録に書かれ、ADRに測定の結論が反映されていることである。

## 状態

本書は完了時点で凍結した記録であり、以後の変更を反映しない。現行の仕様はコードのdocコメントに、設計判断は[docs/adr/](../../adr/README.md)にある。
完了（不採用）。2026年11月3日に起案して着手し、2026年11月4日に完了した。
教師局面を静止探索の末端へ置き換えた候補は、補正前のネットに対する[STC](../../measurements/nnue-qsearch-leaf/nnue-qsearch-leaf-stc.md)で`H0`となったので、世代反復の教師に置き換えを入れない。
[世代反復の設計書](../nnue-generation-reset.md)は置き換えを前提にしていないので、変更しない。

## 目的

本書の問いは、minaseのNNUEで教師局面を静止探索の末端へ置き換えると対局で強くなるか、である。
将棋の記録は構造によって分かれており、minaseの結果を予想できない。

| 先例 | 構造 | 比較 | 結果 |
|---|---|---|---|
| [tanuki-、2022年](https://nodchip.hatenablog.com/entry/2022/05/15/000000) | HalfKP 256x2-32-32 | 最善手が駒を取る局面を除いて置換しない学習と、学習時に静止探索する学習 | 前者がR−118.0 ±10.2 |
| [tataraの実験、2026年](https://github.com/SH11235/rshogi/releases/tag/nnue-experiments-202607) | HalfKP 256x2-32-32 | 学習前に1回置換する学習と、加工なしの学習 | 前者が+111 ±15 nElo |
| 同上 | SFNN-1536 | 同上 | 前者が−5 ±15 nElo |

tanuki-の前者は、最善手が捕獲または成りの局面を除いて置換しないminaseの現行の方式に近い。
本書で使う語を次のとおり定める。

- **静止探索**：探索の深さの上限で、捕獲など局面を大きく変える手だけを読み進める探索。
- **根**：置き換える前の教師局面。
- **末端**：根から全窓で静止探索したときの主要変化をたどり着いた局面。根から末端までの手数を$`k`$と書く。
- **本**：教師の生成の単位である1ファイル。1本は7,500局前後を記録する。
- **戦術的な局面**：教師の生成で、探索の最善手が捕獲または成りだった局面。探索値は記録されているが、現行の学習は除く。
- **補正前のネット**：線形の経路を対局結果へ回帰する前の、幅128のネット（ファイルのSHA-256が`5257f374…`）。
- **GSPRT**：自己対局の勝敗から強さの差を逐次判定する検定。`H1`は候補が有意に強いという判定、`H0`は10 Elo以上強いとは言えないという判定である（[測定の手引き](../../guides/sprt.md)）。

## 適用範囲

本書で行う作業は次のとおりである。

- 根から末端を取り出す処理を、機能フラグ`qsearch-leaf`の内側に実装する。
- `minase-trainer nnue train`に、読み込み時に教師局面を末端へ置き換える引数`--qsearch-leaf-net`を、同じ機能フラグの内側に加える。
- 候補を学び、標準の3診断を行い、基準とSTCのGSPRTで比べる。
- 結論をADRと測定記録に書く。

次の事項は対象外とする。

- 長時間の時間制御（LTC）の測定とmasterの埋め込みネットの置き換え。比較の結果を見て、世代反復の中で扱う。
- 学習中に末端を取り直す方式。
- 新しい構成（[構成の見直し](nnue-architecture-revision.md)）での測定。
- 教師の新規の生成。

## 依存関係

教師は`data/nnue-lr-schedule-gen/generated-*.bin`の30本である。
基準の学習に使った学習器（`7e720567`）とmasterの間で、`crates/minase-trainer/`の`src/nnue/train`、`src/data`、`src/nnue/gpu`、`src/nnue/model`、および`kernels`に差分はない。
したがって、基準を学び直さなくても、候補との差は置き換えと戦術的な局面の追加だけである。

[世代反復](../nnue-generation-reset.md)は本書の結論を受けて教師の加工を決める。
[構成の見直し](nnue-architecture-revision.md)は別のセッションで進行中であり、GPUと測定機のコアを共用するので、学習と対局の前に使用状況を確かめる。

## 設計判断

| 項目 | 決定 | 棄却した代案 |
|---|---|---|
| 置き換えの方式 | 学習の前に、固定したネットで1回だけ置き換える。やねうら王の`qsearch_psv`とtataraの実験と同じ方式である。 | 学習中に末端を取り直す方式は、tanuki-の2022年の実験やminaseのPSTの実験が使ったが、学習器の変更が大きい。効果の記録がある最も単純な形から測る。 |
| 教師値 | 根の探索値と対局結果を保ち、$`k`$が奇数なら手番側の視点に合わせて符号を反転する。`qsearch_psv`と同じである。 | 末端を探索し直して教師値を付け直す案は、先例がなく費用も大きい。 |
| 根の範囲 | 戦術的な局面も教師に戻してすべて置き換える。詰みの帯と反復の局面は現行どおり除く。生成器の除外の印は戦術的が反復より優先するので、戦術的かつ反復の局面は、記録の中の反復キーで別に除く。 | 静かな局面だけを置き換える案は、先例と条件が異なり、[PSTの測定](../../measurements/qsearch-output-training/qsearch-output-leaf-sample.md)では約9割の局面が変わらない。先例が比べたのは捕獲局面を含めた学習である。 |
| 差し替えの位置 | 学習器がMNSD（教師の形式）を読み、局面を標本へ変換する直前（`data/stream.rs`の`read_file`）で差し替える。 | 変換したファイルを作る案は、MNSDが対局の開始局面と着手列で局面を持つので1局面が約168バイトになり、対局番号が変わって検証集合の分割も崩れる。 |
| 末端を選ぶネット | 基準の補正前のネットを使う。 | 教師を生成したネットは1世代古く、候補の比較相手と離れる。 |
| 置換表と補正 | 置換表を読まず、静的評価の補正（correction history）の計算を無効にする。これで末端の静的評価と静止探索の値が一致し、全局面で検査できる。やねうら王も置換表の読み取りを無効にしている。 | 置換表を読む案は、表の値が静的評価を置き換えて末端と値が対応しなくなる。補正の表を空のままにする案は、未使用の表でも初期値と直前手なしの固定項で補正が0にならない。 |
| 詰みの値 | 静止探索の値が静的評価でなく詰みで決まった根は学習から除き、件数を記録する。 | 根のまま残す案は、詰みの帯を除く現行の方針と合わない。 |
| 検証集合 | 検証の対局の局面も同じく置き換える。検証損失は早期終了だけに使い、基準と比べない。 | 検証を元の局面のままにする案は、学習の目的と違う分布で早期終了を決める。tataraの実験では符号一致率が下がっても強くなった例があり、損失の比較は採否の根拠にならない。 |
| 探索のコード | 機能フラグの内側だけを変える。エンジンは機能フラグなしでビルドされるので、探索の速度と結果は変わらない。 | 実行時の分岐を常に入れる案は、静止探索の中の費用が増える。機能フラグを学習器の依存へ常時付ける案は、ワークスペースの一括ビルドでエンジンにも入る。 |
| 基準 | masterの探索のコードに補正前のネットを載せたコミットとする。候補にも補正を掛けない。 | 補正済みのmasterを基準にする案は、候補にも回帰を掛けることになり、置き換えの効果と混ざる。 |
| 判定 | STCのGSPRTだけで判定する。 | LTCまで測る案は、masterを置き換えないので本書の判断に要らない。 |

## 末端の取り出し

取り出しは、根ごとに次を行う。

1. 根で累算値を作り直し、全窓（`-MATE`から`MATE`）で静止探索を実行する。
2. 値が改善するたびに主要変化を親へ伝え、根の手順を得る。
3. 手順を合法手として再生して末端を作る。
4. 末端の静的評価に$`(-1)^k`$を掛けた値が静止探索の値と一致することを検査する。一致しなければエラーで止める。

窓の内側で値が決まる節点の返り値は、stand-patか子の値である。
fail-highの値の調整と枝刈りの見積りによる引き上げは窓の外の節点にしか現れないので、主要変化の値には影響しない（推論）。
この推論は全局面の検査で確かめる。

## 実装フェーズ

作業は、masterから切ったブランチ`nnue-qsearch-leaf`のworktree（`data/worktrees/nnue-qsearch-leaf`）で行う。
データは`data/nnue-qsearch-leaf/`に置く。

### フェーズ1　実装

次を実装する。実装はcodexへ委任し、テストの事例は設計者が指示書で与える。

- クレート`minase`の機能フラグ`qsearch-leaf`の内側に、根から末端を取り出す処理を加える。
- クレート`minase-trainer`の機能フラグ`qsearch-leaf`（`minase/qsearch-leaf`を有効にする）の内側に、引数`--qsearch-leaf-net <MNUE>`を加える。先読み教師との併用は拒否する。ネットの検査和と置き換えの統計（根の数、$`k\ge1`$の数、詰みで除いた数）は`config.json`に記録する。

完了条件は、「検証」のフェーズ1の項が通っていることである。

### フェーズ2　学習と診断

本体のリポジトリの`data/`にある教師を絶対パスで指定し、[補正前のネットの学習](../../measurements/nnue-material-linear-init/nnue-material-linear-init-training.md)と同じ引数に`--qsearch-leaf-net`を加えて学ぶ。
戦術的な局面を戻すと局面数が約1億に増えるので、メモリの上限は16 GBとする。
先に1本だけで取り出しの速さと統計を確かめる。

学習の後に[学習の手引き](../../guides/nnue-training.md)の8節の3診断を行う。
測定名は`nnue-qsearch-leaf-training`とする。
完了条件は、学習が完了し、駒価値の歪みなどの異常がないことである。
異常があれば対局へ進まず、利用者へ報告する。

### フェーズ3　比較

基準と候補のコミットを、次のブランチに作る。
ブランチ`nnue-qsearch-leaf-baseline`は本ブランチに補正前のネットを載せ、ブランチ`nnue-qsearch-leaf-candidate`は本ブランチに候補のネットを載せる。

```console
minase match run --run-dir data/matches/nnue-qsearch-leaf-stc --seed 20261104500000 \
  --candidate commit:<候補> --baseline commit:<基準> \
  --each time=10000+100 --concurrency 30 gsprt --max-pairs 3000
```

測定は、空いているryzen0（Threadripper 2990WX、物理32コア、メモリ125 GB）で行い、記録にその旨を書く。作業機は別の計画の学習と共用していて、メモリに余裕がないからである。
測定名は`nnue-qsearch-leaf-stc`とする。
判定の読み方は次のとおりである。

| 判定 | 読み方 | 世代反復への提案 |
|---|---|---|
| `H1` | 置き換えは現行の教師より強い。 | 置き換えを入れる。 |
| 上限で`pending`、LLRが0以上 | 10 Elo未満の改善があり得る。 | 実装の費用と比べて利用者が決める。 |
| `H0`、または上限で`pending`かつLLRが負 | 10 Elo以上の改善は確認できない。 | 入れない。 |

### フェーズ4　文書の移し替えと凍結

ADRへ測定の結論を書き、ROADMAPと世代反復の設計書を改める。
masterへの統合は利用者の許可を得てから行う。
統合するのは文書と測定記録であり、実装を残すかは結果を見て利用者に尋ねる。
最後に「状態」節を完了の段落に書き換えて本書を凍結し、`docs/plans/archived/`へ移す。

## 検証

フェーズ1の完了前に次を確かめる。

- 機能フラグなしで`cargo test --locked --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、および`cargo fmt --all --check`が通る。
- 機能フラグつきで`cargo test --locked -p minase --features qsearch-leaf`と`cargo test --locked -p minase-trainer --features qsearch-leaf`、およびそれぞれの`clippy`が通る。
- 機能フラグなしのビルドで、深さ5のbenchの経過時間を除く出力が本ブランチの起点のmasterと全行一致する。
- 取り出しのテストが次を確かめる。捕獲のない局面は$`k=0`$で根を返す。捕獲でstand-patを確実に上回る局面は$`k\ge1`$で、末端の評価と値が一致する。最後の王駒を取る局面は詰みとして扱う。別の根を処理した後に同じ根を取り出しても結果が変わらない（状態が残らない）。
- 読み込みのテストが次を確かめる。$`k`$が奇数なら探索値と対局結果の符号が反転する。戦術的な局面は含まれ、詰みの帯、反復の局面、および戦術的かつ反復の局面は含まれない。対局番号と検証集合への所属は置き換えの前と同じである。先読み教師との併用は拒否される。

測定の前に進行中の測定を確かめ、対局を行った場合はエンジン異常、時間切れ、および拒否着手が0件であることを確かめる。

## 完了条件

次のすべてを満たしたら完了とする。

- 比較の判定または対局前に止めた理由が測定記録に書かれている。
- ADRと世代反復の設計書に結論が反映されている。
- 「フェーズ4」の移し替えと凍結を終えている。
- 状態は、`H1`なら完了（採用）、それ以外は完了（不採用）とする。

# 勝率尺度の1定数化と教師の尺度補正係数の明示（Kの改名）の設計書

## 先に読む要約

本マイルストーンでは、評価関数の学習で「K」と呼んでいる2つの値を、1つの定数と教師ごとの補正係数に組み替え、名前を意味の分かるものに改める。
Kとは、評価値（センチポーン、cp）を勝率へ換算する尺度であり、評価値をKで割った値をシグモイド関数 σ(x) = 1 / (1 + e^(−x)) に通すと勝率になる。
本書はこの量を**勝率尺度**（1ロジットあたりのcp、識別子 `cp_per_logit`）と呼ぶ。ロジットとは、シグモイド関数に入れる前の実数である。
本書で「勝率」と呼ぶ値は、勝ちを1、引き分けを0.5、負けを0と数えた得点の期待値であり、較正もこの値に対して行う。
学習器は、自己対局で各局面を探索して得た探索値と対局結果を混ぜた教師値に、評価関数（NNUEと呼ぶニューラルネット、または比較用に残すPST）の出力が近づくように重みを学習する。
現行の学習器は、ネットの出力に使う勝率尺度（出力K、1072.6529541015625の定数、以下1072.65と略す）と、教師の探索値に使う勝率尺度（教師K、教師の分類ごとに学習のたびに訓練集合から推定）を別々に持つ。
教師の分類とは、探索値を出した評価関数、探索のノード数、局面の由来（自己対局か実戦の棋譜か）、および先読み条件が同じ教師データの集まりである。
2つの値は同じ単位の量だが、前者はエンジンの評価値の単位を定める取り決め、後者は各教師の探索値が勝率とどう対応するかの測定値であり、この違いが名前に現れていないために理解を妨げている（[既存実装の調査](../../research/win-rate-scale-k-prior-art.md)）。
本書は、勝率尺度を重みファイルのヘッダが持つ1つの定数とし、教師の探索値は分類ごとの**尺度補正係数**（勝率尺度を教師の勝率尺度で割った値）でその定数の単位へ換算したものとして説明と記録を組み替える。
補正係数で換算してから1つの定数で割る計算と、探索値を教師の勝率尺度で割る現行の計算は実数演算では同じ値になるが、浮動小数点では丸めが変わり得るので、実装の計算式は変えず、補正係数は無次元の導出量として記録する。
教師の勝率尺度は、学習の必須の引数 `--teacher-cp-per-logit` で与える。値には、この学習の訓練集合から推定させる `calibrate` か、分類ごとの値を持つ較正ファイルのパスのどちらかを指定し、既定値は置かない。
通常の学習では `calibrate` を使い（dlshogiの `--use_evalfix` と同じ方式）、訓練集合の間引きなど教師値を固定したい比較では、新設する較正コマンドが書き出す較正ファイル（JSON）をそのまま渡して値を固定する。
この組み替えは計算する値を変えないので、採否は棋力の測定ではなく、変更前の学習器との学習結果の一致（記録した損失と重みが文字列として一致すること。以下「照合」と呼ぶ）で判定する。
完了条件は、改名、較正コマンド、引数の明示化、文書、およびADRが揃い、照合に合格することである。

## 目的

学習器のソースには、重みファイルのヘッダの `k`、6つの `k()` アクセサ、`teacher_ks`、`ks`、`estimate_k`、`estimate_teacher_ks`、`output_k`、`base.k`、および `args.k` がある。
いずれも、名前から単位や役割を読み取れない。
文書は同じ量を「出力K」「出力用K」「出力尺度」「教師K」「教師用K」「教師尺度」「尺度K」「評価尺度K」と呼び分けており、場所ごとに違う名前で呼んでいる。
さらに、教師データMNSDのヘッダの `teacher_scale` は探索ノード数を指し、「尺度」という語が勝率尺度と衝突している。

命名が混乱している背景には、2つのKが別の性質の量であるのに同じ型の名前で呼ばれているという事情がある。
出力Kは、[学習する評価関数の出力Kを固定するADR](../../adr/archive/fix-the-output-k-of-trained-weights.md)により、評価値の単位を定める定数として固定されている。
教師Kは、教師の分類ごとに、探索値から終局結果を最もよく予測する値として、学習のたびに訓練集合から推定している（`crates/minase-trainer/src/data/mnsd.rs` の `estimate_teacher_ks`）。
分類は、生成コミット、評価関数の重みの検査和、探索のノード数、規則セット、局面の由来、先読み条件、および混合比λの組で決まる（`TeacherClass`）。
混合比λは、教師値のうち探索値の占める割合であり、残りの1−λは対局結果の占める割合である。実戦の棋譜の局面は探索値を持たないのでλ=0とする。
記録された教師K（単位はcp/ロジット）は、1局面10万ノードで生成した世代2と世代3で758と766、1局面2万ノードの教師で1218であり、浅い探索の教師ほど大きい。同じcpの探索値が分類ごとに違う勝率を意味するので、分類ごとの値には根拠がある。
一方、学習のたびに推定し直す方式では、教師値の定義が訓練集合の分割や間引き方に左右される。
[学習率スケジュールの設計書](nnue-lr-schedule.md)は、訓練局面を間引く比較で教師値まで変わらないように、間引く前の訓練集合全体から推定する規定を置き、[out-of-coreシャッフルの設計書](../out-of-core-shuffle.md)は、局面を並べ替える単位の数によらず推定値を一致させる条件を課している。
調べた既存実装13件のうち、学習のたびに推定するのはEtherealのチューナーとdlshogiの `--use_evalfix`（既定では無効）の2件だけであり、残りは手で決めた定数か、一度推定して定数化した値である。

本書の目的は次の2つである。
第1に、勝率尺度を1つの定数とし、教師ごとの違いを補正係数として分離し、教師の勝率尺度を推定させるか固定するかを学習の引数で明示する。
第2に、コード、設定ファイル、および現行の文書の名前を、量の意味と単位が分かる一貫した命名に統一する。

## 適用範囲

本書は次を含む。

- 学習器 `crates/minase-trainer` の全パイプライン（NNUE、PST、FM、同時学習、診断）が共有するデータ層での、教師値の計算の組み替えと識別子の改名。
- エンジン `crates/minase` の重みファイル（MNPT、MNUE）のヘッダの勝率尺度と、MNSDヘッダの探索ノード数のアクセサの改名。バイナリの配置は変えない。
- 教師の勝率尺度を求める較正コマンドの新設と、学習の引数での明示。
- 学習の記録（`config.json`）のキーの改名。
- 現行の文書（docs/guides/、docs/plans/ 直下の設計書、docs/ROADMAP.md、rustdoc）の用語の統一と、新しいADR。

本書は次を含まない。

- 勝率尺度の値1072.6529541015625の変更。この値は採用中の重みの単位であり、変えると評価値のcpを基準に調整した探索係数の前提が崩れる。
- 補正係数を持たない1定数化（tanuki-の方式）。現行の教師は分類間で勝率尺度が最大で約1.6倍（1218対758）異なるので、棋力への影響を測らずには採れない。測るなら別の設計書で段階ゲートにかける。
- MNSD形式の変更。教師の勝率尺度をヘッダに書く案は「設計判断」で棄却した。
- 凍結した設計書、測定記録、監査報告、調査メモ、および既存のADRの本文の書き換え。これらは記録であり、用語は当時のままにする。
- 棋力の測定。計算する値は変わらない。

## 設計判断

| 項目 | 採る方式 | 棄却した代案と理由 |
|---|---|---|
| 勝率尺度の置き場 | 重みファイル（PSTのMNPT、NNUEのMNUE）のヘッダが持つ値をそのまま唯一の定数とし、学習の初期値に与えた重みファイルの値を学習中も書き出す重みにもそのまま使う。現行と同じ。 | 学習の引数で与える案は、重みが既にその単位で書かれているので、再学習なしに変えると探索係数の前提が崩れる。ヘッダの値を単位の定義として残すのが最も単純である。 |
| 教師の探索値の換算 | 分類ごとの尺度補正係数 `f = cp_per_logit / teacher_cp_per_logit` を定義し、教師の勝率を `σ((v × f) / cp_per_logit)` として説明する。実装は現行どおり `σ(v / teacher_cp_per_logit)` を計算し、両者が同じ値であることをdocコメントに書く。 | 実装でも `v × f` を先に掛ける案は、浮動小数点の丸めが変わり、変更前との一致の照合ができない。補正係数は記録と説明のための導出量とする。 |
| 教師の勝率尺度の由来 | 必須の引数 `--teacher-cp-per-logit` で、`calibrate`（この学習の訓練集合から分類ごとに推定する。現行の推定と同じ計算で、dlshogiの `--use_evalfix` と同じ方式）か、新設の較正コマンド `minase-trainer data calibrate` が書き出す較正ファイルのパスのどちらかを指定する。既定値は置かない。較正の計算は、訓練集合の探索値から終局結果を予測する二値交差エントロピーの最小化（黄金分割探索）であり、学習と同じ検証分割と先読み条件を使う。 | 常に推定する現行の方式だけにする案は、教師値を固定したい比較のたびに「間引く前の集合で推定する」といった特則を書き続けることになる（「目的」の節）。較正ファイルだけにする案は、通常の学習でも較正と学習の2段階の手順を要し、別の条件で作った較正ファイルを渡す誤りの余地を増やす。生成器が生成の終了時に推定してMNSDヘッダへ書く案は、形式の版を上げて30ファイル（約43時間）を再生成する必要があり、生成器が検証集合を含む全局面で推定する点も学習器の推定と一致しない。将来、生成器に持たせる場合は別の設計書で扱う。 |
| 引数の形 | `--teacher-cp-per-logit calibrate` か `--teacher-cp-per-logit <較正ファイルのパス>` のどちらかとする。較正ファイルは分類ごとに、生成コミット、重みの検査和の全体、探索の規模、規則セット、由来、先読み条件、および教師の勝率尺度を持ち、学習器はこれらの属性で分類と突き合わせる（混合比λは較正の計算に入らないので突き合わせに使わない）。λが0でない分類に対応する項目がない、項目に対応する分類がない、または同じ分類に複数の項目がある場合は、学習を始めずにエラーで終了する。 | `<検査和の先頭8桁>@<ノード数>=<値>` のような短い鍵を手で書く案は、同じ重みのまま探索コードだけを更新した世代（検査和とノード数が同じで生成コミットが違う分類）を区別できず、その混合を指定する手段がなくなる。鍵なしの値を入力順に並べる案は、`--data` の順序を変えると対応がずれる。単一の値だけを受ける案は、世代の異なる教師を混ぜる学習（分類ごとの尺度が要る理由そのもの）を不可能にする。 |
| 較正ファイルが持つ量 | 教師自身の勝率尺度（例: 1217.6）。較正の計算は出力側の勝率尺度を参照しないので、較正の結果をそのまま表す。補正係数は学習器が導出して記録する。 | 補正係数（例: 0.88）を持たせる案は、勝率尺度（重みファイルのヘッダの値）と教師の勝率尺度の比なので、勝率尺度の異なる重みを初期値にすると同じ教師でも値が変わり、較正の記録と突き合わせにくい。 |
| 較正の値の記録 | 学習の `config.json` に、`calibrate` と較正ファイルのどちらを使ったか（現行の `teacher_k_source` の後継）、較正ファイルの内容、分類ごとの教師の勝率尺度、および導出した補正係数を記録する。再開の照合はこれらを含む。チェックポイント（NPZ）の配列名 `k` も `cp_per_logit` に改める。 | 旧キー `teacher_ks` や旧配列名 `k` を読む互換経路は作らない。改名前の実行ディレクトリとチェックポイントは新しい学習器で再開できず、それでよい。 |
| 改名の範囲 | Rustの識別子、`config.json` のキー、CLIの引数、rustdoc、docs/guides/、docs/plans/ 直下の設計書、docs/ROADMAP.md。日本語の用語は「勝率尺度」「教師の勝率尺度」「尺度補正係数」の3語に統一し、初出で単位（1ロジットあたりのcp）を添える。 | 凍結した設計書、測定記録、監査報告、調査メモ、および既存のADRは記録なので書き換えない。 |
| 推定コードの扱い | 探索値と結果の配列から1つの勝率尺度を推定する関数 `estimate_k` は `estimate_cp_per_logit` に、分類ごとに訓練集合を集めて推定する関数 `estimate_teacher_ks` は `estimate_teacher_cp_per_logit` に改名し、較正コマンドと `calibrate` 指定の学習の両方がこの1つの関数を呼ぶ。探索値がすべて0のように尺度を決められない標本は拒否し、推定値が探索範囲（50から4000）の端に達した場合はその旨を出力と記録に残す。 | 較正を別ツールに書く案は、同じ計算を2か所に持つことになる。 |

## 較正コマンドと学習の引数

較正コマンドは `minase-trainer data calibrate --data <MNSD>... [--lookahead-gamma <γ> --lookahead-plies <n>]` とする。
先読みとは、各局面の探索値を、同じ対局の将来n手の探索値から減衰率γで計算した幾何加重平均で置き換える教師の作り方であり（[先読み教師のADR](../../adr/use-lookahead-teacher-values.md)）、学習と同じ引数で指定する。
較正は、学習と同じ検証分割で訓練集合を選び、先読み条件を指定した場合は先読み値から、分類ごとに教師の勝率尺度を推定する。
出力は較正ファイル（JSON）で、較正の条件（入力ファイルの一覧。各ファイルは学習の記録と同じ識別情報、すなわち正規化したパス、バイト長、およびヘッダの内容で表し、[MNSD全体の検査和をやめた決定](../../adr/archive/record-the-origin-in-mnsd-records.md)に合わせてファイル全体の検査和は持たせない。ほかに検証分割の規則、先読み条件、計算の精度、推定の探索範囲、較正コマンドの版）と、分類ごとの生成コミット、検査和の全体、探索の規模、規則セット、由来、先読み条件、訓練局面数、教師の勝率尺度（f64の値を精度を落とさず復元できる形式で）、および推定値が探索範囲の端に達したかどうかを持つ。
実戦対局の由来の分類は探索値を持たないので出力しない。

学習コマンド（`nnue train`、`pst train`、`fm train`、`joint train`）と教師値を使う診断は、`--teacher-cp-per-logit` を必須とし、既定値を置かない。
値が `calibrate` なら、学習器は較正コマンドと同じ計算でこの学習の訓練集合から分類ごとに推定する。
値が較正ファイルのパスなら、ファイルの分類の属性（生成コミット、検査和、探索の規模、規則セット、由来、先読み条件）で学習の分類と突き合わせ、λが0でないすべての分類に対応する項目があることを確認したうえで、値を検証（有限で正）して使う。
入力ファイルの一覧は突き合わせず、較正ファイルの内容を `config.json` へ写す。教師値を固定したい比較では、較正に使ったファイルの集合と学習のファイルの集合が違ってよいからである。
どちらの場合も、分類ごとの教師の勝率尺度と導出した補正係数を `config.json` に記録する。
較正ファイルを与えた場合、学習器は推定し直さず、別のファイルの集合で求めた値かどうかも検出しない。
これは教師値を外部から固定できるようにすることと引き換えの制約であり、較正ファイルを使う学習の記録（`docs/measurements/`）には、較正ファイルの内容を書く。
較正ファイルは、訓練集合の間引きや分割の変更のように教師値を固定したい比較で使い、通常の学習は `calibrate` を使う。

教師値を使う診断 `diag pst-compare` は、探索値を保持したf32ではなくf64で計算し直してから較正するので、同じ入力でも学習の `calibrate` とは値が一致しないことがある。
診断も同じ引数を受けるが、照合は `calibrate` 指定で行い、学習と診断の較正値の一致は求めない。

## 実装フェーズ

1. **改名（計算と出力の重みは不変、`config.json` のキー名だけ変更）**。「用語と識別子の対応」の表に従ってRustの識別子、rustdoc、`config.json` のキー、および `bench-step` の引数を改め、現行の文書の用語を統一する。完了条件は、`cargo fmt`、`cargo clippy`、`cargo test` が通り、「検証」の照合1に通ることである。
2. **較正コマンドと引数の明示**。`data calibrate` を新設し、学習と診断の引数に必須の `--teacher-cp-per-logit` を加え、`calibrate` と較正ファイルの両方の経路を実装する。完了条件は、照合2と照合3に通ることである。
3. **文書とADR**。新しいADR「勝率尺度を重みファイルの1定数とし、教師の勝率尺度は較正コマンドで求めて学習の引数で与える」を書き、[出力Kを固定するADR](../../adr/archive/fix-the-output-k-of-trained-weights.md)のステータスを置き換え済みにする。docs/guides/ の評価関数の解説と学習手順、docs/ROADMAP.md、および本書を更新する。

フェーズ1と2は別のコミットにし、照合は各フェーズの直後に行う。
実装はcodexへ委任し、GPUを使う照合は委任元が本環境で行う（[GPUを要する学習はcodexへ委任しない](../../lessons/run-gpu-training-outside-codex-sandbox.md)）。

## 検証

照合は、[ファイル形式の整理の照合記録](../../measurements/file-format-consolidation-equivalence.md)と同じ手順で行う。ただし同記録の2ファイルは削除済みなので、現存するMNSD版2のデータ（`data/nnue-lr-schedule-gen/` の先頭2ファイル）を使い、変更前の基準は着手時のmaster（学習率スケジュールのブランチを統合した後のコミット）で取り直す。
NNUEは2エポックで約200秒、PSTは約30秒である。
比べる値は、訓練局面数、検証局面数、分類ごとの教師の勝率尺度、訓練と検証に振り分けた局面の通し番号の列のSHA-256、各エポックの訓練損失、補助損失（駒を1つ除いた局面との評価の差に課す損失）、総損失、検証損失、および書き出した重みのSHA-256である。
一致はすべて、`config.json` と学習ログに書かれた値の文字列としての一致で判定する。

1. **照合1（改名）**。フェーズ1の学習器で学習し、キー名を読み替えたうえで、すべての値が変更前と文字列として一致する。NNUE、PST、FM、同時学習、および教師値を使う診断 `diag pst-compare` で行う。チェックポイントからの再開も、同じ設定で成功することを確かめる。
2. **照合2（較正）**。`data calibrate` の出力が、変更前の学習器が `config.json` に記録した `teacher_ks` と分類ごとに文字列として一致する。先読みありとなしの両方で行う。
3. **照合3（2つの経路での学習）**。`--teacher-cp-per-logit calibrate` で学習した結果と、照合2の較正ファイルを与えて学習した結果が、どちらもすべての値で変更前と一致する。較正ファイルを経由しても値がf64の精度で保たれることを含む。分類が2つになる入力（上の2ファイルに、別の生成器の1ファイルを加えたもの）でも行い、`--data` の順序を入れ替えても分類と値の対応が変わらないことを確かめる（この試験では対応だけを見て、学習結果の一致は求めない）。
4. **引数の拒否と再開**。引数の省略、項目のない分類、分類に合わない項目、同じ分類の重複する項目、0以下や非有限の値、および探索値がすべて0の標本で、学習器と較正コマンドがエラーで終了することをテストで確かめる。λが0の分類と訓練局面のない分類の扱いが現行と同じであること、同じ設定での再開が成功し、較正の指定を変えた再開と改名前の記録からの再開が拒否されることも確かめる。
5. **エンジンの不変**。エンジンの改名はアクセサだけなので、重みファイルの読み込み時の検査（ヘッダの値の範囲と本体の検査和）を行う既存の形式のテストが改名後も通ることと、`bench` の総ノード数と結果が深さ7で変更前と一致することを確かめる。採用中の重みのヘッダの値や検査和を定数として固定するテストは、重みを更新するたびに書き換えが要るので加えない。

## 完了条件

- 「用語と識別子の対応」の表の改名がすべて入り、`k` という名前の勝率尺度がコード、設定ファイル、チェックポイント、および現行の文書に残っていない。
- 較正コマンドと必須の `--teacher-cp-per-logit` が入り、学習器が引数なしに教師の勝率尺度を推定する経路が残っていない。

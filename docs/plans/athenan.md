# Athénanによる評価関数の強化学習と対局探索の設計書

## 先に読む要約

本書は、Cohen-Solalが提案したAthénan（[JMLR 27(130), 2026](https://www.jmlr.org/papers/volume27/25-2259/25-2259.pdf)、[arXiv:2008.01188](https://arxiv.org/abs/2008.01188)）をminaseへ適用し、現行の採用版（以下S0）より強くなるかを確かめる。
Athénanは、学習と対局に別々の探索を使う枠組みである。
学習では、自己対局の各手で、評価値が最善の子を王駒の捕獲や反復などの終局までたどる探索Descentを繰り返して部分的なゲーム木を育て、その内部節点を、木の中で終局の値と静的評価から逆算した値へ近づける（木の学習）。
対局では、学習した評価関数を使う最良優先探索UBFMsで指す。
UBFMsは、根の値を決めている最善の手順をたどり、その先端の局面の子を全て評価して木に加える操作を持ち時間の間繰り返し、探索中に最も多く選んだ手を指す。
minaseでは、評価関数を現行のPST（駒の種類と升ごとの点数を足す評価方式）のまま学習し、Athénanの構成要素のうち中将棋やPSTに合わないものは、理由を付けて置き換える。
論文の実験はニューラルネットの評価関数、中将棋より大幅に短いゲーム、および静止探索も枝刈りも持たないαβ探索との比較によるので、その結果がminaseにそのまま当てはまるとは限らない。
そこで、最初のフェーズ0で、学習をせずにDescentだけを動かし、探索が終局へ届く割合、所要時間、およびメモリ量を実測して、事前の基準で続行を判断する。
続行する場合は、UBFMsを実装し、現行の採用PSTを初期値として48時間の学習を行う。
採否は、学習したPSTを現行のαβ探索に載せた候補Lと、UBFMsに載せた候補Aを、それぞれS0と同じ持ち時間で対局させ、優劣を逐次的に判定する[逐次確率比検定](../guides/sprt.md)の短時間条件STCと長時間条件LTCで決める。
完了条件は、フェーズ0による見送り、学習中の停止規則による見送り、または2つの候補の採否のいずれかが、測定記録とともに確定することである。

起案。2026年9月26日に起案した。
初期値、対照、計算予算、着手の時期、および対局側のUBFMsを計画に含めることは、利用者が決定済みである（「設計判断」の節）。
着手の条件としていた[探索局面を用いた評価関数の学習](search-aware-evaluation.md)の完了は、2026年9月26日に満たされた（同計画はAとBをともに不採用として完了し、採用PSTは変わっていない）。
候補Aを採用した場合に、UBFMsが対応しない先読み、複数スレッド、および投了をどう扱うかは、利用者の判断を待っている（「候補Aを採用する場合の統合」の節）。
この判断はフェーズ4の採否の後に必要となるので、フェーズ0の着手は妨げない。
次の一手は、masterから専用ブランチを作り、フェーズ0の探索器を実装することである。

## 目的

本書は、次の2つの仮説を検証する。

1. Athénan全体の仮説：Descentの木の学習でS0から追加学習したPSTをUBFMsで使うエンジン（候補A）は、S0より強い。
2. 学習側の仮説：同じPSTを現行のαβ探索で使うエンジン（候補L）は、S0より強い。

ここでS0は、フェーズ0の開始時点でmasterに採用されているPSTと探索のコミットを指し、フェーズ0の実測、駒除去の損失と診断の基準、および採否の比較相手に使う。
本学習の初期値もS0とする。
フェーズ0の後にS0を変える必要が生じた場合は、フェーズ0を新しいS0でやり直す。

候補Lと候補Aは同じPSTを使い、対局用の探索だけが異なる。
したがって、候補LとS0の比較は学習側の効果を、候補Aと候補Lの比較は同じPSTの下での対局側の効果を表す。
[先行事例の調査](../research/athenan-prior-art.md)によれば、Athénanの論文群は、学習方式どうしを深さ1の対局で比べ、同じネットワークで対局用の探索どうしを比べている。
しかし、学習側と対局側のそれぞれが、強い既存の探索や評価関数に対してどれだけ寄与するかを分けた比較はない。
本書は、S0を共通の基準として、この2つを分けて測る。

学習側の仮説は、次の3つの変化をまとめて含み、個々の寄与を分けない。

1. 教師値が、深さ約6の探索値と対局結果の混合から、終局まで伸ばした部分木のミニマックス値へ変わる。
2. 学習する局面が、対局で実際に現れた局面から、探索木の内部節点全体へ広がる。
3. 自己対局の着手の選び方が、αβ探索の最善手から、Descentの木に基づく確率的な選択へ変わる。

「Athénanの学習はelmo式の学習より良い」という比較上の主張は、同じ計算予算で現行の方式を回した対照を要するので、本書では検証しない。

線形の評価関数でAthénanやDescentを使った報告はなく、線形の評価関数に対する木の学習の実証は、αβ探索の木を使うTreeStrapに限られる。
フェーズ0で探索が中将棋の終局へ届かないと判定した場合は、αβ探索の木を使うTreeStrapを後続の候補として記録する。

[探索局面の計画](search-aware-evaluation.md)も、探索中の局面を学習へ加える仮説を扱った。
ただし同計画は、局面ごとに独立した1,000万ノードのαβ探索を教師とし、学習局面の半数を置き換える固定の対照実験だった。
本書は教師値を自己対局の木から自己参照的に作り、学習を周回で繰り返し、対局用の探索も替える点が異なるので、同計画の否定的な結果は本書の仮説を否定しない。

## 適用範囲

本マイルストーンでは、次の作業を行う。

- 完全化（completion）つきのUBFMとDescentが共有する探索木を、ライブラリ内の新しいモジュール `crates/minase/src/search/ubfm/` に実装する。
- Descentで自己対局を行い、木の節点を教師データとして出力する生成器 `crates/minase/src/bin/descent_gen/` を新設する。
- 対局結果を持たない教師データ形式を定め、Rustの書き出しとPythonの読み込みを実装する。
- 生成と学習を交互に行う周回の駆動器と、再生バッファ（直近の対局のデータを保持して学習に再利用する仕組み）を `tools/train/pst/` に追加する。
- UBFMsを対局用探索として実装し、αβ探索の時間予算の計算を共有する。候補Aのコミットでは、USI層の`go`、予想手、投了、および`info`の出力をUBFMsに合わせて変える（「USI層の変更」の節）。
- フェーズ0の実現性の実測、UBFMsの動作確認の対局、本学習、および2つの候補の採否の測定を行う。

次の事項は本書に含めない。

- ニューラルネットの評価関数、GPUでの子局面の一括評価（child batching）、および知識なしの初期化からの学習は扱わない。ニューラルネットの系統は[AlphaZero型探索の計画](alphazero.md)で扱う。
- UBFMsの先読み、複数スレッドでの探索、および投了は実装しない。候補Aを採用する場合の扱いは、「候補Aを採用する場合の統合」の節で利用者が決める。
- 論文が提案する他の終局値（得点、移動可能数、駒数）は比較しない。
- αβ探索の探索内容、時間配分、規則処理、およびPSTの特徴と重み形式は変更しない。

## 依存関係

方式の根拠と先行事例は[Athénanの先行事例の調査](../research/athenan-prior-art.md)にまとめる。
PSTのモデル、損失、射影、量子化、駒除去の診断は、[評価関数](evaluation.md)、[PSTの補間](tapered-pst.md)、[段階7](strength-stage7.md)、および[PSTの学習手順](../guides/pst-training.md)を引き継ぐ。
棋力の採否は[SPRTの手引き](../guides/sprt.md)に従う。

評価関数の後続計画の順序は[棋力向上段階の設計書](strength-stages.md#評価関数の後続計画の順序)が定めており、本書はその表に含まれていない。
本書は探索局面の計画の完了後に着手する。
同計画で採用されたPSTがあればそれを、なければ従来の採用PSTをS0とする。
着手後は、[相対2駒評価](relative-pair-eval.md)や[段階12](strength-stage12.md)などの変更を途中で取り込まない。

探索局面の計画のブランチは、結果を持たない教師データ形式を別に作っているが、履歴と経路の再生を必須とする重い契約であり、本書の木の節点には不要である。
本書は同ブランチに依存せず、PSTの入力に必要な内容だけを持つ形式を別に定める。

## 設計判断

### Athénanの構成要素の採否

Athénanの論文の既定の設定と、本書での扱いを次に示す。
「置換」は、中将棋、PST、または測定機の制約に合わせて別の方法に置き換えた要素である。
各要素の効果の証拠は[先行事例の調査](../research/athenan-prior-art.md#構成要素ごとの効果の証拠)による。

| 構成要素 | Athénanの既定 | 本書の扱いと理由 |
|---|---|---|
| 学習用の探索 | 完全化と解決済み部分木の停止つきDescent（Algorithm 10） | 採用する。完全化のないDescentは最適でない不動点に留まり得ると論文が述べ、中将棋には引き分けがあるので、完全化値cと解決値rの両方を持つ。 |
| 木の学習 | 展開した内部節点と終局の節点を学び、未展開の葉は学ばない | 採用する。葉の値は評価関数自身の出力なので、学ぶ情報がないためである。 |
| 終局値 | スコアのないゲームでは加算型の深さヒューリスティック | 採用する。勝ちを `MATE − p`、負けを `−(MATE − p)`、引き分けを0とし、pは対局開始からの手数とする。論文の比較で通常の±1より強かった形である。pが4,000に達すると勝ちの値26,000は静的評価の値域（絶対値28,999以下）と重なるが、勝敗は完全化値cで区別し、cを先に比べるので、順序は崩れない。 |
| 着手の選択 | 完全化つきの順序分布で、活用率ε′を着手ごとに0以上1以下の一様乱数で引く | 採用する。順序分布の効果には公表された表がなく、ε-greedyとの優劣の記述も版によって逆転しているので、論文の長時間学習の設定に合わせることだけを理由とする。 |
| 対局用の探索 | UBFMs（最も多く選んだ手を指すUBFM）、完全化、規則による終局評価、根までの逆伝播 | 採用する。候補Aとして、候補Lとは別に採否を測る。 |
| 評価関数 | 価値ネットワーク | 置換。現行の鏡映共有つき2端点PST（13,680特徴）に固定する。線形の評価関数に対する木の学習にはTreeStrapという先行研究があり、推論費用を変えずに学習と探索の効果だけを調べられるためである。 |
| 初期値 | ランダムな終局状態の値による事前初期化 | 置換。S0のPSTを初期値とする追加学習とする。minaseの目的は棋力であり、S0から始めれば学習の周回を棋力の改善だけに使えるためである（2026年9月26日の利用者決定）。 |
| 置換表 | 学習時も対局時も置換表を使い、手番をまたいで保持する | 置換。転置を共有しない木とし、節点を根からの手順ごとに持つ。反復による引き分け、4,000手の上限、終局値 `MATE − p` はいずれも経路と対局開始からの手数で決まるので、局面キーで節点を共有すると、経路の異なる値を1つの節点に混ぜてしまうためである。完全化の健全性も閉路のないゲーム木を前提としている。置換表を除いたUBFMの平均得点は−4.15（チェス−1、中国象棋−6）であり、この損失を受け入れる。 |
| 解決済み状態の記憶 | 対局をまたいで保持し、12時間ごとに消去 | 不採用。置換表と同じく、解決の結果が経路に依存するためである。 |
| 対局時の木の再利用 | 置換表を手番間で保持 | 不採用。UBFMsは`go`のたびに木を作り直す。前の手番の木を新しい局面に対応付ける処理を省くためである。自己対局の生成器では、新しい根の部分木を次の手へ引き継ぐ（「節点の出力」の行）。 |
| 子局面の一括評価 | 展開した子をGPUでまとめて評価 | 不採用。PSTはCPUで1局面ずつ評価しても速く、一括評価による速度の利得がないためである。一括評価はUBFMsの平均得点を約30点押し上げており、一括評価なしの条件ではチェスでαβ探索がUBFMsを上回ったので、この差は候補Aに不利に働き得る。 |
| 学習の頻度 | 1局ごとに学習 | 置換。同時16対局で一定数の対局を生成するごとに学習する周回とする。重みは実行ファイルへ埋め込まれ、学習器はPythonなので、対局ごとの更新は費用に見合わない。 |
| 再生バッファ | 対局単位の層化版（保持局数µ=100、平均使用回数δ=3） | 置換。通常の再生バッファとし、各節点の期待使用回数がδ=3になるように抽出の割合を定める。論文は層化版と通常版の差が小さすぎて分離できなかったと述べており、周回単位の学習では層化の単位が崩れるためである。 |
| 対称性によるデータ拡張 | 盤の対称な局面を追加 | 置換。PSTの鏡映共有が同じ役割を果たすので、データは拡張しない。 |
| 自己対局の1手の探索量 | 2秒から5秒 | 置換。実時間ではなく子局面の評価回数の上限で定める。フェーズ0で2つの候補値を実測し、事前の規則で1つに固定する。評価回数で定めれば、同じシードで生成が再現できるためである。 |
| 手数の上限 | Arimaaで900手を超えた対局を引き分けとした | 採用する。対局開始から4,000手に達した降下と対局を引き分けとする。 |

### minaseに固有の判断

| 項目 | 決定と理由 |
|---|---|
| 同じ予算の対照 | 対照を置かず、Athénanの工程とS0の比較だけを行う。同じ実時間で現行の `selfplay_gen` と先読み教師による追加学習を行う対照は、本学習とほぼ同じ計算時間が追加で必要になるためである（2026年9月26日の利用者決定）。 |
| 計算予算 | 本学習は同時16対局で48時間を上限とする。48時間は論文の比較実験の1回分の学習時間と同じである。予算はフェーズ0の開始前に `data/athenan/manifest.json` に記録し、フェーズ0の実測や学習中の診断を見てから変更しない（2026年9月26日の利用者決定）。 |
| 着手の時期 | [探索局面を用いた評価関数の学習](search-aware-evaluation.md)の完了後に着手する（2026年9月26日の利用者決定）。 |
| 探索の置き場所 | UBFMとDescentは、根から最善の子をたどって展開し、値を根まで逆算する処理を共有し、終局まで降り続けるかどうかだけが異なる。そこで、両者を `crates/minase/src/search/ubfm/` の1つの木の実装に置き、αβ探索の `crates/minase/src/search/alphabeta/` の隣に並べる。子局面の生成には `minase-core` が公開する `Position` の着手と取り消しを使う。 |
| 候補Aの探索の選び方 | 候補Aのコミットでは、USIの`go`がαβ探索の代わりにUBFMsを呼ぶ。起動引数やUSIオプションによる切替は設けない。採否はコミット対コミットの対局で測り、ハーネスに機能比較のスイッチを置かないという[SPRTの手引き](../guides/sprt.md)の原則に従うためである。 |
| 反復の扱い | 根から現在の節点までの経路と対局の履歴に同じ局面キーが同じ手番で現れた節点は、引き分けの終局として扱う。αβ探索の現行の近似と同じであり、貪欲な降下が循環して終わらなくなることも防ぐ。局面キーには、[競技規則](../rules/RULES.md)第24条が同一局面の条件に含める先獅子の状態が入っている。根だけはこの扱いから外し、対局管理層 `Game` が終局を裁定していない限り、`Game` の合法手から展開する。R1の規則セットでは同一局面の2回目や3回目の出現の後も対局が続くので、木の中で反復の終局とした節点が次の手の根になり得るからである。その場合は、その節点の値を捨てて展開し直す。UBFMsの根の候補手は、αβ探索と同じく探索開始時の局面の写し（`SearchSnapshot`）が持つ合法手とする。 |
| 終局の定義 | 最後の王駒の捕獲は勝ち、合法手がないことは負け（第23条）、経路上の反復と対局開始から4,000手への到達は引き分けとする。詰み（第21条）は、次の手で王駒の捕獲として木に現れるので別に判定しない。R1の攻撃側の負けとE0の駒枯れは木の中では判定せず、αβ探索と同じ近似であることを記録する。対局そのものの終了は、対局管理層 `Game` の正確な裁定に従う。 |
| 降下の実装 | 再帰ではなく、経路を明示的なスタックに持つ反復で実装する。降下は最大4,000手に達し得るので、再帰ではスタックが溢れる恐れがあるためである。 |
| 自己対局の開始局面と規則 | 現行の生成器と同じ8〜16手のランダムな開始手順で多様化する。規則セットは、S0の自己対局と同じエンジン既定構成engine-default（L0＋P0＋R1＋E0）とする。 |
| 生成器のメモリ | 生成器は、木の節点数が上限の80万節点（1ワーカー900 MiBに相当）に達したら、その手の探索を終える。バイト数ではなく節点数で数えるので、同じシードで生成が再現する。この上限で探索を終えた手の割合をフェーズ0で記録する。 |
| 節点の出力 | 着手のたびに、新しい根の部分木に含まれない節点を、その時点の値で確定させて出力し、木から解放する。転置を共有しない木では、新しい根の部分木の外にある節点へ以後の降下が届くことはなく、それらの値はもう変わらない。したがって、出力される値は論文の「対局終了時の木全体を学ぶ」処理と同じになり、メモリを1局分の木全体まで溜めずに済む。 |
| 同じ局面の重複 | 転置を共有しないので、別の手順で同じ局面へ至ると、値の異なり得る2件の教師データになる。重複は除かずにそのまま学び、1局あたりの重複件数をフェーズ0で記録する。どちらの値もその手順の木では正しいミニマックス値であり、どちらかを選ぶ規則を足すと実装が複雑になるためである。 |
| 標本の抽出 | 1局から出力する節点は、1局あたりの上限件数を持つreservoir sampling（到来する標本から一定数を等確率で保持する抽出法）で選ぶ。この方法では、出力の時期によらず、1局のすべての節点が同じ確率で残る。上限はフェーズ0の実測から固定する。 |
| 教師データ形式 | 対局結果の欄を持たない新しい形式を定める。PSTの入力に必要な盤面、手番、先獅子の対象升と、節点の値v、完全化値c、解決値r、対局番号、手数、周回番号を持つ。既存のMNSD形式は対局結果を必須とし、その生成器 `selfplay_gen` は戦術局面と反復局面を除外するので、木の節点には使わない。 |
| 学習器 | 既存の `tools/train/pst/` のモデル、射影、量子化、駒除去の損失を再利用する。生成器は、既に公開されている `Pst::decode` で周回ごとの重みファイルを読み込む。既存の学習器は初期重みを駒除去の損失の基準にも使うので、初期重み（前の周回の重み）と基準（全周回でS0）を別々に指定できるようにする。基準が周回ごとに動くと、少しずつの歪みが次の周回の基準に取り込まれて累積するためである。 |
| 損失 | 教師値vとPSTの出力Fから、固定尺度K0で \(\operatorname{BCE}(\sigma(F/K_0),\sigma(v/K_0)) + 1000\,\mathcal L_{\mathrm{removal}}\) を学ぶ。現行の学習と同じ形であり、終局に由来する大きな値は変換後に0または1へ飽和して有界になる。 |
| UBFMsの持ち時間と停止 | αβ探索の時間予算の計算（`crates/minase/src/search/alphabeta/time.rs` の目安時間softと上限時間hard）を `crates/minase/src/search/` 直下へ移して共有する。移動はαβ探索の挙動を変えない。UBFMsは、各反復の開始前に、外部の停止要求、softの経過、評価回数の上限、およびメモリの上限を確かめ、いずれかに当たれば反復を止めて指す。UBFMsの反復1回は1節点の展開（約70回の評価、数十マイクロ秒）なので、反復の途中で打ち切らなくても、停止はhardより十分早く届く。根の展開は最初の反復として制限にかかわらず行うので、停止要求が直ちに届いても、根の子の値から合法手を1つ返せる。 |
| UBFMsのメモリ | 候補Aでは、USI層は`USI_Hash`の容量で置換表を確保せず、その容量をUBFMsの木のメモリの上限とする。UBFMsは展開の前に、その節点の合法手数から必要な容量を見積もり、上限を超えるなら展開せずに探索を止める。置換表と同じ設定で探索のメモリを抑え、測定の`manifest.json`に記録される容量と一致させるためである。 |
| UBFMsの探索制限 | 持ち時間、1手の固定時間、および評価回数（USIの`nodes`に対応させる）に従う。深さの概念を持たないので、深さだけを指定した`go`はエラーとして扱う。 |
| 採否に出す重み | 本学習の最終周回の重みだけを出す。途中の周回を対局結果で選ぶと、採否の測定の前に候補を結果で選ぶことになるためである。 |
| 候補の採否の規則 | 候補Aと候補Lを、それぞれS0とSTCとLTCで測り、フェーズ4の判定表で採否を決める。両方がS0に勝った場合は、候補Aと候補Lを直接比べ、候補Aの優位が示されたときだけ候補Aを採用する。候補Lは対局用の探索を変えず、先読みや複数スレッドを失わないので、両方が使える場合は候補Lを既定とする。 |

## Athénanの探索の動作

本節では、フェーズ0とフェーズ1で実装する探索の動作を、初めて読む人向けに述べる。
木の各節点は、合法手ごとに、子局面の値v、完全化値c、解決値r、およびその手を選んだ回数nを持つ。
完全化値cは、子の部分木で終局まで読み切った結果が勝ちなら1、負けなら−1、それ以外は0であり、解決値rは、その部分木の結果が確定していれば1、していなければ0である。
各節点は、子のvとcを、その節点で手番を持つ側から見た値で保持し、子の側から見た値を親へ伝えるときは符号を反転する。
したがって、相手に有利な子は負の値を持つ。
値の比較には辞書式順序を使う。
これは、cの大きい子を優先し、cが等しければvの大きい子を優先する比較である。

UBFMの反復1回は、次の手順からなる。
まず、根から始めて、解決していない子のうち辞書式順序で最善の子へ、未展開の節点に着くまで降りる。
未展開の節点も、親を展開したときにPSTで評価したvを持っている。
次に、その節点の全合法手を生成し、各子局面をPSTで評価してvとし、終局となる子は終局値で埋める。
最後に、経路を逆にたどって各節点の (c, v) を子の最善値で、rを子の解決状態で更新し、根で選んだ手のnを1増やす。
逆伝播は途中で打ち切らず、根まで行う。

Descentの反復は、UBFMの反復の展開の後に根へ戻らず、いま展開した節点から同じ規則で最善の子へ降りて展開することを、終局に着くか解決済みの節点に着くまで続ける。
解決済みの節点は部分木の結果が確定しているので、それ以上降りずに、その (c, v) をそのまま経路へ逆伝播する。
展開した直後に全ての子が終局だった節点も、その場で解決済みとなり、降下はそこで終わる。
したがって、Descentでは1回の反復ごとに、終局の値か、終局から確定した値が1つ木へ入る。
ただし、根の値が終局に由来するとは限らない。
降りた子が負けと分かれば、親の最善値は、まだ展開していない兄弟の値、つまり親の展開時に評価した静的評価へ移り得るからである。
このため、生成器は出力する節点ごとに、その値がどの葉から来たかを記録する。
葉の種類は、王駒の捕獲と合法手なしによる勝敗の終局、反復と手数上限による近似の引き分け、および未展開の局面の静的評価の3種類とする。

どちらの探索も、根が解決するか、探索の制限に達するまで反復を繰り返す。
制限は、反復を始める前にだけ確かめ、始めた反復は完了させる。
UBFMsの反復は1節点の展開なので、この規則による制限の超過は数十マイクロ秒に収まる（「UBFMsの持ち時間と停止」の行）。
生成器のDescentの反復は終局まで続くので、1手の評価回数は上限を超え得る。
生成器は時間ではなく評価回数で制限するので、この超過は再現性を損なわず、その量をフェーズ0で記録する。
探索を終えたら、手番側から見てc=1の子（勝ちが確定した子）があればそれを指し、c=−1の子（負けが確定した子）は、c=−1でない子が1つでもある限り選ばない。
それ以外の場合、自己対局の生成器は後述の順序分布で着手を選び、対局用のUBFMsはnが最大の手を指す。
nが等しい手の間では、辞書式順序で最善の手を指す。
この規則は、読みの浅い手がたまたま高い値を持っていても、それを指してしまう危険を減らすためにある。

順序分布は、候補の手を辞書式順序で最善から並べ、先頭から順に採否を決める。
残りの候補がk手のとき、先頭の手を確率 \((\varepsilon'(k-1)+1)/k\) で選び、選ばなければ次の手へ進む（論文のAlgorithm 14）。
この確率は、ε′=1なら1（常に最善手）、ε′=0なら1/k（残りから一様に選ぶ）となり、その間を線形に補間する。
したがって、選ばれる確率は評価値の差の大きさではなく順位だけで決まる。

論文は同値の子を乱数で選ぶ。
本書では再現性のため、生成器の乱数を対局番号と手数から導くシードで生成し、UBFMsでは合法手の生成順で最初の子を選ぶ。

## USI層の変更

候補Aは、αβ探索を前提にしたUSI層の処理を次のとおり変える。
これらの変更は、`go`がUBFMsを呼ぶ変更と同じ1つのコミット（以下、切替コミット）にまとめ、フェーズ1の診断用のコミットとフェーズ4の候補Aの両方に同じ内容で適用する。

- `go`はUBFMsを呼ぶ。深さだけを指定した`go`と`go ponder`はエラーとして応答し、探索しない。UBFMsは予想手を出力しないので、正しいGUIやハーネスから`go ponder`が届くことはない。
- `bestmove`は予想手（`ponder`）を付けない。現行のUSI層は探索結果の手順の2手目から予想手を作るが、切替コミットではこの処理を通さない。
- 投了しない。現行の投了は評価値と深さで判定するが、UBFMsは深さを持たないので、`ResignValue`の値にかかわらず投了の判定を通さない。
- `info`は深さを含めずに、評価回数、経過時間、根の値、および最善の子をたどった手順を出力する。現行のUSI層は深さが増えたときに最終の`info`を出すが、切替コミットでは探索の終了時に1回出す。
- 根の値の完全化値cが0なら値vを`score cp`で出力する。cが±1なら、終局値 `±(MATE − p)` から終局の手数pを逆算し、根からの手数を`score mate`で出力する。
- `USI_Hash`の容量で置換表を確保せず、その容量をUBFMsの木のメモリの上限とする。`Threads`の値にかかわらず1スレッドで探索する。

## 候補Aを採用する場合の統合

UBFMsは、αβ探索が備える先読み（`go ponder`）、Lazy SMPによる複数スレッドの探索、および投了（`ResignValue`）を実装しない。
候補Aのコミットは、予想手を出力しないので先読みの対象にならず、`Threads`の値にかかわらず1スレッドで探索し、投了しない。
段階ゲートの標準コマンドは先読みも複数スレッドも使わず、ハーネスは投了を無効にするので、この欠落は採否の測定に影響しない。
一方、lishogiのBotは先読みを有効にして運用しているので、候補Aをそのまま統合すると運用中の機能が失われる。

候補Aを採用した場合に、次のどれを選ぶかは利用者の判断を待っている。

1. 候補Aをそのまま統合し、3つの機能は後続の計画でUBFMsへ移す。
2. 3つの機能をUBFMsへ移す後続の計画を先に完了させ、その後に統合する。
3. 候補LもS0に対して通過していれば候補Lを統合し、候補Aは測定記録とブランチとして残す。

αβ探索を残して起動時に選べるようにする案は、使われない探索の保守を抱えるので、この一覧に含めない。

## 計算量の見積り

着手前の桁を次のとおり見積もる。
[係数の表の速度測定](../measurements/bench-spsa-params-nps.md)の深さ8のNPS（1秒あたり探索ノード数）は約212万であり、子局面の評価1回がαβ探索の1ノードと同程度の費用だと仮定する。
子局面の評価は着手の適用、PSTの評価、および取り消しからなり、展開ごとに合法手の生成が1回加わる。
αβ探索の1ノードも同じ処理に置換表の参照と手の順序付けを加えたものなので、桁は同じと見込む。

自己対局については、[FM候補の診断](../measurements/fm-candidate-diagnostics.md)の代表6局面の合法手数が34手から96手なので、1手の評価回数の上限を100万回とすると、1手は約0.5秒、中央値420手の対局は1局約3.5分になる。
同時16対局なら1時間に約270局であり、48時間では約1万3,000局になる。
ただし、順序分布による確率的な着手は対局を長くし得るので、この見積りはフェーズ0の実測で置き換える。
メモリは、測定機の実メモリ30 GBのうち同時16対局で半分以内に収めるため、1ワーカーあたり最大常駐メモリ900 MiB（16ワーカーで約15 GB）を上限とする。
展開した節点1つは、合法手ごとに着手、v、c、r、nを持つので1手あたり約16バイト、合法手70手で約1.1 KBを要し、この上限は約80万節点に当たる。
木に残るのは現在の根の部分木だけだが、転置を共有しないので同じ局面が重複して残る。その節点数はフェーズ0で実測する。

対局用のUBFMsは、1回の展開で約70回の評価を行うので、1秒あたり約3万節点を展開し、木は1秒あたり約33 MB増える。
`USI_Hash`の既定の256 MBに達するのは約8秒の探索であり、STCとLTCの1手の目安時間はこれより短いと見込む。
実際の到達はフェーズ1の対局で記録する。

## 実装フェーズ

### フェーズ0　実現性の実測

`crates/minase/src/search/ubfm/` の木、UBFMとDescentの反復、完全化、終局の判定、節点の出力、および `descent_gen` の自己対局を実装する。
開始前に、S0のコミット、48時間の予算、およびフェーズ0の続行基準をmanifestへ固定する。
S0の重みを固定し、学習はしない。
1手の評価回数の上限を10万回と100万回の2通りにして、それぞれ64局（32ペアの開始手順）を生成し、次の量を記録する。

- 降下1回の長さの分布と、1手あたりの降下回数を記録する。
- 降下の終わり方を、王駒の捕獲、合法手なし、反復、手数上限、および解決済みの節点に分けた割合として記録する。解決済みの節点で終わった降下は、その節点の完全化値cが±1なら勝敗、0なら引き分けとして下位分類する。
- 出力した節点の値の由来を、勝敗の終局、近似の引き分け、静的評価に分けた割合として記録する。
- 1手ごとの実際の評価回数と、上限からの超過量、および節点数の上限で探索を終えた手の割合を記録する。
- 1局の手数、所要時間、出力節点数、同じ局面の重複件数、およびワーカーの最大常駐メモリを記録する。
- 対局の終わり方を、対局管理層 `Game` の裁定理由（王駒の捕獲、詰み、合法手なし、反復、駒枯れ）と、生成器が独自に打ち切る4,000手の上限とに分けて記録する。4,000手目の着手で `Game` が終局を裁定した場合は、`Game` の裁定を優先する。

評価回数の上限は、次の続行基準をすべて満たす候補のうち小さいほうに固定する。

1. 64局の全降下を合計した件数の50%以上が、王駒の捕獲、合法手なし、またはcが±1の解決済みの節点で終わる。
2. ワーカーの最大常駐メモリが900 MiB以下である。
3. 同時16対局で、48時間の予算の80%にあたる38.4時間に、生成だけで1,000局以上を生成できる。残りの20%は周回ごとの学習の時間に充てる。

基準1は、論文の機序である「降下のたびに終局の勝敗が木へ入る」ことが中将棋でも働くかを判定する。
降下の過半が反復や手数上限という近似の引き分けで終わると、木に伝わる終局値の大半が、勝敗ではなく本書の近似が与えた0になる。
cが0の解決済みの節点で終わる降下を数えないのは、本書の木の引き分けがすべて反復か手数上限による近似に由来するからである。
過半を境にしたのは、勝敗による終局値が近似の引き分けより多いことを最低限の条件とするためであり、この割合は評価回数の上限ではなく降下の性質で決まるので、2つの候補に同じ基準を使う。
基準2はメモリの節の上限であり、基準3は、論文のArimaaの学習（6,317局）やHexの13×13の学習（5,288局）と同じ千局の桁の対局数を予算内に確保する条件である。
これらの数値は計算を投じる前に固定する運用上の基準であり、統計的な保証ではない。

出力節点の値の由来の割合は、続行の判定には使わず、学習結果の解釈に使う診断とする。
辞書式順序で値を逆算する木では、値が勝敗の終局に由来する節点は、完全化値cが±1の節点、つまり木の中で勝ちか負けが確定した節点と一致する。
対局の序盤や中盤の節点がそのように確定することは構造上まれなので、この割合に下限を課すと、仮説を試す前に計画を止めてしまうおそれがある。
論文の主張も、終局の値がより速く他の節点へ伝わることと、生成される局面が終局に近いことであり、教師値の多くが終局に由来することではない。
ただし、探索値だけを教師とした[混合比λ=1.0の候補](teacher-mixing-ratio.md)は短時間測定で得点率28.0%と大きく負けたので、採否で負けた場合には、この割合を自己参照の教師の危険を示す記録として参照する。
どちらの候補も基準を満たさなければ、本書を見送りとして完了し、測定記録に理由を残す。
記録は `athenan-feasibility` とする。

### フェーズ1　対局用のUBFMs

UBFMsを、フェーズ0の木を使う対局用探索として実装する。
αβ探索の時間予算の計算を `crates/minase/src/search/` 直下へ移し、移動の前後でαβ探索の`bench`のノード数と、代表的な持ち時間に対するsoftとhardの値が変わらないことを確認する。
UBFMsのライブラリの実装は作業ブランチに置き、「USI層の変更」の節の切替コミットは作業ブランチから分岐した別のブランチで作る。

動作確認のため、学習前でS0のPSTを持つ作業ブランチに切替コミットを適用した診断用のコミットを作る。
このコミットをS0とSTCの持ち時間で固定200ペア対局させ、固定局数のEloと95%信頼区間を記録する。
この対局は、UBFMsを時間制御の対局に初めて出す測定なので、[SPRTの手引き](../guides/sprt.md)に従い、時間切れ、エンジン異常、または拒否着手が1件でも出れば停止して原因を調べる。
Eloは、S0のPSTの下での対局側の効果を示す診断であり、続行、停止、または候補の選択には使わない。
測定名は `athenan-ubfms-s0-elo` とし、1手あたりの展開節点数と木のメモリの最大値も記録する。
異常件数が0で完了したら、フェーズ1を完了とする。

フェーズ1の実装は、フェーズ0の測定中に進めてよい。
ただし、フェーズ1の対局は、測定機を共有するので、フェーズ0の測定の後、本学習の前に行う。

### フェーズ2　学習の周回

教師データ形式のPython読み込み、再生バッファ、周回の駆動器を実装する。
周回の大きさ、再生バッファの対局数、1周回の更新回数、学習率、1局あたりの出力上限を、フェーズ0の実測から固定し、`data/athenan/manifest.json` に記録する。
再生バッファの抽出の割合は、各節点の期待使用回数が3回になるように、周回の大きさと再生バッファの対局数から定める。
学習率と駒除去の損失の係数は、現行の学習手順の0.03と1000から始める。
[1エポックの更新回数の教訓](../lessons/check-steps-per-epoch-before-training.md)に従い、固定した設定で本学習全体の更新回数が数千回以上になることを確認する。
4周回の試運転で、重みの読み込み、書き出し、生成器での再読み込み、学習損失の低下が一巡することを確かめて完了とする。

### フェーズ3　本学習

48時間の予算で周回を繰り返す。
周回ごとに、訓練損失、保持した検証用の節点に対する損失、S0に対する重みの差、および駒除去の診断を記録する。
10周回ごとに、S0と固定10万ノードで50ペアを対局させて進捗を記録する。
この進捗の対局は診断であり、途中の停止、延長、重みの選択には使わない。

次の場合は本学習を停止する。

- 非有限値が発生した場合は、不具合を修正して同じ設定で最初からやり直す。
- 周回の重みが、S0を基準とする[PSTの学習手順](../guides/pst-training.md)の既存の駒除去診断に合格しなかった場合は、その周回で停止し、原因を調べる。設定を変えずに解消できなければ見送りとする。既存の診断は、S0と符号が異なる除去の評価差を、改善の向きであっても拒否する。
- 予算に達した場合は、最終周回の重みを候補とする。

記録は `athenan-training` とする。

### フェーズ4　採否と現行設計の更新

最終周回の重みを `crates/minase/nets/pst.bin` に置いたコミットを候補Lとし、候補Lに切替コミットを適用したコミットを候補Aとする。
候補Aと候補Lは、他方の結果を待たずに、それぞれS0に対して[標準手順](../guides/sprt.md)のSTCで測る。
STCからLTCへ進めるかどうかは、手引きの振分け規則に従い、候補ごとに決める。
LTCが`pending`となった場合は、手引きに従い`--resume`で延長して判定を得る。
候補の採否は、S0に対するLTCの結果から次の表で決める。
ここで「通過」は、LTCで`H1`となり、エンジン異常、時間切れ、および拒否着手が0件であることをいう。
STCで振り落とされた候補は、通過しなかったものとして扱う。

| 候補AのS0に対する結果 | 候補LのS0に対する結果 | 採否 |
|---|---|---|
| 通過 | 通過 | 両方の結果が出た後に、候補Aを候補Lに対してSTCとLTCで測る。LTCが`pending`なら同じく延長し、候補Aが通過すれば候補Aを、しなければ候補Lを採用する。 |
| 通過 | 通過しない | 候補Aを採用する。 |
| 通過しない | 通過 | 候補Lを採用する。 |
| 通過しない | 通過しない | どちらも採用せず、不採用として完了する。 |

測定名と基本シードは次のとおりとする。
準備時に、各測定の基本シードから、延長を含めて使い得るペア数の範囲が、既存の実行記録および他の測定の範囲と重ならないことを検査する。

| 測定 | 測定名 | 基本シード |
|---|---|---|
| 候補A対S0のSTC | `athenan-a-stc` | 191000926 |
| 候補A対S0のLTC | `athenan-a-ltc` | 192000926 |
| 候補L対S0のSTC | `athenan-l-stc` | 193000926 |
| 候補L対S0のLTC | `athenan-l-ltc` | 194000926 |
| 候補A対候補LのSTC | `athenan-a-vs-l-stc` | 195000926 |
| 候補A対候補LのLTC | `athenan-a-vs-l-ltc` | 196000926 |
| UBFMsの動作確認（フェーズ1） | `athenan-ubfms-s0-elo` | 197000926 |

候補Lを採用した場合は、[評価関数](evaluation.md)と[PSTの学習手順](../guides/pst-training.md)の現行の教師と学習方法を更新する。
候補Aを採用した場合は、それに加えて、次節の利用者の判断に従ってmasterへ統合する。

## 検証

検証の期待値は論文のアルゴリズムと[競技規則](../rules/RULES.md)から定め、実装の出力をそのまま正解にしない。

| 対象 | 独立した期待値と確認事項 |
|---|---|
| 完全化 | 論文の図3と同じ形の小さな木で、未解決の高い値より解決済みの勝ちを選ぶ。 |
| 解決値 | 全ての子が解決した節点は解決し、勝ちの子が1つあれば他の子が未解決でも解決する。解決済みの節点に着いた降下はそれ以上降りず、展開直後に全ての子が終局だった節点で降下が終わる。 |
| UBFMとDescentの反復 | 手で作った小さな木で、UBFMの反復1回は1節点だけを展開し、Descentの反復1回は終局または解決済みの節点まで展開を続ける。どちらも逆伝播を根まで行う。 |
| 安全な決定 | 値が最大の手と選択回数nが最大の手が異なる木で、UBFMsはnが最大の手を指し、nが等しい手の間では辞書式順序で最善の手を指す。勝ちが確定した子があれば、nにかかわらずそれを指す。 |
| 終局の判定 | 手で作った局面で、最後の王駒の捕獲、合法手なし、経路上の反復、手数上限の各終局値を確認する。王将と太子の両方を持つ側は、一方を取られても終局しない。 |
| 視点 | 先手と後手の節点で、最善の子の選択と値の符号が手番側から正しいことを確認する。 |
| 根の合法手 | R2の規則セットでは既出局面を再現する手が、R3の規則セットでは同じ局面の4回目の出現を生む手だけが、UBFMsの根の候補に入らない。R3で2回目と3回目の出現を生む手は候補に入る。根の候補はいずれも `SearchSnapshot` の合法手と一致する。 |
| 反復の根の再展開 | R1の規則セットで、木の中で反復の終局とした節点が次の手の根になったとき、その節点を `Game` の合法手から展開し直す。 |
| USI層 | 切替コミットで、`bestmove`が予想手を付けず、投了せず、深さのない`info`を出し、深さだけの`go`と`go ponder`をエラーとして応答する。完全化値cが±1の根では`score mate`の手数が根から終局までの手数と一致する。 |
| UBFMsの制限 | 持ち時間ではsoftに達した時点で、`nodes`では評価回数の上限で、`USI_Hash`では木のメモリの上限で、`stop`では次の反復の前に止める。停止要求が探索の開始直後に届いても、合法手を1つ返す。 |
| 時間予算の共有 | 時間予算の計算を移す前後で、αβ探索の`bench`のノード数と、代表的な持ち時間に対するsoftとhardの値が一致する。 |
| 節点の出力 | 同じ対局を、着手ごとの出力と対局終了時の一括出力の2通りで実行し、出力された節点の値が一致することを確認する。別の手順で同じ局面へ至る転置を含む局面列も用い、2つの経路の節点が別々に保たれることを確認する。 |
| 再現性 | 同じシードと評価回数の上限で、同じ対局と同じ出力が得られる。UBFMsは、同じ局面と同じ評価回数の上限で同じ手を指す。 |
| 教師データ | Rustの書き出しとPythonの読み込みで、盤面、先獅子、値が往復で一致し、PSTの評価もRustとPythonで一致する。 |
| 学習 | 固定した小さなデータで、損失が下がり、射影後の重みが保存範囲に収まる。 |

実装時には `cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check` と、変更した学習器の単体テストを通す。
計画書の作成だけを理由に生成や対局測定を実行しない。

学習した重みを対局へ出す前に、[検証損失が駒価値の歪みを隠す教訓](../lessons/validation-loss-hides-material-distortion.md)に従い、初期配置から駒種を1つずつ除いた局面の評価をS0と比べる。
学習が停滞した場合は、[学習曲線を先に確認する教訓](../lessons/check-learning-before-blaming-data.md)に従い、データ量を増やす前に学習器の欠陥を疑う。

## 完了条件

- フェーズ0の見送り、本学習の停止規則による見送り、または2つの候補の採否のいずれかが、事前の規則に従って測定記録とともに確定している。
- 採用する候補は、フェーズ4の判定表の条件を満たしている。
- 見送りまたは不採用の場合は、否定された仮説の範囲（学習側と対局側のどちらか、PSTへの適用、評価回数の上限、予算）と、未検証の範囲（ニューラルネットの評価関数、子局面の一括評価、置換表つきのUBFMs）を区別して記録している。
- 本書の「Athénanの構成要素の採否」の表が、実装した内容と一致している。
- 現行設計、本書の要約と状態、ROADMAPが結論と一致している。

# 秒読みつき時計での持ち時間と秒読みの活用

## 先に読む要約

本書は、lishogiのBotとして指すminaseが、秒読みつきの時計で持ち時間と秒読みを有効に使えていない問題を解決するマイルストーンの設計書である。
秒読みつきの時計とは、持ち時間が残る間は思考時間の全額を持ち時間から引き、持ち時間を使い切った後は1手ごとに一定の秒読みBを与え、使わなかった秒読みを持ち越さない時計をいう。
本書では、持ち時間が残っている間の手を持ち時間期の手、使い切った後の手を秒読み期の手と呼ぶ。
[実戦の調査](../research/lishogi-byoyomi-time-usage.md)では、2つの損失が見つかった。
第1に、秒読み期の手は秒読みの平均55%しか使わず、残りは使い残すか、打ち切って捨てた探索に消えている。
第2に、持ち時間が秒読みの10〜26倍しかない短い対局では、持ち時間期の手も秒読み期の手とほぼ同じ時間しか使わず、持ち時間が1手の読みをほとんど深くしていない。
対策は2段階で行う。
段階Aでは、秒読み期に締切近くまで探索を続け、締切で打ち切った探索の途中結果を着手に採用する。
段階Bでは、持ち時間期の各手に使う時間を局面の難しさで重み付けし、持ち時間の消費の速さが異なる3つの候補を比べる。
3候補は、予算の水準を現行に保つB0、持ち時間を早く使って持ち時間期の手を深くするB1、持ち時間を200手目まで残すB2である。
変更は秒読みが正の時計に限り、秒読みのない時計（標準の測定条件を含む）の挙動は現行と同一に保つ。
採否は、持ち時間と秒読みの比が20と150の2つの秒読みつき条件の自己対局GSPRT（逐次検定）で判定する。

## 状態

起案。2026年10月6日に起案した。
次の一手は、フェーズ0で締切の余裕と難しさの重みを実戦ログから確定し、各候補の消費の予測を本書へ記入することである。
測定の方式（秒読みつき条件のGSPRT）は、時間配分の変更を時計の診断だけで判定するとした2026年9月16日の決定と異なるので、着手前に利用者の確認を要する。

## 目的

秒読みつきの時計で、秒読み期の使い残しをなくし、持ち時間を難しい手の読みに振り向けて、棋力を上げる。
対象は、持ち時間が秒読みの10〜26倍の短い対局と、120〜150倍の長い対局の両方である。
持ち時間が尽きる手数そのものは目的にしない。
持ち時間が尽きる手数が早まっても遅くなっても、2つの条件の自己対局で強くなった候補を採る。

## 適用範囲

対象は次のとおりである。

- `crates/minase/src/search/alphabeta/time.rs`の予算式と反復の開始判定のうち、秒読みが正の時計に関わる部分。
- 根の探索（`root.rs`）の手の順序と打ち切り時の結果、および反復深化の外殻（`deepening.rs`）とワーカー間の結果の選択（`team.rs`）。
- USIオプション`ByoyomiMargin`の追加（`crates/minase/src/protocol/usi.rs`）。
- 予算と停止の契約テスト（`tests/time.rs`、`tests/tuning.rs`、`tests/ponder.rs`、`tests/team.rs`）とその台帳。
- Lishogi-Botの設定（`minase-lishogi-bot`リポジトリの`config.yml`の`usi_options`）。

対象外は次のとおりである。

- 秒読みが0の時計（加算方式、STCとLTC）、`movetime`、深さ、ノード数による探索。これらの予算、開始判定、および打ち切り時の結果は現行と同一に保つ。
- 秒読みの回数（periods）。Lishogi-Botは回数をエンジンへ送らないので、常に1回として扱う。
- 持ち時間が秒読みより少ない手で、残りの持ち時間と秒読みを1手で使い切る規則（YaneuraOuの`isFinalPush`）。1局に1手しか関わらないので扱わない。
- Lishogi-Botの`move_overhead`と、エンジンへ渡す持ち時間から秒読みを引く換算。
- 時計の規則。持ち時間が残る間は思考時間の全額を持ち時間から引く時計（lishogiと対局ハーネスの規則）を前提とする。

## 設計判断

記号を次のとおり定める。
Rはエンジンが受け取った持ち時間、Bは秒読み、mは秒読みの締切の余裕（`ByoyomiMargin`、ミリ秒）、`b = max(1 ms, B − m)`は秒読み期に使える時間である。
`mtg`は現行の残り手数の見積り`max(88, (432 − ply) / 2)`、wは序盤の係数`min(1, (ply + 4) / 40)`、`soft_raw`は現行の`R / mtg + 0.76·加算 + 0.8·B·w`である。
時間はすべて整数ミリ秒で計算し、除算の端数は切り捨てる。

本書の変更を適用する探索を「対象の探索」と呼ぶ。
対象の探索とは、時計（`btime`、`wtime`など）による探索のうち、秒読みが正で、`movetime`、深さ、およびノード数の制限を併用しないものをいう。
予算、反復の開始判定、先読みの的中後の判定、根の手の順序、および途中結果の採用は、すべてこの1つの条件で切り替える。
対象でない探索は、併用の場合も含めて、現行の経路をそのまま通る。

| 判断 | 内容 |
|---|---|
| 損失の所在 | [実戦の調査](../research/lishogi-byoyomi-time-usage.md)によると、秒読み期の手の思考時間は中央値0.515B、主ワーカーが最後に反復を完了した時刻は平均0.423Bである。持ち時間期の思考時間をtとすると、持ち時間が秒読みに比べて上積みする思考時間は`R(1 − uB/t)`（uBは秒読み期の手の実際の思考時間）であり、短い対局ではt/uBが約1.2なので上積みは持ち時間の約2割にとどまる。難しい手の76%は秒読み期に現れ、秒読み期には難しい手も易しい手と同じ時間しか使わない。 |
| 変更を秒読みが正の時計に限る理由 | 人間との対局で棋力を落とす変更は許容しないという2026年9月18日の利用者の決定がある。秒読みのない時計の挙動を式とコードの経路の上で現行と同一に保てば、標準のSTCとLTCで測る必要がなく、その条件の棋力も変わらない。秒読みが正かどうかは`ClockLimits::byoyomi_ms`で判別できる。`movetime`などとの併用を対象から外すのは、現行の`time_budget`が併用時に両者の小さい方を採るので、秒読みの有無だけで切り替えると併用の探索の予算と根の順序が変わるからである。 |
| 秒読み期の締切 | 対象の探索で持ち時間が0の手では、softとhardをともにbとし、経過時間がb未満の間は次の反復を始める。予測完了時刻による開始の制限と、最善手安定時の早期終了は適用しない。先読みが的中した手では締切を的中時刻から数え、的中前に始めた反復を的中時に予測で打ち切る処理（`searcher.rs`の当て直し）も適用しない。未使用の秒読みは持ち越せないので、反復を始めて時間を使うことに損失がないからである。YaneuraOuも秒読み期は秒読みから通信の余裕を引いた時刻まで探索し、締切で打ち切った反復の結果を使う（`source/timeman.cpp`の`round_up`と`NetworkDelay2`）。持ち時間が正の手では、これらの予測による判定を現行どおり残す。 |
| 締切の余裕を絶対値のUSIオプションにする理由 | 通信の遅延は秒読みの長さに比例しないので、余裕は秒読みに対する割合ではなくミリ秒の絶対値で与える。現行の秒読み期のhard`0.8·B`は、B＝60秒で12秒の余裕を残す一方、B＝1秒では0.2秒しか残さない。Lishogi-Botは秒読み期に`move_overhead`を引かずに秒読みの全額を送るので、通信の余裕はエンジン側で持つ必要がある。`ByoyomiMargin`の既定値30 msは現行の安全上限`remaining + byoyomi − 30 ms`と同じ値であり、対局ハーネスの条件を変えない。Botの値はフェーズ0で実測から決め、`usi_options`で渡す。秒読みが正の時計では安全上限も`remaining + byoyomi − m`に置き換え、既定値では現行と一致する。秒読みが0の時計では`ByoyomiMargin`を参照せず、安全上限は現行の30 msのままとする。 |
| 途中結果の採用 | 締切近くまで反復を始めると、模擬では最後に始めた反復の36〜64%が締切までに完了しない（[実戦の調査](../research/lishogi-byoyomi-time-usage.md)の「反復時間の比と開始条件の模擬」）。完了しない反復を捨てると、増やした時間の多くが着手に反映されないので、打ち切った反復の途中結果を「途中結果の採用」の節の規則で採用する。StockfishとYaneuraOuはいずれも、打ち切った反復で完了した手の評価値を保持し、安定な整列によって途中で見つかった新しい最善手を返す。 |
| 途中結果の採用を棄却済みとしない理由 | 9月の再構成の第1段階は途中結果の採用を含んで不採用となったが、同じ段階で予算を公平な分担そのものにして反復完了による超過を断ち、総思考時間を約14%使い残したことが敗因と特定されている（[予算の機構を変えたら総思考時間と使い残しを現行と比べる](../lessons/compare-total-time-usage-before-sprt.md)）。途中結果の採用だけを分けた測定はない。本書は、時間を使い残さない秒読み期の締切と組み合わせて採用を測る。 |
| 難しさの信号 | 主ワーカーが深さ6以上の反復を完了するたびに、「その反復または直前の反復で最善手が変わった」か「深さdの反復の評価値が深さd − 2の反復より歩兵1枚の価値（評価関数の`pawn_value`）以上低い」ときに真とする。2つ前の反復と比べるのは、深さの偶奇によって評価値が振動するためである。実戦の調査の定義から、直前の自分の手との比較を除いた。この比較には探索をまたぐ状態が必要であり、探索の外に状態を持たせる変更を避けるためである。反復ごとの評価値を保持する必要があり、現行の外殻は最善手の列だけを保持する。 |
| 持ち時間期の重み付け | 対象の探索で持ち時間が正の手では、候補ごとの基準時間`base`から、hardを`max(1 ms, min(4.51·base, 0.27·R + 0.8·B, R + B − m))`とする。これは現行の式の`soft_raw`を`base`に置き換えたものであり、残り時間の割合の項を残す（[打ち切り上限は残り時間の割合でも抑える](../lessons/cap-hard-limit-by-remaining-fraction.md)）。softは、難しさの信号が真なら`min(base·r / v̄, hard)`、偽なら`min(base / v̄, hard)`とし、現行の契約`soft ≤ hard`を保つ。rは難しい手と易しい手の時間の価値の比、pは難しい手の割合である。易しい手の重みを1、難しい手の重みをrとすると、重みの平均は`v̄ = (1 − p) + p·r`なので、hardで切られない限り、softの期待値は`(1 − p)·base / v̄ + p·r·base / v̄ = base`になる。この等式が保つのはsoftの期待値だけであり、実際の思考時間は最善手安定時の早期終了、反復の完了による超過、hard、および探索の途中での信号の変化に左右される。実戦の持ち時間期では、思考時間とsoftの比の中央値が最善手の安定した手で0.643、そうでない手で1.406だった。このため、各候補の実際の消費の速さはフェーズ0の再生で別に予測する。rには、実戦の持ち時間期で「次の完了反復で最善手が変わる割合」の難しい手と易しい手の比を使い、読み続けて最善手が変わる見込みを時間の価値の代理とみなす。最善手安定時の早期終了とhardの予測による開始の制限は現行どおり残す。 |
| 消費の速さが異なる3候補 | 時計の規則から、持ち時間が残る間は易しい手の時間も持ち時間から引かれるので、後半の難しい手のために持ち時間を残すには前半の手を秒読み期より浅くする代償がある。どちらが強いかは模型から決まらないので、`base`だけが異なる3候補を測る。B0（集中）は`base = soft_raw`とし、予算の水準を現行に保って手の間で配り直すだけにする。B1（速い消費）は`base = max(R / mtg, w·κ*·b)`とし、対数価値模型の最適値κ*で持ち時間を早く使い切る。B2（予備の確保）は`base = R / max(1, (200 − ply) / 2)`とし、秒読みの項を外して、持ち時間を200手目まで均等に残す。200手目は、実戦の調査で難しい手が初めて過半になる100〜200手の帯の終わりであり、調べた対局11局のうち9局は200手を超えた。`R / mtg`のように想定終局から配る式では、`mtg`に下限88があるので持ち時間が毎手一定の割合でしか減らず、有限の手数で尽きないため採らない。200手目を過ぎて持ち時間が残っていれば`base = R`となり、hardの`0.27·R`の項で数手に分けて使い切る。200は判断値であり、値違いの候補は追加しない。B2は、2026年9月16日に不採用とした持ち時間の温存を、難しさの重み付きの形で再検討する候補であり、2026年10月6日の利用者の決定で候補に含めた。 |
| κ*の導出 | 持ち時間期の手の価値をv·ln(t / b)（vは手の重み、tは思考時間）とし、持ち時間期の手数をR / baseとすると、総価値を最大にする`base / b`は`e·exp(−E[(v/v̄)·ln(v/v̄)])`である。重みがすべて等しければeとなり、KataGoの`divideTimeEvenlyForGame`が注記する最適値（秒読みのe倍を毎手使う）と一致する。手数による重みの変化と探索の中で判明する難しさは模型に含めないので、κ*は候補を定める値であり、採否は測定が決める。序盤の係数wは、最初の数手で秒読み相当の長考をしないという2026年9月17日の利用者の決定に従って残す。 |
| 加算方式で不採用となった延長との関係 | 難しさに応じた延長は、段階6（fail-lowと最善手交替による延長）と9月の再構成の第3段階（Stockfishの係数）で、いずれも加算方式のSTCで不採用となった。第3段階は、持ち時間を200手目までに使い切らせたことが主因である。加算方式では毎手の加算が持続的な予算なので、延長は同じ予算の中の配り直しにしかならない。秒読みつきの時計では、持ち時間期の手が秒読み期と同程度の時間しか使わない限り持ち時間の上積みはほぼ0であり、難しい手へ集中させると上積みそのものが増える。この違いが棋力に表れるという仮説を測る。B0からB2がいずれも負けた場合は、段階Aだけを採否にかける。 |
| 採否の判定方法 | 段階Aは途中結果の採用で着手を変え、段階Bは手ごとの時間を変えるので、時計の診断では棋力の変化を判定できない。2026年9月16日の決定（時間配分の変更は時計の診断で判定する）は、各手の時間の上限を下げるだけの変更を想定したものである。本書の変更は強くすることを目的とするので、2026年10月1日の利用者の指示（強くなっていることが大事）に従い、秒読みつき条件のGSPRTで判定する。この選択は着手前に利用者の確認を要する。 |

## 途中結果の採用

本節の規則は、根の手の順序の変更を含めて、対象の探索だけに適用する。
対象でない探索では、根の手の順序と打ち切り時の結果を現行のまま保つ。
規則は9月の再構成の第1段階のものを引き継ぐ（タグ`archive/time-management-d1`のコミットの`search_root`と`partial_result`）。

根の手の順序は、直前に完了した反復の最善手を先頭に置き、残りを現行の`order_moves`で整列する。
現行は根の置換表の記録手を先頭へ移すだけであり、他のワーカーの記録で上書きされ得るので、直前の最善手が先頭に来るとは限らない。

hardで根の探索が打ち切られたとき、打ち切られた窓で直前の最善手の探索が完了していれば、その窓で完了した手のうち、評価値が上界でない手の最大値を求める。
最大値が窓に入ったときの下限を上回れば、その手を途中結果として返し、そうでなければ現行どおり最後に完了した反復の結果を使う。
窓とは、根の探索に与える評価値の上下限であり、aspiration windowsは直前の反復の評価値の周りに狭い窓を置いて探索し、結果が窓の外に出れば窓を広げて同じ深さを読み直す手法である。
窓を広げて読み直している最中に打ち切られた場合は、窓ごとに結果を消去しているので、直前の最善手が新しい窓で完了していなければ採用しない。
途中結果の深さは完了深さとして数えず、`info string partial`で採用を出力する。

途中結果が決めるのは着手と予想手（主変化の2手目）だけである。
途中結果の評価値は、未探索の手を含む根全体の値ではなく下界にすぎず、負の詰みの値でも負けの証明にならない。
このため、途中結果では根の置換表へ記録せず、投了の判定（`usi.rs`の`ResignValue`との比較）には最後に完了した反復の評価値と完了深さを使う。
`info`の評価値は途中結果の値を下界として`lowerbound`を付けて出力する。

ワーカー間の選択は`(完了深さ, 途中結果の有無, 番号の小ささ)`の辞書式順序で行う。
深さdを完了して深さd＋1の途中結果を持つワーカーは、深さdだけを完了したワーカーより優先し、深さd＋1を完了したワーカーより劣後する。
`tests/ponder.rs`の、当て直しで打ち切った主ワーカーの反復を採用しないことを固定する検査は、対象でない探索と持ち時間が正の手については残し、対象の探索の秒読み期については当て直しを行わない検査へ分ける。

## 候補の予測

フェーズ0で、r、p、κ*、およびmを確定し、各候補の消費を予測して次の表を埋める。
予測は2段階で行う。

第1段階では、1手の実際の思考時間を求める。
実戦ログの持ち時間期の先読み非的中の手それぞれについて、記録された主ワーカーの反復の完了時刻と、各反復の完了時点の難しさの信号と最善手安定の判定を使い、候補の式によるsoftとhardで開始判定を再生して停止時刻を求める。
記録より先の反復を始める場合は、[実戦の調査](../research/lishogi-byoyomi-time-usage.md)の模擬と同じく、累積時間の層ごとの反復時間の比の分布から抽選する。
この再生から、思考時間を`base`で割った比の分布を、手数帯ごとに得る。

第2段階では、時計を1手ずつ進める。
各時計について、初形から手番側の持ち時間を減らし、各手の`base`に第1段階の比の分布から抽選した値を掛けて思考時間とする。
対局を1,000回模擬し、持ち時間が尽きる手数の中央値、432手目までに尽きなかった対局の割合、および432手目の残りの持ち時間の中央値を求める。
易しい手と難しい手のsoftは、整数ミリ秒の丸めとhardによる上限を含めて計算する。

| 時計 | 候補 | 易しい手のsoft/b（初手、100手目、200手目） | 難しい手のsoft/b（同） | 持ち時間が尽きる手数の中央値 | 432手目までに尽きない割合 |
|---|---|---|---|---:|---:|
| 短い条件（持ち時間/秒読み＝20） | 現行、B0、B1、B2 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 |
| 長い条件（持ち時間/秒読み＝150） | 現行、B0、B1、B2 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 |
| 10分＋秒読み30秒 | 現行、B0、B1、B2 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 |
| 90分＋秒読み60秒 | 現行、B0、B1、B2 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 | フェーズ0で記入 |

第1段階の比は秒読み30〜60秒、4スレッドの実戦から得たものなので、秒読み300 msの測定条件の予測は近似である。
測定条件の予測は、フェーズ4の煙試験の実測と照合する。

短い条件で易しい手のsoftが0.25b未満になる候補は、秒読み期の手より大幅に浅い手を持ち時間期に指すことになる。
B2はこれに該当する見込みが高いので、該当した場合は予測を利用者へ示し、測定するかの判断を仰いでから進める。

## 測定条件

測定は、持ち時間と秒読みの比が短い対局に近い条件と長い対局に近い条件の2つで行う。
短い条件は`time=6000+0,byoyomi=300`、長い条件は`time=45000+0,byoyomi=300`とする。
秒読み300 msは、秒読みつき条件の前例（[time-management-opening-coefficient-noninferiority](../measurements/time-management-opening-coefficient-noninferiority.md)）と同じ値である。
中将棋の対局は400手を超えることが多く、秒読み期の手数が多いので、秒読みを長くすると1ペアの所要時間がほぼ比例して増える。
秒読みを600 msにすると、短い条件の3,000ペアは約20時間かかる。
1ペアあたりの所要時間は、前例の同時16対局での実績から見積もる。
前例は有効3,574ペア（ほかに手数上限で破棄191ペア）に46,710秒を要し、有効ペアあたり同時対局1枠で約209秒だった。
段階Aの候補は秒読み期の使用率を約0.55Bから約0.9Bへ上げるので、片側の秒読み期の時間が約1.6倍になり、有効ペアあたり約260秒と見込む。
長い条件は持ち時間が片側39秒多い一方で秒読み期の手が少ないので、同程度の約260〜300秒と見込む。
3,000ペアの所要時間は、どちらの条件も約14〜16時間である。
これらの値は、フェーズ2とフェーズ4の煙試験で実時間、破棄率、およびペア得点の分散を測って更新する。
GSPRTの判定までの期待ペア数は、真の差が20 Eloなら約950ペア、10 Eloなら約2,600ペアである。

この条件は配備と次の点で異なり、これらは本書の限界として記録する。
秒読み300 msの探索は配備の30〜60秒より浅く、秒読み期の深さは実戦の調査が反復の比を測った深さ6以上の領域より浅い可能性がある。
既定の余裕30 msは秒読み300 msの10%であり、配備で見込む余裕（秒読みの数%）より大きい。
測定は`Threads=1`、先読みなしで行い、配備は`Threads=4`、先読みありである。
対局ハーネスはスレッド数を指定する引数を持たないので、採否測定は`Threads=1`で行う。
ただし、今回変えるワーカー間の選択と先読みの的中後の判定は4スレッドと先読みで初めて組み合わさるので、配備前に`Threads=4`と先読みを含む統合テストを行う（フェーズ2）。

測定の順序と判定は次のとおりである。

1. 段階Aを着手前のコミットと短い条件で比べる。`H0`なら長い条件を測らずに段階Aを不採用とする。
2. 短い条件が`H1`なら、長い条件で比べる。両方が`H1`で、時間切れ、エンジン異常、および拒否着手が0件なら採用する。判定保留の測定は`--resume`と`--target-pairs`で延長する。
3. 段階Aが採用されなかった場合は、段階Bへ進まず、結果を記録して利用者と方針を相談する。段階Bの候補は段階Aの締切と途中結果の採用を前提とするからである。
4. 段階Bの3候補を、段階Aの採用コミットと短い条件でそれぞれ比べる。上限は3,000ペアとする。
5. `H1`、または上限到達で停止時のLLRが0以上の候補を通過とし、通過した候補から事前に定めた優先順位B1、B0、B2の順で1つを選ぶ。該当がなければ段階Bは不採用とする。優先順位は、対数価値模型の最適値に従うB1を先に、現行の水準を保つB0を次に、模型が不利と予測するB2を最後に置いた。`H1`で停止した候補どうしのLLRは境界をわずかに超えた量の差にすぎず、強さの順位を表さないので、LLRの大小では選ばない。複数の候補が通過した場合は、選ばなかった候補の結果も利用者へ報告する。
6. 選んだ候補が上限到達で保留なら、まず長い条件で比べる。長い条件が`H0`なら、短い条件を延長せずに段階Bを不採用とする。長い条件が`H1`なら、短い条件を判定まで延長し、両方が`H1`で異常が0件なら採用する。

本書の採用条件は、短時間の選別と長時間の最終判定からなる標準の段階ゲートより厳しく、2つの条件の両方で`H1`を要求する。
人間との対局で棋力を落とさないという利用者の決定に従い、短い対局と長い対局のどちらでも強くなったことを確かめるためである。

シードは測定ごとに、既存の測定のシードからペア数以上離れた未使用の値とする（[隣接する基本シードは1局ずれた同じ対局列を生む](../lessons/derive-seed-adjacent-collision.md)）。
測定機で重い計算を始める前に、進行中の測定を確かめる（[測定機で重い計算を始める前に進行中の測定を確認する](../lessons/check-running-measurements-before-cpu-load.md)）。
所要時間は、段階Aが1〜2測定で約4〜40時間、段階Bが最大5測定で約20〜70時間と見込む。

## 実装フェーズ

### フェーズ0　定数の確定と予測

2026年9月21日から10月5日までのLishogi-Botのログ（[実戦の調査](../research/lishogi-byoyomi-time-usage.md)と同じ入力）から、次の値を事前に定めた規則で確定し、本書へ記入する。
規則で計算できない場合や、各群の標本が200件に満たない場合は、値を推測で埋めずに作業を止め、利用者へ報告する。

- 余裕m：秒読み期の全手について、Botがエンジンへ`go`を送った時刻から着手の`POST`を送った時刻までの時間と、エンジンの思考時間（`go`から`bestmove`まで）の差を求める。これはBot側の処理時間であり、同時対局の重なりで負荷の高い手も含める。その最大値に、lishogiまでの通信の見込みとして500 msを加え、100 ms単位へ切り上げた値をmとする。lishogiの公開棋譜は消費時間を秒単位でしか持たず、ミリ秒の照合には使えないので、通信の遅延そのものは測らない。
- 価値の比r：持ち時間期の先読み非的中の手で、同時対局の重なりのない手を対象とする。主ワーカーの深さ6以上の完了反復を判断点とし、その直後の反復が同じ手の中で完了した判断点だけを数える。詰みの評価値を含む判断点は、評価値の比較ができないので除く。判断点を、その時点の難しさの信号の真偽で2群に分け、群ごとに「直後の完了反復で最善手が変わった割合」を求め、真の群の割合を偽の群の割合で割った値をrとする。直後の反復が完了しなかった判断点の割合を群ごとに併記する。最善手安定時の早期終了が働いた判断点は直後の反復を持たないので、偽の群の標本はこの選択の偏りを含む。偽の群の割合が0の場合は計算不能として止める。
- 割合p：rと同じ対象の手のうち、最後の完了反復の時点で難しさの信号が真だった手の割合。
- κ*：rとpから「設計判断」の式で計算した値。
- 「候補の予測」の表。

完了条件は、5項目の記入と、B2の測定の可否についての利用者の判断である。

### フェーズ1　段階Aの実装

`ByoyomiMargin`、対象の探索の判定、秒読み期の締切と開始判定、先読みの的中後の判定、根の手の順序、途中結果の採用、およびワーカー間の選択を実装する。
締切と開始判定のコミットと、途中結果の採用のコミットを分ける。
次の検査を加える。

- 対象でない探索（秒読み0の時計、および`movetime`、深さ、ノード数との併用を含む）で、予算値、開始判定、停止理由、根の手の順序、および打ち切り時の結果が現行と一致すること。
- 秒読み期の予算値と開始判定、および先読みの的中後に予測で打ち切らないこと。
- 途中結果の採用規則、途中結果を根の置換表へ記録しないこと、および投了の判定が最後に完了した反復の値を使うこと。
- `Threads=4`、秒読み期の時計、および`ponderhit`を含む探索で、返す着手が合法で、思考時間が締切を超えないこと。

完了条件は、`cargo test`の通過と、固定深さのbench総ノード数が着手前と一致することである。

### フェーズ2　段階Aの診断と測定

測定の2条件で、採否測定と同じ同時対局数の10ペアの煙試験を行う。
判定条件は、時間切れ、エンジン異常、および拒否着手が0件であること、秒読み期の思考時間/Bの中央値が0.80以上であること、手数帯ごとの完了深さが着手前を下回らないことである。
0.80は次のように定めた。
秒読み300 msで余裕30 msのとき、打ち切りは0.9Bであり、段階Aは0.9B未満なら反復を始めるので、実戦の調査の模擬の「開始条件0.7B、打ち切り0.9B」（使用率の平均0.867）より使用率は高くなる。
一方、測定の秒読みは実戦より短く、1手あたりの固定費が占める割合が大きいので、模擬の値から0.067を割り引いた。
あわせて、途中結果を採用した手の割合、採用によって直前の完了反復の最善手と異なる手を返した割合、1ペアの実時間、および破棄ペア数を記録し、所要時間の見積りを更新する。
同じ2条件で`--ponder`を付けた10ペアの煙試験も行い、時間切れと不合法な予想手が0件であることを確かめる。
煙試験を通過したら、「測定条件」の手順1と2に従って測定する。
完了条件は、段階Aの採否の判定と測定記録である。

### フェーズ3　段階Bの実装

難しさの信号と反復ごとの評価値の保持を1コミットで実装し、その上にB0、B1、B2をそれぞれ1コミットで作る。
3候補は同じ親を持つ別々のコミットとし、互いに積まない。
秒読みが0の時計の予算値と開始判定が現行と一致することを、単体テストで確かめる。
完了条件は、`cargo test`の通過である。

### フェーズ4　段階Bの診断と測定

各候補について、測定の2条件で10ペアの煙試験を行い、時間切れ、エンジン異常、および拒否着手が0件であることを確かめる。
あわせて、持ち時間が尽きる手数を記録し、「候補の予測」の値と比べる。
予測から50%以上ずれた候補は、測定の前に原因を調べる。
段階Bは難しさの信号が深さ6以上の反復でしか働かないので、短い条件の持ち時間期の手について、深さ6の反復を完了した手の割合と、最後の判断点で信号が真だった手の割合も記録する。
深さ6に達した手が50%未満、または信号が真だった手が10%未満なら、測定条件では段階Bがほとんど発動しないので、測定へ進まずに利用者へ報告し、秒読みを600 msへ延ばすか（所要時間は約2倍）を相談する（[採否測定の条件で改良が発動することを実装前に確認する](../lessons/measure-feature-activation-before-sprt.md)）。
煙試験を通過したら、「測定条件」の手順4から6に従って測定する。
完了条件は、段階Bの採否の判定と測定記録である。

### フェーズ5　配備の確認と文書

採用した構成をmasterへ統合し、Lishogi-Botの`usi_options`に`ByoyomiMargin`を設定して配備する。
配備後の秒読みつきの対局20局のログで、秒読み期の思考時間/Bの中央値と時間切れの件数を記録する。
[探索部](search.md)の「時間管理」節と`clock_budget`のrustdocを更新する。
完了条件は、配備後の記録と文書の更新である。

## 検証

- 対象でない探索の代表入力（秒読み0の時計と、`movetime`、深さ、ノード数との併用を含む）で、予算値、開始判定、および停止理由が現行と一致すること。
- 固定深さのbench総ノード数が、各段階の着手前と一致すること。途中結果の採用と根の手の順序の変更は対象の探索だけに効くので、固定深さの探索を変えない。
- 煙試験と測定の時間切れ、エンジン異常、および拒否着手が0件であること。
- 手数上限に近い着手列を1手ずつ与えて、1手あたりの固定費とhardの超過の和が余裕mの内側に収まることを確かめること（[手数に比例する固定費は超長手数の対局で時間切れを起こす](../lessons/per-move-overhead-grows-with-game-length.md)）。

## 完了条件

採用で完了する条件は、段階Aまたは段階Bの候補が「測定条件」の判定で採用され、フェーズ5の記録と文書の更新が済んでいることである。
不採用で完了する条件は、段階Aが採用されず、測定記録と原因の記録が残っていることである。
段階Aだけを採用した場合は、段階Bの各候補の測定記録を残し、一部不採用で完了する。

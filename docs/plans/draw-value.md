# 引き分けの評価値の設定（DrawValue）の設計書

## 先に読む要約

本マイルストーンは、探索が千日手の引き分けに返す評価値を、エンジンを使う人がUSIオプションで設定できるようにする。
この仕組みは一般にcontemptと呼ばれる。引き分けの値を0より低くすると、エンジンは、千日手にならない手の評価値がその値より高ければ、千日手を避けてその手を選ぶようになる。
現行の探索は、探索木の中で同一局面が再現すると、常に評価値0を返す。
本書は、やねうら王と同じく`DrawValueBlack`と`DrawValueWhite`の2つのオプションを設け、探索の開始時に根（探索を開始する現局面）の手番に応じてどちらかを選び、根の手番側に+v、相手側に−vを与える方式を採る。
値の単位は、`info score cp`や`ResignValue`と同じMinaseの評価値のcpとする。
適用するのは、同一局面の4回目の出現を原則として引き分けとする反復規則R1（RULES.md第31条）で、千日手が引き分けになる場合だけである。
既定値は0とし、既定の設定での探索は現行と変わらない。
Stockfishの測定記録では、0以外の引き分け値は自己対局で中立からわずかに負であり（[既存実装の調査](../research/draw-value-prior-art.md)）、Minaseが新しい機能の採用に用いる段階ゲート（自己対局のGSPRTで10 Eloの向上を判定する測定）を通ることは見込めないからである。
このため、既定の設定のままでは千日手を避ける効果はなく、効果を得るには、lishogiのBotの運用者などが設定で値を与える必要がある。
採否は、既定値で探索が変わらないことをテストと`bench`で確かめて決め、自己対局の測定は行わない。
完了条件は、オプションとテストが揃い、文書が更新されていることである。

## 目的

現行の探索は、探索木の中で同一局面が再現すると、規則によらず定数`DRAW_SCORE`（0）を返す（`crates/minase/src/search/alphabeta/negamax.rs`の`search_move`）。
探索木の中で引き分けの値を返すのはこの1か所だけであり、駒枯れ（RULES.md第22条）と、規則コードE3（RULES.md第32条）の裸玉裁定の引き分けは木の中で判定しない（[探索木の中の裁定の近似のADR](../adr/approximate-adjudication-inside-search-tree.md)）。
したがってエンジンは、千日手の引き分けを評価値0の通常の局面と同じ価値とみなし、ほかの手の評価値が0よりわずかに低いだけでも千日手を選ぶ。
対局の相手が自分より弱いと分かっている場合などに、利用者がこの価値づけを変えられるようにすることが本書の目的である。

ただし、千日手を避けることが常に良いわけではない。
2026年10月15日のlishogiの対局[5XnQYei1](https://lishogi.org/5XnQYei1)は、R1の千日手で引き分けになった。
双方がすべての手で攻撃的着手を続けた周回なので、R1の裁定どおりの引き分けである。
Botのログによれば、Minaseは周回に入る前の5手で、自分から見た評価値を−14から−135 cpと報告しており、相手のレーティングもMinaseより150高かった。
この対局では引き分けがMinaseにとって良い結果であり、負の引き分け値はこの引き分けを捨てる方向に働く。
引き分けを避けるべきかどうかは相手と形勢に依存するので、本書は既定値を0とし、値の選択を利用者に委ねる。

## 適用範囲

対象は3つある。第1はUSIのオプションの定義と解析、および値の変更時に置換表を空にする処理（`crates/minase/src/protocol/usi.rs`）、第2は探索の入力（`SearchSnapshot`または探索の制限）、第3は`search_move`が反復の引き分けで返す値である。
CECP（XBoardプロトコル）には対応するオプションの仕組みがない。また、CECPで対局する中将棋エンジンHaChuとの比較はR2の規則で行い、R2では探索木の中の再現が禁止手として除かれて引き分けが生じないので、本書はCECPを変えない。
教師局面の生成（`crates/minase/src/bin/minase/selfplay_gen/`）とlishogi棋譜への評価付与は、USIを通さずに既定値で探索するので変わらない。

次の事項は範囲に含めない。

- 形勢や相手のレーティングに応じて値を変える仕組み。Stockfishの動的contemptは導入と取り消しを繰り返したうえで削除され、Lc0は相手とのElo差を入力とする別の方式をとる（[既存実装の調査](../research/draw-value-prior-art.md)）。相手に応じて値を変える場合は、対局ごとに相手を知っているBotの側でオプションの値を選ぶのが単純であり、エンジンはオプションを受け取るだけにする。
- 引き分け値の揺らぎ（Stockfishとやねうら王の±1）。効果は非常に長い持ち時間でだけ確認されている（[探索内の反復の扱いに関する既存実装の調査](../research/search-repetition-prior-art.md)）。
- 評価値の側に偏りを加えるoptimism（Stockfish）。引き分けの値ではなく評価関数の変更であり、本書の目的と異なる。

## 依存関係

本書は[探索部の反復負け回避と反復禁止](archived/search-repetition.md)の後に着手する。
両者は`search_move`の同じ箇所を変更し、同書の項目2は、R1の再現のうち攻撃側が一方に定まる周回を勝敗の値で返し、残りだけを引き分けとする。
同書の項目2が不採用になった場合は、R1の再現はすべて引き分けとして扱われ、本書の値はそのすべてに適用される。
同書が反復の勝敗に設ける専用の帯（絶対値29,487以上29,744未満の評価値）の値は変えない。
置換表は`usinewgame`で空になるので（`crates/minase/src/protocol/usi.rs`の`NewGame`の処理）、前の対局の引き分けの値に基づく評価値は次の対局へ持ち越されない。

## 設計判断

| 項目 | 決定 |
|---|---|
| 方式 | 利用者が設定する固定の値を引き分けに返す、やねうら王式のオプションとする（利用者の決定）。Stockfishの、評価値への加算や根の評価値に応じた動的な値は採らない。Stockfishでは、これらは取り消しと削除を経て、現行のコードに残っていない。 |
| オプションの数 | やねうら王と同じく、根の手番が先手のときの値`DrawValueBlack`と、後手のときの値`DrawValueWhite`の2つを設ける。中将棋の先手と後手で引き分けの価値を変えたい利用者が、対局ごとに手番を調べて値を送り直さずに済むからである。 |
| 符号づけ | 探索の開始時に、根の手番に応じた値vを選ぶ。探索木の中では、引き分けを返すノードの手番が根の手番と同じなら+v、異なればその符号を反転した−vを返す。やねうら王（`aca35b5a`）と技巧の方式であり、引き分けの価値を両者で打ち消し合う対称な探索になる。手を選んだ側の手番で値を決めるdlshogiの方式は、やねうら王の作者が非対称な探索として指摘しており、採らない。 |
| 単位と範囲 | 値はMinaseの評価値のcpで指定し、`info score cp`、`ResignValue`、および評価関数の出力と同じ単位とする。範囲は評価関数の出力の範囲と同じ±28,999とし、反復の勝敗の専用の帯（絶対値29,487以上）と詰みの帯に入らないようにする。やねうら王は歩=100の単位で指定させて駒価値で換算するが、MinaseのNNUEは歩兵を約68 cp（標準偏差約40 cp）と見ており（[評価関数の駒価値の比較](../research/evaluator-piece-values.md)）、換算の係数が定まらないので採らない。 |
| 適用する規則 | R1の再現で引き分けを返す場合だけに適用する。R2では探索木の中の再現は禁止手として除かれ、引き分けにならない。R3の禁止されない再現に返す0は、対局の引き分けではなく、周回が損得を生まないことを表す近似なので変えない（[探索部の反復負け回避と反復禁止](archived/search-repetition.md)の項目3）。 |
| 既定値 | 0とする（利用者の決定）。既定の設定では探索が現行と変わらないので、自己対局の測定を行わずにテストで採否を決める。0以外の既定値は棋力に影響し得るのでSPRTの対象になるが、Stockfishの記録では、Contempt=20の自己対局はSTCで0.10±2.0 Elo、LTCで−2.06±1.9 Eloと−2.69±1.9 Eloであり、H1=10 Eloの段階ゲートを通ることは見込めない。やねうら王の既定値−2は内部値で−1であり、0に切り捨てられない最小の値として同点の手を区別するために選ばれた値で、測定に基づくものではない。Minaseで−1 cpとしても、選択が変わるのは評価値がちょうど同じ手の間だけであり、千日手を実際に避けるには数十cpの値が要る。その値は、強い相手や劣勢の局面で正しい引き分けを捨てる危険と引き換えになる。 |
| 採否の測り方 | 既定値0では探索が変わらないので、テスト、`bench`の総ノード数と結果の一致、およびオプションの解析の検証で採否を決める。0以外の値の効果を自己対局で測ることはしない。両者が同じ値を使う自己対局では、弱い相手から引き分けを避けるという本来の効果が現れないからである。Stockfishは、値を入れた版と入れない版をそれぞれ同じ弱い旧版と対局させ、2つのElo差を比べたが、その差は6.4±3.9 Eloであった。Minaseの固定200ペアのEloは95%信頼区間の幅が約65 Eloあるので（[docs/guides/sprt.md](../guides/sprt.md)）、同じ方法では差を検出できない。 |
| 置換表 | 置換表には、引き分けの値を含めて求めた親ノードの値が保存され、次の探索では反復の判定より前にその値で打ち切ることがある。一方、置換表のキーは、探索開始時の根の手番とオプションの値を区別しない（局面自体の手番はキーに含まれる）。そこで、受理した`setoption`で2つのオプションのどちらかの値が変わった場合は、置換表とhistory表を空にする。既存の`usinewgame`と規則の変更と同じ扱いである。根の手番については、対局中のエンジンは自分の手番の局面だけを根にするので（先読みの根も自分の手番である）、通常の対局では問題にならない。同じ対局の中で双方の手番の局面を解析すると、別の手番を根にした探索の値が再利用される。これはやねうら王も扱っていない既知の近似として残す。 |
| 投了との関係 | USIの投了判定（`should_resign`）は、採用した手の評価値が`-ResignValue`以下なら投了する。引き分けの値を`-ResignValue`以下に設定すると、千日手しか残らない局面で、引き分けにできるのに投了し得る。本書はこの組み合わせを拒否せず、投了判定は引き分けの値を含む評価値で行うという仕様を明記し、境界をテストで固定する。オプション間の整合を検査すると、2つのオプションを送る順序によって受理と拒否が変わり、単純さを損なうからである。`ResignValue`の既定値は20,000なので、既定の設定では起こらない。 |
| Botの設定 | lishogiのBotでは、`DrawValueBlack`と`DrawValueWhite`をどちらも−1に設定する（利用者の決定）。やねうら王の既定値−2の内部値に当たる値であり、評価値がちょうど同じ手の間でだけ千日手を避けさせる。値を変えるのはBotの設定だけなので、エンジンの既定の探索は変わらず、棋力の測定の対象にしない。 |

## 実装フェーズ

### フェーズ1　オプションと探索

USIに`DrawValueBlack`と`DrawValueWhite`を追加し、探索の開始時に根の手番に応じた値を探索ワーカーへ渡して、`search_move`がR1の反復の引き分けで符号づけした値を返すようにする。
オプションの書式と解析の誤りの扱いは、既存の`ResignValue`と`ByoyomiMargin`に揃える。
完了条件は、「検証」の節のテストがすべて通り、既定値での`bench`の総ノード数と結果が着手時のmasterと一致することである。

### フェーズ2　Botの設定

フェーズ1を含むエンジンの版をリリースした後、リポジトリ`minase-lishogi-bot`のエンジンのUSIオプションの設定（`config.yml`の`usi_options`）で2つのオプションを−1に設定する。
完了条件は、Botが起動時にこの値を送り、エンジンが受理したことを入出力のログで確かめることである。

### フェーズ3　文書の更新

USIのオプションの一覧（`crates/minase/src/protocol/usi.rs`のdocコメント）と、`search_move`のdocコメントを現行の実装に合わせる。凍結した[探索部](archived/search.md)は書き換えない（[設計書の書き方](README.md)）。
設計判断の「方式」「符号づけ」「既定値」をADRへ移し、docs/ROADMAP.mdの状態表を更新する。

## 検証

テストは仕様から期待値を導き、各テストの名前または説明にRULES.md第31条R1を引く。

- `usi`への応答に、2つのオプションが既定値0、範囲±28,999で現れる。
- 範囲外の値、数値でない値、および値の欠落を、`ResignValue`と同じ形式の誤りとして拒否する。
- 既定値では、`bench`の総ノード数と結果が着手時のmasterと一致する。
- 根の手番が先手で`DrawValueBlack`に負の値vを設定した場合、R1の引き分けの再現に、根と同じ手番のノードではv、相手の手番のノードでは−vが返る。根の手番が後手の場合は`DrawValueWhite`が使われる。
- 負の値を設定した場合、千日手になる手と、評価値がその値より高い千日手にならない手がある局面で、探索が後者を選ぶ。値が0の場合は千日手になる手を選び得ることを、同じ局面で確かめる。
- [探索部の反復負け回避と反復禁止](archived/search-repetition.md)の項目2を採用した構成では、R1の攻撃側が一方に定まる周回に、値の設定にかかわらず専用の帯の勝敗の値が返る。項目2を採用しない構成では、R1のすべての再現に符号づけした引き分けの値が返る。
- R2とR3の規則セットでは、値を設定しても探索の結果とノード数が変わらない。
- 先手番と後手番の対局を`usinewgame`を挟んで続けて行った場合、後の対局の探索が前の対局の値を置換表から再利用しない。
- `usinewgame`を挟まずに`setoption`で値を変えた場合、変更後の探索が、変更前の値に基づく置換表の値によって打ち切られない。値が変わらない`setoption`では置換表を空にしない。
- 引き分けの値を`-ResignValue`以下に設定し、採用した手が千日手の場合に投了すること、`-ResignValue`より大きい場合に投了しないことを確かめる。

完了前に`cargo test`、`cargo clippy`、および`bench`の総ノード数の照合を実行する。

## 完了条件

フェーズ1からフェーズ3までが完了し、既定値で探索が変わらないことを確かめた時点で、状態を完了（採用）へ変える。

# 評価関数の候補と探索係数の共適応の検証の設計書

## 先に読む要約

本書は、評価関数の候補が対局で大きく負ける原因の1つとして、探索係数がいまの評価関数（S0）に合わせて調整されていることを疑い、その仮説を1つの候補で確かめる。
探索係数とは、futility pruningやSEE pruningの余裕値、aspiration windowsの窓幅など、探索がどこまで読むかを決める22個の数値であり、2回の[SPSA](spsa.md)（全係数を同時に少しずらした2設定を対局させ、勝った側へ係数を動かす調整法）でS0に合わせて調整された。
余裕値は、静的評価値が探索の窓からどれだけ離れていれば手を読まずに捨てるかを、歩兵の価値に対する割合で決める。
評価値の散らばり方が変わると、同じ余裕値でも捨てる手の割合が変わるので、評価値の分布を変えた候補は、含む知識の良し悪しと関係なく読み落としや読みすぎを起こし得る。
検証には、[混合比λ=1.0](teacher-mixing-ratio.md)で学び直したPSTを使う。このPSTは、採用された[先読み教師での再学習](lookahead-teacher.md)と同程度だけ重みが動いたのに、短時間条件STCで約−164 Eloと大きく負けた。
このPSTを現行のmasterに載せた版をS0と対局させた後、探索係数だけをSPSAで調整し直した版を同じ開始局面でS0と対局させ、負けがどれだけ縮むかを測る。
負けの半分以上が縮んだ場合は、S0の探索係数を同じ手順で調整し直した対照を追加で測り、どのエンジンでも調整し直せば得られる分を差し引いてから結論を出す。
共適応が支持されれば、今後の評価関数の候補には採否の測定の前に探索係数を調整し直す手順が必要になる。
完了条件は、事前に固定した判定が記録され、その結論が手順の提案または未確定の記録として後続へ引き継がれることである。

## 目的

評価関数の計画では、教師データへの当てはまりを改善した候補が、対局では大きく負ける例が続いている。
λ=1.0のPSTは約−164 Elo、補正倍率1のFactorization Machine（FM）は約−240 Elo、順位の損失のβ=1.0は対照に約−81 Eloだった。
[FMの設計書](factorization-machine.md)は、過去のNNUEの約−150 Eloのうち探索速度の低下で説明できるのは約−64 Eloだけで、残りは評価と探索の相性によると記録している。
一方、FMの補正を1/4に縮めた候補は、STCとLTCの両方で当時の採用PSTに勝った。
これらは、評価値の分布を大きく動かす候補ほど負けるという型を示している。

この型には少なくとも2つの説明がある。
第1は、候補の評価関数そのものが悪いという説明であり、教師の偏りや学習の過程に原因を求める。
第2は、探索係数がS0の評価値の分布に合わせて調整されているので、分布を変えた候補はその係数の下では本来の力を出せないという説明である。
第2の説明が正しければ、評価関数の採否の判定は、候補の知識ではなく係数との不整合で候補を棄却してきたことになる。
本書は、第2の説明を確かめるのに最も適した1つの候補で、その説明がどこまで成り立つかを測る。

λ=1.0のPSTを選ぶ理由は、重みの変化量と結果の組合せにある。
基点からの重みの変化量は序中盤と終盤の平均絶対値で約11と約17センチポーンであり、採用された先読み教師の再学習の約10と約20センチポーンと同程度だった。
[STCの記録](../measurements/teacher-mixing-ratio-100-stc.md)は同じ量を重みの内部単位（1/8センチポーン）で89、139と81、157と記している。
同じ程度に動いた2つの再学習で棋力の向きが逆になった原因は、記録では特定されていない。
また、λ=1.0のPSTは重みファイルの差し替えだけで作れるので、探索のコードを変えずに実験を組める。

## 適用範囲

本書の用語を次のように定める。

- **M**は、着手時のmasterの先頭のコミットである。
- **S0**は、Mそのものであり、Mの`nets/pst.bin`を採用PSTと呼ぶ。
- **Pλ**は、ブランチ`teacher-mixing-ratio-100-candidate`のコミット`16a2257`にある`nets/pst.bin`、すなわちλ=1.0で学び直したPSTの重みである。
- **Cλ**は、Mの`nets/pst.bin`をPλへ差し替え、重みに依存するテストの期待値をPλの値へ改めたコミットである。
- **Cλ\***は、Cλの探索係数をSPSAで調整し、その値を`spsa_runner apply`で係数の表へ書き込んだコミットである。
- **S0\***は、Mの探索係数を同じ手順で調整したコミットであり、「判定」の節の条件を満たした場合だけ作る対照である。
- **探索係数**は、Mの`src/search/alphabeta/params.rs`にある22係数である。探索の16係数と時間管理の6係数からなる。
- **共通ペア**は、比べる測定のすべてで手数上限による破棄がなかったペア番号の集合である。
- **E0、E1、G**は、共通ペアで計算したCλ対S0、Cλ\*対S0、S0\*対S0のEloである。
- **回復量R**はE1−E0、**回復率**はE0<0のときR/|E0|である。

対象は、上記のコミットの作成、SPSAの調整セッション1回または2回、固定局数の対局2回または3回、および条件を満たした場合の採否測定だけである。
評価関数の学習器、探索のコード、対局ハーネス、およびPλの重みは変えない。
過去に不採用となったλ=1.0以外の評価関数の候補は、本書では測らない。

## 依存関係

SPSAの調整には、masterへ統合済みの[SPSAの基盤](spsa.md)と、[利得の較正](spsa-gain-calibration.md)が定めた標準の利得（減衰する利得、終了時の摂動幅が範囲の1/6）と標準の規模3,000ペアをそのまま使う。
対局の測定は[SPRTの手引き](../guides/sprt.md)の固定局数Eloと段階ゲートに従う。
Pλは、Mと同じMNPTバージョン2の重みファイルであり、探索用駒価値と出力K（1072.6529541015625）は採用PSTと同じ値を持つ。

作業は、Mから本書専用のブランチ`eval-search-coadaptation`を作り、worktreeで行う。
測定の途中にmasterの探索や評価関数の変更を取り込まない。
[不採用だった探索部の改良の再調整](search-revival-spsa.md)と[補正1/4のFMの現行PSTへの再学習](fm-quarter-current-pst.md)は測定機を共有するので、実行の順序は利用者が決める。
再調整の計画が先に採用されてmasterの探索係数が変わった場合も、本書は着手時のMを基準とする。

## 設計判断

| 項目 | 決定 |
|---|---|
| 検証に使う候補 | Pλの1つとする。重みの変化量が採用された再学習と同程度で、結果だけが逆という性質が、評価関数そのものの悪さと係数との不整合を区別するのに適しているからである。FMやNNUEは探索速度の費用を伴い、順位の損失の候補は教師への誤差の悪化を伴うので、回復量を係数の効果だけに帰属させにくい。結論はこの1つの候補についてのものであり、他の候補へ一般化するかは利用者が決める。 |
| 調整する係数 | 探索係数22個のすべてとする。22個はいずれも2回のSPSAでS0に合わせて調整された値であり、時間管理の係数も評価値の変動に依存し得るからである。探索の16係数だけに絞る案は、仮説の対象を狭めて確かめやすくする利点があるが、過去の標準のセッションと条件が変わるので採らない。 |
| 調整の規模と利得 | 標準の3,000ペアと標準の利得をそのまま使う。開始値はMの係数の値とし、範囲は係数の表の宣言のとおりとする。3,000ペアは収束を保証しない規模である（[SPSAの設計書](spsa.md)「調整セッションの規模と所要時間」）ので、回復を示せなかった場合も、それだけで共適応を否定しない。 |
| 回復量の測り方 | Cλ対S0とCλ\*対S0を、STCの時間制御（`time=10000+100`）で各400ペアの固定局数Eloとして測る。2回の測定は同じ基本シードを使い、同じ開始局面の組で対局させる。これは意図して同じ対局列を使う比較であり、[隣接シードの教訓](../lessons/derive-seed-adjacent-collision.md)が戒める意図しない重複とは異なる。手数上限による破棄は測定ごとに異なり得るので、R、回復率、およびそれらの95%信頼区間は共通ペアだけから計算する。信頼区間は、共通ペアをペア番号ごとに復元抽出する対応のあるブートストラップ（10,000回、乱数シード固定）で求める。過去の約−164 Eloは基点が`622a879`の測定なので、Mでの値を測り直す。 |
| 調整し直しの一般的な効果の対照 | 回復率の95%信頼区間の下限が0.5以上となった場合だけ、S0\*を同じ規模で作り、S0\*対S0を同じ基本シードの400ペアで測る。どのエンジンでも探索係数を調整し直せば強くなり得るので、その分を差し引かなければ、回復を共適応に帰属できないからである。2回目の調整の実績（STCで約+20 Elo、[記録](../measurements/spsa-stage9-20260925-c5-stc.md)）は1回の測定値であり、この効果の上限には使えない。対照を最初から置く案は、回復が小さく対照が判定に影響しない場合にも約8.5時間を費やすので採らない。 |
| 判定の閾値 | 「判定」の節で、結果を見る前に固定する。 |
| 採否 | 本書は診断であり、Cλ\*を採用するかどうかは、判定の後に条件を満たした場合だけ標準のSTCとLTCのGSPRTで決める。固定局数Eloを採用の根拠には使わない。 |

## 判定

判定は、結果を見る前に次のとおり固定する。
信頼区間はすべて「回復量の測り方」の対応のあるブートストラップで求める。

第1段では、E0とE1から回復率を求めて次のように振り分ける。

| 振り分け | 条件 | 後続 |
|---|---|---|
| 回復が大きい。 | 回復率の95%信頼区間の下限が0.5以上である。 | 第2段へ進み、S0\*を作って対照を測る。 |
| 回復が部分的である。 | Rの95%信頼区間の下限が0を上回り、回復率の95%信頼区間の下限が0.5未満である。 | 調整し直しで負けの一部は縮むが、負けの半分以上を説明するとは示せなかったと記録する。手順を変えるかは利用者が決める。延長や再測定は行わない。 |
| 回復を示せない。 | Rの95%信頼区間が0を含むか、0を下回る。 | 本書の調整の規模では回復を示せなかったと記録する。調整が収束していない可能性が残るので、λ=1.0の負けの原因を教師の側と断定しない。評価関数の採否の手順は変えない。 |

第2段では、共通ペアで計算した共適応に固有の回復量R−Gと、その回復率(R−G)/|E0|を求める。

| 判定 | 条件 | 後続 |
|---|---|---|
| 共適応を支持する。 | (R−G)/|E0|の95%信頼区間の下限が0.5以上である。 | λ=1.0のPSTの負けの半分以上は、探索係数との不整合による。評価関数の候補の採否の測定の前に、候補に合わせて探索係数を調整し直す手順を[SPRTの手引き](../guides/sprt.md)へ加えることを利用者に提案し、教訓を記録する。過去に不採用となった評価関数の候補を調整し直して測り直すかは、別の計画として利用者が決める。 |
| 共適応に固有とは言えない。 | 上記に当たらない。 | 回復の大きな部分は、調整し直しの一般的な効果でも説明できると記録する。手順は変えない。 |

判定とは別に、E1の95%信頼区間の下限が0を上回った場合だけ、Cλ\*をSTCとLTCの段階ゲートでMに対して測り、採否を決める。
第2段でGの95%信頼区間の下限が0を上回った場合は、S0\*も同じく段階ゲートでMに対して測ってよいかを利用者に確かめる。
これらの条件は採用の読み替えではなく、採否の測定に進むための振り分けである。

## 所要時間の見積り

時間は同時対局数16の測定機での見積りである。
固定局数の対局は[λ=1.0のSTC](../measurements/teacher-mixing-ratio-100-stc.md)の1ペアあたり約9.2秒、セッションは[2回目の調整](../measurements/spsa-stage9-20260925-c5.md)の3,000ペアの実績7時間32分を根拠とする。

| 段 | 内容 | 見積り |
|---|---|---|
| 準備 | CλとCλ\*の作成と検証、時間切れの事前確認 | 約30分 |
| 1 | Cλ対S0の400ペア | 約1時間 |
| 2 | Cλの調整セッション | 約7.5時間 |
| 3 | Cλ\*対S0の400ペア | 約1時間 |
| 4（条件付き） | S0\*の調整セッションとS0\*対S0の400ペア | 約8.5時間 |
| 5（条件付き） | Cλ\*対MのSTCとLTC | 約1〜8時間と約5〜30時間 |

第1段で終われば合計は約10時間、第2段まで進めば約18.5時間である。

## 判断待ち

着手の前に、利用者に次の2点を決めてもらう。

1. 対照のS0\*を条件付きにする方式でよいか。最初から置けば判定は1回で済むが、回復が小さい場合にも約8.5時間を費やす。本書は条件付きを推す。
2. [不採用だった探索部の改良の再調整](search-revival-spsa.md)、[補正1/4のFMの現行PSTへの再学習](fm-quarter-current-pst.md)、および本書の実行の順序。本書は、判定の結果が評価関数の今後の計画すべての採否の手順に関わり得るので、評価関数の計画より先に実行することを推す。

## 実装フェーズ

### フェーズ1　候補の作成

Mからブランチを作り、`nets/pst.bin`をPλへ差し替えたCλをコミットする。
Mの`src/eval/pst/tests.rs`には、埋め込みの重みでの初期局面の評価値を学習器の参照値と照合するテストがあり、期待値は採用PSTの値である。
Cλではこの期待値を、λ=1.0の学習の診断が記録した学習器の参照値へ改める。
差し替えた重みのSHA-256がPλと一致すること、`cargo test`、`cargo clippy -- -D warnings`、および`cargo fmt --check`が通ることを確かめる。
完了条件は、Cλのコミットである。

### フェーズ2　調整前の測定

Cλ対S0の400ペアを測り、測定記録`eval-coadaptation-before-stc400`に残す。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/eval-coadaptation-before-stc400 --seed 13000000 \
  --candidate commit:<Cλ> --baseline commit:<M> \
  --each time=10000+100 --concurrency 16 elo --pairs 400
```

この段の結果は判定の片方の値であり、どの値でも次の段へ進む。

### フェーズ3　調整

`spsa_runner params`でCλの調整用ビルドから標準のパラメーターファイルを生成し、開始値がMの係数の値と一致することを確かめる。
時間管理の係数を含むので、[SPSAの手引き](../guides/spsa.md)の時間切れの事前確認を行い、異常0件を確かめてから、基本シード14000000で3,000ペアのセッションを実行する。
セッションの記録は`docs/measurements/eval-coadaptation-spsa.md`に残す。
最終値を`spsa_runner apply`でCλへ書き込み、Cλ\*をコミットする。
完了条件は、Cλ\*のコミットと、セッションの異常が0件であることの確認である。

### フェーズ4　調整後の測定と第1段の判定

Cλ\*対S0の400ペアを、フェーズ2と同じ基本シード13000000で測り、測定記録`eval-coadaptation-after-stc400`に残す。
共通ペアからE0、E1、R、回復率とそれらの信頼区間を計算し、第1段の振り分けを記録する。
計算に使うスクリプトと乱数シードは、測定記録のディレクトリに保存する。

### フェーズ5　対照と第2段の判定（条件付き）

第1段が「回復が大きい」の場合だけ、Mの調整セッションを基本シード17000000で実行してS0\*を作り、S0\*対S0の400ペアを基本シード13000000で測って測定記録`eval-coadaptation-control-stc400`に残す。
3つの測定の共通ペアからR−Gと回復率を計算し、第2段の判定を記録する。

### フェーズ6　採否測定（条件付き）

「判定」の節の条件を満たした場合だけ、Cλ\*をMに対してSTC（`eval-coadaptation-stc`、基本シード15000000）とLTC（`eval-coadaptation-ltc`、基本シード16000000）の段階ゲートで測る。

## 検証

- CλとMの差が`nets/pst.bin`と重みに依存するテストの期待値だけであり、Cλ\*とCλの差が係数の表の既定値だけであることを、`git diff --stat`で確かめる。
- 同じ基本シードを使う測定どうしで、`manifest.json`の基本シード、時間制御、同時対局数、置換表容量、および基準のバイナリのSHA-256が一致することを確かめる。
- 共通ペアの数と、測定ごとの破棄ペアの番号を記録する。
- すべての測定で、エンジン異常、時間切れ、および拒否着手の件数を記録する。1件でも出た場合は測定を止めて原因を調べ、シードを変えた再試行はしない。

## 完了条件

- 実施した固定局数Eloの測定、調整セッション、および判定が測定記録に残っている。
- 「共適応を支持する」場合は、手順の変更の提案と教訓が記録され、採否の手順を変えるかの利用者の決定が[SPRTの手引き](../guides/sprt.md)またはROADMAPに反映されている。
- 採否の測定へ進んだ場合は、その採否が確定し、採用ならPλと調整後の係数が評価関数と探索部の設計書の現行値に反映されている。
- ROADMAPの状態表が本書の結論と一致している。

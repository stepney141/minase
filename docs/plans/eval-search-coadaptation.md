# 評価関数の候補と探索係数の共適応の検証の設計書

## 先に読む要約

本書は、評価関数の候補が対局で大きく負ける原因の1つとして、探索係数がいまの評価関数（S0）に合わせて調整されていることを疑い、その仮説を1つの候補で確かめる。
探索係数とは、futility pruningやSEE pruningの余裕値、aspiration windowsの窓幅など、探索がどこまで読むかを決める29個の数値であり、[SPSA](spsa.md)（全係数を同時に少しずらした2設定を対局させ、勝った側へ係数を動かす調整法）でS0に合わせて調整された。
余裕値は、静的評価値が探索の窓からどれだけ離れていれば手を読まずに捨てるかを、歩兵の価値に対する割合で決める。
評価値の散らばり方が変わると、同じ余裕値でも捨てる手の割合が変わるので、評価値の分布を変えた候補は、含む知識の良し悪しと関係なく読み落としや読みすぎを起こし得る。
検証の候補には、教師の混合比をλ=1.0にしてPSTを学び直したものを使う。過去に同じ作り方をしたPSTは、短時間条件STCで約−164 Eloと大きく負けた。
候補は、過去の重みを使わず、現行の採用PSTから同じ作り方で学び直す。過去の重みは現行の採用PSTより前の学習なので、S0との差に、混合比と無関係で係数の調整では取り戻せない差を含むからである。
候補は混合比のほかに初期値と学習の回数も採用PSTと異なるので、結論は混合比の効果ではなく、この候補の負けについてのものである。
候補をS0と対局させた後、探索係数だけをSPSAで調整し直した版を同じ開始局面でS0と対局させ、負けがどれだけ縮むかを測る。
負けの半分以上が縮んだ場合は、S0の探索係数を同じ手順で調整し直した対照を追加で測り、どのエンジンでも調整し直せば得られる分を差し引いてから結論を出す。
結果として、候補の約150 Eloの負けは、探索係数を調整し直しても縮まなかった。
この候補について、負けを探索係数との不整合で説明する仮説は支持されず、評価関数の候補の採否の手順は変えない。
追加診断では、候補は評価値の散らばりの尺度を変えておらず、負けは混合比λ=1.0に結び付くことがわかった。同じ追加学習をλ=0.75で行った対照は、逆にS0に約55 Elo勝った。
完了条件は、事前に固定した判定が記録され、その結論が手順の提案または未確定の記録として後続へ引き継がれることであり、満たされた。

## 目的

評価関数の計画では、教師データへの当てはまりを改善した候補が、対局では大きく負ける例が続いている。
λ=1.0のPSTは約−164 Elo、補正倍率1のFactorization Machine（FM）は約−240 Elo、順位の損失のβ=1.0は対照に約−81 Eloだった。
[FMの設計書](factorization-machine.md)は、過去のNNUEの約−150 Eloのうち探索速度の低下で説明できるのは約−64 Eloだけで、残りは評価と探索の相性によると記録している。
一方、FMの補正を1/4に縮めた候補は、STCとLTCの両方で当時の採用PSTに勝った。
これらは、評価値の分布を大きく動かす候補ほど負けるという型を示している。

この型には少なくとも2つの説明がある。
第1は、候補の評価関数そのものが悪いという説明であり、教師の偏りや学習の過程に原因を求める。
第2は、探索係数がS0の評価値の分布に合わせて調整されているので、分布を変えた候補はその係数の下では本来の力を出せないという説明である。
第2の説明が正しければ、評価関数の採否の判定は、候補の知識ではなく係数との不整合で候補を棄却してきたことになる。
本書は、第2の説明を確かめるのに最も適した1つの候補で、その説明がどこまで成り立つかを測る。

λ=1.0の再学習を選ぶ理由は、重みの変化量と結果の組合せにある。
過去のλ=1.0の再学習は、基点から序中盤と終盤の平均絶対値で約11と約17センチポーン動き、STCで約−164 Eloだった（[STCの記録](../measurements/teacher-mixing-ratio-100-stc.md)）。
これに対し、採用された[世代3の再学習](pst-gen3.md)のG23は約20と約34センチポーン、すなわち約2倍動いて、LTCで得点率61.3%の`H1`となった（[学習の記録](../measurements/pst-gen3-training.md)）。
重みの変化量が棋力の向きを決めていないので、λ=1.0の負けは、動いた量ではなく動いた向き、すなわち評価値の分布の変わり方によると考えられる。
また、λ=1.0のPSTは重みファイルの差し替えだけで作れるので、探索のコードを変えずに実験を組める。

[不採用だった探索部の改良の再調整](search-revival-spsa.md)は、同じ型の仕組みを探索側で示した。
単独ではSTCで負けた8項目が、探索係数とまとめてSPSAで調整し直すと、得点率約67%で`H1`となった。
本書は、この仕組みが評価関数の候補にも働くかを確かめる。

## 適用範囲

本書の用語を次のように定める。

- **M**は、着手時のmasterの先頭のコミットである。Mは、2026年10月4日に採用した探索部の再調整（29係数）と評価関数G23を含む。
- **S0**は、Mそのものであり、Mの`crates/minase/nets/pst.bin`を採用PSTと呼ぶ。
- **Pλ**は、フェーズ1で学習するPSTの重みである。採用PSTを初期値とし、G23と同じ世代2と世代3の10ファイルを、G23の学習条件のうち混合比だけをλ=1.0に変えて学習する。
- **Cλ**は、Mの`crates/minase/nets/pst.bin`をPλへ差し替え、重みに依存するテストの期待値をPλの値へ改めたコミットである。
- **Cλ\***は、Cλの探索係数をSPSAで調整し、その値を`minase spsa apply`で係数の表へ書き込んだコミットである。
- **S0\***は、Mの探索係数を同じ手順で調整したコミットであり、「判定」の節の条件を満たした場合だけ作る対照である。
- **探索係数**は、Mの`crates/minase/src/search/alphabeta/params.rs`にある35係数のうち、時間管理の6係数を除く29係数である。
- **共通ペア**は、比べる測定のすべてで手数上限による破棄がなかったペア番号の集合である。
- **E0、E1、G**は、共通ペアで計算したCλ対S0、Cλ\*対S0、S0\*対S0のEloである。
- **回復量R**はE1−E0、**回復率**はE0<0のときR/|E0|である。

対象は、Pλの学習、上記のコミットの作成、SPSAの調整セッション1回または2回、固定局数の対局2回または3回、および条件を満たした場合の採否測定だけである。
評価関数の学習器、探索のコード、および対局ハーネスは変えない。
過去に不採用となったλ=1.0以外の評価関数の候補と、過去のλ=1.0の重みは、本書では測らない。

## 依存関係

SPSAの調整には、masterへ統合済みの[SPSAの基盤](spsa.md)と、[利得の較正](spsa-gain-calibration.md)が定めた標準の利得（減衰する利得、終了時の摂動幅が範囲の1/6）と標準の規模3,000ペアを使う。
摂動幅の例外は、[探索部の再調整](search-revival-spsa.md)の規則をそのまま使う（「設計判断」の節）。
Pλの学習には、[PSTの学習手順](../guides/pst-training.md)のコマンド`pst-workflow`と、G23の設定ファイル`data/pst-gen3-g23.toml`の学習条件を使う。
対局の測定は[SPRTの手引き](../guides/sprt.md)の固定局数Eloと段階ゲートに従う。

作業は、Mから本書専用のブランチ`eval-search-coadaptation`を作り、worktreeで行う。
測定の途中にmasterの探索や評価関数の変更を取り込まない。
[補正1/4のFMの再学習](fm-quarter-current-pst.md)は、本書の完了後に着手する。

## 設計判断

| 項目 | 決定 |
|---|---|
| 検証に使う候補 | λ=1.0で学び直したPSTの1つとする。重みの変化量が採用された再学習より小さいのに大きく負けたという性質が、評価関数そのものの悪さと係数との不整合を区別するのに適しているからである。FMやNNUEは探索速度の費用を伴い、順位の損失の候補は教師への誤差の悪化を伴うので、回復量を係数の効果だけに帰属させにくい。結論はこの1つの候補についてのものであり、他の候補へ一般化するかは利用者が決める。 |
| 候補の作り方 | 過去の重み（ブランチ`teacher-mixing-ratio-100-candidate`の`16a2257`）は使わず、過去と同じ作り方を現行の採用PSTへ当て直す。過去の重みは、当時の採用PSTを初期値に、当時の11ファイルで学習した。今回は、採用PSTであるG23を初期値に、G23の学習に使った世代2と世代3の10ファイルで、G23の学習条件（先読み教師γ=0.9、n=40、鏡映共有モデル、出力K 1072.6529541015625、学習率0.03、10エポック、バッチ16,384、乱数シード1、駒除去差分の追加損失の係数1000）に`lambda_override = 1.0`だけを加えて学習する。過去の重みをMに載せると、E0には混合比の効果に加えて、G23の学習による向上と、G23に合わせた係数の調整による向上の欠落が混ざる。これらは係数を調整し直しても取り戻せないので、|E0|が膨らみ、仮説が正しくても回復率が判定の閾値に届かなくなる。学び直しは学習と診断で約30分で済む。PλとG23の差は、混合比のほかに、初期値（G23はその前の採用PST、PλはG23）と、G23の上に重ねた10エポックの学習を含む。学習器は初期値から駒除去差分の損失の参照表を作るので、初期値の違いは損失の基準も変える。したがって、本書はPλの負けの原因を混合比へ帰属させない。仮説が問うのは、評価値の分布が採用PSTと異なる候補の負けを係数の調整がどれだけ取り戻すかであり、分布が変わった理由は問わないので、この限定で検証は成り立つ。混合比だけを変えた対照（G23を初期値に、λ=0.75で同じ追加学習をしたPST）は、この問いに答えるのに要らないので作らない。 |
| 学習器の再現確認 | G23の学習の後に学習器のパッケージ構成が変わったので、Pλの学習の前に、現行の学習器がG23の重み（SHA-256 `e5ba5022…`、Mの`crates/minase/nets/pst.bin`）をバイト単位で再現することを確かめる。ワークフロー`pst-workflow`は基点コミットから初期値を取り出すが、G23の基点`44ae7cb`はcrate分割前の配置で重みのパスが異なるので、ワークフローは使えない。そこで、G23の実行ディレクトリに保存された初期値`data/pst-gen3-g23/pst-base.bin`（`44ae7cb`の`nets/pst.bin`とSHA-256が一致する）と、同ディレクトリの`commands.jsonl`が記録した学習の引数を、現行の学習コマンド`train-pst`へそのまま渡す。一致しない場合は、Pλの学習へ進まずに原因を調べる。 |
| 調整する係数 | 探索係数29個とし、時間管理の6係数は含めない。最新の標準のセッションである[探索部の再調整](../measurements/search-revival-t.md)が同じ29係数を調整したからである。仮説が問うのは評価値の分布に対する余裕値や窓幅の不整合であり、時間管理の係数はその対象ではない。時間管理の係数を除くので、[SPSAの手引き](../guides/spsa.md)の時間切れの事前確認は要らない。Cλ\*とS0\*は同じ29係数を調整する。 |
| 調整の規模と利得 | 標準の3,000ペアと標準の利得をそのまま使う。開始値はMの係数の値とし、範囲は係数の表の宣言のとおりとする。3,000ペアは収束を保証しない規模である（[SPSAの設計書](spsa.md)「調整セッションの規模と所要時間」）ので、回復を示せなかった場合も、それだけで共適応を否定しない。 |
| 摂動幅 | 探索部の再調整で戻した8項目の13係数（`ReverseFutilityMargin`、`LmpBase`、`LmpSlope`、`NullMoveEvalScale`、`RazoringMargin1`、`RazoringMargin2`、`NonImprovingFutility1`から`3`、`CaptureHistoryLimit`、`CaptureHistoryScale`、`QsearchMoveLimit`、`HistoryDecay`）は、同計画の「摂動幅」の規則で`c_end`を定める。すなわち、範囲の1/6と、開始値から近い方の範囲の端までの距離を摂動の初期倍率375^0.101（約1.82）で割った値の小さい方を、小数第1位へ丸める。開始値はMの値なので、同計画の表の値ではなく、Mの値から計算し直す。既存の16係数は、これまでのセッションと同じく既定の範囲の1/6のままとする。この規則は開始値だけで決まるので、Cλ\*とS0\*のセッションは同じパラメーターファイルを使う。 |
| 回復量の測り方 | Cλ対S0とCλ\*対S0を、STCの時間制御（`time=10000+100`）で各400ペアの固定局数Eloとして測る。2回の測定は同じ基本シードを使い、同じ開始局面の組で対局させる。これは意図して同じ対局列を使う比較であり、[隣接シードの教訓](../lessons/derive-seed-adjacent-collision.md)が戒める意図しない重複とは異なる。手数上限による破棄は測定ごとに異なり得るので、各段の量は、その段が使う測定のすべてで完走したペア（共通ペア）だけから計算する。したがって、第0段のE0と、第1段および第2段のE0は対象のペアが異なり得るので、段ごとに対象のペア数と値を記録する。結論の対象は共通ペアであり、破棄が対局の内容に依存し得ることは除けないので、各測定を自身の完走ペアだけで計算したEloも併記する。Eloは、ペアごとの候補側の得点の平均をロジスティックの写像で変換して求める。 |
| 信頼区間と判定の統計量 | 信頼区間は、共通ペアをペア番号ごとに復元抽出する対応のあるブートストラップ（10,000回、乱数シード20261004固定）のパーセンタイル法で、2.5%点と97.5%点をとる。回復率R/|E0|は分母が0に近い復元標本で不安定になるので、判定には比を使わず、同値な差の形を使う。E0<0のとき、回復率が0.5以上であることはD1 = E1 − 0.5·E0が0以上であることと同値であり、対照を差し引いた回復率(R−G)/|E0|が0.5以上であることはD2 = E1 − G − 0.5·E0が0以上であることと同値である。回復率と対照を差し引いた回復率は、点推定だけを参考として記録する。共通ペアのE0の点推定が0以上の場合、共通ペアが200未満の場合、または復元標本の得点の平均が0か1になってEloが有限でない場合は、その段を「判定不能」とし、延長や再測定はせずに記録して終える。 |
| 調整に進む条件 | 第0段で、E0の95%信頼区間の上限が−50 Eloを下回る場合だけ調整へ進む。これは約8.2時間のセッションを費やすかを決める費用上の事前選別であり、識別の可能性を証明する基準ではない。Pλは過去の重みと作り方が同じでも、同じ大きさの負けを示すとは限らない。負けが50 Elo未満なら、その半分は25 Elo未満であり、400ペアの固定局数Eloの95%信頼区間の半幅約23 Elo（[学習シードの散らばりの記録](../measurements/pst-seed-spread-nodes.md)の固定ノード数の400ペアの実測で約22.6〜23.9 Elo）と同程度になるので、セッションの費用に見合う結論を得にくい。この条件を満たせない場合には、負けが50 Elo未満である場合と、負けは大きいが測定の精度が足りない場合の両方を含む。 |
| 調整し直しの一般的な効果の対照 | 第1段で回復が大きいと判定した場合だけ、S0\*を同じ規模で作り、S0\*対S0を同じ基本シードの400ペアで測る。どのエンジンでも探索係数を調整し直せば強くなり得るので、その分を差し引かなければ、回復を共適応に帰属できないからである。Mの係数は探索部の再調整でG23に合わせて調整した直後の値なので、Gは小さいと見込まれるが、1回のセッションの結果から上限を決めることはできない。対照を最初から置く案は、回復が小さく対照が判定に影響しない場合にも約9時間を費やすので採らない（2026年10月4日の利用者決定）。ブートストラップの信頼区間は、作ったCλ\*とS0\*の対局の誤差だけを含み、SPSAのセッションごとの結果の散らばりを含まない。したがって、第2段の結論は今回の1回ずつの調整結果についてのものであり、調整の手順の平均的な効果を主張するには、セッションの反復が別に要る。 |
| 判定の閾値 | 「判定」の節で、結果を見る前に固定する。 |
| 採否 | 本書は診断であり、Cλ\*を採用するかどうかは、判定の後に条件を満たした場合だけ標準のSTCとLTCのGSPRTで決める。固定局数Eloを採用の根拠には使わない。 |

## 判定

判定は、結果を見る前に次のとおり固定する。
信頼区間と「判定不能」の扱いは、「設計判断」の節の「回復量の測り方」と「信頼区間と判定の統計量」に従う。

第0段では、Cλ対S0の測定で完走したペアからE0を求め、調整へ進むかを決める。

| 振り分け | 条件 | 後続 |
|---|---|---|
| 負けが大きい。 | E0の95%信頼区間の上限が−50 Eloを下回る。 | 第1段へ進み、Cλの調整セッションを実行する。 |
| 所定の大きさの負けを確認できない。 | 上記に当たらない。 | 現行の採用PSTから学び直したPλについて、50 Elo以上の負けを確認できなかったと記録して終える。負けが小さいことと、測定の精度が足りないことは区別しない。過去の約−164 Eloの一部は、当時の採用PSTや探索係数に固有だった可能性が残る。評価関数の採否の手順は変えず、別の候補で仮説を確かめるかは利用者が決める。 |

第1段では、Cλ対S0とCλ\*対S0の共通ペアからE0、E1、R、およびD1を求め、表の上の行から順に、最初に条件を満たす行へ振り分ける。

| 振り分け | 条件 | 後続 |
|---|---|---|
| 回復が大きい。 | D1の95%信頼区間の下限が0以上である。 | 第2段へ進み、S0\*を作って対照を測る。 |
| 回復が部分的である。 | Rの95%信頼区間の下限が0を上回り、D1の95%信頼区間の下限が0未満である。 | 調整し直しで負けの一部は縮むが、負けの半分以上が縮むとは示せなかったと記録する。手順を変えるかは利用者が決める。延長や再測定は行わない。 |
| 回復を示せない。 | 上記のいずれにも当たらない。 | 本書の調整の規模では回復を示せなかったと記録する。調整が収束していない可能性が残るので、Pλの負けの原因を評価関数の側と断定しない。評価関数の採否の手順は変えない。 |

第2段では、3つの測定の共通ペアからE0、E1、G、およびD2を求める。

| 判定 | 条件 | 後続 |
|---|---|---|
| 共適応を支持する。 | D2の95%信頼区間の下限が0以上である。 | 今回の調整結果では、調整し直しの一般的な効果を差し引いても、Pλの負けの半分以上が縮んだ。評価関数の候補の採否の測定の前に、候補に合わせて探索係数を調整し直す手順を[SPRTの手引き](../guides/sprt.md)へ加えることを利用者に提案し、教訓を記録する。過去に不採用となった評価関数の候補を調整し直して測り直すかは、別の計画として利用者が決める。 |
| 共適応に固有とは示せない。 | 上記に当たらない。 | 調整し直しの一般的な効果を差し引いた回復が、負けの半分以上に達するとは示せなかったと記録する。Gの大きさと、対照を差し引いた回復率の点推定を併記し、回復が一般的な効果で説明できる場合と、精度が足りない場合を区別できるようにする。手順は変えない。 |

判定とは別に、第1段の共通ペアによるE1の95%信頼区間の下限が0を上回った場合だけ、Cλ\*をSTCとLTCの段階ゲートでMに対して測り、採否を決める。この振り分けは第1段の結果で一度だけ行い、第2段の結果や第2段の判定不能によって変えない。
第2段でGの95%信頼区間の下限が0を上回った場合は、S0\*も同じく段階ゲートでMに対して測ってよいかを利用者に確かめる。
これらの条件は採用の読み替えではなく、採否の測定に進むための振り分けである。

## 追加診断

第1段の判定の後、利用者の指示で、Pλの負けの原因を評価関数の側でさらに切り分ける2つの診断を行う。
どちらも採否の測定ではなく、判定の読み方は結果を見る前に次のとおり固定する。

### 追加学習の対照

PλとG23は、混合比のほかに、G23の上へ10エポックを重ねた点でも異なる。
この2つの効果を分けるため、Pλと同じ設定から`lambda_override`だけを除き、λ=0.75のまま同じ10エポックを重ねたPST（**Pc**）を学習する。
設定ファイルは`data/eval-coadaptation-lambda075.toml`、学習の記録は測定記録`eval-coadaptation-lambda075-training`とする。
Mの`crates/minase/nets/pst.bin`をPcへ差し替えたコミットを**Cc**とし、Mから作るブランチ`eval-coadaptation-lambda075`に置く。
Cc対S0を、フェーズ2と同じ基本シード13000000、同じ時間制御で400ペア測り、測定記録`eval-coadaptation-lambda075-stc400`に残す。

Cc対S0のEloを**Ec**とする。
判定スクリプトの`stage1`を、`--before`にCλ対S0、`--after`にCc対S0の実行ディレクトリを与えて実行すると、この2測定の共通ペアでのE0、Ec（出力のE1）、およびEc−E0（出力のR）とそれらの信頼区間が得られる。
E0は、第1段の349ペアの値を流用せず、この2測定の共通ペアで計算し直した値を使う。
表を適用する前に、測定条件の照合が一致し、`indeterminate_reasons`が空で、EcとEc−E0の信頼区間が有限であることを確かめる。いずれかを満たさなければ「判定不能」と記録する。
次の2つの条件で振り分ける。条件Aは「Ecの95%信頼区間の上限が0を下回る」、条件Bは「Ec−E0の95%信頼区間の下限が0を上回る」である。

| 振り分け | 条件 | 読み方 |
|---|---|---|
| 混合比による悪化だけを示した。 | Aが偽、Bが真。 | λ=1.0がλ=0.75より悪いことは示されたが、追加学習だけによる負けは確認できない。追加学習で負けないとまでは言わない。 |
| 追加学習による負けだけを示した。 | Aが真、Bが偽。 | λ=0.75でも追加学習で負けることは示されたが、λ=1.0による追加の悪化は確認できない。両者が同程度とまでは言わない。 |
| 両方を示した。 | AとBがともに真。 | 追加学習だけでも負け、λ=1.0はさらに負けを大きくする。 |
| 区別できない。 | AとBがともに偽。 | 2つの効果を分けられなかったと記録する。 |

負けの有無や同程度であることを主張するための非劣性または同等性の条件は置かないので、上の読み方は「示された」か「確認できない」にとどめる。
点推定の比Ec/E0も参考として記録する。
Ecの95%信頼区間の下限が0を上回った場合は、Ccが採用PSTより強い可能性があるので、段階ゲートで採否を測るかを利用者に確かめる。

### 評価値の分布の比較

本書の仮説は、候補が評価値の散らばり方を変えることを前提にしているが、Pλがこの前提を満たすかは測っていない。
そこで、対局をせずに、同じ局面の集合で各PSTの静的評価値を比べる。
局面は、G23の学習に使った世代2と世代3の10ファイルから、乱数シード20261005で非復元に一様抽出した100,000局面とし、評価値は手番側から見た量子化後の整数評価値とする。
比べる組は、G23を基点とするPλとPc、および`44ae7cb`の`nets/pst.bin`を基点とする過去のλ=1.0の重み（ブランチ`teacher-mixing-ratio-100-candidate`の`16a2257`）の3組である。

各組は、基点（G23、または過去の重みの基点）に対する候補（Pλ、Pc、または過去のλ=1.0の重み）として、比較の向きをそろえる。
各PSTについて、評価値の平均、標準偏差、絶対値の平均、および絶対値の5%、25%、50%、75%、95%点を求める。
各組について、標準偏差の比（候補／基点）、Pearsonの相関係数、Spearmanの順位相関係数、回帰式「候補の評価値 = a + b × 基点の評価値 + 残差」の係数bと残差の標準偏差、差（候補−基点）の標準偏差、差の絶対値の50%、90%、99%点、および差の絶対値が100 cp（歩兵1枚）を超える局面の割合を求める。
同じ指標を、局面の進行度（位相の分子qを0〜29、30〜59、60〜90の3区間）別と、基点の評価値の帯（絶対値が0〜99、100〜299、300〜999、1000 cp以上の4区間）別にも求める。
探索用の歩兵の価値は、G23、Pλ、Pc、および過去の2つの重みでいずれも100 cpであり、余裕値はこの価値に対する割合で決まるので、cpの差はそのまま余裕値と比べられる。

読み方は次のとおりとする。
全局面の標準偏差の比が0.9〜1.1の外にあれば、その候補は評価値の散らばりの尺度を変えたと読む。内にあれば、全体の尺度はほとんど変えていないと読む。
この目安は全体の尺度の記述に限り、区間別の値と、相関および残差による局面ごとの対応の変化は、記述として併記する。
回帰の係数bは相関と標準偏差の比の積なので、尺度の判定には使わない。
この比較は静的評価値の分布を測るだけであり、探索の余裕値との不整合の有無そのものは判定しない。不整合を直接測るには、探索中の静的評価値と探索窓の差を記録する計装が要り、本診断の範囲外とする。
計算のスクリプトと出力は`docs/measurements/eval-coadaptation-distribution/`に置き、測定記録`eval-coadaptation-distribution`に残す。

## 所要時間の見積り

時間は同時対局数16の測定機での見積りである。
学習は[G23の学習](../measurements/pst-gen3-training.md)の実績（G3とG23の準備、学習、診断で約48分）、固定局数の対局は[λ=1.0のSTC](../measurements/teacher-mixing-ratio-100-stc.md)の1ペアあたり約9.2秒、セッションは[探索部の再調整](../measurements/search-revival-t.md)の29係数、3,000ペアの実績約8.2時間を根拠とする。

| 段 | 内容 | 見積り |
|---|---|---|
| 準備 | 学習器の再現確認、Pλの学習と診断、Cλの作成と検証 | 約1.5時間 |
| 0 | Cλ対S0の400ペア | 約1時間 |
| 1 | Cλの調整セッションとCλ\*対S0の400ペア | 約9時間 |
| 2（条件付き） | S0\*の調整セッションとS0\*対S0の400ペア | 約9時間 |
| 採否（条件付き） | Cλ\*対MのSTCとLTC | 約1〜8時間と約5〜30時間 |

第0段で終われば合計は約2.5時間、第1段で終われば約11.5時間、第2段まで進めば約20.5時間である。

## 実装フェーズ

### フェーズ1　候補の作成

Mからブランチ`eval-search-coadaptation`とworktreeを作る。
最初に、`data/pst-gen3-g23/commands.jsonl`が記録したG23の学習の引数のうち、初期値を`data/pst-gen3-g23/pst-base.bin`、出力先を新しいディレクトリ`data/eval-coadaptation-reproduction/`の下に置き換えて、現行の学習コマンド`uv run --project tools/train train-pst train`へ渡す。
出力の重みがMの`crates/minase/nets/pst.bin`とバイト単位で一致することを確かめ、実行したコマンドの全体、入力ファイルのSHA-256、学習器のコミット、および出力のSHA-256を測定記録`eval-coadaptation-trainer-reproduction`に残す。
次に、`data/pst-gen3-g23.toml`の写しで`base_commit`をMに、`run.directory`を`data/eval-coadaptation-lambda100`に改め、`[train]`節へ`lambda_override = 1.0`を加えた設定でPλを学習し、学習後の診断を通す。
学習の記録は測定記録`eval-coadaptation-lambda100-training`に残し、Pλと採用PSTの浮動小数点の重みの差（序中盤と終盤の平均と最大）を含める。

Pλの診断が通ったら、`crates/minase/nets/pst.bin`をPλへ差し替えたCλをコミットする。
Mの`crates/minase/src/eval/pst/tests.rs`には、埋め込みの重みでの初期局面の評価値を学習器の参照値と照合するテストがあり、期待値は採用PSTの値である。
Cλではこの期待値を、Pλの学習ログ`train.log`の`initial position evaluation:`行が出力した学習器の参照値へ改める。
差し替えた重みのSHA-256がPλと一致すること、`cargo test`、`cargo clippy -- -D warnings`、および`cargo fmt --check`が通ることを確かめる。
完了条件は、再現の一致とCλのコミットである。

### フェーズ2　調整前の測定と第0段の判定

Cλ対S0の400ペアを測り、測定記録`eval-coadaptation-before-stc400`に残す。

```console
cargo run --release --bin minase -- match run \
  --run-dir data/matches/eval-coadaptation-before-stc400 --seed 13000000 \
  --candidate commit:<Cλ> --baseline commit:<M> \
  --each time=10000+100 --concurrency 16 elo --pairs 400
```

E0とその信頼区間を計算し、第0段の振り分けを記録する。
「所定の大きさの負けを確認できない」の場合は、ここで本書を終える。

### フェーズ3　調整

`minase spsa params`でCλの調整用ビルドから既定のパラメーターファイルを生成し、開始値がMの係数の値と一致することを確かめる。
そのファイルから時間管理の6係数を除き、13係数の`c_end`を「摂動幅」の規則で上書きしたファイルを`data/spsa/eval-coadaptation-params/session.txt`に置く。
基本シード14000000で3,000ペアのセッションを実行する。

```console
minase spsa --run-dir data/spsa/eval-coadaptation-clambda --seed 14000000 \
  --engine commit:<Cλ> --params data/spsa/eval-coadaptation-params/session.txt \
  --rules engine-default --each time=10000+100 --concurrency 16 \
  --iterations 375 --pairs-per-iteration 8
```

セッションの記録は`docs/measurements/eval-coadaptation-spsa.md`に残し、パラメーターファイルの全行を含める。
最終値を`minase spsa apply`でCλへ書き込み、Cλ\*をコミットする。
完了条件は、Cλ\*のコミットと、セッションの異常が0件であることの確認である。

### フェーズ4　調整後の測定と第1段の判定

Cλ\*対S0の400ペアを、フェーズ2と同じ基本シード13000000で測り、測定記録`eval-coadaptation-after-stc400`に残す。
共通ペアからE0、E1、R、D1とそれらの信頼区間、および回復率の点推定を計算し、第1段の振り分けを記録する。
計算に使うスクリプトと乱数シードは、測定記録のディレクトリに保存する。

### フェーズ5　対照と第2段の判定（条件付き）

第1段が「回復が大きい」の場合だけ、Mの調整セッションをフェーズ3と同じパラメーターファイルと基本シード17000000で実行してS0\*を作り、測定記録`eval-coadaptation-control-spsa`に残す。
S0\*対S0の400ペアを基本シード13000000で測って測定記録`eval-coadaptation-control-stc400`に残す。
3つの測定の共通ペアからG、D2とそれらの信頼区間、および対照を差し引いた回復率の点推定を計算し、第2段の判定を記録する。

### フェーズ6　採否測定（条件付き）

「判定」の節の条件を満たした場合だけ、Cλ\*をMに対してSTC（`eval-coadaptation-stc`、基本シード15000000）とLTC（`eval-coadaptation-ltc`、基本シード16000000）の段階ゲートで測る。
利用者がS0\*の測定を承認した場合は、S0\*をMに対してSTC（`eval-coadaptation-control-stc`、基本シード18000000）とLTC（`eval-coadaptation-control-ltc`、基本シード19000000）の段階ゲートで測る。

## 検証

- 学習器の再現で、出力の重みのSHA-256がMの`crates/minase/nets/pst.bin`と一致することを確かめる。
- CλとMの差が`crates/minase/nets/pst.bin`と重みに依存するテストの期待値だけであり、Cλ\*とCλの差が係数の表の29係数の既定値だけであることを、`git diff --stat`と`git diff`で確かめる。
- パラメーターファイルが29行であり、開始値がMの係数の値と、13係数の`c_end`が「摂動幅」の規則の計算値と一致することを確かめる。
- 同じ基本シードを使う測定どうしで、`manifest.json`の基本シード、時間制御、同時対局数、置換表容量、および基準のバイナリのSHA-256が一致することを確かめる。
- 共通ペアの数と、測定ごとの破棄ペアの番号を記録する。
- すべての測定で、エンジン異常、時間切れ、および拒否着手の件数を記録する。1件でも出た場合は測定を止めて原因を調べ、シードを変えた再試行はしない。

## 完了条件

- 実施した学習、固定局数Eloの測定、調整セッション、および判定が測定記録に残っている。
- 「共適応を支持する」場合は、手順の変更の提案と教訓が記録され、採否の手順を変えるかの利用者の決定が[SPRTの手引き](../guides/sprt.md)またはROADMAPに反映されている。
- 採否の測定へ進んだ場合は、その採否が確定している。Cλ\*を採用した場合は、Pλと調整後の係数が評価関数と探索部の設計書の現行値に反映されている。S0\*だけを採用した場合は、採用PSTはG23のまま、調整後の係数だけが探索部の設計書の現行値に反映されている。
- ROADMAPの状態表が本書の結論と一致している。

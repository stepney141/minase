# 王の安全度と利きに基づく評価特徴の再学習の設計書

## 先に読む要約

本書は、[棋力向上段階9](strength-stage9.md)で見送った7つの評価項目（王の遮蔽と開いた筋、王の周囲の攻撃域、王の守備駒、安全な可動性、成りの可能性と侵入、獅子の接近と退路、駒への脅威と浮き駒）を、見送りの原因を直したうえで学習し直し、棋力が上がるかを確かめる。
各項目は、盤面から数えた特徴値に学習した係数を掛けて評価値へ加える線形の項である。
段階9では、項目1が学習の採否基準に届かず、項目2から項目7は利きを高速に数える土台が遅すぎたために、学習の前に見送られた。
[原因調査](../audits/heuristic-learning-causes-2026-09-27.md)は、項目1の見送りの原因として、遮蔽を見ない特徴、探索値が大半を占める教師、および損失の最小化と別の条件だった採否基準を挙げた。
本書は、項目1に王駒への射線を数える6個の特徴を加え、全項目の係数を採用中の評価関数と同じ先読み教師で学ぶ。
採否の前段には、学習に一度も使わない新しい自己対局での対局結果の予測損失を置き、7項目を同時に検定して多重比較を補正する。
この選別は盤面から全計算した特徴値で行えるので、速い土台を作る前に、予測に役立つ項目だけを選べる。
選別を通過した項目は、必要な土台の費用によって3つの段に分け、安い段から順に1段ずつ実装して、短時間条件STCと長時間条件LTCの時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[手引き](../guides/sprt.md)）で採否を決める。
完了条件は、7項目の選別の結果と、選別を通過した各段の採否が測定記録とともに確定することである。

## 目的

本書は、「王駒の安全度と駒の利きの関係を表す線形の項を、採用中の教師で学んだ係数で評価値へ加えると、土台の費用を払っても同じ持ち時間で棋力が上がる」という仮説を、項目ごとに検証する。
[lishogiの敗局](../research/lishogi-game-yO464dzl-loss-analysis.md)では、玉の正面の筋が開いて敵の走り駒が集まる間も、評価関数は+1000センチポーンを超える評価値を返し続けた。
段階9の[118列の発火率診断](../measurements/strength-stage9-activation-diag-b.md)では、この敗局の180手目までに、項目1の開いた筋に加えて、項目2の王駒から距離2の升への攻める側の高い利き数と、項目7の支えのない駒への脅威が発火しており、特徴としては危険を表現できていた。

段階9の見送りの理由は、項目によって異なる。

項目1は、中盤の露出局面1,000局面への平均補正が−30センチポーン以下という事前の判定に届かず見送られた。
原因調査は、保存済みの学習データによる対照実験で次のことを確かめた（数値は段階9の学習データ、訓練23,879,611局面と検証1,241,072局面によるもの）。
当時の係数は、係数0から最適解までに得られる訓練損失の改善の91.2%（先読み教師では96.4%）に達しており、最適化は不足していなかった。
当時の基本教師で学ぶ場合、元の24特徴に遮蔽を考慮した射線の6特徴を加えると、全検証局面の対局結果に対する損失が下がり、多重比較の補正の後も5%水準で差を検出した。
中盤の露出局面の平均では改善を検出しなかったが、そのうち射線のある局面（34,505局面、3,035対局）では改善が見られた。
一方、中盤の露出局面の92.39%では射線の特徴が発火しなかった。
遮蔽物を除く将来の攻めはあり得るので、この割合は安全な局面の割合ではない。
中盤の露出局面へ加わる平均補正は教師によって大きく変わり、探索値だけの教師で+1.1センチポーン、基本教師（探索値75%と対局結果25%の混合）で−4.2センチポーン、対局結果だけの教師で−20.3センチポーン、先読み教師で−22.7センチポーンだった。
ただし、基本教師から対局結果だけの教師への変更による損失の差は、原因調査の主要3比較にHolm法の補正を当てると5%水準に達しておらず、どの教師が棋力に適するかも示されていない。
また、判定に使った露出1,000局面では、損失を最小にする解が射線のある88局面を強く減点しても、残りの912局面の補正が小さいため、平均は−30センチポーンに届かなかった。
−30センチポーンは、段階9の診断Aが深い探索の感度に対して置いた値を、係数の寄与の平均へ転用したものであり、損失の最小化とは別の条件だった。

項目2から項目7は、係数を一度も学習していない。
項目2、項目3、項目6、項目7は、升ごとの利き数を差分更新する表（利き数の表）を土台とするが、[利き数の表の速度](../measurements/strength-stage9-table-bench.md)が段階開始版の0.816倍で土台の条件0.90倍を満たさず、見送られた。
項目4と項目5は、駒ごとの到達升の集合（全駒の利き集合）も要し、利き数の表の見送りに伴って見送られた。
つまり、これらの項目が予測や棋力に役立つかは、まだ誰も確かめていない。

本書は、学習と予測の選別を土台の速度から切り離し、選別を通過した項目にだけ土台の費用を払う。
原因調査が分離できなかった教師の品質、生成時の局面の除外、および損失関数と棋力の対応は、本書でも分離しない。

## 適用範囲

対象は、評価関数の追加特徴の計算（`src/eval/`）、探索中の評価への接続、利き数の表と全駒の利き集合の土台、学習用の特徴値の書き出し（`pst_probe`）、学習器の追加特徴の経路（`tools/train/pst/`）、試験用の自己対局の生成、および採否の測定である。
探索の手順、学習PSTの重み、探索用駒価値、出力K、教師データの形式MNSD、および生成器の設定は変えない。

学習PSTと追加係数の同時学習、損失関数の変更、教師の混合比の比較、生成時の局面の除外が教師に与える影響の調査、および段階9が扱わなかった調査の段階8から段階10（王の退路、歩と仲人の閉塞、王を基準にした駒の関係表）は扱わない。
理由は「設計判断」の節に記す。

用語は段階9の設計書に従い、本書で使う主な語を次に定める。

- **学習PST**は、駒の種類と升ごとの重みを足し合わせる現行の評価関数であり、序中盤と終盤の2組の重み（2端点）を持つ。
- **補間係数φ**は、盤上の駒数から計算する0から1の値であり、2端点の重みの混ぜ方を決める。φが0.5以上の局面を**中盤**、0.5未満を**終盤**とする。
- **出力K**は、評価値（センチポーン）を勝率へ変換するときの尺度であり、予測確率は評価値を出力Kで割った値にシグモイド関数を適用して求める。現行値は1072.6529541015625である。
- **守る側**は対象の王駒の持ち主、**攻める側**はその相手である。**前方**は守る側から見た相手陣の方向である。
- **露出局面**は、手番側の王駒がちょうど1枚で、項目1の手番側の走り駒の特徴（守る側の歩のない筋に攻める側の縦の走り駒がいる）が1つ以上発火している局面を指す。
- **射線の特徴**は、本書が項目1に加える6個の特徴を指す（定義は「特徴」の節）。
- **全計算**は、局面ごとに利き数と到達升を盤面から一から数え直す計算を指し、学習用の書き出しと検証に使う。**高速版**は、探索中に差分更新する土台から特徴を計算する実装を指す。
- **先読み教師**は、局面の探索値の代わりに、同じ対局のその後n手までの探索値を減衰率γで重み付けした平均を勝率へ変換し、対局結果とλ:(1−λ)で混ぜた教師値である（定義は[先読み教師値の設計書](lookahead-teacher.md)）。

## 依存関係

本書は、着手時のmasterの採用構成を基準とする。
基準に含まれるのは、学習PSTの重み、探索用駒価値、出力K、SPSAで調整した探索係数、およびその学習PSTの学習に使った教師の設定である。
2026年9月27日時点の学習PSTは、先読み教師（γ=0.9、n=40、λ=0.75）を世代0から世代2の11ファイルへ適用して学習したものである（[学習記録](../measurements/lookahead-teacher-pst-training.md)）。
着手までに評価関数の他の計画が採用され、学習PSTや教師の設定が変わった場合は、変わった後の構成を基準とし、本書の数値の見積もりをその構成で確かめ直す。

本書は段階9の成果物を移植して使う。
全7項目118列の全計算と書き出しはブランチ `strength-stage9-diag-b`、利き数の表の差分更新と探索の側の利用はブランチ `strength-stage9-table` にある。
項目1の評価側の実装、探索中の評価への接続、MNKF（追加特徴の特徴値ファイル）の書き出し、および学習器の追加特徴の経路は、段階9の完了時にmasterから外された。
その後の[src/coreの再編](core-layout.md)と[探索部と評価関数のモジュール再編](search-eval-layout.md)でモジュールの配置が変わったので、いずれも単純な差し戻しではなく現行の配置への移植になる。
移植の元のコミットと差分の一覧は、各フェーズの準備記録に残す。
段階9の診断用に書き出した118列の特徴値ファイル（`data/strength-stage9/features-b/`）は、移植した全計算の回帰の参照値に使う。

[残存誤りに対応する関係補正項](relational-correction.md)は、誤りの分類の候補に、王駒から8方向の最初の駒とその奥の敵の走り駒の組を採点する射線表を含む。
本書の射線の特徴は、筋の方向だけを見て本数を数える線形の項であり、駒の組ごとの表ではない。
本書で採用した項目があれば、関係補正項の計画は、その採用版を基準S0として誤りを分類し直すことになる。

[合法手生成と利き計算の高速化（第3期）](movegen-speedup-3.md)が先に採用されて利き計算が速くなった場合も、本書の手順は変わらず、各段の速度の記録がその効果を含む。

## 設計判断

| 項目 | 決定 |
|---|---|
| 選別を土台の前に置く | 段階9は、速い土台を先に作り、その速度の条件で項目2から項目7を学習の前に見送った。しかし、係数の学習と予測損失の選別は全計算の特徴値で行えるので、土台の速度に依存しない。予測に役立たない項目のために土台を作る費用を避け、役立つ項目が速度の条件だけで捨てられることも避けるため、全項目の選別を先に行う。 |
| 1項目1定式化 | 各項目の定式化は、項目1を除いて段階9の設計書の定義のまま測り、項目1は元の24特徴に射線の特徴6個を加えた1つの定式化とする。選別または採否測定で不採用となった項目について、区間、特徴、教師、または標本を変えた変種を測り直さない。結果を見てから変種を足すことは、[SPRTの手引き](../guides/sprt.md)が禁じる操作に当たる。 |
| 項目1に射線の特徴を加える | 原因調査で、射線の6特徴の追加だけが、多重比較の補正の後も5%水準で損失の改善を示した。この特徴は、元の走り駒の特徴が同じ値を返す局面のうち、実際に射線が通る局面を区別する。元の24特徴は、筋の開き方と遮られている走り駒も将来の攻めの準備を表し得るので残す。 |
| 敵歩と走り駒の交互作用を加えない | 原因調査は、元の特徴が敵歩の有無によって走り駒の効果を変えられないことを未検証の仮説として挙げた。攻める側の歩が走り駒と王駒の間にある場合は射線の特徴が発火しないので、この交互作用の主要な場合は射線の特徴が区別する。交互作用を別の列として加えると、証拠のない変種を1つの候補へ混ぜることになる。 |
| 教師は採用構成の教師 | 追加係数は、固定した学習PSTの予測と教師値の残差に対して学習される。学習PSTと同じ教師を使えば、評価関数の全体が1つの目標に揃う。先読み教師による項目1の中盤の露出局面への補正（−22.7センチポーン）は、基本教師の小さな補正（−4.2センチポーン）と異なり、対局結果だけの教師（−20.3センチポーン）と同程度である。 |
| 教師の比較を行わない | 教師を替えた候補を並べると、比較の数だけ多重比較の補正と採否測定が要る。対局結果だけの教師は、[教訓](../lessons/game-constant-target-memorization.md)が示す対局内で一定の教師成分の記憶の危険も持つ。 |
| 学習PSTを固定する | 学習PST、探索用駒価値、および出力Kを固定し、追加係数だけを0から学習する。学習前の候補は採用版と同じ評価値を返すので、採否の差を追加項目に帰属できる。同時学習は、この帰属を失わせ、駒価値の歪みの点検（[教訓](../lessons/validation-loss-hides-material-distortion.md)）も要するので行わない。 |
| 学習器は既存の経路を使う | 原因調査で、既存の学習器は目的関数の改善の9割以上に達し、収束させても検証損失が変わらなかった。新しい最適化器は作らず、段階9の学習器の経路と設定を移植して使う。学習曲線は[教訓](../lessons/check-learning-before-blaming-data.md)に従って記録する。 |
| 選別は新しい対局で1度だけ行う | 段階9の検証集合はエポックの選択に使われ、項目1の判定に使った露出1,000局面はすべて訓練の分割に属していた。原因調査の部分群の結果も、同じ検証集合で事後的に見つけたものである。そこで、着手時の採用版で新しい自己対局を生成し、7項目の学習が終わるまで一切読まない試験集合とする。試験集合での損失の計算は、選別の1度だけ行う。 |
| 選別の主指標は対局結果に対する損失 | 探索値の教師に対する損失は、教師が見落としている危険を特徴が捉えても改善を示さない。本書の特徴の目的はその見落としを補うことなので、対局結果に対する二値交差エントロピーを主指標とする。ただし、対局結果への適合は自己対局の方策の結果への適合でもあり、探索で使う局面価値の改善を直接は示さない。この指標と棋力の対応は未検証なので、選別は採否測定へ進むかどうかの絞り込みにだけ使い、採用はLTCの判定で決める。 |
| 7項目を同時に検定する | 7項目の選別は、同じ試験集合での7つの片側検定であり、偶然の通過を抑えるためにHolm法で家族全体の有意水準を5%に保つ。原因調査では、補正の有無で教師の差の結論が変わった。 |
| 大きさの閾値を置かない | 係数の大きさ、符号、および局面群への平均寄与は、診断値として記録するだけで合否に使わない。平均補正の閾値は、性質の異なる局面の混ざった群の平均であり、改善に必要な量から導けないからである。 |
| 段は土台の費用で分ける | 選別を通過した項目を、土台なしで計算できる項目1（段0）、利き数の表を要する項目2、項目3、項目6、項目7（段1）、全駒の利き集合も要する項目4と項目5（段2）に分ける。棋力の検定は速度の損失と特徴の効果の差を測るので、費用の異なる項目を1つの候補に混ぜると、不採用のときにどの費用が原因かを分けられない。同じ段の項目は土台の費用を共有するので、1つの候補にまとめる。 |
| 段ごとの累積の候補（利用者の確認待ち） | 段0、段1、段2の順に、その段で選別を通過した項目だけをその時点の最新の採用版へ加えた候補を1つ作り、最新の採用版と比べる。段階9は項目ごとに検定したが、7項目を個別に測ると最大7組のSTCとLTCになる。段ごとにまとめれば最大3組で済み、土台の費用を同じ段の項目で分担できる。代わりに、同じ段の中の項目ごとの寄与は棋力では分けられない。 |
| 速度の下限を置かない（利用者の確認待ち） | 段階9は、土台に0.90倍、項目に0.85倍の速度の下限を置いた。これは見込みのない候補の学習と測定に時間を使わないための目安だったが、本書では学習と選別が速度に依存せず、候補も最大3つなので、下限で避けられる費用は各段の高速版の実装とSTCだけである。STCは真の差が小さい候補を最大3,000ペアで打ち切り、大きく劣る候補は少ないペア数で `H0` に達する。一方、下限を置くと、段階9と同じく利き数の表（0.816倍）を使う項目が棋力を測られないまま捨てられる。そこで下限を置かず、各段のNPSの比と、段階9の換算（損失は216×log2(1/r) Elo）による速度の損失の目安を、STCの前に記録するだけとする。 |
| 選別と棋力の対応を記録する | 選別の記録から、各段のSTCとLTCの測定記録へリンクする。選別を通過した項目が数件たまれば、損失の改善量と棋力の対応を実測で較正できる。本書はその較正を行わない。 |
| 時間の見積もりを先に示す | 数時間を超える生成、学習、および測定は、着手の前に所要時間の見積もりを利用者へ示す。 |

## 特徴

候補の追加特徴は124列であり、定義の識別値は3とする。
列の並びは、項目1（0〜29）、項目2（30〜61）、項目3（62〜67）、項目4（68〜89）、項目5（90〜95）、項目6（96〜107）、項目7（108〜123）である。
項目2から項目7の各列は、[段階9の設計書](strength-stage9.md)の「特徴」の節の定義と、段階9の定義の識別値2の列の並び（各項目の前半が手番側、後半が相手側）のまま使う。

項目1の列0から列23は、段階9の項目1の24列（手番側12列、相手側12列）のまま使う。
各視点について、筋の状態の6列（距離0、1、2と、「守る側の歩がなく攻める側の歩がある」「双方の歩がない」の組）と、走り駒の6列（距離0、1、2と、「1枚」「2枚以上」の組）を持つ。

列24から列29は射線の特徴であり、次のとおり定める。
対象は、王駒の筋と左右2筋までの最大5筋であり、王駒との筋の差を距離0、1、2とする。
守る側の成っていない歩兵または仲人が王駒の段より前方にある筋は、元の走り駒の特徴と同じく対象から除く。
残りの各筋について、王駒の段より厳密に前方の升を王駒に近い順にたどり、最初に駒がある升を求める。
その駒が攻める側の縦の走り駒、すなわち攻める側から見て前方へ任意の升数を進める駒であれば、その筋を射線のある筋とする。
特徴値は距離ごとの射線のある筋の本数であり、手番側の王駒の3列、相手側の王駒の3列の順に、距離の小さい順で並べる。
射線のある筋では元の走り駒の特徴も必ず発火するので、手番側の王駒が1枚で手番側の射線の特徴が発火する局面は、露出局面の部分集合になる。

王駒の数と盤端の扱いは段階9の共通の基盤に従う。
王駒を対象にする項目1、項目2、項目3、および項目6の接近の特徴は、対象の側の王駒がちょうど1枚でない場合に0とする。
盤の外にはみ出す筋と升は数えず、盤端で対象が少なくなっても正規化しない。

特徴の除外と2端点の共有は、段階9の規則を訓練の分割だけに当てて学習の前に決め、結果を見て変えない。
発火率が0.1%未満の列は除外し、2端点の識別性（特徴値の二乗を重みとしたφの偏差平方和）が100未満の列は2端点で同じ重みを共有する。
段階9の診断では、118列のうち発火率が0.1%未満の列が4つ、識別性が100未満の列が1つあった。
原因調査では、項目1の相手側の射線の距離0の列が全データで発火しなかった。
生成器は、探索値が詰みの帯にある局面と、探索が選んだ最善手が捕獲または成りである局面を保存しない。
手番側の走り駒が相手の王駒へ遮られずに向く局面では、最善手が王駒の捕獲になって保存されないので、この列が発火しなかったと考えられる。
この列は、発火率の規則で除外される見込みである。
段階9の学習器は2端点の共有を実装していないので、共有を求める列が出た場合は、共有を学習と重みの保存へ実装してから学習する。
段階9の診断では、項目6の孤立の列と項目7の獅子の脅威の列が全局面で同一だった。
項目ごとの学習では問題にならないが、両項目を同じ候補で学ぶ場合は係数が識別できないので、項目6の列を残し、項目7の同一の列を除外する。

特徴の全計算は、段階9の診断用の全計算を移植してRustの1か所に置き、学習用の書き出しと、各段の高速版の検証が同じ関数を呼ぶ。
高速版は段ごとに実装し、全計算と同じ値を返すことを検証する。
原因調査の診断コード（Python）は射線の特徴を独立に計算しているので、Rustの全計算との照合にだけ使い、学習の入力には使わない。

## 教師と学習

学習データと教師は、着手時の採用PSTの学習と同じにする。
2026年9月27日時点では、世代0から世代2の11ファイルに先読み教師（γ=0.9、n=40、λ=0.75）を適用し、訓練と検証の分割、教師K（探索値を勝率へ変換する尺度）、および二値交差エントロピーの損失を採用PSTの学習に合わせる。
採用PSTの学習は駒除去差分の追加損失を係数1000で使ったが、この損失は学習PSTの重みにだけ働き、学習器は学習PSTを固定した設定で0以外の係数を拒否するので、本書では係数を0とする。

その他の設定は、段階9の項目1の学習と同じにする。
モデルは `mirrored`（左右の鏡映で重みを共有する学習PSTのモデル）、学習率は3.0、エポック数は10、バッチは16,384、乱数シードは1、`freeze_pst = true` とする。
最良のエポックは既存の手順どおり検証の分割で選ぶ。

学習は2種類ある。
選別のための学習では、項目ごとに、学習PSTを固定してその項目の列だけを0から学ぶ7つのモデルを作る。
各段の候補のための学習では、その段で選別を通過した項目の列を同時に0から学び、それまでに採用した項目の係数と学習PSTは固定する。
候補の係数は選別のモデルの係数と異なり得るが、試験集合では評価し直さず、棋力の検定に委ねる。

試験集合は学習器から読めないようにする。
既存の学習の手順は、同じ実行設定で生成したファイルをすべて学習の入力へ加えるので、試験集合の生成と学習は別の実行設定と別の実行ディレクトリに分ける。

学習後は、段階9の学習後の診断を通す。
記録するのは、学習曲線、各列の係数と発火率、除外と共有の判定、学習PSTの部分が1ビットも変わらないことの確認、全計算の特徴値による学習器の予測とRustの評価の一致、および敗局の検証局面（段階9の診断と同じ手数）での各項目の寄与である。
敗局の局面は段階9で特徴の選定に使ったので、参考として記録するだけで判定に使わない。

## 試験用の対局

試験集合は、着手時の採用版を生成器で動かした新しい自己対局である。
生成器の設定は、局面ごとの探索ノード数、乱数の序盤、規則セット、置換表、および保存時の除外を含めて、[世代2の生成](../measurements/strength-stage7-gen2-generation.md)と同じにする。
生成の前に、解決済みの実行設定、実行する全コマンド、生成コミット、および実行バイナリのSHA-256を測定記録へ書き、生成は[来歴固定のworktree](../lessons/pin-generation-binary-to-worktree.md)から行う。

生成のシードは、予備生成を含めて、過去のすべての生成と測定が使ったシードの区間と重ならない値とする。
区間は、各生成の基本シードから、その生成の対局数だけ先までの範囲である（[教訓](../lessons/derive-seed-adjacent-collision.md)）。
今回の区間と過去の区間の非重複を、生成の前に一覧で確かめて記録する。

試験集合の規模は、局面を1つ以上記録した対局（以下、記録を含む対局）で12,000局とし、生成の結果を見て増やさない。
世代2の生成では、37,500局のうち記録を含む対局が36,632局（97.7%）で、残りは手数上限による破棄と記録を含まない終局だった。
そこで、本生成で試みる対局数は、予備生成で測った記録を含む対局の割合で12,000局を割って切り上げた数とし、本生成の前に固定する。
項目2から項目7には効果量の手がかりがないので、この数は項目1の部分群の結果から求めた仮定的な試算である。
原因調査では、射線のある中盤の露出局面での損失差（30特徴から24特徴を引いた値）は−3.63×10⁻⁴、95%区間は［−5.57×10⁻⁴, −1.69×10⁻⁴］であり、区間の半幅から標準誤差は約9.9×10⁻⁵となる。
この局面を含む対局は3,035局、検証集合の対局は3,676局だった。
7項目のHolm法では、最も厳しい段階の片側の有意水準が0.05/7≈0.0071となる。
真の効果が観測値の半分（−1.8×10⁻⁴）であっても、この水準で80%の検出力を得るには、標準誤差を1.8×10⁻⁴ ÷ (2.45 + 0.84) ≈ 5.5×10⁻⁵まで下げる必要がある。
2.45と0.84は、それぞれ片側の有意水準0.0071と検出力80%に当たる標準正規分布の分位点である。
標準誤差は対局数の平方根に反比例するとみなすと、部分群を含む対局が約9,900局要り、記録を含む対局のうち部分群を含む対局の割合（3,035/3,676≈83%）で割って約12,000局になる。
観測値の半分を置くのは、事後的に見つけた部分群の効果は過大に推定されやすいからである。
原因調査は旧い学習PSTの上で30特徴と24特徴を比べたが、本書は採用中の学習PSTの上で項目と追加係数0を比べるので、比較の対象と局面の分布が違い、この検出力は保証されない。

本生成の前に、試験集合と重ならないシードで100局の予備生成を行い、1局あたりの時間、記録を含む対局の割合、および項目1の部分群の局面と対局の割合だけを測る。
予備生成の対局は試験集合に入れず、損失も計算しない。

試験集合の各局面について、手番側の視点の対局結果（勝ち1、引き分け0.5、負け0）を目標とする。

## 選別

選別は、7項目のそれぞれについて、選別のための学習で作ったモデルを試験集合で1度だけ評価して行う。

基準のモデルは着手時の採用版、すなわち追加係数をすべて0としたモデルであり、項目iのモデルは、項目iの学習済みの係数を保存形式（1/8センチポーン刻み）へ丸めて持つモデルである。
丸めるのは、対局で使う重みと同じ値で評価するためである。
各局面の予測は、評価値を出力Kで割った値にシグモイド関数を適用した確率である。
局面ごとの損失差dを、項目iのモデルの二値交差エントロピーから基準の二値交差エントロピーを引いた値とし、負を改善とする。
同じ対局の局面は互いに相関するので、原因調査と同じく対局を単位として集計する。
対象局面を持つ対局の数をm、対局gの対象局面数をn_g、損失差の合計をd_gとすると、局面平均は `D = Σd_g / Σn_g`、標準誤差は `√(m Σ(d_g − D n_g)² / (m − 1)) / Σn_g` である。
この標準誤差は、対局ごとの損失差の合計を観測の単位とした比の推定量の分散から求めるもので、同じ対局の局面どうしの相関を含む。

各項目の検定の対象Sᵢを次のとおり定める。

| 項目 | 検定の対象Sᵢ | 理由 |
|---|---|---|
| 項目1 | 中盤であり、手番側の王駒がちょうど1枚で、手番側の射線の特徴3列のいずれかが正である局面。 | 原因調査で改善が見られた局面群（中盤の露出局面のうち射線のある局面）と同じ集合である。自分の王駒の危険を見落とすことが敗局の型なので、手番側に限る。 |
| 項目2から項目7 | 試験集合の全局面。 | 効果の現れる局面群を絞る手がかりがないので、全局面の損失差を検定の対象とする。項目iの列がすべて0の局面では損失差も0なので、全局面の平均は、項目iが発火する局面での平均を発火率で薄めた値になる。 |

項目iは、次の2条件をともに満たした場合に選別を通過する。

1. Sᵢでの損失差の片側検定が、Holm法（Holm–Bonferroni法）で補正した有意水準で改善を示すこと。検定統計量は `zᵢ = −D_Sᵢ / 標準誤差` とし、片側のp値を標準正規分布から求める。7つのp値を小さい順にp₍₁₎≤…≤p₍₇₎と並べ、k=1から順に、p₍ₖ₎が `0.05 / (7 − k + 1)` 以下である限りその項目を通過とし、初めて超えたところで止める。止まった項目とそれ以降の項目は、この条件を満たさない。
2. 試験集合の全局面での局面平均の損失差Dが0以下であること。項目1では、部分群での改善が他の局面の悪化で打ち消されている明白な場合を落とす。項目2から項目7では条件1が全局面を対象とするので、自動的に満たされる。

全局面の条件はDの符号だけを見て、統計的な非劣性の検定にはしない。
非劣性の検定には許容幅が要り、その値を導く根拠がないからである。
選別は採否測定へ進む候補の絞り込みであり、最終の判定は棋力の検定が行う。

条件の値、p値、Holm法での順位と水準、および各Sᵢの局面数と対局数は、合否にかかわらず測定記録 `evaluation-terms-relearning-gate` へ残す。
記録には、対局単位で平均した損失差、中盤と終盤の内訳、先読み教師に対する損失差、および項目ごとの平均寄与（センチポーン）も添えるが、これらは合否に使わない。
どの項目も通過しなければ、候補を作らずに完了する。

## 段ごとの候補と棋力の採否

選別を通過した項目を、必要な土台によって3つの段に分ける。
段0は、盤上の駒の配置だけで計算できる項目1である。
段1は、升ごとの利き数だけを読む項目2、項目3、項目6、項目7であり、利き数の表を土台とする。
段2は、駒ごとの到達升を要する項目4と項目5であり、利き数の表に加えて全駒の利き集合を土台とする。

各段の候補は、その時点の**最新の採用版**と比べる。
最新の採用版は、最初は着手時のmasterであり、段の候補を採用したときにだけその候補へ更新する。
段の候補を採用しなかった場合と、段を飛ばした場合は更新しない。
したがって、段0を採用して段1を採用しなかった場合、段2の候補は段0を含む版を基準とする。

段0、段1、段2の順に、通過した項目を含む段についてだけ、次の手順を行う。
通過した項目のない段は飛ばす。

1. その段の高速版を実装する。段0は土台を要しない。段1は利き数の表を、段2は利き数の表に加えて全駒の利き集合を、段階9の設計書の「土台」の節の設計で実装する。最新の採用版が利き数の表を含まない場合（段1を採用しなかった場合と飛ばした場合）、段2の候補は利き数の表も含み、その費用も負担する。
2. 高速版の特徴値が全計算と一致することを検証する。
3. 候補の学習で、その段で通過した項目の係数を同時に学ぶ。最新の採用版が持つ追加係数と学習PSTは固定する。
4. 候補は、最新の採用版へ、その段の土台、通過した項目の計算、特徴数の定数、および学習済みの重みを加えたコミットとする。
5. 新しい係数を0とした候補と最新の採用版の `bench` のNPSを、Pコアへ固定した `taskset` で交互に各5回測り、中央値の比rと、速度の損失の目安216×log2(1/r) Eloを記録する。この目安は、持ち時間を2倍にすると棋力が216 Elo上がった自己対局の測定（[sensitivity-time2x](../measurements/sensitivity-time2x.md)）から、NPSの比を持ち時間の比とみなし、棋力が持ち時間の対数に比例すると仮定して求める近似であり、段階9の設計書と同じである。
6. 候補を最新の採用版と[手引き](../guides/sprt.md)の段階ゲートで比べる。STCは `time=10000+100` で上限3,000ペア、LTCは `time=60000+200` とし、振分けと採用の規則は手引きに従う。採用するのは、LTCが `H1` であり、エンジン異常、時間切れ、および拒否着手が0件の場合だけである。STCを省略する理由はないので、STCから始める。

測定名は、段ごとに `evaluation-terms-relearning-tier<段>-stc` と `evaluation-terms-relearning-tier<段>-ltc` とし、それぞれ独立した測定記録に残す。
選別の記録 `evaluation-terms-relearning-gate` から、各段の測定記録へリンクする。
LTCのシードは、STCの基本シードからペア数以上離れた未使用の値とする。
各段の結論は「その段で選別を通過した項目をまとめて加えた効果」と表現し、同じ段の項目ごとの寄与は主張しない。

## 所要時間の見積もり

世代2の生成は14,057,872局面に約17.7時間を要した。
過去の検証の分割では1局あたり約338局面なので、12,000局は約406万局面となり、同じ速さなら約5時間である。
予備生成の実測で見積もりを改め、本生成の前に利用者へ示す。
段階9の118列の全計算の書き出しは11ファイルを並列に約1分で終え、項目1の学習は約13分だった。
選別のための7つの学習は、項目1と同程度なら合計で約1.5時間である。
各段の高速版の実装の所要時間と、STCとLTCの所要時間は、その段に着手する前に利用者へ示す。

## 実装フェーズ

### フェーズ1　全計算の書き出し

段階9の全7項目の全計算と書き出しを現行のモジュール配置へ移植し、項目1に射線の特徴6列を加えて124列とする。
項目1の評価側の接続と学習器の追加特徴の経路も、この時点で移植する。
完了条件は、「検証」の節の全計算に関する項目がすべて通り、移植の元のコミットが準備記録に残っていることである。

### フェーズ2　試験用の対局の生成

予備生成で時間と部分群の割合を測り、見積もりを利用者へ示してから12,000局を生成する。
完了条件は、試験集合のファイル、そのSHA-256、シードの区間と非重複の確認、実行設定、全コマンド、生成コミット、および実行バイナリのSHA-256が測定記録に残っていることである。
この時点では試験集合の特徴値も損失も計算しない。

### フェーズ3　選別のための学習

学習データの124列を書き出し、除外と端点の共有を決めてから、7項目のそれぞれを学習し、学習後の診断を通す。
完了条件は、7つのモデルの重み、学習曲線、除外と共有の判定、および学習後の診断が測定記録に残っていることである。
これ以降、選別のモデルの設定と重みを変えない。

### フェーズ4　選別

試験集合の124列を書き出し、7項目の選別を1度だけ行う。
完了条件は、「選別」の節が定める値がすべて測定記録 `evaluation-terms-relearning-gate` に残り、各項目の通過か不通過かが確定していることである。

### フェーズ5　段ごとの採否

通過した項目を含む段について、段0、段1、段2の順に「段ごとの候補と棋力の採否」の節の手順を行う。
各段の完了条件は、高速版の検証、候補の学習、速度の記録、および手引きの規則による採否が測定記録に残っていることである。

### フェーズ6　現行設計の更新

採用した段があれば、[評価関数の設計書](evaluation.md)の現行設計と、段階9の設計書の該当する項目の記述を改め、masterへ統合する。
採用しなかった段の実装はmasterへ入れず、ブランチに残す。
いずれの場合も、本書の状態と[ROADMAP](../ROADMAP.md)の状態表を更新する。

## 検証

全計算については、次を確かめる。

- 移植した全計算の項目1の元の24列と項目2から項目7の94列が、段階9の診断用に書き出した118列の特徴値ファイルと、世代0から世代2の11ファイルの全局面で一致する。
- 射線の特徴が、原因調査の診断コードの計算と、訓練の分割から固定シードで選んだ10,000局面で一致する。
- 手で数えた局面のテストが、各項目の規則の境界に当たる局面を含む。項目1では、王駒が2枚の側、盤端の筋、守る側の歩がある筋、攻める側の歩が走り駒と王駒の間にある筋、および走り駒でない駒が最初にある筋を含める。

学習と選別については、次を確かめる。

- 追加係数を0としたモデルが、診断の標本の全局面で採用版と同じ評価値を返す。
- 学習後のモデルで、学習PSTの部分が採用版と1ビットも変わらない。
- 学習の実行設定、準備の記録、およびログに、試験集合のファイル名と検査和が現れない。
- 選別の集計を、学習器とは別の配列計算で再計算し、各項目のD_Sᵢ、その標準誤差、p値、および全体の損失差が一致する（[教訓](../lessons/compare-diagnostics-with-independent-reference.md)）。

各段の候補については、次を確かめる。

- 高速版の特徴値が、全計算と、試験集合を除く標本の全局面、および `bench` の局面を深さ5で探索する検査用ビルドの全ノードで一致する。
- 追加係数へ固定シードの乱数で0以外の値を入れた検査用の重みで、探索中の差分更新による評価と、公開の全再計算による評価が、同じ検査用ビルドの全ノードで一致する。追加特徴が探索中の評価へ接続されていない不具合は、係数が0の検査では見つからないからである。
- 学習済みの係数による学習器の予測とRustの評価値が、試験集合を除く標本で一致する。

## 完了条件

次の2つがともに測定記録とともに確定した時点で完了とする。

- 7項目の選別の結果。
- 選別を通過した項目を含む各段について、候補の採用または不採用。

採用した段があれば、その実装と重みがmasterへ統合されていることも求める。
選別の記録からは、各段のSTCとLTCの測定記録へリンクしていることを求める。

# 補正1/4のFMの現行PSTへの再学習の設計書

## 先に読む要約

本書は、2026年9月に棋力の向上を示した評価関数の拡張「補正1/4のFM」を、現行の採用PSTの上で学び直し、masterへ採用できるかを確かめる。
FM（Factorization Machine）は、駒の種類と升ごとの点数を足すPST（piece-square table）に、2駒の位置関係の補正を加える評価項である。各特徴に長さ32のベクトルを持たせ、2駒の組の係数を、2つのベクトルの成分ごとの積に符号を持つ学習係数を掛けて足し合わせた値で表す（[設計書](factorization-machine.md)）。
当時のFMは、補正をそのまま使うと短時間条件STCで約−240 Eloだった。補正を1/4に縮めた版は、当時の採用PSTに対してSTCとLTCの両方で`H1`となったが、masterへは統合されなかった。
その補正は当時のPSTの誤りを埋めるように学習されている。その後PSTは6回学び直されていずれも採用され、最後の[エポック数の延長](pst-longer-training.md)では評価値の尺度も約14%大きくなったので、当時の重みを現行のmasterへ載せることはできない。
そこで、FMの実装を現行のmasterへ移植し、現行の採用PSTを固定したまま、FMの補正だけを学び直して、補正を1/4に縮めた1つの候補を作る。
学習の打ち切りと最良エポックの選択は、PSTの学習器と同じく、一般的な早期終了の定義に合わせる。
採否は、現行のmasterに対するSTCとLTCの標準の段階ゲートで決め、検証損失や探索速度は記録にとどめて採否には使わない。
完了条件は、候補の採否が測定記録とともに確定し、採用ならFMが評価関数の現行設計に反映されることである。

## 状態

起案。2026年10月3日に起案し、10月6日に、採用PSTの変更とPSTの学習器の早期終了の変更に合わせて改訂した。
実行の順序は、2026年10月4日の利用者決定のとおり、[共適応の検証](eval-search-coadaptation.md)の後とした。共適応の検証は10月5日に完了し、評価関数の採否の手順は変わらなかったので、本書は標準の段階ゲートで採否を測る。
未着手であり、利用者の判断を待つ点は「判断待ち」の節の2点である。

## 目的

ブランチ`fm-eval`で測った補正1/4のFMは、当時の採用PSTに対してSTCで得点率54.63%、LTCで53.40%となり、両方で`H1`だった（同ブランチの`docs/measurements/fm-quarter-vs-pst-stc.md`と`fm-quarter-vs-pst-ltc.md`）。
この結果はmasterへ統合されないまま、評価関数の計画はPSTの再学習の方向へ進み、PSTはその後の再学習で大きく強くなった。
PSTに加える2駒関係の補正が、強くなった現行のPSTの上でも上積みになるかは確かめられていない。
本書は、対局で向上を示した方式を現行のmasterで測り直し、採用できるかを確かめる。

## 適用範囲

本書の用語を次のように定める。

- **M**は、着手時のmasterの先頭のコミットである。
- **採用PST**は、Mの`crates/minase/nets/pst.bin`にあるPSTの重みである。本書の改訂時点では、[エポック数の延長](pst-longer-training.md)で採用した候補L（SHA-256 `b2d2cd1b…`）である。
- **FMの補正**は、[FMの設計書](factorization-machine.md)の評価式のうち、PSTの評価値に加える2駒関係の項である。
- **補正1/4**は、整数化したFMの重みの指数を1増やし、補正を0方向への切り捨てを伴って1/4にする変換である。整数のFMの補正は、整数の分子を2^(2e+1)で割って0方向へ切り捨てた値であり（eは重みファイルに保存した指数）、eを1増やすと除数が4倍になる。ブランチ`fm-eval`の`docs/plans/fm-quarter.md`が定めた変換と同じである。
- **F**は、Mに移植したFMの実装と、学び直して補正1/4を施した重みを持つ候補のコミットである。

対象は次のとおりである。

- FMの推論、整数化、差分更新、重み形式MNPTバージョン3の読み書き、および探索への接続を、`fm-eval`からMの`crates/minase/src/eval/pst/`の構成へ移植する。
- FMの学習器`train_fm.py`を、Mの学習ツールのパッケージ`tools/train/src/minase_train/`の構成へ移植する。学習の起動では、`lambda_override`の伝達、教師Kの推定と`--teacher-ks`への受け渡し、および推定値と教師分類の順の記録を行う。先読みつきの教師を選んだ場合は、教師Kの推定と、訓練と検証の教師値の生成のすべてで、同じ先読みの設定で変換した探索値を使う。
- Rustと学習器の評価値の一致を確かめる検査を移植する。

`fm-eval`にある診断用の道具（`fm_teacher_probe`、`match_positions`、FMの教師診断と強さの診断のスクリプト）は、本書の採否に使わないので移植しない。
採用PSTの重み、探索用駒価値、出力K、探索、および探索係数は変えない。

## 依存関係

FMの方式は[FMの設計書](factorization-machine.md)の「設計判断」に従い、本書はそのうち学習の入力、教師、および早期終了を現行の条件へ置き換える。
学習の入力と検証の分割は、採用PSTを学習した入力と同じく、世代2の5ファイル（`data/strength-stage7/gen2/generated-<seed>.bin`）と世代3の5ファイル（`data/gen3/generated-<seed>.bin`）とする（訓練27,745,843局面、検証1,462,975局面）。当時のFMは、世代0と世代1の6ファイル（訓練10,520,846局面）だけで学習した。
教師の比率の置き換えには、masterに統合済みの`train.lambda_override`を使う（[混合比λ=1.0の設計書](teacher-mixing-ratio.md)）。
早期終了は、[エポック数の延長](pst-longer-training.md)でPSTの学習器に入れた一般的な定義に合わせる。
採否の測定は[SPRTの手引き](../guides/sprt.md)の段階ゲートに従う。

作業は、Mから本書専用のブランチ`fm-quarter-current-pst`を作り、worktreeで行う。

## 設計判断

| 項目 | 決定 |
|---|---|
| 候補の作り方 | 採用PSTを固定し、FMの補正だけを学び直してから補正1/4を施す。当時の補正は当時のPSTが残した誤りを学んだものである。採用PSTはその後、鏡映共有、世代2の再学習、先読み教師での再学習、世代3の再学習（G23）、10エポックの追加学習（Pc）、および200エポックの追加学習（候補L）の6回学び直された。最後の候補Lだけでも、Pcから重みが序中盤と終盤の平均で約108と約250センチポーン動き、評価値の尺度が約14%大きくなった（[記録](../measurements/pst-longer-training-training.md)）。当時の補正が埋めていた誤りが現行のPSTに残っているとは限らない。 |
| 当時の重みの移植 | 採らない。当時のPSTと補正1/4のFMの組をそのまま載せる案は学習が不要で最も安いが、採用PSTを当時のPSTへ戻し、その後に段階ゲートで採用された6回の再学習を捨てることになる。最後の候補Lだけでも、直前のPcに対するLTCの得点率は73.5%であり（[記録](../measurements/pst-longer-training-ltc.md)）、補正1/4のFMの当時のPSTに対するLTCの53.40%を大きく上回るので、この組は現行のmasterより大きく弱い見込みである。当時の補正だけを採用PSTへ載せる案も、補正と土台のPSTの対応が崩れるので採らない。 |
| 学習の入力 | 採用PSTを学習した世代2と世代3の10ファイルとし、検証の分割も同じにする。補正は採用PSTの誤りを学ぶので、採用PSTと同じ局面の分布で学ぶのが直接である。当時の6ファイルは古い探索で付けた教師値であり、現行のPSTの学習に使っていない。 |
| 教師 | 先読みを使わない探索値だけの教師（λ=1.0）とし、当時のFMと同じにする。対局結果を混ぜない理由は、当時の学習でλ=0.75の教師ではFMが過学習したことにある。対局結果の成分は同じ対局のすべての局面で一定であり、FMは動かない駒の組から対局を識別してその成分を記憶できる（[FMの設計書](factorization-machine.md)）。先読みを使わない理由は2つある。第1に、FMの補正で棋力の向上を示したのはこの教師だけである。第2に、先読みつきのλ=1.0の教師で学び直したPSTは、2回（当時の採用PSTからとG23から）とも約−150〜−164 Eloと大きく負け、互角に近い局面の評価の並びを大きく入れ替えていた（[分布の比較](../measurements/eval-coadaptation-distribution.md)）。これはPSTの混合比を変えた結果であり、FMの教師としての先読みの有無を直接比べたものではないので、間接的な参考にとどまる。一方、採用PSTは先読みつきのλ=0.75で学習されているので、先読みのない教師で学ぶ補正は、採用PSTが先読みで得た変化の一部を打ち消す向きに働き得る。補正を1/4に縮めることでこの影響は小さくなるが、除けない交絡として残る。この選択は「判断待ち」の節で利用者に確認する。 |
| 教師K | 選んだ教師（先読みの有無と混合比）の世代ごとの値を、PSTの学習ツールが学習の起動時に使う推定の仕組みで、訓練集合だけから推定する。当時の`train_fm.py`は教師Kを引数`--teacher-ks`で受け取り、自身では推定しないので、移植では推定した値と教師分類の順を記録に保存してから`--teacher-ks`へ渡す。先読みを使わない教師では、世代2の値は約777.6と見込まれる（[先読み教師での再学習の記録](../measurements/lookahead-teacher-pst-training.md)）。 |
| 学習条件 | 当時の候補と同じく、潜在次元32、補正の正則化係数λres=10⁻⁴、AdamW、学習率10⁻³、重み減衰10⁻⁴、バッチ4,096、乱数シード1とする。未観測の特徴の埋め込みを0に固定する処理と、PSTと厳密に一致する初期化（補正0から始める）も当時の設計に従う。結果を見て条件を変えた再学習はしない。 |
| 早期終了 | PSTの学習器と同じく、一般的な早期終了の定義（Goodfellow, Bengio, Courville, *Deep Learning*, 7.8節のアルゴリズム7.1、およびKerasの`EarlyStopping`で`min_delta=0`、`restore_best_weights=True`とした場合）に合わせる。各エポックの後に検証損失を測り、最良値を厳密に下回れば最良の重みを更新し、最後に最良を更新したエポックから待つエポック数だけ続けて更新がなければ止め、学習したエポックの中で最良の重みを返す。当時の学習器は、PSTの旧学習器と同じく学習前の状態（補正0）をエポック0として最良の候補に含めていたので、これを改め、エポック0の検証損失は記録だけにする。待つエポック数は当時と同じ3とする。上限エポック数は「判断待ち」の節で利用者に確認する。 |
| 学習が補正を学べない場合 | 学習したエポックの最良の検証損失がエポック0（補正0、すなわち採用PSTと同じ評価）を下回らなくても、それだけでは見送らない。「代理指標の扱い」の方針のとおり、検証損失だけで候補を見送らず、正しさの検査を通過した候補は対局で測る。エポック0との比較は記録に残す。ただし、整数化した補正1/4がすべての特徴の組で0になり、候補の評価がMと同じになる場合は、対局で測る意味がないので見送りとして記録する。 |
| 補正の縮小率 | 1/4に固定する。対局で向上を示した縮小率は1/4だけである。縮小率を複数作ってSTCで選ぶ案は、測定が縮小率の数だけ増え、教師と入力が当時と異なる以上どの値も根拠が同程度なので採らない。補正をそのまま使う版も、当時約−240 Eloだったので測らない。 |
| 代理指標の扱い | 検証損失の改善幅と探索速度は記録するが、採否の条件にしない。利用者の方針（代理指標だけで候補を見送らず、対局で測る）に従う。探索速度は、合法手生成の高速化で評価関数以外の処理が当時より速くなっているので、当時の約1.2%より大きな割合になり得る。その費用は対局の結果に含まれる。 |
| 実装の正しさの検査 | 量子化の前後の平均絶対誤差が2センチポーン以下であること、Rustと学習器の評価値が一致すること、採用PSTの部分と探索用駒価値と出力Kが変わらないこと、および補正1/4が整数の関係として成り立つことを、測定の前に確かめる。いずれかを満たさない場合は測定へ進まず、原因を直してから同じ条件で学び直す。 |
| 測定機の共用 | 測定機は他の作業と共用するので、各対局の開始前に`minase match run`と`match_runner`の実行ファイルが他に動いていないことを、実行ファイル名で確かめる。対局の途中に他の作業の対局が重なった場合は、重なった時間帯と同時対局数を測定記録に残す。runnerはMでビルドした`minase`を専用の場所へ複製して固定する。 |
| 採否 | FをMに対して標準のSTCとLTCで測り、LTCで`H1`かつエンジン異常、時間切れ、拒否着手が0件の場合だけ採用する。 |

対局は当時のSTC（567ペアで約72分）とLTC（808ペアで約5時間16分）の実績を根拠とする。

## 判断待ち

着手の前に、利用者に次の2点を決めてもらう。

1. FMの補正の教師を、先読みを使わないλ=1.0（当時のFMと同じ）とするか、先読みつきのλ=1.0とするか。先読みつきにすれば、採用PSTの教師との先読みの有無の違いはなくなるが、混合比の違い（採用PSTはλ=0.75、FMはλ=1.0）は残る。また、先読みつきのλ=1.0の教師で学び直したPSTは2回とも約150 Elo以上負けたが、これは混合比を変えたPSTの結果であり、FMの教師として先読みの有無のどちらが良いかを直接示すものではない。その教師は後続局面の値の平均が対局ごとに相関する成分を含むので、対局結果と同じ機構でFMが過学習するおそれもある（この機構は確かめられていない）。本書は、FMで向上を示した唯一の教師である先読みなしを推す。
2. 上限エポック数を、当時と同じ20とするか、PSTのエポック数の延長と同じく200とするか。当時の潜在次元32の候補は、上限の20エポックまで検証損失が下がり続けていた（`fm-eval`の`docs/measurements/fm-phase1-training.md`）。PSTでは学習を延ばすと大きく強くなったので、FMでも延ばす価値はある。一方、当時のFMは補正が大きすぎて負け、1/4に縮めて初めて勝ったので、長く学習して補正が大きくなると、1/4では縮め足りなくなるおそれがある。また今回の入力は当時の約2.6倍なので、上限20エポックでも更新回数は当時の約2.6倍になる。本書は、向上を示した条件に近い20を推し、延ばす案は本書の結果を見てから別に扱う。

## 実装フェーズ

### フェーズ1　移植

FMの実装を`fm-eval`からMへ移植する。
移植元は`fm-eval`の先頭のコミットであり、Mでは評価関数が`crates/minase/src/eval/pst/`の下へ分割され、学習データの形式が`crates/minase/src/training/`へ、学習ツールが`tools/train/src/minase_train/`へ移されているので、その構成へ合わせる。
MNPTバージョン3はバージョン2のPSTに埋め込みの表を加えた形式であり、Mの重み形式の読み書き、Python側の読み書き、および検査をバージョン3へ改める。
FMの学習器の早期終了は、PSTの学習器の`should_replace_best_epoch`と`should_stop_early`を共有して、「早期終了」の節の定義に合わせる。
`fm-eval`のFMの単体テストと、Rustと学習器の評価値を照合するテストを移植する。
埋め込みをすべて0にしたFMを読み込んだMのビルドが、Mと同じ`bench`のノード数と評価値を返すことを確かめる。
完了条件は、`cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習ツールの単体テストの通過と、移植のコミットである。

### フェーズ2　学習と候補の作成

学習の入力、分割、教師、教師K、学習条件、および上限エポック数を学習の記録へ固定し、FMの補正を学習する。
最良エポックの重みを整数化し、補正1/4を施して`crates/minase/nets/pst.bin`へ書き込み、Fをコミットする。
「実装の正しさの検査」の各項目を確かめ、`bench`の探索速度をMと比べて記録する。
benchは、[段階9](strength-stage9.md)と同じくtasksetでPコアに固定して測る。
結果は測定記録`fm-quarter-current-pst-training`に残し、エポックごとの検証損失、最良エポック、止まったエポック、補正の大きさ（補正1/4の前後の標準偏差）を含める。
完了条件は、検査の通過とFのコミット、または補正がすべて0になった場合の見送りの記録である。

### フェーズ3　採否測定

「測定機の共用」の節の確認を行ってから、FをMに対してSTCで測り、振り分け規則に従ってLTCへ進める。

```console
<固定したminase> match run \
  --run-dir data/matches/fm-quarter-current-pst-stc --seed 11000000 \
  --candidate commit:<F> --baseline commit:<M> \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

LTCは測定名`fm-quarter-current-pst-ltc`、基本シード12000000、`time=60000+200`とし、`--max-pairs`を付けない。
採否を記録し、採用なら評価関数の現行設計を改める。

## 検証

- FとMの差が、FMの実装と`crates/minase/nets/pst.bin`の差し替え、および重みに依存するテストだけであることを確かめる。
- Fの`crates/minase/nets/pst.bin`のPSTの部分、探索用駒価値、および出力Kが、Mの`crates/minase/nets/pst.bin`とバイト単位で一致することを確かめる。
- 採否の測定は[SPRTの手引き](../guides/sprt.md)の標準コマンドに従い、エンジン異常、時間切れ、および拒否着手が0件であることを採用の条件にする。段階ゲートで開始する最初の測定で1件でも出た場合は、測定を止めて原因を調べる。

## 完了条件

- 学習の記録、実装の正しさの検査、探索速度、および採否または見送りが測定記録に残っている。
- 採用した場合は、[評価関数](evaluation.md)の現行設計と[PSTの学習手順](../guides/pst-training.md)にFMの補正と学習の手順が反映され、[FMの設計書](factorization-machine.md)の状態から本書へリンクされている。
- 不採用または見送りの場合は、移植したコードをmasterへ統合せず、結論と測定記録だけをmasterへ残す。
- ROADMAPの状態表が本書の結論と一致している。

# 補正1/4のFMの現行PSTへの再学習の設計書

## 先に読む要約

本書は、2026年9月に棋力の向上を示した唯一の評価関数の拡張である「補正1/4のFM」を、現行の採用PSTの上で学び直し、masterへ採用できるかを確かめる。
FM（Factorization Machine）は、駒の種類と升ごとの点数を足すPST（piece-square table）に、2駒の位置関係の補正を加える評価項であり、各特徴に長さ32のベクトルを持たせ、2駒の組の係数をベクトルの内積で表す（[設計書](factorization-machine.md)）。
当時のFMは補正をそのまま使うと短時間条件STCで約−240 Eloだったが、補正を1/4に縮めた版は当時の採用PSTに対してSTCとLTCの両方で`H1`となった。
ただしその補正は当時のPSTの誤りを埋めるように学習されている。その後PSTは、左右対称な升の重みを共有する鏡映共有、新しい自己対局の局面を加えた世代2の再学習、および[先読み教師](lookahead-teacher.md)での再学習の3回学び直され、いずれも段階ゲートで採用されたので、当時の重みをそのまま現行のmasterへ載せることはできない。
そこで、FMの実装を現行のmasterへ移植し、現行の採用PSTを固定したまま、当時と同じ学習条件でFMの補正だけを学び直し、補正を1/4に縮めた1つの候補を作る。
採否は、現行のmasterに対するSTCとLTCの標準の段階ゲートで決め、検証損失や探索速度は記録にとどめて採否には使わない。
完了条件は、候補の採否が測定記録とともに確定し、採用ならFMが評価関数の現行設計に反映されることである。

## 状態

起案。2026年10月3日に起案した。
実行の順序は、2026年10月4日に利用者が決定し、[共適応の検証](eval-search-coadaptation.md)の完了後に着手する。共適応の検証は2026年10月5日に完了し、評価関数の採否の手順は変わらなかったので、本書は標準の段階ゲートで採否を測る。
未着手であり、利用者の判断を待つ点は「判断待ち」の節の1点である。

## 目的

評価関数に採用された変更は、9月23日の先読み教師での再学習が最後である。
その間に試した候補は、いずれも教師データへの当てはまりを改善したが、対局では負けた。
一方、ブランチ`fm-eval`で測った補正1/4のFMは、当時の採用PSTに対してSTCで得点率54.63%、LTCで53.40%となり、両方で`H1`だった（同ブランチの`docs/measurements/fm-quarter-vs-pst-stc.md`と`fm-quarter-vs-pst-ltc.md`）。
この結果はmasterへ統合されないまま、評価関数の計画はPSTの再学習の方向へ進んだ。
本書は、対局で向上を示した方式を現行のmasterで測り直し、採用できるかを確かめる。

## 適用範囲

本書の用語を次のように定める。

- **M**は、着手時のmasterの先頭のコミットである。
- **採用PST**は、Mの`crates/minase/nets/pst.bin`にあるPSTの重みである。
- **FMの補正**は、[FMの設計書](factorization-machine.md)の評価式のうち、PSTの評価値に加える2駒関係の項である。
- **補正1/4**は、整数化したFMの重みの指数を1増やし、補正を0方向への切り捨てを伴って1/4にする変換である。整数のFMの補正は、整数の分子を2^(2e+1)で割って0方向へ切り捨てた値であり（eは重みファイルに保存した指数）、eを1増やすと除数が4倍になる。ブランチ`fm-eval`の`docs/plans/fm-quarter.md`が定めた変換と同じである。
- **F**は、Mに移植したFMの実装と、学び直して補正1/4を施した重みを持つ候補のコミットである。

対象は次のとおりである。

- FMの推論、整数化、差分更新、重み形式MNPTバージョン3の読み書き、および探索への接続を、`fm-eval`からMの`crates/minase/src/eval/pst/`の構成へ移植する。
- FMの学習器`train_fm.py`と、その学習に必要な範囲の学習手順を`tools/train/pst/`へ移植する。
- Rustと学習器の評価値の一致を確かめる検査を移植する。

`fm-eval`にある診断用の道具（`fm_teacher_probe`、`match_positions`、FMの教師診断と強さの診断のスクリプト）は、本書の採否に使わないので移植しない。
採用PSTの重み、探索用駒価値、出力K、探索、および探索係数は変えない。

## 依存関係

FMの方式は[FMの設計書](factorization-machine.md)の「設計判断」に従い、本書はそのうち学習の入力と教師だけを現行の条件へ置き換える。
学習の入力と検証の分割は、採用PSTを作った[先読み教師での再学習](../measurements/lookahead-teacher-pst-training.md)の11ファイル（25,120,683局面）と同じものを使う。当時のFMは、そのうち古い6ファイル（11,062,811局面）だけで学習した。
教師の比率の置き換えには、masterに統合済みの`train.lambda_override`を使う（[混合比λ=1.0の設計書](teacher-mixing-ratio.md)）。
採否の測定は[SPRTの手引き](../guides/sprt.md)の段階ゲートに従う。

作業は、Mから本書専用のブランチ`fm-quarter-current-pst`を作り、worktreeで行う。
本書は、測定機を共有する[評価関数の候補と探索係数の共適応の検証](eval-search-coadaptation.md)の完了後に着手する（2026年10月4日の利用者決定）。
共適応の検証の結論を受けて利用者が評価関数の採否の手順を改めた場合、本書の着手前であれば着手時の手順に従い、着手後であれば手順を変えない。

## 設計判断

| 項目 | 決定 |
|---|---|
| 候補の作り方 | 採用PSTを固定し、FMの補正だけを学び直してから補正1/4を施す。当時の補正は当時のPSTが残した誤りを学んだものであり、採用PSTはその後に3回学び直され、最後の先読み教師での再学習だけでも序中盤と終盤の平均絶対値にして約10と約20センチポーン動いているので、当時の補正が埋めていた誤りが現行のPSTに残っているとは限らないからである。 |
| 当時の重みの移植 | 採らない。当時のPSTと補正1/4のFMの組をそのまま載せる案は学習が不要で最も安いが、採用PSTを当時のPSTへ戻し、その後に段階ゲートで採用された3回の再学習を捨てることになる。3回のうち先読み教師での再学習の1回だけでも、直前のPSTに対するSTCの得点率は57.5%であり（[記録](../measurements/lookahead-teacher-pst-stc.md)）、補正1/4のFMの当時のPSTに対するSTCの54.63%を上回るので、この組は現行のmasterより弱い見込みが大きい。当時の補正だけを採用PSTへ載せる案も、補正と土台のPSTの対応が崩れるので採らない。 |
| 教師 | 先読みを使わない探索値だけの教師（λ=1.0）とし、当時のFMと同じにする。対局結果を混ぜない理由は、当時の学習でλ=0.75の教師ではFMが過学習したことにある。対局結果の成分は同じ対局のすべての局面で一定であり、FMは動かない駒の組から対局を識別してその成分を記憶できる（[FMの設計書](factorization-machine.md)）。先読みを使わない理由は2つある。第1に、FMの補正で棋力の向上を示したのはこの教師だけである。第2に、先読みつきのλ=1.0の教師は、PSTの教師としては約−164 Eloとなった教師そのものである（[記録](../measurements/teacher-mixing-ratio-100-stc.md)）。一方、採用PSTは先読みつきのλ=0.75で学習されているので、先読みのない教師で学ぶ補正は、採用PSTが先読みで得た変化の一部を打ち消す向きに働き得る。補正を1/4に縮めることでこの影響は小さくなるが、除けない交絡として残る。この選択は「判断待ち」の節で利用者に確認する。 |
| 教師K | 先読みを使わない教師の世代ごとの値（804.0、1,099.7、777.6）を使う。採用PSTの学習記録が、先読み教師の値（768.5、1,068.2、758.4）と並べて記している値である。 |
| 学習条件 | 当時の候補と同じく、潜在次元32、補正の正則化係数λres=10⁻⁴、AdamW、学習率10⁻³、重み減衰10⁻⁴、バッチ4,096、最大20エポック、検証損失が3エポック改善しなければ停止、乱数シード1とする。未観測の特徴の埋め込みを0に固定する処理と、PSTと厳密に一致する初期化も当時の設計に従う。結果を見て条件を変えた再学習はしない。 |
| 補正の縮小率 | 1/4に固定する。対局で向上を示した縮小率は1/4だけである。縮小率を複数作ってSTCで選ぶ案は、測定が縮小率の数だけ増え、教師と入力が当時と異なる以上どの値も根拠が同程度なので採らない。補正をそのまま使う版も、当時約−240 Eloだったので測らない。 |
| 学習が補正を学べない場合 | 最良エポックが0の場合（検証損失が初期状態から下がらない場合）は、候補が採用PSTと同じ評価になるので、測定せずに見送りとして記録する。 |
| 代理指標の扱い | 検証損失の改善幅と探索速度は記録するが、採否の条件にしない。利用者の方針（代理指標だけで候補を見送らず、対局で測る）に従う。探索速度は、合法手生成の高速化で評価関数以外の処理が当時より速くなっているので、当時の約1.2%より大きな割合になり得る。その費用は対局の結果に含まれる。 |
| 実装の正しさの検査 | 量子化の前後の平均絶対誤差が2センチポーン以下であること、Rustと学習器の評価値が一致すること、採用PSTの部分と探索用駒価値と出力Kが変わらないこと、および補正1/4が整数の関係として成り立つことを、測定の前に確かめる。いずれかを満たさない場合は測定へ進まず、原因を直してから同じ条件で学び直す。 |
| 採否 | FをMに対して標準のSTCとLTCで測り、LTCで`H1`かつエンジン異常、時間切れ、拒否着手が0件の場合だけ採用する。 |

## 所要時間の見積り

時間は同時対局数16の測定機での見積りである。
学習は当時の11,062,811局面で3エポック約4分の実績を、局面数が約2.3倍の今回の入力で最大20エポックへ伸ばして見積もる。対局は当時のSTC（567ペアで約72分）とLTC（808ペアで約5時間16分）の実績を根拠とする。

| 段 | 内容 | 見積り |
|---|---|---|
| 準備 | FMの実装と学習器の移植、検査 | codexへの委任で数時間 |
| 1 | FMの補正の学習と補正1/4の変換 | 約1〜1.5時間 |
| 2 | FとMのSTC | 約1〜8時間 |
| 3 | FとMのLTC | 約5〜30時間 |

STCで終われば測定機の時間は約2〜9時間、LTCまで進めば約7〜39時間である。

## 判断待ち

着手の前に、FMの補正の教師を、先読みを使わないλ=1.0（当時のFMと同じ）とするか、先読みつきのλ=1.0とするかを、利用者に決めてもらう。先読みつきにすれば採用PSTの教師と同じ系統になり、補正が採用PSTの変化を打ち消す交絡はなくなる。しかしその教師はPSTの教師としては約−164 Eloであり、後続局面の値の平均が対局ごとに相関する成分を含むので、対局結果と同じ機構でFMが過学習するおそれもある（この機構は確かめられていない）。本書は、FMで向上を示した唯一の教師である先読みなしを推す。

## 実装フェーズ

### フェーズ1　移植

FMの実装を`fm-eval`からMへ移植する。
移植元は`fm-eval`の先頭のコミットであり、Mでは評価関数が`crates/minase/src/eval/pst/`の下へ分割され、学習データの形式が`crates/minase/src/training/`へ移されているので、その構成へ合わせる。
MNPTバージョン3はバージョン2のPSTに埋め込みの表を加えた形式であり、Mの重み形式の読み書き、Python側の読み書き、および検査をバージョン3へ改める。
`fm-eval`のFMの単体テストと、Rustと学習器の評価値を照合するテストを移植する。
埋め込みをすべて0にしたFMを読み込んだMのビルドが、Mと同じ`bench`のノード数と評価値を返すことを確かめる。
完了条件は、`cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習器の単体テストの通過と、移植のコミットである。

### フェーズ2　学習と候補の作成

学習の入力、分割、教師、学習条件を準備の記録へ固定し、FMの補正を学習する。
最良エポックの重みを整数化し、補正1/4を施して`crates/minase/nets/pst.bin`へ書き込み、Fをコミットする。
「実装の正しさの検査」の各項目を確かめ、`bench`の探索速度をMと比べて記録する。
benchは、[段階9](strength-stage9.md)と同じくtasksetでPコアに固定して測る。
結果は測定記録`fm-quarter-current-pst-training`に残す。
完了条件は、検査の通過とFのコミット、または最良エポックが0の場合の見送りの記録である。

### フェーズ3　採否測定

FをMに対してSTCで測り、振り分け規則に従ってLTCへ進める。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/fm-quarter-current-pst-stc --seed 11000000 \
  --candidate commit:<F> --baseline commit:<M> \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

LTCは測定名`fm-quarter-current-pst-ltc`、基本シード12000000、`time=60000+200`とする。
採否を記録し、採用なら評価関数の現行設計を改める。

## 検証

- FとMの差が、FMの実装と`crates/minase/nets/pst.bin`の差し替えだけであることを確かめる。
- Fの`crates/minase/nets/pst.bin`のPSTの部分、探索用駒価値、および出力Kが、Mの`crates/minase/nets/pst.bin`とバイト単位で一致することを確かめる。
- 採否の測定は[SPRTの手引き](../guides/sprt.md)の標準コマンドに従い、エンジン異常、時間切れ、および拒否着手が0件であることを採用の条件にする。段階ゲートで開始する最初の測定で1件でも出た場合は、測定を止めて原因を調べる。

## 完了条件

- 学習の記録、実装の正しさの検査、探索速度、および採否または見送りが測定記録に残っている。
- 採用した場合は、[評価関数](evaluation.md)の現行設計と[PSTの学習手順](../guides/pst-training.md)にFMの補正と学習の手順が反映され、[FMの設計書](factorization-machine.md)の状態から本書へリンクされている。
- 不採用または見送りの場合は、移植したコードをmasterへ統合せず、結論と測定記録だけをmasterへ残す。
- ROADMAPの状態表が本書の結論と一致している。

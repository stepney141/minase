# FMの補正の倍率をSPSAで調整する設計書

## 先に読む要約

本書は、[PSTとFMの同時学習](pst-fm-joint-training.md)で作った候補J75の評価関数について、FMの補正に掛ける倍率bを自己対局の勝敗から決め、現行のmasterより強くなるかを確かめる。
評価関数は、駒の種類と升ごとの点数を足すPST（piece-square table）と、2駒の位置関係から評価を補うFM（Factorization Machine）の補正の和であり、本書はこれを、PSTの係数aを1に固定したa·PST＋b·FMとみなす。
J75は補正を縮めずに使ったので、自己対局の短時間条件でmasterに約8 Elo負け、採用しなかった。
同時学習の出発点（補正を縮めない評価）がmasterに約67 Elo負けたことから、補正の過大を不採用の有力な原因と考える（[出発点の測定](../measurements/pst-fm-joint-training-e0-stc.md)）。
倍率bは、FMの重みと同じ学習の損失では決められないので、自己対局の勝敗から係数を調整するSPSA（simultaneous perturbation stochastic approximation、同時摂動確率近似）で決める。
J75のPSTとFMの重みは固定し、bだけを0から1の範囲で調整する（2026年10月8日の利用者の決定）。
決まったbはFMの重みの整数化に焼き込み、エンジンの評価式は変えない。
採否は、焼き込んだ候補とmasterの自己対局による段階ゲート（[SPRTの手引き](../guides/sprt.md)）で決める。
完了条件は、bの調整結果と候補の採否が測定記録とともに確定することである。

## 目的

同時学習の2候補と出発点は、masterに対して次の強さだった。
Eloは対局の勝率から換算した強さの差であり、負の値はmasterより弱いことを表す。
括弧内は95%信頼区間である。

| 対masterの測定 | 補正の大きさ | Elo |
|---|---:|---|
| 出発点（現行のPSTと、縮小前の現行のFM） | 273 cp | −67（−98〜−38） |
| J100（教師の混合比λ=1.0で同時学習） | 253 cp | −46（−72〜−21） |
| J75（教師の混合比λ=0.75で同時学習） | 282 cp | −8（−21〜+5） |

3つは別々の開始局面で測った間接比較であるが、J75は出発点より約59 Elo（−67から−8への差）強く、縮めない補正のままでもmasterとほぼ互角である。
J75の補正の大きさを対局に合わせて縮めれば、masterを上回る見込みがある。
本書は、J75の重みを変えずに倍率bだけを対局で決め、その候補がmasterより強いかを確かめる。

倍率を対局で決めるのは、学習の損失がこの判断に使えないからである。
現行のPST（候補L）に、縮小前の現行のFM（候補Fa）の補正をs倍して足した評価の検証損失（検証用に分けた146万局面での二値交差エントロピー）は、s=1/4で0.431323、s=1で0.430257であり、損失はs=1を好む（[同時学習の学習記録](../measurements/pst-fm-joint-training-training.md)の倍率の走査）。
一方、対局ではs=1の出発点が、s=1/4のmasterより約67 Elo弱かった。
J75についても、比較した3点（FMを1/4、1/2、1倍）の検証損失は0.430391、0.429845、0.429552であり、1倍が最良だった。
同じ損失で倍率を選ぶと、対局で強い倍率にならない見込みが高い。
その原因は確定していないが、教師に使った実戦の局面では当たる補正が、探索中に評価する別の種類の局面では誤差になるという仮説が有力である（[同時学習の設計書](pst-fm-joint-training.md)の状態と測定記録）。

## 適用範囲

本書の用語と記号を次のように定める。

- **master**は、着手時のmasterの先頭のコミットである。起案時点では、その評価関数は、[エポック数の延長](pst-longer-training.md)で採用したPST（候補L）と、[FMの再学習](fm-quarter-current-pst.md)で採用したFM（候補Fa）の補正を1/4に縮めたものからなる。本書では、この2つをLとFaと呼ぶ。
- **J75**は、[同時学習](pst-fm-joint-training.md)の候補J75の重み（`data/pst-fm-joint-training/j75/pst.bin`と、整数化前の重み`pst-float.npz`）である。
- **cp**（センチポーン）は評価値の単位であり、歩兵1枚の価値を100 cpとする。
- **補正の大きさ**は、検証集合から乱数シード1で選んだ1万局面での、整数化したFMの補正の標準偏差（cp）である。[同時学習の設計書](pst-fm-joint-training.md)と同じ測り方である。
- **倍率b**は、FMの補正に掛ける0以上1以下の実数である。エンジンの係数の表は整数しか扱わないので、bを1024倍した整数`FmScale`（0から1024）で表す。刻みは1/1024（約0.1%）である。
- **MNPT**は、PSTとFMの重みを保存するminaseの重みファイル形式であり、バージョン2はPSTだけ、バージョン3はPSTとFMを含む。どちらも、探索の枝刈りに使う駒の価値（探索用駒価値）と、評価値を勝率へ換算する尺度（出力K）を持つ。
- **焼き込み**は、整数化前（浮動小数点）のFMの出力係数をb倍してから既存の整数化（`tools/train/src/minase_train/fm/train.py`の`quantize`）を行い、重みファイルを作り直すことをいう。b>0ならMNPTバージョン3、b=0ならFMを含まないバージョン2を出力し、PSTの部分は変えない。
- **STC**と**LTC**は、それぞれ10秒＋1手0.1秒と60秒＋1手0.2秒の持ち時間で行う自己対局の採否測定であり、勝敗から強さの差を逐次判定する（[SPRTの手引き](../guides/sprt.md)）。
- **調整用ビルド**、**θ**（調整中の係数の現在値）、**反復**などSPSAの用語は、[SPSAによる係数調整の手引き](../guides/spsa.md)に従う。

対象は次のとおりである。

- 調整用ビルドでだけFMの補正にbを掛ける係数`FmScale`を、探索係数の表へ加える。
- J75の重みを固定し、`FmScale`だけをSPSAで調整する。
- 得られたbを焼き込んだ候補を作り、masterとの段階ゲートで採否を決める。

次の事項は対象外とする。

- PSTとFMの重みの再学習は行わない。FMの補正はFMの出力係数に比例するので、bを決めた後に同じ損失で学び直すと、出力係数が1/b倍に戻って縮小を打ち消し得るからである。
- 探索係数の再調整は行わない。bと探索係数を同時に調整すると、bの効果を分けられない。
- 通常ビルドの評価式は変えない。採用する候補では、bは重みファイルの値として表れる。

## 設計判断

| 項目 | 決定 |
|---|---|
| 倍率の決め方 | 自己対局の勝敗からSPSAで決める（2026年10月8日の利用者の決定）。目的とする量が対局の強さそのものであり、既存のSPSAの基盤と運用の実績を使える。学習の損失で決める案は、「目的」の節のとおり大きな倍率を選ぶ見込みが高いので採らない。探索中の局面で損失を測って選ぶ案は、局面の採取と教師の再生成の実装が必要で、選んだ倍率と強さの対応も別に確かめる必要があるので、本書では採らない。 |
| 倍率の範囲 | 0以上1以下とする。利用者はPSTの係数を1に固定し、FMの補正だけを縮める形（a=1>b）を示した。本書は、縮小が不要という結果も許すために上端のb=1（J75そのもの）を範囲に含める。 |
| 調整の土台 | J75の重みとする（2026年10月8日の利用者の決定）。J75は縮めない補正のままでmasterとほぼ互角であり、3つの候補の中で最も強い。出発点（LのPSTと縮小前のFa）を土台にする案は、b=1/4がmasterそのものになり、得られる改善が「1/4が最適でなかった分」に限られるので採らない。J75のPSTは縮めない補正と組んで学ばれたので、縮めるとPSTとFMの役割分担が崩れ得るが、その影響も対局の勝敗に含めて測る。 |
| 開始値 | 範囲の中点の0.5（`FmScale`=512）とする。SPSAは開始値の両側へ係数をずらした2つの設定を対局させるが、上端の1から始めると上側へずらした設定が範囲の端で切り詰められ、両側の比較が成り立たない。masterの1/4から始める案は、対局で選んだわけではない縮小率を開始値として持ち込むので採らない。開始値は人が選んだ条件であり、有限の反復数では結果に影響し得るので、θの推移を記録する。 |
| SPSAの設定 | 既定の設定を流用する。摂動幅の終了値`c_end`は範囲の1/6（1024/6≈170.67）、学習率の終了値`r_end`は0.002、指数α=0.602とγ=0.101、安定化定数A=反復数の0.1倍であり、[利得の較正](spsa-gain-calibration.md)で選んだ値である。反復は375回、1反復8ペア（計3,000ペア）、持ち時間はSTCと同じ、同時対局数16とする。これは過去の2回のセッションと同じ規模である。bの単位では、2つの設定のずれ幅は開始時に約±0.30、終了時に約±0.17となる。この設定がFMの倍率に適するかは確かめていない。3,000ペアは最適な倍率を精密に求める量ではなく、候補を1つ作るための予算である。 |
| 調整用ビルドでの倍率の掛け方 | FMの補正を計算する唯一の関数`Fm::correction`（`crates/minase/src/eval/pst/fm.rs`）で、2駒の組の寄与を整数で足し合わせた分子Nと、既存の分母D=2^(2e+1)（eは重みファイルの指数）に対して、補正をtrunc(N·FmScale/(1024·D))とする。truncは0方向への切り捨てである。指数の上限30では分母が`i64`に収まらないので、この計算は`i128`で行う。探索、診断用のプローブ、およびUSIの評価表示がすべてこの関数を通るので、調整中の評価はどの経路でも一致する。 |
| 通常ビルドの扱い | 通常ビルドでは、`Fm::correction`の既存の式を条件付きコンパイルでそのまま残し、乗算を含めない。係数の既定値は1024とし、調整用ビルドの既定の評価も通常ビルドと一致させる。開始値の0.5はパラメーターファイルで指定する。 |
| 係数を表に残すか | 残す。FMやPSTを学び直すたびに倍率も決め直す必要があるので、将来用ではなく、重みを更新する手順の一部である。通常ビルドでは評価に作用しない。 |
| 採用時の倍率の表し方 | 焼き込みで重みファイルへ入れる。SPSAの通常の採用手順（`minase spsa apply`で表の既定値を書き換える）に従うと、通常ビルドの評価式に乗算が加わり、学習ツールと診断器の整数の参照評価もbを知る必要が生じる。焼き込みなら評価式は変わらず、重みファイルだけで評価が決まる。焼き込んだ補正は、調整中の補正trunc(N·FmScale/(1024·D))と整数化の誤差の分だけ異なるので、その差を検証で測る。 |
| 結果が端に達した場合 | 最終のθが1024に丸まった場合は、候補がJ75と同じになる。J75はすでにSTCで棄却されたので、「依存関係」の前提が成り立つ限り、測定せずに不採用とする。0に丸まった場合は、候補がJ75のPSTだけになるので、FMを含まないMNPTバージョン2として焼き込み、同じ段階ゲートで測る。この場合、調整中はFMの計算を行ったまま補正を0にしていたのに対し、候補はFMの計算そのものを省くので、探索速度も変わる。この差は採否の段階ゲートの結果に含めて判断し、調整中にFMを取り外す機構は加えない。 |
| 採否 | 焼き込んだ候補をmasterに対してSTCで測り、振り分け規則に従ってLTCへ進め、LTCで有意に強く、エンジン異常、時間切れ、および拒否着手が0件なら採用する。SPSA中の対局結果は採用の根拠にしない。候補が棄却された場合も、倍率を変えて測り直さない。 |
| 代理指標の扱い | 焼き込んだ候補の補正の大きさ、着手差のFM分、深さ9までのノード数、および検証損失は記録するが、採否の条件にしない。 |

## 実装フェーズ

### フェーズ1　倍率の係数、焼き込みの道具、および診断器

masterから専用のブランチを作り、J75の重みファイルと、コミット`4aad6df`の探索のテストの局面の変更を取り込む。
この時点のコミットは、評価関数がJ75であることを除いてmasterと同じエンジンになる。

次を実装する。

1. 探索係数の表（`crates/minase/src/search/alphabeta/params.rs`）に`FmScale`（既定1024、範囲0から1024）を加え、評価のモジュールから読めるように公開範囲を変える。
2. 調整用ビルドでだけ、`Fm::correction`をtrunc(N·FmScale/(1024·D))に変える。中間の計算は`i128`で行う。通常ビルドの式は変えない。
3. 焼き込みの道具を学習ツールに加える。入力はJ75の重みファイル、整数化前の重み、および`FmScale`の整数値であり、PSTの部分はそのまま、FMの部分は出力係数を`FmScale`/1024倍して整数化した重みファイルを出力する。`FmScale`が0の場合はPSTだけのMNPTバージョン2を出力する。
4. ブランチ`pst-fm-joint-training`の学習ツールから、`fm-diagnostics --pst-changed`と、探索用駒価値と出力Kの一致を調べる`validate_search_constants`を取り込む。同時学習器（`train-joint`）は取り込まない。

次のテストを加える。

- 調整用ビルドで、`FmScale`=1024の補正が通常ビルドと一致すること。
- 調整用ビルドで、`FmScale`=0、512、768の補正が、正と負の分子のそれぞれについて、式trunc(N·FmScale/(1024·D))と一致すること。768は、整数に切り捨てた補正にあとから倍率を掛ける式とは切り捨ての結果が分かれる値として加える（たとえばN/D=1.5のとき、本書の式は1、あとから掛ける式は0になる）。
- 指数26と30の重みでも、調整用ビルドの補正が桁あふれせずに式と一致すること。
- 焼き込みの道具の出力で、PSTの部分と探索用駒価値と出力Kが入力と一致し、`FmScale`=1024の出力のFMの部分が入力と一致すること。

完了条件は、`cargo test`（通常ビルドと調整用ビルド）、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習ツールの単体テストの通過と、実装のコミットである。

### フェーズ2　SPSAによる調整

パラメーターファイルは次の1行だけとする。
6つの欄は、名前、開始値、最小、最大、摂動幅の終了値`c_end`（範囲の1/6）、学習率の終了値`r_end`である。

```text
FmScale, 512, 0, 1024, 170.6666666667, 0.002
```

```console
<固定したminase> spsa \
  --run-dir data/spsa/fm-scale-spsa --seed 101000000 \
  --engine commit:<フェーズ1のコミット> --params <パラメーターファイル> \
  --rules engine-default --each time=10000+100 --concurrency 16 \
  --iterations 375 --pairs-per-iteration 8
```

開始前に、測定機で他の対局測定とSPSAが動いていないことを実行ファイル名で確かめる。
runner（対局を進めるコマンド）は、masterでビルドした`minase`を専用の場所へ複製して固定する。
最終のθを整数に丸めた値を、調整の結果とする。
途中の値を対局の成績で選び直さない。
結果は測定記録`fm-scale-spsa`に、θの推移（反復ごとの値）、異常件数、および所要時間とともに残す。
完了条件は、セッションの完了と測定記録の保存である。

### フェーズ3　焼き込みと採否測定

得られた`FmScale`を焼き込んだ重みファイルを`crates/minase/nets/pst.bin`へ書き込み、初期局面の評価値のテストを更新してコミットする。
「検証」の節の正しさの検査を行い、結果を測定記録`fm-scale-spsa-candidate`に残す。

```console
<固定したminase> match run \
  --run-dir data/matches/fm-scale-spsa-stc --seed 102000000 \
  --candidate commit:<候補> --baseline commit:<master> \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

LTCは測定名の接尾辞を`-ltc`、基本シードを103000000、持ち時間を`time=60000+200`とし、`--max-pairs`を付けない。
基本シードを100万ずつ離すのは、近い基本シードが同じ対局列を生む事故を避けるためである（[教訓](../lessons/derive-seed-adjacent-collision.md)）。
3つの基本シードは、保存済みの測定とSPSAの基本シード（`data/matches/`と`data/spsa/`の`manifest.json`）のいずれからもペア数以上離れた未使用の値である。
採否を記録し、採用した場合は[評価関数](evaluation.md)の現行設計と[PSTの学習手順](../guides/pst-training.md)に、重みを更新したら倍率も決め直す手順を加える。

## 検証

- フェーズ1のコミットの通常ビルドが、J75の候補コミット（`4aad6df`）と同じ探索をすること。1スレッド、深さ6のbenchで、局面ごとのノード数、最善手、および評価値がすべて一致することを確かめる。
- 焼き込んだ重みの浮動小数点の評価と整数の評価の平均絶対誤差が2 cp以下であること。
- 焼き込んだ重みの補正と、調整中の補正trunc(N·FmScale/(1024·D))の差の平均絶対値と最大値を、検証の1万局面で記録すること。平均絶対値が2 cpを超える場合は、整数化の扱いを見直してから測定へ進む。
- `fm-diagnostics --pst-changed`で、10万局面のRustの評価と学習ツールの整数評価が完全に一致すること。`FmScale`が0の場合は、MNPTバージョン2の既存のPSTの照合（`pst-diagnostics`と`minase dev pst-probe`）で同じ一致を確かめる。
- 焼き込んだ候補の探索用駒価値と出力Kがmasterの重みファイルと一致し、PSTの部分がJ75と一致すること。
- 補正の大きさ、着手差のFM分（代表6局面と1,000局面）、深さ9までのノード数、および検証損失を、master、J75と並べて記録すること。いずれも採否の条件にしない。
- `cargo test`（通常ビルドと調整用ビルド）、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習ツールの単体テストが通過すること。
- SPSAと採否の測定でエンジン異常、時間切れ、および拒否着手が0件であること。最初の測定で1件でも出た場合は、測定を止めて原因を調べる。

## 完了条件

- SPSAの結果（θの推移と最終値）と、候補の正しさの検査、探索速度、および採否が測定記録に残っている。
- 採用した場合は、[評価関数](evaluation.md)の現行設計と[PSTの学習手順](../guides/pst-training.md)に、倍率を対局で決める手順が反映されている。
- 不採用の場合は、結論と測定記録だけをmasterへ残し、実装はmasterへ統合しない。
- ROADMAPの状態表が本書の結論と一致している。

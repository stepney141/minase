# 中将棋の対局管理層の設計書（第2版）

**失効注記（2026年8月9日）**：本書が定めた規則コードR0のコード表現は、マイルストーン「審判ロジック再編とR0撤去」（[adjudication-refactor.md](adjudication-refactor.md)）で廃止された。以下は当時の実施記録である。

## 1. 目的と適用範囲

本書は、中将棋エンジン minase のマイルストーン「審判層の完成」の設計を定める。
第1版が定めた対局管理層（2026年7月31日に完成）を前提に、駒枯れ（第22条）と R2 の裁定を実装し、標準規則の千日手（第25条）を規則コード R0 としてローカルルール化する。
規則の正は RULES.md であり、本書と RULES.md が矛盾する場合は RULES.md を優先する。
本マイルストーンには RULES.md の第7版への改定を含む。

`Game` の消費者は、2026年8月1日の設計セッションで、将来の CUI 対局マネージャと XBoard アダプタであると確定した。
探索部は `Game` を経由せず `Position` と make/unmake を直接使う前提であり、`Game` に探索向けの性能要件を課さない点は第1版から変わらない。
マイルストーンの順序も同セッションで「審判層の完成、その後に探索部」と確定した。

## 3. 第25条の R0 化（RULES.md 第7版）

標準第25条の帰責判定は、本マイルストーンでも実装しない。
「同じ一群の相手駒」「反復を開始した側」という文言は対人運用を前提とした規定であり、コンピュータ実装には解釈の発明が必要になる。
第1版3節が R1 を既定に選んだのも同じ理由であった。
2026年8月1日の設計セッションでは、条文に解釈を継ぎ足すのではなく、連盟の規定を原文のままローカルルール R0 へ移すと決めた。
これにより条文への忠実性を保ったまま、「裁定できない規則を正直に拒否する」という現行設計を規則文書の水準でも成立させる。

RULES.md 第7版の改定内容は次のとおりとする。

- 第25条の本文を、第31条の表へ **R0** として原文のまま移す（典拠は連盟総則編のまま）。
- 第8章の第25条は選択規定に置き換える。「反復の裁定は、採用した反復規則（R0、R1 または R2 のいずれか1つ）による。指定がない場合は R0 を適用する。」
- 第31条の「R1 と R2 は同時に採用できず、採用時は第25条を置き換える」という文言を「R0、R1、R2 は同時に採用できない」に改める。
- 第31条の R2 欄に同一局面判定の明確化を追記する。R2 の禁止判定は第24条1項 a から c の範囲（盤面、手番、先獅子）で行い、履歴由来の合法手差（第24条1項 d）は判定に含めない。この明確化がないと、R2 自身が合法手を履歴に依存させるため、同一局面の定義が循環する。
- 第33条の表示規定を更新する。標準規則は R0 を含むため通常表示しない（L0 と同じ扱い）。エンジン既定は「標準規則－R0＋R1」と表示する（第33条3項の「標準規則－L0＋L1」と同型）。

実装側では `RuleCode::R0` を追加し、排他対 (R0, R1)、(R0, R2)、(R1, R2) を `from_codes` の検査に加える。
R0 は `Rules` としては受理し（規則セットの表示と設定に必要なため）、`Game::new` が `UnsupportedStandardRepetition` で拒否する。
このエラーの意味は「R0 の裁定は未実装」に改まるが、名称は維持する。

## 4. 既定構成の変更

エンジンの既定構成は「標準規則－R0＋R1」とする。
現行の既定「標準規則＋R1＋E2」から E2 が外れるのは、第22条が裁定可能になり、駒枯れ見送りを正直に表示するという E2 既定の理由（第1版3節）が消滅するためである。

反復規則の暫定既定は R1 とする。
R0 は未実装であり、R2 には参照実装がないのに対し、R1 には Lishogi（scalashogi）という参照実装と検証済みの裁定実装がある。
既定の再検討は R0 を実装する時点で行う。

## 5. 駒枯れ（第22条）の裁定

**余分な駒**とは、盤上に唯一残った王駒以外の駒をいう。
ただし最奥段で移動不能になった歩兵と香車（第19条2項と3項）は余分な駒として数えない（第22条4項）。
移動不能の歩兵または香車が唯一の非王駒である場合、駒枯れの裁定は行わず対局を継続する。

駒枯れの成立条件は、双方の王駒がちょうど1枚ずつ残り、かつ非王駒がちょうど1枚だけ一方に属して残っていることである（第22条1項）。
王将（玉将）と太子が併存する側がある間は成立しない。

裁定は着手のたびに次の流れで評価する。

1. 余分な駒が歩兵または仲人である場合、勝利条件はその成り（金将、醉象）である（2項と3項）。成るまでは裁定せず、対局を継続する。この待機中も反復の裁定は通常どおり働く。成った時点で余分な駒は歩兵でも仲人でもなくなるため、次項の裁定に合流する。歩兵が最奥段で不成のまま移動不能になった場合は、4項により余分な駒として数えなくなる。
2. それ以外の駒の場合、原則として余分な駒を持つ側の勝ちとする（1項）。ただし条件成立の直後に王駒だけとなった側が手番を持ち、かつ余分な駒をその1手で取れる場合は、裁定を保留してその1手を認める（5項）。
3. 保留した1手で余分な駒が取られた場合、駒枯れによる勝利は成立せず（6項）、双方が王駒のみとなって次項の引き分けへ進む。取られなかった場合、余分な駒を持つ側の勝ちとする（7項）。
4. 盤上に王駒以外の駒がない場合は引き分けとする（8項）。王駒はすべて周囲1升の動きしか持たず、相手王駒の捕獲を強制する手段が存在しないため、8項の「いずれも詰めることができない」は駒種構成だけで確定する。

条文が明示しない境界について、本書は次の読みを固定する。

- **猶予の適用条件**：5項の「直後に……次の着手で」は、条件成立時に王駒だけとなった側が手番を持つ場合に限って適用する。余分な駒を持つ側が手番なら1項で直ちに裁定する。猶予を相手の任意の1手の後まで残すと、余分な駒側が駒を逃がしてから裁定を受けられることになり、5項の「直後」が意味を失うためである。
- **猶予の消費**：保留は1ビットの状態として持ち、王駒だけとなった側の次の1手で必ず解消する。取らない着手を選んだ時点で7項により裁定し、保留を再付与しない。
- **成りの時点の裁定**：歩兵または仲人が非捕獲の着手で成った時点では、5項の猶予を適用せず直ちに裁定する。2項と3項は成りそのものを勝利条件と定めており、5項の猶予は「条件が成立した直後」（歩兵または仲人が余分な駒となった時点）を指すためである。王駒だけとなった側は、待機中に余分な駒を取る機会を持ち続けていた。この即時裁定は非捕獲の成りに限る。非捕獲の着手は駒数を変えないため、成った後に条件が成立していれば成る前から成立していたことが保証される。捕獲を伴う成りで条件が同時に成立した場合は、成る前に条件が成立しておらず待機局面が存在しないため、2項の前提（歩兵が既に余分な駒であること）を欠き、1項と5項の通常の流れで猶予を判定する。

`WinReason` に駒枯れ勝ちを、`DrawReason` に8項の引き分けを追加する。
E2 採用時は本節の裁定全体を行わない（現行どおり）。
E1 と第22条は併存できる（E1 が無効化するのは第21条の詰み裁定だけである）。

## 6. R2 の裁定（完全統合）

R2 は、同じ手番の既出局面を再現する着手を禁止する（第31条）。
4回目の再現だけを禁止する緩和方式は、条文が別の明示を要求しており、本実装では提供しない。

同一局面の判定キーには、先獅子トリガーを織り込んだ `Position` の Zobrist ハッシュ（2026年8月1日に実装）をそのまま使う。
手番はキーに含まれるため、「同じ手番の既出局面」はキーの一致だけで判定できる。
`Game` が反復裁定のために持つ出現回数表が、そのまま履歴集合を兼ねる。
履歴には現局面も含まれる。

R2 採用時、`play` は着手適用後のキーが履歴に存在する場合、着手を巻き戻して `IllegalMove` で拒否する（第26条11項）。
なお R2 採用時は同一局面が再現され得ないため、出現回数はすべて1であり、4回系の反復裁定は発生しない。

統合の要になるのは次の補題である。
捕獲を含む着手と成りを含む着手は、駒数または駒種の不可逆な変化を伴うため、既出局面を再現し得ず、R2 で禁止されることはない。
この補題により、詰み判定で相手が指す「王駒を取る応手」が R2 で禁止されるケースは存在しない。

第23条との連動では、手番側の生成手がすべて R2 で禁止される場合を合法手なしとして手番側の負けとする（第23条1項）。
第21条の詰み判定との連動では、2手読みの1手目（手番側の受け）に R2 フィルタを適用した合法手集合を使う。
2手目（相手の王駒捕獲応手）は捕獲着手であり、補題によりフィルタ不要である。
実装としては `is_mate` と `has_no_legal_move` に履歴キー集合への禁止述語を渡す形へ拡張し、R2 非採用時は空の述語で現行と同じ挙動にする。

R2 と E1 は併存できる。
E1 は詰み裁定を無効化するだけで、R2 の着手フィルタと第23条の連動はそのまま働く。

## 7. 裁定の適用順序

裁定の順序は、王駒捕獲、反復（R1）、駒枯れ、合法手なし、詰み（E1 指定時は無効）とする。
R2 採用時は反復裁定の位置に何も入らず、代わりに着手受理時のフィルタが働く。

この順序が結果に影響しないことは次のとおり確認できる。
反復と駒枯れの保留が同一着手で衝突することはない。
保留は捕獲の直後にのみ発生し、捕獲後の局面は駒数が減っているためすべて初出であり、保留解消までの高々1手で4回目の同一局面は構成できない。
駒枯れと合法手なしまたは詰みが同一局面で同時に成立する場合、勝者はどちらの裁定でも余分な駒を持つ側で一致し、差は `WinReason` の表示だけである。
本実装は駒枯れを先に評価する。

## 8. やらないこと

R0 の裁定実装（`Game::new` は Unsupported で拒否し続ける）、R2 の緩和方式、L1 から L3 と P1 から P4、`Game` の undo と待った、棋譜入出力、時間管理は、本マイルストーンでは実装しない。
いずれも消費者または採用の決定が現れた時点で追加する。

## 9. 実装順序と発注単位

実装は次の4スライスに分け、S1 と S2 は codex への発注で行う。
各スライスの受入条件は、cargo test の全緑、clippy の無警告、および既存 perft 期待値の不変である。

**S0（RULES.md 第7版）**：3節の改定を RULES.md に適用する。
規則文書の改定は本セッションの決定を反映する編集作業であるため、codex ではなく本体で行う。

**S1（第22条と規則コード再編）**：`RuleCode::R0` の追加、排他対の検査、`UnsupportedPieceExhaustion` の廃止、5節の状態機械、`WinReason` と `DrawReason` の追加、第22条の条文テスト。

**S2（R2）**：`from_codes` の R2 受理、`play` の着手フィルタ、`is_mate` と `has_no_legal_move` の述語拡張、第23条連動、6節の補題を含む条文テスト。

**S3（既定切替）**：`engine_default` の変更（R1 のみ）、`with_default_rules` と既存テストの追随、表示の更新。

S0 から S3 までは2026年8月1日にすべて完了した。
S1 のレビューでは、捕獲を伴う成りで駒枯れ条件が同時に成立する境界（5節の第3の読みの但し書き）を検出して修正した。

## 10. 検証

**条文対応テスト**：第22条の1項から8項まで、および5節で固定した3つの読みの境界局面。R2 の受理拒否、第23条連動、詰み連動、補題の境界（捕獲着手が禁止されないこと）。R0 指定時の Unsupported。

**ソークテスト**：既定構成（標準規則－R0＋R1）のランダム自己対局は現行のまま維持する。
R2 構成でも終局到達を検査する。
R2 では反復による終局がないため、終局理由は捕獲、駒枯れ、合法手なし、詰みに限られる。

**回帰**：第1版で定めた Zobrist 整合プロパティと R1 の条文テストは変更なしで全緑を維持する。

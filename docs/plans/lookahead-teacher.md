# 先読み教師値（TD(λ)方式の教師値）の設計書

## 先に読む要約

本書は、評価関数の学習に使う教師値（学習の目標にする値）を、記録した局面そのものの探索値から、同じ対局でその後に現れた局面の探索値を混ぜた値へ変える方式を定め、王の安全度の特徴がその教師で重みを得るかを診断して、得た場合に採否を自己対局で測る。
現行の教師値は、局面ごとに10万ノードの探索値（深さ約6）を勝率へ変換し、対局結果と3:1で混ぜた値である。
[棋力向上段階9](strength-stage9.md)の3つの診断は、この教師のままでは王の安全度の特徴に重みが乗らないこと、探索を1,000万ノードへ深くしても、人間の対局結果や人間の配置から始めた自己対局を使っても、その状況が変わらないことを示した。
一方で、[lishogiの敗局](../research/lishogi-game-yO464dzl-loss-analysis.md)と[HaChuとの対局の分析](../research/hachu-minase-playing-style-analysis.md)は、minaseが自身を有利とする評価を保ったまま、数手から十数手の後に評価が急落して負ける型を示している。
そこで本書は、局面tの教師値に、同じ対局のt+1手からt+n手までの探索値を、手数が離れるほど小さくなる幾何級数の重みで平均した値（先読み値）を使う。
これはKnightCapが用いたTD(λ)（時間差分学習）の目標値と同じ形であり、追加の探索を要せず、既存の教師データの対局番号と手数だけから計算できる。
進め方は、先読み値と現在の探索値の差の分布を記録し、項目1（王の遮蔽と開いた筋、24列）の重みを先読み教師で学習して、自王側の危険を表す列の序中盤の重みが負の値を得るかを事前に固定した基準で判定し、基準を満たした候補だけを短時間と長時間の時間制御GSPRT（[docs/guides/sprt.md](../guides/sprt.md)）で測る。
完了条件は、差の分布の記録、基準に対する判定、候補の採否または見送りが測定記録とともに残り、採用した場合は先読み教師で学習PSTごと学習し直した候補の採否も記録されていることである。

## 目的

現行の学習は、局面の静的評価をその局面の探索値へ近づける。
探索値は深さ約6の読みの範囲でしか局面を見ないので、駒を取らない手が7手から9手続く攻めの準備を数値に含まない。
段階9の診断は、この盲点を教師の側から埋める3つの方法（深い探索、人間の対局結果、人間の配置）のどれも、王の安全度の特徴が説明できる残差を教師に持ち込まないことを示した。
本書の方法は、探索を深くする代わりに、対局が実際に進んだ先の探索値を使う。
攻めの準備が整った局面では、その後の十数手で探索値が下がるので、先読み値はその局面を現在の探索値より低く評価する。
静的評価がこの値へ近づけば、評価関数は準備が整った配置を静的に減点し、探索はその配置を避ける。

## 適用範囲

対象は、`tools/train/pst/` の学習器（教師値の計算と教師の分類）、診断器、および段階9の項目1の候補である。
評価関数の特徴、探索、教師データの形式（MNSD）、生成器は変えない。
本書の用語は段階9の設計書に従い、次の語を加える。

- **探索値** `v_t` は、記録した局面tの手番側から見た探索値（センチポーン）を指す。
- **先読み値** `v̂_t` は、同じ対局のt+1手からt+n手までに記録された局面の探索値を、局面tの手番側の視点へそろえ、手数の差kに重み `λ^(k−1)` を掛けて平均した値を指す。記録されていない手数は平均に含めず、重みは含めた手数だけで正規化する。t+1手からt+n手までに記録された局面がなければ `v̂_t = v_t` とする。
- **先読み教師値**は、現行の教師値の探索値を先読み値に置き換えた値 `0.75 · sigmoid(v̂_t / K) + 0.25 · result` を指す。教師Kは先読み値から教師の分類ごとに推定する。
- **急落局面**は、`v̂_t − v_t` が−300センチポーン以下の局面を指す。−300は、王手を伴わない大駒1枚分の損失に当たる値として本書が置く目安であり、記録にだけ使う。

## 依存関係

教師の分類、来歴ファイル、付け直しファイル、および追加特徴の学習は[棋力向上段階9](strength-stage9.md)のフェーズ4とフェーズ6の基盤を使う。
本書の候補は段階9の項目1の候補であり、測定名と基本シードは段階9の規則に従って本書が割り当てる。
ブランチは、段階9の基盤がmasterへ入っていないため、`strength-stage9` から分岐した `lookahead-teacher` とする。
段階9の完了処理は、本書の結論を項目1の採否として取り込む。

## 設計判断

| 項目 | 決定 |
|---|---|
| 先読み値の形 | 幾何級数の重みによる平均とし、将来の最小値は採らない。最小値は探索値の揺れによって系統的に低い側へ偏り、両陣営で同じ偏りが生じると1つの局面に矛盾する目標を与えるためである。幾何級数の平均は揺れに対して不偏であり、KnightCapのTD(λ)の目標値と同じ形である。 |
| λと手数の上限n | λ=0.9、n=40手（先後合計）とし、結果を見て変えない。敗局では174手目の局面から急落まで約12手から16手あり、λ=0.9では20手以内の重みの合計が88%、12手目の重みが約3%である。KnightCapのλ=0.7は1手ごとの減衰が速く、12手先の重みが1.4%になるので採らない。λ=0.7と0.95の値は診断で記録だけを行い、候補には使わない。 |
| 記録されていない手数の扱い | 生成時の除外（詰みの帯、捕獲または成りの最善手、再出現）で記録されない手数は平均から除き、重みを正規化する。除外された局面の探索値は保存されていないためである。対局の終わりの局面では先読み値が現在の探索値に近づくが、対局結果の項が終局の情報を持つ。 |
| 対局結果との混合 | λ=0.75の混合は変えない。先読み値は探索値の置き換えであり、対局結果の項の役割（対局全体の帰結）は変わらない。 |
| 教師の分類 | 先読み値を使う教師は、λとnを分類の属性に加えた別の分類とし、教師Kを先読み値から推定し直す。同じファイルを現行の教師と先読み教師の両方で使うことはしない。 |
| 静止探索の末端で合わせる方式との関係 | 将棋の学習器が採る「静止探索の末端の局面の静的評価を深い探索値に合わせる」方式は、本書の対象外とする。本書は目標値の側だけを変え、入力の局面は変えない。両方を同時に変えると効果を切り分けられない。 |
| 事前の判定 | 候補を自己対局で測るかどうかは、先読み教師で学習した項目1の重みが事前の基準を満たすかで決める。基準は、自王側の走り駒の6列（1枚の距離0、1、2と2枚以上の距離0、1、2）の序中盤端点の重みのうち、少なくとも1列が−30センチポーン以下であることとする。現行の教師では、この6列の序中盤端点は絶対値52以下で多くが正であり、−30は診断Aが置いた運用上の最小の差と同じ値である。基準を満たさなければ候補を作らず、見送りを記録する。 |
| 候補の範囲 | 最初の候補は、段階開始版の学習PSTを固定し、項目1の24列だけを先読み教師で学習したものとする。採用された場合に限り、学習PSTと項目1を先読み教師で同時に学習した第2の候補を測る。第2の候補の結論は「先読み教師への変更全体の効果」と表現する。 |
| 診断の記録 | 先読み値と探索値の差の分布（駒数の帯ごと）、急落局面の割合、および118列の特徴と先読み教師の残差との相関を記録する。これらは記録であり、事前の判定には使わない。 |

## 先読み値の計算

学習器は、各MNSDファイルを読むときに、対局番号ごとに記録を手数の順に並べ、次の式で先読み値を計算する。

```text
u_s = v_s            （s − t が偶数のとき。局面sの手番が局面tの手番と同じ）
u_s = −v_s           （s − t が奇数のとき）
v̂_t = Σ_{s} λ^(s−t−1) u_s / Σ_{s} λ^(s−t−1)   （sは同じ対局で t < s ≤ t+n の記録された手数）
```

記録された手数がなければ `v̂_t = v_t` とする。
計算は決定的であり、同じファイルとパラメータから同じ値が得られる。
先読み値はセンチポーンの整数へ丸めず、実数のまま教師Kの推定と教師値の計算に使う。
MNSDファイルの記録は対局番号の順、対局の中では手数の順に並んでいることを前提とし、順序が崩れているファイルは拒否する。

## 実装フェーズ

### フェーズ1　学習器の先読み値

学習器と診断器に、設定 `train.lookahead`（λとn）と対応するコマンドライン引数を加え、先読み値の計算、教師の分類の属性、教師Kの推定、および記録（`inputs.json`、`training.json`）への反映を実装する。
完了条件は、次のことがテストで固定されていることである。

- 手数の欠けた列、視点の反転、上限nでの打ち切り、対局の終わりでの現在の探索値への退避が定義どおりに計算される。
- 同じ入力とパラメータから同じ先読み値が得られる。
- 対局の順序が崩れた入力が拒否される。
- 先読み値を使う分類の教師Kが、現行の教師と別に推定される。

### フェーズ2　差の分布の記録と項目1の学習

基本の教師の11ファイルについて、先読み値と探索値の差の分布、急落局面の割合、および118列との残差相関を記録し、測定記録 `lookahead-teacher-diag` に残す。
続けて、段階開始版の学習PSTを固定して項目1の24列を先読み教師で学習し、学習後の診断（段階7と段階9の基準）を通したうえで、事前の判定を行う。
学習した重みと判定は測定記録 `lookahead-teacher-shelter-training` に残す。

### フェーズ3　採否測定

判定を通過した場合、候補のコミット（特徴数の定数と重みファイルをそろえたもの）を作り、STC（`lookahead-teacher-shelter-stc`、基本シード42000921）とLTC（`lookahead-teacher-shelter-ltc`、基本シード45000921）で測る。
採用した場合は、学習PSTと項目1を先読み教師で同時に学習した第2の候補を、`lookahead-teacher-joint-stc` と `lookahead-teacher-joint-ltc`（基本シード48000921と51000921）で測る。

## 検証

- 先読み値の計算は、手で計算した小さな対局列（記録の欠け、対局の境界、上限nを含む）で固定する。
- 学習後の診断は段階9の「検証」の基準に従う。固定した学習PST、探索用駒価値、出力Kが1ビットも変わらないこと、量子化の前後の平均絶対誤差が2センチポーン以下であること、Rustと学習器の評価値が一致することを確かめる。
- 敗局の174手目から182手目の局面について、項目1の寄与を記録する。この敗局は特徴の選定に使ったので、参考の診断であり、採否の基準にしない。
- 採否測定は[SPRTの手引き](../guides/sprt.md)の標準コマンドに従い、エンジン異常、時間切れ、拒否着手が0件であることを採用の条件にする。
- すべてのコミットで `cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習器の単体テストが通ることを確かめる。

## 完了条件

- 差の分布、急落局面の割合、残差相関が測定記録に残っている。
- 項目1の先読み教師での重みと事前の判定の結果が測定記録に残っている。
- 判定を通過した場合は、候補のSTCとLTCの結果と採否が記録され、採用した場合は第2の候補の採否も記録されている。
- 段階9の設計書の状態に、項目1の採否または見送りが本書の記録とともに反映されている。

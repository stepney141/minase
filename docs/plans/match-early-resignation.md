# 早期投了の導入判定

## 先に読む要約

本マイルストーンは、自己対局中の評価値から勝敗を早期に確定しても、規則上の終局まで指した場合と統計結果が変わらないかを検証する。
対局時間の短縮は望ましいが、誤った投了はエンジンの棋力差を作り替えるため、評価値の大きさだけを根拠に直ちに導入しない。

完成済みの対局ハーネスは、両エンジンの評価値、評価の視点、詰み表示、探索深さ、および思考時間を記録しながら、規則上の終局まで対局を継続できる。
この完走記録を校正群と独立した検証群へ分け、仮想的な投了条件だけをオフラインで適用する。

検証群では、仮想投了が発火した独立3,000局以上について、最終勝者との不一致0件、ペア得点分類の変更0件、および総思考時間15%以上の削減を要求する。
条件をすべて満たした場合だけ投了裁定を実装し、満たさない場合は不採用結果を記録して完了する。
現在は、必要な記録量に達しておらず、観測単位、評価値の同期、および実装後比較の契約も未確定なので待機する。

## 状態

本設計書は2026年8月28日に、[棋力測定ハーネス基盤の効率化](match-harness-efficiency.md)から分離して起案した。
校正群とは別に仮想投了が3,000回以上発火する検証群を確保できる記録量へ達しておらず、後述する統計契約も未確定なので、状態は待機中とする。

## 目的

本マイルストーンは、次の3点を達成する。

- 評価値による早期投了候補を、棋力測定の統計結果を変えない条件として定義する。
- 独立した完走対局で誤裁定率と削減時間を測る。
- 導入条件を満たした場合だけ裁定を実装し、満たさない場合は不採用の根拠を残す。

## 文書の所有権

本書は、評価値による早期投了の閾値選定、独立検証、および導入判断を所有する。
評価値を含む対局記録の形式は[棋力測定ハーネス基盤の効率化](match-harness-efficiency.md)が、棋力測定の標準手順は[SPRTによる棋力測定の手引き](../sprt.md)が所有する。

## 対象外

評価値による早期引き分けは導入しない。
現行の自己対局は引き分けが少なく便益を見積もれず、誤裁定が終盤処理の変更を隠すためである。

評価尺度、詰み探索、終盤の勝ち切り、反復、または終局裁定を変更する候補の最終測定では、早期投了を使わない。
これらの変更は投了条件の前提そのものを変えるため、導入後も完走対局で測る。

## 設計判断

| 論点 | 決定 |
|---|---|
| 初期動作 | 評価値を記録するだけにし、対局は規則上の終局まで続ける。 |
| 発火条件 | 両エンジンが同じ勝者を支持する評価閾値と連続手数を1組だけ使う。 |
| データ分割 | 閾値を選ぶ校正群を検証群へ再利用しない。 |
| 最低標本数 | 仮想投了が発火した独立3,000局以上を要求する。 |
| 正確性 | 最終勝者との不一致とペア得点分類の変更をともに0件とする。 |
| 便益 | シミュレーション上の総思考時間を15%以上削減する。 |
| 不成立 | 条件を満たさなければ裁定を実装せず、不採用結果を記録して完了する。 |
| 互換動作 | 裁定なしへの暗黙の切替えや、評価値が欠測した場合の片側判定を設けない。 |

## 記録要件

各着手について、両エンジンが最後に返した評価値、評価の視点、詰み表示、探索深さ、および思考時間を使う。
評価情報を返さないエンジン、CECPの`nopost`で動かしたエンジン、および必要な記録が欠けた対局は検証対象へ含めない。

対局は規則上の終局まで完走し、最終勝者、終局理由、およびペア得点分類を保存する。
異常終了、時間切れ、拒否着手、および手数上限による打切りを含む対局は、通常終局した対局と混ぜずに除外理由を記録する。

## 閾値の選定

校正群を使い、両エンジンが同じ勝者を支持する評価閾値と連続手数を1組だけ選ぶ。
片方だけの評価値では発火させないため、評価尺度が異なるコミット間でも一方の過大評価だけで勝敗を決めない。

候補の閾値と連続手数は、検証群を見る前に固定する。
検証結果を見て値を調整する場合は、その検証群を破棄して、新しい独立検証群を収集する。

## 独立検証

検証群では、固定した条件を各完走対局へ仮想的に適用し、最初の発火時点以後の思考時間を削減可能時間として集計する。
仮想投了が発火した独立3,000局以上について、次の3条件を同時に満たすことを要求する。

- 仮想投了が支持した勝者と規則上の最終勝者との不一致が0件である。
- 仮想投了を各局へ適用しても、ペア得点のペンタノミアル分類が1件も変わらない。
- 検証対象全体の総思考時間を15%以上削減する。

誤り0件を`n`件観測した場合、3の法則は真の誤裁定率の片側95%上限を約`3/n`と見積もる。
3,000局で不一致0件なら上限は約0.1%となる。
評価関数を変更した複数世代の対局を検証群に含め、単一評価器だけに適合した条件を全変更へ適用しない。

## 着手前に確定する契約

同じ開始局面から先後を入れ替えた2局には相関があるため、3の法則を局単位へ適用できるかは未確定である。
着手前に独立性の根拠を示すか、開始局面またはペアを観測単位として必要標本数を定義し直す。

保存記録は各着手で手番側エンジンの評価値を持つため、「両エンジンが同じ勝者を支持する」時点の揃え方も未確定である。
異なる局面の直近評価値を対応させる規則、連続手数の起点と終点、評価値の視点変換、および詰み表示の扱いを、閾値選定前に固定する。

裁定実装後の比較は、ハーネスへ機能切替スイッチを追加せず、裁定実装コミットと直前コミットを固定して行う。
実装前に、エンジンの比較カード、固定ペア数、時間制御、シード、ペンタノミアル分類とEloの許容差、時間削減率、および異常0件の条件を定める。
これらを確定するまで、完走記録の収集を除く実装フェーズへ進まない。

## 裁定の実装

独立検証の3条件を満たした場合だけ、早期投了を別の実装フェーズとして追加する。
実装後は、裁定ありと裁定なしを同じ開始局面で固定ペア数比較し、ペンタノミアル度数、Elo、LLR、および実時間を確認する。

裁定ありの実行は、評価値の欠測、視点の不一致、または詰み表示の解釈不能を検出した場合に勝敗を推測しない。
安全に裁定できない対局を継続する互換経路は設けず、その測定条件では早期投了を利用できないことを明示的なエラーとして扱う。

## 実装フェーズ

### フェーズ1　完走記録の収集

複数世代の評価関数を含む対局を完走させ、校正群と独立検証群へ分けられる記録量を確保する。

### フェーズ2　閾値の固定と検証

校正群で閾値と連続手数を1組に固定し、独立検証群で正確性と削減時間を測る。

### フェーズ3　導入または不採用

導入条件を満たした場合だけ裁定を実装して比較測定を行う。
満たさない場合は裁定を実装せず、不採用結果を記録する。

## 完了条件

次のいずれかを満たしたとき、本マイルストーンを完了とする。

- 独立検証が3条件を満たし、裁定ありと裁定なしの比較で統計結果を変えずに時間を削減できることを確認して、標準手順へ反映している。
- 独立検証が1条件以上を満たさず、裁定を実装しない判断と測定結果を記録している。

どちらの場合も、校正群と検証群の識別、対象コミット、対局数、除外数、誤裁定数、ペア分類変更数、および削減時間を保存する。
着手前に、観測単位、評価値の同期規則、および実装後比較の合否契約が確定していることも必要とする。

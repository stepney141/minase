# 棋力測定の段階ゲート

## 先に読む要約

本マイルストーンは、探索と評価の変更を採否判定へかける標準の測定手順を、短時間の選別と長時間の最終測定の2段階へ改める。
短時間条件を**STC**（short time control、持ち時間10秒と1手0.1秒加算）、長時間条件を**LTC**（long time control、持ち時間60秒と1手0.6秒加算）と呼び、いずれも秒読みを使わない。
この2条件はStockfishの分散測定基盤fishtestの標準値と同じであり、時間制御の選定理由を本プロジェクトが独自に正当化する必要をなくす。
変更はまずSTCのGSPRT（docs/sprt.md参照）で選別し、通過した候補だけをLTCのGSPRTへ進める。
候補の棄却はSTCでもLTCでも起こるが、採用の決定はLTCの判定だけが下し、STCの通過を採用の根拠にしない。
測定条件の妥当性は、新規の校正測定ではなく、既存の測定記録の事後検証で根拠づける。
ハーネスへの変更は、同時対局数を物理コア数から自動計算する既定値の追加だけである。
完了条件は文書と実装と検証コマンドの成功であり、追加の対局測定を要しない。

## 状態

本マイルストーンは完了である。
2026年8月28日に起案し、2026年9月1日の全面改訂で着手して、同日に完了した。
機能採否の標準手順をSTCの選別とLTCの最終測定の2段階へ改め、`match_runner`の同時対局数の自動計算を実装し、`docs/sprt.md`を段階ゲートだけを標準とする形へ改訂した。

## 目的

本マイルストーンは、次の4点を達成する。

- 通常の探索変更と評価変更の採否測定を、STCの選別とLTCの最終測定の2段階へ標準化する。
- STCとLTCの時間制御をfishtestの標準値に合わせ、秒読みを廃止する。
- 同時対局数を測定機の物理コア数から自動計算し、手順書から機材依存の数値を除く。
- 以上を`docs/sprt.md`の唯一の標準手順として反映する。

## 適用範囲

本書が定めるのは、通常の探索変更と評価変更の機能採否測定の経路である。
凍結ベースラインへの完了基準ゲート、外部エンジンとの強さ比較、および進捗記録の固定局数Eloの各手順は変えない。
完了済みの測定への遡及適用はせず、評価値による早期投了は[早期投了の導入判定](match-early-resignation.md)が扱う。
フェーズ3が完了するまでは`docs/sprt.md`の現行手順が有効であり、移行期間中に開始する測定は現行手順に従う。
本書の手順はフェーズ3の反映後に開始する測定から適用し、新旧の併存や暗黙の切替えはない。

## 設計判断

### fishtestの標準値への整列

現行の標準時間制御は、持ち時間30秒、1手0.3秒加算、秒読み0.5秒の単一条件である。
選別と最終の2条件を新設するにあたり、値はfishtestの標準であるSTC（10秒+0.1秒）とLTC（60秒+0.6秒）をそのまま使う。
確立した慣行に合わせれば、時間制御の妥当性を本プロジェクトが独自の校正測定で示す必要がなくなるからである。
秒読みはfishtestにもTanukiColiseum（やねうら王系の測定に使われる自己対局ツール）にもない要素なので廃止する。
秒読みなしの実運用には実績があり、HaChu比較の3測定（`time=60000+1000`）はいずれも時間切れ0件で完走した。
STCと同じ持ち時間の既存測定（`time=10000+100,byoyomi=200`）は8並列で毎時92ペアを時間切れ0件で処理しており、選別の回転率は現行条件の3倍以上になる。
棄却した代案は2つある。
LTCを現行標準のままとする案は、測定コストは最小だが、秒読みという整列先にない要素が残るため棄却した。
やねうら王系の慣行（持ち時間300秒と2秒加算の固定2,000局）に合わせる案は、1局が現行の10倍を超えて毎回の採否ゲートには重すぎるため棄却した。

### 校正方式の廃止と既存記録による事後検証

旧設計は、真の効果が既知の比較カード4種で候補時間制御の効率を校正してから標準化する方式だった。
初回校正は、負例カードのP型NNUEが学習PSTに400局全敗してペア得点分散が0となり、主指標を算出できずに不成立となった（[calibration-negative-current](../measurements/calibration-negative-current.md)）。
加えて、200ペア規模の校正は正例のElo信頼区間が40〜108（幅約68）と粗く、改善率の閾値判定にはさらに大きい標本が要るため、校正というメタ測定に本測定以上の資源を割く構図になる。
この2点から、校正方式そのものを廃止する。
初回校正の測定値は[calibration-positive-current](../measurements/calibration-positive-current.md)と[calibration-negative-current](../measurements/calibration-negative-current.md)が、カード選定の規則は教訓[効果量が極端な対は測定条件の比較情報を持たない](../lessons/calibration-card-needs-contested-pair.md)が保持する。
代わりに、条件の妥当性は既存の測定記録の事後検証で根拠づける。
事後検証で確かめる性質は、安価な測定条件が現行の時間制御と同じ優劣の向きを与えることである。
符号の一致は3例ある。
学習PSTの世代0は固定ノードと時間制御の双方で優位（[pst-gen0-nodes100k](../measurements/pst-gen0-nodes100k.md)、[pst-gen0-tc](../measurements/pst-gen0-tc.md)）、世代1も双方で優位（[pst-gen1-nodes100k](../measurements/pst-gen1-nodes100k.md)、[pst-gen1-tc](../measurements/pst-gen1-tc.md)）、P型NNUE世代1は双方で劣位（[nnue-gen1-nodes100k](../measurements/nnue-gen1-nodes100k.md)、[nnue-gen1-tc](../measurements/nnue-gen1-tc.md)）である。
浅い条件が変更の優劣の符号を反転させた実例は、記録にない。
零差の煙試験も新設しない。
同一コミット同士の10ペア煙試験2件（[search-phase5-time-control-smoke](../measurements/search-phase5-time-control-smoke.md)、[search-phase6-time-control-smoke](../measurements/search-phase6-time-control-smoke.md)）が信頼区間に0を含むことを確認済みであり、以後の全測定でも異常件数と時間切れが記録され採用条件に含まれるからである。
同一コミット対局にしかない測定系の偏りの検出精度は既存の10ペア（信頼区間の幅約130 Elo）にとどまるが、この粗さを承知のうえで省略を選んだ。
その代わり、新条件で開始する最初の測定で時間切れ、エンジン異常、または拒否着手が1件でも出た場合は、測定を停止して原因を調査する。

### 検定境界の維持

仮説と誤り率は、現行のH0=elo 0、H1=elo 5、α=β=0.05をSTCとLTCの両方で使う。
fishtestはSTCに[0, 2]、LTCに[0, 1]相当の狭い境界を使うが、これは世界中の分散ワーカーが標本を供給する前提の設定である。
minaseの実測のペア得点分散σ²≈0.12では、境界[0, 2]の決着に約7万ペアを要し、単機では1回の測定が数百時間になるため採らない。
測定能力が増えた時点で、境界を狭める再検討を行う。
なお、α=β=0.05は各GSPRT単体の名目誤り率である。
段階ゲート全体では、STCの棄却と振分けが手前に入るため、誤採用率は単体の0.05より下がる一方で検出力も下がり、全体の誤り率を0.05に制御するとは主張しない。

### STCの上限とLLRの符号による振分け

docs/sprt.mdの標本数の目安が示すとおり、真の効果が境界5付近にある変更は決着に約13,000ペアを要する。
STCを決着まで回すと選別だけで3日規模になり、安価な選別という目的が崩れるため、上限を3,000ペアとする。
上限到達による判定保留は、停止時点のLLRが0以上ならLTCへ進め、負なら進めないという規則で振り分ける。
LLRは仮説H1（elo 5）とH0（elo 0）の相対尤度であり、負値は「5 eloの改善という仮説より0 eloに近い」ことを意味し、候補が基準より弱いことの証明ではない。
したがって数elo規模の小さな改善も負側へ振り分けられ得るが、5 elo未満の変更へ長時間の資源を割かないという選別の目的には合致し、測定前に固定された機械的規則なので裁量の余地もない。
判定保留を一律に不通過とする案は、3〜5 elo規模の実在する改善が構造的に選別で止まるため棄却した。
上限なしで決着まで回す案は、境界付近の変更で選別が最終測定より重くなるため棄却した。

### STC省略の条件

時間管理の変更、`Threads`の変更、STCの探索深さでは発火しない機構のように、短時間条件では効果が原理的に現れない変更がある。
時間管理は時計の規模で配分の挙動そのものが変わり、並列化の利得は深い探索でしか累積せず、発火条件に深さを持つ機構はSTCが到達する深さ4〜5では動かないからである。
そのような変更は、省略の理由を測定開始前に設計書へ記録すれば、変更種別を問わずSTCを省略してLTCへ直行できる。
結果を見た後の経路変更は認めない。
省略できる変更種別を限定列挙する案は、列挙外の正当な省略事由を扱えないため採らず、理由の事前記録を歯止めとする。

### 同時対局数の自動計算

同時対局数は、`--concurrency`の省略時に`match_runner`が「物理コア数から1を引き、候補と基準の`Threads`の大きい方で割った商」として計算する。
この式は現行手順の上限則（物理コア数を超えず、OSとハーネス用に1コア以上残す）をそのまま既定値にしたものであり、fishtestワーカーの「コア数−1」と同じ流儀である。
たとえばこの測定機（物理20コア、両エンジン`Threads=1`）では19になり、1コアが残る。
物理コア数または両エンジンの`Threads`が取得できない場合、および計算結果が1未満になる場合は、既定値を推測せずに明示エラーで終了し、`--concurrency`の明示を求める。
`--concurrency`の明示指定は上書きとして残し、解決後の値を`manifest.json`へ記録して再開時の一致検査の対象とする。
旧設計の4点掃引（同時対局数8、12、16、19を各100ペア）は、見込める差が回転率の数%にとどまる一方で測定と判定基準の文書化が重いため廃止する。

### ハーネスへ追加しないもの

STCの振分けに使うLLRは、`match_runner`が標準出力へ出す値を読むだけである。
したがって選別用のモードやスイッチをハーネスへ追加せず、機能比較のスイッチを追加しない原則（docs/sprt.md）を維持する。

## 段階ゲートの手順

通常の探索変更と評価変更は、STCの選別とLTCの最終測定を順に実行する。
各マイルストーンの設計書は、STCから始めるかLTCへ直行するかの経路を、測定開始前に宣言する。
STCとLTCは別の測定として扱い、測定名と実行ディレクトリを段階ごとに分ける（標準コマンドの例は接尾辞`-stc`と`-ltc`で区別する）。

STCの標準コマンドは次のとおりである。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/<測定名>-stc --seed <シード> \
  --candidate commit:<新コミット> --baseline commit:<旧コミット> \
  --each time=10000+100 --max-pairs 3000 gsprt
```

STCの判定は次のとおり扱う。

- `decision: H1`は、候補をLTCへ進める。
- `decision: H0`は、候補を採用しない。
- `decision: pending`は、停止時点のLLRが0以上ならLTCへ進め、負なら進めない。

LTCの標準コマンドは次のとおりである。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/<測定名>-ltc --seed <シード> \
  --candidate commit:<新コミット> --baseline commit:<旧コミット> \
  --each time=60000+600 gsprt
```

LTCのシードは、STCの基本シードからペア数以上離れた未使用の値とする（[隣接シードの教訓](../lessons/derive-seed-adjacent-collision.md)）。
`decision: H1`であり、かつエンジン異常、時間切れ、および拒否着手が0件の場合だけ採用する。
`decision: pending`は、同じ実行ディレクトリを`--resume`で再開し、`--max-pairs`だけを増やして対局列を延長する（docs/sprt.mdの再開手順）。
STCとLTCの結果の合算、シードを変えた再試行、および信頼区間や固定局数Eloによる採用の読み替えは行わない。
同じ着想のパラメータ違いはSTCまでに1つへ絞り、LTCの結果を見て別候補を同じ主張へ追加しない。

## 実装フェーズ

### フェーズ1　設計書の全面改訂

本書を校正方式から段階ゲートの標準化へ書き直し、ファイル名を`match-staged-gate.md`へ改め、被参照文書とROADMAPを更新し、教訓を切り出す。
完了条件は、独立サブエージェントの2段階レビューとcodexのレビューを通過していることである。

### フェーズ2　同時対局数の自動計算

`match_runner`の`--concurrency`を省略可能にし、省略時は物理コア数から計算した値を使い、解決後の値を`manifest.json`へ記録する。
完了条件は、`cargo test`が成功し、明示指定した従来の経路の挙動が変わらず、省略時の計算式、取得不能時の明示エラー、および計算結果が1未満になる境界が単体テストで固定されていることである。

### フェーズ3　標準手順の反映

`docs/sprt.md`の機能採否の節をSTCとLTCの2段階へ書き換え、振分け規則、省略規則、禁止事項、初回測定の停止規則、および同時対局数の既定値を反映する。
改訂は機能採否の節に限らない。
全標準コマンドから`--concurrency`の明示と同時対局数の手計算則を除き、ペア数上限の説明へSTCの3,000ペアが振分け規則である旨を加え、時間制御比較と校正指標の節は標準手順から診断用途へ位置づけ直す。
旧時間制御を機能採否の標準として指す他文書の記述（strength-stages.mdの依存関係節を含む）も、この時点で新標準へ更新する。
完了条件は、`docs/sprt.md`が段階ゲートだけを標準とし、docs/以下に旧標準を機能採否の標準として指す記述が残っていないことである。

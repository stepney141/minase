# 手の順序付け（move ordering）の改善の設計書

## 先に読む要約

本マイルストーンでは、通常探索と静止探索の手の順序付け（move ordering。同じノードの合法手を有望な順に並べて探索する手順）について、損失の所在を測ったうえで1項目ずつ改める。
αβ探索では、良い手を先に読むほどβカット（ある手の結果が相手の許容上限βに達したため、残りの手を読まずに済ませること）が早く起こり、同じ時間でより深く読める。
現行の順序は、置換表（探索済み局面の結果を保存して再利用する表）の記録手、捕獲手、killer手、残りの静かな手の順である。静かな手とは相手の駒を取らない手をいい、killer手は根からの同じ手数のノードで直前にβカットを起こした静かな手をいう。捕獲手はMVV-LVA順（取る駒の価値の降順、取る側の駒の価値の昇順）に捕獲履歴（capture history、捕獲手の成績を学習する表）の補正を加えた順で並び、残りの静かな手はhistory（βカットを起こした静かな手の統計）の降順で並ぶ。
βカットのうち最初に探索した手によるものの割合（初手βカット率）は、現行masterの`bench`で深さ5が66.4%、深さ8が70.1%であり（[move-ordering-baseline-bench](../measurements/move-ordering-baseline-bench.md)）、Chess Programming Wikiが順序付けの目安とする90%超を下回る。
ただしこの割合はβカットを件数で集計するので、βカットの件数の83〜87%を占める残り深さ1のノード（[2026年9月27日の監査](../audits/beta-cutoff-first-move-2026-09-27.md)の値）に支配される。残り深さ1でβカットが遅れたときに失う部分木と、残り深さ5で遅れたときに失う部分木は大きさが違うはずだが、件数の指標はこの差を区別できず、費用の分布はまだ測っていない。
そこで最初のフェーズでは、βカットした手より前に読んだ手の部分木ノード数の和（先行費用W）を残り深さ別・先頭手の種別別に数える診断を入れ、損失の所在をノード数で測る。
候補は8件あり、静かな手がβカットしたときにも探索済み捕獲手の捕獲履歴を減点する変更を先頭に、実装費用が小さい順に1主張1測定で短時間（STC）と長時間（LTC）の自己対局GSPRT（勝敗から強さの差を逐次判定する統計検定）にかける。
完了条件は、診断の結果と8候補の採否（見送りを含む）が記録され、採用した候補の挙動がテストで固定されていることである。

## 状態

起案。2026年10月9日にcodexとの議論（[調査メモ](../research/move-ordering-discussion.md)）を経て起案し、まだ着手していない。次の一手は、利用者の着手の指示を受けてフェーズ1の診断パッチを実装し、現行masterの`bench`深さ6と対局再生で先行費用Wと各候補の発動率を測ることである。

## 目的

本マイルストーンの目的は、順序付けの誤りで無駄に読んでいるノードを減らし、同じ持ち時間でより深く読めるようにすることである。
[棋力向上段階12](strength-stage12.md)では他エンジンの定番の改良7件がいずれも効果を示さず、その後の[再調整](search-revival-spsa.md)で係数を調整し直した3件が採用された。
この経緯は、改良の効果が中将棋の手の構成（1局面の合法手が100手を超え、捕獲手が多い）に依存し、他エンジンの結果からは見積もれないことを示す。
本書では、効果を他エンジンの測定値から見積もるのではなく、minaseの探索で失っているノード数を診断で測ったうえで候補を具体化する。

## 適用範囲

本書は、通常探索の手選択器（`crates/minase/src/search/alphabeta/ordering.rs`の`MovePicker`）、静止探索の捕獲手の群内の順序（`quiesce.rs`）、根の手の順序（`root.rs`）、butterfly historyと捕獲履歴の更新規則と寿命、およびこれらの診断を扱う。
前向き枝刈りの余裕値、LMR（late move reductions。順序付けの後方の静かな手を浅く読む手法）の減深量の式、静止探索の手数制限の値、静的交換評価（SEE。到達升での駒の取り合いを見積もる計算）の算法、評価関数、置換表、時間管理、および合法手の定義は変更しない。
候補が既存の係数と相互作用する場合の係数の再調整は、[SPSAの手引き](../guides/spsa.md)の調整セッションに委ねる。

## 設計判断

| 項目 | 決定 |
|---|---|
| 診断の主指標 | 初手βカット率ではなく、先行費用Wを使う。Wは、βカットしたノードで、カットした手より前に実際に探索した各手について`search_move`の前後のワーカー固有のノード数（`self.nodes`）の差を合計した値であり、減深した探索と読み直しの費用を含む。初手βカット率は件数の指標であり、残り深さ1のノードが件数の8割超を占めるため、1件の損失が静止探索の部分木である場合と、残り深さ5の通常探索の部分木である場合を区別できないからである。Wは祖先と子孫で同じ展開を重複して含み、先行した探索が置換表とhistoryを更新する効果も含むので、全深さの総和をそのまま削減可能なノード数とみなすことはできない。候補の根拠には、残り深さ別の分布と、先頭手の種別別の平均だけを使う。 |
| 診断の分類 | 残り深さは、置換表の記録手がないノードで残り深さを1減らす減深（internal iterative reduction）を適用した後の値で、1、2、3、4以上に分ける。残り深さ3以下は零窓（幅1の窓、`β = α + 1`）のノードで枝刈りが働く範囲なので1ずつ分け、4以上は枝刈りが働かないのでまとめる。先頭手は、置換表の記録手、捕獲手、killer手、その他の静かな手に分ける。捕獲手が先頭のノードでは、その手の`see_prunes(…, 0)`の結果で「負」と「負と確定しない」に分ける。「負、非負、判定不能」の3分類にしないのは、`see_prunes`が真偽値しか返さず、偽には非負と判定不能の両方が含まれるからである。カット手の種別、βカットしなかったノードの数、および捕獲段で終わり静かな手を生成しなかったノードの数を分母として併せて数える。 |
| 診断の実施方法 | 診断は1本の`search-stats`パッチで行い、候補1から7の発動率をその1本で数える。1回の探索で完結する項目は`bench`の深さ6で、表の持ち越しに依存する候補4と候補6は保存済みの対局の着手列に沿った再生で数える。`bench`は局面ごとに置換表とhistory表を消すので、持ち越しの効果を見られないからである。再生では、持ち越す表と根ごとに初期化する影の表の2組を同じ探索の観測で更新し、順序を決める時点で両方の表から順序を求めて比べる。計数はワーカーごとに保持し、診断パッチを当てても固定深さの総ノード数と探索結果が変わらないことを確かめる。速度は診断コードを外した構成で測り、追加のSEEや影の表を含む診断版のNPSを候補の費用とみなさない。 |
| 候補の順序 | 候補1（捕獲履歴の減点の拡張）、候補2（先頭捕獲のSEE判定によるkiller手の前置）、候補3（静止探索への捕獲履歴）、候補4（捕獲履歴の持ち越し）、候補5（静かな手の同点破り）、候補6（counter move historyとcontinuation historyの再診断）、候補7（根の整列）、候補8（malusの再測定）の順に進める。順位は実装費用と既存の土台で決めた。候補1は探索済み捕獲手の列と表が既にあり、新しいSEEも手生成も要らない。候補2は追加のSEEがノードあたり最大1回で済む。候補3と候補4は候補1で確定した捕獲履歴の更新規則を前提にするので、その後に置く。候補6は表2枚で約70 MBを使い、診断を通っても表の大きさと初期化の費用の設計が別に必要になる。候補7と候補8は効果の根拠が最も薄い。効果の大きさの順ではない。 |
| 候補の単位 | 1候補を1主張とし、1回のSTCと1回のLTCで判定する。候補1、2、3は同じ捕獲手の順序に関わるが、変える機構（学習の情報、捕獲とkillerの順、静止探索の群内の順）と費用が異なるので、まとめない。まとめると1回の測定で分かるのは組合せ全体の効果だけであり、どの項目が効いたかを特定するには各項目を1つずつ外した版との比較が必要になるからである。対象深さ、SEEの走査範囲、減点の尺度、群内の比較キーなどの変種は、STCの開始前に診断で1つへ絞り、STCの結果を見てから変えない。 |
| 基準と採否 | 各候補は直前に採用した構成を基準に、1候補1コミットで測る。直前の採用構成を基準にするのは、候補が実際に組み込まれる構成でその候補だけの寄与を測るためである。STCで`H1`、または上限3,000ペアでLLRが0以上ならLTCへ進め、LTCが`H1`かつ異常0件なら採用する。不採用の候補はコードから外し、次の候補の基準は直前に採用した構成のままとする。STCを省略してLTCへ直行する候補はない。 |
| 発動の事前確認 | 各候補は、実装前の診断で発動率（同じ判断の時点で現行と候補の判断を並べて比べ、判断が変わった割合）が5%以上であることを確かめる。5%は段階5以降の探索の設計書が発動の事前確認に使ってきた基準であり、分母と分子は候補ごとに各論の節で定める。発動率だけでは進める根拠にならない候補には、各論の節で追加の条件を定める。候補2では回避できる先行費用が追加のSEEと静かな手の生成の費用を上回ること、候補5では同点群の成功手の順位が改善すること、候補7では前回反復の情報によって新しい最善手の順位が改善することを条件とする。値の非ゼロ率のような指標は補助として記録するが、判定には使わない。基準に届かない候補は見送りを提案し、対局で測るかどうかは利用者が決める。 |
| 過去の不採用との関係 | 候補2は、段階12の項目2（全捕獲手のSEEを生成時に計算し、負の捕獲手を静かな手の後ろへ回す段、STC `H0`）の狭い変種であり、再測定として扱う。項目2の敗因が追加のSEEの費用（NPS約−9.7%）か順序の変更そのものかは記録から判定できないので、候補2では費用を最大1回のSEEに抑え、負の捕獲手はkiller手の後ろ、静かな手の前に置く。候補8は段階5のmalus（STC上限到達時のLLR −1.58）の再測定であり、教訓に従って係数を既存の係数と調整し直してから判定する。候補6は段階12が「項目5を採用した場合」に定めた再診断であり、持ち越しが再調整で採用されたので条件が成立している。 |
| 新しい係数 | 候補1、候補2、候補3、候補5は係数を追加しない。候補4の減衰率は`params.rs`に置き、採否測定の中では動かさず、採用後に次のSPSAの調整セッションで調整する。係数ごとにGSPRTで候補値を比べると1件のLTCに数十時間を要するからである。候補8だけは例外とし、教訓に従って加点と減点の尺度を既存の係数とまとめてSPSAで調整してから、確定した値でSTCとLTCにかける。 |
| 規則依存の除外 | 最後の王駒を取る手と、獅子が1手で2枚を取る手は、順序の後回しの対象から外す。SEEが規則上判定不能の捕獲手は、段階8と同じく損と判定しない側に置く。 |
| 並列探索 | 既定の`Threads=1`で判定する。表はワーカーごとに持ち、持ち越しもワーカーの番号ごとに行う。 |
| 診断コードの扱い | 診断の計測は`bench`と再生ツールへの一時的な変更で行い、コードは残さない。差分は測定記録の付属ディレクトリへ保存する。 |
| 未採用コードの扱い | 不採用または見送りとなった候補はコードに残さず、設計だけを本書に保持する。 |

## 診断の定義

フェーズ1の診断パッチは、次の項目を数える。
1から5は`bench`深さ6で、6と7は対局再生で数える。
以下で影の表とは、候補の更新規則に従って同じ探索の観測から更新するが、探索の判断には使わない表をいう。現行の表と並べて保持し、「同じ時点で候補ならどう判断したか」を数えるために置く。
後続ノードとは、同じ探索でその観測より後に訪れるノードをいう。

1. βカットしたノードごとの先行費用W。残り深さ（1、2、3、4以上）×先頭手の種別（置換表の記録手、SEE負の捕獲手、負と確定しない捕獲手、killer手、静かな手）で件数と合計を集計する。併せて、βカットしなかったノードの数、カット手の種別の分布、捕獲段で終わり静かな手を生成しなかったノードの数、および先頭の捕獲手単独の部分木ノード数を数える。「ノードの先頭」と「置換表の記録手の後に来る捕獲段の先頭」は区別する。
2. 候補1の発動率。判定に使う発動率は、置換表の記録手を除いた捕獲手が2手以上ある捕獲段のうち、減点を加えた影の表の値で並べると順序が現行と変わる段の割合とする。補助として、静かな手がβカットしたノードのうち先に探索した捕獲手が1手以上あるノードの割合（更新の機会率）と、観測されたカット手の順位が現行の順序と影の表の順序とで何位ずれるかを記録する。
3. 候補2の発動率。零窓ノードを残り深さ（1、2、3）と置換表の記録手の有無で分け、それぞれについて、捕獲段の先頭が`see_prunes(…, 0)`で負であり、かつ合法なkiller手が1手以上あるノードの割合を数える。併せて、その先頭の捕獲手単独の部分木ノード数と、現行では捕獲段でカットして静かな手を生成しなかったノードの割合を記録する。killer手の合法性の確認には診断専用の生成領域を使い、本番の手選択器の状態（`quiets_generated`など）を変えない。
4. 候補3の発動率。静止探索の各ノードで、置換表の記録手を除いた捕獲手が2手以上ある捕獲価値の群の割合と、群内の比較キーを候補の「捕獲履歴の生の値の降順、取る側の駒の価値の昇順、生成順」に変えたときに先頭が変わる群の割合を数える。併せて、探索する捕獲手の集合の差を次の手順で数える。ノードに入った時点のαを固定し、現行の順序と候補の順序のそれぞれについて、置換表の記録手の重複除外、delta pruning、SEE pruningを現行の規則で適用しながら、`QsearchMoveLimit`（現行4）の枠（最後の王駒の捕獲、直前の捕獲への取り返し、獅子の2枚取りの例外を含む）に入る捕獲手の集合を求め、その集合が両者で異なるノードの割合を求める。
5. 候補5の発動率。静かな手の段で、history値が同じ手の群の大きさの分布と、その群からカット手またはαを上げた手が出た回数を数える。併せて、段の整列時点（探索結果でhistoryを更新する前）に現行の順位とPST（piece-square table、駒と升ごとの評価値の表）の差分で並べ直した順位の両方を保存し、カット手またはαを上げた手について「現行の順位−候補の順位」の分布（前進した件数、後退した件数、移動幅）を記録する。
6. 候補4の発動率。対局再生で、持ち越す捕獲履歴と根ごとに初期化する影の表を同じ観測で更新し、置換表の記録手を除いた捕獲手が2手以上ある捕獲段のうち両者で順序が異なる段の割合と、観測されたカット手の順位の差を数える。持ち越す診断状態は`Searcher`の中ではなくワーカーごとに探索の外で保持し、初期化、減衰、および受け渡しはbutterfly historyと同じ時点で行う。
7. 候補6の発動率。対局再生で、持ち越すcounter move historyとcontinuation historyの影の表を表ごとに更新し、静かな手の順序付けで表の値が0でない手の割合と、順序が変わるノードの割合を表ごとに数える。参照に必要な「plyごとに動かした駒種と到達升」の記録と、null moveでそのplyの記録を空にする扱いは、[段階5](strength-stage5.md)の設計を診断用に復元する。診断状態の保持は項目6と同じである。

候補7の診断は時間制御の根の反復で行い、深さ別の最善手の交替率、交替した反復のノード数が全反復に占める割合、新しい最善手の前回反復での順位と前回反復の部分木ノード数で並べた場合の順位、および零窓から全窓への読み直しの費用を記録する。
候補8の診断では、影のhistory表に減点を加えたことによる順序の差と、`lmr_reduction`の減深量が変わる手の割合とを別々に数える。

## 各候補

### 候補1　静かな手のβカット時の捕獲履歴の減点（capture history malus）

現行の捕獲履歴は、捕獲手がβカットを起こしたときに、その手へ加点し同じノードで先に探索した捕獲手を減点する。
静かな手がβカットを起こしたノードでは、先に探索した捕獲手を減点しない。
「捕獲段を読み終えて静かな手がカットした」という観測は、先に読んだ捕獲手が有望でなかったことを示すので、本候補はこの場合にも探索済み捕獲手を減点する。
Stockfishは、最善手の種別によらず探索済みの捕獲手を減点する（参考資料の`search.cpp` 2028〜2034行）。
減点の大きさは現行の`record_cutoff`と同じ`min(depth², 上限)`とし、尺度を変える係数は持たない。
本候補の狙いは、繰り返し失敗する捕獲手の順位を捕獲段の中で下げることであり、静かな手より後ろへ移すものではない。

発動率は「診断の定義」の項目2のとおり、捕獲手が2手以上ある捕獲段のうち影の表で順序が変わる段の割合とし、5%未満なら見送る。
更新の機会率は補助として記録する。

### 候補2　先頭の捕獲手のSEE判定によるkiller手の前置（killers before losing captures）

現行の`negamax`は、手のループの最初の手を枝刈りしない。
置換表の記録手がなく捕獲手があるノードでは、最初の手がMVV-LVA先頭の捕獲手であり、その手がSEEで負でも必ず読まれる。
本候補では、置換表の記録手を返した後に捕獲段の先頭の1手だけを`see_prunes(…, 0)`で判定し、負であれば合法なkiller手2手を先に返してから、元の捕獲列（先頭の負の捕獲手を含む）と残りの静かな手へ進む。
killer手を負の捕獲手より先に置くのは、同じ手数の近いノードでβカットを起こした静かな手の方が、損をする取り合いよりβカットを起こしやすいと見込むからである。
追加のSEEはノードあたり最大1回である。
killer手の合法性は、現行と同じく静かな手の生成結果との照合で確かめるので、捕獲段の先頭が負のノードでは静かな手の生成が前倒しになる。
現行で捕獲段のうちにカットするノードでは、この生成が追加の費用になる。

段階12の項目2との差は、SEEを全捕獲手ではなく先頭の1手だけに計算すること、負の捕獲手を静かな手の後ろではなくkiller手の後ろに置くこと、および対象を置換表の記録手がない残り深さ1の零窓ノードに限る変種を診断で比べることである。
監査でkiller手が先頭のノードの初手βカット率が96〜98%だったことは、母集団（置換表の記録手も捕獲手もないノード）が本候補の対象と異なるので、成功率の根拠にしない。

発動率の分母は置換表の記録手がない零窓ノード、分子は捕獲段の先頭が負で合法なkiller手があるノードとし、残り深さ別に数える。
対象を残り深さ3以下の零窓ノード全体にする変種と残り深さ1に限る変種は、残り深さ別の発動率と先行費用Wの分布を見て診断の段階で1つに絞る。
進める条件は、対象ノードで回避できる見込みの先行費用（先頭の負の捕獲手単独の部分木ノード数の合計）が、追加のSEEと静かな手の生成の前倒しの費用を上回ることである。

### 候補3　静止探索の群内の順序への捕獲履歴の適用（capture history in quiescence ordering）

静止探索は、取る駒の価値のランク群ごとに捕獲手を遅延生成し、群内を取る側の駒の価値の昇順で返す。
`QsearchMoveLimit`（現行4）は実際に読んだ捕獲手を数えるので、群内の順序がどの捕獲手を読むかを決める。
本候補では、群の生成時に各捕獲手の捕獲履歴の生の値（`adjustment`による歩兵価値への換算を経ない値）を保存し、群内の比較キーを「捕獲履歴の降順、取る側の駒の価値の昇順、生成順」に変更する。
群の構造は保つので、価値の高い駒を取る手が先に来る性質は変わらない。
表引きは群の生成時に候補ごとに1回とし、整列の比較の中で表を引かない。

通常探索で学んだ履歴が静止探索でも有効かは未検証である。
発動率の分母は置換表の記録手を除いた捕獲手が2手以上ある群、分子は捕獲履歴で先頭が変わる群とする。
読む集合が変わるノードの割合も「診断の定義」の項目4の手順で記録する。
実装後、STCの前に、無作為に抽出した局面で候補と現行を同じノード予算で探索し、根の評価値と最善手をより深い参照探索と比べて、候補の誤差が現行より悪化していないことを確かめる。
静止探索は再帰するので、1ノードで失う良い結果の割合が小さくても損失が深さ方向に積み重なる。段階12の静止探索の手数制限（`N=1`）は局所の指標では小さな損失だったがSTCで約−173 Eloと大敗した（[教訓](../lessons/recall-loss-does-not-bound-recursive-pruning.md)）ので、発動率と参照比較を満たしても採否は自己対局だけで判定する。

### 候補4　捕獲履歴の持ち越し（capture history aging）

現行はbutterfly historyを根の探索ごとに`HistoryDecay`だけ残して持ち越す一方、捕獲履歴は探索ごとに初期化する。
本候補は、捕獲履歴をbutterfly historyと同じ経路で受け渡し、同じ時点で初期化し、根ごとに減衰させる。
表は現行の要素型で約0.97 MBであり、根ごとの減衰ではこの表全体を走査する。
減衰率は`HistoryDecay`とは別の係数とする。初期値を選ぶ根拠が診断からは得られないので、`HistoryDecay`と同じ値から始め、採用後にSPSAで調整する。

発動率は対局再生で数え、分母は置換表の記録手を除いた捕獲手が2手以上ある捕獲段、分子は持ち越し表と初期化表で順序が異なる段とする。

### 候補5　静かな手の同点破り（PST-delta tiebreak）

静かな手はhistory値の降順で並び、同点は生成順（駒種の順、次に升の順）である。
[段階8](strength-stage8.md)の起案時の`bench`では、浅い非PVノード（PVは最善応手列principal variationの略で、非PVノードは零窓で読むノード）で枝刈りを検査する静かな手の90.3%がhistory 0だった。この値はhistoryの持ち越しを採用する前のものであり、現行の値はフェーズ1で測り直す。
本候補は、同点の手を、PST差分（その駒の到達升のPSTの値から移動元の升のPSTの値を引いた差。成る手は到達升を成り後の駒の表で引く）の降順で並べる。
PST差分は既存の重みの定数時間の参照で求まるが、成る手は成り後の駒の表を引き、序中盤と終盤の補間を現行の評価と同じ規則で行う必要があり、費用はゼロではない。
FM（factorization machine、2駒関係の評価補正）の項は含めない。
late move pruningは静かな手の順位に基づいて読む手を制限するので、同点破りは探索量だけでなく、どの手を読むかの選択にも影響する。

発動率の分母は静かな手の段を開いたノード、分子はPST差分で先頭の静かな手が変わるノードとする。
進める条件は、発動率に加えて、同点群から出たカット手またはαを上げた手の「現行の順位−候補の順位」の分布で、前進の件数と幅が後退を上回ることである。

### 候補6　counter move historyとcontinuation historyの再診断

段階5では、直前の相手の手に対する応手の統計（counter move history）と、2手前の自分の手との組合せの統計（continuation history）について、根ごとに初期化する表では非ゼロ参照率（静かな手の順序付けで表の値が0でない手の割合）が0.73%と0.62%と低かったため、見送った。
段階12は、表の持ち越しを採用した場合に持ち越し状態で再診断すると定めた。
その後、再調整で持ち越しが採用されたので、本候補ではこの再診断を行う。
表は段階5の設計（添字は駒種29×升144×駒種29×升144で約1,744万要素、要素は`i16`で1表約35 MB、2表で約70 MB）のままとし、減衰率は診断のために`HistoryDecay`と同じ値から始める。
診断を通っても、本書では実装しない。
表の寸法と初期化の費用を含めた設計を別の設計書として起こす。

発動率の分母は静かな手の段を開いたノード、分子は表の値で順序が変わるノードとする。
非ゼロ参照率は補助として記録する。

### 候補7　根の手の前回反復の情報による整列（root move ordering）

根では、手を通常の順序付けキーで整列したうえで置換表の記録手を先頭に置き、さらに直前の反復の最善手をその前に置く。
2手目以降の手は零窓で読み、値がαを超えてβを下回れば全窓で読み直す。
順序の効果として最も大きいと見込むのは、最善手が交替する反復で新しい最善手を早く見つけてαを上げ、残りの零窓探索のノード数を抑えることである。先に読んだ部分木が置換表とhistoryを更新する効果は他の反復にもあり得るが、本候補の診断は交替する反復の利得を優先して測る。
旧版の診断では、直前の反復と最善手が異なる反復の割合は深さ5から8で33.3%、33.8%、32.1%、27.9%だった（[strength-stage6-iteration-diag](../measurements/strength-stage6-iteration-diag.md)）。
本候補は、直前の最善手を先頭に保ち、残りの手を前回反復の各手の部分木ノード数の降順で並べる。
零窓で得た値は上界または下界であり正確な評価値ではないので、評価値では並べない。部分木ノード数は前回反復で実際に払った探索量であり、値の種類を区別せずに使える。

診断は時間制御の根の反復で行い、最善手が交替した反復のノード数が全反復のノード数に占める割合と、新しい最善手の現行の順位および前回反復の部分木ノード数で並べた場合の順位を記録する。
進める条件は、交替した反復のノード比が5%以上であり、かつ部分木ノード数による順位が現行の順位より新しい最善手を前に置くことである。

### 候補8　malusの再測定（history malus）

段階5のmalusは、βカットを起こした静かな手に加点し、同じノードで先に探索した静かな手に同じ大きさを減点し、更新式を`v += bonus − v · |bonus| / 上限`に改めるものだった。
STCは上限3,000ペアでLLR −1.58の判定保留となり不採用になった。
当時のLMRは固定減深であり、history値を参照していなかったので、不採用の原因が減深の変化にあったとは言えない。
現行へ再導入すると、負のhistory値が`lmr_reduction`の減深を1増やす経路が新たに動く。
本候補は、加点と減点の尺度を別の係数にし、順序の変更、更新式、および減深への影響を診断で分けて測ったうえで、係数を既存の係数とまとめてSPSAで調整し、確定した値でSTCとLTCにかける。
Stockfishは加点と減点を、それぞれ上限付きの深さの一次式に補正を加えた別の値で決める（参考資料の`search.cpp` 1995〜1997行）。

診断は影のhistory表で順序の差と減深量の変更率を別々に数え、順序の改善がなく減深の変更しか根拠がなければ、順序付けの候補としては進めない。

## 測定の所要時間

段階8の実績（同時対局数16）では、STCが1ペアあたり約9.5秒、LTCが約27秒であり、`H1`に達した測定はSTCが約420〜500ペア（約1.1〜1.3時間）、LTCが約720〜830ペア（約5.5〜6.2時間）であった（[SEE pruningのLTC](../measurements/strength-stage8-see-capture-ltc.md)、[補正表のLTC](../measurements/strength-stage8-correction-ltc.md)）。
段階5のmalusのSTCは、上限の3,000ペアに達するまで約8時間を要した（同時対局数14、[strength-stage5-malus-stc](../measurements/strength-stage5-malus-stc.md)）。
現行の評価関数はFMの補正で約14%遅いので、同じペア数でも時間は段階8よりやや長くなる。
したがって、1候補が明確な効果を持てばSTCとLTCで約7時間、STCで早く`H0`となれば2時間程度、上限まで走る判定保留では8時間を超える。
真の差が5 Elo前後の候補は、LTCだけで約32時間になり得る。
8候補の合計は約1日から2週間の幅を持つので、長時間の測定に入る前に候補ごとにこの見積りを示して進め方を確認する。

## 実装フェーズ

### フェーズ1　診断

現行masterへ診断パッチを当て、「診断の定義」の項目1から5を`bench`深さ6で、6と7を対局再生で数える。
対局再生は、直近のLTCの保存記録からSTC相当20局とLTC相当10局を固定したシードで無作為に選び、各局の初手から最終手まで、その手までの着手列を与えて`go nodes`で探索し、`usinewgame`の後は1プロセスで表を保持する。1手のノード数は、その記録の思考時間の中央値に現行の`bench`のNPSを掛けて決める。段階12の再生スクリプトは診断の出力形式を固定しているので、新しい統計の出力に合わせて改める。
診断パッチを当てても探索が変わらないことは、固定深さの`bench`に加えて、同じ着手列の固定ノードの再生でも結果の一致で確かめる。
結果は測定記録`move-ordering-diag`へ残し、見送る候補と、候補2の対象深さの変種を本書に反映する。
後のフェーズの候補は、直前に採用した構成で発動率を測り直してから実装する。

### フェーズ2から9　候補ごとの実装と採否測定

候補1から候補8を、設計判断の順に1フェーズ1候補で進める。
各フェーズでは、実装、テスト、発動率の確認、STC、およびLTCの順に進め、測定記録を`move-ordering-<候補名>-stc`と`-ltc`の名前で残す。
候補6は再診断だけを行い、実装と採否測定は別の設計書に委ねる。
不採用の候補はコードから外す。

### フェーズ10　進捗指標の記録

採用した候補が1つ以上あれば、最終構成について、段階開始版との固定200ペアのElo（`move-ordering-elo200`）を[棋力向上の段階計画](strength-stages.md)の検証の節の条件で記録する。
採用した候補がなければ測らない。

## 検証

- 診断パッチを当てた構成が、当てない構成と固定深さの総ノード数および根の最善手と評価値で一致することを、`bench`の全局面で確かめる。
- 手選択器が各合法手を正確に1回だけ返すことを、候補2の順序変更を含めて既存のテストで固定する。
- 候補1の減点、候補3の群内の比較キー、候補4の持ち越しと減衰、候補5の同点破りは、それぞれ単体テストで更新式と順序を固定する。
- 候補4の持ち越しは、置換表を初期化する時点（新規対局、受理された規則変更、受理された`USI_Hash`の変更）とワーカー数の変更で捕獲履歴も初期化されることをテストで固定する。
- 各候補は、実装直後に`bench`深さ6の総ノード数とNPSを記録し、NPSは診断コードを含まない構成で測る。
- 採否測定では、エンジン異常、時間切れ、および拒否着手が0件であることを確かめる。

## 完了条件

- フェーズ1の診断が測定記録に残り、各候補を進めるか見送るかの判断が、測定記録へのリンクとともに本書に書かれている。
- 候補1から8の採否（見送りを含む）が記録され、不採用の候補のコードが外されている。
- 採用した候補の更新規則と順序がテストで固定され、`params.rs`の新しい係数が[SPSAの設計書](spsa.md)の係数表に載っている。
- 採用した候補がある場合、段階開始版との固定200ペアのEloが記録されている。

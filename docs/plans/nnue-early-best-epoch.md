# NNUEの検証損失が早く頭打ちになる原因の切り分けの設計書

## 先に読む要約

中将棋エンジンminaseの評価関数NNUEは、自己対局で生成した教師データ（約22万局、約8,300万局面）から学習する。
学習に使わない約1万1千局の局面での損失（検証損失）は、学習の早い段階で約0.4489に達し、以後は訓練損失だけが下がる。
学習率を1/10にすると、最良になるエポックは10まで遅れるが、最良の検証損失はほぼ同じ値で止まる。したがって問題は「何エポック目で最良になるか」ではなく、「検証損失が学習の条件によらず同じ所で頭打ちになること」である。
[分割の検査](../measurements/nnue-validation-split-check.md)では、訓練と検証の分割、局面の重複、および両集合の分布に不具合はなかった。そのため、ネットが訓練に使った対局の癖を覚え、ほかの対局へ一般化しなくなること（過剰適合）が頭打ちの原因と見ている。
本書は、教師の側の3つの要因を調べる。
1つ目は、同じ対局の後続40手の探索値を教師値に混ぜる先読み教師（TD(λ)に似た目標値）が、対局ごとの癖を覚えやすくしているという仮説である。これは、先読みを外して学んだネットとの比較で調べる。
2つ目は、独立な単位である対局の数が少ないことが効いているという仮説である。これは、同じ局面数で「少数の対局から全局面」と「多数の対局から疎に」を比べる間引き（subsampling）の学習で調べる。
3つ目として、勝敗がほぼ決まった局面が教師の大半を占める状況を、既存データの集計で定量化する。
先読みを外したネットは採用の候補にもなるので、通常の段階ゲート（短時間STCで選別し長時間LTCで判定する時間制御のGSPRT）で採否を決める。
完了条件は、2つの仮説に事前に定めた基準で「支持」「不支持」「判定不能」のいずれかの結論が付き、集計の結果が測定記録にまとまり、先読みなしのネットの採否が決まっていることである。

## 目的

NNUEの学習が早く頭打ちになる現象は、[NNUEの完全代替](archived/nnue-replacement.md)の初代のネットから続いている。
[学習率スケジュール](archived/nnue-lr-schedule.md)は、cosine annealingで最良のエポックを1から3へ遅らせ、最良の検証損失を0.4490365から0.4489074へ下げた。
しかし、同じ記録で学習率を一定の1/10倍にした学習は、エポック10で最良となり、その検証損失は0.4489338だった（[学習の記録](../measurements/nnue-lr-schedule-training.md)）。
学習率の与え方を変えても、検証損失はほぼ同じ値で止まっている。
現行の埋め込みネットD0bは、補助損失を外して同じcosineで学んだもので、エポック2で最良となった（0.4488929）。
その後、[HalfKP-hm-b8の再学習](../measurements/halfkp-retrain-stc.md)は、パラメータの多い入力特徴集合ほど訓練と検証の差が大きく出ることと、対局での大差の負けを示した。
利用者は、エポック1で学習しきれることは通常ありえず、モデル、教師、または学習の手順のどこかに問題があると指摘した。

本書の目的は、頭打ちの原因を教師の側の要因に切り分け、教師の作り方を直す次の計画に根拠を与えることである。
先読みを外したネットは、それ自体が採用の候補にもなるので、段階ゲートで採否を決める。

本書で使う語を次のように定める。

- **教師値**は、各局面の学習の目標である。本書の学習はすべて対局結果を混ぜない（λ=1.0）ので、教師値は探索値を教師の勝率尺度でロジスティック関数にかけた確率である。
- **先読み教師**は、局面tの探索値を、同じ対局のt+1手からt+40手までに記録された局面（除外の印がないもの）の探索値について、局面tの手番側の視点へそろえて減衰率0.9で加重平均した値に置き換えた教師値である。局面t自身の探索値は平均に含まず、窓に記録がなければ元の探索値を使う（`compute_lookahead`のdocコメント、[ADR](../adr/use-lookahead-teacher-values.md)）。**先読みなしの教師**は、局面tの探索値をそのまま使う教師値である。教師データMNSDに記録されているのは素の探索値だけであり、先読みは学習器が読み込むときに計算する。
- **結果の目標**は、対局の結果を手番側から見た値（勝ち1、引き分け0.5、負け0）である。どの教師で学んだネットにも共通の目標として、比較に使う。
- **結果の損失**は、ネットの評価値をそのネットの勝率尺度でロジスティック関数にかけた確率と、結果の目標との二値交差エントロピーである。
- **汎化差**は、あるネットの「検証の結果の損失−訓練の結果の損失」である。値が大きいほど、訓練の対局の結果をよく当てる一方で、ほかの対局には当てはまらない。比べる2つのネットに共通の基準として、データを学習していないエポック0のネット（PSTの初期値だけを持つ）の汎化差も記録する。
- **損失の下限**は、教師の確率そのものの二値エントロピーの平均であり、**下限からの超過**は、損失から下限を引いた値である。
- **決着局面**は、素の探索値の絶対値が大きく、勝敗がほぼ決まった局面である。区切りは「決着局面の集計」の節で定める。
- **D0b**は、現行の埋め込みネットと、それを作った学習の条件を指し（[学習の記録](../measurements/nnue-hidden-layer-training.md)）、本書の学習の基準になる。

## 適用範囲

本書で行う作業は次のとおりである。

- 既存の30ファイルの教師を探索値の区間に分け、区間ごとの局面の割合、教師の確率、対局結果、およびエポック0とD0bの下限からの超過を集計する。
- 先読みを外した学習を2本行う。1本は、教師の勝率尺度を先読みなしの探索値から推定し直すもの（採用の候補）、もう1本は、教師の勝率尺度をD0bと同じ値に固定するもの（先読みの効果だけを見る対照）である。
- これらのネットとD0bについて、汎化差と検証の結果の損失を対局単位のブートストラップによる信頼区間つきで求め、事前に定めた基準で判定する。
- 採用の候補を、現行のmasterと段階ゲートで比べ、採否を決める。
- 学習器に、訓練集合を対局単位または局面単位で間引く引数`--train-subsample`を加え、同じ局面数で「少数の対局から全局面」と「多数の対局から疎に」を、抽出の組を変えて4本ずつ学んで比べる。

次の事項は対象外とし、本書の結論を見て別の設計書で起案する。

- 教師データの作り方の変更（1局から記録する局面の間引き、決着局面の除外や重みの変更、先読みの式の変更、生成時のノード数）。
- 教師の対局数を増やすための生成（[vast.aiでの教師生成](vast-selfplay.md)など）。
- 2つの仮説で頭打ちを説明できなかった場合の、モデルと最適化の対照（D0bの条件から学習率だけを下げる、重み減衰だけを強める、幅だけを減らす）。どれも既存の引数で実施できる。
- 先読みなしの教師での間引きの比較。2つの仮説がともに支持された場合に、両者が独立かを確かめる追加の実験として起案する。
- HalfKP-hm-b8などの入力特徴集合の比較のやり直し。
- `minase match run`が物理コア数を誤判定する件の修正。本書の測定では同時対局数を明示する。

## 依存関係

教師データは[学習率スケジュール](archived/nnue-lr-schedule.md)で再生成した30ファイル（`data/nnue-lr-schedule-gen/generated-*.bin`）であり、D0bと同じものを使う。
学習器はmasterの`minase-trainer`である。`--buckets 1`の学習はD0bの学習器とビット単位で同じ結果を出す経路であり（[一様シャッフル](archived/out-of-core-shuffle.md)）、その後の学習器の変更も照合の記録では計算値を変えていない。
本書の学習の前に、フェーズ2の冒頭でD0bのコマンドをそのまま実行し、`nnue.bin`のSHA-256が`046be0e6…`に一致することを確かめる。保存したネットの検証損失を再現するだけでは順伝播しか確かめられず、更新の処理が変わっていないことは示せないからである。

集計とブートストラップは、[分割の検査](../measurements/nnue-validation-split-check.md)で学習器の規則を移植した使い捨てのプログラムを拡張して行う。
このプログラムは、学習器の局面数と3つのネットの検証損失を再現している。リポジトリには含めず、ソースを`data/nnue-early-best-epoch/tools/`に出力とともに保存する。

測定機（Intel Core Ultra 7 265KF、20コア、RTX 3060 Ti）では、[NNUEに合わせた探索係数のSPSA](nnue-search-spsa.md)が動いており、その後も同計画の段階ゲートが続く。
本書の学習はGPUで行い、`systemd-run`のscope（nice値19、CPUスレッド4本、メモリ上限12 GB）で動かして、SPSAの対局への影響を抑える。
段階ゲートは、ryzen0（Threadripper 2990WX、物理32コア）で行い、同時対局数は`--concurrency 30`と明示する。対局を進める`minase match run`は、自動ではこのCPUの物理コア数を8と判定し、同時対局数を7にするからである（[HalfKPの再学習の記録](../measurements/halfkp-retrain-stc.md)）。
本書のSTCとLTCは、時間制御の条件を揃えるため、すべてryzen0で行う。

## 設計判断

| 項目 | 決定 | 棄却した代案 |
|---|---|---|
| 問いの立て方 | 最良のエポックではなく、検証損失の頭打ちと訓練の対局への適合を問う。最良のエポックと更新回数ごとの検証損失（`--validation-interval`）は参考として記録するにとどめ、判定には使わない。 | 最良のエポックが後ろへずれることを判定に使う案は、学習率の与え方だけで最良のエポックが1から10まで動くので（「目的」参照）、過剰適合の変化を表さない。 |
| 教師が異なる学習の比べ方 | 結果の目標という共通の目標で比べ、汎化差と検証の結果の損失を主指標とする。補助として、各ネットを両方の教師（先読みあり、なし）でも評価した交差表と、訓練と検証の下限からの超過の実数を記録する。 | 各学習がそれぞれ使った教師での「検証の超過÷訓練の超過」の比を主指標にする案は、分母の訓練の超過が教師の予測しにくさや学習不足でも変わるので、過剰適合の変化と区別できない。検証損失をそのまま比べる案は、教師ごとに下限が違うので意味を持たない。学習器が記録する符号一致率（`sign_accuracy`）は、引き分けを除き、局面単位で集計するので手数の長い対局ほど影響が大きくなる指標であり、補助として探索値の区間別に記録するにとどめる。 |
| 先読みの効果の分離 | 先読みを外す学習を2本行う。教師の勝率尺度を推定し直す学習（候補）と、尺度をD0bの値（`config.json`に記録された1007.4941198261047センチポーン）に固定する学習（対照）である。対照は、先読みなしの条件で`minase-trainer data calibrate`が書いた較正ファイルを写し、`teacher_cp_per_logit`の値だけをD0bの値に書き換えた専用のファイルを渡す。較正ファイルの照合は分類の6属性だけで行われ、値を推定し直して比べる処理はないので、この方法で学習できる。ファイルの内容は学習の`config.json`に保存され、再開時の照合に使われるので、学習の途中では変更しない。仮説の判定には対照を使い、候補は段階ゲートに出す。 | 尺度を推定し直す1本だけにする案は、先読みを外す効果と、確率の尺度を変える効果が混ざる。先読みの窓を短くする案（n=10など）は効果が中間的になり、判定がぼやける。先読みに局面自身の探索値を含める案は、教師の作り方の変更であり、本書の結論を見て別に起案する。 |
| 信頼区間 | 対局を単位とする対応のあるブートストラップで、モデル間の差の95%区間を求める。訓練の対局（[分割の検査](../measurements/nnue-validation-split-check.md)と同じく10局面ごとに抽出した局面を持つ対局）と検証の対局をそれぞれ復元抽出し、各回の同じ抽出をすべてのネットに当てる。損失は、抽出した対局の局面の損失の合計を局面数の合計で割った局面加重の平均とし、1,000回の分位点で区間を求める（シード固定）。評価するのは各学習が書き出した最良の重み（`nnue.bin`）である。この区間は、固定したネットの評価標本による変動だけを扱い、学び直しによる変動と、検証集合で最良のエポックを選んだことの影響は含まない。 | 局面を単位とする区間は、同じ対局の局面の相関を無視して狭すぎる。学び直しの反復と、選択用と評価用の対局の分離を設ける案は、学習の本数が数倍になる。 |
| 先読みなしのネットの段階ゲート | 学習の結果にかかわらず、候補を通常の段階ゲートに出す。代理指標だけで見送らず、強さを対局で確かめる。 | 汎化差がD0bより大きければ見送る案は、代理指標で採否を決めることになる。 |
| 段階ゲートの前の診断 | [学習の手引き](../guides/nnue-training.md)の「学習した重みを診断する」の3つの診断（評価値の分布、駒除去差分、合法手の評価差）と量子化誤差の検査を候補に行い、計算経路の不一致のような実装上の失敗があれば段階ゲートへ進まない。診断の値は採否の基準にしない。 | 量子化誤差の検査だけにする案は、実数と整数のネットが共通して持つ評価の歪みを見落とす。 |
| 間引きの方式 | nnue-pytorchの`--random-fen-skipping`と同じく、学習時に訓練集合を間引く（「先行実装」参照）。引数は`--train-subsample games:<k>:<r>`と`positions:<k>:<r>`とし、抽出の鍵は、`games`では（ファイルの通し番号、対局番号）、`positions`では（ファイルの通し番号、対局番号、手数）のSplitMix64のハッシュとし、kで割った余りがrの局面を残す。教師の勝率尺度、先読み教師、観測マスク、および初期値は、間引く前の訓練集合全体から作る。 | 局面を局面単位で検証へ分け直す案は、同じ対局の情報が検証側へ漏れる。生成し直したデータで比べる案は、生成に約1日かかる。 |
| 間引いた学習の更新回数 | 前処理に使う全訓練局面数と、更新に使う抽出後の局面数を分けて扱い、1エポックのバッチ数、進捗、学習率スケジュール、および再開の検査を抽出後の局面数から計算する。抽出後の局面が0なら学習を始めずに停止する。抽出後の局面の通し番号の列のSHA-256を`config.json`へ記録する。 | 全局面数からバッチ数を計算する案は、予定したバッチ数に満たずに学習器が停止する（`nnue/train/mod.rs`、`pipeline.rs`）。 |
| 間引きの本数と更新予算 | k=4で、`games:4:r`と`positions:4:r`をr=0、1、2、3の4本ずつ、計8本を学習する。早期終了を使わないよう`--epochs 8 --patience 8`とし、`--validation-interval`で更新回数ごとの検証損失を記録する。抽出後の局面数はハッシュの剰余で決まり、`games`では対局の長さにも左右されるので、8本の更新回数は厳密には揃わない。そこで、8本のうち最も少ない総更新回数Uを共通の予算とし、各本の更新回数U以内での最小の検証損失を比べる。抽出後の局面数が8本の平均から3%を超えて離れた本があれば、その旨を記録する。D0bとの比較は、更新予算が約4分の1なので参考にとどめる。 | 方式ごとに1〜2本にする案は、抽出の組によるばらつきを方式ごとに見積もれない。 |
| 間引きの教師 | D0bと同じ先読み教師で学ぶ。答えられる問いは「現行の先読み教師で約2,000万局面を使うとき、少数の対局から密に採るより多数の対局から疎に採るほうがよいか」に限られ、結論もこの範囲で書く。 | 先読みなしの教師でも行う案は、本数が倍になる。2つの仮説がともに支持された場合の追加の実験とする。 |
| 決着局面の扱い | 区間ごとの記述にとどめ、支持や不支持の判定はしない。残差が小さい区間が、学習に役立たなかったのか既に学び終えたのかは、1つのネットの集計からは区別できないからである。原因を確かめる介入（区間の重みを変える学習）は、教師の作り方の計画で行う。 | 残差の偏りから決着局面が頭打ちの原因だと結論する案は、因果を示さない。 |
| 決着局面の区切り | 素の探索値の絶対値で、0〜200、200〜500、500〜1,000、1,000〜2,000、2,000〜4,000、4,000以上（センチポーン）の6区間に分ける。教師の勝率尺度約1,007センチポーンでは、2,000センチポーンが勝率約88%、4,000センチポーンが約98%に当たる。区間ごとに、素の探索値が有利とする側から見た先読み後の教師の確率の平均と、その側の勝ち・引き分け・負けの割合を集計し、区切りが「決着」に当たるかを確かめる。正負の局面を混ぜて平均すると、確率0.98と0.02の局面が打ち消し合って0.5に見えるからである。 | 単一の閾値で2分する案は、どの区間に残差が集まるかが分からない。 |

| nnue-pytorch（Fairy-Stockfish版のvariant-nnue-pytorch） | 読み込み時に、平均してN局面を飛ばして1局面を使う`--random-fen-skipping`があり、既定値は3である（train.py 36行）。READMEは「1局から使う局面を減らす。大きなデータで有用」と説明する（README.md 63行）。 | 学習時の除外はない。 | 別ファイルを検証に使い、対局単位の分割はない（train.py 27行）。 | 探索値と対局結果の混合で、既定は探索値だけ（train.py 29行）。将来の局面の値は使わない。 |
| やねうら王の旧学習器と生成器（`source/learn/`、削除前の版） | 生成時、手数が`write_minply`（既定16）に満たない序盤の局面を書き出さない。理由は「初期局面周辺は類似局面ばかりなので学習に用いると過学習になりかねない」とある（learner.cpp 655行から661行、845行）。局面の重複を表で除き、乱数の着手を入れた時点でそれまでの局面を捨てる。 | 生成時、探索値の絶対値が3,000以上になった時点で対局を打ち切り、それ以後の局面を書き出さない（同540行から546行、826行）。 | 別ファイル、または先頭2,000局面を検証に使い、対局単位の分割はない。 | 探索値と対局結果の混合（elmo式）。将来の局面の値は使わない。 |

この調査から、本書に関わる点が3つ分かる。
第1に、同じ対局の局面を間引いて使う方式（nnue-pytorch）と、似た局面や決着局面を生成時に書き出さない方式（やねうら王、variant-nnue-tools）は、どちらも一般的である。minaseの生成器は、詰みの帯（詰みを示す範囲の探索値）の局面、最善手が捕獲または成りの局面、および反復の局面だけを除き、それ以外は全局面を記録し、学習器も全局面を使う。
第2に、同じ対局の将来の探索値を目標値に混ぜる教師は、調べた4つの実装のどれにもない。minaseの先読み教師は、[PSTの学習で採用した](../adr/use-lookahead-teacher-values.md)独自の方式であり、NNUEでの効果は測られていない。
第3に、調べた学習器は、検証集合を対局単位で分ける処理を自身では持たない。検証用のファイルを作る段階で対局を分けているかは確かめていないので、これらの実装で対局ごとの過剰適合が検証損失に現れるかは分からない。minaseは学習器が対局単位で分けるので、この過剰適合を検証損失で検出できる。
nnue-pytorchの最良のネットは、160億局面を200エポック以上学んだとされる（README.md 70行）。既定の1エポックは2,000万局面なので（train.py 39行）、各局面が使われる回数はminaseの1エポックよりずっと少ない。

## 決着局面の集計

各区間について、検証集合と訓練集合（10局面ごとの抽出）で次を集計する。

- 局面の割合と対局の数
- 素の探索値が有利とする側から見た、先読み後の教師の確率の平均と勝ち・引き分け・負けの割合、および損失の下限
- エポック0のネットとD0bの、下限からの超過の平均
- 区間の寄与（区間の超過の平均に区間の局面数を掛け、全区間の合計で割った値）と、エポック0からD0bへの超過の減少量に占める区間の割合

この集計は判定を伴わず、教師の作り方の計画への入力として、残差がどの区間に集まり、学習でどの区間が改善したかを記述する。

## 仮説ごとの判定

学習の前に、判定の基準を次のとおり定める。
結論は「支持」「不支持」「判定不能」のいずれかであり、どれも完了の条件を満たす。

**先読み教師が訓練の対局への適合を強めるという仮説。**
D0bと対照（先読みなし、尺度固定）について、次の2つの差の95%区間を求める。
差d1 = （D0bの汎化差）−（対照の汎化差）は、先読みを外すと訓練の対局への適合が弱まるかを表す。
差d2 = （D0bの検証の結果の損失）−（対照の検証の結果の損失）は、先読みを外すとほかの対局の結果をよく当てるようになるかを表す。
d1の区間の下限が0より大きければ、この仮説を「支持」、上限が0より小さければ「不支持」、0を含めば「判定不能」とする。
汎化差は、訓練の損失が悪化するだけでも縮むので、d1の支持だけでは頭打ちが改善したとは言えない。
そこで、d1が支持され、かつd2の区間の下限が0より大きい場合に限り、「先読み教師は頭打ちの一因である」と結論する。
d1が支持されてもd2の区間が0を含むか負なら、「先読みを外すと訓練の対局への適合は弱まるが、検証の当てはまりは改善しない」と書く。
候補（尺度を推定し直したもの）の同じ値、両方の教師での交差表、訓練と検証の下限からの超過、最良のエポック、および更新回数ごとの検証損失は、判定には使わず記録する。

**対局数の少なさが効くという仮説。**
`games:4:r`の4本と`positions:4:r`の4本について、共通の更新予算U以内での最小の検証損失を比べる。
`positions`の4本のすべてが`games`の4本のすべてより低ければ「支持」、`games`の4本のすべてが`positions`の4本のすべてより低ければ「不支持」、それ以外は「判定不能」とする。
この規則は、固定した30ファイルの上での判定規則であり、統計的な有意性を主張しない。r=0から3は1つの集合を4つに分けたものであり、独立に抽出し直した反復ではないので、8本の順位が無作為に並ぶという前提は成り立たないからである。
方式ごとの平均と、本数の範囲（最小と最大）も記録する。

## 実装フェーズ

### フェーズ1　決着局面の集計と道具の拡張

集計プログラムに、区間別の集計、結果の損失、汎化差、対応のある対局単位のブートストラップ、および教師の切り替え（先読みあり、なし、尺度の指定）を加え、ソースを`data/nnue-early-best-epoch/tools/`に置く。
既存の値（D0bの検証損失0.4488929など）を再現することを確かめてから、決着局面の集計を実行する。
完了条件は、区間ごとの表が測定記録`nnue-teacher-decided-positions`に書かれていることである。

### フェーズ2　先読みなしの学習と診断

まず、D0bのコマンドをそのまま実行し、`nnue.bin`のSHA-256が`046be0e6…`に一致することを確かめる。
次に、D0bのコマンドから`--lookahead-gamma 0.9 --lookahead-plies 40`を外した候補（`--teacher-cp-per-logit calibrate`）と、同じく外したうえで尺度をD0bの値に固定した対照の2本を学習する。どちらも`--validation-interval`で更新回数ごとの検証損失を記録する。
学習後、集計プログラムで汎化差、検証の結果の損失、交差表、および区間別の符号一致率を求め、「仮説ごとの判定」に従って先読みの仮説を判定する。
候補に、手引きの3つの診断と量子化誤差の検査を行う。
完了条件は、判定と診断の結果が測定記録`nnue-no-lookahead-training`に書かれていることである。

### フェーズ3　候補の段階ゲート

masterに対し、`crates/minase/nets/nnue.bin`を候補のネットへ差し替えただけのコミットを、ブランチ`nnue-no-lookahead`に作る。
ryzen0へ送り、[SPRTの手引き](../guides/sprt.md)の標準コマンドに`--concurrency 30`を加えてSTCを行う。
手引きの振分け規則に従い、STCが`H1`のとき、または上限3,000ペアに達した判定保留で対数尤度比が0以上のときにLTCへ進む。
LTCが判定保留なら、同じ実行ディレクトリを`--resume`と`--target-pairs`で延長する。
完了条件は、採否が測定記録`nnue-no-lookahead-stc`（LTCを行えば`nnue-no-lookahead-ltc`）に書かれていることである。

### フェーズ4　間引きの実装

`minase-trainer nnue train`に`--train-subsample`を加える。
仕様は「設計判断」の間引きの行のとおりであり、`--buckets`が2以上の経路でも同じ局面を残す。
完了条件は、学習器の手引きに引数を書き加え、テストで次の5点を確かめていることである。

- 指定しない学習が、変更前とビット単位で同じ結果になる。
- 残る局面が、抽出の鍵の規則どおりである。
- 抽出後の局面数から、バッチ数と学習率スケジュールが決まる。
- 抽出後の局面が0なら、学習を始めずに停止する。
- 間引いた学習を途中で止めて再開した結果が、止めずに学習した結果とビット単位で同じになる。

### フェーズ5　間引きの学習

D0bと同じ学習コマンドに`--train-subsample`、`--epochs 8 --patience 8`、および`--validation-interval`を加え、8本を順に学習する。
完了条件は、8本の最良の検証損失、最良のエポック、抽出後の局面数と対局数、区間別の局面の構成、および抽出列のハッシュが、「仮説ごとの判定」の結論とともに測定記録`nnue-train-subsample`に書かれていることである。

## 検証

完了前に次を確認する。

- `cargo test -p minase-trainer`と、`gpu_`で始まるGPUのテスト（`cargo test -p minase-trainer -- --ignored gpu_`）がすべて通る。
- フェーズ4の変更後のバイナリで、`--train-subsample`を指定しない小さな学習（1ファイル、1エポック）が、変更前のバイナリとビット単位で同じ重みを書き出す。
- 集計プログラムが、D0bの検証損失（0.4488929）と、フェーズ2の学習器が記録した検証損失を、整数評価による差の範囲で再現する。
- 段階ゲートに出すネットが、手引きの3つの診断で計算経路の不一致を示さず、量子化誤差の検査（検証1万局面の平均絶対誤差が`cp_per_logit / 40`以下）を通る。

## 完了条件

次のすべてを満たしたら完了とする。

- 2つの仮説のそれぞれに、「仮説ごとの判定」の基準で「支持」「不支持」「判定不能」のいずれかの結論が付き、測定記録に書かれている。
- 決着局面の集計が測定記録に書かれている。
- 先読みなしの候補の採否が段階ゲートで決まっている。LTCで`H1`となり、異常件数、時間切れ、および拒否着手が0件なら、そのネットを埋め込んでmasterへ取り込み（マージは利用者の許可を得てから行う）、学習の手引きの標準コマンドと[NNUEの教師のADR](../adr/train-the-nnue-on-search-value-lookahead-teachers.md)を改める。
- 状態は、先読みなしの候補を採用すれば完了（採用）、採用しなければ完了（一部不採用）とする。仮説の結論と`--train-subsample`の実装は、採否によらず成果として残す。

# NNUEの出力部を引数で構成する層積み（layer stack）に統一する設計書

## 先に読む要約

中将棋エンジンminaseの評価関数は、着手ごとに第1層の出力を差分更新できる小さなニューラルネットNNUEである。
そのネットの出力部（第1層の累算値から評価値を出す後段）は、現在、直接内積、位相補間、幅16の隠れ層、および位相補間と幅16の隠れ層を組み合わせたものという4つの固定の型を持ち、エンジンはコンパイル時に`ActiveHead`で1つを選ぶ。
[NNUEの隠れ層と位相補間の出力](archived/nnue-hidden-layer.md)（以下、前計画）は直接内積以外の3つを候補として試し、いずれも検証損失で直接内積を下回らなかったので採用しなかったが、コードは次の実験に使うために残した。
本書は、この4つの型を、隠れ層の段数と各段の幅、および端点の数を引数で与える1つの出力部「層積み（layer stack）」に置き換える。
現行の直接内積は隠れ層0段・端点1の構成として同じ型で表し、前計画の3候補もそれぞれ1つの構成になる。
重みファイルの構造記述文字列と学習器の引数`--head`は、たとえば`stack-h16-e2`（幅16の隠れ層1段、端点2）のように構成を名前で表す。
目的は、別の幅や段数のアーキテクチャを試すたびに推論と学習器の両方を書き足す手間をなくし、以後の実験を「構成名を変えて学び、段階ゲートで測る」だけにすることである。
本書は構造の整理であり棋力の変更ではないので、段階ゲートは設けない。
完了条件は、現行の埋め込みネットを層積みの構成で読んだエンジンが探索結果を1ノードも変えず速度も変わらないこと、および学習器が前計画の4本の学習結果をビット単位で再現することである。

## 状態

起案。2026年10月16日に起案した。
着手は利用者の指示を待つ。
前計画の出力部のコードが実装の土台であり、[補助損失なしのネット対masterの段階ゲート](../measurements/adhoc/nnue-no-removal-loss-stc.md)の結果には依存しない。

## 目的

利用者は2026年10月16日に、前計画の候補を採用しない一方で、実装した出力部の部品を別アーキテクチャの実験に使えるようにし、現行のアーキテクチャも同じ仕組みの1構成として書き直すことを決めた。
現在の実装は、`DirectScrelu`、`DirectScreluPhase2`、`ScreluHidden16`、`ScreluHidden16Phase2`の4つの型が、活性化、端点の内積、隠れ層、補間という部品を共有しているだけであり、幅や段数を変えるには型を増やし、学習器のパラメータの種類（`Parameter`の12種類）、CUDAカーネル、チェックポイントの配列名を合わせて増やす必要がある。
この構造では、次の実験（幅32の隠れ層、2段の隠れ層など）のたびに前計画のフェーズ2と3に相当する実装が要る。

本書は、出力部を構成の記述から組み立てる形に改め、推論の整数化、重みファイルの区画、学習器のパラメータ、CUDAカーネル、およびチェックポイントが、構成に対して自動的に決まるようにする。
やねうら王、Stockfish、tataraのNNUEもこの形であり、いずれも固定の層の並び（第1層、隠れ層1〜2段、出力）の各幅を設定で変える。
層の種類を自由に組み合わせる仕組みは設けない（「設計判断」参照）。

本書で使う語は前計画に従う。
第1層の累算値は各視点H個（幅H=128）で、SCReLU（0以上1以下に切り詰めてから二乗する活性化）を通した2H個が出力部の入力になる。
勝率尺度`cp_per_logit`、構造記述文字列、区画、量子化誤差の合格基準`cp_per_logit / 40`は前計画と同じ意味である。

## 適用範囲

本書で行う作業は次のとおりである。

- エンジンの推論（`crates/minase/src/eval/nnue/head.rs`）の4つの出力部の型を、構成を持つ1つの型`LayerStack`に置き換え、型ごとの定数と関数で区画を定めていた`Head`トレイトを削除する。構造記述文字列の`head=`の名前を先に解析して構成を得て、区画の長さの計算、復号、符号化、および構造記述文字列の再生成をその構成から行う。
- 重みファイルMNUE版5の出力区画を、構成から導く並びにする。現行の4つの名前の区画は、対応する構成名の区画と同じバイト列にし、既存の`nnue.bin`は名前だけを書き換えれば読めるようにする（「層積みの定義」参照）。
- 学習器（`crates/minase-trainer/src/nnue/`）のパラメータの種類を固定の12種類から、構成から導く可変の並びにし、CPU参照、CUDAカーネル、最適化器、チェックポイント、量子化と書き出し、診断を構成に対して動くようにする。`--head`は構成名を受ける。
- 前計画の4種類の学習結果（直接内積D0b、位相補間D2、幅16の隠れ層S1、その両方S2）を、対応する構成名でビット単位に再現することを確かめる。

次の事項は対象外とする。

- 新しいアーキテクチャの候補の学習と採否。構成ごとの実験は、本書の完了後に別の設計書で行う。
- 第1層の後の要素積（pairwise multiplication）、二乗と通常の活性化の連結、3端点以上の補間、硬い区切りの出力バケット、進行度の推定。これらは層の種類の追加であり、本書が置く層積みの範囲（全結合層と2端点の補間）には入れない。必要になった設計書で、構成名の文法と区画を拡張する。
- 量子化を考慮した学習（QAT）。
- 第1層と線形経路、入力特徴集合の変更。

## 依存関係

前計画で加えた推論の3つの出力部（コミット`3b3b94b5`）と学習器の出力部（`92fda089`、`049baee4`）がmasterにある。
推論の`Head`トレイトは`NAME`定数、`byte_len`、`decode`、`to_bytes`、`output(us, them, q)`を持ち、`Network<F, H>`は`H::decode`で区画を読む。構造記述文字列は`architecture_text::<F, H>`が`H::NAME`から組み立て、復号時に完全一致を要求する。
学習器は`HeadKind`（4値）と`Parameter`（12種類、存在しない区画は長さ0）で出力部を表し、CPU参照`reference/head.rs`が順伝播を、`output_backward`と`reduce_partials`が勾配を、`kernels/head.cu`、`reduce.cu`、`optimizer.cu`がGPU側を担う。
チェックポイントは`Parameter::name()`の名前で配列を保存し、`Reader`は配列の余分と欠落があれば読み込みを拒否する。
`diag`の`IntegerNetwork`は、入力特徴集合2通りと出力部4通りの組合せである8通りの型から、構造記述文字列に応じて選ぶ。
前計画の学習結果は`data/nnue-hidden-layer-train/`（D0b `046be0e6…`、D2 `f0962232…`、S1 `46d411cc…`、S2 `efbb09a3…`）にあり、学習器のバイナリ`minase-trainer-phase3`と同じ条件で学び直せる。
`minase`と`minase-core`は`unsafe_code = "forbid"`であり、本書もこれを変えない。

| 構成名 | 構造記述文字列の`head=`と学習器の`--head`は`stack`に続けて、隠れ層を段の順に`-h<幅>`、端点数を`-e<1または2>`で書く（例: `stack-e1`は直接内積、`stack-e2`は位相補間、`stack-h16-e1`は幅16の隠れ層、`stack-h16-h32-e2`は幅16と32の2段と位相補間）。幅は8の倍数で8以上256以下、段数は0以上3以下、端点は1または2とし、範囲外は復号と引数の検査で拒否する。表記はASCIIの十進数で、先頭の0、符号、空白を認めず、`-e<n>`は末尾に1回だけ置く。解析した構成から名前を再生成して入力と完全一致しなければ拒否するので、同じ構成の別表記（`stack-h016-e1`など）は受理されない。現行の4つの名前（`direct-screlu`など）は受理しない。 |

## 層積みの定義

入力は現行と同じく、手番側視点H個の後に相手側視点H個を並べた活性化（実数ではs = clamp(x, 0, 1)²、整数ではc = clamp(acc, 0, 127)、a = (c × c) >> 7）である。
構成は隠れ層の幅の列(w₁, …, w_L)と端点数E（1または2）で定まる。

実数の式は次のとおりである。x₀ = s、入力幅n₀ = 2H、n_l = w_lとして、

- 隠れ層: `x_l = clamp(W_l x_{l−1} + b_l, 0, 1)`（l = 1..L、W_lはw_l×n_{l−1}、b_lはw_l個）。
- 端点: `out_e = o_e·s + v_e·x_L + b_e`（o_eは2H個、v_eはw_L個でL=0なら項がない、b_eはスカラー）。
- 出力: E=1なら`out = out_0`、E=2なら`out = φ·out_0 + (1−φ)·out_1`（φ = q/90、qは王駒を含む盤上総駒数Nから`min(90, max(0, N−2))`で求める線形経路と同じ係数、out_0が序盤用、out_1が終盤用）。

評価値は現行と同じく、線形経路の評価にこの出力を勝率尺度でセンチポーンへ換算した値を足したものである。

学習器の実数の計算では、加算順と精度を現行から変えない。P型では共有する2成分の活性化を足してから重みを掛け、直接内積は視点ごとに、各段の内積は両視点を連結した入力について、それぞれ固定の木（32刻みの部分和を距離16、8、4、2、1で縮約）でf32で足し、隠れ層出力重みとの内積は添字順にf32で足し、端点は（直接内積＋隠れ層の内積）＋バイアスの順に足してから補間する。後退では、各段の微分（clipped ReLUの微分は0以上1以下で1）と端点の合流をf64で計算し、損失の勾配gを最後に掛けてf32へ丸める。

出力区画は次の順に置く。

1. 端点ごとに、直接出力重みi16[2H]と出力バイアスi32を、端点0、端点1の順に置く。
2. 段ごとに、重みW_l（i8、w_l行×n_{l−1}列の行優先）とバイアスb_l（i32[w_l]）を、l = 1..Lの順に置く。
3. L ≥ 1なら、端点ごとに隠れ層出力重みv_e（i16[w_L]）を端点0、端点1の順に置く。

この並びは、`stack-e1`が現行の`direct-screlu`、`stack-e2`が`direct-screlu-phase2`、`stack-h16-e1`が`screlu-hidden16`、`stack-h16-e2`が`screlu-hidden16-phase2`の区画とバイト単位で一致する。

整数推論は次のとおりである。

1. 各段: `z_k = Σ_i W_l[k][i]·x_{l−1}[i] + b_l[k]`をi32で計算し、`x_l[k] = clamp(z_k >> 6, 0, 127)`とする。x₀はaである。
2. 各端点: `out_e = Σ_i o_e[i]·a_i + Σ_k v_e[k]·x_L[k] + b_e`をi32で計算する。
3. 補間: E=2なら`out = floor((q·out_0 + (90−q)·out_1) / 90)`をi64で計算し、負の値でも床方向へ丸める。
4. 以後は現行と同じく`cp_nl = (out × scale + 32,768) >> 16`でセンチポーンへ換算する。

値域は、W_lが絶対値127以下、b_lが絶対値65,024以下、o_eとv_eが絶対値8,192以下、b_eが絶対値4,161,536以下であり、復号と符号化の両方で検査する。
学習時の切り詰めは、W_lを±127/64、b_lを±8、o_eとv_eを±1.98、b_eを±8とする。

## 所要時間の見積り

実装はcodexへ委任し（[委任の手引き](../guides/codex-delegation.md)）、推論側が約1日、学習器のCPU側が約1日、CUDA側が約1日、再現の検査と文書が半日と見込む。
前計画の4本の再現の学習は各20分で、合計約1.5時間である。

## 実装フェーズ

### フェーズ1　推論の層積み

`head.rs`の4つの型と`Head`トレイトを`LayerStack`に置き換え、構成名の解析と正準表記の検査、区画の復号と符号化、整数の順伝播（段数0・端点1の専用経路を含む）を実装する。`Network<F, H>`の型引数Hは外す。
埋め込みネットは名前を`stack-e1`に書き換えたものに差し替える。
`diag`の`IntegerNetwork`は入力特徴集合の2通りだけを選べばよくなる。

完了条件は、現行のテスト（差分更新と全再計算の一致、鏡映、符号化の往復、拒否、仕様の例、幅512の上界）が構成名で回り、構成名の文法の検査（範囲外の幅、段数、端点数、非正準表記、旧名の拒否）と、幅8、40、256および3段の構成の順伝播の検査が加わり、既存の4つの名前の`nnue.bin`が名前の欄を書き換えただけで読めて同じ評価を返し、深さ9のbenchのノード数が現行と一致し、NPSが「設計判断」の条件を満たすことである。

### フェーズ2　学習器のCPU側

`HeadKind`と`Parameter`を構成から導く形に改め、CPU参照、量子化と書き出し、チェックポイント、診断、整数参照を一般化する。
完了条件は、現行のCPUテスト（数値微分、エポック0の一致、再開の一致、整数参照）が幅8、40、256および3段を含む構成で回り、4つの既存構成について現行の実装と初期状態、1更新、連続3更新がビット単位で一致し、CUDA側が未対応の間は明示のエラーで止まることである。

### フェーズ3　学習器のCUDA側

カーネルを段数と幅の実行時引数で動かし、等価性検査、`check-equivalence`、`bench-step`を構成名で回す。
完了条件は、`gpu_`のテストと`check-equivalence`が4つの既存構成と、幅40を含む3段の構成（たとえば`stack-h40-h32-h16-e2`）および幅256の構成で、両特徴集合について一致し、2回の実行がビット単位で一致し、4つの既存構成の1更新と連続3更新が現行のCUDA実装とビット単位で一致することである。

### フェーズ4　再現と文書

前計画の4本を対応する構成名で学び直し、`nnue.bin`（名前の欄を除く）と`best.npz`の重みおよびAdamWの両モーメントがビット単位で一致することを確かめる。
構成名の文法、区画、整数推論の計算手順、パラメータの並び、チェックポイントの配列名を、それらを読み書きするモジュールのdocコメントへ移し、手引き[NNUEの学習](../guides/nnue-training.md)の`--head`の説明を書き換える。
設計判断をADRに書き、本書を凍結する。

## 検証

完了前に次を確認する。

- `cargo test`（ワークスペース全体）と`gpu_`のテストがすべて通る。
- 埋め込みネットを`stack-e1`の名前に書き換えたエンジンの深さ9のbenchのノード数、最善手、評価値が現行と一致し、NPSが「設計判断」の条件を満たす。

- 幅40を含む3段の構成と幅256の構成で、GPUとCPU参照の等価性、数値微分、整数参照、再開の一致が通る。

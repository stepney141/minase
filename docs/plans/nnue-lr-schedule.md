# NNUE学習器の学習率スケジュール（learning-rate schedule）の設計書

## 先に読む要約

本マイルストーンは、中将棋エンジンminaseの評価関数であるNNUEのRust製学習器（`crates/minase-trainer`）に、更新ごとに学習率を変える学習率スケジュール（learning-rate schedule）を加え、学習率の与え方を変えると検証損失（学習に使わない対局の局面での損失）が下がるか、下がったネットが強いかを確かめる。
動機は、[NNUEの完全代替](archived/nnue-replacement.md)（以下、前計画）のフェーズ4で、2つの入力特徴集合（P型とHalfKP-hm-b8）のどちらも検証損失が最初の訓練エポックの直後で最良になり、以後は訓練損失だけが下がり続けたことである。
この症状は、学習率が大きすぎて最良点を通り過ぎた場合にも、同じ対局の局面どうしの相関で実質の標本数が少なく過学習した場合にも生じるので、両者を見分ける手がかりを集める。
学習器には、学習率に掛ける倍率を完了した更新回数の関数として与える3つの形（一定、指数減衰、cosine annealing）と、エポックの途中で検証損失を記録する機能を加える。
前計画が採用したP型の幅128について、一定の1倍、1/3倍、1/10倍、指数減衰、cosineの5本を同じデータとシードで学び、エポック境界の最良の検証損失が最も低い1本を選ぶ。
選んだ1本が一定の1倍でなければ、そのネットを埋め込んだコミットを、一定の1倍のネットを埋め込んだコミットと段階ゲート（短時間STCで選別し長時間LTCで判定する時間制御のGSPRT、[測定の手引き](../guides/sprt.md)）で比べて採否を決める。
一定の1倍が最良なら、試した設定では学習率による改善がないと結論し、訓練に使う対局の数を変えて相関の影響を調べる条件つきのフェーズへ進む。この場合は自己対局による棋力の測定を行わない。
完了条件は、採否と、試した設定で改善したかどうかの結論が測定記録とともに確定していることである。

## 目的

前計画のネットは、現行のPST（駒と升の組ごとの点数表）を移植した線形経路と、第1層と出力部からなる非線形経路を持つ。
学習器は、この3つの部分をパラメータ群とし、群ごとに一定の学習率（線形経路0.03、第1層10⁻³、出力部10⁻³）を与える最適化器AdamWを使う。
全訓練局面を並べ替えた順列を1回通すことを1エポックといい、学習前の評価をエポック0、e回目の順列を終えた時点をエポックeと呼ぶ。
検証損失が5エポック続けて改善しなければ止め、検証損失が最良のエポックの重みを書き出す。
前計画は、将棋のNNUE学習器tataraの既定の減衰（約1億局面ごとに0.992倍）を採らず、学習率を一定とした。前計画の予算（約8,000万局面を20エポック前後、約16億局面）では減衰が16回程度しか起きず、学習率が0.992¹⁶ ≈ 0.88倍にしか下がらないからである。
前計画のフェーズ4の本学習（訓練82,712,114局面、1エポック5,049更新）では、両型とも最良がエポック1で、エポック2以降は訓練損失が下がり続ける一方で検証損失が単調に悪化し、改善なしが5エポック続いたエポック6で止まった（[学習の記録](../measurements/nnue-replacement-training.md)）。

この症状には2つの説明がある。
第1は、学習率が大きすぎて、1エポックの間に検証損失の最良点を通り過ぎ、その後は訓練集合の細部へ移っていくという説明である。
この場合は、学習率を下げるか更新とともに減らすと、最良の検証損失そのものが下がると見込まれる。
第2は、同じ対局の局面が強く相関しており、8,271万局面でも実質の標本数は対局の数に近く、ネットが対局ごとの癖を覚えるという説明である。
教師値は、各局面の探索値に同じ対局の後続40手までの探索値を混ぜた先読み教師なので、相関はさらに強まる。
この場合は、学習率を変えても最良点が後ろへずれるだけで、最良の検証損失はほとんど下がらないと見込まれる。
検証集合は対局単位で分けており、検証に使う対局の局面は訓練に1つも現れない。
このため、ネットが訓練の対局に固有の癖を覚えても検証損失は下がらず、訓練損失との差として現れる。

5本の学習は、2つの説明のどちらかを証明するものではない。
学習率を変えて改善すれば、それ自体が採用候補になり、第1の説明を支持する証拠になる。
改善しなければ、試した5つの設定の範囲では学習率で改善しないという結論にとどめ、第2の説明を調べる条件つきの実験へ進む。
隠れ層を加える[NNUEの隠れ層と位相補間の出力](nnue-hidden-layer.md)は表現力を増やす変更であり、過学習が主な原因なら表現力を増やしても検証損失は下がりにくい。このため本書の結論は、同書の結果を読むときの手がかりにもなる。

本書で使う指標の意味は次のとおりである。
損失は、ネットの出力を勝率に換算した値と教師値（探索値を勝率に換算した値）の二値交差エントロピーである。
教師用Kは探索値を勝率へ換算する尺度で、教師データの分類ごとに訓練集合から推定する。
符号一致率は、検証局面のうち、ネットの評価と教師値の有利不利の向きが一致した割合である。
量子化誤差は、学習した実数の重みを整数へ丸めたネットの評価と、丸める前の評価の差である。
補助損失は、駒を1枚除いた局面で評価が駒の持ち主の損になる向きへ動くことを求める損失で、前計画の学習器が主の損失に加えている。

## 適用範囲

本マイルストーンで行う作業は次のとおりである。

- 学習器に、更新ごとの学習率の倍率（一定、指数減衰、cosine annealing）を加える。倍率は3つのパラメータ群に同じ値で掛け、群の間の比を保つ。
- 学習器に、エポックの途中で検証損失を記録する機能を加える。記録は診断用であり、早期終了と最良の重みの選択はエポック境界のまま変えない。
- 5つの学習率の設定で学び、最良の1本を段階ゲートに出す。
- 学習率で改善しなかった場合に限り、対局の多様性を調べる条件つきのフェーズを行う。

次の事項は対象外とする。

- warmup。フェーズ4の学習はエポック0からエポック1で両型とも検証損失が下がり、学習の初期に不安定さは見られていない。初期の発散や損失の急増が観測された場合に別に起案する。
- 検証損失に応じて学習率を下げ、最良の重みへ巻き戻すnewbob型（やねうら王の旧学習器）。AdamWの1次と2次のモーメントの巻き戻し、減衰後の試行期間、早期終了との優先順位という設計が要るので、本書の5本で学習率による改善が見えた場合に限って次の段階として検討する。
- 最適化器の変更（Ranger、RAdamなど）と損失関数の変更。
- 学習率の群ごとの比の変更と、重み減衰の係数の変更。
- 隠れ層、出力バケット、駒除去差分の補助損失の扱い。これらは[NNUEの隠れ層と位相補間の出力](nnue-hidden-layer.md)が扱う。

## 依存関係

学習器は[Rust製NNUE学習器（GPU）](archived/nnue-trainer-rust.md)の`minase-trainer nnue train`であり、引数、保存物、および再開の仕様は学習器のコード（`crates/minase-trainer/src/nnue/`）のdocコメントが定め、使い方は手引き[NNUEの学習](../guides/nnue-training.md)にある。
学習率はホストが群ごとに保持し、更新のたびにバイアス補正の係数とともに倍精度でカーネルへ渡している（`src/nnue/gpu/optimizer.rs`の`Optimizer::update`、CPU参照は汎用部品`src/nn/adam.rs`の`AdamCoefficients::new`）。
したがって倍率を掛けるのはホスト側の変更で済み、CUDAカーネルは変えない。
重み減衰はAdamWの分離型で`p ← p·(1 − lr·wd)`として掛かるので、倍率を掛けると減衰も同じ割合で小さくなる。
チェックポイント（MNTRCKPT版2）は完了した更新回数、エポック、AdamWの状態を保存しており、再開時は`更新回数 = エポック × ceil(訓練局面数 / バッチ)`を検査する。
チェックポイントには実測の累積時間とそれを含む検査和も入るので、連続実行と再開実行のファイル全体は一致しない。
再開の設定ハッシュは、引数から出力先、再開元、入力ファイル（データ、`--init-pst`、`--base`）、`--epochs`、`--patience`、時間の上限`--time-limit-hours`、`--threads`を除いて作る（`src/nnue/train/record.rs`）。入力ファイルは、正規化したパスと内容のSHA-256をまとめた別のハッシュで照合する。
再開時は、`training.jsonl`の各行をエポックの記録として読み、エポック番号が1ずつ増えることを検査する（`src/nnue/train/record.rs`の`reconcile_log`）。
教師用Kの推定と観測マスクは訓練集合から作り、第1層の初期化は観測された行だけで乱数を消費する。

入力特徴集合と幅は、[NNUEの完全代替](archived/nnue-replacement.md)が採用してエンジンに埋め込んだP型の幅128とし、比較の基準となる一定の1倍のネットは、埋め込んだネットと同じ条件で学び直す。
フェーズ4の学習条件（全30ファイル、現行PSTの元になった候補J75の実数の重み`pst-float.npz`による初期化、先読み教師γ=0.9・n=40、バッチ16,384、シード1、補助損失の係数1000）は本書でもそのまま使う。
学習はGPUのある本環境（RTX 3060 Ti 8GB）で行い、段階ゲートの対局と同時には学習しない。
学習のワーカーがCPUを使い、時間制御の対局の時計を乱すからである。

## 設計判断

| 項目 | 判断 |
|---|---|
| 倍率の形（schedule） | 学習率を`lr_g(t) = lr_g · m(t)`とし、群gの基準学習率`lr_g`に、完了した更新回数tだけの関数である倍率`m(t)`を掛ける。形は一定（`m = c`）、指数減衰（`m = max(f, 2^(−t/(h·U)))`）、cosine annealing（`m = f + (1 − f)·(1 + cos(π·min(t/(T·U), 1)))/2`）の3つとする。Uは1エポックの更新回数、hは半減期のエポック数、Tはcosineの総長のエポック数、fは下限の倍率である。tataraは同じ系統の7種類の形をsuperbatch（6,104更新）単位で持つが、minaseは最良がエポック1に来るので、エポック単位の階段では最初の減衰が最良点の後になる。このため更新単位の連続な形にする。 |
| 群への適用 | 3群に同じ倍率を掛け、群の間の比（線形0.03対非線形10⁻³）は保つ。群ごとに別の形を持たせる案は、比較する組合せが増えるだけで、本書の問い（学習率の大きさで改善するか）に答えないので採らない。 |
| 重み減衰 | 倍率は重み減衰にも掛かる（`p ← p·(1 − lr_g·m(t)·wd_g)`）。PyTorchのスケジューラとAdamWの組合せと同じ振る舞いである。倍率を減衰に掛けないと、学習率を下げた区間では勾配による更新だけが小さくなり、重みを0へ引く減衰が相対的に強まって、学習率を下げる効果に正則化の強化が混ざるからである。重み減衰に別の倍率を持たせる案は、係数の根拠がないので採らない。 |
| 総長と早期終了 | 倍率の形と引数（c、h、T、f）は学習の軌跡を変えるので、すべて再開の設定ハッシュに含める。総長Tは`--epochs`とは別の引数にする。`--epochs`は予算として再開時に変えられる値であり、これに総長を結びつけると再開の前後で曲線が黙って伸び縮みするからである。tataraは、この伸び縮みの問題を、総長だけをチェックポイントに保存して解決している（`docs/decisions/2026-05-31-ckpt-lr-horizon.md`）が、minaseは倍率がtだけの関数で、tはチェックポイントに既に保存されているので、チェックポイントの形式は変えない。早期終了（改善なし5エポック）は倍率と独立に働き、cosineの総長に達した後は下限fのまま学習を続ける。 |
| 試す設定の範囲 | 一定の倍率は1、1/3、1/10の3点とし、1桁の範囲を対数でほぼ等間隔に覆う。減衰する2つの形の下限fは、試す一定の倍率の最小値と同じ0.1にそろえ、減衰しきった後の学習率が一定の1/10倍と同じになるようにする。指数減衰の半減期hは1エポックとし、最良点が現れた最初の訓練エポック（エポック0の後からエポック1までの更新）の間に学習率が半分になるようにする。cosineの総長Tは3エポックとし、前計画のフェーズ4で早期終了したエポック6（最良のエポック1に改善なしの5エポックを足した時点）より十分前に下限へ達するようにする。いずれも事前に固定した探索の範囲であり、最適性は確かめていない。fを0より大きくするのは、AdamWの群の検査が学習率に正の値を求めるからでもある。 |
| エポック途中の検証 | `--validation-interval <更新回数>`を加え、指定した更新回数ごとに検証集合全体の損失と符号一致率を記録する。記録はエポックの記録とは別のファイル`validation-interval.jsonl`に書き、再開時の`reconcile_log`の契約を変えない。最良の重みの選択、早期終了、チェックポイントはエポック境界のまま変えない。エポック境界でしか再開しない現在の契約を保つためである。最良点がエポック1のどこにあるかを知らないと、学習率を変えたときに最良点が下がったのか、後ろへずれただけなのかを読み分けられない。 |
| 候補の数と選び方 | 一定の1倍、1/3倍、1/10倍、指数減衰（h = 1、f = 0.1）、cosine（T = 3、f = 0.1）の5本を、同じデータ、初期値、シード、順列で学ぶ。1倍はフェーズ4と同じ条件の再学習であり、エポック途中の検証を記録するために学び直す。候補の選択には、学習器が実際に書き出す最良の重みに対応する、エポック境界の最良の検証損失だけを使い、エポック途中の値は使わない。シードを変えた反復は行わない。1本あたり約25分から2時間かかる見込みで、シードをn個に増やせば学習時間もn倍になるうえ、採否は段階ゲートが決めるからである。 |
| 学習率による改善の結論 | 学習の前に次の2つの場合分けを定める。(a) 1倍以外の4本のいずれかで、エポック境界の最良の検証損失が1倍のそれを下回った場合は、試した設定で学習率による改善があったと結論し、最も低い1本を段階ゲートに出す。(b) 4本のどれも下回らなかった場合は、試した設定では学習率による改善がないと結論し、条件つきのフェーズへ進む。2つの場合は排他であり、すべての結果がどちらかに入る。下回る幅の閾値は置かず、根拠の数値を記録する。エポック途中の検証の推移は、結論を解釈する補助として記録するが、場合分けには使わない。 |
| 採否の判定 | (a) の場合、選んだネットを埋め込んだコミットを候補、1倍のネットを埋め込んだコミットを基準として、STCからLTCへ進める。STCが上限に達して判定保留（`pending`）になった場合は停止時点の対数尤度比LLRの符号で振り分け、LTCの判定保留は`--resume`で延長する（[測定の手引き](../guides/sprt.md)）。STCの結果を見て別の候補を出し直さない。 |
| 対局の多様性の検査（条件つき） | (b) の場合に限り、`--train-subsample games:<k>`と`--train-subsample positions:<k>`を加え、少数の対局から密に採った訓練集合と、多数の対局から疎に採った訓練集合を比べる。比較を対局の多様性の違いだけにするため、教師用K、先読み教師、観測マスク、初期値は間引く前の訓練集合全体から作り、間引きは各エポックの順列から局面を除くことだけで行う。抽出の鍵は、`games`では（ファイルの通し番号、対局番号）、`positions`では（ファイルの通し番号、対局番号、手数）のSplitMix64のハッシュとし、ハッシュをkで割った余りが0のものを残す。残した局面の通し番号の列のSHA-256を記録する。両者の局面数は期待値で同じであり、`positions`は`games`の約k倍の数の対局から局面を採る。`positions`の最良の検証損失が`games`より低ければ、同じ局面数なら対局の数が多いほうがよいことになり、対局の数（多様性）の不足が頭打ちの原因だという説明を支持する証拠とする。局面を局面単位で検証へ分け直す案は、同じ対局の情報が検証側へ漏れるので採らない。 |

## 学習率の倍率の仕様

更新回数tは、エポック0の後の最初の更新をt = 0とし、更新を終えるたびに1増える。
更新tで使う学習率は`lr_g · m(t)`であり、バイアス補正の係数は従来どおり`1 − β₁^(t+1)`と`1 − β₂^(t+1)`から計算する。
倍率は倍精度で計算し、カーネルへは従来と同じく倍精度の学習率として渡す。
CPU参照実装も同じ関数で倍率を計算するので、GPUとCPU参照の等価性検査はそのまま使える。

引数は次のとおりとする。

| 引数 | 意味 | 既定値 |
|---|---|---|
| `--lr-schedule constant:<c>` | 倍率を常にcとする（cは正）。 | `constant:1`（現行と同じ） |
| `--lr-schedule exponential:<h>:<f>` | 倍率を`max(f, 2^(−t/(h·U)))`とする。hは半減期のエポック数（正の実数）、fは下限（0より大きく1以下）。 | 既定値なし（指定したときだけ使う） |
| `--lr-schedule cosine:<T>:<f>` | 倍率を`f + (1 − f)·(1 + cos(π·min(t/(T·U), 1)))/2`とする。Tは総長のエポック数（正の実数）、fは下限。 | 既定値なし（指定したときだけ使う） |
| `--validation-interval <n>` | n更新ごとに検証集合全体を評価して記録する。0は無効。 | 0 |

Uは`ceil(訓練局面数 / バッチ)`であり、データとバッチから決まるので引数にしない。
`training.jsonl`の各エポックの記録には、そのエポックの最初と最後の更新で使った倍率を加える。

エポック途中の検証は、更新tを終えた直後のパラメータで行う。
GPUの学習器は、更新の損失をGPUからホストへ1更新遅れて読み出し、次の更新の計算と重ねている。エポック途中の検証はこの読み出しと同じ記録先を使うので、検証の前に未回収の損失をすべて読み出し、回収済みとして扱う。
記録は`validation-interval.jsonl`に、`{"step": t, "epoch": e, "epoch_fraction": ..., "validation_loss": ..., "sign_agreement": ...}`の1行として書く。
再開時は、チェックポイントの更新回数以下の行だけを残し、それより後の行（中断したエポックの途中記録）を捨ててから学習を続ける。
既定値の`constant:1`と`--validation-interval 0`では、学習の軌跡と`nnue.bin`が現行の学習器とビット単位で同じになる。
記録のファイルは、倍率の欄が加わる点だけが異なる。

## 実装フェーズ

### フェーズ1　倍率とエポック途中の検証

`--lr-schedule`と`--validation-interval`を学習器に加え、CPU参照とGPUの両方の経路で使う。
倍率の関数は1か所に置き、CPU参照とGPUのホスト側の両方から呼ぶ。

完了条件は次のとおりである。

- 既定値で、教師データの1ファイル（世代3の`data/gen3/generated-1500000.bin`）の1エポック学習の訓練損失、検証損失、および`nnue.bin`のファイル全体が、現行の学習器とビット単位で同じである。
- 3つの形の倍率の値が、単体テストで式どおりである（t = 0、半減期、総長、下限に達した後の値）。
- 倍率を変えた学習で、GPUとCPU参照の3更新の全状態が許容誤差（`|GPU−CPU| ≤ 10⁻⁶ + 10⁻⁵·|CPU|`）で一致する。
- 指数減衰で、連続2エポックの学習と、1エポックで止めて再開した学習について、`latest.bin`を復号した重み、AdamWの状態、更新回数がビット単位で一致し、`nnue.bin`のファイル全体が一致する。
- `--validation-interval`を指定した学習をエポックの途中で中断して再開したとき、`validation-interval.jsonl`がチェックポイント以前の行だけを残し、再開後の学習の軌跡と`nnue.bin`が中断しない学習と一致する。
- 再開時に`--lr-schedule`を変えると、設定ハッシュの不一致で拒否される。
- `--validation-interval`を指定しても、学習の軌跡と`nnue.bin`が指定しない場合と同じである。
- 加えた引数、`training.jsonl`の倍率の欄、および`validation-interval.jsonl`の仕様が、同じコミットで、それらを読み書きする項目のdocコメントに書かれ、使い方が手引き[NNUEの学習](../guides/nnue-training.md)に反映されている。

### フェーズ2　5本の学習

5つの設定で学ぶ。
エポック途中の検証は、約0.25エポックごとに当たる`--validation-interval 1262`とする。
検証集合（約435万局面）の評価は1回あたり約20秒と見込まれ（146万局面で6.3秒という実測からの比例）、前計画のフェーズ4で実測した1エポックの学習時間（145〜155秒）に約80秒が加わる。
上限は50エポックと24時間のままとし、早期終了で止める。
一定の1/10倍は最良点が遅くなり、最良がエポック10前後に移れば早期終了まで約15エポック、約2時間かかると見込む。
5本の合計は約4〜7時間である。

完了条件は、5本の学習記録（エポック境界の最良エポックと最良の検証損失、エポック途中の検証損失の推移、量子化誤差の平均と最大）が[学習の記録](../measurements/nnue-lr-schedule-training.md)に書かれ、「設計判断」の場合分け (a) と (b) のどちらに当たるかが確定していることである。

### フェーズ3　段階ゲート

(a) の場合に限り、選んだネットを`crates/minase/nets/nnue.bin`へ埋め込んだコミットを作り、1倍のネットを埋め込んだコミットを基準に、STC（`time=10000+100`、上限3,000ペア）を測る。
STCが`H1`、または上限に達してLLRが0以上なら、LTC（`time=60000+200`）を測る。
所要時間は、STCが約1〜8時間、LTCが早期判定なら約2時間、保留が続けば数十時間である。

完了条件は、実施した段階の測定記録が書かれ、採否が確定していることである。

### フェーズ4　対局の多様性の検査（条件つき）

(b) の場合に限り、`--train-subsample`を加えて、k = 4で`games`と`positions`の2本を学ぶ。
訓練局面は約2,070万局面になり、1本あたり約10〜30分と見込む。
完了条件は、2本の最良の検証損失と抽出列のハッシュが記録され、多様性の不足を支持するかどうかの結論が書かれていることである。
この結論は採否の測定を伴わず、[NNUEの隠れ層と位相補間の出力](nnue-hidden-layer.md)と世代反復の設計への入力として使う。

## 検証

完了前に次を確認する。

- `cargo test -p minase-trainer`と、`gpu_`で始まるGPUのテスト（`cargo test -p minase-trainer -- --ignored gpu_`）がすべて通る。
- フェーズ1の完了条件のビット一致と再開の一致を、変更後のバイナリで確かめる。
- 段階ゲートに出すネットが、書き出し時の量子化誤差の検査（検証1万局面の平均絶対誤差が`K/40`以下）を通り、最大誤差を記録する。

## 完了条件

次のいずれかで完了とする。

- (a) で、選んだネットがLTCで`H1`となり、異常件数、時間切れ、拒否着手が0件である。学習器の既定の`--lr-schedule`を選んだ設定に変える。状態は完了（採用）とする。
- (a) で、選んだネットがSTCまたはLTCで棄却された。学習器の既定は`constant:1`のまま残し、加えた引数は残す。状態は完了（不採用）とする。
- (b) で、フェーズ4の結論が記録された。候補を段階ゲートに出さずに見送ったので、状態は完了（一部不採用）とする。加えた`--lr-schedule`は既定で使われない機能になるので、残すか削除するかを利用者に確認し、その結論を書く。

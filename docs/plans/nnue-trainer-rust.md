# Rust製NNUE学習器（GPU）の設計書

## 先に読む要約

本マイルストーンは、minaseのNNUE（第1層の出力を着手ごとに差分更新できる小さなニューラルネット）を学習するプログラムを、PythonとPyTorchの学習器（`tools/train`の`train-nnue`）から、`crates/nnue-trainer`に置くRustのプログラムへ置き換える。
学習の計算はNVIDIAのGPUで行い、CUDAカーネル（GPU上で走る小さな関数）はCUDA C++で書いて起動時にNVRTC（CUDAの実行時コンパイラ）でコンパイルし、ホスト側（データの読み込み、特徴抽出、転送、カーネル起動）をRustで書く。
この構成は、将棋のNNUE学習器tataraとチェスのNNUE学習フレームワークbulletが採るものと同じである。
置き換えの動機は速度である。現行のPython学習器は1更新（16,384局面）に0.6〜0.8秒かかり、全教師データ約7,600万局面の1エポックに47〜61分を要するが、その時間の9割はGPU上で(局面数, 145, 幅)の密な配列を作って読み書きする実装に費やされており、本来必要な疎な計算は1割に満たない（[調査](../research/nnue-trainer-speed.md)）。
本書の学習器は、tataraの設計から、発火した重みの行をその場で足し合わせる第1層の前進、バッチ内の発火を特徴番号で並べ替えた逆索引による後退、融合した最適化器の更新、特徴分解の畳み込みと縮約、およびページ固定メモリと転送専用ストリームによる非同期のデータ供給を取り入れる。
学習の数学的な内容（入力特徴集合、ネットの構造、損失、最適化器の係数、量子化、重みファイル）は[NNUEの共通土台と初代のネットの設計書](nnue-replacement.md)が定めたものを変えず、Pythonの学習器と同じ重みファイルを出力する。
完了条件は、GPUカーネルがCPUの参照実装と一致し、1更新の勾配と更新後の重みがPythonの学習器と許容誤差内で一致し、全教師データでの学習速度が記録され、NNUEの設計書のフェーズ4の学習をこの学習器で実行できる状態になることである。
用語の定義は「目的」の節の末尾にある。

## 状態

起案。2026年10月12日に利用者の指示で起案した。
同日の利用者の決定は3つある。学習器をRustで`crates/`配下に自作し、crates.ioへは公開しないこと。`minase`と`minase-core`は`unsafe_code = "forbid"`を保つが、学習器のcrateはその制約を外すこと。最初からGPUで学習する設計にし、CPUだけの学習経路を先に測って決める案は採らないこと。
ブランチ`nnue-trainer-rust`は、入力特徴集合のトレイト、MNUE版5、MNSDの読み手が`master`にないため、`nnue-replacement`から分岐した（設計書1枚につき`master`から1ブランチという規約からの逸脱であり、`nnue-replacement`のマージ後に`master`へ載せ替える）。
起案時に、学習器crateの骨組みとcudarc 0.19.10の依存をブランチへ入れ、本環境（CUDA 13.4、RTX 3060 Ti）でNVRTCのコンパイルとカーネル起動が動くことを確かめた。
次の一手は、設計書のcodexレビューと、フェーズ0の委任である。
NNUEの設計書のフェーズ4（全データでの学習）を、本学習器の完成を待たずにPythonの学習器で始めるかどうかは、利用者の判断を待つ。

## 目的

NNUEの設計書は、評価関数の改善の主な経路を「採用した評価関数で教師を生成し直して学び直す世代反復」に置いた。
反復の1周は、教師データの生成（約22時間）と学習（候補1本あたり10〜20時間、上限24時間）からなり、学習が周期の半分近くを占める。
現行の学習器の1更新0.6〜0.8秒のうち、GPUカーネルが86〜89%を占め、その内訳は駒除去差分の補助損失の経路が65〜69%、スライスの後退によるゼロ埋めとコピーが残りの約半分であり、第1層のgatherとscatterは合計でも1割に満たない（[調査](../research/nnue-trainer-speed.md)）。
PyTorchの自動微分の枠内でこれを直すには、第1層と補助損失のカスタムカーネルをCuPyなどで書く必要があり、それはRustで書くのと同じ作業量になる。
利用者は、チェスと将棋のNNUE学習器がRustで書かれる流れ（bullet、tatara）に合わせ、学習器をRustで自作することを決めた。

本書の目的は、同じ重みファイルを出力する学習器を、1エポックが数分で終わる速度で作ることである。
速度の目標値は設けず、実測を記録する。
見積りでは、第1層の前進と後退のメモリ転送量は1更新あたり約0.6 GB、補助損失が約1 GB、最適化器が約0.3 GBであり、RTX 3060 Tiの帯域（448 GB/s）では1更新が10 ms程度になる。
起動の固定費と並列度の不足を見込んでも、現行の0.6〜0.8秒に対して10倍以上の短縮を期待できるが、これは見積りであり、採否や計画の変更は実測に基づいて行う。

本書で使う用語を次のように定める。NNUEの設計書で定義した用語（基底特徴、入力特徴集合、文脈、特徴分解、特徴変換部、出力部、構造記述文字列、SCReLU、直接内積、先読み教師、対局単位の検証分割、教師用K、出力用K、基準M）はそのまま使う。

- **ホスト**とは、CPUとそのメモリで動くプログラムの部分をいい、**デバイス**とはGPUとそのメモリをいう。
- **カーネル**とは、デバイス上で多数のスレッドが並列に実行する関数をいう。**起動**とは、ホストがカーネルの実行をデバイスへ依頼することをいう。
- **ストリーム**とは、デバイス上で順に実行される作業の列をいう。異なるストリームの作業は並行し得る。**イベント**とは、ストリーム上の時点を記録し、別のストリームや ホストがそれを待つための印をいう。
- **ページ固定メモリ**（pinned memory）とは、OSがスワップや移動をしないと保証したホストメモリをいい、デバイスとの転送を非同期に行える。
- **gather**とは、索引で指定した行を集めて足す操作をいい、**scatter**とは、索引で指定した行へ値を足し込む操作をいう。
- **逆索引**とは、バッチ内の「どの局面のどの視点で、どの特徴が発火したか」の組を、特徴番号ごとにまとめ直した表をいう。
- **CPU参照実装**とは、各カーネルと同じ計算を単純なRustで書いたものをいい、GPUの結果を検査する基準に使う。学習の実行には使わない。
- **正準行**とは、P型の第1層と線形経路で、左右鏡映の対の重みを共有するために持つ6,841行（鏡映で対になる基底特徴の片方と埋め草1行）をいう。筋が6以上の特徴は、正準行を幅の半分だけ回転して読む。

## 適用範囲

本マイルストーンで行う作業は次のとおりである。

- `crates/nnue-trainer`（パッケージ名`nnue-trainer`、`publish = false`）を作り、GPUで学習する`nnue-trainer train`と、検証用の補助サブコマンドを実装する。
- `minase`のライブラリに、学習器が推論と同じ番号付けを使うための公開API（`eval::features`の公開化と、`HalfKpContext`の読み出し）と、MNUE版5の符号化を加える。
- CPU参照実装と、GPUカーネルとの等価性テスト、Pythonの学習器との1更新の照合、およびエポック0の検証損失の照合を実装する。
- 全教師データ（約7,600万局面）での学習速度とGPUメモリを測り、記録する。

次の事項は対象外とする。

- 学習の数学的な内容の変更。入力特徴集合、ネットの構造、損失、最適化器の係数、教師の作り方、量子化、重みファイルの形式はNNUEの設計書のとおりとし、本書では変えない。
- 半精度（f16）やTF32の使用、CUDA Graphs、複数GPU。f32の実装を測ってから、必要なら別に起案する。
- CPUだけで学習する経路。CPU実装は等価性テストの参照に限る（2026年10月12日の利用者の決定）。
- Pythonの学習器の削除。`train-nnue train`は本計画の完了後に削除の候補とし、整数参照推論（`minase_train.nnue.reference`）、重みファイルの読み書き（`format`）、入力特徴集合の仕様（`feature_sets`）、浮動小数点のモデル（`model`）、および診断（`nnue-diagnostics`）は、Rustの推論と学習器に対する独立な照合役として残す。
- 世代反復の運用。NNUEの設計書の対象外事項と同じである。

## 依存関係

NNUEの設計書のフェーズ2とフェーズ3の成果（`crates/minase/src/eval/nnue/`の`FeatureSet`トレイト、P型と`HalfKpHmB8`、MNUE版5の復号、`crates/minase/src/training/records.rs`のMNSDの読み手、Pythonの学習器と整数参照）を前提にする。
これらは`master`になく、ブランチ`nnue-replacement`にあるので、本書のブランチはそこから分岐した。
教師データはNNUEの設計書と同じ30ファイル（既存10ファイルと新規20ファイル、約8,000万局面、1局面160バイト）であり、本環境のメモリ（30 GB）のページキャッシュに収まる。
GPUはRTX 3060 Ti（8 GB）、CUDAツールキットは13.4（`/opt/cuda`、nvccとlibnvrtc）、Rustはstableの1.98である。
cudarc 0.19.10は、`driver`、`nvrtc`、`dynamic-loading`、`cuda-13040`のfeatureで使う。`dynamic-loading`は`libcuda`を実行時に読み込むので、GPUのない環境でもビルドとCPUのテストができる。
学習の実行とGPUのテストは本環境で行い、codexへは委任しない（[教訓](../lessons/run-gpu-training-outside-codex-sandbox.md)）。
codexはネットワークを使えないので、依存の追加は委任元が行って`Cargo.lock`を確定させる（[手引き](../guides/codex-delegation.md)）。起案時にcudarc、memmap2、clap、serde、serde_json、sha2を入れた。
測定機はlishogiのBotと教師データの生成と共用するので、学習の試走は進行中の処理を確かめてから始める（[教訓](../lessons/check-running-measurements-before-cpu-load.md)）。

## 設計判断

| 項目 | 決定と理由 |
|---|---|
| 言語と計算の経路 | ホストをRust、カーネルをCUDA C++で書き、起動時にNVRTCでコンパイルする。tataraの速さはRustではなく、疎なgather、逆索引の後退、融合した最適化器、非同期の供給という設計に由来する（[調査](../research/nnue-trainer-speed.md)）。カーネルをCUDA C++で書くのは、tataraの既定経路とbulletと同じであり、cuda-oxide（RustをPTXへコンパイルする）はnightlyと固定リビジョンを要し、tatara自身が境界検査の費用を記録している。NVRTCで実行時にコンパイルするのは、ビルドにnvccを要さず、GPUのないcodexのサンドボックスでもビルドとCPUのテストができるからである。カーネルのソースは`crates/nnue-trainer/kernels/*.cu`に置き、`include_str!`で埋め込む。 |
| GPU直行 | CPUだけの学習経路を先に作って測る案は、利用者が退けた（2026年10月12日）。CPU実装はカーネルごとの参照に限り、学習ループは持たない。codexのCPU試作（標準ライブラリのスレッドだけ、2コア）がHalfKP-hm-b8の幅128で約27万局面/秒を出したという事実は記録するが、採否の根拠にはしない。 |
| unsafeの扱い | 学習器のcrateは`[lints]`でworkspaceを継承せず、`unsafe`を許す（2026年10月12日の利用者の決定）。`minase`と`minase-core`は`unsafe_code = "forbid"`を保つ。cudarcのカーネル起動とページ固定メモリの確保は`unsafe`を要する。`unsafe`ブロックは`gpu`モジュールに閉じ込め、各ブロックに前提条件のコメントを付ける。 |
| crateの配置 | `crates/nnue-trainer`をworkspaceのメンバーにし、`publish = false`にする。`release.toml`の対象外であり、cargo-releaseの`pre-release-hook`は`minase`と`minase-core`以外を拒否するので、リリース手順は変わらない。CHANGELOGにも載らない。Pythonの`minase_train`と紛れないよう、名前に`train`だけを使わない。 |
| 推論との番号付けの共有 | 特徴番号はRustの推論と同じ関数で計算する。`minase::eval::features`を公開モジュールにし、`feature_index`、`lion_feature_index`、`piece_state`、`mirror_feature`、定数を`pub`にする。`HalfKpContext`の区分と鏡映を読むアクセサを加える。番号付けを学習器に写す方式は、推論と学習がずれる危険があるので採らない。 |
| 重みファイルの書き出し | MNUE版5の符号化を`crates/minase/src/eval/nnue/format.rs`の隣に加え、復号との往復テストを置く。学習器は整数化した重みをこの符号化で書き、書いた直後に`minase`の復号で読み直して検証する。 |
| 学習の数学的な内容 | NNUEの設計書が定めたものを変えない。損失、教師用Kの推定、先読み教師、検証分割、駒除去差分の補助損失、3つのパラメータ群の学習率と重み減衰、切り詰め、未観測行の規則、初期化の標準偏差、量子化の丸めはすべて同じである。等価性の契約は「Pythonとの等価性」の節に列挙する。 |
| 最適化器の意味論 | AdamWはPyTorchの`torch.optim.AdamW`と同じ式（バイアス補正あり、分離した重み減衰、β₁=0.9、β₂=0.999、ε=10⁻⁸）にする。tataraとbulletのAdamWはバイアス補正を持たず、PyTorchと更新式が異なる。既存の学習率10⁻³と重み減衰10⁻⁴はPyTorchのAdamWで使った値なので、式を変えると同じ係数の意味が変わる。 |
| 第1層の後退 | 逆索引を使い、特徴ごとに固定順で足して1回で書く。アトミック加算は加算順が実行ごとに変わり、CPU参照との等価性テストに緩い許容誤差が要る。逆索引なら縮約順を固定でき、同じ入力で同じ結果を返す（学習の再現性）。逆索引はホストのワーカースレッドがバッチごとに計数ソートで作り、バッチと一緒に転送する。tataraはデバイス上で4段のカーネルで作るが、minaseのワーカーは特徴抽出の後に余力があり、ホストで作れば後退カーネルは1本で済む。 |
| 縮約の決定性 | 出力重み、バイアス、損失の総和のような局面方向の縮約は、ブロックごとの部分和を配列に書いてから固定順で足す2段の方式にし、アトミック加算を使わない。 |
| 駒除去差分の補助損失 | 除去1件あたりの(幅)の中間配列を実体化せず、除去ごとのスカラーの勾配だけを保持し、第1層の後退で行ごとの寄与を再計算する。現行の最大の費用がここにあり、tataraにもbulletにも相当物がないので、minaseが自前で設計する唯一の部分である。式は「カーネル」の節に置く。 |
| 特徴分解 | HalfKP-hm-b8では、tataraと同じく、更新後に`C = W + V[base]`を全行で作って前進に使い（fold）、仮想行の勾配を`dV[p] = Σ_k dW[k·13,680+p]`で作る（reduce）。foldは最適化器のカーネルに融合し、reduceは独立した1カーネルにする。疎な索引へ仮想特徴を追加する方式は、tataraが37%の低下を記録しているので採らない。P型には適用しない。 |
| P型の鏡映共有 | 第1層と線形経路を正準行6,841行で持ち、筋が6以上の特徴は正準行を幅の半分だけ回転して読む。前進と後退のカーネルは回転の有無を索引の1ビットで受け取る。バイアスと出力重みは幅の半分を自由パラメータとし、展開した全幅の配列を更新のたびに作る。全13,680行を持って更新後に平均で対称化する方式は、共有パラメータの勾配（両鏡映からの和）と同値にならないので採らない。 |
| データの供給 | 全MNSDファイルをmmapで開き、エポックごとに訓練局面の通し番号の順列（シードとエポック番号から決まるSplitMix64のFisher–Yates）を作り、ワーカースレッド（既定は物理コア数から2を引いた数）がバッチの範囲ごとに復号、特徴抽出、逆索引の構築を行ってページ固定メモリの面へ書く。面は3つを環状に使い、転送専用ストリームで非同期に転送し、計算ストリームはイベントで転送の完了を待つ。損失と検証の指標は1ステップ遅れでページ固定メモリへ非同期に読み出す。tataraの「事前シャッフル済みの逐次読み」は、MNSDが対局順で検証分割が対局番号のハッシュで決まるため使えない。 |
| 前処理 | 起動時に、全ファイルを1回走査して、検証分割、先読み教師値（1局面あたりf32、約320 MB）、教師の分類ごとの教師用K、観測マスク（訓練集合の手番側の特徴を鏡映込みで数えたものと、両視点を鏡映なしで数えたもの）を計算し、実行ディレクトリへ記録する。再開時は記録を読み直さずに再計算し、記録と一致することを確かめる。 |
| 初期化 | 線形の2列は基準MのJ75の整数化前の重み（`pst-float.npz`、圧縮なしのzip）を読み、再量子化が基準Mの重みファイルのPST部分と一致することを確かめる。npzの読み手は圧縮なしのzipと`.npy`のヘッダだけを扱う小さな関数として学習器に置く。第1層の正準行は、観測済みの行に標準偏差0.05の正規分布を、学習器自身の乱数列（SplitMix64とBox–Muller法、シードから決定的）で与える。HalfKP-hm-b8の仮想行には同じ乱数列で同じ値を与え、特徴の行は0にする。torchの乱数列は再現しないので、エポック0のネットはPythonのものと第1層の乱数が異なるが、出力重みが0なので評価は一致する。 |
| チェックポイントと再開 | エポックごとに、浮動小数点の全パラメータと最適化器の状態、エポック番号、最良エポックの記録を実行ディレクトリへ書く（最新と最良の2つ）。`--resume`は最新から再開し、エポック番号とシードから順列を作り直す。現行のPython学習器にはないが、24時間の学習が途中で止まると1日を失うので置く。形式は学習器固有の単純なバイナリ（識別子、版、構造記述文字列、f32の配列）とし、Pythonとの照合にもこの形式を使う。 |
| GPUがない環境 | 学習は明示的なエラーで止める。GPUを要するテストは名前を`gpu_`で始めて`#[ignore]`にし、本環境で`--ignored`を付けて実行する。CPUに黙って切り替える経路は置かない。 |
| バッチと係数 | バッチは16,384、学習率と重み減衰はNNUEの設計書の値のまま変えない。GPUメモリはHalfKP-hm-b8の幅128で、重み、合成重み、勾配、最適化器の2状態が約330 MB、仮想行が約35 MB、バッチの索引と累算器が面あたり約60 MBであり、8 GBに対して余裕がある。 |
| 速度の記録 | 1秒あたりの学習局面数、1更新の時間、前処理の時間、GPUメモリの最大使用量を、1ファイルと全30ファイルで測って記録する。目標値は設けない。 |

## 先行実装

tatara（コミット`db08ed2`）は、ホストをRust、カーネルをnvccでコンパイルしたCUDA C++で書き、第1層の前進は1スレッドが1局面×4出力を受け持つgather（`crates/cuda-native-runtime/kernels/native_kernels.cu`264〜304行）、後退は逆索引の4段構成（`bins/nnue_train/src/trainer_layerstack.rs`4193〜4214行）、最適化器は融合した1カーネル（同`.cu`1479〜1515行）、特徴分解はfoldとreduce（同306〜508行）である。
データ供給はワーカーの復号と特徴抽出、固定幅の索引配列、ページ固定メモリの2面と転送専用ストリーム、1ステップ遅れの損失回収からなる（`crates/nnue-train/src/dataloader.rs`、`bins/nnue_train/src/trainer_common.rs`）。
GPUとCPUの等価性テストは`bins/nnue_train/src/tests/gpu_cpu_equivalence_tests.rs`にある。

bullet（BulletOu同梱のフォーク、HEAD `cc202f3`）は、カーネルをRustの`format!`で組み立てたCUDA C++の文字列として実行時にNVRTCでコンパイルし（`crates/gpu/src/pointwise/write.rs`212〜284行、`crates/gpu/src/runtime/cuda.rs`209〜236行）、第1層の後退は`atomicAdd`、最適化器は融合した1カーネルでバイアス補正なし（`crates/trainer/src/optimiser/adam.rs`33〜139行）である。
本書のNVRTCの使い方はbulletに倣い、後退の方式はtataraに倣う。

variant-nnue-pytorch（HEAD `749db94`）は、第1層をCuPyの`RawKernel`で書き、後退は`atomicAdd`で、呼び出しのたびに勾配の配列を新しく確保する（`feature_transformer.py`266〜270行、353行、464行）。
特徴分解は疎な索引へ仮想特徴を追加する方式である。
いずれも本書は採らない。

## モジュールの構成

`crates/nnue-trainer/src/`を次のモジュールに分ける。

- `data`: MNSDファイルのmmap、検証分割（Pythonの`hash64`と同じSplitMix64の変形）、先読み教師、教師用Kの黄金分割探索、観測マスク、エポックの順列、およびワーカーによるバッチの構築。バッチは、両視点の固定幅145列の特徴番号（空升と先獅子のない枠は番兵）、手番側の線形経路の正準行番号、盤上総駒数、教師値、除去の参照に要する情報、および逆索引（行ごとの開始位置と、`局面番号、視点、列、回転`を詰めた要素の列）からなる。列は両視点で元の盤面の升に対応させ、補助損失が列ごとに両視点の行を引けるようにする（NNUEの設計書の「学習器」の節と同じ）。
- `model`: パラメータの形（線形の正準行6,841×2、第1層のD×H、HalfKP-hm-b8の仮想行13,681×H、バイアス、出力重み、出力バイアス）、初期化、切り詰め、未観測行のマスク、量子化、およびチェックポイントの形式。
- `reference`: 各カーネルのCPU参照実装。前進、補助損失、出力部の後退、第1層の後退、AdamW、fold、reduce。等価性テストが使う。
- `gpu`: cudarcの文脈、ストリーム、イベント、ページ固定メモリの環、デバイス上の配列、NVRTCのコンパイル、カーネル起動。`unsafe`はこのモジュールに閉じる。
- `train`: 学習ループ、検証、早期終了、時間の上限、チェックポイント、再開、記録。
- `export`: 量子化、MNUE版5の書き出し、読み直しの検証、量子化誤差の検査（検証1万局面で、浮動小数点の評価と、書き出したファイルを`minase`の復号で読んだ整数推論との平均絶対誤差がK/40以下）。
- `main`: サブコマンド。`train`（学習）、`check-equivalence`（GPUとCPU参照の等価性を固定入力で検査して報告）、`dump-batch`（Pythonとの照合用に、固定したバッチと浮動小数点のモデルをファイルへ書く）。

## カーネル

1更新で起動するカーネルは、P型で9本、HalfKP-hm-b8で10本である。
Bはバッチの局面数、Hは幅、Dは入力特徴集合の特徴数、φは盤上総駒数Nから決まる補間率`min(90, max(0, N−2))/90`である。

1. **第1層の前進**。1スレッドが（局面、視点、連続する4出力）を受け持ち、145列を走査して番兵でない列の行を足し、バイアスを加えて累算器`acc[B][2][H]`へ書く。同じカーネルの別のスレッド群が、手番側の線形経路の正準行を足して`lin[B][2]`（序中盤用と終盤用の和）を書く。P型では回転ビットに応じて列`(j + H/2) mod H`を読む。
2. **駒除去差分の補助損失の前進**。1ブロックが1局面を受け持ち、144列のうち適格な除去（番兵でなく、王駒でなく、参照の向きが0でない）について、両視点の`acc − W[f]`と`lin − L[base]`から除去後の評価を計算し、除去差分、罰則、および罰則の除去差分に関する微分`d_delta`（スカラー）を求める。局面ごとに、`d_delta`の和`S`と、`Σ_r d_delta_r · o_v ⊙ 2·clamp(acc_v − W[f_r,v], 0, 1)`（視点ごとH成分）を`d_acc_removal[B][2][H]`へ書き、出力重みへの寄与`Σ_r d_delta_r · SCReLU(acc_v − W[f_r,v])`をブロックごとの部分和として書く。適格性、符号、上限と下限の定義は`minase_train.pst.removal.removal_loss`と同じである。
3. **出力部と損失**。1スレッドが1局面を受け持ち、SCReLU、直接内積、`lin`の補間と出力用Kによる換算、ロジット、二値交差エントロピー、`d_logit`を計算し、`d_acc[B][2][H] = (d_logit − S)·o_v ⊙ 2·clamp(acc_v) + d_acc_removal`と、線形経路の勾配の係数（`(d_logit − S)·(φ, 1−φ)/K`と除去ごとの補正）を書く。損失と補助損失のブロックごとの部分和も書く。
4. **部分和の縮約**。出力重み、出力バイアス、バイアス、損失の部分和を固定順で足す。
5. **第1層の後退**。1スレッドが（特徴の行、連続する4出力）を受け持ち、逆索引の範囲を固定順に走査して`d_acc[局面][視点]`を足し、除去の対象だった列については`d_delta_r · o_v ⊙ 2·clamp(acc_v − W[f_r,v], 0, 1)`を引いて、勾配の行を1回で書く。範囲が空の行には0を書くので、勾配のゼロ埋めは要らない。P型では回転ビットに応じて`d_acc`の列をずらして読む。
6. **線形経路の後退**。同じ逆索引の手番側の要素から、正準行ごとに2列の勾配を書く。
7. **仮想行の縮約**（HalfKP-hm-b8だけ）。`dV[p] = Σ_k dW[k·13,680+p]`を8区分について固定順で足す。
8. **AdamWと切り詰め**。パラメータ群ごとに起動し、PyTorchのAdamWの式で更新し、未観測行のマスクに当たる行は更新せず初期値を保ち、切り詰めを適用する。HalfKP-hm-b8では、仮想行の更新と切り詰めの後に特徴の行を「仮想行との和が±8に収まる範囲」へ切り詰め、合成重み`C = W + V[base]`を同じカーネルで書く。P型では、更新後のバイアスと出力重みの半幅のパラメータから全幅の配列を展開する。
9. **検証の前進**。訓練の前進と同じカーネルを後退なしで使い、損失、符号一致率、非線形の出力の標準偏差、活性化の飽和率を部分和として集める。

カーネルの引数と配列の形は、`reference`モジュールの関数の引数と1対1に対応させ、等価性テストが同じ入力を両方へ与えられるようにする。

## Pythonとの等価性

次の事項を、Pythonの学習器と同じにする。各項目のPython側の定義の所在を併記する。

- 検証分割: `minase_train.data.mnsd`の`hash64(seed, game) % 20 == 0`（自己対局の由来）。分割を変えると旧記録と比較できなくなる（[教訓](../lessons/validation-split-change-invalidates-old-baseline.md)）。
- 先読み教師: `minase_train.data.lookahead`の式（手数差d≤40の記録を`γ^(d−d₁)`で重みづけし、奇数なら符号を反転して平均、γ=0.9）。
- 教師用K: `minase_train.pst.teacher`の黄金分割探索（区間[50, 4000]、64回、二値交差エントロピーを最小化）。教師の分類は（生成した評価関数の検査和、ノード数、先読みの有無）。
- 損失: 二値交差エントロピー、教師値`σ(score/K_teacher)`（λ=1.0）、補助損失の係数1000、`removal_loss`の定義（参照は基準Mの整数PST、下限の余裕0.25センチポーン、上限は参照と逆向きの除去だけ、局面ごとに適格な除去で平均、バッチで平均、Kで割る）。
- 鏡映共有: P型の正準行6,841行と`roll(W/2)`、バイアスと出力重みの半幅の共有。線形経路の鏡映対の共有はどちらの型でも同じ。
- 未観測行の規則: `feature_observations`（手番側、鏡映込み）と`input_feature_observations`（両視点、鏡映なし）の2つのマスクの用途。
- 切り詰め: 線形[−4096, 4095.875]、第1層±8（分解型は和が±8）、バイアス±8、出力重み±1.98、出力バイアス±8。
- 初期化の標準偏差0.05と、仮想行をP型の展開値で初期化し特徴の行を0にする規則。
- 量子化: 尺度（線形8、第1層とバイアス127、出力重み4,096、出力バイアス127×4,096）、偶数丸め（`round_ties_even`）、上限の検査、MNUE版5の並び（線形は特徴ごとに序中盤用と終盤用を交互に）。
- AdamWの式と係数、学習率一定、早期終了（改善なし5エポック、エポック0を最良にしない）、上限（50エポックまたは24時間）。

Pythonと同じにしない事項は、第1層の乱数列（学習器自身のSplitMix64）、チェックポイントの有無、およびデータ供給の並列化である。

照合は次の3つで行う。

1. エポック0の検証損失。同じデータ、同じ分割、同じ先読み、同じ教師用Kで、Pythonの記録（世代3の1ファイルで0.437095）と一致すること。出力重みが0なので乱数列の違いは影響しない。
2. 1更新の照合。`dump-batch`で、乱数初期化後の浮動小数点のモデルと固定したバッチ（局面の通し番号）をファイルへ書き、`tools/train`に置くスクリプトがそれをPyTorchのモデルへ読み込んで同じバッチで1更新し、損失、各パラメータ群の勾配、更新後の重みを許容誤差（相対10⁻⁴、絶対10⁻⁵）で比べる。浮動小数点の加算順が違うので厳密一致は求めない。
3. 特徴番号の照合。`dump-batch`が書いた両視点の特徴番号と線形経路の番号を、`minase_train.nnue.feature_sets`の`indices`で計算した値と全列で比べる。

## 実装フェーズ

### フェーズ0　`minase`の公開APIとMNUE版5の符号化

`minase::eval::features`を公開モジュールにし、`feature_index`、`lion_feature_index`、`piece_state`、`mirror_feature`、`active_features_for`、および定数を`pub`にする。
`HalfKpContext`に区分と鏡映を返すメソッドを加える。
`crates/minase/src/eval/nnue/format.rs`に、ヘッダと整数の配列からMNUE版5のバイト列を作る符号化を加え、既存の`nets/nnue.bin`を復号して符号化すると同じバイト列になること、および不正な値（範囲外、鏡映の共有違反）を符号化が拒否することをテストで固定する。
`eval/pst/`と`handcrafted.rs`は変更しない。
完了条件は、`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all --check`が通り、推論のベンチ（`minase dev bench --depth 9`）のノード数が変わらないことである。
codexへ委任する。

### フェーズ1　データ経路とCPU参照実装

`data`、`model`、`reference`モジュールを実装する。
完了条件は次のとおりである。
第1に、検証分割、先読み教師、教師用K、観測マスクが、Pythonの関数と同じ入力（世代3の1ファイル）で同じ値（局面数、Kの値、マスクの件数）を返すこと。Python側の値は`tools/train`のスクリプトで出力して照合する。
第2に、バッチの特徴番号が`feature_sets.indices`と全列で一致すること。
第3に、`reference`の前進がPythonの浮動小数点のモデル（`minase_train.nnue.model`）と同じ評価を返すこと（`dump-batch`の出力を使う）。
第4に、逆索引の構築が、要素の並びを固定順にし、特徴ごとの件数の和がバッチの発火数に等しいこと。
第5に、`reference`の後退が、有限差分による数値微分と一致すること（小さな幅、小さなバッチ）。
codexへ委任する。GPUは要らない。

### フェーズ2　GPUカーネルと等価性テスト

`gpu`モジュールとカーネル10本を実装し、`check-equivalence`サブコマンドと`gpu_`で始まる`#[ignore]`のテストを置く。
完了条件は、小さな固定入力（幅8と幅128、バッチ64と4,096、両方の入力特徴集合、除去の適格と不適格、回転の有無、空の逆索引の範囲）で、全カーネルの出力がCPU参照と相対10⁻⁵以内で一致し、同じ入力で2回実行した結果がビット単位で一致することである。
codexにカーネルとテストを書かせ、GPUのテストは委任1回ごとに本環境で実行する。カーネルのコンパイルエラーはNVRTCのメッセージをcodexへ戻して直させる。

### フェーズ3　学習ループ、書き出し、照合

`train`、`export`、`main`を実装し、「Pythonとの等価性」の3つの照合を通す。
世代3の1ファイルで、両方の入力特徴集合について幅128の1エポックを試走し、1秒あたりの学習局面数、1更新の時間、GPUメモリの最大使用量、エポック0と1エポック後の検証損失、量子化誤差を測って、Pythonの試走（[記録](../measurements/nnue-replacement-training.md)）と並べて記録する。
書き出したMNUE版5を`minase`で復号し、`minase dev nnue-probe`の評価がPythonの整数参照と一致することも確かめる（既存の`nnue-diagnostics compare`）。
完了条件は、3つの照合が通り、試走の記録が`docs/measurements/nnue-trainer-rust-checks.md`にあることである。

### フェーズ4　全データの試走と引き継ぎ

全30ファイルで前処理の時間と1エポックの時間を測り、記録する。
NNUEの設計書の「状態」と「学習器」の設計判断を、本学習器を使う形に改める。
Pythonの学習器`train-nnue train`の扱い（削除か保持か）を利用者に確認する。

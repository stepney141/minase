# 直前局面生成器の設計書

## 実施状況

2026年8月10日に本設計書を起案した。
同日の設計レビューを受けて、`last_lion_capture`に対する獅子在庫と角鷹・飛鷲の局所条件、E3の記載、`mark_promotion_deferred()`の削除、`Eq`とZobrist値の同値性の保証、および計測後の最適化候補の記録を追記した。
同日の返却形式の検討を受けて、`Vec<Position>`の返却が計測で支配的と出た場合の置き換え先として、ビジターAPIを性能測定節の第3候補へ追記した。
設計は確定済みであり、実装は未着手である。

本マイルストーンはプロトコル層の完了後に開始する。
進行中のプロトコル層には変更を加えず、完了後に本マイルストーンの最初のフェーズで一時状態の表現を統合する。

## 目的

本マイルストーンは、規則集合`Rules`と対象局面`Position`を受け取り、その対象局面へ1手の局面合法手で到達できる直前局面を漏れなく列挙する`PredecessorGenerator`を実装する。
出力は盤面、手番、一時状態を含む完全な`Position`の集合とし、同じ直前局面へ至る着手が複数あっても、その局面を1回だけ返す。

主な利用者は、minaseを依存ライブラリとして呼び出す独立したRustプログラムである。
これにより、IshiiとTanakaが将棋の到達可能性判定に用いた逆方向探索と同型の探索を、中将棋の`Position`グラフ上へ構築できるようにする。

## 適用範囲

本マイルストーンでは、次の作業を行う。

- 先獅子状態とP1成り権保留状態を公開値`TransientState`へ統合する。
- 内部型`LionTrigger`を公開値`LastLionCapture`へ置き換える。
- `Position`と`Undo`の既存実装を`TransientState`へ移行する。
- `Position`に検証付き一時状態構築APIと衝突安全な`Hash`実装を追加する。
- 全直前局面を列挙する公開型`PredecessorGenerator`を追加する。
- 初期配置の駒在庫を基準に、復元できる捕獲駒を所有者別かつ由来別に制限する。
- 通常移動、走り、固定跳び、獅子、角鷹および飛鷲の全移動形式を逆向きに構成する。
- 非捕獲、1枚捕獲、2枚捕獲、既成駒の移動および直前手での成りを扱う。
- 対象局面から決定できない直前局面の一時状態をすべて列挙する。
- 全候補を既存の順方向合法手生成器で検証し、対象局面との完全一致を確認する。
- 健全性、相対的完全性、一意性および性能を再現可能な方法で検証する。

次の項目は対象外とする。

- `Game`全体、反復履歴、手数、駒枯れ猶予および終局結果の逆生成は行わない。
- 初期局面から各直前局面までの大域的な到達可能性は判定しない。
- 集計、状態の縮約、状態数の計算および永続化は行わない。
- 多手の逆方向探索、探索順序、目標集合および到達不能判定は実装しない。
- ファイル入出力、CLI、USI、CECPおよびGUIとの接続は行わない。
- 計測前に専用逆利き表、並列化、キャッシュまたは逆向き差分更新を導入しない。

## 直前局面の定義

規則集合を`R`、対象局面を`q`、`R`の下で`p`から生成される局面合法手集合を`Moves_R(p)`、着手適用後の局面を`Next_R(p, m)`とする。
本機能が返す集合を次のように定義する。

\[
\operatorname{Pred}_R(q)
=
\{p\in A\mid
\exists m\in\operatorname{Moves}_R(p),\
\operatorname{Next}_R(p,m)=q
\}.
\]

集合`A`は、`Position::validate()`を満たし、2種類のZobrist値が再計算値と一致し、各所有者の由来別駒数が初期在庫を超えず、採用規則と一時状態が次の局所条件を満たす`Position`の集合とする。

- P1を採用しない規則では、`promotion_deferred`が空である。
- `promotion_deferred`の各升には、所有者から見た敵陣内に不成の成れる駒がある。
- `last_lion_capture`が`Some`なら、記録升は空であるか、`p.side_to_move().opposite()`の非獅子駒または麒麟由来の成獅子で占められている。
- `last_lion_capture`が`Some`なら、`p.side_to_move()`の獅子由来または麒麟由来の駒が、由来別在庫から1枚以上欠けている。
- `last_lion_capture`の記録升が空なら、`p.side_to_move().opposite()`の角鷹または飛鷲が盤上にある。

後2条件は、先獅子状態の成立過程から従う必要条件である。
先獅子状態は、直前の着手で`p.side_to_move()`の獅子が非獅子に取られた場合にしか生じないため、手番側の獅子になり得る駒が在庫どおり盤上に揃っている局面では`None`以外を許さない。
また、記録升が空になるのは経由升での捕獲に限られ、非獅子で経由升の捕獲を行える駒は角鷹と飛鷲だけである。
この2条件がないと、空升を指す`Some`の変種が候補ごとに数十通り生成され、順方向再適用では除外できないまま、歴史的に到達不能な局面として出力を膨張させる。

これらは局面単体で判定できる必要条件だけであり、その一時状態を生じさせた直前着手の存在までは要求しない。
候補着手の順方向再適用は、候補`p`から対象局面`q`への遷移と矛盾する組合せだけを除外する。
`p`より前の履歴における一時状態の到達可能性は、本機能では判定しない。
局面の一致は盤面、手番および`TransientState`について判定し、Zobrist値は一致を高速化する派生データとして扱う。

同じ`p`から異なる着手で`q`へ到達できても、`p`は1回だけ返す。
中将棋では、異なる獅子力の駒による「じっと」が同じ結果局面へ至る場合があるため、着手ではなく局面を一意性の単位とする。

初期在庫制約は到達可能性の必要条件にすぎない。
返された`p`が初期局面から実際に到達可能かどうかは、後続の逆方向探索が判定する。

## 設計判断

| 項目 | 決定 |
|---|---|
| 生成対象 | `Game`ではなく、次の局面合法手を決める`Position`を対象とする。 |
| 出力単位 | 一時状態を含む完全な直前`Position`とする。着手は内部検証にだけ使う。 |
| 一意性 | 同じ`Position`を1回だけ返し、返却順序は公開契約に含めない。 |
| 合法性の正 | 既存の`MoveGenerator`を唯一の正とし、逆生成側に合法手判定を複製しない。 |
| 候補生成 | 逆向きの幾何、在庫および一時状態から上位集合を構成し、順方向再適用で絞る。 |
| 移動元 | 既存の移動プロファイルから`Bitboard`として構成し、専用逆利き表は設けない。 |
| 捕獲駒 | 初期配置から対象局面の盤上駒を差し引いた由来別在庫だけを復元候補にする。 |
| 一時状態 | 不明値や既定値へ置換せず、局所的に整合する具象`TransientState`を列挙する。 |
| 候補局面 | 初回実装では`PositionBuilder`で盤面全体を再構築する。 |
| 不正入力 | 空集合へ変換せず、型付きエラーにする。 |
| ハッシュ | `HashSet`のバケット選択に使い、局面一致は常に`Eq`で確定する。 |
| 実行状態 | generatorは呼び出し間の可変状態を持たない。 |
| 最適化 | 全機能版の計測後に、支配的と確認された処理だけを変更する。 |
| 互換性 | 旧一時状態型、別名API、暗黙の規則変更および失敗時の代替経路を残さない。 |

## 一時状態の統合

盤面と手番だけから導出できず、過去の着手に由来して、後続の合法手または局面同一性の判定に影響する局面付随状態を**一時状態**と定義する。
公開型は次の形とする。

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct LastLionCapture {
    pub square: Square,
}

#[derive(Clone, Copy, Default, PartialEq, Eq, Hash, Debug)]
pub struct TransientState {
    pub last_lion_capture: Option<LastLionCapture>,
    pub promotion_deferred: Bitboard,
}
```

`LastLionCapture`は、直前の着手で獅子以外の駒が相手獅子を取った升を保持する。
角鷹または飛鷲が経由升で獅子を取り、その後に別の升へ進んだ場合、記録升は空になり得る。

既存の`LionTrigger::by_kirin_promotion`は削除する。
L2の麒麟成り例外は、記録升に直前着手側の麒麟由来の成獅子がいるかどうかから導出できるため、独立した真偽値を保持しない。
これに伴い、麒麟成りフラグ専用のZobristキーも削除する。

`Position`は`lion_taken_by_non_lion`と`promotion_deferred`を個別に保持せず、1個の`transient: TransientState`を保持する。
通常Zobrist値とP1権利Zobrist値は派生キャッシュであるため、`TransientState`には含めない。

`Undo`は個別の一時状態フィールドを廃止し、着手前の`TransientState`全体を`previous_transient`として保存する。
`TransientState`は固定長の`Copy`型であり、現行`Undo`が保存している同じ情報を一括して復元する。

外部クレートには`Position::transient_state()`を公開する。
`PositionBuilder::set_transient_state()`は、盤面と一時状態の局所的な整合性を検査してから値を設定する唯一の公開構築経路とする。
既存の`PositionBuilder::mark_promotion_deferred()`は削除し、この経路へ置き換える。
`last_lion_capture`の記録升は、空升または構築する局面の`side_to_move().opposite()`の駒がある升だけを許す。
記録升に獅子がいる場合は、麒麟由来の成獅子でなければならない。
手番側の駒または不成の獅子が記録升にある状態は拒否する。

`PositionBuilder::finish()`は2種類のZobrist値を再計算してから`Position::validate()`を呼ぶ順序へ変更する。
これにより、構築途中の古い派生値を入力不正と誤判定せず、完成した局面では派生値の一致も保証する。
プロトコル層の完了後は、その局面設定処理もこの構築経路へ統合する。

## Positionのハッシュ

外部のRustプログラムとgenerator内部で`HashSet<Position>`を使えるよう、`Position`へ`Hash`を実装する。
実装は通常Zobrist値とP1権利Zobrist値を`Hasher`へ渡し、衝突時の同一性判定を既存の`Eq`へ委ねる。

既存の`Eq`は導出実装であり、派生キャッシュである2種類のZobrist値も比較へ含む。
この比較が盤面、手番および`TransientState`による一致判定と同値であることは、`Position::validate()`のZobrist一致検査と、検証済み構築経路だけを公開することによって保証する。

ハッシュ値は永続識別子、交換形式または局面一致の代用として使用しない。
`Position::validate()`は、通常Zobrist値とP1権利Zobrist値が再計算値に一致することも検査する。

## 公開API

実装は`src/core/predecessor/`に置き、`src/core/mod.rs`と`src/lib.rs`から公開する。
公開面は次の形とする。

```rust
#[derive(Clone)]
pub struct PredecessorGenerator {
    forward: MoveGenerator,
}

impl PredecessorGenerator {
    pub fn standard() -> Self;
    pub fn new(rules: Rules) -> Self;

    pub fn generate_predecessors(
        &self,
        target: &Position,
    ) -> Result<Vec<Position>, PredecessorError>;
}
```

`standard()`は`Rules::standard()`を明示的に選ぶ便宜コンストラクタとする。
`new`へ渡された`Rules`はそのまま保持し、規則の不足や矛盾を別の規則へ置換しない。

`generate_predecessors`は重複のない局面を返すが、順序は保証しない。
generatorは規則と既存の`MoveGenerator`だけを保持し、作業領域やキャッシュを呼び出し間で共有しない。

エラー型は少なくとも次の原因を区別する。

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum PredecessorError {
    InvalidPosition(PositionError),
    MaterialExceedsInitial {
        color: Color,
        origin: PieceKind,
        found: u8,
        maximum: u8,
    },
    RuleStateMismatch,
}
```

正常な局面に直前局面がない場合だけ`Ok(Vec::new())`を返す。
P1を採用していない規則で成り権保留状態を持つ場合など、局面単体は構築できても採用規則から生じない状態には`RuleStateMismatch`を返す。

## 駒在庫

中将棋では各対局者が46枚の駒を持って開始し、取られた駒は盤上から除かれて再使用されない。
したがって、直前手で取られた駒は、対象局面で初期在庫から欠けている駒に限られる。

在庫は現在の`PieceKind`ではなく、成る前の由来ごとに数える。
これにより、初期配置の金将と歩兵が成った金将、初期配置の獅子と麒麟が成った獅子を別在庫として扱う。

製品コードの初期在庫は`Position::initial()`から導出し、同じ配置表を別の定数として複製しない。
テストではRULES.md第4条と第5条から独立に書いた期待数と照合し、初期配置と在庫計算が同じ誤りを共有しても検出できるようにする。

対象局面が初期在庫を超える場合は`MaterialExceedsInitial`を返す。
捕獲駒を復元するたびに残数を減らし、2枚捕獲で同じ由来を2回使う場合も上限を超えないようにする。

## 逆向き候補の構成

対象局面の手番と反対側を直前の着手者とする。
対象局面にある直前着手者の各駒を、直前手で動いた駒として順に仮定する。

到達駒が不成駒なら、移動前も同じ不成駒であり、`promote`は`false`である。
到達駒が成駒なら、既に成っていた駒が`promote: false`で動いた場合と、対応する不成駒が`promote: true`で動いた場合を列挙する。

移動元候補は既存の移動プロファイルから`Bitboard`として構成する。

- 固定移動と固定跳びは、相対変位を反転して到達升から移動元を求める。
- 走りは、到達升から進行方向の逆向きへ、空の占有集合を渡した既存の走り利き計算を使う。
- 獅子の1升移動と直接跳びは対称なので、到達升に対する既存表を使う。
- 角鷹と飛鷲は、許可された相対方向を反転して1升前と2升前を求める。

走りでは、対象局面の占有状態を使って経路を打ち切らない。
対象局面から消えている捕獲駒を復元した後の遮蔽物判定は、候補盤面に対する順方向検証へ委ねる。

獅子力のある駒では、1段階移動、直接跳び、じっと、居喰いおよび2段階移動を区別する。
`mid: Some(square)`は経由升で必ず捕獲する正準表現とし、空の経由升を持つ別表現は生成しない。

各候補は`PositionBuilder`で盤面全体を再構築する。
局所的な生変更APIや逆向き差分適用は、性能測定節の第3候補が計測で正当化されるまで追加しない。

## 捕獲駒の復元

通常移動、走り、固定跳びおよび直接跳びでは、到達升が空だった場合と、相手駒を捕獲した場合を列挙する。
2段階移動と居喰いでは、経由升へ相手駒を必ず復元する。
2段階移動の到達升では、非捕獲と捕獲を列挙するため、最大2枚を復元する。
じっとでは捕獲駒を復元せず、居喰いと移動元へ戻る2段階移動では経由升だけへ復元する。
到達升への復元は`to != from`の場合に限る。

復元候補は相手側の不足在庫から選ぶ。
成れる由来駒については、捕獲時に不成だった場合と成っていた場合を双方列挙する。
本将棋の持駒のような所有者変更や駒打ちは導入しない。

## 一時状態の逆生成

直前局面の`last_lion_capture`は着手適用時に上書きされるため、対象局面から一意に決まらない。
`None`と全144升を上限とする合計145状態から、集合`A`で定義した局所条件に反する値だけを除き、残りを列挙する。
候補`p`の手番側の獅子由来と麒麟由来の駒が両方とも盤上にある場合は、獅子在庫の局所条件により`Some`の全状態が除かれ、`None`だけが残る。
記録升が空の場合は経由升で獅子を取った場合として扱い、候補`p`の`side_to_move().opposite()`の非獅子駒がある場合は到達升で取った場合として扱う。
同じ所有者の麒麟由来の成獅子がある場合だけ、L2の麒麟成り例外を適用できる状態として扱う。
この所有者は`p → q`の着手者ではなく、`p`の一時状態を生じさせたさらに1手前の着手者である。
記録された捕獲の実在は推測せず、局所条件を通った各値を候補着手の順方向再適用へ渡す。
再適用は`p → q`との整合だけを検査し、記録された捕獲の存在を証明しない。
不明値を表す列挙子や`None`への正規化は導入しない。

P1成り権保留状態は、対象局面の`promotion_deferred`から、移動元、到達升および実際の捕獲升のビットを最初にすべて除外して構成する。
着手に影響されない升だけを対象局面から引き継ぎ、移動元の駒と実際の捕獲升に復元した適格駒について、直前の保留ありと保留なしを独立に列挙する。
対象局面の到達升にあるビットは直前手で新設された可能性があるため、そのまま直前局面へコピーしない。
到達升が移動元または捕獲升でもある場合は、その升に直前局面で置く駒について列挙した値だけを使う。
したがって、じっとと居喰いの`from == to`でも対象局面の値を引き継がず、影響升を1個の`Bitboard`へまとめて重複処理を避ける。

P1を採用しない規則で非空の成り権保留状態を持つ対象局面は`RuleStateMismatch`とする。
P2は独立した局面内状態を持たないため、P2用の追加状態を導入しない。

## 順方向検証

逆向きに構成した候補は、その時点では合法手とみなさない。
候補局面の複製へ、同じ規則の`MoveGenerator`を渡した`try_make_move`で候補着手を適用する。

```rust
let mut replayed = candidate.clone();
if replayed.try_make_move(mv, &self.forward).is_ok() && replayed == *target {
    // candidateを採用する
}
```

この1回の順方向検証により、移動、遮蔽物、捕獲、成り、先獅子およびP1状態を既存実装だけで判定する。
逆生成側には同じ合法性判定を複製しない。

採用局面は`HashSet<Position>`で既出判定し、初出時だけ返却用`Vec`へ追加する。
ハッシュ衝突時には`Eq`が完全な局面を比較するため、異なる局面を失わない。

## ローカルルール

L1からL3までとP1からP4までは、候補局面または候補着手の順方向合法性を変え得るため、最初の完成時点からすべて対応する。
標準規則専用の部分実装を完成扱いにしない。

R1からR3までとE1からE3までは、`Position`単位の順方向合法手を変えないため、対局履歴や終局裁定へ展開しない。
規則セット名lishogiのようにE3を含む`Rules`が渡された場合も、generatorは値をそのまま保持するだけで裁定は行わない。
generatorは渡された`Rules`を保持し、後続の`try_make_move`にも同じ値を使う。

## 完全性の根拠

順方向再適用は、生成した候補が正しいことを示す健全性検査であり、候補の漏れがないことまでは示さない。
相対的完全性は、次の3層で検証する。

第1層では、全順方向移動形式と逆構成の対応表を実施記録へ残す。
全144升の完全性をテスト件数だけから主張せず、各移動形式、捕獲数、成りおよび一時状態に対応する逆構成が存在することを場合分けして説明する。

第2層では、固定局面とシード固定局面の全合法手を順方向に適用する。
各辺`p → q`について、`generate_predecessors(q)`が`p`を含むことを確認する。

第3層では、テスト専用の有限状態オラクルを作る。
限定した升集合、駒集合、手番および一時状態を先に全列挙し、既存の順方向生成器から後続局面ごとの直前局面表を作る。
製品コードの逆経路、在庫枝刈りおよび捕獲復元関数をオラクルから呼ばず、有限集合内にある製品出力と集合比較する。

## 検証項目

固定テストは、次の分類をすべて含める。

| 分類 | 必須事例 |
|---|---|
| 通常移動 | 非捕獲、到達升捕獲、盤端および両所有者を扱う。 |
| 走り | 距離1、距離2以上、味方遮蔽、相手遮蔽および捕獲を扱う。 |
| 固定跳び | 中間升が空、味方駒、相手駒の場合と到達升捕獲を扱う。 |
| 獅子の1段階移動 | 非捕獲と捕獲を扱う。 |
| 獅子の直接跳び | 非捕獲と到達升捕獲を扱う。 |
| じっと | 異なる駒のじっとが同じ結果局面へ至る場合も1局面だけ返す。 |
| 居喰い | `from == to`、`mid == Some`および1枚捕獲を扱う。 |
| 2段階移動 | 経由升だけの捕獲と、経由升および到達升の2枚捕獲を扱う。 |
| 角鷹と飛鷲 | 両所有者について、向き付き1段階移動、直接跳び、じっと、居喰いおよび2段階捕獲を扱う。 |
| 成り | 不成のみ、成りと不成の両候補、直前手での成り、既成駒の移動および二重成りの拒否を扱う。 |
| 先獅子 | 標準規則、L1、L2およびL3で、以前の捕獲升と新しい捕獲升を扱う。手番側の獅子在庫が揃っていて`Some`状態が全滅する局面と、記録升が空の状態に必要な角鷹または飛鷲の有無も扱う。 |
| P1 | 移動駒、復元捕獲駒、到達升および無関係な駒の保留状態を扱う。 |
| 在庫 | 不成と成駒の由来、同一由来2枚の復元、在庫充足および在庫超過を扱う。 |

各出力について、直前局面が`Position::validate()`を満たし、手番が対象局面と反対であり、順方向再適用結果が対象局面と完全一致することを検査する。
入力した対象局面は変更されず、返却局面に重複がなく、エラーと正常な空集合が区別されることも確認する。

`tests/`には公開APIだけを使う深さ2の逆方向探索を置く。
初期局面から2手進めた対象局面を逆方向へ2手たどり、`HashSet<Position>`を使って初期局面を発見する。
製品用の探索器は追加しない。

## 性能測定

全機能版の正しさを確立した後、releaseビルドで固定コーパスを測定する。
コーパスには、初期局面付近、1枚捕獲後、2枚捕獲後、成り直後、先獅子状態あり、P1状態あり、および駒が少ない局面を含める。

各局面について、候補構成数、`try_make_move`回数、採用局面数、候補対採用比、経過時間の中央値および95パーセンタイルを記録する。
初回マイルストーンには根拠のない速度閾値を置かない。

性能改善を行う場合は、同じ環境と固定コーパスで変更前後を比較する。
プロファイルで支配的と確認されていない処理は最適化しない。

現時点で判明している変更候補を3つ記録する。
第1に、現行の`try_make_move`は内部で全合法手を生成してから照合するため、検証コストは候補数と全手生成の積になる。
第2に、対象局面の`last_lion_capture`が`Some`である場合、直前手はその記録升で非獅子が獅子を取る着手に限られるため、候補構成段階の枝刈りに使える。
第3に、返却局面の構築と保持が支配的である場合は、`for_each_predecessor(&self, q, f: impl FnMut(&Position))`の形のビジターAPIへ置き換える。
生成器が作業用`Position`を1つ保持し、候補ごとに逆差分の適用、順方向検証および巻き戻しを行い、採用局面だけを参照として閉包へ貸し出す。
`PositionBuilder`による盤面全体の再構築と所有権付き`Vec<Position>`の返却を廃止し、利用側は貸し出された参照から必要な形式だけを自分で複製する。
標準の`Iterator`は自身のバッファへの参照を要素にできないため、外部イテレータではなく内部イテレーションを採用する。
導入する場合は`generate_predecessors`をこのAPIで置き換え、両方式を併存させない。
一意性保証のための既出判定集合は生成器内部に残るため、この変更で削れるのは返却用と利用側の保持分に限られる。
いずれも計測で支配的と確認されるまで導入しない。

## 実装フェーズ

### フェーズ1　一時状態の統合

プロトコル層の完了後に本フェーズを開始する。
`LastLionCapture`と`TransientState`を追加し、`Position`、`Undo`、規則判定、Zobrist更新および完了したプロトコル層を新しい表現へ統合する。
旧型、旧フィールドおよび別の一時状態注入経路は残さない。

`Position::Hash`、`Position::transient_state()`、`PositionBuilder::set_transient_state()`およびZobrist値を含む`Position::validate()`を追加する。
make/unmake、反復判定、拡張SFEN、全既存テストおよびperftに挙動変更がないことを確認する。

### フェーズ2　公開API、入力検査および在庫

`PredecessorGenerator`、`PredecessorError`、由来別在庫計算および衝突安全な重複排除を実装する。
不正局面、規則状態の矛盾、在庫超過、正常な空集合および`Position::Hash`の契約をテストする。

### フェーズ3　通常移動、捕獲および成り

固定移動、走り、固定跳びの移動元候補を`Bitboard`として構成する。
0枚または1枚の捕獲駒、既成駒の移動および直前手での成りを復元し、全候補を順方向に検証する。

### フェーズ4　獅子力と一時状態

獅子、角鷹および飛鷲の1段階移動、直接跳び、じっと、居喰いおよび2段階移動を実装する。
最大2枚の捕獲復元、`LastLionCapture`の最大145状態、P1状態および結果に影響する全ローカルルールを扱う。

### フェーズ5　完全性検証と計測

全順方向辺の逆包含テスト、有限状態オラクル、移動形式との対応表および公開APIによる深さ2の結合テストを追加する。
固定コーパスをreleaseビルドで測定し、候補数、採用数および時間を本書の実施記録へ追記する。

## 完了条件

次の条件をすべて満たした時点で、本マイルストーンを完了とする。

- `LastLionCapture`が捕獲升だけを保持し、麒麟成り例外を盤面から導出している。
- `Position`、`Undo`およびプロトコル層が同じ一時状態表現と構築経路を使っている。
- `Position::Hash`が`Eq`と整合し、衝突時にも異なる局面を保持する。
- 公開APIが本書の定義どおり`Pred_R(q)`を重複なく列挙する。
- 不正局面、在庫超過および規則状態の矛盾が型付きエラーになり、正常な空集合と区別される。
- 通常移動、走り、固定跳び、獅子、角鷹、飛鷲、非捕獲、1枚捕獲、2枚捕獲および成りの固定テストが成功する。
- 標準規則、L1からL3まで、P1からP4までの`Position`遷移に関係する全分岐が検証されている。
- 全順方向辺の逆包含テストと有限状態オラクルとの集合一致が成立する。
- 公開APIによる深さ2の逆方向探索が初期局面を発見する。
- 固定コーパスの測定条件、候補数、採用数、中央値および95パーセンタイルが本書へ記録されている。

- 検証コマンドがすべて成功し、保護対象3ファイルの既存差分が維持されている。

## 逆方向探索への接続条件

本機能だけでは、論文と同じ意味で到達不能を証明できない。
後続の逆方向探索マイルストーンでは、目標集合、探索終了条件、経路保存および`Game`履歴の扱いを別途確定する。

探索を途中で打ち切る場合は、不明と到達不能を別の結果型にする。
open集合が空になるまで探索した場合だけ、generatorの相対的完全性を前提として到達不能を返せる。

本将棋の論文が用いる玉2枚だけの目標集合は、中将棋ではそのまま使わない。
中将棋には持駒と駒打ちがなく、捕獲で減った駒を再び盤上へ増やせないためである。

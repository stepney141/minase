# 世代3の教師データによるPSTの再学習とデータ半分割の診断

## 先に読む要約

本書は、評価関数（駒の種類と升ごとの点数を足すPST、piece-square table）について、性格の異なる2つの作業を定める。
1つ目は、現在の採用版（S0）の評価関数と探索で自己対局の教師データ「世代3」を新しく生成し、それを加えて学習し直したPSTの採否を対局で決めることである。
採用版のPSTは世代0から世代2までの11ファイルで学習しており、最も新しい世代2でも段階7の構成で生成したデータであるため、より強いエンジンが付けた教師値で改善するかを確かめる。
2つ目は、採用版と同じ学習手順のまま訓練データを対局単位で2つに分け、それぞれで学習した2本のPSTを対局させる診断である。
これは、過去の評価関数の候補が検証損失を改善しても対局で負けた理由として、「同じ手順と同程度の損失でも、データの偶然だけで棋力が大きく変わる」という仮説を調べるものである。
1つ目は[逐次確率比検定](../guides/sprt.md)の短時間（STC）と長時間（LTC）の標準手順で採否を決め、2つ目は採否を伴わない固定ノード数の対局で、事前に固定した判定規則に当てはめる。
完了条件は、世代3の候補の採否と半分割の判定が測定記録に残り、採用PSTとROADMAPが結論と一致していることである。

## 状態

進行中。2026年10月2日に起案と着手をした。
世代3の5ファイルの生成を同日に開始した（所要は約19時間）。
学習器の対局単位の半分割オプションは未実装であり、本書のレビューの後にcodexへ委任する。
次の一手は、半分割オプションの実装と、生成中にGPUで行う半分割の2本の学習である。

## 目的

評価関数の改善計画は、2026年9月下旬から10月初めにかけて5件続けて不採用となった。
そのうち教師や学習目標を変えた候補は、検証損失をほとんど変えないまま、STCで約−57から−164 Eloの大きな負けを示した（[混合比λ=1.0](../measurements/teacher-mixing-ratio-100-stc.md)、[探索局面の対照A](../measurements/search-aware-pst-a-vs-base-stc.md)）。
本書は、この状況に対して2つの方向から手を打つ。

世代3の再学習は、学習手順を変えずに教師データだけを新しくする、従来の世代反復のやり方である。
世代反復は世代0から世代2まで、いずれも採用に至った実績がある。
世代2を生成した段階7の構成に比べ、現在のS0は段階8の枝刈り、2回のSPSAによる探索係数の調整、および先読み教師で学習したPSTを含むので、同じ1局面10万ノードの探索でも教師値はより正確になると期待できる。

データ半分割は、評価関数の候補を検証損失で選ぶという手順そのものが、棋力の選別として機能しているかを確かめる。
[学習シードだけを変えた測定](../measurements/pst-seed-spread-nodes.md)では、シードがミニバッチの順序しか変えず、重みの差が平均0.06センチポーンにとどまったので、この問いには答えられなかった。
データを対局単位で分ければ、同じ手順で実質的に異なる重みを作れる。
2本の棋力差が大きければ、損失による選別は信頼できず、候補の選別に対局を組み込む必要がある。
差が小さければ、過去の大きな負けは教師の作り方や探索係数との組合せといった系統的な原因によるものであり、原因の候補を絞れる。

## 適用範囲

対象は、世代3の教師データの生成、`tools/train/pst/train_pst.py`への訓練データの半分割オプションの追加、学習した重みファイルだけを差し替えた候補の学習と測定である。
評価関数の特徴、探索、教師データの形式、生成器、および教師値の定義（先読み教師、混合比）は変えない。

本書では次の語を使う。

- **S0**は、本書の起案時のmaster（`44ae7cb`）の採用構成を指す。そのPSTは[先読み教師での再学習](../measurements/lookahead-teacher-pst-training.md)で得たものである。
- **世代3**は、S0の生成器で本書が生成する5ファイル（各7,500局）を指す。世代0から世代2は既存の11ファイルである。
- **採用手順**は、S0のPSTを得た学習条件を指す。鏡映共有モデル、出力K 1072.6529541015625（固定）、学習率0.03、駒除去差分の追加損失の係数1000、10エポック、バッチ16,384、乱数シード1、混合比λ=0.75、先読み教師（γ=0.9、n=40）である。
- **訓練半分**は、訓練の分割に属する対局を、対局単位のハッシュで2群に分けた一方を指す。検証の分割は変えない。

## 依存関係

本書専用のブランチ`pst-gen3`をmasterから作り、候補の重みと学習器の変更を置く。
世代3の生成は、`pst_workflow.py`が基点コミットに固定したworktreeでビルドした生成器で行う（[長時間の生成は生成コミットを固定したworktreeで実行する](../lessons/pin-generation-binary-to-worktree.md)）。
学習は、本書の起案時のmasterの学習器で行う。
その学習器が採用手順でS0の重みをバイト単位で再現することを、候補の学習の前に確かめる。
再現しない場合は、差の原因を特定するまで候補の学習へ進まない。

生成中はCPUの16コアが埋まるので、対局測定は生成の完了後に行う。
半分割の学習はGPUで行い、生成と並行してよい。
実験の途中に他の探索や評価関数の変更を取り込まない。

## 設計判断

| 項目 | 決定 |
|---|---|
| 世代3の生成条件 | 世代2と同じ条件にそろえる。各7,500局、1局面100,000ノード、同時16対局、置換表16 MB、手数上限4,000、序盤のランダム着手0、基本シード1100000、1200000、1300000、1400000、1500000である。教師の除外（詰み帯、最善手が捕獲または成りの局面、同一対局内の再出現）は生成器の既定のとおり適用する。 |
| 既存の15,000局を使わない理由 | [順位の損失の計画](rank-loss-training.md)がS0の生成器で作った15,000局は、捕獲局面と成り局面も記録しており、世代0から世代2の教師と分布が異なる。学習器で静かな局面だけを選ぶ変更より、世代2と同じ条件で生成し直すほうが単純で、世代間の条件差を作らない。 |
| 世代3の候補 | 結果を見る前に次の2本に固定し、追加しない。候補G3は世代0から世代3の全16ファイル、候補G23は世代2と世代3の10ファイルを入力とする。G3は世代反復の従来のやり方であり、G23は古い世代を外すことの効果を見る。どちらもS0の重みを初期値とし、採用手順で学習する。 |
| 世代3の採否 | 候補ごとにS0に対してSTCとLTCの標準手順で測る。両方がLTCで採用条件を満たした場合は、G23をG3と対局させるLTCのGSPRTを行い、`H1`ならG23を、それ以外ならG3を採用する。一方だけが満たした場合はその候補を採用する。 |
| 学習後の診断 | 段階7と段階9の基準に従う。量子化の前後の平均絶対誤差が2センチポーン以下、Rustと学習器の評価値が一致、駒除去差分の符号の反転なし、および除去差分から導いた駒価値が探索用駒価値の±5%以内であることを確かめる。失敗した候補は測定へ進めず原因を調べ、設定を変えて通す再学習は行わない。 |
| 半分割の入力と初期値 | 採用手順の入力（世代0から世代2の11ファイル）と、S0の学習が使った初期値（`6c5c559`の重み）を使い、S0の学習を半分のデータで繰り返す形にする。世代3を含めないのは、生成の完了を待たずに実行でき、結果を採用中の手順そのものに当てはめられるためである。 |
| 半分割の分け方 | 対局単位で分け、同じ対局の局面を同じ群に入れる。ファイル単位では世代と群が交絡するためである。群は、ファイルのヘッダのシードと対局番号から計算するハッシュで決める。検証の分割に使うハッシュとは別の値を使い、検証の分割と訓練半分の割り当てが相関しないようにする。検証の分割は変えない。 |
| 半分割の測定 | 訓練半分0で学習した重みをA、訓練半分1で学習した重みをBとする。A対B、A対S0、B対S0を、1手100,000ノードの固定局数Eloで各400ペア測る。固定ノード数にするのは、PSTの差し替えでは探索速度が変わらず、時間制御の雑音を除けるためである。 |
| 半分割の判定 | 主たる判定はA対Bで行い、結果を見る前に固定する。95%信頼区間が0を含まない、または点推定の絶対値が40 Elo以上なら「散らばりが大きい」とする。信頼区間が0を含み、かつ点推定の絶対値が20 Elo以下なら「散らばりが小さい」とする。どちらにも当たらなければ、3本すべてを`--resume`で800ペアへ1回だけ延長して判定し直し、なお当たらなければ「中程度で未確定」と記録する。A対S0とB対S0は、データを半分にしたことによる損失の参考値として記録し、判定には使わない。 |
| 半分割の解釈の範囲 | 半分のデータの重みのぶれは、全データの重みのぶれより大きい。重みの標準誤差はデータ量の平方根に反比例するので、約1.4倍と見込む。「大きい」と判定した場合も、全データでの散らばりはこの分を割り引いて述べる。また、本診断は同じ手順の内側のぶれだけを測り、教師や学習目標を変えたときの系統的な効果は扱わない。 |
| 学習シードの散らばりとの関係 | シードの違いは重みをほとんど変えないので、半分割の学習は採用手順と同じシード1を使い、データの違いだけを変える。 |

## 半分割オプションの契約

`train_pst.py train`に、訓練の分割から一方の訓練半分だけを使うオプションを1つ追加する。
値は0または1であり、省略した場合は現在と同じく訓練の分割の全体を使う。
省略した場合の学習の出力は、オプションの追加前とバイト単位で一致しなければならない。

群の割り当ては、局面の対局を識別する値（ファイルのヘッダのシードと対局番号）だけから決定的に計算し、乱数シード、ファイルの読み込み順、およびバッチの構成に依存しない。
両群は互いに素で、合わせると訓練の分割に一致する。
検証の分割、教師Kの推定、および先読み教師の計算は、オプションの値によって変わらない。
教師Kの推定は訓練の分割の全体を使い続け、AとBで同じ値にする。
使った訓練半分の値と、群ごとの訓練局面数を学習の記録（`training.json`）に残す。

## 実装フェーズ

### フェーズ1　世代3の生成

`data/gen3.toml`に設定を固定し、`pst_workflow.py prepare`と`generate`で5ファイルを生成する。
各ファイルを`selfplay_gen inspect`で検証し、除外の理由別件数、手数上限による破棄数、および記録局面数を測定記録`pst-gen3-generation`に残す。

### フェーズ2　学習器の再現確認と半分割オプション

本書の起案時のmasterの学習器で採用手順を実行し、出力がS0の`nets/pst.bin`とバイト単位で一致することを確かめる。
半分割オプションをcodexに実装させ、次をテストで固定する。

- 省略時の出力が追加前と一致する。
- 両群が互いに素で、合わせると訓練の分割に一致し、検証の分割と重ならない。
- 群の割り当てが、乱数シードとファイルの読み込み順に依存しない。
- 教師Kと検証の分割がオプションの値で変わらない。
- 0と1以外の値を拒否する。

### フェーズ3　半分割の学習と測定

採用手順でAとBを学習し、学習後の診断を通す。
AとBの重みの差の平均と最大を、序中盤と終盤に分けて記録する。
世代3の生成の完了後に、A対B（基本シード99400000）、A対S0（99500000）、B対S0（99600000）を測り、判定を測定記録`pst-data-split-nodes`に残す。

### フェーズ4　世代3の候補の学習と採否測定

G3とG23を採用手順で学習し、学習後の診断を通す。
G3は`pst-gen3-g3-stc`（基本シード60000921）と`pst-gen3-g3-ltc`（63000921）、G23は`pst-gen3-g23-stc`（84000921）と`pst-gen3-g23-ltc`（87000921）で測る。
両方がLTCで採用条件を満たした場合の比較は`pst-gen3-g23-vs-g3-ltc`（89000921）で行う。
半分割の測定と世代3の採否測定は、同じ測定機を順に使う。

## 検証

- 世代3の各ファイルについて、`inspect`が全記録の整合を確かめ、生成器のSHA-256が準備の記録と一致することを確かめる。
- 学習器がS0の重みを再現することを、候補の学習の前に確かめる。
- 半分割オプションは、フェーズ2の契約をテストで固定し、`tools/train`の全テストが通ることを確かめる。
- 採否測定は[SPRTの手引き](../guides/sprt.md)の標準コマンドに従い、エンジン異常、時間切れ、および拒否着手が0件であることを採用の条件にする。
- すべてのコミットで`cargo test`、`cargo clippy -- -D warnings`、および`cargo fmt --check`が通ることを確かめる。

## 完了条件

- 世代3の生成記録、半分割の判定、およびG3とG23の採否が測定記録に残っている。
- 採用した場合は、採用PSTと[PSTの学習手順](../guides/pst-training.md)の入力ファイルの一覧が更新されている。
- 半分割の判定に基づき、評価関数の候補の選別方法を見直すかどうかがROADMAPの次期候補に反映されている。
- ROADMAPの状態表が本書の結論と一致している。

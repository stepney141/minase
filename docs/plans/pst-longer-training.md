# 採用PSTの追加学習のエポック数の延長の設計書

## 先に読む要約

本書は、採用PST（駒の種類と升ごとの点数を足す評価表、piece-square table）を、同じデータと同じ学習条件のまま、より多くのエポックで学習し直すと棋力が上がるかを確かめる。
きっかけは[共適応の検証](eval-search-coadaptation.md)の対照である。当時の採用PSTのG23に、同じ10ファイルで10エポックを重ねただけのPST（Pc）が、段階ゲートのSTCとLTCでともに`H1`（得点率約57%）となり、採用PSTになった。
G23もPcも、10エポック目まで検証損失が下がり続けていたので、同じデータでの再学習にはまだ伸びる余地があると考えられる。
そこで、Pcを初期値に最大200エポックまで学び直し、学習に使わない検証用の対局での損失が最小のエポックの重みを候補とする。
学習器は実行ごとに最適化器の状態を作り直すので、結論はこの候補の棋力についてのものであり、最適なエポック数までは確定しない。
早期終了（early stopping）のうち、検証損失が最良のエポックの重みを選ぶ部分は学習器が既に備えているが、学習前の重みも候補に含める点で一般の定義と異なる。
本書は、この選択を一般の定義に合わせ、残りの部分である打ち切りを学習器に加えて、検証損失の最良値が5エポック続けて更新されなければ学習を止める。
これにより、必要なエポック数がわからなくても上限を大きく置け、最小値の後の無駄な計算を省ける。
採否は、現行のmasterに対する標準の段階ゲート（STCとLTCの逐次確率比検定）で決める。
完了条件は、早期終了の変更がmasterへ統合され、候補の採否と学習曲線が測定記録に残り、採用なら採用PSTと学習手順の記述が更新されていることである。

## 状態

起案。2026年10月5日に起案した。
2026年10月5日に、上限を200エポックとし、打ち切りを学習器に加え、最良エポックの選択を一般的な早期終了の定義に合わせる改訂を利用者が承認した。
フェーズ1の実装をブランチ`pst-longer-training`で進めており、次の一手は、変更後の学習器でG23の再現を確かめて統合することである。

## 目的

PSTの学習は、これまで世代ごとに10エポックで行ってきた。
共適応の検証で、G23を初期値に同じデータと条件で10エポックを学習し直したPcがG23より強かったので、同じデータによる再学習で棋力が伸びる余地があることがわかった。
ただし学習器は、実行ごとに最適化器Adamと乱数生成器を新しく作り、量子化した重みから学習を始めるので、Pcの向上が学習の総量によるのか、こうした再初期化によるのかは区別できていない。
本書は、Pcから同じ操作をより多くのエポックで行った候補が強いかを確かめ、強ければその候補を採用する。
結論はこの候補の棋力についてのものであり、エポック数だけの効果や最適なエポック数は確定しない。

Pcの学習では、検証損失はエポックごとに約1.1〜1.5×10⁻⁴ずつ下がり、10エポック目の下げ幅は1エポック目の約7割だった（[学習の記録](../measurements/eval-coadaptation-lambda075-training.md)）。
下げ幅は1エポックあたり約0.965倍の割合で縮んでいた。新しい学習の下げ幅が、Pcの10エポック目の続きとして同じ割合で縮むと仮定すると、残る改善の合計は約3.0×10⁻³と見込まれ、そのうち40エポックで約76%、80エポックで約94%、120エポックで約99%を得る。
10点からの粗い外挿であり、最適化器の状態の作り直しで下げ方が変わることもあるが、最良のエポックが40を超える可能性は高い。
学習器は実行ごとに最適化器の状態を作り直すので、上限が足りなかった結果から学習を続けても、1本の学習の延長にはならない。途切れない1本の学習で最小値まで行くには、最初から十分な上限を置く必要がある。

## 適用範囲

本書の用語を次のように定める。

- **M**は、着手時のmasterの先頭のコミットであり、採用PSTはPc（SHA-256 `a5bc54f1…`）である。
- **候補L**は、Pcを初期値に、Pcと同じ10ファイルと同じ学習条件で最大200エポック学習し、打ち切りを適用して、学習したエポックの中で検証損失が最良のエポックの重みを量子化したPSTである。
- **CL**は、Mの`crates/minase/nets/pst.bin`を候補Lへ差し替え、重みに依存するテストの期待値を改めたコミットである。

対象は、学習器への打ち切りの追加、候補Lの学習、CLの作成、およびCLとMの段階ゲートだけである。
学習器への変更は、打ち切りの追加と、最良エポックの選択から学習前の重みを除くことだけである。探索、対局ハーネス、および教師データは変えない。
学習率の減衰、データの追加、および混合比の変更は、本書では扱わない。

## 依存関係

学習には、[PSTの学習手順](../guides/pst-training.md)のコマンド`pst-workflow`と、Pcの設定ファイル`data/eval-coadaptation-lambda075.toml`の学習条件を使う。
ワークフローは基点コミットの`crates/minase/nets/pst.bin`を初期値にするので、基点コミットをMにすれば初期値はPcになる。
採否の測定は[SPRTの手引き](../guides/sprt.md)の段階ゲートに従う。
本書は[補正1/4のFMの再学習](fm-quarter-current-pst.md)と測定機を共有し、採用PSTを変え得るので、FMの計画より先に完了させる。

## 設計判断

| 項目 | 決定 |
|---|---|
| 初期値 | Pcとする。Pcは、G23の上へ10エポックを重ねて強くなった採用PSTであり、同じ操作の延長として最も直接に問いへ答えるからである。段階開始版の重みから最大エポック数を増やして一度に学習し直す案は、学習の総量を一度に測れるが、Pcで得た向上をやり直すことになり、採用PSTに対する差も読みにくくなるので採らない。 |
| 学習条件 | Pcと同じとする。入力は世代2と世代3の10ファイル、先読み教師（γ=0.9、n=40）、混合比λ=0.75、鏡映共有モデル、出力K 1072.6529541015625、Adam、学習率0.03（一定）、バッチ16,384、乱数シード1、駒除去差分の追加損失の係数1000である。列挙したハイパーパラメータのうち、変えるのはエポック数の上限と打ち切りだけである。ただし学習器は、初期値の重みから駒除去差分の追加損失の参照表を作るので、初期値がG23からPcへ変わると、追加損失の基準もPcへ変わる。この違いも、結果をエポック数だけへ帰属できない理由に含める。1エポックは訓練27,745,843局面をバッチ16,384で回す約1,694ステップであり、[ステップ数の教訓](../lessons/check-steps-per-epoch-before-training.md)が求める総ステップ数を満たす。 |
| 最大エポック数 | 200とする。外挿では最良のエポックが100前後にあると見込まれ、その2倍を上限にする。打ち切らずに200まで回った場合でも約6.7時間で済む。最良のエポックが200になった場合は、損失がまだ下がっていると記録し、さらに延ばすかは後続の計画として利用者が決める。 |
| 早期終了 | 一般的な早期終了の定義に合わせる。基準は、Goodfellow, Bengio, Courville, *Deep Learning*, 7.8節のアルゴリズム7.1と、Kerasの`EarlyStopping`（`min_delta=0`、`restore_best_weights=True`）である。いずれも、検証集合の誤差を一定の間隔で測り、最良値を厳密に下回れば最良の重みとエポックを更新してカウンタを0に戻し、下回らなければカウンタを1増やし、カウンタが待つ回数（patience）に達したら止めて、最良の重みを返す。最良値は無限大から始めるので、最初に学習した評価は必ず最良になり、学習前の重みは返らない。本書の実装は、評価の間隔を1エポック（約1,694ステップ）、待つ回数を5、上限を200エポックとする。既存の学習器は学習前の重みの検証損失をエポック0として最良の初期値にし、出力の候補にもしていた。これを改め、エポック0の検証損失は記録だけにして、最良の選択と打ち切りの数え方をエポック1から始める。既存の動作のままだと、最適化器を作り直した直後に検証損失が一時的に悪化した場合、そこから5エポックで止まって初期値が返り、上限を大きく置いた意味がなくなるからである。学習が初期値を改善したかは、本書の「見送り」の規則で、最良エポックとエポック0の検証損失を比べて判断する。過去に保存された17本の学習では最良エポックが0の例はなく（10が14本、4が3本）、この変更で過去の出力は変わらない。監視する量は、駒除去差分の追加損失を含まない検証集合の二値交差エントロピーであり、アルゴリズム7.1が監視する検証集合の誤差（`ValidationSetError`）にあたる。検証用の局面は、学習に使わない対局（対局の識別子のハッシュで全体の約5%）の全局面であり、毎回同じ局面で計算するので、標本の取り方による揺らぎはない。待つ回数を5とするのは、検証損失の揺らぎが学習の軌道によるものだけで小さく、Pcの学習では10エポック続けて単調に下がっていたからである。下げ幅の下限（`min_delta`）は置かず、Kerasの既定と同じ0とする。同じ学習の軌道では、打ち切りの有無で途中までの経過は変わらないので、打ち切りの効果は、上限を大きく置いたまま最小値の後の計算を省くことである。検証損失が最小のエポックが、未知のデータへの当てはまりや棋力でも最良であるとは限らない。同じ検証集合で多数のエポックを比べる選択の偏りも残るので、採否は段階ゲートだけで判定する。 |
| 打ち切りの指定 | 学習コマンド`train-pst train`に、待つエポック数を指定する`--patience`を加え、ワークフローの設定に省略可能な項目`train.patience`を加える。省略した場合は打ち切らず、既存の設定ファイルと学習の結果は変わらない。止まったエポックと待つエポック数は、学習ログと`<出力名>.training.json`に記録する。準備の記録`inputs.json`の`total_steps`は上限での総更新回数のままとし、実際の更新回数は従来どおり`training.json`の`total_updates`に記録する。 |
| 候補の数 | 候補Lの1つとする。途中のエポックの重みを複数の候補として対局させれば、エポック数と棋力の関係がわかるが、採否に要る測定ではなく、候補ごとに約1時間以上の対局を要するので採らない。学習曲線は学習の記録から得る。 |
| 学習後の診断 | 学習後の診断（Rustと学習器の評価値の一致、量子化誤差、駒除去差分の符号）に加えて、[駒価値の歪みの教訓](../lessons/validation-loss-hides-material-distortion.md)に従い、Pcに対する重みの変化量と、駒除去差分の変化を記録する。駒除去差分の符号の反転が1件でもあれば、対局へ進まずに原因を調べる。 |
| 採否 | CLをMに対してSTC（`pst-longer-training-stc`、基本シード21000000）とLTC（`pst-longer-training-ltc`、基本シード22000000）の標準の段階ゲートで測り、LTCの`H1`と異常0件で採用する。 |
| 見送り | 学習したエポックの最良の検証損失が、エポック0（初期値のPc）の検証損失を厳密に下回らない場合は、学習が初期値を改善しなかったので、対局へ進まずに見送る。 |

## 実装フェーズ

### フェーズ1　早期終了の実装

Mからブランチ`pst-longer-training`とworktreeを作り、「早期終了」と「打ち切りの指定」の節のとおり、学習器とワークフローを改める。
テストでは、改善が指定数のエポック続けて止まったときに止まること、止まった後の出力が学習したエポックの中の最良の重みであること、学習前の重みが出力の候補にならないこと、およびエポック0の検証損失が記録され続けることを固定する。
変更していない部分を壊していないことは、回帰テストとして、[G23の再現](../measurements/eval-coadaptation-trainer-reproduction.md)と同じ引数で打ち切りを指定せずに学習し、出力をG23と比べて確かめる。G23の最良エポックは10なので、変更後も同じ重みが出るはずである。
この比較は決定性を保証するためのものではない。一致しなかった場合も統合は止めず、検証損失の推移と最良エポックがG23の記録と同等なら差の原因を記録して進め、同等でなければコード変更の誤りを疑って調べる。
[PSTの学習手順](../guides/pst-training.md)に`train.patience`を記載する。
完了条件は、`tools/train`の全テストが通り、回帰テストの結果が記録され、実装がmasterへ統合されることである。

### フェーズ2　候補の学習

フェーズ1を統合したmasterの先頭をMとする。
`data/eval-coadaptation-lambda075.toml`の写しで、`run.directory`を`data/pst-longer-training`に、`run.base_commit`をMに、`train.epochs`を200に改め、`train.patience = 5`を加えた設定ファイル`data/pst-longer-training.toml`を作り、準備、学習、診断を行う。

```console
uv run --project tools/train pst-workflow prepare --config data/pst-longer-training.toml
uv run --project tools/train pst-workflow train --run-dir data/pst-longer-training
uv run --project tools/train pst-workflow diagnose --run-dir data/pst-longer-training
```

学習の記録は測定記録`pst-longer-training-training`に残し、エポックごとの検証損失、最良のエポック、止まったエポック、学習後の診断、Pcに対する重みの変化量、および駒除去差分の変化を含める。
完了条件は、候補Lの診断が通過し、記録が残ることである。

### フェーズ3　候補のコミット

`crates/minase/nets/pst.bin`を候補Lへ差し替え、`crates/minase/src/eval/pst/tests.rs`の初期局面の評価値の期待値を、学習ログの`initial position evaluation:`行の値へ改めたCLをコミットする。
開局からの自己対局のテスト（`crates/minase/src/bin/minase/selfplay_gen/opening.rs`）が手数上限に達して失敗した場合は、Pcのときと同じく、対局が終わるノード数へ改める。
`cargo test`、`cargo clippy -- -D warnings`、および`cargo fmt --check`が通ることを確かめる。

### フェーズ4　段階ゲート

CLをMに対してSTCで測る。`H1`、または3,000ペアに達した`pending`で停止時点のLLRが0以上ならLTCへ進み、`H0`、または`pending`でLLRが負なら採用しない。
測定中に作業ツリーの`minase`を再ビルドしても再開できるよう、runnerはMでビルドした`minase`を専用の場所へ固定して使う。

```console
<固定したminase> match run \
  --run-dir data/matches/pst-longer-training-stc --seed 21000000 \
  --candidate commit:<CL> --baseline commit:<M> \
  --each time=10000+100 --concurrency 16 gsprt --max-pairs 3000
```

LTCは、同じ形で`--run-dir data/matches/pst-longer-training-ltc --seed 22000000 --each time=60000+200`とし、`--max-pairs`を付けない。

## 検証

- 学習の設定ファイルとPcの設定ファイルの差が、`run.directory`、`run.base_commit`、`train.epochs`、および`train.patience`だけであることを`diff`で確かめる。
- 準備の記録で、初期値`pst-base.bin`のSHA-256がPc（`a5bc54f1…`）と一致することを確かめる。
- CLとMの差が、重みファイルと重みに依存するテストだけであることを`git diff --stat`で確かめる。
- 段階ゲートの各測定で、エンジン異常、時間切れ、および拒否着手の件数を記録する。

## 完了条件

- 候補Lの学習曲線と診断、および段階ゲートの結果（または見送りの理由）が測定記録に残っている。
- 採用した場合は、候補Lが採用PSTとしてmasterへ統合され、[評価関数の設計書](evaluation.md#教師値と損失)の採用PSTの来歴が更新されている。
- ROADMAPの状態表が本書の結論と一致している。

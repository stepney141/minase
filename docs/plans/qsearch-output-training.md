# 静止探索の出力を学ぶPSTの学習の設計書

## 先に読む要約

本書は、中将棋エンジンminaseの評価関数学習で、学習目標の変更と捕獲局面の追加を分けて比較する。
評価モデルは、駒の種類と升ごとの点数を足すPSTに固定し、学習目標の候補には、探索の深さ上限で捕獲を追加で調べる静止探索の出力を使う。
対照Rは静かな局面の静的評価を教師へ近づけ、候補Qは同じ局面から静止探索した値を同じ教師へ近づける。
候補QcはQと同じ学習目標を使い、捕獲局面を追加する。
R、Q、Qcは、着手時のmasterにある採用版S0を初期値とし、教師、尺度、静かな局面の抽出順、および更新回数をそろえて別々に学習する。
QとQcは、その時点の重みで静止探索の値を決めた末端を区間ごとに取り直し、手番の符号をそろえて末端へ勾配を渡す。
学習前には保存済み6局面の探索を追跡し、200局の小標本で末端の抽出費用、特徴の変化、および勾配の変化を測る。
同じ持ち時間のQ対Rで学習目標の効果を、Qc対Qで捕獲局面追加の効果を調べ、事前の規則で1候補に絞ってS0との採否測定へ進める。
対局には逐次確率比検定GSPRTの短時間条件STCと長時間条件LTCを使い、採用の判定はS0とのLTCで行う（[手引き](../guides/sprt.md)）。
完了条件は、実施不能による見送り、候補の不採用、または1候補の採用が測定記録とともに確定することである。

## 目的

本書は、同じPSTについて、静かな局面の学習目標を静的値から静止探索出力へ変える効果と、その学習へ捕獲局面を追加する効果を別に検証する。
[探索局面の計画](search-aware-evaluation.md)の候補Bは、静止探索の途中で静的評価を呼んだ局面をそのまま学んだ。
Bはそれらの局面の過小評価を半分以下に減らした代わりに、通常の局面を平均251センチポーン高く見積もるようになり、対照Aに対して得点率6.9%で不採用となった（[診断](../measurements/search-aware-pst-diagnostics.md)）。
Bのデータには取り合いの途中局面が含まれ、配置ごとの危険性を区別できないPSTが、通常局面にも同じ補正を及ぼした可能性がある。
本書では静止探索の出力を決めた末端へ勾配を渡し、入力局面と学習目標を分けて検証する。
末端には合法な捕獲が残る場合もあるため、取り合いが完全に解消した局面とは仮定しない。

末端の静的評価を根の教師値へ近づけることは、根から静止探索した出力を学ぶことを意味する。
末端自身の真の価値が根の教師値に等しいとは仮定しない。
RとQは同じ根を使い、QとQcは同じ学習目標を使うことで、比較ごとに変更する要因を1つにする。
評価モデルは現行のPSTに固定する。
PSTで改善しなかった場合も、関係を表せるモデルで同じ学習目標を使う方式を否定したとは解釈しない。
ゲーム理論的価値への収束や評価値の急落の消失は、完了条件にしない。

## 適用範囲

本書の用語を次のように定める。
S0は、着手時のmasterにある採用PSTと探索のコミットを指し、教師、比較の基準、および学習の初期重みに使う。
局面は、その局面で指された最善手によって3種類に分ける。
最善手が捕獲でも成りでもない局面を**静かな局面**、最善手が捕獲である局面を**捕獲局面**、最善手が捕獲を伴わない成りである局面を**成り局面**と呼ぶ。
捕獲局面には、成りを伴う捕獲を含む。
学習の入力になる局面を**根**、根から静止探索して値を決めた静的評価の局面を**末端**、根から末端までの手数を$k$と書く。
重み$\theta$のPSTによる局面$s$の手番側から見た静的評価を$F_\theta(s)$、その重みで根$s$から静止探索したときの末端を$\ell_\theta(s)$と書く。

本書で実装するものは次の5つである。

- 探索の各ノードで、残り深さ、深さの削減量、枝を省いた理由、返した値とその種類を記録する追跡出力を、cargoの機能フラグの内側に実装する。
- 与えた重みで根から静止探索し、値を決めた末端と$k$と末端の種類を出力するコマンドを実装する。
- 自己対局の生成器に、捕獲局面と成り局面も種類の分類とともに記録する指定を加える。
- 自己対局の生成器に、対局ごとの開始手順と着手列を記録と行で対応する別ファイルへ保存する指定を加え、任意の根を反復判定の履歴ごと復元できるようにする。
- 学習器に、末端の静的評価へ根の教師値を当てる学習目標と、区間ごとに末端を取り直す処理を加える。

QもQcも採用しない場合、これらのコードはmasterへ入れない。
採用する場合はその候補の学習に必要なコードだけを統合し、フェーズ0の追跡出力はmasterへ入れない。

次の事項は本書に含めない。

- 評価モデルの表現は変えず、局所2駒表、王駒の射線表、および小型NNUEを実装しない。
- 浅い探索の手の順位を学ぶ損失、TreeStrap、およびTDLeafを実装しない。
- 探索の係数と枝刈りは変えず、フェーズ0で特定の枝刈りが疑われても、その修正は探索の系列へ引き渡す。
- 静止探索は捕獲を伴わない成りを読まないので、成り局面はQとQcのどちらにも使わない。
- 教師値の定義（先読みの式と混合比λ）と出力の尺度Kは、採用PSTを学習したときの値から変えない。教師尺度K_gだけは、既存の推定手順で新しい世代の静かな局面から推定し直し、学習前に固定してR、Q、Qcで共有する。
- 規則は`engine-default`、すなわち`L0,P0,R1,E0`に固定し、他の規則の棋譜を混ぜない。

## 依存関係

方式の根拠は総論、[評価表現の構成案](../research/evaluation-architecture-candidates.md)、および[一次資料の調査](../research/evaluation-learning-primary-sources-2026-09.md)に置く。
PSTの評価、量子化、駒除去の診断、および学習の手順は、[評価関数](evaluation.md)、[先読み教師値](lookahead-teacher.md)、および[学習の手引き](../guides/pst-training.md)を引き継ぐ。
棋力の採否は[SPRTの手引き](../guides/sprt.md)に従う。

S0は着手時のmasterに固定し、本書の完了まで更新しない。
起案時のmasterの探索と採用PSTは、探索局面の計画の基点と同じ挙動であり、[相対2駒評価の準備記録](../measurements/relative-pair-prep.md)が12の子局面の再探索値の一致で確かめている。
そのため、探索局面の計画が[校正](../measurements/search-aware-teacher-calibration.md)で固定した判定の差m=142.1センチポーンをフェーズ3でも使う。
着手までに[段階12](strength-stage12.md)などの採用で探索またはPSTが変わった場合は、同じ校正の手順でmを測り直してから診断へ進む。
実験の途中では、他の計画の変更をブランチへ取り込まない。

フェーズ0は、準備記録の6根と、その再現に使ったスクリプト`docs/measurements/relative-pair-prep/residual_pv.py`をmasterから使う。
フェーズ3の診断は、探索局面の計画の最終診断に使った256根から、フェーズ0の6根を除いた250根で行う。
これらの根は対局の開始手順と着手列が`data/search-aware-evaluation/`に保存されており、反復の履歴を含めて復元できる。
MNSD形式の記録は局面と先獅子状態だけを持ち、着手の履歴を持たない。
生成中の探索は対局の履歴を使っているが、保存形式に履歴がないので、フェーズ2の生成器に対局ごとの開始手順と着手列を別ファイルへ保存する指定を加え、新しく生成する対局の根も履歴ごと復元できるようにする。
総論が求める履歴の保存要件は、この保存で満たす。
候補集合にR、Q、Qcの提案手を加え、安定した根の集合とS0の値を同じ実行の中で計算し直して、各候補とS0を同じ根の対として比べる。
Qcを実施しない場合は、以後の診断と比較からQcを除く。
S0、A、Bの既存の値は参考として並べ、比較の基準にはしない。
根を履歴ごと復元し、候補手の子局面を独立に探索する診断器`search_aware_diagnostic`は、探索局面の計画のブランチ`search-aware-evaluation`にある。
診断器は本書のブランチへ移し、R、Q、Qcの提案手を共通の候補集合へ含められるように拡張する。
教師にはS0の探索と重みを使い、診断器は採否にかかわらずmasterへ統合しない。

測定機は、Descentによる強化学習の本学習（同時16対局で48時間）、段階12の自己対局、および本書のフェーズ2と4で共有する。
各フェーズの計算費用は「所要時間の見積り」の節に示し、生成、学習、探索、および対局は他の計画の重い計算と重ねずに予定する。
重い計算を始める前には、[進行中の測定を確認する](../lessons/check-running-measurements-before-cpu-load.md)。

## 設計判断

| 項目 | 決定と理由 |
|---|---|
| 評価モデル | 現行の鏡映共有つき2端点PSTに固定する。表現を変えずに学習目標の効果を測るためである。 |
| 学習目標 | 根$s$の予測を、現在の重みで全窓の静止探索をした値$Q_\theta(s)=(-1)^kF_\theta(\ell_\theta(s))$とし、教師値との損失の勾配を末端$\ell_\theta(s)$の特徴へ渡す。これは静止探索の出力の回帰であり、末端自身の価値を学ぶものではない。 |
| 末端の取り直し | 区間ごとに、その時点のQとQcの重みで末端を取り直す。固定した重みで1回だけ置換する方式は、重み変更による読み筋の変化を無視する近似となるため、候補にしない。フェーズ1で費用が予算を超えた場合は学習を始めず、別の実験条件を定めるか、見送る。 |
| 末端を選ぶ重み | 取り出しには、区間の開始時の重みを実戦用と同じ手順で量子化したPSTを使い、勾配は浮動小数点の重みで末端について計算する。量子化の前後の差は既存の診断で平均0.6センチポーン程度だが、枝刈りと経路への影響も含めて小標本で確認する。 |
| 捕獲局面の記録 | [評価関数の設計書](evaluation.md)は末端の再構成費用を理由に根を記録する。本書も根を保存し、末端の抽出費用は学習時に測る。Qcを採用した場合に、捕獲局面の除外に関する判断を改める。 |
| 学習データ | R、Q、Qcに、S0で新しく生成する15,000局の同じ自己対局データを使う。RとQには同じ静かな根を渡し、Qcにだけ捕獲根を加える。既存の11ファイルは混ぜず、対局単位の訓練と検証の所属を3者で共有する。 |
| 対照 | RとQは学習目標だけを変え、QとQcは捕獲根の追加だけを変える。3者はS0から独立に学習し、Qの学習済み重みをQcの初期値にしない。Q対R、Qc対QのSTCを別々に行う。 |
| 教師値 | 採用PSTの先読み教師値（γ=0.9、n=40、λ=0.75）を3者で共有する。捕獲局面と成り局面を先読みの平均の窓に加えず、静かな局面の教師値を変えない。捕獲局面の教師値も、後続の静かな局面から同じ式で求める。 |
| 尺度 | 出力の尺度Kは採用時の1072.65に固定する。教師尺度K_gは新しい世代の静かな局面から既存の推定手順で求め、学習前に固定して3者で共有する。教師値の定義は変えないが、K_gの値はS0の学習時から動くので、S0との比較にはこの更新も含まれる。 |
| 学習の設定 | 初期重みS0、学習率0.03、乱数シード1、駒除去差分の追加損失の係数1000を3者で共有する。 |
| バッチの構成 | RとQは同じ静かな局面16,384根を使う。Qcは同じ静かな根へ、訓練集合の比率に従って捕獲根を追加する。回帰損失は各バッチ内の根の平均とし、駒除去損失は3者とも同じ静かな根だけで計算する。静かな根の除外も3者で共有する。 |
| 更新回数 | 総更新回数は、除外前のRの訓練集合を10周する回数に固定して3者でそろえる。区間ごとの除外で更新回数を変えない。 |
| 重みの選択 | 3者とも最終の更新後の重みを使う。定義の異なる検証損失で区間を選び直さない。 |
| 採否の順序 | Q対RとQc対Qで個々の変更を測る。QcをS0比較へ選ぶ場合にはQc対Rも通過させる。S0との採否測定へ進める候補は、これらのSTCから事前規則で1つに決める。RだけのS0比較は行わない。 |
| 探索の追跡 | フェーズ0はQの採否と独立の診断とし、その結果で学習へ進むかを決めない。6根は教師の判定が安定した根から損失の大きい順に選んだ標本であり、誤り全体を代表しないためである。 |

## 探索の見落としを追跡する

フェーズ0では、[相対2駒評価の準備記録](../measurements/relative-pair-prep.md)の6根で、S0の100,000ノードの探索が教師の手順をどこで失うかを調べる。
準備記録によれば、6根すべてで、S0の提案探索の名目深さの内側に、2つの読み筋の駒の損得がm以上離れる位置があった。
最初の3根ではS0の提案手の後に相手の応手で駒を失い、次の2根では教師の最善手が6手以内に駒を得る。
前者では提案手の過大評価、後者では教師の最善手の過小評価が疑われるため、それぞれの手順と、浅い探索が返した値を照合する。
名目深さはすべての枝の到達深さを表さず、通常の読み筋には静止探索の手も含まれない。
残る1根では教師推奨手の駒の損得が読み筋末端でも悪かったため、駒の損得の差だけでは取り合いの決着や探索機構の原因を確定できない。
深さ削減や枝刈りに加え、末端での静的評価、置換表の上下界、探索の打ち切りを調べ、原因を特定できない根もそのまま記録する。

追跡用ビルドは、指定した手順に沿うノードごとに、その手が探索されたか、深さの削減後の残り深さ、枝を省いた理由、返した値とその上下界の種類を記録する。
静止探索に入った場合は、差の見込みによる枝刈りと静的交換評価SEEによる枝刈りの判断も記録する。
手順には、教師の10,000,000ノードの読み筋を使う。
追跡は機能フラグ`search-trace`の内側に置き、フラグなしのビルドはmasterとbenchの総ノード数と最善手が一致することを確かめる。

浅い探索の値が教師の読み筋から最初にm以上外れたノードを特定した後、そこで働いた機構を1種類ずつ無効にして、S0の提案探索と同じ完了深さまで探索し直す。
無効化は追跡用ビルドだけが持つ診断の手段であり、棋力測定の比較スイッチではない。
固定ノードで枝刈りを外すと到達深さも下がるため、同じ深さを完了する条件で機構の関与を調べる。
その後、100,000ノードの固定でも根の選択が教師の手へ変わるかを記録する。

各根は、追跡と介入の両方で1つの機構の関与を確認できた根、複数の機構の関与が疑われる根、特定できない根に分類する。
名目深さ内に駒の損得の差があるだけの根は、特定できた根へ数えない。
同じ機構が3根以上で特定された場合は、段階12または探索の後続計画の候補として記録し、本書では修正しない。
本書が機構の関与を調べる条件は、同じ完了深さと固定100,000ノードに限る。
総論が求める固定時間での効果の測定は、引き渡し先の計画が探索の変更を実装したうえで、段階ゲートのSTCとLTCとして行う。
学習候補の時間制御対局では探索の機構を無効化しないので、本書の対局はこの測定を代替しない。
静止探索の枝刈りが特定された場合は、同じ静止探索を使う末端の取り出しへの影響として、フェーズ1の記録に注記する。
6根は以後、本書のどの検証集合にも使わない。

## 静止探索の末端を取り出す

取り出しのコマンドは、MNSD形式（minaseの教師データの形式）の記録を入力に取り、各根についてS0の探索と同じ静止探索の関数を実行する。
窓は$(-\mathrm{MATE},\mathrm{MATE})$の全窓とし、置換表は読まない。
やねうら王の`qsearch_psv`も、全窓で置換表の読み取りを無効にして末端を抽出している（[一次資料の調査](../research/evaluation-learning-primary-sources-2026-09.md)）。
差の見込みによる枝刈りとSEEによる枝刈りは、実戦の静止探索と同じ処理をそのまま使う。

静止探索の関数は、現在は内部の手を主変化に含めない。
取り出しのビルドでは、機能フラグの内側で値を決めた子の手を記録し、根にその手順を適用して末端を作る。
末端の種類は次の3つに分ける。

- 静的評価で値が決まった末端は、学習に使う。
- 手数の上限`MAX_PLY`で打ち切った静的評価の末端も学習に使い、件数を別に数える。
- 最後の王駒の捕獲による詰みの値で決まった根は、その区間の学習から除き、件数を数える。静かな根の除外はR、Q、Qcで共通にする。

出力は入力の記録と行で対応させ、末端の局面をMNSDと同じ局面の符号で書き、$k$、種類、および根から末端までの着手列を添える。
末端の局面と$k$だけからは着手列を一意に復元できないので、末端の独立再評価へ渡す履歴はこの着手列から作る。
各根について、末端の静的評価に$(-1)^k$を掛けた値が静止探索の返り値と整数で一致することを検査し、一致しなければ停止する。
内部ノードには上下界を返すものもあるため、根の値を実際に決めた返値だけをたどり、静的評価へ到達できたことを確認する。
根を全窓で探索することだけを、内部のすべての返値が正確である根拠にはしない。

## 学習データを作る

フェーズ2では、S0の生成器`selfplay_gen`で15,000局の自己対局を生成する。
ノード数100,000、同時16対局、手数上限4,000、置換表16 MiBは、採用PSTの学習データと同じ設定である。
基本シードは7,500局ずつ2つとし、[隣接シードの教訓](../lessons/derive-seed-adjacent-collision.md)に従って対局数以上離し、過去の生成とも重ねない。
生成は、[生成コミットを固定したworktree](../lessons/pin-generation-binary-to-worktree.md)のバイナリから実行する。

生成器は、静かな局面、捕獲局面、および成り局面を種類とともに記録する。
MNSD形式の予約領域は0でなければならないので、種類は記録と行で対応する別のファイルに持つ。
同じ形式で、対局ごとの開始手順と着手列も別のファイルへ保存し、任意の記録をその対局の履歴ごと復元できるようにする。
詰みの値の帯と同一対局内の再出現による除外は、現行の規則のまま適用する。
生成器は探索を終えた後、選んだ手を指す前に記録するので、記録を増やしても着手の選択と乱数の列は変わらない。
記録する指定のない生成器の出力は、masterの生成器と同じシードで記録の本体がバイト単位で一致することを確かめる。
ヘッダには生成したコミットが入るので、ヘッダの来歴は別に照合する。
記録する指定のある出力から捕獲局面と成り局面を除き、記録数を数え直すと、指定のない出力の記録の本体と一致することも確かめる。
保存した開始手順と着手列から根を復元すると、記録の局面と先獅子状態に一致することも、生成した記録の標本で確かめる。

先読み教師値の計算では、値を求める対象の局面と、平均に使う後続の局面を分ける。
対象はすべての種類の局面とし、平均に使うのは静かな局面だけとする。
現在の学習器は同じ対局のすべての記録を平均に使うので、この区別を加える。

検証集合は、既存の規則どおり棋譜IDのハッシュで対局単位に分け、同じ対局の局面を訓練と検証へまたがせない。

## 対照と候補を学習する

対照Rの根は、訓練集合の静かな局面である。
予測は$\sigma(F_\theta(s)/K)$、教師値は$y=\lambda\,\sigma(\hat v/K_g)+(1-\lambda)z$とし、二値交差エントロピーに駒除去差分の追加損失を加える。
ここで$\hat v$は先読み値、$K_g$は教師の尺度、$z$は対局結果である。
これは採用PSTの学習と同じ損失であり、データだけを新しい世代に替えたものである。

候補Qの根は、Rと同じ訓練集合の静かな局面である。
予測を$\sigma(Q_\theta(s)/K)$に替え、教師値と損失の形はRと同じにする。
候補QcはQと同じ予測と教師値を使い、同じ静かな根へ捕獲根を追加する。
3者は同じS0から独立に学習し、同じ静かな根を同じ順序で使う。
駒除去差分の損失は3者で共通の静かな根に対して計算する。

区間の長さは、除外前のRの訓練集合1周分の更新回数に固定する。
各区間の開始時にQとQcの重みを別々に書き出し、それぞれで末端を取り直してから3者をその区間だけ学習する。
静かな根は、QとQcのどちらかで静的評価の末端を得られなければ、その区間の3者から共通に除外する。
Qcを実施しない場合はQの結果だけで共通の受理集合を決め、捕獲根の除外はQcだけに適用する。
各区間の受理集合、バッチ、および除外数を保存し、3者で静かな根の抽出回数と更新回数が一致することを検査する。
共通に受理できる静かな根がなくなった場合は、学習を停止し、実施不能として記録する。
GPUを使う学習は、[教訓](../lessons/run-gpu-training-outside-codex-sandbox.md)に従い、codexのサンドボックスではなく本環境で実行する。

総更新回数は、Rの訓練集合を10周する回数とする。
1周の局面数はフェーズ2の生成数で決まるので、学習の前に総更新回数を計算し、[2,000回以上](../lessons/check-steps-per-epoch-before-training.md)であることを確かめる。
記録の実績から見積もると、15,000局で静かな局面は約570万となり、総更新回数は約3,300回になる。

## 採否前の診断

学習したR、Q、Qcの重みは、まず整合性を検査し、QとQcについては着手と評価の診断も行う。
第1は既存の整合性の検査であり、RustとPythonの評価と差分の一致、量子化の誤差、および駒除去差分の符号を調べる。
S0にない逆向きの駒除去差分が1件でもあれば、その重みは対局へ出さない。

第2は、学習に使っていない根での着手と評価の診断であり、探索局面の計画の最終診断と同じ手順で行う。
対象は「依存関係」の節の250根であり、いずれもR、Q、Qcの学習データとは別の対局から採られている。
各根で、S0、R、Q、Qcの100,000ノードの提案手と、S0の重みによる1,000,000ノードと10,000,000ノードの教師の提案手を候補集合とする。
各候補手の子局面を両予算で独立に探索し、候補集合のすべての手の組が判定の差m以上の安定した支持か小差に入る根を、教師の判定が安定した根とする。
根の局面自体もS0の重みで10,000,000ノード探索し、通常の評価値が得られた根を通常の根として、静的評価との誤差の基準にする。
記録するのは、安定した根での平均の選択損失、通常の根の静的評価の平均誤差と平均絶対誤差、評価を下げる成り手の件数、およびQとQcの重みでの$k$の分布である。

QとQcは、次の2条件をそれぞれ判定し、どちらかを満たした候補をS0との採否測定へ進めない。

- 安定した根で、根ごとの選択損失の差（候補からS0を引いた値）の平均が有意に正である。
- 通常の根で、根ごとの静的評価の絶対誤差の差（候補からS0を引いた値）の平均が有意に正である。

有意に正とは、差の平均から標準誤差の1.96倍を引いた値が0を超えることをいう。
同じ対局から採られた根は独立でないので、標準誤差は対局ごとに差を合計してから計算する。
対象の根が150に満たない指標は判定に使わず、件数とともに記録する。
この規則は明らかな悪化を除く選別であり、改善を要求するものではない。
過去の候補Bに当てると、選択損失の差の平均は+24.1センチポーン、根を独立とみなした標準誤差は8.57センチポーンなので、Bは除かれる。
S0に負けた対照Aは差が+1.7センチポーンと小さく、この規則では除かれない。
約200根の標本ではAの大きさの差を識別できないので、総論が挙げた「改善したモデルだけを対局へ進める」条件は判定に使わず、記録にとどめる。
フェーズ3の学習の前に、この規則をAとBの保存記録へ対局単位の標準誤差で当てた結果を記録する。
採否は次節の対局で決める。
整合性を通過したQは、採用候補から除かれてもQc対Qの対照に使える。
対照としての使用と採用候補としての適格性を分け、除外したQをS0との採否測定へ戻すことはしない。

## 棋力の採否

測定はコミット対コミットで行い、R、Q、Qcの重みを、それぞれS0に`nets/pst.bin`の差し替えだけを加えたコミットに置く。
測定名は`qsearch-output-`で始め、基本シードは測定ごとにペア数以上離す。

比較用のSTCは、`H1`、または上限3,000ペアでLLRが0以上なら通過とし、それ以外は非通過とする。
通過は次の測定への選別であり、長時間での効果の確定とは扱わない。
経路は学習結果を見る前に次のとおり固定し、比較用のSTCは省かない。

1. Q対Rを測り、同じ静かな根における学習目標の変更を調べる（`qsearch-output-q-vs-r-stc`）。
2. Qcが診断を通過していれば、Q対Rの結果にかかわらずQc対Qを測り、捕獲根追加の効果を調べる（`qsearch-output-qc-vs-q-stc`）。
3. Qc対Qが通過した場合はQc対Rも測る（`qsearch-output-qc-vs-r-stc`）。これも通過した場合だけQcをS0との比較へ選び、非通過なら採用候補なしとして完了する。
4. Qcが実施対象外か診断で除外された場合、またはQc対Qが非通過だった場合は、Qが診断とQ対Rを通過していればQをS0との比較へ選ぶ。それ以外は採用候補なしとして完了する。

選んだ1候補だけをS0と標準のSTCとLTCで比べる。
測定名はQなら`qsearch-output-q-vs-base-stc`と`qsearch-output-q-vs-base-ltc`、Qcなら`qsearch-output-qc-vs-base-stc`と`qsearch-output-qc-vs-base-ltc`とする。
振分けと採用の規則は[SPRTの手引き](../guides/sprt.md)の段階ゲートに従い、LTCが`H1`で、エンジン異常、時間切れ、および拒否着手が0件の場合だけ採用する。
選んだ候補のS0比較が非通過でも、残った候補で採否測定をやり直さない。
整合性検査で失敗した重みは対照にも使わず、原因を修正して同じ条件で再学習するか、実施不能として見送る。

## 停止と後続の判断

静止探索値と静的評価値の差が小さいことだけでは、学習へ進むかを決めない。
末端の特徴が変われば勾配も変わり得るため、小標本では値、特徴、勾配の変化を別々に記録する。
学習可能な静かな根を得られなければ実施不能として見送る。
捕獲根を得られない場合はQcを実施対象外とし、RとQの比較だけを行う。
取り出しの費用が基準を超えた場合は、状態を待機中とし、測定記録に費用の内訳を残して利用者に諮る。
諮る内容は、1回だけ置換する方式や取り直しの間隔を広げる方式を別の候補として起案するか、本書を見送りで完了するかである。

診断で除いた候補、比較用のSTCが非通過だった候補、およびS0比較で不採用だった候補は、どの条件で除いたかを分けて記録する。
Q対Rは学習目標、Qc対Qは入力追加、Qc対Rは両変更の合計を測る比較として解釈する。
S0との対局を行っていない候補について、S0より弱いとは結論しない。
新しい世代のデータで学んだRがS0より強いかは本書では測らず、S0による世代の更新という別の問いとして後続の候補に記録する。
選んだ候補とS0の対局は、データの更新、教師尺度K_gの更新、および学習目標の変更を含む工程全体の比較であり、その勝敗から個別の寄与は分離できない。
学習目標の寄与を示すのはQ対Rだけである。
関係を表すモデルの比較は、[関係補正項の計画](relational-correction.md)が、独立した局面群で配置に依存する誤りを確認した場合に限って行う。

Qを採用した場合は、静かな根だけの静止探索出力回帰と取り出しのコマンドを統合する。
Qcを採用した場合は、これに加えて捕獲根の記録と学習を統合する。
採用候補のデータ範囲、教師、尺度、区間、更新回数、および学習時の受理規則を[評価関数の設計書](evaluation.md)と[学習の手引き](../guides/pst-training.md)へ反映し、ROADMAPを更新する。
採否にかかわらず、次は[順位の損失の計画](rank-loss-training.md)、その後に[関係補正項の計画](relational-correction.md)へ進む。
順位の損失の計画には15,000局のデータ全体と元の分割を渡すが、学習に使う局面の種類はQ採用なら静かな根、Qc採用なら静かな根と捕獲根、不採用なら静かな根の静的回帰とする。
関係補正項の計画は、その着手時の採用構成を学習したデータを使うため、両学習計画で候補を採用しなければ従来の採用PSTのデータを使う。

## 所要時間の見積り

各フェーズの主な計算と見積りを次の表に示す。
生成と探索の速度は過去の記録からの推定であり、フェーズ1の小標本の実測で置き換える。

| フェーズ | 主な計算 | 見積り |
|---|---|---|
| 0 | 12の子局面の10,000,000ノードの探索と、機構ごとの再探索 | 1時間以内 |
| 1 | 200局の生成、末端の取り出し、256根の根と末端の独立探索 | 約30分 |
| 2 | 15,000局の生成（同時16対局） | 約4〜8時間 |
| 3 | R、Q、Qcの学習、および250根の診断の探索 | Rの学習は1時間以内、QとQcは取り出しを含めて各2時間以内、診断は約15〜20分 |
| 4 | 最大STC 4本とLTC 1本 | STCは各約1〜8時間、LTCは約4〜21時間 |

フェーズ2の見積りは、世代1の生成が7,500局に約3.9時間を要した記録を上限とし、その後の[合法手生成の高速化](movegen-speedup.md)と[第2期](movegen-speedup-2.md)で1秒あたりの探索ノード数が上がったことから下限を見積もった。
Rの学習の見積りは、採用PSTの学習が約2,500万局面の10周に約27分を要した記録による。
QとQcの学習の見積りは、それぞれこの時間に取り出し10回分の上限60分を加えたものである。
取り出しはQとQcで別に行い、両候補を実施する場合の上限は合計120分とする。
フェーズ1の10,000,000ノードの探索は、段階9の測定で1局面約6.7秒だったので、約510回を同時16で実行して約4分になる。
フェーズ3の診断は、探索局面の計画の最終診断が同じ256根を同時16で約15分で終えた記録を基に、候補手の追加分を見込む。
実際の費用は候補手の重複率にも依存するため、実行時に内訳を記録する。
STCの見積りは、過去の評価関数のSTCが約300ペアで約50分だった記録による。
上限の3,000ペアまで続いた場合は約8時間を要する。
LTCの見積りは、SPSAの係数のLTCが約500ペアで約4時間だった記録による。
真の差がH1の10 Eloに近い場合、[手引き](../guides/sprt.md)は判定までに約2,600ペアを見込んでおり、同じ速度なら約21時間を要する。
Qcを実施せずQが採否測定へ進む経路ではSTC 2本とLTC 1本になり、採用候補が残らない経路ではS0との対局を行わない。

## 実装フェーズ

### フェーズ0　探索の見落としの追跡

追跡用ビルドと機構ごとの無効化を実装し、6根を追跡して分類する。
結果は測定記録`qsearch-output-search-trace`へ残す。
完了条件は、6根の分類と引き渡しの有無が記録され、機能フラグなしのビルドのbenchがmasterと一致することである。

### フェーズ1　末端の取り出しと小標本

生成器の記録の指定と取り出しのコマンドを実装し、200局を生成して末端を取り出す。
結果は測定記録`qsearch-output-leaf-sample`へ残す。
記録する項目は、局面の種類ごとの$k$の分布、末端の種類ごとの件数、1根あたりの取り出し時間、根と末端の特徴と勾配の変化、および独立探索の比較である。
特徴の比較には、局面$s$の手番と局面段階を反映したPSTの特徴ベクトル$\phi(s)$を使い、$\phi(s)$と$(-1)^k\phi(\ell(s))$が異なる根の割合を記録する。
勾配の比較では、同じS0の重みと同じ教師値を使い、静的回帰と静止探索出力回帰の根ごとの損失と勾配の差を求める。
静止探索の出力と根の静的評価が近くても、取り合いによって特徴が変われば勾配は変わり得るため、出力の差と勾配の差を分けて集計する。
独立探索の比較では、$k\ge1$の根から最大256根を抽出し、根と末端をS0の重みでそれぞれ10,000,000ノード探索して、手番の符号をそろえた差の分布を記録する。
該当する根が256未満なら全件を使い、0件なら比較不能として件数を残す。
根の探索には、フェーズ1の生成で保存した開始手順と着手列から復元した履歴を渡す。
末端の探索には、その履歴に根から末端までの着手列を加えた履歴を渡す。
この差は、根の教師値を末端へそのまま付け替える近似がどの程度外れるかを示す記録であり、判定には使わない。

フェーズ2へ進む条件は、末端と返り値の一致を検査でき、学習可能な静かな根が得られ、取り出し費用が予算内に収まることである。
費用は局面の種類ごとの件数と実測時間から見積もり、同時16でQとQcの各訓練集合を10回取り出す時間が、それぞれ60分以内であることを求める。
両候補を実施する場合は合計120分以内とし、捕獲根を得られずQcを実施しない場合はQの60分以内を条件とする。
出力差、特徴差、勾配差には学習効果を断定する閾値を置かず、学習目標の有効性はQ対Rで検証する。
整合性の問題は修正後に再検査し、根を得られない場合や費用が基準を超えた場合は「停止と後続の判断」の節に従う。

### フェーズ2　学習データの生成

15,000局を生成し、局面の種類ごとの件数、除外の理由別の件数、および先読み教師値の分布を測定記録`qsearch-output-data`へ残す。
完了条件は、記録の一致の検査が通り、教師の尺度を固定したことである。

### フェーズ3　学習と診断

学習器の変更を実装してR、Q、Qcを学習し、採否前の診断を行う。
結果は測定記録`qsearch-output-training`と`qsearch-output-diagnostics`へ残す。
取り出しの時間は、S0の重みで測ったフェーズ1の値だけでなく、QとQcそれぞれの学習中の10回すべてについて記録する。
完了条件は、実施した全候補の学習曲線、共通の静かな根の受理集合、取り出しの統計、および診断の判定が記録されたことである。

### フェーズ4　採否

「棋力の採否」の節の順に対局を行い、測定ごとに記録を残す。

### フェーズ5　現行設計の更新

採否に応じて「停止と後続の判断」の節に従って関係する文書を更新し、本書の状態を完了へ書き換える。

## 検証

完了の前に、次の確認を行う。

- 取り出しのコマンドは、全根で末端の静的評価と静止探索の返り値の一致を検査し、末端への手順を審判層の合法手として再生できることを確かめる。
- 取り出しの単体テストは、駒を取り返せる形と取り返せない形を組み立てた局面で、期待する末端と$k$を仕様から定めて検査する。
- 機能フラグを付けないビルドは、benchの総ノード数と最善手がmasterと一致する。
- 生成器は、記録する指定の有無による記録の本体の一致を、固定シードの小さな生成で検査し、ヘッダの来歴は別に照合する。
- 保存した開始手順と着手列から復元した根が記録の局面と先獅子状態に一致し、末端の探索へ渡す履歴が根の履歴に取り出した着手列を加えたものになっていることを確かめる。
- 先読み教師値は、捕獲局面と成り局面の記録を加えても、静かな局面の値が変わらないことをテストで確かめる。
- 学習器は、同じ静かな根と同じ重みを使い、すべての根で$k=0$の入力を与えたとき、Qの損失と勾配がRと一致することをテストで確かめる。
- 学習器は、根と末端の評価値が等しく特徴が異なる局面で、教師との誤差が0でなければ両者の勾配が異なることを検査し、偶数手と奇数手の末端で符号も確認する。
- 共通の静かな根の受理集合と抽出順、および更新回数がR、Q、Qcで一致し、捕獲根の追加がQcだけに適用されることを検査する。
- 学習器が計算する末端の評価値は、Rustの評価値と一致する。

## 完了条件

次のいずれかが測定記録とともに確定した時点で、状態を完了にする。

- 整合性、学習可能な根、または計算費用の条件から、実施不能による見送りが確定した。
- 採否前の診断と比較用のSTCの規則により、S0との比較へ進む候補がないと確定した。
- 選んだ1候補とS0のSTCまたはLTCで、採否が確定した。

いずれの場合も、フェーズ0の追跡の記録を残す。

# 浅い探索の手の順位を学ぶ損失の設計書

## 先に読む要約

本書は、評価関数PSTの学習に、深い探索が安定して支持する手を浅い探索でも上位に評価させる順位の損失を加えると、同じPSTのまま着手が改善するかを確かめる。
PSTは駒の種類と升ごとの点数を足す現行の評価方式であり、この損失は将棋エンジンBonanzaの探索後順位学習（Minimax Tree Optimization、MMTO）の原理を、人間の棋譜の手から深い探索の手へ置き換えたものである。
浅い探索には、根の各候補手を指した子局面から、駒の取り合いだけを読む静止探索を行う深さ1の探索を使い、その値の差を損失へ入れる。
教師は、候補手の子局面を1,000,000ノードと10,000,000ノードの2予算で独立に探索し、両予算で同じ手を校正済みの差以上で安定して支持した手の組だけを使う。
順位だけでは評価の尺度が決まらないので、採用中の学習方式による値の回帰に順位の損失を重みβで加え、βは学習に使わない検証集合で1つに決める。
比較のため、同じデータと更新回数で順位の損失だけを外した対照Cを作る。
学習の前に256根の小標本で、教師の組の数と生成費用、および浅い探索が教師と逆に並べている組の割合を測り、事前に固定した基準に届かなければ見送る。
採否は、まず候補と対照Cを短時間条件STCで対局させて順位の損失の効果を確かめ、通過した候補を着手時のmasterにある採用版S0とSTCと長時間条件LTCの2段階で対局させて決める。
対局の判定には、逐次確率比検定GSPRTを使う（[手引き](../guides/sprt.md)）。
完了条件は、小標本の判定による見送り、候補の不採用、または候補の採用のいずれかが測定記録とともに確定することである。

## 状態

起案。2026年9月27日に起案した。
方式の根拠は[評価関数を改善する3つの観点](../research/evaluation-improvement-strategy.md)（以下「総論」）の第3の観点と実施順3であり、総論は学習目標を1つずつ比較するため、[静止探索の出力を学ぶPSTの学習](qsearch-output-training.md)（以下「静止探索の計画」）の完了後に着手する。
着手時の値の回帰は、静止探索の計画で採用された方式を引き継ぎ、同計画が不採用なら採用PSTの学習と同じ静的値の回帰とする。
次の一手は、静止探索の計画の完了を待ち、そのときのmasterから専用ブランチ`rank-loss-training`とそのworktreeを作って、フェーズ1の小標本を準備することである。

## 目的

本書は、「浅い探索の手の順位を深い教師へ合わせる損失を加えると、同じPSTのまま着手が改善する」という仮説を検証する。
これまでの学習は局面ごとの値を教師へ近づける回帰だけであり、教師への検証損失が下がっても棋力が上がらない例が続いた。
[探索局面の計画](search-aware-evaluation.md)の候補Bは、モデル選択の損失が下がった一方で、教師が安定して判定した根の選択損失が当時の採用版の26.4センチポーンから50.5センチポーンへ増えた（[診断](../measurements/search-aware-pst-diagnostics.md)）。
順位の損失は、対局で使う判断である手の選択そのものを学習の目的に含める。

学習の対象は深さ1と静止探索による手の順位に限り、深い探索の手順そのものは学ばない。
PSTで改善しなかった場合も、関係を表せるモデルで同じ損失を使う方式を否定したとは解釈しない。

## 適用範囲

本書の用語を次のように定める。
S0は、着手時のmasterにある採用PSTと探索のコミットを指し、教師、比較の基準、および学習の初期重みに使う。
本書の完了までS0を固定し、他の計画の変更を取り込まない。
重み$\theta$のPSTによる局面$s$の手番側から見た静的評価を$F_\theta(s)$、局面$s$から静止探索した値を$Q_\theta(s)$と書く。
根$s$で手$a$を指した子局面を$s_a$とし、根の手番側から見た深さ1の値を$Q^{(1)}_\theta(s,a)=-Q_\theta(s_a)$と書く。
子局面では手番が相手に移るので、子局面の手番側から見た値の符号を反転して根の手番側の値にそろえる。
**値の回帰**は、着手時に採用されている学習方式による局面ごとの損失を指す。
**安定した組**は、根$s$の2手$a,b$について、2手の教師値の差を各予算で求めたとき、両予算で差の絶対値が判定の差m以上で同じ手を支持し、両予算の差どうしの開きもm以内である組を指す。
これは探索局面の計画が定めた「安定した支持」と同じ定義である。
mは[探索局面の計画](search-aware-evaluation.md)が校正した142.1センチポーンであり、着手時のS0が同計画の基点から変わっていた場合は同じ手順で測り直す。

本書で実装するものは次の3つである。

- 根ごとに候補手を選び、各子局面を2予算で探索して、安定した組を記録する教師の生成器を実装する。
- 学習器に、子局面の静止探索の末端を区間ごとに取り直し、順位の損失を値の回帰へ加える処理を実装する。
- 順位の検証集合での正答率と、値の検証誤差を計算する診断を実装する。

子局面の末端の取り出しには、静止探索の計画が実装した取り出しのコマンドを使う。
同計画で候補を採用しなかった場合は、同計画のブランチから取り出しのコマンドだけを本書のブランチへ移し、本書で採用した場合に限ってmasterへ入れる。

次の事項は本書に含めない。

- 深さ2以上の探索による順位、TreeStrap、およびTDLeafは実装しない。
- 評価モデルの表現と探索は変えない。
- 教師値の定義、出力の尺度、および値の回帰の方式は、着手時の採用構成から変えない。
- 規則は`engine-default`、すなわち`L0,P0,R1,E0`に固定する。

## 依存関係

方式の根拠は総論と[一次資料の調査](../research/evaluation-learning-primary-sources-2026-09.md)に置き、Bonanzaの原論文は[Hoki and Kaneko, 2014](https://www.jair.org/index.php/jair/article/download/10871/25935)である。
値の回帰、末端の取り出し、学習データ、および採否前の診断は、静止探索の計画を引き継ぐ。
棋力の採否は[SPRTの手引き](../guides/sprt.md)に従う。

学習データは、静止探索の計画のフェーズ2で生成した15,000局全体を、訓練集合と検証集合の分割を保って引き継ぐ。
順位の学習に使う根は訓練集合から、βの選択に使う根は検証集合から採る。
同じ対局の根、および各根から派生する候補手の子局面、静止探索の末端、教師の組は、すべて元の対局と同じ集合へ置く。
同計画がフェーズ1の判定で見送られてこのデータがない場合、またはその後にS0が変わった場合は、同計画の「学習データを作る」の節の手順で15,000局を生成する。
新しく生成する場合も、同計画の規則で対局単位に分割してから根を抽出する。

値の回帰の設定は、静止探索の計画の採否に応じて次の3通りに分ける。

- 静かな局面だけで静止探索の出力を学ぶQを採用した場合は、Qの学習目標とバッチの構成を引き継ぐ。
- Qに捕獲局面を加えて学ぶQcを採用した場合は、Qcの学習目標とバッチの構成を引き継ぐ。
- QもQcも採用しなかった場合は、同計画の対照Rと同じく、静かな局面だけで静的値を回帰する。

総更新回数は、いずれも同計画と同じく、静かな局面の訓練集合を10周する回数とする。

候補手の子局面の教師探索には、静止探索の計画が対局ごとに保存した開始手順と着手列から根を復元し、その履歴に候補手を加えて渡す。
教師の探索は反復の判定に履歴を使うので、履歴を捨てて局面から新しい対局を始めると、教師の順位が生成時の探索と変わり得るためである。
候補手の各組$(a,b)$は着手の表記の辞書順で順序を固定し、教師値の高い手に合わせて並べ替えない。

採否前の診断は、静止探索の計画と同じく、探索局面の計画の最終診断に使った256根から[相対2駒評価の準備記録](../measurements/relative-pair-prep.md)の6根を除いた250根で行う。
これらの根の診断には、静止探索の計画と同じく、探索局面の計画のブランチ`search-aware-evaluation`の診断器を同ブランチのworktreeから実行し、S0、C、候補の重みを渡す。
この診断器は測定専用とし、masterへ統合しない。
着手までにS0の探索が変わっていた場合は、診断器を本書のブランチへ移して使い、masterへは入れない。

教師の生成は測定機を同時16で数時間使うので、[Athénanの計画](athenan.md)、[段階12](strength-stage12.md)、およびその時点で進行中の測定と重ねずに予定する。

## 設計判断

| 項目 | 決定と理由 |
|---|---|
| 浅い探索の深さ | 深さ1と静止探索に固定する。Bonanzaの原論文の学習と同じ深さであり、子局面の末端の取り出しだけで予測と勾配を計算できるためである。深さ2以上は、選ばれる読み筋が重みとともに変わる影響が大きく、本書では扱わない。 |
| 候補手 | 各根で、10,000,000ノードの教師の最善手、S0の100,000ノードの提案手、およびS0の重みでの$Q^{(1)}$の上位3手を候補とし、重複を除く。浅い探索が上位に置く手のうち教師が支持しない手を下げることが、この損失の目的だからである。全合法手は、教師の探索費用が大きすぎるので使わない。候補手集合は教師の生成時に固定し、学習中に更新しない。学習後のモデルが候補外の手を新たに高く評価しても、その手を直接比べる順位の損失はなく、その手の評価は共有するPSTの重みと値の回帰を通じてだけ変わる。 |
| 教師の組 | 安定した組だけを使い、教師の判定が予算で変わる組や差がm未満の組は使わない。総論は、予算で順位が変わる根を確定した悪手として強く学ばせないことを求めている。 |
| 損失 | 安定した組$(s,a,b)$で教師が$a$を支持するとき、$\log(1+\exp[-(Q^{(1)}_\theta(s,a)-Q^{(1)}_\theta(s,b))/\tau])$を順位の損失とし、組ごとの重みは1とする。尺度$\tau$は判定の差mとし、再校正した場合はその値を使う。教師が区別できる最小の差と同じ尺度で浅い探索の差を測り、教師が区別できない細かな差まで強く学ばせないためである。教師の差の大きさで重みを変える方式は、自由度を増やさないため採らない。総論は、尺度$\tau$を候補選択用の集合で選び、組の重み$w_{sab}$を教師の差と安定性から定める式を例として示す。本書は$\tau$をmに固定してβだけを検証集合で選び、重みは安定した組の選別による0または1に具体化する。 |
| 値の回帰との併用 | 全体の損失を「値の回帰＋β×順位の損失の組平均」とする。順位の損失だけでは評価値の尺度が決まらず、探索の枝刈りの閾値との関係が崩れるためである。 |
| βの選択 | βを0.1、0.3、1.0の3通りで学習し、検証集合の安定した組での順位の正答率が最も高いものを候補にする。ただし、検証集合の静かな局面での静的評価と教師値の平均絶対誤差が、対照Cの1.05倍を超える値は候補にしない。3通りとも超える場合は見送る。 |
| 末端の取り直し | 静止探索の計画と同じく、区間ごとに現在の重みで子局面の末端を取り直す。 |
| 対照 | 対照Cは、同じデータ、初期重み、更新回数で、β=0として学習する。候補とCの差を順位の損失だけに限るためである。 |
| 更新回数 | 値の回帰のバッチの構成と総更新回数は、依存関係で定めたQ、Qc、Rのいずれかの設定を引き継ぐ。順位の損失のバッチは、各更新で安定した組から4,096組を無作為に選ぶ。 |
| 分割 | 引き継ぐ15,000局の訓練集合と検証集合は元の分割を保つ。新しく生成する場合は棋譜IDのハッシュで対局単位に分け、同じ対局の根と各根から派生するすべてのデータを訓練と検証へまたがせない。 |
| 採否の順序 | 候補対CのSTCで順位の損失の効果を確かめ、通過した候補だけをS0とのSTCとLTCにかける。追加学習だけの効果と順位の損失の効果を区別するため、候補対CのSTCは省かない。 |

## 教師の組を作る

フェーズ1では、訓練集合と検証集合からそれぞれ128根を無作為に抽出し、候補手の子局面を2予算で探索する。
記録するのは、1根あたりの安定した組の数、組の種類（教師の最善手対S0の提案手、教師の最善手対$Q^{(1)}$の上位の手など）ごとの件数、教師が詰みの値を示した子の件数、および1根あたりの探索時間である。
詰みの値を示す子を含む組は、値の差をセンチポーンへ換算できないので使わない。

次の2つの判定を、結果を見る前にここで固定する。

- 1根あたりの安定した組の数と探索時間から見積もって、検証の1,000根を含む教師の生成全体が同時16で12時間以内に収まり、その中で訓練用の安定した組を20,000組以上得られること。
- 安定した組のうち、S0の重みで$Q^{(1)}$の順位が教師と逆になっている組が10%以上あること。

第1の判定は、順位の損失の標本数を、学習1回あたり4,096組の抽出が同じ組の繰り返しに偏らない規模に保つためのものである。
第2の判定は、損失が直そうとする誤った並びの頻度を確かめるものである。
正しく並んだ組にも勾配は残るが、その寄与は差を広げるだけであり、S0の誤りを直す組が少なければ候補と対照Cの差は生じにくい。
逆順位の組の予測差の分布と、順位の損失とその勾配の大きさの分布も記録する。
2つの判定は独立に適用し、どちらか1つでも満たさなければ見送りとして記録し、本書を完了する。

2つとも満たした場合は、フェーズ2で、第1の判定の見積りに従って根の数を決め、訓練集合の根の教師を生成する。
検証集合の根は1,000根とし、βの選択に使う。

## 学習する

各区間の開始時に、根の候補手のすべての子局面の末端を、現在の重みで取り出す。
取り直すのは既存の候補手の子局面の末端であり、候補手集合は更新しない。
値の回帰の末端の取り出しも、着手時の採用構成が静止探索の出力の回帰であれば同じ時点で行う。
3通りのβと対照Cの計4本を、同じ乱数シードで学習する。
値の回帰が静止探索出力を使う場合は、4本すべてで静的評価の末端が得られる根をその区間の共通の受理集合とする。
順位の損失では、3候補すべてで両手の静的評価の末端が得られる組だけを、その区間の共通の受理集合とする。
受理集合を保存して同じ抽出順でバッチを作り、値の回帰のバッチは4本で、順位の組は3候補で一致させる。
検証集合でも同じ規則で共通の受理集合を作り、値の回帰の検証損失は4本で、順位の正答率は3候補で分母をそろえ、除外数を記録する。
詰みの値を返す根と組は、順位の勾配を作らず除外数を記録し、必要な受理集合が空になった場合は実施不能として停止する。
GPUを使う学習は、[教訓](../lessons/run-gpu-training-outside-codex-sandbox.md)に従い、codexのサンドボックスではなく本環境で実行する。

学習曲線は、値の回帰の検証損失、順位の検証の正答率、および静かな局面の平均絶対誤差を区間ごとに記録する。
候補の重みは最終の更新後のものとし、区間を選び直さない。

## 採否前の診断

静止探索の計画と同じ2種類の診断を行う。
第1は既存の整合性の検査であり、S0にない逆向きの駒除去差分が1件でもあれば対局へ出さない。
第2は250根での着手と評価の診断であり、候補集合にS0、C、候補の100,000ノードの提案手と教師の両予算の提案手を入れる。
静止探索の計画の規則のとおり、根ごとの選択損失の差または通常の根の絶対誤差の差（候補からS0を引いた値）の平均が有意に正であれば、対局へ出さずに不採用とする。
この規則は、総論が挙げる「候補手順位と過大評価が改善したモデルだけを対局へ進める」条件を、対局前の必須条件にはしない。
約200根の標本では小さな改善を識別できないため、有意な悪化を検出した候補だけを除き、診断の通過を改善や非劣性の証明とは扱わない。

## 棋力の採否

測定はコミット対コミットで行い、候補とCの重みを、それぞれS0に`nets/pst.bin`の差し替えだけを加えたコミットに置く。
測定名は`rank-loss-`で始め、基本シードは測定ごとにペア数以上離す。

最初に、候補とCを標準のSTCで比べる（`rank-loss-vs-control-stc`）。
`H1`であれば、または上限3,000ペアに達した時点のLLRが0以上であれば、次へ進む。
それ以外は、Cに対する10 Eloの改善を示せなかったと記録し、S0に対する強さは測っていないことを明記して不採用で完了する。

次に、候補とS0を標準のSTCとLTCで比べる（`rank-loss-vs-base-stc`、`rank-loss-vs-base-ltc`）。
LTCが`H1`で、エンジン異常、時間切れ、および拒否着手が0件の場合だけ採用する。

## 停止と後続の判断

採用した場合は、[評価関数の設計書](evaluation.md)と[学習の手引き](../guides/pst-training.md)の学習方法を更新し、教師の生成器と学習器の変更をmasterへ統合する。
不採用の場合は、診断、対照Cとの比較、S0との比較のどの条件で除いたかを分けて記録し、対局していない相手に対する強弱は結論しない。
深さ2以上の順位や、関係を表すモデルとの組合せは、[関係補正項の計画](relational-correction.md)の結果を見て別に起案する。

## 所要時間の見積り

| フェーズ | 主な計算 | 見積り |
|---|---|---|
| 1 | 256根の候補手の子局面の探索 | 約15分 |
| 2 | 訓練の根と検証の1,000根の教師の生成 | 最大12時間 |
| 3 | 4本の学習と、250根の診断の探索 | 学習は各2時間以内、診断は約15分 |
| 4 | STC 2本とLTC 1本 | STCは各約1時間から8時間、LTCは約4時間から21時間 |

フェーズ1は、1根あたり最大5手の子局面をそれぞれ約7.4秒（10,000,000ノードの約6.7秒と1,000,000ノードの約0.7秒）で探索し、256根で同時16約15分となる。
フェーズ2の上限は、第1の判定で定めた12時間であり、検証の1,000根を含む。
診断とSTC、LTCの見積りは、静止探索の計画と同じ記録による。
短い方の値は早期に判定が決まった場合、長い方の値はSTCが上限3,000ペアに達した場合と、真の差がH1の10 Eloに近くLTCが約2,600ペアを要する場合である。

## 実装フェーズ

### フェーズ1　小標本

教師の生成器を実装し、256根で安定した組の数と費用、および浅い探索の逆順位の割合を測り、2つの判定を行う。
結果は測定記録`rank-loss-pilot`へ残す。

### フェーズ2　教師の生成

訓練の根と検証の1,000根の教師を生成し、安定した組の数と種類ごとの件数を測定記録`rank-loss-data`へ残す。

### フェーズ3　学習と診断

学習器と診断を実装し、4本を学習してβを選び、採否前の診断を行う。
結果は測定記録`rank-loss-training`と`rank-loss-diagnostics`へ残す。

### フェーズ4　採否

「棋力の採否」の節の順に対局を行い、測定ごとに記録を残す。

### フェーズ5　現行設計の更新

採用した場合は「停止と後続の判断」の節に従って関係する文書を更新し、本書の状態を完了へ書き換える。

## 検証

完了の前に、次の確認を行う。

- 教師の生成器は、同じ根と候補手で子局面の探索値が決定的に再現し、安定した組の判定が定義どおりであることを、判定の境界の値を含む単体テストで確かめる。
- 教師の生成器は、保存した開始手順と着手列から復元した履歴を教師探索へ渡し、同一局面の再出現を含む組み立てた着手列で、履歴なしの探索と反復の判定が異なることを確かめる。
- 元の対局から派生した根、子局面、末端、および教師の組が、訓練集合と検証集合をまたがないことを確認する。
- 学習器は、β=0のときに損失と勾配が値の回帰だけの学習と一致することを確かめる。
- 末端の種類が候補ごとに異なる場合も、区間内の共通の受理集合、バッチ、および検証の分母が定義どおりに一致することを確かめる。
- 順位の損失の勾配は、2つの子局面の末端の特徴にだけ入り、符号が根の手番側の視点と一致することを、組み立てた局面で確かめる。
- 学習器が計算する子局面の深さ1の値は、Rustの静止探索の返り値の符号を反転した値と一致する。

## 完了条件

次のいずれかが測定記録とともに確定した時点で、状態を完了にする。

- フェーズ1の判定、またはβの選択で見送った。
- 学習か検証に必要な共通の受理集合が空になり、実施不能として見送った。
- 採否前の診断、または候補対CのSTCで不採用とした。
- 候補対S0のSTCまたはLTCで採否が確定した。

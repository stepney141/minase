# 審判層の裁定が繰り返す合法手生成の削減の設計書

## 先に読む要約

本書は、対局の審判層`minase_core::game::Game`の着手の適用`Game::play`を、裁定の結果を変えずに速くするマイルストーンの設計書である。
[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)により、MCTS（モンテカルロ木探索）の探索木は新しい節点を作るたびに根の`Game`の複製へ経路の着手を`Game::play`で適用して審判層の裁定を得るようになり、自己対局用のGumbel AlphaZeroの32回の探索で根の探索時間の中央値が0.094 msから0.555 msへ増えた。
プロファイルでは、`Game::play`が着手の合法性検査、反復規則R1（Lishogi式の4回反復の裁定で、攻撃的着手を続けた側を負けとする規則）の攻撃的着手の判定、および合法手なしと詰みの判定で合法手の全件生成を繰り返し、再生する1手につき約10回呼んでいると推定できた。
対策は3つである。第1に詰み判定が候補手ごとに払う費用を遅延評価と疑似利き（利き表による王手判定、attack bitboardによるcheck detection）で減らし、第2に合法性検査、R1の判定、および駒枯れの裁定の全件生成を動かす駒1枚の生成または利きの逆引きで置き換え、第3に合法手なしと詰みの判定で駒ごとに生成して最初の逃れる手で打ち切る。
変更は審判層と、審判層が使う着手の検査`Position::try_make_move`および合法手生成器`MoveGenerator`の駒1枚の生成の入口に及ぶが、公開APIの互換性は壊さない。
疑似利きによる判定は、獅子でない駒の升へ疑似利きが届くこととその駒を取る合法手があることが一致するという補題に基づき、この補題は`Position::gives_check`が既に使い、乱数局面での合法手生成との一致が試験で固定されている。
これらにより、再生1手あたりの全件生成は通常の経路で約10回から1回未満になる見込みである。
完了条件は、裁定の結果が独立した参照実装と一致する試験と既存の試験が通ること、同じ条件で実行した探索の測定の出力が変更の前後で時間の項目を除いて一致すること、および再生1手あたりに正規化した探索時間の中央値が序盤と王駒の捕獲の近傍の両方で変更前の半分以下になった測定記録を残してmasterへマージすることである。

## 状態

進行中。2026年10月28日に起案し、同日に[やねうら王の王手判定と合法手生成の使い分けを審判層の裁定へ応用する調査](../research/yaneuraou-check-detection-for-referee.md)の反映候補5件を取り込んで改訂したうえで、利用者の指示により`referee-adjudication-movegen`ブランチで着手した。次の一手は、フェーズ1の参照試験を現行の実装で通すことである。

## 目的

[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)は、探索木が審判層の詰みと駒枯れの終局を認識しない欠陥を、根の`Game`の複製に経路を再生して裁定を得る方式で直した。
その[測定記録](../measurements/alphazero-audit-remediation/alphazero-audit-remediation-driver-cost.md)では、本番の駆動部を一様評価器で駆動した109局面で、根の探索時間の中央値が自己対局用のGumbelの32回の探索で0.094 msから0.555 msへ、対局用のPUCTの800回の探索で2.09 msから19.1 msへ増えた。
自己対局の生成はGPUの推論が律速である見込みだが、再生の費用は経路の深さと探索回数に比例して積み上がるので、減らせる分は減らしてから[強化学習の実行](alphazero-rl.md)の試走に臨むほうが、試走の結果から再生の費用を切り分けやすい。
本書に現れる規則コードは、RULES.md第31条と第32条が定めるローカルルールの記号であり、R1はLishogi式の4回反復の裁定、R2とR3は既出局面の再現の禁止、E0は標準規則の駒枯れ、E1は王駒の実捕獲による終局、E3は裸玉の即時裁定を表す。

費用の内訳は、同じ測定プログラム`driver_cost`（[tools/train/zero/feasibility/src/bin/driver_cost.rs](../../tools/train/zero/feasibility/src/bin/driver_cost.rs)）を探索関数の区間だけ集計するvalgrindのcallgrindで調べた。
探索の費用に占める割合は次のとおりである。

| 探索の費用の内訳（命令数の割合） | 割合 |
|---|---:|
| `Game::play`（経路の再生） | 93.9% |
| 　うち合法手なしと詰みの判定での合法手生成 | 44.6% |
| 　うち攻撃的着手の判定`move_was_attacking` | 37.4% |
| 　　うちその中の合法手生成 | 34.2% |
| 　うち着手の合法性検査の合法手生成 | 8.8% |
| 葉の`Game::legal_moves` | 3.4% |
| `Game::clone` | 0.14% |
| 木の操作とその他 | 約2.6% |

合法性検査の合法手生成は再生1手につき1回なので、その命令数（再生154,170手で5.82 G命令、1回あたり約37.7 k命令）を単位にすると、合法手なしと詰みの判定の生成が約5.1回、攻撃的着手の判定の中の生成が約3.9回、合計で約10回になる。
これは命令数の比から求めた推定であり、生成1回の費用が局面と手番で異なることを無視している。
全区間での呼出し回数の比（`generate_moves`が3,087,381回、`Game::play`が288,907回）は10.7回だが、この比には、測定の入力局面を作る処理と、結果の集計で着手を再生する処理が混ざる。
根の`Game`の複製（反復の履歴を含む）は0.14%であり、対局の手数の長さは費用の要因ではない。

`Game::play`は1手ごとに、合法性検査で1回、R1の攻撃的着手の記録で1回、合法手なしの判定で1回、詰み判定の冒頭で1回の合計4回の合法手生成を行う（[crates/minase-core/src/game/adjudication/mod.rs](../../crates/minase-core/src/game/adjudication/mod.rs)の`adjudicate_after_move`と`candidate_immediate_result`）。
詰み判定はさらに、候補手を1つ試すごとに、即時結果の判定の中の攻撃的着手の判定と、相手が王駒を取れるかの判定で2回の生成を行う（[mate.rs](../../crates/minase-core/src/game/adjudication/mate.rs)の`is_mate`と`can_capture_last_royal`）。
詰み判定は逃れる候補手が1つ見つかった時点で打ち切るので、R1で早期に終局せず、各候補手の即時結果が定まらない通常の経路では、逃れる手が見つかるまでに試す候補手の数をkとして生成回数は4+2k回になる。
命令数の比から推定したkは平均で約3手であり、合計が約10回になる。
王駒が攻撃されている局面では、詰み判定で逃れる手が見つかるまでに試す候補手の数kが増え、通常のビルドの実測で、再生1手あたりに正規化した探索時間の中央値は序盤の局面で約9 µs、王駒の捕獲の近傍の局面で74〜104 µsだった。
駒枯れの引き分けと猶予、および裸玉の裁定も合法手生成を使うが、双方の駒が王駒だけに近い終盤でしか走らず、上の内訳には現れない。

本書の目的は、この約10回を、裁定の結果を変えずに1回未満へ減らすことである。
合法手生成そのものを速くすることは本書の対象ではない。
置き換えの考え方の多くは、将棋エンジンのやねうら王が探索の中で合法手の全件生成を避ける方法を調べた[調査メモ](../research/yaneuraou-check-detection-for-referee.md)による。

## 適用範囲

本書では、次の作業を行う。

- `candidate_immediate_result`で候補手ごとに先に計算している攻撃的着手の判定を、`R1History::candidate_result`が実際に参照する場合だけ計算する遅延評価にする。
- `can_capture_last_royal`を、相手の王駒が1枚なら`Position::attackers_to_by`の疑似利きで判定し、2枚なら現行の合法手生成で判定する形に改める。
- `Position::try_make_move_with_undo`の合法性検査を、全件生成との照合から`MoveGenerator::is_legal_move`による動かす駒1枚の生成との照合に改める。公開の`Position::try_make_move`も同じ検査を使う。
- `MoveGenerator`に、駒1枚の全合法手と捕獲限定の合法手を生成する`pub(crate)`の入口を足す。
- `move_was_attacking`を、王駒の升ごとの`attackers_to_by`と、到達升の駒1枚に関する捕獲限定の生成で判定する形に改める。
- `can_capture_any_royal`を王駒の升ごとの`attackers_to_by`の論理和に改め、`piece_exhaustion_outcome`の猶予の判定を王駒だけになった側の王駒1枚の生成に改める。
- `adjudicate_after_move`で、合法手なしの判定と詰み判定に使う合法手を駒ごとに生成して両方の判定で順に評価し、最初の逃れる手が見つかった時点で残りの駒の生成を打ち切る。
- 変更から独立した参照実装との突き合わせと、完全な規則と履歴を持つ固定例の試験を加える。
- `driver_cost`の出力に、Gumbelが選んだ手と方策の目標、PUCTの最善手、および終局の勝者を加え、変更の前後を同じ条件で測って`docs/measurements/referee-adjudication-movegen/`に記録する。
- 補題と判定の範囲をdocコメントとADRに書く。

次の項目は対象外とする。

- 経路の再生で着手の合法性検査を省く軽いAPIは、[ADR](../adr/adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)が「GPUの試走で1サイクルの時間が予算に収まらず、再生の費用が主因だと確かめられた場合に限り検討する」と定めているので、本書では扱わない。本書の合法性検査の変更は検査を省かず、生成する駒を減らすだけである。
- `Game`に合法手列を保持して`legal_moves()`に使う案は、効果が探索の約3%で、状態を増やす割に小さいので扱わない。
- `generate_moves`の内部（着手ごとの成りの選択肢の決定、獅子の捕獲制限の検査、および`captured_squares`を着手ごとに2回計算していること）は、αβ探索にも効く汎用の高速化として別の設計書で扱う。
- やねうら王の`checkersBB`のように王駒への利きを局面に付随させて差分更新する方式は、`attackers_to_by`の費用が測定で問題になるまで扱わない。
- αβ探索の根の候補手の選別（`root_repetition.rs`）が行う応手の全件生成は、`Game::play`の外の処理なので扱わない。
- 探索木が経路の深さに比例して再生する構造と、3手詰めの判定のような新しい終局判定は扱わない。

## 依存関係

本書は、masterへマージ済みの[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)の実装を前提とする。
[強化学習の実行](alphazero-rl.md)の内容は変えない。

### 升ごとの補題

本書の疑似利きによる判定は、すべて次の補題に基づく。
相手の駒が獅子でない升について、その升へ手番側の疑似利き（`Position::attackers_to_by`）が届くことと、その駒を取る合法手があることは一致する。
王手を定める第8条（RULES.md）はこの一致を前提にしており、`Position::gives_check`（[crates/minase-core/src/movegen/gives_check.rs](../../crates/minase-core/src/movegen/gives_check.rs)）は同じ補題で王駒1枚の場合を疑似利きで判定し、[その試験](../../crates/minase-core/src/movegen/tests/gives_check.rs)が乱数局面と成りと獅子の規則の組合せで合法手生成による参照実装との一致を固定している。
αβ探索の`royal_under_attack`（[crates/minase/src/search/alphabeta/royal.rs](../../crates/minase/src/search/alphabeta/royal.rs)）も同じ判定を使う。

補題が成り立つ理由は次の4点である。
第1に、着手の合法性を制限する規則のうち、獅子の捕獲制限（第14条）、先獅子（第15条）、および付け喰い（第16条）は獅子を取る手だけに掛かる。
第2に、R2とR3の禁止は、既出局面を再現し得ない捕獲手には掛からない。
第3に、中将棋では王駒を相手の利きへ移す手も王手の放置も合法なので、自分の王駒の安全は着手を制限しない（第8条第3項から第5項）。
第4に、獅子でない駒を取る手を禁じる規則はほかにない。
獅子、角鷹、および飛鷲の2段階移動は、中間の駒を取らずに2升先へ直接跳べる（第11条第1項dと第4項、第12条第5項から第7項）。
経由升で取って元の升へ戻る居喰いも常に生成される。
そのため、中間升が自分の駒や捕獲できない獅子で埋まっていても、対象の駒だけを取る1段階の手は残り、`attackers_to_by`の特殊移動の逆引きがそのまま使える。
成り規則P1からP6は成りと不成の少なくとも一方を残すので捕獲手を消さず、最奥段で移動不能になった歩兵と香車は盤内への利きを持たない。
E3の裸玉は着手の禁止ではなく着手後の即時の裁定なので、候補手の即時結果を先に調べる現行の順序を保てば影響しない。

補題は対象の升ごとに成り立ち、王駒の枚数に依存しないので、「いずれかの王駒を取れるか」は王駒の升ごとの判定の論理和で求められる。
一方、「残存王駒をすべて1手で取れるか」は2枚のときに1手で両方を取る合法手が要るので、補題では判定できない。
`attackers_to_by`のdocコメントは「審判層の判定の代わりにはならない」と記しているので、獅子でない駒の捕獲可能性を例外として補題とともに書き、各判定のdocコメントにも根拠を書く。
この決定はADRに記録する。

### 即時結果の判定を遅延評価にする

`is_mate`は、候補手を仮に指した局面で`candidate_immediate_result`を呼び、候補手が即時の勝ち、負け、または引き分けを生じるかを調べる。
現行の実装は、R1の場合に`move_was_attacking`を先に計算して`R1History::candidate_result`へ渡す。
しかし`candidate_result`は、候補手が不可逆手である場合、可逆手が候補手を含めて12手に満たない場合（第31条R1の前提条件）、および局面の出現回数が3回に満たない場合のいずれかに当たると、その値を見ずに`None`を返す。
攻撃的着手の判定は履歴を変えないので、`candidate_result`がこれらの検査を通過した後にだけ行うよう並べ替えても、返す値は変わらない。
`candidate_result`は`pub(crate)`であり本番の呼出しは1か所なので、攻撃的着手の判定をクロージャ（closure）として受け取るよう引数を変え、後方互換用の関数は設けない。
`record_move`は攻撃の連続数を常に更新するので、記録側の判定はこれまでどおり先に計算する。

### 王駒の捕獲可能性を疑似利きで判定する

`is_mate`は、候補手を仮に指した後の局面で`can_capture_last_royal`を呼び、手番側（詰めている側）が相手の残存王駒をすべて取れる合法手を持つかを、合法手を全件生成して調べる。
王駒が1枚なら、升ごとの補題により、その升へ手番側の疑似利きが届くことと、その王駒を取る合法手があることは一致する。
王将または玉将と太子の2枚が残る場合は、1手で両方を取る合法手が要り、獅子の2枚取りと角鷹や飛鷲の2段階の捕獲の合法性を伴うので、現行の合法手生成を維持する。
王駒が0枚の場合と、`Game::from_position`が枚数を検証しないために構築局面で3枚以上ある場合は、1手の最大捕獲数が2枚なので現行どおり偽を返す。

### 着手の合法性検査を動かす駒1枚の生成にする

`Position::try_make_move_with_undo`（[crates/minase-core/src/movegen/checked.rs](../../crates/minase-core/src/movegen/checked.rs)）は、全合法手を生成して`contains`で照合する。
`MoveGenerator::is_legal_move`は、移動元の駒が手番側の駒であることを確かめてから、その駒1枚の合法手を`generate_piece_moves`で生成して照合する。
`generate_moves`は手番側の全駒について同じ`generate_piece_moves`を呼ぶ和集合であり、獅子の捕獲制限と成りの展開は駒ごとの生成の中で着手ごとに行われる。
そのため、全件生成の列に含まれることと`is_legal_move`が真を返すことは、生成の仕組みの上で一致する。
`predecessor/reverse.rs`は既にこの一致に依存している。
検査自体は省かないので、ADRが先送りした軽いAPIには当たらない。
公開の`Position::try_make_move`は同じ検査を経由するので、審判層の外の呼出しも同じ変更を受けるが、受理する着手の集合は変わらない。
やねうら王は、Stockfishが置換表の手を`MoveList<LEGAL>(pos).contains()`で検証していた箇所を、1手だけを調べる`pseudo_legal_s<true>(m) && legal(m)`へ置き換えている（調査メモ参照）。

### 駒1枚の生成の入口

駒ごとの生成`generate_piece_moves`は`pub(super)`であり、`game`から呼べない。
`MoveGenerator`に、指定した升の駒1枚について全合法手を生成する入口と、捕獲限定の合法手を生成する入口を`pub(crate)`で足す。
どちらも、升に手番側の駒があることを呼出し側の前提とし、出力の列を`output`へ追記し、作業領域`base_moves`を`generate_captures_with_scratch`と同じ契約で消去して使う。
全合法手の列は`generate_moves`の出力からその駒の手を抜き出した列と、捕獲限定の列は`generate_captures`の出力からその駒の手を抜き出した列と、要素、重複、順序まで一致する。
公開APIには足さないので、CONTRIBUTING.mdの互換性の規約には触れない。

### R1の攻撃的着手を利きの逆引きと動かした駒1枚の捕獲生成で判定する

`move_was_attacking`（[crates/minase-core/src/game/repetition/r1.rs](../../crates/minase-core/src/game/repetition/r1.rs)）は、着手側の全合法手を生成し、いずれかの相手の王駒を取る手があるか、または動かした駒（到達升にある駒）に捕獲手があるかを調べる。
起案時の本書は、動かした駒が取れる相手の駒が獅子だけの場合に獅子を取る手が捕獲制限で不合法になり得るとして、この判定を全件生成のまま残していた。
この理由は2つの条件をまとめて疑似利きで判定する案に対するものであり、条件ごとに分ければ全件生成なしに正確に判定できる。
第1の条件「相手のいずれかの王駒を取る合法手がある」は、升ごとの補題により、王駒の升ごとに`attackers_to_by(mover, royal, occupied)`が非空かの論理和で判定する。
第2の条件「動かした駒に捕獲手がある」は、到達升の駒1枚について捕獲限定の生成を行えば、獅子の捕獲制限を含めて全件生成の中でその駒が持つ捕獲手と一致する。
先獅子の状態は`Position`が持つので、他の駒の生成には依存しない。
じっと（隣接升へ進んで同じ着手で元の升へ戻る非捕獲の着手）の到達升は元の升なので、同じ扱いでよい。
捕獲先の駒が獅子でなければ利きの逆引きだけで判定できるが、場合分けを増やすより駒1枚の生成に統一する。
この置き換えは、`record_move`の記録と、遅延評価の後に残る候補手の判定の両方に使う。
やねうら王は、連続王手の千日手のカウンタへ入れる王手の真偽値を、合法手生成ではなく`gives_check`の表参照から得ている（調査メモ参照）。

### いずれかの王駒の捕獲可能性と駒枯れの猶予を1駒の範囲で判定する

駒枯れの引き分け（第22条第8項）と裸玉の裁定（第32条E3）が使う`can_capture_any_royal`（[crates/minase-core/src/game/adjudication/bare_king.rs](../../crates/minase-core/src/game/adjudication/bare_king.rs)）は、手番を入れ替えた局面の複製から全合法手を生成して「いずれかの王駒」を取る手を探す。
条文は升ごとの条件で書かれているので、升ごとの補題により王駒の升ごとの`attackers_to_by`の論理和へ置き換える。
駒枯れの猶予（第22条第5項）の判定（[exhaustion.rs](../../crates/minase-core/src/game/adjudication/exhaustion.rs)の`piece_exhaustion_outcome`）は、王駒だけになった側の手番で、余分な駒または相手の最後の王駒を取れるかを全合法手の生成で調べ、`candidate_immediate_result`から候補手ごとにも到達する。
余分な駒は獅子であり得るので補題は使えない。
しかし、王駒だけになった側が動かせる駒は王駒1枚だけである（死に駒は動けず、第9項により王将と太子を併せ持つ側は余分な駒を持つ側になる）。
したがって、その王駒1枚の生成で全件生成と一致する。
これらは設計書の測定の経路では費用を占めないが、同じ補題と同じ1駒の生成の適用なので、同じ変更で扱う。

### 合法手なしと詰みの判定を駒ごとの生成で打ち切る

`adjudicate_after_move`は、駒枯れの裁定の後に`has_no_legal_move`で手番側の合法手を生成し、続けて`is_mate`が同じ局面の合法手を再び生成する。
どちらも生成の後にR2とR3の禁止手を除く同じ処理を行い、どちらも「条件を満たす手が1つ見つかれば終わる」判定である。
合法手なしは禁止手を除いた最初の合法手で偽が確定し、詰みは最初の逃れる手で偽が確定する。
起案時の本書は全件を1回生成して両方に渡す方式を採っていたが、駒ごとに生成して候補手を順に試し、逃れる手が見つかった時点で残りの駒の生成を省く方式に改める。

手順は次のとおりである。
生成は、王駒の捕獲、反復、駒枯れの猶予、および裸玉の裁定による早期の終了の後に始める。
駒ごとに生成した各候補手について、まずR2とR3の禁止手なら除く。
禁止手でない最初の候補手が出た時点で合法手なしを否定し、E1で詰み判定を省く場合はそこで生成を止める。
詰み判定では、候補手ごとに現行の`is_mate`と同じ順序で、相手の最後の王駒を先に取る手なら逃れる手とし、そうでなければ着手を適用して即時の裁定を調べ、裁定がなければ相手が最後の王駒を取れるかを判定し、着手を復元する。
逃れる手が見つかった時点で、その候補手の復元を済ませてから残りの駒の生成を省く。
全駒の候補手を試し終えて逃れる手がなければ詰みとする。

生成の順序は、駒を3つの群に分け、各駒を最初に属する群で1回だけ生成する。
第1群は手番側の王駒（王将、玉将、太子）である。
第2群は、手番側の王駒へ疑似利きを持つ相手駒の升のいずれかへ`attackers_to_by`が届く手番側の駒である。
第3群は残りの駒である。
各群の中は`PieceKind::ALL`の駒種順、同じ駒種は升の生値の昇順とし、`generate_moves`の順序と比較できるようにする。
王駒が攻撃されている局面では逃れる手が王駒の移動と攻撃駒の捕獲に偏るので、この順序で逃れる手が見つかるまでに試す候補手の数kが減ると見込む。
ただし、逃れる手が反復の裁定による勝ちである既存の固定例のように、王駒の手が逃れる手にならない局面ではkが増える。
そのため、kの減少はフェーズ3の測定で確かめる仮説とする。
中将棋の詰みの定義（第21条第3項）は即時の勝ちと引き分けを生じる着手と相手の最後の王駒を先に取る着手も逃れる手に数えるので、やねうら王の王手回避の生成のように候補を王駒の移動、攻撃駒の捕獲、および合駒に限ることはせず、順序だけを変える。
判定の結果は真偽値なので、生成と走査の順序は結果に影響しない。
`Game::legal_moves`の順序は変えない。

### 期待する効果

通常の経路の生成回数4+2kは、遅延評価で候補手ごとの1回が消えて4+k回、疑似利きの判定で候補手ごとのもう1回が消えて4回になる。
合法性検査の1駒生成とR1の記録の置き換えで、全件生成は合法手なしと詰み判定の2回になり、駒ごとの生成で両方の判定に使えば、逃れる手が見つかるまでの数駒分になる。
王駒が攻撃されている局面では、候補手ごとの費用が合法手生成2回から、着手の適用と復元、駒枯れの判定、および利きの判定だけになる。
王駒が2枚残る場合、R1の反復の裁定が候補手で成立し得る場合、および駒枯れの猶予の判定が走る場合には、追加の生成が残る。
1駒の生成と`attackers_to_by`の費用は、片側の駒数（初期配置で46枚）に比例して全件生成の46分の1になるわけではなく、生成以外の処理も残るので、探索時間の半減はここからは導けない。
Gumbelの32回の探索の根の探索時間は、再生が94%を占める現状の0.555 msから0.2 ms前後になると見込むが、これは命令数の割合からの概算である。
採否は測定記録で判断する。

## 実装フェーズ

### フェーズ1　参照試験

変更の前に、変更する箇所から独立した参照実装を試験に書き、次を固定する。
参照実装は、全件生成で判定する現行の形をそのまま試験の中に持ち、変更後の`candidate_result`、駒ごとの生成、および1駒の生成に依存しない。
局面は、`gives_check`の試験と同じ成りと獅子の規則の組合せごとの`sampled_random_positions`と、各規則セットで乱数により進めた対局の各手の局面とし、それぞれ両方の手番で評価する。

- `is_legal_move`が、全件生成の列に含まれるかの判定と一致すること。候補は全件生成の列の各手と、移動元、経由升、到達升、または成りを1つ変えた不合法な手とする。
- `can_capture_last_royal`が、合法手生成による参照実装と一致すること。固定例として、太子だけが残る場合、王将と太子の2枚が残る場合、構築局面で王駒が3枚ある場合、中間升が自分の駒または捕獲できない獅子で埋まった獅子、角鷹、飛鷲の跳躍、P5とP6の強制の成りを伴う王駒の捕獲、最奥段で移動不能になった歩兵と香車、および王駒が0枚の場合を加える。
- `move_was_attacking`が、全件生成による参照実装と一致すること。固定例として、動かした駒が取れる相手駒が獅子だけで捕獲制限により取れない場合と取れる場合、じっと、動かさなかった駒だけが王駒へ利く場合、および王駒が2枚で一方だけに利く場合を加える。
- `candidate_result`が、不可逆手、可逆手の不足、および出現回数の不足のそれぞれで早期に終了する分岐と、通過して裁定する分岐の結果を返すこと。
- `can_capture_any_royal`と`piece_exhaustion_outcome`が参照実装と一致すること。固定例として、余分な駒が獅子で王駒だけの側がそれを取れる場合と取れない場合、王将と太子を併せ持つ側に対する猶予、および死に駒を含む場合を加える。
- `is_mate`が、同じ局面と固定例で参照実装と一致し、呼出しの前後で局面が復元されること。
- 完全な`Rules`と履歴を持つ`Game`の固定例で、`Game::play`の結果と理由が変わらないこと。R1では、候補手を含む可逆手が11手と12手の場合、同一局面の3回目と4回目の出現、不可逆手による前提の解除、および候補手の即時の勝ち、引き分け、負けを含める。R2とR3では、禁止手を除くと唯一の逃れる手が消える場合と合法手列全体が空になる場合を含め、R3には3回目までの再現と4回目の境界を足す。E1では、合法手なしと詰みの2つの判定のうち詰みだけが省かれ、王駒の捕獲、反復、駒枯れ、および裸玉の裁定は働くことを含める。E0の駒枯れの猶予とE3の即時の裁定が詰み判定より先に働くことも含める。既存の試験（`crates/minase-core/src/game/adjudication/tests.rs`のR1の境界、`crates/minase-core/src/game/tests/win.rs`の詰みの回避とR2、`crates/minase-core/src/game/tests/no_legal_move.rs`、`crates/minase-core/src/game/tests/local_rules.rs`のE1）を再利用し、足りない例を加える。

フェーズの完了条件は、追加した試験が現行の実装で通ることである。

### フェーズ2　実装

「設計判断」の各節を実装し、docコメントを更新する。
駒1枚の生成の入口には、全合法手の列と捕獲限定の列が全件生成からその駒の手を抜き出した列と一致する試験を、居喰い、経由升だけで取る手、および捕獲手がない駒の固定例とともに足す。
遅延評価には、攻撃的着手の判定のクロージャが早期の終了では呼ばれず、裁定に至る分岐で1回だけ呼ばれる試験を足す。
`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、および`cargo test --workspace`を通す。
フェーズの完了条件は、フェーズ1の試験と既存の試験がすべて通ることである。

### フェーズ3　測定

`driver_cost`の出力に、Gumbelが選んだ手と方策の目標、PUCTの最善手、および終局の勝者を加える。
監査対応の測定と同じ手順で、`driver_cost`をmasterの比較元と本ブランチのそれぞれでビルドし、同じシード、同じ対局数、同じCPUコアで、両方とも`--adjudication after`で実行する（`before`は監査対応の前のAPIでビルドするための指定で、裁定の集計を意図的に0にする）。
比較元と本ブランチを同じコアで交互に5回ずつ実行し、局面と方式ごとの反復の中央値から、局面の分類ごとの値を求める。
指標は、1回の探索の時間を再生した着手数で割った「再生1手あたりに正規化した探索時間」とし、Gumbelの32回とPUCTの800回、序盤と王駒の捕獲の近傍の分類を分けて中央値を報告する。
変更の前後の出力は、時間の項目（`elapsed_ms`、`summary_ms`、およびスナップショットの計測値）を除いて一致しなければならない。
一致は回帰の検査であり、裁定の等価性の保証はフェーズ1の試験が担う。
一致しなければ裁定または探索の結果が変わっているので、原因を直してから測り直す。
任意で、探索関数の区間だけを集計するcallgrindのプロファイルを変更の前後で取り、`Game::play`の内訳と、命令数から推定した呼出し元ごとの生成回数を比較元の版とともに記録に添える。
生成の順序の仮説は、詰み判定で試した候補手の数の合計を`driver_cost`の集計に加え、`PieceKind::ALL`順と3群の順の両方で測って確かめる。
記録は`docs/measurements/referee-adjudication-movegen/referee-adjudication-movegen-driver-cost.md`に置く。

ADRを追加し、ROADMAPの状態表と現在地を更新する。

## 検証

フェーズ1の参照試験と固定例に加えて、次の試験を追加する。

- 固定の局面で、王駒1枚が疑似利きで攻撃されている詰み、2枚の王駒を獅子が1手で取れる詰み、2枚の王駒が隣接せず詰みにならない場合、候補手が即時の勝ちまたは引き分けになる場合の回避、および候補手が即時の負けになる場合に回避にならないことを確かめる。既存の固定例（監査が再現した駒枯れの勝ち、駒枯れの引き分け、および詰みの3例、R1の正確な裁定、駒枯れの猶予、E1での詰み判定の省略）は変えない。
- 駒ごとの生成の順序を変えても`is_mate`と合法手なしの判定の結果が変わらないこと、および逃れる手が第1群から第3群のいずれの駒の手でも見つかることを、固定の局面で確かめる。

マージの前に、[docs/guides/testing.md](../guides/testing.md)の「運用」の節が定める4つの検査を通す。
審判層、αβ探索の根の候補手の選別（`crates/minase-core/src/game/root_repetition.rs`の試験）、探索木の終局判定、対局ハーネス、および自己対局の生成器の既存の試験は、この検査の対象に含まれる。
`driver_cost`の変更の前後の出力が時間の項目を除いて一致することを確かめ、記録に残す。
αβ探索の根の候補手の選別は`Game::play`を使うので、深さ6のbench（`--depth 6 --threads 1`）の局面ごとの結果が比較元と一致することを確かめる。
裁定の結果が同一なので棋力は変わらず、SPRTは行わない。
コミットの種別は`perf`とする。

## 完了条件

本書の完了条件は、次の4つをすべて満たすことである。
「検証」の節の試験と既存の試験がすべて通る。
`driver_cost`の変更の前後の出力が時間の項目を除いて一致する。
再生1手あたりに正規化した探索時間の中央値が、Gumbelの32回とPUCTの800回のそれぞれで、序盤の局面と王駒の捕獲の近傍の局面の両方で変更前の半分以下になった測定記録が残る。
補題と判定の範囲をdocコメントとADRへ移したうえで、実装と文書がmasterへマージされる。
半減は採否の目標であり、生成回数の削減から導かれる保証ではない。
半分以下にならなかった場合は、測定記録に内訳を残して利用者の判断を仰ぐ。

- プロファイルの再現手順：通常のビルドは`target-cpu=native`の命令をvalgrindが解釈できないので、計測用に別ディレクトリへビルドする。`--toggle-collect`は命令数だけを区切り、呼出し回数は全区間の値のまま出る。

```console
RUSTFLAGS="-C target-cpu=x86-64-v2" cargo build --release --offline --locked \
  --manifest-path tools/train/zero/feasibility/Cargo.toml --bin driver_cost --target-dir <出力先>
valgrind --tool=callgrind --collect-atstart=no --toggle-collect='driver_cost::search' \
  --callgrind-out-file=<記録> <出力先>/release/driver_cost --seed 20261028 --games 32 --adjudication after
callgrind_annotate --tree=both --inclusive=yes <記録>
```

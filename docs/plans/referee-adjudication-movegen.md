# 審判層の裁定が繰り返す合法手生成の削減の設計書

## 先に読む要約

本書は、対局の審判層`minase_core::game::Game`が着手ごとに行う裁定のうち、合法手なしと詰みの判定、および反復規則R1の攻撃的着手の判定が繰り返し呼ぶ合法手生成を減らし、裁定の結果を変えずに`Game::play`を速くするマイルストーンの設計書である。
[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)により、MCTS（モンテカルロ木探索）の探索木は新しい節点を作るたびに、根の`Game`の複製へ経路の着手を`Game::play`で適用して審判層の裁定を得るようになった（[ADR](../adr/adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)）。
その結果、根の探索時間の中央値は、自己対局用のGumbel AlphaZeroの32回の探索で0.094 msから0.555 msへ増えた。
監査対応の完了後に取ったプロファイルでは、探索全体の命令数の94%を`Game::play`が、91%を合法手生成`generate_moves`が占め、再生する1手につき合法手生成が約10回呼ばれていると推定できた。
対策は審判層の内部の3点である。
第1に、詰みの回避手の候補ごとに先に計算している攻撃的着手の判定を、反復の裁定が実際に参照する場合だけ計算する遅延評価にする。
第2に、合法手なしの判定と詰み判定で同じ合法手列を1回だけ生成して共有する。
第3に、候補手の後に相手が最後の王駒を取れるかの判定を、王駒が1枚なら合法手生成ではなく疑似利き（利き表による王手判定、attack bitboardによるcheck detection）で行う。中将棋では王将または玉将と太子（醉象の成駒）が並び立つので、王駒は最大2枚残る。
第3の判定は、王駒が1枚なら「疑似利きが届くこと」と「合法手で取れること」が一致するという補題に基づく。この補題は`Position::gives_check`が既に使い、乱数局面での合法手生成との一致が試験で固定されている。
これら3点により、再生1手あたりの合法手生成は通常の経路で約10回から約3回になる見込みであり、王駒が攻撃されている局面では候補手ごとの生成2回が安価な利きの判定に置き換わる。
審判層は対局ハーネス、USIの対局進行、自己対局の生成器、およびαβ探索の根の候補手の選別も使うので、効果はMCTSに限らない。
完了条件は、裁定の結果が独立した参照実装と一致する試験と既存の試験が通ることと、同じ条件で実行した探索の測定の出力（選んだ手、方策の目標、終局の勝者を含む）が変更の前後で時間の項目を除いて一致することである。
そのうえで、再生1手あたりに正規化した探索時間の中央値が序盤と王駒の捕獲の近傍の両方で変更前の半分以下になった測定記録を残して、masterへマージする。

## 目的

[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)は、探索木が審判層の詰みと駒枯れの終局を認識しない欠陥を、根の`Game`の複製に経路を再生して裁定を得る方式で直した。
その[測定記録](../measurements/alphazero-audit-remediation/alphazero-audit-remediation-driver-cost.md)では、本番の駆動部を一様評価器で駆動した109局面で、根の探索時間の中央値が自己対局用のGumbelの32回の探索で0.094 msから0.555 msへ、対局用のPUCTの800回の探索で2.09 msから19.1 msへ増えた。
自己対局の生成はGPUの推論が律速である見込みだが、再生の費用は経路の深さと探索回数に比例して積み上がるので、減らせる分は減らしてから[強化学習の実行](alphazero-rl.md)の試走に臨むほうが、試走の結果から再生の費用を切り分けやすい。
本書に現れる規則コードは、RULES.md第31条と第32条が定めるローカルルールの記号であり、R1はLishogi式の4回反復の裁定、R2とR3は既出局面の再現の禁止、E1は王駒の実捕獲による終局、E3は裸玉の即時裁定を表す。

費用の内訳は、同じ測定プログラム`driver_cost`（[tools/train/zero/feasibility/src/bin/driver_cost.rs](../../tools/train/zero/feasibility/src/bin/driver_cost.rs)）を探索関数の区間だけ集計するvalgrindのcallgrindで調べた。
探索の費用に占める割合は次のとおりである。

| 探索の費用の内訳（命令数の割合） | 割合 |
|---|---:|
| `Game::play`（経路の再生） | 93.9% |
| 　うち合法手なしと詰みの判定での合法手生成 | 44.6% |
| 　うち攻撃的着手の判定`move_was_attacking` | 37.4% |
| 　　うちその中の合法手生成 | 34.2% |
| 　うち着手の合法性検査の合法手生成 | 8.8% |
| 葉の`Game::legal_moves` | 3.4% |
| `Game::clone` | 0.14% |
| 木の操作とその他 | 約2.6% |

合法性検査の合法手生成は再生1手につき1回なので、その命令数（再生154,170手で5.82 G命令、1回あたり約37.7 k命令）を単位にすると、合法手なしと詰みの判定の生成が約5.1回、攻撃的着手の判定の中の生成が約3.9回、合計で約10回になる。
これは命令数の比から求めた推定であり、生成1回の費用が局面と手番で異なることを無視している。
全区間での呼出し回数の比（`generate_moves`が3,087,381回、`Game::play`が288,907回）は10.7回だが、この比には測定の入力の作成と集計の再生が混ざる。
根の`Game`の複製（反復の履歴を含む）は0.14%であり、対局の手数の長さは費用の要因ではない。

`Game::play`は1手ごとに、合法性検査で1回、R1の攻撃的着手の記録で1回、合法手なしの判定で1回、詰み判定の冒頭で1回の合計4回の合法手生成を行う（[crates/minase-core/src/game/adjudication/mod.rs](../../crates/minase-core/src/game/adjudication/mod.rs)の`adjudicate_after_move`と`candidate_immediate_result`）。
詰み判定はさらに、候補手を1つ試すごとに、即時結果の判定の中の攻撃的着手の判定と、相手が王駒を取れるかの判定で2回の生成を行う（[mate.rs](../../crates/minase-core/src/game/adjudication/mate.rs)の`is_mate`と`can_capture_last_royal`）。
詰み判定は逃れる候補手が1つ見つかった時点で打ち切るので、R1で早期に終局せず、各候補手の即時結果が定まらない通常の経路では、逃れる手が見つかるまでに試す候補手の数をkとして生成回数は4+2k回になる。
命令数の比から推定したkは平均で約3手であり、合計が約10回になる。
王駒が攻撃されている局面では候補手が増え、通常のビルドの実測で、再生1手あたりに正規化した探索時間の中央値は序盤の局面で約9 µs、王駒の捕獲の近傍の局面で74〜104 µsだった。

本書の目的は、この約10回を、裁定の結果を変えずに約3回へ減らすことである。
合法手生成そのものを速くすることは本書の対象ではない。

## 適用範囲

本書では、次の作業を行う。

- `candidate_immediate_result`で候補手ごとに先に計算している攻撃的着手の判定を、`R1History::candidate_result`が実際に参照する場合だけ計算する遅延評価にする。
- `adjudicate_after_move`で、合法手なしの判定と詰み判定が使う合法手列を1回だけ生成して共有する。
- `can_capture_last_royal`を、相手の王駒が1枚なら`Position::attackers_to_by`の疑似利きで判定し、2枚なら現行の合法手生成で判定する形に改める。
- 変更から独立した参照実装との突き合わせと、完全な規則と履歴を持つ固定例の試験を加える。
- `driver_cost`の出力に、Gumbelが選んだ手と方策の目標、PUCTの最善手、および終局の勝者を加え、変更の前後を同じ条件で測って`docs/measurements/referee-adjudication-movegen/`に記録する。
- 補題と判定の範囲をdocコメントとADRに書く。

次の項目は対象外とする。

- 経路の再生で着手の合法性検査を省く軽いAPIは、[ADR](../adr/adjudicate-mcts-leaves-by-the-referee-before-the-repetition-approximation.md)が「GPUの試走で1サイクルの時間が予算に収まらず、再生の費用が主因だと確かめられた場合に限り検討する」と定めているので、本書では扱わない。
- R1の攻撃的着手の記録（`record_move`）の判定は、動かした駒が取れる相手の駒が獅子だけの場合に、獅子を取る手が第14条から第16条の捕獲制限で不合法になり得て利きだけでは判定できないので、合法手生成のまま残す。
- `Game`に合法手列を保持して`legal_moves()`に使う案は、効果が探索の約3%で、状態を増やす割に小さいので扱わない。
- `generate_moves`の内部（着手ごとの成りの選択肢の決定、獅子の捕獲制限の検査、および`captured_squares`を着手ごとに2回計算していること）は、αβ探索にも効く汎用の高速化として別の設計書で扱う。
- 探索木が経路の深さに比例して再生する構造と、3手詰めの判定のような新しい終局判定は扱わない。

## 依存関係

本書は、masterへマージ済みの[AlphaZero型探索の監査対応](archived/alphazero-audit-remediation.md)の実装を前提とする。
[強化学習の実行](alphazero-rl.md)の内容は変えない。
強化学習の試走の前に本書を完了するかどうかは、利用者が決める。
測定には、監査対応の測定に使った`driver_cost`と同じ局面、乱数、および探索回数を使う。

## 設計判断

| 論点 | 採る方式 | 棄却した代案 |
|---|---|---|
| 即時結果の判定の攻撃的着手 | `candidate_result`の不可逆手、可逆手の不足、および出現回数の不足による早期の終了を通過した場合にだけ計算する遅延評価 | 現行の先行計算。候補手ごとの判定結果の記憶（同じ候補手を2回試すことはない） |
| 合法手列の共有 | `adjudicate_after_move`が駒枯れと裸玉の裁定の後に1回生成してR2とR3の禁止手を除き、合法手なしの判定と詰み判定に同じ列を渡す | 現行の2回の生成。`Game`に合法手列を保持して葉の`legal_moves()`にも使う |
| 王駒の捕獲可能性 | 相手の王駒が1枚なら、着手後の手番側の疑似利きがその升に届くかで判定する。2枚なら現行の合法手生成を維持する | 2枚の場合も疑似利きで近似する。全件の合法手生成の維持 |
| 再生の合法性検査 | 維持する | ADRが条件付きで先送りした軽いAPI |
| R1の記録の攻撃的着手 | 合法手生成を維持する | 疑似利きで判定し、捕獲先が獅子だけの場合に合法手生成へ戻す |
| 等価性の検証 | 変更から独立した参照実装との突き合わせ、完全な規則と履歴を持つ固定例、および`driver_cost`の出力の一致 | 棋力測定（裁定が同一なので不要）。`driver_cost`の出力の一致だけに頼る |

### 即時結果の判定を遅延評価にする

`is_mate`は、候補手を仮に指した局面で`candidate_immediate_result`を呼び、候補手が即時の勝ち、負け、または引き分けを生じるかを調べる。
現行の実装は、R1の場合に`move_was_attacking`を先に計算して`R1History::candidate_result`へ渡すが、`candidate_result`は候補手が不可逆手である場合、可逆手が候補手を含めて12手に満たない場合（第31条R1の前提条件）、および局面の出現回数が3回に満たない場合に、その値を見ずに`None`を返す。
攻撃的着手の判定は履歴を変えないので、`candidate_result`がこれらの検査を通過した後にだけ行うよう並べ替えても、返す値は変わらない。
`candidate_result`は`pub(crate)`であり本番の呼出しは1か所なので、攻撃的着手の判定をクロージャ（closure）として受け取る形に署名を変え、互換用の入口は置かない。
`record_move`は攻撃の連続数を常に更新するので、記録側の判定はこれまでどおり先に計算する。

### 合法手なしと詰みの判定で合法手列を共有する

`adjudicate_after_move`は、駒枯れの裁定の後に`has_no_legal_move`で手番側の合法手を生成し、続けて`is_mate`が同じ局面の合法手を再び生成する。
どちらも生成の後にR2とR3の禁止手を除く同じ処理を行う。
1回だけ生成して両方に渡し、空なら合法手なし、空でなければ詰み判定に進める。
生成は、王駒の捕獲、反復、駒枯れの猶予、および裸玉の裁定による早期の終了の後に行い、E1で詰み判定を省く場合も合法手なしの判定は保つ。

### 王駒の捕獲可能性を疑似利きで判定する

`is_mate`は、候補手を仮に指した後の局面で`can_capture_last_royal`を呼び、手番側（詰めている側）が相手の残存王駒をすべて取れる合法手を持つかを、合法手を全件生成して調べる。
王駒が1枚なら、その升へ手番側の疑似利きが届くことと、その王駒を取る合法手があることは一致する。
王手を定める第8条（RULES.md）はこの一致を前提にしており、`Position::gives_check`（[crates/minase-core/src/movegen/gives_check.rs](../../crates/minase-core/src/movegen/gives_check.rs)）は同じ補題で王駒1枚の場合を疑似利きで判定し、[その試験](../../crates/minase-core/src/movegen/tests/gives_check.rs)が乱数局面と成りと獅子の規則の組合せで合法手生成による参照実装との一致を固定している。
αβ探索の`royal_under_attack`（[crates/minase/src/search/alphabeta/royal.rs](../../crates/minase/src/search/alphabeta/royal.rs)）も同じ判定を使う。
補題が成り立つのは、着手の合法性を制限する規則のうち、獅子の捕獲制限（第14条）、先獅子（第15条）、および付け喰い（第16条）が獅子を取る手だけに掛かり、R2とR3の禁止が既出局面を再現し得ない捕獲手に掛からず、自分の王駒の安全は着手を制限せず（第8条第3項から第5項）、王駒を取る手を禁じる規則がほかにないからである。
獅子、角鷹、および飛鷲の2段階移動は、2升先へ中間の駒を取らずに直接跳べる（第11条第1項dと第4項、第12条第5項から第7項）ので、中間升が自分の駒や捕獲できない獅子で埋まっていても王駒を取る手は残り、`attackers_to_by`の特殊移動の逆引きがそのまま使える。
成り規則P1からP6は成りと不成の少なくとも一方を残すので捕獲手を消さず、最奥段で移動不能になった歩兵と香車は盤内への利きを持たない。
E3の裸玉は着手の禁止ではなく着手後の即時の裁定なので、候補手の即時結果を先に調べる現行の順序を保てば影響しない。
王将または玉将と太子の2枚が残る場合は、1手で両方を取る合法手が要り、獅子の2枚取りと角鷹や飛鷲の2段階の捕獲の合法性を伴うので、現行の合法手生成を維持する。
`attackers_to_by`のdocコメントは「審判層の判定の代わりにはならない」と記しているので、王駒1枚の捕獲可能性を例外として補題とともに書き、`can_capture_last_royal`と`is_mate`のdocコメントにも判定の根拠を書く。
この決定はADRに記録する。

### 期待する効果

通常の経路の生成回数4+2kは、遅延評価で候補手ごとの1回が消えて4+k回、合法手列の共有で3+k回、疑似利きの判定で候補手ごとのもう1回が消えて3回になる。
王駒が攻撃されている局面では、候補手ごとの費用が合法手生成2回から、着手の適用と復元、駒枯れの判定、および利きの判定だけになる。
王駒が2枚残る場合、R1の反復の裁定が候補手で成立し得る場合、および駒枯れと裸玉の裁定が合法手を生成する場合には、追加の生成が残る。
序盤の局面ではkが1に近く、生成は約6回から約3回になるが、生成以外の処理は残るので、探索時間の半減はここからは導けない。
Gumbelの32回の探索の根の探索時間は、再生が94%を占める現状の0.555 msから0.2 ms前後になると見込むが、これは命令数の割合からの概算である。
採否は測定記録で判断する。

## 実装フェーズ

### フェーズ1　参照試験

変更の前に、変更する箇所から独立した参照実装を試験に書き、次を固定する。
参照実装は、攻撃的着手の判定を先に計算し、捕獲可能性を合法手生成で調べる現行の形をそのまま試験の中に持ち、変更後の`candidate_result`や共有した合法手列に依存しない。

- `can_capture_last_royal`が、合法手生成による参照実装と一致すること。局面は、`gives_check`の試験と同じ成りと獅子の規則の組合せごとの`sampled_random_positions`と、各規則セットで乱数により進めた対局の各手の局面とし、それぞれ両方の手番で評価する。固定例として、太子だけが残る場合、王将と太子の2枚が残る場合、中間升が自分の駒または捕獲できない獅子で埋まった獅子、角鷹、飛鷲の跳躍、P5とP6の強制の成りを伴う王駒の捕獲、最奥段で移動不能になった歩兵と香車、および王駒が0枚の場合を加える。
- `is_mate`が、同じ局面と固定例で参照実装と一致し、呼出しの前後で局面が復元されること。
- 完全な`Rules`と履歴を持つ`Game`の固定例で、`Game::play`の結果と理由が変わらないこと。R1では、候補手を含む可逆手が11手と12手の場合、同一局面の3回目と4回目の出現、不可逆手による前提の解除、および候補手の即時の勝ち、引き分け、負けを含める。R2とR3では、禁止手を除くと唯一の逃れる手が消える場合と合法手列全体が空になる場合を含め、R3には3回目までの再現と4回目の境界を足す。E1では合法手なしの敗北だけが裁定されること、E0の駒枯れの猶予とE3の即時の裁定が詰み判定より先に働くことを含める。既存の試験（`crates/minase-core/src/game/adjudication/tests.rs`のR1の境界、`crates/minase-core/src/game/tests/win.rs`の詰みの回避とR2、`crates/minase-core/src/game/tests/no_legal_move.rs`）を再利用し、足りない例を加える。

フェーズの完了条件は、追加した試験が現行の実装で通ることである。

「設計判断」の3点を実装し、docコメントを更新する。
`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、および`cargo test --workspace`を通す。
フェーズの完了条件は、フェーズ1の試験と既存の試験がすべて通ることである。

### フェーズ3　測定

`driver_cost`の出力に、Gumbelが選んだ手と方策の目標、PUCTの最善手、および終局の勝者を加える。
監査対応の測定と同じ手順で、`driver_cost`をmasterの比較元と本ブランチのそれぞれでビルドし、同じシード、同じ対局数、同じCPUコアで、両方とも`--adjudication after`で実行する（`before`は監査対応の前のAPIでビルドするための指定で、裁定の集計を意図的に0にする）。
比較元と本ブランチを同じコアで交互に5回ずつ実行し、局面と方式ごとの反復の中央値から、局面の分類ごとの値を求める。
指標は、1回の探索の時間を再生した着手数で割った「再生1手あたりに正規化した探索時間」とし、Gumbelの32回とPUCTの800回、序盤と王駒の捕獲の近傍の分類を分けて中央値を報告する。
変更の前後の出力は、時間の項目（`elapsed_ms`、`summary_ms`、およびスナップショットの計測値）を除いて一致しなければならない。
一致は回帰の検査であり、裁定の等価性の保証はフェーズ1の試験が担う。
一致しなければ裁定または探索の結果が変わっているので、原因を直してから測り直す。
任意で、探索関数の区間だけを集計するcallgrindのプロファイルを変更の前後で取り、`Game::play`の内訳と、命令数から推定した呼出し元ごとの生成回数を比較元の版とともに記録に添える。
記録は`docs/measurements/referee-adjudication-movegen/referee-adjudication-movegen-driver-cost.md`に置く。

## 検証

フェーズ1の参照試験と固定例に加えて、次の試験を追加する。

- 固定の局面で、王駒1枚が疑似利きで攻撃されている局面の詰み、2枚の王駒を獅子が1手で取れる局面の詰み、2枚の王駒が隣接せず詰みにならない局面、候補手が即時の勝ちまたは引き分けになる局面での回避、および候補手が即時の負けになる局面で回避にならないことを確かめる。既存の固定例（監査が再現した駒枯れの勝ち、駒枯れの引き分け、および詰みの3例、R1の正確な裁定、駒枯れの猶予、E1での詰み判定の省略）は変えない。

マージの前に、[docs/guides/testing.md](../guides/testing.md)の「運用」の節が定める4つの検査を通す。
審判層、αβ探索の根の候補手の選別（`crates/minase-core/src/game/root_repetition.rs`の試験）、探索木の終局判定、対局ハーネス、および自己対局の生成器の既存の試験は、この4つに含まれる。
`driver_cost`の変更の前後の出力が時間の項目を除いて一致することを確かめ、記録に残す。
αβ探索の根の候補手の選別は`Game::play`を使うので、深さ6のbench（`--depth 6 --threads 1`）の局面ごとの結果が比較元と一致することを確かめる。
裁定の結果が同一なので棋力は変わらず、SPRTは行わない。
コミットの種別は`perf`とする。

## 完了条件

本書の完了条件は、「検証」の節の試験と既存の試験がすべて通り、`driver_cost`の変更の前後の出力が時間の項目を除いて一致し、再生1手あたりに正規化した探索時間の中央値が、Gumbelの32回とPUCTの800回のそれぞれで、序盤の局面と王駒の捕獲の近傍の局面の両方で変更前の半分以下になった測定記録が残り、補題と判定の範囲をdocコメントとADRへ移したうえで、実装と文書がmasterへマージされることである。
半減は採否の目標であり、生成回数の削減から導かれる保証ではない。
半分以下にならなかった場合は、測定記録に内訳を残して利用者の判断を仰ぐ。

```console
RUSTFLAGS="-C target-cpu=x86-64-v2" cargo build --release --offline --locked \
  --manifest-path tools/train/zero/feasibility/Cargo.toml --bin driver_cost --target-dir <出力先>
valgrind --tool=callgrind --collect-atstart=no --toggle-collect='driver_cost::search' \
  --callgrind-out-file=<記録> <出力先>/release/driver_cost --seed 20261028 --games 32 --adjudication after
callgrind_annotate --tree=both --inclusive=yes <記録>
```

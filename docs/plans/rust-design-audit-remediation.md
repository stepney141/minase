# Rust設計監査対応の設計書

## 実施状況

本マイルストーンは2026年8月26日に着手し、同日に完了した。
非ASCIIのUSI着手と過大な置換表容量によるパニックを型付きエラーへ変更し、`position`の不正な欄を黙示的に補完せず拒否するようにした。

公開境界では、`PieceCode`、`SetupPosition`、`SearchLimits`、`ClockLimits`および`SearchSnapshot`の不変条件をコンストラクタへ集約した。
uncheckedな局面更新と`Undo`はcrate内部へ狭め、公開着手適用と戦術手判定は不正な`Move`を`IllegalMove`として返す。

探索では、検証済みPSTを同期版へ借用、非同期版へ`Arc`で明示的に渡す所有権へ変更した。
`SearchHandle`は`Drop`でも停止とjoinを行い、ワーカーのパニック時は残るワーカーへ停止を通知してからペイロードを`join`へ返す。
統合検査中に、補助ワーカーが主ワーカーより先に固定深さへ達すると主ワーカーの進捗が空になる競合を再現したため、固定深さの完了通知は主ワーカーだけが行うよう修正し、同じテストを10回連続で通した。

Cargoには`rust-version = "1.88"`、`publish = false`および全ターゲット共通のlintを追加した。
一時環境へ導入したRust 1.88.0で全ターゲットを実際に検査し、最小対応版の宣言と実装が一致することを確認した。

最終検証では全490件のテスト、Clippyの警告エラー化、rustdocの警告エラー化および差分検査が成功した。
`SearchHandle::drop`の最大待機時間は監査から確定できなかったため、停止確認まで同期的にjoinする契約を採用した。
この設計判断により、未解決の仕様不明項目は残っていない。
自動変異検査器は使用していないが、0検査、PST配線、Drop時の停止とjoin、ワーカーパニック時の停止通知、および固定深さの主ワーカー進捗について、各処理を除けば失敗する回帰テストを確認した。

## 根拠

`docs/rust-design-audit-2026-08-26.md`は、コミット`7e13888`相当のRustソースについて、公開境界、不変条件、探索資源の寿命およびパッケージ契約を監査した。
本マイルストーンは同報告書を要求の根拠とし、現行HEADで各所見が残っていることを確認してから変更する。

テストの期待値は監査報告書、公開APIの契約およびプロトコルの外部可観測動作から定める。
現行実装が黙殺またはパニックすることは、期待動作の根拠にしない。

## 適用範囲

今回の変更は、次の契約を対象とする。

- 非ASCIIのUSI着手と不正な`position`コマンドを、パニックや黙殺ではなく構文エラーとして扱う。
- 置換表の生成とサイズ変更をfallibleにし、表現不能なサイズを型付きエラーで返す。
- 盤上へ置ける駒コードをSFENが表現できる範囲と一致させる。
- `SetupPosition`、探索条件および探索局面のフィールドを非公開にし、検証済みコンストラクタを設ける。
- uncheckedな局面更新と巻き戻しトークンをcrate内部へ限定する。
- USI文字列化では採用規則の合法手生成器による検査を必須とし、未検証着手を拒否する。
- `SearchHandle`の破棄時に停止要求とスレッド回収を行い、ワーカーのパニック時にも残るワーカーへ停止を通知する。
- 規則解析と対局ライフサイクルの失敗を専用エラー型で保持する。
- 学習評価の特徴番号、unchecked更新、巻き戻しトークンなど、crate内部だけで使う表現の公開範囲を狭める。
- 検証済みの任意PSTを同期探索と非同期探索へ明示的に渡し、探索入口で埋込みPSTを暗黙に選ばない。
- 置換表の最善手を助言値と定め、生成済み合法手との一致を確認した場合だけ手順序付けに使う。
- 擬似乱数生成器の0でないシードと添字上限を専用型で表す。
- Rustの最小対応版、公開可否およびlint方針をCargoメタデータへ明記する。
- 二分法と中央値の中点計算を`f64::midpoint`へ置き換え、監査で特定した`random_play`の冗長な`clone`を削除する。
- `Rules`の表示を、規則コードを直接書き出す処理へ単純化する。
- CECPの`force_mode`と`engine_side`を、`Force`と`Playing`を持つenumへ統合する。

## 設計判断

| 項目 | 決定 |
|---|---|
| 互換性 | 旧APIの別名、互換コンストラクタおよび黙示的な既定値を残さない。 |
| 外部入力 | 通常の誤入力は専用の`Error`または既存の構文エラーへ変換し、パニックさせない。 |
| 数値制約 | 内部で常に0を認めないシード、スレッド数および添字上限は`NonZeroU64`または`NonZeroUsize`で受ける。外部から受ける置換表容量や探索制限は、専用エラーを返すコンストラクタで検査する。 |
| 公開状態 | フィールドを非公開にし、構築時に全不変条件を検査する。読取りは必要なアクセサだけを公開する。 |
| 探索資源 | `SearchHandle`を探索スレッドの唯一の回収責任者とし、明示的な`join`と`Drop`の両方で停止と回収を完了する。 |
| 評価器 | `Pst::decode`で検証した任意PSTを公開探索APIへ渡せるようにする。同期探索は`&Pst`、非同期探索は`Arc<Pst>`を受け、埋込みPSTは各バイナリが明示的に選ぶ。将来用の評価器traitは追加しない。 |
| 着手表現 | 今回は`MoveSpec`と`LegalMove`の全面分離を行わない。unchecked更新と`Undo`を外部から隠し、公開入口で着手合法性を検査する。 |
| 置換表の助言手 | 最善手を評価値と同じ原子語へ移さない。並行書込みでは別局面の値が混ざり得る助言値として文書化し、合法手集合との一致を確認した場合だけ手順序付けに使う。 |
| プロトコル状態 | 現行のUSIとCECPで別々の処理を保つ。共通化だけを目的とする`SearchSession`は追加しない。 |

## 対象外

性能または配布方式を決めなければ採否を判断できない所見は、無測定では変更しない。
対象は`target-cpu=native`、開発ビルドの最適化、大きなローカル配列および置換表の原子語配置変更である。
これらを変更する場合は、ベンチマークまたはSPRTの要否を個別に判定し、再現手順と実測値を残す。

置換表の原子語配置を変えない場合も、最善手が評価値と同じ書込みに由来する保証はない。
そのため、助言値としての契約と合法手照合は今回の対象に含める。

ライブラリとCLIのcrate分割、`rng`と`stats`の別crate化、`Square`と`Bitboard`の安定公開API再設計も対象外とする。
外部利用者または配布要件が確定していないため、今回分割すると責務より構成変更が先行する。

`rng`と`stats`は複数バイナリから共有する既存判断に従って公開モジュールのまま保つ。
`doc(hidden)`だけで公開契約を弱められるとは扱わず、将来非公開化する場合はcrate分割と同時に設計する。

USIとCECPの探索状態を表すenum化は対象外とする。
置換表と探索ハンドルが別の状態機械に属し、今回の公開境界と探索資源の修正後も不整合が再現しなかったためである。

`Option<Option<Move>>`の専用enum化、残るlint抑制の`expect`化、長い内部関数の分割も対象外とする。
監査は現状をRustの誤用とは判定しておらず、今回の公開契約を成立させる条件ではない。

`selfplay_gen`と`perft`のバイナリ境界テスト拡充は、各バイナリの要求を別に定める必要がある。
監査だけでは決定性や既存ファイル処理の完全な期待値を確定できないため、本マイルストーンでは追加しない。

## 検証契約

回帰テストは、少なくとも次の外部可観測動作を固定する。

| 入力または状態 | 期待結果 |
|---|---|
| 非ASCIIを含むUSI着手 | `UsiError`を返し、プロセスを停止しない。 |
| 採用規則で不合法な`Move`のUSI文字列化 | `IllegalMove`を返し、文字列を生成しない。 |
| 表現不能な置換表サイズ | 生成または変更が専用エラーを返し、既存表を保持する。 |
| 未知の`position`形式または余分なSFEN欄 | コマンドを拒否し、対局状態を変更しない。 |
| 未成として存在できない駒種 | 駒または局面の構築時に拒否する。 |
| 範囲外の手数を持つ開始局面 | `SetupPosition`の構築時に拒否する。 |
| 空升を移動元とする未検証着手 | 公開APIが`IllegalMove`を返し、局面を変更せず、評価用の戦術手判定もパニックしない。 |
| 無制限と制限付き条件の混在、または0の制限 | 探索開始前に型または専用エラーで拒否する。 |
| 終局局面または合法手がない局面の探索スナップショット | `SearchSnapshot`の構築時に専用エラーで拒否する。 |
| 外部バイト列から復号した有効なPST | 同期探索と非同期探索の両方へ明示的に渡して使用できる。 |
| `SearchHandle`を`join`せずに破棄 | 停止要求後に探索スレッドを回収する。 |
| 主ワーカーまたは補助ワーカーのパニック | 残るワーカーへ停止を通知して回収し、呼出し側へパニック結果を返す。 |
| 未開始対局への着手 | 規則または局面エラーとは異なるライフサイクルエラーとして分類する。 |
| 未知の規則コードまたはプリセットの不正な併記 | 文字列比較を要しない専用エラー型で分類する。 |
| 置換表から得た最善手 | 生成済み合法手と一致する場合だけ手順序付けへ使う。 |
| 0の乱数シードまたは0の添字上限 | 呼出し時の型で表現できない。 |
| Cargoのパッケージ契約 | 最小Rust版、非公開パッケージ、ライブラリと全ターゲットへ適用するlintをメタデータから確認できる。 |

変更後は`cargo fmt --all -- --check`、`cargo check --all-targets --all-features`、`cargo clippy --all-targets --all-features`、`cargo test --all-targets --all-features`および`RUSTDOCFLAGS='-D warnings' cargo doc --no-deps --all-features`を実行する。
公開APIを変更するため、全ターゲットのコンパイルとrustdocを完了条件に含める。

## 完了条件

適用範囲の各契約が実装とテストに反映され、検証契約の各行に対応する回帰テストがあり、対象外の候補が無測定で変更されていなければ完了とする。
公開項目の可視性はrustdocだけでなく、外部crateから到達できる再公開経路が残っていないことも確認する。
置換表の助言手については、探索側の合法手照合と契約文書の両方を完了条件とする。
完了時には本書へ実施結果と検証結果を記録し、`docs/ROADMAP.md`の状態表と現在地を更新する。

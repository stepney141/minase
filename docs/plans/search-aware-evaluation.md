# 探索局面を用いた評価関数の学習

## 先に読む要約

本書は、[教師の混合比の計画](teacher-mixing-ratio.md)の採否または見送りが確定した後、学習する局面に探索中の局面を加えると、同じ評価方式のまま着手が改善するかを確かめる。
対象の駒位置表PST（piece-square table）は、駒の種類と升ごとの点数を足す現行の評価方式である。
過去に差分更新型の小型ニューラルネットNNUEも試したが棋力改善には至らなかったため、その再導入を本書の前提にはしない。
まず、過去の候補と採用版で選ぶ手が異なる局面を深く探索し、学習の正解に使う値である教師値が、十分な差のある着手の誤りを安定して指摘できるかを調べる。
教師の診断を通過した場合に、通常の対局局面だけで学ぶ対照Aと、半数を探索中の評価局面へ置き換えて学ぶ候補Bを作る。
AとBでは、PSTの構造、初期重み、教師への問い合わせ回数と各探索のノード上限、学習する局面数、学習方法をそろえる。
探索局面の教師値はその局面から独立に探索して求め、探索開始局面の値や後の対局結果を代入しない。
候補Bの採否は、同じ持ち時間で対照Aと計画着手時の採用版へ順に対局させ、対局を進めながら優劣を判定する[逐次確率比検定](../guides/sprt.md)で決める。
対照Aと採用版の比較も測定前に登録し、深い教師による通常局面の再学習だけの効果を記録するとともに、Bを採用しない場合にだけAの採用経路とする。
完了条件は、診断による見送り、AとBの不採用、またはAかBの採用のいずれかが測定記録とともに確定することである。
複数駒の配置に対応する誤りが残る場合は、PSTでの改善の有無だけで判断せず、[相対2駒評価](relative-pair-eval.md)の着手条件を点検する。
実行の結果、BはAに対して、AはS0に対して、ともにSTCで`H0`となり、どちらも採用しなかった。

## 状態

完了（不採用）。2026年9月25日に起案し、2026年9月26日に着手して同日に完了した。
基点S0は着手時のmasterであり、従来の採用PST（混合比計画の基点と同じ重み）を使った。

教師の診断は続行条件を満たした。
校正で差mを142.1センチポーンに固定し（[search-aware-teacher-calibration](../measurements/search-aware-teacher-calibration.md)）、確認128根では安定支持と小差の合計が112根、基準手の安定支持が9根であった（[search-aware-teacher-confirmation](../measurements/search-aware-teacher-confirmation.md)）。

フェーズ3では、自己対局5,600局から訓練32,768組、モデル選択4,096組、最終診断256組を確保し、10,000,000ノードの教師でラベルを付けた（[search-aware-data](../measurements/search-aware-data.md)）。
採取した探索局面の9.5%で教師が詰みを示す値を返したため、訓練で使える組は28,947組（予定数の88.3%）であった。
当初の規則は訓練にも予定数の90%以上を求めていたが、学習の開始前に、利用者の判断で訓練の受理条件を「受理した組で総更新回数が2,000回を超えること」に改めた。
90%の基準は総更新回数の下限を保証するために置いたものであり、28,947組でも計2,280回の更新を確保できる。
この改訂により、結論の範囲は「教師が詰みを示す局面を除いた探索局面」を学習分布に加える効果に限られる。

フェーズ4では、AとBを同じ28,947組で学習し（[search-aware-pst-training](../measurements/search-aware-pst-training.md)）、事前に固定した規則による採否前の診断で両者とも対局へ進めると判定した（[search-aware-pst-diagnostics](../measurements/search-aware-pst-diagnostics.md)）。
ただし最終診断では、Bの着手の損失と通常局面の評価誤差がS0とAより大きく、深さ8までの探索ノード数もS0の約12倍になった。

フェーズ5では、B対AのSTCが101ペアで`H0`（得点率6.9%、[search-aware-pst-b-vs-a-stc](../measurements/search-aware-pst-b-vs-a-stc.md)）、A対S0のSTCが276ペアで`H0`（得点率41.8%、[search-aware-pst-a-vs-base-stc](../measurements/search-aware-pst-a-vs-base-stc.md)）となった。
事前登録の経路に従い、LTCとB対S0は行わず、AとBをともに不採用とした。

この結果が示すのは、今回の標本の定義と固定したPSTの下では、探索局面を学習分布へ混ぜる変更も、深い教師で通常局面を学び直す変更も、棋力を上げなかったことである。
Bは探索局面の過小評価を半分以下に減らした代わりに、通常局面を平均251センチポーン高く見積もるようになった。
PSTは局面が戦術的に動いている最中かどうかを表せないので、探索局面の偏りを直す変更が通常局面にもそのまま及んだと考えられる。
関係を表せるモデルで同じ学習方法を使った場合の効果は、この結果からは判断できない。

後続の[相対2駒評価](relative-pair-eval.md)へは、従来の採用PST、教師の診断結果とm、学習処理が正常に動いたこと、および最終診断の記録を引き継ぐ。
駒の配置に依存する残存誤りは、最終診断の根で具体例と特徴を比べる形では確認していないので、相対2駒評価の準備段階で扱う。

## 目的

本書は、学習時と探索時に評価する局面の分布が異なることを、評価改善の独立した仮説として検証する。
[NNUEの固定ノード測定](../measurements/nnue-gen1-nodes100k.md)と[時間制御測定](../measurements/nnue-gen1-tc.md)は、初期化を修正した非線形モデルも、教師への適合の改善だけでは強くならなかったことを示す。
2駒関係を低ランクの因子で表すFM（factorization machine）についても、[相対2駒評価の計画](relative-pair-eval.md)が、候補が自ら選ぶ局面で補正が偏る現象を記録している。
ただし、これらだけでは失敗の原因を学習分布に確定できないため、表現と推論費用を固定した対照実験を行う。

学習の目標は、同じ局面を深く探索して得る有限予算の近似値である。
ゲーム理論的価値への収束、評価値の急落の消失、複数駒の関係の獲得は、本書の完了条件にしない。
PSTで改善しなかった場合も、関係を表せるモデルでの同じ学習方法を否定したとは解釈しない。

## 適用範囲

本書では、履歴を保つ教師診断器、探索中に評価した局面の採取器、対局結果を要求しない教師データの読み込み、およびPSTの対照学習を実装する。
学習分布を変える候補はBの1個とし、対照Aは事前登録したS0との比較でだけ採用候補になる。
探索の係数、時間管理、PSTの特徴、重み形式、駒価値の表は固定する。
採取器を使わない実戦用ビルドには、採取の処理や共有カウンタを残さない。

次の事項は本書に含めない。

- NNUEやFMの実戦用実装を復元しない。
- 利き表、利きの補助出力、相対2駒表、3駒以上の新しい特徴を実装しない。
- 探索を微分する順位損失、静止探索の主変化の復元、および置換表の上下界を使う学習を実装しない。
- 候補Bからデータを生成し直す世代反復や、結果を見て置換率を変える追加候補を作らない。
- 対照Aの採否経路は事前登録したA対S0の測定だけとし、候補Bの結果を見た後に追加しない。

後続の計画へ進む条件は、「停止と後続の判断」の節に定める。

## 依存関係

方式の根拠は、[考察メモ](../research/search-aware-evaluation.md)と[一次資料の調査](../research/relational-evaluation-primary-sources.md)に置く。
PSTの評価、量子化、駒除去診断は、[評価関数](evaluation.md)、[PSTの補間](tapered-pst.md)、[段階7](strength-stage7.md)、[学習の手引き](../guides/pst-training.md)を引き継ぐ。
棋力の採否は[SPRTの手引き](../guides/sprt.md)に従う。

全体の順序は[評価関数の後続計画の順序](strength-stages.md#評価関数の後続計画の順序)に従う。
[教師の混合比](teacher-mixing-ratio.md)の採否または見送りが確定した後に着手する。
前段で採用されたPSTを使い、不採用や見送りなら従来の採用PSTを使う。
その時点のmasterを基点として固定し、本書専用のブランチで作業する。
[相対2駒評価](relative-pair-eval.md)や[段階12](strength-stage12.md)などの変更を、実験の途中では取り込まない。
本書のAとBはともに探索値だけを教師とするが、既存の混合比計画とは教師値の作り方、学習局面、比較相手が異なる。
混合比計画は既存データによるλ=1の再学習全体を採用版と比べ、本書は同じ深い教師で再学習したAとBを比べて学習分布の効果を調べる。
本書のAを作ることだけでは、混合比計画を実施したことにはならない。
前段が不採用でも、教師値と局面が異なる本書の実験は見送ったことにならない。
本書の教師診断と学習分布の比較は、同じ基点と教師を使う連続した段階とし、途中で基点を更新しない。

## 設計判断

| 項目 | 決定と理由 |
|---|---|
| 最初の評価方式 | 現行の鏡映共有つき2端点PSTに固定する。既存の推論を変えず、学習分布の効果を調べられるためである。 |
| 基点と教師 | 混合比計画の判定後の採用版を基点S0とし、その探索コードとPSTを教師Tにも使う。教師診断から本書の採否まで、基点と教師の重みを更新しない。 |
| 規則 | 最初の実験は `engine-default`、すなわち `L0,P0,R1,E0` に固定する。他の規則の棋譜を混ぜない。 |
| 旧モデル | 旧NNUEは世代1の時間制御測定、旧FMは補正1/4版の採否測定の保存記録から提案手を得る診断資料として使う。全FMの実行ディレクトリは残っていないので使わない。古い探索全体をmasterへ統合しない。 |
| 教師の能力 | 最上位手の完全一致を要求せず、固定した提案手間の差と、安定した判定が得られる割合を調べる。 |
| 根の候補手の評価 | 候補手を指した子局面を、それぞれ独立に探索する。複数の主変化を返す機能や根の手を制限する新しい公開インターフェースは不要である。 |
| 探索からの採取 | 静止探索で実際に静的評価を呼んだ局面を採る。主変化の末端と同じものだとは扱わない。 |
| 教師値の型 | 通常の評価値、終局、詰みを示す探索値、未完了を区別する。初回の回帰には通常の評価値だけを使う。 |
| 学習データ | 棋譜と根からの経路を保持する専用形式を使う。未知の勝敗を引き分けで埋めて既存の教師形式へ入れない。 |
| 学習方法 | AとBで既存の二値交差エントロピーと駒除去差分の損失を共通にする。考察メモのHuber損失への変更も今回は分離する。 |
| 比較の範囲 | AとBの教師への問い合わせ枠を一致させる。探索局面を採取する追加費用は別に記録し、全工程の費用が同じとは主張しない。 |
| 採否 | B対Aで学習分布を変える利得を確かめ、通過したBをS0と比較する。A対S0も事前登録して深い教師の効果を記録し、Bを採用しない場合にだけAの採用経路とする。比較を合算せず、同じ候補を使う。 |

## 比較条件を固定する

以下では、探索を始める局面を根と呼ぶ。
フェーズ1で `data/search-aware-evaluation/manifest.json` を作成する。
基点と教師のソースの版、バイナリと重みの検査和、規則、出力尺度K、探索用駒価値、思考制限、スレッド数、置換表の大きさ、入力ファイルの検査和、抽出シード、分割、採取数を必須項目にする。
具体的なコミットハッシュはこの実行記録に保存し、設計書には転記しない。
記録の欠落や不一致を検出した処理は停止し、別の重みや規則で継続しない。

診断と教師生成は1スレッド、置換表64 MiBとし、局面ごと、候補手ごと、予算ごとに置換表を空にして探索する。
提案手を得る浅い探索は100,000ノード、教師の診断は1,000,000ノードと10,000,000ノードの2段階に固定する。
学習ラベルは10,000,000ノードの教師で作る。
これらは今回比較する運用上の予算であり、その探索予算で真値へ達したことを意味しない。

教師の予算を増やす追加試行は、本書では行わない。
費用は校正標本で実測し、学習ラベルの生成と3組の棋力測定の見積りを測定記録へ残してから大量生成へ進む。
着手前の桁は次のとおりである。
[係数の表の速度測定](../measurements/bench-spsa-params-nps.md)の深さ8のNPSは約212万なので、1,000万ノードの教師は1局面約5秒を要する。
訓練の3局面組と選択集合を合わせた約10万局面のラベル生成は単一スレッドで約140時間、同時16で約9時間になる。
訓練、選択、最終診断に必要な約7万根を集めるには約5,000局の自己対局が要り、1手10万ノードで同時16なら約3時間である。
この概算は、1局から上限の16根を採取できること、自己対局が平均640手であること、および性能コア1個で測った単一スレッドのNPSが同時16でも保たれることを仮定する。
採取の不成立と並列時の速度低下は、校正標本の実測で置き換える。
資源の都合で中断する場合は状態を待機中とし、同じmanifestで再開する。
都合に合わせて予算や標本数を減らした結果を、同じ実験として扱わない。

## 局面を履歴ごと復元する

原局面は、対局記録の開始手順と着手列を、同じ規則の `Game` へ再生して復元する。
根の手番、盤面、先獅子、成り権、反復の履歴、裁定に必要な状態を保持する。
既存の教師データ形式MNSDと再評価値の形式MNRSは完全な履歴を持たず、既存の `selfplay_gen rescore` は局面から新しい対局を始めるため、本書の履歴つき教師へそのまま使わない。
盤面と局所状態を文字列へ表す拡張SFENも、履歴の代わりにはならない。

探索局面は、元の対局、根の手数、根からの着手列で表す。
着手列には獅子の中間升、居喰い、成りの選択も保存し、単なる升の組へ縮めない。
採取時には実際の `Position` の複製と経路上の局面キーを保持する。
保存前に、再生した `Game` の局面と複製を `Position::Eq` で比較し、盤面、手番、先獅子、成り権、派生状態が一致することを確かめる。
根の `SearchSnapshot::history_keys()` と経路で観測したキーの列も、再生した `Game::search_key_history()` の対応する列と照合する。
保存後の改変検出には、拡張SFENと正準化した履歴キー列の検査和を使う。
仮想のパスであるnull move配下、反復を含む経路、対局管理層が終局または不合法と判定する経路は採取対象から外し、理由別の件数を記録する。
一度受理した標本の再生が一致しない場合は入力の不整合として停止する。

教師への入力は、復元した `Game` から作る `SearchSnapshot` とする。
対局管理層の裁定履歴は棋譜から復元するが、現行の探索は裁定の全カウンタを受け取らず、静止探索には反復検出もない。
探索が持つ局面と履歴キー列を照合しても、全裁定状態を探索内部で使ったとは扱わない。
この制約を教師の条件として記録し、探索の裁定方法を本書で変更しない。
候補手の固定には、対局を複製し、`Game::play` でその手を指してから子を探索する方法を使う。
子の通常評価値の符号を反転すると根の手番側の値になる。
終局は対局管理層の結果を使い、詰みを示す探索値は通常のセンチポーン差へ混ぜない。
教師探索がノード上限に達しても、完了した反復の値と完了深さが得られていればその値を保存する。
深さ0、未完了の反復の途中値、置換表から採った上下界は回帰用ラベルにしない。
応答は、`Game` の終局、完了深さ0による未完了、`abs(score) >= search::MATE_THRESHOLD` による詰みの推定値、それ以外の通常評価の順に分類する。
旧データ形式の詰み判定の閾値を、新形式へ転記しない。

## 教師が着手の誤りを識別できるか調べる

校正用64根と、別の対局群に由来する確認用128根を、教師探索の前に固定する。
各集合の半分を旧NNUE、半分を旧FMの資料に割り当て、1つの先後対局ペアからは1根までにする。
旧NNUEの資料は[世代1の固定ノード測定](../measurements/nnue-gen1-nodes100k.md)と[時間制御測定](../measurements/nnue-gen1-tc.md)の実行ディレクトリ `data/matches/nnue-gen1-nodes100k` と `data/matches/nnue-gen1-tc`、旧FMの資料は補正1/4版の実行ディレクトリ `data/matches/fm-quarter-vs-original-stc`、`data/matches/fm-quarter-vs-pst-stc`、および `data/matches/fm-quarter-vs-pst-ltc` とする。
校正集合は `nnue-gen1-nodes100k` と `fm-quarter-vs-original-stc` から、確認集合は `nnue-gen1-tc` と `fm-quarter-vs-pst-stc` から取り、後者で不足する場合だけ `fm-quarter-vs-pst-ltc` を確認集合に加える。
全FMの採否測定は実行ディレクトリが残っていないので使わない。
補正1/4版は当時のPSTに対する採否測定を通過しているため、その手が基準手と異なることを誤りとは推定せず、後述の分類で両方向の支持を数える。
校正と確認の対局群は実行ディレクトリの単位で分け、同じ実行ディレクトリから両方へ根を取らない。
旧候補が提案した手と基準の手が異なる根を、教師の値を見ずに抽出する。
棋譜を完全に復元できない資料は本診断から除外し、予定数を確保できなければ資料不足として待機する。
既に分析したFMの16局面とlishogiの敗局は、動作確認や参考分析に使えても確認用128根へ含めない。

旧候補の手は、保存着手、または固定した旧バイナリに同一の開始手順と着手列を与えて得た提案手を使う。
どちらを使うかは校正前に資料ごとに固定し、旧バイナリが局面を再現できない場合に別方式へ黙って切り替えない。
基準手はS0の100,000ノード探索で求める。
旧候補とS0では探索も異なり得るため、この診断だけからモデル構造の因果効果を結論しない。

根ごとの候補集合には、旧候補手、S0の提案手、教師の両予算の提案手を含める。
重複を除いた同じ集合の各手について、両予算で子を独立に探索する。
探索順は正準化した手の順で固定する。
この集合で最良の手は、全合法手で最良の手を証明するものではない。

予算nで子を調べた根視点の値を \(Q_n(s,a)\) とし、基準手を \(a_0\)、旧候補手を \(a_c\) とする。
比較する量は次式である。

\[
D_n(s)=Q_n(s,a_0)-Q_n(s,a_c).
\]

正の値は教師が基準手を良いと判定したことを表し、同じ手なら0になる。
校正集合の通常評価が得られた根で、\(|D_{10M}-D_{1M}|\)の90パーセンタイルを線形補間で求める。
基点の歩兵価値をPとし、判定に使う差mを \(\max(P/4,\operatorname{p90}|D_{10M}-D_{1M}|)\) に固定する。
校正で通常評価の比較が32根未満なら教師診断を通過せず、その理由を記録する。
確認集合の結果を見てmを変えない。

確認集合は次の規則で分類する。

| 分類 | 条件 |
|---|---|
| 基準手を安定して支持する。 | 両予算のDがm以上で、予算間の差 \(\lvert D_{10M}-D_{1M}\rvert\) がm以下である。 |
| 旧候補手を安定して支持する。 | 両予算のDが−m以下で、予算間の差 \(\lvert D_{10M}-D_{1M}\rvert\) がm以下である。 |
| 差が小さい。 | 両予算でDの絶対値がm未満である。 |
| 判定が不安定である。 | 通常評価で比較できるが、上のいずれにも入らない。 |
| 通常評価では比較できない。 | 終局、詰みを示す値、未完了などを含む。 |

確認128根のうち、最初の3分類が合わせて64根以上であり、基準手を安定して支持する根が8根以上なら学習へ進む。
旧NNUEと旧FMそれぞれの件数も示し、一方でしか識別できなければ結論をその一方へ限定する。
差が小さい根の最上位手が入れ替わっても、単独では停止理由にしない。
これらの数とmは、今回の学習費用を掛けるための運用上の基準であり、教師の正確さの統計的保証ではない。
予算間の変動幅を信頼区間と呼ばない。

条件を満たさなければ、今回の教師構成では必要な診断根拠が得られなかったとして見送りにする。
教師の変更や予算増加は、別の設計判断と独立した確認集合を要する後続作業とする。

## 探索中の評価局面を採取する

採取器はS0の重みを使い、100,000ノードの探索を行う。
静止探索で静的評価を実際に呼び出した位置に、診断ビルドだけで有効な採取処理を置く。
捕獲の枝がまだ残る局面も対象になり得るため、採取局面を「取り合いが終了した最善経路の末端」と呼ばない。
通常探索の枝刈り用の静的評価、置換表だけで返った値、詰みの値は、この採取集合へ混ぜない。

各根でnull move配下を除く評価局面を重複除去し、reservoir samplingで1局面を保持する。
重複は、手番をそろえたPSTの入力特徴と補間係数が一致することで判定し、同じ根で最初に現れた経路を残す。
これは到来する標本から一定数を等確率で保持する抽出法であり、シードは元の対局ID、根の手数、抽出用シードから導き、同じ入力から同じ標本を得る。
大きい補正や教師に都合のよい値を見て採取対象を選ばない。
抽出した1局面は保存前に経路を対局管理層で再生し、不適格なら根ごと除外して別の局面を引き直さない。
採取結果がない根の割合と除外理由を記録し、学習分布はこの条件で採取できた局面に限ると明示する。

採取の有無によって、同じ入力の最善手、評価値、完了深さ、探索ノード数が変わらないことを確認する。
採取つきバイナリの1秒あたり探索ノード数NPSを実戦用の速度として報告しない。
実戦用ビルドで採取処理が除かれることも確認する。

## 教師データの契約

新しいデータは、実行条件を持つmanifest、棋譜への参照、局面と経路を持つJSON Lines、教師の応答を持つJSON Linesに分ける。
各ファイルは形式名と版を明示し、内容の検査和で対応付ける。
棋譜の複製を局面ごとに保存せず、元ファイルの検査和と対局IDで参照する。

| 記録 | 必須の内容 |
|---|---|
| 局面の由来 | 元の対局ペアID、対局ID、根の手数、経路、採取理由、規則、分割を保持する。 |
| 局面の照合 | 再生後の拡張SFEN、先獅子などの局所状態、正準化した履歴キー列の検査和を保持する。 |
| 教師の応答 | 教師の版と重み、要求予算、実消費ノード、完了深さ、値の種類、手番側の評価値、最善手を保持する。 |
| 採取の集計 | 呼出件数、重複、null move配下、反復、不合法、終局、および各除外理由の件数を保持する。 |

通常の教師値が得られた局面は、最善手が捕獲や成りでも自動除外しない。
既存のMNSD読み込みにある戦術局面の除外を流用すると、今回調べる探索分布を再び変えてしまうためである。
終局、詰みを示す探索値、未完了は別の集計に残し、通常評価へ換算して学習しない。
未記録の対局結果に仮の値を与えず、教師の尺度Kを勝敗から推定する既存経路も呼ばない。

入力の一部が欠けた場合は、再実行で同じ局面の同じ教師要求を補う。
別の局面で不足件数を埋める処理や、教師の応答の種類を無視する処理は設けない。

## 学習用と診断用の分割

旧モデルの教師診断に使った対局群は、学習、モデル選択、最終診断から除外する。
学習用の原棋譜は、S0同士の対局から収集する。
開始手順をランダム化し、使うシード範囲と全棋譜を保存する。
既存の保存棋譜を使う場合も、必要な来歴と完全な再生が可能なものだけをmanifestへ明記する。

分割は局面抽出の前に対局ペア単位で固定する。
同じ開始手順、同じ元対局、同じ根からの子と探索局面、左右反転で一致する局面は分割をまたがせない。
採取後にも局面の正準化した特徴を照合し、分割をまたぐ重複があれば、その対局群全体を同じ分割へまとめてから分割を凍結し直す。
この処理は教師ラベルの生成前に完了させる。
同じPST入力に異なる履歴が対応する場合も、学習と診断の間の重複として数える。

対局群は訓練80%、モデル選択10%、最終診断10%を目安に割り当て、実際の比率を保存する。
訓練は各群65,536局面、モデル選択は共通の8,192局面とし、最終診断には未使用の256根と各根から採取した1局面を確保する。
各対局から使う根は16個までに抑え、必要数を確保できるまで教師を見る前に原棋譜を収集する。
原棋譜が不足する場合は待機して同じ条件で追加し、検証局面を訓練へ移さない。

## 同じPSTで学習分布を比較する

AとBの訓練集合を次のように固定する。
通常局面は対局で実際に現れた根であり、探索局面は同じ原棋譜の根から前述の方法で採取した局面である。

| 群 | 通常局面 | 探索局面 | 役割 |
|---|---:|---:|---|
| A | 65,536局面を使う。 | 使わない。 | 深い教師による通常の再学習の対照である。 |
| B | Aと共通の32,768局面を使う。 | 残り32,768根に対応する探索局面を1個ずつ使う。 | 学習対象の半分を置き換える候補である。 |

両群で使う通常局面と探索局面の対応を、教師の生成前に確定する。
適格な探索局面がない根は、対応するAの根とともに抽出の候補から除く。
学習用の1組は、両群に共通の通常局面u、Aだけが使う通常局面v、Bがvの代わりに使う探索局面zの3局面とする。
組み方は教師を見る前に固定し、32,768組を作る。
モデル選択用の共通集合は、通常局面とその根から採取した探索局面を1個ずつ持つ4,096組で構成する。
同じ群内で入力が重複する局面を増やして必要数を満たすことはしない。

両群の教師への問い合わせ回数と1回ごとのノード上限をそろえる。
共通局面の教師応答は再利用できるが、各群へ帰属する問い合わせ枠は同じとする。
早期終了によって使わなかった予算を追加局面へ再投資しない。
組のうち1局面でも通常評価以外の応答があれば、組全体を学習から外す。
これによりAとBの件数を等しく保ち、Bとモデル選択集合では通常局面と探索局面を半数ずつに保つ。
組の受理について、学習前に次の2条件を満たさなければ今回の固定比較は見送りにする。受理した訓練の組で総更新回数が2,000回を超えること、およびモデル選択で使える組が予定数の90%以上であることである。
当初は訓練にも予定数の90%以上を求めていたが、2026年9月26日に、学習の開始前にこの条件を改めた（改訂の経緯は「状態」の節）。
この除外で比較の対象が通常評価を得られた局面に限られることも明記する。
予定数を割り当てたことと、実際に学習できた件数を区別して報告する。

教師の10,000,000ノード値をT(x)、PSTの出力をF(x)、S0の出力尺度をK0として、勝敗との混合なしに次を学習する。

\[
\mathcal L
=\operatorname{BCE}\!\left(\sigma(F(x)/K_0),\sigma(T(x)/K_0)\right)
+1000\,\mathcal L_{\mathrm{removal}}.
\]

BCEは二値交差エントロピー、\(\sigma\)はシグモイド関数である。
\(\mathcal L_{\mathrm{removal}}\)は[段階7](strength-stage7.md)の、駒を除いた評価差の符号反転を抑える損失とし、S0を参照に固定する。
K0、探索用駒価値、特徴の定義、鏡映共有、2端点補間をAとBで一致させる。
同じ教師TとK0を両群に使うため、教師値の尺度の推定による違いは入れない。

最適化はAdam、学習率0.03、40エポック、バッチ1,024、学習シード1とする。
学習率0.03と駒除去損失の係数1000は、[段階7の予備比較](../measurements/strength-stage7-removal-absolute.md)で選び現行の学習手順が用いる組をそのまま使う。
予定数なら1エポック64更新、全体2,560更新となり、90%以上の組を受理した場合も2,000更新を超えることを確認する。
段階7の再学習の約6分の1の更新回数だが、両群ともS0の重みから始める追加学習であり、[教訓](../lessons/check-steps-per-epoch-before-training.md)が求める数千回の下限を満たし、比較の目的は同じ日程の下でのAとBの差なので、この回数で固定する。
収束を主張するための回数ではないため、両群の選択がエポック0に留まった場合は学習で変更を得られなかったとして記録する。
各更新後の重みの保存範囲への射影と、非有限値の拒否は既存の契約を使う。
AとBはともにS0の重みと新しい最適化状態から開始し、全40エポックを実行する。
エポック0を含め、共通のモデル選択集合で教師へのBCEが最小となった重みをそれぞれ選び、同値なら早いエポックを選ぶ。
結果を見て学習率、置換率、エポック数、乱数シードを足さない。
訓練損失とモデル選択用の損失の推移を記録するが、曲線の見た目だけで中止や設定変更を決めない。

## 採否前の診断

まず、浮動小数点と量子化後の平均絶対誤差が2センチポーン以下であること、RustとPythonの評価が一致すること、鏡映共有と重みの範囲が保たれることを確認する。
駒除去差分と成りの評価差は、既存の診断に加えて、共通のモデル選択集合から固定した標本でも点検する。
符号反転の件数と最大幅を記録し、S0にはない駒除去差分の符号反転があれば対局へ進めない。
S0自身にも同じ診断を先に適用し、既存の違反と新たな違反を区別する。

最終診断用256根では、S0、A、Bの100,000ノードでの提案手と、教師の両予算の提案手を同じ集合に入れる。
各手の子を独立に調べ、全候補手で両予算の通常評価が得られた根について、候補集合内の選択損失を求める。
その集合のすべての手の組に先のDとmによる分類を適用し、すべてが安定した支持または小差に入る根を、教師の判定が安定した根とする。
終局、詰みを示す値、未完了を含む根は別に数え、通常評価の損失へ混ぜない。
候補wが選んだ手を \(a_w\)、候補集合をC(s)とすると、その損失は次式である。

\[
R_T(s,w)=\max_{a\in C(s)}Q_{10M}(s,a)-Q_{10M}(s,a_w).
\]

全合法手に対する真の損失とは呼ばず、教師が安定した根と不安定な根の件数を併記する。
最終診断の通常局面と採取局面にはそれぞれ独立した教師値を付け、評価誤差、正方向の誤差の95パーセンタイル、対局群ごとの平均も記録する。
この診断の問い合わせは学習用の枠とは分け、通常評価を得た件数と除外件数を示す。
これらは機序を調べる診断であり、平均誤差が下がったことを棋力の採用根拠にしない。
最終診断の結果を見て別エポックを選び直さない。

速度は実戦用ビルドの `bench` と、同じ着手列での評価更新時間を記録する。
S0の重みを載せた実戦用ビルドはS0と同じ探索結果を返すことを確認し、診断処理の混入がないことを確かめる。
AとBで探索木が変わることによるNPSの差は、推論構造の費用と分けて解釈する。

## 棋力の採否

診断を通ったBを、まずAに対して、次にS0に対して測る。
それぞれ[標準手順](../guides/sprt.md)の短時間条件STCと長時間条件LTCを使い、B対AでLTCの採用条件を満たした場合だけB対S0へ進む。
STCは10秒と1手あたり0.1秒の加算、LTCは60秒と1手あたり0.2秒の加算である。
各比較ではSTCで候補を選別し、通過した場合だけLTCへ進む。
比較の結果を合算しない。
ただし、AとS0の量子化後の重みが等しく、実戦用の探索と評価の処理も同一と確認できた場合には、B対S0の1組の測定で両要件を判定し、A対S0は測らない。
この一致の判定は対局前に行い、該当時にはB対S0の測定名とシードを使う。

A対S0のSTCは、Bの結果にかかわらず測定前に登録して実行し、深い教師による通常局面の再学習だけの効果として記録する。
この記録は、相対2駒評価の準備が参照する教師の能力の根拠になる。
A対S0のLTCは、Bが採用されず、かつA対S0のSTCがLTCへ進む条件を満たした場合にだけ実行し、LTCの採用条件を満たせばAを採用する。
Bを採用した場合はA対S0のLTCを実行しない。
この経路は事前登録によるものであり、Bの結果を見てAの扱いを変えることではない。

測定名は順に `search-aware-pst-b-vs-a-stc`、`search-aware-pst-b-vs-a-ltc`、`search-aware-pst-a-vs-base-stc`、`search-aware-pst-a-vs-base-ltc`、`search-aware-pst-b-vs-base-stc`、`search-aware-pst-b-vs-base-ltc` とする。
基本シードは順に161000925、162000925、165000925、166000925、163000925、164000925を予約し、準備時に既存の実行記録と重複しないことを検査する。
重複が見つかった場合は測定開始前に未使用範囲へ変更してmanifestを固定し、結果を見た後のシード変更はしない。
各比較の先後を入れ替えたペアを同じ手順で生成する。

候補と基準はコミットで指定し、ハーネスへ方式比較のスイッチを加えない。
STCの上限は3,000ペアとし、不採用へ進むH0、LTCへ進むH1、上限時の保留の振分けは手引きどおりとする。
LTCの保留は同じ測定を再開し、保留のまま採用や不採用へ読み替えない。
異常、時間切れ、拒否着手を扱う規則も手引きに従う。

必要な比較のLTCをすべて通過した場合だけ、Bを採用する。
B対Aを通過してB対S0を通過しなかった場合は、分布変更の比較結果と実戦用の不採用を分けて報告する。
Aの採用は前述の事前登録した経路だけによる。

## 停止と後続の判断

| 条件 | 処理と再開条件 |
|---|---|
| 棋譜、規則、符号、検査和、再生の不整合がある。 | 待機して不具合を修正し、同じ固定入力で影響する工程をやり直す。 |
| 校正または確認で教師の条件を満たさない。 | 今回の教師構成を見送りとして完了し、別の教師や予算は別計画で判断する。 |
| 入力資料や計算資源が不足する。 | 待機し、同じ抽出規則と予算で資料や資源を確保して再開する。 |
| 受理した訓練の組で総更新回数が2,000回以下になる、またはモデル選択で使える組が予定数の90%未満である。 | 今回の分布比較を見送りとして完了し、標本の定義を次の計画で見直す。 |
| 非有限値が発生する、または量子化や駒除去診断に失敗する。 | 実装の不具合なら修正して両群を同じ設定で再実行する。設定を変えないと解消できなければ、失敗した群だけを見送りにする。 |
| AまたはBの一方だけが採否前の診断に失敗した。 | 失敗した群を含む比較は対局しない。Aだけが正常ならA対S0を事前登録どおり測り、その採用経路も事前登録の規則に従う。Bだけが正常でも、B対Aを測れないためBは採用せず、分布比較を見送りにする。 |
| BとS0の量子化後の重みが同じになった。 | Bの比較は対局せず、今回の学習分布の変更では出力の変更を得られなかったとして見送りにする。A対S0は事前登録どおり測る。 |
| AとBの量子化後の重みが同じになった。 | 学習分布による出力の差が得られなかったとしてB対Aは対局せず、分布比較を見送りにする。A対S0は事前登録どおり測り、Aの採用経路も事前登録の規則に従う。 |
| 棋力測定が停止条件に達する。 | STCとLTCの標準規則に従い、採用、不採用、または継続を確定する。 |

本書の採否または見送りが確定したら、最後に採用されたPSTと、教師の診断、学習処理の検証、残存誤りの記録を[相対2駒評価](relative-pair-eval.md)の準備へ渡す。
事前登録した経路で採用されなかったAやBの重みを、次段の基点へ回すことはしない。
教師が安定した着手の誤りを示し、学習処理も成立し、複数駒の配置に対応する誤りが残る場合には、関係項を比較する根拠として記録する。
その対応は未使用局面の具体例と特徴の比較で確認し、PSTで改善しなかっただけで表現力不足とは断定しない。
Bの採用は相対2駒評価の必須条件ではなく、採用されても着手の根拠が得られなければ自動的に進めない。
教師診断に失敗した場合や学習の不具合が残る場合は、その原因を先に扱い、失敗した教師を関係項の学習へ流用しない。

関係項を学ぶ教師、局面の分布、尺度、分割は、相対2駒の計画で準備時に固定する。
本書の分布や診断値を都合に応じて引き継がず、教師や分布自体の効果を新たに比較する場合は、関係項の追加から分けて計画する。
共通する棋譜の復元と教師の再評価には本書の契約を使い、相対2駒表に固有の速度や補正量の診断は同計画が定める。

旧FMの補正1/4版は診断の参考資料とし、その先行統合を必須にしない。
FMの再利用は相対2駒表と比べる代替候補とし、NNUEを使うなら過去の構成との違いと必要な費用を改めて定める。
利きの補助学習は、利きに関する誤りが残り、かつ同じ中間表現で補助出力を学べる構成を比較するときの別の介入とする。
これらの条件がそろっても、本書から自動的に実装や測定を始めない。

## 実装フェーズ

### フェーズ1　条件の固定と教師診断器

混合比計画の判定と、引き継ぐ採用PSTを確認してmanifestへ固定し、棋譜の再生、値の分類、候補集合、教師の独立した子探索を実装する。
新しい診断用実行ファイルを `src/bin/eval_teacher.rs` に置き、既存の `Game`、`SearchSnapshot`、同期探索を利用する。
旧FMの診断器は値の分類と独立探索の参考とし、履歴を失う入力処理を引き継がない。
校正と確認の抽出規則を固定し、符号と状態の再現の検証を通すことを完了条件とする。

### フェーズ2　教師の校正と確認

校正64根でmと費用の見積りを固定し、独立した確認128根で続行条件を判定する。
結果を `search-aware-teacher-calibration` と `search-aware-teacher-confirmation` の測定記録に残す。
続行または見送りが事前の規則どおり確定することを完了条件とする。

### フェーズ3　探索局面と教師データ

診断ビルドの採取処理、経路の再生、分割と重複の照合、専用データ形式、および教師ラベルの生成を実装する。
`src/eval/` には保存契約に必要な処理だけを置き、実験の選別や集計は診断器と `tools/train/pst/` に置く。
計数の有無で探索結果が変わらず、AとBの問い合わせ枠と学習件数がそろうことを確認する。
入力と除外の内訳を `search-aware-data` に記録することを完了条件とする。

### フェーズ4　対照学習と診断

既存のPSTモデル、損失、射影、量子化を再利用し、対局結果なしで固定K0の教師値を読む学習経路を追加する。
既存のMNSD経路とは入力の意味が異なるため、形式で明示的に区別し、勝敗や来歴を補完しない。
AとBを同じ設定で学習し、選んだ重みを固定して、量子化、駒価値、最終診断、速度を確認する。
`search-aware-pst-training` と `search-aware-pst-diagnostics` に、候補を対局へ出すか見送るかの結論が残ることを完了条件とする。

### フェーズ5　採否と現行設計の更新

B対A、A対S0のSTC、通過した場合はB対S0、Bを採用しない場合はA対S0のLTCの順に測定する。
採用した場合は、重みとともに[評価関数](evaluation.md)と[PSTの学習手順](../guides/pst-training.md)の現行の教師と学習方法を更新する。
最後に採用されたPSTと残存誤りの記録を確定し、相対2駒評価の準備で検討すべき根拠と未解決の原因を記す。
採否または見送りが測定記録で確定し、本書とROADMAPの状態が一致することを完了条件とする。

## 検証

検証の期待値は本書の契約と[競技規則](../../RULES.md)から定め、実装の出力をそのまま正解にしない。
主な確認事項は次のとおりである。

| 対象 | 独立した期待値と確認事項 |
|---|---|
| 棋譜の再生 | 手で作った先獅子、獅子の2枚取り、居喰い、成り、反復の例を使い、盤面が同じでも必要な状態を失わない。 |
| 親子の視点 | 子が+120なら親のその手は−120になる。先後、偶奇、終局の勝者、詰みを示す値の分類を別々に確認する。 |
| 候補手の比較 | 同じ手ならDは0で両候補の選択損失は等しい。集合内の教師最良手の選択損失は0となり、他の手は正になり得る。他の探索の置換表を共有しない。 |
| 教師の判定 | 手計算の数列で分位点と閾値境界を確認し、小差の順位入替え、大差の反転、比較不能を区別する。 |
| 採取 | 採取の有無で決定的探索の結果が一致し、null move配下や再生不能な経路を受理しない。 |
| データと分割 | 元対局、根、子、探索局面、鏡映、転置をまたぐ漏洩、欠けた履歴、教師版の混在を拒否する。 |
| 教師の対応 | 根と末端の値が異なる小さい探索例で、末端へ根の値を誤って付けたデータを照合で検出する。 |
| 学習 | 対局結果の有無で固定教師値が変わらず、AとBで構造、初期値、尺度、更新数が一致する。 |
| 出力 | Pythonの参照評価とRustの量子化評価、駒除去と成りの前後差を照合し、該当する値だけを壊した入力が拒否される。 |

実装時には `cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check` と、変更した学習器の単体テストを通す。
計画書の作成だけを理由に学習や対局測定を実行しない。

## 完了条件

- 教師診断、データ、学習、採否のうち実行した段階について、条件と結果の記録が残っている。
- 教師または学習診断による見送り、AとBの不採用、AまたはBの採用のいずれかが事前の規則に従って確定している。
- Bを採用する場合は、同じBがAとS0に対する必要なLTCを通過している。Aを採用する場合は、Bが採用されず、A対S0のSTCとLTCを通過している。いずれも実戦用ビルドに採取処理が含まれていない。
- 不採用や見送りの場合は、今回否定された仮説の範囲と、未検証の関係モデルを区別して記録している。
- 後続へ渡す採用PST、教師の診断、学習の成立の有無、残存誤りを記録し、相対2駒評価の着手をBの採否だけで決めていない。
- 現行設計、本書の要約と状態、ROADMAPが採否と一致している。

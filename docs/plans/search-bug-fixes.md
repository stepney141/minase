# 探索部の不具合修正の設計書

## 先に読む要約

本マイルストーンは、[探索部の不具合監査](../audits/search-bugs-2026-09-28.md)（以下「監査」）が確認した3件の不具合を修正し、修正後の探索がmasterより10 Elo規模で弱くなっていないことを自己対局で確かめてから取り込む。
第1の不具合は、読みの末端で捕獲手だけを読む静止探索が、見込みの薄い捕獲を省く枝刈り（delta pruning）で、捕獲と同時に成る手の成り益を無視することである。このため、成りで大きく得をする捕獲を読まず、真の値より低い値を返す。
第2の不具合は、静止探索が、手番側の王駒がすべて相手の駒に狙われている局面でも、何も指さずに現局面の評価値を確保できるとみなす下限（stand-pat）を使うことである。このため、次の手で最後の王駒を取られる負けを見落とす。
第3の不具合は、手番を仮に相手へ渡して浅く読む枝刈り（null move pruning）の直後に、相手がじっと（獅子が隣の升へ出て同じ手で元の升へ戻る手）を指すと、盤面が元に戻ったことを同一局面の反復として引き分けと判定することである。null moveは実際の対局に現れないので、この引き分けは実在しない。
修正は、成り益を枝刈りの判定に加えること、王駒がすべて狙われている静止探索の局面では捕獲以外の手を含む全合法手を読むこと、および反復の検出をnull moveより前の局面へ遡らせないことである。
3件はいずれも探索の正しさの修正なので、利用者の決定により、採否は棋力の向上ではなく非劣性で判定する。
非劣性の判定は、masterを候補、修正の最終コミットを基準にした標準のGSPRT（勝敗から強さの差を逐次判定する統計検定、[棋力測定の手引き](../guides/sprt.md)）を、短時間と長時間の2条件で1回ずつ行う。どちらも「masterが10 Elo強い」という仮説が棄却されれば（判定`H0`）修正を採用する。
完了条件は、3件の修正がテストで固定され、非劣性の測定記録とともに採否が確定していることである。

## 状態

起案。2026年9月28日に起案した。
監査の基準コミット（監査報告の冒頭に記載）から分岐したブランチ`search-bug-fixes`で実装する。
非劣性の測定は、実行中のHaChuとの固定200ペアの測定（`strength-stage12-hachu-elo200`）の終了後に始める。
次の一手は、フェーズ1（null moveをまたぐ反復）の実装である。

## 目的

監査は、3件の不具合のそれぞれについて、探索が真の値と矛盾する値を返す再現例と、固定局面の探索ベンチ`bench`（15局面を固定深さで探索し、総ノード数を出力する実行ファイル）での発生頻度を示した。
delta pruningの件では、深さ7で成り益のある捕獲を除外した静止探索ノードが5.0%あり、探索窓の上端を超える捕獲成りを捨てて、誤った上界を返していた。
stand-patの件では、静止探索ノードの3.0%で手番側の王駒がすべて狙われており、深さ1の探索は詰みの手を評価値4661と評価した。
null moveの件では、深さ9でnull moveをまたぐ反復が1,986件あり、これを反復と扱わないだけで総ノード数が8.0%減った。
本マイルストーンは、これらを直して探索が返す値の正しさを回復する。
棋力の向上は目的に含めないが、修正が棋力を10 Elo規模で下げていないことは測定で確かめる。

## 適用範囲

対象は`src/search/alphabeta/`の`quiesce.rs`、`negamax.rs`、`searcher.rs`、`royal.rs`と、関係するテストである。
合法手生成、評価関数、および対局管理層は変更しない。

監査の軽微な指摘のうち、静止探索が合法手のない局面の負け（RULES.md第23条）を検出しない件は、第2の修正が発動する局面でだけ解消する。
第2の修正は、発動した局面で全合法手を生成するので、合法手が1つもないことをその場で判定できるからである。
それ以外の静止探索の局面では現行のまま残す。
中将棋ではこの局面がほとんど現れず、全静止探索ノードで合法手を生成する費用に見合わない。
置換表の詰みの値が深い位置で詰みの帯から外れ得る件は、実際の探索深さで起こらないので扱わない。

第2の修正は、費用を抑えるために、1本の静止探索の経路で発動する回数に上限を設ける（設計判断の節）。
上限に達した後の局面では、王駒がすべて狙われていても現行どおりstand-patを使うので、その経路では第2の不具合が残る。
たとえば、捕獲以外の手で王駒を逃がした後、相手の捕獲で再び王駒がすべて狙われた局面がこれに当たる。

監査が既知の近似として除いた、置換表を通じた反復の値の漏れと、反復規則を探索の木の中で引き分けとして扱う近似は、[探索内の反復負け回避](search-repetition.md)の範囲であり、本書では扱わない。

## 依存関係

基準は監査の基準コミット（masterの先頭）である。
[探索内の反復負け回避](search-repetition.md)は起案の状態であり、同書は「null moveを含む手順で局面が再現した場合は引き分けとする」ことを前提にしている。
第3の修正はこの前提を「null moveより前の局面の再現は反復として検出しない」に変えるので、同書の記述は本マイルストーンの完了時に書き直す（検証の節）。

## 設計判断

| 判断事項 | 採った方式と理由 |
|---|---|
| 採否の判定 | 利用者の決定により非劣性で判定する。3件はいずれも探索が返す値の誤りの修正であり、棋力に中立でも取り込む価値がある。通常の段階ゲートは+10 Eloの向上（`H1`）を要求するので、中立の修正は不採用となり不具合が残る。非劣性は、ハーネスへ比較のスイッチを足さずに、候補と基準を入れ替えた標準のGSPRTで判定する。masterを候補、修正の最終コミットを基準にすると、修正から見た比較点は0 Eloと−10 Eloになる。判定が`H0`なら「masterが10 Elo強い」が棄却され、10 Eloを非劣性の限界とする測定を通過したとして採用する。`H1`なら不採用とする。`H0`は10 Elo未満の小さな低下までは否定しない。この入れ替えは[持ち時間の効率的な使用](time-management-efficiency.md)の非劣性の測定と同じ手続きである。 |
| 測定の単位と回数 | 3件を別々のコミットとして積み、最終コミットとmasterの1組を、短時間（STC）と長時間（LTC）で1回ずつ測る。3件はどれも正しさの修正であり、個別の効果量は採否に使わないので、1組で非劣性を示せば十分である。1組が不合格となった場合は、各コミットをその親コミットと比べる個別の測定（STC）で原因を調べるが、個別の測定は診断であり、採否を決めない。個別の測定の結果を受けて修正を外したり組み直したりする場合は、本書を改訂して利用者の承認を得てから、新しいコミット、測定名、未使用のシードで測り直す。同じ候補を別のシードで再試行することはしない。採否を決める検定をSTCとLTCの各1回に限ることで、手続き全体の誤り率が単一の検定の5%を超えないようにする。 |
| 修正の順序 | 第3の修正（null move）、第1の修正（delta pruning）、第2の修正（静止探索の逃げる手）の順に積む。探索木への影響が小さく局所的なものから積み、ノード数が最も増え得る第2の修正を最後に置くことで、個別の測定が必要になった場合に親コミットとの差が他の修正と混ざらないようにする。 |
| 第1の修正の判定式 | 捕獲手の成り益を、成る手なら成った後の駒価値から成る前の駒価値を引いた値、成らない手なら0と定める。成り益は負にもなり得る（強制成りで価値が下がる駒）。静止探索は、取る駒の価値と成り益の和が閾値を超える捕獲と、最後の王駒を取る捕獲だけを展開する。この値は、SEE（静的交換評価。到達升での駒の取り合いを最後まで見積もる計算）が最初の着手の利得として使う値と同じであり、主探索の枝刈りと判定を揃える。Stockfishのように成る手を枝刈りから一律に外す案は、成り益が小さい駒の成りまで展開して静止探索の費用を増やすので採らない。 |
| 第1の修正の対象集合 | 静止探索が展開の対象とする捕獲は、現行と同じ捕獲の生成規則（獅子が経由升で取って別の空升へ進む手を除外する規則`is_excluded_lion_capture`を含む）で得られる捕獲のうち、判定式を満たすものと最後の王駒を取るものである。この集合は、delta pruningを適用した後、SEEによる枝刈りを適用する前の段階で定義する。修正は、特殊な捕獲の生成、通常の捕獲の有無の確認、置換表の手、および探索中にα（探索窓の下端）が上がった後の再判定のすべてに同じ判定式を使う。候補の生成は升単位で対象を絞っているので、成り益の上限（駒価値表から求まる、正の成り益の最大値）を足しても閾値以下の升だけを除外し、残った升への捕獲は着手ごとに判定式で判定する。成り益は上限以下なので、この絞り込みで判定式を満たす捕獲を失うことはない。 |
| 第2の修正の発動条件 | 静止探索のノードで、手番側に王駒が1枚以上あり、そのすべてに相手の駒の利きが届き、かつ現在の静止探索の経路で捕獲以外の逃げる手の回数が上限に達していない場合に発動する。王駒の一部だけが狙われている場合は、失っても対局が続く駒損なので、他の駒への脅威と同じく現行どおりstand-patを使う。 |
| 第2の修正の手の読み方 | 発動したノードではstand-patを使わず、捕獲以外の手を含む全合法手を生成して読む。全合法手は通常探索と同じ合法手生成で得るので、通常の静止探索が除外する獅子の手も含む。最後の王駒を取る手は子局面の終局値`MATE - (ply + 1)`とする。捕獲以外の手は、適用した直後に通常探索と同じ規則（第3の修正の検出範囲を含む）で反復を判定し、反復なら引き分けの値とし、そうでなければ局面キーを探索経路へ積んでから子局面の静止探索を再帰する。捕獲手は駒が減るので反復を判定せず、子局面の静止探索を再帰する。置換表の手が合法ならそれを最初に読み、続いて捕獲手をMVV-LVA（取る駒の価値の降順、動かす駒の価値の昇順）で、最後に捕獲以外の手を生成順で読む。発動したノードではdelta pruningとSEEによる枝刈りを行わない。探索値の初期値は負の無限大であり、合法手がなければRULES.md第23条により`-MATE + ply`を返す。 |
| 第2の修正の上限 | 静止探索は捕獲手だけを読むので、駒が減り続けて必ず終わる。捕獲以外の逃げる手はこの性質を壊し、王駒を狙い合う手順が交互に続くと再帰が深くなる。現行の静止探索には最大手数256での停止があるので終了はするが、そこまでの手数の再帰は費用の点で許されない。そこで、1本の静止探索の経路で捕獲以外の逃げる手を指せる回数に上限`K`を設ける。捕獲による逃げ方は駒を減らすので回数に数えない。`K`は読み落としの抑制ではなく費用のための近似であり、フェーズ3の診断で候補1、2、3から事前に定めた規則で選ぶ。規則は、`bench`の深さ9で、`K`=1のときの総ノード数の1.1倍以下に収まる候補のうち最大の値を選ぶことである。深さの上限のない再帰では、読み落としを抑える側の最も控えめな値（ここでは最大の値）を選ぶという[教訓](../lessons/recall-loss-does-not-bound-recursive-pruning.md)に従い、費用の許す範囲で大きい値を採る。 |
| 第2の修正と置換表 | 同じ局面でも、経路上で既に使った逃げる手の回数によって、読む手とstand-patの使用条件が変わる。この違いは局面キーに含まれないので、回数の異なるノードが置換表の値を共有すると、上限に達して詰みを見落とした値が、まだ回数の残るノードの打ち切りに使われる。そこで、置換表の照会と格納は、経路上で逃げる手をまだ1回も指していない静止探索ノードだけで行う。捕獲以外の逃げる手の後の部分木では置換表を使わない。この部分木は1回目の逃げる手の後に限られ、その多くは捕獲だけを読むので、費用は小さいと見込み、フェーズ3で該当ノードの数を記録する。通常探索は静止探索の中から呼ばれないので、通常探索の置換表の使い方は変わらない。回数を局面キーへ混ぜる案は、置換表の同じ局面の項目を回数ごとに分けて命中を減らすうえ、実装が局面キーの計算に及ぶので採らない。 |
| 第3の修正の検出範囲 | 探索ワーカーは、直近のnull moveを適用した時点の探索経路の長さを境界として保持する。null moveを適用したら、null move直後の局面の局面キーを探索経路へ積む。この局面キー自体では反復を判定しない。null moveの部分木の中では、境界以降に積んだ局面キー（null move直後の局面を含む）との一致だけを反復とし、境界より前の探索経路と対局履歴は参照しない。null moveの外では現行どおり、対局履歴と探索経路の全体を参照する。null moveより前の局面の再現は、実際の対局に現れないnull moveを挟んでいるので、対局上の反復ではないからである。null move直後の局面を積むのは、部分木の中で双方がじっとを指してnull move直後の局面へ戻る手順が、null moveを含まない本物の反復だからである。Stockfishは反復の検出を直前のnull moveまでに限り、ElephantEyeも遡りをnull moveで止める（[反復の先行実装の調査](../research/search-repetition-prior-art.md)）。null moveが入れ子になる場合は内側のnull moveの境界を使い、部分木から戻るとき（中断による戻りを含む）に探索経路と外側の境界を元に戻す。 |

## 測定の所要時間

段階8と段階12の実績（同時対局数16）では、STC（`time=10000+100`）が1ペアあたり約9.5秒、LTC（`time=60000+200`）が約27秒であった。
真の差が0に近い場合、非劣性の判定までの期待ペア数は[棋力測定の手引き](../guides/sprt.md)の近似式で約2,600ペアである。
したがって、STCは約7時間、LTCは約20時間を見込む。
第2の修正で棋力が上がった場合は、LLR（対数尤度比。GSPRTが判定に使う統計量）がmasterの弱い方向へ速く動くので、両測定とも短くなる。
LTCへ進む前に、STCの結果とこの見積りを利用者へ示して進め方を確認する。

## 実装フェーズ

各フェーズは、実装を委任するコーディングエージェント（codex）へ1フェーズ1タスクで委任し、テスト、`cargo clippy --all-targets`、`cargo fmt --check`の通過を確認してからコミットする。
コミットの件名は`fix(search): ...`とする。
`bench`の総ノード数とNPS（1秒あたりの探索ノード数）は、各フェーズの完了時に深さ9で、他の測定がない状態でPコアに固定して測り、測定記録`search-bug-fixes-bench`へ残す。
深さ9は監査がnull moveの件を計数した深さであり、null moveの子が通常探索になる残り深さ5以上のノードを十分に含む。

### フェーズ1　null moveをまたぐ反復の修正

設計判断の「第3の修正の検出範囲」を実装する。
既存のテスト`src/search/alphabeta/tests/contracts.rs`の、null move後の実着手による反復を引き分けとする検査は、新しい契約に書き換える。
次の4点をテストで固定する。
null moveの直後に相手がじっとを指して、null moveの前の局面へ盤面が戻る場合は引き分けとしない。
null moveの部分木の中で双方がじっとを指し、null move直後の局面へ戻る場合は引き分けとする。
null moveの外の反復の検出は変わらない。
入れ子のnull moveから戻る場合と探索が中断した場合に、探索経路と境界が元に戻る。

### フェーズ2　delta pruningの成り益の修正

設計判断の「第1の修正の判定式」と「第1の修正の対象集合」を実装する。
次の3点をテストで固定する。
監査の再現局面（SFEN形式で`11k/12/6p5/12/6O5/12/12/12/12/12/12/K11 b`）を、探索窓の下端αを1300、上端βを1301として静止探索すると、β以上の値が返る。監査ではこの窓で、着手前の評価値874を返していた。
成り益が負になる強制成りの捕獲は、成り益を含めた判定で除外される。
設計判断で定義した対象集合が、`bench`の局面と固定シードのランダム局面で、判定式から直接求めた参照の集合と一致する。

### フェーズ3　静止探索の逃げる手の修正

設計判断の「第2の修正の発動条件」「第2の修正の手の読み方」「第2の修正の上限」「第2の修正と置換表」を実装する。
まず`K`を1、2、3とした3つの版で`bench`を深さ9で実行し、上限の節の規則で`K`を選んで測定記録`search-bug-fixes-bench`に残す。
あわせて、置換表を使わない静止探索ノードの数を記録する。
次の6点をテストで固定する。
監査の再現局面（`11k/12/12/12/12/12/12/3b8/12/r2n8/P11/KP10 w`）で、深さ1の探索が詰みの値を返す。
王駒の一部だけが狙われている局面では、stand-patを使う。
王駒がすべて狙われていても、それを守る手がある局面では、詰みの値を返さない。
王駒がすべて狙われ、合法手が1つもない局面では、`-MATE + ply`を返す。
捕獲以外の逃げる手を`K`回指した経路では発動せず、その部分木では置換表を照会も格納もしない。
捕獲以外の逃げる手が対局履歴または探索経路の局面を再現する場合は、引き分けの値になる。

### フェーズ4　非劣性の測定

フェーズ3の完了時点のコミットを修正の最終コミットとし、監査の基準コミットと比べる。
測定はHaChuとの測定の終了後に、他の測定がない状態で始める。
STCの標準コマンドに対して候補と基準を入れ替え、次のとおり実行する。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/search-bug-fixes-noninferiority-stc --seed 83000000 \
  --candidate commit:<基準コミット> --baseline commit:<最終コミット> \
  --concurrency 16 --each time=10000+100 gsprt --max-pairs 3000
```

STCが`H0`ならLTCへ進み、`H1`なら不合格とする。
上限3,000ペアに達した`pending`は、停止時点のLLRが負ならLTCへ進み、0以上なら不合格とする。
LTCは次のとおり実行し、`H0`なら採用、`H1`なら不合格とし、`pending`なら同じ実行ディレクトリを`--resume`で再開して`--max-pairs`だけを増やす。

```console
cargo run --release --bin match_runner -- \
  --run-dir data/matches/search-bug-fixes-noninferiority-ltc --seed 83100000 \
  --candidate commit:<基準コミット> --baseline commit:<最終コミット> \
  --concurrency 16 --each time=60000+200 gsprt
```

いずれの測定も、エンジン異常、時間切れ、および拒否着手が0件であることを採用の条件に含める。
シードは既存の測定で使われていない値であり、STCとLTCは上限ペア数以上離してある。

STCまたはLTCで不合格となった場合は、採否の判定を終え、原因の診断として各修正コミットを候補と基準を入れ替えてその親コミットとSTCで比べる。
診断の測定名は`search-bug-fixes-<null-move|delta-promotion|qsearch-evasion>-diag-stc`、シードは`83010000`、`83020000`、`83030000`とし、`--max-pairs 3000`で打ち切る。
診断の結果は、どの判定であっても採否を決めず、測定記録と本書の状態の節に残して利用者へ報告する。
修正を外すか組み直すかは、設計判断の「測定の単位と回数」に従い、本書の改訂として利用者が決める。

## 検証

- 3件の修正のそれぞれについて、フェーズの節に挙げたテストが通る。
- 手選択器と静止探索の候補生成が、各合法手を高々1回だけ返すことを既存のテストで固定する。
- `cargo test`、`cargo clippy --all-targets`、`cargo fmt --check`が通る。
- 3件はいずれも探索の挙動を変えるので、`bench`の総ノード数の不変は採否の条件にしない。
- 採用した場合は、[探索部の設計書](search.md)の「静止探索」節と「探索内の終局と規則処理」節を修正後の挙動へ書き直し、「静止探索」節の「王手放置が合法な中将棋では、チェスで必要な『王手中はstand-pat禁止』の特例は不要である」という文を、第2の修正の説明へ置き換える。
- 第3の修正を採用した場合は、[探索内の反復負け回避](search-repetition.md)の「周回の区間と攻撃側の判定」の行と検証の節にある、null moveを含む区間を引き分けとする記述を、null moveより前の局面の再現は反復として検出しないという記述へ改める。

## 完了条件

- 3件の修正がそれぞれテストで固定されている。
- 非劣性の測定記録（STC、LTC、および不合格の場合は診断の測定）が残り、採否が本書の状態の節に記録されている。
- 採用した場合は修正がmasterへ統合され、関係する設計書が修正後の挙動と一致している。不採用の場合は修正がmasterへ入っていない。

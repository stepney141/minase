# 探索部の不具合修正の設計書

## 先に読む要約

本マイルストーンは、[探索部の不具合監査](../audits/search-bugs-2026-09-28.md)（以下「監査」）が挙げた指摘のうち、探索の手法がそれ自身の契約に反していた2件を修正し、修正後の探索がmasterより10 Elo規模で弱くなっていないことを自己対局で確かめてから取り込む。
1件目は、読みの末端で捕獲手だけを読む静止探索が、見込みの薄い捕獲を省く枝刈り（delta pruning）で、捕獲と同時に成る手の成り益を無視することである。このため、成りで大きく得をする捕獲を読まず、真の値より低い値を返す。
2件目は、手番を仮に相手へ渡して浅く読む枝刈り（null move pruning）の直後に、相手がじっと（獅子が隣の升へ出て同じ手で元の升へ戻る手）を指すと、盤面が元に戻ったことを同一局面の反復として引き分けと判定することである。null moveは実際の対局に現れないので、この引き分けは実在しない。
修正は、成り益を枝刈りの判定に加えることと、反復の検出をnull moveより前の局面へ遡らせないことである。
監査は3件目として、手番側の王駒がすべて狙われている静止探索の局面で、何も指さずに現局面の評価値を確保できるとみなす下限（stand-pat）を使うことも挙げた。しかしこれは、静止探索がどの脅威に対しても置く近似の一例であり、手法の契約違反ではないので、本計画の対象から外した。全合法手を読む修正を試した測定では、約120 Elo弱くなった。
2件はいずれも探索の正しさの修正なので、利用者の決定により、採否は棋力の向上ではなく非劣性で判定する。
非劣性の判定は、masterを候補、修正の最終コミットを基準にした標準のGSPRT（勝敗から強さの差を逐次判定する統計検定、[棋力測定の手引き](../guides/sprt.md)）を、短時間と長時間の2条件で1回ずつ行う。どちらも「masterが10 Elo強い」という仮説が棄却されれば（判定`H0`）修正を採用する。
完了条件は、2件の修正がテストで固定され、非劣性の測定記録とともに採否が確定していることである。

## 状態

進行中。2026年9月28日に起案し、同日に着手した。
監査の基準コミット（監査報告の冒頭に記載）から分岐したブランチ`search-bug-fixes`で、当初は3件の修正を積み、1組の非劣性のSTCで不合格（[search-bug-fixes-noninferiority-stc](../measurements/search-bug-fixes-noninferiority-stc.md)、masterの得点率69.1%）となった。
原因の診断では、stand-patの件の修正がその親コミットより有意に弱く（[search-bug-fixes-qsearch-evasion-diag-stc](../measurements/search-bug-fixes-qsearch-evasion-diag-stc.md)、親の得点率67.0%）、利用者の決定により、この件を不具合ではなく静止探索の近似と分類し直して本計画から外し、修正をブランチから取り除いた。
残る2件の修正の診断（delta pruningの件、続いてnull moveの件）を実行している。
次の一手は、2件の診断がいずれも`H1`でなければ、2件だけを積んだ版で非劣性のSTCをやり直すことである。

## 目的

監査は、対象の2件のそれぞれについて、探索が手法の契約と矛盾する値を返す再現例と、固定局面の探索ベンチ`bench`（15局面を固定深さで探索し、総ノード数を出力する実行ファイル）での発生頻度を示した。
delta pruningの件では、深さ7で成り益のある捕獲を除外した静止探索ノードが5.0%あり、探索窓の上端を超える捕獲成りを捨てて、誤った上界を返していた。
null moveの件では、深さ9でnull moveをまたぐ反復が1,986件あり、これを反復と扱わないだけで総ノード数が8.0%減った。
本マイルストーンは、これらを直して探索が返す値の正しさを回復する。
棋力の向上は目的に含めないが、修正が棋力を10 Elo規模で下げていないことは測定で確かめる。

## 適用範囲

対象は`src/search/alphabeta/`の`quiesce.rs`、`negamax.rs`、`searcher.rs`、`see.rs`と、関係するテストである。
合法手生成、評価関数、および対局管理層は変更しない。

監査の指摘のうち、本計画で扱わないものと理由は次のとおりである。

- stand-patの件は、不具合ではなく静止探索の近似として扱う（設計判断の「不具合の判定基準」）。
- 静止探索が合法手のない局面の負け（RULES.md第23条）を検出しない件は、中将棋でこの局面がほとんど現れず、全静止探索ノードで合法手を生成する費用に見合わないので扱わない。
- 置換表の詰みの値が深い位置で詰みの帯から外れ得る件は、実際の探索深さで起こらないので扱わない。
- 置換表を通じた反復の値の漏れと、反復規則を探索の木の中で引き分けとして扱う近似は、[探索内の反復負け回避](search-repetition.md)の範囲なので扱わない。

## 依存関係

基準は監査の基準コミット（masterの先頭）である。
[探索内の反復負け回避](search-repetition.md)は起案の状態であり、同書は「null moveを含む手順で局面が再現した場合は引き分けとする」ことを前提にしている。
null moveの件の修正はこの前提を「null moveより前の局面の再現は反復として検出しない」に変えるので、同書の記述は本マイルストーンの完了時に書き直す（検証の節）。

## 設計判断

| 判断事項 | 採った方式と理由 |
|---|---|
| 不具合の判定基準 | 不具合とは、実装がその手法自身の契約に反し、契約上起こらないはずの値を返すことをいう。delta pruningの契約は「最善の場合でもαに届かない捕獲だけを省く」ことであり、成り益を無視するとαに届く捕獲まで省くので、これに反する。反復検出の契約は「対局上の同一局面の再現を引き分けとする」ことであり、実際の対局に現れないnull moveを挟んだ再現を引き分けとするのは、これに反する。一方、stand-patは「現局面の評価値を下回らない手がある」とみなす楽観的な近似であり、王駒が詰んでいる局面での誤りは、両取りのように避けられない脅威すべてに共通する誤りの一例である。監査の再現例で深さ1が詰みを見落とし深さ2で見つけたのも、固定深さの探索に伴う地平線効果である。したがって、stand-patの件は不具合ではなく近似の限界であり、変えるなら通常の段階ゲート（+10 Eloの向上を要求するSTCとLTC）で判定すべき探索の改良である。王駒がすべて狙われた静止探索の局面で全合法手を読む方式は、親コミットに対する診断のSTCで約120 Elo弱かった（[search-bug-fixes-qsearch-evasion-diag-stc](../measurements/search-bug-fixes-qsearch-evasion-diag-stc.md)）。 |
| 採否の判定 | 利用者の決定により非劣性で判定する。2件はいずれも探索が返す値の誤りの修正であり、棋力に中立でも取り込む価値がある。通常の段階ゲートは+10 Eloの向上（`H1`）を要求するので、中立の修正は不採用となり不具合が残る。非劣性は、ハーネスへ比較のスイッチを足さずに、候補と基準を入れ替えた標準のGSPRTで判定する。masterを候補、修正の最終コミットを基準にすると、修正から見た比較点は0 Eloと−10 Eloになる。判定が`H0`なら「masterが10 Elo強い」が棄却され、10 Eloを非劣性の限界とする測定を通過したとして採用する。`H1`なら不採用とする。`H0`は10 Elo未満の小さな低下までは否定しない。この入れ替えは[持ち時間の効率的な使用](time-management-efficiency.md)の非劣性の測定と同じ手続きである。 |
| 測定の単位と回数 | 修正を別々のコミットとして積み、最終コミットとmasterの1組を、短時間（STC）と長時間（LTC）で1回ずつ測る。修正はどれも正しさの修正であり、個別の効果量は採否に使わないので、1組で非劣性を示せば十分である。1組が不合格となった場合は、各コミットをその親コミットと比べる個別の測定（STC）で原因を調べるが、個別の測定は診断であり、採否を決めない。個別の測定の結果を受けて修正を外したり組み直したりする場合は、本書を改訂して利用者の承認を得てから、新しいコミット、測定名、未使用のシードで測り直す。同じ候補を別のシードで再試行することはしない。3件を積んだ最初の1組が不合格となった後、利用者の承認を得てstand-patの件を外したのは、この手続きによる組み直しである。 |
| delta pruningの判定式 | 捕獲手の成り益を、成る手なら成った後の駒価値から成る前の駒価値を引いた値、成らない手なら0と定める。成り益は負にもなり得る（強制成りで価値が下がる駒）。静止探索は、取る駒の価値と成り益の和が閾値を超える捕獲と、最後の王駒を取る捕獲だけを展開する。この値は、SEE（静的交換評価。到達升での駒の取り合いを最後まで見積もる計算）が最初の着手の利得として使う値と同じであり、成り益の計算はSEEと共有する。Stockfishのように成る手を枝刈りから一律に外す案は、成り益が小さい駒の成りまで展開して静止探索の費用を増やすので採らない。 |
| delta pruningの対象集合 | 静止探索が展開の対象とする捕獲は、現行と同じ捕獲の生成規則（獅子が経由升で取って別の空升へ進む手を除外する規則`is_excluded_lion_capture`を含む）で得られる捕獲のうち、判定式を満たすものと最後の王駒を取るものである。この集合は、delta pruningを適用した後、SEEによる枝刈りを適用する前の段階で定義する。特殊な捕獲の生成、通常の捕獲の有無の確認、置換表の手、および探索中にα（探索窓の下端）が上がった後の再判定のすべてに同じ判定式を使う。候補の生成は升単位で対象を絞っているので、成り益の上限（駒価値表から求まる、正の成り益の最大値）を足しても閾値以下の升だけを除外し、残った升への捕獲は着手ごとに判定式で判定する。成り益は上限以下なので、この絞り込みで判定式を満たす捕獲を失うことはない。 |
| null moveの件の検出範囲 | 探索ワーカーは、直近のnull moveを適用した時点の探索経路の長さを境界として保持する。null moveを適用したら、null move直後の局面の局面キーを探索経路へ積む。この局面キー自体では反復を判定しない。null moveの部分木の中では、境界以降に積んだ局面キー（null move直後の局面を含む）との一致だけを反復とし、境界より前の探索経路と対局履歴は参照しない。null moveの外では現行どおり、対局履歴と探索経路の全体を参照する。null move直後の局面を積むのは、部分木の中で双方がじっとを指してnull move直後の局面へ戻る手順が、null moveを含まない本物の反復だからである。Stockfishは反復の検出を直前のnull moveまでに限り、ElephantEyeも遡りをnull moveで止める（[反復の先行実装の調査](../research/search-repetition-prior-art.md)）。null moveが入れ子になる場合は内側のnull moveの境界を使い、部分木から戻るとき（中断による戻りを含む）に探索経路と外側の境界を元に戻す。 |

## 測定の所要時間

段階8と段階12の実績（同時対局数16）では、STC（`time=10000+100`）が1ペアあたり約9.5秒、LTC（`time=60000+200`）が約27秒であった。
真の差が0に近い場合、非劣性の判定までの期待ペア数は[棋力測定の手引き](../guides/sprt.md)の近似式で約2,600ペアである。
したがって、STCは約7時間、LTCは約20時間を見込む。
LLR（対数尤度比。GSPRTが判定に使う統計量）は、差が大きいほど速く境界に達するので、大きな差があれば測定は短く終わる。
LTCへ進む前に、STCの結果とこの見積りを利用者へ示して進め方を確認する。

## 実装フェーズ

各フェーズは、実装を委任するコーディングエージェント（codex）へ1フェーズ1タスクで委任し、テスト、`cargo clippy --all-targets`、`cargo fmt --check`の通過を確認してからコミットする。
`bench`の総ノード数は各フェーズの完了時に深さ9で測り、測定記録[search-bug-fixes-bench](../measurements/search-bug-fixes-bench.md)へ残す。

### フェーズ1　null moveをまたぐ反復の修正（完了）

設計判断の「null moveの件の検出範囲」を実装した。
null moveの直後に相手がじっとを指してnull moveの前の局面へ戻る場合は引き分けとしないこと、部分木の中で双方がじっとを指してnull move直後の局面へ戻る場合は引き分けとすること、null moveの外の反復検出が変わらないこと、および入れ子のnull moveから戻る場合と中断した場合に探索経路と境界が元に戻ることを、テストで固定した。

### フェーズ2　delta pruningの成り益の修正（完了）

設計判断の「delta pruningの判定式」と「delta pruningの対象集合」を実装した。
監査の再現局面（SFEN形式で`11k/12/6p5/12/6O5/12/12/12/12/12/12/K11 b`）を探索窓の下端αを1300、上端βを1301として静止探索するとβ以上の値が返ること、成り益が負になる強制成りの捕獲が除外されること、および対象集合が判定式から直接求めた参照の集合と一致することを、テストで固定した。

### フェーズ3　非劣性の測定

フェーズ2の完了時点のコミットを修正の最終コミットとし、監査の基準コミットと比べる。
3件を積んだ最初の組の測定と診断は、状態の節に挙げた測定記録に残してある。
2件の組の測定は、delta pruningの件とnull moveの件の診断（測定名`search-bug-fixes-delta-promotion-diag-stc`と`search-bug-fixes-null-move-diag-stc`、シード`83020000`と`83010000`）がいずれも`H1`でない場合に始める。
どちらかが`H1`なら、測定を始めずに結果を利用者へ報告する。
STCの標準コマンドに対して候補と基準を入れ替え、次のとおり実行する。

```console
data/worktrees/search-bug-fixes-runner/target/release/match_runner \
  --run-dir data/matches/search-bug-fixes-2-noninferiority-stc --seed 83200000 \
  --candidate commit:<基準コミット> --baseline commit:<最終コミット> \
  --concurrency 16 --each time=10000+100 gsprt --max-pairs 3000
```

STCが`H0`ならLTCへ進み、`H1`なら不合格とする。
上限3,000ペアに達した`pending`は、停止時点のLLRが負ならLTCへ進み、0以上なら不合格とする。
LTCは次のとおり実行し、`H0`なら採用、`H1`なら不合格とし、`pending`なら同じ実行ディレクトリを`--resume`で再開して`--max-pairs`だけを増やす。

```console
data/worktrees/search-bug-fixes-runner/target/release/match_runner \
  --run-dir data/matches/search-bug-fixes-2-noninferiority-ltc --seed 83300000 \
  --candidate commit:<基準コミット> --baseline commit:<最終コミット> \
  --concurrency 16 --each time=60000+200 gsprt
```

`match_runner`は、測定中にmasterが進んでも再開できるよう、監査の基準コミットに固定したworktreeでビルドしたものを使う。
いずれの測定も、エンジン異常、時間切れ、および拒否着手が0件であることを採用の条件に含める。
シードは既存の測定で使われていない値であり、STCとLTCは上限ペア数以上離してある。
2件の組が不合格となった場合は、採否の判定を終えて利用者へ報告する。

## 検証

- 2件の修正のそれぞれについて、フェーズの節に挙げたテストが通る。
- `cargo test`、`cargo clippy --all-targets`、`cargo fmt --check`が通る。
- 2件はいずれも探索の挙動を変えるので、`bench`の総ノード数の不変は採否の条件にしない。
- [探索部の設計書](search.md)の「静止探索」節の「王手放置が合法な中将棋では、チェスで必要な『王手中はstand-pat禁止』の特例は不要である」という文は、理由付けを改める。王手中のstand-patも他の脅威を無視するのと同じ種類の近似であることと、全合法手を読む方式が測定で約120 Elo弱かったことを、測定記録へのリンクとともに書く。この改訂は採否によらず行う。
- 採用した場合は、[探索部の設計書](search.md)の「静止探索」節のdelta pruningの記述と「探索内の終局と規則処理」節の反復の記述を修正後の挙動へ書き直す。
- null moveの件の修正を採用した場合は、[探索内の反復負け回避](search-repetition.md)の「周回の区間と攻撃側の判定」の行と検証の節にある、null moveを含む区間を引き分けとする記述を、null moveより前の局面の再現は反復として検出しないという記述へ改める。

## 完了条件

- 2件の修正がそれぞれテストで固定されている。
- 非劣性の測定記録（2件の組のSTCとLTC、および3件の組の測定と診断）が残り、採否が本書の状態の節に記録されている。
- 採用した場合は修正がmasterへ統合され、関係する設計書が修正後の挙動と一致している。不採用の場合は修正がmasterへ入っていない。

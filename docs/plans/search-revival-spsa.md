# 不採用だった探索部の改良をSPSAで調整し直す計画の設計書

## 先に読む要約

本書は、過去の段階計画で不採用となった探索部の改良を現行のmasterへ戻し、その係数をSPSAで調整し直せば棋力が上がるかを確かめる（issue #10）。
SPSA（simultaneous perturbation stochastic approximation、同時摂動確率近似）は、全係数を同時に少しずらした2つの設定を対局させて係数を勝った側へ動かす調整法であり、minaseでは[SPSAの設計書](spsa.md)が導入した。
過去の改良の係数は、チェスや将棋の先行エンジンの値を中将棋の駒価値の尺度へ置き換えたものか、固定局面集で良手を失う割合などを数えて選んだものであった。
改良はその係数のまま1回だけ自己対局で測られ、いずれも短時間条件STCで負け越した。
本書が検証するのは、「負けの原因は手法ではなく係数の値にあった」という仮説である。
そこで、元の実装が数値係数を持っていた8項目だけを戻し、既存の探索係数と新しい係数をまとめてSPSAで調整する。
8項目のうち7項目は元の実装のまま戻す。
late move pruningだけは、元の実装が捕獲手も数えてkiller手まで切っていたことを診断で確かめたので、静かな手だけを数える定義に改めて戻す（2026年10月2日の利用者の決定）。
したがって、late move pruningについては「値だけが問題だった」という仮説を純粋な形では検証しない。
各係数の範囲には改良を事実上無効にする値を含めるので、害のある項目はSPSAが係数をその値へ近づけて外せる。
調整した版は、まず現行のmasterと対局させて強いかを判定する。
次に、調整した版から8項目だけを取り除き、既存の係数は調整後の値のまま残した版と対局させ、向上が8項目によるのか既存の係数の調整し直しによるのかを切り分ける。
完了条件は、8項目の一括採用、または不採用が、測定記録とともに確定することである。

## 目的

本書は、issue #10の着想と3つの懸念に、測定の設計で答える。
着想は、過去に不採用となった探索部の改良をまとめて戻し、SPSAで係数を調整したうえでGSPRT（勝敗から強さの差を逐次判定する統計検定、[手引き](../guides/sprt.md)）で測ることである。
懸念は次の3つであった。
第1は、SPSAで既存の係数も動くので、棋力の向上が戻した改良によるのか、既存の係数の調整し直しによるのかを判別できないことである。
第2は、同じ理由で、向上がSPSAによるのか改良の導入によるのかを区別できないことである。
第3は、改良を1件ずつSPSAとGSPRTにかけるのは確実だが、計算の費用が高いことである。

第1と第2の懸念には、既存の係数を調整後の値に揃えたまま8項目の有無だけを変えた2版を比べることで答える（「効果の帰属」の節）。
第3の懸念には、8項目を1つの候補として扱い、項目ごとの寄与はSPSAが係数を無効値へ動かしたかどうかで部分的に読むことで答える（「項目ごとの扱い」の節）。

## 適用範囲

本書の用語を次のように定める。
**M**は、測定の開始時のmasterの先頭のコミットであり、評価関数のPSTに重みG23を採用した b96a931 である。
**既存の探索係数**は、Mの`src/search/alphabeta/params.rs`にある22係数のうち、時間管理の6係数を除く16係数である（LMR、futility pruning、SEE pruning、aspiration windows、null move pruning、history、correction history、およびdelta pruningの係数）。
**新しい係数**は、本書が8項目のために係数の表へ加える13係数である。
**T**は、Mに8項目を戻したコミットであり、Tを調整した値を書き込んだコミットを**T\***とする。
**T\*′**は、Mのコードに、T\*の既存の探索係数16個の値だけを書き込んだコミットである。T\*から8項目と新しい係数を取り除いた版に当たる。
**無効値**は、その値に置くと改良が1ノードも発動しない係数の値である。
**無効側の端**は、範囲の端のうち改良の発動を減らす側の端である。
STCは`time=10000+100`、LTCは`time=60000+200`の時間制御であり、どちらも[手引き](../guides/sprt.md)が定める。
GSPRTの判定`H1`は候補が有意に強いこと、`H0`は10 Eloの改善があるとは言えないことを表し、上限のペア数に達して判定が出ない場合を判定保留（`pending`）という。

本書は次の作業を行う。

- 8項目をMへ移植し、新しい係数を係数の表へ加える。
- Tの調整セッションを実行し、「効果の帰属」の節の順序でGSPRTにかける。
- 採否に応じて、探索部の設計書と[SPSAの設計書](spsa.md)の現行値を更新する。

次の項目は対象外とする。

- 元の実装が数値係数を持たなかった改良。aspiration windowsのfail-high時の減深、負の捕獲手の後回し、null moveの前提条件、PVノードでの置換表の打ち切りの停止、piece-to history、およびmalusとhistory gravityの更新式がこれに当たる。係数がなければ「値が合っていなかった」という仮説が成り立たないからである。
- 発動率などの診断だけで見送り、対局で測っていない改良。verification search、counter-move history、continuation history、置換表のクラスタ化、mate distance pruning、ProbCut、およびhistory pruningがこれに当たる。見送りの理由は係数ではなく発動率の低さや費用であり、本書の仮説の外にある。
- [探索部の不具合修正](search-bug-fixes.md)で修正候補として測った2件。これらは改良ではなく、不具合か近似かの分類を問うた測定である。
- 時間管理の6係数。現行値に固定する（「設計判断」の節）。
- Mの既存の探索係数だけを3回目に調整し直す候補。必要なら通常の段階ゲートで別に測る。

## 依存関係

係数の表、調整用ビルド、`spsa_runner`、更新則、および標準の規模は[SPSAの設計書](spsa.md)と[SPSAの手引き](../guides/spsa.md)が定め、利得の既定値は[利得の較正](spsa-gain-calibration.md)が定める。
採否の手順は[手引き](../guides/sprt.md)の段階ゲートに従う。
8項目の元の設計と測定は、[段階4](strength-stage4.md)、[段階8](strength-stage8.md)、および[段階12](strength-stage12.md)が持つ。

測定機は評価関数と探索部の他の計画と共有するので、着手の順序は利用者が決める。
探索部で次の対象に挙がっていた[反復負け回避](search-repetition.md)とは同時に実行せず、本書を先に実行する。
Mが変わると係数の最適値も動くので、本書の測定の途中でmasterの探索または評価関数が変わった場合は、変わる前のMで本書の測定を完了させる。

従う教訓は次のとおりである。
[採否測定の条件で改良が発動することを実装前に確認する](../lessons/measure-feature-activation-before-sprt.md)、[隣接する基本シードは1局ずれた同じ対局列を生む](../lessons/derive-seed-adjacent-collision.md)、[長時間の生成は生成コミットを固定したworktreeで実行する](../lessons/pin-generation-binary-to-worktree.md)、および[失う良手の割合で閾値を選ぶ規則を深さの上限のない再帰に使わない](../lessons/recall-loss-does-not-bound-recursive-pruning.md)である。

## 設計判断

| 項目 | 決定 |
|---|---|
| 戻す項目の選び方 | 元の実装が数値係数を持ち、対局の測定で不採用となった探索部の改良に限る。該当は8項目である（「戻す8項目」の節）。仮説が係数の値を問うので、係数のない改良は戻しても仮説を検証できない。 |
| 調整する係数 | 既存の探索係数16個と新しい係数13個の29個をまとめて調整する。8項目と既存の係数には相互作用があり（たとえばfutility pruningとreverse futility pruningの余裕値）、issue #10はこの相互作用を問題にしているからである。既存の係数を固定して新しい係数だけを調整する案は採らない。この案ならT\*′がMと一致して帰属の判定が段階2に含まれ、STCが1回減り、T\*′の偏りも生じないが、issue #10が問題にした相互作用を検証の外に置くからである。 |
| 効果の帰属 | T\*対T\*′で判定する。2版は既存の探索係数が同じ値で、8項目と新しい係数の有無だけが異なるので、差は8項目に帰属できる。SPSAをもう1回実行してMだけを調整した版と比べる方式は採らない。調整の偶然の当たり外れが2回のセッションで異なると、その差が8項目の差に混ざるからである。 |
| 帰属の判定の偏り | T\*の既存の係数は8項目がある状態で調整されたので、8項目を取り除いたT\*′には合わない値が残り得る。たとえば、reverse futility pruningやlate move pruningが枝刈りを担うので、futility pruningの余裕値が狭められていることがある。この偏りはT\*′を不利にし、帰属の判定を8項目に有利な向きへずらす。本書は、この判定が示すのは「調整した系から8項目を取り除くと弱くなる」ことであり、8項目を含まずに調整し直した最良の版より強いことではないと明記する。採用の可否はT\*対MのLTCが決めるので、採用した版がMより強いことはこの偏りに左右されない。 |
| 失敗を安く確定させる順序 | T\*対MのSTCを最初に行い、通過しなければ以後の測定を行わない。 |
| 一括の候補 | 8項目を1つの候補として採否を決める。SPSAの設計書と同じく、不採用のときに一部の項目や係数だけを選び直して再測定しない。項目ごとにSPSAとGSPRTを繰り返す方式は、1項目あたり約10〜40時間を要するので採らない。 |
| 無効値を範囲に含める | 各係数の範囲に、無効値または無効側の端を含める。害のある項目は、SPSAが係数を無効側へ動かして事実上取り除ける。 |
| 開始値 | 新しい係数の開始値は、元の測定で負けた値と無効側の端の中点を整数へ丸めた値とし、中点がちょうど半整数なら無効側へ丸める。開始値は係数の表の既定値としてTにコミットする。`spsa_runner apply`は、セッションの開始値が表の既定値と一致することを要求するからである。元の値から始めない理由は、元の測定で各項目を1つずつ足して約−2〜−173 Eloだった値が重なり、出発点がMから遠すぎることである。標準の規模と利得は最適値の近くから始める前提で較正されているので、遠い出発点からは範囲を渡り切れないおそれがある。無効値から始めない理由は、範囲の端では摂動が切り詰められ、片側の勾配しか得られないことである。中点から始めても、摂動の初期幅（範囲の約0.30倍）は端までの距離（範囲の0.25倍）より大きいので、最初の約7反復では無効側で摂動が切り詰められる。375反復のうちの約2%なので受け入れる。late move pruningの基数と傾きの開始値は、StockfishとYaneuraOuの式のimprovingが真の場合の値に合わせて300と100とする。このとき上限は`(300 + 100 × 残り深さ²) / 100`であり、残り深さ1、2、3で4、7、12になるので、数える静かな手のうち5手目、8手目、13手目以降を切る。改めた定義には負けた元の値がないので、中点の規則は適用せず、開始点の確認がこの開始値も守る。 |
| 摂動幅 | 新しい係数の`c_end`は、`spsa_runner`の既定である範囲の1/6と、開始値から近い方の範囲の端までの距離を摂動の初期倍率で割った値の小さい方とし、パラメーターファイルで上書きする。初期倍率は、反復1の摂動幅と`c_end`の比`N^γ`であり、N = 375、γ = 0.101で約1.82である。この規則により、反復1から摂動が範囲の端で切り詰められない。範囲の上限を発動率1%の値まで広げた係数では、範囲の1/6が開始値の近くの探索の尺度より大きくなるので、この上書きが要る。たとえば`LmpBase`は範囲が0〜8,600で既定なら`c_end`が約1,433になり、開始値300からの摂動のほとんどが下限0で切り詰められる。学習率は`c_end²`に比例するので、`c_end`を小さくした係数は1回のセッションで動ける幅も小さくなる。このため`LmpBase`と`LmpSlope`は、害があってもセッション内で無効側の端まで動くことは見込めず、無効値を範囲に含める設計の効果はこの2係数では限られる。既存の探索係数16個は、これまでの2回のセッションと同じく既定の`c_end`のままとする。 |
| 開始点の確認 | セッションの前に、開始値のTとMを固定100ペアのSTCで対局させ、Tの得点率が40%以上であることを確かめる。満たさなければ、新しい係数の開始値を、その時点の開始値と無効側の端の中点へ寄せて確かめ直す。この寄せと確認を2回繰り返しても満たさなければ、セッションを始めずに利用者へ報告する。 |
| late move pruningの定義の変更 | 元の実装（コミット2643294）を戻さず、次の3点を改める。第1に、上限と比べる数を、捕獲手も含めた手番号から、そのノードで手の選択器が返した「数える静かな手」の数に改める。数える静かな手は、置換表の手、捕獲手、成る手、およびkiller手のいずれでもない手であり、探索した手も枝刈りで展開しなかった手も数える。ある手を展開するかどうかは、その手より前に返った数える静かな手の数が上限以上かどうかで決める。第2に、killer手を枝刈りの対象から外し、数える静かな手にも含めない。killer手を数えると、展開が保証された手が他の静かな手の枠を消費するからである。第3に、深さごとに独立した3つの上限を、深さの単調な式`(基数 + 傾き × 残り深さ²) / 100`（整数の除算で小数を切り捨てる）に改め、基数と傾きの2つを係数とする。根拠は[診断](../measurements/search-revival-lmp-diag.md)である。深さ5の`bench`の残り深さ1では、late move pruningが最初に手を切るまでに探索した手は平均で捕獲手8.1手、静かな手4.5手であり、late move pruningが手を切ったノードの36%は静かな手を1手も探索していなかった。killer手はそうしたノードあたり平均0.56手が切られていた。元の上限12、23、13は深さ3が深さ2より厳しい単調でない値であり、深さ3の上限はαを上回った手50件の標本から選ばれていた。式の形は、StockfishとYaneuraOuの上限`(3 + depth²) / (2 − improving)`からimprovingの項を除いたものであり（`search.cpp`と`yaneuraou-search.cpp`の手元の版で確認）、改良の発動を深さとともに緩める。improvingの項を除くのは、improvingを別の項目として戻すので、2項目の効果を互いに独立させるためである。なお、両エンジンの手数は捕獲手と置換表の手も数え、killer手も枝刈りの対象から外さない。本書がこの点で両エンジンと異なる数え方を採るのは、チェスと本将棋より捕獲手が多い中将棋では、捕獲手を数えると上の診断のとおり静かな手の枠が捕獲手で埋まるからである。適用するノードの条件（残り深さ3以下、非PV、詰み帯でない、王駒に利きがない）は元の実装のまま残す。他の7項目も元のノードの条件のまま戻すので、束としての比較を段階4の測定と揃えるためである。深さの上限を外してStockfishと同じく全深さへ適用する変更は、後続の候補として記録する。 |
| 小さな整数の係数 | 静止探索の手数制限は整数の適用条件であり、[SPSAの設計書](spsa.md)は最初のセッションで小さな整数の適用条件を対象外とした。本書では、これを調整しなければこの項目の仮説を検証できないので対象に含める。段階12で範囲1〜16として係数の表に置かれた前例がある。late move pruningの基数と傾きは百分率で持つので、この扱いの対象ではない。 |
| 時間管理の係数 | 現行値に固定する。8項目は時間配分に関わらず、固定すれば調整する次元が増えない。 |
| 調整の規模 | 標準の3,000ペア（375反復×8ペア）、STC、同時対局数16とする。係数が29個に増えることを考えて6,000ペアへ倍にする案は採らない。[利得の較正](spsa-gain-calibration.md)の模擬比較では、現行の利得の3,000ペアが旧設定の12,000ペアに8通りの場面のすべてで劣らなかった。調整値の良し悪しは最終的にGSPRTが判定するので、規模の不足は棄却として現れ、誤った採用にはつながらない。 |
| 失敗の解釈 | T\*がMに勝てなかった場合の結論は、「本書の予算と判定の下で、この候補は採用されなかった」に限る。1回の有限のセッションは最適値への収束を保証せず、STCの棄却には10 Elo未満の小さな向上を見逃すことも含まれるからである（[段階ゲートの設計書](match-staged-gate.md)）。適切な係数なら役立つ可能性までは否定しない。また、係数を無効側へ動かしても王駒への利きの判定や表の更新などの固定費用は残るので、項目の探索上の効果が中立でも、費用だけで候補が負けることがある。この場合も結論は同じ範囲に限る。 |
| 測定規約との関係 | 本書の候補は、過去の候補とは基準のコミット、評価関数、および係数の値が異なる新しい候補であり、過去の測定の判定を読み替えない。したがって、手引きが禁じる完了済みの測定への遡及適用と、シードを変えた再試行には当たらない。過去の8項目はいずれもSTCで棄却されており、LTCの結果を見てから係数を変えた候補を同じ主張へ追加することにも当たらない。 |

## 戻す8項目

8項目の元の測定はいずれもSTCで、各項目を1つずつ当時の基準へ足して測ったものであり、LTCには進んでいない。
Elo差は元の記録のペンタノミアル度数からロジスティックの写像で換算した値であり、当時の基準は現在のMとは異なる。
段階4と段階8の測定は1回目のSPSAより前であり、評価関数も現行の重みより古い。

上限を無効側の端とする4項目（reverse futility pruning、late move pruning、razoring、静止探索の手数制限）では、各係数の範囲の上限を、深さ5の`bench`で、その項目の条件を満たしたノードのうち改良が発動したノードの割合が1%以下になる最小の値とする。
late move pruningの基数と傾きはどちらも上限を大きくする係数なので、基数の範囲の上限は傾きを開始値100に置いて測り、傾きの範囲の上限は基数を開始値300に置いて測る。
下限は、元の値から上限と反対の向きへ、元の値と上限の差と同じ幅を取った値とし、係数の定義域の下限を下回る場合は定義域の下限とする。
定義域の下限は、静止探索の手数制限では1、reverse futility pruningとrazoringの余裕値では0である。
late move pruningの基数と傾きには元の値がないので、下限を定義域の下限0とする。
したがって、元の値1の静止探索の手数制限は、範囲の下限が元の値と一致する。

## 効果の帰属

採否は次の順序で判定し、各段の結果で次に進むかを決める。
順序と判定は測定の開始前に固定し、結果を見てから変えない。

1. Tの調整セッションを実行し、T\*とT\*′を作る。
2. T\*対MのSTCを実行する。`H1`なら次へ進み、`H0`なら不採用で完了する。上限3,000ペアで判定保留となった場合は、停止時点のLLR（対数尤度比）が0以上なら次へ進み、負なら不採用で完了する。これは手引きの振分け規則と同じである。
3. T\*対T\*′のSTCを上限3,000ペアで実行する。`H1`でなければ8項目の寄与を確認できないので、不採用で完了する。段階2と異なり、判定保留はLLRの符号によらず不採用とする。段階3はLTCへ送る選別ではなく、寄与の証拠を求める判定だからである。
4. T\*対MのLTCを実行する。`H1`で、エンジン異常、時間切れ、および拒否着手が0件の場合だけT\*を採用する。判定保留の場合は、手引きのとおり同じ実行ディレクトリを再開して延長する。

段階2と段階4はT\*がMより強いかを問い、段階3はその強さが8項目によるかを問う。
段階3を段階4より前に置くのは、最も時間のかかるLTCを、寄与を確認した場合だけ実行するためである。
採用の決定は、段階ゲートの規則どおりLTCの段階4だけが下し、段階3は採用を棄却する条件としてだけ使う。
[SPSAの設計書](spsa.md)は調整前のコミットを基準とするが、本書の調整前のコミットTは8項目を「設計判断」の節の開始値で含む版であり、採否で問うのは現行のmasterより強いかどうかなので、基準をMとする。

この順序で、issue #10の第1と第2の懸念は次のように解消する。
T\*対Mだけでは、向上が8項目によるのか既存の係数の調整し直しによるのかを分けられない。
T\*′は、T\*と同じ既存の係数を持ち、8項目だけを持たないので、既存の係数の調整し直しの効果を両側で揃える。
T\*がT\*′に勝てば、調整した系から8項目を取り除くと弱くなる、すなわち8項目が寄与していると読める。
「設計判断」の節に書いた偏りのため、この判定はT\*′を既存の係数だけで調整し直した版より強いとは主張しない。

段階3で寄与を確認できなかった場合、T\*′が既存の係数の調整し直しとしてMより強い可能性は残る。
T\*′やMの3回目の調整を通常の段階ゲートで測るかどうかは、利用者が別に決める。

## 項目ごとの扱い

採用した場合、調整後の係数が厳密な無効値に達した項目はコードから取り除く。
取り除いた版がT\*と同じ探索をすることは、深さ5の`bench`の総ノード数の一致で確認する。
ただしbutterfly historyの持ち越しは、`bench`が局面ごとに履歴を消すので`bench`では確認できず、取り除いた版で連続する探索の履歴がMと同じく消えることを単体テストで確かめる。
上限を無効側の端とする項目が上限に達した場合は、取り除くと探索がわずかに変わるので、本書ではコードに残す。
その項目を取り除いてよいかは、取り除いた版がT\*に劣らないことを測る非劣性の測定で判断し、この測定は本書では行わず後続の候補として記録する。

1項目ずつ取り除いてT\*と比べる測定（leave-one-out）は本書では行わない。
8項目それぞれにSTCが要り、合計で10〜60時間を要するからである。
採用後に項目ごとの寄与を知る必要が生じた場合は、別の計画として起案する。

## 所要時間の見積り

時間は同時対局数16の測定機での見積りである。
セッションは[2回目の調整](../measurements/spsa-stage9-20260925-c5.md)の3,000ペアの実績7時間32分を、GSPRTは段階8と段階12の実績を根拠とする。
LTCの30時間は見積りの目安であり、判定保留なら延長するので上限ではない。

| 段 | 内容 | 見積り |
|---|---|---|
| 準備 | 8項目の移植、範囲の測定、開始点の確認（100ペア） | 移植を除いて約1時間 |
| 1 | Tの調整セッション | 約7.5時間 |
| 2 | T\*対MのSTC | 約1〜8時間 |
| 3 | T\*対T\*′のSTC | 約1〜8時間 |
| 4 | T\*対MのLTC | 約5〜30時間 |

段階2で終われば合計は約9.5〜16.5時間であり、段階4まで進めば約15.5〜54.5時間である。

## 実装フェーズ

### フェーズ1　移植と範囲

8項目をMへ移植し、Tを作る。
段階4と段階8の項目は係数の表の導入より前の実装なので、定数を係数の表へ置き換え、`src/search/alphabeta/`の現行の構成へ合わせる。
late move pruningは、元の実装のノードの条件を使い、「設計判断」の節の定義で実装し直す。
段階12の項目は係数の表を使う実装なので、Mとの差分だけを合わせる。
各項目の元のコミットにあった単体テストを移植し、係数を既定値から変えると探索に反映されることを係数ごとのテストで固定する。

範囲と無効値は、診断用のビルドで測る。
診断用のビルドは、8項目それぞれについて、条件を満たしたノードの数と改良が発動したノードの数を数える計数を加え、係数の既定値を書き換えた`bench`である。
`bench`は調整用オプションを受け付けない別のコマンドなので、試す値は既定値の書き換えで与える。
診断用の変更はコミットせず、これまでの段階と同じくパッチを測定記録のディレクトリへ保存する。
この診断用のビルドで、上限を無効側の端とする4項目の上限を定め、厳密な無効値を持つ項目のうち捕獲履歴、null moveの加算、およびimprovingの3項目が無効値で1回も発動しないことを確かめる。
butterfly historyの持ち越しの無効値だけは、`bench`が局面ごとに履歴を消して持ち越しを観測できないので、連続する探索の間に履歴が消えることを単体テストで確かめる。

最後に、開始値を係数の表の既定値として書き込む。
完了条件は、`cargo test`の通過と、新しい係数の範囲と開始値のコミットである。

### フェーズ2　調整

開始点の確認を行い、Tの調整セッションを実行する。
調整値を書き込んでT\*とT\*′を作る。
T\*はTのコミットから`spsa_runner apply`で作る。
T\*′は、T\*で書き込まれた既存の探索係数16個の値を、Mの係数の表へ写して作る。
`apply`は表の係数の名前がセッションと一致することを要求するので、新しい係数を持たないMへは直接使えない。
完了条件は、T\*とT\*′のコミットである。

### フェーズ3　採否

「効果の帰属」の節の段階2から段階4を順に実行する。
採用した場合は、厳密な無効値に達した項目を取り除き、探索部の各設計書と[SPSAの設計書](spsa.md)の係数の表を現行値へ改める。
完了条件は、採否の確定と現行設計の更新である。

## 検証

- 移植した8項目のそれぞれについて、係数の値が探索に反映されることを単体テストで確かめる。
- 厳密な無効値に置いた4項目が発動しないことを、診断用のビルドまたは単体テストで確かめる。
- T\*′とMの差が、既存の探索係数の既定値だけであることを`git diff`で確かめる。
- セッションの要約で、エンジン異常、時間切れ、および不正着手が0件であることを確かめる。0件でなければ原因を調べてから次の段へ進む。
- 各GSPRTの基本シードは、使用済みのシードからペア数以上離す。
- 採用時に項目を取り除いた場合は、取り除く前後で深さ5の`bench`の総ノード数が一致することを確かめる。

## 完了条件

次のいずれかが、測定記録とともに確定した時点で完了とする。

- T\*を採用する（段階4の`H1`）。
- T\*がMに勝てず不採用とする（段階2）。
- 8項目の寄与を確認できず不採用とする（段階3）。
- 開始点の確認を2回寄せても満たさず、利用者の判断で中止する。

## 保留・逸脱の記録

1. **D5-SFEN-11の「先頭`+`付き手数の拒否」は未テスト（仕様と実装の乖離）**: 実装は`fields[3].parse::<u32>()`を使い、Rustの`u32::from_str`が先頭`+`を受理するため`+1`はOk(1)になる（`"+1".parse::<u32>() == Ok(1)`を確認済み）。マトリクスは「先頭`+`付きなどの拒否」を期待する。全緑を保つためテスト化せず、実装修正（明示的な数字検査）または文書側の許容明記のどちらかで解消すべき事項として記録する。
2. **SU-2（内部密番号）**: じっと代表升の直値と第5欄の並び直値は、候補が一意に定まる局面を除き断定しない。文書補修後に直値を固定するテストを追加できる。
3. **SU-4（3升連結＋`+`の解析結果）**: 表記層が構文受理するか拒否するかは断定せず、「合法手の出力に現れない」ことだけを断定した。
4. **D5-SFEN-13の「拒否時に局面状態が変化しない」**: `parse_extended_sfen`は純関数（Resultを返すのみ）であり、可変状態が存在しないため専用の断定は不要と判断した。
5. **D5-SFEN-09の「`-`の局面と捕獲升ありの局面は同一局面と扱われない」**: 反復判定（第24条第1項c）はD3領域の挙動であり、表記層では捕獲升の往復保存（SetupPositionの一致）で代替した。
6. **D5-SFEN-10のL2導出そのもの**: 第3欄からの「麒麟由来かどうか」の導出は表記層の外（消費側）で行われるため、表記層のテストは受理条件と`+o`/`n`の出自保存（導出の一意性の前提）までを断定した。

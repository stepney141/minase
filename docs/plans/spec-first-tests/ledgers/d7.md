## 難しさの信号の契約

[秒読みつき時計の設計](../../byoyomi-time-usage.md)の「設計判断」の「難しさの信号」と「フェーズ3　段階Bの実装」、およびフェーズ3aの実装指示を根拠とする。

詰み帯の除外は実装指示に従い、比較する深さdとd−2のどちらかの絶対値が`MATE_THRESHOLD`以上なら評価値を比較しない。

| 深さ6以上、最後または直前の反復で最善手が交替、元の手へ戻る場合、さらに古い交替 | 直近2反復の交替だけが信号を真にする。 | `difficulty_signal_detects_either_recent_best_move_change` |

この契約に未確定の仕様はない。
フェーズ3aでは信号を計算するだけであり、予算と反復の開始判定は変更しない。
歩兵価値以上の比較を「超える」へ変える変異は、閾値ちょうどのテストの失敗で検出した。

## 保留・注記

- **D7-TT-07（エントリ16バイト以内）: テスト不能**。`Entry`型はtt.rs内の非公開型で、編集可能なテストモジュール（search/alphabeta/tests/）から到達できない。同内容の静的アサーション `const _: () = assert!(size_of::<Entry>() <= 16)` がプロダクション側（crates/minase/src/search/alphabeta/tt.rs）に既存であり、コンパイル時に同じ性質を担保している。テストとしての計上は保留（31/32挙動をテスト化）。
- **D7-TIME-02境界（movetime=0の拒否）: assert置かず**。マトリクスは[実装契約]として拒否を期待するが、現行実装の`SearchLimits::validate`はmovetime=0を受理する。プロダクションコードの修正は本台帳の範囲外のため、この境界はテスト化せず記録に留める（規範文書への追記候補）。
- D7-TT-01のじっと表記: マトリクスは「midは隣接空升」と記すが、本実装の正準表記は獅子指し手正準化により「midなし・to=from」である。規則レベルの意味（第12条第9項）は同じであり、テストは正準表記で検出した。
- 座標規約: マトリクスの筋段表記は`fs(筋, 段) = Square::new(12−筋, 12−段)`で内部座標へ写した（sfen表記の写像と同一）。
- D7-SRCH-01/02/04では捕獲升が敵陣にあり成・不成の2手が同値になるため、SPEC_UNCLEAR-07の方針に従い移動元・到達升だけを固定し、promoteは固定しない。

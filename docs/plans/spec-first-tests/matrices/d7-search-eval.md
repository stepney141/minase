# D7 探索と評価　挙動マトリクス

本マトリクスは領域D7（探索と評価）のspec-firstテストの期待値を定める。期待値の根拠は docs/plans/search.md（2026年8月14日の規範追記を含む版。以下「search.md」）とRULES.md第20〜23条に限り、実装コード（src/）は一切参照していない。条文・規範節に接地できない挙動には[実装契約]を付す。

## 記法と共通規約

- 座標は「筋段」で書く。筋は先手から見て右端を1、左端を12とし、段はRULES.md第5条に従い後手側最奥を一段目とする（例: 6一＝6筋1段）。
- 定数はsearch.md「置換表」節の規範値を使う: `MATE = 30000`、最大探索ply 256、詰み帯閾値 `MATE − 256 = 29744`、通常評価値は絶対値29000未満。
- スコアは手番側視点のセンチポーン（歩=100、search.md「評価関数v0」）。
- 根のplyは0とする。これは規約の明文ではなく、「格納時は根相対をノード相対へ変換（`score + ply`）」（search.md 置換表節）が根において恒等変換であることからの導出である。したがって根で発見される最後の王駒捕獲は `MATE − 0 = 30000` を返す。
- ID体系は指定形式（D7-XXX-nn）に従い、SRCH（探索本体）・LIM（SearchLimits）・TIME（時間予算）・API（探索呼び出し境界）・TT（置換表）・EVAL（評価関数）の6族を使う。
- 各局面フィクスチャで明示しない升はすべて空升とし、双方が王駒1枚以上を持つ進行中局面として構築する。規則セットは自己対局既定の標準−R0＋R1とする（search.md 測定基盤節）。

### 横断的性質（全挙動に適用）

- INV-1: `Finished`の最善手は、`SearchSnapshot`が持つ審判層確定済みルート合法手の集合に必ず含まれる（search.md 時間管理節「常に合法な`bestmove`を返す」、スレッド構成節）。
- INV-2: `depth`または`nodes`制限だけの探索は同一入力に対し完全に決定的である（search.md bench節・検証節、docs/sprt.mdの再現契約）。時間制御の探索はこの契約の対象外である。
- INV-3: スコアの帯域は排他である。詰みスコアは絶対値が`MATE − 256`以上、通常評価値は絶対値29000未満であり、29000以上29744未満の値は現れない（search.md 置換表節）。

| 前提 | 先手: 飛車3十、王将6十二。後手: 歩兵3四（不成）、飛車3一、玉将6一。3二・3三・3五〜3九は空。後手飛車3一は3四の歩兵を縦に守る。先手番 |

### D7-SRCH-09　捕獲のない葉の評価は静的評価に一致

| 項目 | 内容 |
|---|---|
| 典拠 | search.md「静止探索」節（stand-pat、捕獲手のみ展開。王手をかける静かな手と非捕獲の成りは展開しない） |
| 前提 | 先手: 王将6十二、金将6十。後手: 玉将6一、金将6三。先手番。双方の駒は、先手のどの着手の後も後手に捕獲手が存在しない距離にある |
| 操作と期待観測 | depth=1で探索する。各子局面で後手に捕獲手がないため静止探索はstand-patで終わり、根の評価はルート合法手ごとの`−evaluate(子局面)`の最大値に一致する（`evaluate`は手番側視点） |
| 境界・不正事例 | 子局面で後手に王手をかける静かな手や成りがあっても展開されない（本フィクスチャでは該当手がないため、捕獲の不在だけが決定因子） |
| 性質 | 静止探索は捕獲のない局面では評価関数と同値であり、深さ1探索の評価値は静的評価だけから導出できる |

### D7-SRCH-10　stand-patは損な捕獲より優先される下限

| 項目 | 内容 |
|---|---|
| 典拠 | search.md「静止探索」節（現局面の静的評価をfail-softの下限（stand-pat）とする。王手放置が合法な中将棋ではstand-pat禁止の特例は不要） |
| 前提 | 先手: 王将6十二、歩兵9九（不成）、飛車9十二。後手: 玉将6一、飛車9三。9四〜9八、9十・9十一は空。先手飛車9十二は9九の歩兵を縦に守る。先手番 |
| 操作と期待観測 | depth=1で探索する。先手が王将6十二→6十一のように9筋に影響しない静かな手を指した子局面では、後手の唯一の捕獲手（飛車9三→9九）は直後に先手飛車9十二→9九で取り返される損な捕獲であり、静止探索は後手側でstand-patを採る。よってその子局面の葉の値は静的評価`−evaluate(子局面)`に一致し、損な捕獲の値（歩兵得）に置き換わらない |
| 境界・不正事例 | 先手が歩兵9九→9八と進めると後手飛車の利きが先手飛車9十二まで通らず（歩兵が遮る）、やはり捕獲は損になる。どの子局面でも後手が捕獲を強制されない |
| 性質 | stand-patにより葉の値は静的評価を下回らない（fail-softの下限）。王手中の特例がないため、先手王将の位置にかかわらず同じ扱いである |

## D7-LIM　SearchLimits

### D7-LIM-01　深さ制約の受理範囲は1以上256以下

| 項目 | 内容 |
|---|---|
| 典拠 | search.md「時間管理」節（深さ制約は1以上、最大探索ply（256）以下だけを受理し、範囲外は`SearchLimits`の検証とプロトコル層の入力検査の双方で拒否） |
| 前提 | 任意の合法局面 |
| 操作と期待観測 | depth=0の`SearchLimits`構築は検証エラーで拒否される。depth=257も拒否される。depth=1とdepth=256は受理される |

### D7-LIM-02　全制約欠落のSearchLimitsの拒否　[実装契約]

| 項目 | 内容 |
|---|---|
| 典拠 | search.md「時間管理」節の制約列挙（残り時間、加算時間、秒読み、固定時間、深さ、ノード数、無期限）からの導出。無期限が明示の制約値として存在するため、全制約の欠落は「無期限の指定」ではなく指定漏れとして拒否する。明文はないため[実装契約] |

### D7-LIM-04　深さ1完了前の停止でも合法なbestmoveを返す

| 項目 | 内容 |
|---|---|
| 典拠 | search.md「時間管理」節（探索開始前にルート合法手から1手を返却用に確保する。hard limitが深さ1の完了前に到来した場合でも常に合法な`bestmove`を返す）、「スレッド構成」節（深さ1の完了前に停止した場合も確保した1手を返す） |
| 前提 | 合法手の多い局面（初期局面で可）。無期限またはnodes大の`SearchLimits`で探索を開始する |
| 操作と期待観測 | 開始直後に停止フラグを立てる。`Finished`が必ず届き、最善手はスナップショットのルート合法手集合に含まれ、停止理由は外部停止要求 |
| 境界・不正事例 | 停止フラグを探索開始前に立てておく最速ケースでも同じ保証が成り立つ。極小のhard予算（D7-TIME-01の下限1ms）でも同保証（その場合の停止理由はhardリミット） |

### D7-LIM-05　無期限は外部停止だけで停止する

## D7-TIME　時間予算

予算式（search.md「実施状況」2026年8月12日確定＋「時間管理」節）:
soft = 残り時間/50 ＋ 加算×0.7 ＋ 秒読み×0.8。
hard = min(soft×4, 残り時間/4 ＋ 秒読み×0.8)。hardは1ms以上とし、「残り時間＋秒読み−30ms」の安全上限を超えない。
以下の数値例はすべてこの式から導出した固定値であり、端数の出ない入力だけを使う（丸め規約はSPEC_UNCLEAR-02）。

### D7-TIME-01　時計からのsoft/hard予算の計算

| 項目 | 内容 |
|---|---|
| 典拠 | 上掲の予算式（search.md） |
| 前提 | 予算計算を単体で呼べること（到達手段は実装読解フェーズで確定） |
| 操作と期待観測 | (a) 残り60000ms・加算1000ms・秒読み0 → soft = 60000/50 + 1000×0.7 = **1900ms**、hard = min(1900×4, 60000/4) = min(7600, 15000) = **7600ms**（安全上限59970msに非到達）。 (b) 残り10000ms・加算0・秒読み200ms → soft = 200 + 160 = **360ms**、hard = min(1440, 2500+160) = **1440ms**。 (c) 残り0ms・加算0・秒読み100ms → soft = **80ms**、hard = min(320, 80) = 80ms、安全上限 = 0+100−30 = 70ms により **hard = 70ms**（安全上限が実際に効く例） |
| 境界・不正事例 | 残り20ms・加算0・秒読み0では、式のhard（1.6ms）・下限1ms・安全上限（−10ms）が両立しない。優先順位は明文がなく（SPEC_UNCLEAR-03）、hard ≥ 1msだけを[実装契約]としてassertする |
| 性質 | 安全上限と下限はhardにのみ規定される。(c)ではsoft(80ms) > hard(70ms)となるが、本文はsoftへの上限適用を定めないためsoftは80msのままassertする（機構上はhardが先に発火する） |

| 性質 | 固定時間は測定基盤がそのまま使う制約である（search.md 時間管理節） |

### D7-TIME-03　movetimeと時計の併用はsoft/hardごとに小さい方

| 項目 | 内容 |
|---|---|

| 境界・不正事例 | ちょうど16バイトは適合。フィールドのbitパック境界が将来のアトミック化を妨げない配置という記述は検証可能な観測がなくテスト対象外 |
| 性質 | メモリ量の規範（既定256MB）とスロット数の関係を成立させる前提条件である |

### D7-TT-08　原子型エントリの16バイト配置と詰め込みの往復

| 項目 | 内容 |
|---|---|
| 典拠 | lazy-smp.md「共有置換表」節（1エントリは`critical`と`advisory`の2個の`AtomicU64`からなる16バイトとし、検証キー、評価値、深さ、バウンド、指し手、および世代を所定の幅へ詰め込む） |
| 前提 | 検証キー、負の評価値、深さ、上界、2段階移動かつ成る指し手、および非0の世代を含む1エントリ |
| 操作と期待観測 | エントリ型のサイズが厳密に16バイトである。store後の2個の原子値から各フィールドを取り出すと入力値と一致し、probeでも評価値、深さ、バウンド、および指し手が一致する |
| 境界・不正事例 | `critical`の予約6ビットと`advisory`の予約31ビットはすべて0であり、バウンド0は有効値として生成されない |
| 性質 | 2個の原子値にまたがる助言情報を除き、各フィールドの詰め込みと復号は恒等写像になる |

### D7-TT-09　破損した原子型エントリの未命中化

| 項目 | 内容 |

| 典拠 | lazy-smp.md「共有置換表」節（検証キー、予約ビット、バウンド、および指し手の復号に失敗した場合は未命中とし、不正な`Move`を構築しない） |
| 前提 | `critical`と`advisory`へテスト用補助で生の原子値を書き込める置換表 |
| 操作と期待観測 | `critical`の予約ビットが非0、バウンドが0、検証キーが不一致、fromまたはtoが144以上、midが`0xff`以外かつ144以上の各エントリをprobeすると、panicせず`None`を返す |
| 境界・不正事例 | from、mid、toの有効上限143と、midなしを表す`0xff`は有効である。指し手以外のフィールドを有効値に保ち、各不正条件を独立に検査する |

### D7-TT-10　同一スロット集合への並行probeとstore

## SPEC_UNCLEAR登録簿（D7分）

規範文書から期待挙動を確定できず、assertを置かない（または[実装契約]として弱いassertに留める）事項を登録する。番号は本マトリクス内の参照用である。

1. **PSTの具体値**。search.mdは「成れる駒の敵陣接近、王駒の安全側待機、獅子・奔王など主力の中央性の最小限」としか定めない。方針として、PSTは「初期局面の評価0（D7-EVAL-01）」と「点対称性（D7-EVAL-04）」以外を固定しない。個別升の値・係数のテストは書かない。
2. **時間予算式の端数処理**。ミリ秒未満の丸め（切り捨て・切り上げ・四捨五入）の規約がない。数値例は端数の出ない入力に限定した。
3. **hard下限1msと安全上限の競合**。残り時間＋秒読み＜31msでは下限1msと安全上限（負値になり得る）が両立しない。適用順序の明文がなく、hard≥1msだけを[実装契約]とした（D7-TIME-01境界）。
4. **movetime時（soft=hard）の停止理由**。softとhardが同値のとき、どちらの理由を報告するかは規定されない。2値のいずれかであることをassertする（D7-TIME-04、D7-API-03）。
5. **ノード上限の確認周期**。hard limitと停止フラグの確認は4096ノード周期と記録されているが、ノード上限の確認周期と超過幅の上限は明文がない。ノード数の下限（≥指定値）だけをassertする（D7-LIM-03）。
6. **探索中のリサイズ要求の処遇**。「探索中でないときに限って適用」の対偶（拒否かjoin後の遅延適用か）が規定されない（D7-TT-06）。
7. **同値最善手のタイブレーク**。複数の候補手が同スコアのときのbestmove選択規則がない。テストのフィクスチャは最善手が厳密に一意になるよう設計する（D7-SRCH-06は例外的にスコアだけをassertする）。
8. **詰み発見時の早期停止**。指定深さ・時間の消化前に詰みを確定した場合の早期終了の有無が規定されない。時間近傍性のテストは詰みのない局面で行う（D7-TIME-04）。
9. **制約の同着・併用の細目**。複数制約の同時充足時に報告する停止理由の優先、およびinfiniteと他制約の併用の意味が規定されない。テストは単独制約に限定する（D7-LIM-05、D7-API-03）。
10. **全制約欠落のSearchLimits**。拒否が自然だが明文がない。D7-LIM-02を[実装契約]として置き、search.md時間管理節への1文追記（文書補修）を推奨する。

## 集計

仕様化した挙動は35件である（SRCH 10、LIM 5、TIME 4、API 5、TT 7、EVAL 4）。うち[実装契約]ラベルの主挙動は3件（D7-LIM-02、D7-EVAL-04、および各挙動内の弱いassert群）、SPEC_UNCLEAR登録は10件である。

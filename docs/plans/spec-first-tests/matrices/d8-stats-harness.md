## 1. GSPRT統計（D8-STAT）

### D8-STAT-01 fishtest参照値5件によるLLR計算の外部等価性

- **典拠**: [SPRT]統計的手続き節（「実装はfishtest本家で計算した参照値5件と1e-6以内で一致することを単体テストで固定している」と契約を明記）、[SEARCH]実施状況（fishtest `LLR_logistic`、statistic="expectation"のMLE法と同一アルゴリズム、LLRcalc.py事前計算値）、[SFT]引き継ぎ資産1。
- **前提**: sprt.mdの固定契約（ロジスティックElo写像、H0: elo=0、H1: elo=5）。度数はペンタノミアル、候補側ペア得点[0, 0.5, 1, 1.5, 2]の順。
- **操作と期待観測**: 次の5組の度数を与えたLLRが、各参照値と絶対誤差1e-6以内で一致する。**この5組は旧テストから引き継ぐ絶対に失えない資産であり、再取得にはfishtest本家での再計算が必要である。**

  | ペンタノミアル度数 [0, 0.5, 1, 1.5, 2] | 期待LLR |
  |---|---|
  | [10, 25, 45, 25, 10] | -0.0421241799 |
  | [30, 120, 240, 180, 30] | 1.6228091706 |
  | [0, 3, 65, 4, 2] | 0.6755509925 |
  | [50, 150, 400, 200, 60] | 1.7993290877 |
  | [141, 593, 1112, 666, 158] | 2.1466073915 |

- **境界・不正事例**: 第3組は度数0のセルを含み、fishtestと同一の正則化経路を通ることを外部値との一致で検証する（正則化の内部式は契約ではない。一致だけが契約である）。
- **性質**: 対称な度数（例: [10, 25, 45, 25, 10]に近い釣り合い）はLLRが0近傍になる。度数を左右反転（候補と基準の入替に相当）するとLLRの符号傾向が反転する（メタモルフィック関係。厳密な反対称性は仮説が非対称（elo 0対5）のため要求しない）。

### D8-STAT-02 判定境界とH1/H0/pendingの裁定

- **典拠**: [SPRT]統計的手続き節（α=β=0.05、境界`log((1-β)/α) ≈ +2.944`と`log(β/(1-α)) ≈ -2.944`、1ペアごとにLLR再計算、停止は境界交差）、[SEARCH]GSPRTと固定局数Elo節。
- **前提**: α=β=0.05固定。
- **操作と期待観測**: 上側境界定数が`ln(0.95/0.05) = ln 19 = 2.9444…`、下側境界定数が`ln(0.05/0.95) = -ln 19`と一致する（式からの導出値と照合し、実装定数を写さない）。LLRが上側境界以上に達したら`decision: H1`（候補が有意に強い、採用）、下側境界以下に達したら`decision: H0`（elo=5の改善があるとは言えない、不採用）で停止する。
- **境界・不正事例**: LLRがちょうど境界値に達した場合の比較演算（`>=`か`>`か）は文書に明文がない → SPEC_UNCLEAR-01。境界内に留まる限り継続し、ペア数上限で`decision: pending`（判定保留）となる（D8-STAT-06）。
- **性質**: 判定は3値（H1/H0/pending）で網羅的・排他的である。1ペア取り込むごとのLLR再計算により、停止ペア番号は入力列だけから一意に決まる。

### D8-STAT-03 Eloのロジスティック写像

- **典拠**: [SPRT]統計的手続き節（`s = 1/(1+10^(-elo/400))`、H0はelo=0、H1はelo=5）。
- **前提**: なし（純関数）。
- **操作と期待観測**: elo=0で期待スコアs=0.5、elo=5で`s = 1/(1+10^(-1/80)) ≈ 0.507190`となる（式から独立に導出した値と照合）。
- **境界・不正事例**: elo=±400でs=1/(1+10^∓1)（0.909…と0.0909…）。
- **性質**: sはeloについて狭義単調増加、値域(0,1)、`s(-x) = 1 - s(x)`の点対称。

### D8-STAT-04 観測単位はペア（ペンタノミアル）

- **典拠**: [SPRT]統計的手続き節（同一開始局面・先後入替の2局間に相関があるため、局単位ではなく候補側ペア得点合計の5分類度数でLLRを計算する）、[SEARCH]GSPRTと固定局数Elo節（トリノミアルでは分散を過小評価し偽陽性率が名目より悪化する）。
- **前提**: ペア対局（D8-HARN-02）の結果集計。
- **操作と期待観測**: 統計層への入力はペア得点合計{0, 0.5, 1, 1.5, 2}の5分類度数であり、局単位の勝敗3分類ではない。候補が2局とも勝てば度数[.., .., .., .., +1]、1勝1敗なら得点1.0のセルへ+1、といった対応で集計される。
- **境界・不正事例**: 反則負け（D8-HARN-06）の局は当該局の敗北としてペア得点へ算入される。候補側がペア両局とも反則負けならペア得点0（相手のペア得点2相当）のセルへ入る（[SFT]引き継ぎ資産6「反則負けの統計契約」）。破棄ペア（D8-HARN-07）は度数へ一切入らない。
- **性質**: 度数の総和は有効ペア数（破棄を除く）に等しい（保存則）。

### D8-STAT-05 モンテカルロによる検定の健全性

- **典拠**: [SEARCH]GSPRTと固定局数Elo節（既知の分布から5分類の結果を生成して検定全体を反復し、elo=0のとき誤採用率が名目αと整合、elo=5のとき検出率が1−βと整合することを確認する）、[SEARCH]実施状況フェーズ1（elo=0とelo=5を各3,000反復、H1誤採用率8%以下と検出率90%以上の条件に合格）、[SFT]引き継ぎ資産5（決定的シード群）。
- **前提**: 合成したペンタノミアル結果の生成器と固定シード。実対局は使わない。
- **操作と期待観測**: 固定シードで決定的に、真のelo=0の分布から生成した反復でH1誤採用率が8%以下（名目α=0.05と整合する裕度つき閾値）、真のelo=5の分布から生成した反復で検出率が90%以上（名目1−β=0.95と整合する裕度つき閾値）となる。閾値と反復数3,000は[SEARCH]実施状況の確定記録に接地する。
- **境界・不正事例**: シードを固定しない実行は決定性契約を満たさないため、テストでは必ず固定する。
- **性質**: 同一シードで結果（合格率の数値まで）が完全再現される。

### D8-STAT-06 ペア数上限とpending

- **典拠**: [SPRT]統計的手続き節（ペア数上限`--max-pairs`、既定100,000はfishtestと同様の暴走保険であり、到達時は判定保留として報告する）、[SEARCH]GSPRTと固定局数Elo節（起案時上限1000は不足と指摘され100,000へ改めた確定記録）。
- **前提**: LLRが境界に達しないままペアを消化する系列。
- **操作と期待観測**: 上限ペア数に達しても境界を交差しない場合、`decision: pending`として報告し、H1/H0のいずれも宣言しない。
- **境界・不正事例**: [SPRT]機能採否のSPRT節には「上限ペア数（既定1000）」という記述が残るが、これは統計的手続き節および[SEARCH]の改定記録（100,000）と矛盾する旧文言である。本マトリクスは100,000を規範とし、文書補修対象としてSPEC_UNCLEAR-02へ登録する。
- **性質**: pendingは「判定保留」であり敗北・採用のいずれでもない（運用上は水準を変えた再測定か変更見直しへ戻る）。

### D8-STAT-07 固定局数Eloモードの点推定と信頼区間

- **典拠**: [SPRT]統計的手続き節（正規化ペア得点の平均と分散からEloの点推定と95%信頼区間を計算する。観測単位はペア、分散はペンタノミアル度数から推定する）、[SEARCH]GSPRTと固定局数Elo節。
- **前提**: ペンタノミアル度数（固定ペア数`--pairs`の消化後）。
- **操作と期待観測**: ペンタノミアル度数を入力とし、ロジスティックEloの点推定と95%信頼区間を返す。平均正規化ペア得点が0.5（例: 完全対称な度数[a, b, c, b, a]）ならElo点推定は0となり、信頼区間は0を含む。
- **境界・不正事例**: 全勝・全敗の標本ではロジスティックEloの点推定が無限大になる（[SPRT]進捗記録の固定局数Elo節が明記）。その場合の運用は「勝率と局数をそのまま記録し、必要ならrule of threeによる1局あたり期待スコアの95%下限を併記する」であり、これは記録者向け手順である。**ツール出力がこのとき何を表示するか（±∞表記か、推定不能の明示か）は文書が定めない** → SPEC_UNCLEAR-03。分散0（全ペアが同一得点）の信頼区間の扱いも同様に未規定である。
- **性質**: 度数を左右反転（候補と基準の入替）するとElo点推定の符号が反転する（ロジスティック写像の点対称、D8-STAT-03の性質から従う）。信頼区間は点推定を含む。ペア数を増やした同一分布のスケーリング（度数を定数倍）で点推定は不変、信頼区間は狭くなる（単調性）。信頼区間の構成法の細部（正規近似の式形）は文書にない → SPEC_UNCLEAR-04。

### D8-STAT-08 LLR取り込み順序の決定性

- **典拠**: [SPRT]ペア対局と再現性節（`--concurrency N`でもLLRへの取り込みと出力はペア番号順に整列されるため、判定は並列度に依存しない）、[HARN]並列実行と決定性節。
- **前提**: 同一シード・同一引数。
- **操作と期待観測**: LLRの再計算はペア完了順ではなくペア番号順に行われ、停止ペア番号・判定・度数が並列度1とNで一致する（ハーネス側の観測はD8-HARN-05）。
- **性質**: 統計層の判定は「ペア結果の列」だけの関数であり、実行スケジュールの影響を受けない。

## 2. 対局ハーネス match_runner（D8-HARN）

### D8-HARN-01 エンジンspecの4形式

- **典拠**: [SPRT]エンジンの指定方法節、[HARN]エンジン指定と解決節・実施状況フェーズ3。
- **前提**: `--candidate <spec>`と`--baseline <spec>`。
- **操作と期待観測**:
  - `commit:<hash>`: rev-parseで正規化し、git worktreeで当該コミットを展開して`cargo build --release --bin minase`を実行し、完全ハッシュをキーに`target/match-cache/`へキャッシュする。キャッシュ命中時はビルドを省略し、worktreeはビルド後に破棄する。起動引数`--protocol usi --rules <マッチ規則>`が自動付与される。
  - 起動コマンド形式: パス＋空白区切り引数として解釈し、2語目以降を起動引数として渡す（例 `"target/release/minase --protocol usi --rules engine-default"`）。minase本体は`--protocol`と`--rules`が必須である。
  - `random`: 予約specであり、同一ビルドの`usi_random`（合法手から一様ランダムに着手する校正用エンジン）を起動する。真のelo差0が既知の唯一の対戦カードで、ハーネス自体の煙試験に使う。
  - `cecp:<起動コマンド>`: CECPで対局するエンジンを起動する。パス形式と同じく2語目以降を起動引数として渡す。規則はエンジン側の設定に委ねられ、`--rules`にはそのエンジンが実装する規則を指定する（[SPRT]エンジンの指定方法節、[HARN]エンジン指定と解決節。2026年8月24日追加）。
- **境界・不正事例**: `cecp:`に起動コマンドがない指定は拒否される。CECPエンジンに`nodes`、秒読み、または秒未満の持ち時間・加算を含む思考制限を与える指定は解決時に拒否される（[SPRT]同節、[HARN]CECPセッション管理節）。存在しないコミットハッシュの解決失敗、worktree内ビルド失敗時の挙動は文書が定めない → SPEC_UNCLEAR-05 [実装契約]。
- **性質**: `commit:`の短縮ハッシュと完全ハッシュは同一コミットなら同一キャッシュエントリへ解決される（rev-parse正規化の帰結）。

### D8-HARN-02 ペア対局と開始局面生成

- **典拠**: [SPRT]ペア対局と再現性節（ペア番号ごとに決定的に派生したシードで初期局面から8〜12手（一様選択）をランダムに進めて作る。同一開始局面で先後を入れ替えて2局対戦し、手番差のバイアスを除去する）、[SEARCH]自己対局ハーネス節（生成中に終局した場合は次のシードで再生成する。プレイヤー用の乱数ストリームは開始局面用と分離する）。
- **前提**: 対局開始。
- **操作と期待観測**: 各ペアの2局は同一の開始局面を使い、候補と基準の先後だけが入れ替わる。開始局面は初期局面から8〜12手（この範囲から一様選択）だけランダムに進めた局面である。生成途中で終局した場合は破棄して次のシードで再生成する。
- **境界・不正事例**: 進める手数が8未満・13以上になることはない。開始局面生成の乱数消費がプレイヤー側の乱数列へ影響しない（ストリーム分離）。
- **性質**: ペア内2局の開始局面SFENは同一。ペアシードはペア番号から独立に派生するため、あるペアの結果は他のペアの実行有無に依存しない（[HARN]並列実行と決定性節）。

### D8-HARN-03 シード派生の決定性

- **典拠**: [SEARCH]自己対局ハーネス節（ペア番号ごとにシードを1回派生し、random_playと同型のsplitmix64合成を使う）、[RP]シード派生節（splitmix64の標準定数による有限混合の完全な式、派生値0の非ゼロ定数`0x9E37_79B9_7F4A_7C15`への置換）、[SFT]引き継ぎ資産5。
- **前提**: `--seed`指定。
- **操作と期待観測**: ペアシードは基本シードとペア番号のsplitmix64合成で決定的に派生する。splitmix64自体の式は[RP]が仕様として固定している（`z = x + 0x9E37_79B9_7F4A_7C15`、`z = (z ^ (z >> 30)) * 0xBF58_476D_1CE4_E5B9`、`z = (z ^ (z >> 27)) * 0x94D0_49BB_1331_11EB`、`z ^ (z >> 31)`、すべてラッピング演算）。
- **境界・不正事例**: 派生値が0になる入力ではXorShift64のシード0禁止と両立させるため非ゼロ定数へ置換する（[RP]）。
- **性質**: 同一（基本シード、ペア番号）は常に同一ペアシードを与える。**注意**: match_runnerにおけるペア番号の起算（[RP]のrandom_playは1起算と明文）と、開始局面用・プレイヤー用・局用の各ストリームの派生合成の厳密式は文書が「random_playと同型」としか定めない → SPEC_UNCLEAR-06 [実装契約]。テストで固定するのは「同一入力同一派生」と「ペア間独立」の性質、および1起算の類推適用までとする。

### D8-HARN-04 完全再現契約

- **典拠**: [SPRT]ペア対局と再現性節（同じ`--seed`と引数を与えれば、出力（経過時間の行を除く）・ペンタノミアル度数・LLR・判定・停止ペア番号は完全に再現される。この契約は`depth`または`nodes`制限の対局に限る。シード省略時は時刻から生成される。記録に残す測定では`--seed`を明示し、出力先頭の`seed:`行とともに保存する）。
- **前提**: `--each depth=N`または`--each nodes=M`の対局。
- **操作と期待観測**: 同一`--seed`・同一引数の2回実行で、経過時間の行を除く全出力が一致する。特にペンタノミアル度数、LLR、判定、停止ペア番号が一致する。出力の先頭側に`seed:`行があり、使用シード（省略時は時刻由来の生成値）が必ず表示される。
- **境界・不正事例**: 時間制御対局（`time=`）は着手時間の実測に依存するため再現契約の対象外である。その場合は最終サマリの`time_forfeits`を必ず記録する（D8-HARN-10）。
- **性質**: 再現性は引数全体（`--rules`、思考制限、`--max-ply`を含む）に条件付けられる。エンジンプロセスは局ごとに起動し直すため、内部状態（将来の置換表を含む）の局間持ち越しはない（[SPRT]。[HARN]USIセッション管理節には「ペアごとに起動し直し」の文言があるが、直後に「ペア内2局の間で内部状態を持ち越さない」と定めており、観測可能な契約は局間の状態非持ち越しで一致する。文言差はSPEC_UNCLEAR-07で文書補修候補とする）。

### D8-HARN-05 並列度非依存

- **典拠**: [SPRT]ペア対局と再現性節、[HARN]並列実行と決定性節・実施状況フェーズ3（並列度1と4の出力一致を統合テストで固定）。
- **前提**: 同一シード・同一引数、`--concurrency 1`対`--concurrency N`。
- **操作と期待観測**: 経過時間の行を除く全出力（局結果行の順序を含む）が並列度によらず一致する。LLR取り込みと出力はペア番号順に整列される。
- **性質**: fishtestの「対局実行とLLR判定の分離」の単機再現であり、判定はスケジュール非依存（D8-STAT-08と表裏）。

### D8-HARN-06 異常時裁定（反則負け）

- **典拠**: [SPRT]異常時の裁定節、[HARN]異常時裁定節（fastchessと同方式）。
- **前提**: 対局中のエンジン異常。
- **操作と期待観測**: 次の3事象は、いずれも起こしたエンジンの当該局の反則負けとして統計（ペンタノミアル）へ算入され、終局理由が局結果の行と最終サマリに記録される。
  1. 不正着手: `bestmove`の着手が審判層の合法手リストにない（IllegalMove相当）。
  2. クラッシュ: エンジンプロセスの異常終了・パイプ切断（Crash相当）。
  3. 応答タイムアウト: `--response-timeout`（既定120秒）超過（Timeout相当）。
  4. 着手拒否: CECPエンジンが、審判層の合法手として転送された相手の着手を`Illegal move`で拒否した（RejectedMove相当。[HARN]異常時裁定節、2026年8月24日追加）。
- **境界・不正事例**: CECPエンジンが着手を返さずに結果行だけを出した場合は投了であり、当該局の負けに算入されるが`engine_failures:`には数えない（[HARN]CECPセッション管理節）。反則負けはペア破棄ではない（当該局の敗北として算入。D8-STAT-04参照）。「バグで落ちるエンジンは弱いエンジンとして測る」というfastchess・fishtestと同じ思想である。
- **性質**: 最終サマリの`engine_failures:`行に理由別件数が出る。測定採用前の確認対象であり、異常0件の対局群では全理由の件数が0になる。

### D8-HARN-17 random_playのシード派生式（仕様として固定）

- **典拠**: [RP]シード派生節（再現性を実装の細部でなく仕様として固定するための明文式）。
- **前提**: 基本シード`base_seed`、局番号`n`（1起算。表示・`--game`指定とも同じ値）。
- **操作と期待観測**: 各局の乱数状態は`splitmix64(base_seed.wrapping_add(n))`。splitmix64は標準定数による有限混合: `z = x + 0x9E37_79B9_7F4A_7C15`、`z = (z ^ (z >> 30)) * 0xBF58_476D_1CE4_E5B9`、`z = (z ^ (z >> 27)) * 0x94D0_49BB_1331_11EB`、`z ^ (z >> 31)`（加算・乗算はすべてラッピング演算）。派生値が0になる場合は固定の非ゼロ定数`0x9E37_79B9_7F4A_7C15`へ置き換える。
- **境界・不正事例**: 派生値0の置換はXorShift64のシード0禁止との両立のためであり、置換定数も仕様の一部である。
- **性質**: 同一の`--rules`（および既定値以外を使った場合は同一の`--max-ply`）の下で、`--seed X --game N`により当該局の着手列が完全に再現される。規則セットは合法手集合と終局を変えるため、シードと局番号だけでは再現は完結しない。

### D8-HARN-18 random_playの毎手不変条件と終局後検査

- **典拠**: [RP]対局ループと検証節。
- **前提**: 1局の進行。
- **操作と期待観測**: 毎手、(1) `legal_moves()`が返した着手を`play()`が拒否しないこと（拒否は即座に異常）、(2) 着手後の局面が`Position::validate()`を通過することを検査する。`--verify-all`指定時は全合法手をそれぞれ複製したGameへ適用し、すべて受理されることを確認する。終局後は`legal_moves()`が空を返し、追加の`play()`が`GameError::GameAlreadyOver`を返すことを確認する。
- **境界・不正事例**: 終局（`GameStatus::Finished`）または手数上限で局を抜ける。上限到達は異常ではなく打ち切り。
- **性質**: 合法手生成と審判層の全経路整合性の実行時検査装置である（単局観察は`--verbose`が兼ねる）。

### D8-HARN-19 random_playの異常時ダンプと正常時集計

- **典拠**: [RP]異常時の出力節・正常時の出力節。
- **前提**: 異常検出または全局完了。
- **操作と期待観測**: 異常時は、採用規則、基本シード、局番号、手数、問題の着手、直前局面のSFEN、開始からの全手順を標準エラー出力へダンプし、非ゼロの終了コードで終了する。着手表記はperftの`move_text`と同じ形式である（両ツールの出力の突き合わせ可能性が契約）。正常時は1局ごとに局番号・手数・結果と終局理由を1行で出力し、全局終了後に勝敗と終局理由別局数、手数の最小・最大・平均、打ち切り局数、所要時間を集計出力する。
- **境界・不正事例**: 集計行の正確な書式は文書が定めない → SPEC_UNCLEAR-12 [実装契約]。
- **性質**: 異常局はダンプ中の`--seed`と`--game`だけから単独再実行できる（[RP]完了条件）。

## 4. 校正エンジン usi_random（D8-RAND）

### D8-RAND-01 一様ランダム着手とシード注入

- **典拠**: [HARN]ランダムUSIエンジン節（`position`と`go`を受けて合法手から一様ランダムに1手を`bestmove`で返す。乱数は`setoption name Seed value <u64>`で注入し、ハーネスが局ごとに決定的に派生したシードを設定する。規則セットは既存の`setoption name RuleSet value ...`を使う）、[SPRT]エンジンの指定方法節。
- **前提**: USIセッション初期化済み、Seed設定済み。
- **操作と期待観測**: `position`＋`go`に対し、現局面の合法手から選んだ1手を`bestmove`で返す。返る手は常に審判層の合法手集合に含まれる。
- **境界・不正事例**: 合法手が1つの局面では常にその手を返す。
- **性質**: elo=0が既知の唯一の校正カード（random対random）の構成要素であり、ハーネス煙試験の前提である。選択の一様性は分布としての性質（多数試行でのカイ二乗検定級）であり、決定性テストとは分離する。

### D8-RAND-02 同一シード同一bestmove列の決定性

- **典拠**: [HARN]検証節（ランダムUSIエンジンのシード再現性（同一シードで同一着手列）をテストする）、[SFT]引き継ぎ資産5（決定的シード群と`usi_random`のシード42導出）。
- **前提**: 同一のSeed値・RuleSet・position列。
- **操作と期待観測**: 同一シードを注入した2セッションが、同一のposition/go列に対して同一のbestmove列を返す。異なるシードは（一般に）異なる着手列を与える。
- **境界・不正事例**: 引き継ぎ資産の「シード42導出」の具体値は旧テスト由来であり、導出式の細目は文書にない。テストで固定する場合は[実装契約]と明示する → SPEC_UNCLEAR-13。
- **性質**: 決定性はD8-HARN-04の完全再現契約の必要条件である。

### D8-RAND-03 シード0の拒否

- **典拠**: [RP]乱数モジュールの分離節（XorShift64のシード0の禁止は現行どおりassertで保つ）、[RP]シード派生節（派生値0の非ゼロ置換はシード0禁止との両立のため）。
- **前提**: `setoption name Seed value 0`。
- **操作と期待観測**: シード0はXorShift64の不正状態（全ビット0で乱数列が退化する）であり、有効なシードとして受理されない。
- **境界・不正事例**: 拒否の具体的応答（エラー応答か、assertか、無視か）は文書が定めない → SPEC_UNCLEAR-14 [実装契約]。拒否されるという事実だけを本マトリクスの契約とする。
- **性質**: ハーネス側の派生（D8-HARN-03、D8-HARN-17）は0を生成しないため、正常経路でこの境界へ到達しない（防御的契約）。

### D8-RAND-04 本体USIと同じエラー契約 [実装契約]

- **典拠**: [HARN]同期版go節は本体minaseについて「`go`に両引数がない場合と未対応引数が付く場合は、既存の契約に合わせて`info string error: ...`を返し`bestmove`を送出しない」と定める。usi_randomが同一のエラー契約に従うことは、USIプロトコル層の規範文書（領域D6の所有）とusi_randomが本体と同じUSI実装基盤を共有する設計意図からの類推であり、D8の規範文書に明文はない。
- **前提**: 不正なUSI入力。
- **操作と期待観測**: 不正入力に対する応答形（エラーの通知方法、`bestmove`の非送出）が本体minaseのUSI実装と同一である。
- **境界・不正事例**: エラー文言そのものは契約ではない（実装固有文字列への一致assertは書かない）。
- **性質**: テスト化する場合は「本体との差分がないこと」の等価性テストとし、[実装契約]であることをテスト名またはコメントで明示する。

## 5. bench（D8-BENCH）

### D8-BENCH-01 固定局面集の合法性

- **典拠**: [SEARCH]bench節（固定局面集は初期局面とlishogiリプレイ棋譜から抽出した中盤・終盤局面10〜20局面）、[SEARCH]実施状況フェーズ2（lishogiリプレイ7局から抽出した14局面と初期局面の計15局面で確定）。
- **前提**: benchバイナリの埋め込み局面。
- **操作と期待観測**: 埋め込まれた全局面が、パース可能かつ局面検証を通過する合法な対局局面である（実対局の棋譜由来という出自の帰結として、到達可能な実戦局面の性質を持つ）。局面数は15（初期局面1＋抽出14）。
- **境界・不正事例**: 局面の追加・変更はbenchの決定性アンカー（D8-BENCH-02）を変えるため、設計書の改定を伴う。
- **性質**: 各局面は独立に検証可能（1局面の破損が他を隠さない）。

### D8-BENCH-02 総ノード数の決定性（数値は固定しない）

- **典拠**: [SEARCH]検証節（benchの総ノード数の決定性を、探索へ意図しない挙動変化が入っていないことの確認に使う）、[SEARCH]bench節（総ノード数は探索の決定性チェックを兼ねる）、[HARN]（fishtestのbench署名検証に相当する仕組みとして総ノード数照合が担う）。
- **前提**: 同一ビルド・同一深さ。
- **操作と期待観測**: benchを2回実行した総ノード数が完全に一致する。決定性の担保は探索側の「同一入力同一結果」契約（領域D7）によるものであり、benchはその観測点である。
- **境界・不正事例**: **特定の総ノード数（241,231、217,305、1,708,418、2,574,220など設計書の実施状況に現れる値）は各時点の測定記録であって、テストで固定してはならない。** 探索の正当な改良（置換表・静止探索等）で値は変わることが設計上予定されており（実施状況に削減率として記録されている）、数値固定は仕様でなく実装の写しになる。テストが固定するのは「再実行間の一致」だけである。
- **性質**: 決定性は凍結ベースライン照合（コミット0045833のbench一致で凍結を確認した[HARN]実施状況）の前提であり、コミット間の値比較は人間の測定手順に属する。

### D8-BENCH-03 出力項目（総ノード数とNPS）

- **典拠**: [SEARCH]bench節（固定深さで探索し、総ノード数とNPSを表示する。NPSはmimalloc採否とVec割当改善の実測値になる）、[SEARCH]実施状況フェーズ3（NPSは各局面の探索時間の合計から計算し、置換表確保を計測区間外に置く決定）。
- **前提**: bench実行完了。
- **操作と期待観測**: 出力に総ノード数とNPSが含まれる。NPSは各局面の探索時間の合計に基づく（計測区間に局面ごとの資源確保を含めない設計決定）。
- **境界・不正事例**: NPSの値自体は環境依存の実測値であり、いかなる数値もテストで固定しない。出力の正確な書式は文書が定めない → SPEC_UNCLEAR-15 [実装契約]。
- **性質**: 総ノード数は決定的（D8-BENCH-02）、NPSは非決定的、という2項目の性質差が出力契約の核である。

# SPSAの摂動幅と学習率の較正の設計書

## 先に読む要約

本マイルストーンは、SPSA（同時摂動確率近似、[spsa.md](spsa.md)）の摂動幅と学習率の設定を見直し、同じ棋力の改善を少ない対局数で得られるようにする。
SPSAは、全係数を正負へ少しずらした2つの設定θ+とθ−を対局させ、勝った側の向きへ係数の中心値θを動かす操作を繰り返す。
θ+とθ−のずらし幅を**摂動幅**、1回の勝敗でθを動かす量の係数を**学習率**と呼び、反復ごとの両者の系列をまとめて**利得**と呼ぶ。
最初のセッションの記録では、1反復16局の勝敗差の揺れ（標準偏差3.64）が、有意に検出できた係数の信号（0.21〜0.57）の6倍から17倍あり、多くの係数では信号が揺れに埋もれて検出できなかった。そのため、どの更新則に替えても対局数の削減は定数倍にとどまることが[調査](../research/spsa-acceleration-methods.md)で分かった。
同じ調査は、改善の余地がアルゴリズムの交換ではなく摂動幅と学習率の較正にあると結論した。特に、目的関数を2次関数とみなす連続時間の近似では、摂動幅を広げても最適値の周りに残る揺れは変わらず、最適値へ近づく速さが摂動幅の2乗に比例して上がる。
ただし、広い摂動幅は、目的関数が2次関数から外れる場合や係数が範囲の端にある場合に偏りを生む。
そこで本書は、実測の勝敗の揺れに合わせた模擬実験で、現行の設定と摂動幅を広げた設定を同じ対局数の予算で比べ、事前に固定した規則で新しい既定値と次のセッションの規模を選ぶ。
選んだ設定で実際のセッションを1回実行し、その結果の値を既存の採否の手順（STCとLTCのGSPRT）で判定する。
完了条件は、模擬実験の記録が残り、選定規則が選んだ設定が `spsa_runner` の既定値としてmasterへ入り、その設定による実セッションの値の採否がSTCでの棄却かLTCの判定で確定することである。

## 目的

最初のSPSAセッションは、1,500反復×8ペア（12,000ペア）に約30時間を要した。
その記録（実行ディレクトリ`data/spsa/stage9-20260923`の全1,500反復）から計算すると、1反復のD（θ+側の勝ち数から負け数を引いた値）の標本分散は13.28、標準偏差は3.64だった。
係数iを摂動した向き（θ+側で係数iを増やしたなら+1、減らしたなら−1）を`flip_i`とすると、`D·flip_i`の平均は係数iを増やす向きの有利さを表す。
以下、この平均`mean(D·flip_i)`を係数iの**信号**と呼ぶ。
信号は、NullMoveBaseの+0.574を除いて絶対値0.24以下だった。
信号対雑音比が0.05の係数では、勾配の符号を2標準誤差で見分けるだけで約1,600反復を要する。
この量は同じ対局データから引き出せる情報で決まり、更新則を替えても桁では減らない。
[文献調査](../research/spsa-acceleration-methods.md)も、雑音の支配する条件でSPSAより定数倍を超えて速い方法を示した一次資料はないと結論した。

一方、現行の設定は、雑音の大きさに合わせて選んだものではない。
摂動幅の終了値`c_end`（範囲の1/20）、学習率の終了値`r_end`（0.002）、および減衰の指数（α = 0.602、γ = 0.101）は、fishtestとOpenBenchの既定値をそのまま使っている。
fishtestの理論文書は、Elo曲面を2次関数とみなし、定数の利得での更新を連続時間で近似している。この近似では、θが最適値の周りに定常的に残す揺れによる損失は`r`だけで決まり、最適値へ近づく時定数は`r·c²`に反比例する。有限の予算で終えたときの損失は、この定常損失と、近づき切れなかった分の和になる。
fishtest自身も、このモデルからハイパーパラメーターを決めるAutoselectでは、摂動幅を範囲の1/6とし、利得を一定にしている。
このモデルに従えば、摂動幅を範囲の1/20から1/6へ広げると、同じ対局数で最適値へ近づく割合が大きく上がる。
しかし、この見込みは2次関数の近似と範囲の端での切り詰めがないことに依存しており、minaseの係数でそのまま成り立つかは分からない。
本書の目的は、この見込みを実対局の前に模擬実験で確かめ、成り立つ範囲で既定値を改めることである。

## 適用範囲

本マイルストーンでは、次の作業を行う。

- `spsa_runner` のテストに、実測の勝敗の揺れに合わせた模擬実験を追加する。模擬実験は既存の更新ループ`runner::run`へ合成の対局結果を渡すので、実際の更新則の実装をそのまま検査する。
- 模擬実験の結果を測定記録に残し、事前に固定した規則で新しい既定値と次のセッションの規模を選ぶ。
- 選ばれた設定を `spsa_runner` の既定値（減衰の指数と、`params` サブコマンドが生成する`c_end`と`r_end`）に反映し、[spsa.md](spsa.md) の更新則の節と[手引き](../guides/spsa.md)を改める。
- 選ばれた設定で実セッションを1回実行し、その値を標準の段階ゲートで判定する。

次の項目は対象外とする。

- 2SPSA、Adam、モーメンタム、1測定SPSA、ブロッキング、およびベイズ最適化への更新則の交換。[調査](../research/spsa-acceleration-methods.md#候補の比較)が、minaseの雑音の水準では効果の根拠がないか、対局予算を大きく超えると結論した。
- 信号のない係数を外す選別。同じセッションの結果で係数を選ぶと選択の偏りが入り、模擬実験の較正にもその結果を使うので、模擬実験では効果を正しく評価できない。選別は、本書の設定で実セッションを終えた後に別途検討する。
- CLOPのような全対局への回帰による推定。22係数の2次模型は係数が276個あり、[調査](../research/spsa-acceleration-methods.md#clop)が現在の予算では割り当てが足りないと結論した。
- 時間制御の変更。調整は引き続きSTCで行う。

| 選定規則 | 本実験の後に次の3段階で機械的に決め、結果を見てから規則を変えない。構成は候補、予算、および最終値の取り方（終了時のθか後半の平均）の組であり、基準構成はC0、12,000ペア、終了時のθ（以下、**現行構成**）とする。第1段階では、12,000ペアと終了時のθで現行構成に劣らない候補を**適格**とし、適格な候補のうち、8通りの場面での現行構成に対する平均損失の比の幾何平均が最小のものを選ぶ。場面ごとに損失の大きさが1桁以上違うので、差の和では損失の大きい場面だけで順位が決まる。比の幾何平均は、各場面での改善の割合を同じ重みで扱う。C0は定義により適格である。幾何平均が等しい場合は候補の番号の小さいほうを選ぶ。第2段階では、選んだ候補について、予算を3,000、6,000、12,000ペアの順に、最終値の2通りの取り方のそれぞれが現行構成に劣らないかを調べ、劣らない取り方が最初に現れた予算を採る。第1段階の定義により、12,000ペアの終了時のθは必ず劣らない。第3段階では、採った予算で2通りの取り方がともに劣らなければ、幾何平均の小さいほうを採り、等しければ終了時のθを採る。こうして最終的に採る構成は、必ず8通りの場面すべてで現行構成に劣らない。損失の平均が0になる場面は生じない（θは実数値で、雑音によって必ず最適値から離れる）が、生じた場合はその場面の比を1とする。 |
| 選定結果の反映 | 選ばれた候補がC0でも、予算か最終値の取り方が変われば、フェーズ2でそれを既定の手順と実装に反映する。3つとも現行のままならフェーズ2を省く。後半の平均を採る場合は、`spsa_runner`の終了時の表示と`apply`が後半の平均を使うよう改める。選んだ予算は、フェーズ3の実セッションと以後の標準の規模にする。 |
| 範囲の端の扱い | 範囲の端での切り詰めは現行のまま残し、反射や係数ごとの摂動幅の自動調整は入れない。場面Bでの偏りが大きく、広い摂動幅の候補が不適格になった場合は、その結果を記録し、候補の選択は「選定規則」に委ねる。端の扱いを改める設計は、その記録を根拠に別に起案する。 |
| 並列実行の扱い | 模擬実験は同時対局数1で実行し、反復を1つずつ順に適用する。実セッションは同時対局数16と1反復8ペアで動くので、約2反復が並走し、更新が発行時点より1〜2反復遅れて適用される。この遅れは、2次関数モデルの時定数（広い摂動幅の候補でも数十反復以上）に比べて小さいので、模擬実験の結論はそのまま適用する。ただし、この扱いは近似であり、測定記録にもそう明記する。 |
| 模擬実験の置き場 | `src/bin/spsa_runner/tests.rs`の子モジュール`src/bin/spsa_runner/tests/simulation.rs`に置き、既存の合成試験と同じく`#[ignore]`を付けたテストとする。子モジュールにするのは、1,300行を超える`tests.rs`をこれ以上長くせず、区分を2局の結果へ写す補助関数`pair`をそのまま使うためである。通常のテストの実行時間を増やさず、`cargo test --release`で明示的に実行する。係数の範囲は既存の試験と同じく`src/search/params.rs`の表から読み、実測のペンタノミアル度数、最初のセッションの開始値、および係数ごとの信号は、測定記録に書いた値を定数として持つ。実行ディレクトリの保存記録を直接読まないので、記録が手元にない環境でも同じ結果を再現できる。 |
| 既定値の反映方法 | 減衰の指数は`src/bin/spsa_runner/model.rs`の定数`ALPHA`と`GAMMA`を書き換え、`c_end`と`r_end`の既定は`params`サブコマンドの生成式を書き換える。CLIに指数を選ぶ引数は足さない。選ばれた1つの設定だけを使い続けるので、選択肢を残す理由がないからである。指数は既存の`manifest.json`に記録されているので、書き換えた後も過去のセッションの`apply`は保存された値で検査できる。 |
| 時間切れの事前確認 | 時間管理の係数も広い摂動幅で調整する。摂動は範囲の内側に切り詰められ、手引きの事前確認は範囲のうち最も長く考える側の端をすでに検査しているので、確認の手順は変えない。広い摂動幅では端の値で指す対局が増えるので、実セッションの時間切れ件数は0でなければ採否へ進む前に原因を調べる既存の規則をそのまま適用する。 |
| 採否 | 実セッションの値は、[spsa.md](spsa.md)の採否の手順どおり、`apply`で候補のコミットにして調整対象のコミットと標準のSTCとLTCのGSPRTで判定する。設定の選定は模擬実験が決め、実セッションの採否は値の採否だけを決める。実セッションの値が不採用になっても、それだけでは設定の選定を覆さない。開始点がすでに最適値に近ければ、どの設定でも改善は小さいからである。 |

## 模擬実験の手順

模擬実験は、候補5通り、場面8通り、予算3通り、およびS本のシード（事前の検査で決め、最小200本）の組を、既存の`runner::run`に同時対局数1で渡して実行する。
S = 200でも、1回の実行が約2万4千本、合計約1億7千万ペアになる。
1ペアの計算は22係数の摂動と目的関数の評価と分布の傾斜だけだが、所要時間は実測していない。
本実験の前に、1つの候補と場面の3予算をreleaseビルドで実行して時間を測り、全体と再現性の確認の2回分を外挿してから本実験を始める。
更新後のθと反復番号は`runner::run`の保存用のコールバックが受け取る反復記録から集め、後半の平均もそこから計算する。
出力は、候補、場面、予算、最終値の取り方ごとの平均損失、現行構成との差の平均と標準誤差、開始時の損失、および範囲の端で切り詰められた摂動の割合の表とする。
切り詰めの判定には丸めた後の整数値を使わず、直前に適用した反復記録のθと`rates`の摂動幅から、切り詰め前の`θ ± c`が範囲の外に出たかを数える。
切り詰めの割合は、場面Bと広い摂動幅の候補で偏りの原因を読むために残す。

場面Mで最適値の距離を解く式は次のとおりである。
C0の摂動幅の全反復の平均を`c̄_i`とする（N = 1,500では約`1.11·c_end`、範囲の約0.0556倍）。
目的関数の項は`f_i(x) = −(4E_i/W_i²)·(x − x*_i)²`と書けるので、摂動の前後の差は`f_i(θ + c̄_i) − f_i(θ − c̄_i) = (4E_i/W_i²)·4c̄_i·(x*_i − θ_i) = 16·E_i·c̄_i·(x*_i − θ_i)/W_i²`となり、これが係数iを増やす向きのElo差になる。
この16は2次式の展開から出る係数（4×4）である。
一方、1局あたりのθ+側の勝ち数から負け数を引いた値の期待値は、Elo差δに対して約`δ·ln 10/800`であり（ロジスティック関数の0での傾き）、1反復は16局（8ペア×2局）なので、`E[D·flip_i] ≈ 16·(ln 10/800)·16·E_i·c̄_i·(x*_i − θ_i)/W_i²`となる。
この式の最初の16は局数であり、2つ目の16とは由来が異なる。
この式を実測の信号と等しいと置き、`x*_i − θ_i = 800·W_i²·mean(D·flip_i)/(256·ln 10·E_i·c̄_i)`と解く。
実測の値は最初のセッションの全1,500反復の平均であり、θが途中で動いたことは無視する。

## 実セッションの開始点

実セッションは、`spsa-phase4`の採否が確定した後のmasterから始める。
2026年9月25日の利用者の決定による。
得られた値はそのまま次の候補になり、実対局の予算を採用し得る値の探索に使える。
最初のセッションと同じ調整対象（`7a5a0e3`）から始めて、少ない予算で同じ判定に届くかを確かめる案は採らない。
その対局は確認のためだけに使われ、得られた値が現行のmasterに対する候補にならないからである。
最初のセッションで係数がすでに動いた後の開始点なので、改善は小さく、設定の効果を実対局で読むことは難しい。
設定の選定は模擬比較が担う。

## 実装フェーズ

### フェーズ1　模擬実験

実測のペンタノミアル度数、22係数の開始値、および係数ごとの信号を、最初のセッションの実行ディレクトリ（主作業ツリーの`data/spsa/stage9-20260923`）から計算し、測定記録 `docs/measurements/spsa-gain-simulation.md` に書く。
`src/bin/spsa_runner/tests/simulation.rs`に、分布の指数傾斜、場面の目的関数、および候補と予算の組を回す`#[ignore]`テストを追加する。
所要時間を小さな組で実測して外挿し、事前の検査の3項目を通した後に本実験を実行して、表と選定規則の適用結果を同じ測定記録に書く。
完了条件は、測定記録に、選ばれた候補、予算、および最終値の取り方と、場面Mの実測の信号と模擬で得た信号の対照表が書かれていることである。

### フェーズ2　既定値の反映

選定結果のうち現行と異なる項目だけを反映する。候補が変われば`ALPHA`と`GAMMA`、`params`サブコマンドの`c_end`と`r_end`の生成式を改め、予算が変われば[spsa.md](spsa.md)の規模の節と[手引き](../guides/spsa.md)の標準コマンドを改める。いずれの場合も[spsa.md](spsa.md)の更新則の節を選定結果に合わせる。
反復の平均化を採る場合は、終了時の表示と`apply`の最終値を後半の平均に改め、その計算をテストで固定する。
既存の`rates_match_independent_fishtest_reference`は現行の指数での参照値を検査しているので、指数を引数に取る形のまま残し、新しい既定値での値を別に検査する。
完了条件は、`cargo test`と調整用ビルドの両方が通り、`params`サブコマンドの出力が新しい既定値になっていることである。

### フェーズ3　実セッションと採否

調整対象のコミットを決め、手引きの手順で時間切れの事前確認、セッション、`apply`、および採否のSTCとLTCを実行する。
規模はフェーズ1が決めた予算とする。
完了条件は、セッションと採否測定の記録が `docs/measurements/` に残り、STCで棄却されるかLTCの判定が確定することである。

## 検証

フェーズ1では、事前の検査の3項目の結果と、固定シードで模擬実験を2回実行したときに表が完全に一致することを確かめる。
フェーズ2では、既存の`spsa_runner`のテストがすべて通ること、新しい既定値で`rates`が摂動幅と学習率を期待どおりに返すこと、および既存のセッションの`manifest.json`に対する`apply`の検査が変わらないことを確かめる。
フェーズ3では、手引きの事前確認と段階ゲートの規則に従う。

## 完了条件

本マイルストーンは、次の3つがそろった時点で完了とする。
第1に、模擬実験の測定記録に、選定規則の適用結果が残っていることである。
第2に、選定結果が`spsa_runner`の既定値と手引きとしてmasterへ入っていることである。3つの項目がすべて現行のままなら、変えないことを記録すれば足りる。
第3に、その設定による実セッションの値が、STCで棄却されるかLTCの判定が確定していることである。

# 棋力向上段階3

## 先に読む要約

本マイルストーンは、静止探索（読みの末端で捕獲手だけを読み進め、駒の取り合いの途中で評価しないための探索）が読む捕獲手の質を高める。
現行の静止探索は、捕獲手をMVV-LVA（取る駒の価値が高い順、動かす駒の価値が低い順）で並べ、stand-pat（現局面の静的評価）に取る駒の価値と余裕値200を加えてもαに届かない手だけを展開せずに済ませるので、守られた駒を高価な駒で取る損な捕獲も展開され、その先の取り返しまで読んでから損だと分かる。
本書はSEE（静的交換評価。ある升での駒の取り合いを実際には読まず、取る駒の価値から取り返される自駒の価値を順に差し引いて見積もる手法）を導入し、見積りが負の捕獲手を静止探索で展開しない。
中将棋には獅子の2段階移動、先獅子、付け喰い（RULES.md第12条から第16条）という捕獲の規則があり、獅子が絡む取り合いを静的に解くのは難しいので、SEEは規則依存の要素を含まない取り合いだけを評価し、それ以外は「判定不能」として枝刈りしない。
判定不能とするのは、獅子または成って獅子になる麒麟が獅子を取る段階を含む交換列と、経由升で捕獲する2段階移動に限る。
SEEの前提として、ある升を取れる駒の集合を幾何だけで求める関数`attackers_to`を`Position`へ加え、既存の利き計算との一致をテストで固定する。
並べ替えと余裕値が使う駒価値は最初の手書き評価関数v0の表（歩兵100、獅子2,500など）のままなので、採用中の学習PST（駒種と升の組ごとの重みを自己対局の教師データで学習した線形評価関数。[評価関数](evaluation.md)）の重みから導いた値へ改める（導いた駒価値はv0の表と一致せず、たとえば成っていない龍王は1,000に対して1,180、角鷹は1,250に対して1,603である）。
静止探索専用の深さ上限は、bench（固定局面集を固定深さで探索する速度計測コマンド）で深さ分布を測ったうえで要否を決める。
採否は項目ごとに、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/sprt.md](../sprt.md)）で判定し、段階開始版（本書の着手時点のコミット）は変更せず、各項目は直前に採用した構成を基準に測る。
完了条件は、各項目の採否が記録され、採用した場合は`attackers_to`とSEEの契約がテストで固定され、段階開始版と外部エンジンHaChuに対する固定200ペアのElo（採否には使わない進捗指標）が記録されていることである。

## 状態

本マイルストーンは2026年9月5日に起案して同日に着手し、進行中である。
フェーズ1の診断で、学習PSTから導出した非王駒の駒価値はすべて正であり、学習PSTを駒価値の基準として使えることを確認した。
いま詰まっている点はない。
フェーズ2の駒価値の再調整は、段階開始版との[STC](../measurements/strength-stage3-values-stc.md)と[LTC](../measurements/strength-stage3-values-ltc.md)がともに`H1`かつ異常0件となり採用した。
フェーズ3の`attackers_to`とSEEは実装とテストを終え、benchの深さ3で捕獲手の38.7%をSEEが負として除き、25.0%を判定不能とする発動を確認した。
フェーズ4の深さ上限は、[深さ分布のbench](../measurements/strength-stage3-qsearch-depth-bench.md)で深さ8以上が0.82%と事前基準の1%を下回ったため見送った。
いま詰まっている点はない。
次の一手は、SEEを駒価値の採用コミットを基準にSTCへかけ、`H1`ならLTCへ進めることである。

## 目的

本マイルストーンは、静止探索が展開する捕獲手から、取り返しで損をすることが静的に分かる手を除き、同じ時間でより深く、またはより正確に読めるようにする。
評価尺度の変更に取り残された余裕値と駒価値を採用中の評価関数に合わせ、段階4の枝刈りの余裕値が依存する駒価値の基準を確定する。
各変更の効果を個別に測定し、効果が確認できない複雑化をコードへ残さない。

## 適用範囲

本書は、升への疑似利き集合の関数、SEE、静止探索でのSEEによる枝刈り、静止探索の余裕値、指し手順序付けの駒価値、および静止探索の深さ上限を扱う。
合法手の定義、獅子捕獲規則、審判層の王手判定、評価関数の重み、時間管理、および通常探索の枝刈りは変更しない。
通常探索でSEEが負の捕獲手をkiller手の後ろへ回す順序付けは、静止探索の質とは別の順序付けの変更なので本書の対象外とし、[棋力向上の段階計画](strength-stages.md)の段階5で扱うかを決める。
利きマップの増分更新と、利きに基づく評価特徴は段階8が扱う。

| `attackers_to`の契約 | `Position::attackers_to(square, occupied)`は、指定の占有状態で`square`へ利きが届く両陣営の駒のうち、`occupied`に含まれる駒の集合を返す。駒`p`が結果に含まれることと、`p`の升が`occupied`に含まれ、かつ`square`が`p`の`piece_control_with_occupancy`（固定利き、走り、および特殊移動の到達範囲）に含まれることが同値である。`occupied`との積を契約に含めるのは、SEEが交換列の途中で動いた駒を`occupied`から除き、その駒が固定利きや特殊移動の到達範囲から再び攻撃駒として現れないようにするためである。固定利きは相手色の同じ動きの表を逆引きし、走りは`square`から各方向へ伸ばした利き線と逆方向へ走る駒の集合の積で求め、獅子の跳びと角鷹および飛鷲の2段階目の到達升は占有状態に依存しない表で求める。規則を考慮しない疑似利きなので、審判層の王手判定は置き換えない。 |
| SEEの契約 | `see(position, rules, mv)`は、捕獲手`mv`について、到達升での取り合いを駒価値の交換列で見積もった手番側視点の値を`Some`で返し、規則依存の要素を含む場合は`None`を返す。`None`は「判定不能」を表し、呼び出し側は枝刈りしない。規則が捕獲の可否を変えるのは、獅子が獅子を取る場合（第14条の隣接と足、第16条の付け喰い）と、麒麟が獅子を取って成った直後の取り返し（第15条第7項）だけである。非獅子が獅子を取る手と獅子が非獅子を取る手は常に合法であり（第14条第5項）、その後の先獅子（第15条）は取った側に残る別の獅子の捕獲を禁じるだけで、到達升での取り合いには働かない。したがって`None`とする条件は、着手について、`mv`が経由升`mid`を持つ（第1段階で捕獲し得る2段階移動であり、居喰いと付け喰いを含む）場合、および麒麟が獅子を取って成る場合である。交換列の各段階について、到達升にある駒が獅子（麒麟が成った獅子を含む）であり、取り返す側の攻撃駒に獅子または成れる麒麟が含まれる場合である。獅子が非獅子を取る初手、非獅子が獅子を取る初手、角鷹と飛鷲が`mid`を持たずに到達升だけで捕獲する初手、および獅子、角鷹、飛鷲による非獅子の取り返しは、捕獲が1回として扱える規則独立の交換であり、通常の交換として計算する。2段階移動で2枚目を取れる可能性は価値の見積りから除くので、獅子、角鷹、飛鷲が取り返す側の得は過小に見積もられる。 |
| SEEの計算 | 標準の交換列で計算する。到達升へ最も安い駒から順に取り返し、各段階で相手が取り返さない選択肢を持つとして値を確定する。走り駒が動いた後の利きの開通（x-ray）は、動いた駒を占有状態から除いて`attackers_to`を再計算することで反映する。初手が成る場合は、到達升に置かれる駒の価値を成った後の値とする。取り返す駒が成れるかどうかは、その駒の升から到達升への着手について合法手生成と同じ`MoveRules::promotion_choice`で判定し、成りの規則（RULES.md第18条、第19条、および第30条のP1からP6まで）をSEEへ複製しない。判定が任意成りなら、成る前と成った後の価値の大きい方を到達升に置かれる駒の価値とし、成りの差額が正のときだけ得に加える。判定が強制成りなら差額の符号にかかわらず成った後の値を使い、成れないなら成る前の値を使う。任意成りで大きい方を採るのは、第18条第5項の選択を価値の見積りに反映するためであり、正値性の不変条件は成った後の価値が成る前以上であることを保証しないので、差額を符号つきで加えると意味論が崩れる。王駒は相手の利きへ動けるので（RULES.md第8条第3項）、王駒の取り返しに特別な停止規則は置かず、王駒の駒価値が交換列の中で失われる値として働く。最後の王駒を取る手は静止探索が詰みとして扱うので、SEEの対象にしない。 |

## 駒価値の再調整

学習PSTの重みは、手番側視点の自駒と相手駒それぞれについて、駒状態と升の組ごとに1つの整数を持ち、評価値はその局面で有効な重みの和を8で割ったセンチポーン値である。
つまり1つの重みはセンチポーンの8倍の尺度で保存されており、駒1枚が評価値へ与える寄与はその升の重みを8で割った値である。
駒状態`s`の駒価値`v(s)`は、自駒の重みの144升平均と相手駒の重みの符号を反転した144升平均の中間値を8で割り、最も近い整数へ丸めた値とする。

```text
v(s)      = round((mean_{sq}(w[own, s, sq]) − mean_{sq}(w[enemy, s, sq])) / 16)   （非王駒）
v(royal)  = max_{s: 非王駒} v(s) + v(成っていない歩兵)                            （王将、玉将、太子）
DELTA_MARGIN = 2 · v(成っていない歩兵)
```

王駒の値は、非王駒の最大値に歩兵1枚分の余裕を加えたものであり、王駒を取る手がどの非王駒を取る手よりも先に並ぶことだけを保証する。

指し手順序付けの`move_order_key`は、取る駒と動かす駒の駒価値をこの表から引く。
駒価値は駒種だけでなく現在の成り可否で変わるので、`piece_value`の引数は駒種から駒コードへ改める。
v0の`handcrafted::piece_value`は、v0の評価関数の一部として残す。

採用中の学習PST（K=1,072.65）から導出した駒価値は、盤上に現れ得る非王駒のすべてで正であり、自駒の平均と相手駒の符号反転平均は、差が最も大きい成っていない歩兵でも95と105であり、他の状態では3%以内で一致する。

仲人、香車、および反車の成っていない状態は、動ける範囲が狭く教師局面で観測された升が24升にとどまるため、導出値がv0に近い。
成りの対象にならない駒種の成り状態（歩兵の成り状態など）は盤上に現れないので、表から除き、正値性の検査の対象にもしない。
王駒の導出値（王将2,492、太子2,416）は獅子を下回り、学習で定まらないという設計判断と整合するので、王駒には上の式の固定値（獅子の2,522に歩兵の100を加えた2,622）を使う。
この表は診断時点の値であり、実装はコードに定数を書かず`Pst`の復号時に導出する。

## 升への疑似利き集合

`attackers_to`は要求のたびに計算する関数であり、増分更新は持たない。
計算は次の3つの和を`occupied`で制限したものである。

- 固定利き。各動きの型（`MovementProfileId`）について、`square`から相手色の同じ型の固定利きを引くと、その型の駒が`square`へ届く出発升の集合になる。180度回転の対称性は、既存の利き表のテストが固定している。
- 走り。`square`から各方向へ占有状態を考慮した利き線を伸ばし、その方向の逆向きへ走れる駒の集合との積を取る。現行の駒の走りはすべて歩数の上限がなく、横行と竪行の直交する1升移動は固定利きとして定義されているが、走りの定義（`SlideSpec`）は上限を持てるので、逆引きも上限を考慮した利き線を使い、`piece_control_with_occupancy`との同値を保つ。
- 特殊移動。獅子は`square`から距離2以内の升にある獅子、角鷹と飛鷲はその駒から見て前方（角鷹）または前斜め（飛鷲）の1升目と2升目に`square`がある駒を加える。これらの到達範囲は占有状態に依存しない。

結果は両陣営の駒を含む1つのビットボードとし、陣営別の集合は`pieces_of`との積で得る。
特殊移動の到達範囲でだけ届く駒と固定利きや走りで届く駒は区別せず、SEEはどちらも1回の捕獲として扱う。

## 静的交換評価

SEEは、到達升に置かれる駒と取られる駒の駒価値の列を作り、末尾から「取り返さない」選択肢と比較しながら畳み込む標準の手続きで計算する。

```text
mv が mid を持つ、または麒麟が獅子を取って成る手なら None を返す
gain[0]  = v(取られる駒) + (mv が成るなら v(成った後の駒) − v(動かす駒))   // 初手で得る価値
piece    = mv が成るなら v(成った後の駒)、そうでなければ v(動かす駒)         // 到達升に置かれ、次に取られ得る駒の価値
lion_on_square = 動かす駒が獅子、または成って獅子になる麒麟
side     = 相手側
occupied から動かす駒を除く
d = 0
繰り返し:
  attackers = attackers_to(到達升, occupied) ∩ side の駒
  lion_on_square かつ attackers に獅子または成れる麒麟があれば None を返す
  attackers が空なら終了
  d += 1
  gain[d] = piece − gain[d−1]                   // side がここで取り返したときの side 視点の得
  next    = attackers のうち最も安い駒
  choice  = promotion_choice(next の升 → 到達升の着手)
  choice が任意成りなら  piece = max(v(next), v(成った後の next))、gain[d] += max(0, v(成った後の next) − v(next))
  choice が強制成りなら  piece = v(成った後の next)、gain[d] += v(成った後の next) − v(next)
  そうでなければ         piece = v(next)
  lion_on_square = next が獅子、または成れる麒麟
  occupied から next を除く
  side    = 反対側
d を末尾として、d ≥ 1 の間 gain[d−1] = −max(−gain[d−1], gain[d]) を d を1ずつ減らしながら適用する
Some(gain[0]) を返す
```

`gain`の長さは盤上の駒数を超えないので、駒数の上限（92）を長さとする固定配列で足りる。
畳み込みの式は、各段階の側が「取り返す（`gain[d]`）」と「取り返さない（`−gain[d−1]`）」のうち自分に有利な方を選ぶミニマックスであり、手番側視点に戻した`gain[0]`が初手の見積りになる。
判定不能の検査は、交換列を作る前に着手そのものについて行い、その後は繰り返しの各段階で到達升の駒と攻撃駒集合について行う。
2段階に分けるのは、初期の攻撃駒集合に含まれない駒が走り駒の後ろから開通して後の段階で現れるためである。
獅子が絡む捕獲をすべて判定不能とする案は、benchの深さ3で捕獲手の約70%が判定不能になり（経由升あり13%、獅子を取る手22%、獅子で取る手19%、取り返し候補の獅子15%）、SEEが適用できる手が3割に満たないため採らない。
取り返す駒の成りを交換列に含めるのは、成りを無視すると成って取り返す側の得を過小に見積もり、その側が初手側なら正の捕獲を負と誤って枝刈りするためである。
成りの可否を`promotion_choice`で判定するのは、標準規則の条件で近似するとP5の成り保留中の歩兵が敵陣内の捕獲で成るとみなされ、同じ誤りが逆向きに起こるためである。

静止探索は、捕獲手ごとに次の順で判定する。

1. 最後の王駒を取る手は詰みの値を返す（現行どおり）。
2. delta pruningの条件を満たす手は展開しない（現行どおり）。
3. SEEが`Some`で負なら展開しない（本書で追加）。

## 静止探索の深さ上限

benchの各局面を標準時間制御の到達深さに近い深さ5で探索し、静止探索へ入ってからの深さごとのノード数を数える。
この計数はbenchへの一時的な変更で行い、コードは残さない。
深さ8以上のノードが静止探索ノードの1%未満なら、上限は発動しない改良として見送る。
深さ8と1%は本書が測定前に固定する事前選別の閾値であり、上限で削れるのは分布の裾だけなので、裾が1%未満なら実装と測定の費用に見合わないという判断である。
上限はstand-patで探索結果を変えるので、上位計画が探索挙動を変えない高速化に課す3%のNPS基準とは無関係であり、実装する場合は棋力で採否を決める。
1%以上なら、分布の99パーセンタイルの深さを上限とし、上限に達したノードはstand-patを返す実装を1項目として測る。
上限の値は診断で1つに決め、STCまでに別の値へ変えない。
[深さ分布のbench](../measurements/strength-stage3-qsearch-depth-bench.md)では、深さ5の探索で静止探索ノードの99.2%が深さ7以内にあり、深さ8以上は0.82%であったため、上限は見送った。

## 実装フェーズ

### フェーズ1　駒価値の診断

学習PSTから47状態の駒価値を導出し、v0の表、升の値域、および初期値のまま残った升の数と並べて確認する。
盤上に現れ得る非王駒の値がすべて正であれば学習PSTを駒価値の基準とし、正でなければv0の表をKの比で一様に拡大する方式に切り替える。
この診断はスクリプトで行い、コードは残さない。
診断の結果は「駒価値の再調整」節のとおりで、非王駒はすべて正であった。

### フェーズ2　駒価値の再調整

`Pst`に駒価値の表を持たせ、復号時に正値性を検査し、`move_order_key`と`DELTA_MARGIN`をその表に基づく値へ改める。
単体テストで、埋め込みPSTの表が非王駒で正であること、王駒の値が非王駒の最大値を上回ること、余裕値が歩兵の2倍であること、および非王駒の導出値が正でない重みを`decode`が専用のエラーで拒否することを固定する。
benchの総ノード数が変わることを確認し（順序と枝刈りが変わるため）、段階開始版とのSTCとLTCで採否を決める。
benchの総ノード数は深さ3で607,322から773,071へ変わり、[STC](../measurements/strength-stage3-values-stc.md)と[LTC](../measurements/strength-stage3-values-ltc.md)がともに`H1`かつ異常0件となったため採用した。

### フェーズ3　`attackers_to`とSEE

`attackers_to`を実装し、bench局面とランダム局面で全升と全駒について契約の同値をテストで固定する。
SEEを実装し、判定不能の条件と交換列の値を単体テストで固定してから静止探索へ組み込む。
benchでSEEにより除かれる捕獲手の割合を数えて発動を確認し、フェーズ2の採用結果とのSTCとLTCで採否を決める。
フェーズ2が不採用なら、SEEはv0の駒価値の表を使い、段階開始版を基準にする。
`attackers_to`とSEEは1つの項目であり、採否も一体で決める。

### フェーズ4　静止探索の深さ上限

benchで深さ分布を測り、見送るか実装するかを本書の基準で決める。
実装する場合は、上限に達したノードがstand-patを返すことを単体テストで固定し、直前の採用構成とのSTCとLTCで採否を決める。
[深さ分布のbench](../measurements/strength-stage3-qsearch-depth-bench.md)は深さ8以上が0.82%であり、基準により見送った。

### フェーズ5　進捗指標の記録

全項目の採否が確定した後に、段階開始版との固定200ペアEloをSTCで、HaChu戦の固定200ペアEloを`time=60000+1000`で記録する。
採用項目が1つもなく最終構成が段階開始版と同一の場合は、同一バイナリの自己比較に意味がないので段階開始版との比較を省略し、HaChu戦だけを記録する。

## 検証

- `attackers_to`のテストは、初期局面、benchの14局面、およびランダム対局から採った局面について、全升と全駒で「`occupied`に含まれ、かつ`piece_control_with_occupancy`が`square`を含む」ことと結果に含まれることの同値を確認する。占有状態から駒を1枚および複数枚除いた仮想盤面でも同値を確認し、除いた駒が固定利きや特殊移動の到達範囲から再び現れないことと、x-rayの開通が正しいことを固定する。
- SEEのテストは、判定不能を返す事例として、付け喰い、居喰い、麒麟が獅子を取って成る手、獅子で非獅子を取った後に距離2の相手獅子が取り返せる升、非獅子で獅子を取った後に取り返され、さらに自獅子で取り返す段階で相手獅子が届く升、および到達升の獅子を敵陣の麒麟が取り返せる升を含む。値を返す事例として、守られていない駒の捕獲、守られた駒を高価な駒で取る捕獲、走り駒の後ろから開通する取り返し、王駒による取り返し、非獅子で守られていない獅子を取る手、獅子で非獅子を取り非獅子に取り返される交換列、獅子が非獅子を取り返す交換列、2升前の角鷹と斜め2升前の飛鷲が取り返す交換列、成った初手の駒が直後に取り返されて成った後の価値が失われる交換列、成って取り返す駒を含む交換列、P5の成り保留中の歩兵が最奥段以外で取り返す交換列、角鷹が隣接升へ1升移動して取る初手、および角鷹と飛鷲が2升目へ直接跳んで1枚だけ取る初手を含み、期待値は交換列を手で計算した値とする。
- SEEの値の正しさは前項の単体テストが固定し、静止探索がSEEの`None`で枝刈りしないことは別に、判定不能の事例だけを含む局面で、SEEの枝刈りの有無にかかわらず展開される手の集合が一致することで確認する。
- 各変更後に`cargo test`、`cargo clippy --all-targets --all-features -- -D warnings`、および`cargo fmt --check`が成功する。
- フェーズ2からフェーズ4は探索の挙動を変えるので、benchの総ノード数の変化を記録し、変化が意図した項目だけによることを確認する。
- 採否測定は`docs/sprt.md`のコミット対コミット測定に従い、各測定の`time_forfeits`と異常件数を記録する。

## 完了条件

次の条件をすべて満たしたとき、本マイルストーンを完了とする。

- 駒価値の再調整、`attackers_to`とSEE、および静止探索の深さ上限の採否または見送りが個別の測定記録に残り、不採用の実装がコードに残っていない。
- 採用した項目について、テスト、Clippy、および整形検査が成功している。
- 採用した項目のLTCの連鎖がすべて`H1`で、`time_forfeits`と異常件数が0件であるか、全項目が不採用となり段階開始版からコード変更が残っていない。
- `attackers_to`とSEEを採用した場合は、その契約がテストで固定されている。
- HaChu比較の固定200ペアEloと、採用項目がある場合は段階開始版との固定200ペアEloが測定記録に残っている。

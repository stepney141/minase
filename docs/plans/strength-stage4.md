# 棋力向上段階4

## 先に読む要約

本マイルストーンは、通常探索（読みの末端で静止探索へ入る前の、全手を対象とする探索）に前向き枝刈り（劣ると見込んだ枝を読まずに済ませる手法）の第2層を1項目ずつ導入する。
現行の通常探索が持つ前向き枝刈りは、null move pruning（手番を渡しても評価がβを下回らないなら打ち切る手法）と、LMR（late move reductions。順序付けの後方にある静かな手を浅く読む手法）だけであり、静的評価（その局面を探索せずに評価関数で求めた値）を枝刈りの判断に使う機構がない。
本書は、静的評価がβを余裕値以上に上回る浅いノードで探索せずに静的評価を返すreverse futility pruning、静的評価に余裕値を加えてもαに届かない浅いノードで静かな手を展開しないfutility pruning、順序付けの後方にある静かな手を深さに応じた手数で打ち切るlate move pruning、null move pruningの減深量を静的評価とβの差にも依存させる変更、null moveの打ち切りを縮めた通常探索で確かめるverification search、および静的評価がαを大きく下回る浅いノードを静止探索の値で済ませるrazoringを扱う。
中将棋は1局面の合法手が100手を超え、王手を解消しない着手も合法（RULES.md第8条）なので、余裕値と手数の上限はチェスや本将棋の値を流用せず、bench（固定局面集を固定深さで探索する速度計測コマンド）で測った静的評価と探索値のずれの分布から本書の規則で1つに決め、王駒に相手の利きが届くノードでは静的評価に基づく枝刈りを行わない。
採否は項目ごとに、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/sprt.md](../sprt.md)）で判定し、段階開始版（本書の着手時点のコミット）は変更せず、各項目は直前に採用した構成を基準に測る。
各項目は実装前にbenchの診断で発動を確かめ、発動または効果の見込みが本書の基準に届かなければ実装せずに見送る。
完了条件は、各項目の採否または見送りが記録され、採用した枝刈りが誤った詰みの値を返さないことがテストで固定され、段階開始版と外部エンジンHaChuに対する固定200ペアのElo（採否には使わない進捗指標）が記録されていることである。

## 状態

本マイルストーンは2026年9月5日に起案して同日に着手し、進行中である。
フェーズ1の[診断bench](../measurements/strength-stage4-pruning-bench.md)を完了し、reverse futility pruning、futility pruning、late move pruningの余裕値と手数の上限を「採用した余裕値」節のとおり確定した。
診断では、起案時の「条件付き不一致率10%」の規則が基礎率の低さで縮退することが分かり、最初のSTCより前に「失う良い結果の割合10%」の規則へ置き換えた。
フェーズ2のreverse futility pruningは、段階開始版との[STC](../measurements/strength-stage4-rfp-stc.md)が`H0`となり不採用とし、王駒への利きの判定とともに実装を外した。
次の一手は、フェーズ3のfutility pruningを実装し、段階開始版とのSTCへ進むことである。

## 目的

本マイルストーンは、通常探索の浅いノードで静的評価から結果が見込める枝を読まずに済ませ、同じ時間でより深く読めるようにする。
持ち時間を2倍にしただけで自己対局の固定200ペアが+216 Eloになった実測（[棋力向上の段階計画](strength-stages.md)の現状の診断）が示すとおり、同じ評価関数でも探索量の増加はそのまま棋力へ転化するので、枝刈りによる探索木の縮小は棋力に直結する。
各変更の効果を個別に測定し、効果が確認できない複雑化をコードへ残さない。

## 適用範囲

本書は、通常探索のreverse futility pruning、futility pruning、late move pruning、null move pruningの減深量とverification search、razoring、およびこれらが共有する王駒への利きの判定を扱う。
静止探索、指し手順序付け、LMRの減深量、置換表、時間管理、評価関数の重み、および合法手の定義は変更しない。
静的評価を置換表へ保存して再計算を省く変更は段階6が扱う。
LMRの減深量の式とhistoryの拡張は段階5が扱う。

## 依存関係

探索とbenchの契約は[探索部](search.md)に従い、機能採否の時間制御GSPRTは[SPRTによる棋力測定の手引き](../sprt.md)と[棋力測定の段階ゲート](match-staged-gate.md)に従う。

段階の順序、項目、共通の採否基準、および全体の完了条件は[棋力向上の段階計画](strength-stages.md)が所有し、本書は段階4の実装方式、検証範囲、および不採用時の処理を具体化する。

## 設計判断

| 項目 | 決定 |
|---|---|
| 項目の順序 | reverse futility pruning、futility pruning、late move pruning、null move pruningの減深量、verification search、razoringの順に進める。上位計画の順序を保ち、各項目は直前に採用した構成を基準に測る。静的評価に基づく3項目を先に置くのは、最も広く使われ効果の見込みが大きいためであり、verification searchとrazoringを最後に置くのは、診断で見送りになり得るためである。 |
| 静的評価の取得 | 各ノードの静的評価は、[段階1](strength-stage1.md)で採用した評価値の差分更新（着手のたびに評価値の内部和を差分で更新する仕組み）の累算値から`evaluate_accumulator`で求める。累算値は探索が既にplyごとに保持しているので計算は定数時間であり、置換表への保存（段階6）を待たずに導入できる。 |
| 余裕値と手数の単位 | 余裕値は歩兵の駒価値`p`（学習PST、すなわち駒種と升の組ごとの重みを学習した線形評価関数から導出した成っていない歩兵の値。現行の埋め込みPSTでは100）の倍数で表し、`p / 2`の刻みで丸める。駒価値は評価関数の重みファイルを読み込む時点で`Pst`型が導出するので、余裕値もコードに定数を書かず`Pst`から導く。 |
| 余裕値と手数の決め方 | チェスや本将棋の値を流用せず、診断benchで測る。各項目について「参照探索で枝刈りの見込みと逆の結果になった良い結果」（reverse futilityとrazoringでは探索値が境界を下回ったノード、futilityとlate move pruningでは探索値がαを上回った手）を定義し、候補値を適用したときに失う良い結果の割合が10%以下になる最小の余裕値または手数を、深さごとに1つ選ぶ（手続きは「診断による余裕値の決定」節）。参照探索は診断時点の現行探索であり、null moveやLMRの枝刈りを含むので、この割合は完全探索に対する損失ではなく、現行探索の結果に対する損失である。候補値以上の対象に占める食い違いの割合（条件付き不一致率）で選ぶ案は、良い結果の基礎率が零窓ノードでは1%から10%程度しかなく、候補値によらず10%を下回って最小候補を選んでしまうため採らない（[診断bench](../measurements/strength-stage4-pruning-bench.md)）。10%は理論から導いた値ではなく、失う良い結果と探索木の縮小の釣り合いを1点に固定するために本書が最初のSTCより前に決める基準であり、STCの結果を見てから余裕値を変えない。同じ項目の余裕値違いをSTCの後に追加することは[docs/sprt.md](../sprt.md)が禁じる。 |
| 適用するノード | 静的評価に基づく枝刈り（reverse futility、futility、late move pruning、razoring）は、探索窓の幅が1の非PVノードであること、αとβがいずれも詰み帯（絶対値が`MATE_THRESHOLD`以上）になく、王駒に相手の疑似利きが届かないことのすべてを満たすノードに限る。根ノードは常にPVノードなので対象にならない。 |
| 王駒への利きの判定 | 手番側のいずれかの王駒（王将、玉将、太子）の升に相手駒の疑似利きが届くノードでは、静的評価に基づく枝刈りを行わない。判定は`attackers_to`と相手駒の集合の積で行い、増分更新は持たない。王駒が取られる局面の静的評価は、最後の王駒の捕獲が詰みの値になる探索値から大きく外れるためである。王駒の捕獲を禁じる規則はなく王手放置も合法（RULES.md第8条）なので、王駒の升については疑似利きと実際に捕獲できる駒の集合が一致し、判定に過不足はない。王駒を2枚持つ側は1枚を失っても負けないが、その場合も枝刈りを控える側に倒す。診断で除外率が対象ノードの半数を超える場合は、判定を最後の王駒に限る変種と比較する。null move pruningには現行どおりこの判定を加えない。 |
| 展開しない手の範囲 | futility pruningとlate move pruningは、置換表の記録手、捕獲手（`move_order_key`が`Some`を返す手）、および成る手を対象にせず、そのノードで探索済みの最善値が負の詰み帯にある間（1手も探索していない状態を含む）は行わない。成る手を除くのは、麒麟が獅子に成る手のように非捕獲でも評価が大きく動く手があるためである。最善値が負の詰み帯にある間に枝刈りしないのは、2つの誤りを防ぐためである。第1に、現行の`negamax`は「探索した手が1つもない」ことを合法手なしの負け（RULES.md第23条）の根拠にして詰みの値を返すので、全手を枝刈りしたノードが詰みと区別できなくなる。第2に、最初に探索した手が王駒を失う手で負の詰み帯の値になった場合、残りの安全な手を枝刈りすると、その詰み値が上界として置換表へ保存され、親には勝ちの詰み値が伝わる。 |
| reverse futility pruningの返り値 | 条件を満たしたノードは静的評価をそのまま返し、置換表には保存しない。診断が保証するのは境界判定の一致だけであり、返す値の大きさは近似である。この近似はnull move pruningやLMRの返り値にも含まれるfail-softの性質と同じなので、同じ扱いにする。βへ丸める案は境界としては常に正しいが、上位ノードで得られる情報を減らすので採らない。 |
| null move pruningの減深量 | 現行の`R = 2 + depth / 6`に、静的評価とβの差を`2p`で割って0以上3以下に切り詰めた値を加える。静的評価がβを下回るときは加算が0になるので、null moveを試す条件は変えない。`depth − 1 − R`は現行どおり0で飽和させる。上限3は、STCの到達深さ5〜6で縮めた深さが0に達してnull moveの検証が静止探索だけになる頻度を抑えるための値であり、静止探索だけの検証は手番を渡した側の反撃を読まないので打ち切りの誤りが増える。 |
| verification searchの要否 | null move pruningの減深量の採否が確定した後に、その構成で診断する。null moveがβ以上を返し、かつ縮めた深さ`depth − 1 − R`が1以上のノードのすべて（PVノードと王駒に利きが届くノードを含む）について、null moveを禁じた縮めた深さの通常探索を実行し、その値がβを下回る割合を数える。割合が1%未満なら、verification searchは発動しても結果を変えない改良として実装せず見送る。1%以上なら、同じ条件でnull moveを禁じた縮めた深さの探索で確かめ、βを下回れば通常の探索へ戻す実装を1項目として測る。縮めた深さが0のときは通常探索を行えず静止探索のstand-patだけで通過し得るので、診断と実装のどちらも対象にしない。verification searchはnull moveの打ち切りの誤りを捕まえる機構であり、その誤りは手番を渡すことが不利になる局面（zugzwang）で起こる。中将棋は駒数が多くzugzwangが稀なので見送りになる見込みが高いが、上位計画の「要否を測る」に従い診断で確定する。 |
| razoringの要否 | futility pruningが不採用なら、razoringは実装せず見送る。不採用から静的評価の予測力を否定できるわけではないが、同じ静的評価とαの差を根拠にする項目を2つ測る予算を認めない方針である。futility pruningを採用した場合は、その時点の採用構成で余裕値を診断し、深さ2以下の非PVノードで静的評価に余裕値を加えてもαに届かないとき静止探索を呼び、その値がα以下ならその値を返す実装を1項目として測る。 |
| 発動の事前確認 | 各項目は、実装前の診断でbench深さ5の発動率が5%以上であることを確認する（[採否測定の条件で改良が発動することを実装前に確認する](../lessons/measure-feature-activation-before-sprt.md)）。発動率の分子と分母は項目ごとに「診断による余裕値の決定」節が定め、5%未満なら発動しない改良として見送り、その項目のフェーズは実行しない。verification searchは枝刈りを追加する処理ではないので、発動率の代わりに矛盾率1%を基準にする。 |
| 診断の時期 | reverse futility pruning、futility pruning、late move pruningの余裕値と手数は、フェーズ1で段階開始版の分布から決める。先行する項目の採用で分布が動くことは許容し、再診断しない。razoringとverification searchは前提となる項目の採否が確定した後に、その時点の採用構成で診断する。 |
| 診断コードの扱い | 診断の計測はbenchへの一時的な変更で行い、コードは残さない。段階3の静止探索の深さ分布と同じ扱いである。 |
| 未採用コードの扱い | 不採用または見送りとなった項目はコードに残さず、設計だけを本書に保持する。 |

## 現行の通常探索

本書で使う探索の用語を先に定める。
探索は各ノードで「この値以上なら手番側にとって十分」という下限αと「この値以上なら相手が許さない」という上限βの窓を持ち、窓の幅が1（`β = α + 1`）の探索を零窓探索という。
零窓探索は真の値が窓のどちら側にあるかだけを答え、fail-softの実装では、返り値がβ以上ならその値は真の値の下界、α以下なら上界である。
最善応手列（PV）上のノードは幅のある窓で探索され、それ以外の非PVノードは零窓で探索される。
詰みの値は`MATE − ply`（`ply`は根からの手数）で表し、絶対値が`MATE_THRESHOLD`以上の値の範囲を詰み帯という。
置換表は探索済み局面の値と最善手を保存する表であり、killer手とhistoryは静かな手（捕獲を伴わない手）の順序付けに使う統計である。

`negamax`は、深さ0で静止探索へ入り、置換表の照会、null move pruning、段階的な手選択による全手の探索、置換表への保存の順で進む。
null move pruningは、深さ3以上、直前がnull moveでなく、βが詰み帯になく、手番側に王駒以外の駒がある局面で、`R = 2 + depth / 6`だけ縮めた零窓探索を行う。
LMRは、深さ3以上で、置換表の記録手、捕獲手、killer手を除く4手目以降の手を1だけ減深する。
合法手がない局面は`−MATE + ply`を返し、この値は最善手が1つも見つからなかったことを根拠にする。
静的評価は静止探索のstand-patにだけ使われ、通常探索では参照されていない。

標準時間制御の到達深さは、STCで4〜6、LTCで6〜7である（[LTCの煙試験](../measurements/match-cost-ltc-smoke.md)）。
根の深さが`D`の探索は、根から`D − d`手進んだノードを残り深さ`d`で探索するので、根の深さが4以上なら残り深さ3以下のノードは必ず現れる。
したがって本書の枝刈りは、残り深さ3以下のノードを対象にすれば、両方の時間制御で発動する。

## 診断による余裕値の決定

診断は、benchの15局面を深さ5で探索し、一時的な計測で分布を採る。
計測の対象ノードは、探索窓の幅が1、αとβが詰み帯になく、王駒に相手の疑似利きが届かず、置換表で打ち切られなかったノードに限る。
計測の対象手は、対象ノードで探索された手のうち、置換表の記録手、捕獲手、成る手を除き、かつその手を探索する時点で探索済みの最善値が負の詰み帯になかった手とする。

「探索値がβを下回った」および「αを上回った」は、fail-softで返る値が零窓の上界または下界であることを利用した境界判定である。
探索値がβを下回ればその値は参照探索における上界なので、参照探索の値もβを下回り、そのノードを枝刈りすると参照探索の結果を失うことが確定する。
探索値がβ以上なら失うものはない。
αについても同様である。
参照探索は診断時点の現行探索であり、その値は完全探索の値ではないので、この割合は現行探索の結果に対する損失である。

各項目の候補値、失う割合、および発動率は次のとおり定める。

- reverse futility pruning。深さ1から3の対象ノードについて、静的評価からβを引いた差と、探索値がβを下回ったかどうかを記録する。候補値`m`は`p / 2`から`10p`までの`p / 2`刻みとし、探索値がβを下回った対象ノードのうち差が`m`以上のものの割合が10%以下になる最小の`m`を深さ`d`の余裕値とする。発動率は、余裕値を適用したときに枝刈りされるノード数を対象ノード数で割った値とする。
- futility pruning。深さ1から3の対象手について、αから静的評価を引いた差と、その手の探索値がαを上回ったかどうかを記録する。候補値と選び方はreverse futility pruningと同じで、探索値がαを上回った対象手のうち差が`m`以上のものの割合を使う。発動率は、余裕値を適用したときに展開されない手数を対象手数で割った値とする。
- late move pruning。同じ対象手について、そのノードでの手番号と、探索値がαを上回ったかどうかを記録する。候補値`k`は1から200までの整数とし、探索値がαを上回った対象手のうち手番号が`k`以上のものの割合が10%以下になる最小の`k`を深さ`d`の手数の上限とする。発動率はfutility pruningと同じ定義である。
- razoring。深さ1と2の対象ノードについて、αから静的評価を引いた差と、探索値がαを上回ったかどうかを記録し、futility pruningと同じ候補値と選び方で余裕値を決める。発動率は、余裕値を適用したときに静止探索の値がα以下となって打ち切られるノード数を対象ノード数で割った値とし、静的評価の条件が成立しただけのノードは数えない。
- verification search。null moveがβ以上を返し、縮めた深さが1以上のノードのすべてについて、null moveを禁じた縮めた深さの探索を実行し、その値がβを下回った件数を数える。矛盾率はこの件数をそのようなノード数で割った値とし、深さと縮めた深さごとにも記録する。
- 王駒への利きの判定。深さ3以下の非PVノードのうち、王駒に相手の疑似利きが届くために対象から外れたノードの割合を数える（[保守的な適用除外は実装直後に除外率を測ってから確定する](../lessons/measure-conservative-guard-coverage.md)）。割合が半数を超える場合は、判定を最後の王駒（その側の王駒が1枚だけのときの王駒）に限る変種でも同じ分布を採り、除外率の低い方を採用してから余裕値を決める。

候補値は最初から刻みの上で評価するので、選んだ後に丸めることはない。
深さごとに対象件数、良い結果の件数、失う件数、および発動件数を記録し、次の場合はその深さでは枝刈りを行わない。
対象件数が1,000件未満の深さ、候補値の範囲内に失う割合10%以下の値がない深さ、および対象件数が0件の深さである。
対象件数が0件または少数の深さを損失0%とみなして枝刈りを認めることはしない。
全深さで枝刈りを行わない項目は見送る。
決めた値は「採用した余裕値」節へ表として記録し、STC以降は変えない。
分布を採るための計測コードは残さず、候補値の評価はスクリプトで行う。

## 採用した余裕値

フェーズ1の[診断bench](../measurements/strength-stage4-pruning-bench.md)で確定した値は次のとおりである。
`p`は現行の埋め込みPSTの歩兵価値100であり、実装は`p`の倍率で保持する。

| 残り深さ | reverse futility の余裕値 | futility の余裕値 | late move pruning の手数上限 |
|---|---|---|---|
| 1 | 50（`p / 2`） | 50（`p / 2`） | 12 |
| 2 | 50（`p / 2`） | 150（`3p / 2`） | 23 |
| 3 | 50（`p / 2`） | 150（`3p / 2`） | 13 |

発動率はreverse futilityが深さ順に67.6%、55.4%、38.2%、futilityが91.7%、63.0%、65.1%、late move pruningが92.3%、80.5%、93.4%であり、いずれも5%以上である。
王駒への利きの判定による除外率は1.6%から3.0%で、いずれかの王駒に利きが届けば枝刈りを控える方式を採用した。
razoringの余裕値とverification searchの矛盾率は、それぞれの診断が終わった時点でここへ追記する。

## 各項目の実装

### reverse futility pruning

置換表の照会の後、null move pruningの前に判定する。
深さ3以下、非PVノード、βが詰み帯になく、王駒に相手の疑似利きが届かず、静的評価から深さ`d`の余裕値を引いた値がβ以上なら、静的評価を返す。

### futility pruning

手のループの中で判定する。
深さ3以下、非PVノード、αが詰み帯になく、王駒に相手の疑似利きが届かず、探索済みの最善値が負の詰み帯になく、静的評価に深さ`d`の余裕値を加えた値がα以下なら、置換表の記録手、捕獲手、成る手を除く手を展開しない。
静的評価と余裕値の和はノードで1回計算し、手ごとには判定だけを行う。
展開しなかった手は最善手の候補にならず、killer手とhistoryの更新の対象にもならないが、手番号は進める。
現行の`negamax`は手番号の加算をループの末尾に置いているので、飛ばす手でも加算されるように位置を改める。

### late move pruning

futility pruningと同じ手のループで判定する。
深さ3以下、非PVノード、αが詰み帯になく、王駒に相手の疑似利きが届かず、探索済みの最善値が負の詰み帯になく、手番号が深さ`d`の上限以上なら、置換表の記録手、捕獲手、成る手を除く手を展開しない。
手番号は現行のLMRが使う`index`と同じ数え方であり、捕獲手も含めた探索順の通し番号で、飛ばした手でも進める。
捕獲手が多い局面では捕獲手の段階の途中で上限に達し得るので、上限に達してもループは抜けず、手ごとに捕獲手と成る手を除外したうえで対象の静かな手だけを飛ばす。

### null move pruningの減深量

現行の`R = 2 + depth / 6`を`R = 2 + depth / 6 + clamp((static_eval − β) / (2p), 0, 3)`へ改める。
null moveを試す条件、縮めた深さを`saturating_sub`で0に飽和させる処理、および詰み帯の値をβへ丸める処理は変えない。

### verification search

null move pruningの減深量の採否が確定した構成での診断で、矛盾率が1%以上の場合に限り実装する。
null moveの零窓探索がβ以上を返し、縮めた深さ`depth − 1 − R`が1以上のとき、`null_move_ply`と同じ仕組みでこのノードのnull moveを禁じ、縮めた深さの零窓探索を行う。
その値もβ以上ならnull moveの打ち切りを採用し、βを下回れば通常の手のループへ進む。

### razoring

futility pruningを採用した場合に限り、その時点の採用構成で余裕値を診断し、発動率が5%以上なら実装する。
reverse futility pruningの後に判定する。
深さ2以下、非PVノード、αが詰み帯になく、王駒に相手の疑似利きが届かず、静的評価に深さ`d`の余裕値を加えた値がα以下なら、静止探索を呼ぶ。
静止探索の値がα以下ならその値を返し、αを上回れば通常の探索へ進む。

## 実装フェーズ

### フェーズ1　診断

段階開始版のbenchへ一時的な計測を入れて「診断による余裕値の決定」節の分布を採り、王駒への利きの判定の除外率を確かめたうえで、reverse futility pruning、futility pruning、late move pruningの余裕値と手数の上限を決める。
発動率が5%未満の項目、および全深さで枝刈りを行わない項目は見送る。
結果は[strength-stage4-pruning-bench](../measurements/strength-stage4-pruning-bench.md)へ記録し、余裕値は「採用した余裕値」節へ書く。
完了条件は、この3項目について実装するか見送るかが確定していることである。
見送った項目のフェーズは実行しない。

### フェーズ2　王駒への利きの判定と reverse futility pruning

王駒への利きの判定を`negamax`に加え、reverse futility pruningを実装する。
benchで総ノード数の変化と、判定の追加によるNPSの変化を記録する。
段階開始版とのSTCとLTCで採否を決める。
不採用なら、王駒への利きの判定も含めて外し、次の項目で改めて入れる。

### フェーズ3　futility pruning

futility pruningを実装し、直前の採用構成とのSTCとLTCで採否を決める。
枝刈りによって誤った詰みの値を返さないことを単体テストで固定する。

### フェーズ4　late move pruning

late move pruningを実装し、直前の採用構成とのSTCとLTCで採否を決める。
futility pruningと同じ単体テストの対象に加える。

### フェーズ5　null move pruningの減深量

減深量の式を改め、直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ6　verification search

フェーズ5の採否が確定した構成のbenchで矛盾率を診断し、[strength-stage4-nmp-verify-bench](../measurements/strength-stage4-nmp-verify-bench.md)へ記録する。
矛盾率が1%以上の場合に限り、実装して直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ7　razoring

futility pruningを採用した場合に限り、フェーズ6までの採否が確定した構成のbenchで余裕値と発動率を診断し、[strength-stage4-razoring-bench](../measurements/strength-stage4-razoring-bench.md)へ記録する。
発動率が5%以上の場合に限り、実装して直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ8　進捗指標の記録

全項目の採否が確定した後に、段階開始版との固定200ペアEloをSTCで、HaChu戦の固定200ペアEloを`time=60000+1000`で記録する。
採用項目が1つもなく最終構成が段階開始版と同一の場合は、段階開始版との比較を省略し、HaChu戦だけを記録する。

## 検証

- 枝刈りの単体テストは2つの局面を使う。第1は、合法手が静かな手だけでfutility pruningまたはlate move pruningの条件を満たす局面であり、探索が`−MATE + ply`ではなく静的評価の近傍の値を返すことを固定する。第2は、最初に探索される手が王駒を相手の利きへ動かして負の詰み帯の値になり、後方に安全な静かな手がある局面であり、返り値が詰み帯になく、置換表にも詰み帯の値が保存されないことを固定する。
- reverse futility pruningのテストは、静的評価がβを余裕値以上に上回る非PVノードで静的評価が返ることと、同じ局面でも王駒に相手の疑似利きが届く場合、探索窓の幅が1でない場合、およびβが詰み帯にある場合は枝刈りされないことを固定する。
- 王駒への利きの判定のテストは、王将と太子の2枚を持つ側で太子だけに利きが届く局面でも判定が真になることと、距離2の升から跳んで届く獅子の利きも数えることを固定する。
- null move pruningの減深量のテストは、静的評価とβの差が負、`2p`未満、`2p`以上`4p`未満、`6p`以上の4つの場合に加算が0、0、1、3になることを固定する。
- verification searchを実装した場合は、null moveの打ち切りが縮めた通常探索で覆される局面で通常の探索へ進むことと、縮めた深さが0のノードでは検証を行わないことを固定する。
- 各変更後に`cargo test`、`cargo clippy --all-targets --all-features -- -D warnings`、および`cargo fmt --check`が成功する。
- 全フェーズは探索の挙動を変えるので、benchの総ノード数の変化を記録し、変化が意図した項目だけによることを確認する。
- 採否測定は`docs/sprt.md`のコミット対コミット測定に従い、各測定の`time_forfeits`と異常件数を記録する。測定名は`strength-stage4-<項目>-stc`および`-ltc`とし、項目は`rfp`、`futility`、`lmp`、`nmp-r`、`nmp-verify`、`razoring`とする。

## 完了条件

次の条件をすべて満たしたとき、本マイルストーンを完了とする。

- reverse futility pruning、futility pruning、late move pruning、null move pruningの減深量、verification search、およびrazoringの採否または見送りが個別の測定記録に残り、不採用の実装がコードに残っていない。
- 採用した項目について、テスト、Clippy、および整形検査が成功し、枝刈りによって誤った詰みの値を返さないことがテストで固定されている。
- 「採用した余裕値」節に、診断した項目の余裕値、手数の上限、および発動率が記録されている。
- HaChu戦の固定200ペアEloが測定記録に残り、採用項目が1つでもあれば段階開始版との固定200ペアEloも残っている。
- [棋力向上の段階計画](strength-stages.md)の段階4の節と docs/ROADMAP.md の状態表が更新されている。

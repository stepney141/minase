# 棋力向上段階5

## 先に読む要約

本マイルストーンは、通常探索（読みの末端で静止探索へ入る前の、全手を対象とする探索）の指し手順序付けとLMR（late move reductions。順序付けの後方にある静かな手を浅く読む手法）を、1局面の合法手が100手を超える中将棋に合わせて1項目ずつ改める。
順序付けとは、同じノードの合法手を有望な順に並べて探索する手順であり、良い手を先に読むほどαβ探索の打ち切りが早く起こり、同じ時間でより深く読める。
静かな手とは捕獲を伴わない手をいい、β打ち切りとは、ある手の結果が相手の許容上限βに達したためそのノードの残りの手を読まずに済ませることをいう。
現行の順序付けは、置換表（探索済み局面の結果を保存して再利用する表）の記録手、捕獲手、killer手（同じ深さで直前にβ打ち切りを起こした静かな手）、残りの静かな手をhistory（β打ち切りを起こした静かな手の統計）の降順に並べ、historyは手番側と移動元と移動先だけで引く。
現行のLMRは、残り深さ3以上で置換表の記録手、捕獲手、killer手を除く4手目以降の静かな手を固定で1だけ浅く読む。
本書は、順序付けキーの重複計算の除去、駒種と到達升で引くhistoryの追加、直前の相手の手に対する応手の統計（counter move history）の追加、2手前の自分の手との組合せの統計（continuation history）の追加、β打ち切りを起こさなかった静かな手への減点（malus）、および残り深さと手番号の対数に基づきhistory値で増減するLMRの減深量の6項目を扱う。
減深量の式の係数とhistory値の閾値は、チェスや本将棋の値を流用せず、bench（固定局面集を固定深さで探索する速度計測コマンド）で測った「浅く読んだ結果が本来の深さの結果と食い違う割合」から「診断による係数の決定」節の規則で1つに決め、最初の採否測定より後には変えない。
採否は項目ごとに、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/guides/sprt.md](../guides/sprt.md)）で判定し、探索の挙動を変えない重複計算の除去だけはbenchの総ノード数の一致で判定する。
完了条件は、各項目の採否が記録され、採用したhistoryの更新とLMRの減深量がテストで固定され、段階開始版（本書の着手時点のコミット）と外部エンジンHaChuに対する固定200ペアのElo（採否には使わない進捗指標）が記録されていることである。
順序付けキーの重複計算の除去をbenchで、LMRの減深量をSTCとLTCがともに`H1`で採用し、駒種と到達升で引くhistoryはSTCで`H0`、malusはSTCの上限3,000ペアで負のLLRの判定保留となり不採用、counter move historyとcontinuation historyは発動率が1%未満のため見送った。

## 目的

本マイルストーンは、順序付けの精度を高めて打ち切りまでに読む手数を減らし、順序付けの後方にある手をより大きく減深して、同じ時間でより深く読めるようにする。
持ち時間を2倍にしただけで自己対局の固定200ペアが+216 Eloになった実測（[棋力向上の段階計画](strength-stages.md)の現状の診断）が示すとおり、探索量の増加はそのまま棋力へ転化するので、探索木の縮小は棋力に直結する。
中将棋は合法手が多いため、順序付けの誤りとLMRの減深量の不足が探索木に与える影響はチェスより大きいと見込まれる。
各変更の効果を個別に測定し、効果が確認できない複雑化をコードへ残さない。

## 適用範囲

本書は、通常探索の指し手順序付け（history表の構成、更新、および参照）、LMRの減深量、およびこれらが共有する手の分類を扱う。
静止探索の順序付け、捕獲手のMVV-LVA（価値の高い駒を取る手を先に、同点なら価値の低い駒で取る手を先に読む順序付け）、killer手の仕組み、置換表、前向き枝刈り、時間管理、評価関数の重み、および合法手の定義は変更しない。
history表を探索の間で持ち越す変更、捕獲手のhistory、および置換表の記録手がないノードの減深は本書の対象外である。

## 依存関係

探索とbenchの契約は[探索部](search.md)に従い、機能採否の時間制御GSPRTは[SPRTによる棋力測定の手引き](../guides/sprt.md)と[棋力測定の段階ゲート](match-staged-gate.md)に従う。
futility pruningが展開しない手の範囲と手番号の数え方は[棋力向上段階4](strength-stage4.md)が所有し、本書の手の分類はその範囲と一致させる。
段階の順序、項目、共通の採否基準、および全体の完了条件は[棋力向上の段階計画](strength-stages.md)が所有し、本書は段階5の実装方式、検証範囲、および不採用時の処理を具体化する。
段階6のinternal iterative reductionと静的評価の置換表保存は、本書の順序付けを前提にする。

## 設計判断

| 項目 | 決定 |
|---|---|
| 項目の順序 | 順序付けキーの重複計算の除去、駒種と到達升で引くhistory、counter move history、continuation history、malus、LMRの減深量の順に進める。上位計画はLMRの減深量を先頭に置くが、本書は最後に置く。減深量の式はhistory値で増減するので、その閾値をhistoryの最終構成で診断すれば再診断が要らず、malusの採否が確定した後なら負のhistory値による増深も同じ診断で決められるためである。重複計算の除去を先頭に置くのは、後続の全項目が使う手の分類を先に確定させるためである。各項目は直前に採用した構成を基準に測る。 |
| 手の分類 | 手選択器`MovePicker`が、返す手とともに捕獲手かどうかを返す。捕獲手は捕獲専用生成が返した手と、捕獲手である置換表の記録手であり、それ以外を静かな手とする。現行は同じ手について`move_order_key`を順序付け、futility pruningの判定、LMRの判定、β打ち切りの記録で繰り返し呼び、捕獲升ごとの駒価値の合計を毎回計算し直している。分類は生成の段階で決まるので、手と一緒に運べば再計算が要らず、後続の項目もこの分類を使う。捕獲専用生成は相手駒を1枚以上取る手だけを返し、`move_order_key`は取る駒の価値の合計が正のときに`Some`を返し、全駒種の駒価値は正なので、両者が捕獲手とする集合は一致する。したがって探索の挙動は変わらず、benchの総ノード数の一致で確認する。 |
| 重複計算の除去の採否 | この項目は高速化ではなく重複の除去であり、上位計画がNPS3%以上の事前ゲートを課す高速化項目には当たらない。採否はbenchの総ノード数が段階開始版と一致し、NPS中央値が段階開始版を下回らないことで決める。時間制御GSPRTは行わず、この扱いは上位計画の段階5の節にも明記する。同じ手を同じ位置で探索する変更なので、後続の各項目の採否測定は、この変更を含む構成を基準に行う。 |
| history表の構成 | 現行の手番側・移動元・移動先で引く表（butterfly表）を残し、手番側・駒種・到達升で引く表（piece-to表）を加える。順序付けとLMRの判定に使うhistory値は、その手について採用済みの全表の値の合計とする。駒種は`PieceKind`の29種で、着手前に移動元にある駒の種類とする。順序付けは着手前に行うので移動元の駒種が直ちに分かり、成る手も成る前の駒種で引く。移動元を駒種に置き換える案は、144升の盤で移動元の情報を失うので採らない。手番側・駒種・移動元・移動先の4次元表は2×29×144×144の約120万要素になり、1回の探索で各要素が受ける更新が少なすぎて順序付けの信号にならないので採らない。 |
| counter move historyとcontinuation history | 直前の相手の手（1手前）と2手前の自分の手のそれぞれについて、「その手の駒種と到達升」から「応手の駒種と到達升」を引く表を持つ。添字は`[29][144][29][144]`で、1表あたり約1,744万要素である。直前の手が同じノードでは、参照する部分表が29×144要素（`i16`で約8KB）の連続領域に収まり、一般的なL1データキャッシュ（32KB以上）に入るので、順序付けで1ノードあたり100手以上を引いても表の大きさは速度に響かない。直前の手の駒種と到達升は、探索がplyごとに保持する着手の記録から取り、null moveはそのplyの記録を空にする。記録が空のplyを参照する表は、参照せず更新もしない。直前の手を到達升だけで引く圧縮案は、表を29分の1にできるが、同じ升へ来る駒種の違いを区別できないので採らない。 |
| 表の要素型と初期化 | 追加する表の要素は`i16`とし、値の絶対値の上限は現行の`HISTORY_LIMIT`（16,384）に合わせ、加減算と合計は`i32`で行う。表は現行どおり根探索の開始時に初期化する。continuation historyの2表は1表約35MBになり、初期化の費用は実測前の見積りで1回の探索あたり数msなので、benchのNPSで費用を記録する。探索の間で表を持ち越す方式は初期化を省けるが、持ち越しの減衰という別の設計判断を伴うので本書では扱わない。 |
| historyの更新値 | β打ち切りを起こした静かな手への加点は`min(depth², 1,024)`とする。到達し得る深さ32以下では現行の`depth²`と同じであり、上限は`HISTORY_LIMIT`との和が`i16`に収まることを保証するためだけに置く。malusの導入までは現行どおり、いずれかの値が上限を超えたときに採用済みの全表を半減する。 |
| malusと更新式 | β打ち切りを起こした静かな手に加点し、同じノードでその手より前に探索した静かな手に同じ大きさを減点する。減点の対象は探索した手に限り、futility pruningで展開しなかった手は含めない。減点により値が負になるので、更新式を`v += bonus − v · |bonus| / HISTORY_LIMIT`（bonusは加点なら`+min(depth², 1,024)`、減点なら`−min(depth², 1,024)`）へ改める。この式はStockfishなどが用いる標準の更新式であり、`|bonus| ≤ HISTORY_LIMIT`なら値が`[−HISTORY_LIMIT, HISTORY_LIMIT]`を出ないことを帰納的に保証する。表全体の半減は、35MBの表では1回に数msから10ms程度を要する見積りであるうえ、減点で上限到達が頻発するので、この項目で廃止する。更新は採用済みの全表へ同じ値で行う。 |
| LMRの減深量 | 残り深さ`d`と手番号`m`（そのノードで先に探索した手の数。捕獲手と展開しなかった手も数え、現行の`index`と同じ）から、減深量を`r = clamp(T[d][m] + a, 0, min(3, d − 2))`で求める。`T[d][m] = floor(ln(d) · ln(m) / c)`は起動時に前計算する表で、`m = 0`の最初の手は全窓で読むので減深の対象にならず、手番号256以上は最後の列で引く。`a`は「history値による増減」で定める−1、0、+1のいずれかである。減深後の深さは1以上に保ち、静止探索へは落とさない。上限3は診断で測る減深量の範囲であり、STCの到達深さ5〜6で減深後の深さが1になる頻度を抑える。減深後の深さが1の探索は相手の応手を1手読んだだけで静止探索へ入るので、αを上回る誤った結果による読み直しが増えるためである。適用範囲は現行と同じく、置換表の記録手、捕獲手、killer手を除く静かな手であり、`d − 2 ≥ 1`から残り深さ3以上に限られる。現行の「4手目以降」の条件は式に置き換える。 |
| history値による増減 | 手のhistory値（採用済みの全表の合計）が`+H`以上なら`a = −1`、`−H`以下なら`a = +1`、それ以外は`a = 0`とする。`H`は診断で決める。連続的な比例増減（`r −= history / K`）は、`K`と切り詰めの2つの自由度を持ち込み、それぞれに診断と1つへの絞り込みが要るので採らない。 |
| 係数と閾値の決め方 | チェスや本将棋の値を流用せず、診断benchで測る。減深する手のうち「本来の深さの零窓探索がαを上回った手」を良い結果と定義し、候補の`(c, H)`を適用したときに、良い結果のうち減深した探索がα以下を返す割合（失う良い結果の割合）を、同じ標本に現行の規則（`index ≥ 3`なら1）を適用した割合と比べる。現行の割合を超えない組の中から、減深量の平均が最大の組を選ぶ（手続きと同率の処理は「診断による係数の決定」節）。段階4と同じ「10%以下」の絶対基準は採らない。[試行診断](../measurements/strength-stage5-lmr-trial-bench.md)で良い結果の基礎率が0.6%と低く、採用済みの現行の減深量そのものが良い結果の31.5%を失っていたため、絶対基準では現行構成すら適格にならないからである。基準は最初のSTCより前に決め、STCの結果を見てから変えない。同じ項目の係数違いをSTCの後に追加することは[docs/guides/sprt.md](../guides/sprt.md)が禁じる。 |
| 発動の事前確認 | 各項目は、実装前または実装直後の診断でbench深さ5の発動率が5%以上であることを確認する（[採否測定の条件で改良が発動することを実装前に確認する](../lessons/measure-feature-activation-before-sprt.md)）。history表の項目は、静かな手の順序付けで新しい表の値が0でない手の割合を発動率とする。malusは、当初は減点を受ける手の割合を発動率としたが、減点は以後のノードの順序付け全体へ波及するのでこの割合は発動を過小評価する（診断では3.99%だったがbenchの総ノード数は17.9%減った）。このため、malusの発動はbench深さ5の総ノード数が変化することで確認し、この置き換えはmalusのSTCより前に確定した。LMRの減深量は、診断で選んだ`(c, H)`で現行と異なる減深量になる対象手の割合を発動率とする。5%未満なら発動しない改良として見送り、その項目のフェーズは実行しない。 |
| 診断コードの扱い | 診断の計測はbenchへの一時的な変更で行い、コードは残さない。段階4と同じ扱いである。 |
| 未採用コードの扱い | 見送りとは実装前の診断で実装しないと決めること、不採用とは実装して採否測定で採らないと決めることをいう。不採用または見送りとなった項目はコードに残さず、設計だけを本書に保持する。 |

## 現行の順序付けとLMR

本書で使う探索の用語を先に定める。
探索は各ノードで「この値以上なら手番側にとって十分」という下限αと「この値以上なら相手が許さない」という上限βの窓を持ち、窓の幅が1（`β = α + 1`）の探索を零窓探索という。
零窓探索は真の値が窓のどちら側にあるかだけを答え、fail-softの実装では、返り値がβ以上ならその値は真の値の下界、α以下なら上界である。
詰みの値は`MATE − ply`（`ply`は根からの手数）で表し、絶対値が`MATE_THRESHOLD`以上の値の範囲を詰み帯という。

`negamax`は、置換表の照会、null move pruning、段階的な手選択による全手の探索、置換表への保存の順で進む。
手選択器`MovePicker`は、置換表の記録手、捕獲専用生成の手をMVV-LVA順、killer手2手、残りの静かな手をhistory降順の順に返す。
各手は`search_move`で探索され、最初の手は全窓（αからβまでの幅のある窓）、2手目以降は零窓で読み、減深した零窓探索がαを上回れば本来の深さの零窓探索で読み直し、それもαを上回りβを下回れば全窓で読み直す。
LMRは、残り深さ3以上で、置換表の記録手、捕獲手、killer手を除く4手目以降（`index ≥ 3`）の手を1だけ減深する。
β打ち切りを起こした静かな手は、killer表へ新しい順に記録され、history表の手番側・移動元・移動先の要素へ`depth²`が加点される。
いずれかの要素が`HISTORY_LIMIT`を超えると表全体を半減する。
history表とkiller表は根探索の開始時に初期化される。
根の手は反復のたびに`order_moves`で同じ順序付けキーにより整列され、置換表の記録手が先頭に置かれる。根ではLMRを行わない。

標準時間制御の到達深さは、STCで4〜6、LTCで6〜7である（[LTCの煙試験](../measurements/match-cost-ltc-smoke.md)）。
根の深さが`D`の探索は、根から`D − d`手進んだノードを残り深さ`d`で探索するので、残り深さ3以上のノードは両方の時間制御で現れる。

## 診断による係数の決定

診断は、benchの15局面を深さ6で探索し、一時的な計測で標本を採る。
根ではLMRを行わないので、標本の残り深さは3から5までになり、残り深さ6以上には式を外挿する。
計測の対象手は、残り深さ3以上のノードで探索された、置換表の記録手、捕獲手、killer手を除く静かな手のうち、手番号が1以上であり、かつfutility pruningで展開された手とする。
対象手ごとに、残り深さ`d`、手番号`m`、その時点のhistory値、および減深量`r`を`min(3, d − 2)`から0まで変えた零窓探索のそれぞれがαを上回ったかどうかを記録する。
副次的な探索は減深量の大きい順に行い、本来の深さ（`r = 0`）の探索を最後に行う。
置換表は深い探索の記録を浅い探索の打ち切りに使うので、深い探索を先に行うと浅い探索がその結果をそのまま返し、損失が見かけ上0になるためである。
本来の探索の流れには、現行の減深量（`index ≥ 3`なら1、それ以外は0）に対応する記録済みの結果を使い、読み直しの手順は変えない。
副次的な探索の内部では計測を行わず、置換表、killer表、およびhistory表への副次的な探索の書き込みが本来の探索へ及ぼす変化は許容する。

「本来の深さの零窓探索がαを上回った」は、fail-softで返る値が零窓の下界であることを利用した境界判定である。
減深した探索がα以下を返せばその手は読み直されないので、本来の深さならαを上回った手を減深で失うことになる。
減深した探索がαを上回れば本来の深さで読み直されるので、失うものはない。
参照探索は診断時点の現行探索であり、その値は完全探索の値ではないので、この割合は現行探索の結果に対する損失である。

候補の係数`c`は0.5から4.0までの0.25刻み、候補の閾値`H`は64から8,192までの2の冪、および増減なしの9通りとする。
閾値の下限は、malusを適用した探索でhistory値の99%点が442、1%点が−84であった試行診断に合わせ、分布の内側に候補が置かれるように定めた。
`c`の範囲は、チェスのStockfishが用いる`r ≈ 0.47 · ln(d) · ln(m)`に相当する`c ≈ 2.1`を中心に、4倍積極的な値から2倍保守的な値までを覆う。
各`(c, H)`について、対象手ごとに減深量を「LMRの減深量」の式で求め、良い結果（`r = 0`の探索がαを上回った手）のうち、その減深量の探索がα以下を返した手の割合を計算する。
同じ標本に現行の規則（`index ≥ 3`なら1、それ以外は0）を適用した失う割合と減深量の平均も計算する。
失う割合が全体で現行以下であり、かつ対象手が1,000件以上で良い結果が1件以上ある残り深さのそれぞれでも現行以下である組を適格とする。
対象手が1,000件未満または良い結果が0件の残り深さは、深さごとの制約からは外し、全体の割合にだけ算入する。
全深さを合わせた良い結果が0件なら、割合を定義できないので診断不足として減深量の式を見送る。
1,000件は段階4と同じ基準であり、対象件数が0件または少数の深さを損失0%とみなして適格と判定することはしない。
適格な組の中から、対象手の減深量の平均が最大の組を選び、同率なら失う割合が小さい組、なお同率なら`c`が大きい組、なお同率なら`H`が大きい（増減なしを最大とする）組を選ぶ。
適格な組がない場合、または選んだ組の減深量の平均が現行と同じ場合は、減深量の式は見送り、現行の固定1を保つ。
残り深さごとに対象件数、良い結果の件数、および候補ごとの失う件数を記録する。
閾値の候補がhistory値の実際の分布から外れていないことを確かめるため、history値の分位点も記録する。
決めた値は「採用した係数」節へ表として記録し、STC以降は変えない。
分布を採るための計測コードは残さず、候補の評価はスクリプトで行う。

## 採用した係数

フェーズ6の[診断bench](../measurements/strength-stage5-lmr-bench.md)で確定した値は次のとおりである。
historyの最終構成はbutterfly表だけである。

| 項目 | 値 |
|---|---|
| 係数`c` | 2.00 |
| 閾値`H` | 128 |
| 失う良い結果の割合（全体） | 27.9%（現行の規則は35.5%） |
| 減深量の平均 | 1.557（現行の規則は0.999） |
| 発動率 | 60.3% |

残り深さごとの失う割合は3、4、5の順に19.5%、40.5%、32.0%であり、いずれも現行の規則（31.5%、41.1%、40.0%）以下である。

## 各項目の実装

### 順序付けキーの重複計算の除去

`MovePicker::next`が返す値を、手と捕獲手かどうかの組にする。
捕獲専用生成の段階で返す手は捕獲手、静かな手の生成の段階とkiller手の段階で返す手は静かな手であり、置換表の記録手だけは`move_order_key`で1回分類する。
`negamax`のfutility pruningの判定、LMRの判定、およびβ打ち切りの記録は、この分類を使い`move_order_key`を呼ばない。
静止探索と根の順序付けは変更しない。

### 駒種と到達升で引くhistory

`[COLOR_COUNT][PIECE_KIND_COUNT][BOARD_SQUARE_COUNT]`の`i16`表を`Searcher`へ加える。
静かな手の順序付けキーとLMRの判定に使うhistory値を、butterfly表とpiece-to表の合計にする。
β打ち切りの記録では両表へ同じ値を加点し、半減の判定はいずれかの表の要素が上限を超えたときに両表を半減する。
根の`order_moves`も同じ合計を使う。

### counter move history

`[PIECE_KIND_COUNT][BOARD_SQUARE_COUNT][PIECE_KIND_COUNT][BOARD_SQUARE_COUNT]`の`i16`表を`Searcher`へ加え、plyごとに「その手で動いた駒の駒種と到達升」を記録する配列を持つ。
`search_move`は着手のたびにそのplyの記録を上書きし、null moveはそのplyの記録を空にする。
ply `p`のノードでは、ply `p − 1`の記録が空でないときに限り、その記録で引いた部分表を静かな手の駒種と到達升で参照し、history値の合計に加える。
β打ち切りの記録も同じ部分表へ行う。
根（ply 0）では直前の手の記録がないので参照しない。

### continuation history

counter move historyと同じ形の表をもう1つ加え、ply `p − 2`の記録で引く。
参照と更新の規則はcounter move historyと同じであり、ply `p − 1`がnull moveで空でもply `p − 2`の記録が空でなければ参照する。
2つの表は互いに独立に、それぞれの参照元の記録だけで参照の可否を決める。

### malus

`negamax`が、そのノードで探索した静かな手を順に保持する。
β打ち切りを起こした静かな手には採用済みの全表へ`+min(depth², 1,024)`、それより前に探索した静かな手には`−min(depth², 1,024)`を、更新式`v += bonus − v · |bonus| / HISTORY_LIMIT`で適用する。
表全体の半減は廃止する。
killer表の更新は変えない。

### LMRの減深量

起動時に残り深さと手番号の組ごとの減深量表`T`を`floor(ln(d) · ln(m) / c)`で前計算する。
手番号の列数は256とし、それ以上の手番号は最後の列で引く。中将棋でも1局面の合法手が256を超えることは稀であり、超えた手は既に上限3で切り詰められるためである。
`negamax`の減深量を`clamp(T[d][m] + a, 0, min(3, d − 2))`にする。
適用範囲の条件（置換表の記録手、捕獲手、killer手を除く）は変えず、`index ≥ 3`の条件は外す。
`search_move`の読み直しの手順は変えない。

## 実装フェーズ

### フェーズ1　順序付けキーの重複計算の除去

段階開始版に手の分類を実装し、release版benchを変更前と変更後でそれぞれ3回実行して総ノード数の一致とNPS中央値を記録する。
総ノード数が一致し、NPS中央値が低下していなければ採用し、結果は[strength-stage5-order-key-bench](../measurements/strength-stage5-order-key-bench.md)へ記録する。
探索の挙動を変えない変更なので、時間制御GSPRTは行わない。
完了条件は、`negamax`が`move_order_key`を呼ばなくなり、benchの総ノード数が段階開始版と一致していることである。

### フェーズ2　駒種と到達升で引くhistory

piece-to表を実装し、benchで発動率を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ3　counter move history

plyごとの着手の記録とcounter move historyを実装し、benchで発動率とNPSの変化を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。
不採用なら、plyごとの着手の記録も含めて外す。
continuation historyも同じ記録を必要とするので、その場合はフェーズ4で改めて入れる。

### フェーズ4　continuation history

continuation historyを実装し、benchで発動率とNPSの変化を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ5　malus

malusと更新式を実装し、benchで発動率を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。
更新式が値を上限内に収めることを単体テストで固定する。

### フェーズ6　LMRの減深量

フェーズ5までの採否が確定した構成のbenchで「診断による係数の決定」節の標本を採り、`(c, H)`を決めて[strength-stage5-lmr-bench](../measurements/strength-stage5-lmr-bench.md)へ記録し、「採用した係数」節へ書く。
適格な組がなければ見送る。
実装後に発動率を確かめ、直前の採用構成とのSTCとLTCで採否を決める。
減深量の表と切り詰めを単体テストで固定する。

### フェーズ7　進捗指標の記録

全項目の採否が確定した後に、段階開始版との固定200ペアEloをSTCで、HaChu戦の固定200ペアEloを`time=60000+1000`で記録する。
採用項目がフェーズ1だけで、benchの総ノード数が段階開始版と一致する場合は、段階開始版との比較を省略し、HaChu戦だけを記録する。

## 検証

- 手の分類のテストは、置換表の記録手が捕獲手と静かな手のそれぞれの場合に分類が`move_order_key`と一致することと、捕獲専用生成が返す全手について分類が捕獲手になることを固定する。
- history表のテストは、β打ち切りを起こした静かな手についてbutterfly表とpiece-to表の両方が更新されることと、成る手が成る前の駒種で引かれることを固定する。
- counter move historyとcontinuation historyのテストは、null moveがそのplyの記録を空にすること、記録が空のplyを参照元とする表は参照も更新もしないこと、直前がnull moveでも2手前の記録があればcontinuation historyは参照すること、および根では直前の手の記録がないことを固定する。
- malusのテストは、β打ち切りより前に探索した静かな手が減点され、futility pruningで展開しなかった手が減点されないこと、および更新式を上限値に繰り返し適用しても値が`[−HISTORY_LIMIT, HISTORY_LIMIT]`を出ないことを固定する。
- LMRのテストは、減深量表`T`の生成規則（`m = 1`で0、選んだ`c`での代表値、および切り詰め前の`T`は3を超え得ること）と、最終の減深量`r`の規則（`T`が4以上で`a = −1`でも`r = 3`になること、history値が`+H`以上で1減り`−H`以下で1増えること、`[0, min(3, d − 2)]`に収まること、および減深後の深さが1を下回らないこと）を分けて固定する。
- 各変更後に`cargo test`、`cargo clippy --all-targets --all-features -- -D warnings`、および`cargo fmt --check`が成功する。
- フェーズ1はbenchの総ノード数が一致することを、フェーズ2以降は総ノード数の変化が意図した項目だけによることを確認する。
- 採否測定は`docs/guides/sprt.md`のコミット対コミット測定に従い、各測定の`time_forfeits`と異常件数を記録する。測定名は`strength-stage5-<項目>-stc`および`-ltc`とし、項目は`piece-history`、`cmh`、`continuation`、`malus`、`lmr`とする。

## 完了条件

次の条件をすべて満たしたとき、本マイルストーンを完了とする。

- 順序付けキーの重複計算の除去、駒種と到達升で引くhistory、counter move history、continuation history、malus、およびLMRの減深量の採否または見送りが個別の測定記録に残り、不採用の実装がコードに残っていない。
- 採用した項目について、テスト、Clippy、および整形検査が成功し、historyの更新とLMRの減深量がテストで固定されている。
- LMRの減深量を実装した場合は、「採用した係数」節に係数、閾値、失う良い結果の割合、および発動率が記録されている。
- HaChu戦の固定200ペアEloが測定記録に残り、探索の挙動を変える採用項目が1つでもあれば段階開始版との固定200ペアEloも残っている。
- [棋力向上の段階計画](strength-stages.md)の段階5の節と docs/ROADMAP.md の状態表が更新されている。

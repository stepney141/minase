# 棋力向上段階6

## 先に読む要約

本マイルストーンは、反復深化（深さ1から1ずつ読みを深める探索の外殻）の各反復で探索窓を前回の評価値の近傍に絞るaspiration windows、置換表（探索済み局面の結果を保存して再利用する表）の改良、詰み探索と順序付けに関わる2つの枝刈り、および時間管理の適応的な延長と早期終了を、1項目ずつ採否判定する。
探索は各ノードで「この値以上なら手番側にとって十分」という下限αと「この値以上なら相手が許さない」という上限βの窓を持ち、真の値が窓の外にあるときは、窓の端を超えたことだけを答える（fail-soft）。
aspiration windowsは、前回の反復の評価値を中心にした狭い窓で根を読み始め、窓を外れた側を広げて読み直すことで、大半の反復を狭い窓の速い探索で済ませる手法である。
時間管理は、反復の完了時に標準予算softと上限hardで次の反復へ入るかを決めており、本書はaspiration windowsの窓外れのうち評価値が前回の反復より窓の幅を超えて下がるfail-low（最善手が崩れた兆候）と、反復の間で最善手が入れ替わったことを、次の反復へ入るかの判断からsoftの条件を一時的に外す信号（延長）として使う。
上位計画が挙げる項目のうち、静的評価の置換表保存とmate distance pruningは、着手時の診断で発動率（採否測定の条件でその改良が働く手やノードの割合）または効果の上限が段階5までと同じ事前基準を下回ったため実装せずに見送り、置換表のクラスタ化（1スロットに4エントリを置き、最も古く浅い記録を置き換える方式）は実装後の固定深さの対局再生で総ノード数が0.14%しか減らず基準の3%に届かなかったため採否測定へ進めずに外した。
aspiration windows、internal iterative reduction（置換表の記録手がないノードを1だけ浅く読む手法）、fail-lowによる延長、最善手交替時の延長、および最善手が4反復続けて同じときに次の反復を予測完了時刻がsoft以内の場合に限る早期終了の5項目を実装して測る。
係数の再調整は、5項目の採否が確定した構成で反復の所要時間比と対局長を再導出し、現行値との差が20%を超える場合だけ1回の測定を行う。
採否は項目ごとに、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/sprt.md](../sprt.md)）で判定する。
完了条件は、各項目の採否または見送りが測定記録に残り、採用した窓の規則、減深、および時間管理の判断がテストで固定され、外部エンジンHaChuに対する固定200ペアのElo（採否には使わない進捗指標）と、採用項目が1つでもあれば段階開始版（本書の着手時点のコミット）に対する同じEloが記録されていることである。

## 状態

本マイルストーンは2026年9月10日に起案して同日に着手し、進行中である。
着手時の診断として、[保存記録の再構成](../measurements/strength-stage6-records-profile.md)、[置換表と記録手の診断bench](../measurements/strength-stage6-tt-bench.md)、[置換表の対局再生診断](../measurements/strength-stage6-tt-replay.md)、[評価の費用のbench](../measurements/strength-stage6-eval-cost-bench.md)、および[反復深化の診断](../measurements/strength-stage6-iteration-diag.md)を終え、静的評価の置換表保存とmate distance pruningを見送った。
aspiration windows（[bench](../measurements/strength-stage6-aspiration-bench.md)）、置換表のクラスタ化、internal iterative reduction（[bench](../measurements/strength-stage6-iir-bench.md)）、および時間管理の3項目（[信号の計数](../measurements/strength-stage6-time-signals-diag.md)）を実装し、クラスタ化は[固定深さの対局再生](../measurements/strength-stage6-tt-cluster-replay.md)で総ノード数の減少が0.14%と基準の3%に届かなかったため採否測定へ進めずに外した。
aspiration windowsは段階開始版との[STC](../measurements/strength-stage6-aspiration-stc.md)と[LTC](../measurements/strength-stage6-aspiration-ltc.md)がともに`H1`かつ異常0件で採用した。
internal iterative reductionは[STC](../measurements/strength-stage6-iir-stc.md)が`H1`、[LTC](../measurements/strength-stage6-iir-ltc.md)も`H1`だが、LTCの途中で外部のOOMによる約33秒の停止が起こり時間切れが11件（候補側6件、基準側5件）出たため、docs/sprt.md の採用条件（時間切れ0件）からの逸脱を伴う採用の可否を利用者の決定に委ねている（該当ペアを除いてもLLR +3.11で`H1`）。
fail-lowによる延長は、この構成を暫定の基準とする[STC](../measurements/strength-stage6-faillow-stc.md)が`H0`となり不採用とし、実装を外した。
最善手交替時の延長も同じ暫定の基準との[STC](../measurements/strength-stage6-bmchange-stc.md)が`H0`となり不採用とし、実装を外した。
最善手安定時の早期終了は延長の信号を持たない形で実装し（コミット8f4e41c）、同じ暫定の基準との[STC](../measurements/strength-stage6-stable-stc.md)が`H1`となり、LTCを実行中である。
次の一手は、利用者の決定を受けてinternal iterative reductionの採否を確定し、最善手安定時の早期終了のSTCとLTC、係数の再導出、および進捗指標の記録へ進むことである。

## 目的

本マイルストーンは、同じ持ち時間でより深く読むための探索窓の制御と、読みが不安定な局面へ時間を寄せる時間管理の判断を、現状の実測に基づいて1項目ずつ確定する。
持ち時間を2倍にしただけで自己対局の固定200ペアが+216 Eloになった実測（[棋力向上の段階計画](strength-stages.md)の現状の診断）が示すとおり、探索量の増加はそのまま棋力へ転化するので、同じ時間で反復を1つ深く進める窓の制御は棋力に直結する。
一方、時間管理の延長は総時間を増やさず配分を変えるだけなので、効果は自己対局でしか確かめられない。
各変更の効果を個別に測定し、効果が確認できない複雑化をコードへ残さない。

## 適用範囲

本書は、根の反復深化の探索窓、`negamax`が置換表の記録手を持たないノードで行う減深、反復の完了時に次の反復へ入るかの判断、および時間管理の係数の再導出を扱う。
置換表については、スロットの構成と置換方針を扱い、エントリの16バイト2語の配置と原子操作の契約（[Lazy SMP](lazy-smp.md)）は変更しない。
前向き枝刈りの余裕値、指し手順序付け、静止探索、評価関数の重み、および合法手の定義は変更しない。
秒読みを含む予算式の変更は、標準のSTCとLTCに秒読みがなく発動を確認できないため対象外とし、[棋力向上段階2](strength-stage2.md)の煙試験による安全性の確認を保つ。

## 依存関係

探索とbenchの契約は[探索部](search.md)に従い、aspiration windowsの仕様は同書が「第2層の探索改良」節に保持する設計を出発点とする。
時間管理の予算式、反復継続の判断、および停止理由の記録は[棋力向上段階2](strength-stage2.md)が所有し、本書はその判断へ信号を加える。
前向き枝刈りの範囲は[棋力向上段階4](strength-stage4.md)、順序付けとLMRは[棋力向上段階5](strength-stage5.md)が所有し、本書は変更しない。
機能採否の時間制御GSPRTは[SPRTによる棋力測定の手引き](../sprt.md)と[棋力測定の段階ゲート](match-staged-gate.md)に従う。
段階の順序、項目、共通の採否基準、および全体の完了条件は[棋力向上の段階計画](strength-stages.md)が所有し、本書は段階6の実装方式、検証範囲、および不採用時の処理を具体化する。
対局ハーネスは手ごとの記録に完了深さ、評価値、停止理由、および完了反復の経過時間を保存しており（段階2の停止理由の記録）、本書の発動確認はその記録から再構成する。

## 設計判断

| 項目 | 決定 |
|---|---|
| 項目の順序 | aspiration windows、置換表のクラスタ化、internal iterative reduction、fail-lowによる延長、最善手交替時の延長、最善手安定時の早期終了、係数の再導出の順に進める。fail-lowの検出はaspiration windowsの窓外れで定義するので、窓の制御を先に確定する。置換表のクラスタ化は記録手の保持を変えるので、記録手の有無で減深するinternal iterative reductionより先に置く。時間管理の3項目は探索木を変えないが、反復の所要時間は探索木に依存するので、探索を変える3項目の後に置く。早期終了は延長の2項目の後に置く。安定の判定は延長の信号がないことを前提にするので、延長の採否を先に確定すれば早期終了の規則を1つに固定できるためである。係数の再導出は反復の所要時間と対局長に依存するため最後に置く。各項目は直前に採用した構成を基準に測る。 |
| 見送りの規則 | 見送りとは実装前の診断で実装しないと決めること、不採用とは実装して採否測定で採らないと決めることをいう。探索木を変える項目は、bench（固定局面集を固定深さで探索する速度計測コマンド）の深さ6で発動率が5%以上であることを確認する（[採否測定の条件で改良が発動することを実装前に確認する](../lessons/measure-feature-activation-before-sprt.md)）。深さ6は、段階5の保存記録でSTCの完了深さの最頻値が6、LTCが8であることから、両時間制御で到達する深さとして選んだ。発動率を対局の記録から求められる項目は、記録の手の割合で判定する。探索の挙動を変えない高速化は、上位計画の事前ゲートに従いNPS（1秒あたり探索ノード数）の改善が3%以上見込めない場合に見送る。診断の結果は測定記録へ残し、見送った項目の設計は本書に保持する。 |
| 窓の幅 | 初期の窓の半幅は`δ₀ = pawn_value / 2`とする。採用中の学習PST（駒種と升の組ごとの重みを学習した線形評価関数）の歩兵の駒価値は100なので、探索部設計書の仕様である±50と同じ値になる。駒価値で定義するのは、評価尺度が変わっても窓の意味を保つためである。[反復深化の診断](../measurements/strength-stage6-iteration-diag.md)では、深さ5から8までの反復で評価値が前回から50を超えて動く割合が24.3%であり、窓外れが少数派で読み直しが多数派にならない範囲にある。半幅の候補を複数測ることはせず、探索部設計書の仕様を保つ。同じ項目の係数違いをSTCの後に追加することは[docs/sprt.md](../sprt.md)が禁じる。 |
| 窓の適用条件と拡大 | 深さ5以上の反復で、同じワーカーが直前に完了した反復の評価値`prev`が詰み帯（絶対値が`MATE_THRESHOLD`以上の範囲）にない場合に、窓`[prev − δ, prev + δ]`（`δ = δ₀`）で根を探索する。深さ4以下、直前の完了反復がない場合、および`prev`が詰み帯にある場合は全窓`[−INFINITY, INFINITY]`を使う。結果`s`が`s ≤ α`ならfail-lowとしてαを`α − δ`へ下げ、`s ≥ β`ならfail-highとしてβを`β + δ`へ上げ、いずれの場合も`δ`を2倍にして同じ深さを読み直す。外れなかった側の端は動かさない。下げたαが`−MATE_THRESHOLD`以下になれば`−INFINITY`、上げたβが`MATE_THRESHOLD`以上になれば`INFINITY`へ置き換え、以後その側は広げない。この置き換えは初期窓の端にも適用する。`prev`が詰み帯の直前にあると初期窓の端が詰み帯へ掛かるためである。判定は`s ≤ α`と`s ≥ β`の等号を含み、fail-lowとfail-highが交互に起こっても`δ`が倍々に増えるので読み直しは有限回で終わる。窓の内側に収まった結果だけを反復の完了として採用する。Stockfishのように外れなかった側を中点へ寄せる方式は、読み直しの回数を減らす一方で窓の意味を複雑にするので採らない。 |
| 根の探索の窓化 | `search_root`は窓`(α, β)`を受け取る。最初の手を全窓、2手目以降を零窓（幅1の窓）で読み、窓内なら全窓で読み直す現行のPVSは変えない。現行の根にはβ打ち切りがないので、最善値と最善手をαの更新とは独立に更新し、最善値がβ以上になった時点で残りの手を読まずに打ち切る。根の置換表への保存は、最善値が入力時のα以下なら上界、β以上なら下界、それ以外なら正確な値として記録し、記録手は最善値を与えた手とする。fail-lowの結果の最善手は各手の上界のうち最大のものにすぎないので、順序付けの助言としてだけ使い、主変化、`Progress`イベント、および採用結果には反映しない。読み直しのたびに置換表の記録手を照会し直すので、fail-highで打ち切った手とfail-lowで最大の上界を持った手が読み直しの先頭に来る。主ワーカーと補助ワーカーのいずれも、窓内で完了するまで採用済みの手、評価値、深さ、および主変化を更新せず、読み直しの途中で中断された場合は直前に完了した反復の結果を返す。窓を広げた読み直しが窓内に収まれば、その結果を通常の完了反復と同じく採用し、`Progress`で通知する。 |
| 補助ワーカーへの適用 | Lazy SMPの補助ワーカーも同じ規則で窓を使い、`prev`にはそのワーカー自身が直前に完了した反復（主ワーカーの反復ではなく、深さを飛ばした場合は2つ以上浅い反復）の評価値を使う。補助ワーカーは深さを飛ばすので窓外れが増え得るが、`Threads`の既定値は1であり、採否測定も`Threads=1`で行うので、補助ワーカーの窓は主ワーカーと同じ実装を共有することを優先する。 |
| fail-lowの定義と保持 | 1手の探索の中で、根のaspiration windowsが1回でもfail-lowを起こしたことを、その手の探索が終わるまで保持する。fail-highは保持しない。fail-highは評価値が上がる兆候であり、最善手を急いで確定しても損が小さいので、延長の信号をfail-lowに絞り、fail-highによる延長を別の項目にはしない。 |
| 窓外れの報告 | 窓を外れた探索はプロトコルへ出力しない。USIには`lowerbound`と`upperbound`の語彙があるが、対局ハーネスは最後の`info`行の深さと経過時間を手の記録として保存するので、窓外れの行を出すと、読み直しの途中でhard limitに達した手の記録が未完了の反復の値になり、保存記録からの時計の再構成を汚す。着手時の診断では、連続する反復の評価値の差が`δ₀`以上であることを窓外れの代理指標として数えたが、この代理指標は読み直しの回数、中断、および窓に依存する枝刈りの影響を含まないので、実装前の参考値にとどめる。実装後は「標準時間制御の予算での計数」節の手順で、窓を使った反復の数、両方向の窓外れ、読み直し、中断、および時間管理の信号が判断を変えた件数を一時的な計数で数える。 |
| 置換表のクラスタ化（実装後に外した） | 1スロットを64バイトに揃えた4エントリのクラスタにし、照会はクラスタ内で検証キーが一致する最初のエントリを返す。保存は、同じ検証キーのエントリがあれば現行と同じ規則（新しい深さが既存以上のときだけ置き換える）で扱い、なければ空のエントリを使い、空きもなければ古さ`age = generation.wrapping_sub(entry_generation)`（`u8`の周回差。現行の`store`と同じ）が最大のエントリ、同じ古さなら深さが最も浅いエントリ、なお同じなら添字の小さいエントリを置き換える。世代は`u8`で周回するので256世代差を0と区別できないが、これは現行と同じ制約である。深さと世代を重み付きで合成する置換優先度（Stockfishの`depth − 8·age`）は係数を1つ持ち込むので採らず、古さを深さより優先する順序だけで決める。エントリの16バイト2語の配置、検証キー、および原子操作の契約は変えず、スロット番号はクラスタ数のマスクで求める。同じ探索の中の衝突は、[置換表と記録手の診断bench](../measurements/strength-stage6-tt-bench.md)で深い記録の0.07%、[置換表の対局再生診断](../measurements/strength-stage6-tt-replay.md)で0.01%にすぎないが、対局中は現行の直接マップが過去の世代の記録を深さによらず置き換えるため、再生診断では静止探索の浅い記録が過去の世代の深い記録を上書きする保存が全保存の7.1%（LTC相当では12.2%）を占め、残り深さ1以上の記録1件あたり0.39件（同0.54件）が失われる。深い記録による上書きも合わせると全保存の8.3%（同15.3%）になる。発動率の判定には浅い記録による上書きの割合を使い、クラスタ化はこの上書きを直接減らす変更であって基準5%を満たすので実装した。しかし[固定深さの対局再生](../measurements/strength-stage6-tt-cluster-replay.md)では、上書きは14%減ったものの照合成功率は25.9%で変わらず、固定深さ6の総ノード数の減少は0.14%でフェーズ2の基準3%に届かなかったので、採否測定へ進めずに実装を外した。古さを深さより優先する置換順序では、深い過去の記録がクラスタ内で最古になれば依然として追い出されるためと考えられるが、深さを重み付けする置換優先度は係数を要するので本段階では試さない。HaChu対minaseの条件格子測定（[hachu-condition-grid.md](hachu-condition-grid.md)）で置換表容量を16倍変えても差が検出されなかったことは、効果が固定200ペアの分解能（約±40 Elo）を下回る可能性を示すが、上限の証明ではないので見送りの根拠にしない。 |
| 静的評価の置換表保存の見送り | 評価関数は段階1の差分更新により、plyごとの累算値から定数時間の補間で求まる。[評価の費用のbench](../measurements/strength-stage6-eval-cost-bench.md)では、通常探索と静止探索の各ノードで評価を10回余分に計算すると処理時間が2.4%増えたので、評価1回の費用はノードの処理時間の0.24%である。置換表に保存しても省けるのは置換表に当たったノードの評価1回分にすぎず、上位計画が高速化の事前ゲートとする3%に届かないので見送る。 |

| fail-lowによる延長 | その手の探索でfail-lowを保持している間は、反復の完了時の判断からsoftの条件を外し、「経過時間に固定比を掛けた予測完了時刻がhard以下」だけで次の反復へ入るかを決める。判断は固定比`r = 2.5`を使う1つの純粋関数`r·elapsed ≤ hard かつ (extend または (stable なら r·elapsed ≤ soft、それ以外は elapsed < soft))`に統合し、`extend`は延長の信号、`stable`は「最善手安定時の早期終了」の条件（`extend`が偽のときだけ真になり得る）である。延長の余地は経過時間の上限で`hard / r − soft`であり、`hard < r·soft`なら延長は起こらない。`hard = r·soft`では経過時間がちょうど`soft`のときだけ判断が変わる（通常は止まり、延長時は続ける）。持ち時間が十分でhardが`4·soft`のときは、次の反復へ入る上限が経過時間`soft`から`1.6·soft`へ伸びる。残り時間が乏しく`hard = remaining / 4`が拘束する局面では余地が縮み、STCの200手目以降の典型（残り0.58秒、加算0.1秒でsoft 76ms、hard 145ms）では延長が起こらないが、残り時間が加算の10倍程度を超える局面（300手目、残り1,000ms、加算100msでsoft 80ms、hard 250ms）では上限が100msまで伸びる。いずれの場合もhardの予測とhard limitの探索中の検査の内側にあるので、hard limitの範囲内という上位計画の条件を満たす。新しい係数は導入せず、延長の幅はhardの予測だけで決める。 |

## 現状の探索と時間管理

本書で使う探索の用語を先に定める。
探索は各ノードで下限αと上限βの窓を持ち、fail-softの実装では、返り値がβ以上ならその値は真の値の下界、α以下なら上界である。
詰みの値は`MATE − ply`（`ply`は根からの手数）で表し、絶対値が`MATE_THRESHOLD`以上の値の範囲を詰み帯という。

主ワーカーは深さ1から順に`search_root`を呼び、根を常に全窓`[−INFINITY, INFINITY]`で探索する。
根では最初の手を全窓、2手目以降を零窓で読み、窓内なら全窓で読み直す。
完了した反復の最善手、評価値、および主変化を採用結果とし、`Progress`イベントで通知する。
`negamax`は、置換表の照会、null move pruning、futility pruningの余裕値の計算、段階的な手選択による全手の探索、置換表への保存の順で進み、置換表の記録手がないノードでも本来の残り深さで探索する。

時間管理は、`soft = min(soft_raw, hard)`と`hard = min(4·soft_raw, remaining / 4 + 0.8·byoyomi, safe_hard)`の二段リミットを持つ（式は段階2）。
主ワーカーは反復の完了時に、経過時間がsoft未満で、かつ経過時間に固定比2.5を掛けた予測完了時刻がhard以下の場合だけ次の深さへ入る。
どちらかを満たさなければsoftによる停止として現在の最善手を返し、探索中にhardへ達すれば直前の完了反復の最善手を返す。

段階5の保存記録（[保存記録の再構成](../measurements/strength-stage6-records-profile.md)）では、候補側の完了深さはSTCで最頻値6（深さ5以上が96.8%）、LTCで最頻値8（深さ5以上が99.9%）であり、hard limitによる打ち切りはSTCで12.3%、LTCで9.8%である。
残り時間の中央値は、STCでは200手目以降に約0.6秒、LTCでは300手目以降に約1.2から1.5秒へ落ち着き、基本時間はそれまでに使い切られている。

## 標準時間制御の予算での計数

窓外れと時間管理の信号は、固定深さのbenchでは時間の判断が働かず、対局の記録では反復の列が残らないので、実装後に一時的な計数で数える。
[反復深化の診断](../measurements/strength-stage6-iteration-diag.md)と同じ240局面に、STCとLTCのそれぞれについて、その局面の手数帯で[保存記録の再構成](../measurements/strength-stage6-records-profile.md)が示す候補側の着手前残り時間の中央値を両側の残り時間に、加算をSTCで100ms、LTCで200msとしてUSIの`go`を与える。
エンジンは計数を`info string`で報告し、スクリプトが集計する。
各局面は新しいプロセスで探索し、置換表は空から始め、着手列は`position startpos moves`で復元し、10プロセスを並列に走らせる。
数えるのは、窓を使った反復の数、fail-lowとfail-highの回数、読み直しの回数、読み直しの途中で中断された回数、および時間管理の各信号が次の反復へ入るかの判断を実際に変えた件数である。
判断を変えた件数は、完了した反復ごとの判断について、同じ経過時間と状態で直前の採用構成の判断と当該項目の信号を加えた判断を並べて評価し、結果が異なる件数（分子）とする。
先に採用した延長が既に続行を決めている判断は、後の項目の分子に数えない。
発動率の分母は局面数（1局面につき1手の探索）とする。
1手の反復深化では最初の数反復の判断が経過時間の不足でどの規則でも続行になり、判断数を分母にすると時間管理が働く単位である1手の停止の判断が薄まるためである。
[時間管理の信号の計数](../measurements/strength-stage6-time-signals-diag.md)の最初の計数では、判断数を分母にした割合が3項目とも1.1〜3.4%、局面数を分母にした割合が7.5〜21.3%であり、当初は判断数を分母と定めていたが、この結果を受けて各項目のSTCの開始前に分母を局面数へ改めた。
判定はSTCとLTCのそれぞれで行い、いずれかで分子が分母の5%未満なら、その項目は発動しない改良として見送る。
計数コードは残さず、結果は各項目の測定記録に含める。

## 各項目の実装

### aspiration windows

`search_root`に窓`(α, β)`の引数を加え、最善値がβ以上になった時点で残りの手を読まずに打ち切り、置換表への保存の種別を入力時のαとβから分類する。
反復深化の各ワーカーは、深さ`d`の反復について次の手順で根を探索する。

1. `d < 5`、直前に完了した反復がない、または`prev`が詰み帯にあるなら、全窓で`search_root`を1回呼び、その結果を採用して終える。
2. それ以外は`δ = δ₀`とし、`α = prev − δ`、`β = prev + δ`を初期窓とする。初期窓にも手順5の置き換えを適用する。
3. 窓`(α, β)`で`search_root`を呼ぶ。中断で`None`が返れば、反復を完了せずに直前の採用結果を保って終える。
4. 結果`s`が`α < s < β`なら採用して終える。`s ≤ α`ならfail-lowを保持して`α`を`α − δ`へ下げ、`s ≥ β`なら`β`を`β + δ`へ上げる。外れなかった側は動かさない。
5. `α`が`−MATE_THRESHOLD`以下なら`−INFINITY`、`β`が`MATE_THRESHOLD`以上なら`INFINITY`へ置き換える。無限になった側は以後広げない。
6. `δ`を2倍にして手順3へ戻る。

`δ₀`は`Pst::pawn_value() / 2`で求める。
窓の初期化と拡大は経過時間や乱数を受けない純粋関数にし、単体テストで固定する。

### 置換表のクラスタ化

`TranspositionTable`のエントリ配列を、`#[repr(align(64))]`の4エントリのクラスタ配列にし、容量に収まる最大の2の冪個のクラスタを確保する。
`probe`はクラスタ内の4エントリを順に読み、検証キーが一致する最初のエントリの探索値と記録手を返す。
`store`は、同じ検証キーのエントリがあれば現行の同一局面の規則で置き換え、なければ空のエントリ、空きもなければ周回差の古さが最大で、同じ古さなら深さが最も浅く、なお同じなら添字が最小のエントリを置き換える。
エントリの2語の書き込み順（`advisory`をRelaxedで書いた後に`critical`をReleaseで公開）と読み取り順は変えない。

### internal iterative reduction

`negamax`の置換表の照会の直後に、残り深さが3以上で記録手がなければ残り深さを1減らす。
減らした深さを以後のnull move pruning、futility pruning、LMR、および置換表への保存に使う。
根の探索は対象にしない。

### fail-lowによる延長

反復の完了時の判断を、経過時間、予算、およびsoftの条件を外すかの真偽値を受ける純粋関数にする。
主ワーカーは、その手の探索でfail-lowを保持している間は真偽値を真にして呼ぶ。
停止理由の語彙は変えず、延長中にhardの予測で止まった場合もsoftによる停止として報告する。

### 最善手交替時の延長

主ワーカーは、完了した反復の最善手が直前の完了反復の最善手と異なる場合、その直後の判断だけ真偽値を真にする。
深さ1の完了時は直前の反復がないので偽とする。
fail-lowによる延長が採用済みなら、両方の信号の論理和を渡す。

### 最善手安定時の早期終了

主ワーカーは、完了した反復の最善手を深さ順に保持し、直近4反復の最善手が同じで、かつ採用済みの延長の信号がない場合、判断の純粋関数に「予測完了時刻をsoftで抑える」真偽値を真にして渡す。
判断は「fail-lowによる延長」の統合式に従い、`extend`が真ならsoftの条件を外し、`extend`が偽で`stable`が真なら「経過時間に固定比を掛けた予測完了時刻がsoft以下」、いずれも偽なら「経過時間がsoft未満」をsoftの条件とし、hardの条件をそのまま重ねる。
深さ4未満の完了時は4反復が揃わないので偽とする。

### 係数の再導出

最終構成のリリースバイナリで、[反復深化の診断](../measurements/strength-stage6-iteration-diag.md)と同じ局面と手順により深さ8までの反復の所要時間を採り、深さ5から8までの累積時間比の中央値を求める。
段階6のSTCとLTCの保存記録から、段階2と同じ手数帯ごとの条件付き期待残り手数と、終局時の残り時間の中央値を求める。
設計判断の基準を満たす項目があれば、再導出した値を1組として実装し、直前の採用構成とのSTCとLTCで採否を決める。

## 実装フェーズ

### フェーズ0　着手時の診断

段階開始版で、保存記録の再構成、置換表と記録手の診断bench、評価の費用のbench、および反復深化の診断を行い、見送る項目を確定する。
このフェーズは完了しており、結果は「状態」節の測定記録が持つ。

### フェーズ1　aspiration windows

窓の制御を実装し、benchで深さ5と6の総ノード数の変化を記録し、「標準時間制御の予算での計数」節の手順で窓を使った反復の数、両方向の窓外れ、読み直し、および中断の回数を記録したうえで、段階開始版とのSTCとLTCで採否を決める。発動は保存記録で確認済みなので、この計数は判定基準ではなく記録である。
窓の計算と根の置換表への保存の種別を単体テストで固定する。
不採用なら、fail-lowによる延長はfail-lowを定義できないので見送り、フェーズ4を実行しない。

### フェーズ2　置換表のクラスタ化

クラスタ化を実装し、benchで総ノード数とNPSの変化を記録し、[置換表の対局再生診断](../measurements/strength-stage6-tt-replay.md)と同じ再生で深い記録が上書きされる割合と照合成功率の変化を確かめる。
クラスタ化の効果は置換表の再利用による探索効率にしかないので、同じ着手列に沿って置換表を保持したまま各手を固定深さ6で探索する再生で、総ノード数が直前の採用構成より3%以上減ることを発動の基準とし、減らなければ発動しない改良として見送る。
3%は上位計画が高速化の事前ゲートとするNPSの改善幅と同じ値であり、固定深さの総ノード数の減少はNPSの改善と同じく持ち時間感度で棋力へ換算できるためである。
基準を満たせば、直前の採用構成とのSTCとLTCで採否を決める。
クラスタの大きさと整列、照会がクラスタ内の一致を返すこと、および置換の順序（同一局面、空き、最古、最浅、最小添字）を単体テストで固定する。

### フェーズ3　internal iterative reduction

減深を実装し、benchで総ノード数の変化を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。
記録手がないノードが減らした深さで探索され、その深さで置換表へ保存されることを単体テストで固定する。

### フェーズ4　fail-lowによる延長

判断の純粋関数とfail-lowの保持を実装し、「標準時間制御の予算での計数」節の手順でfail-lowが判断を変えた件数を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。
延長がhardの予測を超えないこと、および`hard < 2.5·soft`のとき延長が起こらないことを単体テストで固定する。

### フェーズ5　最善手交替時の延長

最善手の比較を実装し、「標準時間制御の予算での計数」節の手順で交替が判断を変えた件数を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。

### フェーズ6　最善手安定時の早期終了

安定の判定と判断の条件の置き換えを実装し、「標準時間制御の予算での計数」節の手順で判断が変わった件数を確かめたうえで、直前の採用構成とのSTCとLTCで採否を決める。
安定の判定が延長の信号と両立しないこと、および置き換えた条件がhardの条件を緩めないことを単体テストで固定する。

### フェーズ7　係数の再導出

最終構成で固定比、対局長の定数、および加算の係数を再導出し、基準を満たす場合だけ1回のSTCとLTCで採否を決める。
結果は基準を満たさない場合も[strength-stage6-coefficients-diag](../measurements/strength-stage6-coefficients-diag.md)へ残す。
最終構成では、秒読みを含む時間制御で時間切れが出ないことを段階2と同じ煙試験で確かめ、[strength-stage6-byoyomi-smoke](../measurements/strength-stage6-byoyomi-smoke.md)へ記録する。

### フェーズ8　進捗指標の記録

全項目の採否が確定した後に、段階開始版との固定200ペアEloをSTCで、HaChu戦の固定200ペアEloを`time=60000+1000`で記録する。
採用項目が1つもなければ段階開始版との比較を省略し、HaChu戦だけを記録する。

## 検証

- aspiration windowsのテストは、深さ4以下と直前の反復がない場合が全窓になること、詰み帯の`prev`が全窓になること、fail-lowで下側だけが`δ`ずつ広がり`δ`が倍になること、fail-highで上側だけが広がること、fail-lowとfail-highが交互に起こっても両側が広がり続けること、判定が等号を含むこと、初期窓と拡大した窓の端が詰み帯の閾値に達したときに無限へ置き換わること、根がβ以上の手で打ち切ること、および根の置換表への保存が入力時の窓に対して上界、下界、正確な値へ分類されることを固定する。窓内に収まった結果だけが`Progress`として通知されること、および読み直しの途中で中断された探索が直前の完了反復の結果を返すことは、進捗イベントのテストに深さ5以上の反復と中断を加えて固定する。
- 置換表のクラスタ化のテストは、クラスタが64バイトで64バイト境界に整列すること、同じクラスタに保存した4局面がいずれも照会できること、5局面目が周回差で最も古いエントリを置き換えること（世代が255から0へ周回した直後の場合を含む）、同じ古さでは最浅のエントリを置き換えること、および同一局面の置き換えが現行の深さの規則に従うことを固定する。
- internal iterative reductionのテストは、記録手のない残り深さ3のノードが残り深さ2で探索されて置換表に深さ2で保存されること、記録手のあるノードと残り深さ2以下のノードが減深されないことを固定する。
- 時間管理のテストは、softの条件を外す真偽値が真でもhardの予測を超えて次の反復へ入らないこと、`hard < 2.5·soft`なら真偽値にかかわらず判断が変わらないこと、`hard = 2.5·soft`で経過時間が`soft`に等しいときだけ判断が変わること、真偽値が偽なら現行の判断と一致すること、fail-lowの保持が手の探索の終わりまで続くこと、最善手の交替が直後の判断だけに働くこと、安定の判定が延長の信号と両立しないこと、および安定時の条件がhardの条件を緩めないことを固定する。予算式の`soft ≤ hard`の不変条件は段階2のテストで保つ。
- 各変更後に`cargo test`、`cargo clippy --all-targets --all-features -- -D warnings`、および`cargo fmt --check`が成功する。
- 各フェーズでbenchの総ノード数の変化が意図した項目だけによることを確認する。時間管理の2項目は固定深さのbenchで総ノード数を変えない。
- 採否測定は`docs/sprt.md`のコミット対コミット測定に従い、各測定の`time_forfeits`と異常件数を記録する。測定名は`strength-stage6-<項目>-stc`および`-ltc`とし、項目は`aspiration`、`tt-cluster`、`iir`、`faillow`、`bmchange`、`stable`、`coefficients`とする。進捗指標は`strength-stage6-elo200`（段階開始版との`time=10000+100`）と`strength-stage6-hachu-elo200`（HaChuとの`time=60000+1000`、規則`L1,L3,P0,P5,P6,R2,E1,E2`、置換表は両者256 MB）、係数の再導出は`strength-stage6-coefficients-diag`、煙試験は`strength-stage6-byoyomi-smoke`とする。基本シードは20600903から測定の順に割り当て、次の測定の基本シードは先行する全測定が実際に使ったペア数以上離す（目安は10,000刻みで、1万ペアを超えた測定の後はその分だけ次を離す）。各測定記録には基本シードと使用ペア数を残し、派生シードの範囲が重ならないことを確認できるようにする（[隣接する基本シードは1局ずれた同じ対局列を生む](../lessons/derive-seed-adjacent-collision.md)）。

## 完了条件

次の条件をすべて満たしたとき、本マイルストーンを完了とする。

- aspiration windows、置換表のクラスタ化、internal iterative reduction、fail-lowによる延長、最善手交替時の延長、最善手安定時の早期終了、および係数の再導出の採否または見送りが個別の測定記録に残り、不採用の実装がコードに残っていない。
- 静的評価の置換表保存とmate distance pruningの見送りが、診断の測定記録と本書の設計判断に残っている。
- 最終構成の秒読みを含む煙試験が時間切れ0件で記録されている。
- 採用した項目について、テスト、Clippy、および整形検査が成功し、窓の規則、置換表の置換順序、減深、および時間管理の判断がテストで固定されている。採用した項目が変えた契約に応じて、[探索部](search.md)と[Lazy SMP](lazy-smp.md)の該当する節が現行の実装と一致するよう更新されている。
- HaChu戦の固定200ペアEloが測定記録に残り、採用項目が1つでもあれば段階開始版との固定200ペアEloも残っている。
- [棋力向上の段階計画](strength-stages.md)の段階6の節と状態、および docs/ROADMAP.md の状態表と「現在地」が上書きされている。

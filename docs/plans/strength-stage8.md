# 棋力向上段階8（前向き枝刈りの第3層）の設計書

## 先に読む要約

本マイルストーンは、通常探索（読みの末端で静止探索へ入る前の、全手を対象とする探索）に前向き枝刈り（劣ると見込んだ枝を読まずに済ませる手法）の第3層を1項目ずつ導入し、同じ持ち時間で読む深さを増やして棋力を上げることを目的とする。
第1層は探索部マイルストーンで入れたnull move pruningとLMR（順序付けの後方にある静かな手を浅く読む手法）、第2層は[段階4](strength-stage4.md)で入れた深さ3以下のfutility pruningであり、本書はその次の層である。
現行（第2期高速化の最終の採用版）の通常探索は、これらに加えて殺し手と履歴による着手順、aspiration windows、およびinternal iterative reductionを持つ。
[起案時の発動率診断](../measurements/strength-stage8-activation-diag.md)では、浅い非PVノードで検査する捕獲手の40%は静的交換評価（SEE、到達升での駒の取り合いを見積もる評価）が負であり、検査する非捕獲手の90%は履歴値（過去に打ち切りを起こした回数に基づく値）が0で、ノードの29%は2手前より静的評価が上がっていない。
本書は、SEEが負の捕獲手を浅い非PVノードで展開しない枝刈り（一般にSEE pruningと呼ぶ）、静的評価が2手前より上がっていないノードで枝刈りと減深を強める変更（improvingフラグ）、順序付けの後方にある履歴値の低い非捕獲手を浅い非PVノードで展開しない枝刈り（history pruning、late move pruningに履歴の条件を加えたもの）、および探索値と静的評価のずれを局面の特徴ごとに学習して静的評価を補正する変更（correction history）を扱う。
中将棋は1局面の合法手が100手を超えるので、閾値はチェスや本将棋の値を流用せず、[段階4](strength-stage4.md)と同じく`bench`（固定局面集を固定深さで探索する速度計測コマンド）の診断で「失う良い結果の割合が10%以下の候補のうち枝刈りが最も多いもの」として決める。
採否は項目ごとに、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/guides/sprt.md](../guides/sprt.md)）で判定し、各項目は直前に採用した構成を基準に測る。
結果として、SEE pruning（余裕値は残り深さ順に0、歩兵2枚分、0）とcorrection history（最善手が捕獲手でなく王駒に利きが届かないノードで更新し、鍵は駒種別の枚数の組）を採用し、improvingフラグはSTCで`H0`となり不採用、history pruningは失う良い結果の割合が10%以下の候補がなく見送った。
王手延長、ProbCut、および獅子の2段階の非捕獲移動の減深は、発動率か正準表現の制約により実装せずに見送った。
完了条件は、各項目の採否または見送りが記録され、採用した枝刈りが誤った詰みの値を返さないことがテストで固定され、段階開始版と外部エンジンHaChuに対する固定200ペアのElo（採否には使わない進捗指標）が記録されていることである。

## 目的

第2期高速化の最終の採用版は、`bench`深さ6で通常探索のノードの98%が浅い非PVノードであり、futility pruningが非捕獲手の展開を6割省いている一方で、捕獲手には枝刈りがなく（futilityは駒の増減がない手にだけ静的評価を上界として使えるので、捕獲手を対象にできない）、futilityが働かないノード（静的評価に余裕値を加えるとαを超えるノード）の非捕獲手は手番号や履歴によらず展開している。
本段階は、この残りの展開を静的交換評価、履歴、および静的評価の推移で選別し、探索木を縮める。
効果の見込みは期待Eloとしては書かず、各項目の発動率と診断で求める「失う良い結果の割合」で代える（[棋力向上の段階計画](strength-stages.md)の設計判断）。

## 適用範囲

対象は`src/search/alphabeta/`の通常探索（`negamax`、`search_move`、`lmr_reduction`、futilityの判定）、`src/search/alphabeta/see.rs`（SEEの判定契約を余裕値つきへ拡張する場合）、および探索ワーカーが持つ履歴表と補正表である。
本書の用語は段階4と段階5の設計書の定義に従う。加えて、**負の詰み帯**は探索値が自分の王駒を取られる詰みを表す範囲（`−MATE + ply`付近、`−MATE_THRESHOLD`以下）であり、**上限**と**下限**は置換表に保存する探索値の種類（探索値がβ以上で打ち切ったノードの値は真の値の下限、αを超えなかったノードの値は上限、その間の値は正確な値）であり、**補正表**は対局者と局面の鍵ごとに探索値と静的評価の差の移動平均を持つ探索ワーカー内の配列である。
静止探索、評価関数、時間管理、合法手生成、規則の解釈は変えない。
不採用または見送りとなった項目はコードに残さず、設計だけを本書に保持する。

| 適用するノード | 静的評価または履歴に基づく枝刈り（捕獲手のSEE、非捕獲手の後方枝刈り）は、段階4のfutility pruningと同じく、残り深さ1から3、探索窓の幅が1の非PVノード、αとβがともに詰み帯の外、探索済みの最善値が負の詰み帯の外（最初の手が詰まされる値を返した後は安全な手を探し続ける）、手番側の王駒に相手の利きが届かないノードに限り、置換表の記録手を対象にしない。improvingフラグは既存のfutilityとLMRの条件を変えるだけなので新たな適用条件を持たない。 |
| 閾値の決め方 | チェスや本将棋の値を流用せず、段階4と同じ手続きで診断benchから決める。各項目について「良い結果」を「参照探索（診断時点の現行探索、同じ深さと窓）で探索値がαを上回った対象手」と定義し、失う割合を「候補の条件で枝刈りされる良い結果の数 ÷ 対象内の良い結果の総数」とする。候補集合は項目ごとに定め（SEEの余裕値は`m ∈ {0, p/2, p, 2p, 3p}`、後方枝刈りは手番号の下限`k ∈ {4, 6, 8, 12, 16, 24, 32}`と履歴値の上限`h ∈ {0, 32, 128}`の全組、improvingの倍率は`{1, 3/4, 1/2, 1/4}`）、失う割合が10%以下の候補のうち枝刈りされる手の数が最大のものを深さごとに1つ選ぶ。同数なら閾値の緩い方（枝刈りの少ない方）を選ぶ。対象手が1,000件未満の深さ、良い結果が0件の深さ、および10%以下の候補がない深さでは、その深さには適用しない。条件付き不一致率（候補以上の対象に占める食い違いの割合）では選ばない。段階4でこの指標は、良い結果の基礎率が低いため候補値によらず10%を下回って最小候補を選んでしまった。閾値はSTCの前に固定し、STCの結果を見てから変えない。同じ項目の閾値違いをSTCの後に追加することは[docs/guides/sprt.md](../guides/sprt.md)が禁じる。 |
| 発動の事前確認 | 各項目は、実装前の診断でbench深さ6の発動率が5%以上であることを確認する。[起案時の発動率診断](../measurements/strength-stage8-activation-diag.md)の値は候補条件の成立率であり、王駒への利き、負の詰み帯、成る手などの適用条件と確定した閾値を含まない。したがってフェーズ1で、項目ごとに分母と分子を次のとおり定めて測り直す。捕獲手のSEEは「適用するノードで検査する捕獲手」に対する「閾値で枝刈りされる手」、後方枝刈りは「適用するノードでfutilityが展開すると決めた非捕獲手」に対する「閾値で枝刈りされる手」、improvingは「futilityが展開すると決めた非捕獲手、またはLMRの判断を受ける非捕獲手」に対する「improvingの導入で展開されなくなる手、または減深量が変わる手」（減深量が既に上限なら変わらない）、静的評価の補正は「枝刈りと減深の判断」に対する「非ゼロの補正値が参照された判断」とする。起案時の成立率（捕獲手の39.8%、非捕獲手の88.5%、ノードの28.6%）はこの基準を大きく超えるので着手の根拠にはなるが、通過の確認はフェーズ1の値で行う。王手延長（1.9%）とProbCut（0.4%）は成立率の段階で基準に届かず見送る。improvingの発動率は、起案時にはノードの単位（判断があるノードに対する、判断が変わるノード）で定めていたが、フェーズ1の診断で1.42%となった。残り深さ1のノードの大半は現行の余裕値で既に全非捕獲手を展開しておらず、倍率を掛けても判断が変わらないので、ノードの単位の分母は発動を薄める。同じ診断で手の単位では展開する非捕獲手の16.9%が新たに枝刈りされており、段階5のmalusでも手の割合3.99%の改良がbenchの総ノード数を17.9%減らした前例があるので、利用者の決定により2026年9月19日に指標を手の単位へ改めた。この変更は、improvingの実装と最初の採否測定より前に確定した。 |
| 段階4のlate move pruningとの区別 | 段階4は手番号だけで非捕獲手を打ち切る方式（深さ順に12、23、13手）を、futility pruningの採用版を基準にSTCで`H0`として不採用にした。本書の後方枝刈りの主張は「過去に打ち切りを起こした履歴のある手を保護すれば、手番号だけの枝刈りが失っていた良い結果を減らせる」であり、手番号の再調整ではない。この主張はフェーズ1で確かめる。同じ発動率（枝刈りする手の数）で比べたとき、履歴条件つきの候補の失う割合が手番号だけの候補より3分の1以上小さくなければ、主張は成り立たないとして着手しない。成り立つ場合も、同じ主張の再測定と見なす余地は残るので、着手の可否は利用者が確定する。 |
| 履歴値の分布 | malusが不採用（段階5）なので履歴値は非負であり、浅い非PVノードで検査する非捕獲手の90.3%は履歴値0である。したがって「負の履歴」による枝刈りは定義できず、履歴値の上限（0、32、128の候補）と手番号の下限の組で条件を作る。 |
| SEEの余裕値 | 捕獲手の枝刈りは「SEEが`−m`未満」を条件とし、`m`は0、`p / 2`、`p`、`2p`、`3p`（`p`は歩兵の駒価値100）を候補に診断で決める。`m = 0`なら現行の`see_prunes`（静止探索の判定と同じ契約）をそのまま使い、`m > 0`なら早期終了の契約を余裕値つきへ拡張し、参照実装との一致テストを余裕値ごとに固定する。規則に依存して判定不能（`None`）の手は枝刈りしない。 |
| improvingの定義 | `improving`は、2手前の同じ手番の静的評価より現局面の静的評価が高いことを表す。2手前がない場合と、直近2手のいずれかがnull moveである場合（現行の実装はnull moveでも`ply`を進めるので比較区間に仮想の着手が入る）は真とし、追加の枝刈りを行わない。比較には補正前の静的評価（差分更新の累算値）を使い、静的評価の補正を採用しても比較基準を動かさない。improvingでないノードでは、futility pruningの余裕値を診断で決めた倍率で縮め（枝刈りを増やす）、殺し手でも置換表の手でもない後方の非捕獲手のLMRの減深量を1増やす。2つの変更はどちらも同じフラグで発動し、単独では検出できる効果が見込めないので1項目として測るが、追加減深はフェーズ1の損失測定で不適格なら外し、余裕値の変更だけで測る。 |
| 静的評価の補正（correction history） | 一般にcorrection historyと呼ばれる手法であり、StockfishとYaneuraOuが同名の表（`correctionHistory`）で実装している（[既存実装の調査](../research/forward-pruning-prior-art.md)）。探索ワーカーが対局者×鍵ごとの補正値の表を持ち、置換表へ保存する探索値が修正の向きを確定するノード、すなわち正確な値、静的評価より低い上限、または静的評価より高い下限を保存するノードで、探索値と静的評価の差を深さに比例し上限を持つ重みで指数移動平均に取り込む。詰み帯の探索値（絶対値が`MATE_THRESHOLD`以上）は更新に使わず、補正値は`±2p`に切り詰める。静的評価に補正値を加えた値を枝刈りと減深の判断に使い、評価関数、置換表の保存値、静止探索の`stand_pat`は変えない。鍵は、王駒の升の組、駒種別の枚数の組、およびその2つの組合せを候補とする。3つは同じ標本で説明分散を比べると細かい鍵ほど有利になるので、フェーズ1では探索の進行に沿って表を実際に初期化と更新しながら「更新前の表が次の観測の差を予測する誤差」を測り、補正なしの平均絶対誤差に対する改善率、鍵の再利用率、および非ゼロ補正の参照率を鍵ごとに記録して、改善率が最も高い鍵を選ぶ。改善率が10%未満か非ゼロ補正の参照率が5%未満なら見送る。フェーズ1の診断では観測点の97%が下限で、差の平均絶対値が歩兵12枚分あり、3種の鍵の改善率がほぼ等しかった。StockfishとYaneuraOuは、最善手が捕獲手であるノードと王手を受けているノードでは補正を更新しない（[既存実装の調査](../research/forward-pruning-prior-art.md)）。捕獲手による駒得は評価の偏りではないからである。そこでフェーズ5の再診断では、更新の条件に「最善手が捕獲手でなく、手番側の王駒に相手の利きが届かない」を加えた変種Bと、Stockfishと同じく上限を保存するノードには最善手の除外を適用しない変種C（上限のノードでは捕獲手を含む全手を読んでも値が静的評価を下回ったと分かっているので、形式上の最善手の種類は補正の向きに関係しない）を候補に加える。評価集合は変種Bの条件を満たす観測点に固定する。補正を使うのは非捕獲手のfutilityの判断なので、各変種は同じ評価集合、すなわち追加の条件を満たす観測点での予測誤差で比べ、改善率の高い方を採る。見送りの基準（改善率10%、参照率5%）は選んだ変種に同じ評価集合で適用する。 |
| 見送る項目 | 王手延長は手番側の王駒に相手の利きが届くノードが1.9%で発動率の基準に届かない。ProbCutは残り深さ5以上の非PVノードが起案時の深さ6で0.4%であり基準に届かない。LTCの到達深さに相当する深さ8でも、最終構成の[診断](../measurements/strength-stage8-probcut-diag.md)で1.47%にとどまったので、次期の候補には加えず、到達深さがさらに伸びた段階で測り直す。獅子の2段階の非捕獲移動の減深は、正準表現がじっと以外を直接の跳びと同一視するので手の側から区別できず、獅子の非捕獲手全体（検査する非捕獲手の13.5%）を対象にする根拠もないので見送る。 |
| 診断コードの扱い | 診断の計測はbenchへの一時的な変更で行い、コードは残さない。差分は測定記録の付属ディレクトリへ保存する。 |

## 各項目の実装

### SEEによる捕獲手の枝刈り（SEE pruning）

適用するノードで、置換表の記録手でも相手の最後の王駒を取る手でもない捕獲手について、SEEが`−m`未満なら展開せず次の手へ進む。
判定は`see_prunes`（`m = 0`）または余裕値つきの変種で行い、規則に依存する手は展開する。
枝刈りした手は着手順の手番号に数え、履歴の更新は行わない。

### improvingフラグ

`negamax`の入口で静的評価を求め、2手前の同じ手番の静的評価と比べて`improving`を決める。
futility pruningの余裕値は、improvingでないノードで診断の倍率（1未満）を掛ける。
LMRの減深量をimprovingでないノードで1増やす変更は、採用構成の再診断で失う割合の増分が基準を超えたので実装しない（「採用した閾値」節）。実装する場合の上限は、現行の`LMR_MAX_REDUCTION`と`depth − 2`の小さい方である。

### 履歴による非捕獲手の後方枝刈り（history pruning）

適用するノード（残り深さ1から3）で、置換表の記録手でも殺し手でも成る手でもない非捕獲手について、手番号が深さごとの下限`k_d`以上かつ履歴値が上限`h_d`以下なら展開しない。
futility pruningが展開しないと決めた手は本項目の対象に数えず、本項目はfutilityの判定の後に置く。
枝刈りした手は手番号に数え、履歴の更新は行わない。

### 静的評価の補正（correction history）

実装は`src/search/alphabeta/correction.rs`にある。
探索ワーカーに補正表（手番側ごとに4,096要素、値は補正値の1,024倍の固定小数点）を持たせ、探索の開始時にゼロで初期化して、反復深化の間は持ち越す。対局の中で表を持ち越す案は別の主張なので本段階では扱わず、探索ごとの初期化だけを測った。
鍵は双方の駒種別（成駒は別種）の枚数の組であり、駒の種類ごとの固定の64ビット値を盤上の全駒について足し合わせたハッシュで表す。この値は駒の位置によらず、plyごとに持って着手の適用時に取られた駒と成りの分だけ差分更新し、null moveでは変えない。
`negamax`が置換表へ保存する直前に、探索値が詰み帯の外にあり、保存する値が修正の向きを確定し（正確な値、静的評価より低い上限、または静的評価より高い下限）、最善手が捕獲手でなく、手番側の王駒に相手の利きが届かないノードで、`差 = 探索値 − 補正前の静的評価`を求め、`補正 += (差 − 補正) × min(depth, 8) × 33 / 1024`で更新して歩兵価値の`±193%`へ切り詰める。
補正値は、適用するノードのfutility pruningの判定で静的評価へ加える。置換表の保存値、静止探索の`stand_pat`、null move、LMR、およびSEEによる捕獲手の枝刈りは変えない。

## 採用した閾値

SEEによる捕獲手の枝刈りの値はフェーズ1の[診断](../measurements/strength-stage8-pruning-bench.md)（段階開始版、bench深さ6）で、improvingの値はSEEによる捕獲手の枝刈りを採用した構成の[再診断](../measurements/strength-stage8-improving-bench.md)で確定した。静的評価の補正の値も同じ採用構成の再診断で確定した。

| 項目 | 残り深さ1 | 残り深さ2 | 残り深さ3 | 発動率 |
|---|---|---|---|---|
| SEEによる捕獲手の枝刈りの余裕値`m` | 0 | 200 | 0 | 28.5% |
| improvingでないノードのfutility余裕値の倍率（STCで`H0`、不採用） | 1/4 | 1/2 | 1/2 | 10.93%（手の単位） |
| 履歴による非捕獲手の後方枝刈りの`(k, h)` | 適用しない | 適用しない | 適用しない | 0% |

[最初のSPSAの長時間測定](../measurements/spsa-stage9-20260923-ltc.md)を通過した後の値は、SEEによる捕獲手の枝刈りの余裕値が残り深さ順に歩兵価値の0%、195%、10%、静的評価の補正値の上限が歩兵価値の202%、更新の重みが`min(depth, 8) × 35 / 1024`であった。
[2回目のSPSAの長時間測定](../measurements/spsa-stage9-20260925-c5-ltc.md)を通過した後の現行値は、SEEによる捕獲手の枝刈りの余裕値が同じ順に歩兵価値の2%、210%、7%、補正値の上限が歩兵価値の193%、更新の重みが`min(depth, 8) × 33 / 1024`である。
上の表と以下の診断値は段階8の測定時点の値であり、SPSA後の発動率や補正の改善率を示すものではない。

段階8のimprovingの診断では、当時のfutility余裕値50、150、150に倍率を掛けて端数を切り捨てた12、75、75を使った。
LMRの追加減深は、再診断で失う割合の増分が15.0ポイント（3／20から6／20）となり基準の10ポイントを超えたので外し、improvingフラグは余裕値の変更だけで測った。
静的評価の補正は、採用構成の[再診断](../measurements/strength-stage8-correction-bench.md)で、更新の条件を変種B（最善手が捕獲手でなく、手番側の王駒に相手の利きが届かない）、鍵を双方の駒種別の枚数の組と手番側、重みを`min(depth, 8) / 32`と決めた（共通の評価集合での改善率15.41%、非ゼロ補正の参照率66.9%）。全観測点で更新する変種Aの改善率は−4.84%から1.99%であった。

## 実装フェーズ

### フェーズ1　診断

段階開始版に一時的な計測を加え、bench深さ6で次を記録する。

- 捕獲手のSEEの余裕値: 適用するノードの捕獲手について、SEEの値（参照実装）と探索値がαを上回ったかを記録し、候補`m`ごとに失う良い結果の割合と発動率を求める。
- 非捕獲手の後方枝刈り: 適用するノードでfutilityが展開すると決めた非捕獲手について、手番号、履歴値、探索値がαを上回ったかを記録し、`(k_d, h_d)`の候補ごとに失う良い結果の割合と発動率を求める。
- improving: improvingでないノードのfutility余裕値の倍率（1、3/4、1/2、1/4）ごとに失う良い結果の割合を求める。LMRの追加減深は段階5の診断手順を継承し、improvingでないノードの後方の非捕獲手について、本来の深さの探索でαを上回る手を分母、現行の減深量と追加後の減深量それぞれの減深探索でα以下になる手を分子として失う割合を求め、追加による増分が10ポイントを超えれば追加減深を外す。置換表による結果の流用を防ぐため、各手の3通りの探索は置換表を空にした同じ順序で行う。
- 静的評価の補正: 鍵と重みの候補ごとに、探索の進行に沿って表を初期化と更新しながら、更新前の表による次の観測の予測誤差、補正なしに対する改善率、鍵の再利用率、および非ゼロ補正の参照率を記録する。

各件数は独立した参照と照合し、不一致なら診断を停止する。
照合する量、参照値の算出元、および停止条件は次のとおりである。

- 手の分類（捕獲手かどうか、成る手かどうか、相手の最後の王駒を取る手かどうか、手番側の王駒に相手の利きが届くかどうか）は、手選択器が返す分類を使わず、局面と手から再計算した値と全件で照合し、1件でも食い違えば停止する。
- 静的評価は、差分更新の累算値を局面からの全再計算の評価値と全ノードで照合し、1件でも食い違えば停止する。
- SEEの値は参照実装（`see_reference`）で求め、`see_prunes`との契約（`see_prunes == 参照値が負`）を全件で照合し、1件でも食い違えば停止する。
- 探索値は、対象手の64件に1件について、置換表を空にした参照探索（同じ深さと窓）を行い、「αを上回ったか」の判定を照合する。置換表の有無は探索値を正当に変え得るので全件一致は求めず、記録側が良い結果とした手のうち参照探索でも良い結果である割合と、その逆の割合がともに80%以上であることを求め、下回れば停止して計測の誤りを調べる。
- 参照探索を有効にしても本来の探索の標本が1件も変わらないこと、および計測を入れたbenchの総ノード数（副次的な探索を除く）が段階開始版のbenchと一致することを確認する。

LMRの追加減深の副次的な探索は置換表、殺し手、および履歴を本来の探索から切り離して行い、その他の計測とは別の実行にする。
結果は測定記録`strength-stage8-pruning-bench`へ残し、閾値と鍵を本書の「採用した閾値」節へ書く。

### フェーズ2　SEEによる捕獲手の枝刈り（SEE pruning）

実装し、SEEの契約テスト（余裕値つきの場合はその一致テスト）と、枝刈りが詰みの値を返さないテストを通し、STC、続いてLTCで判定する。

### フェーズ3　improvingフラグ

直前の採用構成で倍率を診断し直し、実装して判定する。

### フェーズ4　履歴による非捕獲手の後方枝刈り（history pruning）

利用者が着手を認めた場合に、直前の採用構成で`(k_d, h_d)`を診断し直し、実装して判定する。

### フェーズ5　静的評価の補正（correction history）

直前の採用構成で、更新の条件の変種（設計判断の節）を含めて鍵と重みを診断し直す。選んだ変種の改善率が10%以上かつ非ゼロ補正の参照率が5%以上なら実装し、補正表の更新と読み出しのテストを通して判定する。

### フェーズ6　進捗指標の記録

段階開始版との固定200ペアのEloと、HaChuとの固定200ペアのElo（規則`L1,L3,P0,P5,P6,R2,E1,E2`、`time=60000+1000`）を記録し、LTCの到達深さ8でのProbCutの対象ノードの割合を測って次期の候補として残す（LTCでは残り深さ5以上のノードが増えるので、深さ6の成立率だけでは次期の着手可否を決められない）。

## 検証

- 各項目の実装前に、bench深さ6の発動率が5%以上であることを診断で確認する。
- 各項目は`cargo fmt --check`、`cargo clippy --release --all-targets`、`cargo test --release`を通し、benchの総ノード数が当該項目だけで変わることを局面別出力で確認する。
- 枝刈りが誤った詰みの値を返さないことをテストで固定する。段階4と同じ2例、すなわち全手が枝刈りの対象になる局面で合法手なしと誤認して`−MATE`を返さないこと、および最初の手が負の詰み帯の値を返した後に残る安全な手を枝刈りしないことを、捕獲手のSEEと非捕獲手の後方枝刈りの両方について、返り値と置換表へ保存する値の両方で検査する。
- SEEの余裕値つきの判定は、参照実装との一致（`prune == reference.is_some_and(|v| v < −m)`）を固定シードの局面で検査する。
- 補正表は、更新と読み出しが探索ワーカーごとに独立であることと、探索開始時に初期化されることをテストで固定する。
- 採否はSTC、続いてLTCの時間制御GSPRTで判定し、測定名`strength-stage8-<項目名>-stc`および`-ltc`で記録する。

- SEEによる捕獲手の枝刈り、improvingフラグ、履歴による非捕獲手の後方枝刈り、および静的評価の補正の採否または見送りが個別の測定記録に残り、不採用の実装がコードに残っていない。
- 王手延長、ProbCut、獅子の2段階の非捕獲移動の減深の見送りが、発動率の記録とともに本書に残っている。

- 段階開始版とHaChuに対する固定200ペアのEloが記録されている（採否には使わず、上位計画が求める段階ごとの強さの系列として残す）。

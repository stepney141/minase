# 棋力向上段階9（利きの土台、教師データの改善、王の安全度と利きに基づく評価特徴）の設計書

## 先に読む要約

本マイルストーンは、評価関数（局面の有利不利を数値にする関数）が王の危険と駒の利き（駒が届く升）を評価できるようにして、棋力を上げることを目的とする。
現行の評価関数は学習PST（駒の種類と位置ごとの重みを足し合わせる表、piece-square table）だけで構成され、2026年9月21日のlishogiでの[敗局](../research/lishogi-game-yO464dzl-loss-analysis.md)では、玉の正面の筋が開いて敵の走り駒が集まる間も、歩兵10枚分に当たる+1000センチポーンを超える評価値を返し続けた。
着手後の測定で、評価特徴を足すだけでは解けない問題が2つ見つかった。
第1の問題は費用であり、利きを使う特徴を升ごとの逆引きで計算すると毎秒の探索ノード数（NPS）が82.2%下がって0.18倍になり、先行エンジンが持つ利きの土台（利きを保持または共有するデータ構造）がminaseにないことが原因だった。
第2の問題は教師であり、現行の教師データ（自己対局の局面に探索値と対局結果を付けたデータ）で学習した王の遮蔽の重みは終盤でだけ大きく、敗局の中盤の局面では評価値を28センチポーンしか動かさなかった。
本書は、第1の問題を解く土台の柱、第2の問題を解く教師の柱、および特徴の柱の3つで進める。
土台の柱は、1つの探索ノードの中で静的評価を重ねて計算しないようにし（評価の償却）、升ごとの利き数の表を着手のたびに差分更新する（やねうら王の long effect library の `board_effect` に当たる）。
教師の柱は、深い探索による付け直し（一般に rescoring と呼ぶ）、人間の実戦棋譜の局面、および実戦棋譜の局面から始める自己対局の3つの追加を、それぞれ事前に固定した基準の診断にかけ、基準を満たした追加だけで教師の構成を確定する。
特徴の柱は、[評価項目の調査](../research/evaluation-terms-survey.md)の上位7段階を、王駒の近くを見るA群（遮蔽と開いた筋、攻撃域、守備駒）と盤全体を見るB群（安全な可動性、成りと侵入、獅子、駒への脅威）に分け、確定した教師で1項目ずつ重みを学習して、短時間（STC）と長時間（LTC）の時間制御GSPRT（自己対局の勝敗から強さの差を逐次判定する統計検定、[docs/guides/sprt.md](../guides/sprt.md)）で採否を判定する。
完了条件は、土台の速度、教師の3つの診断、および7項目の採否または見送りが測定記録とともに残り、本段階の着手時点の版とHaChuのそれぞれに対する固定200ペアのElo（採否には使わない進捗指標）が記録されていることである。

## 目的

評価関数は駒種、成りの可否、升だけを特徴とする線形モデルであり、王駒の安全、可動性、駒どうしの利きの関係は入力に含まれない。
敗局の分析では、182手目の局面で深さ1の探索値と深さ16の探索値の差が約2800センチポーンに達し、その差は目前の駒の取り合いでは説明できなかった。
先手の攻めは駒を取らない手が7手から9手続く手順であり、対局時の探索深さ10から16では駒損が見える前に探索が打ち切られた。
探索の深さでこの種の攻めを捕捉することは現実的でないので、攻めの準備が整った配置を静的に減点できる特徴を評価関数へ加える。
[HaChuとMinaseの勝ち方・負け方](../research/hachu-minase-playing-style-analysis.md)は、Minaseが負ける局では自身を有利とする評価を終盤まで維持してから急落する傾向を報告しており、この敗局は孤立した事例ではない。

特徴を足すだけでは足りないことを、着手後の測定が示した。

第1の発見は費用である。
王の周囲の攻撃域と守備駒を、升ごとに「その升へ届く駒」を逆引きする計算で実装したところ、重みがすべて0の構成でもNPSが82.2%下がり、0.18倍になった。
逆引きは1回あたり約22 nsから33 nsかかり、現行の1ノードの時間は約0.47 μsなので、低下を10%以内に収めるには逆引きを1評価あたり2回程度までしか使えない。
[土台の調査](../research/evaluation-infrastructure-survey.md)によれば、先行エンジンは同じ項目を費用なしで得ているのではなく、Fairy-Stockfishは評価の中で駒ごとの利きを1回ずつ作って複数の項で使い回し、やねうら王は着手のたびに升ごとの利き数の表を差分更新し、HaChuは1手ごとに利きマップを作り直して手生成と共有する。
minaseにはこのどれもない。
自己対局の測定では、持ち時間を2倍にすると棋力が216 Elo上がった（[sensitivity-time2x](../measurements/sensitivity-time2x.md)）。
同じ持ち時間で探索できるノード数はNPSに比例するので、NPSがr倍になることを持ち時間がr倍になることと同じとみなし、棋力が持ち時間の対数に比例すると仮定すると、損失は216×log2(1/r) Eloと換算できる。
たとえばr=0.85ではlog2(1/0.85)が約0.234なので約51 Eloであり、同じ式で0.9倍は約33 Elo、0.8倍は約70 Eloに当たる。
この換算は本書が目安として置く近似である。

第2の発見は教師である。
王の遮蔽と開いた筋の24個の重みを、学習PSTを固定して現行の教師で学習したところ、期待する符号は、自分の王駒の側の開いた筋と敵の走り駒が自分の評価を下げる負である。
終盤の端点の重みは−67から−233センチポーンとなって期待どおりの符号を持ったが、序中盤の端点の重みは絶対値が52以下と小さく、正の符号のものが多かった。
敗局の174手目から182手目の局面は評価値が序中盤の端点でほぼ決まるので、追加特徴の寄与は−19から−28センチポーンにとどまった。
教師の探索値は現行の学習PSTによる100,000ノードの探索の値であり、敗因と同じ盲点を持つ。
追加特徴の重みは学習PSTの予測と教師値の残差に対してだけ学習されるので、教師が危険を見ていなければ重みは小さくなる。
[将棋の教師生成と学習ツールの調査](../research/teacher-generation-prior-art.md)によれば、将棋の教師の質は、強い評価関数による1手1,000,000ノードの探索、自分より強い評価器による教師値の付け替え、および外部の開始局面集で作られているが、どれも評価関数が既に王の危険を知っていることを前提にしており、minaseには教師値を付け替えられるほど強い別の評価器がない。
したがって、minaseの教師へ新しい情報を持ち込める源は、深い探索、人間の実戦棋譜の対局結果、および人間が作った配置から始めた自己対局の対局結果に限られる。

第3の発見は、この2つが互いに依存することである。
王の危険を表せない特徴のままで教師だけを改めても、その情報を受け取る重みがなく、王の危険を含まない教師のままで特徴だけを足しても、重みが学習されない。
本書は、教師の構成を先に確定し、その教師で特徴を学習して、採否を特徴の候補の自己対局で判定する。

効果の見込みは期待Eloとしては書かず、各項目の発火率と検証局面での評価値の変化で代える（[棋力向上の段階計画](strength-stages.md)の設計判断）。

## 適用範囲

対象は、`src/eval/`（特徴の定義、重み形式、評価値の計算）、`src/search/mod.rs`（静的評価の呼び出し、王手の判定、探索の深さ方向の位置であるplyごとの状態の前送り）、`src/search/see.rs`、`src/core/attacks/`（利きの表）、`src/bin/pst_probe.rs`、`src/bin/selfplay_gen.rs`（保存済みの局面の付け直しと、開始局面の一覧からの生成）、教師データの来歴を記す付随ファイル、lishogiの棋譜を教師データへ変換する道具、および `tools/train/pst/` の学習器と診断器である。
本書の用語は[PSTの序中盤と終盤の補間](tapered-pst.md)、[評価関数](evaluation.md)、および[段階7](strength-stage7.md)の定義に従い、次の語を加える。

- **王駒**は、王将、玉将、太子を指す。
- **学習PSTの特徴**は、現行の13,680個の特徴を指す。**追加特徴**は、本書が学習PSTの特徴の後ろへ加える特徴を指し、**特徴値**は、1局面で追加特徴が取る0以上の整数を指す。
- **疑似利き**は、駒の動き方と途中の駒による遮蔽だけから決まる「その駒が届く升」を指す。獅子の捕獲制限のような規則による制限は考慮せず、自分の駒がいる升へ届く場合も含める。獅子が複数の経路で同じ升へ届いても1つと数える。王手放置が合法なので、王駒へのピンによる除外はしない。
- **短い利き**は、途中の駒に遮られず、駒の位置だけで決まる利きを指す。固定の利き、獅子の到達範囲、および角鷹と飛鷲の2段階移動の到達升が当たる。**長い利き**は、走りの利き、すなわち途中の駒に当たるまで任意の升数を進む利きを指す。名称はやねうら王の用語に合わせた。minaseの走りはどの駒種でも距離が無制限である。
- **土台**は、評価特徴の計算が前提とするデータ構造と、その更新の仕組みを指す。
- **利き数の表**は、升ごとに、先手の疑似利きの数と後手の疑似利きの数を持つ表を指す。**走りの方向の表**は、升ごとに、その升へ届いている長い利きの方向を、先後それぞれ8ビットで持つ表を指す。空升では利きはその升を通って先へ進み、駒のある升では利きはその升で止まる。駒が除かれると、記録された方向の利きが先へ伸びる。
- **評価の償却**は、1つの探索ノードの中で1度計算した静的評価（探索せずに局面だけから求める評価値）を、同じノードの中の別の処理で再利用し、評価の計算の回数を減らすことを指す。
- **`bench`** は、固定した15局面を固定の深さで探索し、総ノード数とNPSを出力する測定プログラムを指す。探索木が変わらない変更では総ノード数が一致するので、NPSの差が計算の費用の差だけを表す。
- **チェビシェフ距離**は、2つの升の筋の差と段の差の大きい方を指す。王駒から距離1の升は隣接する最大8升であり、距離2の升はその外側を囲む最大16升である。
- **駒の区分**は、B群の特徴が駒をまとめる単位を指し、現在の駒種の動きで定める。**小駒**は、金将、銀将、銅将、猛豹、盲虎、醉象、麒麟、鳳凰である。**片走り駒**は、香車、反車、横行、竪行、白駒、鯨鯢、飛鹿である。**大駒**は、角行、飛車、龍馬、龍王、奔王、奔猪、飛牛、角鷹、飛鷲である。**獅子**は単独の区分とする。成った歩兵は金将として扱う。歩兵、仲人、および王駒は、どの区分にも入れない。
- **安全な升**は、ある駒の疑似利きが届く升のうち、自分の駒がおらず、敵の利き数が0である升を指す。
- **補間係数φ**は、序中盤の端点の重みと終盤の端点の重みを混ぜる比を指し、盤上の駒数から決まる。初期配置の92枚で1、駒数が減るにつれて0へ近づく（定義は[PSTの序中盤と終盤の補間](tapered-pst.md)）。**中盤の局面**は、φが0.5以上、すなわち盤上の駒数が47以上の局面を指す。
- **露出局面**は、手番側の王駒について、項目1の走り駒の特徴（歩のない筋に相手の縦の走り駒がいる）が1つ以上発火している局面を指し、**対照局面**は、その特徴が発火していない局面を指す。
- **世代**は、教師データを生成した評価関数の版を指す。世代0から世代2までが既にあり、世代2は[段階7](strength-stage7.md)の採用版で生成した14,057,872局面である。
- **教師の分類**は、教師値の作り方が同じデータのまとまりを指す。教師の探索のコミットと重み、ノード数、規則セット、探索の条件（対局中の探索か局面単独の探索か）、対局結果の由来（自己対局か実戦棋譜か）、および開始局面の由来が同じであれば同じ分類とする。
- **教師の構成**は、学習の入力にする教師の分類の集まりを指す。**基本の教師**は、世代0から世代2の既存のデータを指す。
- **付け直し**は、保存済みの教師データの各局面を改めて探索し、探索値だけを置き換えることを指す。**記録**は、MNSDファイルが1局面につき1つ持つ固定長のデータを指す。**付け直しファイル**は、付け直しの結果を、元のMNSDファイルの記録と同じ順に1件ずつ持つ別のファイルを指す。元のMNSDファイルは書き換えず、学習器が読み込み時に探索値を差し替える。
- **実戦棋譜**は、lishogiの中将棋の対局の棋譜を指す。**実戦開始の自己対局**は、実戦棋譜の途中の局面を開始局面とし、以後は両側が同じ評価関数で指す自己対局を指す。初期局面から乱数の着手で始める現行の自己対局を、**乱数開始の自己対局**と呼ぶ。
- **段階開始版**は、本書のフェーズ1の着手時点のmasterの先頭コミットを指し、**直前の採用版**は、本段階で最後に採用された候補を指す。採用された候補がまだない間は、段階開始版が直前の採用版である。
- **発火率**は、追加特徴の1列ごとに求める、教師データの局面のうちその列の特徴値が0でない局面の割合を指す。
- 学習の用語として、**出力K**は評価関数の評価値を勝率へ変換する尺度を、**教師K**は教師の探索値を勝率へ変換する尺度を指し、教師Kは教師の分類ごとに推定する。**ロジット**は評価値を出力Kで割って勝率へ変換する直前の値を、**量子化**は学習した実数の重みを1/8センチポーン単位の整数へ丸めることを指す。
- 升は筋の番号と段の英字で表し、3aは3筋のa段の升である。

探索の枝刈り、時間管理、合法手生成、規則の解釈、および教師データの形式（MNSD）は変えない。
調査の段階8から段階10、NNUE、マジックビットボード、`unsafe`、PGO、遅延評価、置換表への静的評価の保存、教師の探索の全局面でのノード数の引き上げ、および静止探索の末端の局面を教師にする方式は対象外とし、理由は設計判断の表に記す。
不採用または見送りとなった項目と、どの採用項目からも使われなくなった土台は、コードに残さず、設計だけを本書に保持する。
教師データと測定記録は、採否にかかわらず後続の研究の入力として保持する。

## 依存関係

段階の順序、項目の共通の採否基準、進捗指標の測定条件、および全体の完了条件は[棋力向上の段階計画](strength-stages.md)が所有し、本書は段階9の実装方式、検証範囲、および不採用時の処理を具体化する。

疑似利きの逆引き `attackers_to_by` は[段階3](strength-stage3.md)が導入し、[合法手生成と利き計算の高速化（第2期）](movegen-speedup-2.md)が現行の実装を定める。本書は、利き数の表の正しさを確かめる独立の参照として使う。

## 設計判断

### 全体

| 項目 | 決定 |
|---|---|
| 3つの柱を1つの計画にする | 土台、教師、特徴は互いに依存する。利きの特徴は土台がなければ速度の条件を満たさず、王の危険の特徴は教師がそれを含まなければ重みが学習されず、教師の改善は王の危険を表せる特徴がなければ評価関数に反映されない。別々の設計書では、この依存が採否の設計に現れない。 |
| 教師の構成は診断の基準で確定する | 教師への追加は、追加ごとの診断が事前に固定した基準を満たすかどうかだけで採り、追加ごとの自己対局の検定は行わない。現行の特徴は王の危険を表せないので、現行の特徴で教師だけを替えた評価関数を検定にかけても、教師が持ち込む情報は評価関数へ届かず、検定は教師の良し悪しを測れない。教師の構成は、特徴の学習を始める前に1度だけ確定し、以後は学習や対局の結果を見て変えない。教師の変更を含む全重みの再学習は、最後の同時学習の候補が1つの検定で判定する。 |
| 採否の単位 | 自己対局の検定にかける候補は、直前の採用版へ特徴の項目を1つだけ加えた候補と、最後の同時学習の候補に限る。各項目の結論は「確定した教師の構成の下でのその項目の効果」と表現する。項目が不採用となったときに教師と特徴のどちらが原因かは検定からは分からないので、最初に測る項目では、基本の教師だけで学習した重みと、確定した教師の構成で学習した重みを、検証局面での寄与とともに記録して比べる。この比較は局面の集合も異なるので、原因を分離する対照ではなく、差を観察するための記録である。付け直した局面と同じ局面で探索値だけを元へ戻す対照の学習は、工程の全体を1つの検定で評価する本書の方針では採否に使う場面がないので行わない。利用者の決定により、教師と特徴の原因を切り分ける対照は事前には定めず、全部の項目が不採用となった場合に、その時点で方法を検討する。 |
| 重みの決め方 | 追加特徴の重みは学習で決め、手書きの係数を置かない。上位計画の「評価特徴の追加方法」の決定に従う。先行実装の定数は、チェスまたは本将棋で調整された値なので移さない。終盤の端点の重みを序中盤の端点へ写すなど、手で重みを決める方法も採らない。 |
| 1項目1定式化 | 各項目と各追加は、本書が定める1つの定式化だけを測る。不採用または基準に届かなかったものは、区間、範囲、標本を変えた変種を測り直さない。結果を見てから変種を足すことは、[SPRTの手引き](../guides/sprt.md)が禁じる操作に当たる。診断の基準の境界にかかる結果は「判断材料不足」とし、その追加は採らない。学習した重みの符号が直感と逆であることは、測定へ進まない理由にしない。 |
| 時間の見積もりを先に示す | 数時間を超える探索、生成、学習、および測定は、着手の前に所要時間の見積もりを利用者へ示す。 |

### 土台

| 項目 | 決定 |
|---|---|
| 主の土台は利き数の表 | 項目2、項目3、項目6、項目7は、升ごとの先後の利き数だけで定義どおりに計算できるので、利き数の表を主の土台とする。項目4と項目5も、安全な升の判定に利き数の表を使う。1つの土台が6項目を支え、評価の側は表を読むだけになるので、累算器を読むだけという現行の評価の性質を保てる。王手の判定と静的交換評価も同じ表を使えるので、費用の一部を探索の側で回収できる。tataraの推論側も同じ表を差分更新し、学習側の全計算と照合している。表が持つのは利きの数だけであり、利いている駒の識別は持たない。 |
| 全駒の利き集合は項目4と項目5にだけ使う | 項目4と項目5は駒ごとの到達升を要するので、利き数の表では計算できず、評価のたびに駒ごとの疑似利きを作る必要がある。走りの計算は駒1枚の1方向ごとに1回呼ばれ、1回の中央値は6.21 nsである。中将棋の初期配置で、片側の走り駒は香車2枚（各1方向）、反車、横行、竪行が各2枚（各2方向）、角行、飛車、龍馬、龍王が各2枚（各4方向）、奔王1枚（8方向）の17枚であり、走る方向の数は双方で108になる。108回の走りの計算だけで約0.67 μsとなって現行の1ノードの時間を上回るので、事前の試算では速度の条件を満たさない見込みである。この試算は単体の計測値からの見積もりであり、決定には使わない。フェーズ1では、全駒の利き集合を評価のたびに作る構成のNPSを参考として測る。利き数の表がまだないので、この構成は敵の利きがない升を全駒の利き集合の和から求め、本番の構成とは異なる。拘束力のある判定は、利き数の表を実装した後のフェーズ2で、本番と同じ構成を測って行い、NPSの比が直前の採用版の0.85倍に届かなければ、項目4と項目5は対局候補として実装せずに見送る。利き数の表を見送った場合も、項目4と項目5を見送る。 |
| 採らない土台 | マジックビットボードは、試作が現行の算術方式を上回らなかったので採らない。HaChu式のノードごとの利きマップは、駒のある升への利きしか持たず、王の周囲の空升の利き数を得られないので採らない。走り駒の到達升の数を差分で保持する方式は、安全な升が敵の利き数に依存し、盤上のどの利きが変わっても値が変わるので採らない。 |
| 速度の条件 | 土台の条件は、評価の償却、利き数の表の更新、および探索の側の利用を入れ、表を読む特徴を持たない構成のNPSが、段階開始版の0.90倍以上であることとする。項目の条件は、新しい項目の重みだけを0にした候補のNPSが、直前の採用版の0.85倍以上であることとする。土台を最初に使う項目の候補では、土台の費用も候補の側に含める。目的の節の換算で、0.90倍の損失は約33 Elo、0.85倍の損失は約51 Eloに当たり、これを特徴の効果が上回るかは時間制御GSPRTが判定する。2つの値は本書が置く目安であり、項目1の計算だけで0.91倍であることを参考に、1項目が負担できる費用の上限として選んだ。速度の条件は、見込みのない候補の学習と測定に数時間を使うことを避けるための事前の選別であり、条件を満たさない候補は採否測定へ進まない。土台の条件を満たさない場合は、利き数の表を見送り、王駒の近傍25升へ届き得る駒だけの利き集合で項目2と項目3を計算する構成に項目の条件を当てる。この場合、項目4から項目7は見送る。近傍の利き集合も項目の条件を満たさなければ、項目2と項目3も見送る。 |
| 速度の測り方 | 土台と、重みが0の候補は、探索木を変えない。`bench` 深さ5の総ノード数と15局面の最善手と評価値が基準と一致することを確かめ、NPSで判定する。測定は性能コアの1つへ固定し、各構成を3回ずつ、基準と交互に実行する。各回の値は `bench` が出力する3反復の中央値とし、構成の値は3回の中央値、判定に使う比は候補の値を基準の値で割った値とする。比が判定の境界から0.01以内の場合は、両方を5回ずつ測り直し、5回の中央値の比で判定する。回数を数えるビルドと速度を測るビルドは分け、計測用のカウンタはワーカーごとの局所変数に置く（[教訓](../lessons/shared-probe-counter-distorts-threads.md)）。 |
| 土台の採否 | 土台は単独では棋力を上げないので、土台だけの自己対局測定は行わない。利き数の表のコードは、それを読む項目が長時間測定で最初に採用された時点で、その項目と同じ統合でmasterへ入れる。表を読む項目2から項目7がすべて不採用または見送りとなった場合は、表のコードもmasterへ入れない。効果を確認できない状態をコードに残さないという[高速化（第2期）](movegen-speedup-2.md)の決定に従う。評価の償却は、追加特徴を持つ最初の採用候補と同じ統合で入れる。 |
| 償却の範囲 | 主探索は、futility pruning（静的評価が探索窓を大きく下回る手を読まずに省く枝刈り）の境界の計算と、correction history（静的評価と探索値の差を学習して静的評価を補正する表）の更新で、同じ局面の静的評価を別々に計算している。最初に計算した値をノードの中で保持し、2回目はその値を使う。置換表への静的評価の保存は扱わない。現行のエントリは2個の原子値からなり、照合キーと同じ語の空きは6ビットしかなく、もう一方の語へ評価値を置くと、並列探索で別の局面の評価値を読む可能性がある。エントリを広げると同じ容量で持てる件数が減って探索木が変わる。遅延評価（安い項で探索窓の外と判定できる局面で高い項の計算を省く方式）も探索木を変える。これらは、探索木を変えないという速度の測り方に収まらないので、必要になった時点で別の設計書として起案する。 |

### 特徴

| 項目 | 決定 |
|---|---|
| 項目と順序 | 項目は調査の上位7段階とし、番号は調査の順位に合わせる。測る順は、項目1、項目2、項目3、項目6、項目7、項目4、項目5とする。土台を使わない項目1を最初にし、利き数の表だけを使う項目2、項目3、項目6、項目7をその後に調査の順位で並べ、全駒の利き集合も要する項目4と項目5を最後に置く。項目1の候補は、評価の償却を含み、確定した教師の構成で重みを学習し直した新しい候補であり、停止した測定の候補とは別のコミットである。ただし、教師の構成が基本の教師のままとなった場合は、重みが停止した測定の候補と実質的に同じになり、シードを変えた再試行に近くなるので、項目1を測るかどうかを利用者が決め、測らない場合は見送りと記録する。停止した測定の候補を同じ条件で測り直すことはしない。調査の段階8（王の退路）は、移動先ごとに王駒を除いた仮想の占有で利きを判定し直す必要があり、利き数の表では計算できないので扱わない。段階9（歩と仲人の閉塞）は敗因への効果が間接的であり、本段階の採用後に歩を進めなくなる偏りが観測された場合にだけ別の設計書で扱う。段階10（王を基準にした駒の関係表）は、累算器の添字と学習器の特徴抽出の拡張を要し、学習で関係を表す方式が対局で劣った実績があるので扱わない。 |
| 固定する範囲 | 各項目の候補は、直前の採用版の全重みを初期値とし、新しく加える項目の重みだけを0から学習する。採用済みの学習PST、採用済みの追加特徴の重み、探索用駒価値47個、および出力Kは固定する。学習前の候補は直前の採用版と同じ評価値を返す。固定する理由は、採否の差を新しい項目だけに帰属させることと、評価値の尺度の変化が枝刈りに与える影響を避けることである。 |
| 特徴の形 | 追加特徴は、特徴値と重みの積の和として評価値へ加わる線形の項とする。数を数える量は区間ごとに別の特徴とし、各特徴は学習PSTと同じく序中盤と終盤の2端点の重みを持つ。各項目は、最も平常な状態に当たる区間に特徴を割り当てず、評価値への寄与を0とする。全部の区間に特徴を割り当てると、区間の和が駒の枚数と一致し、追加特徴が駒の価値を吸収するためである。Fairy-Stockfishの王の危険度は、学習する重みの和そのものを二乗する式であり、現行の線形モデルでは表せないので採らない。 |
| 視点と番号 | 各特徴は、対象の王駒または駒が手番側のものである場合と、相手側のものである場合で別の番号を持ち、重みを別に学習する。これは学習PSTが自駒と敵駒を別の番号にしていることに合わせる。 |
| 王駒が2枚の側 | 王駒を対象にする項目1、項目2、項目3、および項目6の接近の特徴は、対象の側の王駒がちょうど1枚の場合にだけ計算し、王将または玉将と太子が両方いる側の特徴値はすべて0とする。線形の和では「一方を取られても負けない」ことによる危険度の減衰を表せず、王駒の数ごとに番号を分ける方式は特徴数を倍にするためである。番号を分ける方式を起案する目安は、訓練の分割で王駒が2枚の側を含む局面が5%以上であることとする。発火率の診断でこの割合は0.81%だったので、特徴値を0とする方式を確定し、以後の結果を見て変えない。 |
| 特徴の計算の正 | 追加特徴はRustで1か所に実装し、対局時の評価と学習用の書き出しが同じ関数を呼ぶ。追加特徴をPythonで再実装しない。利き数の表を読む項目では、特徴の計算は表を引数に取り、探索は差分更新した表を、学習用の書き出しは局面から全計算した表を渡す。 |
| 成り権の保留状態 | MNSDは成り権の保留状態を保存しないので、特徴は盤面と手番だけから計算する。項目5は、敵陣の外から敵陣へ入る着手だけを対象にする。この着手は保留状態に関わらず成ることができるためである（RULES.md 第18条第1項）。 |
| 駒除去差分の扱い | 段階7の駒除去差分の損失と符号の検査は、元の局面の学習PSTの和から駒1枚の重みを引く式であり、追加特徴を含む評価値には使えない。駒を1枚除くと残った走り駒の利きが変わり、追加特徴の値も変わるためである。固定の候補では学習PSTの部分が1ビットも変わらないことを確かめ、評価値全体の除去差分は記録だけを行う。同時学習では、損失と符号の検査を学習PSTの部分にだけ適用する。 |
| 候補に含める範囲 | 各項目の対局候補は、採用済みの項目と今回の新しい項目だけを、特徴数の定数、重みファイル、実行時の特徴の計算のすべてで含む。まだ測っていない項目の計算を候補に含めると、その項目の費用まで今回の項目が負担するためである。未測定の項目を切り替えるフラグは置かない。全項目をまとめて計算する構成は、診断用のブランチにだけ置く。 |

### 教師

| 項目 | 決定 |
|---|---|
| 教師への3つの追加 | 追加Aは、基本の教師の中盤の露出局面を10,000,000ノードの探索で付け直す。追加Bは、実戦棋譜の局面を、対局結果だけを教師値とする教師の分類として加える。追加Cは、実戦開始の自己対局の局面を加える。それぞれの前提を、診断A、診断B、診断Cで先に確かめる。基準、主指標、標本の選び方は本書で固定し、診断の結果を見てから変えない。結果を見ながら標本を増やす手順は置かない。 |
| 混合の比は教師の分類ごとに定める | 自己対局の教師の分類は、乱数開始と実戦開始のどちらも、探索値75%と対局結果25%の混合（λ=0.75）のまま固定する。理由は、変数を増やさず段階7までの採用構成と比較できる状態を保つことである。実戦棋譜の教師の分類は、λ=0、すなわち対局結果だけを教師値とする。実戦棋譜の局面に付ける探索値は現行の評価関数の探索値であり、本書が原因と疑う盲点をそのまま持つ。実戦棋譜が持ち込む新しい情報は対局結果だけなので、λ=0.75で混ぜると、その情報は教師値の25%へ薄まる。やねうら王の教師の加工の道具も、実戦棋譜を探索値なしで対局結果と指された手だけの教師へ変換する。混合の比はデータの由来で決まる教師の分類の属性であり、局面の内容では変えない。λ=0の値は結果を見て変えず、中間の値を探索しない。 |
| 採らない教師の変更 | 全局面のノード数の引き上げは採らない。世代2の生成は14,057,872局面に約17.7時間を要したので、ノード数を10倍にすると約1週間かかり、敗局の174手目の局面は対局時の深さ12で+1037、90秒の深さ14でも+880であって、探索を数倍深くしても危険が見えなかった。静止探索の末端の局面を教師にする方式は、探索値と静的評価の不一致を減らすが、王の危険という盲点には関係しないので採らない。自分より強い評価器による教師値の付け替えは、minaseより強く規則を一致させられる評価器がないので採れない。探索木の内部で見た局面を保存する方式は、枝刈りで得た上下界と正確な値の区別を要し、探索を変えない本書には入れない。 |
| 付け直しの探索の条件 | 付け直しは、保存済みの局面を `Record::to_position` で復元し、その局面だけを履歴の最初として探索する。探索の経路の中の反復は検出するが、保存前の対局の履歴は復元しない。各局面の各ノード数の探索の前に置換表を消去し、探索は1スレッド、置換表は生成器と同じ16 MBとし、並列化は局面の単位で行って置換表を共有しない。ノード数の上限で中断した探索は最後に完了した深さの値を返すので、実際のノード数と完了した深さを保存する。 |

## 土台

### 評価の償却

主探索の静的評価を1ノードで1回にまとめる。
静止探索は1ノードで1回しか評価しないので変えない。
この変更は探索木を変えず、追加特徴を持つ全部の候補の速度に効くので、土台の最初に入れる。

### 利き数の表と走りの方向の表

表は、探索が持つplyごとの配列に置き、学習PSTの累算器と同じく、親の表を子へ写してから着手の差分を適用する。
`Position` には持たせない。
`Position` へ置くと、着手の取り消し、等価性、およびハッシュの契約に触れるためである。
表は、先後の利き数が各192バイト、走りの方向が384バイトの合計768バイトである。
前送りは、通常探索、静止探索、およびnull move（手番だけを渡す仮の着手）のすべての経路で行い、盤面が変わらないnull moveとじっとでは写しだけを行う。
写しだけを行う構成のNPSの比が0.97を下回る場合にだけ、取り消しつきの更新へ変える。

更新は「升から駒を除く」と「升へ駒を置く」の2つの操作だけで構成し、着手はこの操作の列へ分解する。
獅子が1手で2枚を取る着手は除く操作2回と獅子の移動で、居喰い（隣接する敵駒を取って元の升へ戻る着手、RULES.md 第12条）は除く操作1回で、成りは移動元から元の駒種を除いて移動先へ成駒を置く操作で表せる。
利き線をどこで止めるかは占有で決まるので、更新は着手の適用前の占有の写しから始め、操作を1つ適用するたびにその写しを更新して、次の操作へ渡す。
着手の適用後の占有を全部の操作へ渡すと、移動元からの利きの減算が移動先の自分自身で止まって古い利きが残り、適用前の占有を全部の操作へ渡すと、移動先からの利きの加算が移動元で止まる。
学習PSTの累算器は着手の適用後に更新しているので、表の更新は、適用前の占有を着手の適用の前に取っておく。
やねうら王は移動元と移動先の更新を相殺する工夫を持つが、最初の実装には含めず、測定で必要と分かった場合にだけ加える。

升から駒を除く操作は、次の順に行う。

1. 除く駒の短い利きが届く各升の、その色の利き数を1減らす。
2. 除く駒の走りの方向ごとに、隣の升から順に進み、各升でその色の利き数を1減らして走りの方向のビットを消す。駒のある升も更新に含め、その升で止まる。
3. 除いた升の走りの方向の表が記録している方向ごとに、その先へ同じ手順で進み、各升で利き数を1増やして走りの方向のビットを立てる。除いた駒が遮っていた利きが、先へ伸びるためである。

升へ駒を置く操作は、この逆である。
置く升に届いていた利きを先で打ち切ってから、置いた駒の短い利きと走りの利きを加える。
置いた升に届いていた利きの方向のビットは、その升では残す。
駒のある升のビットは「この駒がなくなれば先へ伸びる利き」を表すためである。

全計算の関数は、局面から表を最初から作り直す関数であり、差分更新の結果を検査する基準になる。
この関数は、空の盤へ置く操作を順に適用する形では実装せず、各駒の疑似利きを現在の占有で計算して加える独立の実装とする。
置く操作を使い回すと、置く操作の誤りが差分更新と全計算の両方に同じ形で現れ、2つを比べても食い違いが出ないためである。
学習用の書き出しは、この全計算の関数で表を作る。

### 探索の側の利用

王手の判定を、全部の王駒の升の利き数の参照へ置き換える。
静的交換評価（SEE）は、最初の逆引きの前に移動元を占有から除くので、到達升の現在の利き数が0でも、移動元が空くことで敵の走りが通って取り返される場合がある。
そこで、逆引きを省く条件は、到達升の敵の利き数が0であり、かつ移動元へ届いている敵の長い利きが1つもないこととする。
移動元へ敵の長い利きが届いていなければ、移動元を空けても敵の利き線は伸びず、短い利きは占有に依存しないので、この条件の下では省略しても結果が変わらない。
獅子の足の判定は仮想の盤面を使うので置き換えない。
どちらの置き換えも探索木を変えないことを `bench` の総ノード数の一致で確かめ、NPSが置き換えの前を下回る置き換えは採らない。

### 全駒の利き集合

項目4と項目5のための土台であり、フェーズ2の測定が項目の速度の条件を満たした場合にだけ、対局候補として実装する。
評価の中で、王駒を除く全部の駒について、疑似利きを現在の占有で1回ずつ計算し、項目4と項目5が同じ結果を使う。
敵の利きがない升の集合は、利き数の表から作る。

## 特徴

### 共通の基盤

追加特徴を評価と学習へ通す次の仕組みは、ブランチ `strength-stage9` に実装済みであり、本書はそのまま使う。

- 追加特徴は、学習PSTの13,680特徴の直後から番号を振り、特徴数の定数を学習PSTの分と追加特徴の分に分けて持つ。重み形式MNPTは、ヘッダの特徴数と本体の長さが実行バイナリの定数と一致することを検査するので、形式の版は変えない。候補を作るときは、特徴数の定数の変更と重みファイルを同じコミットにそろえ、不採用なら両方を戻す。
- 採用済みの重みを新しい特徴数の配置へ移す1度限りの変換を、学習器の側に置く。変換は、各端点の既存の重み、探索用駒価値47個、出力Kを保持し、新しい特徴の重みだけを0にして、特徴数と検査和を更新する。変換した重みと元の重みが、診断の標本の全局面で同じ評価値を返すことを確かめる。
- 学習PSTの部分は探索の累算器が差分更新し、追加特徴の部分は静的評価を呼ぶ時点の局面と土台から毎回計算する。評価の関数は、累算器の2端点の和の一時的な写しへ追加特徴の和を加えてから補間し、累算器そのものへは加えない。累算器を使わない公開の全再計算の関数も、同じ追加特徴を加える。
- `pst_probe` は、MNSDの各局面について追加特徴の特徴値を、局面の順に、固定長の符号なし8ビット整数の列として書き出す。特徴値は駒または升の数なので最大92であり、値が範囲を超えた場合は丸めずにエラーで終了する。書き出したファイルは、入力のMNSDの検査和、局面数、列数、特徴の定義の識別値を先頭に持ち、学習器は読み込み時にこれらを照合する。学習器は、候補が使う列だけを選んで読む。
- 学習器は、鏡映を共有する学習PSTの重みと、追加特徴の重みを、別のパラメータとして持つ。追加特徴は、王駒からの距離、駒の区分、および数で定義するので、左右の鏡映について初めから対称である。固定の候補では、新しい項目の重みだけを最適化の対象にする。段階7の保存範囲への射影は、追加特徴の重みにも適用する。損失、出力K、検証分割、乱数シードは段階7の採用構成に合わせる。

特徴の除外と端点の共有は、確定した教師の構成の訓練の分割だけを使い、学習の前に次の規則で決める。
発火率が0.1%未満の特徴は、その項目から除外する。
0.1%は基本の教師の訓練の分割の約2,388万局面のうち約2.4万局面に当たり、これを下回る特徴は重みを安定に決められないと見込むためである。
区間の統合と、区間の境界の変更は行わない。
ある項目の全特徴が除外された場合は、その項目を学習と測定へ送らず、見送りを記録する。
2端点の識別性は、特徴値の二乗を重みとした補間係数φの偏差平方和で判定し、100未満の特徴は2端点で同じ重みを共有する。
端点ごとの説明変数は特徴値とφの積、および特徴値と1−φの積であり、その分散は特徴値の二乗に比例するので、二乗を重みにする。
2以上の特徴値を取る特徴に同じ閾値100を使うことは本書が置く経験則であり、診断で指標の値を全特徴について記録する。

追加特徴の列は、項目の番号の順、対象が手番側のものか相手側のものかの順、各項目の節が特徴を挙げる順に並べ、距離を持つ特徴は距離の小さい順に並べる。

各候補が持つのは、このうち採用済みの項目と新しい項目の列だけである。

### 項目1　王の遮蔽と開いた筋（king shelter and open files）

王駒の筋と、その左右2筋までの最大5筋を対象にし、王駒との筋の差を距離0、1、2とする。
各筋について、王駒の段より厳密に前方で盤端までの升に、守る側の成っていない歩兵または仲人があるかと、攻める側の成っていない歩兵または仲人があるかを調べる。
筋の状態は、「守る側の歩がある」「守る側の歩がなく攻める側の歩がある」「双方の歩がない」の3つである。
1つ目の状態には特徴を割り当てない。
特徴は、距離の3区分と後ろ2つの状態の組の6個であり、特徴値はその組に当たる筋の本数である。

項目1は、これとは別に走り駒の特徴を6個持つ。
守る側の歩がない筋のそれぞれについて、王駒の段より厳密に前方にいる攻める側の縦の走り駒の枚数を数え、「1枚」「2枚以上」に分ける。
特徴は、距離の3区分とこの2区分の組の6個であり、特徴値はその組に当たる筋の本数である。
縦の走り駒は、攻める側から見て前方へ任意の升数を進める駒とし、駒種の判定は利きの表の走りの方向から導く。
この特徴は「歩のない筋に縦の走り駒がいる」ことを表し、途中の駒による遮蔽は見ない。
遮蔽を考慮した実際の利きは項目2が受け持つ。

敗局の173手目終了後の局面の後手玉3aを例にする。
対象は1筋から5筋であり、後手の歩は5筋にだけあり、先手の歩は4筋にだけある。
筋の状態の特徴値は、「双方の歩がない」の距離0（3筋）、距離1（2筋）、距離2（1筋）がそれぞれ1、「守る側の歩がなく攻める側の歩がある」の距離1（4筋）が1であり、残りは0である。
走り駒の特徴値は、「1枚」の距離0（3筋の飛車）と距離1（2筋の竪行）がそれぞれ1、「2枚以上」の距離2（1筋の反車と香車）が1であり、残りは0である。
項目1の計算は実装済みであり、段ごとの前方の升の集合と縦の走り駒の駒種を前計算する実装で、NPSの低下は8.5%から9.3%である。

### 項目2　王の周囲の攻撃域（king attack zone）

王駒からチェビシェフ距離1の最大8升と、距離2の最大16升を対象にし、王駒自身の升は含めない。
各升について、攻める側の利き数と、守る側の利き数から王駒自身の利きを除いた数を、それぞれ0、1、2以上に切り詰める。
王駒自身の利きは距離1の升にだけ届くので、距離1の升で守る側の利き数から1を引く。
2つの数の組は3×3の9通りあり、双方が0の組には特徴を割り当てない。
特徴は、距離ごとに残りの8通り、2つの距離で16個であり、特徴値はその組に当たる升の数である。
この形は、やねうら王の実験用の評価（MATERIAL_LEVEL 6）が全升に使う利きの数の9区分を、王駒の近傍に限って学習の対象にしたものである。
王の周囲を攻める駒の枚数は、駒の識別を要して利き数の表から計算できないので、特徴にしない。
攻めの集中は、利き数が2以上の区間が受け持つ。

### 項目3　王の守備駒（king defenders）

王駒からチェビシェフ距離1の最大8升を対象にする。
各升について、守る側の駒があるかと、王駒自身を除く守る側の利きがあるかを調べる。
特徴は、この2つの組のうち「駒がなく利きもない」を除いた3個であり、特徴値はその組に当たる升の数である。
この形は、やねうら王の実験用の評価（MATERIAL_LEVEL 8）の玉の8近傍の項と同じである。
HaChuの特定の囲いの形は移さない。

### 項目4　安全な可動性（safe mobility）

歩兵、仲人、および王駒を除く各駒について、安全な升の数を数える。
同じ升への成りと不成、獅子の複数の経路は1升と数える。
特徴は、駒の区分ごとに、安全な升の数の区間に当たる駒の枚数である。
区間は、小駒が「0」「1から2」、片走り駒が「0」「1から2」「3から5」、大駒が「0から2」「3から5」「6から9」「10から14」、獅子が「0から3」「4から9」であり、これより多い区間には特徴を割り当てない。
走り駒が多く盤が広い中将棋では、升数に比例する無制限の加点が走り駒の展開を過大に評価するので、可動性が乏しい状態だけを区間で表す。
区間の境界は本書が置く経験則であり、発火率の診断で安全な升の数の分布を区分ごとに記録するが、境界は結果を見て変えない。

### 項目5　成りの可能性と侵入（promotion potential and invasion）

敵陣の外にいる成っていない駒のうち、敵陣の中に安全な升を持つ駒の枚数を数える。
特徴は、成りの区分ごとの枚数の3個である。
成りの区分は、麒麟、鳳凰、醉象の「大きい成り」、飛車、角行、龍馬、龍王、香車、反車、横行、竪行の「走り駒の成り」、および金将、銀将、銅将、猛豹、盲虎、歩兵、仲人の「小駒の成り」である。
既に成った駒の価値と、敵陣の中にいる駒の位置の価値は学習PSTが持つので、この項は、次の1手で安全に成れる見込みだけを加える。
歩兵と仲人は項目4の対象ではないが、本項目では前方の1升が敵陣の中の安全な升であるかを調べる。

### 項目6　獅子の接近と退路（lion proximity and trapped lion）

獅子には、麒麟が成った獅子を含む。
接近の特徴は、相手の王駒がちょうど1枚の場合に、自分の獅子と相手の王駒のチェビシェフ距離を「2以下」「3から4」「5から6」に分けた3個であり、特徴値はその区間に当たる獅子の枚数である。
孤立の特徴は、獅子の升に敵の利きがあり味方の利きがない獅子の枚数の1個である。
退路の特徴は、獅子に隣接する升のうち安全な升の数を「0から1」「2から3」に分けた2個であり、特徴値はその区間に当たる獅子の枚数である。
距離だけの加点が獅子の無理な突入を招かないよう、接近は孤立と退路と同じ項目にまとめて学習する。
獅子の升への敵の利きは疑似利きであり、獅子による獅子の捕獲制限と先獅子の状態は反映しない。
HaChuの `LIONTRAP` の隅の表は移さない。

### 項目7　駒への脅威と浮き駒（threats and hanging pieces）

小駒、片走り駒、大駒、獅子の各駒について、その升の敵の利き数と味方の利き数を調べる。
特徴は、駒の区分の4つと、「敵の利きがあり味方の利きがない」「敵の利きがあり味方の利きもある」の2つの組の8個であり、特徴値はその組に当たる駒の枚数である。
敵の利きがない駒には特徴を割り当てない。
攻撃側と標的側の駒種の全組を独立に学習する形は、特徴数が多く、利いている駒の識別を要するので採らない。
捕獲で実現する利得を直接に加点すると静止探索と二重に計上しやすいので（[教訓](../lessons/correction-history-exclude-tactical-gains.md)）、特徴は支えの有無の区別を中心に置く。
この形は、やねうら王の実験用の評価（MATERIAL_LEVEL 7）と、盤上の駒の升の利き数を0、1、2以上に分けるtataraの入力特徴に近い。

## 教師

### 教師の構成の決め方

教師の構成は、基本の教師に、診断の基準を満たした追加だけを加えたものとする。
3つの診断がすべて終わった時点で構成を確定し、測定記録 `strength-stage9-teacher-composition` に、採った追加、採らなかった追加、およびそれぞれの診断の結果を記す。
どの追加も基準を満たさなかった場合は、基本の教師をそのまま教師の構成とする。
確定した構成は、全部の項目の学習と、最後の同時学習に使う。

診断B、診断C、および露出局面の判定が使う特徴値は、フェーズ3の診断用の構成が書き出す項目1と項目2の列である。

### 診断A　深い探索の感度

診断Aの問いは、10,000,000ノードの探索が、100,000ノードの探索に比べて、中盤の露出局面の値を対照局面より下げるかである。
局面ごとに、10,000,000ノードの値から100,000ノードの値を引いた差dを求める。
探索を深くすると値はどの局面でも多少は動くので、露出局面のdの平均だけでは、王の露出による変化か、深い探索の一般的な変化かを区別できない。
そこで主指標を、露出局面のdの平均から対照局面のdの平均を引いた値Dとする。
100,000ノードの値は保存済みの値を使わずに測り直す。
保存済みの値は、対局中の置換表を引き継いだ探索の値だからである。

露出局面と対照局面は、形勢、教師の世代、手番などの構成が違うと、その違いがDに混ざる。
これを防ぐために、局面を層に分け、層の中で露出局面と対照局面を比べる。
層は、教師の世代（3通り）、手番の先後（2通り）、相手側の王駒の数（1枚か2枚かの2通り）、および保存済みの教師の探索値の5つの区分（−500未満、−500以上−100未満、−100以上+100未満、+100以上+500未満、+500以上）の組であり、最大60層になる。
手番側の王駒が1枚でない局面は、露出を判定できないので、対象から除いて件数を数える。
主指標は `D = Σ w_h × (層hの露出局面のdの平均 − 層hの対照局面のdの平均)` とし、重み `w_h` は、対象の局面の全体で層hが露出局面に占める割合に固定する。

診断は次の順で進める。

1. 探索を行わずに、訓練の分割の中盤の局面について、層ごとの露出局面と対照局面の数、および対局の数を数え、重み `w_h` を確定する。
2. 対局番号のハッシュで対局を予備用と本番用に分け、同じ対局が両方に入らないようにする。
3. 予備用の対局から、層の重みに比例した数の露出局面と対照局面を層ごとに同数ずつ、合計で各群1,000局面を固定シードで抽出し、2つのノード数で付け直す。本番と同じ推定量でDを求め、対局を単位とする再標本化でDの標準誤差と、16並列での1局面あたりの探索時間を測る。
4. 本番の各群の局面数を、Dの標準誤差が12センチポーンになる数とする。標準誤差は局面数の平方根に反比例するとみなして、予備標本の標準誤差から求める。12センチポーンは、真のDが−60センチポーンのときに検出力80%で基準を満たす値であり、30センチポーンを `1.645 + 0.84` で割って得る。
5. 本番の探索の見積もりが12時間を超える場合は、本番を行わず、到達できる検出力を記録して「判断材料不足」とする。
6. 本番用の対局から同じ方法で抽出し、2つのノード数で付け直して判定する。

判定は、2つのノード数の両方で通常の値を持つ局面について行う。
除外の後に片方の群が空になった層は外し、残りの層の重みを合計が1になるよう直して、外した層の重みの合計を記録する。
信頼区間は、同じ対局の全部の局面を群と層をまたいで一緒に扱う再標本化を2,000回行い、毎回同じ推定量を計算して求める。
Dが負で大きければ、深い探索は露出局面に限って、浅い探索が見ていない危険を見ていることになる。
基準は、Dの片側95%の信頼区間の上端が−30センチポーン以下であること、すなわち、誤差を見込んでもDが−30センチポーンより負の側にあることとする。
−30センチポーンは、付け直しの費用をかける価値があると本書がみなす運用上の最小の差であり、項目1が敗局の局面で動かした評価値と同じ大きさから選んだ。
詰みの帯へ移った局面は、群ごとに、勝ちと負けの別に割合を記録するが、判定には使わない。

### 診断B　実戦棋譜の信号

診断Bの問いは、実戦棋譜で、学習PSTの予測に王の安全度の特徴を加えると対局結果の予測が改善するかである。
受理した対局の全局面を、既定の規則セットの100,000ノードで探索し、生成時の3つの除外を適用する。
追加Bの教師値は対局結果だけなので、この探索値は教師値には使わず、自己対局のデータと同じ除外を適用して局面の種類をそろえるためにだけ使う。

棋譜は最初に、棋譜のIDのハッシュで、診断用の対局と検証用の対局へ半分ずつ分ける。
検証用の対局は、モデルの係数と設定を決め終えるまで一切使わず、最後に1度だけ損失の計算に使う。
目標は、手番側から見た対局結果である。

基準のモデルは、学習PSTの予測のロジット（学習PSTの評価値を出力Kで割った値）を係数1の固定の項とし、双方のレーティングの差、双方のレーティングの平均、持ち時間の区分、手番の先後、および駒数の帯を説明変数とするロジスティック回帰である。
候補のモデルは、これに追加特徴の10列を加える。
10列は、手番側の王駒についての、項目1の走り駒の6列と、項目2のうち攻める側の利き数が1または2以上で守る側の利き数が0である区間の4列である。
2つのモデルの係数は診断用の対局だけで決め、正則化などの設定も診断用の対局の中で確定する。
主指標は、検証用の対局における、対局ごとの平均の対数損失の差の平均とし、差は基準のモデルの損失から候補のモデルの損失を引いた値とする。
基準は、この平均の片側95%の信頼下限が0を超えることとし、信頼区間は対局を単位として求める。
特徴ごとの係数は方向の確認のために併記し、列の多数決は行わない。

### 診断C　実戦開始の自己対局の信号

診断Cの問いは、実戦開始の自己対局が、乱数開始の自己対局より、王の安全度の特徴と対局結果の結びつきを強く含むかである。
既存の世代0から世代2のデータは学習PSTの訓練に使われているので、比較の相手には使わず、乱数開始の自己対局も新しく生成する。

開始局面の全体を確定し、その中から、1つの棋譜につき最大1局面の条件で、固定シードで2,000局面を抽出する。
この2,000局面から実戦開始の自己対局を1局ずつ生成し、同じコミット、重み、ノード数、および設定で、未使用のシードから乱数開始の自己対局を2,000局生成する。
世代0の生成は5,120局に約1.6時間を要したので、4,000局の目安は約1.3時間である。

2つの群のそれぞれで、対局を、実戦開始では棋譜のIDのハッシュ、乱数開始では対局番号のハッシュで、係数を決める対局と検証の対局へ半分ずつ分ける。
対象は、生成時の除外を通過した中盤の局面であり、目標は手番側から見た対局結果である。
基準のモデルは、学習PSTの予測のロジットを係数1の固定の項とし、手番の先後と駒数の帯を説明変数とするロジスティック回帰である。
候補のモデルは、これに診断Bと同じ10列を加える。
群ごとに、係数を決める対局だけで2つのモデルの係数と設定を決め、検証の対局で、対局ごとの平均の対数損失の差の平均 `g` を求める。
主指標は `G = g(実戦開始) − g(乱数開始)` とし、信頼区間は、群ごとに対局を単位とする再標本化を2,000回行って求める。
基準は、`g(実戦開始)` の片側95%の信頼下限が0を超え、かつGの片側95%の信頼下限が0を超えることとする。
Gだけで判定すると、両方の群で予測が悪化していても、悪化の小さい側が通過するためである。

2つの群は、開始局面の形勢の絞り込み、駒数、手数、および特徴の出現頻度が異なるので、Gはこれらの分布の差を含む。
したがって、本診断の結論は「生成方式の全体として、実戦開始の自己対局の方が王の安全度の特徴について多くの情報を持つ」に限定する。
各群2,000局は生成の時間から決めた予算であり、検出力から決めた数ではない。

次の場合は「判断材料不足」とし、追加Cを採らない。

- 開始局面の条件を満たす棋譜が1,000に満たない場合。1,000以上2,000未満の場合は、全部の棋譜から1局面ずつを使い、乱数開始も同じ数だけ生成する。
- 手数上限による破棄と、中盤の記録が1つもない対局を除いた後の検証の対局が、どちらかの群で300に満たない場合。除いた対局は補充せず、件数を記録する。
- ロジスティック回帰が収束しない場合、または再標本化の5%以上で指標を計算できない場合。
- 2つの条件のどちらかで、信頼区間が0をまたぐ場合。

### 追加の作成

追加Aは、診断Aが基準を満たした場合に、基本の教師の全データのうち、中盤の露出局面を10,000,000ノードで付け直す。
診断Aが調べたのは中盤の局面だけなので、終盤の局面は元の教師値のままにする。
対象の局面数と診断Aで測った探索時間から所要時間を見積もり、48時間を超える場合は、固定シードの抽出で48時間に収まる数へ減らし、抽出の前後の数を記録する。

追加Bは、診断Bが基準を満たした場合に、診断Bで作った全対局の局面を、λ=0の教師の分類として加える。
診断Bの検証用の対局は、学習の検証の分割に入れる。

追加Cは、診断Cが基準を満たした場合に、開始局面の全体のうち診断Cで使っていない局面から、実戦開始の自己対局を1局面につき1局ずつ生成し、診断Cの実戦開始の2,000局と合わせて、λ=0.75の教師の分類として加える。
診断Cの乱数開始の2,000局は、比較のための記録として保持し、教師の構成には加えない。
所要時間の見積もりが12時間を超える場合は、固定シードの抽出で12時間に収まる数へ減らし、抽出の前後の数を記録する。

## 実装フェーズ

フェーズ1からフェーズ3は速度と特徴値だけを扱い、フェーズ4とフェーズ5は教師だけを扱うので、2つの系列は並行して進められる。
依存は2つある。
診断A、診断B、診断Cは、フェーズ3の診断用の構成が書き出す項目1と項目2の列を使うので、フェーズ3の書き出しの完成を待つ。
`bench` による速度の測定は、他の負荷でNPSが揺れることを避けるために、探索や生成が同じ測定機で動いていない時間に行う。

### フェーズ1　評価の償却と土台の費用の診断

主探索の静的評価を1ノードで1回にまとめ、総ノード数と評価値が変更前と一致することを確かめる。
続けて、診断用のブランチで次の量を `bench` 深さ5で測り、測定記録 `strength-stage9-foundation-diag` に残す。

- 項目1の候補の構成での、評価の償却によるNPSの変化。
- 静的評価の呼び出し回数の、呼び出し箇所ごとの数と、ノード数に対する比。
- 王手の判定の呼び出し回数と、静的交換評価の呼び出しのうち省略の条件を満たす割合。条件は逆引きで判定する。
- 1手あたりに利き数が変わる升の数。着手の前と後の局面でそれぞれ利き数の表を全計算し、値が異なる升と色の組を数える。この数は、差分更新が1手で書き換える升の数の下限である。
- 全駒の利き集合を評価のたびに作り、項目4と項目5の特徴値を計算する構成のNPS。重みはすべて0とする。敵の利きがない升は全駒の利き集合の和から求める。この値は参考であり、項目4と項目5の判定には使わない。
- 王駒を中心とする5×5の25升へ、他の駒がないと仮定したときに届き得る駒だけの利き集合を作り、項目2と項目3の特徴値を計算する構成のNPS。この値は、土台の条件を満たさなかった場合にだけ使う。

完了条件は、測定記録が保存されていることである。

### フェーズ2　利き数の表と探索の側の利用

利き数の表、走りの方向の表、2つの更新の操作、全計算の関数、plyごとの前送り、および探索の側の利用を実装する。
続けて、利き数の表から敵の利きがない升を求める本番と同じ構成で、全駒の利き集合を評価のたびに作って項目4と項目5の特徴値を計算する構成のNPSを測り、直前の採用版の0.85倍に届かなければ、項目4と項目5を見送る。
見送った項目は対局候補として実装しないが、診断用の構成は118列の全部の計算を保持する。
完了条件は、検証の節の一致の確認がすべて通り、土台の条件に対する結論と、項目4と項目5を実装するかどうかが、測定記録 `strength-stage9-table-bench` に残っていることである。
記録には、写しだけの構成、表の更新を加えた構成、探索の側の利用を加えた構成、および項目4と項目5の構成のNPSを分けて残す。

### フェーズ3　特徴値の書き出しと発火率の診断

診断用のブランチで、全計算の表から118列の特徴値を書き出す構成を作り、基本の教師について、特徴ごとの発火率と特徴値の分布、端点の識別性の指標、特徴どうしの相関、学習PSTの予測と教師値の残差に対する各特徴の相関、安全な升の数の駒の区分ごとの分布、および敗局の検証局面における各特徴値を記録する。
本フェーズは速度に関わらないので、フェーズ2と並行して進められる。
完了条件は、測定記録 `strength-stage9-activation-diag-b` が保存されていることである。
特徴の除外と端点の共有は、教師の構成が確定した後のフェーズ6で確定する。

### フェーズ4　教師の道具と診断A

`selfplay_gen` に、保存済みのMNSDを付け直して付け直しファイルを書く操作を加え、来歴ファイル、学習器の付け直しファイルの読み込み、および教師の分類ごとの教師Kと混合の比を実装する。
完了条件は、次のことがテストで固定され、測定記録 `strength-stage9-depth-sensitivity` が保存されていることである。

- 同じ入力、バイナリ、重み、規則、置換表の容量、ノード数の上限で出力が再現する。
- 付け直しは元のMNSDファイルへ何も書き込まず、付け直しの前後で元のファイルの検査和が変わらない。
- 付け直しファイルで差し替えた学習の入力が、同じ値を直接書き込んだMNSDファイルを読んだ場合と、局面、教師値、除外の結果のすべてで一致する。
- 元のファイルの検査和または記録数が一致しない付け直しファイルと、同じMNSDファイルが2回入る入力が拒否される。
- 中断した付け直しは、条件とバイナリが一致するときだけ再開し、再開した出力が中断のない出力と一致する。
- 教師の分類が異なれば、同じ重みの検査和でも教師Kが別に推定され、λ=0の分類の教師値は対局結果だけになる。

### フェーズ5　実戦棋譜の取得、診断B、診断C、教師の構成の確定

利用条件の確認、取得の道具の作り直し、棋譜の取得、既定の規則セットでの再生と教師データへの変換、100,000ノードの探索、および診断Bを行う。
レーティングと持ち時間の区分は、MNSDに入れず、棋譜のIDで引ける付随の表に置く。
続けて、`selfplay_gen` に、開始局面の一覧を受け取って1局面につき1局を生成する操作を加え、開始局面の確定と診断Cを行う。
開始局面の一覧は、局面と、棋譜のIDおよび手数を持ち、生成器はこれを対局番号との対応表として来歴ファイルへ書く。
基準を満たした追加のデータを作成し、教師の構成を確定する。
完了条件は、測定記録 `strength-stage9-human-signal`、`strength-stage9-human-start-signal`、および `strength-stage9-teacher-composition` が保存されていることである。

### フェーズ6　項目ごとの候補

確定した教師の構成の全部のファイルについて118列の特徴値を書き出し、特徴の除外と端点の共有を確定する。
続けて、設計判断の表の順に、項目ごとに次の手順を進める。

1. 直前の採用版へ新しい項目だけを加えた候補を作り、新しい項目の重みだけを0にした `bench` で項目の速度の条件を確かめる。
2. 条件を満たした候補を、確定した教師の構成で学習し、検証の節の診断を通す。最初に測る項目では、基本の教師だけで学習した重みも記録する。
3. 学習した重み、検証局面での寄与、および測定の所要時間の見込みを利用者へ示してから、STC、LTCの順に測る。
4. 採用した場合は候補が直前の採用版になり、不採用の場合は項目の実装をコードから外す。

完了条件は、各項目の採否または見送りが、測定記録とともに本書の状態へ反映されていることである。

### フェーズ7　世代3の生成と同時学習

固定の候補は各項目の効果を切り分けるためのものであり、学習PSTは王の安全度の平均的な効果を升の重みへ既に取り込んでいる。
同時学習の目的は、追加特徴がその効果を受け持った後の学習PSTを合わせ直すことと、王の安全度を測れる評価で教師を作り直すことである。
1つ以上の項目を採用した場合に、最後の採用版で世代3の教師データを生成し、確定した教師の構成へ世代3を加えた入力で、学習PSTと追加特徴の全重みを同時に学習した候補を、STCとLTCで測る。
この候補の結論は、「教師の変更、世代3、および同時学習を含む学習の工程全体の効果」と表現する。
生成の条件は段階7の世代2と同じとし、生成の基本シードは1,200,000から100,000刻みの5個とする。
世代2の生成は14,057,872局面に約17.7時間を要し、追加特徴の費用の分だけ長くなる。
同時学習の候補が採用された場合は、段階7の基準で探索用駒価値を再導出し、更新の基準である20%を超える差があれば、駒価値を更新した候補を別の1候補として測る。
採用した項目がない場合は、本フェーズを実行しない。

最終構成について、段階開始版との固定200ペアのEloを `time=10000+100` で、HaChuとの固定200ペアのEloを上位計画の検証の節が定める条件で記録する。

## 検証

- 各特徴は、手で特徴値を数えた局面によるテストで固定する。局面には、盤端と隅の王駒、王駒と同じ段に歩がある配置、走りの途中に遮蔽駒がある配置、同じ獅子が複数の経路で同じ升へ届く配置、王駒が2枚の側、可動性が0の駒、敵陣の手前の駒、孤立した獅子、支えのある駒とない駒、および手番を入れ替えた配置を含める。期待値は実装の出力からではなく、本書の定義と RULES.md の駒の動きから導く。
- 利き数の表は、`bench` の15局面、ランダム対局の局面、および手作りの局面で、差分更新の結果と全計算の結果が全升で一致することを確かめる。手作りの局面には、獅子の2枚取り、居喰い、成り、太子の誕生、王駒に隣接して駒が密集する配置、同じ線上に同色と異色の走り駒が並ぶ配置、および駒が動いて別の走り駒の利きが通る着手を含める。tataraの設計の記録は、長い利きの更新の漏れが、駒が動いて通る利きの変化を黙って落とすことを落とし穴に挙げている。
- 全計算の結果は、全升と両方の色について、`attackers_to_by` が返す集合の枚数と一致することを確かめる。`attackers_to_by` は既存の利き生成との一致テストを持つ独立の参照である。
- 走りの方向の表は、全升と全方向について、その升から逆方向へ最初に当たる駒がその方向へ走る駒であることと、ビットが立っていることが同値であることを確かめる。
- 探索の中では、デバッグビルドで、評価を呼ぶたびに差分更新の表と全計算の表の一致を検査する。
- 追加した検査は、更新の操作の1つを一時的に誤らせて失敗することを確かめてから採用する（[教訓](../lessons/confirm-regression-test-fails-without-fix.md)）。
- 陣営の入れ替え、段の反転、手番の入れ替えを同時に行った局面で、手番側から見た評価値が元の局面と等しいことを、固定シードのランダムな局面で検査する。左右の鏡映でも同じ検査を行う。
- 0でない追加特徴の重みを持つ重みファイルで、探索が使う評価値と公開の全再計算の評価値が、探索中の全ノードで一致することを検査する。0の重みだけでは、呼び出しの漏れを検出できないためである。
- 実戦棋譜の変換は、既存の[全棋譜の再生の固定データ](../../tests/fixtures/lishogi_replays.ndjson.gz)の13局に、最終の盤面を手で確かめた対局、途中の局面から始まる対局、時間切れの対局、対応表にない終局の理由の対局、および勝者の記載がない対局を加えた固定データで、取り込みと除外の結果をテストで固定する。
- 開始局面の一覧から生成した対局は、1手目の局面が一覧の局面と一致し、開始局面そのものが教師データに記録されていないことをテストで固定する。
- 診断A、診断B、診断Cの抽出は固定シードで行い、抽出した局面の通し番号と層の割り当てを保存して再現できるようにする。
- 学習した候補は、GSPRTの前に次の診断を通す。固定した学習PST、採用済みの追加特徴の重み、探索用駒価値、出力Kが、学習の前後で1ビットも変わらない。量子化の前後の評価値の平均絶対誤差が2センチポーン以下である。診断の標本の元の局面、成りを適用した局面、および駒を1枚除いた局面について、Rustが返す特徴値からPythonが独立に計算した整数の評価値が、Rustの評価値と全局面で一致する。
- 学習の診断として、由来別、世代別、対局単位、および王駒の数の区分ごとの検証損失の学習曲線、λが0でない教師の分類ごとの教師Kの推定値、追加特徴の重みの値、および評価値全体の駒除去差分を測定記録へ残す。あわせて、中盤の検証の局面で、新しい項目の重みを0にしたときの検証損失の増分を、学習PSTの重みから無作為に選んだ同じ数の重みを0にしたときの増分と比べて記録する。無作為の選択は固定シードで5回行う。これらは記録であり、測定へ進むかどうかの基準にしない。
- 教師Kの推定値が探索の範囲の端（50または4,000）に近い場合は、原因を調べる。追加Aを採った場合は、付け直しの前後の教師値を、分類ごとの教師Kで勝率へ変換した後の差として、露出局面と対照局面に分けて記録する。診断Aはセンチポーンの差を調べるが、学習器は再推定した教師Kで探索値を勝率へ変換するので、教師Kが変わると、探索値が下がっても教師値が上がることがあるためである。
- 敗局の174手目、176手目、178手目、180手目、182手目の局面と、王の側の歩を突いた50手目、140手目、144手目の前後の局面について、学習PSTの部分、追加特徴の部分、深さ1の探索値、および対局時と同じ9.7秒の探索の最善手を記録する。この敗局は特徴の選定に使ったので、結果は参考の診断であり、採否の基準にしない。
- 採否測定は [SPRTの手引き](../guides/sprt.md) の標準コマンドに従い、測定名は `strength-stage9-<項目>-stc` と `strength-stage9-<項目>-ltc` とする。項目名は、項目1から順に `shelter2`、`attack-zone`、`defenders`、`mobility`、`promotion`、`lion`、`threats` とし、同時学習は `gen3`、駒価値の更新は `values` とする。進捗指標の測定名は `strength-stage9-elo200` と `strength-stage9-hachu-elo200` とする。項目1の項目名を `shelter2` とするのは、停止した `strength-stage9-shelter-stc` の実行ディレクトリを保存し、新しい候補の測定と区別するためである。停止した測定が基本シード40000921を使ったので、基本シードは41000921から1,000,000刻みで測定の順に割り当て、着手前に既存の記録の実使用の範囲と重ならないことを確かめる。
- 段階8の実績では、採否が明瞭な項目でSTCが約1.1時間、LTCが約5.5時間から6.2時間だった。効果が小さい項目はSTCが上限の3,000ペアまで延びる。測定の開始前に、測定機の利用可能なメモリが同時対局数に対して足りることを確かめる。
- 評価特徴を時間制御の対局で判定する理由は、速度の低下を含めた効果を測るためである。tataraの脅威の特徴の先行実験は、深さを固定した対局では基準を上回り、固定時間の対局では速度の低下で負け越したと記録している。
- 長時間の生成と付け直しは、対象のコミットを固定したworktreeのバイナリから実行する（[教訓](../lessons/pin-generation-binary-to-worktree.md)）。
- すべてのコミットで `cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習器の単体テストが通ることを確かめる。

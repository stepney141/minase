# 教師の混合比の比較の設計書

## 先に読む要約

本書は、評価関数の学習に使う教師値（学習の目標にする値）のうち、探索値と対局結果を混ぜる比率λを比較し、現行の0.75より強い比率があるかを自己対局で確かめる。
現行の教師値は `t = λ · sigmoid(v / K) + (1 − λ) · result` であり、λ=0.75は[評価関数](evaluation.md)が初期値として置き、世代0で比較して固定すると定めた値だが、その比較の測定記録は残っていない。
[チェス評価関数の教師と混合比の調査](../research/chess-evaluation-targets.md)によれば、先行するチェスエンジンには対局結果だけ、探索値だけ、および両者を混ぜる方式があり、75:25を普遍的な最適値とする根拠はない。
そこで本書は、比率を0.25、0.5、1.0に変えた3つの候補を、直前の採用版の学習PSTを初期値として同じ設定で学習し、短時間の時間制御GSPRT（[docs/guides/sprt.md](../guides/sprt.md)）で選別して、1つだけを長時間の測定へ進める。
候補は比率だけが異なり、学習の初期値、設定、入力、教師の作り方（先読みの有無）は直前の採用版と同じにする。
比率が異なる候補は教師値そのものが異なるので、学習損失では比べられず、対局結果の予測誤差など共通の指標を診断として記録したうえで、採否は対局だけで決める。
完了条件は、3候補の学習と診断、短時間測定の結果、選んだ1候補の長時間測定の採否が測定記録とともに残り、採用した場合は評価関数の設計書のλの値が更新されていることである。

## 状態

起案。2026年9月22日に起案した。
着手は、進行中の[先読み教師値](lookahead-teacher.md)の候補の採否が確定した後とする。その結果によって、本書の候補の基点（直前の採用版とその教師の作り方）が決まるためである。
次の一手は本書のレビューと、学習器への比率の上書きの実装である。

## 目的

教師値の混合比は、探索値の信頼性と対局結果の雑音の釣り合いで決まる量であり、エンジンごとに異なる。
minaseの探索値は10万ノード（深さ約6）の浅い探索の値であり、自己対局は平均640手と長く、序盤の局面の対局結果は着手列の偶然に強く依存する。
探索値の重みを下げれば浅い探索の盲点を対局結果で補えるが、対局結果の雑音が増える。
どちらが勝るかは測るまで分からないので、比率を事前に固定した3つの値で比べる。

## 適用範囲

対象は `tools/train/pst/` の学習器（教師値の計算と教師の分類）と、学習した重みファイルだけを差し替えた候補である。
評価関数の特徴、探索、教師データの形式、生成器は変えない。
本書の用語は[評価関数](evaluation.md)、[棋力向上段階9](strength-stage9.md)、および[先読み教師値](lookahead-teacher.md)に従い、次の語を加える。

- **混合比λ**は、教師値に占める探索値（または先読み値）の割合を指す。λ=1は探索値だけ、λ=0は対局結果だけの教師である。
- **基点**は、本書の着手時点の直前の採用版を指す。基点の学習PSTを初期値とし、基点の教師の作り方（現行の探索値か先読み値か、γとn）を引き継ぐ。
- **比率の上書き**は、来歴ファイルが持つ自己対局の分類のλを、学習時の設定で一括して置き換えることを指す。

## 依存関係

教師の分類、来歴ファイル、および学習時の変換の記録は、[棋力向上段階9](strength-stage9.md)のフェーズ4と[先読み教師値](lookahead-teacher.md)の基盤を使う。
ブランチは、これらの基盤がmasterへ入っていないため、`lookahead-teacher` から分岐した `teacher-mixing-ratio` とする。
基点は、[先読み教師値](lookahead-teacher.md)の候補が採用されればその候補（先読み教師、γ=0.9、n=40）、採用されなければ段階開始版（現行の教師）である。
測定の基本シードは、段階9と先読み教師値が割り当てた範囲（41000921から51000921）の続きから取る。

## 設計判断

| 項目 | 決定 |
|---|---|
| 比較する比率 | λ ∈ {0.25, 0.5, 1.0} の3つとし、結果を見て値を足さない。0.25はbulletの配布例（探索25%、結果75%）、0.5は中点、1.0は探索値だけの教師（Stockfishの採用例）に当たる。基点の0.75は基準として測定の相手になる。 |
| 候補の構成 | 各候補は、基点の学習PSTを初期値に、段階7の採用設定（鏡映共有、学習率0.03、駒除去差分の追加損失の係数1000、10エポック、バッチ16,384、乱数シード1、出力K固定）で、基本の教師の11ファイルから学習する。追加特徴は含めない。基点と候補の差は重みファイルだけとする。 |
| 比率の上書きの実装 | 学習の設定 `train.lambda_override` で、自己対局の分類のλを一括して置き換える。来歴ファイルは変えない。上書きしたλは教師の分類の属性として教師Kの推定、`inputs.json`、`training.json` に記録し、再開時に照合する。実戦棋譜の分類（λ=0）には適用しない。 |
| 教師Kの扱い | 教師Kは候補ごとに訓練の分割から推定し直す。λ=1でも対局結果からKを推定し、探索値の勝率への換算に使う。 |
| 診断 | 候補ごとの教師値は異なるので、学習損失で候補を並べない。共通の診断として、検証の分割における対局結果の二値交差エントロピー（λ=0の教師に対する損失）、探索値との平均絶対誤差、評価値の符号と対局結果の一致率、除去差分から導いた駒価値を記録する。これらは記録であり、選別には使わない。 |
| 選別と採否 | 3候補をそれぞれ基点とSTCで測る。`decision: H1` の候補があればLLRが最大の1つを、なければ上限到達時にLLRが0以上の候補のうちLLRが最大の1つを、LTCへ進める。該当する候補がなければ本書は見送りで完了する。LTCの採否は[SPRTの手引き](../guides/sprt.md)の規則に従う。STCの結果を見てから比率を足したり、2つ目の候補をLTCへ送ったりはしない。 |
| 先読み教師値との関係 | 本書は比率だけを変え、先読みの有無は基点に従う。両方を同時に変えると効果を切り分けられない。 |
| 学習中に比率を変える方式 | Stockfishが採る、学習の途中でλを変える方式は採らない。固定の比率の比較で方向が分かってから検討する。 |

## 実装フェーズ

### フェーズ1　比率の上書き

学習器と診断器に `train.lambda_override` と対応するコマンドライン引数を加え、自己対局の分類のλを置き換え、教師の分類の属性、教師Kの推定、記録、および再開時の照合に反映する。
完了条件は、次のことがテストで固定されていることである。

- 上書きが自己対局の分類にだけ適用され、実戦棋譜の分類のλ=0は変わらない。
- 上書きしたλで教師値と教師Kが計算され、分類の記録に上書きの値が入る。
- 範囲外の値（0未満、1超、非有限）が拒否される。

### フェーズ2　候補の学習と診断

基点の設定に `train.lambda_override` を加えた3つの設定で学習し、学習後の診断（段階7と段階9の基準）と本書の共通の診断を通す。
結果は測定記録 `teacher-mixing-ratio-training` に残す。

### フェーズ3　選別と採否測定

3候補を `teacher-mixing-ratio-025-stc`、`teacher-mixing-ratio-050-stc`、`teacher-mixing-ratio-100-stc`（基本シード54000921、57000921、60000921）で測り、選別の規則で1つを `teacher-mixing-ratio-<選んだ比率>-ltc`（基本シード63000921）へ進める。

## 検証

- 3候補の学習は同じ入力、初期値、設定、乱数シードで行い、設定の差が `train.lambda_override` だけであることを準備の記録で確かめる。
- 学習後の診断は段階7と段階9の基準に従う。量子化の前後の平均絶対誤差が2センチポーン以下であること、Rustと学習器の評価値が一致すること、駒除去差分の符号の反転がないこと、探索用駒価値と出力Kが変わらないことを確かめる。
- 採否測定は[SPRTの手引き](../guides/sprt.md)の標準コマンドに従い、エンジン異常、時間切れ、拒否着手が0件であることを採用の条件にする。
- すべてのコミットで `cargo test`、`cargo clippy -- -D warnings`、`cargo fmt --check`、および学習器の単体テストが通ることを確かめる。

## 完了条件

- 3候補の学習、共通の診断、STCの結果が測定記録に残っている。
- 選んだ候補のLTCの採否、または該当する候補がなかったことが記録されている。
- 採用した場合は[評価関数](evaluation.md)の「教師値と損失」のλの値と、[PSTの学習手順](../guides/pst-training.md)の設定が更新され、ROADMAPの状態表が本書の結論と一致している。

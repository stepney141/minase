# 探索の不安定さに応じた持ち時間の伸縮の設計書

## 先に読む要約

本書は、1手に使う目安の時間を探索の不安定さに応じて連続的に伸び縮みさせる時間管理（Stockfishの`totalTime`の計算に当たる、time management by search instability）を入れ、起点のmasterより強くなるかを確かめる。
minaseの主ワーカーは、反復深化（深さ1から1ずつ読みを深める探索の外殻）の各反復を終えるたびに、目安の時間softと打ち切りの上限hardを見て次の反復を始めるかを決める。
起点でsoftを変える信号は、最善手が4反復続けて同じときに判定を厳しくする二値の短縮だけである。
Stockfishは、評価値の下落（falling eval）、最善手が最後に変わった深さからの距離（best move stability）、最善手の変化回数（best move instability）、および最善手の部分木が全ノードに占める割合（best move effort）の4因子をsoftに掛け、両方向に連続で伸縮させる。
本書はこの4因子をStockfishと同じ形で入れ、あわせて時間管理にあるStockfishの5つの項目（相手との残り時間の差による補正、根の候補が1手の局面の上限、目安の時間の半分を過ぎたら深さを増やさない規則、詰みを見つけたときの早期停止、および先読みを使う対局での目安時間の25%増し）を加える。
二値の短縮は残し、その反復数も調整の対象にする。
新しい係数はStockfishの値を換算して始め、既存の係数とまとめてSPSA（simultaneous perturbation stochastic approximation、全係数を同時に少しずらした2つの設定を対局させて係数を動かす調整法）で調整する。
[探索の関数形の見直しの統括計画](search-forms.md)の決定により、調整した版は、起点との短時間条件STCの逐次検定の結果によらず採用し、STCは記録として残す。
相手との残り時間の差の補正を除く項目は、秒読みつきの時計（lishogiのBotが主に使う時計）の持ち時間期にも働かせ、STCの後に秒読みつきの2条件で起点と比べて、両方で有意に強ければそのまま使い、そうでなければ秒読みが0の時計に限る。
完了条件は、形の変更の検証、SPSA、事前対局、STC、および秒読みつきの時計での扱いが測定記録とともに確定し、候補がmasterへ統合されることである。

## 目的

本書が確かめるのは、「探索の不安定さに応じてsoftをStockfishの形で連続的に伸縮させ、その強さをSPSAで調整すれば、起点の時間管理より強くなる」という仮説である。
発端は、[係数の関数形の比較](../research/search-coefficient-forms-prior-art.md)が、探索の不安定さによる伸縮を、minaseの時間管理が参照していない変数として挙げたことである。
StockfishとYaneuraOuは、反復を終えるたびに4因子の積をsoftに掛け、局面が不安定なら長く、安定なら短く読む（Stockfish `src/search.cpp:592-613`、YaneuraOu `yaneuraou-search.cpp:1969-1990`）。
minaseの二値の短縮は安定な手を短くするだけであり、短縮の程度も安定の度合いによらない。

時間管理の改善について、利用者は2026年10月7日に目的を棋力とし、「新しい時間配分の計画は立てない」として検討を終えた。
その後、係数の関数形の比較を受けて、利用者は2026年10月17日に本書の起案を明示的に指示した。
本書は、持ち時間の消費の速さや人間との対局での使い方を目的とする計画ではなく、探索の関数形を両エンジンの形へ寄せる系列（[枝刈りとLMRの関数形の見直し](archived/search-pruning-forms.md)から始まる連鎖）の最後の1本である。

同じ日に、利用者は系列の全設計書に共通する方針を決めた（2026年10月17日の利用者の決定）。

- 両エンジンで形や値が違う場合はStockfishに合わせ、YaneuraOuにだけある項目は入れず、Stockfishにだけある項目は入れる。秒読みのようにStockfishに相当する仕組みがない事項は、YaneuraOuに合わせる。
- 新しい係数の開始値は、両エンジンの値を換算した値（両者が違えばStockfishの値）とする。既存の係数も、Stockfishに同じ形の値があれば換算値を開始値に置き直す。
- SPSAで調整するのは、各仕組みの強さを決める値（切片、傾き、重み、倍率など）だけとし、上下限や更新の内部の定数はStockfishの値で固定する。
- minaseにあってStockfishにない既存の仕組みのうち、中将棋の診断や測定で決めたものは残し、Stockfishの仕組みを追加して併用し、残したものもSPSAで調整する。最善手が4反復続いたら早く止める規則はこれに当たる。
- 評価値の単位を持つ定数は、開始値をStockfishの換算値としたうえで、範囲にStockfishとYaneuraOuの換算値とminaseの現行の対応する値をすべて含める。中将棋は将棋ともチェスとも異なるゲームなので、値はminaseのSPSAが決める。

本書については、秒読みつきの時計でも因子を使うこと、ノード占有率をStockfishの連続の形にすること、および相手との残り時間の差による補正と合法手が1つの局面の上限を含めることを、同じ日に利用者が決めた。
あわせて、前の手の探索の値を持ち越す項と、Stockfishにだけある`increaseDepth`、詰みでの早期停止、および先読み中の25%増し（本書のT9。対象は設計判断の表で絞った）を含めることも決めた。

似た変更を含む候補は、過去に3つの設計書で扱われた。
測定まで進んだ候補はいずれも、改善を示せない判定`H0`か、判定前の中止に終わった。
本書はそれぞれと次の点で異なる。

[棋力向上段階6](archived/strength-stage6.md)は、2つの二値の延長をSTCで測り、いずれも`H0`だった（[fail-lowによる延長](../measurements/strength-stage6/strength-stage6-faillow-stc.md)、[最善手交替時の延長](../measurements/strength-stage6/strength-stage6-bmchange-stc.md)）。
fail-lowとは、aspiration windows（直前の反復の評価値の周りに狭い窓を置いて根を読む手法）で、評価値が窓の下限を割り込むことであり、最善手が崩れた兆候とされる。
2つの延長はどちらも、信号が立った反復の境界ではsoftの条件を外し、hardの予測だけで次の反復を始めるかを決める形であり、伸ばす量は信号の大きさによらなかった。
本書の因子は信号の大きさに応じてsoftを伸縮させ、縮める方向も持ち、強さはSPSAで調整する。

[持ち時間の効率的な使用](archived/time-management-efficiency.md)の第3段階は、本書と同じ4因子の積を、各因子の定数をStockfishのまま実装し、積全体に正規化の定数0.48を掛けた。
同じ設計書の第2段階は`increaseDepth`に当たる深さの抑制を実装したが、[事前判定](../measurements/time-management-efficiency/time-management-efficiency-stage2-bench.md)で抑えた反復が置換表の照会だけで終わる空費と判定して見送った。
第3段階は単独では測られず、予算の再定義と途中結果の採用（第1段階）を積んだ最終候補としてSTCで`H0`となった（[測定記録](../measurements/time-management-efficiency/time-management-efficiency-stc.md)）。
事前の[ベンチ](../measurements/time-management-efficiency/time-management-efficiency-stage3-bench.md)では、Stockfishの定数はminaseの深さ6〜8の探索で積を系統的に大きくし、正規化前の積の中央値は2.08であり、最善手の安定による因子（Stockfishの`reduction`、本書のT2）は240局面中180局面以上で上限に張り付いた。
事後分析は、`H0`となった主因を、係数つきの予算が持ち時間を200手目までに使い切らせ、中終盤で浅くなったことと結論した。
同じ候補は、hardから残り時間の割合の項を外していたので、時間切れも2件出した。
本書の開始値は第3段階の正規化前の定数とほぼ同じであり、開始時点の積が大きくなる見込みは同じである。
違いは3つある。
第1に、本書は強さを決める定数を固定せず、積の水準を決める係数（T2の分母など）を含めてSPSAで調整する。
第2に、起点のsoftとhardの式（T5の補正とT9の増分を除く）、次の反復の予測、および秒読みのない時計で中断した反復を捨てる機構を変えず、hardを残り時間の割合で抑える項を残す。
第3に、第2段階と第3段階の測定はNNUEへの置き換え（2026年10月12日）より前の評価関数で行われ、[ADR](../adr/reject-fair-share-budget-with-partial-results.md)は同じ方式の再提案に現行の構成での再測定を求めている。
起点の探索の深さは当時より深く、[起点の時計の記録](../measurements/time-instability-scaling/time-instability-scaling-baseline.md)では、STCの平均完了深さは手数帯ごとに約14〜17である。
開始時点の時間の使い方は、SPSAの前の開始値の事前対局（フェーズ2）で記録する。

[秒読みつき時計での持ち時間と秒読みの活用](byoyomi-time-usage.md)は、持ち時間期（持ち時間を使い切る前の手）の配分を局面の難しさで変える段階Bとして、持ち時間の消費の速さが異なる3候補を用意した。
B0は消費の水準を現行に保つ候補、B1は持ち時間を早く使い切る候補、B2は持ち時間を200手目まで残す候補である。
3候補はいずれも、先に採用した段階A（秒読み期の締切と途中結果の採用）の構成を秒読みつきの条件で上回らなかった。
3候補は共通の二値の「難しさの信号」を使った。
この信号は、深さ6以上の反復を終えるたびに、その反復か直前の反復で最善手が変わったか、評価値が深さd − 2の反復より歩兵1枚以上下がったときに真となる。
softは、信号が真なら基準時間の`r/v̄`倍、偽なら`1/v̄`倍とした（rとv̄は実戦のログから事前に求めた定数）。
B1は短い条件で`H0`となった（[測定記録](../measurements/byoyomi-time-usage/byoyomi-b1-short-r2.md)）。
B0は判定前に利用者の判断で止め（[記録](../measurements/byoyomi-time-usage/byoyomi-b0-short-r2.md)）、B2は[煙試験](../measurements/byoyomi-time-usage/byoyomi-b-smoke.md)だけで選別の測定をせずに不採用とした。
本書の因子は、2段階ではなく連続の量であり、深さ6以上という発動の条件を持たずに毎反復で働き、強さを実戦のログからの定数ではなくSPSAで決める。
また、段階Bは基準時間の式そのものを候補ごとに変えたが、本書は`soft_raw`（残り時間、加算、および秒読みから求める目安時間）の式を、秒読みのない時計でのT5の補正を除いて変えない。
B1の`H0`は基準時間の変更と信号を併せた結果なので、信号による伸縮だけの効果を示すものではない。

## 適用範囲

本書の用語を次のように定める。

- **起点**は、連鎖の1つ前の[aspiration windowsの形](archived/aspiration-window-forms.md)が完了した後のmasterの先頭のコミット`370f7077`である。
- **形の変更**は、本書の項目を実装したコミット列であり、新しい係数を開始値に置く。
- **候補**は、形の変更の上に、SPSAの最終値を`minase spsa apply`で表（`crates/minase/src/search/alphabeta/params.rs`）の既定値へ書き込んだコミットである。
- **STC**と**LTC**は、それぞれ10秒＋1手0.1秒と60秒＋1手0.2秒の持ち時間で行う自己対局の逐次検定である（[SPRTの手引き](../guides/sprt.md)）。判定はGSPRT（ペア単位の結果で対数尤度比を逐次計算し、境界に達した時点で止める検定）で行い、`H1`は候補が有意に強い判定、`H0`は改善を示せない判定である。統括計画の決定により、本書の候補はLTCでは測らない。
- **調整機**は、統括計画がSPSAと対局のためにvast.aiで借りる計算機であり、**測定機**は、開発と棋力測定に使う手元の機械である。
- **soft**と**hard**は、`crates/minase/src/search/alphabeta/time.rs`の`TimeBudget`の目安時間と上限時間である。softは反復を終えたときに次の反復を始めるかの判定に、hardは探索の途中で打ち切る判定に使う。`soft_raw`は、hardで抑える前の目安時間である。
- **基礎予算**は、探索の開始時に`time_budget`が求めるsoftとhardの組である。T5は基礎予算の計算の中で`soft_raw`に掛かり、T9は基礎予算のsoftを1回だけ増やす。
- **hardで抑える前の時間**`t`は、完了反復ごとに、基礎予算のsoftにT1〜T4の積を掛け、T6の上限で抑えた時間である（Stockfishの`totalTime`）。**伸縮後のsoft**`soft'`は`min(t, hard)`であり、反復の開始判定に使う。
- **持ち時間期**と**秒読み期**は、秒読みが正の時計で持ち時間を使い切る前と後の手である。秒読み期は`TimeBudget::byoyomi_period`が真になる探索であり、予測と安定性を使わず、締切まで反復を始める。
- **二値の短縮**は、直近`StableIterations`反復（起点は定数4）の最善手が同じとき（`stable_signal`）、次の反復を始める条件を「経過時間がsoft未満」から「予測完了時刻がsoft以下」へ置き換える起点の規則である（[ADR](../adr/stop-early-on-stable-best-move-without-extensions.md)）。
- **主ワーカー**は、Lazy SMP（複数のスレッドが置換表を共有してそれぞれ反復深化を行う並列化）の0番のワーカーであり、反復の境界で次の反復を始めるかの判定はこのワーカーだけが行う。探索中のhardの検査は、すべてのワーカーが行う。**補助ワーカー**は1番以降のワーカーであり、深さを飛ばして反復する（[ADR](../adr/diversify-lazy-smp-workers-by-skipping-depths.md)）。
- **完了反復**は、ワーカーがaspiration windowsの窓の内側で読み終えた反復であり、`d`はその反復の番号（Stockfishの`rootDepth`）を表す。fail highによる窓の減深（aspiration windowsの設計書のA5）とT7で窓を浅く読んでも、`d`は反復の番号のままである。
- **詰み帯と専用の帯**は、詰みまでの手数を表す評価値の範囲と、千日手などの同一局面の反復の結果を表す評価値の範囲（`crates/minase/src/search/mod.rs`の`MATE_THRESHOLD`と`REPETITION_BAND_START`）である。勝ちの値は`MATE − n`であり、nは双方の着手をそれぞれ1手と数えた根から詰みまでの手数である（`MATE`は30,000）。
- **前の探索**は、同じ`HistoryTables`で直前に終わった探索であり、先読みの探索も含む。`HistoryTables`は、プロトコル層が新規対局（USIの`usinewgame`、CECPの`new`）、規則変更、置換表容量の指定、引き分けの評価値の変更、およびワーカー数の変更で初期化するので、前の探索の値もこれらで消える。
- **先読み**は、USIの`go ponder`で始まる探索（相手の予想手を指したと仮定した局面を相手の手番中に読むこと）であり、予想が当たると`ponderhit`、外れると`stop`が届く。**先読みの的中**は`ponderhit`を受けることであり、**的中前**は先読みの探索がまだ的中を受けていない間をいう。
- **先読みの印**は、`HistoryTables`の初期化の後に先読みの探索を1回以上始めたことを示す印である。Stockfishの`Ponder`オプションの代わりに、T9の対象を決める。
- **根の候補**は、探索が根で読む手の列（`SearchSnapshot::root_moves`）である。反復規則によって勝ちの手への限定や負けの手の除外をした後の列なので、盤面の合法手の数とは限らない。
- **千分率**は1/1000を単位とする整数であり、因子と係数の多くをこの単位で表す。1000‰が倍率1に当たる。
- **手数帯**は、`scripts/clock_profile.py`が集計に使う通算の手数の区間（0〜49、50〜99、100〜149、150〜199、200〜299、300〜399、400以上）である。

対象は次の10項目である。

- 評価値の下落による因子（T1、falling eval）。前の探索の平均値との差の項を含む。
- 最善手が最後に変わった深さからの距離による因子（T2、best move stability）。前の探索の値を持ち越す項を含む。
- 最善手の変化回数による因子（T3、best move instability）。
- 最善手の部分木のノード占有率による因子（T4、best move effort）。
- 相手との残り時間の差による補正（T5、time advantage）。
- 根の候補が1手の局面での目安時間の上限（T6）。
- hardで抑える前の時間の半分を過ぎたら次の反復の深さを増やさない規則（T7、Stockfishの`increaseDepth`）。
- 詰みを見つけたときの早期停止（T8）。
- 先読みの印が立っている探索での目安時間の25%増し（T9）。
- 二値の短縮の反復数の係数化（T10）。

次の事項は対象外とする。

- 基礎予算の式（残り手数の見積り、加算と秒読みの配分、およびhardの上限）。Stockfishの基礎予算の式（残り時間の対数と手数のべき乗による倍率、`originalTimeAdjust`、周期的な時間制御、ノード数を時間として使う方式）は移さず、起点の式を保つ。
- 秒読みに関わる係数と`ByoyomiMargin`（秒読みの締切に残す余裕を与えるUSIオプション）。秒読みのない時計で調整するSPSAでは勝敗に影響しないからである（[ADR](../adr/exclude-byoyomi-terms-and-safety-margin-from-spsa.md)）。
- 秒読み期の判定。秒読み期は締切まで反復を始める規則であり、softを使わないので、本書の因子は働かない。YaneuraOuも秒読み期は締切まで読む。
- `movetime`を指定した探索へのT1〜T9の適用。Stockfishは`movetime`だけの探索では時間管理を使わない。minaseは、時計と`movetime`を併用した探索にもT1〜T9を使わない。T10は二値の短縮の反復数なので、併用した探索の二値の短縮にも働く。
- fail highの回数による減深（Stockfishの`failedHighCnt`と`failHighRecovery`）。[aspiration windowsの設計書](archived/aspiration-window-forms.md)のA5が実装済みであり、T7はA5の窓の読む深さの式に減深の項を1つ加える。

本書は次の4つのADRの決定の一部を変える。
採用した場合は、完了時に新しいADRで置き換え、変えずに残る決定も新しいADRへ引き継ぐ。

- [延長の信号を使わないADR](../adr/stop-early-on-stable-best-move-without-extensions.md)は、fail-lowと最善手交替による延長を使わず、最善手が4反復続けて同じときだけ早く止めると決めた。本書の因子は1を超えてsoftを伸ばせるので、延長を使わないという決定を変える。二値の短縮は残し、反復数を係数にする。測定はNNUEへの置き換えより前の評価関数で行われた。このADRは評価関数の時期による再測定の留保を書いていないが、「延長を再び提案する場合は、別の信号として段階ゲートにかける必要がある」としている。本書の候補は統括計画の決定によりSTCの判定によらず採用するので、この求めの代わりに、統括計画の[採用の例外のADR](../adr/adopt-search-form-subtasks-regardless-of-stc-and-check-the-whole-chain-by-ltc.md)に従う。
- [予算を分担そのものにする時間管理を採らないADR](../adr/reject-fair-share-budget-with-partial-results.md)は、代案として「局面の信号の積でsoftを伸縮させる案」と「softの半分を過ぎた後の反復の深さを抑える案」を棄却した。本書はこの2つを、予算の再定義を伴わない形で再び提案する。秒読みのない時計でhardまで続けて中断した反復を捨てる機構と、hardを残り時間の割合でも抑える決定は変えない。測定はNNUEへの置き換えより前の評価関数で行われ、ADR自身が「同じ方式を再提案するには現行の構成での再測定が要る」と留保している。
- [先読みの的中から予算を測るADR](../adr/continue-search-and-measure-budget-from-ponderhit.md)は、目減りを補う別の機構を持たないと決めた。本書のT9は、先読みの印が立っている、先読みでない探索にだけ25%増しを加える（設計判断の表を参照）。的中から予算を測る機構は変えず、的中時の再判定にも伸縮後のsoftを渡す。測定はNNUEへの置き換えより前で、起点や再判定の方式を変える提案には再測定が要ると留保している。
- [fail highの減深のADR](../adr/reduce-aspiration-re-search-depth-after-fail-highs-and-keep-the-iteration-depth.md)は、「Stockfishの`searchAgainCounter`の項は、minaseにその回数を増やす時間管理の仕組みがまだないので置かない」とした。T7はこの項を加える。

次のADRの決定は変えないが、本書の変更と関係するので、それぞれの留保とあわせて記す。

- [対局内で表を持ち越すADR](../adr/carry-histories-and-correction-histories-within-a-game.md)の表の寿命と共有範囲は変えない。本書は同じ`HistoryTables`に前の探索の値と先読みの印を加えるが、承認済みのADRは本文を書き換えない規約（[ADRの索引](../adr/README.md)の「不変性」）なので、この持ち越しの決定は本書の新しいADRに書く。
- [残り手数の見積りのADR](../adr/estimate-moves-to-go-from-ply.md)の見積りと、softをhard以下に保つ契約は変えない。T5は見積りから求めた`soft_raw`に因子を掛けるだけである。測定はNNUEへの置き換えより前で、見積りの方式を変える提案には再測定が要ると留保している。
- [次の反復の完了時刻を固定倍で予測するADR](../adr/predict-next-iteration-by-fixed-ratio.md)の予測式は変えない。二値の短縮が予測完了時刻と比べるsoftが、伸縮後のsoftになる。測定はNNUEへの置き換えより前で、予測の方式を変える提案には再測定が要ると留保している。
- [持ち時間を温存しないADR](../adr/spend-main-time-from-the-opening.md)は、持ち時間を後半のために温存しないと決めた。本書の因子は各手の判定でsoftを伸縮させるだけで、後半のために時間を残す配分ではない。T5は不利なときに消費を減らすので、秒読みつきの時計で働かせると持ち時間を残す方向に作用する。秒読みつきの時計を前提とするYaneuraOuはこの補正を持たないので、T5は秒読みが0の時計に限る。このADRは温存を再提案する場合に秒読みつきの時計での測定を求めている。
- [序盤の係数を秒読みの項にだけ掛けるADR](../adr/scale-only-the-byoyomi-term-in-the-opening.md)の係数と式は変えない。
- [秒読みの項の係数をSPSAで調整しないADR](../adr/exclude-byoyomi-terms-and-safety-margin-from-spsa.md)は、秒読みのない対局で勝敗に影響しない係数を調整の対象から外すと決めた。新しい係数は秒読みのない対局の予算を変えるので、調整の対象にできる。
- [根の手を前回のノード数で並べるADR](../adr/order-root-moves-by-previous-subtree-nodes.md)の並べ方は変えない。T4は並べ替え用の反復ごとのノード数ではなく、M2が持つ探索全体の累計を使う。

| 事前対局での時間の使い方の確認 | 開始値と候補の事前対局で、1局の総思考時間の起点に対する比と、手数帯ごとの完了深さを、[教訓](../lessons/compare-total-time-usage-before-sprt.md)が求める条件（総思考時間が起点の90%以上110%以下、完了深さがどの帯でも起点を下回らない）に照らして記録する。この教訓は、1手ごとの指標を満たした予算の機構の変更が、1局の時間の使い残しや手数帯の間の偏りのために段階ゲートで`H0`となった経験から定めたものであり、本書は予算の機構を変えるので、条件を満たすかを必ず集計する。ただし、統括計画の決定により採否はSTCによらないので、条件は採否測定へ進むための合否ではなく、記録とする。満たさない場合も、集計を利用者に示したうえでSTCへ進む。時間切れとエンジン異常は、1件でも出れば原因を直すまで先へ進まない。第3段階が`H0`となった主因（序盤の使いすぎで中終盤が浅くなること）は、手数帯ごとの完了深さに表れる。T7で窓を浅く読むと、完了深さは反復の番号であって実際に読んだ深さより深く数えられるので、完了深さだけで探索量を比べることには限界がある。 |

## 変更の内容

以下の式で、`P`は探索用の歩兵価値（評価関数の`pawn_value`）、`v`は主ワーカーの完了反復の評価値（`search_iteration`が窓の内側で完了して返した値、Stockfishの`bestValue`）を表す。
因子と、因子に足し引きする係数は千分率で表し、`clamp(x, lo, hi)`は`lo`以上`hi`以下への切り詰めを表す。
`⌊ ⌋`は床関数、`trunc₀`は0の方向への丸めを表す（設計判断の「丸めと桁あふれ」）。

### 伸縮の適用

本書の項目は、設計判断の「適用の条件」の探索に使う。
主ワーカーは完了反復ごとにT1〜T4の因子を求め、次の式でhardで抑える前の時間`t`と伸縮後のsoft`soft'`を求める。

```math
t = \left\lfloor \frac{\mathrm{soft} \times f_1 \times f_2 \times f_3 \times f_4}{1000^4} \right\rfloor, \qquad \mathrm{soft'} = \min(t,\ \mathrm{hard})
```

`soft`と`hard`は基礎予算の値であり、T9を掛ける探索では`soft`はT9で増やした値である。
根の候補が1手なら、`soft'`を求める前に`t = min(t, 500 ms)`とする（T6）。
`soft'`は、反復の完了時の`should_start_next_iteration`、先読みとして始めた探索の的中後に次の反復を始める前の判定（直前の完了反復で求めた`soft'`）、的中時の`check_time`での`iteration_prediction_fits`による当て直し（`PonderIteration`に保存する予算）、および二値の短縮が予測完了時刻と比べる値として、softの代わりに使う。
的中前の先読みでも、完了反復のたびに因子を計算し、`soft'`、T7の状態、T8の記録、および`r`を更新する。的中まで行わないのは、時間予算とT8による停止の判定だけであり、深さとノード数の上限と外部停止は的中前も働く。
最初の反復を終えるまでは、T1〜T4による伸縮をせず、基礎予算のsoftを使う。基礎予算に入るT5とT9は、最初の反復から効いている。
本書の項目を使わない探索、秒読み期、および探索中のhardの検査は起点のままである。

### T1　評価値の下落（falling eval）

```math
f_1 = \mathrm{clamp}\left(\mathrm{TimeFallingBase} + \mathrm{trunc}_0\left( \frac{\mathrm{TimeFallingPrevious} \times (A_{\mathrm{prev}} - v) + \mathrm{TimeFallingIteration} \times (I - v)}{P} \right),\ 576,\ 1728\right)
```

`A_prev`は前の探索で採用したワーカーの、返した手の平均値、`I`は4反復前の完了反復の値である。
`I`は、主ワーカーが持つ4要素の環状配列の現在位置から読み、因子を求めた後に`v`で上書きして位置を進める。
環状配列は探索の開始時に前の探索の評価値で埋め、前の探索の値がなければ0で埋める。
前の探索の値がない場合は、その探索のすべての完了反復で`f_1`を1728‰とする。
この場合も環状配列は同じ規則で更新するが、その探索の`f_1`には影響しない。

### T2　最善手が最後に変わった深さからの距離（best move stability）

```math
r = \mathrm{clamp}(\mathrm{TimeReductionIntercept} + \mathrm{TimeReductionSlope} \times x,\ 629,\ 1544), \qquad f_2 = \left\lfloor \frac{(1468 + r_{\mathrm{prev}}) \times 10^6}{\mathrm{TimeReductionScale} \times r} \right\rfloor
```

`x`は、反復の番号dから、最善手が最後に変わった完了反復の番号を引いた値である（`src/search.cpp:533-534, 600-602`）。
主ワーカーの完了反復の最善手の列の末尾で同じ手が続く長さを`L`とすると、`x = L − 1`であり、最初の完了反復と、深さdで最善手が変わった直後は`x = 0`である。
Stockfishの`lastBestMoveDepth`は、詰みの値を読み直しで失った場合（`forgottenMate`）に前の詰みの最善手を戻す処理と組になっている（`src/search.cpp:526-560`）が、minaseにはこの復元がないので、完了反復の最善手だけで数える。
`r_prev`は前の探索の最後の`r`であり、設計判断の「前の探索の値の持ち越し」の規則で決まる。

### T3　最善手の変化回数（best move instability）

```math
c_d = \left\lfloor \frac{c_{d-1}}{2} \right\rfloor + 1024 \times n_d, \qquad f_3 = \mathrm{TimeInstabilityBase} + \left\lfloor \frac{\mathrm{TimeInstabilitySlope} \times c_d}{1024 \times W} \right\rfloor
```

`n_d`は、主ワーカーが前の完了反復で回収した後から反復dの完了で回収するまでに（最初の完了反復では探索の開始から）、全ワーカーが数えた最善手の入れ替わりの回数の合計である。
`c_d`は変化回数の減衰つきの累計を1/1024回の単位で持ち、探索の開始時に`c_0 = 0`とする。主ワーカーは、反復を始めるたびに累計を半分にし、反復を完了したときに`1024 × n_d`を加える。
1024単位の切り捨ては、Stockfishの浮動小数の累計の近似である。
`W`は設定上のワーカー数である。
Stockfishと同じく、`f_3`に上下限は置かない。

### T4　最善手のノード占有率（best move effort）

```math
e = \left\lfloor \frac{100000 \times E_{\mathrm{best}}}{\max(1, N)} \right\rfloor, \qquad f_4 = \mathrm{clamp}\left(\mathrm{TimeEffortIntercept} + \mathrm{trunc}_0\left( \frac{\mathrm{TimeEffortSlope} \times e}{100000} \right),\ 693,\ 838\right)
```

`E_best`は、主ワーカーが探索の開始から反復dの最善手の部分木に使ったノード数の累計であり、M2の`effort`である。
`N`は主ワーカーの全ノード数（`Searcher::nodes`）である。
`e`はStockfishの`nodesEffort`と同じく、割合を100000倍した値である。

### T5　相手との残り時間の差（time advantage）

設計判断の「適用の条件」のT5の探索に限り、`ClockCoefficients::budget`で`soft_raw`に次の因子を掛けてから、hardとsoftを起点の式で求める。

```math
D = \max(0,\ R_o - R), \qquad f_5 = 1000 - \left\lfloor \frac{\mathrm{TimeAdvantage} \times D}{R + R_o + 1} \right\rfloor, \qquad \mathrm{soft\_raw'} = \left\lfloor \frac{\mathrm{soft\_raw} \times f_5}{1000} \right\rfloor
```

`R`は自分の残り時間、`R_o`は相手の残り時間（いずれもミリ秒）である。
自分の残り時間が相手以上なら因子は1000‰である。
`D < R + R_o + 1`であり、`TimeAdvantage`は1000以下なので、引く項は1000未満となり、`f_5`は正である。この式は、1000に加える負の補正項を0の方向へ丸めたものであり、Stockfishの`1 + 0.9 × min(timeAdvantage, 0)`の倍率全体を千分率に丸める方法とは異なる整数の近似である。
hardのうち`soft_raw`の倍数の項は`soft_raw'`から求めるので、自分が不利なときはhardの候補も縮む。

### T7　深さを増やさない規則（increaseDepth）

主ワーカーは、時間で止めなかった完了反復の境界で、的中前の先読みなら「深さを増やしてよい」、そうでなければ、経過時間がhardで抑える前の時間`t`の50%以下なら「増やしてよい」、超えていれば「増やさない」を、全ワーカーが共有する状態に書き込む。
状態は探索ごとに「増やしてよい」から始める。
各ワーカーは自分の回数`k`を探索の開始時に0とし、反復を始めるときに状態が「増やさない」なら`k`を1増やす。
`k`はその探索の間は減らさず、反復の番号dの窓を次の深さで読む。

```math
\mathrm{depth} = \max\left(1,\ d - h - h_{\mathrm{carry}} - \left\lfloor \frac{3 \times (k + 1)}{4} \right\rfloor\right)
```

`h`と`h_carry`は、[aspiration windowsの設計書](archived/aspiration-window-forms.md)のA5のfail highの回数と持ち越し（`FailHighReduction`の`failed_high_count`と`recovery`、Stockfishの`failedHighCnt`と`failHighRecovery`）である。
A5の窓の読む深さ`max(1, d − h − h_carry)`に、T7の項を1つだけ加えた式であり、窓を読み直すたびにこの深さを使う。
`k`が0の間はT7の項も0である。
主ワーカーの反復の番号dは状態にかかわらず1ずつ増え、T2の距離と二値の短縮は反復の番号で数える。補助ワーカーの反復の番号は、起点と同じく深さを飛ばして増える。

### T8　詰みでの早期停止

伸縮後のsoftで止めるかを判定する反復の境界で、最善手の値`v`が`MATE − 3`以上か、`−(MATE − 2)`に等しければ、経過時間にかかわらず止める。
的中前の先読みでは止めず、最新の完了反復がこの条件を満たしたことを記録し、的中の後に反復を始める前の判定と時計の検査で止める。

### T9　先読みの印による25%増し

先読みの印が立っている探索のうち、先読み以外で始めた探索では、基礎予算のsoftを`soft + ⌊soft / 4⌋`とし、hardを超えないように抑える。
先読みとして始めた探索には、的中してそのまま続いた場合も含めて掛けない。
先読みの印は、探索チームが先読みとして探索を始めるときに、ワーカー数の不一致による表の作り直しを終えた後で`HistoryTables`に立てる。

### T10　二値の短縮の反復数

`stable_signal`が比べる直近の完了反復の数を、定数`STABLE_ITERATIONS`から係数`StableIterations`に改める。

## 所要時間の見積り

時間切れの事前確認、SPSA、候補の事前対局、およびSTCは調整機で、形の変更の検証、開始値の事前対局、反映、およびテストは測定機で行う。
SPSAの所要時間は、[統括計画](search-forms.md#所要時間と費用)の見積りにより、物理192コアの調整機で同時対局数191なら約13〜18時間である。前の6本のサブタスクは、同じ規模の調整機で事前確認からSTCまで約8〜10時間、約16〜21米ドルだった。
本書の開始値は積を大きくし、思考時間を延ばす見込みがあるので、事前確認とSPSAの初めのうちは1局の時間が起点より長くなり得る。

| フェーズ | 内容 | 見積り |
|---|---|---|
| 0 | 起点の時計の再構成（保存済みの対局記録の集計のみ） | 約10分（済み） |
| 1 | 形の変更の実装と検証（codexへ委任） | 半日〜1日程度 |
| 2 | 開始値の事前対局（測定機、16ペア）と時間切れの事前確認（調整機） | 約30分と約35分 |
| 3 | SPSA（調整機、30,000ペア） | 約8〜18時間 |
| 4 | 反映とテスト（測定機）、候補の事前対局（調整機、32ペア） | 約1時間 |
| 5 | STC（調整機） | 約0.2〜1.3時間 |
| 6 | 秒読みつきの時計での確認（利用者の判断による） | フェーズ6の節を参照 |

測定機の占有は、フェーズ1の検証、開始値の事前対局、および反映とテストの合計約2時間である。

## 実装フェーズ

基本シードは、時間切れの事前確認を5000000000、開始値の事前対局を5025000000、SPSAのセッションを5050000000、候補の事前対局を5100000000、STCを5150000000、秒読みつきの短い条件を5250000000、長い条件を5350000000とする。
着手時に、`data/matches/`、`data/spsa/`、および`data/vast-spsa/`の保存済みの記録の基本シードを調べ、4,900,000,000から5,600,000,000の間には、直前のSTC（4,850,000,000、上限3,000ペア）より大きい値がないことを確かめた（[教訓](../lessons/derive-seed-adjacent-collision.md)）。
測定機で探索速度を測る前と各測定の開始前に、ほかの対局測定、SPSA、教師生成、および学習が動いていないことを実行ファイル名で確かめる。

### フェーズ0　起点の時計の再構成

[教訓](../lessons/reconstruct-clock-from-match-records.md)に従い、起点と同じ探索と時間管理のコードを一方の側に持つ直近のSTCの実行ディレクトリ（[aspiration windowsの形のSTC](../measurements/aspiration-window-forms/aspiration-window-forms-stc.md)の候補側）から、`scripts/clock_profile.py`でその側の時計を再構成した。
手数帯ごとの完了深さ、思考時間と残り時間の中央値、および停止理由の分布は、測定記録`time-instability-scaling-baseline`に残した。
本書の因子は、反復の境界の判定による停止（`StopReason::SoftLimit`）で終わる手と、hardによる中断（`StopReason::HardLimit`）で終わる手の両方に働く。
hardで中断された手も、最後の反復の境界では開始判定を通っており、因子が1より小さければその境界で止まり得るからである。
T1〜T4とT6はhardそのものを延ばさないが、起点での停止理由だけから、変更後の反復の進み方や思考時間への影響は決められない。
この記録は、フェーズ2とフェーズ4の事前対局と比べる基準であり、採否の条件にはしない。

### フェーズ1　形の変更の実装

起点からブランチ`time-instability-scaling`を切り、worktree `data/worktrees/time-instability-scaling`で作業する。
次の順に、1項目を1コミットにする。
新しい係数は、それを使うコミットで`params.rs`の表へ追加する。参照されない係数やフィールドを先に定義すると、未使用のコードへのコンパイラの警告（`-D warnings`ではエラー）が出るからである。

1. T10（`StableIterations`の係数化）。開始値4では探索を変えない。
2. T5の入力（`ClockLimits::new`の相手の残り時間の引数、`SearchLimits::new`の検査、USIの`go`の解析、CECPの`otim`の保持）。探索の結果は変えないが、これまで受理した入力を拒否し、公開APIの引数が変わるので、互換性を壊す変更として`feat!`と`BREAKING CHANGE:`のフッターで書く（[CONTRIBUTING.md](../../CONTRIBUTING.md)）。
3. 伸縮の適用の枠組み、前の探索の評価値と平均値の持ち越し、およびT1。
4. T2と`r`の持ち越し。
5. T3（最善手の変化の計数と因子）。
6. T4。
7. T5の因子。
8. T6。
9. T7。
10. T8。
11. T9と先読みの印。

`minase dev bench`（固定の15局面を固定の深さで読み、探索ノード数、評価値、および最善手を出力するベンチ）は時間管理を通らない。
固定深さの探索では時間予算を使わず、T7の状態も「増やしてよい」のままで`k`が0なので、全11コミットでbenchの全15局面の深さ3、5、7の探索ノード数、評価値、および最善手が起点と一致する見込みである。
各コミットでこの一致を確かめ、変わった場合は、T3の最善手の変化の計数などの追加した処理が、探索の順序や評価値を意図せず変えていないかを調べる。
benchの一致は、持ち越しの正しさ、入力の検査、および先読みでの予算の受け渡しを検証しないので、それらは単体テストと結合テストで確かめる。
あわせて、`taskset -c 3`で1つのコアに固定した`minase dev bench --depth 9 --repetitions 3`の中央値を、起点と最後のコミットで交互に3回ずつ測り、探索速度の変化を記録する（[教訓](../lessons/pin-bench-to-performance-core.md)）。

因子の計算と予算の合成は、係数を引数で受け取る純粋な関数に分け、単体テストは式を写して計算せず、手で求めた数値の例で書く（[テストの手引き](../guides/testing.md)）。
係数の効果を確かめる入力は、上下限に張り付かない値を選ぶ。
単体テストと結合テストでは次を確かめる。

- 因子の向き、上下限、`soft' ≤ hard`、T6の上限、0の方向への丸め、および積の飽和。
- T1とT2の持ち越しで、採用したワーカー、途中結果、深さ0、T1〜T9を使わない探索、外れた先読み、および表の初期化の各場合の記録。
- T3で、最初の手を除くこと、α以下の手を除くこと、窓の読み直しの回数を含むこと、回収した回数を二重に数えないこと、およびワーカー数で割ること。
- T5を使う時計で相手の残り時間がない入力が、USI、CECP、および`SearchLimits::new`のそれぞれでエラーになること。相手の残り時間の0を受理すること、先後のそれぞれ、先読み、深さとノード数との併用、および`movetime`による適用の除外。
- T7で、探索ごとの初期化、実際に反復を始めたときだけの加算、補助ワーカーの深さの飛ばし、A5との合成、およびhardで抑える前の時間との比較。
- T8で、3手と4手で詰ます値、2手とそれ以外で詰まされる値、専用の帯の値、的中が反復の開始の前と後にある場合、および的中前の記録が次の完了反復で偽に戻る場合。
- T9で、最初の先読みの探索、拒否された入力、的中してそのまま続く探索、および表の初期化。
- 新しい係数が調整用ビルド（`--features tuning`つきのビルド）の`Tune_<係数名>`のUSIオプションとして宣言され、調整用の値が計算に渡ること。

起点の既存のテストのうち、固定の4反復の二値の短縮、`ClockLimits::new`の引数、および先読みの予算の受け渡しを前提にしたものは、確かめていた性質を保ったまま、新しい仕様の入力と期待値に書き直す。
片側の時計だけを持つ`movetime`併用の入力（`depth 2 ponder nodes 100 movetime 20 btime 1000`など）は、T5の対象外なので受理されたままであることを確かめる。
`excluded_clocks_preserve_clock_budget`は、深さやノード数を併用した時計（T5が働く）と、`movetime`を併用した時計（T5が働かない）を分けて確かめる。
途中結果のテストは、公開する結果の評価値と深さを完了反復の値に保つ既存の契約と、持ち越しに途中結果の評価値を使う新しい契約を、別々に確かめる。
時計の予算を手計算の数値例と照らすテスト`tuning_default_clock_budget_matches_numeric_examples`が明示している固定の係数は、起点の既定値へ置き換えない。全係数の登録件数は104になる。
秒読み期の締切だけによる判定、`movetime`だけの探索、無期限探索の外部停止、および主ワーカーの進捗の深さが1ずつ増える性質は変えない。

フェーズ1の最後に、調整係数の既定値を範囲の1/3と2/3に置いた一時的な表で4つの検査を実行し、係数の既定値に期待値を結びつけたテストがないことを確かめる。SPSAが既定値を動かした後に落ちるテストを、SPSAの前に見つけるためである。
失敗したテストは原因を調べ、期待値が係数の既定値に依存していた場合はテストを係数によらず成り立つ形に直し、実装の不具合なら実装を直して、別のコミットにする。
完了条件は、次の4つの検査の通過（通常ビルドと調整用ビルド）、形の変更の全コミットでのbenchの一致、探索速度の記録、および1/3と2/3の表での検査の通過である。

```console
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p minase --lib --features search-stats,tuning
```

### フェーズ2　パラメーターファイル、開始値の事前対局、および時間切れの事前確認

形の変更の最後のコミットでビルドした`minase`を`data/spsa/time-instability-scaling-runner/`へ複製してrunner（測定を実行するプログラム）として固定し、測定機で行う以後のフェーズはこのrunnerで実行する。
時間切れの事前確認とSPSAのセッションは[SPSAの手引き](../guides/spsa.md)の調整機の手順で実行し、調整機では同じコミットからビルドしたrunnerを使う。
`minase spsa params --engine commit:<形の変更> --rules engine-default`で既定のパラメーターファイルを生成し、`FmScale`の行を削除したファイルを`data/spsa/time-instability-scaling.params`とする。
開始値と範囲が形の変更の`params.rs`の表と一致すること、および`c_end`と`r_end`が既定値であることを、使い捨てのスクリプトで機械的に突き合わせる。

まず、調整機を借りる前に、開始値の形の変更と起点を、STCの条件で16ペア、測定機で対局させる。

```console
<固定したminase> match run \
  --run-dir data/matches/time-instability-scaling-start --seed 5025000000 \
  --candidate commit:<形の変更> --baseline commit:<起点> \
  --each time=10000+100 --concurrency 16 elo --pairs 16
```

1局の総思考時間の比、終局時の残り時間、手数帯ごとの完了深さ、および停止理由の分布を`scripts/clock_profile.py`で集計し、測定記録`time-instability-scaling-start`に残す。
この対局は開始値での時間の使い方の変化を記録するものであり、採否や係数の選び直しには使わない。
時間切れまたはエンジン異常が1件でもあれば、原因を調べてから調整機を借りる。

続いて、手引きの第3節に従い、時間管理の係数を思考時間が長くなる側の範囲の端に置いても時間切れが起きないことを確かめる。
パラメーターファイルの写し`data/spsa/time-instability-scaling-safety.params`を作り、手引きの4係数の開始値を`HardRemainingShare`＝50、`HardSoftRatio`＝800、`MinMoves`＝40、`IterationRatio`＝150に置き換える。
新しい係数は、時間を長く使う傾向を狙った確認用の値に置き換える。全局面で積が最大になる組ではない。たとえば評価値が上がった局面では、差に掛かる係数を0にした方がT1の因子は大きくなる。
値は、`TimeFallingBase`＝1500、`TimeFallingPrevious`＝8000、`TimeFallingIteration`＝5000、`TimeReductionIntercept`＝0、`TimeReductionSlope`＝0、`TimeReductionScale`＝1000、`TimeInstabilityBase`＝1500、`TimeInstabilitySlope`＝4000、`TimeEffortIntercept`＝2500、`TimeEffortSlope`＝500、`TimeAdvantage`＝0、`StableIterations`＝8とする。
このファイルで、[統括計画](search-forms.md#実行の構成)が定める反復数（同時対局数191なら156反復、1,248ペア。同時対局数は調整機ごとに決まる）を調整機で実行する。
この組では`soft'`の多くがhardに達し、序盤からhardの近くまで読む手が多くなって、残り時間が少ない局面へ早く入る見込みである。予測完了時刻の判定は残るので、hardまで読むことが保証されるわけではない。この確認は、全局面での最長の思考時間を示すものとしては扱わない。
T1〜T4とT6はhardを伸ばさず、T5は`TimeAdvantage`が0以上なのでhardを縮める側にしか働かない。
hardには残り時間の割合の項と、残り時間から余裕を引いた安全上限も残るので、時間切れは起きにくいと見込むが、実際に起きないことを測定で確かめる。

```console
<調整機のminase> spsa \
  --run-dir data/spsa/time-instability-scaling-safety --seed 5000000000 \
  --engine commit:<形の変更> --params data/spsa/time-instability-scaling-safety.params \
  --rules engine-default --each <換算した持ち時間> --concurrency <調整機の同時対局数> \
  --iterations <事前確認の反復数> --pairs-per-iteration 8
```

`time_forfeits`（時間切れの件数）が1件でもあれば、調整機でSPSAを動かすスクリプト`remote.py`は本番のセッションを始めずに止まる。[デバッグの手引き](../guides/debugging.md#時間切れと時間管理)の手順で原因を調べ、該当する係数の範囲を狭める案を利用者に示してから本番へ進む。
結果は測定記録`time-instability-scaling-safety`に残す。
完了条件は、時間切れとエンジン異常が0件であることと、2つの測定記録の保存である。

```console
<調整機のminase> spsa \
  --run-dir data/spsa/time-instability-scaling --seed 5050000000 \
  --engine commit:<形の変更> --params data/spsa/time-instability-scaling.params \

```

このコマンドは調整機で実行し、実行ディレクトリは測定機の`data/spsa/time-instability-scaling`へ取得してから反映に使う。
最終のθ（調整中の係数の中心値の組）を整数に丸めた値を調整の結果とし、途中の値を対局の成績で選び直さない。
結果は測定記録`time-instability-scaling`に、手引きの第6節の項目とともに残す。
最終値を丸めた整数が範囲の上限または下限になった係数を示す。
新しい12係数については、最終値が開始値からどれだけ離れたかを`c_end`に対する比で示す。
この比は、どの因子が使われたかを読むための目安であり、採否には使わない。
完了条件は、セッションの完了と測定記録の保存である。

### フェーズ4　反映と事前対局

手引きの第7節の手順1に従い、`minase spsa apply`で最終値を表の既定値へ書き込み、`git diff`で既定値だけが変わったことを確かめてコミットする。
続いて`cargo test`（通常ビルドと調整用ビルド）を測定より先に実行し、表の既定値に依存するテストが失敗した場合は、フェーズ1の末尾と同じ形でテストを直して別のコミットにする。
テストの失敗を、末尾に`; true`を付けるようなコマンドの組み方で隠さない。
候補の調整用ビルドの宣言を`minase spsa params`で出力し、既定値の欄が`apply`の出力と一致することを確かめる。

STCの前に、候補が時間切れやエンジン異常を起こさないことと、時間の使い方の変化を確かめるため、STCの条件で候補と起点の32ペアの事前対局を行う。
事前対局とSTCは、統括計画の設計判断「対局の実行場所」により、SPSAを終えた調整機で、持ち時間を換算せずに行う。候補のコミットは`git bundle`で調整機のcloneへ渡し、`<調整機のminase>`は調整機でrunnerのコミットからビルドしたminaseとする。同時対局数は、SPSAと同じ調整機の同時対局数とする。実行ディレクトリは測定機の`data/matches/`へ取得してから集計し、記録する。

```console
<調整機のminase> match run \
  --run-dir data/matches/time-instability-scaling-smoke --seed 5100000000 \
  --candidate commit:<候補> --baseline commit:<起点> \
  --each time=10000+100 --concurrency <調整機の同時対局数> elo --pairs 32
```

対局は32ペアなので、同時対局数を指定しても同時に動くのは最大32ペアであり、STCより負荷が軽い。前の6本のサブタスクと同じ規模の確認であり、STCと同じ負荷での時間切れの確認はSTC自身で行う。
候補と起点の1局の総思考時間の比、終局時の残り時間、手数帯ごとの完了深さ、および停止理由の分布を`scripts/clock_profile.py`の再構成で集計し、測定記録`time-instability-scaling-smoke`に残す。
設計判断の「事前対局での時間の使い方の確認」の条件を満たすかを記録し、満たさない場合は集計を利用者に示したうえでSTCへ進む。
完了条件は、テストの通過、事前対局での時間切れとエンジン異常が0件であること、時間の使い方の条件の記録、および測定記録の保存である。

### フェーズ5　STC

2026年10月18日の利用者の決定により、本書の変更はSTCの判定によらず採用する（[統括計画](search-forms.md)の設計判断「各サブタスクの採否」）。
STCは、事前対局と同じ調整機で、同じ同時対局数で行う。

```console
<調整機のminase> match run \
  --run-dir data/matches/time-instability-scaling-stc --seed 5150000000 \
```

逐次検定の停止規則は[SPRTの手引き](../guides/sprt.md)のSTCのとおりとし、判定は記録するが採否には使わない。
採用はLTCの`H1`だけが決めるという同手引きの原則の例外であり、統括計画の[採用の例外のADR](../adr/adopt-search-form-subtasks-regardless-of-stc-and-check-the-whole-chain-by-ltc.md)に従う。
結果は測定記録`time-instability-scaling-stc`に残す。
完了条件は、STCの判定と測定記録の保存である。

### フェーズ6　秒読みつきの時計での確認

統括計画は、秒読みつきの時計での確認の扱いを、サブタスクを始めるときに決めるとしている。
本書のT1〜T4とT6〜T9は秒読みつきの時計の持ち時間期にも働くので、lishogiのBotと人間との対局に影響する。
扱いは利用者が決める。選択肢は次の3つであり、2026年10月22日に利用者は案1を選んだ。
いずれの案でも、T10とSPSAで調整し直した既存の係数は秒読みつきの時計にも働くので、秒読みつきの時計での挙動が起点に戻るわけではない。調整し直した係数が秒読みつきの時計に働くことは、前の6本のサブタスクと同じである。

- 案1（推奨）は、候補を秒読みつきの2条件（短い条件`time=6000+0,byoyomi=300`、長い条件`time=45000+0,byoyomi=300`）のGSPRTで起点と比べ、両方が`H1`なら候補をそのまま統合し、どちらかが`H1`でなければ、T1〜T4とT6〜T9の適用を秒読みが0の時計に限定するコミットを加えて統合する案である。2026年9月18日の利用者の方針（人間との対局で棋力が落ちる変更を許容しない）と、起案時に定めた規則に合う。限定するコミットを加えた版は測り直さない。
- 案2は、同じ2条件を記録として行い、結果によらず候補をそのまま統合する案である。統括計画の「結果によらず採用する」扱いに合わせる。
- 案3は、対局を行わず、T1〜T4とT6〜T9の適用を秒読みが0の時計に限定するコミットを加えて統合する案である。対局の費用はかからないが、秒読みつきの時計での棋力への影響は確かめないまま統合する。

案1と案2の対局は、統括計画の設計判断「対局の実行場所」に従い、STCを終えた調整機で行う。
ただし、秒読みの短い締切に対して処理能力の余裕を残すため、統括計画の同時対局数の規則に例外を設け、同時対局数をSPSAの同時対局数`c`の半分（`max(1, ⌊c / 2⌋)`）とする。
測定機では、Botと学習のプロセスが同居した状態で同時対局数16の秒読みつきの測定が過負荷による時間切れで無効になった先例（[段階Aの短い条件](../measurements/byoyomi-time-usage/byoyomi-a-short-c10.md)）があるが、専用の調整機で半分にする必要を実測したものではない。候補と起点には同じ条件を使う。
所要時間は、[段階Aの短い条件](../measurements/byoyomi-time-usage/byoyomi-a-short-c10.md)が同時対局数10で1ペア約30秒、[長い条件](../measurements/byoyomi-time-usage/byoyomi-a-long-c10.md)が約39秒だったことから、所要時間が同時対局数に反比例すると仮定して見積もる。
同時対局数95の調整機では、判定までの130〜3,000ペアに対して、短い条件が約0.1〜2.6時間、長い条件が約0.15〜3.4時間であり、両方が3,000ペア以内で終われば合わせて最大約6時間（1時間約1.9米ドルの機械で約11米ドル）である。
案1の長い条件にはペア数の上限がないので、この値は案1の所要時間と費用の上限ではない。

```console
<調整機のminase> match run \
  --run-dir data/matches/time-instability-scaling-byoyomi-short --seed 5250000000 \
  --candidate commit:<候補> --baseline commit:<起点> \
  --each time=6000+0,byoyomi=300 --concurrency <max(1, ⌊c / 2⌋)> gsprt --max-pairs 3000
```

案1では、短い条件が`H1`なら、測定名の接尾辞を`-byoyomi-long`、基本シードを5350000000、持ち時間を`time=45000+0,byoyomi=300`とし、`--max-pairs`を付けずに長い条件で比べる。
両方が`H1`で、エンジン異常、時間切れ、および拒否着手が0件なら、候補をそのまま統合する。
どちらかが`H1`でなければ、T1〜T4とT6〜T9の適用を秒読みが0の時計に限定するコミットを加えて統合する。
このコミットでは、秒読みが0の時計の予算と判定が変わらないことを単体テストで確かめる。
短い条件で上限の3,000ペアに達した判定保留は、対数尤度比が0以上でも`H1`とはみなさず、限定するコミットを加える。
案2では、短い条件と長い条件をどちらも行い、判定を記録する。長い条件の上限も3,000ペアとする。
完了条件は、秒読みつきの時計の扱いの確定と測定記録の保存である。

## 検証

- フェーズ1の形の変更の各コミット（SPSAの最終値を反映する前）で、`Threads = 1`の`minase dev bench`の全15局面の深さ3、5、7の探索ノード数、評価値、および最善手が起点と一致すること。
- 単体テストと結合テストが、フェーズ1に挙げた項目を検査していること。
- T5を使う時計で相手の残り時間がない入力が、USI、CECP、および`SearchLimits::new`でエラーになり、`movetime`を併用した入力は受理されること。
- 新しい12係数が調整用ビルドの`Tune_`オプションとして宣言され、パラメーターファイルの開始値と範囲が表と一致すること。
- 候補の`params.rs`の差分が既定値の書き換えだけであり、調整用ビルドの宣言の既定値が`apply`の出力と一致すること。
- `cargo test`（通常ビルドと調整用ビルド）、`cargo clippy -- -D warnings`、および`cargo fmt --check`が通過すること。
- 開始値の事前対局、時間切れの事前確認、SPSA、候補の事前対局、STC、および秒読みつきの時計での対局で、エンジン異常、時間切れ、および拒否着手が0件であること。1件でも出た場合は、その測定を止めて原因を調べる。
- 候補の事前対局で、総思考時間の起点に対する比と、手数帯ごとの完了深さが記録されていること。

## 完了条件

- 起点の時計の再構成、形の変更の検証結果、開始値の事前対局、時間切れの事前確認、SPSAの結果、候補の事前対局、STC、および秒読みつきの時計での扱いが、測定記録に残っている。
- 候補のブランチ（秒読みつきの時計での確認で後始末のコミットを加えた場合はそれを含む）がmasterへ統合され、依存関係の節に挙げた4つのADRが新しいADRに置き換えられ、前の探索の値と先読みの印を`HistoryTables`で持ち越す決定が新しいADRに書かれている。統合は利用者の許可を得てから行う。
- ROADMAPの状態表と統括計画の状態が、本書の結論と一致している。

# 局面適応の予算に残り時間の歯止めを戻す

## 先に読む要約

本書は、[持ち時間の効率的な使用](time-management-efficiency.md)で不採用となった第3段階（局面適応の係数。評価値の下落や最善手の入替などの信号を予算に乗算する機構）の配分の欠陥を直し、改めて採否を測るマイルストーンの設計書である。
STCの[事後分析](../measurements/time-management-efficiency-stc.md)によれば、不採用の主因は係数つきの予算が持ち時間を200手目までに使い切らせ、大半の局が決まる200〜600手で候補が基準より0.3〜0.5浅く読んだことにある。
原因は3つで、係数の積の分布が右に裾が長いこと、積で決まる閾値`total`を反復の完了時にしか検査しないため実際の消費が閾値の2倍前後になること、および打ち切り上限hardに残り時間に比例する歯止めがないことである。
本書は、`total`を探索中の中断閾値にして途中結果を採用し、hardに現行の式が持つ`remaining / 4 + 0.8·byoyomi`の項を戻し、正規化定数を実際の消費の平均が公平な分担に一致するよう定め、採否測定と同じ時間制御の煙試験で残り時間の推移が比較対象の80%以上であることを確かめてから、標準のSTCとLTC（[棋力測定の手引き](../guides/sprt.md)が定める短時間と長時間の自己対局の逐次検定）で判定する。
候補は[分解測定](time-management-decomposition.md)の第1段階だけの構成（D1）の上に積み、D1がLTCで採用されていればD1を比較対象とし、そうでなければ分解測定の共通基準B′を親にD1の変更と本書の変更を1つの候補にまとめてB′と比べる。
完了条件は、煙試験の判定条件と時間切れ0件を満たし、LTCで`H1`（候補が有意に強いという判定）となることである。

## 状態

起案。2026年9月18日に起案し、着手日は未定である。
着手は[分解測定](time-management-decomposition.md)のD1の採否（LTCまで）の確定後とし、利用者の承認を要する。
次の一手は、D1の採否を待つことである。

## 目的

局面の信号に応じて予算を伸縮させる第3段階を、持ち時間を序盤で使い切らず、実際の消費の平均が公平な分担に一致する配分に直し、中終盤の到達深さを比較対象と同等以上に保ったうえで採否を測る。

## 適用範囲

対象は、`clock_budget`のhardの式、`total`の適用方法と正規化定数、および採否測定の前の煙試験の判定条件である。
係数の4つの式と定数、序盤の係数、途中結果の採用の条件、最終押し込み、合法手1つの即時停止は変えない。
第2段階（深さの抑制）は再検討しない。

## 依存関係

- [分解測定](time-management-decomposition.md)のD1の採否が比較対象を決める。D1がLTCで採用されていればD1のコミットを比較対象とし、候補はD1の直後のコミットとする。D1が採用されていなければ、B′を親として「D1の変更＋本書の変更」を1つの候補にまとめ、その全体の採否をB′と比べる。
- 第1段階の途中結果の採用（[持ち時間の効率的な使用](time-management-efficiency.md)の「途中結果の採用の条件」）を前提とする。
- [打ち切り上限は残り時間の割合でも抑える](../lessons/cap-hard-limit-by-remaining-fraction.md)の規則に従う。
- 採否測定は[docs/guides/sprt.md](../guides/sprt.md)の段階ゲートに従う。

## 設計判断

用語は[持ち時間の効率的な使用](time-management-efficiency.md)の「予算の再定義」「序盤の係数」「局面適応の係数」に従う。
`remaining`は着手前の残り時間、`increment`は加算、`byoyomi`は秒読み、`moves_to_go = max(100, (450 − ply) / 2)`は残り手数の見積り、`w = min(1, (ply + 4) / 40)`は序盤の係数、`safe_hard = max(1 ms, remaining + byoyomi − 30 ms)`は安全上限、`share = remaining / moves_to_go + 0.7·increment`は持ち時間と加算の分担である。

| 判断 | 内容 |
|---|---|
| 予算の分岐 | 残り時間0の手は`soft = hard = max(1 ms, min(0.7·increment + 0.8·byoyomi, safe_hard))`、最終押し込みの手（秒読みが正で`0 < remaining < 1.2·byoyomi`）は`soft = hard = safe_hard`とし、いずれも係数を適用しない（第1段階のまま）。それ以外の手に次の2行を適用する。`movetime`との併用は、これらの予算を求めた後にsoftとhardのそれぞれで指定時間との小さい方を採り、局面適応を無効にする既存の規則を保つ。 |
| `total`を中断閾値にする | `soft = max(1 ms, min(w·(share + 0.8·byoyomi), safe_hard))`は変えない。`total = soft × c × fallingEval × reduction × bestMoveInstability × highBestMoveEffort`を各反復の完了時に更新し、次の反復の探索中の中断閾値を`hard = max(1 ms, min(total, w·(5·share + 0.8·byoyomi), remaining / 4 + 0.8·byoyomi, safe_hard))`とする。中断した反復は第1段階の条件で途中結果を採用する。不採用の候補は`total`を反復の完了時にだけ検査したため、反復の所要時間が前の反復の2.5倍前後になる深さ6〜7の探索では、実際の消費が閾値の2倍前後（[stage3-bench](../measurements/time-management-efficiency-stage3-bench.md)のv2で最終`info`の経過時間÷softの平均2.33、中央値1.93）になっていた。中断閾値にすれば消費は閾値に一致する。`remaining / 4 + 0.8·byoyomi`は不採用前の式が持っていた項であり、残り時間が減るほど1手の上限を縮めて、時計を安全上限−30 msの帯まで使い切らせない。最初の反復（`total`が未定義）の中断閾値は`total`を`soft`とみなして求める。 |
| 正規化定数c | cは、代表局面のbenchで記録した正規化前の積P_iと各局面の上限比U_i（`min(w·(5·share + 0.8·byoyomi), remaining / 4 + 0.8·byoyomi, safe_hard) / soft`）について、`(1/N)·Σ min(c·P_i, U_i) = 1`を満たす値とする。切り詰めと定数倍は交換できないので、中央値を1にした0.48を平均で割る計算では求まらない。v2の分布とU_i = 5の近似では約0.317である（0.33では平均1.04）。確定後、同じbenchで実測した最終`info`の経過時間÷softの平均が0.9以上1.1以下に入ることを確認し、入らなければ原因（中断の遅れ、最初の反復の扱い）を調べてから確定する。cはSTCの開始後は変えない。 |
| 煙試験の判定条件 | 採否測定の前に、候補と比較対象を`time=10000+100`で、採否測定と同じ同時対局数と外部負荷の下、ペア数を同時対局数の3倍以上（同時対局数16なら48ペア）にして対局させる。ハーネスの実ワーカー数は待ち行列のペア数で頭打ちになるので、10ペアでは同時対局数を再現できない。判定は、初形からのplyで`[200, 300)`と`[300, 400)`の各帯について、候補側の全着手の着手前の残り時間をまとめた中央値が、比較対象側の同じ値の80%以上であることとする。各帯の標本が両側とも200手に満たない場合はペアを追加する。80%は本書が事前に定める値であり、不採用の候補は8%と4%であった。あわせて`time=9000+0,byoyomi=300`の同じペア数の煙試験を行い、こちらは時間切れ0件だけを判定する（残り時間は両側とも0になる帯があるため比の判定は行わない）。満たさない場合はcを再計算せず、反復単位の超過と中断の遅れを調べ、hardの項の見直しを別に起案する。 |
| 採否の判定 | 標準のSTCとLTCのGSPRTで判定する。候補は1つで、定数違いは追加しない。 |

## 実装フェーズ

### フェーズ1　中断閾値、hardの歯止め、正規化の再計算

`total`を中断閾値にし、hardに`remaining / 4 + 0.8·byoyomi`の項を戻し、代表局面のbenchでcを求めて確定する。単体テストの予算値とD7-TIME群の期待値を更新する。

### フェーズ2　煙試験

「設計判断」の煙試験を行い、`docs/measurements/time-management-budget-cap-smoke.md`へ記録する。

### フェーズ3　採否測定

標準のSTCとLTCで判定し、`-stc.md`と`-ltc.md`へ記録する。

### フェーズ4　文書の更新

採用なら[探索部](search.md)の時間管理の節と関連するrustdocを書き換える。

## 検証

- 本書の変更の前後で、同じD1の構成における固定深さのbench総ノード数が一致すること（係数は時間制御でだけ働く）。比較対象がB′の場合、B′との差はD1の探索順序の変更によるものとして別に記録する。
- 煙試験と採否測定の`time_forfeits`、エンジン異常、拒否着手が0件であること。
- 煙試験の残り時間の判定条件を満たすこと。

## 完了条件

採用で完了する条件は、煙試験の判定条件の達成、LTCの`H1`、および異常0件である。
不採用で完了する条件は、測定記録が残り、hardの項の見直しの要否が「状態」に書かれていることである。

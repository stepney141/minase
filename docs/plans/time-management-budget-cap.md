# 局面適応の予算に残り時間の歯止めを戻す

## 先に読む要約

本書は、[持ち時間の効率的な使用](time-management-efficiency.md)で不採用となった第3段階（局面適応の係数）の配分の欠陥を直し、改めて採否を測るマイルストーンの設計書である。
STCの[事後分析](../measurements/time-management-efficiency-stc.md)によれば、不採用の主因は係数つきの予算が持ち時間を200手目までに使い切らせ、大半の局が決まる200〜600手で候補が基準より0.3〜0.5浅く読んだことにある。
原因は2つで、係数の積の分布が右に裾が長く平均の消費が公平な分担を上回ること、および打ち切り上限hardに残り時間に比例する歯止めがないことである。
本書は、hardに現行の式が持つ`remaining / 4 + 0.8·byoyomi`の項を戻し、係数の正規化を中央値ではなく上限で切った平均が1になるよう改め、採否測定の前に採否測定と同じ時間制御の煙試験で残り時間の推移が基準を下回らないことを確かめる。
候補は[分解測定](time-management-decomposition.md)の第1段階だけの構成（D1）の上に積み、D1が採用されていればD1を、そうでなければ分解測定の共通基準を比較対象として、標準のSTCとLTCで判定する。
完了条件は、煙試験で残り時間の推移と時間切れ0件を満たし、LTCで`H1`となることである。

## 状態

起案。2026年9月18日に起案し、着手日は未定である。
着手は[分解測定](time-management-decomposition.md)のD1の判定の後とし、利用者の承認を要する。
次の一手は、D1の判定を待つことである。

## 目的

局面の信号に応じて予算を伸縮させる第3段階を、持ち時間を序盤で使い切らない配分に直し、中終盤の到達深さを基準と同等以上に保ったうえで採否を測る。

## 適用範囲

対象は、`clock_budget`のhardの式、`total`の正規化定数、および採否測定の前の煙試験の判定条件である。
係数の4つの式と定数、序盤の係数、途中結果の採用、最終押し込みは変えない。
第2段階（深さの抑制）は再検討しない。

## 依存関係

- [分解測定](time-management-decomposition.md)のD1の判定が比較対象を決める。D1が`H1`ならD1のコミットを、そうでなければ分解測定の共通基準B′を比較対象とし、候補はどちらの場合もD1の構成の上に本書の修正を積む。
- [打ち切り上限は残り時間の割合でも抑える](../lessons/cap-hard-limit-by-remaining-fraction.md)の規則に従う。
- 採否測定は[docs/guides/sprt.md](../guides/sprt.md)の段階ゲートに従う。

## 設計判断

| 判断 | 内容 |
|---|---|
| hardの歯止め | `hard = max(1 ms, min(w·(5·(remaining / moves_to_go + 0.7·increment) + 0.8·byoyomi), remaining / 4 + 0.8·byoyomi, safe_hard))`とする。`remaining / 4 + 0.8·byoyomi`は不採用前の式が持っていた項であり、残り時間が減るほど1手の上限を縮めて、時計を安全上限−30 msの帯まで使い切らせない。秒読み局面（残り時間0）と最終押し込みの手は第1段階のままである。 |
| 正規化の基準 | `total = soft × c × 積`のcを、代表局面のbenchで「hardの上限5で切った積」の平均が1になる値とする。不採用の候補は積の中央値を1にしたが、分布の裾が長いため上限で切った平均は1.44であり、平均の消費が分担の1.44倍になって持ち時間を使い切った。v2の分布から見積もるとcは0.48から約0.33へ下がる。値はbenchで再計算して確定し、STCの開始後は変えない。 |
| 煙試験の判定条件 | 採否測定の前に、候補と比較対象を`time=10000+100`の10ペア（採否測定と同じ同時対局数）で対局させ、手数帯200〜300手と300〜400手の着手前の残り時間の中央値が比較対象の値の80%以上であること、および時間切れ0件を判定条件とする。80%は本書が事前に定める値で、不採用の候補は8%と4%であった。満たさない場合はcを再計算せず、hardの項の見直しを別に起案する。 |
| 採否の判定 | 標準のSTCとLTCのGSPRTで判定する。候補は1つで、定数違いは追加しない。 |

## 実装フェーズ

### フェーズ1　hardの歯止めと正規化の再計算

`clock_budget`のhardに`remaining / 4 + 0.8·byoyomi`の項を戻し、代表局面のbenchでcを再計算して確定する。単体テストの予算値とD7-TIME群の期待値を更新する。

### フェーズ2　煙試験

`time=10000+100`と`time=9000+0,byoyomi=300`の各10ペアで、残り時間の推移の判定条件と時間切れ0件を確かめ、`docs/measurements/time-management-budget-cap-smoke.md`へ記録する。

### フェーズ3　採否測定

標準のSTCとLTCで判定し、`-stc.md`と`-ltc.md`へ記録する。

### フェーズ4　文書の更新

採用なら[探索部](search.md)の時間管理の節と関連するrustdocを書き換える。

## 検証

- 固定深さのbench総ノード数が比較対象と一致すること（係数は時間制御でだけ働く）。
- 煙試験と採否測定の`time_forfeits`、エンジン異常、拒否着手が0件であること。
- 煙試験の残り時間の推移が判定条件を満たすこと。

## 完了条件

採用で完了する条件は、煙試験の判定条件の達成、LTCの`H1`、および異常0件である。
不採用で完了する条件は、測定記録が残り、hardの項の見直しの要否が「状態」に書かれていることである。

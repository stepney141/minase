# 学習の系列の記録と進捗図の設計書

## 先に読む要約

本書は、中将棋エンジンminaseのニューラルネットワーク（以下、ネット）の学習について、損失などの指標が異常なく推移しているかと、どのくらい強くなったかを、系列ごとに1か所へ記録して図にする枠組みを作る設計書である。
系列とは、1つの初期ネットから続く、自己対局の生成と学習のサイクルの連なりをいい、対象はAlphaZero型探索の強化学習である。
AlphaZero型探索は、ネットでモンテカルロ木探索（以下、MCTS）を導く探索である。
これまでは、10サイクルごとの測定のたびに測定記録を1本書き、サイクルごとの値を表へ手で写していたので、系列を通した推移を読むには複数の記録をたどる必要があり、図もなかった。
本書では、系列ごとのディレクトリ`docs/training/<系列名>/`を新しく設け、系列の現在の状態を書く系列のページ、図の元になる表を保存するCSVファイル、および進捗図を置く。
進捗図は、固定の相手に対する強さ、方策と価値の損失、固定の検証用データで人間が指した手と一致した割合、1局の手数、および自己対局の終わり方の割合の6つのパネルを、横軸を揃えて縦に並べた1枚の画像であり、強さは、対局の結果から求める尺度であるEloの差で表す。
記録からCSVを作る収集と、CSVから図を描く作図は、1つの道具の別々の操作にする。
最初の適用として、中断した1回目の強化学習の32サイクルから系列のページを作り、2回目の強化学習の値と重ねて読む基準にする。
完了条件は、置き場の規則が文書に入り、道具が試験を通り、1回目の系列のページができ、強化学習を回す実行器が、別の設計書で欄を改めた後に書く記録からCSVを作れて、手引きと設計判断の記録が改まっていることである。

## 目的

本書の目的は、学習の系列の推移を、1つの場所と1枚の図で読めるようにすることである。

強化学習は、実行器`minase_zero run-cycles`が、自己対局の生成、学習、および出力の照合を1サイクルとして繰り返して進める。
出力の照合は、学習器が計算したネットの出力と、対局に使う推論の実装が計算した出力が一致することの検査である。
実行器は、サイクルを1つ終えるたびに、生成の統計、学習の統計、および実行環境を1行のJSONにまとめ、系列ごとのファイルへ追記する。
以下、このファイルを系列の記録と呼ぶ。
系列の記録は、ネットワーク接続の記憶装置（以下、NAS）にあり、1回目の強化学習では`cycles.jsonl`である。

1回目の強化学習では、10サイクルごとの進捗を測定記録に書いた（例は[20サイクル目の記録](../measurements/alphazero-rl/alphazero-rl-restart-progress-c0020.md)）。
この測定記録は、サイクルごとの対局数、手数、引き分け、および損失を、系列の記録から10行の表へ手で写している。
1回目は途中で設定を改めてサイクル1から学び直したので、その前後を合わせると進捗の測定記録は6本に分かれ、系列を通した推移は、6本を順に開いて表を見比べないと読めない。
測定記録は、1回の測定を設計書ごとのディレクトリに置いて凍結する文書であり（[設計判断の記録](../adr/group-measurement-records-by-commissioning-plan.md)。以下、設計判断の記録をADRと書く）、系列が進むたびに書き換える記録の置き場ではない。

[2回目の実行の設計書](alphazero-rl-2.md)は、10サイクルごとに、固定の相手に対するElo、固定の検証用データの診断、および費用を利用者へ示して、続けるかどうかの承認を得ると定めている。
固定の相手は、学習の間ずっと変えない2つの相手であり、gitのコミットと1手のノード数を固定したminaseのαβ探索（minaseの既定の探索方式）と、思考の深さを固定した中将棋の外部エンジンHaChuである。
固定の検証用データは、学習に使わない811局の人間同士の棋譜である。
この判断の材料を毎回同じ形で出せるようにすることが、本書の直接の用途である。

## 適用範囲

本書では、次の作業を行う。

- 学習の系列の記録の置き場`docs/training/`と、その規則を定める。
- 固定の相手との対局の集計、固定の検証用データの診断、および系列の記録からCSVを作り、CSVから進捗図を描く道具を作る。
- 1回目の強化学習の系列のページを作る。
- [深層強化学習を回す手引き](../guides/alphazero-training.md)の定例の測定の手順に、収集、作図、および系列のページの更新を加える。

次の項目は対象外とする。

- NNUEの学習の作図と、NNUEの学習の記録の形式の変更は行わない。NNUEは、着手ごとに差分で更新できる小さなネットの評価関数である。NNUEの学習器は、将棋のNNUE学習器tataraに倣った枠組みへ載せ替える[設計書](nnue-tatara-framework-and-halfkp-vm.md)（以下、tatara化の設計書）で作り直すので、作図はその完了の後に、その時点の学習器の出力を読む形で別に計画する。記録の形式をtataraに揃えるかどうかは、本書では決めない（「NNUEの扱い」の節）。
- 定例の測定そのものの条件と手順は変えない。固定の相手との対局は[強さを測る固定の相手の設計書](archived/mcts-fixed-opponents.md)が、10サイクルごとの測定の内容と続行の判断は2回目の実行の設計書が定める。
- 既存の測定記録は移動しない。`docs/measurements/`の記録は、ADRと凍結した設計書が参照しているからである。
- 全部の対局からネットのレーティングを同時に推定する計算と、記録を表示するWebの画面は作らない。

## 設計判断

| 論点 | 採る方式 | 棄却した代案 |
|---|---|---|
| 置き場 | 系列ごとのディレクトリ`docs/training/<系列名>/`（2026年11月16日の利用者の決定） | `docs/measurements/`の設計書ごとのディレクトリに置く案は、系列が複数の設計書をまたぎ、上書きする記録と凍結する記録が混ざる |
| 記録の単位 | 系列のページ1つを、系列が進むたびに上書きする | 定例の測定ごとに進捗の測定記録を書き、サイクルの表を手で写す1回目の方法は、推移を1か所で読めない |
| 図の元データ | gitに置くCSVとし、収集と作図を別の操作にする | NASの系列の記録から直接描く案は、NASのない場所で図を作り直せない。系列の記録は1回目の32サイクルで27 MBあり、サイクルごとに増えるので、gitには置かない |
| 強さの線 | 固定の相手との対局のEloの差を、相手と測定の条件ごとに別の線で描く | 隣り合うネットのEloの差を足し上げる案は、値が実際の強さより大きく出る。全対局からの同時推定は、固定の相手との対局だけを描く間は要らない |
| 対局とサイクルの対応 | 系列の定義に、サイクルの番号と集計の場所を書く | ネットのSHA-256（ファイルの内容から求める識別子）で自動的に結ぶ案は、1回目の基準の対局が書き出し直したネットを使っていて、系列の記録のSHA-256と対局の集計のSHA-256が一致しない |
| 横軸 | 学習用に残した局面の累計 | サイクルの番号は、サイクルごとの量の違いを隠す。学習器が読んだ標本の累計は、同じ局面を繰り返し数えるので、作ったデータの量を表さない |
| 設定の変更の表示 | 設定を表す列の値が前のサイクルから変わった位置に、縦線と値を描く | 変更の一覧を手で保守する案は、書き忘れを検出できない。サイクルごとに自動で調整する投了の閾値のように、自動で決まる値まで縦線にする案は、設定の変更と区別がつかなくなる |
| 道具の形 | `tools/train/progress/`に、依存をロックファイルで固定した独立のPythonの環境を置く | 学習器の環境に作図の依存を足す案は、借りた計算機にも作図の依存が入る。学習の指標を表示する道具TensorBoardを使う案は、gitのCSVから、NASも表示のサーバーもなしに共有用の画像を作り直す用途には、必要な構成が多い |
| 1回目の記録の読み込み | 一度だけの変換でCSVを作り、道具には今の欄だけを読ませる | 道具に古い欄の名前の読み替えを持たせる案は、使い終えた形式の互換のコードを残す |
| NNUE | 対象外とする | 同じ設計書でNNUEの記録の形式を替える案（「NNUEの扱い」の節） |

### 先行実装

先行例は[調査メモ](../research/training-progress-records-prior-art.md)にまとめた。
本書の方式のうち、先例があるものと、minaseが加えるものは次のとおりである。

固定の相手との対局を主な線にする判断は、ELF OpenGoの論文とLeela Chess Zero（以下、lc0）の記述に基づく。
ELF OpenGoの論文は、連続するネットの対から求めた自己対局のEloが膨張すると述べている。
lc0は、最良ネットとの対戦のEloの差を足し上げた値を学習サイトの図にしているが、公式ブログで、この値が、Eloが既知のエンジンとの対局から求めた推定の動きに従わないことが多いと述べている。
強さを誤差棒つきの点で描く形はKataGoの学習サイトに、横軸に累積の学習量を取る形はlc0、KataGo、およびAlphaZeroの論文にある。
損失と強さを縦に並べる形は、Stockfishの学習器nnue-pytorchの`do_plots.py`にある。
ただし、同スクリプトは損失の横軸を更新のステップ、Eloの横軸をエポックとしており、横軸は揃えていない。
設定を変えた時点を図に示す例は、lc0の公式ブログが説明する図にあり、学習率を下げた時点に点を置いている。
学習1回の記録を1か所にまとめ、学習曲線、強さ、および設定を同じページに載せる形は、tataraの作者の実験管理サイトnnue-labにある。

minaseが加えるものは3つある。
第1は、全部のパネルの横軸を同じ量に揃えることである。
第2は、設定の変更を、系列の記録から検出して縦線で示すことである。1回目のサイクル14でリプレイバッファの範囲を変えたときに損失が同時に動いたことを、表からは読み取りにくかったためである。
第3は、自己対局の性質（1局の手数と、引き分けなどの割合）の推移を図にすることであり、この例は調べた範囲になかった。
手引きは、勝敗のつかないまま手数だけが延びる対局（引き延ばし）を疑うために、これらの値の推移をサイクルごとに見るよう求めている。
利用者は、同じ局面の繰り返しによる引き分け（千日手）を減らす意向も持っている（[提案](../proposals/repetition-draw-reduction.md)）。

## 置き場と系列のページ

`docs/training/`の直下に、系列ごとのディレクトリを置く。
ディレクトリの名前は、系列のページを作るときに決め、実行器が使う系列の名前（`--cycles-dir`の値）は系列のページに書く。
1回目の強化学習は`alphazero-rl-1`、2回目は`alphazero-rl-2`とする。
`docs/training/README.md`は、本節の規則と、系列の一覧を持つ。

系列のディレクトリには、次のファイルを置く。

| ファイル | 内容 | 書き手 |
|---|---|---|
| `README.md` | 系列のページ | 人またはエージェント |
| `series.toml` | 系列の定義。固定の相手との対局の集計と、固定の検証用データの診断を、サイクルの番号に対応づける | 人またはエージェント |
| `cycles.csv`、`strength.csv`、`validation.csv` | 図の元になる値 | `series_progress.py` |
| `progress.png` | 進捗図 | `series_progress.py` |
| `validation/` | 固定の検証用データの診断のJSON（サイクルごと） | `minase_zero external-eval` |

系列のページは、次の節を順に持つ。

1. 系列の説明（目的、設計書へのリンク、系列の記録とネットの置き場所）
2. 状態（最後に終えたサイクル、最後の定例の測定、次の判断）
3. 進捗図
4. 読み取れること（図と値から言えることを、根拠の値とともに書く）
5. 測定の条件（`series.toml`に書いた測定条件の名前ごとに、MCTSのコミット、1手のシミュレーション回数、対局の規則、および条件を定めた設計書へのリンク）
6. 費用（それまでの累計と、次の10サイクルの見込み）
7. 測定記録（定例の測定の記録へのリンクを、サイクルの順に並べた表）

系列のページは、追記せずに上書きする。
設計書の「先に読む要約」と同じ扱いであり、過去の状態はgitの履歴に任せる。
系列が終わったら、状態の節に終わった日と理由を書いて凍結し、以後は書き換えない。
ただし、終わった系列のネットを、後から新しい測定の条件で測り直すことがある。
2回目の実行の設計書は、MCTSの探索の結果を変える変更がバイナリに入った場合に、1回目の基準のネットを測り直すと定めている。
その場合は、凍結した系列の`series.toml`に対局を足して`strength.csv`を作り直し、系列のページには測定の条件と測定記録の表の行だけを足す。

1回で完結する測定の記録は、これまでどおり`docs/measurements/<設計書名>/`に置く。
固定の相手との対局、出力の照合、および持ち時間つきの対局の記録がこれに当たる。
置き場を決める規則は、「系列が進むたびに書き換える記録は`docs/training/`に、1回の測定で凍結する記録は`docs/measurements/`に置く」の1文とする。
定例の測定の記録は、これまでと同じ見出し（目的、コマンドライン、エンジン、環境、結果、および結論）で書き、サイクルごとの値の表は書かない。

## 道具

### 構成

道具は、`tools/train/progress/`に置く1本のPythonのスクリプト`series_progress.py`であり、同じディレクトリに試験を置く。
依存は作図のライブラリmatplotlibだけであり、同じディレクトリの`pyproject.toml`と`uv.lock`で版を固定する。uvは、Pythonの環境を管理する道具である。
学習器の環境（`tools/train/zero/`）とは分ける。
借りた計算機に入れる環境に、作業機でしか使わない作図の依存を足さないためである。

操作は2つに分ける。

- `collect`は、系列の定義が指すファイルを読み、系列のディレクトリのCSVを書き直す。
- `plot`は、系列のディレクトリのCSVだけを読み、`progress.png`を書き直す。

`plot`がCSVだけを読むので、NASのない場所でも図を作り直せる。
CSVの列の名前、型、意味、および空欄にできる条件と、系列の定義の欄は、フェーズ2でスクリプトのdocstringに定め、[ファイル形式の手引き](../guides/file-formats.md)から場所を示す。

### 系列の定義

`series.toml`は、gitにあるファイルだけを、リポジトリの根からの相対パスで指す。
欄は2種類である。

- 固定の相手との対局は、サイクルの番号、集計スクリプトが書いた`summary.json`の場所、その中の測定名（`run_name`）、および測定条件の名前の4つを1件として並べる。
- 固定の検証用データの診断は、サイクルの番号と、診断のJSONの場所の2つを1件として並べる。

測定条件の名前は、MCTSの側の条件の組に付ける名前である。
集計スクリプトの出力は、相手の種類、相手の制限（αβ探索のノード数、またはHaChuの深さ）、対局に使った中将棋の規則、および手数の上限を持つが、MCTSのコミットと1手のシミュレーション回数を持たない。
どの対局を同じ条件として比べてよいかは、測定を計画した設計書が決めるので、その判断を名前として書き、名前の意味は系列のページの「測定の条件」の節に書く。

系列の記録はNASにあるので、系列の定義には書かず、`collect`の引数で渡す（フェーズ4）。

### CSVの内容

`strength.csv`は、対局1件を1行とする。
列は、サイクルの番号、相手の種類、相手の制限、測定条件の名前、対局の規則、手数の上限、測定名、対局に使ったネットのSHA-256、試行したペアの数、有効なペアの数、破棄したペアの数、ペンタノミアル度数、得点率、およびEloの差とその95%信頼区間である。
ペアは、同じ開始局面で先後を入れ替えた2局の組である。
破棄したペアは、どちらかの対局が対局の手数の上限に達したために、集計から外したペアである。
ペンタノミアル度数は、ペアの得点が0、0.5、1、1.5、2点であった件数の5つの値である。
2回目の実行の設計書が続行の判断の材料として求める値も、同じ行に持つ。
拒否着手または不正着手を含むペアを除いたElo、それらのペアと破棄したペアを合わせた件数と割合、破棄したペアを2敗とした場合のElo、および2勝とした場合のEloである。
拒否着手は、minaseの審判（着手が規則に合うかを判定する部分）が認めたMCTSの着手を、HaChuが受け付けなかったものをいう。
不正着手は、規則に反する着手である。
これらはすべて、集計スクリプトの出力にある。

`validation.csv`は、診断1件を1行とする。
列は、サイクルの番号、データのSHA-256、対局数、局面数、対局結果に対する価値の損失、人間が指した手との一致率、および手数の4つの帯（1〜40手目、41〜100手目、101〜200手目、201手目以降）ごとの同じ2つの値である。

`cycles.csv`は、サイクル1つを1行とする。
列は、次の4群である。

| 群 | 列 |
|---|---|
| 量 | サイクルの番号、そのサイクルで学習用に残した局面数、その累計、対局数、手数の合計 |
| 自己対局の性質 | 引き分けの対局数、手数の上限に達した対局数、投了で終わった対局数 |
| 学習の診断 | そのサイクルで生成したデータの訓練の標本と検証局面のそれぞれについて、方策の損失、対局結果に対する価値の損失、および合法手に乗る確率質量 |
| 設定 | 名前が`setting_`で始まる列。系列ごとに、系列の記録にある設定の値を入れる |

学習用に残した局面数は、生成器（自己対局で教師の局面を作るプログラム）が学習用のファイルへ書いた局面の数であり、検証用に分ける前の値である。
今の系列の記録では`selfplay_summary.training_positions`に当たる。
生成器は、手数の上限に達した対局を学習に使わずに捨てる。
学習用に残した局面数は、この対局の局面と、生成し直しのときに学習から除いた投了の対局の局面を含まない。
一方、対局数と手数の合計は、手数の上限に達した対局を含む。
生成し直しがあったサイクルでは、局面数、対局数、手数の合計、および自己対局の性質の3つの件数のすべてに、生成し直した分を足す。
生成し直しは、通常の生成に対局を足す処理であり、局面数だけを足すと、横軸と自己対局の性質が別々の対局の集まりを表すからである。
割合と1局の手数は、足した後の値から求め、分母は、手数の上限に達した対局を含む対局数とする。

学習の診断は、系列の記録の`training_summary.diagnostics`の`latest_training_sample`と`validation`から取る。
方策の損失は、探索が選んだ手の分布とネットの出力の食い違いであり、価値の損失は、ネットが予測した勝率と対局の結果の食い違いである。
合法手に乗る確率質量は、ネットの方策の出力のうち、合法手に割り当てられた確率の合計である。
訓練の標本と検証局面は、どちらもそのサイクルで生成したデータから取った局面であり、学習に使ったかどうかだけが違う。
どちらの値も、そのサイクルの学習を終えた重みで診断した局面ごとの平均なので、この2本の差は過学習の目安として読める。
価値の損失は、対局結果だけを教師とする値（`value_result`）に揃える。
固定の検証用データの診断が持つ価値の損失がこの値だからである。

設定の列は、列の名前の一覧を道具に固定せず、`setting_`で始まる列をすべて設定として扱う。
設定の種類は系列によって違うからである。1回目はリプレイバッファが含む最古のサイクルを持ち、2回目はリプレイバッファの局数の上限を持つ。
意味の違う値を同じ列に入れないために、列は設定ごとに分ける。
改めた後の系列の記録のどの欄からどの列を作るかは、フェーズ4で確定する。

### 入力の検査

`collect`は、次の場合にエラーで止まる。

- 系列の定義が指すファイルがない。
- 測定名が集計の中にない。
- 集計または診断のJSONに、CSVの列を作るための欄がない。
- 相手の種類、相手の制限、および測定条件の名前が同じ対局が、同じサイクルに2件ある。
- 相手の種類、相手の制限、および測定条件の名前が同じ対局の間で、規則または手数の上限が違う。
- 同じサイクルの診断が2件ある。
- 診断のデータのSHA-256が、系列の中で揃わない。
- 系列の記録のサイクルの番号が、1から連続していない（フェーズ4）。

`plot`は、対局または診断のサイクルの番号が、0でも`cycles.csv`にある番号でもない場合に、エラーで止まる。
サイクル0は初期ネットであり、横軸の位置は0とする。

測っていない値は空欄にし、0で埋めない。
空欄にできるのは、有効なペアが0件の対局のElo、局面のない手数の帯の診断の値、および設定の列だけであり、ほかの列の空欄はエラーにする。

### 進捗図

進捗図は、横軸を揃えたパネルを縦に並べた1枚のPNGである。
横軸は、学習用に残した局面の累計とし、定例の測定を行ったサイクルの位置にサイクルの番号を添える。

| パネル | 縦軸 | 線 |
|---|---|---|
| 強さ | 固定の相手に対するEloの差 | 相手の種類、相手の制限、および測定条件の名前の組ごとに1本。点と95%信頼区間の誤差棒 |
| 方策の損失 | 交差エントロピー | 訓練の標本、検証局面 |
| 価値の損失 | 対局結果に対する二値交差エントロピー | 訓練の標本、検証局面、固定の検証用データ。ln 2の水平線 |
| 一致率 | 固定の検証用データで、人間が指した手と一致した割合 | 全体と、手数の4つの帯 |
| 1局の手数 | 手数の合計を対局数で割った値 | 1本 |
| 自己対局の終わり方の割合 | 対局数に対する割合 | 引き分け、手数の上限、投了 |

ln 2（約0.693）は、どの局面でも勝率を5割と答えた場合の価値の損失であり、これより上の値は、予測が役に立っていないことを表す。

強さのパネルは、次の規則で描く。

- 相手の種類、相手の制限、または測定条件の名前が異なる対局は、同じ線に結ばない。αβ探索に対する値とHaChuに対する値は、別々の相手に対するEloの差であり、共通のレーティングではない。
- 得点率が0.1未満または0.9を超える点は、白抜きの点にする。2回目の実行の設計書は、得点率がこの外側に出たら相手の制限を1段階強い値または弱い値へ改めると定めている。改めた後の値は新しい線になる。同じネットを新旧2つの制限で対局させて求めたEloの差を、以後の値に足して比べる計算は、系列のページの「読み取れること」に書く。
- 信頼区間の端が無限大の点は、点を描き、誤差棒をパネルの端まで伸ばして矢印で示す。1回目のサイクル10のHaChuとの対局がこれに当たり、下端が負の無限大である。点推定が無限大の点は、パネルの端に三角の印で示す。
- 破棄したペアを2敗または2勝とした場合のEloは、図に描かず、CSVと系列のページに置く。この2つの値の幅は破棄の扱いによる幅であり、対局数の少なさによる信頼区間とは別の量だからである。

価値の損失のパネルでは、平均の取り方が線によって違う。
訓練の標本と検証局面の値は局面ごとの平均であり、固定の検証用データの値は、1局の中で平均してから対局の間で平均した値である。
凡例にその別を書き、固定の検証用データの線とほかの2本の線の差を、過学習の大きさとして読まない。

設定の変更は、設定の列の値が前のサイクルの値から変わった位置に、全パネルを通る縦線と、列の名前と新しい値を描く。
前のサイクルの値と今のサイクルの値のどちらかが空欄の場合は描かない。
設定の列にしない変更は図に現れないので、系列のページの「読み取れること」に書く。1回目では、サイクル10からの手数の上限の変更と、サイクル21〜25の重みの移動平均の書き出しがこれに当たる。手数の上限は、系列の記録に欄がない。移動平均の欄`ema_period_samples`はサイクル25までの記録にしかなく、自己対局は移動平均をとらない重みで行ったので、設定の列にしない。

`plot`は、参照の系列を引数で受け取れる。
参照の系列のCSVを読み、強さ、価値の損失のうち固定の検証用データの線、および一致率を、薄い色で重ねる。
重ねるのは、強さでは相手の種類、相手の制限、および測定条件の名前が一致する線、診断ではデータのSHA-256が一致する線だけである。
2回目の実行の設計書が、強さと診断の値を1回目の値と並べて読むよう求めているので、2回目の進捗図には1回目の系列を参照として重ねる。
ただし、学習レシピを先行実装に揃える設計書は、2回目では全部の手番の局面を学習用に残すと定めているので、同じ局面数でも対局数と計算の費用は1回目と揃わない。
横軸の位置の違いから、計算の効率の優劣は判断しない。

道具が扱うのは、サイクル0の初期ネットから始まる系列だけとする。
ほかの系列の途中から分かれた系列で累計を引き継ぐ処理は、そのような系列を記録する必要が生じたときに加える。

## 1回目の系列

1回目の強化学習は、サイクル32で中断して凍結した（[設計書](archived/alphazero-rl.md)）。
本書では、この系列のページを`docs/training/alphazero-rl-1/`に作り、道具の受け入れの確認と、2回目の参照に使う。

`strength.csv`と`validation.csv`は、`collect`で作る。
入力は、1回目のサイクル10、20、および32のネットによる固定の相手との対局6件と、サイクル0、10、20、および32のネットの固定の検証用データの診断4件であり、どちらもgitにある。

`cycles.csv`は、NASの`cycles.jsonl`から、一度だけの変換で作る。
1回目の系列の記録は、欄の名前が今の実行器と違う。
リプレイバッファに含めたサイクルの番号の一覧は`window_cycles`という古い名前であり、範囲の先頭の設定を表す`window_first_cycle`はサイクル14以降にしかない。
今の実行器が書く開始局面の種類の欄もない。
変換のスクリプトは、一度しか使わないのでリポジトリに置かず、どの欄からどの列を作ったかを系列のページに書く。

最古のサイクルは`window_cycles`の最小値であり、サイクル13まで1、サイクル14から3である。
記録にない値は空欄にし、既定値で埋めない。

1回目の系列のページは、作った時点で凍結する。
既存の進捗の測定記録6本は動かさず、系列のページの測定記録の表からリンクする。

## NNUEの扱い

NNUEの学習は、本書の対象外とする。
理由は2つある。

第1に、NNUEの学習器はtatara化の設計書で作り直す予定であり、学習器の出力が確定するのはその完了の後である。
今の学習器は、superbatch（学習を区切る単位）ごとの訓練損失、検証損失、および符号の一致率を`training.jsonl`に書いており（`crates/minase-trainer/src/nnue/train/record.rs`）、学習の中の曲線を描くだけなら、この記録で足りる。

第2に、NNUEの記録をtataraの形に揃えるかどうかは、作図とは別の判断である。
tataraは学習1回につき1つの`experiment.json`を書き、nnue-labがそれを表示する。
minaseの学習器が書く3つのファイル（`training.jsonl`、`summary.json`、`config.json`）を、同じ形の1つのファイルへ替える場合の影響は、次のとおりである。

- 教師の生成と学習を世代ごとに続けて行う連続生成スクリプト`scripts/vast/generation_chain.py`は、学習の完了を`summary.json`の有無と内容で判定している。`experiment.json`は学習の開始時から存在するので、判定の方法を改める必要がある。
- 今の学習器は、学習を再開するときに、設定が前回と同じであることを`config.json`で照合している。照合に使うファイルを改める必要がある。
- 今の`training.jsonl`には、訓練損失のない学習前の検証の行がある。tataraの履歴は、訓練損失を必須の実数とする。
- tataraの系譜の欄は、学習の途中の状態を保存したファイル（チェックポイント）からの再開と派生を表す。NNUEの世代反復は、重みを世代ごとに初期化し、前の世代のネットを教師の生成に使うので、世代のつながりはこの欄では表せない。

利用者は、NNUEの学習器と抽象化をtataraの設計に揃えることを優先すると決めている（2026年11月15日）。
記録の形式までtataraに揃えるかどうかは、tatara化の設計書に着手する前に、上の影響を示して利用者に諮る。

NNUEの世代反復の系列のページは、[世代反復の設計書](nnue-generation-iteration.md)に着手するときに`docs/training/`に作る。
世代は最大5つで、点が5つ以下の推移は表で読めるので、世代をまたぐ強さは図にしない。
同書が定める、それまでで最も強いと判定された世代との対局の結果を、表に書く。

## 実装フェーズ

フェーズ1〜3は続けて行い、フェーズ4は依存する設計書の後に行う。
プログラムの実装はcodexへ委任し、文書はClaudeが書く。

### フェーズ1　置き場と規則

`docs/training/README.md`を作り、[docs/README.md](../README.md)の分類表と分類の判定の順に`training/`を加える。
CONTRIBUTING.mdの開発ドキュメントの節と、[設計書の書き方](README.md)の測定記録の節に、置き場を決める1文の規則を書く。
後に続く3本の設計書にも、本書が先送りした事項を書き足す。
tatara化の設計書には、着手の前に記録の形式を利用者に諮ることを、世代反復の設計書には、系列のページを`docs/training/`に作ることを、2回目の実行の設計書の「記録」の節には、系列のページの場所を書く。
完了条件は、定例の測定の記録、サイクルごとの値、および系列の状態の3つの例について、どこに書くかを、置き場の規則を書いた4つの文書（`docs/training/README.md`、docs/README.md、CONTRIBUTING.md、および設計書の書き方）だけで決められることである。

### フェーズ2　道具

`tools/train/progress/`に、スクリプト、依存の定義とロックファイル、および試験を作る。
CSVの列の名前、型、意味、および空欄にできる条件を、docstringに定める。
`collect`は、この時点では`strength.csv`と`validation.csv`だけを書く。
完了条件は、試験が通ることと、[テストの手引き](../guides/testing-minase-rules.md)のマージ前のローカル検査（マージの前に手元で実行する検査の一覧）に、試験のコマンドが加わっていることである。

### フェーズ3　1回目の系列のページ

1回目の系列の`series.toml`を書き、`collect`でCSVを作る。
`cycles.csv`を一度だけの変換で作り、`plot`で進捗図を描いて、系列のページを書く。
完了条件は、「検証」の節の実データでの確認がすべて通り、系列のページが凍結されていることである。

### フェーズ4　系列の記録からの収集

学習レシピを先行実装に揃える設計書が系列の記録の欄を改めた後に、`collect`へ、系列の記録から`cycles.csv`を作る処理を加える。
記録のどの欄からどの列を作るかと、設定の列の一覧を、このときに確定してdocstringに書く。
同じ変更で、深層強化学習を回す手引きの定例の測定の節に、診断のJSONを系列のディレクトリへ置く手順、`series.toml`への追記、`collect`と`plot`の実行、および系列のページの更新を加える。
完了条件は、改めた後の実行器が、短い系列を実際に回す試走で書いた系列の記録から`cycles.csv`ができ、進捗図が描けることである。

### フェーズ5　設計判断の記録と凍結

置き場の決定と、図の元データをgitのCSVにする決定を、ADRに書く。
測定記録の置き場のADRは、1回の測定の記録について引き続き有効なので、置き換えない。
ファイル形式の手引きに、CSVと系列の定義の場所を加える。
完了条件は、ADRとファイル形式の手引きが改まり、本書の状態を完了に書き換えて`docs/plans/archived/`へ移してあることである。

## 検証

道具の試験は、試験用に作った小さな入力で、次のことを確かめる。

- `collect`が、集計の`summary.json`と診断のJSONから、定義どおりの列と値のCSVを書く。
- 「入力の検査」の節の各場合に、エラーで止まる。
- 空欄にできる列だけが空欄になり、測っていない値が0にならない。
- `plot`が描く強さのパネルで、得点率が範囲の外の行が白抜きの点に、信頼区間の端が無限大の行が矢印つきの誤差棒に、点推定が無限大の行が三角の印になる。試験は、画像の一致ではなく、描いた要素の種類と座標で確かめる。
- `plot`が、相手の種類、相手の制限、または測定条件の名前の異なる対局を別の線にし、参照の系列のうち条件の一致する線だけを重ねる。
- `plot`が、設定の列の値が変わったサイクルにだけ縦線を描き、空欄をまたぐ位置には描かない。

試験の期待値は、本書とdocstringの定義から決め、道具の出力から写さない。

フェーズ3では、1回目の実データで次を確かめる。

- `strength.csv`のEloの差が、基準の記録の値と一致する。αβ探索に対してサイクル10、20、32の順に−576、−135、+17、HaChuに対して−727、−351、−133である。
- `validation.csv`の4行が、基準の記録の値と一致する。
- `cycles.csv`の学習用に残した局面の累計が、サイクル10、20、32で9,912,465、19,686,284、31,594,296である。
- 生成し直しのあったサイクル8の値が、通常の生成と生成し直しの和である。局面数は884,453と33,841の和の918,294、対局数は8,232と306の和の8,538、手数の合計は5,336,681、引き分けは886局、手数の上限に達した対局は1,451局である。
- 進捗図に、サイクル0の診断の点、HaChuのサイクル10の矢印つきの誤差棒、およびサイクル14のリプレイバッファの変更の縦線があることを、目で確かめる。

フェーズ4では、改めた後の実行器の試走の記録で、`cycles.csv`の各列が系列の記録の欄と一致することを確かめる。

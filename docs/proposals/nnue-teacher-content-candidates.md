# NNUEの教師の局面と教師値を変える候補

本書は、中将棋エンジンminaseの評価関数NNUEの教師データについて、教師にする局面の出所と、局面に付ける教師値を変える候補を並べた提案である。
NNUE（efficiently updatable neural network）は、着手ごとに差分で更新できる小さなニューラルネット評価関数である。
教師データは、自己対局の局面に、その局面の探索値と対局結果を付けた学習用のデータであり、以下では教師と呼ぶ。
作成日は2026年11月14日である。
本書の候補は、これまで[ロードマップ](../ROADMAP.md)の「現在地」の節と、2本の調査メモの「minaseへの含意」の節にだけ書かれていた。
2本の調査メモは、[強豪エンジンの教師生成の調査](../research/teacher-generation-strong-engines.md)と[自己対局の偏りの先行事例](../research/self-play-bias-prior-art.md)である。
利用者が候補を見比べて採否を選べるように、本書はそれらを1つの表に集める。
先行実装の事実と出典は2本の調査メモにあり、本書には判断に必要な値だけを引く。
出典のない見積もりと含意には「推論」と付ける。
採否は利用者が決める。

本書で使う語は次のとおりである。
探索値は、αβ探索が1局面2万ノードで求めた評価値を指す。
静的評価は、探索をせずに評価関数が局面へ直接返す値であり、静止探索は、駒の取り合いが収まるまで読む短い探索である。
世代反復は、あるネットの自己対局で教師を作り、その教師から次のネットを学ぶことの繰り返しを指す。
AlphaZero型のネットは、局面から方策と価値を出力するニューラルネットワークであり、自己対局の強化学習でゼロから学ぶ（[統括計画](../plans/alphazero.md)）。
規則セットは、対局に採用する規則コードの組である（[競技規則](../rules/chu-shogi.md)第33条）。
本書に現れる規則セットのうち、`JCSA`は日本中将棋連盟の規則に基づく組であり、`lishogi`はオンライン対局サイトlishogiの実装に近い組である。
ADRは設計判断の記録を表す。
Eloとレーティング差Rは、対局から推定した強さの差の単位であり、cpは歩兵の価値の1/100を単位とする評価値である。
先例に挙げるStockfishとFairy-Stockfishはチェスとその変種、tanuki-、dlshogi、およびAobaZeroは将棋のエンジンである。

## 位置づけ

現行の教師は、自分の評価関数だけで作られている。
生成器`minase data selfplay generate`は、初期局面から8〜16手のランダムな手順で開始局面を作り、その後は1局面2万ノードの探索で規則上の終局まで指す。
学習の教師値は探索値だけであり、対局結果を混ぜない（[ADR](../adr/train-the-nnue-on-search-value-teachers-with-the-squared-win-rate-difference.md)）。
[NNUEの標準レシピの設計書](../plans/nnue-standard-recipe.md)は、規則セットを`JCSA`から`lishogi`へ改め、学習の条件を決め直したうえで、世代反復を最初からやり直す。
やり直す世代反復も、教師の作り方はこのまま使う。

本書の候補が狙うのは、自分の評価関数で作った教師から次の評価関数を学ぶ反復が、評価の誤りと配置の偏りを強める問題である。
lishogiで対局したminaseのBotでは、麒麟が成る前に盤上にいた手数の59%が右端の2筋だった（[分析](../measurements/adhoc/kirin-right-edge-bias.md)）。
人間の上位者ではこの割合が0.3%である。
2026年11月3日時点のネットで指した対局では、20〜99手目の奔王が自陣の最下段から2段以内にいる割合も85.8%に達した（[集計](../measurements/adhoc/piece-placement-census.md)）。
NNUEの評価値のうち、駒と升ごとの点数の表にあたる部分を線形の経路と呼ぶ。
学習の後に線形の経路を対局結果へ回帰して補正すると、補正の前後を比べた[測定](../measurements/nnue-outcome-regression/nnue-outcome-regression-placement-stc.md)で、奔王の割合は86.0%から14.6%へ下がった。
しかし、補正したネットは補正しないネットに対局で負けたので、標準レシピv1はこの補正を行わない（[測定](../measurements/nnue-standard-recipe/nnue-standard-recipe-fit-stc.md)）。
やり直す世代反復で偏りがどの程度残るかは、標準レシピの設計書が最終候補の採否で配置の距離を測るまで分からない。
配置の距離は、全21駒種の配置の分布が、人間の上位者、既存の中将棋エンジンHaChu、およびAlphaZero型のネットの配置からどれだけ離れているかを1つにまとめた値である。
先例では、自己生成の反復は初めの数世代の後に伸びにくくなり、停滞から抜けた例は自分の外の評価器か非常に深い探索を教師に持ち込んでいる。

次の表の方式は、すでに決定があるので本書の候補にしない。

| 方式 | 決定 |
|---|---|
| 人間の棋譜を、教師の局面、開始局面、または教師値に使う | 使わない（[ADR](../adr/do-not-use-human-games-to-strengthen-the-engine.md)、2026年10月25日） |
| 対局の途中に、合法手から一様に選んだランダムな手を差し込む | 差し込まない（[ADR](../adr/skip-random-move-injection-in-teacher-games.md)、2026年8月29日） |
| 既存の中将棋エンジンHaChuか、手書きの評価関数v0を相手にした対局を混ぜる | 混ぜない（同じADR） |
| 自分の評価関数の深い探索で教師値を付け直す | 加えない（[ADR](../adr/keep-deep-rescoring-and-human-games-out-of-the-teacher.md)、2026年9月23日） |
| 教師の局面を、静止探索の末端の局面へ置き換える | 置き換えない（[ADR](../adr/do-not-replace-nnue-teacher-positions-with-qsearch-leaves.md)、2026年11月4日） |
| 直前の世代の教師を学習に併用する | 併用しない（[測定](../measurements/nnue-standard-recipe/nnue-standard-recipe-window-stc.md)、2026年11月7日） |
| 評価値で対局を打ち切る | 標準レシピの設計書が対象外とした |
| 記録する局面を間引き、記録しない手を少ないノード数で指す | [設計書](../plans/sparse-teacher-recording.md)が扱う |

## 候補

### AlphaZero型のネットの評価値で教師値を付け直す

この候補では、教師の各局面の教師値を、αβ探索の探索値から、AlphaZero型のネットが返す評価値へ置き換える。
先例の効果は、本書の候補の中で最も大きい。
tanuki-は、深層学習系の将棋エンジン2つの勝率で評価値を付け直し、付け直しの有無だけを変えた比較でR+104.3（乱数から学習）とR+94.6（追加学習）を得た。
Stockfishは、別のエンジンLeela Chess Zeroの大型ネットの価値出力で全教師局面の評価値を付け直しており、自分で教師を生成して次のネットを学ぶ反復をしていない。

この方向は利用者がすでに選んでいる。
2026年10月25日に利用者は、教師生成の見直しを、AlphaZero型の計画の後にそのネットの評価値で教師を付け直す形で起案すると決めた。
[統括計画](../plans/alphazero.md)も、学習したネットをNNUEの教師の付け直しに使う予定と書き、付け直しの手順とその前の診断は付け直しの計画で定めるとしている。
したがって、この候補で未決なのは、行うかどうかではなく、起案の時期と方式である。

起案の前提は2つある。
1つ目は、ネットが教師にできる強さに達することである。
強化学習は自己対局の生成とネットの学習を1サイクルとして繰り返すものであり、1回目の強化学習の32サイクル目のネットは、αβ探索との対局で2勝192敗だった。
2回目の強化学習は[設計書](../plans/alphazero-rl-2.md)の起案の段階にあり、付け直しに使えるネットはまだない。
2つ目は、そのネットが配置の偏りを持たないことを確かめることである。
方法には、人間の対局の局面で麒麟を置き直したときの評価の差を調べる[麒麟の診断](../measurements/nnue-material-linear-init/nnue-material-linear-init-kirin.md)を使う。
規則セットは障害にならないと見込む（推論）。
2回目の強化学習の自己対局と、やり直す世代反復の教師生成は、どちらも規則セット`lishogi`で行うからである（2026年11月13日の利用者の決定）。

費用はまだ見積もっていない。
1世代の教師は約1億局面であり、付け直しはその全局面をネットで評価する。
評価の速さは使うネットと機械で決まるので、見積もりは付け直しに使うネットが決まってから行う。

### AlphaZero型のネットの自己対局の局面を開始局面に加える

この候補では、AlphaZero型のネットが自己対局で通った局面を、NNUEの教師生成の開始局面の一部に使う。
ねらいは、αβ探索とNNUEの自己対局が自分からは進まない配置を教師に入れることである。
先例の効果は、付け直しより小さく、負の記録もある。
AobaZeroは、強豪の棋譜に似た局面を開始局面にして+20 Elo、別系統の棋譜を20〜25%混ぜて約+50 Eloを得た。
一方、tanuki-は開始局面を別の局面集へ替えた生成でR−48.0に後退し、元の局面集と半分ずつ混ぜてもR+3.2 ± 9.6にとどまった。
tanuki-の記録では、開始局面の手数を70手まで深くすると有意に弱くなった。
局面を足す対策は与えた型の近くにしか効かないという報告もあり、チェスで、パズルの局面から自己対局を始めたAlphaZeroが、別の種類の局面を解けた割合は11.76%だった。

この候補には取り下げた草稿がある。
2026年11月3日に、32サイクル目のネットの自己対局に由来する局面から始める設計書を起案したが、そのネットより強いネットが要るので同じ日に取り下げた。
草稿はコミット`7e368921`の`docs/plans/nnue-placement-bias.md`にあり、先例との照合は[自己対局の偏りの先行事例](../research/self-play-bias-prior-art.md)の最後の節にある。
前提は付け直しと同じく、ネットが十分な強さに達することである。

費用は生成器の側では小さい（推論）。
生成器は開始局面の一覧を読む引数`--openings`を持つ。
ただし、一覧の局面の復元は規則セット`JCSA`の移動規則に固定されているので（`crates/minase/src/bin/minase/selfplay_gen/opening.rs`）、`lishogi`の教師生成で使うには改める必要がある。
混ぜる割合と開始局面の手数には先例からの裏付けがなく、測定で決めることになる。

### 序盤の手を、最善手との評価値の差が小さい候補手から抽選する

この候補では、開始局面の後の序盤の一定の手数で、探索が良いと評価した複数の候補手から抽選して指す。
合法手から一様に選ぶ方式と違い、手の質を大きく落とさずに対局の分岐を増やすことがねらいである。
Fairy-Stockfishの生成器はこの方式を既定にしており、24手目までのうち5手を、上位5手のうち最善手との評価値の差が内部の単位で100以内の手から抽選する。
しかし、対局で測った効果は割れている。
tanuki-は対局途中のランダムな手をやめた生成でR+18.9を記録し、ランダムな手を入れた前回の生成のR+12.9を上回った。
dlshogiでも効果は誤差の範囲だった。

この候補を採るには、既存のADRを置き換える判断が要る。
[ランダム着手を注入しないADR](../adr/skip-random-move-injection-in-teacher-games.md)は一様な注入を試験して退けたものであり、範囲を絞った抽選は試していない。
その試験では、注入する側だけ記録を始める手数が遅れたので、記録の範囲が変わった影響と、注入による分布の歪みとを区別できなかった。
このため同じADRは、再検討するなら、対照の側も同じ手数から記録する比較で基準を作り直すことを求めている。
2026年10月25日に利用者は、この候補と後述の食い違う局面の採取を、その時点の教師生成の見直しには入れないと選んだ。

費用は生成器の変更と探索の増加である（推論）。
抽選の手では複数の候補手の評価値が要るので、その手の探索は1手を選ぶだけの探索より重くなる。
麒麟の配置は序盤の数十手で決まると考えられるので、抽選の範囲はチェスの24手より長く取る必要があるかもしれない（推論）。

### 評価値と対局結果が矛盾する局面を、学習から確率的に除く

この候補では、教師の評価値から見込まれる結果と実際の対局結果が食い違う局面を、食い違いの大きさに応じた確率で学習から除く。
Stockfishが2021年11月に導入した方式であり、勝ち（win）、引き分け（draw）、負け（loss）の確率を使うのでWDL選別と呼ばれる。
Stockfishの開発者は、この選別の下では対局結果を教師値へ混ぜないほうが良かったと報告している。
強豪エンジンの教師生成の調査は、選別の有無だけを比べた対局の値を確認していない。

この候補は、既存の教師と対局結果だけで試せる。
生成器を変えず、学習器が局面を読む段階の変更で済むので、本書の候補の中で費用が最も小さい（推論）。
ただし、配置の偏りには効かない可能性が高い（推論）。
自己対局の双方が同じ配置を好むなら、その配置は勝敗を分けにくく、結果との食い違いとして現れないからである。
期待できるのは、勝敗の予測を誤っている教師値の影響を減らすことである。

### 静的評価と探索値が大きく食い違う局面を集めて開始局面にする

この候補では、探索の中で静的評価と探索値の差が大きい局面を書き出し、そこから始めた自己対局で教師を作る。
評価関数が誤っていそうな局面を教師に多く入れることがねらいである。
Stockfishは2021年6月にこの方法で20億局面を生成し、既存の640億局面に加えたネットを採用した。
ただし、この局面集だけの効果は分離されていない。
dlshogiも評価が割れる局面からの生成を行っているが、棋力の数値は公開されていない。

費用は、局面を書き出す機能の追加と、開始局面の読み込みの変更である（推論）。
限界は前の候補と同じであり、静的評価と探索値がそろって同じ配置を好む場合、その配置は食い違いとして現れない（推論）。

### 評価関数が誤る局面へ、教師の探索の予算を重点的に配る

この候補では、全局面を同じノード数で探索する代わりに、学習中の評価関数が手を誤る局面へ、より多くのノード数を割り当てる。
出どころは2026年9月27日の[評価関数を改善する3つの観点](archived/evaluation-improvement-strategy.md)であり、同書はこれを担当する計画のない後続課題として残した。
同書の分析は、NNUEより前の評価関数であるPST（駒と升ごとの点数の表）の時期のものであり、NNUEでは確かめていない。
近い考え方の先例として、探索の価値と対局結果の差が大きい局面を選んで自己対局を再開する囲碁の研究があり、囲碁のエンジンKataGoに対する勝率を、一様に選ぶ再開の69.2%から78.2%へ上げた。

この候補は、利用者の既存の決定と関わる。
[標準レシピの設計書](../plans/nnue-standard-recipe.md)は、教師の探索のノード数の変更を利用者の決定により扱わないとしている。
一部の局面のノード数を増やすこの候補がその決定の範囲に入るかは、起案の前に利用者へ確かめる必要がある。

## 勧める順序

本節は推論である。
どの候補も、標準レシピの世代反復が最終候補の棋力と配置の距離を測り終えるまで起案を待つのがよい。
やり直す世代反復は規則セットと学習の条件が以前と違うので、偏りがどの程度残るかが分かってから、対策の要否と強さを選べるからである。

その後の順序は、先例の効果の確かさと前提で決める。
最初に勧めるのは教師値の付け直しである。
効果の記録が最も大きく、利用者がすでに選んだ方向であり、起案の時期はAlphaZero型のネットの強さで決まる。
次に勧めるのは、同じネットの自己対局の局面を開始局面に加える候補である。
付け直しと同じ前提で試せるが、先例の効果が小さく負の記録もあるので、付け直しの結果を見てから要否を決める。

AlphaZero型のネットを待つ間に試せるのは、結果と矛盾する局面を除く候補と、序盤の抽選である。
前者は費用が最も小さいが、配置の偏りへの効果は見込めない。
後者はADRの置き換えを要し、先例の効果が割れている。
食い違う局面の採取と予算の重点配分は、単独の効果の記録がないか、NNUEで確かめていないので、最後に置く。

## 確認できなかった事項

- 付け直しに使う評価値を、ネットの価値出力そのものにするか、探索を経た値にするかは、先例を比べていない。
- AlphaZero型のネットで1億局面を評価する時間は測っていない。
- 結果と矛盾する局面を除く選別の、有無だけを比べた対局の値は確認していない。

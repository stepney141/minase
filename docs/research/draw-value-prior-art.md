# 引き分けの評価値（contempt）の既存実装と測定の調査

本書は、探索が千日手などの引き分けに返す評価値を0以外に設定する仕組み（一般名はcontempt）について、主要エンジンの実装と、その効果を測った記録を調べた結果である。
[引き分けの評価値の設計書](../plans/archived/draw-value.md)の設計判断の根拠に用いる。
反復の判定そのものと引き分け値の揺らぎは、[探索内の反復の扱いに関する既存実装の調査](search-repetition-prior-art.md)が扱っているので、本書では扱わない。
調査は2026年10月15日に行った。

## 要旨

調べた範囲では、contemptの効果を対局で測った記録はStockfishのコミットメッセージにしかない。
その記録では、contemptは自己対局で中立からわずかに負であり、弱い相手に対してだけ数Eloの向上を示した。
StockfishはNNUEの導入後にcontemptを機能させられず、2021年にUCIオプションを削除した。
やねうら王の既定値−2は、0に切り捨てられない最小の値として、同点の手を区別するために選ばれたものであり、測定に基づく値ではない。
やねうら王と技巧は、根の手番側に+v、相手側に−vを与える対称な符号づけを採る。dlshogiは手を選んだ側の手番で値を決める方式であり、やねうら王の作者はこれを非対称な探索として報告している。

## Stockfish

最初の実装は、2012年10月5日のコミット`c9f9262a`（Add experimental contempt factor）である。
反復と50手規則による引き分けに、0ではなくcontemptの分だけ負の値を返し、コミットメッセージは正の値を弱い相手向けと説明している。
翌日の`cedbd333`で根の手番から見た値に改め、解析中は無効にした。
2014年9月8日の`aa10d0aa`で、オプションの名前をContemptにした。

2014年には、contemptに関する変更が3つ入り、いずれも取り消された。2つは値を動的に変える変更、1つは既定値の変更である。
動的な引き分け値（`b917cd27`）は、弱いエンジン相手でも期待どおりに働かず、むしろ退行したとして`bbd69c02`（2014年3月3日）で取り消された。
優勢のときにcontemptを上げる変更（`ef43e6b0`）は、固定局数の測定が「ELO: -0.86 +-1.7」だったので`5413fda7`で取り消された。
既定値を0から20へ変えた`67a5e1ec`（2014年7月15日）は、LTCの測定が「-2.06 +-1.9」と「-2.69 +-1.9」だったので`7f68fc61`で取り消された。

2017年12月5日の`be382bb0`（PR #1325）で、contemptは引き分け値への加算から評価値への加算へ移り、引き分け値は0に戻った。
その後、既定値を20とし（`254d995e`、2018年1月22日）、根の評価値に応じて変える動的contemptを導入し（`cb132431`、2018年2月9日）、既定値を21（`86e46752`）、24（`2a7213f7`）と改めた。

2021年6月16日の`ed436a36`（PR #3575）は、UCIオプションContemptを削除した。
コミットメッセージは、NNUEで働くcontemptをかなり試したが何も機能しなかったと述べている。
動的な部分は`trend`という名前で残ったが、2022年11月3日の`a4139007`で削除された。
現行のStockfishに引き分け値の非対称性はなく、引き分け値の±1の揺らぎだけが残る（`src/search.cpp`138行）。
後継の考え方はoptimismであり（`a5a89b27`、2021年11月19日）、評価値の側で根の手番に応じた偏りを加える。このコミットは、masterに対するEloの向上として検定を通った（LTCのLLR 2.95）。

### 測定の記録

fishtestでのcontemptの測定は、自己対局の非退行のSPRTと、弱い旧版を相手にした固定局数の対局の組み合わせだった。
後者は、contemptを入れた版と入れない版をそれぞれ同じ弱い相手と対局させ、2つのElo差の差を読む方法である。
コミットメッセージにある数値は次のとおりである。

| コミット | 条件 | 結果 |
|---|---|---|
| `67a5e1ec` | 自己対局、Contempt=20 | ELO: 0.10 +-2.0（40,000局） |
| `67a5e1ec` | SF 3が相手、masterとContempt=20 | +182.86と+189.25、差は6.4 +/- 3.9 |
| `7f68fc61` | 自己対局のLTC、Contempt=20 | -2.06 +-1.9、-2.69 +-1.9 |
| `5413fda7` | 優勢時にcontemptを上げる変更 | -0.86 +-1.7 |
| `86e46752` | SF 7が相手のLTC | +196.08と+203.92 |
| `2a7213f7` | SF 9が相手、contempt 21と24 | 差なし |

`67a5e1ec`は、fishtestの引き分けの裁定がcontemptと干渉するので、弱い相手への向上は過小に見積もられている可能性があると注記している。
fishtestのページそのものは取得しておらず、数値はすべてコミットメッセージの記載による。

## やねうら王

2017年6月3日の`4f2e2cea`でContemptの既定値を1とし、同日の`2fa71808`で2とした。理由は「千日手での引き分けを回避しやすくなるように」である。
2021年2月12日の`aca35b5a`で、Contemptを廃止して`DrawValueBlack`と`DrawValueWhite`に置き換えた。値の意味が「相手を侮る量」から「引き分けの値」に変わったので、既定値の符号が反転して−2になった。
このコミットの動機は、手を選んだ側の手番で値を決めるdlshogiの方式の非対称性を直すことだった。
現行の実装は、探索の開始時に根の手番に応じてどちらかの値を選び、根の手番側に+v、相手側に−vを設定する（`source/engine/yaneuraou-engine/yaneuraou-search.cpp`1003行から1009行）。
値は歩=100の単位で指定し、`Eval::PawnValue`（90、`source/evaluate.h`78行）を掛けて100で割る整数除算で内部値へ換算するので、−2の内部値は−2×90÷100＝−1.8を0の側へ切り捨てた−1である。
コメントは、−1を指定すると換算の切り捨てで0になるので−2にしたと説明する（同174行から178行）。
したがって−2は、0にならない最小の値を同点の手の区別に使う設定であり、棋力を測って決めた値ではない。
コミット、WikiのUSIオプションの説明、およびブログを探したが、測定の記録は見つからなかった。

## dlshogi

オプションは`Draw_Value_Black`と`Draw_Value_White`で、千分率の勝率で指定し、既定値はどちらも500である（`cppshogi/usi.cpp`128行と129行）。
2020年1月19日の`02918cf`で導入された。
値は、その手を選んだ側の手番で適用される（`usi/UctSearch.cpp`1515行から1524行と1598行から1608行）。
やねうら王の作者が報告したissue #36（千日手の処理が非対称）は、調査の時点で未解決である。
作者のブログ（[2022年1月3日](https://tadaoyamaoka.hatenablog.com/entry/2022/01/03/213335)）は、先手の値を500未満、後手の値を500超にして先手番の千日手を避ける使い方を述べ、千日手が80手を超えてから生じる戦型では序盤の探索に値が届かないという課題を挙げている。この記事に測定はない。

## その他の実装

技巧は`DrawScore`を持ち、既定値は0、範囲は−200から200（歩=100）である（`src/usi.cc`309行と310行）。根の手番側に+v、相手側に−vを与える（`src/search.h`113行から116行）。理由と測定の記述は見つからなかった。
Aperyには引き分け値のオプションがなく、千日手は`ScoreDraw`を返す（`src/search.cpp`773行）。
Fairy-Stockfishには、引き分け値のUCIオプションがない（`src/ucioption.cpp`183行から211行）。上流の`ed436a36`をマージで取り込んでいる。変種の定義にある`nFoldValue`は、反復を勝ちや負けにする規則の値であり、好みで調整する値ではない（`src/variant.h`126行と127行）。

Lc0は、2020年2月17日にマージされたPR #1066で0以外の引き分け値を導入し、2023年5月28日にマージされたPR #1791で、対局の勝ち、引き分け、負けの確率を相手とのElo差に応じて変換する方式に置き換えた。
PR #1791の本文は、置き換えの理由として、固定の引き分け値は序盤の選択にほとんど影響しないことなどを挙げている。
公式ブログ（[2023年7月20日](https://lczero.org/blog/2023/07/the-lc0-v0.30.0-wdl-rescale/contempt-implementation/)）は、相手とのElo差を指定して弱い相手や強い相手に合わせて指す用途を説明している。
対局によるEloの測定は、ブログにもPRにも見つからなかった。

## Minaseへの含意

Stockfishの記録が中将棋にも当てはまるなら、0以外の引き分け値は、Minaseが新しい機能の採用に用いる段階ゲート（H1=10 EloのGSPRT、[docs/guides/sprt.md](../guides/sprt.md)）を通らない。自己対局での効果は中立からわずかに負であり、弱い相手に対する向上も数Eloにとどまるからである。
自己対局では、両者が同じ値を使うので、格下の相手との引き分けを避けるという本来の効果は測れない。
符号づけは、やねうら王と技巧の対称な方式を採るのがよい。dlshogiの方式は、やねうら王の作者が非対称な探索として指摘している。
同点の手を区別するための最小の値は、評価値がちょうど同じ手の間でしか選択を変えない。千日手を実際に避けるには、Minaseの評価値の単位（cp）で数十の値が必要であり、その値は強い相手に対して正しい引き分けを捨てる危険と引き換えになる。

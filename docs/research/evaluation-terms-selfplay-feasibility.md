# 評価項目の自己対局による係数学習

[評価項目の調査](evaluation-terms-survey.md)の10項目は、いずれも人間が計算方法を定義し、その係数を自己対局結果から学習する対象にできる。
上位7項目は、[段階9の設計書](../plans/strength-stage9.md)で既に118列の特徴へ具体化されている。
ただし、特徴を学習可能な形へ表すこと、既存データから係数を識別すること、および計算費用を含めて棋力を上げることは別の問題である。
以下は2026年9月22日の調査であり、学習や対局測定の実施報告ではない。
先行例の詳細は[TexelとEtherealの調査](handcrafted-evaluation-selfplay.md)を参照する。

## 学習の定式化

既存の評価を \(E_0(x)\)、追加する特徴を \(\phi_j(x)\) とすると、線形の追加項は次の形にできる。

\[
E_w(x)=E_0(x)+\sum_jw_j\phi_j(x),\qquad
p_w(x)=\sigma(E_w(x)/K).
\]

ここで \(K>0\) は出力の尺度、\(\sigma\) はロジスティック関数である。
序中盤と終盤の2端点を使う場合も、各特徴に局面から決まる補間係数を掛ければ、重みについて線形のまま扱える。
各局面の手番側から見た自己対局結果を、勝ち1、引き分け0.5、負け0の \(z_i\) として、\(p_w(x_i)\) を \(z_i\) へ近づける。
この予測対象は、勝率に引き分け率の半分を加えた得点期待値である。

現行学習器の二値交差エントロピーを維持するなら、損失は次式になる。

\[
L(w)=-\frac1N\sum_i\{z_i\log p_w(x_i)+(1-z_i)\log[1-p_w(x_i)]\}.
\]

これは「手作り特徴の係数を自己対局結果から学ぶ」という方式に該当する。
ただし、Texel原法は学習中の評価関数による静止探索の出力と対局結果の二乗誤差を最小化し、Etherealの公開方式も二乗誤差を用いる。
したがって、現行学習器で結果の割合を100%にする実験と、Texel原法をそのまま再現する実験は区別する。[Texel作者の説明](https://www.talkchess.com/forum/viewtopic.php?start=26&t=50823)、[Etherealの損失](https://github.com/AndyGrant/Ethereal/blob/0e47e9b67f345c75eb965d9fb3e2493b6a11d09a/src/tuner.c#L343-L358)、[現行の学習更新](../../tools/train/pst/train_pst.py)

この定式化では、既存の探索評価がある危険を認識していることは必須ではない。
他の特徴を考慮しても、その危険を表す特徴が実際の敗北と結び付いていれば、対局結果から減点を学ぶ経路がある。
一方、自己対局の双方がその弱点を利用できず、結果にも現れない場合は、そのデータだけから有用な重みが得られるとは限らない。
これは対局結果を学習する目的関数からの考察であり、minaseで棋力が改善するという実測結果ではない。

## 各項目の表現

入力の数え方が非線形でも、数え方と区間の境界が固定されていれば、その区間ごとの重みは線形モデルで学習できる。
例えば、安全な移動先が0個、1〜2個、3個以上の駒をそれぞれ数え、各個数へ掛ける係数を学習すればよい。
以下は[調査書](evaluation-terms-survey.md)の項目を学習へ載せる方法と、[段階9の現在の具体化](../plans/strength-stage9.md)の対応である。

| 項目 | 学習する値の例 | 現行計画との関係 |
|---|---|---|
| 1 王の遮蔽と開いた筋 | 歩の有無、王からの筋距離、敵の走り駒数ごとの加減点を学習する。 | 24列として具体化され、現在のブランチにも実装されている。 |
| 2 王の周囲の攻撃域 | 王からの距離と、攻守の利き数の組ごとの重みを学習する。 | 32列として具体化されている。 |
| 3 王の守備駒と囲い | 隣接升の駒と守備の利きの有無に応じた重みを学習する。 | 特定の囲いを列挙せず、6列として具体化されている。 |
| 4 安全な可動性 | 駒の群と安全な移動先数の区分ごとの重みを学習する。 | 22列として具体化されている。 |
| 5 成りの可能性と侵入 | 安全に成り込める駒の種類や個数に対する重みを学習する。 | 敵陣の外から入る場合に限定して6列とし、保存データにない成り権の保留状態への依存を避けている。 |
| 6 獅子の接近と退路 | 王との距離、味方の支え、退路数に対する重みを学習する。 | 疑似利きによる12列に限定し、捕獲合法性までを表す案とは区別している。 |
| 7 駒への脅威と浮き駒 | 標的の駒の群と敵味方の利きの有無に対する重みを学習する。 | 攻撃側の駒種を省いた16列として具体化されている。 |
| 8 王の退路と安全な王手候補 | 仮想盤面で数えた安全な退路や攻撃拠点の数に対する重みを学習する。 | 追加の計算費用などを理由に段階9では対象外としている。 |
| 9 歩と仲人の閉塞と前進路 | 閉塞、支援、前進を助ける配置への加減点を学習する。 | 優先順位を理由に段階9では対象外としている。 |
| 10 王を基準にした駒の関係表 | 王との相対位置と駒種を添字にした表の値を学習する。 | 線形の表でも実装できるが、特徴数と過学習を別途検討する必要があり、段階9では対象外としている。 |

王将と太子が共存する場合も、王駒の数に応じて特徴を分けること自体は可能である。
現行計画は、データ中の出現頻度を踏まえ、項目1〜3と項目6の接近について、対象側の王駒が2枚なら特徴を0にする。
これは学習不能を意味せず、どの局面をモデルで表すかという選択である。[現行の王駒2枚の扱い](../plans/strength-stage9.md)

## 非線形項の扱い

調査書の「二乗の形は線形の学習に載らず、手調整が必要になる」という説明は、一般論としては強すぎる。
正確には、重みの和を二乗する式を、現在の線形モデルにそのまま入れることはできない。
Texel原法の局所探索は勾配を要さず、Etherealの解説は非線形の王の安全性の項について勾配を導いているため、学習器を拡張すれば係数を学習できる。[Texelの局所探索](https://github.com/peterosterlund2/texel/blob/ed426c529eeab401c19ead47e15221d1cbfc634c/texelutil/src/chesstool.cpp#L210-L267)、[Ethereal作者解説§1.4、§3.5、§3.6](https://github.com/AndyGrant/Ethereal/blob/0e47e9b67f345c75eb965d9fb3e2493b6a11d09a/Tuning.pdf)

現在の段階9は「現行の線形モデルでは表せないので採らない」と範囲を限定しており、これは別の設計判断である。
非線形項を採る必要性と、採った場合に学習できるかどうかを分けて判断する。

## 現在の実装との差

Python学習器の `build_targets` は、混合係数 \(\lambda=0\) なら探索値と教師の尺度を参照せず、対局結果だけを返す。
追加特徴の重みだけを学習し、既存の位置評価表を固定する機構もある。
ただし、Rustの来歴検証は自己対局の \(\lambda\) を0.75に固定しており、自己対局の結果100%という設定を拒否する。
正式な生成と準備の経路で実験するには、混合比の設計と来歴検証を整合させる変更が必要になる。[教師の作成](../../tools/train/pst/train_pst.py)、[来歴の検証](../../src/training/provenance.rs)、[現行の混合比の設計](../plans/strength-stage9.md)

既存の自己対局データには終局結果が保存されているので、結果100%の比較のためだけに全局を生成し直す必要はない。
現行の生成器は、終局した対局について各保存局面へ結果を付け、手数上限で未終局の対局は記録対象から除く。
一方、最善手が捕獲や成りの局面などを除外しており、保存データがあらゆる特徴を同じように含むわけではない。[自己対局生成](../../src/bin/selfplay_gen.rs)

Texel原法の再現では、係数更新に応じて静止探索をやり直す処理も必要になる。
Ethereal式に探索の終端局面を静的評価する場合も、現在の元局面の特徴ファイルをそのまま使うことはできず、終端局面に対して特徴を計算し直す必要がある。
まず教師の混合比だけを比較する実験なら、これらの変更は同時に入れず、現行の静的評価と交差エントロピーを使う実験として明示できる。

## 既存の測定から言えること

現在のデータで、全係数を独立に決められるわけではない。
[118列の診断](../measurements/strength-stage9-activation-diag-b.md)では、手番側の獅子が敵王から距離2以内にいる列が発火せず、獅子の孤立と支えのない獅子への脅威の列は同一である。
常に0の特徴の係数はデータから決まらず、同一の2列があれば、それぞれの係数を独立に決めることはできない。
特徴の除外や統合が必要になる理由はここにあり、学習方式を替えてもこの識別性の問題は残る。

[教師成分ごとの残差診断](../measurements/teacher-quality-residual-diag.md)は、探索値だけ、75:25の混合、および対局結果だけについて、固定した位置評価表との残差相関を測ったものである。
項目1の一部では、探索値側で正だった相関が結果側では負になっているが、絶対値は小さい。
これは結果側の情報を調べる動機にはなるが、係数学習後の棋力向上を示すものではない。
逆に、単独の特徴と残差との相関が小さいことだけから、複数の特徴や局面の進行度を含む学習が無効だとも結論できない。

実戦棋譜を扱う[診断B](../measurements/strength-stage9-human-signal.md)などには、補助的なロジスティックモデルの学習がある。
それとは区別して、自己対局結果100%でエンジンの評価関数を学習し、その重みを組み込んで対局採否を測った記録は、今回確認した資料にはない。
項目1の実際の学習は \(\lambda=0.75\) である。[項目1の学習記録](../measurements/strength-stage9-shelter-training.md)

計算費用も独立した制約である。
段階9は、利き数の表が速度条件を満たさず、項目2〜7を見送っている。
特徴を事前計算して係数を学ぶことはできても、その特徴を対局中に毎回計算する費用は残る。[段階9の状態](../plans/strength-stage9.md)、[速度の測定](../measurements/strength-stage9-table-bench.md)

## 最初の比較候補

実施を検討するなら、既に実装された項目1を対象に、同じデータ、対局単位の分割、特徴、初期値、および出力の尺度を使い、75:25と結果100%で学習する比較が小さく始められる。
目的が混合比の影響の確認なら、損失関数や静止探索の扱いは同時に変えない。
検証では両候補を共通の対局結果に対する損失で比べ、異なる教師に対して計算した学習損失の値を直接比べない。
棋力への採否は、計算費用を含む時間制御の自己対局で、[既存の逐次検定の手順](../guides/sprt.md)に従って判断する。

最初に既存の位置評価表を固定する比較は、追加項が補える情報を調べる実験になる。
その結果だけでは、既存項を含めて同時学習した場合や、他の評価項目を追加した場合まで否定できない。
この比較案は現行計画の混合比を変更する提案であり、本調査では計画や実装を変更せず、実験も開始していない。

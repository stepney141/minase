# 4つの評価関数が駒に与える価値の比較

## 結論

手書き評価v0、単独のPST、PST＋FM、およびNNUEの4つの評価関数について、実戦局面から駒を1枚除いたときの評価値の下がり幅を駒の種類ごとに平均し、各評価関数が駒に与えている価値として比べた。

学習した3つの評価関数は、成っていない駒の相対的な価値がほぼ一致する。
尺度を揃えると、3つの差はおおむね5%以内に収まる。
大きく違うのは、手書き評価v0と学習した3つの間である。
学習した評価関数はv0と比べて、歩兵と仲人を半分以下、獅子を約0.9倍に見ており、竪行を約1.5倍、麒麟と鳳凰を約1.2〜1.3倍、龍馬と龍王を約1.15倍に見ている。

学習した3つの差は、成駒に集中する。
FMを加えると成駒の価値が上がり、NNUEではさらに上がる。
たとえば尺度を揃えた奔猪は、PSTで1,286、PST＋FMで1,487、NNUEで1,869である。
一方NNUEは、成っていない大駒をPST＋FMよりやや低く見る。

探索が捕獲手の順序付け、静的交換評価（SEE）、および枝刈りの余裕値に使う駒価値は、重みファイルに固定した別の値であり、本調査の値とは一致しない。
固定値では歩兵が100だが、学習した評価関数は歩兵を約68センチポーンと見ている。
したがって、歩兵の価値を単位に決めた余裕値やaspiration windowの幅は、評価値の上ではその約1.5倍の広さで効いている。

## 用語

PST（piece-square table、駒位置表）は、駒の種類と成り可否、手番側から見た升の組ごとに値を持つ線形の評価関数である。
序中盤と終盤の2つの値を、盤上の駒数で補間する。
FMは、2つの特徴の組ごとの関係を低ランクの内積で表す補正項であり、PSTの評価値に足される。
NNUEは、探索が現在使う唯一の評価関数であり、PSTと同じ線形の経路と浅い非線形の層を持つ（[解説](../guides/evaluation-nnue.md)）。
手書き評価v0は、HaChuの駒価値表を歩兵100へ換算した駒割に小さなPSTを足した評価関数であり、探索からは呼ばれず比較用に残している（`crates/minase/src/eval/handcrafted.rs`）。
cpはセンチポーンであり、評価値の単位である。
駒状態は、駒種と今後成れるかどうかの組であり、47個ある（`crates/minase/src/eval/features.rs`の`piece_state`）。

## 対象と方法

### 比べた重み

PSTとPST＋FMは、FMの有無だけが違う同じPSTではなく、それぞれ探索に採用されていた時期の重みを使った。

| 列名 | 評価関数 | 重み |
|---|---|---|
| 手書き | 手書き評価v0 | ソースの固定表 |
| PST | FM導入前に採用していた単独PST（候補L） | コミット5b6ec1fの`crates/minase/nets/pst.bin`（MNPT版2） |
| PST＋FM | PSTとFMを同時に学習し、FMを611/1024倍した重み（J75） | 現行の`crates/minase/nets/pst.bin`（コミットf965ba2） |
| NNUE | 現行の探索用評価関数 | 現行の`crates/minase/nets/nnue.bin`（コミット230ea92） |

候補Lは現行の復号器が受け付けないMNPT版2なので、計測用のcrateが本体を読み、`Pst::from_weights`でFMなしの重みとして組み立てた。
J75のPST部分も測ったが、全駒状態で候補Lとの差が5 cp以内だったので、表では候補Lの列だけを示す。
このため、FMの効果は「PST＋FM − PST」で読める。

### 物差し

PST＋FMとNNUEには、評価式から直接読める駒価値がない。
そこで、4つに共通する物差しとして駒除去差分を使った。
局面pの駒xについて、xの持ち主の視点で評価した値をE(p)とし、xを除いた局面p∖xとの差E(p) − E(p∖x)を駒除去差分とする。
除いた後も手番と先獅子の升は変えない。
この差を駒状態ごとに平均し、その駒状態の価値とみなした。
王将、玉将、および太子は、除くと最後の王駒の喪失による終局に当たる場合があり、学習した重みも定まらないので除外した。
評価値が上限28,999に達した組は除外する設定にしたが、該当は0件だった。

### 局面

局面は、NNUEの学習率計画で生成中の教師ファイル`data/nnue-lr-schedule-gen/generated-7100000.bin`から取った。
このファイルは、コミット31c2a46の現行NNUEが1手20,000ノードで指した自己対局7,414局の記録であり、規則セットはL0,P0,R1,E0（RULES.md第33条のengine-default）、SHA-256は`6397daa8f1feabea6eb65deb1b2d98614f20930d2b49ba37958edfe98cb63c07`である。
先頭から10局面ごとに1局面を抜き出して5万局面を使い、除いた駒は合計2,770,005枚になった。

### 尺度

学習した3つは、学習時にcpを勝率のロジットへ換算した尺度Kがいずれも1072.65なので、生のcp値をそのまま比べられる。
手書き評価v0はHaChuの値に由来する別の尺度なので、生のcp値は学習した3つと比べられない。
そこで、初期配置の片側45枚（王駒を除く）の駒除去差分の合計がv0の合計20,178に一致するよう、評価関数ごとに一律の倍率をかけた値も求め、全軍換算値と呼ぶ。
倍率は、PSTが0.661、PST＋FMが0.651、NNUEが0.685である。
歩兵の値を100に揃える正規化は採らなかった。歩兵の値は約68 cpと小さいうえに標準偏差が約40 cpあり、その誤差がすべての駒の値へ拡大されるためである。

## 解釈と限界

### PSTの値は駒がいる升で決まる

線形のPSTでは、駒除去差分は、駒が実際にいる升の重みに、駒数による補間係数の変化分を足した値になる。
探索用の固定駒価値を導いた式（[ADR](../adr/derive-search-piece-values-from-the-learned-pst.md)）は、盤の144升（12×12）を一様に平均するので、駒が偏った升にいるほど除去差分との差が開く。
候補Lについて、序中盤と終盤の端点で別々に求めた一様平均の範囲と、除去差分の平均を比べる。
香車は373〜398 cpに対して644 cp、と金は460〜513 cpに対して831 cp、竪行は848〜893 cpに対して1,161 cpである。
歩兵は逆に105〜155 cpに対して69 cpであり、歩兵が実戦で置かれる升の重みは盤全体の平均より低い。
探索中の評価に実際に効いている駒の価値は、一様平均ではなく除去差分の値の方である。

### 固定駒価値との関係

`pst.bin`と`nnue.bin`が格納する47個の探索用駒価値は、ADRの決定どおり同一であり、龍王1,180、角鷹1,603、獅子2,522などの値を持つ。
これらは[棋力向上段階3](../plans/archived/strength-stage3.md)の時点のPSTから一様平均で導いた値を引き継いだものであり、現在の評価関数が駒除去で示す値とは尺度も比率も違う。
ADRが「結果」の節で予期した、評価関数が学ぶ駒の価値と探索用駒価値の乖離が、本調査の数値で確認できる。
固定値を導き直すかどうかは、ADRのとおり、評価関数とは別の候補として、短時間と長時間の2段階の自己対局測定（[段階ゲート](../guides/sprt.md)）で判定する必要がある。

### 限界

駒除去差分は、駒そのものの価値だけでなく、その駒が局面で果たしている役割と、除いたことで生じる他の駒への影響を含む。
とくにNNUEとPST＋FMでは、除いた駒と他の駒の関係による寄与が差分に入る。
局面は現行NNUEの自己対局から取ったので、平均値はその対局での駒の配置と局面の分布に依存する。
成駒の行は件数が666〜6,976件であり、数万〜数十万件ある成っていない駒の行より平均値の誤差が大きい。
本調査は評価関数の静的な値を比べるだけであり、どの価値付けが棋力につながるかは示さない。

## 再現手順

計測用のcrateは[evaluator-piece-values/](evaluator-piece-values/)にあり、minaseのワークスペースから独立した単独のcrateである。
依存するminaseに埋め込まれた重みを使うので、本調査と同じ重みで再現するには、本調査を行った時点のコミット4d1f3e7のminaseでビルドする。
リポジトリのルートで次を実行する。

```console
git show 5b6ec1f:crates/minase/nets/pst.bin > /tmp/pst-L-v2.bin
CARGO_TARGET_DIR=/tmp/evaluator-piece-values cargo build --release \
  --manifest-path docs/research/evaluator-piece-values/Cargo.toml
/tmp/evaluator-piece-values/release/evaluator-piece-values \
  data/nnue-lr-schedule-gen/generated-7100000.bin /tmp/pst-L-v2.bin 10 50000 \
  > removal.tsv
python3 docs/research/evaluator-piece-values/normalize.py removal.tsv > normalized.tsv
```

計測器の引数`10`は局面の抽出間隔、`50000`は抽出する局面数の上限であり、計測は1スレッドで約30秒かかる。
出力の列のうち`derivL_mg`と`derivL_eg`は候補Lの序中盤（mg）と終盤（eg）の端点での一様平均、`derivJ_mg`と`derivJ_eg`はJ75のPST部分の同じ値、`mean_J`と`med_J`はJ75のPST部分の駒除去差分の平均と中央値である。

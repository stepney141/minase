# 詰中将棋ソルバfmcs（ｆｍ／fmza系）の調査

本書は、[詰み探索（df-pn）の設計書](../plans/mate-search.md)の参考として、神無次郎氏のフェアリー詰将棋ソルバｆｍの系統にある詰中将棋ソルバ`fmcs.exe`を、説明書、作品集、逆コンパイルしたコードの読解、およびwine上での実行で調べた結果をまとめる。
調査日は2026年10月11日である。
配布元は神無七郎氏のサイト（https://k7ro.sakura.ne.jp/fm.html と同 fmz/fmZ.html）で、調べた版は`fmcs.exe` 0.03.003（2025年4月25日、64ビットWindows用）である。汎用の`fmza.exe` 7.08.011は説明書だけを読み、バイナリは読解していない。
説明書と作品集の読解は[付録「説明書と作品集」](fm-fmcs-survey/docs-and-collections.md)に、逆コンパイル結果の読解はClaudeの2本（[探索](fm-fmcs-survey/re-search-claude.md)、[規則](fm-fmcs-survey/re-rules-claude.md)）とcodexの1本（[独立解析](fm-fmcs-survey/re-codex.md)）に、両者の突き合わせは[比較](fm-fmcs-survey/comparison.md)に置く。
逆コンパイルの出力そのものはリポジトリに含めず、再生成の手順と実行環境は[付録「再現手順」](fm-fmcs-survey/reproduction.md)に記す。

## 結論

fmcsは、詰中将棋の「最善詰」（攻め方は最短で詰め、受け方は最長で逃げる）を、手数上限つきのdf-pn（深さ優先の証明数探索）で解く。
攻め方の手を王手に限り、王手を「放置すれば次の手で盤上から王属性駒が消える状態」と定義する点は、minaseの設計書が採った「最後の王駒への脅威」と同じ考え方である。
受け方の王駒が2枚（玉将と太子）の局面では、獅子、成獅子、角鷹、飛鷲が1手で両方を取れる配置だけを王手とし、片方への脅威は王手としない。
受け方の王手放置は探索から除外する（詰将棋の慣習）。
反復は、攻め方の手が探索経路上の同一局面を再現した時点でその手を削除するだけであり、受け方側の判定、置換表との整合（GHI）、駒枯れや引き分けの裁定はない。
したがって、fmcsはminaseの詰み探索の設計を裏づける先例であると同時に、規則の差（王駒2枚、反復、駒枯れ、じっと、付け喰い、成保留駒）を記録したうえで照合相手に使える。

付属の作品集『中将棊指南抄』『中将棊作物』『中将棊絹篩』は、重複を含めて150問（有効問題は30、50、70）であり、作者の検討注記（不詰、早詰）がある。
歴史的作品なので固定局面集の候補になるが、題名で不詰とされる作品の手数は打ち切り手数であって証明ではなく、同じ図でも版により駒種と手数が異なる例があるので、重複排除と版の選別が要る。

## 探索方式（逆コンパイルの読解）

Claudeの2本の解析とcodexの独立解析は、次の点で一致した。

| 項目 | fmcsの実装 |
|---|---|
| 探索 | df-pn系。攻め方のOR節点と受け方のAND節点が相互再帰し、節点に証明数pnと反証数dnを持つ。無限大は`0x3fffffff`、未展開の葉は`(1, 1)`。 |
| 閾値 | OR節点で`thpn(子) = min(thpn, pn2 + 1 + pn1/10)`、`thdn(子) = thdn + dn1 - dn`。AND節点は対称。`pn1/10`の加算は1+εトリックの変形に当たる。 |
| 和の飽和 | 子の和が1,000万を超えると最大の子の値へ切り替える（二重カウントの簡便な抑制）。 |
| 手数上限 | `#n`は固定の上限であり反復深化しない。上限に達して詰みでなければ「手数不足」の反証とする。 |
| 置換表 | 攻め方用と受け方用の2表、各2^21バケットの連結リスト。キーは攻受2本の64ビットZobristハッシュと深さ。値はpn、dn、残り手数、旗。 |
| ハッシュ | 升、陣営、駒種ごとの乱数（MT19937で生成）。成保留駒は別の駒番号、獅子の捕獲時に定数を混ぜる。 |
| 解の後処理 | 最初の詰を得たら、上限を2手ずつ縮めて早詰を探し、検査深度で変化を整理し、採用手順外の攻め方の手で余詰を探す。 |
| 手の順序 | 生成時の4ビットの優先度による整列だけ。killer、history、αβ、評価関数はない。 |
| 協力詰 | 素朴な深さ優先探索と、不詰局面の表（参照回数によるLFU回収）。「攻方不詰局面を再使用」の表示はこの表のもので、最善詰には関係しない。 |

fmzaの説明書も、最善系の解析状況表示で「証明数・反証数、閾値」を表示すると書いており（fmza_help.txt 1376〜1378行）、読解と整合する。

## 規則の実装（RULES.mdとの対照）

| 項目 | fmcs | RULES.md | 差 |
|---|---|---|---|
| 王手 | 受け方の王駒1枚なら利きが届くこと。2枚なら獅子系の駒が1手で両方を取れる配置。`!MGY`（複玉）で1枚への当たり。 | 第8条はどの王駒への脅威も王手。詰みは最後の王駒で定義（第21条）。 | ソルバが攻め方に許す手の定義として、minaseの設計書と同じ。 |
| 王手放置 | 攻め方も受け方も、自分の王駒が次に全滅する手を生成しない。 | 第8条で合法。 | 詰将棋の慣習。結論は同じで、minaseは受け方の王手放置を証明済みの子として扱う。 |
| 受け方が攻め方の王駒を取る | 「逃れ（攻方王詰）」として反証。攻め方の王駒2枚のうち1枚を取られる手は残る。 | 第21条第3項b、第4項。 | 同じ扱い。 |
| 獅子系の2段階移動 | 居喰い、経由升の捕獲、2枚取りを生成する。じっとは生成しない。 | 第12条第9項でじっとは合法。 | じっとがない。 |
| 足と先獅子 | 足は現局面の利きを走査し、裏足と王駒を含む。先獅子は足条件つきだが獅子による捕獲には適用しない（L0＋L4相当）。L2はない。 | 第13条から第15条、第29条。 | 標準規則L0ではなくL0＋L4。 |
| 付け喰い | 1歩目が歩兵または仲人なら、足の有無を見ずに2歩目の獅子捕獲を除外する。 | 第14条第3項は足のない獅子の捕獲を認め、第16条第3項は歩兵・仲人による付け喰いを認めない。 | 足のない獅子を歩兵経由で取る手を除く点でRULES.mdより狭い。 |
| 成り | 移動元または移動先が敵陣なら成れる。不成の駒は成保留駒になり、捕獲を伴う場合と敵陣外へ出た後の再入で成れる。歩兵・香車の最奥段での非捕獲の成りは生成側は試みるが、適用側が予約駒番号を歩兵・香車の番号と比較するため拒否される（実機で確認）。 | 第17条から第19条（P0）、P3。 | P0に近いが最奥段の救済は働かない。初形で敵陣内にある未成駒も成保留駒になる。 |
| 反復 | 攻め方の手が経路上の同手番局面を再現した時点（2回目）で削除。受け方側の判定なし。 | 第31条R1、R2、R3。 | R2の攻め方側だけに近い。 |
| 合法手なし | 王手を受けて手がなければ詰、王手でなければ逃れ。 | 第23条は王手の有無を問わず負け。 | 王手でない合法手なしを勝ちにしない。 |
| 駒枯れ、引き分け | 裁定なし。 | 第22条。 | 「設計判断」節の駒枯れの局面をfmcsは1手詰とする（実機で確認）。 |
| 岩と穽 | 岩は着手不可で走りを止め、穽は着手不可で走りを通す。跳びは岩を越える。 | 規則にない。 | 詰中将棋の作品形式に固有。 |

読解で見つかった実装上の不整合は、攻め方の王詰検査が足の判定に隣の欄を読むこと、飛鷲の2枚取り判定が筋2〜9に限られること、歩み・走り駒の生成が先獅子で保護された獅子に当たると打ち切ることの3点であり、詳細は[比較](fm-fmcs-survey/comparison.md)にある。
Claudeとcodexの読解が食い違った3点（付け喰いの除外範囲、成保留駒の最奥段成り、`/ESSZS`の足の検査側）は、逆コンパイル結果の該当行と実機の実行で確かめ、いずれもcodexの読みが正確だった。codexだけが挙げた和の飽和は該当行で確認し、Claudeだけが挙げた歩み・走り駒の生成の打ち切りは機械語で分岐の存在を確認したが、飛び先が生成の終了か次の方向かは未確認である。

## wine上の実行と確認した挙動

fmcsはコンソールアプリであり、wineでは疑似端末（`script`）の下で起動する。
問題ファイルで規則名（最善詰）の行と盤面の行が分かれていると、駒ごとの処理関数の表が未設定のまま盤面走査に入り、アドレス0を呼び出して落ちる。
規則名と盤面を同じ行に書けば元のバイナリでも動き、これを推奨する。規則名だけの行でも初期化するように2箇所の条件分岐を書き換えたパッチ版でも動く（書き換えたバイトは[再現手順](fm-fmcs-survey/reproduction.md)）。
付属の作品集はいずれも行が分かれているので、そのままでは動かない（Windows実機での挙動は未確認）。
制限時間の書式は説明書の`/LT<n>M`ではなく`/LT=<n>M`である。

| 実行 | 結果 |
|---|---|
| 『中将棊指南抄』1番（#21） | 7秒、展開局面数857,452で21手詰を検出。作品集の手数と一致。 |
| 『中将棊絹篩』34番（#27） | 3分の制限で展開局面数10,199,218、解なし（作者注記のとおり駒種に疑問のある図）。 |
| 成保留の歩兵が最奥段へ非捕獲で成る1手詰 | 成る手が生成されず解なし（成保留駒の最奥段救済は働かない）。 |
| `/ESSZS`で攻め方の獅子だけに足がある図 | 「受方先獅子指定エラー」。攻め方手番の開始図では受け方（直前に着手した側）の獅子に足を要求する。 |
| `/ESSZS`で受け方の獅子に足がある図 | 「開始図では受方先獅子とします」として受理。 |
| 攻め方の太子と王将、受け方の玉将だけの図（設計書の駒枯れの局面） | 王将で王手する1手詰と判定。受け方が王将を取る応手は王手放置として除かれ、駒枯れの引き分けは考慮されない。 |
| 受け方の玉将と太子、攻め方の奔王が玉将に当たる図 | 王手なしとして即座に不詰。 |

試した問題は[tests/](fm-fmcs-survey/tests/)にある。
付属の作品集150問を1問5分で解かせた測定は[fmcsによる付属作品集150問の解答測定](../measurements/fmcs-tsume-collection.md)にある。

## 設計への含意

1. 王手の定義と王手放置の扱いは、minaseの設計書と同じ結論に至っている。受け方の王駒2枚の扱い（獅子系の2枚取りだけを王手とする）は、設計書が後続の候補とした拡張の先例になる。
2. 閾値の`pn2 + 1 + pn1/10`と、和が1,000万を超えたときの最大値への切り替えは、1+εトリックと二重カウント対策の簡便法として、設計書が後回しにした項目の参考になる。
3. 置換表のキーに深さを含める手数上限つきの方式は、minaseの局面キーだけの方式とは別物であり、経路依存の結果を置換表に書かない規律はfmcsにはない。
4. fmcsは「詰みの有無と最短手数」を返すので、minaseの固定局面集の照合相手に使える。照合では、じっと、付け喰いの除外、成保留駒、反復、駒枯れの差を既知の差として除く。wineで動かすには、規則名と盤面を同じ行に書くか、パッチ版を使う。
5. 作品集の150問は固定局面集の候補である。不詰と注記された作品と、版で駒種が異なる作品を除いたうえで、座標（筋1〜9とa〜c、段1〜9とA〜C、1筋が攻め方の右端、1段が受け方の最奥段）をSFENへ変換する。

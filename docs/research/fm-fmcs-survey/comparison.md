# fmcs.exe 解析の突き合わせ（Claude subagent 2本 vs codex）

本書は、fmcs.exe の逆コンパイル結果を読んだ3本の報告（[re-search-claude.md](re-search-claude.md)（Claude、探索）、[re-rules-claude.md](re-rules-claude.md)（Claude、規則）、[re-codex.md](re-codex.md)（codex、両方））の結論を突き合わせた記録である。食い違いは逆コンパイル出力 fmcs.c（[reproduction.md](reproduction.md) の手順で再生成できる）と objdump で確認し、一部は実機で確かめた（本文 [fm-fmcs-survey.md](../fm-fmcs-survey.md) の実行の表）。

## 一致した点

| 項目 | 結論 |
|---|---|
| 探索方式 | df-pn 系。攻方 OR（FUN_1400036d0）と受方 AND（FUN_1400072e0）の相互再帰。節点に pn(+0x18)/dn(+0x1c)、INF=0x3fffffff。葉は (1,1)。 |
| 閾値 | OR: thpn(child)=min(thpn, pn2+1+pn1/10)、thdn(child)=thdn+dn1−dn。AND は対称。1+ε に相当する加算 pn1/10。 |
| 手数上限 | #n は固定の上限。反復深化しない。上限到達で詰みでなければ「手数不足」の反証。 |
| 置換表 | 攻方用・受方用の2表、各 2^21 バケットの連結リスト。キーは攻受2本の64ビット Zobrist ハッシュと深さ。値は pn/dn/残手数/旗。 |
| ハッシュ | Zobrist（升×陣営×駒種、MT19937 で生成）。成保留駒は別番号、獅子捕獲時に定数を XOR（先獅子状態）。 |
| 協力詰 | 素朴な DFS と不詰局面表（2^23 バケット、28B レコード、参照回数 LFU 回収）。「攻方不詰局面を再使用」はこの表の回収通知であり最善詰とは無関係。 |
| 解の後処理 | 最初の詰 → 早詰検索（上限 n−2 で再探索を反復）→ 検査深度 n−2 で変化を整理 → 余詰検索（採用手順外の攻方手）。 |
| 手の順序 | 生成時の4ビット優先度による整列のみ。killer、history、αβ、評価関数なし。GHI 対策なし。 |
| 王手の定義 | 受方王駒1枚: 当たりがあること。2枚: 獅子・成獅子・角鷹・飛鷲が1手で両方を取れる配置だけ。!MGY で1枚への当たり。 |
| 王手放置 | 攻方・受方とも、自分の王駒が次に全滅する手は生成しない（RULES 第8条より狭い）。 |
| 逃れ（攻方王詰） | 受方の応手で攻方王に当たりがつき、攻方に解消手がない状態を反証として使う。 |
| 獅子系 | 居喰い・経由升捕獲・2枚取りを生成。じっとは生成しない。 |
| 足 | 現局面の利きを走査して陣営別の旗（+0xb5）に集約。裏足を考慮。王駒も足になる。 |
| 先獅子 | 足条件つき（L0）だが獅子による捕獲には適用しない → L0＋L4 相当。L2 なし。 |
| 反復 | 攻方の手が経路上の同手番局面を再現した時点（2回目）で削除。受方側の検査なし。 |
| 終局 | 受方に手がなく王手なら詰、王手でなければ逃れ。駒枯れ・引き分けの裁定なし。 |
| 盤 | 144バイト、升=12×(筋−1)+(段−1)、0x80/0x40 陣営ビット、岩 0x3e、穽 0x3f。走りは岩で止まり穽を透過、跳びは岩を越える。 |
| 推定バグ | 攻方王詰検査 FUN_14000d6d0 が足判定に +0xb6 を使う（+0xb5 の誤り）。飛鷲の2枚取り判定が筋2〜9に限定。 |

## 食い違いと確認結果

| 項目 | Claude | codex | fmcs.c での確認 |
|---|---|---|---|
| 付け喰い（1歩目が歩兵・仲人） | 「歩兵/仲人経由のみ禁止、足・先獅子無視。第14・16条と一致」 | 「足の有無を調べずに除外。足のない獅子への2枚取りも除くので第16条より広い」 | 1484〜1488行: 1歩目の駒の属性 0x400000 と2歩目の駒の属性 0x800000 だけで除外し、足を見ない。RULES 第14条第3項は足のない獅子の捕獲を認めるので、codex の読みが正確。Claude の「一致」は第16条第3項だけを見た評価。 |
| 成保留駒の最奥段成り（P3） | 「成保留駒は捕獲か歩兵・香車の最奥段到達で再成り → P0＋P3」 | 「生成側は元の駒番号で判定するが、適用側 FUN_14000ddd0 は予約番号を 1 または 3 と比較するので、成保留駒の非捕獲成りは拒否される（asm 0x14000de4e で確認）」 | 9297〜9302行: `bVar2 = *param_2`（現在の駒番号）で `bVar2 != 1 && bVar2 != 3` を判定。成保留駒の番号は 0x16〜0x1d なので、非捕獲（param_2[4]==0xff）の成りは最奥段でも `return 0`。codex が正しい。実機で確認する（テスト t1）。 |
| 和の飽和 | 言及なし | 「和が1,000万を超えると最大の子の値へ切り替える」 | FUN_140004da0/e00（2651〜2716行）: 和が 0x989681 未満なら和を返し、以上なら最大値側へ。codex が正しい。 |
| /ESSZS の足の検査 | 「事前検査は手番側獅子の足を要求し、効力判定は相手側獅子の足を見る」 | 「奇数手 #n で攻方手番なら受方の足旗 0x05 を検査し『受方先獅子』と表示。保護される直前着手側の足を要求する」 | 6947〜6967行: 分岐は規則旗 DAT_140047c28 と手数の偶奇 DAT_140047c34 で決まり、片方は旗 0x0a（攻方）、他方は旗 0x05（受方）を検査する。どちらの分岐が標準の最善詰で選ばれるかは静的には確定しない。実機で確認する（テスト t2、t2b）。 |
| 歩み・走り駒の生成の打ち切り | 「先獅子で禁止の獅子に出会うと残りの移動先を打ち切る（asm 0x1400027d9）」 | 言及なし | 0x1400027c5〜0x1400027d9: 升の駒が 0x53（受方獅子）か 0x70（受方成獅子）なら FUN_140017500（先獅子保護）を呼び、非0なら 0x14000280a へ跳ぶ。跳び先が「次の方向へ」か「生成終了」かは未確認。影響は限定的（直前に獅子を取られた側の獅子に走りが当たる方向だけ）。 |

## 設計への含意（minase の設計書との対照）

- fmcs も「最後の王駒を次に取れる状態」を王手とし、受方王駒2枚では1手で両方を取れる手だけを王手とする。minase 初版の「受方王駒1枚だけ対象」は、fmcs が実装している2枚の扱い（獅子系の2枚取りだけ）を後続候補として参照できる。
- fmcs は王手放置を双方で不合法として扱う（詰将棋の慣習）。minase は RULES 第8条に従い受方の王手放置を「証明済みの子」として扱うので、結論は同じで表現が異なる。攻方の王手が自分の王駒を取られる場合、fmcs は「逃れ（攻方王詰）」で反証、minase は「受方が攻方の最後の王駒を取る手」で反証。攻方王駒2枚のときの駒枯れ引き分けは fmcs にはない。
- fmcs の置換表はキーに深さを含み、手数上限つきの探索なので、minase の局面キーだけの表とは別物。経路依存の扱いは「攻方の再現手を削除する」だけで、置換表との整合（GHI）には手当てがない。minase の設計書が採った「経路依存の確定値を置換表に書かない」規律は fmcs にはない。
- 閾値の `pn2 + 1 + pn1/10` は 1+ε トリックの変形であり、minase 初版で後回しにした項目の先例になる。和の 1,000万での最大値への切り替えは二重カウント対策の簡便法として参考になる。
- じっとを生成しない点、付け喰いの除外が広い点、成保留駒の非捕獲成りが拒否される点は、fmcs を minase の照合相手にするときの既知の差として記録する。

# fmcs.exe 0.03.003 探索アルゴリズムの復元（Ghidra 逆コンパイル解析）

本書は、詰中将棋ソルバ fmcs.exe 0.03.003 を Ghidra で逆コンパイルした C 出力（fmcs.c、[reproduction.md](reproduction.md)）、文字列表、および仕様書 fmcs_help.txt を読んで、探索アルゴリズムを復元した読解の記録である（Claude による解析。codex による独立解析 [re-codex.md](re-codex.md) との突き合わせは [comparison.md](comparison.md)）。「報告書」「設問」は、この読解を依頼した指示書の項目番号を指す。

対象は `ghidra/out/fmcs.c`（861関数、行番号は本ファイルのもの）、文字列は `ghidra/out/strings_va.txt`、仕様は `fmcs/fmcs_help.txt.utf8` である。
利用者コードは `0x140001000` から `0x14001acd0`（fmcs.c の 1 行目から 18979 行目）にあり、以降は MSVC の CRT である。
本文で「確認」と書いた事項は逆コンパイル結果の読解に基づき、「推定」と書いた事項は構造や名称からの推測である。

## 1. 結論の要約

最善詰（`#n`）は **df-pn（depth-first proof-number search）** であり、攻め方の OR 節点 `FUN_1400036d0` と受け方の AND 節点 `FUN_1400072e0` が相互再帰する。
証明数 pn と反証数 dn（無限大は `0x3fffffff`）、深さ別のしきい値配列（文字列「証明数配列領域」「反証数配列領域」で割り当て）、1+ε 型のしきい値緩和、同一局面を 128 ビット Zobrist ハッシュで共有する節点表を備える。
手数上限 `#n` は固定の深さ上限として扱われ、反復深化はしない。解が見つかった後に、上限を `n-2` に下げた再探索（早詰検索）、変化手順に対する `n-2` 上限の再探索（検査深度による変化・早詰の除去）、最善手順以外の攻め方の手に対する再探索（余詰検索）を順に行う。

「攻方不詰局面（参照回数 %d以下）を再使用します」は最善系ではなく **協力詰系（`H#`、`H=`）専用** の処理である。協力系は df-pn を使わず、素朴な深さ優先全探索（`FUN_140003fe0` と `FUN_140007c50`）に「不詰（逃れ）と判定済みの局面」の置換表を組み合わせており、表が満杯になると参照回数の少ないエントリを回収して再使用する。

## 2. 共通の基盤

### 2.1 規則フラグ

規則名表は `.rdata` の `0x140045310`（1 エントリ 0x18 バイト）にあり、`FUN_14000b4b0`（7249 行）が読む。PE ファイルから直接読んだ値は次のとおりである。

| 文字列 | `DAT_140047c28`（規則） | `DAT_140047c24`（補助条件） |
| --- | --- | --- |
| 最善, # | `0x80000000` | |
| 協力, H# | `0x20000000` | |
| 協力ステイルメイト, H= | `0x10000000` | |
| 複玉, !MGY | | `0x80000000` |
| 非王手可, チェス式, !NMO | | `0x800000` |

`FUN_14000e820`（9740 行）が `(DAT_140047c28 & 0xc0000000) != 0` なら最善系の `FUN_140005300` を、そうでなければ協力系の `FUN_14000d170` を呼ぶ。
手番の割り当ては `FUN_140005460`（3120 行）が「規則ビットと `depth + n` の偶奇」で決め、通常の `#n`（n が奇数）では根が OR 節点（攻め方）になる。

### 2.2 局面構造体（0xcc = 204 バイト）

`FUN_140017010`（16102 行、文字列「局面構造体領域」`0x1400380a0`）が 10,000 個単位で確保する。主なオフセットは次のとおりである（`FUN_14000dee0`（9318 行）、`FUN_14000d3e0`（8826 行）、`FUN_140001000`（1 行）から確認）。

| --- | --- |
| +0x08, +0x10 | 128 ビットの局面ハッシュ（2 本の 64 ビット鍵） |
| +0x18 .. +0xa7 | 144 升の盤面。1 升 1 バイトで、`0x80` が攻め方駒、`0x40` が受け方駒、下位 6 ビットが駒種コード |
| +0xa8 .. +0xaf | 直前の着手（駒種、移動元、移動先、2 段目の移動先など）。+0xaf の `0x40` と `0x80` は協力系の解手順マーク |
| +0xb0 | 深さ（手数） |

### 2.3 Zobrist ハッシュ

`FUN_14000cff0`（8626 行、文字列「ハッシュ盤面領域」`0x140037310`）が `calloc(0x4801, 8)` で乱数表を確保し、144 升 × 2 表 × 64 駒コードの 64 ビット乱数（`FUN_14000ce40` の 32 ビット乱数を 2 つ連結）で埋める。
さらに 2 つの 64 ビット定数 `DAT_1400bb1c8` と `DAT_1400bb1c0` を用意し、`FUN_14000d3e0` は取った駒のコードが `0x13` または `0x30` のときにこの定数を鍵に XOR する。駒名表（`0x14003773c` 以降）では獅子が 19 番目の生駒、獅子(成麒)が 16 番目の成駒であり、生駒を 1 から、成駒を `0x20` から数えると `0x13` と `0x30` に一致するので、この 2 つは獅子と成獅子の捕獲を表すと推定する。先獅子状態を局面鍵へ織り込むための処理と推定する。
鍵の更新は `FUN_14000d3e0` が差分で行い、第 1 鍵（+0x08）は移動元と移動先の升と駒、第 2 鍵（+0x10）は取った駒の表で更新する。
表の添字は、どの表でも `(lo32(鍵1) ^ lo32(鍵2)) & マスク` で求め、照合は 128 ビット全体で行う。

### 2.4 手生成と手順

駒種ごとの関数ポインタ表 `DAT_1400bafc0`（64 エントリ、`FUN_14000fb80`（10705 行）が構築）に、攻め方の手生成（+0x28, +0x30）、受け方の手生成（+0x38, +0x40）、合法手の有無判定（+0x58, +0x60）の関数が入る。

- 「実効駒情報配列領域」（`0x1400378f8`）: `FUN_14000fb80` が `calloc(駒種数, 0x74)` で確保する駒種情報の実体。
- 「跳び移動先配列領域」（`0x140037910`）と「走り移動先ベクトル配列領域」（`0x140037928`）: 同関数が `calloc(駒種数 × 4, 0x488)` で確保する、駒種別の跳び移動先と走り方向の事前計算表（推定：升ごとの到達升リスト）。
- `FUN_1400035a0`（1510 行）は攻め方の全駒について生成関数を呼び、`FUN_140003630`（1538 行）が王手になる手だけを残す。`!NMO`（`DAT_140047c24 & 0x800000`）のときは `DAT_140047d37 = 1` にして王手でない手も通す。
- `FUN_1400071f0`（4302 行）は受け方の手生成で、`FUN_140007280`（4330 行）が王手解消の手だけを残す。
- `FUN_1400196e0`（18006 行）は「合法手が 1 つもない」判定であり、OR 節点では受け方王に王手がかかっている局面にこれを適用して詰とする。`FUN_1400197a0`（18040 行）は同じ判定のステイルメイト用である。
- `FUN_140009f80`（6406 行）は子節点を着手の `+0x3d & 0xf`（局面の +0xaf 下位 4 ビット、推定：手生成側で付ける優先度）で昇順に挿入ソートする。これが唯一の手順付け（move ordering）であり、killer や履歴表は見当たらない。
- `FUN_140004e60`（2718 行）は経路配列 `DAT_140047c78`（深さ別の局面ポインタ、「局面構造体ポインタ配列領域」`0x140036ea8`）を 2 手おきに遡り、同じ 128 ビット鍵があれば千日手とする。
- 「詰手順情報構造体配列領域」（`0x140037e18`）と「詰手順ノード構造体領域」（`0x140037e38`）: `FUN_140016030`（15288 行）が出力用に作る構造で、0x2c バイトのエントリ配列（初期 0x1000、満杯で倍増、`0x7fff` 超で「枝分れの多過ぎた分を無視」）と、各エントリに付く手順ノード配列および局面である。探索木から変化・余詰・非限定の表示用に写し取るための領域と推定する。
- 「手順中局面構造体配列領域」（`0x140037328`）: `FUN_14000ce70`（8538 行）が 10,000 個単位で確保する 0x1c バイトのエントリで、`FUN_14001a280`（18535 行）が `DAT_1420bbb60`（2^20 バケット）に登録する。協力系で現在の手順上の局面を記録し、`FUN_140019da0`（18334 行）が同一局面の再訪（千日手）を検出する。

## 3. 最善詰の探索（df-pn）

### 3.1 節点構造体（0x40 = 64 バイト）

`FUN_140016b70`（15930 行、「ノード構造体領域」`0x1400380e0`）が 100,000 個単位で確保する。

| オフセット | 内容 |
| --- | --- |
| +0x00 | 先頭の子節点 |
| +0x08 | 次の兄弟節点 |
| +0x10 | 展開中は局面ポインタ、節点表に登録後はハッシュ鎖のリンク |
| +0x18 | 証明数 pn（`FUN_140004690` のトレース出力 `(%s,%s)` の 1 番目） |
| +0x1c | 反証数 dn（同 2 番目） |
| +0x20, +0x28 | 局面の 128 ビット鍵（局面 +0x08, +0x10 の写し） |
| +0x30 | 深さ |
| +0x32 | 終端までの手数（詰なら詰までの手数、`0xffff` は未定） |
| +0x34 | フラグ。`0x8000` 詰（証明）、`0x4000` 逃れ（反証）、`0x800` 自身で確定、`0x200` 指定手順外、`0x8`/`0x4` OR 表/AND 表に登録済み、`0x80` 解放済み、`0x2` 最善手順上（`FUN_1400064a0` での使われ方からの推定で、設定箇所は未特定） |
| +0x36 .. +0x3d | 着手（局面 +0xa8 .. +0xaf の写し）。+0x3d 下位 4 ビットが手順付けの鍵 |

トレース 1 行の書式 `"% 3d: %-15s (%s,%s) [%s,%s] %d+%d=%d %04x %d"`（`FUN_140004690`、2329 行）は、深さ、着手、`(pn, dn)`、`[しきい値 pn, しきい値 dn]`、`深さ+残手数=合計`、フラグ、手順鍵である。

### 3.2 OR 節点 `FUN_1400036d0`（1577 行、攻め方）

1. `DAT_140047d10` を増やし、周期的に `FUN_140009010`（5692 行）で時間制限、キー入力、進行表示を処理する。到達深度 `DAT_140047d30` を更新する。トレース有効なら「深化 C」（`0x1400365cc`、1623 行）を出す。
2. 子がなければ `FUN_1400035a0` で王手を生成する。各子について `FUN_14000d3e0` で鍵を更新し、`FUN_140004e60(pos, 1)` が真なら「千日手 C」（`0x1400365d8`、1647 行）として子を削除する（攻め方の千日手は不成立の攻めとして捨てる）。
3. 各子を評価する（1668 行から）。
   - 指定手順（`/EMOVES`、`DAT_140047c5c`）に合わなければ「指定手順外 C1」（`0x1400365e8`）とし pn=dn=0、フラグ `0xa00` で除外する。
   - `FUN_140004f50` で AND 節点表を照合し、既知なら pn、dn、残手数、フラグを写す。
   - 未知（pn=dn=1）の子で、受け方王に王手（局面 +0xb6 の符号ビット）かつ `FUN_1400196e0` が合法手なしを返せば「詰 C」（`0x1400365f8`、1674 行）：pn=0、dn=INF、フラグ `0x8800`。
   - 子の深さが上限 `DAT_140047c34`（`#n`）以上なら「疑似逃れ（手数不足）C」（`0x140036600`、1684 行）：pn=INF、dn=0、フラグ `0x4800`。上限未満なら pn=dn=1 の葉として残す。
   - 終端になった子は `FUN_1400050e0` で AND 節点表へ登録する。
4. `FUN_140009f80` で子を手順鍵順に並べる。子が 1 つもなければ「逃れ（王手なし）C」（`0x140036630`、1712 行）：pn=INF、dn=0。
5. 全子が指定手順外なら「指定手順外 C2」（`0x140036618`）で節点全体を除外する。
6. `FUN_140003f20`（1862 行）で自身を OR 節点表に登録し、次の反復に入る（1749 行から）。
   - pn = 子の pn の最小（`FUN_140004d50`、2607 行）、dn = 子の dn の総和（`FUN_140004da0`、2636 行。INF を含めば INF、総和が 10,000,000 以上なら最大値で代用）。
   - pn と dn がともに 0 の状態が同じ節点で 100 回続くと `FUN_1400180f0(4)` で「INF_LOOP」として異常終了する。
   - `しきい値pn[depth] <= pn` または `しきい値dn[depth] <= dn` なら離脱する（「離脱 C4」`0x140036658`）。このとき証明済みなら残手数 = 証明済みの子の残手数の最小 + 1（`FUN_140004cc0`）、反証済みなら反証済みの子の残手数の最大 + 1（`FUN_140004be0`）を +0x32 に書く。
   - `FUN_140005250`（3006 行）が pn 最小の子（同点なら dn が大きい方）を選び、2 番目に小さい pn を返す。子がなければ「離脱 C5」。
   - 子のしきい値を次のように設定する（1769 行から）。
     `しきい値pn[child] = min(しきい値pn[depth], pn2 + 1 + pn_best / 10)`、
     `しきい値dn[child] = しきい値dn[depth] + dn_child - dn`。
     `pn2 + 1 + pn_best/10` は 1+ε 法（ε = 0.1 相当）の変形と推定する。
   - `FUN_14000dee0` で子の局面を作り、`FUN_1400072e0`（AND 節点）を再帰呼び出しする。戻ると「復帰 C」（`0x140036668`）。子が指定手順外（フラグ `0x200`）になった場合は未処理子数を減らして次の子へ進み、全子が指定手順外になれば「指定手順外 C3」（`0x140036670`）で節点を除外する。
7. トレース深度 `DAT_140047c58`（`/T`、`FUN_14000f530`（10356 行）で設定、既定 2）が 0 でなければ、その深さまではしきい値を使わず全子を順に展開する（「離脱 C3」、1832 行から）。深さがトレース深度に達した節点は反証扱いにする。
8. 最後に `FUN_140004fe0`（2810 行）で自身の結果を OR 節点表へ書き戻す（「離脱 C1/C2/C6」はいずれもここへ合流する）。

関数は値を返さず、結果は節点の pn、dn、+0x32、+0x34 に残る。pn=0 かつ dn=INF が「詰」、pn=INF かつ dn=0 が「逃れ」、pn=dn=0 が「除外（指定手順外）」、それ以外は未確定である。

### 3.3 AND 節点 `FUN_1400072e0`（4351 行、受け方）

構造は OR 節点と対称である。相違点は次のとおりである。

- 入口で深さが上限以上なら、王手かつ合法手なしで「詰* E」（`0x140036af4`、4403 行、pn=0、dn=INF）、そうでなければ反証（pn=INF、トレース文字列なし）として「離脱 E1」で戻る。
- `FUN_1400071f0` で受け方の手を生成する。子が 1 つもなく詰でもなければ「逃れ（受手なし）E」（`0x140036b10`、4493 行、pn=INF）。王手を受けていながら合法手がない局面は OR 側で既に「詰 C」と判定されるので、ここに来るのはステイルメイト相当の局面である。
- 各子（攻め方手番）の照合は `FUN_140004ec0`（OR 節点表）で行う。未知の子で攻め方王に王手（+0xb6 の `0x40`）かつ `FUN_14000db80` が真なら「逃れ（攻方王詰）E」（`0x140036b40`、4455 行）：受け方が攻め方の王を詰めたので、節点全体を反証（pn=INF）し全子を解放する。
- 反復では pn = 子の pn の総和（`FUN_140004e00`）、dn = 子の dn の最小（`FUN_140004d00`）。子の選択は `FUN_1400051e0`（dn 最小、同点なら pn が大きい方）。しきい値は
  `しきい値pn[child] = しきい値pn[depth] + pn_child - pn`、
  `しきい値dn[child] = min(しきい値dn[depth], dn2 + 1 + dn_best / 10)`。
- 証明時の残手数は証明済みの子の最大 + 1（`FUN_140004c30`）、反証時は反証済みの子の最小 + 1（`FUN_140004c80`）。
- 最後に `FUN_1400050e0` で AND 節点表へ書き戻す。「離脱 E2 .. E8」「復帰 E」「指定手順外 E1 .. E3」「深化 E」は OR 側の対応物である。

### 3.4 節点表（置換表）

最善系の置換表は、探索木の節点そのものを鎖でつなぐ 2 つのハッシュ表である（節点表と呼ぶ）。

| 表 | バケット配列 | 登録 | 照合 | 対象 |
| --- | --- | --- | --- | --- |
| OR 節点表 | `DAT_1410bbb40`、2^21 バケット × 8 バイト（16 MB、静的 `.data`） | `FUN_140003f20`（展開開始時）、`FUN_140004fe0`（終了時） | `FUN_140004ec0` | 攻め方手番の局面 |
| AND 節点表 | `DAT_1400bbb00`、同上 | `FUN_140007b90`、`FUN_1400050e0` | `FUN_140004f50` | 受け方手番の局面 |

- 鍵は 128 ビット鍵 **と深さ** の一致である（`FUN_140004ec0` 2746 行の比較）。深さを含めるので、同一局面でも残り手数が違えば別エントリになり、深さ上限つき探索の正しさを保つ。
- 格納値は pn、dn、残手数（+0x32）、フラグである。照合でヒットすると子節点にこれらを写し、子を展開せずに済ませる。
- 書き戻し `FUN_140004fe0` は、既存エントリが詰なら残手数が短いもの、逃れなら残手数が長いものだけに置き換える（2810 行から）。すなわち同一局面の最良の結果を保持する。
- 解決済みの部分木は `FUN_140016a20`（15852 行）で解放されるが、表に登録済みで終端確定した節点は解放せずに `DAT_140047ca0`（保持リスト）へ移す。表だけがそれを参照し、再訪時に結果を提供する。

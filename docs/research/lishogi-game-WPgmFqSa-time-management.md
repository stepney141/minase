# lishogi対局 WPgmFqSa の時間配分

2026年9月21日の[対局WPgmFqSa](https://lishogi.org/WPgmFqSa/gote)では、後手minaseが90分の本時間を160手目で使い切り、その後も451手目まで対局が続いた。
改善候補は、最善手が安定している局面で次の反復を始める条件を厳しくする変更と、序盤の時間配分を抑える期間を延ばす変更である。
ログでは、約19秒まで同じ最善手を選び続けた後、次の反復に進んで約192秒を使った手があり、反復の開始判断から見直す根拠がある。
本時間中にも秒読み相当の時間を毎手加算する配分も早期消費を促すため、両候補を別々に測定する。
本書は棋譜と保存ログを調べた検討結果であり、実装変更、再探索、採否測定は行っていない。

## 棋譜と実行条件

対局は本時間90分、秒読み60秒、加算なしであり、先手a14481に対して後手minase-botが451手で敗れた。
公開された[消費時間つき棋譜](https://lishogi.org/game/export/WPgmFqSa?clocks=true)の累計時間から求めた後手の残り時間は次のとおりである。
手数は先後を通算した棋譜上の番号であり、160手目は後手の80回目の着手に当たる。

| 手数 | 後手の累計消費時間 | 本時間の残り |
|---|---:|---:|
| 40手目 | 20分28秒 | 69分32秒 |
| 60手目 | 36分22秒 | 53分38秒 |
| 100手目 | 64分00秒 | 26分00秒 |
| 140手目 | 84分58秒 | 5分02秒 |
| 160手目 | 90分43秒 | 0秒 |

保存ログは、将棋エンジン用通信規約のUniversal Shogi Interface（USI）のコマンドを探索ごとにまとめて調べた。
抽出した[ログの一時集計](/tmp/minase-WPgmFqSa-engine-trace.json)には、実戦で採用した後手225着手があり、全着手の`bestmove`が公開棋譜と一致した。
エンジンの申告名は`minase 1.0.0`、設定は`Threads=4`、`USI_Hash=2048`であり、先読み187回のうち41回が的中し、146回が外れた。
対局時のソースコミットは確定していないため、予算式と停止条件の照合には調査時のコミット`1633f53`を使った。
以下では、ログで観測した時間と、現行コードを当てて説明した機構を区別する。

Botがエンジンへ渡す残り時間は、公開棋譜から再構成した本時間より小さい。
[Botの時計処理](../../minase-lishogi-bot/README.md)は、通信などの余裕時間に加えて秒読み時間も控除し、負になる値を0にする。
本局では156手目から`go wtime 0`となったが、棋譜上で本時間が尽きたのは160手目である。
エンジンへ残り時間を渡した76着手に、初手の固定1秒探索を加えた77着手を、以下の本時間側の集計対象とした。

## 毎手の配分と長考の機構

現行の時間管理は、反復の境界で止める目安を**soft**、探索途中でも止める上限を**hard**としている。
[時間配分の実装](../../src/search/alphabeta/time.rs)では、初形からの手数を`p`、エンジンへ渡された本時間を`R`、加算を`I`、秒読みを`B`として、ミリ秒単位で次の式を用いる。
`N`は自分が今後指す手数の見積りである。
以下は係数を実数で表した式であり、実装では時間の各項を整数ミリ秒へ切り捨てる。

```text
N = max(100, floor((450 − p) / 2))
w = min(1, (p + 4) / 40)                 # R > 0 の場合
w = 1                                   # R = 0 の場合
soft_raw = R/N + 0.7I + 0.8B·w
hard = max(1, min(4soft_raw, R/4 + 0.8B, max(1, R+B−30)))
soft = min(soft_raw, hard)
```

本局の秒読みは60秒なので、`p ≥ 36`では本時間の分担に48秒を毎手加算する。
後手では38手目からこの係数が上限に達し、本時間が残る間も秒読み相当の予算を本時間から消費する。
想定終局手数450手は実際の451手に近く、残り手数の下限100手が働き始めるのは本時間が尽きた後である。
想定終局手数を増やすだけでは48秒の加算が残るため、主な消費要因への対処にならない。

反復を開始する条件も、実消費をsoftより長くする。
直近4反復の最善手が一致する場合、経過時間の2.5倍がsoft以内なら次へ進み、それ以外は経過時間がsoft未満なら次へ進む。
どちらも経過時間の2.5倍がhard以内であることを要求するが、開始した反復の途中では通常softを検査しない。
評価値が予測した範囲を外れた際の読み直しも同じ反復に含まれ、反復が長引けばhardまで続く。
したがって、softによる停止でも、最後に完了した反復が予算を大きく超える場合がある。

## ログに残った長考

62手目と118手目は通常の`go`で始まっており、先読みの経過時間を差し引く必要がない。
実際の時計入力と現行式による予算を並べると、次のようになる。
探索時間は`go`から`bestmove`までのログ時刻の差であり、棋譜の秒単位の丸めとは区別した。

| 手数 | `wtime` | soft | hard | 探索時間 | 停止理由 |
|---|---:|---:|---:|---:|---|
| 62手目 | 3,156,116 ms | 64.268秒 | 257.072秒 | 191.751秒 | soft |
| 118手目 | 1,098,070 ms | 54.614秒 | 218.456秒 | 218.467秒 | hard |

62手目では深さ12から15まで最善手が`3e3f`で一致し、深さ15は累計19.063秒で完了した。
次の深さ16は累計191.739秒で完了し、最善手は同じ`3e3f`だった。
現行の安定時の予測は`19.063 × 2.5 = 47.6575秒`でsoft以内だったため、次の反復を許す。
この手では、予測が最後の反復の所要時間を大きく過小評価していた。

118手目でも、深さ9から12まで最善手が`6d8f`で一致し、深さ12は累計17.494秒、深さ13は累計18.474秒で完了した。
次の反復はhardまでに完了せず、最終的に`6d8f`を返した。
最後の完了通知から着手までに約200秒を使っており、前に完了した結果へ戻る停止方式では、この時間を完了深さへ反映できていない。
ただし、最善手が同じだったという事実だけで、その手の正しさや長い探索の価値までは判定できない。

本時間側77着手の停止理由はsoftが75回、hardが2回であり、hard停止は118手目と154手目だった。
この2手で、最後の完了通知後から着手までに課金された時間は合計247.448秒である。
これはログ時刻から求めた時間であり、内部の計算時間を直接測った値ではない。
62手目のようにsoft停止でも長考するため、hard停止だけを減らしても早期消費の全体は説明できない。

先読みの的中後は、[探索実装](../../src/search/)が`ponderhit`からhardを計時する。
一方、`info time`には先読み開始からの時間が含まれるため、先読み41的中分の課金時間は`ponderhit`から着手までで集計した。
通常探索639組について、深さ8以上、直前の累計時間1秒以上に絞った隣接する完了反復の累計時間比は、中央値2.124、90パーセンタイル5.045であり、252組が2.5を超えた。
未完了反復を含まないことによる生存バイアスがあり、局面、ワーカー、置換表にも依存するため、この分布だけから新しい係数を最適値として選ぶことはできない。

## 比較する改善候補

第1候補は、最善手が安定した場合にsoftと比べる予測係数だけを2.5から3.5へ変更する。
hardに対する予測や安全上限には同じ変更を及ぼさず、通常探索と先読みの的中後で安定時の判断を揃える。
記録された全反復境界へ順にこの条件を当てると、62手目は深さ15の19.063秒、118手目は深さ12の17.494秒で次の反復を開始しなくなる。
それぞれ`19.063 × 3.5 = 66.7205秒 > 64.268秒`、`17.494 × 3.5 = 61.229秒 > 54.614秒`となるためである。
2手の記録上の差は合計約374秒に相当するが、実再探索はしておらず、1局全体の節約量や棋力の予測ではない。
3.5は比較候補であり、次の反復で良い手を見つける局面を逃す損失も測る必要がある。

本時間が正で通常探索だった67着手へ同じ条件を当てると、14着手で停止が早まり、そのうち11着手は実戦の最終最善手と一致し、56手目、78手目、82手目は異なる。
初手の固定時間探索と先読みの的中分を除いた比較であり、着手の良し悪しは判定していない。
この比較は他のワーカー、以後の時計、置換表の変化を固定した記録上の試算なので、採否には実際の対局が必要である。

第2候補は、秒読み項の序盤係数の初期値0.1を保ち、上限へ達する手数を36手から120手へ延ばす。
候補式は`w = min(1, 0.1 + 0.9p/120)`とし、本時間が0の場合は現行どおり`w = 1`とする。
本時間の分担と反復の停止方式を保ちながら、最初の数十着手に秒読み項が増える速度を抑える比較になる。
120手も最適値として実証した値ではなく、局面の難しさにかかわらず序盤の読みを減らす影響を確認するための候補である。
2候補を別コミットで基準と比べ、両方を採る場合の相互作用は別に判定する。

本時間中の秒読み項を全面的に外す方式と、hardを直接縮める方式は後回しにする。
[既存の設計判断](../plans/time-management-efficiency.md)が扱う時計では、本時間を使い切るまで秒読みを利用できず、温存によって1局の総探索時間が減る場合がある。
[過去のD2測定](../measurements/time-management-decomposition-d2-stc.md)は途中停止と予算変更を含む構成が加算方式で劣った結果であり、本時間の温存だけを棄却する証拠にはならない。
[hard倍率を変えたK1の診断](../lessons/simulate-acceptance-criteria-on-the-candidate.md)では、候補式と判定条件が整合しなかったため、今回は各候補の式へ判定条件を先に当てる。

## 採否を決める検証

候補の比較では、100手目、200手目、300手目の残り時間と本時間が尽きる手数に加え、完了深さ、hard停止、最後の完了通知から停止までの課金時間、総思考時間を記録する。
序盤の安定した局面と戦術的な局面を分け、節約した時間と引き換えに読みや着手が悪化していないかを確認する。
現行より残り時間が多いことだけを採用条件にはせず、棋力は[棋力測定の手引き](../guides/sprt.md)に従うコミット対コミットの逐次確率比検定（SPRT）で判定する。

本局と同じ本時間対秒読みの比90対1を含め、短時間の診断候補として本時間18,000 msと秒読み200 ms、その後の候補として本時間90,000 msと秒読み1,000 msを用意する。
時間の比だけでは反復の深さや所要時間を再現できないため、実時間での代表局面と、配備条件の4スレッド、先読みありの挙動も確認する。
第1候補は秒読みのない加算方式でも発動するため、規約に従う標準の短時間測定と長時間測定に加えて、比90対1の秒読み条件を調べる。
秒読み項だけを変える第2候補は、標準の加算方式による短時間測定と長時間測定では発動しない。
そのため、秒読み条件を採否へ組み込む手順は実装前の計画で定め、現行の測定規約からの変更を本調査だけで承認済みとは扱わない。

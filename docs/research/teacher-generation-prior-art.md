# 将棋の教師生成と学習ツールの調査（GenSfenとtatara）

## 結論

[棋力向上段階9](../plans/strength-stage9.md)の教師データの改善の参考として、やねうら王の教師生成スクリプトGenSfenと、将棋のNNUE学習ツールtataraのソースを調べた。
結論は5点ある。

1. 将棋の教師の質は、生成時の工夫ではなく、強い評価関数による1手1,000,000ノードの探索、自分より強い評価器による教師値の付け替え（知識蒸留）、および大量の開始局面集の3つで作られている。GenSfenは対局の全局面をそのまま記録し、選別と加工は生成の後の別の道具が行う。
2. この3つは、どれも「評価関数が既に王の危険を知っている」ことを前提にしており、minaseの問題（評価関数が王の危険を知らないので、その探索値も危険を含まない）を直接には解かない。minaseには、教師値を付け替えられるほど強い別の評価器がない。
3. 転用できる着想は3つある。第1は、開始局面を乱数の着手ではなく外部の局面集から取ることであり、実戦棋譜の局面を開始局面にした自己対局という新しい候補になる。第2は、実戦棋譜を探索値なしで対局結果だけの教師にする先例があることであり、候補Bの混合の比の前提に関わる。第3は、tataraが付け直した値を元のデータと行が対応する別ファイルで持つ方式であり、計画書の来歴の設計を単純にできる。
4. tataraの教師値の付け直しは、学習済みのネットの探索なしの静的評価で全局面の値を置き換える機能であり、深い探索で付け直す診断Aとは方向が逆である。tataraの損失の工夫には棋力の測定結果が付いておらず、計画書の「混合の比を変えない」決定を動かす材料にはならない。
5. tataraの利きの入力特徴は、升ごとの利き数を0、1、2以上に切り詰める点と、推論側で利き数の表を差分更新して学習側の全計算と照合する点で、[棋力向上段階9](../plans/strength-stage9.md)の土台と同じ構成を採る。脅威の特徴の先行実験は、深さ固定では基準を上回り、固定時間では速度の低下で負け越したと記録している。

## GenSfenの生成方式

GenSfenは、USIエンジンを2つ起動して自己対局させ、各手の指し手と探索値を棋譜の形で保存するPythonのスクリプトである（GenSfen/gensfen.py 305行から378行）。
minaseの生成器 `selfplay_gen` との違いを次の表に示す。

| 観点 | GenSfen | minase（[評価関数の設計書](../plans/evaluation.md)） |
|---|---|---|
| 開始局面 | 外部の局面集から1局に1つずつ取り出す。局面集は読み込み時にシャッフルする（gensfen.py 156行から211行）。定跡ファイルの先端の局面を局面集へ変換する道具 `yanebook2startsfen.py` を同梱する。対局中に乱数の着手は入れない。 | 初期局面から8手から16手を乱数で進める。 |
| 探索の量 | 設定の見本は1手あたり1,000,000ノードである（settings/gensfen-settings-sample.json5）。 | 1手あたり100,000ノードである。 |
| 終局 | 投了、入玉宣言、千日手、および手数上限320手で終わる。手数上限と通常の千日手は引き分けとして保存し、連続王手の千日手は王手を続けた側の負けとして保存する（gensfen.py 46行から57行、333行から346行）。評価値による打ち切りは既定では行わない。 | 手数上限（生成器の既定は4,000手、世代0は600手）に達した対局は全局面を破棄する。 |
| 記録する局面 | 対局の全局面を記録する。生成時の除外はない。棋譜から局面への変換 `convert_teacher.py` にも除外の条件はない。 | 詰みの帯の値、最善手が捕獲または成りの局面、および同じ対局の中の再出現を除外する。除外率は約25%である。 |
| 生成の後の加工 | 評価値の絶対値が25,000以上の局面の除外（teacher/filter_hcpe_by_eval.py）、引き分けの対局の除外（任意）、同じレコードの除去（任意）、および局面の単位のシャッフルを、別の道具で行う（teacher/README.md）。 | 生成時に除外を済ませ、学習器が対局の単位で検証の分割を決める。 |
| 教師値の付け替え | 既存の教師の評価値を、深層学習のモデルの出力で置き換える道具を持つ。READMEは、大きなモデルで付け替えた教師から小さなモデルを学習することを知識蒸留と呼ぶ（teacher/README.md のre-evalの節）。 | 同じ評価関数による深い探索での付け直しを、診断Aで調べる計画である。 |
| 実戦棋譜 | CSA形式の棋譜を、両対局者のレーティングの下限で絞って教師へ変換する。評価値は0を書き、実際に指された手と対局結果だけを教師にする（teacher/csa_to_hcpe.py、既定は16手未満の棋譜の除外）。 | 調査の時点の候補Bは、実戦棋譜の局面に探索値を付け、既存のデータと同じ混合の比で加える計画だった。 |

GenSfenの生成の流れは単純であり、教師の質を上げる仕組みは、強いエンジン、多いノード数、多様な開始局面、および生成の後の付け替えに置かれている。
静止探索の末端の局面を教師にする処理や、王手の局面と捕獲の局面の除外は、GenSfenにもtataraの読み込みにもない。
やねうら王の旧来の学習部が持っていたこれらの処理を、現在の生成と学習の道具は使っていないことになるが、その理由を述べた文書は今回の範囲にはなく、未確認である。

tataraは学習器だけで構成され、教師の生成と、探索による付け直しの機能を持たない。
文書が置く前提は、入力が事前に全体でシャッフルされていることだけであり、生成の条件を記した文書はない。

## minaseの問題との対応

計画書が調べる仮説は、教師の探索が駒を取らない長い攻めを危険と見ないことと、自己対局ではどちらの側もその攻めを実行しないことの2つである。
将棋の方式がこの2つに効くかを、次の表に整理する。

| 将棋の方式 | minaseで成り立つか |
|---|---|
| 強い評価関数による1,000,000ノードの探索 | 成り立たない。敗局の174手目は、対局時の深さ12で+1037、90秒の深さ14でも+880であり、ノード数を増やしても危険が見えなかった。計画書は全局面のノード数の引き上げを既に棄却している。 |
| 自分より強い評価器による教師値の付け替え | 成り立たない。minaseより強く、規則を一致させられる評価器がない。HaChuには固定200ペアで+541 Eloの差をつけている。 |
| 外部の局面集を開始局面にした自己対局 | 成り立つ。実戦棋譜の局面が局面集になる。詳細は次節に記す。 |
| 実戦棋譜を対局結果だけで教師にする | 成り立つ。候補Bの前提に関わる。詳細は次節に記す。 |
| 世代の反復 | 条件つきで成り立つ。対局結果の成分で学習した重みは、次の世代の探索値へ反映されて強まる。ただし、最初の世代で重みが正しい符号で学習されることが前提であり、項目1の序中盤の重みは小さく、符号も期待と逆のものが多かった。 |

## 計画書への含意

本節は、調査の時点の教師データの改善の計画に対する含意を記す。
この計画は、本節の3点（実戦開始の自己対局と診断C、教師の分類ごとの混合の比、付け直しファイル）を取り込んだうえで、[棋力向上段階9](../plans/strength-stage9.md)へ統合された。
以下の「計画書」と「候補B」は調査の時点の計画を指し、候補Bは段階9の設計書の追加Bに当たる。

### 実戦棋譜の局面を開始局面にした自己対局

GenSfenは、開始局面の多様性を乱数の着手ではなく外部の局面集で確保する。
minaseの自己対局は、初期局面から乱数で8手から16手を進めた局面から始まり、以後は両側が同じ評価関数で指すので、人間の対局に現れる王の露出した配置へ到達しにくい。
実戦棋譜の途中の局面を開始局面にすれば、人間が作った配置から自己対局を始められる。

この方式は、計画書の候補Bが抱える規則の問題を避けられる。
候補Bは、lishogiの規則セットで指された棋譜を既定の規則セットで再生し、勝者の不一致や不合法な手を理由に対局を除外する必要がある。
開始局面だけを借りる方式では、教師の探索値と対局結果の両方が既定の規則セットの自己対局から得られ、規則をまたぐ教師が生じない。
一方、対局結果は人間ではなくエンジンの手順の結果になるので、「人間は長い攻めを実行する」という候補Bの根拠は失われる。
攻めが既に進んだ局面から始めれば、残りの手数が短くなり、探索が結末まで読める可能性はあるが、これは未測定である。
計画書は「実戦棋譜の露出局面を深く探索する方式」を後続の候補として記録しており、この方式はその変種に当たる。

### 候補Bの混合の比

GenSfenの `csa_to_hcpe.py` は、実戦棋譜の局面に探索値を付けず、対局結果と指された手だけを教師にする。
調査の時点の候補Bは、実戦棋譜の局面にminaseの探索値を付け、既存のデータと同じλ=0.75で混ぜる計画だった。
この場合、教師値の75%は現行の評価関数の探索値であり、計画書が原因と疑う盲点をそのまま持つ。
実戦棋譜が持ち込む新しい情報は対局結果の成分だけなので、その寄与は25%へ薄まる。
診断Bは対局結果の予測の改善を調べるので、診断Bが基準を満たしても、候補Bの学習ではその信号の4分の1しか使われない。

計画書は、露出局面だけ対局結果の比を上げる案を「局面に応じて教師の目標を変える別の候補」として範囲外にしている。
教師の分類ごとに混合の比を変える案は、局面の内容ではなくデータの由来で決まるので、これとは別の選択である。
tataraは、引き分けの行だけ対局結果の重みを0にするという形で、行ごとに混合の比を変える仕組みを持つ。
計画書は教師Kを教師の分類ごとに推定すると既に定めているので、混合の比を同じ単位で持たせる拡張は小さい。
ただし、対局結果だけを教師にすると、1局の中で一定の目標を、対局中にほぼ変わらない囲いの特徴が記憶するおそれがあり、[教訓](../lessons/game-constant-target-memorization.md)の監視が要る。

### 付け直した値を別ファイルで持つ

計画書は、付け直した局面を別のMNSDファイルにすると、同じシードでは読み込みが拒否され、シードを変えると検証の所属が変わることを課題に挙げ、来歴ファイルと元の局面との対応表で解く設計にしている。
tataraの方式は、元のデータを書き換えず、行が対応する探索値の別ファイルと、元の値を残す行のビットマップで差し替える。
この形では、局面、対局結果、対局番号、手数が元のファイルのまま変わらないので、検証の所属は元のシードと対局番号のまま保たれ、元の局面との対応は行番号だけで済む。
候補Aの対照（探索値だけを元の値へ戻した学習）は、別ファイルを外すだけでは作れない。
別ファイルを外すと、新しい探索の結果による除外も失われ、局面の集合が変わるためである。
対照は、別ファイルを与えたまま、差し替えを行わずに除外だけを適用する動作で作る。
新しい探索で生成時の除外に当たった局面は、別ファイルに除外を表す値を置き、読み込み時に捨てる形で表せる。
教師の分類を来歴として記録する必要は変わらない。

長時間の付け直しでは、出力を変える条件を記録して一致するときだけ再開し、未コミットの変更を含むビルドでは再開を拒否するtataraの規則が、[生成コミットを固定する教訓](../lessons/pin-generation-binary-to-worktree.md)の機械的な強制として使える。

### 診断の指標

候補と対照は教師値が違うので、損失どうしを直接には比べられない。
モデルの出力の符号と対局結果の一致率は、教師値にも損失の尺度にも依存しないので、共通の検証の対局で、候補、対照、基準を1つの数で並べられる。
特徴の寄与は、王の安全度の列の重みを0にしたときの検証損失の増分を、同じ数の無作為な列を0にしたときの増分と比べる方法で、重みの大きさや符号より解釈しやすく測れる。
どちらも診断の読みやすさを上げるだけであり、棋力の根拠にはならない。

### 当てはまらないもの

- ネットの静的評価による付け直しは、教師にするネットが教師の探索値より良い評価を持つことを前提にするので、線形の評価関数しか持たないminaseには使えない。
- 引き分けの帯を表すtataraの勝率モデルの損失は、既定値がチェス向けであり、tatara自身の将棋の例も単純なシグモイドへ退化させている。
- 窓の中だけのシャッフルは、数億局面以上を外部記憶から読むための仕組みであり、約2,500万局面のminaseには要らない。
- 検証の分割は、tataraでは対局の単位ではなく、minaseの現行の方式の方が厳密である。
- 多数の候補手の評価値から方策の分布を作るGenSfenの出力は、方策を学習しないminaseには関係しない。

## 利きの入力特徴

tataraは、利きを入力特徴にする仕組みを2つ持つ。
第1は、盤上の各駒が立つ升への攻めと守りの利き数を0、1、2以上に切り詰め、その駒の既存の特徴の番号を細分する方式である（crates/shogi-features/src/effect_bucket.rs 82行から88行）。
区分はやねうら王の入力特徴HalfKPE9と同じであり、対象は駒のいる升に限られるので、minaseの評価項目の調査でいう駒への脅威の段階に近く、王の周囲の空升を見る攻撃域には当たらない。
第2は、「ある駒が別の駒に利いている」という関係1つを1つの特徴にする方式である（crates/shogi-features/src/threat.rs 3行から15行）。

設計の記録から、[棋力向上段階9](../plans/strength-stage9.md)の土台に関わる点を3つ挙げる。

- 推論側は利き数の表を差分更新し、学習側は局面から全計算して、両者をバイトの単位で照合している。照合の局面には、王に隣接して駒が密集する局面、成駒、走り駒の遮蔽を含めるよう定めている（docs/decisions/2026-07-09-effect-bucket-feature-set.md 108行から109行）。
- 落とし穴として、王の利きを利き数に含めるかどうかの不一致と、長い利きの更新の漏れによって開き利きの変化を落とすことを挙げている（同57行から59行、85行から86行）。
- 脅威の特徴の先行実験は、深さを固定した対局では基準を上回ったが、固定時間の対局では速度の低下で探索が浅くなり、負け越したと記録している（docs/decisions/2026-06-19-threat-feature-set.md 11行から20行）。これは、速度の下限を進む条件とし、採否を時間制御の検定で決めるminaseの方針と同じ結論である。
